The machine-coding round, step by step

A machine-coding round asks for working, extensible code for a small system in 60 to 90 minutes. This chapter gives you a timeline with checkpoints, a five-minute clarification script, a mechanical way to turn a problem statement into classes and methods, a thin-domain-plus-services structure over in-memory repositories, what to test, how to present your trade-offs and absorb a new requirement, and the failure modes that sink most candidates. It ends with a timed library-management exercise and a scoring rubric.

After this chapter you can
  • Split a 60-90 minute round into five phases with two checkpoints, and know what to cut when you fall behind
  • Run a five-minute clarification that ends with written scope, rules and assumptions
  • Extract classes, attributes, policies and methods from a statement (nouns → classes, verbs → methods) and filter out the false candidates
  • Structure code as a thin domain plus services over in-memory repositories, built and run in vertical slices
  • Choose the handful of tests that prove the happy path and each rule, and present the design and its trade-offs
  • Recognise over-engineering, a missing happy path and missing tests before the interviewer does

What the round is, and what it scores

A machine-coding round gives you a one-page problem statement (an expense splitter, a parking lot, a library, a snake-and-ladder game), 60 to 90 minutes, your own editor, and one expectation: at the end, the code runs. A driver or a handful of tests demonstrates the main flows, and the interviewer reads the code with you. Storage is in memory, there is no UI, and many interviewers add a requirement near the end ("now support splitting by percentage") to see whether the design bends or breaks.

It is scored on roughly five things (the rubric at the end of the chapter gives typical weights):

  1. Working code: the main use cases run end to end, and bad input produces a clear error, not a crash.
  2. Modelling: the classes match the domain, states are explicit, and each rule lives next to the data it protects.
  3. Extensibility: the new requirement is an addition (a class, a method), not a rewrite.
  4. Code quality and tests: clear names, short functions, type hints, a few tests that check real rules.
  5. Communication: you stated scope and assumptions, kept to time, and can defend your trade-offs.

Same skills, different evidence. In machine coding the design is judged through code that works.

What the interviewer is really asking: can you turn an ambiguous page into working, readable code on a clock, and does the design survive a new requirement? Open by saying your plan: 'I'll take five minutes to pin down scope and write down assumptions, ten to sketch the classes and method signatures with you, then build the main flow end to end before anything else. I'll keep fifteen minutes for tests and leave room for an extension. If I fall behind, I'll cut edge cases, not the working flow.'

Clarify requirements in five minutes

Clarifying has three jobs: shrink the problem to what fits in the time, surface the rules that shape the model (limits, rounding, states, who may do what), and agree on how the code will be driven (a main() driver, tests, or commands read from input).

Ask closed questions with a default: "I'll assume money is in integer paise and equal-split remainders go to the first members; is that fine?" The interviewer can only correct you, which takes seconds, instead of opening a discussion that takes minutes. Then write the answers into the file, where both of you can see them.

Find the entities: nouns become classes, verbs become methods

▶ Video lesson: Nouns to classes, verbs to methods 4:25 · 6 scenes · narrated, pause anytime and explore

A mechanical first pass beats staring at the statement. It gives you a defensible class list in about five minutes, and the interviewer can watch the reasoning.

  1. Fade the filler words, so the statement is easy to scan.
  2. Underline every noun. Each one is a candidate class.
  3. Filter the candidates. The system itself and outside callers are not entities; synonyms merge; a noun with no identity or rules of its own is an attribute; a value you can compute from other data is a method.
  4. Words that name alternatives ("equally or by exact amounts", "hourly or flat") are a policy: one interface and one small class per variant (the Strategy pattern, see Behavioural patterns).
  5. Circle every verb. Each is a candidate method. Give it to the class that owns the data it changes. A verb that only describes data ("paid by") is a field; a verb that states a guarantee ("must clear every debt") is a test.
  6. States ("pending", "settled") become an Enum; limits and rates become named constants or a policy.

Structure: a thin domain, services and in-memory repositories

Five kinds of code, each with one job. Keeping them apart is what makes the twist at minute 60 cheap.

  • Domain models are small dataclasses that hold state and protect their own invariants: Group.add_member refuses duplicates, Expense refuses shares that do not add up. No I/O, no printing, no idea how they are stored.
  • Policies hold the rules that vary (EqualSplit, ExactSplit) behind one small interface.
  • Repositories hide storage behind add, get and find. In the round each one wraps a dict; the interface is what lets "now persist it" be a new class rather than a rewrite.
  • Services implement the use cases, one method per verb you found: load what they need from repositories, check the rules that span several objects, call domain methods and policies, store, return. They hold no state beyond their collaborators.
  • The driver (main()) or the tests wire everything together in one place, the composition root, and it is the only code that prints.

Thin means two things: the domain does not grow into a god object that knows about storage and output, and the services do not turn into scripts that poke at other objects' fields. Each rule has exactly one home.

flowchart TD
  DRV[Driver, tests<br/>wire and print] --> SVC[Services<br/>use cases]
  SVC --> DOM[Domain models<br/>state, invariants]
  SVC --> POL[Policies<br/>rules that vary]
  SVC --> REP[Repository interfaces<br/>add, get, find]
  MEM[In-memory repos<br/>one dict each] -.->|implements| REP
  MEM --> DOM
  DRV -.->|creates| MEM
Arrows point at what each part depends on. The domain depends on nothing, so it is the easiest code to test; only the driver knows which repositories are concrete.

The expense splitter, part by part

Dataclasses with their invariants inside. frozen=True for objects that never change after creation. Domain errors get their own exception type, so the driver can tell a broken rule from a bug.

from __future__ import annotations

from dataclasses import dataclass, field


class DomainError(Exception):
    """A business rule was broken. The message says which one."""


class NotFound(DomainError):
    """An id that does not exist."""


@dataclass(frozen=True)
class User:
    user_id: str
    name: str


@dataclass
class Group:
    group_id: str
    name: str
    members: list[str] = field(default_factory=list)

    def add_member(self, user_id: str) -> None:
        if user_id in self.members:                      # the rule lives with the data it protects
            raise DomainError(f"{user_id} is already in {self.name}")
        self.members.append(user_id)


@dataclass(frozen=True)
class Expense:
    expense_id: str
    group_id: str
    paid_by: str
    amount: int                                          # integer paise: ₹900.00 is 90000
    shares: dict[str, int]                               # user_id -> what that user owes for this expense

    def __post_init__(self) -> None:
        if sum(self.shares.values()) != self.amount:     # invariant checked once, at creation
            raise DomainError("shares must add up to the amount")


@dataclass(frozen=True)
class Transfer:
    payer: str
    payee: str
    amount: int

One Protocol, one class per variant. The service never asks which kind of split it was given.

from typing import Protocol


class SplitStrategy(Protocol):
    def split(self, amount: int, members: list[str]) -> dict[str, int]: ...


class EqualSplit:
    def split(self, amount: int, members: list[str]) -> dict[str, int]:
        base, extra = divmod(amount, len(members))
        # the first `extra` members pay one paisa more, so the shares always add up to the amount
        return {m: base + (1 if i < extra else 0) for i, m in enumerate(members)}


class ExactSplit:
    def __init__(self, amounts: dict[str, int]):
        self.amounts = dict(amounts)

    def split(self, amount: int, members: list[str]) -> dict[str, int]:
        if not set(self.amounts) <= set(members):
            raise DomainError("exact split names someone outside the group")
        if sum(self.amounts.values()) != amount:
            raise DomainError(f"exact amounts add up to {sum(self.amounts.values())}, not {amount}")
        return dict(self.amounts)

One generic dict-backed repository serves every entity. A database version would replace find(predicate) with named queries such as for_group(group_id).

from typing import Callable, Generic, Protocol, TypeVar

T = TypeVar("T")


class Repository(Protocol[T]):
    def add(self, item: T) -> None: ...
    def get(self, item_id: str) -> T: ...
    def find(self, predicate: Callable[[T], bool]) -> list[T]: ...


class InMemoryRepository(Generic[T]):
    """A dict behind the interface a database-backed repository would also offer."""

    def __init__(self, key: Callable[[T], str]) -> None:
        self._key = key
        self._items: dict[str, T] = {}

    def add(self, item: T) -> None:
        item_id = self._key(item)
        if item_id in self._items:
            raise DomainError(f"duplicate id {item_id}")
        self._items[item_id] = item

    def get(self, item_id: str) -> T:
        try:
            return self._items[item_id]
        except KeyError:
            raise NotFound(item_id) from None

    def find(self, predicate: Callable[[T], bool]) -> list[T]:
        return [item for item in self._items.values() if predicate(item)]

One method per use case. Each loads, checks the rules that span objects, calls the domain and the policy, stores and returns. Ids are injectable so tests can predict them.

import heapq
import itertools
from collections import defaultdict
from typing import Iterator


class GroupService:
    def __init__(self, users: Repository[User], groups: Repository[Group], ids: Iterator[str] | None = None):
        self._users, self._groups = users, groups
        self._ids = ids or (f"g{n}" for n in itertools.count(1))

    def register_user(self, user_id: str, name: str) -> User:
        user = User(user_id, name)
        self._users.add(user)                            # duplicate ids are refused by the repository
        return user

    def create_group(self, name: str, member_ids: list[str]) -> Group:
        group = Group(next(self._ids), name)
        for user_id in member_ids:
            self._users.get(user_id)                     # raises NotFound for an unknown user
            group.add_member(user_id)
        self._groups.add(group)
        return group

    def add_member(self, group_id: str, user_id: str) -> None:
        self._users.get(user_id)
        self._groups.get(group_id).add_member(user_id)   # load, then delegate to the domain rule


class ExpenseService:
    def __init__(self, groups: Repository[Group], expenses: Repository[Expense], ids: Iterator[str] | None = None):
        self._groups, self._expenses = groups, expenses
        self._ids = ids or (f"e{n}" for n in itertools.count(1))

    def add_expense(self, group_id: str, paid_by: str, amount: int, strategy: SplitStrategy,
                    participants: list[str] | None = None) -> Expense:
        if amount <= 0:
            raise DomainError("amount must be positive")
        group = self._groups.get(group_id)
        members = participants or group.members
        if paid_by not in group.members or not set(members) <= set(group.members):
            raise DomainError("the payer and every participant must be in the group")
        expense = Expense(next(self._ids), group_id, paid_by, amount, strategy.split(amount, members))
        self._expenses.add(expense)
        return expense


class BalanceService:
    def __init__(self, expenses: Repository[Expense]):
        self._expenses = expenses

    def balances(self, group_id: str) -> dict[str, int]:
        """Derived on every call, never stored. Positive: the group owes this user. Negative: the user owes."""
        net: dict[str, int] = defaultdict(int)
        for e in self._expenses.find(lambda e: e.group_id == group_id):
            net[e.paid_by] += e.amount
            for user_id, share in e.shares.items():
                net[user_id] -= share
        return dict(net)

    def suggest_settlements(self, group_id: str) -> list[Transfer]:
        """Greedy: the largest debtor pays the largest creditor. At most n - 1 transfers."""
        net = self.balances(group_id)
        debtors = [(v, u) for u, v in net.items() if v < 0]          # most negative first
        creditors = [(-v, u) for u, v in net.items() if v > 0]       # largest credit first (negated)
        heapq.heapify(debtors)
        heapq.heapify(creditors)
        transfers: list[Transfer] = []
        while debtors and creditors:
            debt, debtor = heapq.heappop(debtors)
            credit, creditor = heapq.heappop(creditors)
            pay = min(-debt, -credit)
            transfers.append(Transfer(debtor, creditor, pay))
            if -debt > pay:
                heapq.heappush(debtors, (debt + pay, debtor))
            if -credit > pay:
                heapq.heappush(creditors, (credit + pay, creditor))
        return transfers

The composition root: the only place that names concrete classes and the only place that prints. Running it is your demo.

def main() -> None:
    users = InMemoryRepository[User](key=lambda u: u.user_id)
    groups = InMemoryRepository[Group](key=lambda g: g.group_id)
    expenses = InMemoryRepository[Expense](key=lambda e: e.expense_id)
    group_service = GroupService(users, groups)
    expense_service = ExpenseService(groups, expenses)
    balance_service = BalanceService(expenses)

    for user_id, name in [("alice", "Alice"), ("bob", "Bob"), ("cara", "Cara")]:
        group_service.register_user(user_id, name)
    trip = group_service.create_group("Goa trip", ["alice", "bob", "cara"])

    expense_service.add_expense(trip.group_id, "alice", 90000, EqualSplit())         # dinner, ₹900
    expense_service.add_expense(trip.group_id, "bob", 30000, ExactSplit({"bob": 10000, "cara": 20000}))

    print(balance_service.balances(trip.group_id))      # {'alice': 60000, 'bob': -10000, 'cara': -50000}
    for t in balance_service.suggest_settlements(trip.group_id):
        print(f"{t.payer} pays {t.payee} ₹{t.amount / 100:.2f}")   # cara pays alice ₹500.00, then bob ₹100.00
    try:
        expense_service.add_expense(trip.group_id, "mallory", 500, EqualSplit())
    except DomainError as err:
        print("refused:", err)                          # a broken rule is reported, not a crash


if __name__ == "__main__":
    main()

Inject anything that differs between runs: id generators and the clock. A service that calls datetime.now() or uuid4() inside cannot be tested exactly; one that receives clock= and ids= can, and production passes the real ones.

Build the happy path in slices, then test the rules

Build in vertical slices: one use case through every layer (model, policy, repository, service, two lines in the driver), run it, then start the next. After every slice the program works, so you can stop and demo at any moment, and cutting scope removes a whole slice instead of leaving half of everything. The alternative, horizontal layers (all models, then all repositories, then all services), runs nothing until the last layer exists.

What to test in fifteen minutes

Fifteen minutes buys about six tests. Spend them where a bug would be invisible in the demo: rules, refusals and boundaries. Getters, dataclass fields and dictionary lookups are Python's job, not yours.

Six tests for the expense splitter

import pytest


def build():
    users = InMemoryRepository(key=lambda u: u.user_id)
    groups = InMemoryRepository(key=lambda g: g.group_id)
    expenses = InMemoryRepository(key=lambda e: e.expense_id)
    group_service = GroupService(users, groups)
    for user_id in ("alice", "bob", "cara"):
        group_service.register_user(user_id, user_id.title())
    trip = group_service.create_group("Goa trip", ["alice", "bob", "cara"])
    return trip.group_id, ExpenseService(groups, expenses), BalanceService(expenses)


def test_equal_split_happy_path():
    gid, expenses, balances = build()
    expenses.add_expense(gid, "alice", 90000, EqualSplit())
    assert balances.balances(gid) == {"alice": 60000, "bob": -30000, "cara": -30000}


def test_equal_split_spreads_the_remainder():
    assert EqualSplit().split(100, ["a", "b", "c"]) == {"a": 34, "b": 33, "c": 33}


def test_exact_split_must_add_up():
    gid, expenses, _ = build()
    with pytest.raises(DomainError):
        expenses.add_expense(gid, "bob", 30000, ExactSplit({"bob": 10000, "cara": 10000}))


def test_payer_must_be_a_member():
    gid, expenses, _ = build()
    with pytest.raises(DomainError):
        expenses.add_expense(gid, "mallory", 500, EqualSplit())


def test_no_duplicate_members():
    group = Group("g9", "flat")
    group.add_member("alice")
    with pytest.raises(DomainError):
        group.add_member("alice")


def test_settlements_clear_every_balance():           # the invariant: one test, the whole algorithm
    gid, expenses, balances = build()
    expenses.add_expense(gid, "alice", 90000, EqualSplit())
    expenses.add_expense(gid, "bob", 30000, ExactSplit({"bob": 10000, "cara": 20000}))
    net = balances.balances(gid)
    for t in balances.suggest_settlements(gid):
        net[t.payer] += t.amount
        net[t.payee] -= t.amount
    assert set(net.values()) == {0}
Plain functions with assert: pytest finds and runs them as they are. Without pytest, call them from a loop and use a five-line raises helper, as the practice solution below does.

Three failure modes, and what they look like on the clock

▶ Video lesson: Three ways to lose the round 4:05 · 6 scenes · narrated, pause anytime and explore

Most failed rounds fail in one of three ways, and all three are decided by minute 50. The design never becomes working code (over-engineering), the code never becomes a complete flow (no working happy path), or the code works by luck and nobody can tell (no tests). Failure 1: over-engineering

The smallest structure the statement needs

One interface for the one thing the statement says varies. Add a factory when building an object gets complicated, and a bus when there are real subscribers.

from typing import Protocol

More ways to lose points (click each)

Fifteen minutes of questions

Clarifying is time-boxed to five minutes. A question whose answer would not change a class, a rule or the demo becomes a written assumption instead.

One god class

A Splitwise class with twenty methods and every dict in the program. It is fast for twenty minutes, then every change touches it and every test needs all of it. Split it into models, policies, repositories and services.

Strings for states and kinds

status == 'setled' fails silently. An Enum turns the typo into an AttributeError and lists the legal values in one place.

Float money

0.1 + 0.2 == 0.30000000000000004. Use integer minor units (paise, cents) or decimal.Decimal, and format only for display.

Printing inside the domain

Return values and raise exceptions; print in the driver. Code that prints cannot be tested or reused, and the interviewer cannot tell output from debugging noise.

Swallowing errors

Returning None or False for every failure leaves the caller guessing why. Raise a domain exception with a message; the driver catches it and reports it.

Concurrency nobody asked for

Locks everywhere add risk and time. Say 'single-threaded, as agreed; the lock would go around the check-and-update in add_expense', and build it only if asked. Concurrency & thread safety has the patterns.

First run at minute 60

Forty minutes of code that has never run produces ten bugs at once, with no time to find them. Run after every slice.

Present the design and absorb the twist

Keep the last minutes for a walkthrough. It is scored, and it is where the interviewer decides whether the design was deliberate or accidental.

  1. Run it first: the driver or the tests, before a word about the design. Working code earns the right to talk.
  2. Walk the model top-down: services, then entities, then policies. One sentence each on what it owns.
  3. Name two or three trade-offs you made on purpose: what you gained, what you gave up, and what would make you change your mind (the table below).
  4. Say what is missing and where it would go: "persistence would be a second repository class; thread safety, a lock around add_expense." Out-of-scope work placed precisely is worth almost as much as written code.

Library management system

60:00

Build an in-memory library system, driven by a main() or by tests (no UI, no database).

  • Librarians add books (ISBN, title, author) and any number of physical copies of each.
  • Members register, borrow a copy of a book by ISBN and return it.
  • A member may hold at most 3 copies at once. A loan lasts 14 days.
  • A late return costs 10 per full day late, added to the member's fines. A member who owes more than 100 cannot borrow until they pay.
  • Members can search books by title or author (case-insensitive).
  • If no copy is available, a member can reserve the book. A returned copy is then held for the first member in the queue for 2 days; while the hold lasts, only that member can borrow it.

Hints

Hint 1

Nouns: book, copy, member, loan, fine, reservation, hold. Fine is a number on the member, hold is a state of a copy plus who it is for, and reservation is a queue per book.

Hint 2

Copy states: AVAILABLE, ON_LOAN, ON_HOLD. Put them in an Enum and change them in as few methods as possible.

Hint 3

One LibraryService with dicts for books, copies, members and active loans (keyed by copy id), plus a deque of member ids per ISBN for reservations.

Hint 4

Inject clock: Callable[[], datetime]. In tests a FakeClock with advance(days=...) replaces any sleeping.

Hint 5

Expire holds lazily: whenever someone borrows or reserves a book, first release any of its copies whose hold ran out. No background thread needed.

Hint 6

Slices: books and copies, then borrow and return, then the limit and fines, then search, then reservations and holds, then the tests.

Reference solution (open after your attempt)

What to notice

  • The docstring at the top is the clarification, written down; every rule in it has a test.
  • CopyStatus changes in only two places (borrow and _release), so the hold logic cannot drift apart.
  • The fine is a policy object (PerDayFine). A capped or tiered fine is a new class passed to the constructor.
  • Holds expire lazily when someone looks at the book: no timer, no background job, nothing to race with.
  • The dicts inside LibraryService are repositories in their simplest form. When a second service needs the same data, or the interviewer asks for persistence, promote them to repository classes behind an interface, as in the expense splitter.
  • Deliberately missing: thread safety (a lock around borrow and return_copy, or a conditional update in a database), a notification when a hold starts (an observer called from _release), and renewals (a new method with one rule: not while someone is waiting).
"""Library management: a reference solution for the 60-minute round.

In scope: books and copies, members, borrow/return, 3-loan limit, 14-day loans, late fines (10 per full day),
fines over 100 block borrowing, search by title/author, reservations with a 2-day hold.
Out of scope: auth, UI, persistence, notifications, payments beyond 'pay_fine'.
Assumptions: one process, single-threaded; money in integer units; the clock is injected.
"""
from __future__ import annotations

import itertools
from collections import deque
from contextlib import contextmanager
from dataclasses import dataclass
from datetime import datetime, timedelta
from enum import Enum
from typing import Callable

LOAN_PERIOD = timedelta(days=14)
HOLD_PERIOD = timedelta(days=2)
MAX_LOANS = 3
FINE_LIMIT = 100                      # owing more than this blocks borrowing


class LibraryError(Exception):
    """A rule was broken; the message says which."""


class CopyStatus(Enum):
    AVAILABLE = "available"
    ON_LOAN = "on loan"
    ON_HOLD = "on hold"


@dataclass(frozen=True)
class Book:
    isbn: str
    title: str
    author: str


@dataclass
class Copy:
    copy_id: str
    isbn: str
    status: CopyStatus = CopyStatus.AVAILABLE
    held_for: str | None = None
    hold_until: datetime | None = None


@dataclass
class Member:
    member_id: str
    name: str
    fines: int = 0


@dataclass
class Loan:
    copy_id: str
    member_id: str
    due: datetime


@dataclass(frozen=True)
class PerDayFine:                     # a policy: swap it for a capped or tiered fine without touching the service
    rate: int = 10

    def __call__(self, late: timedelta) -> int:
        return max(0, late.days) * self.rate


class LibraryService:
    def __init__(self, clock: Callable[[], datetime] = datetime.now, fine_policy: Callable[[timedelta], int] = PerDayFine()):
        self._clock, self._fine = clock, fine_policy
        # in-memory repositories in their simplest form: promote them to classes when a second service needs them
        self._books: dict[str, Book] = {}
        self._copies: dict[str, Copy] = {}
        self._members: dict[str, Member] = {}
        self._loans: dict[str, Loan] = {}                   # copy_id -> active loan
        self._waiting: dict[str, deque[str]] = {}           # isbn -> member ids, first come first served
        self._copy_ids = (f"c{n}" for n in itertools.count(1))

    # --- catalogue and members -------------------------------------------------
    def add_book(self, isbn: str, title: str, author: str, copies: int = 1) -> list[str]:
        if isbn in self._books:
            raise LibraryError(f"book {isbn} exists; use add_copies")
        self._books[isbn] = Book(isbn, title, author)
        return self.add_copies(isbn, copies)

    def add_copies(self, isbn: str, count: int) -> list[str]:
        self._book(isbn)
        new = [Copy(next(self._copy_ids), isbn) for _ in range(count)]
        self._copies.update((c.copy_id, c) for c in new)
        return [c.copy_id for c in new]

    def register_member(self, member_id: str, name: str) -> None:
        if member_id in self._members:
            raise LibraryError(f"member {member_id} exists")
        self._members[member_id] = Member(member_id, name)

    def search(self, text: str) -> list[Book]:
        needle = text.casefold()
        hits = [b for b in self._books.values() if needle in b.title.casefold() or needle in b.author.casefold()]
        return sorted(hits, key=lambda b: b.title)

    # --- loans -------------------------------------------------------------------
    def borrow(self, member_id: str, isbn: str) -> Loan:
        member = self._member(member_id)
        if member.fines > FINE_LIMIT:
            raise LibraryError(f"{member_id} owes {member.fines}; pay before borrowing")
        if sum(1 for loan in self._loans.values() if loan.member_id == member_id) >= MAX_LOANS:
            raise LibraryError(f"{member_id} already has {MAX_LOANS} loans")
        copy = self._copy_for(member_id, isbn)
        copy.status, copy.held_for, copy.hold_until = CopyStatus.ON_LOAN, None, None
        loan = Loan(copy.copy_id, member_id, self._clock() + LOAN_PERIOD)
        self._loans[copy.copy_id] = loan
        return loan

    def return_copy(self, copy_id: str) -> int:
        loan = self._loans.pop(copy_id, None)
        if loan is None:
            raise LibraryError(f"copy {copy_id} is not on loan")
        fine = self._fine(self._clock() - loan.due)
        self._members[loan.member_id].fines += fine
        self._release(self._copies[copy_id])
        return fine

    def pay_fine(self, member_id: str, amount: int) -> None:
        member = self._member(member_id)
        member.fines = max(0, member.fines - amount)

    # --- reservations ------------------------------------------------------------
    def reserve(self, member_id: str, isbn: str) -> int:
        self._member(member_id)
        self._book(isbn)
        self._expire_holds(isbn)
        if any(c.isbn == isbn and c.status is CopyStatus.AVAILABLE for c in self._copies.values()):
            raise LibraryError("a copy is available: borrow it instead")
        queue = self._waiting.setdefault(isbn, deque())
        if member_id in queue:
            raise LibraryError(f"{member_id} already reserved {isbn}")
        queue.append(member_id)
        return len(queue)                                   # position in the queue

    # --- helpers -------------------------------------------------------------------
    def _copy_for(self, member_id: str, isbn: str) -> Copy:
        self._book(isbn)
        self._expire_holds(isbn)
        copies = [c for c in self._copies.values() if c.isbn == isbn]
        held = next((c for c in copies if c.status is CopyStatus.ON_HOLD and c.held_for == member_id), None)
        free = next((c for c in copies if c.status is CopyStatus.AVAILABLE), None)
        if held or free:
            return held or free
        raise LibraryError(f"no copy of {isbn} is available; reserve it")

    def _release(self, copy: Copy) -> None:
        """A copy coming back goes to the first person waiting, or back on the shelf."""
        queue = self._waiting.get(copy.isbn)
        if queue:
            copy.status, copy.held_for = CopyStatus.ON_HOLD, queue.popleft()
            copy.hold_until = self._clock() + HOLD_PERIOD
        else:
            copy.status, copy.held_for, copy.hold_until = CopyStatus.AVAILABLE, None, None

    def _expire_holds(self, isbn: str) -> None:
        now = self._clock()
        for c in self._copies.values():
            if c.isbn == isbn and c.status is CopyStatus.ON_HOLD and c.hold_until <= now:
                self._release(c)                            # expired: pass it on, lazily, when anyone looks

    def _book(self, isbn: str) -> Book:
        if isbn not in self._books:
            raise LibraryError(f"no book {isbn}")
        return self._books[isbn]

    def _member(self, member_id: str) -> Member:
        if member_id not in self._members:
            raise LibraryError(f"no member {member_id}")
        return self._members[member_id]


# --- tests: run with `pytest library.py` or `python library.py` ---------------------------
class FakeClock:
    def __init__(self, start: datetime):
        self.now = start

    def __call__(self) -> datetime:
        return self.now

    def advance(self, **delta: float) -> None:
        self.now += timedelta(**delta)


@contextmanager
def raises(error: type[Exception]):
    try:
        yield
    except error:
        return
    raise AssertionError(f"{error.__name__} was not raised")


def make() -> tuple[LibraryService, FakeClock]:
    clock = FakeClock(datetime(2026, 1, 1, 10, 0))
    lib = LibraryService(clock)
    lib.add_book("111", "Dune", "Frank Herbert", copies=3)
    lib.add_book("222", "Emma", "Jane Austen", copies=1)
    lib.add_book("333", "Ulysses", "James Joyce", copies=1)
    lib.register_member("m1", "Asha")
    lib.register_member("m2", "Ravi")
    return lib, clock


def test_borrow_and_return_on_time():
    lib, clock = make()
    loan = lib.borrow("m1", "111")
    clock.advance(days=14)
    assert lib.return_copy(loan.copy_id) == 0


def test_loan_limit():
    lib, _ = make()
    for isbn in ("111", "222", "333"):
        lib.borrow("m1", isbn)
    with raises(LibraryError):
        lib.borrow("m1", "111")


def test_late_return_is_fined_per_full_day():
    lib, clock = make()
    loan = lib.borrow("m1", "111")
    clock.advance(days=17, hours=5)
    assert lib.return_copy(loan.copy_id) == 30


def test_fines_over_the_limit_block_borrowing():
    lib, clock = make()
    loan = lib.borrow("m1", "111")
    clock.advance(days=26)
    lib.return_copy(loan.copy_id)                           # 12 days late: 120
    with raises(LibraryError):
        lib.borrow("m1", "222")
    lib.pay_fine("m1", 120)
    assert lib.borrow("m1", "222").member_id == "m1"


def test_search_is_case_insensitive_on_title_and_author():
    lib, _ = make()
    assert [b.isbn for b in lib.search("JANE")] == ["222"]
    assert [b.isbn for b in lib.search("un")] == ["111"]


def test_returned_copy_is_held_for_the_first_reserver():
    lib, _ = make()
    loan = lib.borrow("m1", "222")
    assert lib.reserve("m2", "222") == 1
    lib.return_copy(loan.copy_id)
    with raises(LibraryError):
        lib.borrow("m1", "222")                             # held for m2, not m1
    assert lib.borrow("m2", "222").copy_id == loan.copy_id


def test_expired_hold_goes_back_on_the_shelf():
    lib, clock = make()
    loan = lib.borrow("m1", "222")
    lib.reserve("m2", "222")
    lib.return_copy(loan.copy_id)
    clock.advance(days=3)
    assert lib.borrow("m1", "222").copy_id == loan.copy_id
