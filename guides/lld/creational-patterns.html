Creational patterns

Creational patterns decide who builds an object and how much the caller has to know about its concrete class. In Python, first-class classes, keyword arguments, modules and dataclasses make most of them lighter than in Java, so the interview skill is knowing when the full pattern earns its place. This chapter covers Singleton (three implementations, thread safety, testing, and why it is often a smell), registry-based factories, Factory Method, Abstract Factory, Builder and Prototype, each with Python code and a class diagram, plus two simulations and a timed exercise.

After this chapter you can
  • Implement a Singleton three ways, make lazy creation thread-safe, and argue for passing one instance in instead
  • Replace an if/elif factory with a registry of callables that fails with a useful error for unknown keys
  • Tell Factory Method apart from a simple factory and a classmethod constructor, and know when passing a class is enough
  • Use Abstract Factory to switch a whole family of objects (production versus tests) without mixing its members
  • Choose between a dataclass with keyword defaults and a Builder, and write a builder that validates at build time
  • Copy configured objects safely with copy, deepcopy and dataclasses.replace

What creational patterns solve

Every S3Storage(...) written inside business code is a decision about a concrete class, made in the wrong place. Creational patterns move that decision somewhere deliberate: one function, one class, one start-up module. The caller then asks for what it needs (a storage for this URL, a validated query) and does not know which class answers.

Python changes the cost of every pattern in this family:

  • Classes are callables. cls() builds an object, and a class can be stored in a dict, passed as an argument or returned from a function. Many 'factories' are just a class handed to someone.
  • Keyword arguments with defaults remove the main reason for Builder in Java: constructors with ten optional parameters.
  • Modules are imported once per process, so a module-level object is already a single shared instance.
  • copy and dataclasses.replace give you Prototype for free.

So the interview question is rarely 'can you write the pattern?'. It is 'do you know when the pattern is worth more than the idiom?'. The flowchart is the short answer; each section gives the long one.

Name the creation problem first. Most branches end at a Python idiom that is lighter than the classic pattern.

When you say 'factory' in an LLD round, say which one: 'a function with a dict from scheme to class' (a simple factory), 'a method that subclasses override to choose the product' (Factory Method), or 'one object per environment that builds the storage and the queue together' (Abstract Factory). They answer different questions, and interviewers notice when the three are blurred.

Singleton, and why Python rarely needs the class

▶ Video lesson: Singleton: one instance, and why passing it in is better 4:23 · 7 scenes · narrated, pause anytime and explore

Intent: ensure a class has exactly one instance, and give everyone a way to reach it.

The need is real: one connection pool per process, one settings object, one metrics registry. But the pattern couples two promises, there is one and anyone can grab it, and the second one causes the trouble. Python offers several ways to build it. Know all of them, and know why the first one is usually right.

Four ways to have one instance

The idiomatic default. A module's top level runs once per process, and every later import returns the same module object from sys.modules. The Python FAQ recommends a config module for exactly this.

# config.py
import os
from dataclasses import dataclass

@dataclass(frozen=True)
class Settings:
    database_url: str
    pool_size: int = 10

settings = Settings(database_url=os.environ.get("DATABASE_URL", "sqlite:///dev.db"))

# orders.py
import config

def pool_size() -> int:
    return config.settings.pool_size    # the same object in every module

Overrides object creation so every call returns the stored instance. Gotcha: Python still calls __init__ on the returned object every time, so a second AppConfig(...) silently re-initialises the shared instance. A subclass created after the base also gets the base's instance.

class AppConfig:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self, path: str = "app.toml") -> None:
        self.path = path                  # runs on EVERY AppConfig(...) call

a = AppConfig("a.toml")
b = AppConfig("b.toml")
print(a is b, a.path)                     # True b.toml: the first caller's path is gone

A metaclass's __call__ runs before __new__ and __init__, so it can return the stored instance without re-initialising it. It is keyed by class, so a subclass gets its own instance, and the lock makes first creation thread-safe. Later constructor arguments are silently ignored, which is its own trap.

import threading

class SingletonMeta(type):
    _instances: dict[type, object] = {}
    _lock = threading.Lock()

    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:             # fast path once created
            with cls._lock:
                if cls not in cls._instances:     # check again: another thread may have won
                    cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

class AppConfig(metaclass=SingletonMeta):
    def __init__(self, path: str = "app.toml") -> None:
        self.path = path

a = AppConfig("a.toml")
b = AppConfig("b.toml")                           # the instance exists: arguments ignored
print(a is b, a.path)                             # True a.toml

A lazy getter. Short and resettable in tests, but the functools docs say the wrapped function can run more than once if a second thread calls it before the first call finishes. Use it only when building twice is harmless.

import os
from functools import cache

from config import Settings

@cache
def get_settings() -> Settings:
    return Settings(database_url=os.environ["DATABASE_URL"])

assert get_settings() is get_settings()
get_settings.cache_clear()                        # tests can reset it

Thread safety

Lazy creation is a check-then-act sequence: test whether the instance exists, then create it. Two threads can both pass the check before either assigns. The GIL does not prevent this, because a thread can be switched out between the two steps, and building a connection pool means network I/O, which releases the GIL. On the free-threaded build of Python 3.13+ the threads run in parallel and the window is wider. Watch the race, then switch to the locked version and to the module-level version.

Two threads, one 'single' connection pool

Each lane is a thread; the bottom lane shows the shared variable (or the module being imported). Compare how many pools exist at the end of each scenario.

Reach for the global, or receive the object

Hidden dependency

The signature says nothing about the pool. Tests share it, and swapping it means resetting class state.

class OrderService:
    def place(self, order) -> None:
        pool = ConnectionPool.instance()          # global state, found by surprise
        with pool.connection() as conn:
            conn.execute("INSERT INTO orders VALUES (?, ?)", (order.id, order.total))

class ReportJob:
    def run(self) -> None:
        pool = ConnectionPool.instance()          # the same hidden arrow again
        ...

# a test: ConnectionPool._instance = FakePool()  ... and remember to undo it

One instance by convention, passed in

Still exactly one pool, created at start-up. The dependency is visible and a test passes a fake.

import os

class OrderService:
    def __init__(self, pool: ConnectionPool) -> None:   # the dependency is in the signature
        self._pool = pool

    def place(self, order) -> None:
        with self._pool.connection() as conn:
            conn.execute("INSERT INTO orders VALUES (?, ?)", (order.id, order.total))

def main() -> None:
    pool = ConnectionPool(dsn=os.environ["DATABASE_URL"], size=10)   # built once
    orders = OrderService(pool)
    reports = ReportJob(pool)
    serve(orders, reports)

# a test: OrderService(FakePool())

Why Singleton is often a smell (click each)

Hidden dependencies

A class that calls AppConfig() inside a method depends on configuration, but its constructor does not say so. Readers and tests discover the dependency by surprise.

State leaks between tests

One test changes the shared instance and a later test fails, depending on the order the tests run in. Every singleton needs a reset hook, which is a sign the object should have been a parameter.

'Exactly one' rarely stays true

A primary database and a read replica, two tenants, a test config and a production config. A design that hard-codes one instance has to be unpicked when the second one arrives.

It does two jobs

The class does its real work and also controls its own lifetime, which is a single responsibility smell (SOLID principles). Let the composition root decide how many to create.

One per process, and copies escape

Each gunicorn worker or multiprocessing process has its own instance. Copying can escape too: copy.copy and pickle rebuild objects through __new__, which bypasses a metaclass's __call__, so copying a metaclass singleton produces a second instance.

When a single shared instance is fine

Process-wide things that are stateless or read-only: logging.getLogger(name) returns the same logger for the same name, a module of constants, a metrics registry. Even then, create it at start-up and pass it to the code you want to test.

Testing code that reads a module-level instance

# config.py
settings = Settings(database_url="postgresql://prod-db/orders")

# orders.py
import config                                # looks the object up at call time

def max_batch() -> int:
    return 500 if config.settings.database_url.startswith("postgresql") else 50

# test_orders.py
import config
import orders

def test_small_batches_on_sqlite(monkeypatch):
    monkeypatch.setattr(config, "settings", Settings(database_url="sqlite://"))
    assert orders.max_batch() == 50          # pytest restores config.settings afterwards
The patch works because orders reads config.settings when it runs. Had it written from config import settings, it would hold its own reference and the patch would miss it: patch the name where it is looked up.

Simple factories and registries: when a dict of callables is enough

▶ Video lesson: Factories and registries: a dict of callables 4:18 · 6 scenes · narrated, pause anytime and explore

Intent: put the 'which class?' decision in one function, so callers ask for a product by key and never name concrete classes. This simple factory is not one of the Gang of Four patterns, but it is what most code means by 'a factory', and in Python it is usually a dict.

The values in the dict can be any callable that returns a product: a class, a function, a functools.partial with preset arguments, a lambda. That is why Python rarely needs factory classes for this job. The standard library and popular packages work the same way: codecs.lookup("utf-8") finds a codec through registered search functions, logging.getLogger(name) returns one logger per name, and SQLAlchemy's create_engine("postgresql+psycopg://...") picks a dialect class from the URL.

A ladder of classes, or a dict of callables

if/elif factory

Every backend edits this function, and the module imports every backend (boto3 included) to name them.

def open_storage(url: str):
    scheme, _, location = url.partition("://")
    if scheme == "file":
        return FileStorage(location)
    elif scheme == "s3":
        return S3Storage(location)
    elif scheme == "memory":
        return MemoryStorage()
    raise ValueError(f"unknown scheme {scheme!r}")

Registry: a decorator fills the dict

A new backend is a new class with a decorator. Any callable can be a value.

from functools import partial
from typing import Callable

BACKENDS: dict[str, Callable] = {}

def backend(scheme: str):
    def register(factory):
        if scheme in BACKENDS:
            raise ValueError(f"scheme {scheme!r} is already registered")
        BACKENDS[scheme] = factory
        return factory
    return register

@backend("file")
class FileStorage:
    def __init__(self, location: str) -> None:
        self.root = location

@backend("s3")
class S3Storage:
    def __init__(self, location: str, region: str = "us-east-1") -> None:
        self.bucket, self.region = location, region

BACKENDS["s3-eu"] = partial(S3Storage, region="eu-west-1")   # a preset is a factory too

def open_storage(url: str):
    scheme, _, location = url.partition("://")
    try:
        factory = BACKENDS[scheme]
    except KeyError:
        raise ValueError(f"unknown scheme {scheme!r}; known: {sorted(BACKENDS)}") from None
    return factory(location)

print(open_storage("s3-eu://invoices").region)   # eu-west-1

A factory choosing a class from a registry

Follow each URL through the lookup. The first scenario builds a new object per call; the second caches one object per parsed config, the safe way to get 'one per key'.

When the dict is enough, and when it is not. A dict of callables covers 'pick one class by key'. It stops being enough in two cases. When the choice needs more than a key (several inputs, fallbacks, a capability check), write a small factory function with real logic and keep it as the only place that makes the choice. When other packages must add entries without your code importing them, use entry points for plugin discovery; Extensibility & modularity covers registries, plugin loading and the 'registered but never imported' bug.

Factory Method: let a subclass choose the product

Intent: define a method that creates an object, and let subclasses decide which class it creates. The base class holds an algorithm that needs a product, and the factory method is the one step subclasses override.

Two things are often confused with it. A simple factory picks a class from a key (the previous section). A classmethod constructor such as datetime.fromisoformat or dict.fromkeys is also called a factory method, but it is an alternative way to build its own class (OOP foundations in Python covers it). The Gang of Four Factory Method is about polymorphism: the base class calls self.create_writer() without knowing what it will get.

Factory Method: the export algorithm is fixed, the writer varies

import csv
import io
import json
from abc import ABC, abstractmethod

class Writer(ABC):
    @abstractmethod
    def write(self, rows: list[dict]) -> str: ...

class CsvWriter(Writer):
    def write(self, rows: list[dict]) -> str:
        buf = io.StringIO()
        out = csv.DictWriter(buf, fieldnames=list(rows[0]))
        out.writeheader()
        out.writerows(rows)
        return buf.getvalue()

class JsonWriter(Writer):
    def write(self, rows: list[dict]) -> str:
        return json.dumps(rows, indent=2)

class Exporter(ABC):
    def export(self, rows: list[dict]) -> str:      # the fixed algorithm
        if not rows:
            raise ValueError("nothing to export")
        writer = self.create_writer()                # the factory method
        return writer.write(rows)

    @abstractmethod
    def create_writer(self) -> Writer: ...

class CsvExporter(Exporter):
    def create_writer(self) -> Writer:
        return CsvWriter()

class JsonExporter(Exporter):
    def create_writer(self) -> Writer:
        return JsonWriter()

print(CsvExporter().export([{"id": 1, "total": 40}]))   # id,total / 1,40

Subclass to choose the product, or pass the class in

Factory Method (inheritance)

Fits when subclasses already customise several hooks (the framework style) and the product is one of them.

class Exporter(ABC):
    def export(self, rows):
        return self.create_writer().write(rows)

    @abstractmethod
    def create_writer(self) -> Writer: ...

class CsvExporter(Exporter):
    def create_writer(self) -> Writer:
        return CsvWriter()

CsvExporter().export(rows)

Pass a callable (composition)

Fits when the product is the only thing that varies: one class, chosen at construction, easy to fake in tests.

from typing import Callable

class Exporter:
    def __init__(self, make_writer: Callable[[], Writer] = CsvWriter) -> None:
        self._make_writer = make_writer      # a class is a callable that returns an instance

    def export(self, rows):
        return self._make_writer().write(rows)

Exporter().export(rows)                      # CSV by default
Exporter(JsonWriter).export(rows)            # no subclass needed

Python's own libraries use both styles. logging.Logger.makeRecord is documented as a factory method that subclasses override to create specialised LogRecord objects, while logging.setLogRecordFactory accepts a plain callable instead. collections.defaultdict(list) and dataclasses.field(default_factory=list) take the class as a callable, the 'pass the class' style. In an interview, show the inheritance version if asked for the pattern by name, then say that in Python you would usually pass the class.

Abstract Factory: families that must match

Intent: provide an interface for creating families of related objects without naming their concrete classes, so the members of one family are always used together.

The textbook example is a UI toolkit whose buttons and checkboxes must share a theme. In back-end code the family is usually the environment. In production the report pipeline writes to S3 and publishes a message to SQS; on a laptop and in tests it writes to a dict and appends to a list. Mixing members, S3 storage with an in-memory queue, is not an unusual configuration. It is a bug: the file is written and nobody is ever told.

Two independent decisions, or one family

Each member chosen on its own

One typo and production publishes to a list in memory. No error is raised anywhere.

import os

env = os.environ.get("APP_ENV", "dev")
storage = S3Storage("reports") if env == "prod" else DictStorage({})
queue = SqsQueue(QUEUE_URL) if env == "production" else ListQueue([])   # typo: prod gets ListQueue

ReportPipeline(storage, queue).run("2026-10-26", csv_bytes)
# The report lands in S3; the 'notification' lands in a Python list and is lost.

One decision picks the whole family

The environment selects a factory, and the factory builds every member, so members cannot be mixed.

import os

FAMILIES = {
    "prod": lambda: AwsFactory(bucket="reports", queue_url=QUEUE_URL),
    "dev": LocalFactory,
}

def infra_for(env: str) -> InfraFactory:
    try:
        return FAMILIES[env]()
    except KeyError:
        raise ValueError(f"unknown env {env!r}; known: {sorted(FAMILIES)}") from None

infra = infra_for(os.environ.get("APP_ENV", "dev"))
ReportPipeline(infra).run("2026-10-26", csv_bytes)   # storage and queue always match

Abstract Factory with Protocols

from typing import Protocol

class Storage(Protocol):
    def put(self, key: str, data: bytes) -> None: ...

class Queue(Protocol):
    def publish(self, message: str) -> None: ...

class InfraFactory(Protocol):
    def storage(self) -> Storage: ...
    def queue(self) -> Queue: ...

# ---- the AWS family
class S3Storage:
    def __init__(self, bucket: str) -> None:
        import boto3                                  # only the AWS family needs boto3
        self._s3, self._bucket = boto3.client("s3"), bucket

    def put(self, key: str, data: bytes) -> None:
        self._s3.put_object(Bucket=self._bucket, Key=key, Body=data)

class SqsQueue:
    def __init__(self, url: str) -> None:
        import boto3
        self._sqs, self._url = boto3.client("sqs"), url

    def publish(self, message: str) -> None:
        self._sqs.send_message(QueueUrl=self._url, MessageBody=message)

class AwsFactory:
    def __init__(self, bucket: str, queue_url: str) -> None:
        self._bucket, self._queue_url = bucket, queue_url

    def storage(self) -> Storage:
        return S3Storage(self._bucket)

    def queue(self) -> Queue:
        return SqsQueue(self._queue_url)

# ---- the local family
class DictStorage:
    def __init__(self, files: dict[str, bytes]) -> None:
        self._files = files

    def put(self, key: str, data: bytes) -> None:
        self._files[key] = data

class ListQueue:
    def __init__(self, messages: list[str]) -> None:
        self._messages = messages

    def publish(self, message: str) -> None:
        self._messages.append(message)

class LocalFactory:
    def __init__(self) -> None:
        self.files: dict[str, bytes] = {}             # exposed so tests can inspect them
        self.messages: list[str] = []

    def storage(self) -> Storage:
        return DictStorage(self.files)

    def queue(self) -> Queue:
        return ListQueue(self.messages)

# ---- the client
class ReportPipeline:
    def __init__(self, infra: InfraFactory) -> None:
        self._storage = infra.storage()
        self._queue = infra.queue()

    def run(self, day: str, csv_bytes: bytes) -> None:
        key = f"reports/{day}.csv"
        self._storage.put(key, csv_bytes)
        self._queue.publish(key)

local = LocalFactory()
ReportPipeline(local).run("2026-10-26", b"id,total\n1,40\n")
assert local.files == {"reports/2026-10-26.csv": b"id,total\n1,40\n"}
assert local.messages == ["reports/2026-10-26.csv"]
The test at the bottom runs the real pipeline against the local family: no AWS account, no mocks.

When it earns its place. Several collaborators switch together and a mix would be wrong: environments, cloud providers, database vendors (connection, SQL dialect and migration tool), UI themes. With a single product it is just a factory, so use the registry. Remember the cost from the diagram: a new product edits every factory, the same 'new operation' trade-off as in SOLID principles.

The lighter Python version is a frozen dataclass whose fields are callables, one instance per family:

@dataclass(frozen=True)
class Infra:
    storage: Callable[[], Storage]
    queue: Callable[[], Queue]

AWS = Infra(storage=lambda: S3Storage("reports"), queue=lambda: SqsQueue(QUEUE_URL))
LOCAL = Infra(storage=lambda: DictStorage({}), queue=lambda: ListQueue([]))

It gives the same guarantee (one value picks every member) with less ceremony. Use the class version when the families share set-up logic or need their own state, as LocalFactory does to expose its dict and list to tests.

Builder: many parts, assembled in steps

▶ Video lesson: Builder: assemble in steps, validate as a whole 3:48 · 6 scenes · narrated, pause anytime and explore

Intent: separate the construction of a complex object from its representation, so the object can be put together step by step and validated as a whole.

In Java, Builder mostly fixes telescoping constructors: one overload per combination of optional parameters. Python does not have that problem. Keyword arguments with defaults, kw_only=True dataclasses and __post_init__ validation give you named, optional, validated construction in a single call. A builder class that only stores fields and then calls the constructor is ceremony.

A Java builder ported to Python, or a dataclass

A builder that only sets fields

Forty lines to do what keyword arguments already do, and no validation anywhere.

class HttpRequest:
    def __init__(self, url, method, headers, timeout_s, retries, body):
        self.url, self.method, self.headers = url, method, headers
        self.timeout_s, self.retries, self.body = timeout_s, retries, body

class HttpRequestBuilder:
    def __init__(self):
        self._url = None
        self._method = "GET"
        self._headers = {}
        self._timeout_s = 10.0
        self._retries = 3
        self._body = None

    def url(self, value): self._url = value; return self
    def method(self, value): self._method = value; return self
    def header(self, k, v): self._headers[k] = v; return self
    def timeout(self, value): self._timeout_s = value; return self
    def body(self, value): self._body = value; return self

    def build(self):
        return HttpRequest(self._url, self._method, self._headers,
                           self._timeout_s, self._retries, self._body)

req = HttpRequestBuilder().url("https://api.example.com").method("POST").timeout(5).build()

Keyword defaults and __post_init__

Named, optional, immutable and validated, in one statement.

from dataclasses import dataclass, field

@dataclass(frozen=True, kw_only=True)
class HttpRequest:
    url: str
    method: str = "GET"
    headers: dict[str, str] = field(default_factory=dict)
    timeout_s: float = 10.0
    retries: int = 3
    body: bytes | None = None

    def __post_init__(self) -> None:
        if not self.url.startswith(("https://", "http://")):
            raise ValueError(f"not an http(s) URL: {self.url!r}")
        if self.method in ("GET", "HEAD") and self.body is not None:
            raise ValueError(f"{self.method} requests carry no body")

req = HttpRequest(url="https://api.example.com", method="POST", timeout_s=5, body=b"{}")

When a Builder earns its place:

  • The object is assembled in steps by a process: parsing a file, a multi-page form, clauses added to a query by different functions.
  • Validation spans several parts and can only run once everything is in: 'a LIMIT needs an ORDER BY', 'a PUT needs a body'.
  • You want the product immutable while the assembly is mutable.
  • The same steps build different representations: the Gang of Four director drives one sequence of calls into an HTML builder or a plain-text builder.

A SQL query builder hits the first three. There are two ways to write one.

Two kinds of query builder

Each call records a part and returns self, so calls chain. build() checks the combination and returns an immutable Query. Values travel as params behind ? placeholders, never inside the SQL text; table and column names must come from your code, never from user input. Trap: a half-built builder is shared state: base.limit(5) and base.limit(10) change the same object, and the last call wins.

from dataclasses import dataclass

@dataclass(frozen=True)
class Query:
    sql: str
    params: tuple

class QueryBuilder:
    def __init__(self, table: str) -> None:
        self._table = table
        self._columns: list[str] = ["*"]
        self._where: list[str] = []
        self._params: list = []
        self._order: str | None = None
        self._limit: int | None = None

    def select(self, *columns: str) -> "QueryBuilder":
        self._columns = list(columns)
        return self

    def where(self, clause: str, *params) -> "QueryBuilder":
        self._where.append(clause)
        self._params.extend(params)
        return self

    def order_by(self, column: str) -> "QueryBuilder":
        self._order = column
        return self

    def limit(self, n: int) -> "QueryBuilder":
        self._limit = n
        return self

    def build(self) -> Query:
        if self._limit is not None and self._order is None:
            raise ValueError("limit without order_by returns arbitrary rows")
        sql = f"SELECT {', '.join(self._columns)} FROM {self._table}"
        if self._where:
            sql += " WHERE " + " AND ".join(f"({w})" for w in self._where)
        if self._order:
            sql += f" ORDER BY {self._order}"
        if self._limit is not None:
            sql += f" LIMIT {int(self._limit)}"
        return Query(sql, tuple(self._params))

query = (QueryBuilder("orders")
         .select("id", "total")
         .where("status = ?", "paid")
         .where("total > ?", 500)
         .order_by("created_at DESC")
         .limit(20)
         .build())
print(query.sql)     # SELECT id, total FROM orders WHERE (status = ?) AND (total > ?) ORDER BY created_at DESC LIMIT 20
print(query.params)  # ('paid', 500)

Each call returns a new builder made with dataclasses.replace, so a partly built query can be shared and extended in two directions without one branch changing the other. SQLAlchemy's select() works this way.

from dataclasses import dataclass, replace

@dataclass(frozen=True)
class Select:
    table: str
    columns: tuple[str, ...] = ("*",)
    where: tuple[str, ...] = ()
    params: tuple = ()
    order: str | None = None
    limit_n: int | None = None

    def filter(self, clause: str, *params) -> "Select":
        return replace(self, where=self.where + (clause,), params=self.params + params)

    def order_by(self, column: str) -> "Select":
        return replace(self, order=column)

    def limit(self, n: int) -> "Select":
        return replace(self, limit_n=n)

    def sql(self) -> tuple[str, tuple]:
        if self.limit_n is not None and self.order is None:
            raise ValueError("limit without order_by returns arbitrary rows")
        text = f"SELECT {', '.join(self.columns)} FROM {self.table}"
        if self.where:
            text += " WHERE " + " AND ".join(f"({w})" for w in self.where)
        if self.order:
            text += f" ORDER BY {self.order}"
        if self.limit_n is not None:
            text += f" LIMIT {int(self.limit_n)}"
        return text, self.params

paid = Select("orders").filter("status = ?", "paid")    # a shared starting point
recent = paid.order_by("created_at DESC").limit(20)
big = paid.filter("total > ?", 500)
print(recent.sql())  # ('SELECT * FROM orders WHERE (status = ?) ORDER BY created_at DESC LIMIT 20', ('paid',))
print(big.sql())     # ('SELECT * FROM orders WHERE (status = ?) AND (total > ?)', ('paid', 500))
print(paid.sql())    # unchanged: ('SELECT * FROM orders WHERE (status = ?)', ('paid',))

Prototype: copy a configured object

Intent: create new objects by copying a configured prototype instead of building them from scratch. It pays off when construction is expensive (a parsed template, an object assembled from several queries) or when 'like that one, but with X' is the natural request.

Python ships the pattern. copy.copy makes a shallow copy: a new outer object that shares the objects inside it. copy.deepcopy copies everything reachable and handles cycles. dataclasses.replace(obj, **changes) builds a new instance with some fields changed, and it is shallow too. A class can customise both copies with __copy__ and __deepcopy__.

Shallow copies share, deep copies do not

import copy
from dataclasses import dataclass, field, replace

@dataclass
class EmailTemplate:
    subject: str
    body: str
    tags: list[str] = field(default_factory=list)

welcome = EmailTemplate("Welcome!", "Hi {name}", tags=["onboarding"])

shallow = copy.copy(welcome)
shallow.tags.append("promo")
print(welcome.tags)                    # ['onboarding', 'promo']: the list is shared

deep = copy.deepcopy(welcome)
deep.tags.append("vip")
print(welcome.tags, deep.tags)         # ['onboarding', 'promo'] ['onboarding', 'promo', 'vip']

variant = replace(welcome, subject="Welcome back!")
print(variant.tags is welcome.tags)    # True: replace() copies references, not the list

PROTOTYPES = {"welcome": welcome, "reset": EmailTemplate("Reset your password", "Use code {code}")}

def new_email(kind: str, **changes) -> EmailTemplate:
    return replace(copy.deepcopy(PROTOTYPES[kind]), **changes)   # deep copy first: nothing shared

mail = new_email("welcome", subject="Hello again")
mail.tags.append("winback")
print(PROTOTYPES["welcome"].tags)      # ['onboarding', 'promo']: the prototype is untouched

A prototype registry is a dict of configured originals. Callers always get a copy, never the original.

Shallow copies share mutable fields. If a prototype holds lists, dicts or other objects that callers will change, deep-copy it, or make those fields immutable: tuples and frozen dataclasses are safe to share.

Start-up code for a document archive

Write the start-up code for a service that archives JSON documents. It must run against S3 in production and entirely in memory in tests.

  • StorageConfig: immutable settings for a storage backend: scheme, location, region=None, timeout_s=5.0 and retries=3. Invalid settings fail at construction: timeout_s must be positive, retries between 0 and 10, and s3 needs a bucket. StorageConfig.from_url("s3://invoices?region=eu-west-1&retries=5") parses a URL.
  • open_storage(url): picks the backend class by URL scheme (memory, file, s3) from a registry. An unknown scheme raises ValueError that lists the known ones. A new backend is added with a decorator, with no edit to open_storage.
  • Env: an abstract factory with storage(), clock() and ids(). ProdEnv uses a storage URL, the real UTC clock and random UUIDs. FakeEnv uses memory storage, a fixed clock and sequential ids (id0001, id0002, ...). Members of different environments are never mixed.
  • Archiver(env): archive(doc) -> str stores the document as JSON under yyyy/mm/dd/<id>.json and returns the key. It never builds its own storage, clock or id generator.
  • No Singleton class anywhere: main() builds one ProdEnv and passes it in.

Design notes. StorageConfig does a Builder's job with a frozen dataclass: defaults, keyword-only fields and one __post_init__ that rejects bad combinations at construction. open_storage is a registry factory, so a backend is one decorated class. ProdEnv and FakeEnv are an Abstract Factory: each builds its own storage, clock and id source, so a test can never end up with the real clock and fake storage. There is exactly one ProdEnv per process because main() builds one, not because a class forbids a second; that keeps Archiver testable with FakeEnv. Say aloud in an interview that the S3 import is deferred on purpose and that the file backend checks for path escapes, because both are the kind of detail interviewers probe.

import itertools
import json
import tempfile
import uuid
from dataclasses import dataclass
from datetime import datetime, timezone
from pathlib import Path
from typing import Callable, Protocol
from urllib.parse import parse_qs, urlsplit


class Storage(Protocol):
    def put(self, key: str, data: bytes) -> None: ...
    def get(self, key: str) -> bytes: ...


# ---- the Builder's job, done by a frozen dataclass and a classmethod ------------
@dataclass(frozen=True, kw_only=True)
class StorageConfig:
    scheme: str
    location: str = ""                     # the bucket for s3, a directory for file
    region: str | None = None
    timeout_s: float = 5.0
    retries: int = 3

    def __post_init__(self) -> None:
        if self.timeout_s <= 0:
            raise ValueError("timeout_s must be positive")
        if not 0 <= self.retries <= 10:
            raise ValueError("retries must be between 0 and 10")
        if self.scheme == "s3" and not self.location:
            raise ValueError("s3 needs a bucket: s3://<bucket>")

    @classmethod
    def from_url(cls, url: str) -> "StorageConfig":
        parts = urlsplit(url)
        query = {key: values[-1] for key, values in parse_qs(parts.query).items()}
        options: dict = {}
        if "region" in query:
            options["region"] = query["region"]
        if "timeout_s" in query:
            options["timeout_s"] = float(query["timeout_s"])
        if "retries" in query:
            options["retries"] = int(query["retries"])
        return cls(scheme=parts.scheme, location=parts.netloc + parts.path, **options)


# ---- registry factory ----------------------------------------------------------
BACKENDS: dict[str, Callable[[StorageConfig], Storage]] = {}


def backend(scheme: str):
    def register(factory):
        if scheme in BACKENDS:
            raise ValueError(f"scheme {scheme!r} is already registered")
        BACKENDS[scheme] = factory
        return factory
    return register


def open_storage(url: str) -> Storage:
    config = StorageConfig.from_url(url)
    try:
        factory = BACKENDS[config.scheme]
    except KeyError:
        raise ValueError(f"unknown scheme {config.scheme!r}; known: {sorted(BACKENDS)}") from None
    return factory(config)


@backend("memory")
class MemoryStorage:
    def __init__(self, config: StorageConfig) -> None:
        self.blobs: dict[str, bytes] = {}

    def put(self, key: str, data: bytes) -> None:
        self.blobs[key] = data

    def get(self, key: str) -> bytes:
        return self.blobs[key]


@backend("file")
class FileStorage:
    def __init__(self, config: StorageConfig) -> None:
        self._root = Path(config.location or ".").resolve()

    def _path(self, key: str) -> Path:
        path = (self._root / key).resolve()
        if not path.is_relative_to(self._root):           # refuse '../secrets.txt'
            raise ValueError(f"key escapes the storage root: {key!r}")
        return path

    def put(self, key: str, data: bytes) -> None:
        path = self._path(key)
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_bytes(data)

    def get(self, key: str) -> bytes:
        return self._path(key).read_bytes()


@backend("s3")
class S3Storage:
    def __init__(self, config: StorageConfig) -> None:
        import boto3                                      # imported only when an s3 URL is opened
        from botocore.config import Config
        self._bucket = config.location
        self._s3 = boto3.client(
            "s3", region_name=config.region,
            config=Config(connect_timeout=config.timeout_s, read_timeout=config.timeout_s,
                          retries={"max_attempts": config.retries}))

    def put(self, key: str, data: bytes) -> None:
        self._s3.put_object(Bucket=self._bucket, Key=key, Body=data)

    def get(self, key: str) -> bytes:
        return self._s3.get_object(Bucket=self._bucket, Key=key)["Body"].read()


# ---- abstract factory: one object per environment -------------------------------
class Env(Protocol):
    def storage(self) -> Storage: ...
    def clock(self) -> Callable[[], datetime]: ...
    def ids(self) -> Callable[[], str]: ...


class ProdEnv:
    def __init__(self, storage_url: str) -> None:
        self._storage = open_storage(storage_url)         # built once, shared by everything using this env

    def storage(self) -> Storage:
        return self._storage

    def clock(self) -> Callable[[], datetime]:
        return lambda: datetime.now(timezone.utc)

    def ids(self) -> Callable[[], str]:
        return lambda: uuid.uuid4().hex


class FakeEnv:
    def __init__(self, now: datetime) -> None:
        self._storage = open_storage("memory://")
        self._now = now
        self._counter = itertools.count(1)

    def storage(self) -> Storage:
        return self._storage

    def clock(self) -> Callable[[], datetime]:
        return lambda: self._now

    def ids(self) -> Callable[[], str]:
        return lambda: f"id{next(self._counter):04d}"


class Archiver:
    def __init__(self, env: Env) -> None:                 # everything arrives through the family
        self._storage = env.storage()
        self._now = env.clock()
        self._new_id = env.ids()

    def archive(self, doc: dict) -> str:
        key = f"{self._now():%Y/%m/%d}/{self._new_id()}.json"
        self._storage.put(key, json.dumps(doc, sort_keys=True).encode())
        return key


def main() -> None:                                       # the composition root: no Singleton class
    env = ProdEnv("s3://invoices?region=eu-west-1")
    archiver = Archiver(env)
    print(archiver.archive({"invoice": 42}))
