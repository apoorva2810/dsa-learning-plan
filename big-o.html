Big-O in plain words

Big-O describes how the running time (or memory) of an algorithm grows as the input grows. It ignores constant factors and small inputs; it answers one question: if I double the input, roughly how much more work is it?

Reading the constraints before you design the algorithm tells you which complexity is expected.

How to count

  1. Sequential steps add: a loop of n then a loop of n is 2n → O(n).
  2. Nested steps multiply: a loop of n with an inner loop of n is n·n → O(n²).
  3. Halving means log: a loop whose variable halves each time runs about log₂ n times.
  4. Drop constants and smaller terms: 3n² + 10n + 7 → O(n²).
  5. Amortised: an inner while that pops from a stack looks like O(n²), but if each element is pushed once and popped at most once, the total is O(n). Count how often each element can be touched.
  6. Recursion: count calls × work per call. T(n) = 2T(n/2) + n (merge sort) is O(n log n); T(n) = T(n−1) + T(n−2) (naive Fibonacci) is exponential.

Space

Space complexity counts extra memory beyond the input. A hash map over n items is O(n). Recursion uses the call stack: depth h costs O(h), which is O(log n) for a balanced tree and O(n) for a linked list or skewed tree. "In place" means O(1) extra space, though a few variables are allowed.

Common trade-offs you will see in the 250

  • Time for space: Two Sum goes from O(n²)/O(1) to O(n)/O(n) by remembering what you saw.
  • Sort first: many O(n²) problems become O(n log n) once sorted (two pointers, intervals, greedy).
  • Precompute: prefix sums turn repeated O(n) range sums into O(1) queries after O(n) setup.
  • Memoise: exponential recursion becomes polynomial when overlapping subproblems are stored (DP).
  • Binary search on the answer: when "is x feasible?" is monotonic, O(n log(range)) replaces trying every x.
