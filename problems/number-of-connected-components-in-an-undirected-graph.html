Number of Connected Components in an Undirected Graph Medium

LeetCode #323 ↗
Status

Count how many separate pieces a set of undirected edges splits n nodes into.

Problem

You are given n nodes labelled 0 to n - 1 and a list edges, where edges[i] = [a, b] is an undirected edge between a and b.

Return the number of connected components: groups of nodes in which every node can reach every other node through edges, and no edge leads outside the group. A node with no edges is a component on its own.

  • There are no self-loops and no edge is listed twice.

Examples

Example 1
Input: n = 5, edges = [[0, 1], [1, 2], [3, 4]]
Output: 2
{0, 1, 2} and {3, 4}.
Example 2
Input: n = 5, edges = [[0, 1], [1, 2], [2, 3], [3, 4]]
Output: 1
A single chain through all five nodes.
Example 3
Input: n = 4, edges = []
Output: 4
With no edges every node is alone.

Constraints

  • 1 <= n <= 2000
  • 0 <= len(edges) <= 5000
  • 0 <= a, b < n and a != b
  • no repeated edges

Think first try before reading the solution

Start a search (DFS or BFS) from some node. Everything it reaches belongs to one component. What should happen next?
Loop over all nodes; every time you meet a node that no earlier search reached, you have found a new component. Count those starts.
Without building an adjacency list: start with n groups and merge the two groups of every edge with union-find. Each merge of two different groups lowers the count by one.

Key idea

Begin with n components, one per node. Each edge either joins two different components into one (the count drops by 1) or connects two nodes that are already in the same component (nothing changes). The answer is n minus the number of edges of the first kind.

Union-find answers "are these two already in the same component?" quickly. Every group keeps a parent pointer chain that ends at a root, the group's representative. find(x) follows the pointers to the root, and merging two groups is one assignment: point one root at the other. Path halving and union by size keep those chains short, so the whole edge list is processed in practically linear time.

A DFS or BFS gives the same answer: count how many times you start a fresh search from an unvisited node.

Approaches from the obvious one to the one you want in an interview

Give every node a label equal to its own number. Then sweep over all edges again and again: whenever the two ends of an edge carry different labels, both take the smaller one. When a full sweep changes nothing, every component is labelled with its smallest node number, so the number of distinct labels is the answer.

It works, but a label can creep along only a few edges per sweep. A long chain listed in an unlucky order needs about n sweeps over all E edges: O(V · E).

Dry run

  1. n = 5, edges [[0, 1], [1, 2], [3, 4]], labels [0, 1, 2, 3, 4]
  2. Sweep 1: 0–1 → both 0; 1–2 → both 0; 3–4 → both 3 → labels [0, 0, 0, 3, 3]
  3. Sweep 2 changes nothing → distinct labels {0, 3} → 2 components

Python

class Solution:
    def countComponents(self, n: int, edges: List[List[int]]) -> int:
        label = list(range(n))                     # every node starts in its own group
        changed = True
        while changed:                              # keep sweeping until the labels settle
            changed = False
            for a, b in edges:
                low = min(label[a], label[b])
                if label[a] != low or label[b] != low:
                    label[a] = label[b] = low       # both ends adopt the smaller label
                    changed = True
        return len(set(label))
Time O(V · E)Space O(V)

Up to about V sweeps, each reading all E edges.

When to use: Never in practice; it shows why you want a structure that merges whole groups at once.

Build an adjacency list. Walk through the nodes 0 .. n - 1; whenever a node has not been visited yet, it starts a new component: add 1 to the count and run a search from it that marks everything reachable. Later nodes in the same component are already marked, so they are skipped.

Each node is marked once and each edge is looked at twice (once from each end): O(V + E). The trade-off against union-find: DFS needs the whole edge list up front to build the adjacency list, while union-find can take edges one at a time.

Dry run

  1. n = 5, edges [[0, 1], [1, 2], [3, 4]]
  2. Node 0 unvisited → count 1, search marks 0, 1, 2
  3. Nodes 1 and 2 already marked → skip. Node 3 unvisited → count 2, search marks 3, 4
  4. Node 4 already marked → answer 2

Python

class Solution:
    def countComponents(self, n: int, edges: List[List[int]]) -> int:
        graph = {node: [] for node in range(n)}
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)
        seen = set()
        components = 0
        for start in range(n):
            if start in seen:
                continue
            components += 1                        # nobody reached `start`: a new component
            seen.add(start)
            stack = [start]
            while stack:                           # mark everything reachable from start
                node = stack.pop()
                for nxt in graph[node]:
                    if nxt not in seen:
                        seen.add(nxt)
                        stack.append(nxt)
        return components
Time O(V + E)Space O(V + E)

Every node is pushed once; every edge is read from both ends.

When to use: When you already have (or need) an adjacency list, or the question asks for the members of each component.

Keep parent[i] pointers that lead from every node to its group's root. Start with components = n. For each edge a–b:

  • find(a) and find(b) climb to the two roots;
  • if the roots are equal, a and b are already connected: skip the edge;
  • otherwise point one root at the other (merge) and do components -= 1.

Path halving (each node on the climb is pointed at its grandparent) and union by size (the smaller group goes under the larger) keep every chain short, so each find is amortised O(α(n)): averaged over all calls it costs a small constant, since α (the inverse Ackermann function) stays below 5 for any input you will ever see.

Dry run

  1. n = 5, edges [[0, 1], [1, 2], [3, 4]], parent [0, 1, 2, 3, 4], components 5
  2. 0–1: roots 0, 1 differ → parent[1] = 0 → components 4
  3. 1–2: find(1) = 0, find(2) = 2 → the group of 0 is larger → parent[2] = 0 → components 3
  4. 3–4: roots 3, 4 differ → parent[4] = 3 → components 2

Python

class Solution:
    def countComponents(self, n: int, edges: List[List[int]]) -> int:
        parent = list(range(n))                    # every node is its own root
        size = [1] * n
        components = n

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]      # path halving keeps the chains short
                x = parent[x]
            return x

        for a, b in edges:
            root_a, root_b = find(a), find(b)
            if root_a == root_b:                   # already in the same component
                continue
            if size[root_a] < size[root_b]:
                root_a, root_b = root_b, root_a
            parent[root_b] = root_a                # merge: smaller group under the larger
            size[root_a] += size[root_b]
            components -= 1
        return components
Time O(V + E · α(V))Space O(V)

One near-constant find/union per edge; only the parent and size arrays are stored.

When to use: The usual answer: short, no adjacency list, and it works when edges arrive one by one.

Common mistakes

  • Returning the number of successful merges instead of n - merges. Start the counter at n and subtract.
  • Decrementing the counter for every edge. An edge between nodes that are already connected (a cycle edge) must not change the count; check find(a) != find(b) first.
  • Comparing parents (parent[a] == parent[b]) instead of roots. Two nodes can be in one group while their direct parents differ; always compare find(a) with find(b).
  • Building the adjacency list only from the edges and then looping over its keys: nodes without edges never appear and are not counted. Loop over range(n).

Python notes

  • parent = list(range(n)) makes every node the root of its own group in one line.
  • Writing find as a while loop (instead of recursion) avoids Python's recursion limit on long parent chains.
  • len({find(v) for v in range(n)}) is another way to count groups at the end: one root per component.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Number of Provinces LC 547 — the same count, but the input is an n × n adjacency matrix: an edge exists where M[i][j] == 1.
  • Number of Islands LC 200 — the graph is a grid: cells are nodes and the four neighbours are the edges. Same 'count the starts' idea.
  • Graph Valid Tree LC 261 — require exactly one component and no cycle: check n - 1 edges and a count of 1.
  • Number of Operations to Make Network Connected LC 1319 — the answer is components - 1 cables to move, provided there are at least n - 1 cables in total.
  • Accounts Merge LC 721 — union-find on strings: join every email in an account, then group emails by their root.
  • What if edges keep arriving and you must report the count after each one? — union-find already handles this online in near O(1) per edge. Deleting edges is much harder: it needs offline tricks or a different structure.
