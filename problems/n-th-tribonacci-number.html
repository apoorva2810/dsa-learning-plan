N-th Tribonacci Number Easy 250

LeetCode #1137 ↗
Status

Return the n-th term of the sequence that starts 0, 1, 1 and then adds the previous three terms.

Problem

The Tribonacci sequence starts with T(0) = 0, T(1) = 1, T(2) = 1. Every later term is the sum of the three terms before it:

T(n) = T(n - 1) + T(n - 2) + T(n - 3) for n >= 3.

So the sequence runs 0, 1, 1, 2, 4, 7, 13, 24, 44, 81, ... Given n, return T(n).

  • n is between 0 and 37, and every answer fits in a 32-bit integer.

Examples

Example 1
Input: n = 4
Output: 4
T(3) = 0 + 1 + 1 = 2, then T(4) = 1 + 1 + 2 = 4.
Example 2
Input: n = 6
Output: 13
The terms are 0, 1, 1, 2, 4, 7, 13.
Example 3
Input: n = 25
Output: 1389537

Constraints

  • 0 <= n <= 37
  • the answer fits in a 32-bit integer

Think first try before reading the solution

The definition is already a formula: T(n) is the sum of the three terms before it. Write it as a function that calls itself. Which inputs stop the recursion?
Plain recursion asks for T(n - 1), T(n - 2) and T(n - 3), and each of those asks for overlapping terms again. T(n) ends up computed roughly 1.84ⁿ times in total. Compute every term once, from T(0) upward.
While filling the terms in order you only ever read the last three. Keep three variables and shift them forward one position per loop iteration.

Key idea

This is Climbing Stairs with one more term. The recurrence is given to you, so the whole problem is about not recomputing it. T(n) needs T(n - 1), T(n - 2) and T(n - 3); T(n - 1) needs T(n - 2) and T(n - 3) again, and so on. Plain recursion redoes the same small terms a huge number of times: about 2.7 million calls for n = 25, and billions for n = 37.

Dynamic programming fixes this by computing each term exactly once. The subproblem is "the value of term i"; the recurrence is T(i) = T(i - 1) + T(i - 2) + T(i - 3); the table order is i = 3, 4, ..., n, because every term reads only terms to its left, which are already final. That gives O(n) time with a list of n + 1 entries.

Then look at what the loop reads: only the last three cells. Everything older is dead. Replace the list by three variables that slide forward, and the memory becomes O(1). The same recipe (recursion → table → rolling variables) works for every "sum of the previous k terms" problem.

Approaches from the obvious one to the one you want in an interview

Translate the definition directly: T(n) = T(n - 1) + T(n - 2) + T(n - 3), stopping at the three given terms. It is correct and it is the shortest possible code.

It is also exponential. Every call makes three more, and the same arguments come back again and again: T(6) computes T(3) four times and T(2) seven times. The number of calls grows by a factor of about 1.84 per extra term: 25 calls for n = 6, about 2.7 million for n = 25, and about 6 billion for n = 37.

One line fixes it: put @cache on the function (memoisation: store each result the first time, look it up afterwards), and every T(k) is computed once. The table and rolling-variable approaches below reach the same O(n) without recursion.

Dry run

  1. T(5) → needs T(4), T(3), T(2)
  2. T(4) → T(3) + T(2) + T(1); T(3) → T(2) + T(1) + T(0) = 1 + 1 + 0 = 2; so T(4) = 2 + 1 + 1 = 4
  3. back in T(5): T(3) is computed again from scratch → 2, then T(2) = 1
  4. T(5) = 4 + 2 + 1 = 7, after 13 calls for 6 different arguments

Python

class Solution:
    def tribonacci(self, n: int) -> int:
        if n == 0:                      # the three given terms stop the recursion
            return 0
        if n <= 2:
            return 1
        # the definition, taken literally: the sum of the three previous terms
        return self.tribonacci(n - 1) + self.tribonacci(n - 2) + self.tribonacci(n - 3)
Time O(1.84ⁿ)Space O(n)

Each call branches in three and repeated arguments are recomputed; the stack is at most n deep.

When to use: Only to confirm the recurrence. It passes the tests here (slowly for n = 25) and is hopeless for n = 37.

Watch it run

Compute the terms in the order they are defined. Tabulation means filling a list dp where dp[i] = T(i): start with dp[0..2] = 0, 1, 1, then for i = 3..n set dp[i] = dp[i - 1] + dp[i - 2] + dp[i - 3].

Left to right is the right order because each cell reads only cells to its left, which are already final. Each term costs one addition, so the whole table is O(n). There is no recursion, so no recursion limit and no repeated work.

Dry run

  1. n = 6: dp = [0, 1, 1, ?, ?, ?, ?]
  2. dp[3] = 1 + 1 + 0 = 2
  3. dp[4] = 2 + 1 + 1 = 4, dp[5] = 4 + 2 + 1 = 7, dp[6] = 7 + 4 + 2 = 13
  4. answer dp[6] = 13

Python

class Solution:
    def tribonacci(self, n: int) -> int:
        if n == 0:
            return 0
        dp = [0] * (n + 1)              # dp[i] = T(i); terms are numbered 0..n, so n + 1 slots
        dp[0], dp[1] = 0, 1
        if n >= 2:
            dp[2] = 1
        for i in range(3, n + 1):       # left to right: the three cells read are already final
            dp[i] = dp[i - 1] + dp[i - 2] + dp[i - 3]
        return dp[n]
Time O(n)Space O(n)

One pass over n + 1 cells, two additions each.

When to use: The standard way to write a DP without recursion; start here when the fill order is not yet clear to you.

Watch it run

Look at what the table loop reads: cell i needs only cells i - 1, i - 2 and i - 3. Older cells are never read again, so storing them is waste. Keep three variables, three_back, two_back, one_back, and shift them one position per iteration: the new one_back is the sum, the old one_back becomes two_back, the old two_back becomes three_back.

This is the space optimisation step of the DP recipe: same recurrence, same O(n) time, O(1) memory. The only care point is n < 3, where the loop does not run and the answer must come straight from the base values.

Dry run

  1. three_back, two_back, one_back = 0, 1, 1 (terms 0, 1, 2)
  2. term 3: new = 0 + 1 + 1 = 2 → (1, 1, 2)
  3. term 4: new = 1 + 1 + 2 = 4 → (1, 2, 4); term 5: → (2, 4, 7); term 6: → (4, 7, 13)
  4. answer one_back = 13

Python

class Solution:
    def tribonacci(self, n: int) -> int:
        if n == 0:                      # the loop below never runs for n < 3, so answer the base terms directly
            return 0
        if n <= 2:
            return 1
        three_back, two_back, one_back = 0, 1, 1   # T(i-3), T(i-2), T(i-1), starting with T(0), T(1), T(2)
        for _ in range(3, n + 1):
            # one tuple assignment: every value on the right is the old one
            three_back, two_back, one_back = two_back, one_back, three_back + two_back + one_back
        return one_back
Time O(n)Space O(1)

One pass, three integers of state.

When to use: The interview answer: present it as the table with everything but the last three cells thrown away.

Common mistakes

  • Starting the sequence like Fibonacci with 1, 1, 2. Tribonacci starts 0, 1, 1, so T(0) = 0; forgetting the zero shifts every answer.
  • Rolling variables without handling n = 0. If the loop runs for i = 3..n and you return the latest variable, n = 0 returns T(2) = 1 instead of 0. Return early for n < 3 or read the base values directly.
  • Shifting the three variables in separate statements: three_back = two_back first, and the sum computed afterwards already uses the new three_back. Use one tuple assignment so every right-hand value is the old one.
  • Running the plain recursion for large n. The call count grows by about 1.84× per extra term; n = 37 needs several billion calls. Add @cache or loop bottom-up.
  • Allocating dp = [0] * n and writing dp[n]: the terms are numbered 0 to n, so the list needs n + 1 slots.

Python notes

  • @cache (from functools, pre-imported) turns the plain recursion into an O(n) solution with one line: each T(k) is computed once and then looked up. Define the helper inside the method so every call starts fresh.
  • Python's default recursion limit is 1000 frames; the memoised recursion goes n deep, fine for n <= 37.
  • three_back, two_back, one_back = two_back, one_back, three_back + two_back + one_back evaluates the whole right side before assigning, which is what makes the shift correct in one line.
  • Python integers never overflow, so no modulo or 64-bit worries here; in other languages T(37) = 2082876103 still fits a signed 32-bit integer, but T(38) does not.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Fibonacci Number LC 509 — the two-term version: F(n) = F(n - 1) + F(n - 2) with F(0) = 0, F(1) = 1; two rolling variables instead of three.
  • Climbing Stairs LC 70 — the same two-term recurrence in disguise, but the base cases are 1, 1 because they count ways, not sequence terms.
  • Combination Sum IV LC 377 — with nums = [1, 2, 3] the number of ordered sums for each target is exactly this recurrence with base cases 1, 1, 2; in general the step sizes come from a list, so the table cannot shrink to three variables.
  • Domino and Tromino Tiling LC 790 — another three-term recurrence, dp[n] = 2·dp[n - 1] + dp[n - 3], taken modulo 10^9 + 7; the work is finding the recurrence, the code is this problem.
  • What if n is 10^18? — even O(n) is too slow. Write the step as a 3×3 matrix multiplying the vector (T(i), T(i-1), T(i-2)), and raise the matrix to the n-th power by repeated squaring in O(log n) multiplications (modulo a prime, since the values overflow).
