Best Time to Buy and Sell Stock II Medium 250

LeetCode #122 ↗
Status

With unlimited buy-and-sell trades but one share at a time, collect the most profit from a price list.

Problem

You are given a list prices where prices[i] is the price of one share on day i.

You may buy and sell as many times as you like, but you can hold at most one share at a time: you must sell the share you own before you buy again. Buying and selling on the same day is allowed.

Return the maximum total profit you can make. If no trade is profitable, return 0.

Examples

Example 1
Input: prices = [7, 1, 5, 3, 6, 4]
Output: 7
Buy on day 1 (price 1) and sell on day 2 (price 5): +4. Buy on day 3 (price 3) and sell on day 4 (price 6): +3. Total 7.
Example 2
Input: prices = [1, 2, 3, 4, 5]
Output: 4
Buy on day 0 and sell on day 4 for 4, or collect each daily rise of 1 four times. Same total.
Example 3
Input: prices = [7, 6, 4, 3, 1]
Output: 0
The price only falls, so the best plan is to never buy.

Constraints

  • 1 <= len(prices) <= 3 * 10^4
  • 0 <= prices[i] <= 10^4

Think first try before reading the solution

You may trade as often as you like, but you hold one share at a time. Does it ever help to hold a share through a day on which the price drops?
The profit of one trade from day i to day j is prices[j] - prices[i], which equals the sum of the daily changes between those days. So every trade is a sum of daily changes. Which daily changes do you want?
Add up every positive difference prices[i] - prices[i - 1]. That is the same as buying at every valley and selling at every peak, with no index juggling.

Key idea

Any single trade, buy on day i and sell on day j, earns prices[j] - prices[i]. That number is the sum of the day-to-day changes from i + 1 to j: the price climbs and dips add up to the total move. So a trade that spans a dip is the same as two trades with the dip skipped, except that the two trades also skip the loss.

Because we may trade as often as we like, we can collect every rise and skip every fall: whenever prices[i] > prices[i - 1], pretend we bought yesterday and sold today, and add the difference. Adjacent rises chain into one longer trade (buy at the valley, sell at the peak), and a fall is a day we simply do not hold a share. One pass, one running total.

The same answer comes out of a more general tool, a two-state dynamic program ("best profit while holding" and "best profit while not holding"). It costs the same O(n) and is worth knowing because it still works when the greedy breaks: with a cooldown day, a transaction fee or a limit on the number of trades.

Approaches from the obvious one to the one you want in an interview

On each day you either do nothing, or you act: buy if you hold nothing, sell if you hold a share. Explore both options recursively and keep the best total.

It is correct and it captures the rule "one share at a time" directly in the holding flag, but every day doubles the number of paths: 2^n in total. Twenty days is a million paths, forty days a trillion. Almost all of those paths re-solve the same question ("best profit from day d while holding / not holding"), which is what the next approach fixes.

Dry run

  1. prices = [7, 1, 5, 3, 6, 4]
  2. day 0: skip, or buy at 7 → two branches
  3. each branch splits again on day 1, and so on: 2^6 = 64 complete paths
  4. the best path: skip 7, buy 1, sell 5, buy 3, sell 6, skip 4 → 7

Python

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        n = len(prices)

        def best(day: int, holding: bool) -> int:
            if day == n:
                return 0                          # no days left; an unsold share earns nothing more
            skip = best(day + 1, holding)         # do nothing today
            if holding:
                act = prices[day] + best(day + 1, False)    # sell today
            else:
                act = -prices[day] + best(day + 1, True)    # buy today
            return max(skip, act)

        return best(0, False)
Time O(2^n)Space O(n)

Two branches per day without memoisation; the recursion is n calls deep.

When to use: Only to see the structure of the problem; it is too slow beyond about 20 days.

The recursion above has only 2 · n distinct questions: for each day, "best profit so far while not holding" (cash) and "best profit so far while holding" (hold). Each day's pair depends only on the previous day's pair:

  • cash = max(cash, hold + price): keep not holding, or sell today;
  • hold = max(hold, cash - price): keep the share, or buy today with yesterday's cash.

Start with cash = 0, hold = -prices[0], sweep once, and answer cash (ending with a share is never better). O(n) time and two variables. It is not simpler than the greedy, but it is the general pattern: the cooldown, transaction-fee and limited-trades variants are the same loop with an extra state or term.

Dry run

  1. prices = [7, 1, 5, 3, 6, 4], cash = 0, hold = −7
  2. day 1 (1): cash = max(0, −7 + 1) = 0, hold = max(−7, 0 − 1) = −1
  3. day 2 (5): cash = max(0, −1 + 5) = 4, hold = max(−1, 0 − 5) = −1
  4. day 3 (3): cash = 4, hold = max(−1, 4 − 3) = 1
  5. day 4 (6): cash = max(4, 1 + 6) = 7, hold = 1; day 5 (4): cash = 7 → answer 7

Python

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        cash = 0                          # best profit so far with no share in hand
        hold = -prices[0]                 # best profit so far while holding a share (bought day 0)
        for price in prices[1:]:
            cash, hold = (max(cash, hold + price),    # keep waiting, or sell today
                          max(hold, cash - price))    # keep the share, or buy today
        return cash                       # finishing with a share in hand never helps
Time O(n)Space O(1)

One pass; the tuple assignment updates both states from the previous day's values.

When to use: When the rules have extra constraints (cooldown, fee, limited trades): the same loop extends.

Watch it run

Every trade's profit is a sum of daily price changes, and we may trade as often as we like. So take every positive daily change and none of the negative ones: whenever today's price is above yesterday's, add the difference.

Consecutive rising days add up to exactly one trade from the valley to the peak (the sales and purchases in between cancel), and a falling day is a day we do not own a share. There is nothing to optimise: skipping a rise can only lose money, and holding through a fall can only lose money.

Dry run

  1. prices = [7, 1, 5, 3, 6, 4], profit = 0
  2. 7 → 1: fall, skip. 1 → 5: +4, profit 4
  3. 5 → 3: fall, skip. 3 → 6: +3, profit 7
  4. 6 → 4: fall, skip. Answer 7

Python

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        profit = 0
        for i in range(1, len(prices)):
            if prices[i] > prices[i - 1]:              # a rise: buy yesterday, sell today
                profit += prices[i] - prices[i - 1]
        return profit                                  # falls are simply skipped
Time O(n)Space O(1)

One comparison and at most one addition per day.

When to use: The interview answer for unlimited trades with no fees or cooldown.

Common mistakes

  • Solving the one-transaction version instead: [7, 1, 5, 3, 6, 4] gives 5 with a single trade but 7 with two. Read the rules of each stock problem carefully.
  • Hunting for explicit valleys and peaks with index arithmetic: it works, but the ends of the list and flat stretches ([2, 2, 2]) breed off-by-one bugs. Summing positive differences is equivalent and has no special cases.
  • Rejecting the greedy because it "sells and buys on the same day": that pair nets 0, so it is the same as holding through the day. The problem allows it anyway.
  • Applying max(0, ...) once to the total instead of skipping each negative day: the total is never negative, but a negative day must not be added.
  • Writing the brute-force recursion without a memo and running it on a long list: two choices per day gives 2^n paths; 40 days is already a trillion.
  • Letting a trailing rise go: [1, 2] has profit 1, so the loop must run through the last day.

Python notes

  • sum(max(0, b - a) for a, b in zip(prices, prices[1:])) is the whole greedy in one expression; the loop version is easier to explain.
  • zip(prices, prices[1:]) pairs each day with the next one without index arithmetic.
  • In the DP, update cash and hold from the previous day's values; assigning both in one tuple statement (cash, hold = ..., ...) does that automatically.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Best Time to Buy and Sell Stock LC 121 — only one trade is allowed: the greedy breaks and you track the lowest price seen so far instead.
  • Best Time to Buy and Sell Stock with Cooldown LC 309 — a day of cooldown after each sale: the greedy breaks; the two-state DP grows a third state (just sold, cannot buy).
  • Best Time to Buy and Sell Stock with Transaction Fee LC 714 — every sale pays a fee, so tiny rises are no longer worth collecting: the DP absorbs it with hold + price - fee on the sell step.
  • Best Time to Buy and Sell Stock III LC 123 — at most two trades: four DP states (first buy, first sell, second buy, second sell), still one pass.
  • Best Time to Buy and Sell Stock IV LC 188 — at most k trades: DP over k; when k >= n / 2 the limit never binds and the problem becomes this one.
  • Return the trades, not just the profit — merge consecutive rising days into one trade: buy at the start of a rise (a valley), sell where the next day does not rise (a peak).
