Same Tree Easy

LeetCode #100 ↗
Status

Decide whether two binary trees have the same shape and the same value at every position.

Problem

Given the roots p and q of two binary trees, return True if the trees are the same and False otherwise.

Two trees are the same when they have the same structure (a node exists in one tree exactly where it exists in the other) and every pair of matching nodes holds the same value. Two empty trees are the same.

Examples

Example 1
Input: p = [1, 2, 3], q = [1, 2, 3]
Output: true
Example 2
Input: p = [1, 2], q = [1, None, 2]
Output: false
Both trees hold the values 1 and 2, but 2 is a left child in p and a right child in q: the shapes differ.
Example 3
Input: p = [1, 2, 1], q = [1, 1, 2]
Output: false
The shapes match, but the left children are 2 and 1: the values differ.

Constraints

  • 0 <= number of nodes in each tree <= 100
  • -10^4 <= Node.val <= 10^4

Think first try before reading the solution

If the two roots hold different values, the answer is already False. If they match, what is left to compare?
Two trees are the same when their roots match and their left subtrees are the same and their right subtrees are the same. That sentence is the recursion. It still needs a base case for when one or both nodes are missing.
Handle the cases in this order: both None (same), exactly one None (different), both real nodes (compare the values, then recurse on the left pair and the right pair). Check for None before reading .val.

Key idea

A tree is a root plus a left subtree plus a right subtree. So "are these two trees the same?" splits into three smaller questions of the same kind: do the roots hold equal values, are the left subtrees the same, and are the right subtrees the same. All three answers have to be yes.

Walk both trees in lock-step, comparing the node at the same position in each. At every pair there are only three cases:

  1. both None: nothing to compare, the pair matches;
  2. exactly one None: one tree has a node where the other has none, so the shapes differ;
  3. both real nodes: they match only if their values are equal and both child pairs match.

Python's and stops at the first False, so the walk ends at the first difference. For two identical trees every node is visited once, which gives O(n) time.

Approaches from the obvious one to the one you want in an interview

Turn each tree into a flat list with a preorder walk (the node, then its left subtree, then its right subtree), writing None for every missing child. Two trees are the same exactly when their lists are equal.

The None markers are essential. Without them [1, 2] and [1, None, 2] would both become [1, 2]. With them the position of every node is pinned down by where its children (or their absence) appear in the list.

It is correct and linear, but it builds two full lists and cannot stop at the first difference. The direct recursion below does the same walk without the lists.

Dry run

  1. p = [1, 2] (node 1 with a left child 2): preorder visits 1, then 2 and its two missing children, then 1's missing right child → [1, 2, None, None, None]
  2. q = [1, None, 2] (node 1 with a right child 2): 1, then its missing left child, then 2 and its two missing children → [1, None, 2, None, None]
  3. The lists first differ at position 1 (2 versus None), so the trees are not the same → False.

Python

class Solution:
    def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
        def serialize(node, out):
            if node is None:
                out.append(None)          # the marker keeps the shape: a missing child is recorded too
                return
            out.append(node.val)          # preorder: node, then left subtree, then right subtree
            serialize(node.left, out)
            serialize(node.right, out)

        p_list, q_list = [], []
        serialize(p, p_list)
        serialize(q, q_list)
        return p_list == q_list           # lists compare element by element
Time O(n + m)Space O(n + m)

Both trees are walked completely (n and m nodes) and both lists are kept in memory.

When to use: Only to see that shape matters. It never stops early, so the recursion below is better.

Compare the two trees position by position. The function takes a pair of nodes, one from each tree:

  • both None → True (two empty subtrees are the same);
  • exactly one None → False (the shapes differ);
  • both real but with different values → False;
  • otherwise they match here, so the answer is whether the left pair matches and the right pair matches.

The order of the first three checks matters: the None checks come before any .val, so the code never reads an attribute of a missing node. Because and stops at the first False, the walk ends at the first difference.

Dry run

  1. p = [1, 2, 1], q = [1, 1, 2]
  2. isSameTree(1, 1): both real, values equal → check the left pair, then the right pair
  3. isSameTree(2, 1) (the left children): 2 ≠ 1 → False
  4. The and sees False on its left side and stops. The right pair is never examined → False.

Python

class Solution:
    def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
        if p is None and q is None:          # both empty: nothing to disagree about
            return True
        if p is None or q is None:           # only one is empty: the shapes differ
            return False
        if p.val != q.val:                   # same position, different value
            return False
        # equal here, so the left subtrees and the right subtrees must both be the same
        return (self.isSameTree(p.left, q.left)
                and self.isSameTree(p.right, q.right))
Time O(n)Space O(h)

Each pair of nodes is compared once and the walk stops at the first difference, so n is the size of the smaller tree. The call stack is as deep as the trees are tall.

When to use: The default. Short, stops early, and the pair-walking pattern is reused by Symmetric Tree and Subtree of Another Tree.

Watch it run

The call stack of the recursive version is really a to-do list of pairs still to be compared. Keep that list yourself: pop a pair, apply the same cases, and when the nodes match push their left pair and their right pair. Any difference returns False immediately. If the stack runs empty, every pair matched.

A pair of two Nones needs no work, so it is simply skipped (continue). This version never hits Python's recursion limit.

Dry run

  1. p = q = [1, 2, 3]: stack = [(1, 1)]
  2. pop (1, 1): values equal → push the right pair (3, 3), then the left pair (2, 2), so the left is compared first
  3. pop (2, 2): equal → push its two (None, None) pairs, which are skipped when popped
  4. pop (3, 3): equal, same story. The stack is empty → True.

Python

class Solution:
    def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
        stack = [(p, q)]                         # pairs of nodes still to be compared
        while stack:
            a, b = stack.pop()
            if a is None and b is None:          # this pair matches and has nothing below it
                continue
            if a is None or b is None or a.val != b.val:
                return False                     # the shape or a value differs
            stack.append((a.right, b.right))     # compare the children later
            stack.append((a.left, b.left))
        return True
Time O(n)Space O(h)

Same pairs as the recursion. The stack holds the pending right pairs along one root-to-leaf path.

When to use: When recursion depth is a concern or you are asked for an iterative solution.

Common mistakes

  • Reading .val before checking for None. p.val != q.val raises AttributeError when one side is missing, so test the both-None and one-None cases first.
  • Comparing only the values and ignoring the shape. [1, 2] and [1, None, 2] hold the same values but are different trees; a preorder list without None markers cannot tell them apart.
  • Returning True when one tree runs out early, for example treating q is None as 'nothing left to check'. That accepts a smaller tree as equal to a bigger one.
  • Comparing the two roots with p == q or p is q. For TreeNode objects that tests identity (same object in memory), so two separately built identical trees would give False.
  • Pairing the wrong children, for example p.left with q.right. That is the mirror test (Symmetric Tree), not equality.

Python notes

  • p is None tests for a missing node. Prefer it to not p here: it reads as 'is there a node?' and cannot be confused with a falsy value.
  • a and b never evaluates b when a is False. That short-circuit is the early exit: after the left pair fails, the right pair is not even visited.
  • Two lists compare element by element with ==: [1, 2] == [1, 2] is True but [1, None, 2] == [1, 2] is False. The serialising solution relies on this.
  • TreeNode defines no __eq__, so p == q between nodes is an identity check. Compare .val and recurse instead.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Subtree of Another Tree LC 572 — run this exact check at every node of the bigger tree and ask whether any of them matches the smaller tree.
  • Symmetric Tree LC 101 — is the tree a mirror of itself? The same two-pointer walk, but pair a.left with b.right and a.right with b.left.
  • Flip Equivalent Binary Trees LC 951 — the trees may differ by swapping the children at any node: at each pair accept the straight pairing of children or the crossed one.
  • Merge Two Binary Trees LC 617 — walk both trees in lock-step again, but build a new tree: add the values where both trees have a node and reuse whichever subtree exists where only one does.
  • Find Duplicate Subtrees LC 652 — the serialising idea scaled up: turn every subtree into a string and use a dictionary to spot strings that occur twice.
