Find Critical and Pseudo Critical Edges in Minimum Spanning Tree Hard 250

LeetCode #1489 ↗
Status

Sort the edges of a weighted graph into those every cheapest spanning tree needs, those some cheapest tree can use, and the rest.

Problem

You are given a connected, undirected, weighted graph with n nodes numbered 0 … n - 1, and edges, where edges[i] = [a, b, weight] is an edge between a and b. Several edges may join the same pair of nodes.

A minimum spanning tree (MST) is a set of n - 1 edges that connects every node with the smallest possible total weight. A graph may have several MSTs with the same total.

  • An edge is critical if removing it from the graph makes every MST more expensive (or makes the graph fall apart).
  • An edge is pseudo-critical if it belongs to some MST but not to all of them.

Return [critical, pseudo_critical]: two lists of edge indices, each in any order.

Examples

Example 1
Input: n = 5, edges = [[0, 1, 1], [1, 2, 1], [2, 3, 2], [0, 3, 2], [0, 4, 3], [3, 4, 3], [1, 4, 6]]
Output: [[0, 1], [2, 3, 4, 5]]
Every MST costs 7. Edges 0 and 1 are in all four of them. Edges 2 and 3 (both weight 2) are interchangeable, as are 4 and 5 (both weight 3). Edge 6 (weight 6) is in none.
Example 2
Input: n = 4, edges = [[0, 1, 1], [1, 2, 1], [2, 3, 1], [0, 3, 1]]
Output: [[], [0, 1, 2, 3]]
The four edges form a square of equal weights. Any three of them make an MST of cost 3, so no edge is in every MST and each is in some.
Example 3
Input: n = 3, edges = [[0, 1, 1], [1, 2, 1], [0, 2, 2]]
Output: [[0, 1], []]
The only MST is {0, 1} with cost 2. Edge 2 costs more than the detour around it, so it is neither critical nor pseudo-critical.

Constraints

  • 2 <= n <= 100
  • 1 <= len(edges) <= min(200, n · (n - 1) / 2)
  • edges[i] = [a, b, weight] with 0 <= a < b < n and 1 <= weight <= 1000
  • the graph is connected

Key idea

Every MST of a graph has the same total weight, call it base. That single number turns a question about all MSTs into two quick experiments per edge, each one a run of Kruskal's algorithm (sort the edges by weight, take each edge whose ends are not yet connected, track connectivity with union-find).

  • Without edge i: if Kruskal on the other edges cannot reach base (it ends higher, or cannot connect all n nodes), every cheapest tree needed edge i. It is critical.
  • With edge i forced in first: union its two ends before the loop, then run Kruskal normally. If the total is still base, there is a cheapest tree that contains edge i, so it is pseudo-critical; if the total is higher, no cheapest tree contains it.

With at most 200 edges, 2 · 200 Kruskal runs of 200 edges each is about 80,000 union-find operations, nothing. The faster alternative looks at the edges one weight group at a time: within a group, an edge is critical exactly when it is a bridge of the graph formed by the components built from lighter edges, and pseudo-critical when it joins two different components but is not a bridge.

Approaches from the obvious one to the one you want in an interview

Take the definitions literally. Try every set of n - 1 edges, keep the ones that form a spanning tree (union-find confirms that no edge closes a loop, so the n - 1 edges connect everything), and record the smallest total. An edge that appears in every minimum tree is critical; one that appears in some but not all is pseudo-critical.

The number of edge subsets is C(E, n - 1), which explodes: with 20 edges and 10 nodes it is already 167,960, and the real limits (200 edges, 100 nodes) are hopeless. It is useful only to pin down what the two words mean.

Dry run

  1. Example 1: 7 edges, choose 4 → 35 subsets; 24 of them are spanning trees
  2. The cheapest total is 7, reached by four trees: {0,1,2,4}, {0,1,2,5}, {0,1,3,4}, {0,1,3,5}
  3. In all four: edges 0 and 1 → critical. In some: 2, 3, 4, 5 → pseudo-critical. Edge 6 is in none

Python

class Solution:
    def findCriticalAndPseudoCriticalEdges(self, n: int, edges: List[List[int]]) -> List[List[int]]:
        m = len(edges)

        def is_spanning_tree(subset) -> bool:      # n - 1 edges that never close a loop connect everything
            parent = list(range(n))

            def find(x: int) -> int:
                while parent[x] != x:
                    x = parent[x]
                return x

            for i in subset:
                a, b, _ = edges[i]
                root_a, root_b = find(a), find(b)
                if root_a == root_b:
                    return False
                parent[root_a] = root_b
            return True

        best = math.inf
        in_every, in_some = set(), set()
        for subset in itertools.combinations(range(m), n - 1):
            if not is_spanning_tree(subset):
                continue
            total = sum(edges[i][2] for i in subset)
            if total < best:                       # a new cheapest tree: start both sets over
                best, in_every, in_some = total, set(subset), set(subset)
            elif total == best:                    # another cheapest tree: intersect and union
                in_every &= set(subset)
                in_some |= set(subset)
        return [sorted(in_every), sorted(in_some - in_every)]
Time O(C(E, n-1) · n)Space O(n + E)

Every (n - 1)-subset of the E edges is checked with an O(n) union-find pass.

When to use: Only to understand the definitions; it dies on a few dozen edges.

Build one MST with Kruskal and call its total base; every MST costs the same. Then for each edge i:

  1. Without i: run Kruskal on the other edges. If the total is above base, or fewer than n - 1 edges get used (the graph fell apart), edge i was needed by every cheapest tree: critical.
  2. With i forced in: union its ends first, count its weight, then run Kruskal on the rest. If the total equals base, some cheapest tree contains edge i: pseudo-critical. If the total is higher, no cheapest tree does.

Why does forcing work? Kruskal with a pre-joined pair still produces the cheapest tree among those containing that edge. So total == base is exactly the statement "an MST containing edge i exists".

Two Kruskal runs per edge, each sorting once up front and doing E union-find operations: O(E²) with near-constant union-find, about 80,000 operations at the limits.

Dry run

  1. Example 1: Kruskal takes 0 (1), 1 (1), 2 (2), skips 3 (loop), takes 4 (3), skips 5 and 6 → base = 7
  2. Without edge 0: the best tree costs 8 → critical. Without edge 1: 8 → critical
  3. Without edge 2: still 7. Forced in: 7 → pseudo-critical. Same for 3, 4 and 5
  4. Without edge 6: 7. Forced in: 10 → in no cheapest tree. Answer [[0, 1], [2, 3, 4, 5]]

Python

class Solution:
    def findCriticalAndPseudoCriticalEdges(self, n: int, edges: List[List[int]]) -> List[List[int]]:
        m = len(edges)
        order = sorted(range(m), key=lambda i: edges[i][2])   # edge indices, cheapest first

        def mst_weight(skip: int = -1, force: int = -1) -> float:
            """Kruskal that never uses `skip` and takes `force` first. inf when the tree is incomplete."""
            parent = list(range(n))

            def find(x: int) -> int:
                while parent[x] != x:
                    parent[x] = parent[parent[x]]      # path halving
                    x = parent[x]
                return x

            def union(a: int, b: int) -> bool:
                root_a, root_b = find(a), find(b)
                if root_a == root_b:
                    return False                       # already connected: this edge would close a loop
                parent[root_a] = root_b
                return True

            total, used = 0, 0
            if force != -1:                            # the forced edge goes in before anything else
                a, b, w = edges[force]
                union(a, b)
                total, used = w, 1
            for i in order:
                if i == skip or i == force:
                    continue
                a, b, w = edges[i]
                if union(a, b):
                    total += w
                    used += 1
            return total if used == n - 1 else math.inf

        base = mst_weight()
        critical, pseudo_critical = [], []
        for i in range(m):
            if mst_weight(skip=i) > base:              # without it, every tree costs more (or does not exist)
                critical.append(i)
            elif mst_weight(force=i) == base:          # some cheapest tree contains it
                pseudo_critical.append(i)
        return [critical, pseudo_critical]
Time O(E² · α(n))Space O(n + E)

One sort, then up to 2E Kruskal runs of E union-find steps each; α is the inverse Ackermann function, effectively constant.

When to use: The expected interview answer at these limits: short, and each experiment is easy to justify.

Watch it run

Process the edges one weight group at a time (all edges of weight 1, then all of weight 2, …), keeping a union-find of everything built from lighter groups. Inside a group, replace each edge's ends by their current roots:

  • an edge whose ends share a root is already connected by lighter edges: it belongs to no MST;
  • the remaining edges form a small graph on the components. An edge that is a bridge of that graph (removing it disconnects two components) must be in every MST: critical. An edge on a cycle of that graph can be swapped for another edge of the same weight: pseudo-critical.

After classifying, union all the group's useful edges and move to the next weight. Bridges come from Tarjan's low-link DFS, skipping the edge you arrived by (not the parent node) so that two parallel edges between the same components are both seen as non-bridges.

One sort plus linear work per group: O(E log E). It is the right tool when E is large, at the cost of noticeably more code.

Dry run

  1. Example 1, weight 1: edges 0 and 1 join components {0}–{1} and {1}–{2}: a path, both are bridges → critical
  2. Weight 2: edges 2 and 3 both join {0,1,2} and {3}: two parallel edges, a cycle → pseudo-critical
  3. Weight 3: edges 4 and 5 both join {0,1,2,3} and {4} → pseudo-critical
  4. Weight 6: edge 6 has both ends in the single remaining component → in no MST

Python

class Solution:
    def findCriticalAndPseudoCriticalEdges(self, n: int, edges: List[List[int]]) -> List[List[int]]:
        m = len(edges)
        parent = list(range(n))

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def bridges(adj: Dict[int, List[Tuple[int, int]]]) -> Set[int]:
            """Edge indices that are bridges of the component graph (Tarjan low-link)."""
            disc, low, found, clock = {}, {}, set(), [0]

            def dfs(u: int, came_by: int) -> None:
                disc[u] = low[u] = clock[0]
                clock[0] += 1
                for v, i in adj[u]:
                    if i == came_by:               # skip the edge we arrived by, not the node: parallel edges count
                        continue
                    if v not in disc:
                        dfs(v, i)
                        low[u] = min(low[u], low[v])
                        if low[v] > disc[u]:       # nothing below v reaches u or above without this edge
                            found.add(i)
                    else:
                        low[u] = min(low[u], disc[v])

            for u in list(adj):
                if u not in disc:
                    dfs(u, -1)
            return found

        order = sorted(range(m), key=lambda i: edges[i][2])
        critical, pseudo_critical = [], []
        pos = 0
        while pos < m:
            weight = edges[order[pos]][2]
            group = []
            while pos < m and edges[order[pos]][2] == weight:   # all edges of this weight
                group.append(order[pos])
                pos += 1
            adj = defaultdict(list)                # graph on the current components
            useful = []
            for i in group:
                a, b, _ = edges[i]
                root_a, root_b = find(a), find(b)
                if root_a == root_b:
                    continue                       # lighter edges already connect these ends: in no MST
                useful.append(i)
                adj[root_a].append((root_b, i))
                adj[root_b].append((root_a, i))
            must_use = bridges(adj)
            for i in useful:
                (critical if i in must_use else pseudo_critical).append(i)
            for i in useful:                       # now merge the whole group before the next weight
                root_a, root_b = find(edges[i][0]), find(edges[i][1])
                if root_a != root_b:
                    parent[root_a] = root_b
        return [sorted(critical), sorted(pseudo_critical)]
Time O(E log E)Space O(n + E)

Sorting dominates; each group's component graph is built and searched for bridges in time linear in its size.

When to use: For large edge counts, or as the follow-up when the interviewer asks how to beat O(E²).

Common mistakes

  • Testing 'is edge i in the MST Kruskal happened to build?' Ties are broken arbitrarily, so an edge missing from one MST may sit in another. Compare totals against base, never membership in one tree.
  • Forgetting the disconnected case: without a critical bridge Kruskal uses fewer than n - 1 edges. Treat that as infinite cost (any value above base works).
  • When forcing an edge in, skipping the union of its ends. The forced edge must count both in the total and in union-find, or Kruskal may add an edge that closes a loop with it.
  • Classifying a critical edge as pseudo-critical too. Forcing a critical edge in also gives base; check the 'without' experiment first and only run 'with' for the edges that survive it.
  • In the bridge-based solution, finding bridges by skipping the parent node instead of the parent edge: two parallel edges between the same components are both pseudo-critical, and the node-based skip would call them bridges.

Python notes

  • sorted(range(len(edges)), key=lambda i: edges[i][2]) sorts indices by weight, so the answer can still name edges by their original position.
  • math.inf compares greater than every real total, which makes 'disconnected' fall into the critical branch for free.
  • A nested find with path halving (parent[x] = parent[parent[x]]) keeps union-find nearly O(1) per call without the ceremony of a class.
  • itertools.combinations(range(m), n - 1) enumerates candidate trees for the brute force; it is only viable for a handful of edges.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Min Cost to Connect All Points LC 1584 — plain MST on a complete graph; the Kruskal routine here is the same, the question is just the total.
  • Redundant Connection LC 684 — the union-find skip in Kruskal, on its own: the first edge whose ends are already connected.
  • Critical Connections in a Network LC 1192 — bridges of a plain graph with Tarjan's low-link values; the faster approach here runs that on each weight group.
  • Number of Operations to Make Network Connected LC 1319 — counting components with union-find; the 'fewer than n - 1 edges used' check from the critical test.
  • Count the number of different MSTs — per weight group, multiply the number of spanning trees of each component graph (Kirchhoff's matrix tree theorem); the group view from the alternative approach is exactly what you need.
  • What if there were 10^5 edges? — the O(E²) experiments are too slow; use the weight-group approach, O(E log E) for the sort plus linear bridge-finding per group.
