Container With Most Water Medium

LeetCode #11 ↗
Status

Pick two vertical lines that, together with the x-axis, hold the most water.

Problem

You are given a list height of n non-negative integers. Picture n vertical lines: line i stands at x = i and is height[i] units tall.

Choose two of the lines. Together with the x-axis they form a container. The water in it can only rise as high as the shorter of the two lines (any higher and it spills), and the container cannot be tilted. So lines i and j hold

min(height[i], height[j]) * (j - i)

units of water. Return the largest amount any pair of lines can hold. The lines in between do not get in the way.

Examples

Example 1
Input: height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
Output: 49
Lines 1 (height 8) and 8 (height 7): the water level is min(8, 7) = 7 and the width is 8 − 1 = 7, so 7 × 7 = 49.
Example 2
Input: height = [1, 1]
Output: 1
Example 3
Input: height = [4, 3, 2, 1, 4]
Output: 16
The two 4s at the ends: 4 × 4 = 16.

Constraints

  • 2 <= len(height) <= 10^5
  • 0 <= height[i] <= 10^4

Think first try before reading the solution

Trying every pair is O(n²). Start from the widest container, the two ends, and ask what it would take to beat it.
Every other container is narrower, so it needs a higher water level to win. If you move the taller of the two lines inward, the level is still capped by the shorter line that stayed. Can that ever help?
Always move the pointer at the shorter line. Keep the best area seen, and stop when the pointers meet.

Key idea

Start with the widest container: left = 0, right = n - 1. Any other pair is narrower, so the only way to beat the current area is a higher water level.

Say height[left] <= height[right]. Now pair the left line with any line between the two pointers: the level can be at most height[left] (that line is still one of the two walls), and the width is smaller. None of those containers can beat the current one, so the left line has already given its best answer and can be dropped with left += 1. When the right line is the shorter one, the same argument drops it instead.

Each step rules out one line for good. The n(n−1)/2 pairs collapse into n − 1 steps, and nothing that could win is ever skipped.

Approaches from the obvious one to the one you want in an interview

Compute min(height[i], height[j]) * (j - i) for every pair i < j and keep the largest. It is obviously correct, and obviously slow: n(n−1)/2 pairs, about 5·10⁹ for n = 10⁵.

Notice how much of that work is hopeless. Once a short line has been paired with the line farthest from it, every other partner gives a narrower container at the same or a lower level. The optimal approach uses exactly that observation to skip those pairs.

Python

class Solution:
    def maxArea(self, height: List[int]) -> int:
        best = 0
        n = len(height)
        for i in range(n):
            for j in range(i + 1, n):
                area = min(height[i], height[j]) * (j - i)   # level of the shorter line x width
                best = max(best, area)
        return best
Time O(n²)Space O(1)

Two nested loops over all pairs; only the running best is stored.

When to use: Only as a baseline to explain what the two pointers avoid.

Watch it run

  1. left = 0, right = n - 1, best = 0.
  2. Record the area of the current pair.
  3. Move the pointer at the shorter line inward (either one on a tie) and repeat until the pointers meet.

Why moving the shorter line is safe: every container still using it would be narrower and could not have a higher level than that line. So the shorter line's best container is the one just measured, and it can be discarded. Moving the taller line instead can never produce a larger area, because the shorter line still caps the level while the width drops.

Dry run

  1. height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
  2. L=0 (1), R=8 (7): area 1 × 8 = 8 → best 8; the left line is shorter → L=1
  3. L=1 (8), R=8 (7): area 7 × 7 = 49 → best 49; the right line is shorter → R=7
  4. R=7 (3): 3 × 6 = 18; R=6 (8): 8 × 5 = 40; tie, move L → L=2 (6): 6 × 4 = 24 → L=3, ...
  5. all remaining pairs are narrower and lower → answer 49

Python

class Solution:
    def maxArea(self, height: List[int]) -> int:
        left, right = 0, len(height) - 1
        best = 0
        while left < right:
            area = min(height[left], height[right]) * (right - left)
            best = max(best, area)
            if height[left] <= height[right]:
                left += 1        # the left line cannot do better with a narrower partner
            else:
                right -= 1       # the right line cannot do better with a narrower partner
        return best
Time O(n)Space O(1)

Each iteration moves one pointer inward; they start n − 1 apart.

When to use: Always. The proof (why the shorter line can be dropped) is what interviewers want to hear.

Common mistakes

  • Moving the taller line. The width shrinks and the level cannot rise above the shorter line that stayed, so every container you reach that way is worse; meanwhile the pairs that could win are left unexplored.
  • Using max instead of min for the water level. Water spills over the shorter side.
  • Computing the width as j - i + 1. The lines stand at x = i and x = j, so the width is j - i.
  • Confusing this with Trapping Rain Water. Here only the two chosen lines matter; the lines in between neither block the water nor hold any of their own.
  • Worrying about ties: when both lines are equally tall, neither can do better with a narrower partner, so moving either pointer is safe.

Python notes

  • min(height[left], height[right]) * (right - left) is the whole area formula; store it in a variable so you can compare it and show it.
  • best = max(best, area) is the idiomatic running maximum.
  • With n = 10⁵ the brute force needs about 5·10⁹ pair checks; at roughly 10⁷ simple operations per second, Python would take minutes.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Trapping Rain Water LC 42 — every bar holds its own column of water and the inner bars matter. The two-pointer walk still moves the lower side, but it adds water bar by bar instead of maximising one rectangle.
  • Largest Rectangle in Histogram LC 84 — a rectangle drawn under the bars is limited by the lowest bar in the whole range, not just the two ends, so a monotonic stack replaces the two pointers.
  • Two Sum II - Input Array Is Sorted LC 167 — the same 'discard the side that cannot help' argument, driven by sorted values instead of heights.
  • Return the two lines, not the area — record (left, right) whenever the best area improves; nothing else changes.
  • Lines at uneven positions — if line i stands at x = xs[i] with xs increasing, the width becomes xs[right] - xs[left]. Moving inward still narrows the container, so the same proof and loop work.
