Serialize and Deserialize Binary Tree Hard

LeetCode #297 ↗
Status

Turn a binary tree into a string and rebuild exactly the same tree from that string.

Problem

Serializing a structure means turning it into a string so it can be saved or sent; deserializing rebuilds the structure from that string. Design both for binary trees.

Implement a class Codec with two methods:

  • serialize(root) returns a string describing the tree;
  • deserialize(data) takes such a string and returns the root of the rebuilt tree.

You may choose any format. The only requirement is that deserialize(serialize(root)) produces a tree with the same shape and the same values as root. Values can repeat, and the tree can be empty.

On this site the tests call Solution().roundtrip(root), a small wrapper that does exactly that round trip and returns the rebuilt tree.

Examples

Example 1
Input: root = [1, 2, 3, null, null, 4, 5]
Output: [1, 2, 3, null, null, 4, 5]
One possible string is 1,2,#,#,3,4,#,#,5,#,# (preorder with # for missing children).
Example 2
Input: root = []
Output: []
The empty tree must survive the round trip too.

Constraints

  • 0 <= number of nodes <= 10^4
  • -1000 <= Node.val <= 1000

Think first try before reading the solution

Writing only the values loses the shape: [1, 2] (2 on the left) and [1, null, 2] (2 on the right) both give 1,2 in preorder. What extra information would make the string unambiguous?
Write a marker such as # for every missing child. With the markers included, a single preorder walk describes exactly one tree.
Deserialize by reading tokens in the same order you wrote them: a recursive read() takes the next token, returns None for #, and otherwise creates a node and reads its left subtree, then its right subtree.

Key idea

A list of values alone is ambiguous: many different shapes give the same preorder. The fix is to also record where the tree stops: write # for each missing child. Now 1,2,#,#,3,#,# can be read back only one way. 1 is the root; its left subtree starts with 2; the two #s after 2 say 2 has no children, so the left subtree is finished; what remains (3,#,#) is the right subtree.

Reading mirrors writing. write(node) emits the node, then its left subtree, then its right subtree. read() consumes one token and, if it is a number, creates the node and calls read() for its left subtree and then its right one. Because both follow the same order, the reader always knows which child the next token belongs to.

A tree with n nodes has exactly n + 1 missing children, so the string holds 2n + 1 tokens: O(n) time and space in both directions. Separate the tokens with commas, because values such as -10 or 200 take several characters.

Approaches from the obvious one to the one you want in an interview

Number the positions like a heap: the root is position 0 and the children of position i are 2i + 1 and 2i + 2. Serialize by writing, for every position up to the largest one used, either the value or #. Deserialize by creating the nodes and linking position i to 2i + 1 and 2i + 2.

It is correct, and it works well for complete trees. But the list must reach the deepest position: a chain of n nodes going right uses positions 0, 2, 6, 14, ..., about 2ⁿ. A 30-node chain would need a billion slots. The waste is writing a placeholder for every position under a missing node, even though nothing can ever live there.

Dry run

  1. [1, 2, 3, null, null, 4, 5]: positions 1→0, 2→1, 3→2, 4→5, 5→6
  2. serialize → 1,2,3,#,#,4,5 (7 slots for 5 nodes: fine)
  3. right chain [1, null, 2, null, 3]: positions 0, 2, 6 → 1,#,2,#,#,#,3 (7 slots for 3 nodes; it doubles per level)

Python

class Codec:
    def serialize(self, root: Optional[TreeNode]) -> str:
        """Value at heap position i (children of i at 2i+1 and 2i+2), '#' for empty positions."""
        if root is None:
            return ""
        at = {}                                   # position -> value
        stack = [(root, 0)]
        while stack:
            node, i = stack.pop()
            at[i] = node.val
            if node.left:
                stack.append((node.left, 2 * i + 1))
            if node.right:
                stack.append((node.right, 2 * i + 2))
        size = max(at) + 1                        # a chain of n nodes needs about 2^n slots
        return ",".join(str(at[i]) if i in at else "#" for i in range(size))

    def deserialize(self, data: str) -> Optional[TreeNode]:
        if not data:
            return None
        tokens = data.split(",")
        nodes = [None if tok == "#" else TreeNode(int(tok)) for tok in tokens]
        for i, node in enumerate(nodes):
            if node is not None:
                if 2 * i + 1 < len(nodes):
                    node.left = nodes[2 * i + 1]
                if 2 * i + 2 < len(nodes):
                    node.right = nodes[2 * i + 2]
        return nodes[0]


class Solution:
    # The site's tests call Solution().roundtrip(root): serialize, deserialize, and compare
    # the rebuilt tree with the original. On LeetCode you submit only the Codec class.
    def roundtrip(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        codec = Codec()
        return codec.deserialize(codec.serialize(root))
Time O(2^h)Space O(2^h)

The string has one slot per position up to the deepest node: fine for balanced trees, exponential for a chain (h = n).

When to use: Never for arbitrary trees; it is how a heap is stored, because a heap is always complete.

Write the tree in preorder and emit # for every missing child:

  • write(None) → #
  • write(node) → node.val, then write(node.left), then write(node.right)

Read it back with the same recursion: take the next token; # becomes None; a number becomes a node whose left subtree is read next, then its right subtree. An iterator over the tokens keeps the position for you.

Only real gaps get a marker (n + 1 of them), so the string has 2n + 1 tokens whatever the shape.

Dry run

  1. [1, 2, 3, null, null, 4, 5]
  2. write 1 → write 2 → # # (2 is a leaf) → write 3 → write 4 → # # → write 5 → # #
  3. string: 1,2,#,#,3,4,#,#,5,#,#
  4. read: 1 (root) → 2 (left of 1) → # # → 3 (right of 1) → 4 → # # → 5 → # #

Python

class Codec:
    def serialize(self, root: Optional[TreeNode]) -> str:
        tokens = []

        def write(node):
            if node is None:
                tokens.append("#")              # marker for a missing child
                return
            tokens.append(str(node.val))
            write(node.left)
            write(node.right)

        write(root)
        return ",".join(tokens)

    def deserialize(self, data: str) -> Optional[TreeNode]:
        tokens = iter(data.split(","))

        def read():
            tok = next(tokens)
            if tok == "#":
                return None
            node = TreeNode(int(tok))
            node.left = read()                  # same order as write(): left subtree first
            node.right = read()
            return node

        return read()


class Solution:
    # The site's tests call Solution().roundtrip(root): serialize, deserialize, and compare
    # the rebuilt tree with the original. On LeetCode you submit only the Codec class.
    def roundtrip(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        codec = Codec()
        return codec.deserialize(codec.serialize(root))
Time O(n)Space O(n)

2n + 1 tokens are written and read once each; the recursion is as deep as the tree height.

When to use: The usual interview answer: short, and the format is easy to explain.

Watch it run

Write the tree level by level with a queue, the way LeetCode prints trees: pop a node, write its value (or # for None), and enqueue both children even when they are missing. To read, create the root from the first token, then for every real node taken from a queue consume the next two tokens as its left and right child.

Same O(n) cost as the preorder version. The trade-off: no recursion, so deep chains are safe, and the string matches the familiar [1, 2, 3, null, null, 4, 5] layout, at the cost of slightly more code.

Python

class Codec:
    def serialize(self, root: Optional[TreeNode]) -> str:
        if root is None:
            return ""
        tokens, queue = [], deque([root])
        while queue:
            node = queue.popleft()
            if node is None:
                tokens.append("#")
                continue
            tokens.append(str(node.val))
            queue.append(node.left)             # enqueue children even when they are None
            queue.append(node.right)
        return ",".join(tokens)

    def deserialize(self, data: str) -> Optional[TreeNode]:
        if not data:
            return None
        tokens = data.split(",")
        root = TreeNode(int(tokens[0]))
        queue, i = deque([root]), 1
        while queue:
            node = queue.popleft()              # its two children are the next two tokens
            if tokens[i] != "#":
                node.left = TreeNode(int(tokens[i]))
                queue.append(node.left)
            i += 1
            if tokens[i] != "#":
                node.right = TreeNode(int(tokens[i]))
                queue.append(node.right)
            i += 1
        return root

        return codec.deserialize(codec.serialize(root))
Time O(n)Space O(n)

Each node and each missing child is queued and written once; the queue holds about one level.

When to use: When recursion depth is a concern, or when you want the LeetCode-style level-order format.

Common mistakes

  • Leaving out the missing-child markers: [1, 2] and [1, null, 2] then serialize to the same string.
  • Concatenating values without a separator: 1 + 23 and 12 + 3 both give 123. Join with commas and split(',').
  • Reading the children in a different order than they were written (right before left) silently builds a mirror image.
  • Advancing a shared index by hand and forgetting a nonlocal declaration or an increment. An iterator, next(tokens), hands each call the next token with no bookkeeping.
  • Recursion depth: a 10^4-node chain goes past Python's default limit of 1000 frames. The BFS version avoids recursion.

Python notes

  • ",".join(tokens) and data.split(",") are the two halves of the delimiter idea; both run in time proportional to the string length.
  • tokens = iter(data.split(",")) plus next(tokens) gives each recursive call the next token without an index variable.
  • The tests on this site call one method, so every approach adds a tiny Solution.roundtrip wrapper around Codec. On LeetCode you submit only the Codec class.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Serialize and Deserialize BST LC 449 — for a BST, plain preorder without markers is enough: the (lo, hi) bounds tell the reader where each subtree ends, so the string is shorter.
  • Serialize and Deserialize N-ary Tree LC 428 — nodes have any number of children: write each node's child count after its value, then its children.
  • Verify Preorder Serialization of a Binary Tree LC 331 — check a string without building the tree: count open child slots (a value fills one and opens two, # fills one).
  • Find Duplicate Subtrees LC 652 — serialize every subtree and count the strings in a dictionary; equal strings mean equal subtrees.
  • Subtree of Another Tree LC 572 — serialize both trees with markers and delimiters and test for a substring; wrap every token (,2,) so 2 does not match inside 12.
  • Encode and Decode Strings LC 271 — the same 'make the format unambiguous' problem for a list of strings, solved by prefixing each string with its length.
