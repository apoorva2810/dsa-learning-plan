Stone Game Medium 250

LeetCode #877 ↗
Status

Two players take turns taking a pile from either end of a row of piles. Decide whether the player who moves first ends with more stones.

Problem

Alice and Bob play with a row of piles of stones; piles[i] is the number of stones in pile i. The number of piles is even and the total number of stones is odd, so the game can never end in a tie.

They take turns, Alice first. On your turn you take one whole pile from either end of the row. When no pile is left, the player with more stones wins. Both players play perfectly.

Return True if Alice wins and False if Bob wins.

Examples

Example 1
Input: piles = [3, 2, 10, 4]
Output: True
Taking the larger end first is a trap: if Alice takes the 4, Bob takes the 10 and Alice ends with 4 + 3 = 7 against 12. If she starts with the 3, Bob must take the 2 or the 4, and Alice then takes the 10: she ends with 13 against 6 either way.
Example 2
Input: piles = [3, 8]
Output: True
Alice takes the 8 and Bob is left with the 3.
Example 3
Input: piles = [2, 9, 4, 5, 1, 6]
Output: True
Alice can end with 20 stones against 7, for example by collecting the piles at positions 1, 3 and 5 (9 + 5 + 6).

Constraints

  • 2 <= len(piles) <= 500
  • len(piles) is even
  • 1 <= piles[i] <= 500
  • sum(piles) is odd

Think first try before reading the solution

With one pile left the player to move simply takes it. For a longer row, what number can describe how well the player to move is doing, whichever player that is?
Let dp[i][j] be the most the player to move can lead by (own stones minus the opponent's) on the piles i..j. After taking an end pile the opponent is the player to move, and the opponent's lead counts against you: dp[i][j] = max(piles[i] - dp[i + 1][j], piles[j] - dp[i][j - 1]).
Alice wins when dp[0][n - 1] > 0. Now look at the constraints: an even number of piles and an odd total. Number the piles 0, 1, 2, ... and think about even and odd positions: can Alice decide which of the two groups she collects?

Key idea

Both players play perfectly, so ask for the lead: (stones I collect) minus (stones my opponent collects) from the row that remains. Let dp[i][j] be the largest lead the player to move can force on the piles i..j. With one pile the player takes it, so dp[i][i] = piles[i]. With more piles, taking piles[i] earns piles[i], and then the opponent is the player to move on i + 1..j. Their best lead there, dp[i + 1][j], counts against us, so it is subtracted:

dp[i][j] = max(piles[i] - dp[i + 1][j], piles[j] - dp[i][j - 1])

The same formula serves both players, because each of them is simply "the player to move". Alice moves first on the full row, so she wins when dp[0][n - 1] > 0. A cell needs the cells for the two shorter rows next to it, so fill the table by interval length: length 1 first (the diagonal), then length 2, and so on.

This puzzle also has a shortcut. Number the piles 0 to n - 1. Because n is even, the two ends of any row Alice faces always have opposite parity, while the two ends of any row Bob faces have the same parity. So Alice can take every even-indexed pile, or every odd-indexed pile, whichever group she prefers. The total is odd, so the two groups never tie; Alice picks the heavier one and always wins. return True is correct only under the stated guarantees. The table is what you need when they change, for example with an odd number of piles.

Approaches from the obvious one to the one you want in an interview

Let lead(i, j) be the best lead (own stones minus the opponent's) that the player to move can force on the piles i..j. With one pile the player takes it. Otherwise the player takes the left or the right pile, and then the opponent is the player to move on what is left. Their best lead counts against us:

lead(i, j) = max(piles[i] - lead(i + 1, j), piles[j] - lead(i, j - 1))

Alice wins if lead(0, n - 1) > 0. This tries both choices at every turn, so the number of calls doubles with each pile taken: about 2^n calls. It is correct, but the same sub-rows are evaluated over and over (the row 1..2 is reached by taking left-then-right and by taking right-then-left), which is the opening for a table.

Dry run

  1. [3, 2, 10, 4]: lead(0, 3) = max(3 - lead(1, 3), 4 - lead(0, 2))
  2. lead(1, 3) = max(2 - 6, 4 - 8) = -4 and lead(0, 2) = max(3 - 8, 10 - 1) = 9 (their own sub-calls give 6, 8 and 1)
  3. lead(0, 3) = max(3 - (-4), 4 - 9) = max(7, -5) = 7 > 0, so Alice wins

Python

class Solution:
    def stoneGame(self, piles: List[int]) -> bool:
        def lead(i: int, j: int) -> int:
            """Best (own stones - opponent's stones) for the player to move on piles[i..j]."""
            if i == j:                                   # one pile left: take it
                return piles[i]
            take_left = piles[i] - lead(i + 1, j)        # then the opponent moves on i+1..j; their lead counts against us
            take_right = piles[j] - lead(i, j - 1)
            return max(take_left, take_right)

        return lead(0, len(piles) - 1) > 0
Time O(2^n)Space O(n)

Two calls per turn, n turns deep; the same sub-rows are recomputed many times.

When to use: To see the game rule as a formula. Beyond about 25 piles it is too slow.

Store the same leads in a table. dp[i][j] is the best lead of the player to move on the piles i..j:

  • dp[i][i] = piles[i] (one pile: take it);
  • dp[i][j] = max(piles[i] - dp[i + 1][j], piles[j] - dp[i][j - 1]) for longer rows.

A cell reads two cells for shorter rows, so fill the table by interval length: first all rows of length 1, then length 2, up to the full row. The answer is dp[0][n - 1] > 0. Each of the O(n²) cells costs O(1).

Alice's actual total is (sum(piles) + dp[0][n - 1]) // 2, because the lead is her total minus Bob's and the two add up to the sum of all piles. This method works for any number of piles and also tells you the size of the win.

Dry run

  1. [3, 2, 10, 4]: length 1 gives the diagonal 3, 2, 10, 4
  2. length 2: dp[0][1] = max(3 - 2, 2 - 3) = 1; dp[1][2] = max(2 - 10, 10 - 2) = 8; dp[2][3] = max(10 - 4, 4 - 10) = 6
  3. length 3: dp[0][2] = max(3 - 8, 10 - 1) = 9; dp[1][3] = max(2 - 6, 4 - 8) = -4
  4. length 4: dp[0][3] = max(3 - (-4), 4 - 9) = 7 > 0 → Alice leads by 7 (13 stones to 6)

Python

class Solution:
    def stoneGame(self, piles: List[int]) -> bool:
        n = len(piles)
        # dp[i][j] = best lead (own stones - opponent's) for the player to move on piles[i..j]
        dp = [[0] * n for _ in range(n)]
        for i in range(n):
            dp[i][i] = piles[i]                          # one pile left: take it
        for length in range(2, n + 1):                   # shorter rows first: a cell reads two shorter rows
            for i in range(n - length + 1):
                j = i + length - 1
                dp[i][j] = max(piles[i] - dp[i + 1][j],  # take the left pile; the opponent leads on i+1..j
                               piles[j] - dp[i][j - 1])  # take the right pile; the opponent leads on i..j-1
        return dp[0][n - 1] > 0                          # Alice moves first: she wins if she can lead
Time O(n²)Space O(n²)

n(n + 1) / 2 cells in the upper triangle, O(1) work each. A single list of length n is enough if you loop i from the right.

When to use: The general solution: it also handles an odd number of piles and ties (Predict the Winner), and it tells you the final score.

Watch it run

Number the piles 0 to n - 1. n is even, so in any row Alice faces (an even number of piles) the two ends have opposite parity, and in any row Bob faces (an odd number of piles, after Alice moved) both ends have the same parity. Suppose Alice decides to collect the even-indexed piles. Her first move takes pile 0. Bob then faces ends 1 and n - 1, both odd, so he must take an odd-indexed pile. Now Alice again faces ends of opposite parity and takes the even-indexed one, and so on. She takes exactly the even-indexed piles. She could just as well have started with the last pile and collected the odd-indexed ones.

The total is odd, so the even-indexed sum and the odd-indexed sum are different. Alice chooses the larger group and wins, whatever Bob does. Under this problem's guarantees the answer is always True.

Dry run

  1. [3, 2, 10, 4]: even-indexed piles 3 + 10 = 13, odd-indexed piles 2 + 4 = 6; 13 > 6, so Alice aims for the even positions
  2. Alice takes pile 0 (the 3); Bob faces [2, 10, 4], ends at indices 1 and 3, both odd, so he takes the 2 or the 4
  3. Alice then takes the 10 (index 2, even), and Bob is left with the last odd-indexed pile: 13 against 6

Common mistakes

  • Greedy: always taking the larger end. On [3, 2, 10, 4] Alice's greedy first move (the 4) ends with 7 stones against 12, while starting with the smaller 3 wins 13 to 6.
  • Adding the opponent's lead instead of subtracting it: piles[i] + dp[i + 1][j]. After your move the opponent is the player to move, so their lead is a lead against you.
  • Carrying the scores or the current player in the state. The row i..j already says whose turn it is, and the lead describes the player to move, so two indices are enough.
  • Filling the table row by row from i = 0. dp[i][j] needs dp[i + 1][j], which belongs to the next row, so that order reads cells that are not computed yet. Fill by increasing interval length.
  • Assuming return True holds in general. It needs an even number of piles and an odd total; for [1, 5, 1] the first player loses 2 to 5.

Python notes

  • for length in range(2, n + 1) with for i in range(n - length + 1) and j = i + length - 1 is the standard loop for interval DP: every sub-row is visited after the shorter sub-rows it needs.
  • Only the upper triangle (i <= j) of the table is used. The lower half stays 0 and is never read.
  • [[0] * n for _ in range(n)] builds n independent rows.
  • piles[0::2] and piles[1::2] are the even-indexed and odd-indexed piles. sum(piles[0::2]) and sum(piles[1::2]) always differ when the total is odd, which is why the parity strategy can never tie.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Predict the Winner LC 486 — any number of piles, and a tie counts as a win for player 1: the same interval table, and the parity shortcut no longer applies.
  • Stone Game II LC 1140 — a player takes 1 to 2M piles from the front, and M grows with the biggest take: the state gets a second number, dp[i][m].
  • Stone Game III LC 1406 — take 1, 2 or 3 piles from the front and the piles may be negative: a one-dimensional table of leads.
  • Stone Game VII LC 1690 — remove a pile from either end and score the sum of the stones that remain: the same interval table, with prefix sums for the score.
  • Return Alice's final score, not just the winner — the lead is her total minus Bob's and the two add up to the sum of all piles, so her score is (sum(piles) + dp[0][n - 1]) // 2.
  • Use O(n) memory — row i of the table needs only row i + 1: loop i from the right and keep one list of leads.
