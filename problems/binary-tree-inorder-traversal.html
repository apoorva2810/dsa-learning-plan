Binary Tree Inorder Traversal Easy 250

LeetCode #94 ↗
Status

List a binary tree's values in inorder: left subtree first, then the node, then the right subtree, at every node.

Problem

Given the root of a binary tree, return the inorder traversal of its values as a list.

Inorder means: at every node, first list everything in its left subtree, then the node's own value, then everything in its right subtree. The same rule applies inside each subtree, all the way down.

An empty tree gives an empty list. The recursive solution is short; the real exercise is doing it without recursion, with a stack you manage yourself.

Examples

Example 1
Input: root = [1, None, 2, 3]
Output: [1, 3, 2]
1 has no left subtree, so it comes first. Its right subtree is 2 with left child 3: 3 before 2.
Example 2
Input: root = [4, 2, 6, 1, 3, 5, 7]
Output: [1, 2, 3, 4, 5, 6, 7]
This tree is a binary search tree, and inorder lists a search tree's values in sorted order.
Example 3
Input: root = []
Output: []

Constraints

  • 0 <= number of nodes <= 100
  • -100 <= Node.val <= 100

Think first try before reading the solution

Say the rule at every node: everything on my left, then me, then everything on my right. Written as a function that calls itself on the two children, that sentence is already the recursive solution.
For the iterative version, ask what recursion remembers for you: the nodes you have entered but not yet recorded, in the order you must come back to them. That memory is a stack.
Two moves repeat. Slide left from the current node, pushing every node you pass. Then pop the top, record it, and slide left again starting from its right child. Stop when the stack is empty and there is no current node.

Key idea

Inorder is a rule about when a node is recorded: only after its whole left subtree, and before any of its right subtree. Recursion makes that effortless. inorder(node) calls inorder(node.left), appends node.val, then calls inorder(node.right). Python's call stack remembers every node that is waiting for its left side to finish.

To drop the recursion, keep that memory yourself. From the current node, walk left as far as you can, pushing each node: these nodes are waiting for their left subtrees. When you cannot go further left, the top of the stack has nothing unrecorded on its left, so pop it and record it. Its right subtree comes next, and everything in it must be recorded before the nodes still on the stack, so make the right child the new current node and slide left again. When the stack is empty and there is no current node, every node has been pushed once and popped once: O(n).

The stack holds one root-to-node path at a time, so it uses O(h) memory for a tree of height h. If even that is too much, Morris traversal stores the way back inside the tree itself with temporary links and uses O(1) extra space.

Approaches from the obvious one to the one you want in an interview

The definition of inorder is already a recursive procedure: to list a subtree, list its left subtree, then its root, then its right subtree. An empty subtree lists nothing.

Write inorder(node) exactly like that and let Python's call stack remember which nodes are still waiting for their left side to finish. Each node is visited once, so the time is O(n); the call stack is as deep as the tree is tall, O(h). Its only weakness is that depth: Python raises RecursionError after about 1000 nested calls.

Dry run

  1. root = [1, None, 2, 3], result = []
  2. inorder(1): left is None → record 1 → [1], then inorder(2)
  3. inorder(2): first inorder(3): left None → record 3 → [1, 3], right None, return
  4. back in inorder(2): record 2 → [1, 3, 2], right None, return
  5. inorder(1) has nothing left to do → [1, 3, 2]

Python

class Solution:
    def inorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        result = []

        def inorder(node):
            if node is None:                    # empty subtree: nothing to record
                return
            inorder(node.left)                  # 1. everything on the left
            result.append(node.val)             # 2. this node
            inorder(node.right)                 # 3. everything on the right

        inorder(root)
        return result
Time O(n)Space O(h)

Each node is entered once. The call stack holds one root-to-node path, h frames at most (n for a chain).

When to use: The natural first answer, and the shape of most tree recursions.

Watch it run

Replace the call stack with a list you control. The stack holds the nodes that are waiting for their left subtree to finish, nearest node on top.

  1. Slide left: from cur, push each node and move to its left child until there is none.
  2. Pop the top: nothing unrecorded is to its left, so record it.
  3. Set cur to the popped node's right child and go back to step 1. Its right subtree must be recorded before the nodes still on the stack, and the slide left from it does exactly that.

Stop when the stack is empty and cur is None. Each node is pushed once and popped once: O(n) time, O(h) stack. No recursion limit, and the same loop drives Kth Smallest in a BST, Validate BST and the BST Iterator.

Dry run

  1. root = [1, None, 2, 3], cur = 1, stack = []
  2. slide left: push 1; cur = None
  3. pop 1 → [1]; cur = 2
  4. slide left: push 2, push 3; cur = None
  5. pop 3 → [1, 3]; 3 has no right child, cur = None
  6. pop 2 → [1, 3, 2]; cur = None, stack empty → done

Python

class Solution:
    def inorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        result, stack = [], []
        cur = root
        while stack or cur:                     # nodes waiting, or a subtree still to enter
            while cur:                          # slide left, remembering every node passed
                stack.append(cur)
                cur = cur.left
            node = stack.pop()                  # its left side is finished: it is next
            result.append(node.val)
            cur = node.right                    # then everything in its right subtree
        return result
Time O(n)Space O(h)

Every node is pushed and popped exactly once. The stack never holds more than one root-to-node path.

When to use: The answer interviewers want after the recursive one; it is also the skeleton for the other BST traversal problems.

Watch it run

The stack only exists so that, after finishing a left subtree, we can find the way back to the node above it. Morris traversal stores that way back inside the tree: before going left from cur, find the rightmost node of its left subtree (the node recorded just before cur, its inorder predecessor) and point that node's empty right at cur.

When the walk later reaches that node and follows the link, it arrives back at cur for the second time. The link's presence says "the left subtree is done": remove it, record cur, and go right. Every edge is walked a constant number of times, so the time is still O(n), and no stack is needed. The tree is modified while the walk runs but is fully restored by the end.

Dry run

  1. root = [4, 2, 6, 1, 3, 5, 7], cur = 4
  2. 4 has a left child; its predecessor is 3 (rightmost in the left subtree). 3.right = 4 (thread), cur = 2
  3. 2 has a left child; predecessor 1. 1.right = 2, cur = 1
  4. 1 has no left child: record 1, cur = 1.right = 2 (the thread)
  5. 2 again: its predecessor 1 already points at 2 → left side done: unlink, record 2, cur = 3
  6. 3: no left child → record 3, follow the thread to 4; 4's predecessor 3 points at 4 → unlink, record 4, cur = 6 ...

Python

class Solution:
    def inorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        result = []
        cur = root
        while cur:
            if cur.left is None:                # nothing on the left: record, then go right
                result.append(cur.val)
                cur = cur.right
                continue
            pred = cur.left                     # inorder predecessor: rightmost node of the left subtree
            while pred.right and pred.right is not cur:
                pred = pred.right
            if pred.right is None:              # first visit: leave a thread back to cur, go left
                pred.right = cur
                cur = cur.left
            else:                               # second visit: the left subtree is done
                pred.right = None               # remove the thread, restoring the tree
                result.append(cur.val)
                cur = cur.right
        return result
Time O(n)Space O(1)

Each predecessor search walks edges that are walked at most three times in total, so the whole run is linear.

When to use: Only when memory is the constraint and the tree may be modified temporarily; it is rarely expected in an interview.

Common mistakes

  • Recording a node when you push it. That lists the node before its left subtree, which is preorder. In inorder a node is recorded when it is popped, after the slide left from it has finished.
  • Looping on while stack: alone. The stack is empty at the very start, and again after popping a node whose right subtree still has to be walked. Use while stack or cur:.
  • Forgetting cur = node.right after a pop. The right subtrees are then never entered, and the loop ends early with only the left spine recorded.
  • Building the answer with inorder(left) + [val] + inorder(right). Each + copies a list, so every value is copied once per ancestor: O(n · h) time on a chain. Append to one shared list instead.
  • Trusting recursion on deep trees. Python stops at about 1000 nested calls (RecursionError), so a chain of a few thousand nodes crashes the recursive version. The iterative version has no such limit.

Python notes

  • A plain list is the stack: append pushes and pop() removes the last item, both O(1).
  • while stack or cur: works because a non-empty list and a TreeNode are truthy, while [] and None are falsy.
  • The nested inorder function may call result.append(...) without nonlocal: it changes the list's contents, it does not rebind the name.
  • sys.getrecursionlimit() is 1000 by default. Raising it with sys.setrecursionlimit helps a little, but the iterative version is the real fix for deep trees.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Binary Tree Preorder Traversal LC 144 — record a node when it is pushed instead of when it is popped, and push the right child before the left so the left comes out first.
  • Binary Tree Postorder Traversal LC 145 — the hardest of the three without recursion: a node is recorded after both children, so either reverse a right-first preorder or remember the last node you finished.
  • Validate Binary Search Tree LC 98 — inorder of a search tree is sorted: keep the previous popped value and check each new one is larger.
  • Kth Smallest Element in a BST LC 230 — the same iterative walk, but stop at the k-th pop instead of collecting everything.
  • Binary Search Tree Iterator LC 173 — split the iterative walk into a class: next() pops one node and slides left from its right child, so the stack holds O(h) nodes between calls.
  • What if you may use no extra memory at all? — Morris traversal: before going left, link the rightmost node of the left subtree back to the current node, so you can find the way back without a stack, and remove the link on the way up.
