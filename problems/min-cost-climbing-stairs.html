Min Cost Climbing Stairs Easy

LeetCode #746 ↗
Status

Reach the top of a staircase as cheaply as possible when each stair charges a price to climb from it.

Problem

You are given a list cost where cost[i] is the price of stair i. When you stand on stair i you may pay cost[i] and climb 1 or 2 stairs.

You may begin on stair 0 or stair 1 without paying anything to get there. The top is just past the last stair (position len(cost)). Return the minimum total price to reach the top.

Examples

Example 1
Input: cost = [10, 15, 20]
Output: 15
Start on stair 1, pay 15 and climb 2 stairs to the top.
Example 2
Input: cost = [1, 100, 1, 1, 1, 100, 1, 1, 100, 1]
Output: 6
Step only on the stairs that cost 1: 0, 2, 4, 6, 7, 9, then the top.
Example 3
Input: cost = [1, 2, 10]
Output: 2
Starting on the cheaper stair 0 leads to 1 + 2 = 3; starting on stair 1 and jumping to the top costs 2.

Constraints

  • 2 <= len(cost) <= 1000
  • 0 <= cost[i] <= 999

Think first try before reading the solution

This is Climbing Stairs with prices. To stand on stair i, which stairs could you have just left?
Let dp[i] be the cheapest total to stand on stair i. You arrive from i - 1 (paying cost[i - 1]) or from i - 2 (paying cost[i - 2]): take the cheaper. What are dp[0] and dp[1]?
dp[0] = dp[1] = 0 because you may start there for free, and the answer is dp[len(cost)]. Each cell reads only the two before it, so two variables suffice.

Key idea

The structure is the same as Climbing Stairs: the last move onto stair i came from stair i - 1 or i - 2. Instead of adding the number of ways, take the cheaper of the two histories.

Define dp[i] = the cheapest total paid to stand on stair i (the price of stair i itself is paid only when you leave it). You may start on stair 0 or 1 for free, so dp[0] = dp[1] = 0. For every other stair,

dp[i] = min(dp[i - 1] + cost[i - 1], dp[i - 2] + cost[i - 2])

and the answer is dp[n] where n = len(cost) is the top.

Picking the cheapest stair in reach at each move (greedy) is not enough: on [1, 2, 10] it starts on stair 0 and pays 3, while starting on stair 1 pays 2. DP compares complete histories, so it cannot be fooled by a cheap step that leads somewhere expensive.

Approaches from the obvious one to the one you want in an interview

Write the recurrence as a function. reach(i) = cheapest total to stand on stair i:

  • reach(0) = reach(1) = 0 (free starting stairs);
  • otherwise reach(i) = min(reach(i - 1) + cost[i - 1], reach(i - 2) + cost[i - 2]).

The answer is reach(n). Like plain Climbing Stairs recursion, every call branches twice and the same stairs are solved again and again, so the running time grows exponentially with the number of stairs.

Dry run

  1. cost = [10, 15, 20], answer reach(3)
  2. reach(3) = min(reach(2) + 20, reach(1) + 15)
  3. reach(2) = min(reach(1) + 15, reach(0) + 10) = min(15, 10) = 10
  4. reach(3) = min(10 + 20, 0 + 15) = 15

Python

class Solution:
    def minCostClimbingStairs(self, cost: List[int]) -> int:
        def reach(i: int) -> int:
            """Cheapest total paid to stand on stair i (the top is stair len(cost))."""
            if i <= 1:                                     # stairs 0 and 1 are free starting points
                return 0
            from_one_below = reach(i - 1) + cost[i - 1]    # pay for stair i - 1, climb 1
            from_two_below = reach(i - 2) + cost[i - 2]    # pay for stair i - 2, climb 2
            return min(from_one_below, from_two_below)

        return reach(len(cost))
Time O(φⁿ) ≈ O(1.62ⁿ)Space O(n)

Two recursive calls per stair with no memory of earlier results; the call stack is n deep.

When to use: Only to derive the recurrence; it cannot handle 1000 stairs.

Add @cache to reach. There are only n + 1 stairs, so only n + 1 different calls ever do real work; every repeated call becomes a dictionary lookup. Time drops to O(n).

The recursion still starts at the top and goes down to stair 1, which is n frames deep: for the largest inputs that is right at Python's default recursion limit.

Python

class Solution:
    def minCostClimbingStairs(self, cost: List[int]) -> int:
        @cache                                             # each stair's answer is computed once
        def reach(i: int) -> int:
            if i <= 1:
                return 0
            return min(reach(i - 1) + cost[i - 1], reach(i - 2) + cost[i - 2])

        return reach(len(cost))
Time O(n)Space O(n)

n + 1 states with O(1) work each; the cache and the call stack hold O(n) entries.

When to use: A quick, correct first version when the recursion is what you thought of first.

Fill dp[0..n] from the bottom. dp[0] = dp[1] = 0; then each later cell takes the cheaper of its two possible previous stairs. Cell i only reads cells i - 1 and i - 2, which are already final when the loop runs left to right. The answer is the last cell, dp[n], which stands for the top.

Dry run

  1. cost = [10, 15, 20], dp = [0, 0, ?, ?]
  2. dp[2] = min(dp[1] + 15, dp[0] + 10) = min(15, 10) = 10
  3. dp[3] = min(dp[2] + 20, dp[1] + 15) = min(30, 15) = 15
  4. answer dp[3] = 15

Python

class Solution:
    def minCostClimbingStairs(self, cost: List[int]) -> int:
        n = len(cost)
        dp = [0] * (n + 1)          # dp[i] = cheapest total to stand on stair i; dp[n] is the top
        # dp[0] = dp[1] = 0 already: both are free starting stairs
        for i in range(2, n + 1):
            from_one_below = dp[i - 1] + cost[i - 1]
            from_two_below = dp[i - 2] + cost[i - 2]
            dp[i] = min(from_one_below, from_two_below)
        return dp[n]
Time O(n)Space O(n)

One pass over n + 1 cells.

When to use: When you want to inspect the table, or reconstruct which stairs were used.

Only the previous two cells are ever read, so replace the list by two_back and one_back and shift them after each stair. Same recurrence, same O(n) time, O(1) memory.

Dry run

  1. cost = [10, 15, 20]: two_back, one_back = 0, 0
  2. stair 2: min(0 + 15, 0 + 10) = 10 → (0, 10)
  3. top: min(10 + 20, 0 + 15) = 15 → (10, 15); answer 15

Python

class Solution:
    def minCostClimbingStairs(self, cost: List[int]) -> int:
        two_back, one_back = 0, 0   # cheapest totals to stand on stairs i - 2 and i - 1 (start: 0 and 1)
        for i in range(2, len(cost) + 1):
            current = min(one_back + cost[i - 1], two_back + cost[i - 2])
            two_back, one_back = one_back, current
        return one_back             # after the loop, "i - 1" is the top
Time O(n)Space O(1)

One pass, two integers of state.

When to use: The interview answer: derive it from the table and say which cells were never read again.

Common mistakes

  • Returning dp[n - 1]: that is the cheapest way to stand on the last stair, but you still have to pay for a stair to leave it. The top is position n, one past the end.
  • Charging for the stair you land on instead of the stair you leave. With this state, a move from stair j adds cost[j]; arriving at the top costs nothing extra.
  • Setting dp[1] = cost[0]: you may start on stair 1 for free, so dp[1] = 0.
  • Greedy choices (always the cheaper next stair, or the cheaper start) fail on inputs such as [1, 2, 10].

Python notes

  • @cache on a helper defined inside the method memoises it per call; the helper reads cost from the enclosing scope, so the cache key is just the stair number.
  • The top-down version recurses about len(cost) frames deep. With 1000 stairs that hits Python's default recursion limit of 1000 and raises RecursionError unless you call sys.setrecursionlimit. The bottom-up versions have no such limit.
  • min(a, b) with two named candidates (from_one_below, from_two_below) reads better than a nested expression and costs nothing extra.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Climbing Stairs LC 70 — count the ways instead of the cheapest climb: min becomes + and the prices disappear.
  • House Robber LC 198 — the same two-back recurrence, but the choice is whether to take a value, and you maximise.
  • Minimum Cost For Tickets LC 983 — look back 1, 7 or 30 days instead of 1 or 2 stairs: dp[d] = min(dp[d-1] + c1, dp[d-7] + c7, dp[d-30] + c30).
  • Jump Game VI LC 1696 — jumps of up to k positions: the max over the last k cells needs a monotonic deque to stay O(n).
  • Return the stairs you step on — store which option won at every stair (or recompute it walking back from the top) and follow those choices backwards.
