Sum of All Subsets XOR Total Easy 250

LeetCode #1863 ↗
Status

Add up the XOR of every subset of a small list of positive integers.

Problem

You are given a list nums of positive integers. The XOR total of a list is the bitwise XOR of all its elements (a ^ b ^ c ...); the XOR total of the empty list is 0.

Look at every subset of nums (every way of keeping some of its elements, none of them, or all of them), work out the XOR total of each subset, and return the sum of all those XOR totals.

  • Subsets are told apart by position, not by value: if two elements have the same value, keeping one or keeping the other gives two different subsets, and both count.
  • A list of n elements has 2ⁿ subsets, including the empty one.

Examples

Example 1
Input: nums = [1, 3]
Output: 6
The four subsets are [] (XOR total 0), [1] (1), [3] (3) and [1, 3] (1 ^ 3 = 2). 0 + 1 + 3 + 2 = 6.
Example 2
Input: nums = [5, 1, 6]
Output: 28
Eight subsets with XOR totals 0, 5, 1, 6, 5 ^ 1 = 4, 5 ^ 6 = 3, 1 ^ 6 = 7 and 5 ^ 1 ^ 6 = 2. Their sum is 28.
Example 3
Input: nums = [2, 4, 4]
Output: 24
The two 4s are different elements, so [4] and [2, 4] each appear twice. The XOR totals are 0, 2, 4, 4, 6, 6, 4 ^ 4 = 0 and 2 ^ 4 ^ 4 = 2, which add up to 24.

Constraints

  • 1 <= len(nums) <= 12
  • 1 <= nums[i] <= 20

Think first try before reading the solution

At most 12 numbers means at most 2¹² = 4096 subsets. Is it a problem to simply visit every one of them and add up what you find?
Build the subsets with take / skip recursion and carry the XOR along: XOR-ing in nums[i] is the choose step. Which single operation undoes it, so that nothing has to be copied?
Look at one bit position across all subsets. Suppose nums[j] has that bit. Pair every subset that leaves nums[j] out with the same subset plus nums[j]: exactly one of the two has the bit in its XOR total. So in how many of the 2ⁿ XOR totals is that bit set?

Key idea

The limits are tiny on purpose: 12 numbers give 2¹² = 4096 subsets, so visiting every subset is allowed, and the only question is how to build them without wasting work. The take / skip recursion from Subsets does it: dfs(i) decides whether nums[i] is in the current subset, and after n decisions one subset is complete. Instead of copying a list at each leaf, carry one integer running, the XOR of the numbers taken so far. Taking nums[i] is running ^= nums[i], and because XOR is its own inverse (a ^ x ^ x == a), doing the same operation again is the un-choose. Every call costs O(1) and the whole search is O(2ⁿ).

There is also a way to skip the search. XOR works bit by bit, so look at a single bit position b over all subsets. If no number has bit b, no XOR total has it either. If some number nums[j] has it, pair up the subsets: each subset without nums[j] goes with the same subset plus nums[j]. Adding nums[j] flips bit b of the XOR total, so exactly one subset in each pair has the bit set. That is exactly half of the 2ⁿ subsets, 2ⁿ⁻¹ of them, and bit b contributes 2ᵇ × 2ⁿ⁻¹ to the answer.

Add that over every bit that appears somewhere in nums, and those bits together are exactly the bitwise OR of all the numbers. The answer is (nums[0] | nums[1] | ... ) × 2ⁿ⁻¹, computed in one pass over the list with no subsets at all.

Approaches from the obvious one to the one you want in an interview

A list of n numbers has 2ⁿ subsets, and the integers 0, 1, …, 2ⁿ − 1 are exactly 2ⁿ bit patterns of n bits. Let bit i of mask say whether nums[i] belongs to the subset. For each mask, XOR together the chosen numbers and add the result to a running sum.

Each mask costs n bit tests, so the total is O(n · 2ⁿ). With n ≤ 12 that is about 50,000 cheap operations, which is why this problem is rated Easy: the point is to be comfortable enumerating subsets, not to avoid it.

The weakness is that a subset's XOR total is rebuilt from scratch for every mask, although neighbouring subsets share almost all of their numbers. Backtracking fixes exactly that.

Dry run

  1. nums = [1, 3]: two bits, masks 0 to 3.
  2. mask = 0 (00): [], XOR total 0. total = 0.
  3. mask = 1 (01): [1], XOR total 1. total = 1.
  4. mask = 2 (10): [3], XOR total 3. total = 4.
  5. mask = 3 (11): [1, 3], XOR total 1 ^ 3 = 2. total = 6.

Python

class Solution:
    def subsetXORSum(self, nums: List[int]) -> int:
        n = len(nums)
        total = 0
        for mask in range(1 << n):               # 2^n masks: one per subset
            xor_total = 0
            for i in range(n):
                if (mask >> i) & 1:              # bit i is set: nums[i] is in this subset
                    xor_total ^= nums[i]
            total += xor_total
        return total
Time O(n · 2ⁿ)Space O(1)

2ⁿ masks, each tested against n bits. Only two integers are stored.

When to use: Fine within the limits and quick to write; it also works for any other function of a subset.

Watch it run

Walk through the numbers left to right and decide each one: take it or skip it. dfs(i) means "the numbers before index i are decided and running is the XOR of the ones taken". When i == len(nums) a subset is complete, so add running to the total.

Taking nums[i] is running ^= nums[i] followed by dfs(i + 1). The un-choose is the same statement again: XOR is its own inverse, so running ^ x ^ x is running. Then dfs(i + 1) once more for the skip branch. Nothing is copied and no list is kept; each call does O(1) work.

The tree has 2ⁿ leaves and 2ⁿ⁺¹ − 1 calls in total, so the time is O(2ⁿ), an n-fold improvement on the bitmask loop, and the recursion is only n deep. This is the same tree as Subsets, with the per-leaf copy replaced by one integer.

Dry run

  1. nums = [1, 3], running = 0, total = 0. dfs(0) takes 1: running = 1. dfs(1) takes 3: running = 1 ^ 3 = 2.
  2. dfs(2): subset [1, 3] complete, total = 0 + 2 = 2.
  3. Back in dfs(1): un-choose 3, running = 2 ^ 3 = 1; skip it → dfs(2) adds 1: total = 3.
  4. Back in dfs(0): un-choose 1, running = 0; skip it. dfs(1) takes 3 → dfs(2) adds 3: total = 6; un-choose, skip → dfs(2) adds 0.
  5. Four leaves, total = 6.

Python

class Solution:
    def subsetXORSum(self, nums: List[int]) -> int:
        total = 0
        running = 0                              # XOR of the numbers taken so far

        def dfs(i: int) -> None:
            nonlocal total, running
            if i == len(nums):                   # every number is decided: one subset is complete
                total += running
                return
            running ^= nums[i]                   # choose: take nums[i] into the subset
            dfs(i + 1)                           # explore the subsets that contain it ...
            running ^= nums[i]                   # un-choose: XOR-ing again cancels it
            dfs(i + 1)                           # ... and the subsets that do not

        dfs(0)
        return total
Time O(2ⁿ)Space O(n)

2ⁿ⁺¹ − 1 calls of O(1) each. The recursion is n deep and there is no list to copy.

When to use: The backtracking pattern this topic is about: state carried down and undone on the way back, with O(1) per call.

Watch it run

XOR works bit by bit, so sum the answer one bit position at a time. Fix a position b. If no number has bit b, no XOR total has it. If some nums[j] has it, pair the subsets up: each subset without nums[j] goes with the same subset plus nums[j]. Adding nums[j] flips bit b of the XOR total, so exactly one subset in every pair has the bit set. That is half of all subsets, 2ⁿ⁻¹ of them, and bit b contributes 2ᵇ × 2ⁿ⁻¹ to the sum.

The bits that appear in at least one number are exactly the bits of nums[0] | nums[1] | …. Adding 2ᵇ × 2ⁿ⁻¹ over those bits gives or_all × 2ⁿ⁻¹, so one pass computing the OR is the whole algorithm: O(n) time, O(1) space, no subsets at all.

Dry run

  1. nums = [1, 3]: or_all = 1 | 3 = 3 (11 in binary), n = 2, so each present bit is set in 2¹ = 2 XOR totals.
  2. Bit 0 (value 1): set in 2 totals → contributes 1 × 2 = 2.
  3. Bit 1 (value 2): set in 2 totals → contributes 2 × 2 = 4.
  4. Answer 3 × 2 = 6, the same as 3 << 1.

Python

class Solution:
    def subsetXORSum(self, nums: List[int]) -> int:
        or_all = 0
        for x in nums:
            or_all |= x                          # every bit that appears in at least one number
        return or_all << (len(nums) - 1)         # each such bit is set in exactly half of the 2^n XOR totals
Time O(n)Space O(1)

One pass to OR the numbers and one shift.

When to use: When you spot the pairing argument. It only works because the quantity is XOR; for most other subset questions the search stays.

Common mistakes

  • Accumulating with + instead of ^. That computes the sum of all subset sums, which happens to agree with the XOR version whenever no two numbers share a bit ([1, 2] gives 6 either way), so a small test can hide the bug; [1, 3] separates them (8 versus 6).
  • Writing 2 ^ (n - 1) for 2 to the power n − 1. In Python ^ is XOR, so 2 ^ 2 is 0. Use 1 << (n - 1) or 2 ** (n - 1).
  • Forgetting the second running ^= nums[i] when running is shared state. The skip branch then still contains nums[i], so every total from that branch is wrong. If you pass the XOR down as an argument instead (dfs(i + 1, running ^ nums[i])) each call owns its own copy and no undo is needed.
  • Testing a bit with mask & (1 << i) == 1. == binds tighter than &, and the AND gives 2 ** i, not 1, so only bit 0 ever counts. Write (mask >> i) & 1.
  • Removing repeated values first, for example with set(nums). Subsets are counted by position, so [2, 4, 4] has eight subsets and the answer is 24; after set() only four remain and you get 12.

Python notes

  • ^ is XOR, | is OR, & is AND and ** is power. 2 ^ 3 is 1, not 8.
  • 1 << k is 2ᵏ and x << k is x × 2ᵏ, so or_all << (n - 1) is the formula in one expression.
  • functools.reduce(operator.xor, values, 0) XORs a whole list; reduce(operator.or_, nums) ORs it.
  • bin(13) is '0b1101', f"{13:05b}" is '01101', and 13 .bit_length() is 4: handy for checking which bits a number has.
  • Rebinding an integer inside a nested function (total += running) needs nonlocal total; calling .append on a list does not, because that mutates an object rather than rebinding a name.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Subsets LC 78 — return the subsets themselves instead of summing a value over them: the same take / skip tree, but each leaf copies path, so the cost becomes O(n · 2ⁿ) and no bit trick can replace the search.
  • Single Number LC 136 — the same XOR property (x ^ x == 0) used the other way round: XOR the whole list and every paired value cancels, leaving the number that appears once.
  • Count Number of Maximum Bitwise-OR Subsets LC 2044 — count the subsets whose OR equals the OR of the whole list: the same take / skip enumeration carrying a running OR (n <= 16), or a DP over the at most 2¹⁷ possible OR values.
  • Find XOR Sum of All Pairs Bitwise AND LC 1835 — another identity instead of an enumeration: the XOR over all pairs of a & b collapses to (XOR of arr1) & (XOR of arr2), so the n × m pairs are never visited.
  • What if you sum the subset sums instead? — each element belongs to exactly half of the subsets, so the answer is sum(nums) × 2ⁿ⁻¹: the pairing argument still works, it is just applied to plain addition.
  • What if equal subsets should count once? — [2, 4, 4] would then have six distinct subsets, not eight. Sort and skip a value equal to the previous one at the same depth, exactly as Subsets II does, and the formula no longer applies.
