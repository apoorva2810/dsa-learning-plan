Valid Parentheses Easy

LeetCode #20 ↗
Status

Decide whether every opening bracket is closed by the right bracket in the right order.

Problem

Given a string s containing only the characters (, ), {, }, [ and ], decide whether it is valid:

  • every opening bracket is closed by a bracket of the same type,
  • brackets close in the correct order (the most recently opened bracket must close first),
  • every closing bracket has a matching opening bracket.

An empty string is valid.

Examples

Example 1
Input: s = "()[]{}"
Output: true
Example 2
Input: s = "([)]"
Output: false
[ is opened after (, so it must close before ) does.
Example 3
Input: s = "{[]}"
Output: true
Nested brackets are fine as long as the innermost closes first.
Example 4
Input: s = "(("
Output: false
Two brackets are never closed.

Constraints

  • 1 <= len(s) <= 10^4
  • s consists only of ()[]{}

Think first try before reading the solution

When you meet a closing bracket, which opening bracket must it match? Not just any earlier one.
The bracket that must close next is always the most recently opened one that is still open. Which data structure gives you 'most recent' first?
Push opening brackets on a stack. On a closing bracket, pop and compare. At the end the stack must be empty.

Key idea

Reading left to right, an opening bracket is a promise: "I will be closed later". Promises are kept in reverse order: the last one made must be fulfilled first (([)] breaks this). A stack is exactly a list where the last thing in is the first thing out.

So: push every opener. For every closer, the top of the stack must be its matching opener; pop it. If the stack is empty when you need to pop, or the top does not match, the string is invalid. If anything is left on the stack at the end, some promise was never kept.

Approaches from the obvious one to the one you want in an interview

A valid string always contains an adjacent pair like (), [] or {} somewhere (the innermost pair). Delete it and the rest is still valid. Keep deleting until nothing changes; the string is valid exactly when it becomes empty.

It is correct, but each replace scans the whole string and you may need n/2 rounds, so it is O(n²). It is worth knowing because it shows why the order matters: ([)] has no adjacent pair at all.

Dry run

  1. "{[]}" → delete [] → "{}" → delete {} → "" → valid.
  2. "([)]" → no (), [] or {} adjacent anywhere → stuck with a non-empty string → invalid.

Python

class Solution:
    def isValid(self, s: str) -> bool:
        while True:
            shorter = s.replace("()", "").replace("[]", "").replace("{}", "")
            if shorter == s:            # nothing left to delete
                return s == ""
            s = shorter
Time O(n²)Space O(n)

Up to n/2 rounds, each scanning the string; replace builds new strings.

When to use: A quick mental check, never in production or an interview.

Keep a stack of brackets that are open and waiting to be closed.

  1. Opener → push.
  2. Closer → the stack must be non-empty and its top must be the matching opener; pop it. Otherwise invalid.
  3. After the loop the stack must be empty.

Every character is pushed and popped at most once, so the whole scan is O(n). The stack can hold at most n characters (all openers), so O(n) extra space in the worst case.

Dry run

  1. s = "{[]}", stack []
  2. { → push → ['{']
  3. [ → push → ['{', '[']
  4. ] → top is [, matches → pop → ['{']
  5. } → top is {, matches → pop → []
  6. end: stack empty → True

Python

class Solution:
    def isValid(self, s: str) -> bool:
        pairs = {")": "(", "]": "[", "}": "{"}   # closer -> opener it needs
        stack = []
        for c in s:
            if c in pairs:                         # a closer
                if not stack or stack[-1] != pairs[c]:
                    return False
                stack.pop()
            else:                                  # an opener
                stack.append(c)
        return not stack                           # nothing left open
Time O(n)Space O(n)

One pass; each character is pushed/popped at most once.

When to use: Always. This is the canonical stack problem.

Common mistakes

  • Forgetting the final return not stack check: "((" has no mismatches but is still invalid.
  • Popping from an empty stack on a stray closer like ")". Check emptiness first (or push a sentinel).
  • Counting brackets per type (3 opens, 3 closes) is not enough: "([)]" has balanced counts but the wrong order.
  • Using list.pop(0) (front removal) instead of pop() turns the stack into a queue and makes each pop O(n).

Python notes

  • A Python list is a stack: append pushes, pop() pops the last item, stack[-1] peeks. All O(1).
  • A dictionary {')': '(', ']': '[', '}': '{'} maps each closer to the opener it needs; c in pairs tests "is this a closer".
  • not stack is True for an empty list: a tidy way to write the final check.
