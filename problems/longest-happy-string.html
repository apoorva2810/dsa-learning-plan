Longest Happy String Medium 250

LeetCode #1405 ↗
Status

Using at most a copies of 'a', b of 'b' and c of 'c', build the longest string that never has three equal letters in a row.

Problem

A string is happy when it contains none of "aaa", "bbb" or "ccc": two equal letters in a row are fine, three are not.

You are given three integers a, b and c. Build a happy string that uses at most a letters 'a', at most b letters 'b' and at most c letters 'c', and is as long as possible. You do not have to use every letter. Return any longest happy string.

Examples

Example 1
Input: a = 1, b = 1, c = 7
Output: "ccaccbcc"
The c's come in runs of two, and the single a and b break the runs. "ccbccacc" is also accepted. One c stays unused.
Example 2
Input: a = 7, b = 1, c = 0
Output: "aabaa"
Only one b is available to break up the a's, so at most two runs of two a's fit. Three a's are left over.
Example 3
Input: a = 0, b = 0, c = 5
Output: "cc"
With a single letter type the string stops at two: a third c in a row is not allowed.

Constraints

  • 0 <= a, b, c <= 100
  • a + b + c > 0

Think first try before reading the solution

Which letter is the hardest to fit in? The one with the most copies left: it needs the most run breaks. Write it whenever the rules allow.
The rules forbid it only when the last two letters written are already that letter. Then write one copy of the second most common letter: that breaks the run, and the top letter is allowed again.
Stop when the top letter would make a run of three and no other letter is left. A max-heap of (-count, letter) gives the top letter and the runner-up in O(log 3).

Key idea

The letter with the most copies left is the one that risks being left over, so spend it first: write the most common letter, unless the last two letters already are that letter; then write one copy of the second most common letter instead. One copy is enough to break the run, and it keeps the rarer letters in reserve for the next break.

The greedy string is as long as any happy string can be. It only stops when the top letter would make a run of three and no other letter is left; at that point every remaining copy is the same letter, and no arrangement of the string so far could absorb another one. Letters that are left over at that moment can never be placed, which is why the problem lets you leave letters unused.

A max-heap of (-count, letter) keeps the top letter at the root and the runner-up one pop away. With three letter types the heap is tiny, so the alternative below simply sorts three counters each round; the heap version is the one that scales to more letter types.

Approaches from the obvious one to the one you want in an interview

Grow a string one letter at a time. At each step try a, b and c: skip a letter that has no copies left or that would make a run of three; otherwise append it and keep growing. Remember the longest string seen.

This explores every happy string that can be built, so it certainly finds a longest one. But the number of happy strings grows roughly like 2.7ⁿ with the length, so even a = b = c = 20 is hopeless. It is useful only to convince yourself what "longest" means on tiny inputs.

Dry run

  1. a = 1, b = 1, c = 7: start with "", try a → "a", then "ab", "abc", "abcc", stuck (c would make "ccc", a and b are used up): length 4
  2. back up and try other letters … eventually "ccaccbcc" and "ccbccacc" of length 8 are found; nothing longer exists

Python

class Solution:
    def longestDiverseString(self, a: int, b: int, c: int) -> str:
        left = {"a": a, "b": b, "c": c}
        best = [""]

        def extend(s: str) -> None:
            if len(s) > len(best[0]):
                best[0] = s
            for ch in "abc":
                if left[ch] == 0 or s[-2:] == ch * 2:   # none left, or it would make a run of three
                    continue
                left[ch] -= 1
                extend(s + ch)
                left[ch] += 1                      # undo, so the other letters can be tried here

        extend("")
        return best[0]
Time O(3ⁿ)Space O(n)

n = a + b + c; up to three choices at every position, and the recursion is as deep as the string.

When to use: Only to explore tiny inputs by hand; never for real sizes.

Put (-count, letter) for every letter with copies into a heap, so the root is the letter with the most copies left. Then repeat:

  1. Pop the root. If the last two letters written are not both that letter, write it and push it back with one copy fewer.
  2. Otherwise a third copy would make a run of three. If the heap is now empty, stop: nothing can break the run. Otherwise pop the runner-up, write one copy of it, push it back with one copy fewer, and push the top letter back untouched; it is allowed again next round.

Each letter written costs at most two pops and two pushes on a heap of at most three entries.

Dry run

  1. a = 1, b = 1, c = 7: heap {c×7, a×1, b×1}
  2. write c, write c → "cc"; c would make "ccc" → write the runner-up a → "cca"; c goes back
  3. write c, write c → "ccacc"; runner-up b → "ccaccb"
  4. write c, write c → "ccaccbcc"; c would make "ccc" and the heap is empty → stop (one c unused)

Python

class Solution:
    def longestDiverseString(self, a: int, b: int, c: int) -> str:
        heap = [(-n, ch) for n, ch in ((a, "a"), (b, "b"), (c, "c")) if n > 0]   # max-heap by copies left
        heapq.heapify(heap)
        out = []
        while heap:
            count, ch = heapq.heappop(heap)                  # the letter with the most copies left
            if len(out) >= 2 and out[-1] == out[-2] == ch:   # a third copy in a row is not allowed
                if not heap:                                 # no other letter can break the run: done
                    break
                count2, ch2 = heapq.heappop(heap)            # one copy of the runner-up breaks the run
                out.append(ch2)
                if count2 + 1 < 0:
                    heapq.heappush(heap, (count2 + 1, ch2))
                heapq.heappush(heap, (count, ch))            # the top letter goes back untouched
            else:
                out.append(ch)
                if count + 1 < 0:
                    heapq.heappush(heap, (count + 1, ch))    # one copy fewer (-7 + 1 = -6)
        return "".join(out)
Time O(n log k)Space O(n)

n = a + b + c letters written at most, each with O(1) heap operations on k = 3 entries; O(n) for the output.

When to use: The interview answer, and the version that still works with 26 letter types or a longer allowed run.

Watch it run

With only three letter types, the heap is overkill: each round, sort the letters that still have copies by count, most copies first, and write the first one that does not make a run of three. If none can be written, stop.

The runner-up is at most the second entry of that list, so this is exactly the same greedy rule; sorting three items is constant time. It is shorter to write, but it does not scale to many letter types the way the heap does.

Python

class Solution:
    def longestDiverseString(self, a: int, b: int, c: int) -> str:
        left = {"a": a, "b": b, "c": c}
        out = []
        while True:
            # letters with copies left, most copies first
            order = sorted((ch for ch in "abc" if left[ch] > 0), key=lambda ch: -left[ch])
            for ch in order:
                if len(out) >= 2 and out[-1] == out[-2] == ch:
                    continue                           # a third copy in a row: try the next letter
                out.append(ch)
                left[ch] -= 1
                break
            else:                                      # no letter could be written: the string is complete
                return "".join(out)
Time O(n)Space O(n)

Each of the at most n rounds sorts three items and writes one letter.

When to use: When there are exactly three letter types and you want the shortest code.

Common mistakes

  • Stopping as soon as the top letter would make a run of three, instead of trying the runner-up: example 1 would end at "cc".
  • Switching to the runner-up too early, after a run of one: a = 7, b = 1 then gives a b a a and stops at 4 letters; the run of two is allowed and gives "aabaa".
  • Forgetting to push the top letter back into the heap after writing the runner-up: its copies vanish and the string ends early.
  • Checking the letter's count instead of the last two letters written: the rule is about the string, not the pile.
  • Checking only out[-1] == ch (no two in a row): that solves Reorganize String, not this problem, and gives a shorter string.
  • Expecting every letter to be used: when the heap empties the string is complete, but when the run rule stops you, copies stay unused.

Python notes

  • heapq is a min-heap, so store (-count, letter); count + 1 on a negated count means one copy fewer (-7 + 1 = -6).
  • out[-1] == out[-2] == ch chains the comparison: both of the last two letters equal ch. Guard it with len(out) >= 2.
  • Build the answer in a list and "".join it once; repeated string += copies the whole string each time.
  • sorted(..., key=lambda ch: -left[ch]) puts the most copies first; sorted is stable, so ties keep alphabetical order.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Reorganize String LC 767 — runs of even two are forbidden and every letter must be used: hold the last letter out of the heap for one round and return "" when stuck.
  • Task Scheduler LC 621 — a cooldown of n between equal letters and idle slots allowed: the same max-heap of counts plus a cooling queue, counting intervals.
  • Rearrange String k Distance Apart LC 358 — equal letters must be at least k apart: hold each used letter out for k - 1 rounds in a queue.
  • What if runs of up to k equal letters were allowed? — track the current run length; take the runner-up when the top letter's run has reached k. The heap code barely changes.
  • What if there were 26 letter types? — the three-counter version becomes a sort per round; the heap version stays O(n log 26) with exactly the same logic.
  • Count the happy strings of maximum length instead of building one — dynamic programming over (a, b, c, last letter, run length); greedy only finds one string.
