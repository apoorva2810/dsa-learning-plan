Pow(x, n) Medium

LeetCode #50 ↗
Status

Compute x raised to the power n for a decimal x and an integer n, in about log n multiplications instead of n.

Problem

Implement pow(x, n): return x raised to the integer power n.

  • x is a decimal number (a float). n is an integer that can be negative, zero or positive, and as large as about two billion.
  • x to the power 0 is 1, and x to the power -n is 1 / (x to the power n).
  • Answers are accepted within a small tolerance, so tiny rounding differences do not matter.

Examples

Example 1
Input: x = 2.0, n = 10
Output: 1024.0
2 multiplied by itself ten times.
Example 2
Input: x = 2.1, n = 3
Output: 9.261
2.1 × 2.1 × 2.1.
Example 3
Input: x = 2.0, n = -2
Output: 0.25
2 to the power -2 is 1 / (2 × 2) = 1/4.

Constraints

  • -100.0 < x < 100.0
  • -2^31 <= n <= 2^31 - 1
  • n is an integer
  • either x is not 0, or n > 0
  • -10^4 <= x^n <= 10^4

Think first try before reading the solution

Multiplying x by itself n times takes n multiplications; for n = 2³¹ − 1 that is two billion. Where is the repeated work? Notice that x¹⁰ is just x⁵ times x⁵.
If you know half = x^(n // 2), then x^n is half * half when n is even, and half * half * x when n is odd. Each call halves the exponent. How many calls does that take?
Deal with a negative exponent once, at the start: x^(-n) = (1/x)^n. After that you only ever work with an exponent of 0 or more.
The loop version reads n in binary. 13 is 1101 in binary, which is 8 + 4 + 1, so x¹³ = x⁸ · x⁴ · x¹. Keep squaring x (x, x², x⁴, x⁸, …) and multiply the square into the answer whenever the current bit of n is 1.

Key idea

Multiplying one x at a time wastes effort. To get x¹⁰ you do not need x², x³, x⁴ … one by one, because x¹⁰ is x⁵ squared, and x⁵ is x² squared times one more x. Halving the exponent does the same job in a handful of steps.

The rule: x^n = (x^(n/2))² when n is even, and x^n = x · (x^((n-1)/2))² when n is odd. Each step cuts the exponent roughly in half, so after about log₂ n halvings it reaches 0, and x⁰ = 1. For n = 2³¹ − 1 that is 31 levels instead of two billion multiplications. The key detail is to compute the half once and reuse it: calling power(x, n // 2) twice would double the work at every level and bring you back to n multiplications.

Seen from the other end, this is binary. Write n in base 2 (13 is 1101). Then x^n is the product of x^(2^k) over the 1-bits of n. Keep a running base that you square every round (x, x², x⁴, x⁸ …) and multiply it into result whenever the lowest bit of n is 1, then shift n right by one bit. That is a loop with no recursion and O(1) memory.

A negative exponent is handled once at the start: x^(-n) = (1/x)^n, so replace x by 1 / x and n by -n.

Approaches from the obvious one to the one you want in an interview

Do what the definition says: start from 1 and multiply by x, |n| times. For a negative n, take 1 / result at the end.

It is correct, but |n| can be about two billion. A Python loop manages roughly ten million multiplications a second, so n = 2³¹ − 1 takes minutes and would be cut off by any time limit. It also repeats work: it computes x², x³, x⁴, … although x⁴ is simply x² squared.

Dry run

  1. x = 2.0, n = 10: result goes 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024. Ten multiplications.
  2. x = 2.0, n = -2: the loop computes 2 × 2 = 4, then returns 1 / 4 = 0.25.

Python

class Solution:
    def myPow(self, x: float, n: int) -> float:
        result = 1.0
        for _ in range(abs(n)):          # |n| multiplications: far too slow for n near 2^31
            result *= x
        return result if n >= 0 else 1 / result
Time O(|n|)Space O(1)

One multiplication per unit of the exponent.

When to use: Only for tiny exponents, or as the baseline that shows what to improve.

Use x^n = (x^(n // 2))², times one more x when n is odd. Turn a negative exponent into a positive one first (x → 1 / x, n → -n). The recursion stops at x⁰ = 1.

The exponent halves on every call, so there are about log₂ n calls (31 for the largest n) and each does one or two multiplications. Compute half once and reuse it. Calling the function twice, once for each half, doubles the work at every level and brings you back to n multiplications.

Dry run

  1. x = 2, n = 10: power(2, 10) needs power(2, 5), which needs power(2, 2), then power(2, 1), then power(2, 0).
  2. power(2, 0) = 1. power(2, 1): odd → 1 · 1 · 2 = 2. power(2, 2): even → 2 · 2 = 4.
  3. power(2, 5): odd → 4 · 4 · 2 = 32. power(2, 10): even → 32 · 32 = 1024.
  4. Five calls and four small multiplications, instead of ten multiplications by 2.

Python

class Solution:
    def myPow(self, x: float, n: int) -> float:
        if n < 0:                                # x^(-n) = (1 / x)^n: make the exponent non-negative once
            x, n = 1 / x, -n

        def power(base: float, exp: int) -> float:
            if exp == 0:
                return 1.0
            half = power(base, exp // 2)         # compute the half ONCE
            if exp % 2 == 0:
                return half * half
            return half * half * base            # odd exponent: one extra factor of base

        return power(x, n)
Time O(log n)Space O(log n)

About log₂ n nested calls, each with one or two multiplications. The call stack is as deep as the number of halvings.

When to use: The most natural way to write the idea. Say "I compute the half once" out loud.

Watch it run

Unroll the recursion by reading n in binary, lowest bit first. Keep two numbers: base, which runs through x, x², x⁴, x⁸ … (squared every round), and result, the answer so far. In each round, if the lowest bit of n is 1, multiply result by base. Then square base and shift n right by one bit. When n reaches 0, result is x^n.

Why it works: n = 13 = 1101₂ means 13 = 8 + 4 + 1, so x¹³ = x⁸ · x⁴ · x¹, and the loop picks up exactly those three powers. About log₂ n rounds, O(1) extra memory, and no recursion depth to worry about.

Dry run

  1. x = 2, n = 10 = 1010₂: result = 1, base = 2
  2. bit 0 is 0 → skip; base = 4. bit 1 is 1 → result = 1 · 4 = 4; base = 16.
  3. bit 2 is 0 → skip; base = 256. bit 3 is 1 → result = 4 · 256 = 1024; n is now 0 → return 1024.
  4. Only four rounds, one per bit of 10. For n = 2³¹ − 1 there are 31 rounds.

Python

class Solution:
    def myPow(self, x: float, n: int) -> float:
        if n < 0:                                # x^(-n) = (1 / x)^n
            x, n = 1 / x, -n
        result = 1.0
        base = x                                 # x^1, then x^2, x^4, x^8, ... as the loop goes on
        while n:
            if n & 1:                            # lowest bit of n is 1: this power of x is part of the answer
                result *= base
            base *= base                         # the next power of two in the exponent
            n >>= 1                              # drop the bit we just used
        return result
Time O(log n)Space O(1)

One loop round per bit of n (at most 31), each with one or two multiplications.

When to use: The standard interview answer: no recursion, constant memory, and it generalises to modular and matrix powers.

Common mistakes

  • Looping n times. With n up to 2³¹ − 1 the loop does two billion multiplications, which takes minutes in Python (about two on a typical machine). Halve the exponent instead.
  • Calling the recursion twice, as in power(x, n // 2) * power(x, n // 2). Every call spawns two calls, the recursion tree ends up with n leaves, and you are back to O(n). Store the half in a variable.
  • Forgetting the extra factor of x when n is odd. half * half alone is x^(n-1).
  • Recursing directly on a negative n. In Python -3 // 2 is -2 (floor division rounds down), so the halving does not behave as for positive numbers, and in C++ or Java -3 / 2 is -1. Convert to a positive exponent first. In a language with 32-bit integers, also beware that -n for n = -2³¹ overflows; use a 64-bit variable there.
  • Comparing floats with ==. Different multiplication orders round differently (2.1 ** 3 is 9.261000000000001), so compare with a tolerance such as abs(a - b) < 1e-5.

Python notes

  • x ** n and pow(x, n) already do all of this (and pow(x, n, mod) is the modular version). The exercise is to write it by hand.
  • n & 1 tests the lowest bit of n, and n >>= 1 shifts it right by one bit. For a non-negative n that is the same as n //= 2.
  • base *= base rebinds base to its own square. Doing that inside the loop is exactly what we want; a negative n is turned positive before the loop for the same reason.
  • A float multiplication that overflows quietly gives inf, while float ** int raises OverflowError. In the loop the last squaring is never used, so even if it overflows no harm is done.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Sqrt(x) LC 69 — another way to halve: binary search on the answer, instead of on the exponent.
  • Super Pow LC 372 — a^b modulo 1337 where b is a huge number given as a list of digits: combine fast power with the digit recurrence a^(10q + d) = (a^q)^10 · a^d.
  • Count Good Numbers LC 1922 — the answer is a product of two powers (5 and 4) with exponents up to about 5 · 10^14, taken modulo 10^9 + 7. Fast modular power is the whole problem.
  • Climbing Stairs LC 70 — the Fibonacci recurrence can be sped up from O(n) to O(log n) by raising a 2 × 2 matrix to the n-th power with exactly this squaring idea.
  • The result must be taken modulo 10^9 + 7 — reduce after every multiplication, or call Python's pow(x, n, mod). A negative exponent then needs a modular inverse: pow(x, -1, mod) (Python 3.8+).
