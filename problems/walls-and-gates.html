Walls and Gates Medium

LeetCode #286 ↗
Status

Fill every empty room with its distance to the nearest gate, changing the grid in place.

Problem

You are given an m × n grid rooms in which every cell holds one of three values:

  • -1: a wall or obstacle,
  • 0: a gate,
  • 2147483647 (that is 2^31 - 1, called INF): an empty room.

Fill each empty room with the number of steps to its nearest gate, moving up, down, left or right and never through a wall. A room that cannot reach any gate keeps the value INF.

Modify rooms in place; the method returns nothing.

Examples

Example 1
Input: rooms = [[INF,-1,0,INF],[INF,INF,INF,-1],[INF,-1,INF,-1],[0,-1,INF,INF]]
Output: [[3,-1,0,1],[2,2,1,-1],[1,-1,2,-1],[0,-1,3,4]]
Room (1,0) is 2 steps from the gate at (3,0) and 3 steps from the gate at (0,2), so it gets 2.
Example 2
Input: rooms = [[-1]]
Output: [[-1]]
Example 3
Input: rooms = [[INF,-1,0]]
Output: [[2147483647,-1,0]]
The wall cuts the room off from the only gate, so it keeps INF.

Constraints

  • 1 <= m, n <= 250
  • rooms[i][j] is -1, 0 or 2^31 - 1

Key idea

Asking every room "where is my nearest gate?" costs one search per room. Turn the question around and let the gates spread outwards together: put every gate in the queue at distance 0 and run a single BFS. The queue then holds a wave front: first every room one step from some gate, then every room two steps away, and so on.

A room is reached for the first time exactly when the wave from its nearest gate arrives, because waves from farther gates get there later. So the first distance written into a room is final, and each room is handled once. This is multi-source BFS: an ordinary BFS whose queue starts with several sources instead of one.

Approaches from the obvious one to the one you want in an interview

Answer the question exactly as asked: for each empty room, run a BFS outwards until it pops a gate. BFS explores in order of distance, so the first gate it reaches is the nearest one. If the search runs out of cells, the room keeps INF.

Each search can cover the whole grid, and there can be m · n rooms, so this is O((m · n)²). Neighbouring rooms repeat almost the same search, which is the waste the optimal solution removes.

Dry run

  1. Example: room (0,0) searches (1,0), then (2,0) and (1,1), then reaches the gate (3,0) at distance 3 → 3.
  2. Room (0,3): its first ring already contains the gate (0,2) → 1.
  3. Room (1,0): reaches (3,0) after 2 steps → 2. The search from (1,0) re-explores most of what (0,0)'s search just saw.

Python

class Solution:
    def wallsAndGates(self, rooms: List[List[int]]) -> None:
        if not rooms or not rooms[0]:
            return
        rows, cols = len(rooms), len(rooms[0])
        INF = 2**31 - 1

        def nearest_gate(sr: int, sc: int) -> int:
            seen = {(sr, sc)}
            queue = deque([(sr, sc, 0)])
            while queue:
                r, c, d = queue.popleft()
                if rooms[r][c] == 0:                  # BFS order: the first gate popped is the nearest
                    return d
                for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                    if (0 <= nr < rows and 0 <= nc < cols
                            and rooms[nr][nc] != -1 and (nr, nc) not in seen):
                        seen.add((nr, nc))
                        queue.append((nr, nc, d + 1))
            return INF                                # no gate reachable

        for r in range(rows):
            for c in range(cols):
                if rooms[r][c] == INF:
                    rooms[r][c] = nearest_gate(r, c)
Time O((m · n)²)Space O(m · n)

Up to m · n rooms, each running a BFS that may visit every cell.

When to use: Only to explain the idea; it is too slow for a 250 × 250 grid.

Search from the gates instead of the rooms. For each gate, run a BFS that writes d + 1 into a neighbouring room only if that is smaller than what the room already holds, and only continues through rooms it improved. After every gate has had its turn, each room holds the minimum over all gates.

The check rooms[nr][nc] > d + 1 also keeps walls (-1) and gates (0) safe, since neither is ever bigger than a positive distance. With few gates this is fast; with G gates it is O(G · m · n), which is still quadratic when the grid is full of gates.

Python

class Solution:
    def wallsAndGates(self, rooms: List[List[int]]) -> None:
        if not rooms or not rooms[0]:
            return
        rows, cols = len(rooms), len(rooms[0])
        for gr in range(rows):
            for gc in range(cols):
                if rooms[gr][gc] != 0:
                    continue
                queue = deque([(gr, gc, 0)])          # an ordinary BFS from this one gate
                while queue:
                    r, c, d = queue.popleft()
                    for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                        if 0 <= nr < rows and 0 <= nc < cols and rooms[nr][nc] > d + 1:
                            rooms[nr][nc] = d + 1      # this gate is closer than any seen so far
                            queue.append((nr, nc, d + 1))
Time O(G · m · n)Space O(m · n)

G is the number of gates; each gate's BFS may walk most of the grid.

When to use: A useful middle step in an interview: it shows why searching from the gates helps, before merging the searches.

Put every gate in the queue (and in visited) before the loop starts. Then run one ordinary BFS: pop a cell, and for each neighbour that is not a wall and not yet visited, write distance of the popped cell + 1, mark it, and queue it.

The queue always holds cells in order of distance from their nearest gate: all the distance-1 rooms around every gate are queued before any distance-2 room. So the first time a room is reached is along a shortest path from the closest gate, and its value never needs changing. Every cell is queued at most once.

Dry run

  1. Example: queue both gates → [(0,2), (3,0)].
  2. Pop (0,2): (1,2) and (0,3) get 1. Pop (3,0): (2,0) gets 1.
  3. Pop (1,2): (2,2) and (1,1) get 2. Pop (0,3): nothing new. Pop (2,0): (1,0) gets 2.
  4. Pop (2,2): (3,2) gets 3. Pop (1,1): nothing new. Pop (1,0): (0,0) gets 3.
  5. Pop (3,2): (3,3) gets 4. Popping (0,0) and (3,3) adds nothing → done.

Python

class Solution:
    def wallsAndGates(self, rooms: List[List[int]]) -> None:
        if not rooms or not rooms[0]:
            return
        rows, cols = len(rooms), len(rooms[0])
        queue = deque()
        visited = set()
        for r in range(rows):
            for c in range(cols):
                if rooms[r][c] == 0:                  # every gate starts the search, at distance 0
                    queue.append((r, c))
                    visited.add((r, c))
        while queue:
            r, c = queue.popleft()
            for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                if (0 <= nr < rows and 0 <= nc < cols
                        and rooms[nr][nc] != -1 and (nr, nc) not in visited):
                    visited.add((nr, nc))             # mark when queued: no room is queued twice
                    rooms[nr][nc] = rooms[r][c] + 1   # one step further than the cell that found it
                    queue.append((nr, nc))

Common mistakes

  • Running a separate search from every room (or every gate): correct, but O((m · n)²) when there are many rooms or gates.
  • Marking a room visited only when it is popped: two neighbours can then both queue it. Mark it, and write its distance, at the moment it is queued.
  • Using DFS to fill in distances: DFS reaches a room along some path, not the shortest one, so values must be lowered again and again.
  • Overwriting gates or walking through walls: a gate's 0 is never changed and a -1 is never entered.
  • Queuing only the first gate you find: rooms that are closer to another gate end up with distances that are too large.

Python notes

  • Give the magic number a name: INF = 2**31 - 1 reads better than 2147483647.
  • The method edits rooms in place: assign into rooms[r][c]. Rebinding rooms = ... inside the method would make a new list that the caller never sees.
  • visited is optional here: a room still holding INF has not been reached yet, so the check rooms[nr][nc] == INF can replace the set and save the memory.
  • deque((r, c) for r in range(rows) for c in range(cols) if rooms[r][c] == 0) builds the starting queue in one line.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Rotting Oranges LC 994 — the same multi-source BFS, but the answer is the time of the last cell reached, or -1 if some fresh orange is never reached.
  • 01 Matrix LC 542 — every cell's distance to its nearest 0: queue all the zeros first, exactly as the gates here.
  • As Far from Land as Possible LC 1162 — queue every land cell, spread over the water, and return the largest distance written.
  • Shortest Distance from All Buildings LC 317 — you need the sum of distances to every building, not the nearest one, so the sources cannot share a queue: run one BFS per building and add up the results.
  • Shortest Path in a Grid with Obstacles Elimination LC 1293 — you may break up to k walls: the BFS state becomes (r, c, walls_left) instead of just (r, c).
