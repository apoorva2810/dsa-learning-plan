Sqrt(x) Easy 250

LeetCode #69 ↗
Status

Compute the square root of a non-negative integer rounded down, without the built-in sqrt or power functions.

Problem

You are given a non-negative integer x. Return the square root of x rounded down to an integer: the largest integer k such that k * k <= x.

You may not use any built-in exponent or square-root function (x ** 0.5, math.sqrt, math.isqrt, pow).

Examples

Example 1
Input: x = 4
Output: 2
2 × 2 = 4 exactly.
Example 2
Input: x = 8
Output: 2
The square root of 8 is about 2.83. Rounded down that is 2: 2 × 2 = 4 fits in 8, 3 × 3 = 9 does not.
Example 3
Input: x = 15
Output: 3
3 × 3 = 9 fits, 4 × 4 = 16 is too big.

Constraints

  • 0 <= x <= 2^31 - 1

Think first try before reading the solution

You cannot compute the root directly, but you can check a candidate k cheaply: is k * k <= x?
If k * k <= x then every smaller k fits too, and if k * k > x every bigger k is too big. So along k = 0, 1, 2, … the checks read yes, yes, …, yes, no, no, …: sorted.
Binary search the candidates for the last yes. When mid * mid <= x, remember mid as the best so far and look higher; otherwise look lower.

Key idea

There is no list to search, but there is a sorted sequence of answers to a question: for k = 0, 1, 2, … the test k * k <= x is true up to some point and false forever after, because squares only grow. The square root rounded down is the last k where the test is still true.

A yes/no question that flips exactly once can be binary searched: test the middle candidate, and the answer tells you which half still contains the flip. The candidates run from 0 to about x / 2, so even for x near 2³¹ the search takes about 30 checks, each a single multiplication. This is binary search on the answer: the same idea as Koko Eating Bananas, with a much simpler check.

Approaches from the obvious one to the one you want in an interview

Start at k = 0 and increase it while (k + 1)² is still at most x. When the next square would overshoot, k is the answer.

It needs about √x steps: 46,340 for the largest allowed x. That is fast enough to pass, but it does the same work as a scan over a sorted list, and the next approach shows how much of it is unnecessary.

Dry run

  1. x = 8: k = 0 → 1² = 1 ≤ 8, k = 1
  2. k = 1 → 2² = 4 ≤ 8, k = 2
  3. k = 2 → 3² = 9 > 8, stop → 2

Python

class Solution:
    def mySqrt(self, x: int) -> int:
        k = 0
        while (k + 1) * (k + 1) <= x:           # the next candidate still fits
            k += 1
        return k
Time O(√x)Space O(1)

One multiplication per candidate up to the root, about 46,000 for x near 2³¹.

When to use: Only as a baseline; it is what binary search speeds up.

Watch it run

The check mid * mid <= x is true for small candidates and false for large ones, so binary search the candidates 0..x // 2 + 1 for the last true:

  • mid * mid <= x → mid fits; remember it in best and look for a bigger one: lo = mid + 1.
  • otherwise → mid and everything above it are too big: hi = mid - 1.

When the loop ends, best is the largest candidate that fit. The best variable avoids the classic off-by-one of returning lo (one too big) at the end; returning hi would also be correct.

The upper bound x // 2 + 1 works because √x ≤ x / 2 for x ≥ 4 and the + 1 covers x = 0, 1, 2, 3.

Dry run

  1. x = 8: lo = 0, hi = 5, best = 0
  2. mid = 2 → 4 ≤ 8 ✓ best = 2, lo = 3
  3. mid = 4 → 16 > 8 ✗ hi = 3
  4. mid = 3 → 9 > 8 ✗ hi = 2 → lo > hi → return best = 2

Python

class Solution:
    def mySqrt(self, x: int) -> int:
        lo, hi = 0, x // 2 + 1                  # the root is never above x // 2 + 1
        best = 0                                # largest k seen so far with k * k <= x
        while lo <= hi:
            mid = (lo + hi) // 2
            if mid * mid <= x:
                best = mid                      # mid fits: remember it ...
                lo = mid + 1                    # ... and try to find a bigger one
            else:
                hi = mid - 1                    # mid is too big, so is everything above it
        return best
Time O(log x)Space O(1)

About log₂(x / 2) ≤ 30 rounds, each one multiplication.

When to use: The expected interview answer, and the 'last value that passes a check' template.

Watch it run

Start with a guess r that is too big (r = x) and replace it by the average of r and x // r. If r is above the root, x // r is below it, so the average lands in between, and it can be shown that the integer version never drops below the rounded-down root. Stop as soon as r * r <= x.

Each round roughly doubles the number of correct digits, so it takes a handful of rounds even for 2³¹: faster than binary search in practice, but the proof that it stops at exactly ⌊√x⌋ is harder than the binary-search argument.

Python

class Solution:
    def mySqrt(self, x: int) -> int:
        if x < 2:
            return x                            # 0 and 1 are their own roots (and avoid x // 0)
        r = x                                   # a guess that is certainly too big
        while r * r > x:
            r = (r + x // r) // 2               # average of a too-big and a too-small estimate
        return r                                # the integer iteration stops exactly at floor(sqrt(x))
Time O(log log x)Space O(1)

Quadratic convergence: about 5-6 rounds for x near 2³¹ once the guess is close.

When to use: When speed matters more than an easy proof; also how math.isqrt is implemented.

Common mistakes

  • Converting to a float: int(x ** 0.5) works for these sizes but is banned by the statement, and above about 2⁵² floating-point rounding can return a value that is one too large.
  • Returning lo when the loop while lo <= hi ends: at that moment lo is the first candidate that is too big and hi is the answer. Return hi, or keep a best variable as the code below does.
  • Forgetting that x = 0 and x = 1 are their own square roots. Starting the search at lo = 1 returns a wrong answer for x = 0 unless you special-case it.
  • Shrinking the range with lo = mid in a while lo < hi loop: when two candidates are left, mid rounds down to lo and the loop never ends. Either move past mid or round mid up when you keep it.
  • In Java or C, mid * mid overflows a 32-bit int for mid above 46,340; compare mid <= x / mid instead. Python integers do not overflow.

Python notes

  • math.isqrt(x) (Python 3.8+) is the exact integer square root and is what real code should use. It is banned here only so that you practise the search.
  • mid * mid <= x is cheaper and safer than mid <= x / mid: no division, no float, and Python integers never overflow.
  • The upper bound x // 2 + 1 is safe because √x ≤ x / 2 once x ≥ 4, and the + 1 covers 0 ≤ x ≤ 3. Using hi = x also works; it just costs one extra round.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Valid Perfect Square LC 367 — the same search, but return whether some mid * mid equals num exactly instead of the last one that fits.
  • Arranging Coins LC 441 — replace the check by k * (k + 1) // 2 <= n: the largest number of complete staircase rows.
  • Koko Eating Bananas LC 875 — binary search on the answer again, with an O(n) check instead of one multiplication, and the first value that works.
  • Pow(x, n) LC 50 — also halves a problem at each step, but by squaring the base instead of halving a search range.
  • What if the answer must be accurate to six decimal places? — binary search on real numbers: keep lo..hi as floats and stop when hi - lo < 1e-7, or run Newton's iteration r = (r + x / r) / 2, which doubles the correct digits every round.
