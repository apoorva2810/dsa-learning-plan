Binary Tree Postorder Traversal Easy 250

LeetCode #145 ↗
Status

List a binary tree's values in postorder: the left subtree, then the right subtree, then the node itself, at every node.

Problem

Given the root of a binary tree, return the postorder traversal of its values as a list.

Postorder means: at every node, list everything in its left subtree first, then everything in its right subtree, and the node's own value last. The same rule applies inside each subtree. So every node appears after all of its descendants, and the root is always the last value.

An empty tree gives an empty list. The recursive solution is three lines. The iterative one is the tricky member of the three traversal orders, because a node must wait until both of its subtrees are finished.

Examples

Example 1
Input: root = [1, 2, 3, 4, 5, None, 6]
Output: [4, 5, 2, 6, 3, 1]
The left subtree comes first: 4 and 5 before their parent 2. Then the right subtree: 6 before its parent 3. The root 1 is last.
Example 2
Input: root = [7, None, 9, 8]
Output: [8, 9, 7]
7 has no left subtree. In its right subtree 8 comes before its parent 9, and 7 itself is last.
Example 3
Input: root = []
Output: []

Constraints

  • 0 <= number of nodes <= 100
  • -100 <= Node.val <= 100

Think first try before reading the solution

Say the rule at every node: everything on my left, then everything on my right, then me. As a function that calls itself on the two children and appends its own value last, that sentence is the recursive solution.
A stack version of postorder is awkward, because a node has to be looked at twice. Start from an easier order: node, then right subtree, then left subtree (preorder with the two children swapped). How is that list related to postorder?
It is postorder written backwards. Run the stack loop of preorder, push the left child first so the right one is popped first, collect the values, and reverse the list at the end.

Key idea

Postorder records a node last: only after both of its subtrees are completely listed. That is the order in which a recursive function finishes with the nodes, so the recursive solution is again short: list the left subtree, list the right subtree, then append the node.

The stack version is harder than preorder or inorder. A node has to be seen twice: once on the way down, and again after both subtrees are done. There are two standard ways around that.

Reverse a mirrored preorder. Run the preorder stack loop, but push the left child first and the right child second. It then lists the node, the right subtree, the left subtree. Read that list backwards and you get the left subtree, the right subtree, the node: postorder. So collect the values, then reverse the list once. Every node is pushed and popped once, so the time is O(n), and the stack holds at most one path of waiting siblings, O(h).

Remember the last node finished. Slide left pushing nodes, then look at the top. If it has a right child that has not been visited yet, go into that right subtree. Otherwise both subtrees are done: record the top, pop it, and remember it as last. Seeing a node for the second time shows up as top.right is last. This needs one stack and no reversal, but the bookkeeping is easy to get wrong.

Approaches from the obvious one to the one you want in an interview

The definition of postorder is already a recursive procedure: to list a subtree, list its left subtree, then its right subtree, and write down its root last. An empty subtree lists nothing.

Write postorder(node) exactly like that. Python's call stack keeps every ancestor waiting until both of its subtrees have returned. Each node is visited once, so the time is O(n). The call stack is as deep as the tree is tall, O(h), and Python raises RecursionError after about 1000 nested calls.

Dry run

  1. root = [1, 2, 3, 4, 5, None, 6], result = []
  2. postorder(1) starts with its left subtree: postorder(2) → postorder(4) records 4, postorder(5) records 5, then 2 itself → [4, 5, 2]
  3. back in postorder(1): the right subtree postorder(3) → its left is empty, postorder(6) records 6, then 3 → [4, 5, 2, 6, 3]
  4. both subtrees of the root are done: record 1 → [4, 5, 2, 6, 3, 1]

Python

class Solution:
    def postorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        result = []

        def postorder(node):
            if node is None:                    # empty subtree: nothing to record
                return
            postorder(node.left)                # 1. everything on the left
            postorder(node.right)               # 2. everything on the right
            result.append(node.val)             # 3. this node, last

        postorder(root)
        return result
Time O(n)Space O(h)

Each node is entered once. The call stack holds one root-to-node path, h frames at most (n for a chain).

When to use: The natural first answer, and the shape of every bottom-up tree computation.

Watch it run

Postorder reads left subtree, right subtree, node. Read it backwards and it says node, right subtree, left subtree, which is a preorder that visits the right child before the left.

So reuse the preorder stack loop with the pushes swapped: pop a node, append it to order, push its left child, then its right child. The right child is on top, so the right subtree is listed before the left one. When the stack is empty, reverse order once. Every node is pushed and popped once: O(n) time, and the stack holds only the waiting left children along one path, O(h). There is no recursion limit.

Dry run

  1. root = [1, 2, 3, 4, 5, None, 6], order = [], stack = [1]
  2. pop 1 → order [1]; push 2, then 3 → stack [2, 3] (3 on top)
  3. pop 3 → [1, 3]; only a right child, push 6 → stack [2, 6]
  4. pop 6 → [1, 3, 6] (leaf); pop 2 → [1, 3, 6, 2]; push 4, then 5 → stack [4, 5]
  5. pop 5 → [1, 3, 6, 2, 5]; pop 4 → [1, 3, 6, 2, 5, 4]; stack empty
  6. reverse → [4, 5, 2, 6, 3, 1]

Python

class Solution:
    def postorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        if root is None:
            return []
        order = []                              # will hold: node, right subtree, left subtree
        stack = [root]
        while stack:
            node = stack.pop()
            order.append(node.val)              # preorder, but with the children swapped...
            if node.left:                       # push LEFT first, so RIGHT is popped first
                stack.append(node.left)
            if node.right:
                stack.append(node.right)
        order.reverse()                         # ...so backwards it reads: left, right, node
        return order
Time O(n)Space O(h)

Every node is pushed and popped once, and the list is reversed once. The stack holds the waiting left children of one path; the answer list itself is not counted.

When to use: The easy way to get an iterative postorder in an interview: it is preorder with two small changes.

Watch it run

Walk the tree the way the recursion does, with a single stack. Slide left, pushing every node. Then look at the top without removing it:

  • if it has a right child that is not last (the node recorded most recently), that subtree is still unvisited: move into it;
  • otherwise both subtrees are finished: record the top, pop it, and set last to it.

When a node comes up for the second time, top.right is last tells you its right subtree is done, so it can be recorded. The time is O(n) and the stack holds one root-to-node path, O(h). It needs no reversal, and it is the form that generalises to problems where you must act on a node after its children while the path is still on the stack.

Dry run

  1. root = [1, 2, 3, 4, 5, None, 6]: slide left → stack [1, 2, 4]; top 4 has no right child → record 4, last = 4
  2. top 2 has a right child 5 that is not last → go into it: push 5; 5 is a leaf → record 5, last = 5
  3. top 2 again: its right child 5 is last → record 2, last = 2
  4. top 1 has a right child 3 → push 3, then 6; record 6; top 3: its right child 6 is last → record 3
  5. top 1: its right child 3 is last → record 1 → [4, 5, 2, 6, 3, 1]

Python

class Solution:
    def postorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        result, stack = [], []
        cur, last = root, None                  # last: the node recorded most recently
        while cur or stack:
            while cur:                          # slide left, remembering every node passed
                stack.append(cur)
                cur = cur.left
            top = stack[-1]                     # look at the top without removing it
            if top.right and top.right is not last:
                cur = top.right                 # its right subtree is not done yet: go there first
            else:
                result.append(top.val)          # both subtrees are done: record it now
                last = stack.pop()
        return result
Time O(n)Space O(h)

Each node is pushed once and examined at most twice (once before its right subtree, once after).

When to use: When you cannot collect and reverse, or want the true postorder walk with the path on the stack.

Common mistakes

  • Recording a node when it is first reached. That is preorder. In postorder a node waits until both of its subtrees have been listed.
  • Using the preorder push order (right child first) and then reversing. The reverse of root, left, right is right, left, root: a mirrored postorder. For the reverse trick push the left child first.
  • Forgetting the final reversal, or writing return order.reverse(). list.reverse() works in place and returns None; call it on its own line, or use order[::-1].
  • In the single-stack version, popping a node the first time you see it. Its right subtree is then skipped. Pop only when there is no right child or top.right is last.
  • In the single-stack version, forgetting last. A node whose right subtree is finished would send the walk into that subtree again, forever.
  • Building the answer with post(left) + post(right) + [val]. Each + copies a list, so a value is copied once per ancestor: O(n · h) time. Append to one shared list instead.

Python notes

  • list.reverse() reverses in place and returns None; order[::-1] returns a new reversed list. Both are O(n).
  • collections.deque has appendleft in O(1), so you can build the answer already reversed (result.appendleft(node.val)) and skip the final reversal. Return list(result).
  • top = stack[-1] peeks at the top of a list used as a stack without removing it.
  • top.right and top.right is not last is false for a missing right child (None), so a node without one is recorded at once.
  • Python stops recursion at about 1000 nested calls; the stack versions have no such limit.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Binary Tree Preorder Traversal LC 144 — the node comes first, so it can be recorded the moment it is popped. The reverse trick above is this loop with the pushes swapped.
  • Binary Tree Inorder Traversal LC 94 — the node comes between its subtrees, so it is recorded when popped after the slide left.
  • Delete Leaves With a Given Value LC 1325 — a postorder idea: clean both children first, then decide about the node, because it may have become a leaf.
  • Diameter of Binary Tree LC 543 — each node needs the heights of both subtrees before it can report its own, which is the postorder shape.
  • Binary Tree Maximum Path Sum LC 124 — the same bottom-up pass: children return their best downward gain, the node combines them.
  • N-ary Tree Postorder Traversal LC 590 — the reverse trick still works: push the children left to right, collect, then reverse.
  • What if you may use no extra memory at all? — Morris traversal can produce postorder as well, but it has to reverse part of the tree's right edge on the way back, so it is rarely used.
