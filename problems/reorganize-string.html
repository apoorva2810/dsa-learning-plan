Reorganize String Medium 250

LeetCode #767 ↗
Status

Rearrange the letters of a string so that no two neighbours are equal, or report that it cannot be done.

Problem

You are given a string s of lowercase letters. Rearrange its letters so that no two neighbouring letters are the same, and return the new string. If no such arrangement exists, return the empty string "".

Any valid arrangement is accepted: the tests check the property, not one fixed answer.

Examples

Example 1
Input: s = "aab"
Output: "aba"
The two a's need a different letter between them, and b does that job.
Example 2
Input: s = "aaab"
Output: ""
Three a's need two separators (a _ a _ a), but there is only one other letter. Impossible.
Example 3
Input: s = "vvvlo"
Output: "vlvov"
"vovlv" is also accepted: the three v's take positions 0, 2, 4 and l, o fill the gaps.

Constraints

  • 1 <= len(s) <= 500
  • s consists of lowercase English letters

Think first try before reading the solution

Which letter is the hardest to place? The most frequent one: any two of its copies need a different letter between them.
Count the letters. If one letter has more than (n + 1) // 2 copies, there are not enough other letters to separate them, so the answer is "". Otherwise an arrangement always exists.
Build the answer left to right: at each position write the letter with the most copies left that is not the letter you just wrote. A max-heap of counts gives it; keep the letter just used out of the heap for one round.

Key idea

The danger is always the letter with the most copies left: if you keep spending the rare letters, the common one ends up with no separators. So the greedy rule is at every position, write the letter with the most copies left, except the one you just wrote. Spending the biggest pile first keeps the piles balanced, which keeps separators available until the end.

A max-heap of (-count, letter) hands out the biggest pile in O(log 26). To stop a letter from being chosen twice in a row, the letter just written is held out of the heap for exactly one round: pop the new letter, push the held one back, then hold the new one. When the heap runs empty while the held letter still has copies, nothing is left to separate them, and the arrangement is impossible.

The same counting also gives a direct test: one letter with more than (n + 1) // 2 copies cannot be separated (there are only n - count other letters to put between count copies), and otherwise the even/odd fill in the alternative below always succeeds.

Approaches from the obvious one to the one you want in an interview

Build the string one position at a time. At each position try every letter type that still has copies and is not the letter just written; recurse; if the recursion gets stuck (letters left but all equal to the previous one), undo and try the next letter type.

It finds an arrangement whenever one exists, but it has no idea which letter is dangerous. On an input such as "aaaaab…" it writes a, b, a, gets stuck, backs up, tries again, and in the worst case explores a tree with up to 26 branches per position: exponential time.

Dry run

  1. "aab": position 0 → try a (2 left → 1); position 1 → a is forbidden, try b; position 2 → a → "aba"
  2. "aaab": a, b, a, then only a is left and a is forbidden → undo; b, a, then stuck twice → undo everything → ""

Python

class Solution:
    def reorganizeString(self, s: str) -> str:
        counts = Counter(s)
        out = []

        def place() -> bool:                       # True once every letter has been written
            if len(out) == len(s):
                return True
            for ch in sorted(counts):              # try every letter type that still has copies
                if counts[ch] == 0 or (out and out[-1] == ch):
                    continue                       # none left, or it would touch its twin
                counts[ch] -= 1
                out.append(ch)
                if place():
                    return True
                out.pop()                          # dead end: undo and try the next letter
                counts[ch] += 1
            return False

        return "".join(out) if place() else ""
Time O(26ⁿ)Space O(n)

Up to 26 choices at each of n positions in the worst case; the recursion depth is n.

When to use: Never for real inputs; it shows that an arrangement is a search problem before you know the greedy rule.

Count the letters and put (-count, letter) pairs into a heap (negated, so the biggest pile is at the root). Then, for each position:

  1. pop the root: the letter with the most copies left among the letters allowed here;
  2. write it;
  3. push the previously held letter back into the heap (it is allowed again);
  4. if the popped letter still has copies, hold it out: it is forbidden at the next position.

The hold-out is what prevents two equal neighbours. If the heap runs empty while a held letter still has copies, there is nothing to put between those copies: return "".

Dry run

  1. "vvvlo": heap {v×3, l×1, o×1}, held none
  2. pos 0: pop v×3, write v, hold v×2 → "v"
  3. pos 1: pop l×1, write l, push v×2 back → "vl"
  4. pos 2: pop v×2, write v, hold v×1 → "vlv"; pos 3: pop o×1, write o, push v×1 → "vlvo"
  5. pos 4: pop v×1, write v, nothing left → "vlvov", heap empty, held none → done

Python

class Solution:
    def reorganizeString(self, s: str) -> str:
        heap = [(-count, ch) for ch, count in Counter(s).items()]   # max-heap by copies left
        heapq.heapify(heap)
        out = []
        held = None                               # the letter just written, kept out of the heap for one round
        while heap:
            count, ch = heapq.heappop(heap)       # most copies left among the letters allowed here
            out.append(ch)
            if held is not None:
                heapq.heappush(heap, held)        # the previous letter is allowed again
            held = (count + 1, ch) if count + 1 < 0 else None   # hold ch out if copies remain (-3 + 1 = -2)
        if held is not None:                      # copies left but nothing to separate them
            return ""
        return "".join(out)
Time O(n log k)Space O(n)

One pop and at most one push per position on a heap of k ≤ 26 letter types; the output takes O(n).

When to use: The interview answer: it also adapts to a longer cooldown (Task Scheduler) and to 'no three in a row' (Longest Happy String).

Watch it run

Sort the letters by count, most frequent first, and write them into the result at indices 0, 2, 4, …; when the even indices run out, continue at 1, 3, 5, ….

The most frequent letter goes first and has at most (n + 1) // 2 copies, exactly the number of even indices, so it never touches itself. Every later letter has at most as many copies as the first, which is too few to fill the rest of the even indices and reach index 1 from the far end, so it cannot touch itself either. If the top count exceeds (n + 1) // 2, no arrangement exists at all. This is O(n) and needs no heap, but it only works because the gap is 1; the heap version generalises.

Dry run

  1. "vvvlo": counts v×3, l×1, o×1; limit (5 + 1) // 2 = 3, v fits
  2. v → indices 0, 2, 4 → v·v·v
  3. index 6 is out of range → continue at 1: l → index 1, o → index 3 → "vlvov"

Python

class Solution:
    def reorganizeString(self, s: str) -> str:
        n = len(s)
        counts = Counter(s)
        top_letter, top = counts.most_common(1)[0]
        if top > (n + 1) // 2:                    # more copies than even indices: cannot be kept apart
            return ""
        result = [""] * n
        i = 0                                     # fill the even indices first: 0, 2, 4, ...
        for ch, count in counts.most_common():    # most frequent letter first
            for _ in range(count):
                result[i] = ch
                i += 2
                if i >= n:                        # even indices are full: continue with the odd ones
                    i = 1
        return "".join(result)
Time O(n)Space O(n)

One counting pass, a sort of at most 26 counts, and one write per position.

When to use: When the gap is exactly one letter and you want the shortest code; be ready to explain why the wrap-around is safe.

Common mistakes

  • Pushing the letter straight back into the heap after writing it: the heap may hand it out again at the very next position ("aab" would become "aab" or "baa"). Hold it out for one round.
  • Returning the partial string when the heap runs dry: "aaab" produces "aba" with one a still unplaced. The leftover held letter means the task is impossible, so return "".
  • In the even/odd fill, placing letters in alphabetical rather than frequency order: for "aab", b first gives b at 0, a at 2, then the second a wraps to index 1 and lands next to its twin: "baa".
  • Using n // 2 as the limit instead of (n + 1) // 2: "aba" has two a's in three letters and is fine.
  • Pushing (count, letter) into heapq without negating: heapq is a min-heap, so you would always get the rarest letter.

Python notes

  • Counter(s) counts in one line; counts.most_common() returns (letter, count) pairs sorted by count, largest first.
  • heapq is a min-heap, so store (-count, letter). Tuples compare item by item: equal counts fall back to the letter, which is harmless here.
  • Build the answer in a list and "".join it at the end; += on a string copies it every time.
  • (n + 1) // 2 is the ceiling of n / 2 in integers: the number of even indices 0, 2, 4, … below n.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Task Scheduler LC 621 — the gap between equal letters is n instead of 1, and idle slots are allowed: the hold-out becomes a cooling queue and you count intervals.
  • Rearrange String k Distance Apart LC 358 — equal letters must be at least k apart and you must return the string: hold each used letter out for k - 1 rounds in a queue.
  • Longest Happy String LC 1405 — two equal letters in a row are fine but not three, and you may leave letters unused: the same max-heap, skipping a letter only when it would make a run of three.
  • Distant Barcodes LC 1054 — the same problem on integers, always solvable: the heap or the even/odd fill works unchanged.
  • What if the alphabet had 10⁵ different symbols? — the heap version becomes O(n log k) with k symbol types; the even/odd fill stays O(n) after an O(k log k) sort of the counts.
