N-Queens Hard

LeetCode #51 ↗
Status

Place n chess queens on an n x n board so that none attacks another, and list every arrangement.

Problem

In chess a queen attacks every square in her row, in her column, and along both diagonals. Given an integer n, place n queens on an n x n board so that no two queens attack each other.

Return every distinct arrangement. An arrangement is a list of n strings, one per row from top to bottom, where "Q" marks a queen and "." an empty square. The arrangements may be returned in any order.

Examples

Example 1
Input: n = 4
Output: [[".Q..", "...Q", "Q...", "..Q."], ["..Q.", "Q...", "...Q", ".Q.."]]
The two boards are mirror images of each other, and they are the only solutions for 4 queens.
Example 2
Input: n = 1
Output: [["Q"]]
Example 3
Input: n = 3
Output: []
Three queens cannot be placed on a 3 x 3 board without an attack, so the answer is empty.

Constraints

  • 1 <= n <= 9

Think first try before reading the solution

Two queens in the same row attack each other, so every row holds exactly one queen. Instead of choosing squares on the board, choose one column for each row, from the top row down.
Place the queens row by row. For row r, try every column c. A square is unsafe if an earlier queen is in column c or on one of the two diagonals through it. Which information about the earlier queens do you need to remember?
All squares on one ↘ diagonal share the value r - c, and all squares on one ↙ diagonal share r + c. Keep three sets (taken columns, taken r - c, taken r + c), so 'is this square attacked?' is three in checks. Add to the sets when you place a queen and remove from them when you take it back.

Key idea

The board has n² squares and you must pick n of them, but most of that freedom is fake. A row can hold only one queen (two would attack each other), so a solution is one column per row. That turns "choose n squares" into "walk down the rows and pick a column in each": a decision tree with n levels. For n = 8 that is already a drop from about 4.4 billion ways to put 8 queens anywhere (C(64, 8)) to 8^8 = 16.8 million column choices.

Now cut the tree wherever a queen would be attacked. A queen at (r, c) attacks along its column and along two diagonals. Moving down-right keeps r - c the same: (0,0), (1,1), (2,2) all have r - c = 0. Moving down-left keeps r + c the same: (0,3), (1,2), (2,1), (3,0) all have r + c = 3. So two queens attack each other exactly when they share c, r - c or r + c (their rows differ by construction). Keep three sets of what is already taken and every safety test becomes three O(1) lookups.

Then use the usual backtracking rhythm: choose (put a queen on the board and add its three values to the sets), explore (recurse into the next row), un-choose (remove the queen and its three values). If a row has no safe column the call returns; that is a dead end, and the row above moves its queen to the next column. For n = 8 this makes only 2,057 calls in total.

Approaches from the obvious one to the one you want in an interview

Two queens in a solution never share a row or a column, so a solution is a permutation of the columns: cols[r] is the column of the queen in row r. Try every permutation of 0 .. n-1 and keep those in which no two queens share a diagonal. Two queens share a diagonal when their r - c values are equal or their r + c values are equal, so a permutation is valid exactly when all r - c values are different and all r + c values are different.

This already avoids the enormous C(n², n) search, but it builds all n! permutations (40,320 for n = 8, 362,880 for n = 9) and looks at the diagonals only at the end. A permutation that begins with two queens on one diagonal is still completed in all (n-2)! ways before it is thrown away.

Dry run

  1. n = 4: there are 4! = 24 permutations of the columns 0, 1, 2, 3.
  2. (0, 1, 2, 3): the values r - c are 0, 0, 0, 0, which repeat, so the queens share a diagonal. Rejected.
  3. (1, 3, 0, 2): r - c is -1, -2, 2, 1 and r + c is 1, 4, 2, 5. All different, so keep it as .Q.. / ...Q / Q... / ..Q..
  4. (2, 0, 3, 1) passes as well. The other 22 permutations fail, so the answer has 2 boards.

Python

class Solution:
    def solveNQueens(self, n: int) -> List[List[str]]:
        boards = []
        # cols[r] is the column of the queen in row r; a permutation uses every column exactly once
        for cols in itertools.permutations(range(n)):
            diagonals = {r - c for r, c in enumerate(cols)}        # one value per "\" diagonal
            anti_diagonals = {r + c for r, c in enumerate(cols)}   # one value per "/" diagonal
            if len(diagonals) == n and len(anti_diagonals) == n:   # no two queens share a diagonal
                boards.append(["." * c + "Q" + "." * (n - c - 1) for c in cols])
        return boards
Time O(n · n!)Space O(n)

All n! permutations are generated and each is checked in O(n). Besides the answer, memory is one permutation at a time.

When to use: Only to show why pruning matters. It is fine up to about n = 8.

Build the arrangement one row at a time and reject a square as soon as it is attacked, instead of finishing a doomed arrangement. place(row) tries every column of the row. A column is allowed when no queen already placed attacks it: queen (r, c) attacks (row, col) when c == col (same column) or abs(c - col) == row - r (same diagonal: the horizontal and vertical distances are equal).

This prunes whole subtrees. For n = 8 the search makes about 2,000 calls instead of building 40,320 permutations. The price is the attack test: it loops over all earlier queens, O(n) per square. The next approach replaces that loop with set lookups.

Dry run

  1. place(0): no queens yet, so every column is safe. Choose column 0.
  2. place(1): column 0 is the same column, column 1 is diagonal (distance 1 across, 1 down), column 2 is safe. Choose it.
  3. place(2): every column is attacked by the queens at (0,0) or (1,2). Dead end: return, and row 1 tries column 3.
  4. Eventually cols = [1, 3, 0, 2] fills all four rows: save .Q.. / ...Q / Q... / ..Q.. Later [2, 0, 3, 1] is found too.

Python

class Solution:
    def solveNQueens(self, n: int) -> List[List[str]]:
        boards = []
        cols = []                                   # cols[r] = column of the queen in row r

        def is_safe(row, col):
            for r, c in enumerate(cols):            # every queen placed so far (rows 0 .. row-1)
                if c == col or abs(c - col) == row - r:   # same column, or same diagonal
                    return False
            return True

        def place(row):
            if row == n:                            # n queens placed: a complete board
                boards.append(["." * c + "Q" + "." * (n - c - 1) for c in cols])
                return
            for col in range(n):
                if is_safe(row, col):
                    cols.append(col)                # choose
                    place(row + 1)                  # explore
                    cols.pop()                      # un-choose

        place(0)
        return boards
Time O(n² · n!)Space O(n)

An upper bound that ignores the pruning: the tree has at most a small multiple of n! nodes, and each node tests n columns at O(n) each. The real count is far smaller (about 2,000 calls for n = 8). Memory is the column list and the recursion.

When to use: A good first version to write in an interview. Then speed up the attack test with sets.

Same row-by-row search, but remember what is already taken in three sets so that the attack test is O(1):

  • cols holds the columns that contain a queen;
  • diags holds row - col for every queen: one value per ↘ diagonal;
  • anti holds row + col for every queen: one value per ↙ diagonal.

Square (row, col) is safe when col not in cols, row - col not in diags and row + col not in anti. To choose it, add the three values and append col to placement; to un-choose, undo all four updates. When row == n every queen is placed: turn placement into strings and save the board. If no column works in a row, the loop ends and the call returns, which sends the row above on to its next column.

Dry run

  1. n = 4. place(0): all sets are empty. Choose column 0: cols {0}, diags {0}, anti {0}.
  2. place(1): column 0 is in cols; column 1 has 1 - 1 = 0 in diags; column 2 is free. Choose it: cols {0, 2}, diags {0, -1}, anti {0, 3}.
  3. place(2): column 0 is taken, column 1 has 2 + 1 = 3 in anti, column 2 is taken, column 3 has 2 - 3 = -1 in diags. No column: return.
  4. Undo (1,2). Row 1 tries column 3, row 2 finds column 1, row 3 finds nothing. Undo back to row 0.
  5. Row 0 tries column 1: the rows then pick columns 3, 0, 2. row == 4, so save .Q.. / ...Q / Q... / ..Q..
  6. Row 0 tries column 2 (second board ..Q. / Q... / ...Q / .Q..) and column 3 (dead end). The answer has 2 boards.

Python

class Solution:
    def solveNQueens(self, n: int) -> List[List[str]]:
        boards = []
        cols = set()                       # columns that already hold a queen
        diags = set()                      # row - col of every queen: one value per "\" diagonal
        anti = set()                       # row + col of every queen: one value per "/" diagonal
        placement = []                     # placement[r] = column of the queen in row r

        def place(row):
            if row == n:                   # all n queens are placed: save the board
                boards.append(["." * c + "Q" + "." * (n - c - 1) for c in placement])
                return
            for col in range(n):
                if col in cols or (row - col) in diags or (row + col) in anti:
                    continue               # this square is attacked: skip it
                cols.add(col)              # choose
                diags.add(row - col)
                anti.add(row + col)
                placement.append(col)
                place(row + 1)             # explore the next row
                placement.pop()            # un-choose: undo all four updates
                anti.remove(row + col)
                diags.remove(row - col)
                cols.remove(col)

        place(0)
        return boards
Time O(n · n!)Space O(n)

Same tree as the previous approach, but each square costs three O(1) lookups, so a node costs O(n) instead of O(n²). As an upper bound it is loose: the search makes only 2,057 calls for n = 8. The sets and the recursion need O(n) memory; the output holds one n x n board per solution.

When to use: The standard answer. Mention bitmasks as the next optimisation and N-Queens II as the counting variant.

Common mistakes

  • Using one set for both diagonals. A r - c value of 1 and a r + c value of 1 name different diagonals, so keep two separate sets (or add an offset to one of them).
  • Removing the queen from only some of the sets when you backtrack. A leftover entry makes later rows think a column or diagonal is still taken, and valid boards go missing.
  • Saving a mutable board (or the placement list) and changing it later. Build the row strings for a solution at the moment you save it.
  • Looping over every square of the board instead of one column per row. That throws away the 'one queen per row' fact and the search explodes.
  • Returning rows as lists of characters. The expected rows are strings, for example "." * c + "Q" + "." * (n - c - 1).
  • Expecting a non-empty answer. For n = 2 and n = 3 there are no solutions and the correct result is []. Also, mirror images such as the two boards for n = 4 are different boards, and both belong in the answer.

Python notes

  • "." * c + "Q" + "." * (n - c - 1) builds a row with a queen in column c: multiplying a string repeats it.
  • A set gives O(1) in, add and remove. The value row - col can be negative, which a set does not mind (a list would need an offset).
  • enumerate(cols) yields (row, column) pairs for the queens placed so far, which is how the second approach tests attacks.
  • itertools.permutations(range(n)) yields tuples; each one is a candidate with one queen in every row and every column.
  • The nested function place changes the sets and lists through their methods (add, remove, append, pop), so it needs no nonlocal.
  • The recursion is only n (at most 9) frames deep.

Follow-up questions

What an interviewer might ask next, and what changes.

  • N-Queens II LC 52 — only the number of solutions is needed, so no board strings are built. Three integers used as bitmasks replace the sets and make the search very fast.
  • Sudoku Solver LC 37 — the same 'what is already taken' sets, now for rows, columns and 3 x 3 boxes. Fill the empty cells with backtracking and undo a digit when a later cell has no legal digit.
  • Valid Sudoku LC 36 — checks the same kind of constraint once, with a set per row, column and box, instead of searching.
  • Permutations LC 46 — N-Queens is permutations of the columns plus extra pruning. The 'used' set that stops a column being reused is the same idea.
  • Stop at the first solution — make place return True as soon as a board is complete and False on a dead end. One solution is found far sooner than all of them, because the search stops at the first complete board.
  • Use bitmasks instead of sets — store taken columns and both diagonals in three integers. Moving to the next row shifts the diagonal masks by one bit. Same structure, much smaller constant.
