Palindrome Partitioning Medium

LeetCode #131 ↗
Status

Cut a string into pieces that are all palindromes, and list every way to do it.

Problem

You are given a string s. Cut it into one or more pieces: substrings that sit next to each other, in order, and together cover all of s. A cutting is valid when every piece is a palindrome, meaning it reads the same forwards and backwards (aba, bb). A single letter is always a palindrome.

Return every valid cutting. Each cutting is a list with its pieces from left to right, and the cuttings may come back in any order.

Examples

Example 1
Input: s = "aab"
Output: [["a", "a", "b"], ["aa", "b"]]
a | ab is invalid because ab is not a palindrome, and aab as one piece is not one either.
Example 2
Input: s = "a"
Output: [["a"]]
Example 3
Input: s = "aba"
Output: [["a", "b", "a"], ["aba"]]
The whole string is a palindrome, so it is allowed as a single piece.

Constraints

  • 1 <= len(s) <= 16
  • s consists of lowercase English letters

Key idea

A cutting is a series of choices of the form "the next piece ends here". At position start the next piece can be s[start:start + 1], s[start:start + 2], and so on up to the end of the string. Only palindromes are allowed, and each allowed piece leaves a shorter string with the same question. Draw it as a decision tree: every node is a position in the string, every branch is "take this piece", and a node that sits at the end of the string is one finished cutting.

Why not cut first and check later? A string of n letters has n - 1 gaps, and each gap is cut or not, which gives 2^(n-1) cuttings. Many are doomed from the first piece: ab | ... is invalid however the rest is cut. Backtracking tests each piece at the moment it is chosen and never extends a bad one, so a single failed test removes every cutting that would have started with it.

The answer itself can be huge: in "aaaa" every substring is a palindrome, so all 2^3 = 8 cuttings are valid, and in general 2^(n-1). No algorithm can beat exponential time on such an input, because it has to write that many lists. Backtracking at least spends its time only on partial answers that are still valid.

Approaches from the obvious one to the one you want in an interview

A string of n letters has n - 1 gaps between neighbouring letters. Each gap is either cut or left alone, so there are 2^(n-1) ways to cut. Loop over all of them (the numbers 0 to 2^(n-1) - 1 do the job, with bit i saying whether gap i is cut), build the pieces, and keep the way only if every piece is a palindrome.

It is correct, but it always does all 2^(n-1) rounds. For abcdefghijklmnop (16 different letters) only one way is valid, yet 32,768 ways are built and checked, because most of them start with a piece such as ab that is already wrong and the loop does not notice until the end.

Dry run

  1. s = "aab" has 2 gaps, so 4 ways to cut: aab, a|ab, aa|b, a|a|b.
  2. Check each way: aab has a non-palindrome piece, a|ab has ab, aa|b is fine, a|a|b is fine.
  3. Answer: [["aa", "b"], ["a", "a", "b"]].

Python

class Solution:
    def partition(self, s: str) -> List[List[str]]:
        n = len(s)
        answer = []
        for mask in range(1 << (n - 1)):           # bit i of mask: is there a cut after letter i?
            pieces = []
            start = 0
            for i in range(n - 1):
                if (mask >> i) & 1:                # cut between letter i and letter i + 1
                    pieces.append(s[start:i + 1])
                    start = i + 1
            pieces.append(s[start:])               # the last piece
            if all(p == p[::-1] for p in pieces):  # keep it only if every piece is a palindrome
                answer.append(pieces)
        return answer
Time O(n · 2^n)Space O(n)

Always 2^(n-1) rounds, each costing O(n) to build and check the pieces. Memory is one cutting at a time, not counting the answer.

When to use: Only as the baseline. It shows how much work 'choose, then check' wastes.

Check each piece when it is chosen, not after the whole cutting is built.

backtrack(start) decides the piece that begins at start:

  • Base case: start == len(s) means the pieces cover the string. Save a copy of them.
  • Otherwise: for every end from start + 1 to len(s), look at the candidate s[start:end]. If it is a palindrome, choose it (append), explore with backtrack(end), and un-choose it (pop). If it is not, skip it: no valid cutting can contain it, so there is nothing to explore below it.

A failed test cuts off a whole subtree, so the work is proportional to the number of valid partial cuttings rather than all 2^(n-1). On abcdefghijklmnop that is 16 levels with one choice each instead of 32,768 complete cuttings.

Dry run

  1. s = "aab". backtrack(0): candidates a, aa, aab. a is a palindrome: choose it, pieces [a].
  2. backtrack(1): candidates a, ab. a is a palindrome: choose it, pieces [a, a].
  3. backtrack(2): candidate b is a palindrome: choose it, pieces [a, a, b]. backtrack(3) sees start == 3 == len(s) and saves a copy.
  4. Pop b, then pop a. Back in backtrack(1) the candidate ab is not a palindrome: skip it.
  5. Pop a. In backtrack(0) the candidate aa is a palindrome: choose it, then b: save [aa, b].
  6. The candidate aab is not a palindrome: skip it. Answer [[a, a, b], [aa, b]].

Python

class Solution:
    def partition(self, s: str) -> List[List[str]]:
        n = len(s)
        answer = []
        pieces = []                               # the palindromic pieces chosen so far

        def backtrack(start):
            if start == n:                        # the pieces cover the whole string
                answer.append(pieces[:])          # save a copy: `pieces` keeps changing
                return
            for end in range(start + 1, n + 1):   # the next piece is s[start:end]
                piece = s[start:end]
                if piece == piece[::-1]:          # only a palindrome may be chosen
                    pieces.append(piece)          # choose
                    backtrack(end)                # explore: cut the rest of the string
                    pieces.pop()                  # un-choose

        backtrack(0)
        return answer
Time O(n · 2^n)Space O(n)

Worst case is a string like aaaa where every piece is a palindrome: about 2^n tree nodes, and each saved cutting costs O(n) to copy. The palindrome tests add little, since the many nodes near the end of the string only test short pieces. On strings with few palindromes the tree stays tiny. Memory is the recursion and the pieces list, not counting the answer.

When to use: The interview answer. It is also the shape of Word Break II and many 'cut a string' problems.

Watch it run

Plain backtracking asks 'is s[a:b] a palindrome?' again and again: many different earlier cuts lead to the same position, and each of them tests the same substrings. Answer every such question once before searching.

Fill a table is_pal[i][j] that is True when s[i..j] (both ends included) is a palindrome. The rule: the two end letters must match, and the part between them, s[i+1..j-1], must itself be a palindrome (or have fewer than 2 letters). Fill the rows from the bottom (i large) upwards so the inside is always ready. The search then does a table lookup instead of slicing and reversing.

Big-O stays the same, because writing the answer dominates in the worst case. The price is O(n^2) memory. The same table is the core of Palindrome Partitioning II, so it is worth knowing.

Dry run

  1. s = "aab": the table has cells for (i, j) with i <= j. Single letters are palindromes: (0,0), (1,1), (2,2) are True.
  2. (1,2) is ab: the ends differ, False. (0,1) is aa: equal ends and length 2, True.
  3. (0,2) is aab: the ends a and b differ, False.
  4. Then run the same search as before, replacing the slice test with is_pal[start][end].

Python

class Solution:
    def partition(self, s: str) -> List[List[str]]:
        n = len(s)
        # is_pal[i][j] is True when s[i..j] (both ends included) is a palindrome
        is_pal = [[False] * n for _ in range(n)]
        for i in range(n - 1, -1, -1):            # rows from the bottom, so row i + 1 is ready
            for j in range(i, n):
                if s[i] == s[j] and (j - i < 2 or is_pal[i + 1][j - 1]):
                    is_pal[i][j] = True

        answer = []
        pieces = []

        def backtrack(start):
            if start == n:
                answer.append(pieces[:])
                return
            for end in range(start, n):           # the piece is s[start..end], end included
                if is_pal[start][end]:            # O(1) lookup instead of reversing a slice
                    pieces.append(s[start:end + 1])
                    backtrack(end + 1)
                    pieces.pop()

        backtrack(0)
        return answer
Time O(n · 2^n)Space O(n^2)

O(n^2) to build the table, then the same search with O(1) palindrome tests. The table is the extra memory.

When to use: Longer strings, or when the table is reused (Palindrome Partitioning II).

Common mistakes

  • Saving pieces instead of a copy (pieces[:]). The list is changed again right afterwards, so every saved answer ends up empty.
  • Stopping the loop one short, with range(start + 1, n). The slice end is exclusive, so the last piece s[start:n] needs end = n: use range(start + 1, n + 1).
  • Forgetting pieces.pop() after the recursive call. Pieces from an earlier branch then stay in the list and the next branch starts from the wrong state.
  • Returning after the first valid cutting. The task asks for all of them, so keep looping after backtrack(end) returns.
  • Testing a palindrome with piece == piece.reverse(). Strings have no reverse() method (that is a list method); use piece == piece[::-1].

Python notes

  • A slice s[start:end] includes start and stops before end, so s[start:len(s)] is the whole tail.
  • piece == piece[::-1] tests for a palindrome: [::-1] makes a reversed copy of the string.
  • pieces[:] (or list(pieces)) copies the list. Without the copy the saved answer is the very list that pop() keeps changing.
  • (mask >> i) & 1 reads bit i of an integer. The brute force uses one integer per way of cutting, with one bit per gap.
  • With n <= 16 there are at most 2^15 = 32,768 cuttings and the recursion is at most 16 deep, so speed and recursion limits are not a worry.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Palindrome Partitioning II LC 132 — return only the minimum number of cuts. Listing all cuttings is far too slow, so use DP over the same is_pal table.
  • Palindromic Substrings LC 647 — count every palindromic substring instead of cutting: expand around each centre.
  • Word Break LC 139 — the same 'cut where the piece is allowed' shape, but the question is only whether one cutting exists, so memoise on start and stop at the first success.
  • Word Break II LC 140 — list every sentence: this problem with 'is the piece in the dictionary?' instead of 'is it a palindrome?'. Memoise the answers for each start to avoid repeating work.
  • Count the cuttings without listing them — let ways[i] be the number of valid cuttings of s[:i], with ways[0] = 1. Then ways[i] is the sum of ways[j] over every j where s[j:i] is a palindrome. O(n^2) time once the is_pal table exists, and no lists.
