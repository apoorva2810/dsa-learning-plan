Kth Smallest Element in a BST Medium

LeetCode #230 ↗
Status

Return the k-th smallest value stored in a binary search tree.

Problem

You are given the root of a binary search tree (every left subtree holds smaller values, every right subtree larger ones) and an integer k. Return the k-th smallest value in the tree, counting from 1.

  • k is always between 1 and the number of nodes.
  • All values in a BST are distinct.

Examples

Example 1
Input: root = [3, 1, 4, null, 2], k = 1
Output: 1
Sorted, the values are 1, 2, 3, 4. The 1st smallest is 1.
Example 2
Input: root = [5, 3, 6, 2, 4, null, null, 1], k = 3
Output: 3
Sorted: 1, 2, 3, 4, 5, 6. The 3rd is 3.

Constraints

  • 1 <= k <= number of nodes <= 10^4
  • 0 <= Node.val <= 10^4

Think first try before reading the solution

If you had the values in sorted order, the answer would be at index k - 1. Is there a traversal of a BST that produces sorted order without sorting?
Inorder traversal (left subtree, node, right subtree) visits a BST from smallest to largest.
You do not need the whole sorted list: run the inorder walk with an explicit stack and stop at the k-th node you pop.

Key idea

The BST rule says everything left of a node is smaller and everything right of it is larger. So if you visit the left subtree first, then the node, then the right subtree (inorder order), you see the values in increasing order. The k-th value you visit is the answer.

The naive version collects the whole inorder list and indexes it. That wastes work when k is small: you only need to walk until the k-th value. An iterative inorder walk can stop exactly there. Keep a stack of nodes whose left side is still being explored: slide left from the current node pushing every node on the way, pop one (it is the next smallest), count it, then repeat from its right child.

It costs O(h) to reach the smallest value (h is the tree height) plus O(1) amortised per further value, so O(h + k) overall. Amortised means averaged over all the steps: an individual step can take longer, but the total is bounded.

Approaches from the obvious one to the one you want in an interview

Visit every node in any order, put the values in a list, sort it, and return the element at index k - 1.

It ignores the one thing the problem gives you, the BST ordering, and pays for a sort: O(n log n) time and O(n) memory, even when k = 1 and the answer is just the leftmost node.

Dry run

  1. root = [5, 3, 6, 2, 4, null, null, 1], k = 3
  2. preorder collect: [5, 3, 2, 1, 4, 6] → sorted [1, 2, 3, 4, 5, 6] → index 2 → 3

Python

class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        values = []

        def collect(node):
            if node:
                values.append(node.val)
                collect(node.left)
                collect(node.right)

        collect(root)
        values.sort()                   # ignores the order the BST already gives us
        return values[k - 1]
Time O(n log n)Space O(n)

Visiting is O(n); the sort dominates.

When to use: Only if the tree were not a BST.

Use the BST property: an inorder traversal (left, node, right) appends the values already sorted, so no sort is needed. Return values[k - 1].

That removes the log factor, but still walks all n nodes and stores all n values, even when the answer is near the start.

Dry run

  1. inorder of [5, 3, 6, 2, 4, null, null, 1]: 1, 2, 3, 4, 5, 6
  2. k = 3 → values[2] = 3

Python

class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        values = []

        def inorder(node):
            if node is None:
                return
            inorder(node.left)          # everything smaller first
            values.append(node.val)     # then this node
            inorder(node.right)         # then everything larger

        inorder(root)
        return values[k - 1]
Time O(n)Space O(n)

Every node is visited and stored; the recursion adds O(h) stack.

When to use: Clear and short; fine when k is close to n anyway.

Run the same inorder walk by hand so it can stop early:

  1. From the current node, slide left, pushing every node passed. The last one pushed has no left child, so it is the smallest value not yet visited.
  2. Pop a node: that is the next value in sorted order. Count it; if it is the k-th, return it.
  3. Move to the popped node's right child (the values just above it) and repeat.

The stack holds the nodes whose left side is being explored, at most one root-to-leaf path: O(h) memory.

Dry run

  1. root = [5, 3, 6, 2, 4, null, null, 1], k = 3
  2. slide left: push 5, 3, 2, 1
  3. pop 1 (#1), no right child → pop 2 (#2), no right child → pop 3 (#3) = k → return 3
  4. nodes 4, 5 and 6 were never popped

Python

class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        stack, node = [], root
        while stack or node:
            while node:                 # go as far left as possible
                stack.append(node)
                node = node.left
            node = stack.pop()          # the next smallest value
            k -= 1
            if k == 0:
                return node.val
            node = node.right           # then the values just above it
        return -1                       # only if k > number of nodes (not allowed)
Time O(h + k)Space O(h)

Reaching the smallest value costs O(h); each further value costs O(1) amortised, since every node is pushed and popped at most once.

When to use: The interview answer: it uses the BST order and stops as soon as the answer is known.

Common mistakes

  • Off-by-one with k: it counts from 1. After sorting, the answer is values[k - 1], and in the stack version you stop when the counter reaches k (or when k counts down to 0).
  • Sorting all the values (sorted(...)) works but ignores the BST property: an interviewer will ask why you paid O(n log n).
  • Building the inorder list with inorder(left) + [val] + inorder(right) creates new lists at every level: O(n·h) copying. Append to one shared list instead.
  • In the iterative walk, forgetting to move to node.right after popping, or pushing the right child and its left chain at the wrong moment. Use the standard two-loop shape: while node: push, go left, then pop, then node = node.right.

Python notes

  • A list is the stack: stack.append(node) pushes, stack.pop() pops the most recent node.
  • The loop condition while stack or node: keeps going while there is either something waiting on the stack or a subtree still to explore.
  • Counting k down (k -= 1; if k == 0: ...) saves a separate counter variable.

Follow-up questions

What an interviewer might ask next, and what changes.

  • The tree changes often and k-th queries are frequent — LeetCode's own follow-up: store in each node the size of its left subtree. Then compare k with that size and go left or right, O(h) per query, and update the sizes on insert/delete.
  • Binary Search Tree Iterator LC 173 — the stack-based inorder walk from this problem, paused between next() calls.
  • Kth Largest Element in an Array LC 215 — no BST to exploit: use a heap of size k or quickselect.
  • Closest Binary Search Tree Value II LC 272 — the k values closest to a target: an inorder walk with a sliding window of size k, or two stacks walking outwards.
  • Kth largest in a BST — run inorder mirrored (right subtree, node, left subtree): values come out from largest to smallest.
