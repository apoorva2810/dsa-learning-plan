Jump Game II Medium

LeetCode #45 ↗
Status

Find the fewest jumps needed to get from the first index of a list to the last, when each value is the longest hop allowed from that index.

Problem

You are given a list of non-negative integers nums and you start on index 0. The value nums[i] is the longest jump you may make forward from index i: you can move any distance from 1 up to nums[i].

Return the minimum number of jumps needed to reach the last index. The input is built so that the last index can always be reached.

Examples

Example 1
Input: nums = [2, 3, 1, 1, 4]
Output: 2
Jump 1 step from index 0 to index 1, then 3 steps to the last index. One jump is not enough.
Example 2
Input: nums = [2, 3, 0, 1, 4]
Output: 2
Jump 1 step to index 1 (not 2 steps onto the 0), then 3 steps to the end.
Example 3
Input: nums = [1, 1, 1, 1]
Output: 3
Every jump can only be 1 long, so each of the three moves is needed.

Constraints

  • 1 <= len(nums) <= 10^4
  • 0 <= nums[i] <= 1000
  • the last index is always reachable

Think first try before reading the solution

Think like a breadth-first search. Which indices can you reach with 0 jumps? With exactly 1 jump? With 2? The answer is the first group that contains the last index.
Each group is a block of consecutive indices, because shorter jumps are allowed. Group k + 1 starts right after group k and ends at the farthest index that anything in group k can reach.
You do not need a queue. Scan i from left to right and keep farthest = max(i + nums[i]). When i reaches the last index of the current group (cur_end), you must spend one more jump: jumps += 1 and cur_end = farthest.

Key idea

Sort the indices into levels by how many jumps it takes to land on them for the first time: level 0 is index 0, level 1 is everything one jump from index 0, and so on. This is breadth-first search, with the indices as nodes. The answer is the level of the last index.

The shortcut is that each level is a block of consecutive indices. This is the same "no holes" fact as in Jump Game: shorter jumps are allowed, so if you can land on index 5 from index 2, you can land on 3 and 4 as well. A block is just two numbers, so there is no need for a queue or a visited set. Level k + 1 starts right after level k and ends at the largest i + nums[i] found while scanning level k.

In one loop, keep two numbers: cur_end, the last index of the current level, and farthest, the best reach seen so far (the end of the next level). Scan i upward and update farthest. When i == cur_end you have looked at every index of this level, so another jump is unavoidable: count it and set cur_end = farthest.

Why is this greedy? You do not decide where to land until the level is fully scanned. Then you effectively pick the landing spot in that level with the best reach. No other spot in the level can reach anything beyond the level that this one cannot, so the choice never loses.

Approaches from the obvious one to the one you want in an interview

Let fewest[i] be the fewest jumps needed to land on index i. Index 0 needs 0. Go through the indices from left to right, and for each i update every index it can reach in one jump: fewest[j] = min(fewest[j], fewest[i] + 1) for j from i + 1 to i + nums[i].

It is correct and easy to trust, but each index may touch up to nums[i] later cells, so the total work is O(n·k) for k the largest jump (O(n²) when k is about n). Most of those updates are wasted: the answer for a cell only ever needs the first level that reaches it.

Dry run

  1. nums = [2, 3, 1, 1, 4], fewest = [0, ∞, ∞, ∞, ∞]
  2. i = 0 (jump 2): indices 1 and 2 get 1 → [0, 1, 1, ∞, ∞]
  3. i = 1 (jump 3): index 2 stays 1; indices 3 and 4 get 2 → [0, 1, 1, 2, 2]
  4. i = 2 (jump 1): index 3 would get 2, no change; i = 3 (jump 1): index 4 would get 3, no change
  5. answer fewest[4] = 2

Python

class Solution:
    def jump(self, nums: List[int]) -> int:
        n = len(nums)
        fewest = [float("inf")] * n              # fewest[i]: fewest jumps to land on index i
        fewest[0] = 0
        for i in range(n - 1):
            for j in range(i + 1, min(n - 1, i + nums[i]) + 1):   # every index one jump from i
                fewest[j] = min(fewest[j], fewest[i] + 1)
        return fewest[n - 1]
Time O(n·k)Space O(n)

k is the largest value in nums. Each index updates up to nums[i] later cells; the table has n entries.

When to use: As a trusted reference on small inputs.

Make the breadth-first search literal, using the fact that a level is a block [level_start, level_end].

  1. Start with level 0 = [0, 0] and jumps = 0.
  2. While the last index is not inside the current level, scan the whole level and take the largest i + nums[i].
  3. The next level is the block right after the current one, ending at that largest reach. Count one jump.

Every index belongs to exactly one level, so the scans never overlap and the total work is O(n). It is easier to read than the one-loop version, and it makes the structure obvious.

Dry run

  1. nums = [2, 3, 1, 1, 4]: level 0 = [0, 0], jumps = 0
  2. farthest reach over level 0 is 0 + 2 = 2 → level 1 = [1, 2], jumps = 1
  3. farthest reach over level 1 is max(1 + 3, 2 + 1) = 4 → level 2 = [3, 4], jumps = 2
  4. level 2 contains the last index → return 2

Python

class Solution:
    def jump(self, nums: List[int]) -> int:
        last = len(nums) - 1
        jumps = 0
        level_start, level_end = 0, 0            # indices first reachable with `jumps` jumps
        while level_end < last:                  # the last index is not in this level yet
            # the problem guarantees the end is reachable, so farthest > level_end
            farthest = max(i + nums[i] for i in range(level_start, level_end + 1))
            level_start, level_end = level_end + 1, farthest   # the next block of indices
            jumps += 1
        return jumps
Time O(n)Space O(1)

The level blocks do not overlap, so every index is scanned once in total.

When to use: When you want the BFS structure to be visible. Same cost as the one-loop version.

Fuse the two loops of the previous approach. Instead of scanning each level a second time to find its best reach, update farthest as i moves along, and use i == cur_end to notice that a level has just finished.

for i in range(len(nums) - 1):
    farthest = max(farthest, i + nums[i])
    if i == cur_end:          # the level is fully scanned
        jumps += 1
        cur_end = farthest

cur_end is the last index you can reach with the current number of jumps, and farthest is what one more jump could reach. The loop stops before the last index, so it never counts a jump taken from the end.

Dry run

  1. nums = [2, 3, 1, 1, 4], jumps = 0, cur_end = 0, farthest = 0
  2. i = 0: farthest = 2; i == cur_end → jumps = 1, cur_end = 2
  3. i = 1: farthest = 4
  4. i = 2: farthest stays 4; i == cur_end → jumps = 2, cur_end = 4
  5. i = 3: nothing changes; the loop ends before index 4 → return 2

Python

class Solution:
    def jump(self, nums: List[int]) -> int:
        jumps = 0
        cur_end = 0                              # last index reachable with `jumps` jumps
        farthest = 0                             # last index reachable with `jumps + 1` jumps
        for i in range(len(nums) - 1):           # we never jump FROM the last index
            farthest = max(farthest, i + nums[i])
            if i == cur_end:                     # scanned the whole level: another jump is needed
                jumps += 1
                cur_end = farthest
        return jumps
Time O(n)Space O(1)

One pass, three integers.

When to use: The interview answer. Draw the levels first, then show how the two numbers track them.

Common mistakes

  • Looping over the last index too. The loop must stop at index n - 2, because you never jump from the last index. With [2, 3, 1, 1, 4], scanning index 4 hits i == cur_end and counts a third jump.
  • Always jumping as far as possible. In [2, 3, 0, 1, 4] the longest jump from index 0 lands on the 0 at index 2 and gets stuck. Choose the landing spot by its reach (i + nums[i]), not by how far it is.
  • Testing i == cur_end before updating farthest with index i. The last index of a level contributes its own reach too, so update farthest first, then check.
  • Counting a jump when you land somewhere instead of when you finish scanning a level. A single-element list needs 0 jumps, and the answer is the number of level changes, not the number of indices visited.
  • Trusting the guarantee blindly in an interview. If the end might be unreachable, farthest stalls at cur_end; check for that at each level change and return -1.

Python notes

  • range(len(nums) - 1) leaves out the last index on purpose. It is the correct loop bound, not an off-by-one.
  • In the level-by-level version, max(i + nums[i] for i in range(a, b + 1)) is a generator expression: no list is built.
  • Tuple assignment level_start, level_end = level_end + 1, farthest evaluates the right side first, so it uses the old level_end.
  • Use float("inf") as "not reachable yet" in the DP table; min(inf, 3) works as you would hope.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Jump Game LC 55 — only ask whether the end is reachable: the same farthest-reach sweep with no levels.
  • Jump Game IV LC 1345 — you may also jump to any index with the same value. Now a level is no longer a block, so run a real BFS with a map from value to indices, and clear each map entry after its first use.
  • Minimum Number of Taps to Open to Water a Garden LC 1326 — turn each tap into a jump (from its left edge to its right edge) and this exact loop gives the answer.
  • Video Stitching LC 1024 — fewest clips that cover [0, time]: the same level-by-level greedy, with each clip as a jump from its start to its end.
  • What if the last index might be unreachable? — when i == cur_end and farthest has not moved past it, no further level exists: return -1.
  • Return the actual jumps — remember, for each level, the index that gave the best farthest; those indices are the landing spots.
