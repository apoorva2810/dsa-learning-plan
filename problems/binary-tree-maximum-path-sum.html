Binary Tree Maximum Path Sum Hard

LeetCode #124 ↗
Status

Find the largest sum of node values along any path in a binary tree; the path may start and end anywhere.

Problem

In a binary tree, a path is a sequence of nodes where each pair of neighbours in the sequence is joined by an edge, and no node appears twice. A path does not have to pass through the root, and it can start and end at any nodes. Its path sum is the sum of its node values.

Given the root of a binary tree, return the maximum path sum over all non-empty paths.

  • A single node is a valid path, so the answer exists even when every value is negative.

Examples

Example 1
Input: root = [1, 2, 3]
Output: 6
The path 2 → 1 → 3 has sum 6.
Example 2
Input: root = [-10, 9, 20, null, null, 15, 7]
Output: 42
The path 15 → 20 → 7 has sum 42. Adding -10 and 9 (via the root) would only make it smaller.
Example 3
Input: root = [-3]
Output: -3
The only path is the single node.

Constraints

  • 1 <= number of nodes <= 3 * 10^4
  • -1000 <= Node.val <= 1000

Think first try before reading the solution

Draw any path in a tree: it has exactly one highest node, where it bends. It comes up from the left side (possibly not at all), passes that node, and goes down the right side (possibly not at all).
If you fix the highest node t, the best path bending there is t.val + the best path going down from t.left + the best path going down from t.right, where a side that would add a negative amount is skipped (counts as 0).
One post-order DFS can do both jobs: each call returns its best downward path (its gain) to the parent, and updates a global answer with left_gain + node.val + right_gain on the way.

Key idea

Look at a path as a shape in the tree. It always has one highest node: the path climbs up to it from one side and goes down into the other side (either side may be empty). So the answer is the best, over every node t, of t.val + (best downward path starting in t's left subtree) + (best downward path starting in t's right subtree).

A downward path starts at a node and keeps stepping to one child. Call the best such sum the node's gain: gain(node) = node.val + max(0, gain(left), gain(right)). The max(0, ...) says a branch that would lower the sum is not taken, since a path may stop anywhere. Gain picks only one side because a parent extending this path can continue down only one way: a path cannot fork.

Computing gains separately for every candidate top repeats work. A single post-order traversal (children first, then the node) does both jobs at once: each call gets its children's gains, records left + node + right as a candidate answer, and returns its own gain upward. One visit per node: O(n).

Approaches from the obvious one to the one you want in an interview

Use the "highest node" observation directly. For every node t, compute the best downward path from t.left and from t.right with a separate recursive helper, and try t.val + max(0, left) + max(0, right).

The helper max_down(node) = node.val + max(0, max_down(left), max_down(right)) walks the whole subtree below it, and it is called again for every ancestor. A node at depth d is re-walked d times, so the total is O(n·h): O(n²) on a chain-shaped tree. The waste: a parent recomputes exactly what its children already computed.

Dry run

  1. [-10, 9, 20, null, null, 15, 7]
  2. top -10: max_down(9) = 9, max_down(20) = 20 + 15 = 35 → -10 + 9 + 35 = 34
  3. top 9: 9. top 20: 20 + 15 + 7 = 42. top 15: 15. top 7: 7.
  4. best = 42, but max_down(15) and max_down(7) were computed twice.

Python

class Solution:
    def maxPathSum(self, root: Optional[TreeNode]) -> int:
        def max_down(node):
            """Best sum of a path that starts at node and only goes down (0 for an empty subtree)."""
            if node is None:
                return 0
            return node.val + max(0, max_down(node.left), max_down(node.right))

        best = float("-inf")
        stack = [root]
        while stack:                              # try every node as the highest point of the path
            node = stack.pop()
            left = max(0, max_down(node.left))    # recomputed from scratch for every node
            right = max(0, max_down(node.right))
            best = max(best, node.val + left + right)
            if node.left:
                stack.append(node.left)
            if node.right:
                stack.append(node.right)
        return best
Time O(n·h), O(n²) worst caseSpace O(h)

Each node triggers a walk of its subtrees; on a chain that is n + (n-1) + ... + 1.

When to use: Only to establish the 'bend at the highest node' idea before removing the repeated work.

Merge the two recursions into one. gain(node):

  1. left = max(gain(node.left), 0) and right = max(gain(node.right), 0): children first (post-order).
  2. Candidate answer: the path bending here, node.val + left + right. Update the global best.
  3. Return node.val + max(left, right): the best path the parent can extend, which may use only one side.

Every node is processed once, and each of its children's gains is computed exactly once, so the repeated walks of the brute force disappear.

Dry run

  1. [-10, 9, 20, null, null, 15, 7], best = -∞
  2. gain(9): leaf → bend 9 → best 9; return 9
  3. gain(15) → best 15; gain(7) → 7
  4. gain(20): left 15, right 7 → bend 15 + 20 + 7 = 42 → best 42; return 20 + 15 = 35
  5. gain(-10): left 9, right 35 → bend 34 < 42; return 25. Answer 42.

Python

class Solution:
    def maxPathSum(self, root: Optional[TreeNode]) -> int:
        best = float("-inf")                      # not 0: every value may be negative

        def gain(node):
            """Best sum of a path that starts at node and goes down one side."""
            nonlocal best
            if node is None:
                return 0
            left = max(gain(node.left), 0)        # a negative branch is better left out
            right = max(gain(node.right), 0)
            best = max(best, node.val + left + right)   # the path that bends at this node
            return node.val + max(left, right)          # the parent may extend only one side

        gain(root)
        return best
Time O(n)Space O(h)

One visit per node with O(1) work; the call stack is as deep as the tree height h.

When to use: The interview answer, and the template for every 'best path through a node' tree problem.

Watch it run

The same computation without recursion, useful because a 3 * 10^4-node chain is deeper than Python's default recursion limit. First list the nodes in an order where every node comes before its children (pop from a stack, push its children). Reversed, that order puts every child before its parent, which is all post-order needs. Then fill a dictionary gain[node] in that order, updating best at each node exactly as the recursive version does.

Python

class Solution:
    def maxPathSum(self, root: Optional[TreeNode]) -> int:
        order, stack = [], [root]
        while stack:                         # every node is listed before its children
            node = stack.pop()
            order.append(node)
            if node.left:
                stack.append(node.left)
            if node.right:
                stack.append(node.right)
        gain = {None: 0}                     # node -> gain; a missing child contributes 0
        best = float("-inf")
        for node in reversed(order):         # children are handled before their parent
            left = max(gain[node.left], 0)
            right = max(gain[node.right], 0)
            best = max(best, node.val + left + right)
            gain[node] = node.val + max(left, right)
        return best
Time O(n)Space O(n)

Two linear passes; the order list and the dictionary hold every node.

When to use: When the tree can be deeper than the recursion limit; costs O(n) memory instead of O(h).

Common mistakes

  • Starting the answer at 0. If every value is negative, the answer is the largest single value ([-3] → -3), so start at float('-inf').
  • Returning node.val + left + right to the parent. That shape forks at the node, and a parent cannot extend a forked path. Record it as a candidate, but return node.val + max(left, right).
  • Forgetting to clamp negative child gains with max(gain, 0). A branch worth -5 should be left out, not added.
  • Clamping the node's own value. The bending node must be on its path even when it is negative; only the children are optional.
  • Keeping best in a class-level variable that is never reset: the next test case starts from the previous answer. Keep it local with nonlocal, or reset it at the start of maxPathSum.

Python notes

  • nonlocal best lets the nested gain function update the outer variable. Without it, the assignment best = ... makes best local to gain and the read before it raises UnboundLocalError.
  • max(gain(node.left), 0) reads as "take this branch only if it helps".
  • A dictionary keyed by TreeNode objects works (they hash by identity), which the iterative version uses to store each node's gain; {None: 0} makes missing children contribute 0 without an if.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Diameter of Binary Tree LC 543 — the same 'bend at every node' recursion, counting edges instead of summing values, so nothing needs clamping.
  • Longest Univalue Path LC 687 — a child's gain only counts when the child has the same value as the node; otherwise it contributes 0.
  • Path Sum III LC 437 — count downward paths with a given sum: keep prefix sums of the root-to-node path in a dictionary.
  • Maximum Sum BST in Binary Tree LC 1373 — the same 'return one thing upward, record another globally' shape, with a tuple (is_bst, min, max, sum).
  • Return the path, not just its sum — remember the node where best was set and every node's gain; then walk down each side, always stepping to the child with the larger positive gain.
