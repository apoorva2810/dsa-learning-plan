Longest Increasing Subsequence Medium

LeetCode #300 ↗
Status

Find the length of the longest strictly increasing sequence you can pick from a list, keeping order.

Problem

Given an integer list nums, return the length of its longest strictly increasing subsequence.

A subsequence keeps the original order but may skip elements: [3, 6, 2, 7] has the subsequence [3, 6, 7]. It does not have to be contiguous. Strictly increasing means each element is larger than the one before (equal values do not count).

Examples

Example 1
Input: nums = [10, 9, 2, 5, 3, 7, 101, 18]
Output: 4
[2, 3, 7, 101] (or [2, 5, 7, 18], among others).
Example 2
Input: nums = [0, 1, 0, 3, 2, 3]
Output: 4
[0, 1, 2, 3].
Example 3
Input: nums = [7, 7, 7, 7]
Output: 1
Equal values are not increasing.

Constraints

  • 1 <= len(nums) <= 2500
  • -10^4 <= nums[i] <= 10^4
  • follow-up: can you do it in O(n log n)?

Think first try before reading the solution

Each element is either in the subsequence or not, so a brute force has 2^n choices. What extra information makes a smaller question reusable?
Define dp[i] = length of the longest increasing subsequence that ends at nums[i]. Which earlier elements may stand directly before nums[i]?
dp[i] = 1 + max(dp[j]) over j < i with nums[j] < nums[i] (or 1 if none), and the answer is max(dp). For O(n log n), keep for each length the smallest possible last element and binary search into that list.

Key idea

"The longest increasing subsequence of the first i elements" is not a good state: knowing its length does not tell you whether nums[i] can extend it, because you do not know its last element. Fix that by making the last element part of the state: dp[i] = length of the longest increasing subsequence that ends exactly at index i.

Any such subsequence is nums[i] alone, or a subsequence ending at some earlier j with nums[j] < nums[i], extended by nums[i]. So dp[i] = 1 + max(dp[j] for j < i if nums[j] < nums[i]), defaulting to 1. The best subsequence can end anywhere, so the answer is max(dp). That is O(n²).

The faster idea asks a different question: for each length k, what is the smallest value an increasing subsequence of length k can end with? Call that list tails. It is always sorted, and a smaller tail is always better (it is easier to extend). Each new x either extends the longest length (append) or lowers the first tail that is >= x (replace). Finding that position is a binary search, so the total is O(n log n), and the answer is len(tails).

Approaches from the obvious one to the one you want in an interview

Walk through the list and decide for each element whether it joins the subsequence. It may join only if it is larger than the last element taken, so the recursion carries the index of that element (prev).

longest(i, prev) = max(skip, take) where skip = longest(i + 1, prev) and, if allowed, take = 1 + longest(i + 1, i). This explores up to 2^n subsequences. Caching (i, prev) would cut it to O(n²) states, but the table below gets there more directly.

Dry run

  1. nums = [3, 1, 2]: at index 0 take 3 or skip it
  2. take 3: neither 1 nor 2 is larger → length 1
  3. skip 3: take 1, then 2 > 1 can be taken → length 2
  4. answer 2

Python

class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        def longest(i: int, prev: int) -> int:
            """Longest increasing subsequence of nums[i:] whose values exceed nums[prev] (prev = -1: no limit)."""
            if i == len(nums):
                return 0
            best = longest(i + 1, prev)                      # skip nums[i]
            if prev == -1 or nums[i] > nums[prev]:           # nums[i] may follow the last taken value
                best = max(best, 1 + longest(i + 1, i))      # take nums[i]
            return best

        return longest(0, -1)
Time O(2ⁿ)Space O(n)

Two choices per element in the worst case (a sorted input); the stack is n deep.

When to use: Only to explain the choice structure; 2500 elements is hopeless.

dp[i] = length of the longest increasing subsequence that ends at nums[i]. Every j < i with nums[j] < nums[i] is a possible predecessor, so dp[i] = 1 + max(dp[j]) over those j (1 if there are none). The answer is max(dp).

Each cell scans all earlier cells, which gives O(n²): about 3 million comparisons for 2500 elements, fast enough here. This is the "best answer ending at index i" DP pattern.

Dry run

  1. nums = [10, 9, 2, 5, 3, 7, 101, 18]
  2. dp[0..2] = 1 (10, 9 and 2 have no smaller predecessor)
  3. dp[3] (5) = dp[2] + 1 = 2; dp[4] (3) = dp[2] + 1 = 2
  4. dp[5] (7) = max(dp[2], dp[3], dp[4]) + 1 = 3
  5. dp[6] (101) = dp[5] + 1 = 4; dp[7] (18) = 4; answer max(dp) = 4

Python

class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        n = len(nums)
        dp = [1] * n                          # dp[i] = longest increasing subsequence ending at nums[i]
        for i in range(n):
            for j in range(i):                # every earlier, smaller value can come right before nums[i]
                if nums[j] < nums[i]:
                    dp[i] = max(dp[i], dp[j] + 1)
        return max(dp)                        # it may end at any index
Time O(n²)Space O(n)

n(n - 1)/2 pairs (j, i), O(1) each; one list of n lengths.

When to use: Clear and easy to extend (counting LIS, rebuilding the sequence, other ordering rules).

Watch it run

Keep tails, where tails[k] is the smallest possible last value of an increasing subsequence of length k + 1 among the elements seen so far. Two facts make it work:

  • tails is strictly increasing (a length-3 subsequence ends with something larger than a length-2 one could).
  • For a new x, find the first tail >= x with bisect_left. If there is none, x extends the longest subsequence: append it. Otherwise x can end a subsequence of that length with a smaller value: overwrite it.

Each element costs one binary search, so O(n log n). The name comes from the card game patience, where cards are dealt onto the leftmost pile whose top is not smaller; the number of piles equals the LIS length.

Dry run

  1. nums = [10, 9, 2, 5, 3, 7, 101, 18]
  2. 10 → [10]; 9 → [9]; 2 → [2] (smaller tails for length 1)
  3. 5 → [2, 5]; 3 → [2, 3]; 7 → [2, 3, 7]
  4. 101 → [2, 3, 7, 101]; 18 → [2, 3, 7, 18]; answer 4

Python

class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        tails = []                            # tails[k] = smallest tail of an increasing subsequence of length k + 1
        for x in nums:
            pos = bisect.bisect_left(tails, x)   # first tail >= x (strict increase needs bisect_left)
            if pos == len(tails):
                tails.append(x)               # x extends the longest subsequence found so far
            else:
                tails[pos] = x                # x is a better (smaller) tail for length pos + 1
        return len(tails)
Time O(n log n)Space O(n)

One binary search over at most n tails per element.

When to use: The answer to the O(n log n) follow-up. Be ready to explain why tails is sorted.

Common mistakes

  • Returning dp[-1] instead of max(dp): the longest subsequence does not have to end at the last element ([1, 2, 0] → dp[-1] is 1, the answer is 2).
  • Using bisect_right in the O(n log n) version. It lets equal values extend a sequence, which computes the longest non-decreasing subsequence ([7, 7, 7] would give 3). Strict needs bisect_left.
  • Believing tails is an actual subsequence. After [3, 5, 6, 2] it is [2, 5, 6], which is not in order in the input; only its length is guaranteed.
  • Starting dp at 0. Every element on its own is an increasing subsequence of length 1.
  • Confusing subsequence with subarray. A contiguous version would be a simple one-pass count.

Python notes

  • bisect.bisect_left(tails, x) returns the first index whose value is >= x (or len(tails) if none), which is exactly the length slot x should improve.
  • A memoised recursion over (i, prev) with @cache works for small inputs, but it recurses n levels deep: with 2500 elements that exceeds Python's default recursion limit of 1000. The table and bisect versions are loops.
  • max(dp) is the answer for the O(n²) table; max(dp, default=0) also handles an empty list.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Number of Longest Increasing Subsequence LC 673 — keep count[i] next to dp[i]: when dp[j] + 1 ties the best, add count[j]; when it beats it, reset to count[j].
  • Russian Doll Envelopes LC 354 — sort by width ascending and height descending, then run the O(n log n) LIS on the heights; the descending tie-break stops equal widths from nesting.
  • Increasing Triplet Subsequence LC 334 — only ask whether the LIS reaches 3: tails with two variables, O(1) space.
  • Longest Common Subsequence LC 1143 — two sequences instead of one ordering rule: a 2-D table over prefixes of both strings.
  • Largest Divisible Subset LC 368 — sort, then the same O(n²) DP with "divides" instead of "smaller than", plus parent pointers to rebuild the set.
  • Return the subsequence itself — O(n²): store the best j for each i and walk back from the argmax. O(n log n): store the index behind each tail and a predecessor array.
