Valid Sudoku Medium

LeetCode #36 ↗
Status

Check that no digit repeats in any row, column or 3×3 box of a partly filled Sudoku board.

Problem

You are given a 9 × 9 Sudoku board board as a list of 9 rows, each a list of 9 one-character strings. A filled cell holds a digit "1" to "9"; an empty cell holds ".".

Return True if the filled cells break none of these rules, and False otherwise:

  1. no digit appears twice in the same row;
  2. no digit appears twice in the same column;
  3. no digit appears twice in the same 3 × 3 box (the board is split into nine such boxes).

You only check the digits already on the board. Whether the puzzle can actually be completed does not matter. In the examples each row is written as a 9-character string for brevity.

Examples

Example 1
Input: board rows = "53..7....", "6..195...", ".98....6.", "8...6...3", "4..8.3..1", "7...2...6", ".6....28.", "...419..5", "....8..79"
Output: true
No row, column or box contains the same digit twice.
Example 2
Input: the same board, but the first row is "83..7...."
Output: false
The top-left 5 became an 8, so column 0 and the top-left box each contain two 8s.

Constraints

  • len(board) == 9
  • len(board[i]) == 9
  • board[i][j] is a digit "1"-"9" or "."

Think first try before reading the solution

Each rule is a "no duplicates in this group" check, which a set does well. How many groups are there?
9 rows + 9 columns + 9 boxes = 27 groups. The digit at (r, c) belongs to exactly three of them: row r, column c and one box.
Number the boxes 0-8 with (r // 3) * 3 + c // 3. Walk the board once; for each digit, check its three sets, then add it to all three.

Key idea

The three rules are really 27 separate "no duplicates" checks: one per row, one per column and one per box. Every filled cell takes part in exactly three of them, so a single walk over the board can check them all, as long as each group has its own set of digits seen so far.

The only puzzle is finding a cell's box. Integer division does it: r // 3 is the box's row band (0, 1 or 2) and c // 3 its column band, so (r // 3) * 3 + c // 3 numbers the boxes 0 to 8, left to right and top to bottom.

Approaches from the obvious one to the one you want in an interview

For every filled cell, scan its whole row, its whole column and its 3 × 3 box for the same digit at a different position. Any twin means the board is invalid.

It is a direct reading of the rules, but each digit triggers about 8 + 8 + 8 cell reads, and every pair of cells that share a row, column or box is compared twice (once from each side). On a 9 × 9 board that is still tiny; written for an n × n board it is O(n³) instead of the O(n²) of reading each cell once.

Dry run

  1. (0, 0) = 5: row 0, column 0 and box 0 contain no other 5
  2. (0, 1) = 3: no other 3 in row 0, column 1 or box 0
  3. ... every filled cell repeats these scans, re-reading cells many times

Python

class Solution:
    def isValidSudoku(self, board: List[List[str]]) -> bool:
        for r in range(9):
            for c in range(9):
                d = board[r][c]
                if d == ".":
                    continue
                for k in range(9):
                    if k != c and board[r][k] == d:          # twin in the same row
                        return False
                    if k != r and board[k][c] == d:          # twin in the same column
                        return False
                top, left = 3 * (r // 3), 3 * (c // 3)       # corner of this cell's box
                for rr in range(top, top + 3):
                    for cc in range(left, left + 3):
                        if (rr, cc) != (r, c) and board[rr][cc] == d:
                            return False
        return True
Time O(n³) for an n × n boardSpace O(1)

Each of the n² cells scans about 3n others. With n = 9 that is about 81 × 24 reads.

When to use: Only to see where the repeated reading comes from.

Check each rule on its own. For every row, collect its digits and compare len(digits) with len(set(digits)): a set drops repeats, so a smaller set means a duplicate. Do the same for every column and every box.

Every cell is read three times (once per rule) instead of about 24 times, so this is O(n²). The code is easy to test piece by piece, at the cost of three loops that look almost the same.

Dry run

  1. rows: row 0 has digits 5, 3, 7 → 3 digits, 3 distinct → fine; ... all 9 rows fine
  2. columns: column 0 has 5, 6, 8, 4, 7 → all distinct; ... all 9 fine
  3. boxes: box 0 has 5, 3, 6, 9, 8 → all distinct; ... all 9 fine → True

Python

class Solution:
    def isValidSudoku(self, board: List[List[str]]) -> bool:
        def has_repeat(cells):                    # cells: the 9 values of one row, column or box
            digits = [x for x in cells if x != "."]
            return len(digits) != len(set(digits))

        for r in range(9):
            if has_repeat(board[r]):
                return False
        for c in range(9):
            if has_repeat([board[r][c] for r in range(9)]):
                return False
        for top in range(0, 9, 3):
            for left in range(0, 9, 3):
                box = [board[r][c] for r in range(top, top + 3) for c in range(left, left + 3)]
                if has_repeat(box):
                    return False
        return True
Time O(n²) for an n × n boardSpace O(n)

Three passes over the n² cells; only one group's digits are held at a time.

When to use: When clarity matters more than a single pass; same complexity as the next approach.

Keep 9 row sets, 9 column sets and 9 box sets. Walk the board once. For a digit d at (r, c), compute its box b = (r // 3) * 3 + c // 3. If d is already in rows[r], cols[c] or boxes[b], a rule is broken; otherwise add d to all three sets.

Each cell is read once and each set operation is O(1) on average. It also stops at the first clash, where the three-pass version might finish all the rows before reaching a column clash.

Dry run

  1. (0, 0) = 5, box 0 → add to rows[0], cols[0], boxes[0]
  2. (0, 1) = 3, box 0 → add; (0, 4) = 7, box 1 → add
  3. (1, 0) = 6 → add; (1, 3) = 1, box 1 → add; ...
  4. in the invalid board, (2, 2) = 8 finds 8 already in boxes[0] (from (0, 0)) → False

Python

class Solution:
    def isValidSudoku(self, board: List[List[str]]) -> bool:
        rows = [set() for _ in range(9)]
        cols = [set() for _ in range(9)]
        boxes = [set() for _ in range(9)]             # numbered 0-8, left to right, top to bottom
        for r in range(9):
            for c in range(9):
                d = board[r][c]
                if d == ".":
                    continue
                b = (r // 3) * 3 + c // 3             # which 3x3 box (r, c) is in
                if d in rows[r] or d in cols[c] or d in boxes[b]:
                    return False                      # d already appeared in one of its groups
                rows[r].add(d)
                cols[c].add(d)
                boxes[b].add(d)
        return True
Time O(n²) for an n × n boardSpace O(n²)

One read per cell plus O(1) set work; the 27 sets together hold each filled digit three times. For the fixed 9 × 9 board both bounds are constants.

When to use: The standard interview answer: one pass, early exit, and the bookkeeping Sudoku Solver reuses.

Common mistakes

  • A wrong box formula: r // 3 + c // 3 only produces 0-4 and merges different boxes. Use (r // 3) * 3 + c // 3, or key the box by the pair (r // 3, c // 3).
  • Forgetting to skip ".": every empty cell would then count as a repeat of the empty marker.
  • [set()] * 9 creates one set referenced nine times, so all rows share it. Build the sets with [set() for _ in range(9)].
  • Trying to solve the puzzle. A board can be valid by these rules and still have no solution; that is not asked.
  • Comparing digits with numbers: the cells are strings, so "5" == 5 is False.

Python notes

  • // is integer (floor) division: 7 // 3 == 2. It is what maps a row or column index to its box band.
  • [set() for _ in range(9)] builds nine independent sets; [set()] * 9 repeats one set nine times.
  • A compact alternative uses one set of tuples: seen.add((d, "row", r)), seen.add((d, "col", c)), seen.add((d, "box", r // 3, c // 3)), checking membership before each add.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Sudoku Solver LC 37 — fill the empty cells: backtracking, using the same 27 sets to test each candidate digit in O(1).
  • N-Queens LC 51 — the same bookkeeping on a different board: sets for columns and both diagonals (keyed by r - c and r + c) make each placement check O(1).
  • Check if Every Row and Column Contains All Numbers LC 2133 — an n × n grid with no boxes, where every row and column must contain all of 1..n: compare each set's size with n.
  • What if the board were n² × n² with n × n boxes? — nothing changes but the box index: (r // n) * n + c // n. The work stays one pass over the cells.
  • Can you use less memory? — store each group as a 9-bit integer: bit d is set once digit d is seen, tested with mask & (1 << d). 27 integers replace 27 sets.
