Word Break II Hard 250

LeetCode #140 ↗
Status

Return every way to cut a string into dictionary words, written as sentences with spaces between the words.

Problem

You are given a string s and a list of words wordDict. Insert spaces into s so that it becomes a sentence in which every word is in wordDict, and return all such sentences.

  • A dictionary word may be used as many times as you like.
  • Every letter of s must belong to exactly one word, and the letters keep their order.
  • The sentences can be returned in any order. If no sentence exists, return an empty list.

Examples

Example 1
Input: s = "gotoday", wordDict = ["go", "to", "today", "goto", "day"]
Output: ["go to day", "go today", "goto day"]
Three ways to cut gotoday into dictionary words: go + to + day, go + today and goto + day.
Example 2
Input: s = "aaa", wordDict = ["a", "aa"]
Output: ["a a a", "a aa", "aa a"]
Words can repeat. The pieces of aaa can be 1 + 1 + 1, 1 + 2 or 2 + 1 letters long.
Example 3
Input: s = "abcde", wordDict = ["ab", "cd", "abc"]
Output: []
ab + cd leaves the e, and abc leaves de. No word covers those letters.

Constraints

  • 1 <= len(s) <= 20
  • 1 <= len(wordDict) <= 1000
  • 1 <= len(wordDict[i]) <= 10
  • s and the words use lowercase letters only
  • all the words in wordDict are different

Think first try before reading the solution

Cut off the first word. At position start, which prefixes of s[start:] are in the dictionary? For each of them, the rest of the string has to be split in the same way.
That is a recursion on the start index. Different earlier cuts can reach the same suffix (in gotoday, both go + to and goto leave day). What could you store so that a suffix is solved only once?
Let sentences(start) return the list of all sentences for s[start:], with [''] when start == len(s). Store each list in a dictionary keyed by start, and test start in memo, not if memo[start]: an empty list is an answer worth remembering too.

Key idea

Split s from left to right. At index start, every prefix s[start:end] that is a dictionary word is a possible first word, and after choosing it the rest s[end:] has to be split in the same way. That is backtracking on the cut points, and it builds each sentence word by word.

The trouble is repetition. Different early cuts often land on the same suffix: in gotoday, go + to and goto both leave day, and a plain search splits day again for each of them. When the string cannot be split at all (a long run of a's followed by a b, with words made of a's) it tries every cut before it finds out. A string of n letters has up to 2ⁿ⁻¹ ways to be cut, so that is exponential.

Memoisation means remembering the answer to a question the first time it is solved. It works when the question has a small answer that does not depend on how you got there. Here the question "which sentences can be made from the letters starting at start?" depends only on start, so sentences(start) returns a list of strings and stores it in memo[start]. When nothing is left (start == n) the answer is ['']: exactly one way to finish, by adding nothing. A caller puts its own word in front of each returned sentence (word + " " + rest, or just word when rest is empty). The empty list is a real answer too ("nothing can be built from here"), and it is cached like any other.

The output itself can still be exponential (a string of a's with the words a, aa, aaa, … has about 2ⁿ⁻¹ sentences), so the worst case stays O(n · 2ⁿ). What the memo removes is the repeated and the wasted work.

Approaches from the obvious one to the one you want in an interview

Walk the string from left to right with a shared list path of the words chosen so far. At index start, try every prefix s[start:end]: if it is a dictionary word, append it, recurse from end, then pop it. When start == n the whole string is used, so join path with spaces and store the sentence.

It is the direct answer and it is correct. Its weakness is that it has no memory. Several different earlier cuts can arrive at the same start, and the suffix is then split from scratch each time. Worse, it cannot tell that a suffix is hopeless until it has tried every cut: for 18 a's followed by a b, with the words a, aa, aaa and aaaa, it makes 158,816 calls to find out that there is no sentence at all.

Dry run

  1. s = "gotoday", words {go, to, today, goto, day}, path = []. backtrack(0): the prefixes that are words are go and goto.
  2. Take go → backtrack(2): to and today are words. to → backtrack(4): day → backtrack(7) records go to day.
  3. Back in backtrack(2): today → backtrack(7) records go today.
  4. Back in backtrack(0): goto → backtrack(4) again. The suffix day is split a second time → goto day.
  5. Three sentences from 7 calls. The repeated backtrack(4) is what a memo would save.

Python

class Solution:
    def wordBreak(self, s: str, wordDict: List[str]) -> List[str]:
        words = set(wordDict)                        # O(1) membership tests
        n = len(s)
        result = []
        path = []                                    # the words chosen so far

        def backtrack(start):
            if start == n:                           # the whole string is used: one sentence
                result.append(" ".join(path))
                return
            for end in range(start + 1, n + 1):
                word = s[start:end]
                if word in words:
                    path.append(word)                # choose
                    backtrack(end)                   # explore
                    path.pop()                       # un-choose

        backtrack(0)
        return result
Time O(n · 2ⁿ)Space O(n)

A string of n letters has up to 2ⁿ⁻¹ ways to be cut and the search can visit all of them, with O(n) work per cut for the substrings and the final join. Apart from the output, only path and a recursion n deep use memory.

When to use: A fine first answer for short strings. Say out loud that the same suffix is split many times, then add the memo.

Let sentences(start) return every sentence that can be made from s[start:]. If start == n that is ['']: one way to finish, by adding nothing. Otherwise, for each prefix s[start:end] that is a dictionary word, take the sentences of the rest, sentences(end), and put the word in front of each one: word + " " + rest, or just word when rest is empty (the word ended the string).

The answer depends only on start, so store it in memo[start]. Check the cache with start in memo, not with truthiness: [] is an answer too ("nothing can be built from here") and has to be cached as well. Each suffix is now solved once, however many earlier cuts lead to it, and a hopeless suffix is rejected once instead of on every visit. For the 18 a's followed by a b the call count falls from 158,816 to 67.

The size of the output still limits the worst case: a string of a's with the words a, aa, … has about 2ⁿ⁻¹ sentences, and each one has to be built.

Dry run

  1. s = "gotoday". sentences(0): the prefixes that are words are go (to index 2) and goto (to index 4).
  2. go → sentences(2): to → sentences(4): day → sentences(7) returns ['']. So memo[4] = ['day'].
  3. Back in sentences(2): to + day gives to day. Then today → sentences(7) returns [''], giving today. memo[2] = ['to day', 'today'].
  4. Back in sentences(0): go in front of each gives ['go to day', 'go today']. Next goto → sentences(4) is in the memo: ['day'], no work → goto day.
  5. memo[0] = ['go to day', 'go today', 'goto day'] is the answer. day was split once.

Python

class Solution:
    def wordBreak(self, s: str, wordDict: List[str]) -> List[str]:
        words = set(wordDict)                        # O(1) membership tests
        n = len(s)
        memo = {}                                    # start index -> every sentence for the suffix s[start:]

        def sentences(start):
            if start == n:                           # nothing left: one way to finish, the empty sentence
                return [""]
            if start in memo:                        # `in`, not truthiness: [] is a real, cached answer
                return memo[start]
            result = []
            for end in range(start + 1, n + 1):
                word = s[start:end]
                if word in words:                    # a word starts here: split the rest recursively
                    for rest in sentences(end):
                        result.append(word + " " + rest if rest else word)
            memo[start] = result
            return result

        return sentences(0)
Time O(n · 2ⁿ)Space O(n · 2ⁿ)

In the worst case there are about 2ⁿ⁻¹ sentences of length O(n), and the memo keeps the sentences of every suffix. The memo makes the work follow the output instead of the number of cuts: a failing input costs only O(n²) substring checks.

When to use: The standard answer. Say why the cache key is only start, and why [] must be cached too.

Watch it run

Combine two questions. First answer Word Break I with a small DP: can[i] is True when the suffix s[i:] can be split into dictionary words (can[n] is True, and can[i] is True when some word s[i:j] has can[j] True). It costs O(n²) and tells you at once whether the answer is [].

Then run the plain backtracking from the first approach with one extra test: step into a word s[start:end] only when can[end] is True. A suffix that cannot be finished is never entered, so every call leads to at least one sentence and no time goes to dead ends. Nothing is cached, so a splittable suffix can still be rebuilt several times, but only on the way to sentences that really exist.

Dry run

  1. s = "abcde", words {ab, cd, abc}. can[5] = True. can[4]: e is not a word → False. can[3]: d, de → False.
  2. can[2]: cd is a word but can[4] is False → False. can[1] is False. can[0]: ab needs can[2], abc needs can[3] → False.
  3. can[0] is False, so return [] without calling backtrack at all.
  4. s = "gotoday": can[7] = True, can[4] = True (day), can[2] = True (to), can[0] = True. Backtracking then only enters words whose end has can True.

Python

class Solution:
    def wordBreak(self, s: str, wordDict: List[str]) -> List[str]:
        words = set(wordDict)
        n = len(s)
        # can[i]: can the suffix s[i:] be split into dictionary words? (the Word Break I question)
        can = [False] * (n + 1)
        can[n] = True                                # the empty suffix needs no words
        for i in range(n - 1, -1, -1):
            for j in range(i + 1, n + 1):
                if can[j] and s[i:j] in words:
                    can[i] = True
                    break
        result = []
        path = []

        def backtrack(start):
            if start == n:
                result.append(" ".join(path))
                return
            for end in range(start + 1, n + 1):
                # only walk into a word whose remaining suffix can still be finished
                if can[end] and s[start:end] in words:
                    path.append(s[start:end])
                    backtrack(end)
                    path.pop()

        if can[0]:                                   # otherwise there is no sentence at all
            backtrack(0)
        return result
Time O(n · 2ⁿ)Space O(n)

O(n²) substring checks for the table, then a search in which no branch is a dead end. In the worst case the output has about 2ⁿ⁻¹ sentences of length O(n). Memory is the table, path and a recursion n deep; the output is not counted.

When to use: When most inputs have no sentence, or you want the search itself to stay simple. It reuses the Word Break I solution.

Common mistakes

  • Checking the cache with if memo.get(start) or if memo[start]:. An empty list is falsy, so a suffix that cannot be split is worked out again on every visit, and a failing input such as 18 a's followed by a b becomes exponential again. Use start in memo.
  • Returning [] for start == len(s). Then no sentence is ever completed. The base case is [''], and the join must add the space only when rest is not empty, or every sentence ends with a trailing space.
  • Caching a result that depends on the words chosen before start. With a shared path list the sentences built so far are part of the state, so they cannot be reused. Cache the sentences of the suffix and let the caller put its word in front.
  • Testing s[start:end] in wordDict with a list. Every test then scans up to 1,000 words. Build set(wordDict) once.

Python notes

  • set(wordDict) gives O(1) average membership tests; word in some_list scans the whole list.
  • s[start:end] is the substring from start up to, but not including, end.
  • " ".join(path) turns a list of words into a sentence.
  • word + " " + rest if rest else word means (word + " " + rest) if rest else word: the space is added only when there is a rest.
  • start in memo asks whether the key exists. memo.get(start) returns None for a missing key but also returns [] for an empty answer, and both are falsy, so it cannot tell them apart.
  • functools.cache can memoise sentences(start) for you. The returned list is then shared between callers, so never change it.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Word Break LC 139 — only a yes/no answer is needed: a DP over prefixes (or the can table below) decides it in O(n²) without building a single sentence.
  • Palindrome Partitioning LC 131 — the same cut-point backtracking, but every piece must be a palindrome instead of a dictionary word; precompute which substrings are palindromes the way can is precomputed here.
  • Extra Characters in a String LC 2707 — letters may be left out of the words and you minimise how many are left over: a DP over suffixes instead of listing sentences.
  • Concatenated Words LC 472 — find the words in the list that are built from at least two other words of the list: a Word Break I check for every word.
  • Restore IP Addresses LC 93 — cut a digit string into exactly four valid pieces: the same cut-point backtracking with a fixed depth, so no memo is needed.
  • Count the sentences instead of listing them — memoise a number rather than a list: ways(start) is the sum of ways(end) over the dictionary words s[start:end]. That runs in O(n²) even when there are 2ⁿ⁻¹ sentences.
