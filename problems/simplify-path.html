Simplify Path Medium 250

LeetCode #71 ↗
Status

Turn a messy absolute Unix path into its shortest canonical form by resolving ., .. and repeated slashes.

Problem

You get an absolute Unix-style path path (it always starts with /). Return its canonical form:

  • it starts with a single /;
  • folder names are separated by exactly one /;
  • it does not end with /, unless the whole path is just the root /;
  • it contains no . and no ...

The meaning of the pieces:

  • a single dot . means "this folder" and is dropped;
  • two dots .. mean "go up to the parent folder", which cancels the folder before them. Going up from the root / stays at the root;
  • several slashes in a row count as one slash;
  • any other run of dots, such as ... or ..hidden, is an ordinary folder name.

Examples

Example 1
Input: path = "/home/user/Documents/../Pictures"
Output: "/home/user/Pictures"
The .. cancels Documents.
Example 2
Input: path = "/home//foo/"
Output: "/home/foo"
The double slash counts as one, and the trailing slash is dropped.
Example 3
Input: path = "/../"
Output: "/"
You cannot go above the root.
Example 4
Input: path = "/.../a/../b/c/../d/./"
Output: "/.../b/d"
... is an ordinary name. a and c are cancelled by a .., and the single . changes nothing.

Constraints

  • 1 <= len(path) <= 3000
  • path consists of English letters, digits, `.`, `/` and `_`
  • path is a valid absolute path: it starts with `/`

Key idea

Reading a path is walking through folders. A name takes you into a folder. .. takes you back out of the folder you entered last. . and the empty pieces created by doubled slashes do nothing. Going back out undoes the most recent step, and "the last thing in is the first thing out" is exactly what a stack does.

So split on / and handle each piece. Ignore "" and ".". On "..", pop the stack if it has anything; at the root there is nothing to go back out of, so do nothing. Anything else is a folder name: push it. When the pieces run out, the stack holds the route from the root to where you ended up, so join it with / and put one / in front.

A tempting shortcut is to delete each .. together with the piece right before it in the original path. That breaks when two .. follow each other: in /a/b/../.. the second .. must cancel a, but the piece before it is the other ... The stack always knows which folder is the last one still open.

Approaches from the obvious one to the one you want in an interview

Split the path, drop the empty pieces and the single dots, and you are left with folder names and .. markers. Then rewrite the list until no .. remains: find the leftmost .., delete it together with the name just before it (or only the .. if it is first, since the root has no parent), and look again from the start.

It is correct, but every round searches from the beginning and deletes from the middle of a list, which shifts everything after it: O(n) per round and up to n/2 rounds, so O(n²). The stack does the same cancelling in a single pass, because it always knows what "the name just before" is.

Dry run

  1. "/a/../../b" → pieces ["a", "..", "..", "b"]
  2. leftmost .. is at index 1 → delete a and .. → ["..", "b"]
  3. leftmost .. is at index 0, nothing before it → delete only the .. → ["b"]
  4. no .. left → "/b"

Python

class Solution:
    def simplifyPath(self, path: str) -> str:
        # drop empty pieces (repeated or trailing slashes) and single dots
        names = [part for part in path.split("/") if part not in ("", ".")]
        while ".." in names:
            i = names.index("..")                 # the leftmost "..": a scan from the start every round
            if i == 0:
                del names[0]                      # nothing to go back out of: the root stays the root
            else:
                del names[i - 1:i + 1]            # remove the ".." and the folder just before it
        return "/" + "/".join(names)
Time O(n²)Space O(n)

Up to n/2 rounds, each doing an O(n) search and an O(n) deletion.

When to use: Only to show what the stack replaces.

Split the path at / and keep a stack that holds the route from the root to the current folder. For each piece:

  • "" or ".": ignore it;
  • "..": pop the stack if it is not empty (the root has no parent);
  • anything else: push it, because it is an ordinary folder name.

At the end, "/" + "/".join(stack) is the canonical path. Every piece is pushed or popped at most once, so the whole pass is O(n).

Dry run

  1. "/a/./b/../../c/" → pieces ["", "a", ".", "b", "..", "..", "c", ""], stack []
  2. "" and "." → ignore; a → push → [a]; b → push → [a, b]
  3. .. → pop b → [a]; .. → pop a → []
  4. c → push → [c]; trailing "" → ignore
  5. join → "/c"

Python

class Solution:
    def simplifyPath(self, path: str) -> str:
        stack = []                                # folders from the root down to where we are now
        for part in path.split("/"):
            if part == "" or part == ".":
                continue                          # an extra slash, or "this folder": nothing to do
            if part == "..":
                if stack:                         # go back out of the last folder (the root has no parent)
                    stack.pop()
            else:
                stack.append(part)                # an ordinary name, even "..." or ".hidden": go in
        return "/" + "/".join(stack)
Time O(n)Space O(n)

split and join are linear, and each piece is pushed or popped at most once.

When to use: Always. This is the expected answer.

Watch it run

The same stack, but without split: build the current name one character at a time and handle it when a slash ends it. A sentinel slash appended to the path makes the last name end the same way as all the others, and an empty name (from a repeated slash) is simply skipped.

Useful if you are asked not to use split, or want to see that split was only a convenience. It creates fewer intermediate lists, but the logic is the same.

Python

class Solution:
    def simplifyPath(self, path: str) -> str:
        stack = []
        name = ""
        for ch in path + "/":                     # the extra slash ends the last name
            if ch != "/":
                name += ch                        # still inside a name
                continue
            # a slash just ended `name`; it is empty after a repeated slash
            if name == "..":
                if stack:
                    stack.pop()
            elif name != "" and name != ".":
                stack.append(name)
            name = ""
        return "/" + "/".join(stack)
Time O(n)Space O(n)

Each character is read once; names are short, so the string building is cheap.

When to use: When split is not allowed, or to practise writing a tiny tokenizer.

Common mistakes

  • Treating ... or ..hidden as special. Only the pieces that are exactly . or .. are special; everything else is a folder name.
  • Popping from an empty stack on a .. at the root. /../ must give /, so guard the pop with if stack.
  • Forgetting that split('/') produces empty strings for a leading, repeated or trailing slash: '/home//foo/' becomes ['', 'home', '', 'foo', '']. Skip every empty piece.
  • Joining without the leading slash, or returning an empty string for the root. Build the answer as '/' + '/'.join(stack): an empty stack gives '/'.
  • Calling path.split() with no argument. That splits on whitespace, not on slashes.

Python notes

  • path.split("/") returns the pieces between slashes, including empty strings. if part in ("", "."): continue skips both kinds of no-op.
  • "/" + "/".join(stack) builds the answer. For an empty stack "/".join([]) is "", so the result is "/", which is the right answer for the root.
  • if stack: stack.pop() guards the root. stack and stack.pop() also works but is harder to read.
  • posixpath.normpath cleans paths too, but it keeps exactly two leading slashes (normpath("//a") returns "//a"), so it does not follow this problem's rules. Interviewers expect the stack.
