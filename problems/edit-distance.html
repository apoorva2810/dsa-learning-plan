Edit Distance Medium

LeetCode #72 ↗
Status

Find the fewest insertions, deletions and replacements that turn one word into another.

Problem

Given two strings word1 and word2, return the minimum number of operations needed to turn word1 into word2.

You may apply three kinds of operation to word1, and each one counts as a single step:

  • insert one character (at any position),
  • delete one character,
  • replace one character with a different one.

Either string may be empty.

Examples

Example 1
Input: word1 = "horse", word2 = "ros"
Output: 3
horse → rorse (replace h with r) → rose (delete r) → ros (delete e).
Example 2
Input: word1 = "intention", word2 = "execution"
Output: 5
Delete t, replace i with e, replace n with x, replace n with c, insert u.
Example 3
Input: word1 = "", word2 = "ab"
Output: 2
Insert both characters.

Constraints

  • 0 <= len(word1), len(word2) <= 500
  • both strings contain only lowercase English letters

Think first try before reading the solution

Compare the last characters of the prefixes word1[:i] and word2[:j]. If they are equal, is there any reason to edit them?
If they differ, the last character of word1[:i] is replaced, or deleted, or the missing last character of word2[:j] is inserted. Each costs 1 and leaves a smaller pair of prefixes. Which pairs?
The state is the pair of prefix lengths (i, j), so fill an (m + 1) × (n + 1) table. Row 0 and column 0 are the base cases: building word2[:j] from nothing takes j insertions, and deleting word1[:i] entirely takes i deletions.

Key idea

Let dp[i][j] be the fewest operations that turn the first i characters of word1 into the first j characters of word2. (This number is called the Levenshtein distance.) Look at the last characters, a = word1[i - 1] and b = word2[j - 1].

  • They are equal: no operation is needed for them, so dp[i][j] = dp[i - 1][j - 1]. Spending an operation here can never be cheaper: a neighbouring cell never differs from dp[i - 1][j - 1] by more than 1, so deleting or inserting (which cost 1 on top of a neighbour) cannot beat the free diagonal.
  • They differ: the last character of word1[:i] has to be dealt with, in one of three ways that cost 1 each, and you keep the cheapest:
    • replace a by b; both prefixes lose their last character: 1 + dp[i - 1][j - 1];
    • delete a; word2[:j] is untouched: 1 + dp[i - 1][j];
    • insert b at the end; it matches the last character of word2[:j], so only word1[:i] against word2[:j - 1] remains: 1 + dp[i][j - 1].

Base cases: turning the empty string into word2[:j] takes j insertions (dp[0][j] = j), and turning word1[:i] into the empty string takes i deletions (dp[i][0] = i).

On the table the three options are three neighbours of the cell: diagonal = replace, up = delete, left = insert. That is the Longest Common Subsequence table again, with min instead of max and a cost of 1 for each step that is not a free match. The answer is the bottom-right cell, and walking back from it recovers an actual list of edits.

Approaches from the obvious one to the one you want in an interview

Let dist(i, j) be the fewest operations that turn word1[:i] into word2[:j], and compare the last characters:

  • i == 0: build word2[:j] from nothing with j insertions; j == 0: delete all i characters.
  • the last characters are equal: nothing to do for them, dist(i - 1, j - 1).
  • otherwise one operation is spent and a smaller pair remains; keep the cheapest: replace 1 + dist(i - 1, j - 1), delete 1 + dist(i - 1, j), insert 1 + dist(i, j - 1).

Three branches per call make an exponential tree, but only (m + 1) · (n + 1) different pairs (i, j) exist and the branches keep meeting the same ones. @cache stores each pair once, so every pair costs O(1) work.

Dry run

  1. word1 = "ab", word2 = "ba": dist(2, 2): last characters b and a differ → 1 + min(dist(1, 1), dist(1, 2), dist(2, 1))
  2. dist(1, 1): a vs b differ → 1 + min(dist(0, 0) = 0, dist(0, 1) = 1, dist(1, 0) = 1) = 1 (a replacement)
  3. dist(1, 2): a and a are equal → dist(0, 1) = 1 (insert the leading b)
  4. dist(2, 1): b and b are equal → dist(1, 0) = 1 (delete the leading a)
  5. dist(2, 2) = 1 + min(1, 1, 1) = 2

Python

class Solution:
    def minDistance(self, word1: str, word2: str) -> int:
        @cache                                          # one stored answer per pair (i, j)
        def dist(i: int, j: int) -> int:
            """Fewest operations that turn word1[:i] into word2[:j]."""
            if i == 0:
                return j                                # insert all j characters
            if j == 0:
                return i                                # delete all i characters
            if word1[i - 1] == word2[j - 1]:            # the last characters already agree
                return dist(i - 1, j - 1)
            return 1 + min(dist(i - 1, j - 1),          # replace word1[i - 1] by word2[j - 1]
                           dist(i - 1, j),              # delete word1[i - 1]
                           dist(i, j - 1))              # insert word2[j - 1]

        return dist(len(word1), len(word2))
Time O(m·n)Space O(m·n)

(m + 1)(n + 1) states, O(1) work each. The recursion can be m + n frames deep: 1000 for the largest inputs.

When to use: The natural first version. For strings beyond a few hundred characters use the table: Python's default recursion limit is 1000.

Fill the same recursion as an (m + 1) × (n + 1) table, where dp[i][j] = fewest operations to turn word1[:i] into word2[:j]. Row 0 and column 0 are the empty prefix: dp[0][j] = j and dp[i][0] = i. Then row by row, left to right:

  • word1[i - 1] == word2[j - 1] → dp[i][j] = dp[i - 1][j - 1] (diagonal, free);
  • otherwise → dp[i][j] = 1 + min(dp[i - 1][j - 1], dp[i - 1][j], dp[i][j - 1]) (replace, delete, insert).

All three neighbours are already filled when the cell is reached. The answer is dp[m][n]. Keeping the whole table lets you walk back from the corner and read off an actual shortest list of edits.

Dry run

  1. word1 = "horse", word2 = "ros": row 0 = [0, 1, 2, 3], and column 0 = 0, 1, 2, 3, 4, 5
  2. row h = [1, 1, 2, 3]: h matches none of r, o, s; e.g. dp[1][1] = 1 + min(0, 1, 1) = 1 (replace h by r)
  3. row o = [2, 2, 1, 2]: dp[2][2] is a match (o == o), so it copies the diagonal dp[1][1] = 1
  4. row r = [3, 2, 2, 2]; row s = [4, 3, 3, 2] (dp[4][3] copies the diagonal dp[3][2] = 2); row e = [5, 4, 4, 3]
  5. the answer is the bottom-right cell: dp[5][3] = 3

Python

class Solution:
    def minDistance(self, word1: str, word2: str) -> int:
        m, n = len(word1), len(word2)
        dp = [[0] * (n + 1) for _ in range(m + 1)]     # dp[i][j] = edits to turn word1[:i] into word2[:j]
        for i in range(m + 1):
            dp[i][0] = i                               # delete all i characters
        for j in range(n + 1):
            dp[0][j] = j                               # insert all j characters
        for i in range(1, m + 1):
            for j in range(1, n + 1):
                if word1[i - 1] == word2[j - 1]:       # the last characters agree: no operation
                    dp[i][j] = dp[i - 1][j - 1]
                else:
                    dp[i][j] = 1 + min(dp[i - 1][j - 1],   # replace
                                       dp[i - 1][j],       # delete
                                       dp[i][j - 1])       # insert
        return dp[m][n]
Time O(m·n)Space O(m·n)

One O(1) update per cell of the (m + 1) × (n + 1) table; no recursion.

When to use: When you also need the edit script, or want to print the table to debug.

Watch it run

Row i reads only row i - 1 (the diagonal and the cell above) and its own previous cell (the cell to the left), so two lists are enough: prev for the finished row and cur for the row being built. Start prev as row 0 (list(range(n + 1))), and for each i start cur with its column-0 base case [i]. When the row is done, prev = cur.

Because the distance is symmetric (a deletion one way is an insertion the other way), put the shorter word on the columns so each row has only min(m, n) + 1 numbers.

The trade-off: with only two rows kept you can no longer walk back to list the edits.

Dry run

  1. word1 = "horse", word2 = "ros", prev = [0, 1, 2, 3]
  2. row h: cur = [1, 1, 2, 3]; prev becomes it
  3. row o: cur = [2, 2, 1, 2]; row r: [3, 2, 2, 2]; row s: [4, 3, 3, 2]; row e: [5, 4, 4, 3]
  4. the answer is the last number of the last row: prev[3] = 3

Python

class Solution:
    def minDistance(self, word1: str, word2: str) -> int:
        if len(word2) > len(word1):
            word1, word2 = word2, word1                # the distance is symmetric: shorter word on the columns
        n = len(word2)
        prev = list(range(n + 1))                      # row 0: dp[0][j] = j insertions
        for i in range(1, len(word1) + 1):
            cur = [i] + [0] * n                        # column 0: i deletions
            for j in range(1, n + 1):
                if word1[i - 1] == word2[j - 1]:
                    cur[j] = prev[j - 1]               # diagonal, free
                else:
                    cur[j] = 1 + min(prev[j - 1],      # replace  (diagonal)
                                     prev[j],          # delete   (above)
                                     cur[j - 1])       # insert   (left)
            prev = cur                                 # the finished row becomes the "row above"
        return prev[n]
Time O(m·n)Space O(min(m, n))

Same m·n cell updates as the table; only two rows of min(m, n) + 1 numbers are alive at a time.

When to use: The interview answer when only the number is asked for. Mention the full table if they want the edits themselves.

Common mistakes

  • Wrong base cases: dp[i][0] is i and dp[0][j] is j, not 0. Turning "abc" into "" takes 3 deletions.
  • Adding 1 on a match. When the last characters agree the cell is a plain copy of the diagonal; replacing a character with itself would cost a step for nothing.
  • Using only insertions and deletions (m + n - 2 * LCS). For horse → ros that gives 4, but one replacement makes it 3.
  • Greedy position-by-position comparison: flaw → lawn differs at all 4 positions, yet deleting f and appending n does it in 2. Characters shift, so compare prefixes, not positions.
  • Top-down recursion on two 500-character strings can go 1000 calls deep, right at Python's default recursion limit. The table has no such depth.

Python notes

  • min(a, b, c) takes any number of arguments, so the three neighbours read naturally as min(dp[i - 1][j - 1], dp[i - 1][j], dp[i][j - 1]).
  • prev = list(range(n + 1)) is row 0 (dp[0][j] = j) in one expression, and cur = [i] + [0] * n starts a row with its column-0 base case.
  • The edit distance is symmetric (a deletion in one direction is an insertion in the other), so the shorter word can always go on the columns to keep the rows short: if len(word2) > len(word1): word1, word2 = word2, word1.
  • @cache keys on (i, j); define the cached function inside the method so each test starts with an empty cache. The recursion is up to m + n frames deep.
  • prev = cur after each row is enough: a fresh cur list is created for the next row, so nothing is overwritten.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Longest Common Subsequence LC 1143 — the sibling table: a match adds 1 and a mismatch takes max(up, left). Edit distance swaps that for 1 + min over three neighbours and a free match.
  • Delete Operation for Two Strings LC 583 — only deletions (from either string) are allowed, so the answer is len(a) + len(b) - 2 * LCS; compare with the replace option here, which can save a step.
  • Minimum ASCII Delete Sum for Two Strings LC 712 — each deletion costs the character's ASCII code instead of 1: the same table with weighted costs.
  • Distinct Subsequences LC 115 — count how many ways word2 appears inside word1 as a subsequence: the same (i, j) table, adding counts instead of taking a minimum.
  • Interleaving String LC 97 — another prefix-pair table, holding booleans: can the first i + j characters of s3 be formed from s1[:i] and s2[:j]?
  • Return the edit script — walk back from the corner: a match goes diagonally for free; otherwise move to the neighbour that is exactly 1 smaller (diagonal = replace, up = delete, left = insert). It needs the full table.
  • Very long strings, small distance k — a cell with abs(i - j) > k can never be part of a path of cost at most k, so only a band of 2k + 1 diagonals needs computing: O(k · n) time.
