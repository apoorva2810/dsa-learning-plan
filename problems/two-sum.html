Two Sum Easy

LeetCode #1 ↗
Status

Find the two positions in a list whose values add up to a target.

Problem

You are given a list of integers nums and an integer target. Return the indices of the two numbers that add up to target.

  • Each input has exactly one valid answer.
  • You may not use the same element twice (the two indices must be different).
  • You can return the pair in any order.

Examples

Example 1
Input: nums = [2, 7, 11, 15], target = 9
Output: [0, 1]
nums[0] + nums[1] = 2 + 7 = 9.
Example 2
Input: nums = [3, 2, 4], target = 6
Output: [1, 2]
3 + 3 would work numerically, but index 0 cannot be used twice. 2 + 4 = 6.
Example 3
Input: nums = [3, 3], target = 6
Output: [0, 1]

Constraints

  • 2 <= len(nums) <= 10^4
  • -10^9 <= nums[i] <= 10^9
  • -10^9 <= target <= 10^9
  • exactly one valid answer exists

Think first try before reading the solution

The slow way is to try every pair. How many pairs are there for a list of length n? That tells you why it is slow.
For a number x you are looking at, the partner you need is fixed: it is target - x. Can you check whether that partner exists without scanning the whole list again?
A dictionary (hash map) answers 'have I seen this value, and where?' in O(1). Build it as you go, so you never pair an element with itself.

Key idea

The brute force asks, for every number, "is there another number that completes it?" by rescanning the list. The trick is to notice that the partner is known the moment you look at a number: it is target - x. So instead of searching for it, remember every number you have already seen in a dictionary (value -> index). When you reach x, one dictionary lookup tells you whether target - x was seen earlier and where.

Doing the lookup before inserting x also guarantees you never pair an element with itself. One pass, one lookup per element: O(n) time, O(n) extra space.

Approaches from the obvious one to the one you want in an interview

The most direct reading of the problem: for every position i, look at every later position j and test whether the two values add up to target. Using j > i means each pair is tested once and an element is never paired with itself.

There are about n²/2 pairs, so for 10,000 numbers that is ~50 million additions. It works, but it is the answer an interviewer expects you to start from, not finish with.

Dry run

  1. nums = [2, 7, 11, 15], target = 9
  2. i = 0 (value 2): try j = 1 → 2 + 7 = 9. Match on the very first pair, return [0, 1].
  3. With nums = [3, 2, 4], target = 6: (3,2)=5, (3,4)=7, (2,4)=6 → [1, 2]. Three checks for three numbers; for n numbers it is n(n-1)/2 checks.

Python

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):          # j > i: never the same index twice
                if nums[i] + nums[j] == target:
                    return [i, j]
        return []                              # unreachable for valid input
Time O(n²)Space O(1)

Two nested loops over n elements; no extra memory beyond a couple of counters.

When to use: Only as a warm-up, or when n is tiny and you want zero extra memory.

Watch it run

First build a dictionary value -> index for the whole list. Then, for every x, look up target - x. The lookup is O(1), so the whole thing is O(n).

The catch is duplicates: {v: i for i, v in enumerate(nums)} keeps only the last index of a repeated value. With [3, 3] and target 6 you must make sure the index you found is not i itself, and with the dictionary built this way, 3 -> 1, so at i = 0 you find index 1 and succeed; at i = 1 you would find yourself. The index_of[need] != i guard handles it, but it is easy to forget.

Dry run

  1. Pass 1 over [2, 7, 11, 15]: index_of = {2: 0, 7: 1, 11: 2, 15: 3}.
  2. Pass 2: i = 0, x = 2, need 7 → in the map at index 1, and 1 ≠ 0 → return [0, 1].

Python

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        index_of = {}
        for i, x in enumerate(nums):           # pass 1: where does each value live?
            index_of[x] = i
        for i, x in enumerate(nums):           # pass 2: look for the partner
            need = target - x
            if need in index_of and index_of[need] != i:
                return [i, index_of[need]]
        return []
Time O(n)Space O(n)

Two linear passes; the dictionary holds up to n entries.

When to use: Fine in practice; the one-pass version below is the same complexity with less to get wrong.

Watch it run

Merge the two passes. Walk the list once and keep a dictionary seen of values already visited. At element x, ask seen whether target - x is in it:

  • yes → its stored index and the current index are the answer;
  • no → store x -> i and move on.

Because you look up before you insert, the partner you find is always an earlier element, so the self-pairing bug disappears by construction, and duplicates are handled for free ([3, 3]: at i = 1 the first 3 is already in seen).

Dry run

  1. nums = [2, 7, 11, 15], target = 9, seen = {}
  2. i = 0, x = 2, need 7: not in seen → seen = {2: 0}
  3. i = 1, x = 7, need 2: in seen at index 0 → return [0, 1]
  4. Only two elements were ever touched.

Python

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}                              # value -> index, for elements before i
        for i, x in enumerate(nums):
            need = target - x
            if need in seen:                   # look up first ...
                return [seen[need], i]
            seen[x] = i                        # ... then remember x
        return []
Time O(n)Space O(n)

One pass; each element costs one dictionary lookup and at most one insert.

When to use: This is the interview answer. Mention the O(n) memory trade-off versus the brute force.

Common mistakes

  • Pairing an element with itself (e.g. [3, 2, 4], target 6 returning [0, 0]). Look up the complement before inserting the current number.
  • Building the whole dictionary first with {v: i for i, v in enumerate(nums)} overwrites earlier indices for duplicate values; [3, 3] then fails. Insert as you go instead.
  • Returning values instead of indices. The question asks for positions.
  • Sorting the list to use two pointers destroys the original indices unless you sort (value, index) pairs.

Python notes

  • enumerate(nums) gives you (index, value) pairs, which is exactly what this problem needs.
  • if complement in seen: is a hash lookup; on average it costs the same for a 10-element list and a 10-million-element list.
  • The dictionary maps value -> index. If the question asked for values, a set would be enough.

Follow-up questions

What an interviewer might ask next, and what changes.

  • 3Sum LC 15 — three numbers that sum to zero, with duplicate triplets removed: sort, fix one number, two-pointer the rest.
  • 4Sum LC 18 — same idea one level deeper; think about how the k-sum pattern generalises.
  • Two Sum III - Data structure design LC 170 — add(number) and find(target) calls interleave: which operation should be O(1) and which O(n)?
  • Count pairs with a given sum — return how many pairs sum to target instead of one pair: keep counts in the dictionary, not indices.
  • What if nums is a stream too large to store? — you cannot answer exactly without memory; discuss trade-offs (Bloom filter for 'probably seen').
