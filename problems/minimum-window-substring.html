Minimum Window Substring Hard

LeetCode #76 ↗
Status

Find the shortest substring of s that contains every character of t, repeats included.

Problem

You are given two strings s and t. Return the shortest substring of s that contains every character of t, counting repeats: if t has two as, the substring needs at least two as. Other characters may appear in the substring too.

If no substring of s qualifies, return the empty string "". When an answer exists it is unique.

Examples

Example 1
Input: s = "ADOBECODEBANC", t = "ABC"
Output: "BANC"
"ADOBEC" and "CODEBA" also contain A, B and C, but "BANC" is the shortest.
Example 2
Input: s = "a", t = "a"
Output: "a"
Example 3
Input: s = "a", t = "aa"
Output: ""
t needs two a's but s has only one.

Constraints

  • 1 <= len(s), len(t) <= 10^5
  • s and t consist of uppercase and lowercase English letters

Think first try before reading the solution

If s[left..right] contains all of t, so does every longer window around it. So for each right, you want the largest left that still keeps the window valid.
Grow right until the window covers t. Then shrink from the left for as long as it stays valid, recording the shortest window. As soon as it stops being valid, go back to growing.
Track need[c] (copies of c still required; negative means surplus) and missing (required characters not yet in the window). Validity is then the O(1) check missing == 0.

Key idea

Validity here is monotone: if a window contains all of t, every bigger window around it does too, and if a window does not, none of the windows inside it do. That is the property that lets a sliding window solve the problem in one pass.

Move right forward to grow the window until it covers t. It is now valid but possibly too long, so move left forward while it stays valid, recording every valid window shorter than the best so far. The moment removing s[left] loses a character t needs, the window is invalid and you go back to growing.

Checking "does the window cover t?" by comparing counters would cost O(alphabet) each time. Instead keep need[c], how many more copies of c the window still needs (negative when it has extra), and missing, the number of required characters still absent. The window is valid exactly when missing == 0. Each pointer crosses s once, so the total is O(len(s) + len(t)).

Approaches from the obvious one to the one you want in an interview

For each start index, extend the window to the right one character at a time, counting characters, until it contains everything t needs. That is the shortest valid window starting there; keep the shortest over all starts.

Checking coverage compares the window's counts with t's, O(k) for k distinct characters of t, and there are up to n² (start, end) pairs, so the total is O(n² · k). Each new start throws away all the counting the previous start did, even though the two windows overlap almost entirely.

Dry run

  1. s = "ADOBECODEBANC", t = "ABC"
  2. start 0: grow to ADOBEC (A, B, C all present) → length 6
  3. start 1: grow to DOBECODEBA → 10; start 2: OBECODEBA → 9; ...
  4. start 9: grow to BANC → 4, the shortest

Python

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        need = Counter(t)
        best = ""
        for start in range(len(s)):
            have = Counter()
            for end in range(start, len(s)):
                have[s[end]] += 1
                if all(have[c] >= need[c] for c in need):         # window covers t
                    if not best or end - start + 1 < len(best):
                        best = s[start:end + 1]
                    break                                         # longer windows from `start` are worse
        return best
Time O(n² · k)Space O(n + k)

n = len(s), k = distinct characters of t; up to n² windows, each coverage check O(k). The best substring is copied when it improves.

When to use: Only to see the wasted recounting that the sliding window avoids.

Keep need = Counter(t) and missing = len(t).

  1. Grow: move right forward. If need[c] > 0 the new character fills a gap, so missing -= 1. Always do need[c] -= 1 (negative values mean the window has more copies than t needs).
  2. Shrink: while missing == 0, the window is valid. Record it if it is the shortest so far, then remove s[left]: need[s[left]] += 1, and if that makes it positive, a needed character just left, so missing += 1. Move left.

Every valid window that could be the answer is examined at the moment it is as short as it can be for its right end. Each index enters and leaves the window once: O(len(s) + len(t)) time.

Dry run

  1. s = "ADOBECODEBANC", t = "ABC", missing 3
  2. grow: A (missing 2), D, O, B (missing 1), E, C (missing 0) → ADOBEC covers t, best 6
  3. shrink: drop A → missing 1 → grow again
  4. grow: O, D, E, B (surplus), A (missing 0) → DOBECODEBA; shrink past D, O, B, E → CODEBA; drop C → missing 1
  5. grow: N, C (missing 0) → ODEBANC; shrink past O, D, E → BANC, best 4; drop B → missing 1
  6. end of s → answer BANC

Python

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        need = Counter(t)                     # copies still needed (< 0 means surplus in the window)
        missing = len(t)                      # needed characters not yet in the window
        best_start, best_len = 0, float("inf")
        left = 0
        for right, c in enumerate(s):
            if need[c] > 0:
                missing -= 1                  # c fills a real gap
            need[c] -= 1
            while missing == 0:               # window covers t: record it, then try to shorten it
                if right - left + 1 < best_len:
                    best_start, best_len = left, right - left + 1
                old = s[left]
                need[old] += 1
                if need[old] > 0:
                    missing += 1              # dropping `old` opened a gap: stop shrinking
                left += 1
        return "" if best_len == float("inf") else s[best_start:best_start + best_len]
Time O(n + m)Space O(k)

n = len(s), m = len(t) (to build the counter); each index of s enters and leaves the window once. need holds the distinct characters seen.

When to use: The standard answer and the template for every 'shortest window that covers ...' problem.

Common mistakes

  • Recording the answer only while growing. The shortest window appears while shrinking, so update the best inside the shrink loop, before removing s[left].
  • Ignoring repeated letters in t: t = "AA" needs two A's. A set of required letters is not enough; use counts.
  • Decrementing missing for every character that enters. Only a character that was still needed (need[c] > 0 before the decrement) reduces it; extra copies and characters outside t do not.
  • Building s[left:right + 1] every time a better window appears: each slice is a copy. Store (start, length) and slice once at the end.
  • Forgetting the no-answer case: start the best length at infinity and return "" if it never changes.

Python notes

  • Counter(t) builds the required counts, and reading need[c] for a character not in t returns 0 without raising.
  • Keep the best window as (start, length) with length = float("inf") at first; one slice at the end builds the answer.
  • for right, c in enumerate(s) drives the right edge; left is a plain integer that only ever increases.
