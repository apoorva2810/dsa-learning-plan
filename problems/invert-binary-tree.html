Invert Binary Tree Easy

LeetCode #226 ↗
Status

Mirror a binary tree by making the left and right child of every node trade places.

Problem

Given the root of a binary tree, invert it and return its root.

Inverting means mirroring the tree left to right: at every node, the left and right children trade places, and each child keeps everything that hangs below it. An empty tree stays empty.

Examples

Example 1
Input: root = [4, 2, 7, 1, 3, 6, 9]
Output: [4, 7, 2, 9, 6, 3, 1]
The root's children 2 and 7 swap, and so do 1 and 3 under node 2, and 6 and 9 under node 7.
Example 2
Input: root = [2, 1, 3]
Output: [2, 3, 1]
Example 3
Input: root = []
Output: []

Constraints

  • 0 <= number of nodes <= 100
  • -100 <= Node.val <= 100

Think first try before reading the solution

Mirror a node that has two leaf children by hand: what happened to the two children? Then try a node whose children have children of their own. What must also happen inside those subtrees?
The mirror of a tree is its two subtrees swapped, with each of them mirrored too. 'Mirror each subtree' is the same problem on a smaller tree, so a recursive call can do it for you.
Base case: None has nothing to swap, return None. At a node: swap left and right, call the function on both children, return the node. Without recursion: put nodes in a queue (or stack) and swap the children of each one you take out.

Key idea

Mirroring a tree is one small move repeated everywhere: at a node, swap its left and right pointers. Doing that at every node mirrors the whole tree. The order in which you visit the nodes does not matter, because swapping at one node only changes that node's own two pointers and never changes which children another node has.

That is why the recursion is so short. invert(node) swaps the two children, then hands each of them to invert; the trees below are the same problem, just smaller. The base case is None: an empty tree is its own mirror, so return it unchanged. Every node is swapped exactly once, so the time is O(n), and the recursion is as deep as the tree is tall.

Level by level works just as well. Keep a queue of nodes that still need their children swapped, take one out, swap, and queue its children. The answer never depends on the visiting order, only on swapping every node once.

Approaches from the obvious one to the one you want in an interview

Define the answer for a node in terms of smaller answers:

  • invert(None) is None: an empty tree is its own mirror.
  • invert(node): swap node.left and node.right, call invert on both children (now in their new places), and return node.

The swap fixes this node; the two recursive calls fix everything below it. Each node is handled once, so the time is O(n). Python's call stack remembers where we are in the tree, so no extra bookkeeping is needed.

Dry run

  1. root = [4, 2, 7, 1, 3, 6, 9]
  2. invert(4): swap its children 2 and 7, so 4's left is now 7 and its right is now 2.
  3. invert(7): swap 6 and 9. Both are leaves, so the two invert(None) calls return at once.
  4. invert(2): swap 1 and 3 the same way.
  5. Back at 4 both subtrees are mirrored: [4, 7, 2, 9, 6, 3, 1].

Python

class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        if root is None:                                # an empty tree is its own mirror
            return None
        root.left, root.right = root.right, root.left   # swap the two children
        self.invertTree(root.left)                      # mirror what is now the left subtree
        self.invertTree(root.right)                     # ... and the right subtree
        return root
Time O(n)Space O(h)

Every node is swapped once. The call stack is as deep as the tree is tall: log n when balanced, n for a chain.

When to use: The default. It is the shortest version and the template for most tree recursion.

Watch it run

Recursion is optional: all that matters is that every node gets swapped once, in any order. Keep a queue of nodes whose children have not been swapped yet. Start with the root. Take a node out, swap its two children, and put each child that exists into the queue so that it is swapped later.

Because the order does not change the result, a stack (take from the end of a list) works just as well; that is the depth-first twin of this code. Both avoid Python's recursion limit, which matters when the tree can be very deep.

Dry run

  1. queue = [4]
  2. take 4: swap 2 and 7, queue 7 then 2 → queue [7, 2]
  3. take 7: swap 6 and 9, queue 9 then 6 → queue [2, 9, 6]
  4. take 2: swap 1 and 3, queue 3 then 1 → queue [9, 6, 3, 1]
  5. 9, 6, 3 and 1 are leaves: nothing to swap, nothing to queue → queue empty, done.

Python

class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        queue = deque([root] if root else [])           # nodes whose children are still to be swapped
        while queue:
            node = queue.popleft()
            node.left, node.right = node.right, node.left   # swap this node's children
            if node.left:                                   # schedule the children that exist
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        return root
Time O(n)Space O(w)

Every node enters the queue once. The queue holds at most one level, so w (the widest level) is up to n/2.

When to use: When the tree might be too deep for recursion, or when you are asked for an iterative solution.

Watch it run

If the input must stay untouched, build a new tree instead of rearranging the old one. The new node for root has the same value; its left child is the mirror of the old right subtree, and its right child is the mirror of the old left subtree. The original nodes are only read, never changed.

The price is memory: n new nodes on top of the recursion stack. The time is still O(n).

Dry run

  1. root = [2, 1, 3]
  2. new node 2: left = mirror of the old right subtree (node 3), right = mirror of the old left subtree (node 1)
  3. each mirror of a leaf is a fresh copy of that leaf → [2, 3, 1], and the original [2, 1, 3] is unchanged.

Python

class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        if root is None:
            return None
        # new node, with the children crossed over: old right becomes new left and vice versa
        return TreeNode(root.val, self.invertTree(root.right), self.invertTree(root.left))
Time O(n)Space O(n)

n new nodes are allocated, plus the call stack.

When to use: When other code still holds the original tree and expects it unchanged.

Common mistakes

  • Writing root.left = root.right and then root.right = root.left. After the first line the old left child is gone, so both pointers end up at the old right child. Swap in one statement: root.left, root.right = root.right, root.left.
  • Guarding the swap with if root.left and root.right. A node with exactly one child must flip sides too: [1, 2] becomes [1, None, 2]. Swap unconditionally; swapping a child with None is fine.
  • Swapping only at the root, or only at the leaves. A mirror image needs a swap at every node, so the recursion (or loop) has to reach all of them.
  • Forgetting return root. The caller reads the returned value, so an implicit None from the top-level call is an empty answer.
  • In the copying version, writing TreeNode(root.val, invert(root.left), invert(root.right)). Without crossing the children that is an exact copy, not a mirror.

Python notes

  • a, b = b, a swaps without a temporary variable: Python builds the tuple (b, a) first and only then assigns. root.left, root.right = root.right, root.left is the idiom for this problem.
  • The one-line form root.left, root.right = self.invertTree(root.right), self.invertTree(root.left) also works, because both recursive calls finish before either assignment happens.
  • A TreeNode object is truthy and None is falsy, so if node.left: is the usual check for 'has a left child'.
  • The visiting order does not matter here, so the iterative version can use a plain list as a stack (pop()) instead of a deque queue (popleft()). Both are O(1); list.pop(0) would be O(n).

Follow-up questions

What an interviewer might ask next, and what changes.

  • Symmetric Tree LC 101 — is the tree its own mirror? Compare the left and right subtrees as a pair: match a.left with b.right and a.right with b.left.
  • Same Tree LC 100 — walk two trees at the same time and compare node by node: the pair-walking pattern that Symmetric Tree builds on.
  • Flip Equivalent Binary Trees LC 951 — two trees are equal if some set of child swaps turns one into the other: at each pair of nodes accept either the straight or the crossed pairing of children.
  • Binary Tree Level Order Traversal LC 102 — the queue loop of the BFS version, but you keep each level's values instead of swapping.
  • What if the tree is a million nodes in a chain? — recursion would overflow Python's call stack (about 1000 frames by default). The queue or stack version keeps its own list of pending nodes, so it has no such limit.
