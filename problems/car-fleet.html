Car Fleet Medium

LeetCode #853 ↗
Status

Cars on a one-lane road cannot overtake; count how many separate groups reach the destination.

Problem

n cars drive along a single-lane road toward mile target. Car i starts at mile position[i] and drives at speed[i] miles per hour.

Cars can never pass each other. When a faster car catches up with a slower one, it slows down and they continue bumper to bumper at the slower speed; such a group is a car fleet. A single car on its own is also a fleet. If a car catches up exactly at mile target, it still counts as part of that fleet.

Return the number of car fleets that arrive at the destination.

Examples

Example 1
Input: target = 12, position = [10, 8, 0, 5, 3], speed = [2, 4, 1, 1, 3]
Output: 3
The cars at 10 and 8 both need 1 hour, so they meet exactly at mile 12. The car at 0 never catches anyone. The car at 3 catches the slow car at 5 at mile 6, and they finish together at hour 7.
Example 2
Input: target = 10, position = [3], speed = [3]
Output: 1
Example 3
Input: target = 100, position = [0, 2, 4], speed = [4, 2, 1]
Output: 1
The car at 0 catches the car at 2 at mile 4; together they catch the car at 4 at mile 6, and all three crawl to the end at speed 1.

Constraints

  • n == len(position) == len(speed), 1 <= n <= 10^5
  • 0 < target <= 10^6
  • 0 <= position[i] < target, all positions are distinct
  • 0 < speed[i] <= 10^6

Think first try before reading the solution

Cars never pass each other, so their order along the road never changes. Which single car decides whether a car gets blocked?
Work out each car's arrival time if the road were empty: (target - position) / speed. Then process the cars starting with the one closest to the target.
A car whose solo time is less than or equal to the arrival time of the fleet just ahead catches it and joins it; otherwise it starts a new, slower fleet. Keep the fleet arrival times on a stack.

Key idea

Overtaking is impossible, so order matters, and the car closest to the target is never slowed down. Walk the cars from the front of the road to the back and compare times, not positions: a car that would arrive no later than the fleet directly ahead of it must catch that fleet on the way (or exactly at the line), and from then on it arrives when the fleet does. A car that would arrive later never catches up, so it leads a new fleet, and every car behind it now compares against this slower fleet.

The fleet arrival times therefore form a stack that only grows upward in time: the top is the fleet directly ahead of the next car. Sorting costs O(n log n) and the scan is O(n).

Approaches from the obvious one to the one you want in an interview

A car leads its own fleet exactly when every car ahead of it (closer to the target) would arrive strictly earlier on an empty road. If some car ahead would arrive at the same time or later, our car reaches it at or before the target and gets absorbed into a fleet. So count the cars that no car ahead of them can block.

Checking every pair of cars costs O(n²): 10¹⁰ comparisons for 10⁵ cars.

Dry run

  1. target 12. Solo times: 10 → 1, 8 → 1, 0 → 12, 5 → 7, 3 → 3
  2. car at 10: nothing ahead → leads a fleet
  3. car at 8 (1 h): the car at 10 needs 1 h ≥ 1 → blocked
  4. car at 5 (7 h): ahead are 1 h and 1 h, both earlier → leads a fleet
  5. car at 3 (3 h): the car at 5 needs 7 h ≥ 3 → blocked
  6. car at 0 (12 h): every car ahead is earlier → leads a fleet. Total 3

Python

class Solution:
    def carFleet(self, target: int, position: List[int], speed: List[int]) -> int:
        n = len(position)
        times = [(target - p) / s for p, s in zip(position, speed)]   # arrival time on an empty road
        fleets = 0
        for i in range(n):
            # car i is caught in a fleet if some car ahead would arrive no earlier than it
            blocked = any(position[j] > position[i] and times[j] >= times[i] for j in range(n))
            if not blocked:
                fleets += 1                    # car i leads its own fleet
        return fleets
Time O(n²)Space O(n)

Every car is compared with every other car; the solo times take O(n) memory.

When to use: Only to make the 'compare arrival times, not speeds' idea concrete.

Sort the cars by position, closest to the target first, and keep a stack of fleet arrival times.

For each car compute its solo time (target - pos) / spd:

  • if the stack is non-empty and time <= stack[-1], the car catches the fleet directly ahead and joins it, so the stack is unchanged;
  • otherwise it is slower than that fleet and never catches it: push time as a new fleet.

The answer is the stack's size. The top is always the fleet directly ahead of the next car, which is the only one that can block it.

Dry run

  1. sorted: (10, 2) → 1 h, (8, 4) → 1 h, (5, 1) → 7 h, (3, 3) → 3 h, (0, 1) → 12 h
  2. 1 h: empty stack → push → [1]
  3. 1 h ≤ 1 → joins (they meet exactly at the target) → [1]
  4. 7 h > 1 → new fleet → [1, 7]
  5. 3 h ≤ 7 → joins the fleet led by the car at 5 → [1, 7]
  6. 12 h > 7 → new fleet → [1, 7, 12] → 3 fleets

Python

class Solution:
    def carFleet(self, target: int, position: List[int], speed: List[int]) -> int:
        cars = sorted(zip(position, speed), reverse=True)   # closest to the target first
        stack = []                                          # arrival time of each fleet, front fleet at the bottom
        for pos, spd in cars:
            time = (target - pos) / spd                     # arrival time on an empty road
            if stack and time <= stack[-1]:
                continue                                    # catches the fleet ahead and joins it
            stack.append(time)                              # too slow to catch up: a new fleet
        return len(stack)
Time O(n log n)Space O(n)

Sorting dominates; the scan is O(n) and the stack holds at most one time per car.

When to use: The standard answer: the stack makes each fleet visible.

Watch it run

The stack only ever grows and only its top is read, so it can shrink to one number: the arrival time of the slowest fleet seen so far (the one directly ahead). The count of fleets is the number of times a car sets a new, strictly later arrival time while you walk back from the target.

Same O(n log n) time because of the sort, O(1) memory beyond it. The trade-off is clarity: the stack version shows the fleets themselves, which helps when a follow-up asks which cars are in each fleet.

Python

class Solution:
    def carFleet(self, target: int, position: List[int], speed: List[int]) -> int:
        fleets = 0
        slowest_ahead = 0.0                     # arrival time of the fleet directly ahead
        for pos, spd in sorted(zip(position, speed), reverse=True):
            time = (target - pos) / spd
            if time > slowest_ahead:            # cannot catch up: leads a new, slower fleet
                fleets += 1
                slowest_ahead = time
        return fleets
Time O(n log n)Space O(1)

The sort dominates; the scan keeps two numbers (the sorted copy itself is O(n)).

When to use: When only the count matters.

Common mistakes

  • Sorting by speed or by arrival time instead of by position: who blocks whom depends only on the order on the road.
  • Using < instead of <=: a car that catches up exactly at the target belongs to that fleet (target 10, cars at 5 and 0 with speeds 1 and 2 form one fleet).
  • Integer division (target - pos) // spd: times 1.33 and 1.0 both become 1, and two separate fleets look merged. Use /.
  • Comparing a car with the solo time of the car directly ahead instead of that car's fleet time: a slowed-down car arrives when its fleet does. The stack top always holds the fleet time.
  • Scanning from the back of the road first: a car's fate depends on the cars in front of it, which you would not have processed yet.

Python notes

  • sorted(zip(position, speed), reverse=True) sorts (position, speed) pairs by position, largest first. Positions are distinct, so speed never breaks a tie.
  • / is true division in Python 3 and returns a float. Floats are safe here: each time comes from one correctly rounded division, so two equal fractions always give exactly equal floats.
  • Only stack[-1] is ever read, so len(stack) is just a counter of "new slowest time" events; see the last approach.
