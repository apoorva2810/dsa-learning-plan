Happy Number Easy

LeetCode #202 ↗
Status

Decide whether repeatedly replacing a number by the sum of the squares of its digits ever reaches 1.

Problem

Start with a positive integer n. Replace it with the sum of the squares of its digits, and repeat. For n = 19: 1² + 9² = 82, then 8² + 2² = 68, then 6² + 8² = 100, then 1² + 0² + 0² = 1.

A number is happy if this process reaches 1. If it never does, it gets stuck in a loop that does not contain 1. Return True if n is happy and False otherwise.

Examples

Example 1
Input: n = 19
Output: true
19 → 82 → 68 → 100 → 1.
Example 2
Input: n = 2
Output: false
2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → … The chain is back at 4, a value it already visited, so it repeats forever and never reaches 1.
Example 3
Input: n = 1
Output: true
Already 1.

Constraints

  • 1 <= n <= 2^31 - 1

Key idea

There are only two ways the process can end. Either it reaches 1 (and then stays on 1, because 1² = 1), or some value comes up a second time, and from then on the same values repeat forever. It cannot grow without limit: a number with four or more digits always shrinks (four digits map to at most 4 × 81 = 324), so after a few steps the value is below 1000, and from then on it can never exceed 3 × 81 = 243. With only a few hundred possible values, a repeat is unavoidable if 1 is never reached.

That turns the question into "have I been here before?". You can remember every value in a set and stop when one repeats. Or you can use Floyd's tortoise and hare: a slow pointer takes one step per round and a fast pointer takes two. If the process loops, the fast pointer eventually laps the slow one and they land on the same value. If it reaches 1, the fast pointer gets there first. No set is needed, so the memory stays constant.

Approaches from the obvious one to the one you want in an interview

The most naive idea: apply the rule a fixed number of times and see whether you land on 1. We cannot write while n != 1, because for an unhappy number that loop never ends, so we cap the number of rounds.

But how many rounds are enough? Here 1000 is just a guess. It happens to work (every happy number below 2³¹ in fact reaches 1 within 7 rounds, which you can only know by checking a few hundred values by computer), but a solution that depends on a guessed constant is fragile, and you cannot defend it in an interview. The next two approaches replace the guess with an exact test for "this is a loop".

Dry run

  1. n = 19: round 1 → 82, round 2 → 68, round 3 → 100, round 4 → 1. The check n == 1 succeeds → True.
  2. n = 2: the values cycle 4, 16, 37, … and never hit 1. After 1000 rounds the loop gives up → False.

Python

class Solution:
    def isHappy(self, n: int) -> bool:
        for _ in range(1000):                          # a guess: "surely 1000 rounds is enough"
            if n == 1:
                return True
            n = sum(int(ch) ** 2 for ch in str(n))     # sum of the squares of the digits
        return False                                   # never reached 1: assume it loops
Time O(log n)Space O(1)

The first digit sum costs one step per digit (about log n). After it the number has at most three digits, and the loop is capped at 1000 rounds.

When to use: Never as a final answer; it shows why an exact loop test is needed.

Follow the chain and put every value in a set. Stop when the value is 1 (happy) or when it is already in the set (we are in a loop that does not contain 1, so not happy). This is exact: no guessed constant.

The set stays small. The first digit sum costs about one step per digit, and from then on the values are at most 810 for a 32-bit n (ten digits × 9²), so only a few hundred distinct values can ever appear.

Dry run

  1. n = 2, seen = {}: 2 is new → add; next is 4
  2. 4 → add; next 16. 16 → add; next 37. Then 58, 89, 145, 42, 20 are all new.
  3. 20 → add; next is 4, which is in seen → return False.
  4. n = 19: 19, 82, 68, 100 are new; the next value is 1 → the loop stops with n == 1 → True.

Python

class Solution:
    def isHappy(self, n: int) -> bool:
        seen = set()
        while n != 1 and n not in seen:          # stop at 1, or at a value we have already visited
            seen.add(n)
            n = self.digit_square_sum(n)
        return n == 1                            # 1 -> happy; a repeated value -> loop

    def digit_square_sum(self, n: int) -> int:
        total = 0
        while n:
            n, digit = divmod(n, 10)             # peel off the last digit
            total += digit * digit
        return total
Time O(log n)Space O(log n)

The first digit sum is O(log n). Afterwards the value is at most 810, so there are only a few hundred distinct values; O(log n) is a safe upper bound for the set's size.

When to use: The easy, obviously correct version. Start here in an interview.

Watch it run

Use two pointers on the chain of values. slow moves one step per round, fast moves two. If the chain ends at 1, fast arrives there first. If the chain falls into a loop, both pointers end up inside it and fast gains one position per round on slow, so it must eventually land on the same value as slow.

So the loop runs while fast != 1 and slow != fast. Afterwards, fast == 1 means happy; anything else means they met inside a loop. No set is needed: only two integers are stored, so the extra memory is O(1).

fast starts one step ahead of slow. If both started on n, the test slow != fast would fail at once and the loop would never run.

Dry run

  1. n = 2: slow = 2, fast = 4
  2. Round 1: slow 4, fast 37 (4 → 16 → 37). Round 2: slow 16, fast 89. Round 3: slow 37, fast 42.
  3. Round 4: slow 58, fast 4. Round 5: slow 89, fast 37. Round 6: slow 145, fast 89.
  4. Round 7: slow 42, fast 42 → they met and fast != 1 → False.
  5. n = 19: slow = 19, fast = 82. Round 1: slow 82, fast 100. Round 2: slow 68, fast 1 → stop, True.

Python

class Solution:
    def isHappy(self, n: int) -> bool:
        slow, fast = n, self.digit_square_sum(n)       # fast starts one step ahead
        while fast != 1 and slow != fast:
            slow = self.digit_square_sum(slow)         # tortoise: one step
            fast = self.digit_square_sum(self.digit_square_sum(fast))   # hare: two steps
        return fast == 1                               # met at 1 -> happy; met elsewhere -> loop

    def digit_square_sum(self, n: int) -> int:
        total = 0
        while n:
            n, digit = divmod(n, 10)
            total += digit * digit
        return total
Time O(log n)Space O(1)

Same number of steps as the set version (a bounded number of rounds, each a digit sum), but only two integers are stored.

When to use: When memory matters, or to show you know the tortoise-and-hare idea from Linked List Cycle.

Common mistakes

  • Looping while n != 1 with no loop check. For an unhappy number such as 2 the loop never ends.
  • Assuming every step makes the number smaller. 99 turns into 162. Only numbers with four or more digits are guaranteed to shrink.
  • Detecting the loop by comparing with the starting value (n == start). The loop does not have to contain the start: for 2 the loop is 4 → 16 → … → 20 → 4, and 2 is never visited again.
  • In the tortoise-and-hare version, starting both pointers on n and looping while slow != fast. The test is false immediately, so the loop never runs. Start the fast pointer one step ahead.
  • Treating "the pointers met" as "not happy". For a happy number both pointers end up sitting on 1 and meet there, so check where they met (or test fast == 1 first).

Python notes

  • n, digit = divmod(n, 10) strips the last digit and hands it to you in one line (divmod(a, b) is (a // b, a % b)).
  • sum(int(ch) ** 2 for ch in str(n)) is the shortest digit-square sum. It builds a string every time; the divmod loop avoids that and is just as clear.
  • x in seen on a set is O(1) on average, but on a list it scans the whole list. Use a set for "seen before?".
  • Python integers never overflow, so inputs near 2³¹ − 1 need no special care here.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Linked List Cycle LC 141 — the same tortoise and hare on real next pointers: step(x) becomes x.next.
  • Linked List Cycle II LC 142 — find where the loop begins, not just whether one exists: after the pointers meet, restart one of them at the head and move both one step at a time.
  • Find the Duplicate Number LC 287 — treat nums[i] as the "next" pointer; the duplicate value is where the loop starts.
  • Add Digits LC 258 — repeat the digit sum until one digit is left. It always ends, and there is even a closed form using % 9.
  • Reverse Integer LC 7 — the same divmod digit loop, plus a 32-bit range check on the result.
  • Count the happy numbers up to N — cache the verdict for every value a chain passes through: all numbers on an unhappy chain are unhappy and all on a happy chain are happy, so each number is classified only once.
