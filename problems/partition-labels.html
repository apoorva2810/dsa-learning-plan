Partition Labels Medium

LeetCode #763 ↗
Status

Cut a string into as many pieces as possible so that no letter appears in more than one piece.

Problem

You are given a string s of lowercase letters. Cut it into as many consecutive parts as possible so that every letter appears in at most one part. Read in order, the parts must join back into s.

Return a list with the length of each part.

Examples

Example 1
Input: s = "ababcbacadefegdehijhklij"
Output: [9, 7, 8]
The parts are "ababcbaca", "defegde" and "hijhklij". Cutting into "ababcbacadefegde" and "hijhklij" is also valid, but it gives only two parts, and we want the most.
Example 2
Input: s = "eccbbbbdec"
Output: [10]
The letter "e" appears at both ends, so the whole string has to be a single part.
Example 3
Input: s = "caedbdedda"
Output: [1, 9]
"c" appears only once, so it is a part by itself. The "a" at the end forces the rest into one part.

Constraints

  • 1 <= len(s) <= 500
  • s contains only lowercase English letters

Think first try before reading the solution

If a letter is in a part, every copy of that letter must be in the same part. So if a part starts at index start, how far to the right must it reach just because of s[start]?
Walk through the part. Every new letter you meet pulls the end further right, because the part must reach that letter's last copy too. To know that, record the last index of every letter before you start.
Keep end = max(end, last[c]) while i moves right. When i == end, no letter inside the part has a copy further right, so you can cut here: record i - start + 1 and start the next part at i + 1.

Key idea

Think of each letter as claiming the stretch of the string from its first to its last occurrence. A part has to contain the whole stretch of every letter it holds. So if two letters' stretches overlap, they must share a part, and so must any further letter whose stretch overlaps theirs. The parts are exactly the groups of chained, overlapping stretches.

One sweep finds them. First record last[c], the last index of each letter. Then start a part at start and move i to the right. Every letter s[i] forces the part to reach at least last[s[i]], so keep end = max(end, last[s[i]]). When i reaches end, every letter seen in this part has all its copies inside it, so the part can close, and the next one starts at i + 1.

Why is cutting at the first allowed spot right? end is the smallest position where the part can legally close, and closing there leaves the rest of the string free for later parts. Short parts mean many parts, which is what we want.

Approaches from the obvious one to the one you want in an interview

Build the parts one at a time. A part starting at start must reach the last copy of s[start], found with s.rfind. Then scan the part: every character inside may have a copy even further right, so ask rfind again for each one and push end out. When the scan reaches end, the part is closed and the next one starts right after.

The logic is the same as the fast solution. The cost is that rfind scans the string from the right on every call, and it is called for each character, so the total is O(n²).

Dry run

  1. s = "abacbddx": start 0, end = rfind("a") = 2
  2. i = 1 (b): rfind gives 4, so end = 4; i = 2, 3, 4 give 2, 3, 4 → the scan reaches 4: part size 5
  3. start 5: end = rfind("d") = 6; i = 5, 6 → part size 2
  4. start 7: end = rfind("x") = 7 → part size 1 → [5, 2, 1]

Python

class Solution:
    def partitionLabels(self, s: str) -> List[int]:
        sizes = []
        start = 0
        while start < len(s):
            end = s.rfind(s[start])              # the part must reach the last copy of its first letter
            i = start
            while i <= end:                      # every letter inside may push the end further right
                end = max(end, s.rfind(s[i]))    # rfind scans the whole string: O(n)
                i += 1
            sizes.append(end - start + 1)
            start = end + 1
        return sizes
Time O(n²)Space O(1)

Each of the n characters triggers one rfind, which can scan up to n characters.

When to use: Fine for n ≤ 500 here, but it repeats work the next approach does once.

Do the expensive lookup once.

  1. Pass 1: last = {c: i for i, c in enumerate(s)} stores the last index of every letter.
  2. Pass 2: sweep i from left to right. Keep end = max(end, last[s[i]]), the farthest index the current part must reach.
  3. When i == end, close the part: append end - start + 1 and set start = i + 1.

Two passes over the string and a dictionary of at most 26 entries. The cut rule is the same "farthest reach" idea as in Jump Game: a block stretches until the sweep catches up with it.

Dry run

  1. s = "abacbddx" → last = {a: 2, b: 4, c: 3, d: 6, x: 7}
  2. i = 0 (a): end = 2; i = 1 (b): end = 4; i = 2 (a), i = 3 (c): end stays 4
  3. i = 4 (b): i == end → size 4 - 0 + 1 = 5, start = 5
  4. i = 5 (d): end = 6; i = 6 (d): i == end → size 2, start = 7
  5. i = 7 (x): end = 7, i == end → size 1 → [5, 2, 1]

Python

class Solution:
    def partitionLabels(self, s: str) -> List[int]:
        last = {c: i for i, c in enumerate(s)}   # last index of each letter (later indices overwrite)
        sizes = []
        start = end = 0                          # the current part is s[start..end]
        for i, c in enumerate(s):
            end = max(end, last[c])              # the part must stretch to cover every copy of c
            if i == end:                         # nothing inside reaches past i: cut here
                sizes.append(end - start + 1)
                start = i + 1
        return sizes
Time O(n)Space O(1)

Two passes over n characters. The dictionary has at most 26 entries.

When to use: The standard answer. Explain end as "the farthest right any letter in this part reaches".

Watch it run

Turn each letter into an interval [first, last]. Letters whose intervals overlap have to share a part, and so do the letters they chain to. So the parts are the merged intervals, which is the Merge Intervals problem on at most 26 intervals.

Sort the intervals by their start, then sweep: if the next interval starts after the current one ends, close the current part; otherwise stretch the current end. It reaches the same answer with a different story, and it shows why this problem is really about intervals.

Dry run

  1. s = "abacbddx" → intervals a:[0,2], b:[1,4], c:[3,3], d:[5,6], x:[7,7] (sorted by start)
  2. start with [0, 2]; b starts at 1 ≤ 2, overlap → end 4; c starts at 3 ≤ 4, overlap → end stays 4
  3. d starts at 5 > 4 → close the part [0, 4] (size 5), start a new part [5, 6]
  4. x starts at 7 > 6 → close [5, 6] (size 2); after the loop close [7, 7] (size 1) → [5, 2, 1]

Python

class Solution:
    def partitionLabels(self, s: str) -> List[int]:
        first, last = {}, {}
        for i, c in enumerate(s):
            first.setdefault(c, i)               # the first time we see c stays
            last[c] = i                          # the last time keeps moving right
        spans = sorted((first[c], last[c]) for c in first)   # one interval per letter, ordered by start

        sizes = []
        cur_start, cur_end = spans[0]
        for begin, finish in spans[1:]:
            if begin > cur_end:                  # a gap: no letter spans it, so the part ends here
                sizes.append(cur_end - cur_start + 1)
                cur_start, cur_end = begin, finish
            else:                                # overlap: same part, stretch it if needed
                cur_end = max(cur_end, finish)
        sizes.append(cur_end - cur_start + 1)    # close the final part
        return sizes
Time O(n + k log k)Space O(k)

k is the number of distinct letters (at most 26): one pass over the string plus a tiny sort.

When to use: When you recognise the interval structure, or the problem is posed with intervals instead of letters.

Common mistakes

  • Cutting as soon as i == last[s[i]], the last copy of the current letter. Other letters in the part may reach further. In "abab" the last a is at index 2, but b continues to index 3, so a cut at 2 would put b in two parts. Use the running maximum end.
  • Using the first occurrence (s.find, s.index) instead of the last (s.rfind, or a dictionary overwritten while you enumerate). The part must reach the last copy.
  • An off-by-one in the length. The part from start to i inclusive has i - start + 1 characters. Do not return the cut positions when the question asks for lengths.
  • Forgetting to move start to i + 1 after a cut, so every length keeps growing.
  • Calling s.rfind(c) inside the loop for every character. Each call scans the string, so the loop becomes O(n²). Build the dictionary once.

Python notes

  • {c: i for i, c in enumerate(s)} records the last index of each letter: later indices overwrite earlier ones for the same key.
  • s.rfind(c) returns the index of the last c (or -1) but scans the string every time it is called.
  • At most 26 letters means the dictionary has at most 26 entries, so the extra space is O(1) even though it is a dictionary.
  • s[start:i + 1] is the text of a finished part, handy if you also need the parts themselves.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Merge Intervals LC 56 — each letter is the interval [first, last]; the parts are the merged intervals, which is the third approach below.
  • Max Chunks To Make Sorted LC 769 — for a permutation of 0..n-1, cut whenever the running maximum equals the index: the same "cut when i == end" idea.
  • Max Chunks To Make Sorted II LC 768 — values may repeat and be large, so compare the maximum of the left part with the minimum of the rest (prefix maximums and suffix minimums), or use a monotonic stack.
  • Partition Array into Disjoint Intervals LC 915 — cut where every value on the left is at most every value on the right, using a prefix maximum and a suffix minimum.
  • What if the string arrives as a stream? — the last occurrence of a letter is unknown until the stream ends, so this cannot be answered online; you must buffer the string or accept a delay.
