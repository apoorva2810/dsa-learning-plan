3Sum Medium

LeetCode #15 ↗
Status

List every distinct triplet of values in an array that adds up to zero.

Problem

Given a list of integers nums, return all triplets [nums[i], nums[j], nums[k]] such that:

  • i, j and k are three different indices, and
  • nums[i] + nums[j] + nums[k] == 0.

The answer must not contain the same triplet twice. Two triplets count as the same when they hold the same three values, in any order ([-1, 0, 1] and [0, 1, -1] are one triplet). The triplets, and the numbers inside each, may be returned in any order.

Examples

Example 1
Input: nums = [-1, 0, 1, 2, -1, -4]
Output: [[-1, -1, 2], [-1, 0, 1]]
-1 + 0 + 1 = 0 can be formed with either of the two -1s, but it is listed only once. -1 + (-1) + 2 = 0 uses both -1s, which is allowed: they are different indices.
Example 2
Input: nums = [0, 1, 1]
Output: []
No three values sum to 0.
Example 3
Input: nums = [0, 0, 0]
Output: [[0, 0, 0]]

Constraints

  • 3 <= len(nums) <= 3000
  • -10^5 <= nums[i] <= 10^5

Think first try before reading the solution

Checking every triplet is O(n³), about 4.5·10⁹ checks for n = 3000. If you fix the first number a, what problem is left for the other two?
The other two must sum to -a: that is Two Sum. On a sorted list, Two Sum takes one O(n) two-pointer walk.
Sort once. For each index i, two-pointer the range i + 1 .. n - 1. To avoid repeated triplets, skip an i whose value equals nums[i - 1], and after a match move left past every copy of the value it just used.

Key idea

Fix one number and the rest is Two Sum: the other two values must add up to -nums[i]. Sorting the list first pays off twice. The inner Two Sum becomes the two-pointer walk from Two Sum II (O(n), no extra memory), and equal values end up next to each other, so duplicates are easy to skip.

How the duplicate rule works: in sorted order, a triplet is determined by its smallest value, then its middle value. If nums[i] == nums[i - 1], every triplet that starts with this value was already found in the previous round, so skip i. Inside the walk, after recording a match, move left past all copies of nums[left]; any triplet with the same first two values also has the same third value, so it would be a repeat.

Sorting costs O(n log n), then n rounds of an O(n) walk: O(n²) overall.

Approaches from the obvious one to the one you want in an interview

Try every combination of three different indices. When the values sum to 0, sort the three values and store them as a tuple in a set, so (-1, 0, 1) found in any order is stored once.

There are about n³/6 combinations: for n = 3000 that is roughly 4.5·10⁹ checks, far beyond what Python can do in time. It is still worth writing once, because it pins down exactly what counts as a duplicate.

Python

class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        n = len(nums)
        found = set()                                   # sorted tuples, so (0, -1, 1) and (-1, 0, 1) collide
        for i in range(n):
            for j in range(i + 1, n):
                for k in range(j + 1, n):
                    if nums[i] + nums[j] + nums[k] == 0:
                        found.add(tuple(sorted((nums[i], nums[j], nums[k]))))
        return [list(t) for t in found]
Time O(n³)Space O(t)

Three nested loops; the set holds the t distinct triplets found.

When to use: Only to define the problem precisely; it times out on real inputs.

Fix the first value nums[i] and solve Two Sum on the rest: scanning j to the right of i, the third value must be need = -nums[i] - nums[j], and a set of the values seen between i and j answers "is it there?" in O(1).

Sorting first makes the triplet (nums[i], need, nums[j]) come out already in increasing order, so the set of tuples removes repeats directly. That is O(n²) time, but it builds a new set per round and still generates duplicate triplets before discarding them.

Python

class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        found = set()
        for i in range(len(nums)):
            if i > 0 and nums[i] == nums[i - 1]:
                continue                                 # same first value as the previous round
            seen = set()                                 # values between i and j
            for j in range(i + 1, len(nums)):
                need = -nums[i] - nums[j]
                if need in seen:
                    found.add((nums[i], need, nums[j]))  # already sorted: nums[i] <= need <= nums[j]
                seen.add(nums[j])
        return [list(t) for t in found]
Time O(n²)Space O(n)

n rounds of a linear scan; each round's set holds up to n values.

When to use: A good stepping stone when you remember Two Sum's hash map but not the two-pointer walk.

Sort the list. For each index i (the smallest value of the triplet):

  1. If nums[i] > 0, stop: every remaining value is positive too.
  2. If nums[i] == nums[i - 1], skip: this first value was already handled.
  3. Run two pointers on i + 1 .. n - 1. Sum below 0 → left += 1; above 0 → right -= 1; exactly 0 → record the triplet, move both pointers, and keep moving left while it sits on the value it just used.

The inner walk is Two Sum II, so every round is O(n) and no extra memory is needed apart from the output. The two skip rules guarantee each triplet is produced exactly once, so no set is required.

Dry run

  1. [-1, 0, 1, 2, -1, -4] → sorted [-4, -1, -1, 0, 1, 2]
  2. i = 0 (-4): need 4; the best pair from the rest is 1 + 2 = 3 < 4 → no triplet
  3. i = 1 (-1): need 1. L = -1, R = 2 → sum 0 → record [-1, -1, 2]; L = 0, R = 1 → sum 0 → record [-1, 0, 1]
  4. i = 2 (-1): same value as i = 1 → skip
  5. i = 3 (0): L = 1, R = 2 → sum 3 > 0 → R moves left → pointers meet → done

Python

class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        res = []
        n = len(nums)
        for i in range(n - 2):
            if nums[i] > 0:
                break                                    # smallest value positive: no zero sum possible
            if i > 0 and nums[i] == nums[i - 1]:
                continue                                 # same first value as the previous round
            left, right = i + 1, n - 1
            while left < right:
                total = nums[i] + nums[left] + nums[right]
                if total < 0:
                    left += 1                            # need a bigger value
                elif total > 0:
                    right -= 1                           # need a smaller value
                else:
                    res.append([nums[i], nums[left], nums[right]])
                    left += 1
                    right -= 1
                    while left < right and nums[left] == nums[left - 1]:
                        left += 1                        # skip copies of the value just used
        return res
Time O(n²)Space O(1)

O(n log n) to sort plus n walks of O(n); extra space is O(1) apart from the output (Python's sort itself may use up to O(n)).

When to use: The standard answer. It is also the template for 3Sum Closest, 4Sum and other k-sum variants.

Common mistakes

  • Skipping duplicates by looking ahead (nums[i] == nums[i + 1]) instead of behind (nums[i] == nums[i - 1]). Looking ahead skips the first copy and loses triplets such as [-1, -1, 2] that need two equal values.
  • After a match, moving the pointers without skipping repeated values: the next comparison finds the same triplet again.
  • Writing nums[i] == nums[i - 1] without the i > 0 guard. At i = 0, nums[-1] is the last element, so the first round can be skipped by mistake.
  • Removing duplicates at the end with a set of sorted tuples works, but every duplicate is still generated first, and the O(n³) or hash-set versions behind it are slower.
  • Returning indices: this problem wants the values.

Python notes

  • nums.sort() sorts in place in O(n log n); sorted(nums) would return a new list.
  • i > 0 and nums[i] == nums[i - 1] relies on and short-circuiting: at i = 0 the comparison never runs, so nums[-1] (the last element) is never read by accident.
  • Lists are not hashable, so the set-based approaches store triplets as tuples and convert back with list(t).

Follow-up questions

What an interviewer might ask next, and what changes.

  • 3Sum Closest LC 16 — return the sum closest to a target: the same sorted walk, keeping the total with the smallest abs(total - target); duplicates no longer matter.
  • 4Sum LC 18 — one more outer loop (O(n³)); to generalise to k-sum, recurse down until two numbers are left and run the two-pointer walk.
  • 3Sum Smaller LC 259 — count triplets with sum below a target: when total < target, every index in (left, right] works with left, so add right - left at once and move left.
  • Two Sum II - Input Array Is Sorted LC 167 — the inner loop of this problem on its own.
  • Valid Triangle Number LC 611 — count triplets whose two shorter sides sum to more than the longest: sort, fix the longest side, and two-pointer the rest, counting whole ranges at once.
  • 3Sum With Multiplicity LC 923 — count index triplets with a target sum, duplicates included: count each value, then combine the counts with combinations instead of listing triplets.
