Median of Two Sorted Arrays Hard

LeetCode #4 ↗
Status

Find the median of two sorted lists combined, without merging them, in logarithmic time.

Problem

You are given two sorted lists, nums1 of length m and nums2 of length n. Return the median of all m + n numbers taken together.

The median is the middle value of the combined sorted list. When the combined length is even, it is the average of the two middle values, so the answer can be a fraction (return a float).

The overall run time must be O(log(m + n)).

Examples

Example 1
Input: nums1 = [1, 3], nums2 = [2]
Output: 2.0
Combined: [1, 2, 3]; the middle value is 2.
Example 2
Input: nums1 = [1, 2], nums2 = [3, 4]
Output: 2.5
Combined: [1, 2, 3, 4]; (2 + 3) / 2 = 2.5.
Example 3
Input: nums1 = [], nums2 = [1]
Output: 1.0
One list may be empty.

Constraints

  • 0 <= m, n <= 1000 and 1 <= m + n <= 2000
  • -10^6 <= nums1[i], nums2[i] <= 10^6
  • both lists are sorted in non-decreasing order

Think first try before reading the solution

Merging the two lists as merge sort does gives the combined order in O(m + n), and you only need to walk to the middle. To reach O(log), stop merging and think about the left half of the combined list instead.
The left half holds half = (m + n + 1) // 2 numbers. If i of them come from the front of nums1, the other half - i come from the front of nums2. Only i is free. How do you know whether i is right?
The split is right when the largest number taken from each list is <= the smallest number left in the other list. If nums1's taken maximum is too big, take fewer from nums1; otherwise take more. Binary search i over the shorter list.

Key idea

The median depends only on where the combined sorted list is cut in half. Any such cut takes a prefix of each list: i numbers from the front of A and j = half − i from the front of B. The cut is the true one exactly when every number on the left is <= every number on the right. Each list is sorted, so only the four numbers next to the two cuts matter:

  • A[i−1] <= B[j] (A's largest on the left is not above B's smallest on the right), and
  • B[j−1] <= A[i].

If A[i−1] > B[j], too many numbers came from A: try a smaller i. If B[j−1] > A[i], too few came from A: try a larger i. That one-way verdict is exactly what binary search needs, so search i over 0..m. Searching the shorter list keeps j inside B and makes the cost O(log(min(m, n))). Once the cut is found, the median is the largest number on the left (odd total) or the average of that and the smallest number on the right (even total).

Approaches from the obvious one to the one you want in an interview

Put all numbers in one list, sort it, and read the middle (or the average of the two middle values).

It is short and obviously correct, but it ignores that both inputs are already sorted: sorting costs O((m + n) log(m + n)), and it builds a new list of m + n numbers.

Python

class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        merged = sorted(nums1 + nums2)
        total = len(merged)
        mid = total // 2
        if total % 2 == 1:
            return float(merged[mid])                  # odd: the single middle value
        return (merged[mid - 1] + merged[mid]) / 2     # even: average of the two middle values
Time O((m + n) log(m + n))Space O(m + n)

When to use: Quick checks and tests; never the interview answer.

Walk both lists with two pointers, always taking the smaller front value, exactly like the merge step of merge sort, but stop at position total // 2 and remember the last two values taken. For an odd total the median is the last value; for an even total it is the average of the last two.

This uses the sortedness and needs no extra list: O(m + n) time, O(1) space. It is the natural first answer, and it shows what the logarithmic version must avoid, namely walking past half of the numbers one by one.

Dry run

  1. [1, 3] and [2]: total 3, walk to position 1 (two steps)
  2. take 1 (from nums1), then 2 (from nums2) → last value 2
  3. odd total → median 2.0
  4. [1, 2] and [3, 4]: walk 3 steps: 1, 2, 3 → even total → (2 + 3) / 2 = 2.5

Python

class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        total = len(nums1) + len(nums2)
        i = j = 0
        prev = curr = 0
        for _ in range(total // 2 + 1):            # walk the merged order up to position total // 2
            prev = curr
            # take from nums1 if nums2 is used up, or if nums1's front is not bigger
            if j >= len(nums2) or (i < len(nums1) and nums1[i] <= nums2[j]):
                curr = nums1[i]
                i += 1
            else:
                curr = nums2[j]
                j += 1
        if total % 2 == 1:
            return float(curr)                     # odd: the middle element
        return (prev + curr) / 2                   # even: the two middle elements
Time O(m + n)Space O(1)

About (m + n) / 2 steps of a two-pointer merge; only two remembered values.

When to use: When linear time is acceptable; much simpler to get right.

Let A be the shorter list (swap if needed) and half = (m + n + 1) // 2. Binary search i, the number of elements the left half takes from A, over 0..m; the left half then takes j = half − i from B.

With the four boundary values (using −∞/+∞ when a side is empty):

  • A[i−1] <= B[j] and B[j−1] <= A[i] → correct cut. The median is max(A[i−1], B[j−1]) for an odd total, or that plus min(A[i], B[j]), divided by 2, for an even total.
  • A[i−1] > B[j] → too many from A: hi = i − 1.
  • otherwise (B[j−1] > A[i]) → too few from A: lo = i + 1.

Every probe halves the candidate values of i, so there are O(log(min(m, n))) probes of O(1) work each.

Dry run

  1. [1, 3, 8, 9, 15] and [7, 11, 18, 19, 21, 25]: total 11, half 6, A is the first list (m = 5)
  2. lo = 0, hi = 5 → i = 2, j = 4: left = {1, 3} + {7, 11, 18, 19}. B's 19 > A's 8 → too few from A → lo = 3
  3. i = 4, j = 2: left = {1, 3, 8, 9} + {7, 11}. 9 ≤ 18 ✓ and 11 ≤ 15 ✓ → correct cut
  4. odd total → median = max(9, 11) = 11.0

Python

class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        A, B = nums1, nums2
        if len(A) > len(B):
            A, B = B, A                            # binary search the shorter list
        m, n = len(A), len(B)
        half = (m + n + 1) // 2                    # size of the left half (gets the extra element if odd)
        lo, hi = 0, m                              # i = how many elements of A go to the left half
        while lo <= hi:
            i = (lo + hi) // 2
            j = half - i                           # the rest of the left half comes from B
            a_left = A[i - 1] if i > 0 else float("-inf")
            a_right = A[i] if i < m else float("inf")
            b_left = B[j - 1] if j > 0 else float("-inf")
            b_right = B[j] if j < n else float("inf")
            if a_left <= b_right and b_left <= a_right:     # everything left <= everything right
                if (m + n) % 2 == 1:
                    return float(max(a_left, b_left))
                return (max(a_left, b_left) + min(a_right, b_right)) / 2
            if a_left > b_right:
                hi = i - 1                         # took too many from A
            else:
                lo = i + 1                         # took too few from A
        raise ValueError("inputs must be sorted")  # unreachable for valid input
Time O(log(min(m, n)))Space O(1)

The search range for i has min(m, n) + 1 values and halves on every probe.

When to use: When the logarithmic bound is required. Explain the cut condition before writing code.

Common mistakes

  • Binary searching the longer list: j = half - i can then be negative or larger than n. Swap so that A is the shorter list.
  • Edges without sentinels: with i = 0 there is no A[i - 1], and Python's A[-1] silently reads the last element. Use −∞ for an empty left side and +∞ for an empty right side.
  • Averaging with //: (2 + 3) // 2 is 2, not 2.5. Use / 2.
  • Mixing conventions: half = (m + n + 1) // 2 puts the extra element of an odd total on the left, so the median is the left maximum. If you compute half = (m + n) // 2 instead, the median is the right minimum. Pick one and be consistent.
  • Moving the cut the wrong way: A[i - 1] > B[j] means i is too big (hi = i - 1); B[j - 1] > A[i] means i is too small.

Python notes

  • float("inf") and float("-inf") (also math.inf) compare correctly with integers, so they work as edge sentinels.
  • / always returns a float in Python 3: (2 + 3) / 2 == 2.5.
  • heapq.merge(nums1, nums2) merges sorted iterables lazily; itertools.islice(heapq.merge(nums1, nums2), k) yields only the first k values, a compact version of the merge-and-pick approach.
  • A, B = B, A swaps two names in one line.

Follow-up questions

What an interviewer might ask next, and what changes.

  • K-th smallest number of two sorted lists — replace half by k in the same partition search, or discard about k/2 numbers per step from one list: O(log k).
  • Find Median from Data Stream LC 295 — the numbers arrive one at a time: keep a max-heap for the lower half and a min-heap for the upper half.
  • Sliding Window Median LC 480 — the median of every window of size k: two heaps with lazy deletion, or a sorted list updated as the window slides.
  • Kth Smallest Element in a Sorted Matrix LC 378 — many sorted rows instead of two lists: binary search on the value and count how many cells are <= mid.
  • Merge Sorted Array LC 88 — the merge step itself, done in place by filling nums1 from the back.
