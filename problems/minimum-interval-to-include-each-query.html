Minimum Interval to Include Each Query Hard

LeetCode #1851 ↗
Status

For each query number, find the size of the smallest interval that contains it.

Problem

You are given intervals, where each [left, right] covers every integer from left to right inclusive, and a list of integers queries.

The size of an interval is the number of integers it covers: right - left + 1. For each query q, find the size of the smallest interval that contains q (that is, left <= q <= right). If no interval contains q, the answer is -1.

Return the answers in the same order as queries.

Examples

Example 1
Input: intervals = [[1, 4], [2, 4], [3, 6], [4, 4]], queries = [2, 3, 4, 5]
Output: [3, 3, 1, 4]
Query 2 lies in [1, 4] (size 4) and [2, 4] (size 3), so the answer is 3. Query 4 lies in [4, 4], size 1. Query 5 lies only in [3, 6], size 4.
Example 2
Input: intervals = [[2, 3], [2, 5], [1, 8], [20, 25]], queries = [2, 19, 5, 22]
Output: [2, -1, 4, 6]
No interval contains 19, so its answer is -1.
Example 3
Input: intervals = [[3, 3]], queries = [3, 4]
Output: [1, -1]
A one-point interval has size 1. The query 4 is outside it.

Constraints

  • 1 <= len(intervals) <= 10^5
  • 1 <= len(queries) <= 10^5
  • intervals[i] = [left, right] with 1 <= left <= right <= 10^7
  • 1 <= queries[j] <= 10^7

Think first try before reading the solution

For one query, looking at every interval is easy. With 10⁵ queries and 10⁵ intervals that is 10¹⁰ checks. What could you reuse from one query to the next?
Answer the queries in increasing order, and remember where each came from. Which intervals can contain the current query, and which can be forgotten for good once the queries have moved past their right end?
Sort the intervals by left end. For each query, push every interval with left <= q onto a min-heap ordered by size. Pop the top while it has already ended (right < q). If the heap is not empty, its top is the smallest interval containing q.

Key idea

One query is easy: scan all intervals, keep the ones that contain it, take the smallest size. The cost comes from doing that for every query. The way out is to answer the queries in increasing order, so that work carries over from one query to the next.

  • Sort the intervals by left. As the query q grows, more intervals have started (left <= q). Each interval joins a pool exactly once, when q reaches its left.
  • An interval with right < q has ended. Later queries are larger still, so it can never contain any of them. It can be forgotten.
  • Among the intervals that have started and not ended, the answer is the one with the smallest size.

A min-heap ordered by size keeps the smallest started interval on top. The one problem is that an ended interval may be sitting there. So before reading the top, pop it while it has ended (right < q). Ended intervals deeper in the heap are not hunted down: such an interval is no smaller than the top, so it cannot change the answer, and it is dropped whenever it finally reaches the top. This habit of removing something only at the moment it would be used is called lazy deletion.

The queries are processed sorted, but the answers must come back in the original order. So sort (query, original_position) pairs and write each answer into answer[original_position].

Approaches from the obvious one to the one you want in an interview

Answer each query on its own. Scan all the intervals, keep the ones with left <= q <= right, and track the smallest size. If none matches, the answer is -1.

It is simple and right, but it repeats the same scan for every query: n intervals times q queries. With 10⁵ of each that is 10¹⁰ checks, far too many.

Dry run

  1. intervals = [[1, 4], [2, 4], [3, 6], [4, 4]], queries = [2, 3, 4, 5]
  2. q = 2: contained in [1, 4] (size 4) and [2, 4] (size 3). The smallest is 3.
  3. q = 4: contained in [1, 4], [2, 4], [3, 6] and [4, 4] (sizes 4, 3, 4, 1). The smallest is 1.
  4. q = 5: contained only in [3, 6], so 4. Every query rescanned all 4 intervals.

Python

class Solution:
    def minInterval(self, intervals: List[List[int]], queries: List[int]) -> List[int]:
        answer = []
        for q in queries:
            best = -1                                     # -1 means: no interval found yet
            for left, right in intervals:
                if left <= q <= right:                    # this interval contains q
                    size = right - left + 1               # inclusive ends
                    if best == -1 or size < best:
                        best = size
            answer.append(best)
        return answer
Time O(n · q)Space O(1)

n intervals scanned for each of q queries. Extra space is only the answer list.

When to use: As the reference answer to check a faster solution against. Not for 10⁵ × 10⁵.

Answer the queries in ascending order and keep a min-heap of (size, right) for the intervals that have started.

For each query q (processed in sorted order, with its original index):

  1. Push every not-yet-pushed interval with left <= q. Intervals are sorted by left, so a single pointer i moves through them once.
  2. Pop while the top has ended, heap[0][1] < q. Later queries are larger, so an ended interval is useless from now on.
  3. If the heap is not empty, its top contains q and has the smallest size of all started intervals: answer[original_index] = heap[0][0]. Otherwise the answer stays -1.

Each interval is pushed once and popped at most once, and each query does a few comparisons, so the cost is two sorts plus n heap operations. The top is only read, never removed, when it answers, because it may answer the next query too.

Dry run

  1. intervals sorted by left: [[1, 4], [2, 4], [3, 6], [4, 4]]; queries ascending: 2, 3, 4, 5; heap = []
  2. q = 2: push [1, 4] as (4, 4) and [2, 4] as (3, 4). The top (3, 4) ends at 4 >= 2, so answer = 3.
  3. q = 3: push [3, 6] as (4, 6). The top is still (3, 4) and 4 >= 3, so answer = 3.
  4. q = 4: push [4, 4] as (1, 4). The top (1, 4) has 4 >= 4, so answer = 1.
  5. q = 5: nothing new to push. The top (1, 4) has 4 < 5: pop. Then (3, 4): pop. Then (4, 4): pop. The top (4, 6) has 6 >= 5, so answer = 4.
  6. Written back to the original positions: [3, 3, 1, 4].

Python

class Solution:
    def minInterval(self, intervals: List[List[int]], queries: List[int]) -> List[int]:
        intervals = sorted(intervals)                     # by left end
        answer = [-1] * len(queries)
        heap = []                                         # (size, right) of the intervals that have started
        i = 0                                             # next interval that has not been pushed yet
        for q, k in sorted((q, k) for k, q in enumerate(queries)):    # queries ascending, keeping their positions
            while i < len(intervals) and intervals[i][0] <= q:        # push every interval that has started
                left, right = intervals[i]
                heapq.heappush(heap, (right - left + 1, right))
                i += 1
            while heap and heap[0][1] < q:                # the smallest ended before q: it can never help again
                heapq.heappop(heap)
            if heap:                                      # top has started and not ended: it contains q
                answer[k] = heap[0][0]
        return answer
Time O(n log n + q log q)Space O(n + q)

Two sorts, then each interval is pushed once and popped at most once (O(log n) each) while the queries are swept.

When to use: Always. This is the expected solution, and 'sort the queries, sweep, keep a heap with lazy deletion' is a reusable pattern.

Watch it run

Turn the loop around. Visit the intervals from smallest to largest and hand each one to the queries it contains that have no answer yet. Because smaller intervals go first, the first interval that covers a query is its smallest one, so each query is answered once.

To find the queries inside [left, right] quickly, sort the distinct query values and use bisect for the first one >= left. To skip the queries that are already answered, keep an array next_open where next_open[i] leads to the next unanswered position at or after i. Following and shortening those links is the union-find idea from Redundant Connection (path compression).

Same O((n + q) log) cost as the heap, with more moving parts. It is worth knowing as the standard "paint smallest first" pattern.

Dry run

  1. points = [2, 3, 4, 5] (sorted queries). Intervals by size: [4, 4] (1), [2, 4] (3), [1, 4] (4), [3, 6] (4).
  2. [4, 4], size 1: the unanswered queries inside it are 4, so 4 gets 1.
  3. [2, 4], size 3: unanswered queries inside are 2 and 3 (4 is skipped, already answered), so both get 3.
  4. [1, 4], size 4: every query inside it is answered already. Nothing to do.
  5. [3, 6], size 4: query 5 is unanswered, so 5 gets 4. Answers in the original order: [3, 3, 1, 4].

Python

class Solution:
    def minInterval(self, intervals: List[List[int]], queries: List[int]) -> List[int]:
        points = sorted(set(queries))                     # distinct query values, ascending
        m = len(points)
        next_open = list(range(m + 1))                    # next_open[i] leads to the first unanswered position >= i (m = none)
        size_of = {}                                      # query value -> answer

        def find(i):                                      # first unanswered position >= i, shortening links on the way
            while next_open[i] != i:
                next_open[i] = next_open[next_open[i]]
                i = next_open[i]
            return i

        for left, right in sorted(intervals, key=lambda iv: iv[1] - iv[0]):   # smallest interval first
            size = right - left + 1
            i = find(bisect.bisect_left(points, left))    # first unanswered query >= left
            while i < m and points[i] <= right:           # ... that is still inside the interval
                size_of[points[i]] = size
                next_open[i] = i + 1                      # answered: skip it from now on
                i = find(i + 1)
        return [size_of.get(q, -1) for q in queries]
Time O(n log n + q log q)Space O(n + q)

Two sorts plus a binary search per interval; each query is answered once and the skip links are shortened as they are followed, so the painting adds little.

When to use: When you like the 'smallest first' view, or you are already using union-find. Mention it after the heap solution.

Common mistakes

  • Losing the original positions. After sorting the queries you must write into answer[original_index]. Collecting answers in sorted-query order gives the right numbers in the wrong places.
  • Forgetting to pop ended intervals. The smallest interval in the heap may already be over (right < q); without the clean-up you report the size of an interval that does not contain the query.
  • Ordering the heap by left or right instead of by size. Store (size, right): the size decides who is on top, and right is what you test for expiry.
  • Off-by-one with inclusive ends. The size is right - left + 1 ([4, 4] has size 1, not 0). Push while left <= q (an interval starting exactly at q contains it) and pop only while right < q (an interval ending exactly at q still contains it).
  • Removing the answering interval from the heap. The top that answers q may also answer the next query, so only peek at it (heap[0]).

Python notes

  • sorted((q, k) for k, q in enumerate(queries)) sorts the queries but keeps each one's original position k, so answer[k] = ... puts the result back in the right place.
  • heapq compares tuples item by item, so (size, right) puts the smallest size on top and breaks ties by the smaller right end. heap[0] reads the top without removing it.
  • while heap and heap[0][1] < q: tests heap first: heap[0] on an empty list raises IndexError.
  • answer = [-1] * len(queries) starts every slot at "no interval", so queries that never find one need no extra code.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Meeting Rooms II LC 253 — the same machinery without queries: intervals sorted by start and a heap of end times.
  • Most Beautiful Item for Each Query LC 2070 — the gentler cousin: sort the items and the queries, sweep once, and keep a running best. The pool never loses members, so no heap is needed.
  • Number of Flowers in Full Bloom LC 2251 — count the intervals containing each query instead of finding the smallest: sort starts and ends separately and use bisect (starts <= q minus ends < q).
  • Maximum Number of Events That Can Be Attended LC 1353 — sweep the days, keep a min-heap of end days of events that have started, drop expired ones from the top, and attend the one ending soonest.
  • The Skyline Problem LC 218 — a sweep over building edges with a max-heap of heights, using the same lazy deletion for buildings that have ended.
