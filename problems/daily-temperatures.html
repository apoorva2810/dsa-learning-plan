Daily Temperatures Medium

LeetCode #739 ↗
Status

For each day, count how many days you must wait for a warmer temperature.

Problem

You are given a list temperatures with one reading per day. Return a list answer of the same length where answer[i] is the number of days after day i until a strictly warmer day. If no later day is warmer, answer[i] is 0.

Examples

Example 1
Input: temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
Output: [1, 1, 4, 2, 1, 1, 0, 0]
Day 2 (75°) waits until day 6 (76°): 4 days. Days 6 and 7 never see anything warmer.
Example 2
Input: temperatures = [30, 40, 50, 60]
Output: [1, 1, 1, 0]
Example 3
Input: temperatures = [30, 60, 90]
Output: [1, 1, 0]

Constraints

  • 1 <= len(temperatures) <= 10^5
  • 30 <= temperatures[i] <= 100

Think first try before reading the solution

For each day you could scan forward until a warmer day. What input makes that scan long for almost every day?
Turn it around: when a warm day arrives, it is the answer for every earlier day that is still waiting and colder. Which earlier days can still be waiting?
Keep the indices of waiting days on a stack. Their temperatures only decrease from bottom to top, so a new day pops every colder day off the top (their answer is i - j) and then waits itself.

Key idea

Picture each day waiting in line for a warmer day. When day i arrives, it settles every waiting day that is colder than it. The days still waiting form a decreasing sequence of temperatures: if a colder day sat below a warmer day, the warmer one would already have settled it. So the colder days are always at the top, and day i only has to pop from the top until it meets a day that is at least as warm.

A stack whose contents stay sorted like this is called a monotonic stack. Every index is pushed once and popped at most once, so the inner while loop costs O(n) in total, not per day: the whole algorithm is O(n).

Approaches from the obvious one to the one you want in an interview

For each day i, walk j = i + 1, i + 2, … until temperatures[j] > temperatures[i], and record j - i. If the walk reaches the end, the answer is 0.

The same later days are read over and over. On a steadily falling list every walk runs to the end, so the total is about n²/2 reads: 5·10⁹ for 10⁵ days.

Dry run

  1. [73, 74, 75, 71, 69, 72, 76, 73]
  2. day 0 (73): day 1 is 74 → 1
  3. day 2 (75): 71, 69, 72 are colder, day 6 is 76 → 4
  4. day 3 (71): 69 colder, day 5 is 72 → 2 (it rereads 69 and 72, which day 2 already read)
  5. days 6 and 7 scan to the end → 0

Python

class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)
        answer = [0] * n
        for i in range(n):
            for j in range(i + 1, n):
                if temperatures[j] > temperatures[i]:
                    answer[i] = j - i           # first warmer day found
                    break
        return answer
Time O(n²)Space O(1)

Two nested loops in the worst case (a falling list); no memory beyond the output.

When to use: Only as the baseline.

Watch it run

Scan left to right with a stack of indices whose answer is still unknown. For day i:

  1. While the day on top is colder than today, pop it: today is its first warmer day, so its answer is i - j.
  2. Push i; it waits for its own warmer day.

The stack's temperatures always decrease from bottom to top (that is the monotonic part), because anything colder than a new day gets popped before the new day goes on. So a new day only ever looks at the top. Each index is pushed once and popped at most once: O(n) overall.

Dry run

  1. i = 0 (73): push → [0]
  2. i = 1 (74): 74 > 73 → pop 0, answer[0] = 1; push → [1]
  3. i = 2 (75): pop 1, answer[1] = 1; push → [2]
  4. i = 3 (71), i = 4 (69): both colder than the top → push → [2, 3, 4]
  5. i = 5 (72): pop 4 (69) → 1, pop 3 (71) → 2; 75 is not colder → push → [2, 5]
  6. i = 6 (76): pop 5 → 1, pop 2 → 4; push → [6]
  7. i = 7 (73): push → [6, 7]; both stay 0

Python

class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        answer = [0] * len(temperatures)        # 0 = no warmer day ahead
        stack = []                              # indices still waiting; temperatures decrease bottom -> top
        for i, temp in enumerate(temperatures):
            # today is the first warmer day for every colder day on top
            while stack and temperatures[stack[-1]] < temp:
                j = stack.pop()
                answer[j] = i - j
            stack.append(i)                     # today waits for its own warmer day
        return answer
Time O(n)Space O(n)

Each index is pushed once and popped at most once. A falling list keeps all n indices on the stack.

When to use: The standard answer, and the template for every 'next greater element' question.

Watch it run

Fill answer from the last day backwards. For day i, start at j = i + 1. If day j is not warmer, there is no need to step to j + 1: every day before j's own warmer day is no warmer than day j, so jump straight to j + answer[j]. If answer[j] is 0, nothing after j is warmer than day j, hence nothing is warmer than day i.

The jumps follow the same chain the stack would hold, so the total work is still O(n), but the only extra memory is the output itself.

Python

class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)
        answer = [0] * n
        for i in range(n - 2, -1, -1):          # the last day always stays 0
            j = i + 1
            # skip days that are not warmer by hopping to their own next-warmer day
            while temperatures[j] <= temperatures[i] and answer[j] > 0:
                j += answer[j]
            if temperatures[j] > temperatures[i]:
                answer[i] = j - i
        return answer
Time O(n)Space O(1)

Each day is hopped over at most once, as with the stack's pops; no memory besides the output.

When to use: When the interviewer asks for O(1) extra space.

Common mistakes

  • Pushing temperatures instead of indices: you need the index to compute i - j, and you can always look up the temperature from it.
  • Popping on <= instead of <: an equal temperature is not warmer. With [70, 70, 71] the first day must wait 2 days, not 1.
  • Forgetting the days still on the stack at the end: they have no warmer day. Initialising answer = [0] * n handles them for free.
  • Concluding the nested while makes it O(n²): count pushes and pops, at most n each.

Python notes

  • answer = [0] * n pre-fills the "no warmer day" default, so only the popped days need writing.
  • while stack and temperatures[stack[-1]] < temp: is the idiom: test emptiness first, then peek with stack[-1].
  • enumerate(temperatures) hands you (i, temp) together, which is exactly what you push and compare.
