Perfect Squares Medium 250

LeetCode #279 ↗
Status

Find the fewest perfect squares (1, 4, 9, 16, ...) that add up to a given number.

Problem

You are given a positive integer n. Return the fewest perfect squares (1, 4, 9, 16, ...) that add up to exactly n. The same square may be used as many times as you like.

An answer always exists, because n is the sum of n ones and 1 is a perfect square.

Examples

Example 1
Input: n = 18
Output: 2
9 + 9. Taking the biggest square first gives 16 + 1 + 1, which is one square more.
Example 2
Input: n = 7
Output: 4
4 + 1 + 1 + 1. The only squares below 7 are 1 and 4, and no mix of them makes 7 with fewer.
Example 3
Input: n = 30
Output: 3
25 + 4 + 1.

Constraints

  • 1 <= n <= 10^4

Think first try before reading the solution

Why can't you just take the biggest square that fits, again and again? Try n = 18 by hand.
Look at the last square of a best answer for a. If it is s * s, what remains is a best answer for a - s * s. This is Coin Change, where the coins are the perfect squares.
Fill dp[0..n] from small to large with dp[0] = 0 and dp[a] = 1 + min(dp[a - s * s]) over every square s * s <= a. There are only about sqrt(n) squares to try for each amount.

Key idea

Greedy is tempting and wrong. For n = 18 it takes 16, is left with 2, and needs two more ones: three squares. The answer is 9 + 9, two squares. A big square now can leave an awkward remainder, so the choices must be compared.

Ask about the last square instead. Any best answer for a ends with some square s * s. Take it away and what is left adds up to a - s * s, and it must itself be a best answer for that amount (a better one could be swapped in to improve a). So

dp[a] = 1 + min(dp[a - s * s]) over every square s * s <= a, with dp[0] = 0.

That is Coin Change with the perfect squares as the coins. Every cell reads only smaller amounts, so filling dp[1], dp[2], ..., dp[n] in order works. Each amount tries about sqrt(a) squares, so the total work is O(n × sqrt(n)): about a million steps for n = 10^4.

A safe starting value for every cell is n itself: n ones always work, so no answer is ever larger, and there is no need for infinity.

Seen as a graph, the amounts 0..n are nodes and every square is an edge from x to x + square. The fewest squares is then the shortest path from 0 to n, which breadth-first search finds level by level.

Approaches from the obvious one to the one you want in an interview

fewest(r) tries every perfect square s * s <= r as the last one and recurses on r - s * s; fewest(0) = 0, and the answer for r starts at r (all ones) before the squares improve it. The smallest result over all choices wins.

It explores every order of squares separately (4 + 1 and 1 + 4 reach the same remainder), and the same remainders come up again and again. The call count grows by about 1.4 times for every +1 on n: 104 calls for n = 12, 55,778 for 30 and 1,829,911 for 40.

Dry run

  1. n = 7: fewest(7) = 1 + min(fewest(6), fewest(3)) (squares 1 and 4 fit)
  2. fewest(3) = 1 + fewest(2) = 1 + 2 = 3, and fewest(6) = 1 + min(fewest(5), fewest(2)) = 3
  3. fewest(2) and fewest(5) are computed once for each branch that reaches them: the repeated work
  4. fewest(7) = 1 + min(3, 3) = 4

Python

class Solution:
    def numSquares(self, n: int) -> int:
        def fewest(remaining: int) -> int:
            """Fewest perfect squares that add up to `remaining`."""
            if remaining == 0:
                return 0
            best = remaining                           # remaining ones always work, so never worse than this
            root = 1
            while root * root <= remaining:            # root * root can be the last square
                best = min(best, fewest(remaining - root * root) + 1)
                root += 1
            return best

        return fewest(n)
Time exponential, about 1.4^nSpace O(n)

About sqrt(r) branches per call and a depth of up to n (subtracting 1 each time).

When to use: Only to discover the recurrence; it is fine for n in the teens and hopeless at 50.

Fill dp[0..n] in increasing order: dp[0] = 0, every other cell starts at n (the all-ones answer is an upper bound, so it plays the part of infinity). For each amount a, try every square s * s <= a as the last one and keep dp[a] = min(dp[a], dp[a - s * s] + 1).

Smaller amounts are final before a larger amount reads them, so one pass is enough. Each amount tries about sqrt(a) squares, so the total is O(n × sqrt(n)), and the table never nests calls. Top-down memoisation has the same cost but can recurse n deep.

Dry run

  1. n = 7, squares [1, 4]: dp = [0, ?, ?, ?, ?, ?, ?, ?]
  2. dp[1] = dp[0] + 1 = 1, dp[2] = 2, dp[3] = 3 (only the square 1 fits)
  3. dp[4] = min(dp[3] + 1, dp[0] + 1) = 1: the square 4 is a whole answer
  4. dp[5] = min(dp[4] + 1, dp[1] + 1) = 2, dp[6] = min(dp[5] + 1, dp[2] + 1) = 3
  5. dp[7] = min(dp[6] + 1, dp[3] + 1) = min(4, 4) = 4

Python

class Solution:
    def numSquares(self, n: int) -> int:
        squares = [k * k for k in range(1, math.isqrt(n) + 1)]    # every perfect square up to n, smallest first
        dp = [0] + [n] * n                    # dp[a] = fewest squares that add up to a; n ones is an upper bound
        for a in range(1, n + 1):             # small amounts first: dp[a - sq] is already final
            for sq in squares:
                if sq > a:
                    break                     # sorted: every later square is too big as well
                dp[a] = min(dp[a], dp[a - sq] + 1)
        return dp[n]
Time O(n √n)Space O(n)

n cells, each trying up to sqrt(n) squares; one list of n + 1 integers.

When to use: The standard answer: no recursion limit, and about a million steps for n = 10^4.

Watch it run

Treat each amount as a node and each square as an edge from x to x + square. Breadth-first search (BFS) first visits every sum reachable with 1 square, then with 2 squares, and so on, so the first time it reaches n the number of levels is the fewest squares. A seen set makes sure every amount is queued once.

The worst case is the same O(n × sqrt(n)) as the table. BFS can stop early when the answer is small (and by the four-square theorem it never needs more than 4 levels), but it needs a queue and a set instead of one list.

Dry run

  1. n = 7, squares [1, 4]: level 1 from 0 reaches 1 and 4
  2. level 2 from 1 reaches 2 and 5; from 4 reaches 5 (seen) and 8 (too big)
  3. level 3 from 2 reaches 3 and 6; from 5 reaches 6 (seen) and 9 (too big)
  4. level 4 from 3 reaches 4 (seen) and 7 = n, so the answer is 4

Python

class Solution:
    def numSquares(self, n: int) -> int:
        squares = [k * k for k in range(1, math.isqrt(n) + 1)]
        seen = {0}
        queue = deque([0])                    # sums reachable with `count` squares
        count = 0
        while queue:
            count += 1                        # one BFS level = one more square
            for _ in range(len(queue)):
                total = queue.popleft()
                for sq in squares:
                    nxt = total + sq
                    if nxt == n:
                        return count
                    if nxt < n and nxt not in seen:
                        seen.add(nxt)         # mark when queued, not when popped
                        queue.append(nxt)
        return 0                              # only reached for n = 0
Time O(n √n)Space O(n)

Each amount below n is queued once and tries up to sqrt(n) squares; the queue and the set hold up to n entries.

When to use: When you recognise "fewest steps" as a shortest path; it often finishes early.

Common mistakes

  • Greedy by the largest square. It is wrong on n = 18 (three squares instead of two) and on n = 12 (9 + 1 + 1 + 1 is four, 4 + 4 + 4 is three).
  • Plain recursion is exponential. The number of calls grows by about 1.4 times for every +1 on n: n = 40 already makes about 1.8 million calls.
  • Top-down recursion that tries the square 1 first nests n calls deep and hits Python's recursion limit of 1000 long before n = 10^4. The loops have no depth.
  • Forgetting dp[0] = 0. Every amount that equals a square reads dp[0], so with a wrong base value every answer is off by the same amount.
  • In BFS, marking a sum as seen only when it is popped. The same sum then enters the queue many times and the search crawls. Mark it when it is queued.

Python notes

  • math.isqrt(n) is the exact integer square root, so range(1, math.isqrt(n) + 1) gives every root whose square is at most n. It avoids the rounding worries of int(n ** 0.5) for big numbers.
  • [k * k for k in range(1, math.isqrt(n) + 1)] is sorted, which is why the inner loop can break at the first square that is larger than the amount.
  • dp = [0] + [n] * n builds the table: index 0 is the base case, everything else starts at the safe upper bound n.
  • BFS uses collections.deque: popleft() is O(1), while list.pop(0) is O(length).

Follow-up questions

What an interviewer might ask next, and what changes.

  • Coin Change LC 322 — the same table with arbitrary coin values: dp[a] = min(dp[a - c] + 1), and -1 when an amount cannot be made.
  • Integer Break LC 343 — also splits n into parts with a table over smaller values, but it multiplies the parts and maximises, instead of counting them and minimising.
  • Can you beat O(n √n)? — Lagrange's four-square theorem says the answer is never above 4. Legendre's three-square theorem says it is exactly 4 when n = 4^a × (8b + 7). Check 1 (is n a square), 2 (scan x * x and test whether n - x * x is a square), else 3: O(sqrt(n)) time.
  • Valid Perfect Square LC 367 — just decide whether a number is a perfect square: math.isqrt(n) ** 2 == n, or a binary search on the root. It is the 'answer is 1' check above.
  • Return the squares themselves — store the winning square for each amount while filling the table, then walk back from n subtracting it until you reach 0.
