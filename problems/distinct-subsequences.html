Distinct Subsequences Hard

LeetCode #115 ↗
Status

Count the ways to pick characters of one string, in order, so that they spell a second string.

Problem

Given two strings s and t, return the number of ways to choose characters from s, keeping their order, so that the chosen characters spell t.

A subsequence of s keeps some of its characters (possibly none, possibly all) in their original order; the kept characters do not have to be next to each other. Two choices count as different when they use different positions in s, even if they spell the same word. Every choice counted here spells t, so the answer is the number of position sets that do.

The test data is chosen so that the answer fits in a 32-bit signed integer.

Examples

Example 1
Input: s = "rabbbit", t = "rabbit"
Output: 3
rabbit needs two bs and rabbbit has three. Skip the first, the second or the third b: three different sets of positions.
Example 2
Input: s = "babgbag", t = "bag"
Output: 5
Five position sets spell bag: (0, 1, 3), (0, 1, 6), (0, 5, 6), (2, 5, 6) and (4, 5, 6).
Example 3
Input: s = "ab", t = "ba"
Output: 0
b appears only after a in s, so b followed by a cannot be read in order.

Constraints

  • 1 <= len(s), len(t) <= 1000
  • s and t consist of English letters
  • the answer fits in a 32-bit signed integer

Think first try before reading the solution

Handle s one character at a time. Each character is either skipped or used to match one specific character of t. How many ways does each of the two choices leave you with?
Let dp[i][j] be the number of ways to build t[:j] from s[:i]. Skipping s[i - 1] leaves dp[i - 1][j] ways. Using it is allowed only if s[i - 1] == t[j - 1], and then t[:j - 1] must come from s[:i - 1]: dp[i - 1][j - 1] ways. The two choices use different positions, so add them.
Base cases: dp[i][0] = 1 (an empty t is built by choosing nothing) and dp[0][j] = 0 for j > 0. The answer is dp[m][n]. A single list also works if you update j from right to left.

Key idea

Take the first i characters of s and the first j characters of t, and count the ways s[:i] contains t[:j]. Look at the last character of the s prefix, s[i - 1]. Every way is of exactly one of two kinds:

  • It does not use s[i - 1]. Ignore that character: these are the ways to build t[:j] from s[:i - 1], which is dp[i - 1][j].
  • It uses s[i - 1]. Then that character plays the last character of t[:j], so it must equal t[j - 1]. Everything before it builds t[:j - 1] from s[:i - 1]: dp[i - 1][j - 1] ways.

The kinds never overlap and together they cover every way, so the counts add: dp[i][j] = dp[i - 1][j], plus dp[i - 1][j - 1] when s[i - 1] == t[j - 1].

This is the Longest Common Subsequence table with one change. LCS keeps the best option, and pairing two equal characters is never a mistake, so a match jumps to the diagonal. Counting needs every way, so a match adds both options. The three bs in rabbbit show why: the third b can serve as the second b of rabbit, but the ways that skip it are valid too.

Base cases: an empty t can be built from any prefix of s in exactly one way (choose nothing), and a non-empty t cannot be built from an empty s.

Approaches from the obvious one to the one you want in an interview

Let ways(i, j) be the number of ways to build t[:j] from s[:i]:

  • j == 0: the empty target is built by choosing nothing, so 1;
  • i == 0 (and j > 0): there is nothing left to choose from, so 0;
  • otherwise ways(i - 1, j) (skip s[i - 1]), plus ways(i - 1, j - 1) when s[i - 1] == t[j - 1] (use it).

Without a cache the two calls branch again and again and reach the same (i, j) along many routes: for 30 as and a t of 15 as that is over a billion calls. With @cache (memoisation: remember each answer the first time it is computed) there are only (m + 1) · (n + 1) different calls, each doing O(1) work.

Dry run

  1. s = "abb", t = "ab": ways(3, 2): s[2] = b equals t[1] = b, so add skip ways(2, 2) and use ways(2, 1).
  2. ways(2, 2): s[1] = b equals t[1] = b: skip ways(1, 2), use ways(1, 1).
  3. ways(1, 2): s[0] = a ≠ t[1] = b, so only skip: ways(0, 2) = 0. ways(1, 1): a == a: skip ways(0, 1) = 0 + use ways(0, 0) = 1 = 1.
  4. ways(2, 2) = 0 + 1 = 1. ways(2, 1): b ≠ a, only skip: ways(1, 1), already cached, 1.
  5. ways(3, 2) = 1 + 1 = 2: a with the first b, or a with the second b.

Python

class Solution:
    def numDistinct(self, s: str, t: str) -> int:
        @cache                                       # one stored answer per pair (i, j)
        def ways(i: int, j: int) -> int:
            """Number of ways to build t[:j] from the characters of s[:i]."""
            if j == 0:                               # empty target: choose nothing
                return 1
            if i == 0:                               # target left over, nothing to choose from
                return 0
            count = ways(i - 1, j)                   # skip s[i - 1]
            if s[i - 1] == t[j - 1]:                 # or use it as the last character of t[:j]
                count += ways(i - 1, j - 1)
            return count

        return ways(len(s), len(t))
Time O(m·n)Space O(m·n)

(m + 1)(n + 1) states with O(1) work each; the recursion is up to m + 1 frames deep.

When to use: The most direct translation of the idea. For len(s) near 1000 the recursion reaches Python's default limit, so switch to a table.

Turn the recursion around and fill dp[i][j] for growing prefixes, so every cell finds its inputs already computed. Row 0 and column 0 are the empty prefix: column 0 is all 1 (the empty t), and row 0 is 0 after its first cell. Then, row by row and left to right:

  • dp[i][j] = dp[i - 1][j]: the ways that skip s[i - 1];
  • if s[i - 1] == t[j - 1], also add dp[i - 1][j - 1]: the ways that use it.

The answer is the bottom-right cell dp[m][n]. Keeping the whole table costs O(m·n) memory but lets you print it and check each cell against the 3-cell picture: up is always read, diagonal only on a match.

Dry run

  1. s = "abb", t = "ab": the table has 4 rows and 3 columns. Column 0 is [1, 1, 1, 1]; row 0 is [1, 0, 0].
  2. Row a: j = 1, a == a: up 0 + diagonal 1 = 1. j = 2, a ≠ b: copy up, 0. Row = [1, 1, 0].
  3. Row b: j = 1, b ≠ a: copy up, 1. j = 2, b == b: up 0 + diagonal 1 = 1. Row = [1, 1, 1].
  4. Row b: j = 1: copy up, 1. j = 2, b == b: up 1 + diagonal 1 = 2. Row = [1, 1, 2], so the answer is 2.

Python

class Solution:
    def numDistinct(self, s: str, t: str) -> int:
        m, n = len(s), len(t)
        dp = [[0] * (n + 1) for _ in range(m + 1)]   # dp[i][j]: ways to build t[:j] from s[:i]
        for i in range(m + 1):
            dp[i][0] = 1                             # empty t: choose nothing, 1 way (row 0 stays 0 after that)
        for i in range(1, m + 1):
            for j in range(1, n + 1):
                dp[i][j] = dp[i - 1][j]              # ways that skip s[i - 1]
                if s[i - 1] == t[j - 1]:             # ways that use s[i - 1] as t[j - 1]
                    dp[i][j] += dp[i - 1][j - 1]
        return dp[m][n]
Time O(m·n)Space O(m·n)

One O(1) update per cell of the (m + 1) × (n + 1) table.

When to use: When you want to see or print the table, or you are still convincing yourself that the recurrence is right.

Watch it run

Row i reads only row i - 1, so one list dp of length n + 1 can hold "the current row": dp[j] is the number of ways to build t[:j] from the characters of s read so far. Start with dp = [1, 0, ..., 0]. For each character ch of s, and for every j with t[j - 1] == ch, do dp[j] += dp[j - 1]. The "skip" term needs no code: dp[j] already holds the previous row's value.

The inner loop must run from right to left. When you update dp[j] you need dp[j - 1] as it was in the previous row, and going right to left means column j - 1 has not been touched yet in this round. Left to right would feed the new dp[j - 1] into dp[j] and use one character of s twice. It is the same direction rule as in the 0/1 knapsack.

Dry run

  1. s = "abb", t = "ab", dp = [1, 0, 0]
  2. read a: only j = 1 has t[0] = a: dp[1] += dp[0] → [1, 1, 0]
  3. read b: only j = 2 has t[1] = b: dp[2] += dp[1] → [1, 1, 1]
  4. read b again: dp[2] += dp[1] → [1, 1, 2], so the answer is dp[2] = 2

Python

class Solution:
    def numDistinct(self, s: str, t: str) -> int:
        n = len(t)
        dp = [1] + [0] * n                           # dp[j]: ways to build t[:j] from the characters read so far
        for ch in s:                                 # add one character of s per round
            for j in range(n, 0, -1):                # right to left: dp[j - 1] still belongs to the previous round
                if ch == t[j - 1]:
                    dp[j] += dp[j - 1]               # use ch as t[j - 1]; skipping it is already in dp[j]
        return dp[n]
Time O(m·n)Space O(n)

The same m·n updates as the table, but only one list of n + 1 numbers is kept.

When to use: The interview answer once the table is clear. Say out loud why the loop runs right to left.

Common mistakes

  • Copying the LCS rule and taking only the diagonal on a match. A matching character can still be skipped: s = "bb", t = "b" has 2 ways, not 1.
  • Starting column 0 at 0. The empty t has exactly one way to be built, so dp[i][0] = 1 in every row, including dp[0][0]. With zeros the whole table stays 0.
  • Rolling the table into one list but looping j from left to right. Then dp[j - 1] is already updated for the current character, so one character of s is used for two characters of t: s = "a", t = "aa" returns 1 instead of 0, and rabbbit / rabbit returns 6 instead of 3. Loop j downward.
  • Recursion without a cache. Every call splits into skip and use, and the same (i, j) is reached along many routes: for 30 as and a t of 15 as the uncached recursion makes about 1.2 billion calls.
  • Reading the 32-bit guarantee as 'every cell fits'. A cell can be far larger than the final answer: with s = "a" * 50 and t = "a" * 20 + "b" the answer is 0, yet one cell holds C(50, 20), about 4.7 · 10^13. In Java or C++ use long or a modulus; Python integers do not overflow.

Python notes

  • [[0] * (n + 1) for _ in range(m + 1)] builds the table and a loop then sets column 0 to 1. Writing [[0] * (n + 1)] * (m + 1) would make every row the same list.
  • @cache keys on (i, j). Define the cached helper inside the method so each call starts with an empty cache.
  • for j in range(n, 0, -1) counts down from n to 1. That direction is the whole trick of the one-row version.
  • Python integers have no upper limit, so intermediate values need no special care.
  • The recursion goes up to len(s) + 1 frames deep. For len(s) near 1000 that exceeds Python's default limit of 1000 frames, so the table versions are the safe choice for the largest inputs.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Is Subsequence LC 392 — only a yes/no for whether t is a subsequence of s: one pass with two pointers, no table. The follow-up is many different ts against one s: precompute where each letter occurs and binary-search the next occurrence.
  • Edit Distance LC 72 — the same prefix table, but each cell takes the cheapest of three neighbours plus 1 (insert, delete, replace) instead of adding two counts.
  • Number of Matching Subsequences LC 792 — many words against one s, and only a yes/no per word: bucket the words by the next character they need and sweep s once, instead of building one table per word.
  • Distinct Subsequences II LC 940 — count the distinct strings that are subsequences of s, with no target. Two position sets can spell the same word, so subtract what the previous occurrence of the same character already counted.
  • Interleaving String LC 97 — a prefix table over two strings again; each cell asks whether the next character of the third string can come from the first or from the second.
  • Return the answer modulo 10^9 + 7 — take % MOD after every addition so cells stay small. This matters in languages with fixed-size integers; the recurrence does not change.
