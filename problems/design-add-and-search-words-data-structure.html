Design Add and Search Words Data Structure Medium

LeetCode #211 ↗
Status

Store words and answer pattern queries where '.' stands for any single letter.

Problem

Design a structure that stores words and tells whether a pattern matches any of them. Implement WordDictionary:

  • WordDictionary() creates an empty structure.
  • addWord(word) stores word.
  • search(word) returns True if some stored word matches word, otherwise False.

In a query, . matches exactly one letter of any kind; every other character must match exactly, so a match always has the same length as the query.

Examples

Example 1
Input: ["WordDictionary","addWord","addWord","addWord","search","search","search","search"] [[],["bad"],["dad"],["mad"],["pad"],["bad"],[".ad"],["b.."]]
Output: [null, null, null, null, false, true, true, true]
No stored word is pad. .ad matches bad, dad and mad; b.. matches bad.

Constraints

  • 1 <= len(word) <= 25
  • words given to addWord are lowercase letters
  • search queries contain lowercase letters or '.'
  • at most 2 dots in each search query
  • at most 10^4 calls in total

Think first try before reading the solution

Without dots this is exactly a trie lookup. What should happen at a ., where you do not know which edge to follow?
At a ., try every child of the current node with the rest of the pattern, and succeed if any of them leads to a match. That is a depth-first search with backtracking.
Write dfs(i, node): 'can pattern[i:] be matched starting at node?'. Base case: i == len(pattern) → node.is_end. A letter follows one edge; a dot loops over the children and returns True on the first success.

Key idea

Store the words in a trie, exactly as in Implement Trie. A query without dots is the usual walk: one edge per letter, then check is_end.

A dot means "any letter", so the walk cannot pick a single edge. Instead it branches: try each child of the current node with the rest of the pattern, and stop as soon as one branch succeeds. When a branch reaches a letter that is missing, abandon it and try the next one. Abandoning a partial attempt and trying another is called backtracking.

The trie is what makes this cheap: a branch only ever explores words that agree with the pattern so far, so every word that disagrees at some letter is skipped as a group. A pattern without dots costs O(L). Each dot can multiply the branches by up to 26, so d dots cost O(26^d · L) in the worst case; the problem allows at most two.

Approaches from the obvious one to the one you want in an interview

Keep the words in a set. A query without dots is a plain membership test. A query with dots is compared with every stored word of the same length, letter by letter, where . accepts anything.

Correct, and fine for a handful of words. But each wildcard query reads all N stored words: O(N · L). With 10^4 calls against a large dictionary that adds up, and most of the work is wasted on words that already differ in their first letter.

Dry run

  1. words = {bad, dad, mad}
  2. search pad: no dot → 'pad' in words → False
  3. search .ad: compare with bad (. b ✓, a ✓, d ✓) → True

Python

class WordDictionary:
    def __init__(self):
        self.words = set()

    def addWord(self, word: str) -> None:
        self.words.add(word)

    def search(self, word: str) -> bool:
        if "." not in word:
            return word in self.words              # exact lookup
        for w in self.words:                       # O(N · L): check every stored word
            if len(w) == len(word) and all(p == "." or p == c for p, c in zip(word, w)):
                return True
        return False
Time O(L) addWord, O(N·L) wildcard searchSpace O(total letters)

N stored words of length up to L; every wildcard query may touch all of them.

When to use: A quick baseline, or when there are only a few words.

Insert words into a trie. To search, run dfs(i, node), meaning "can pattern[i:] be matched starting at node?":

  1. i == len(pattern): matched every character, so the answer is node.is_end.
  2. pattern[i] is a letter: follow that child if it exists, else return False.
  3. pattern[i] is .: for every child, if dfs(i + 1, child) is True, return True. If none works, return False.

Only branches consistent with the pattern so far are ever explored, and a letter (not a dot) never branches at all.

Dry run

  1. trie holds bad, dad, mad
  2. search .ad: . at root → try b: a ✓ → d ✓ → end, is_end True → True (d and m never tried)
  3. search b..: b ✓ → . → only child a ✓ → . → only child d ✓ → end, is_end True → True

Python

class TrieNode:
    def __init__(self):
        self.children = {}          # letter -> TrieNode
        self.is_end = False


class WordDictionary:
    def __init__(self):
        self.root = TrieNode()

    def addWord(self, word: str) -> None:
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def search(self, word: str) -> bool:
        def dfs(i, node):
            """Can word[i:] be matched starting at node?"""
            if i == len(word):
                return node.is_end
            ch = word[i]
            if ch == ".":
                for child in node.children.values():   # any letter: try each branch
                    if dfs(i + 1, child):
                        return True
                return False                           # every branch failed
            if ch not in node.children:
                return False
            return dfs(i + 1, node.children[ch])

        return dfs(0, self.root)
Time O(L) addWord; search O(L) without dots, O(26^d · L) with d dotsSpace O(total letters)

With at most 2 dots the branching is bounded by 26² paths; recursion depth is at most L.

When to use: The interview answer.

Watch it run

Process the pattern one character at a time while keeping a frontier: the list of trie nodes that match the pattern so far. A letter keeps, from each frontier node, the child for that letter; a dot keeps all children. If the frontier ever becomes empty, nothing matches. At the end, a match exists if any frontier node marks a word end.

Same worst case as the DFS. The trade-off: no recursion, and it is easy to see all candidates at once, but it explores every branch even after one would already have succeeded, where the DFS stops at the first match.

Python

class WordDictionary:
    END = "$"                                 # key marking 'a word ends here'

    def __init__(self):
        self.root = {}

    def addWord(self, word: str) -> None:
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})    # walk, creating as needed
        node[self.END] = True

    def search(self, word: str) -> bool:
        frontier = [self.root]                # nodes matching word[:i]
        for ch in word:
            nxt = []
            for node in frontier:
                if ch == ".":
                    nxt.extend(child for key, child in node.items() if key != self.END)
                elif ch in node:
                    nxt.append(node[ch])
            if not nxt:
                return False                  # no stored word matches this far
            frontier = nxt
        return any(self.END in node for node in frontier)
Time O(L) addWord; search O(26^d · L) worst caseSpace O(total letters) + frontier

The frontier can hold up to 26^d nodes after d dots.

When to use: When you prefer iteration, or want every matching word rather than a yes/no.

Common mistakes

  • Forgetting is_end at the end of the pattern: after adding bad, the query ba must be False even though the path exists.
  • Writing return dfs(...) inside the loop over children at a dot. That returns the first child's answer and never tries the others. Return True on success; otherwise keep looping.
  • Treating . like a regular-expression .*. Here it is exactly one letter, so b. cannot match bad.
  • Scanning every stored word on each query: O(N · L) per search, too slow for 10^4 calls on a large dictionary.

Python notes

  • any(dfs(i + 1, child) for child in node.children.values()) stops at the first True: any short-circuits on a generator.
  • The recursion is at most as deep as the pattern (25 letters), so recursion is safe here.
  • For the brute force, grouping words by length (defaultdict(list) keyed by len(word)) is a cheap speed-up, since a match must have the same length as the query.
