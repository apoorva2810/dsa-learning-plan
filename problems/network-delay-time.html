Network Delay Time Medium

LeetCode #743 ↗
Status

Send a signal from one node of a weighted network and report when the last node hears it.

Problem

A network has n nodes labelled 1 to n. Each entry times[i] = [u, v, w] is a one-way link: a signal that leaves u arrives at v exactly w time units later.

A signal is sent from node k at time 0 and travels along every link at once. Return the time at which every node has received it. If some node can never receive it, return -1.

  • Every (u, v) pair appears at most once, and u != v.

Examples

Example 1
Input: times = [[2, 1, 1], [2, 3, 1], [3, 4, 1]], n = 4, k = 2
Output: 2
Nodes 1 and 3 hear it at time 1, node 4 at time 2.
Example 2
Input: times = [[1, 2, 1]], n = 2, k = 1
Output: 1
Example 3
Input: times = [[1, 2, 1]], n = 2, k = 2
Output: -1
The only link points away from node 2, so node 1 never hears the signal.

Constraints

  • 1 <= k <= n <= 100
  • 1 <= len(times) <= 6000
  • times[i] = [u, v, w] with 1 <= u, v <= n, u != v and 0 <= w <= 100
  • all (u, v) pairs are distinct

Think first try before reading the solution

A node hears the signal at the time of its fastest route from k. When does the whole network have it?
At the moment the slowest node hears it: the answer is the largest shortest-route time. So you need shortest routes from one source, with non-negative weights.
Dijkstra: a min-heap of (time, node). The earliest entry popped for a node is final. Push its neighbours at time + w, skip entries that are out of date, and take the maximum at the end.

Key idea

The signal spreads along every link at once, so each node hears it at the length of its shortest route from k, and the network is done when the slowest of those arrives. The answer is max(shortest time to each node), or -1 if some node has no route at all.

BFS cannot find these routes, because it counts links rather than adding up their times. Dijkstra's algorithm does: keep a min-heap of (arrival time, node) offers. The smallest offer in the heap belongs to the node that hears the signal next, and that time is final: every other route to it would have to pass through a node that hears the signal no earlier, and with no negative times the route can only get longer from there. Pop it, offer time + w to each neighbour, and repeat. Offers that a better route has already beaten are skipped when they come out of the heap ("lazy deletion"). With a binary heap this costs O(E log V).

Approaches from the obvious one to the one you want in an interview

Walk every route out of k with a depth-first search, carrying the time so far. Keep arrival[node], the best time seen for each node, and abandon a route as soon as it reaches a node no faster than before (it cannot help anything downstream). At the end, take the largest arrival time, or -1 if a node was never reached.

The pruning keeps it correct, but in the worst case a node keeps being reached by slightly faster routes that are found late, and the search redoes everything below it each time. The number of routes explored can grow exponentially.

Dry run

  1. times = [[2, 1, 1], [2, 3, 1], [3, 4, 1]], k = 2: dfs(2, 0)
  2. → dfs(1, 1): arrival[1] = 1, no links out. → dfs(3, 1): arrival[3] = 1 → dfs(4, 2): arrival[4] = 2
  3. Largest arrival = 2

Python

class Solution:
    def networkDelayTime(self, times: List[List[int]], n: int, k: int) -> int:
        graph = defaultdict(list)
        for u, v, w in times:
            graph[u].append((v, w))
        arrival = {node: math.inf for node in range(1, n + 1)}

        def dfs(node: int, time: int) -> None:
            if time >= arrival[node]:              # already reached at least this early: prune
                return
            arrival[node] = time
            for nxt, w in graph[node]:
                dfs(nxt, time + w)

        dfs(k, 0)
        worst = max(arrival.values())
        return worst if worst < math.inf else -1
Time exponential in the worst caseSpace O(V + E)

A node can be re-entered every time a faster route to it turns up, re-exploring everything below.

When to use: Only to show why you want to settle nodes in order of arrival time.

Relaxing a link u → v means: if dist[u] + w < dist[v], the route through u is faster, so update dist[v]. Do that for every link, and repeat the whole pass. After pass i, every node whose fastest route uses at most i links has its correct time. A fastest route never repeats a node, so it has at most n − 1 links, and n − 1 passes are enough; stop early if a pass changes nothing.

This needs no heap and also works with negative times, but it is O(V · E): up to 99 passes over 6000 links here.

Dry run

  1. times = [[2, 1, 1], [2, 3, 1], [3, 4, 1]], k = 2: dist = [·, ∞, 0, ∞, ∞]
  2. Pass 1: 2→1 gives 1, 2→3 gives 1, 3→4 gives 1 + 1 = 2
  3. Pass 2 changes nothing → stop. Largest = 2

Python

class Solution:
    def networkDelayTime(self, times: List[List[int]], n: int, k: int) -> int:
        dist = [math.inf] * (n + 1)                # slot 0 unused: nodes are 1..n
        dist[k] = 0
        for _ in range(n - 1):                     # a fastest route uses at most n - 1 links
            changed = False
            for u, v, w in times:
                if dist[u] + w < dist[v]:          # relax: going through u is faster
                    dist[v] = dist[u] + w
                    changed = True
            if not changed:                        # nothing improved: all times are final
                break
        worst = max(dist[1:])                      # skip the unused slot 0
        return worst if worst < math.inf else -1
Time O(V · E)Space O(V)

At most n - 1 passes over all E links; only the distance array is stored.

When to use: When links can have negative times, or when you need routes with a limited number of links.

Settle nodes in the order they hear the signal.

  1. dist[k] = 0, everything else ∞; the heap holds (0, k).
  2. Pop the smallest (time, node). If time > dist[node], a faster route was already recorded: skip it.
  3. Otherwise time is final for node. For each link node → nxt taking w, if time + w < dist[nxt], record it and push (time + w, nxt).
  4. When the heap is empty, return the largest dist, or -1 if any node is still ∞.

Each link is relaxed once (when its start node is settled) and each successful relaxation pushes one entry, so there are at most E pushes and pops: O(E log V) with a binary heap.

Dry run

  1. times = [[1, 2, 4], [1, 3, 1], [3, 2, 2], [2, 4, 1]], n = 4, k = 1: heap [(0, 1)]
  2. Pop (0, 1): push (4, 2) and (1, 3)
  3. Pop (1, 3): 1 + 2 = 3 < 4 → dist[2] = 3, push (3, 2)
  4. Pop (3, 2): push (4, 4). Pop (4, 2): stale (3 < 4), skip. Pop (4, 4): final
  5. dist = {1: 0, 2: 3, 3: 1, 4: 4} → answer 4

Python

class Solution:
    def networkDelayTime(self, times: List[List[int]], n: int, k: int) -> int:
        graph = defaultdict(list)
        for u, v, w in times:
            graph[u].append((v, w))
        dist = {node: math.inf for node in range(1, n + 1)}
        dist[k] = 0
        heap = [(0, k)]                            # (arrival time, node)
        while heap:
            time, node = heapq.heappop(heap)
            if time > dist[node]:                  # stale: a faster route was recorded after this push
                continue
            for nxt, w in graph[node]:
                if time + w < dist[nxt]:           # relax the link node -> nxt
                    dist[nxt] = time + w
                    heapq.heappush(heap, (time + w, nxt))
        worst = max(dist.values())
        return worst if worst < math.inf else -1
Time O(E log V)Space O(V + E)

At most E successful relaxations, each one heap push and later one pop.

When to use: The answer for any single-source shortest-route question with non-negative weights.

Common mistakes

  • Using plain BFS. It finds the route with the fewest links, which is not the fastest when links have different times (1 → 2 directly at 4 is slower than 1 → 3 → 2 at 1 + 2).
  • Taking max(dist) over a list that still contains the unused slot 0 (nodes are numbered from 1). That slot is ∞, so every answer becomes -1. Use dist[1:] or a dictionary keyed by node.
  • Returning the largest time found without checking that all n nodes were reached: an unreachable node must turn the answer into -1.
  • Treating a node as final when it is pushed. A later pop can offer it a smaller time; it is final only when popped (or skip stale pops, as in the code).
  • Adding both directions for each link. Links are one-way here.

Python notes

  • heapq.heappush(heap, (time, node)) keeps the smallest time at heap[0]; tuples compare by the first field, then the node number on ties.
  • A dictionary dist = {node: math.inf for node in range(1, n + 1)} avoids the unused-slot-0 issue of a list.
  • max(dist.values()) is the answer once every node is finite; math.inf compares larger than any number.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Cheapest Flights Within K Stops LC 787 — the route may use at most k + 1 links: plain Dijkstra can discard a slightly dearer route that has fewer links. Bellman-Ford rounds (or a heap over (node, stops) states) handle the cap.
  • Path with Maximum Probability LC 1514 — routes multiply probabilities instead of adding times, and you want the largest: a max-heap (push negated values) with p * edge as the relaxation.
  • Path With Minimum Effort LC 1631 — a route costs its single biggest climb, not the sum: Dijkstra with max(effort, step) instead of +.
  • Number of Ways to Arrive at Destination LC 1976 — count the shortest routes too: a strictly better time resets a node's count, an equal time adds to it.
  • What if some link times were negative? — Dijkstra's 'popped means final' argument breaks. Bellman-Ford (the second approach) still works in O(V · E) and can detect a negative cycle.
