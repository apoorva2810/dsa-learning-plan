Best Time to Buy and Sell Stock with Cooldown Medium

LeetCode #309 ↗
Status

Buy and sell a stock as often as you like for maximum profit, but after every sale you must sit out one day.

Problem

prices[i] is the price of a stock on day i. You may complete as many transactions as you like (buy one share, later sell it), under two rules:

  • you hold at most one share at a time, so you must sell before you buy again;
  • after you sell, you must wait one day (a cooldown) before you can buy again.

Each day you can do at most one thing: buy, sell, or nothing. Return the maximum total profit. Doing nothing at all gives profit 0, so the answer is never negative.

Examples

Example 1
Input: prices = [1, 2, 3, 0, 2]
Output: 3
buy (1), sell (2), cooldown, buy (0), sell (2): 1 + 2 = 3.
Example 2
Input: prices = [1, 2, 4]
Output: 3
Buy at 1 and sell at 4. Selling at 2 to trade again is pointless: day 2 would be a cooldown.
Example 3
Input: prices = [1]
Output: 0

Constraints

  • 1 <= len(prices) <= 5000
  • 0 <= prices[i] <= 1000

Think first try before reading the solution

At the end of each day you are in one of three situations: holding a share, having just sold one today, or resting with no share and free to buy tomorrow. Which situations can each one lead to the next day?
holding → holding (wait) or sold (sell today); sold → resting (the forced cooldown); resting → resting (wait) or holding (buy today). Keep the best profit for each of the three situations.
hold = max(hold, rest - p), sold = hold + p, rest = max(rest, sold), where every right-hand side uses yesterday's values.

Key idea

Without the cooldown you could grab every price rise. The cooldown means a sale today blocks a purchase tomorrow, so the past matters, but only a little: all you need to know about the past is which situation you are in now. A small diagram of situations and moves between them is called a state machine:

At the end of todayHow you can get there
hold: you own a shareyou already held one yesterday, or you buy today, which is only allowed if yesterday was rest
sold: you sold todayyou held a share yesterday and sell it today
rest: no share, free to buy tomorrowyou were resting yesterday, or yesterday you sold and today is the cooldown

For each day, keep the best profit achievable in each of the three states. That is a table with one row per day and three columns, dp[day][state]: a 2-D DP whose second dimension is tiny. Each row reads only the row before, so three variables replace the table. The answer is the better of sold and rest on the last day: ending while still holding a share can never be best.

The key detail is the hold update: buying reads yesterday's rest, never yesterday's sold. That single choice is the cooldown rule.

Approaches from the obvious one to the one you want in an interview

Decide one day at a time. best(i, holding) = the most profit from day i onward, given whether you own a share when day i starts:

  • you can always wait: best(i + 1, holding);
  • if holding, you can sell: prices[i] + best(i + 2, False), jumping over the cooldown day;
  • if not holding, you can buy: -prices[i] + best(i + 1, True).

Plain recursion tries every sequence of buy/sell/wait choices, about 2^n of them. There are only 2n distinct (i, holding) pairs, so @cache brings it down to O(n).

Dry run

  1. prices = [1, 2, 4]: best(0, False) = max(wait, buy at 1)
  2. buy at 1 → -1 + best(1, True); best(1, True) = max(wait → best(2, True), sell at 2 → 2 + best(3, False) = 2)
  3. best(2, True) = max(best(3, True) = 0, 4 + best(4, False) = 4) = 4, so best(1, True) = 4
  4. best(0, False) = max(best(1, False) = 2, -1 + 4 = 3) = 3

Python

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        n = len(prices)

        @cache                                         # 2n distinct states: (day, holding)
        def best(i: int, holding: bool) -> int:
            """Most profit from day i onward, starting the day with or without a share."""
            if i >= n:                                 # no days left
                return 0
            wait = best(i + 1, holding)                # do nothing today
            if holding:
                sell = prices[i] + best(i + 2, False)  # sell; day i + 1 is the cooldown, so skip it
                return max(wait, sell)
            buy = -prices[i] + best(i + 1, True)       # buy today
            return max(wait, buy)

        return best(0, False)
Time O(n)Space O(n)

2n states with O(1) work each; cache plus up to n recursion frames.

When to use: A good way to discover the states. With 5000 days the recursion is too deep for Python's default limit, so convert it to a loop.

Make the three situations explicit as columns. dp[i][s] = best profit at the end of day i in state s:

  • hold[i] = max(hold[i - 1], rest[i - 1] - prices[i]): keep the share, or buy today (only after a rest day);
  • sold[i] = hold[i - 1] + prices[i]: sell the share held yesterday;
  • rest[i] = max(rest[i - 1], sold[i - 1]): stay idle, or sit out yesterday's cooldown.

Day 0 is the base row: hold = -prices[0], sold = −∞ (nothing to sell yet), rest = 0. The answer is max(sold, rest) on the last day.

Dry run

  1. [1, 2, 3, 0, 2], day 0: (hold, sold, rest) = (-1, −∞, 0)
  2. day 1 (2): (-1, 1, 0); day 2 (3): (-1, 2, 1)
  3. day 3 (0): hold = max(-1, 1 - 0) = 1 (buy after resting), sold = -1, rest = max(1, 2) = 2
  4. day 4 (2): (1, 3, 2) → answer max(3, 2) = 3

Python

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        HOLD, SOLD, REST = 0, 1, 2
        n = len(prices)
        dp = [[0] * 3 for _ in range(n)]          # dp[i][s] = best profit at the end of day i in state s
        dp[0][HOLD] = -prices[0]                  # bought on day 0
        dp[0][SOLD] = float("-inf")               # nothing to sell on day 0
        dp[0][REST] = 0                           # did nothing
        for i in range(1, n):
            p = prices[i]
            dp[i][HOLD] = max(dp[i - 1][HOLD], dp[i - 1][REST] - p)   # keep, or buy after a rest day
            dp[i][SOLD] = dp[i - 1][HOLD] + p                         # sell yesterday's share
            dp[i][REST] = max(dp[i - 1][REST], dp[i - 1][SOLD])       # idle, or cooldown after a sale
        return max(dp[n - 1][SOLD], dp[n - 1][REST])

Watch it run

Each row of the table reads only the row before it, so keep three numbers: hold, sold and rest. Start before day 0 with hold = sold = −∞ (impossible: you own nothing) and rest = 0, then for every price update all three at once from yesterday's values:

hold, sold, rest = max(hold, rest - p), hold + p, max(rest, sold)

The simultaneous assignment matters. Updated one at a time, sold would use today's hold and sell on the same day the share was bought.

Dry run

  1. [1, 2, 3, 0, 2], start (−∞, −∞, 0)
  2. price 1 → (-1, −∞, 0); price 2 → (-1, 1, 0); price 3 → (-1, 2, 1)
  3. price 0 → (1, -1, 2): buying at 0 is allowed because rest was 1 (the day-2 cooldown is over)
  4. price 2 → (1, 3, 2) → answer 3

Python

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        hold = sold = float("-inf")               # before day 0: no share, nothing sold
        rest = 0
        for p in prices:
            # every right-hand side uses yesterday's values
            hold, sold, rest = max(hold, rest - p), hold + p, max(rest, sold)
        return max(sold, rest)                    # never finish while holding a share

Common mistakes

  • Buying from yesterday's sold state (hold = max(hold, sold - p)): that buys on the cooldown day and gives the answer to the problem without a cooldown.
  • Updating the three variables one at a time: after hold is overwritten, sold = hold + p uses today's hold and sells on the same day it bought. Use tuple assignment or save the old values first.
  • Starting sold (or hold) at 0 instead of minus infinity. Before day 0 you own nothing, so a sale is impossible; 0 can let an impossible state win a max in other variants of this problem.
  • Returning max(hold, sold, rest). A share you still hold at the end has cost money and earned nothing, so hold is never the answer.
  • Greedy 'sell at every local peak' fails: on [2, 1, 4, 5, 2, 9, 7] selling at the peak 5 makes the cheap day (price 2) a cooldown. Selling one day earlier, at 4, is better overall (10 versus 8).

Python notes

  • hold, sold, rest = max(hold, rest - p), hold + p, max(rest, sold) evaluates the whole right-hand side with the old values before assigning, which is exactly "every update uses yesterday".
  • float("-inf") marks an impossible state: -inf + p is still -inf, and max ignores it whenever anything real is available.
  • In the memoised version, jumping to i + 2 after a sale skips the cooldown day without a separate state.
  • The memoised version recurses once per day. 5000 days is far past Python's default limit of 1000 frames (RecursionError), which is why the loop versions are the ones to submit.
  • Naming the columns (HOLD, SOLD, REST = 0, 1, 2) keeps dp[i][SOLD] readable instead of dp[i][1].

Follow-up questions

What an interviewer might ask next, and what changes.

  • Best Time to Buy and Sell Stock LC 121 — only one transaction: track the cheapest price so far; no state machine needed.
  • Best Time to Buy and Sell Stock II LC 122 — unlimited transactions and no cooldown: sold and rest merge into one state (or add every price rise greedily).
  • Best Time to Buy and Sell Stock with Transaction Fee LC 714 — no cooldown but every sale costs a fee: two states, hold and free, and subtract the fee when selling.
  • Best Time to Buy and Sell Stock III LC 123 — at most two transactions: four states (first buy, first sell, second buy, second sell), updated in the same way.
  • Best Time to Buy and Sell Stock IV LC 188 — at most k transactions: the state becomes (transactions used, holding or not), a 2-D table per day.
  • A cooldown of k days — rest must remember sales from up to k days back: keep the sold values of the last k days in a small queue.
