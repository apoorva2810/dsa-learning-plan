Binary Search Easy

LeetCode #704 ↗
Status

Find a target's index in a sorted list in O(log n) by halving the search range.

Problem

You are given a list of distinct integers nums sorted in increasing order, and an integer target. Return the index of target in nums, or -1 if it is not there.

Your algorithm must run in O(log n) time.

Examples

Example 1
Input: nums = [-1, 0, 3, 5, 9, 12], target = 9
Output: 4
nums[4] is 9.
Example 2
Input: nums = [-1, 0, 3, 5, 9, 12], target = 2
Output: -1
2 would sit between 0 and 3, but it is not in the list.

Constraints

  • 1 <= len(nums) <= 10^4
  • -10^4 < nums[i], target < 10^4
  • all values are distinct and sorted in increasing order

Think first try before reading the solution

A left-to-right scan is O(n). Because the list is sorted, one comparison with the middle element tells you something about a whole half of the list. What?
Keep two indices lo and hi that bound where the target can still be. Compare with nums[mid] and move lo or hi past mid.
Loop while lo <= hi. When the range becomes empty (lo > hi), the target is absent.

Key idea

In a sorted list, comparing the target with the middle element rules out half of the list in one step: if nums[mid] < target, then everything at or left of mid is too small as well. So keep a range lo..hi that must contain the target if it exists, look at its middle, and discard the half that cannot contain it.

Each comparison halves the range, so a list of n elements needs at most about log₂(n) + 1 comparisons: 14 for 10,000 elements, against up to 10,000 for a scan.

Approaches from the obvious one to the one you want in an interview

Check every element from the left until you find the target. It ignores the fact that the list is sorted, so it costs O(n): up to 10,000 comparisons, where binary search needs 14. The requirement says O(log n), so this does not pass the problem as stated, but it is the baseline to beat.

Python

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        for i, value in enumerate(nums):
            if value == target:
                return i
        return -1
Time O(n)Space O(1)

When to use: Unsorted data, or tiny lists.

Keep lo and hi so that the target, if present, is inside nums[lo..hi] (both ends included).

  1. mid = (lo + hi) // 2.
  2. nums[mid] == target → return mid.
  3. nums[mid] < target → the target is right of mid: lo = mid + 1.
  4. Otherwise it is left of mid: hi = mid - 1.

Both updates move past mid, so the range shrinks every round; when lo > hi it is empty and the answer is -1.

Dry run

  1. nums = [-1, 0, 3, 5, 9, 12], target 9: lo = 0, hi = 5
  2. mid = 2 → 3 < 9 → lo = 3
  3. mid = 4 → 9 == 9 → return 4
  4. target 2: mid = 2 → 3 > 2 → hi = 1; mid = 0 → −1 < 2 → lo = 1; mid = 1 → 0 < 2 → lo = 2 > hi → −1

Python

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1               # the target can only be inside nums[lo..hi]
        while lo <= hi:                         # empty once lo passes hi
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            if nums[mid] < target:
                lo = mid + 1                    # mid and everything left of it are too small
            else:
                hi = mid - 1                    # mid and everything right of it are too big
        return -1
Time O(log n)Space O(1)

The range halves every round, so there are at most ⌊log₂ n⌋ + 1 rounds.

When to use: The answer to this problem and the template for the whole topic.

Watch it run

bisect.bisect_left(nums, target) runs a binary search and returns the first index whose value is >= target (the insert position). The target is present exactly when that index is inside the list and holds the target.

Same O(log n), written in C, and harder to get wrong. Interviewers usually want the hand-written loop first, but this is what you would write in real Python code.

Python

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        i = bisect.bisect_left(nums, target)    # first index with nums[i] >= target
        if i < len(nums) and nums[i] == target:
            return i
        return -1
Time O(log n)Space O(1)

When to use: Production Python; mention it after writing the loop.

Common mistakes

  • Writing while lo < hi with hi = mid - 1: the loop stops while one candidate (lo == hi) is still unchecked, so a target at that spot is reported missing. With an inclusive range lo..hi, loop while lo <= hi.
  • Setting lo = mid or hi = mid in this inclusive template: once lo == hi (or hi == lo + 1) the range stops shrinking and the loop never ends. Move past mid.
  • Starting with hi = len(nums) in the inclusive template: nums[mid] can then read past the end.
  • Calling nums.index(target): it scans in O(n) and raises ValueError when the target is missing.

Python notes

  • bisect.bisect_left(nums, target) returns the leftmost position where target could be inserted. Check i < len(nums) and nums[i] == target to turn it into a membership test.
  • (lo + hi) // 2 rounds down. Python integers never overflow, so there is no need for lo + (hi - lo) // 2.
  • nums[mid] with a negative mid would silently read from the end; the lo <= hi loop never produces one.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Search Insert Position LC 35 — return where the target would go instead of -1: when the loop ends, lo is exactly that position.
  • Find First and Last Position of Element in Sorted Array LC 34 — duplicates are allowed: run a lower-bound search (bisect_left) and an upper-bound search (bisect_right).
  • Search in Rotated Sorted Array LC 33 — the sorted list was rotated: first decide which half of lo..hi is sorted, then test the target against that half.
  • Search in a Sorted Array of Unknown Size LC 702 — no length is given: double hi until it passes the target (exponential search), then binary search.
  • Sqrt(x) LC 69 — there is no list at all: binary search the answer k in 0..x with the test k * k <= x.
