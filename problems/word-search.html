Word Search Medium

LeetCode #79 ↗
Status

Decide whether a word can be traced through neighbouring cells of a letter grid, using each cell at most once.

Problem

You are given an m x n grid of letters, board, and a string word. Return True if word can be traced on the board, otherwise False.

To trace a word, start on any cell that holds its first letter. Then move one step at a time to a cell directly above, below, left or right of the current one (diagonals do not count), so that the letters you step on spell the word in order. Within one trace, each cell may be used at most once.

Examples

Example 1
Input: board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], word = "ABCCED"
Output: true
A (0,0) → B (0,1) → C (0,2) → C (1,2) → E (2,2) → D (2,1). Cells are written (row, column).
Example 2
Input: board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], word = "SEE"
Output: true
S (1,3) → E (2,3) → E (2,2).
Example 3
Input: board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], word = "ABCB"
Output: false
After A → B → C the next B would have to be the first B again, but a cell cannot be used twice.

Constraints

  • 1 <= m, n <= 6
  • 1 <= len(word) <= 15
  • board and word contain only English letters, upper or lower case

Think first try before reading the solution

A trace can start on any cell that holds word[0]. How will you try all of those starting cells?
From a cell, only some neighbours are worth visiting. Think of a function dfs(r, c, i) that answers: 'can the letters word[i:] be traced starting on cell (r, c)?'
A cell must not be used twice in one trace, so mark it when you step onto it. Then think carefully about when to remove the mark: another trace may want that cell after this one has failed.

Key idea

Treat the board as a maze of letters and the word as the route you must spell. For every cell that holds the first letter, walk outwards, and at each step continue only into a neighbour that holds the next letter. When no neighbour has it, the route is a dead end: step back and try a different neighbour of the previous cell. That "step back and try another way" is backtracking.

The one subtle rule is "each cell at most once per trace". Mark a cell when you step onto it and remove the mark when you step back off it. The removal matters: a cell used by a route that failed is perfectly fine for a different route, so the mark must live only while the cell is on the current path. (Compare Number of Islands, where a visited mark stays forever, because there you only ask whether a cell was seen at all.)

From a cell you have at most 4 neighbours, and after the first step at most 3 of them are new (you cannot step back onto the cell you came from). So a word of length L costs at most about 4 · 3^(L-1) steps per start cell. In practice far fewer, because a neighbour must hold exactly the next letter.

Approaches from the obvious one to the one you want in an interview

The most literal reading: a trace is a route of len(word) cells that never reuses a cell. So generate every such route from every start cell, spell its letters, and compare the spelling with word only when the route is long enough.

It is correct, but it ignores the letters while walking. A route that begins ZZ... is extended to full length before anyone notices it cannot be ABC.... From each start cell there are up to 4 · 3^(L-1) routes (4 directions at first, then at most 3, because you cannot step back onto the cell you came from). For a 6 x 6 board and a 15-letter word that can reach hundreds of millions of routes, which is far too many.

Dry run

  1. word = "ABCB" on the example board. From (0,0) the 4-cell routes include ABCC, ABCE, ABFC and ABFD.
  2. Each route is built to its full length and compared with ABCB only at the end. None of them matches.
  3. The same happens from every other start cell, so the answer is False after all routes were built.

Python

class Solution:
    def exist(self, board: List[List[str]], word: str) -> bool:
        rows, cols = len(board), len(board[0])
        used = set()                                  # cells on the current route

        def walk(r, c, spelled):
            spelled += board[r][c]                    # add this cell's letter to the route's text
            if len(spelled) == len(word):             # the route is long enough: compare only now
                return spelled == word
            used.add((r, c))
            found = False
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and (nr, nc) not in used:
                    if walk(nr, nc, spelled):
                        found = True
                        break
            used.remove((r, c))                       # the route is abandoned: free the cell
            return found

        return any(walk(r, c, "") for r in range(rows) for c in range(cols))
Time O(m · n · 3^L)Space O(L)

Up to 4 · 3^(L-1) routes per start cell for a word of L letters on an m x n board. The cost is paid on almost every input, because letters are not looked at until the route is complete. Memory is the route (L cells).

When to use: Only to see what pruning saves. Never submit it.

Compare letters while walking, and drop a route the moment it goes wrong. dfs(r, c, i) answers "can word[i:] be traced starting on cell (r, c)?":

  1. If i == len(word), every letter has been matched: return True.
  2. If the cell is off the board or does not hold word[i], return False. (A cell already on the path holds #, so it fails this check too.)
  3. Otherwise mark the cell with #, try the four neighbours with i + 1, then un-mark it (restore the letter) and return whether any neighbour succeeded.

exist tries dfs(r, c, 0) from every cell. Because a wrong letter ends the walk at once, only routes that spell a prefix of the word are ever extended. Overwriting the cell with # doubles as the "used" mark, so no separate visited set is needed.

Dry run

  1. word = "SEE". Scan for S: (1,0) holds it. dfs(1,0,0) marks it and looks for E among down A, up A, right F: none. Un-mark, return False.
  2. (1,3) holds S. dfs(1,3,0) marks it. Down is (2,3) E, so dfs(2,3,1) matches and marks it.
  3. dfs(2,3,1) looks for the last E: up is the marked (1,3), left is (2,2) E. dfs(2,2,2) matches and marks it.
  4. The next call has i == 3 == len(word) and returns True. The or chains short-circuit, so (0,3) is never tried and exist returns True.

Python

class Solution:
    def exist(self, board: List[List[str]], word: str) -> bool:
        rows, cols = len(board), len(board[0])

        def dfs(r, c, i):
            if i == len(word):                         # every letter has been matched
                return True
            if not (0 <= r < rows and 0 <= c < cols) or board[r][c] != word[i]:
                return False                           # off the board, wrong letter, or a '#' cell
            letter = board[r][c]
            board[r][c] = "#"                          # mark: this cell is on the current path
            found = (dfs(r + 1, c, i + 1) or dfs(r - 1, c, i + 1)
                     or dfs(r, c + 1, i + 1) or dfs(r, c - 1, i + 1))
            board[r][c] = letter                       # un-mark: backtrack, whatever the outcome
            return found

        return any(dfs(r, c, 0) for r in range(rows) for c in range(cols))
Time O(m · n · 3^L)Space O(L)

The worst case (a board of one repeated letter) is the same as the brute force, 4 · 3^(L-1) routes per start cell. The difference is that ordinary boards stop after one or two letters. Memory is the recursion, L frames; the marks live inside the board.

When to use: The interview answer. State the mark / un-mark rule out loud and why the un-mark is needed.

Watch it run

The plain DFS is the interview answer, but test suites contain nasty boards such as all A with the word AAAAAAAAAB. Every route of As matches until the very last letter, so nothing is cut off and the search is slow.

Two checks run before the search:

  1. Letter counts. If the word needs more copies of some letter than the board contains, return False without searching.
  2. Search from the rarer end. A word can be traced forwards exactly when its reverse can be traced backwards. If the last letter occurs on the board less often than the first, reverse the word: fewer cells match the first letter, so fewer searches start (and the awkward letter is met first).

Neither check changes the worst case, but together they remove the usual time-outs.

Dry run

  1. Board of all A with a single B, word AAAAAAAAAAAB: counts are fine, but A (11 cells) is more common than B (1 cell).
  2. Reverse the word to BAAAAAAAAAAA. Only one cell holds B, so only one search starts instead of eleven.
  3. For a word needing a letter the board lacks, the count check returns False before any search.

Python

class Solution:
    def exist(self, board: List[List[str]], word: str) -> bool:
        rows, cols = len(board), len(board[0])

        # Prune 1: the board must hold every letter the word needs, often enough
        on_board = Counter(ch for row in board for ch in row)
        for ch, needed in Counter(word).items():
            if on_board[ch] < needed:
                return False

        # Prune 2: trace from the rarer end, so fewer start cells match
        if on_board[word[0]] > on_board[word[-1]]:
            word = word[::-1]

        def dfs(r, c, i):
            if i == len(word):
                return True
            if not (0 <= r < rows and 0 <= c < cols) or board[r][c] != word[i]:
                return False
            letter = board[r][c]
            board[r][c] = "#"
            found = (dfs(r + 1, c, i + 1) or dfs(r - 1, c, i + 1)
                     or dfs(r, c + 1, i + 1) or dfs(r, c - 1, i + 1))
            board[r][c] = letter
            return found

        return any(dfs(r, c, 0) for r in range(rows) for c in range(cols))
Time O(m · n · 3^L)Space O(L)

The pre-checks cost O(m · n + L). The search has the same worst-case bound as before.

When to use: When a judge has adversarial boards. Write the plain version first, then add the prunes.

Common mistakes

  • Not marking cells. Without a mark, ABCB on the example board returns True by stepping back onto the first B.
  • Forgetting to restore the cell after the recursive calls. Marks left behind by a failed path block later paths, and answers become False when they should be True.
  • Checking the bounds after indexing. In Python board[-1][0] does not raise an error, it quietly reads the last row, so test 0 <= r < rows and 0 <= c < cols before touching board[r][c].
  • Returning True before restoring the cell. The answer is right, but the caller's board is left with # in it. Keep the result in a variable, restore the cell, then return.
  • Using one global visited set and never removing from it, as in Number of Islands. Here every mark needs a matching un-mark.
  • Boards such as all A with the word AAAAAAAAB. Every route matches until the last letter, so nothing is pruned and the search is slow. Compare letter counts first and start from the rarer end of the word (third approach).

Python notes

  • 0 <= r < rows is a chained comparison: it means 0 <= r and r < rows.
  • Writing board[r][c] = "#" marks the cell without a separate visited set. It works because each row is a list, which can be changed; a row stored as a string could not be assigned into. Restore the letter afterwards.
  • a or b does not evaluate b when a is True, and any(...) over a generator stops at the first True. That is why the search ends the moment one trace succeeds.
  • for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)): is the usual way to loop over the four neighbours.
  • Counter(word) counts letters, and a missing key reads as 0 (no KeyError), which keeps the letter-count check short.
  • The recursion is at most len(word) (15) frames deep, so Python's recursion limit is no concern.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Word Search II LC 212 — find many words at once: put them in a trie and walk the board once, following the trie as you go.
  • Number of Islands LC 200 — the same four-direction grid DFS, but the visited mark is permanent, because you only need to know that a cell was seen. Nothing is undone.
  • Path with Maximum Gold LC 1219 — the same mark, explore, un-mark loop from every start cell, but you maximise the sum of the cells on the path instead of matching a word.
  • Unique Paths III LC 980 — count the routes that visit every empty cell exactly once: backtracking with a counter of cells left to visit.
  • Allow diagonal moves — loop over 8 directions instead of 4. After the first step there are up to 7 new neighbours, so the worst case grows to about 8 · 7^(L-1).
  • Return the path, not just True or False — keep a list of the cells on the current path and return a copy of it as soon as the word is matched.
