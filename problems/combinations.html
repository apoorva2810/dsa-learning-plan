Status

List every way to choose k different numbers from 1 to n, where the order inside a group does not matter.

Problem

You are given two integers n and k. Return every combination of k different numbers chosen from the range 1 to n.

  • A combination is a group, not a sequence: [1, 2] and [2, 1] are the same combination and must appear only once.
  • The combinations can be returned in any order.

Examples

Example 1
Input: n = 4, k = 2
Output: [[1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4]]
Six groups: 4 choose 2 = 4! / (2! × 2!) = 6.
Example 2
Input: n = 1, k = 1
Output: [[1]]
One number, one group.
Example 3
Input: n = 3, k = 3
Output: [[1, 2, 3]]
Choosing every number can be done in only one way.

Constraints

  • 1 <= n <= 20
  • 1 <= k <= n

Think first try before reading the solution

How many answers are there? That count is called 'n choose k'. Why is [1, 2] the same group as [2, 1], and how could you write every group in exactly one canonical order?
Write each group in increasing order. Once you have picked x, only numbers bigger than x may come next. Which single number can the recursion carry along to enforce that?
Give backtrack a parameter start. It loops x from start up to n: append x, call backtrack(x + 1), then pop. A group is complete when path has k numbers. To avoid dead branches, ask how many numbers you still need and whether enough numbers are left to the right.

Key idea

Order inside a group does not matter, so give every group one canonical spelling: write it in increasing order. Then [2, 1] is simply never built, because after picking 2 only numbers larger than 2 are allowed. To make the recursion build only increasing groups, pass along where the last pick stopped: backtrack(start) may choose numbers from start to n, and after choosing x it continues with start = x + 1. That start index plays the role that the used array played in Permutations: numbers to the left of it are never offered again.

The search tree has one level per number picked. The children of a node are the allowed next picks, and a node at depth k is a finished group. There are C(n, k) ("n choose k") finished groups.

One cheap improvement is to prune (cut off) branches that cannot succeed. If need = k - len(path) numbers are still required, a pick x leaves n - x numbers on its right and need - 1 more are required after it, so x <= n - need + 1. Without this bound the code is still correct, but it walks branches such as "pick 4 first" for n = 4, k = 2 that can never become a full group. With the bound, every call leads to at least one answer.

Approaches from the obvious one to the one you want in an interview

A bitmask is an integer whose bit i says whether the number i + 1 is in the group, so the integers 0 to 2ⁿ - 1 describe every subset of 1..n exactly once. Count the set bits of each mask, keep the masks with exactly k of them, and turn each kept mask into a list.

It is easy to get right, and a good way to see what backtracking saves. The loop visits all 2ⁿ subsets of every size, then throws most of them away: for n = 20, k = 2 it looks at 1,048,576 masks to keep 190.

Dry run

  1. n = 3, k = 2: 2³ = 8 masks, one for each subset of {1, 2, 3}.
  2. mask = 3 (011) holds the numbers 1 and 2: two numbers → keep [1, 2].
  3. mask = 5 (101) → [1, 3], mask = 6 (110) → [2, 3]: both kept.
  4. The other five masks have 0, 1 or 3 numbers → skipped. Result: [[1, 2], [1, 3], [2, 3]].

Python

class Solution:
    def combine(self, n: int, k: int) -> List[List[int]]:
        result = []
        for mask in range(1 << n):                         # 2^n masks: one per subset of 1..n
            if bin(mask).count("1") != k:                  # keep only subsets with exactly k numbers
                continue
            result.append([i + 1 for i in range(n) if (mask >> i) & 1])   # bit i set -> number i + 1 is in
        return result
Time O(n · 2ⁿ)Space O(k)

2ⁿ masks, each counted and (when kept) expanded in O(n). Apart from the output, only one group is held at a time.

When to use: Only to see the waste. Fine for n up to about 15; for n = 20 it already visits a million masks.

Build each group in increasing order. backtrack(start) works with a shared list path:

  • if path holds k numbers, copy it into result and return;
  • otherwise loop x from start upward: append x, call backtrack(x + 1) (only larger numbers may follow), then pop.

The loop stops early. With need = k - len(path) numbers still required, x can be at most n - need + 1; any larger x leaves too few numbers on its right. So every call that is made leads to at least one finished group, and nothing is wasted.

The tree has C(n, k) leaves, at most k + 1 calls on the way to each, and each leaf is copied in O(k). That matches the size of the output, so no algorithm can do much better.

Dry run

  1. n = 4, k = 2, path = []. backtrack(1): need = 2, so x runs from 1 to 4 - 2 + 1 = 3. Picking 4 first is never tried.
  2. x = 1 → path = [1], backtrack(2): need = 1, x runs from 2 to 4. x = 2 → [1, 2] is full → record. Pop. x = 3 → [1, 3]. x = 4 → [1, 4].
  3. Pop 1. x = 2 → path = [2], backtrack(3): x = 3 → [2, 3], x = 4 → [2, 4].
  4. x = 3 → path = [3], backtrack(4): x = 4 → [3, 4].
  5. Six groups, C(4, 2) = 6, each built once.

Python

class Solution:
    def combine(self, n: int, k: int) -> List[List[int]]:
        result = []
        path = []                                   # the numbers chosen so far, in increasing order

        def backtrack(start: int) -> None:
            if len(path) == k:                      # k numbers chosen: one complete group
                result.append(path[:])              # store a copy, path keeps changing
                return
            need = k - len(path)                    # how many more numbers this group still needs
            # x can be at most n - need + 1, otherwise too few numbers remain on its right
            for x in range(start, n - need + 2):
                path.append(x)                      # choose x
                backtrack(x + 1)                    # explore: only larger numbers may follow
                path.pop()                          # un-choose x

        backtrack(1)
        return result
Time O(k · C(n, k))Space O(k)

C(n, k) leaves, at most k + 1 calls on the way to each, and an O(k) copy per leaf. The recursion and path are at most k deep; the output is not counted.

When to use: The standard answer, and the template for Combination Sum and Subsets. Mention the bound on x as the optimisation.

Watch it run

Look at the numbers one at a time and make a yes/no decision for each: take x into the group, or skip it. decide(x) handles number x; a group is complete as soon as path holds k numbers.

This is the take/skip tree of Subsets with two cuts. It stops when path is full, and it stops when the numbers from x to n are fewer than the numbers still needed. Both versions build the same groups. The take/skip tree is deeper (a level for every number, not for every pick), so it makes about twice as many calls: 19 instead of 10 for n = 4, k = 2.

Dry run

  1. n = 3, k = 2. decide(1): take 1 → decide(2): take 2 → [1, 2] is full → record.
  2. Back in decide(2): skip 2 → decide(3): take 3 → [1, 3]. Skip 3 → decide(4): no numbers left → cut.
  3. Back in decide(1): skip 1 → decide(2): take 2 → decide(3): take 3 → [2, 3].
  4. Skip 2 → decide(3): only one number left but two are needed → cut. Three groups.

Python

class Solution:
    def combine(self, n: int, k: int) -> List[List[int]]:
        result = []
        path = []

        def decide(x: int) -> None:
            if len(path) == k:                      # k numbers taken: one complete group
                result.append(path[:])
                return
            if n - x + 1 < k - len(path):           # fewer numbers left than we still need
                return
            path.append(x)                          # take x ...
            decide(x + 1)
            path.pop()                              # ... then skip x
            decide(x + 1)

        decide(1)
        return result
Time O(n · C(n, k))Space O(n)

Every call that passes the cut leads to a leaf, so there are at most n + 1 calls on the way to each of the C(n, k) leaves. The recursion can be n deep because skipped numbers add levels.

When to use: When you think in take/skip terms (as in Subsets). It needs no loop, but it is deeper and makes more calls.

Common mistakes

  • Looping x from 1 in the recursive call instead of from start. You then build both [1, 2] and [2, 1], and every group appears k! times.
  • Recursing with backtrack(x) instead of backtrack(x + 1). The same number is picked twice ([1, 1]) and the recursion may never end.
  • Storing path itself instead of a copy (path[:]). The same list is emptied again by the pop calls, so every stored group ends up empty.
  • Off-by-one in the prune bound. range(start, n - need + 2) includes n - need + 1 because range stops before its end. Writing n - need + 1 as the end silently drops valid answers.
  • Leaving the bound out and trusting the answer to be 'correct anyway'. It is correct, but for n = 20, k = 18 the search makes about a million calls instead of about 1,300.
  • Forgetting path.pop() after the recursive call. The next candidate is appended to a path that still holds the previous one, so groups come out too long.

Python notes

  • itertools.combinations(range(1, n + 1), k) yields every group as a tuple, in increasing order. [list(c) for c in ...] is a one-line cross-check, but the backtracking version is what an interview asks for.
  • math.comb(n, k) is the expected number of groups, handy for checking len(result).
  • range(a, b) stops before b, so range(start, n - need + 2) is the numbers from start to n - need + 1.
  • bin(mask).count("1") counts the set bits of an integer; Python 3.10+ also has mask.bit_count().
  • path[:] copies a list. Appending path itself stores a reference that later pop calls keep changing.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Combination Sum LC 39 — numbers may be reused and the group must add up to a target: recurse with i instead of i + 1, and stop when the remaining target goes negative.
  • Combination Sum II LC 40 — the candidates contain duplicates but each can be used once: sort, and skip a value equal to the previous one at the same depth.
  • Subsets LC 78 — groups of every size at once: record path at every call instead of only when it has k numbers.
  • Permutations LC 46 — order matters, so there is no start: any unused number may come next, tracked with a used array.
  • Combination Sum III LC 216 — choose k different digits from 1 to 9 that add up to n: this exact search with a running sum, pruning when the sum gets too big.
  • Produce the combinations one at a time — keep a list of k indices and move the rightmost index that still has room; every next combination then costs O(k) and nothing is stored.
