Stone Game II Medium 250

LeetCode #1140 ↗
Status

Two players take stones from the front of a row of piles, with a take limit that grows as the game goes on. Find the most stones the first player can collect.

Problem

Alice and Bob play with a row of piles; piles[i] is the number of stones in pile i. They take turns, Alice first, and a number M starts at 1.

On your turn you take all the stones of the first X piles that are still in the row, for any X with 1 <= X <= 2M. Then M becomes max(M, X). The game ends when no pile is left. Each player wants to finish with as many stones as possible.

Return the largest number of stones Alice can collect, assuming both players play perfectly.

Examples

Example 1
Input: piles = [4, 2, 7, 1, 6]
Output: 11
Alice takes the 4. If Bob took only the 2, Alice could take 7 and 1 and then Bob would get the 6, so Bob takes the 2 and the 7 together. Now M is 2 and Alice takes the last two piles, 1 and 6: 4 + 1 + 6 = 11 against Bob's 9. Starting with 4 + 2 is worse: M becomes 2 and Bob takes everything left.
Example 2
Input: piles = [1, 2]
Output: 3
With M = 1 Alice may take up to 2 piles, so she takes both.
Example 3
Input: piles = [5]
Output: 5
One pile, and Alice takes it.

Constraints

  • 1 <= len(piles) <= 100
  • 1 <= piles[i] <= 10^4

Think first try before reading the solution

Every stone ends up with someone, so the two totals always add up to the total number of stones. That means you do not need to track both scores. What state describes the game at the moment a player has to move?
The state is (i, m): the first remaining pile and the current limit. Let best(i, m) be the most stones the player to move can collect from piles[i:]. If you take X piles, the opponent plays from (i + X, max(m, X)) and collects best(i + X, max(m, X)) of what is left; the rest is yours.
The rest is suffix[i] - best(i + X, max(m, X)), where suffix[i] is the sum of piles[i:]. Try every X from 1 to 2m and keep the largest. When i + 2m >= n you may take everything left. Cache the results by (i, m).

Key idea

Every stone ends up with someone, so the game is zero-sum: if one player collects more, the other collects less by the same amount. That lets us track one number. Let best(i, m) be the most stones the player to move can still collect from piles[i:] when the limit is M = m.

Suppose that player takes the first X piles. The opponent becomes the player to move in state (i + X, max(m, X)) and collects best(i + X, max(m, X)) of the stones that remain. All other stones in piles[i:], including the X piles just taken, are ours:

best(i, m) = max over X in 1..2m of ( suffix[i] - best(i + X, max(m, X)) )

Here suffix[i] is the number of stones in piles[i:]. Precomputing it once makes each term O(1). If i + 2m >= n, the player is allowed to take every pile that is left, which is the most possible, so best(i, m) = suffix[i]. The answer is best(0, 1).

Without a cache the recursion replays the same position through different move orders: taking 1 pile and then 2 piles reaches (3, 2), and so does taking 2 piles and then 1. Caching by (i, m) gives at most n · n states, each trying fewer than n values of X: O(n³) instead of exponential. Taking many piles is not automatically good, because a larger take raises M and gives the opponent a larger choice next turn.

Approaches from the obvious one to the one you want in an interview

Play the game out. play(i, m, alice_turn) returns the number of stones Alice ends up with from piles[i:], given the limit M = m and whose turn it is. The mover tries every X from 1 to min(2m, n - i), takes the first X piles, and hands over with the new limit max(m, X):

  • on Alice's turn she picks the X that maximises taken + play(...), the stones she just took plus what she gets later;
  • on Bob's turn he wants his own total as large as possible. All stones end up with someone, so that means Alice's total as small as possible: he picks the X that minimises play(...).

This is correct, but the number of different games grows exponentially, and the same position (i, m) is replayed from many move orders: taking 1 pile and then 2 piles reaches the same (3, 2) as taking 2 piles and then 1.

Dry run

  1. [2, 7, 9]: on Alice's first turn M = 1, so she may take X = 1 or X = 2 piles
  2. X = 1: she gets 2, then Bob (M = 1 again) takes both remaining piles, 16 stones, and Alice gets nothing more → 2
  3. X = 2: she gets 2 + 7 = 9, M becomes 2, and Bob takes the last pile → 9
  4. Alice picks the larger: 9

Python

class Solution:
    def stoneGameII(self, piles: List[int]) -> int:
        n = len(piles)

        def play(i: int, m: int, alice_turn: bool) -> int:
            """Stones Alice ends up with from piles[i:], both players playing perfectly."""
            if i >= n:                                            # no piles left
                return 0
            best = None
            for x in range(1, min(2 * m, n - i) + 1):             # take the first x piles
                taken = sum(piles[i:i + x])
                rest = play(i + x, max(m, x), not alice_turn)
                if alice_turn:                                    # Alice maximises her own total
                    value = taken + rest
                    best = value if best is None else max(best, value)
                else:                                             # Bob's stones do not count; he minimises Alice's total
                    best = rest if best is None else min(best, rest)
            return best

        return play(0, 1, True)

Two observations remove the repetition.

1. The game is zero-sum, so one number is enough. Every stone ends up with someone. Let best(i, m) be the most stones the player to move can still collect from piles[i:] when the limit is M = m. If that player takes the first X piles, the opponent becomes the player to move in state (i + X, max(m, X)) and collects best(i + X, max(m, X)) of the stones that remain. Everything else in piles[i:] goes to us, including the X piles we just took:

best(i, m) = max over X in 1..2m of ( suffix[i] - best(i + X, max(m, X)) )

where suffix[i] is the number of stones in piles[i:], computed once so that each term costs O(1). If i + 2m >= n, the player may take every remaining pile, so best(i, m) = suffix[i].

2. Cache by (i, m). Different move orders reach the same state. There are at most n · n states and each tries fewer than n values of X, so the work is O(n³) instead of exponential. The answer is best(0, 1).

Dry run

  1. [4, 2, 7, 1, 6], suffix sums [20, 16, 14, 7, 6, 0]: best(0, 1) = max(20 - best(1, 1), 20 - best(2, 2))
  2. best(2, 2): 2 + 4 ≥ 5, so take everything left: 14. best(1, 1) = max(16 - best(2, 1), 16 - best(3, 2))
  3. best(2, 1) = max(14 - best(3, 1), 14 - best(4, 2)) = max(14 - 7, 14 - 6) = 8, and best(3, 2) = 7 (take all)
  4. best(1, 1) = max(16 - 8, 16 - 7) = 9, so best(0, 1) = max(20 - 9, 20 - 14) = 11

Python

class Solution:
    def stoneGameII(self, piles: List[int]) -> int:
        n = len(piles)
        suffix = [0] * (n + 1)                           # suffix[i] = stones in piles[i:]
        for i in range(n - 1, -1, -1):
            suffix[i] = suffix[i + 1] + piles[i]

        @cache                                           # one stored answer per state (i, m)
        def best(i: int, m: int) -> int:
            """Most stones the player to move can collect from piles[i:] when the limit is M = m."""
            if i + 2 * m >= n:                           # allowed to take everything that is left
                return suffix[i]
            # taking x piles leaves the opponent in state (i + x, max(m, x)); the rest of piles[i:] is ours
            return max(suffix[i] - best(i + x, max(m, x)) for x in range(1, 2 * m + 1))

        return best(0, 1)
Time O(n³)Space O(n²)

At most n · n states, each trying fewer than n values of X; the cache holds one number per state.

When to use: The standard answer. It only solves the states the game can reach.

Watch it run

The same recurrence filled from the end of the row. dp[i][m] is the most the player to move can collect from piles[i:] with limit m, for i from n - 1 down to 0 and m from 1 to n. A cell reads only cells with a larger i (dp[i + X][...] with X >= 1), so going from the end of the row towards the start is a valid order. The answer is dp[0][1].

It computes every (i, m) pair, including states the game can never reach, so it does more work than the cached recursion, but there is no recursion to manage and every cell is easy to inspect.

Dry run

  1. [4, 2, 7, 1, 6], suffix [20, 16, 14, 7, 6, 0]: rows from the bottom: dp[4][m] = 6 and dp[3][m] = 7 for every m (take all)
  2. row 2: dp[2][1] = max(14 - 7, 14 - 6) = 8; for m >= 2 take everything: 14
  3. row 1: dp[1][1] = max(16 - dp[2][1], 16 - dp[3][2]) = max(8, 9) = 9; dp[1][2] = 16
  4. row 0: dp[0][1] = max(20 - 9, 20 - 14) = 11

Python

class Solution:
    def stoneGameII(self, piles: List[int]) -> int:
        n = len(piles)
        suffix = [0] * (n + 1)                           # suffix[i] = stones in piles[i:]
        for i in range(n - 1, -1, -1):
            suffix[i] = suffix[i + 1] + piles[i]
        # dp[i][m]: most stones the player to move collects from piles[i:] when the limit is M = m
        dp = [[0] * (n + 1) for _ in range(n + 1)]
        for i in range(n - 1, -1, -1):                   # a cell needs cells with a larger i, so go from the end
            for m in range(1, n + 1):
                if i + 2 * m >= n:                       # allowed to take everything that is left
                    dp[i][m] = suffix[i]
                else:
                    dp[i][m] = max(suffix[i] - dp[i + x][max(m, x)] for x in range(1, 2 * m + 1))
        return dp[0][1]
Time O(n³)Space O(n²)

n rows and n columns of states, each trying fewer than n values of X.

When to use: When you prefer loops to recursion. The cached recursion above is usually shorter and does less work.

Common mistakes

  • Tracking both players' scores or the current player in the state. The game is zero-sum, so best(i, m) for the player to move is enough: the opponent's best share is subtracted from the stones that remain.
  • Updating the limit wrongly. The new limit is max(m, x). It never shrinks, and it is not 2x or 2m; using x alone forgets the old limit.
  • Forgetting the take-everything case. When i + 2m >= n the player can take all remaining piles, so the answer is suffix[i]. Without that check the loop asks for piles beyond the end of the row.
  • Greedy: taking as many piles as allowed. On [4, 2, 7, 1, 6] taking two piles first (4 + 2) raises M to 2, and Bob then takes all three remaining piles, leaving Alice with 6. Taking only the 4 leads to 11.
  • Summing piles[i:i + x] inside the loop and adding the opponent-minus-us bookkeeping by hand. It works but costs O(n) per candidate; with suffix sums, what we collect is suffix[i] - best(...).
  • Passing the list to a cached function. @cache needs hashable arguments: keep piles in the enclosing scope and cache on (i, m) only.

Python notes

  • @cache (from functools, already imported here) stores results by the argument tuple (i, m). Both are integers, so they are hashable. Do not pass piles as an argument.
  • In the non-leaf case 2m < n - i, so range(1, 2 * m + 1) is never empty and max(...) of the generator is safe.
  • suffix has n + 1 entries; suffix[n] = 0 is the sum of no piles.
  • The recursion is at most n = 100 calls deep, well below Python's default recursion limit of 1000.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Stone Game LC 877 — a player takes one pile from either end of the row: the state becomes the two ends (i, j), an interval DP, and the first player's lead is the quantity to track.
  • Stone Game III LC 1406 — take 1, 2 or 3 piles from the front, and piles can be negative: the same 'what is left minus the opponent's best' idea, with a one-dimensional table because there is no M.
  • Stone Game VII LC 1690 — remove a pile from either end and score the sum of the stones that remain: an interval DP on (i, j) with prefix sums for the score.
  • What if a player may take up to K·M piles? — replace 2 by K in the loop and in the take-everything test i + K * m >= n; the state (i, m) and the recurrence stay the same, only the work per state grows.
  • Return Bob's total, or Alice's first move — Bob's total is sum(piles) - best(0, 1). For the first move, remember which X gave the maximum at (0, 1).
