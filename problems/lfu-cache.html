LFU Cache Hard 250

LeetCode #460 ↗
Status

A fixed-size key-value cache that evicts the least frequently used key (the oldest one on ties), with O(1) get and put.

Problem

Design a Least Frequently Used (LFU) cache: a key-value store with a fixed capacity. When it is full and a new key arrives, it throws out the key that has been used the fewest times. If several keys tie for the lowest count, it throws out the one among them that was used least recently.

Implement the class LFUCache:

  • LFUCache(capacity) creates an empty cache that holds at most capacity keys. A capacity of 0 means nothing is ever stored.
  • get(key) returns the value stored for key, or -1 if it is not there. A successful get counts as one use of the key.
  • put(key, value) stores value under key, replacing the old value if the key exists. Either way this counts as one use. If the key is new and the cache is full, evict first, as described above. A newly inserted key starts with a use count of 1.

A key's use count is the number of get and put calls that have touched it since it was inserted. An evicted key forgets its count: if it comes back, it is a new key. Both get and put must run in O(1) average time.

Examples

Example 1
Input: ["LFUCache","put","put","get","put","get","get","put","put","get","get"] [[2],[4,40],[5,50],[4],[6,60],[5],[6],[7,70],[6,65],[4],[7]]
Output: [null, null, null, 40, null, -1, 60, null, null, -1, 70]
get(4) gives key 4 two uses and key 5 one, so put(6, 60) evicts 5. After get(6), keys 4 and 6 tie at two uses, so put(7, 70) evicts 4, the one used earlier. put(6, 65) replaces the value and counts as a use.
Example 2
Input: ["LFUCache","put","get"] [[0],[1,1],[1]]
Output: [null, null, -1]
With capacity 0 the put stores nothing, so the get misses.

Constraints

  • 0 <= capacity <= 10^4
  • 0 <= key <= 10^5
  • 0 <= value <= 10^9
  • at most 2 * 10^5 calls to get and put

Think first try before reading the solution

Keep a dictionary key -> value and a use count per key. The hard part is finding the victim without scanning every key. What do you need to know to pick it: the lowest count, and among equals, the oldest use?
Group the keys by use count: for each count, keep the keys that have it in order of recent use, oldest first. Then the victim is simply the first key of the group with the lowest count.
Each get or put moves one key from the group count to the group count + 1. Remember the smallest count min_freq too: it only changes in two cases (a new key makes it 1; the lowest group becoming empty after a move makes it go up by one), so you never have to search for it.

Key idea

LRU asks one question about each key, when was it last used?, and a single ordered list answers it. LFU asks two: how many times was it used, and, to break ties, when. One list cannot hold both orders, so keep one recency list per use count: a dictionary from count to the keys that have exactly that count, oldest use first.

Now the eviction rule is a lookup. The victim is the oldest key in the group with the lowest count. To find that group without scanning, keep min_freq, the lowest count that currently has keys. A get or put on a key moves it from group f to group f + 1, as the newest member there. If group f becomes empty and f was min_freq, the key just moved to f + 1, so min_freq becomes f + 1. A brand-new key has count 1, which is always the smallest possible, so min_freq becomes 1.

Everything is a dictionary lookup plus removing or adding one key at the end of a list, so both calls are O(1). An OrderedDict per group gives that: it is a hash map that also remembers order, so popitem(last=False) removes the oldest key.

Approaches from the obvious one to the one you want in an interview

Keep three dictionaries: values (key → value), uses (key → count) and last_used (key → a timestamp from a counter that goes up on every call). get and put on a stored key just update them, which is O(1).

To evict, scan every stored key and take the minimum of (uses[key], last_used[key]). Tuples compare element by element, so that picks the lowest count and, among equals, the oldest use. It is exactly the rule, but a full cache pays O(capacity) for every insertion of a new key.

Dry run

  1. capacity 2: put(4, 40), put(5, 50), get(4) → uses {4: 2, 5: 1}
  2. put(6, 60): full → scan: (2, t3) for 4, (1, t2) for 5 → the smallest is 5 → evict 5, insert 6
  3. get(6) → uses {4: 2, 6: 2}; put(7, 70): tuples (2, t3) and (2, t6) → 4 is older → evict 4

Python

class LFUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.clock = 0                        # goes up on every use; gives each use a timestamp
        self.values = {}                      # key -> value
        self.uses = {}                        # key -> how many times it has been used
        self.last_used = {}                   # key -> clock value of its latest use

    def _touch(self, key):
        self.clock += 1
        self.uses[key] += 1
        self.last_used[key] = self.clock

    def get(self, key: int) -> int:
        if key not in self.values:
            return -1
        self._touch(key)
        return self.values[key]

    def put(self, key: int, value: int) -> None:
        if self.capacity == 0:
            return
        if key in self.values:                # existing key: new value, and it counts as a use
            self.values[key] = value
            self._touch(key)
            return
        if len(self.values) == self.capacity:
            # fewest uses first, then the oldest use: a scan over every key, O(capacity)
            victim = min(self.values, key=lambda k: (self.uses[k], self.last_used[k]))
            del self.values[victim]
            del self.uses[victim]
            del self.last_used[victim]
        self.values[key] = value
        self.uses[key] = 0                    # _touch makes it 1
        self._touch(key)
Time O(1) get, O(capacity) put when fullSpace O(capacity)

The min scan visits every stored key whenever a new key arrives at a full cache.

When to use: A correct first version, and the specification for testing the faster ones.

Replace the scan with a heap. Keep values, uses and stamp (the timestamp of the latest use). On every use, push a new tuple (uses, stamp, key) onto a min-heap. The smallest tuple is the least used key, the oldest among equals: the victim.

Old tuples cannot be removed from the middle of a heap, so they stay as stale entries. When you pop for an eviction, skip any tuple whose key is gone, or whose uses or stamp no longer match the key's current numbers; the first live tuple is the victim. Each push and pop is O(log n), so the cost per call is O(log n) amortized. The heap can hold up to one entry per call, not just per key, which is the price of laziness.

Dry run

  1. capacity 2: put(4, 40) pushes (1, t1, 4); put(5, 50) pushes (1, t2, 5); get(4) pushes (2, t3, 4)
  2. put(6, 60): full → pop (1, t1, 4): key 4 now has 2 uses → stale, skip. Pop (1, t2, 5): matches → evict 5
  3. The heap now holds (2, t3, 4) and the new (1, t4, 6); the next eviction will pop 6 first, because 1 < 2

Python

class LFUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.clock = 0
        self.values = {}                      # key -> value
        self.uses = {}                        # key -> use count
        self.stamp = {}                       # key -> clock value of its latest use
        self.heap = []                        # (uses, stamp, key); old tuples are skipped when popped

    def _touch(self, key):
        self.clock += 1
        self.uses[key] += 1
        self.stamp[key] = self.clock
        heapq.heappush(self.heap, (self.uses[key], self.stamp[key], key))

    def get(self, key: int) -> int:
        if key not in self.values:
            return -1
        self._touch(key)
        return self.values[key]

    def put(self, key: int, value: int) -> None:
        if self.capacity == 0:
            return
        if key in self.values:
            self.values[key] = value
            self._touch(key)
            return
        if len(self.values) == self.capacity:
            while True:                       # pop until the entry is still up to date
                uses, stamp, victim = heapq.heappop(self.heap)
                if victim in self.values and self.uses[victim] == uses and self.stamp[victim] == stamp:
                    break
            del self.values[victim]
            del self.uses[victim]
            del self.stamp[victim]
        self.values[key] = value
        self.uses[key] = 0
        self._touch(key)
Time O(log n) per call, amortizedSpace O(number of calls) worst case

Every use pushes one heap entry, and stale entries are only discarded when they reach the top.

When to use: Much simpler than buckets, so a sensible fallback if you are short on time. Mention the heap growth.

Two maps and one number:

  • entries: key → [value, uses].
  • buckets: uses → an OrderedDict of the keys with exactly that count, oldest use first.
  • min_freq: the lowest count that has any key.

_touch(key) is the one move everything shares: take the key out of bucket f; if that bucket is now empty, delete it, and if f == min_freq raise min_freq by one (the key is about to land in f + 1); then append the key to bucket f + 1, so it is the newest member there.

get = look up + _touch. put on an existing key = replace the value + _touch. put on a new key at full capacity first evicts: buckets[min_freq].popitem(last=False) is the oldest key of the lowest bucket. Then insert the new key into bucket 1 and set min_freq = 1. Every step is a hash-map operation, so each call is O(1).

Dry run

  1. capacity 2: put(4, 40), put(5, 50) → buckets = {1: [4, 5]}, min_freq = 1
  2. get(4) → 4 moves up: {1: [5], 2: [4]}
  3. put(6, 60): full → victim = oldest of bucket min_freq = 1 → key 5. Insert 6 → {1: [6], 2: [4]}
  4. get(6) → bucket 1 empties and was the lowest, so min_freq = 2: {2: [4, 6]}
  5. put(7, 70): full → bucket 2 holds [4, 6] → the first, 4, is the victim → {2: [6], 1: [7]}, min_freq = 1

Python

class LFUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.min_freq = 0                          # lowest use count among stored keys
        self.entries = {}                          # key -> [value, uses]
        self.buckets = defaultdict(OrderedDict)    # uses -> keys with that count, oldest use first

    def _touch(self, key):                         # one more use: move the key up one bucket
        uses = self.entries[key][1]
        del self.buckets[uses][key]
        if not self.buckets[uses]:
            del self.buckets[uses]
            if self.min_freq == uses:              # the lowest bucket just emptied
                self.min_freq += 1
        self.entries[key][1] = uses + 1
        self.buckets[uses + 1][key] = None         # newest member of the next bucket

    def get(self, key: int) -> int:
        if key not in self.entries:
            return -1
        self._touch(key)
        return self.entries[key][0]

    def put(self, key: int, value: int) -> None:
        if self.capacity == 0:
            return
        if key in self.entries:                    # existing key: new value, and it counts as a use
            self.entries[key][0] = value
            self._touch(key)
            return
        if len(self.entries) == self.capacity:     # full: evict the oldest key of the lowest bucket
            victim, _ = self.buckets[self.min_freq].popitem(last=False)
            if not self.buckets[self.min_freq]:
                del self.buckets[self.min_freq]
            del self.entries[victim]
        self.entries[key] = [value, 1]
        self.buckets[1][key] = None
        self.min_freq = 1                          # a new key has one use: the new minimum
Time O(1) per callSpace O(capacity)

Each call does a constant number of dictionary operations; at most capacity keys are stored.

Common mistakes

  • Writing an LRU cache. LFU evicts the key with the lowest count first; recency only breaks ties among keys with the same count.
  • Not counting put on an existing key as a use. It must replace the value and move the key to the next count.
  • Forgetting min_freq = 1 after inserting a new key. The new key has one use, so it is the new minimum; skipping this makes the next eviction look in the wrong group.
  • Not raising min_freq when a get empties the lowest group. The next eviction then looks in a group that no longer exists.
  • Letting an evicted key keep its count. If it is inserted again later, it starts again at 1.
  • Capacity 0: put must return without doing anything. Otherwise it tries to evict from an empty cache.

Python notes

  • OrderedDict.popitem(last=False) removes and returns the oldest key in O(1). A key that joins a group is always its newest member, so move_to_end is not needed here.
  • defaultdict(OrderedDict) creates an empty group the first time you touch it. The code below deletes a group as soon as it becomes empty, which keeps min_freq honest.
  • Tuples compare element by element, so min(keys, key=lambda k: (uses[k], last_used[k])) picks the lowest count first and the oldest use second: exactly the LFU rule.
  • heapq is a min-heap on tuples for the same reason: (uses, stamp, key) pops the least used, oldest entry first.

Follow-up questions

What an interviewer might ask next, and what changes.

  • LRU Cache LC 146 — the simpler cousin: recency only, one doubly linked list. LFU needs one recency list per use count.
  • Maximum Frequency Stack LC 895 — the same bucket idea with a stack in each bucket: pop removes from the highest count, the most recent first.
  • All O`one Data Structure LC 432 — counts go up and down by one and you must report a key with the maximum and one with the minimum count in O(1): a doubly linked list of count buckets, not a dictionary.
  • Top K Frequent Elements LC 347 — group elements by count with bucket sort instead of a heap; the 'bucket per frequency' idea without any eviction.
  • Counts that fade over time — plain LFU never forgets: a key that was popular long ago can stay forever. Practical variants age the counts, for example by halving all of them every so often.
  • A heap instead of buckets — push a (uses, last_used, key) entry on every touch and skip stale entries when popping: O(log n) instead of O(1), but much simpler to get right.
