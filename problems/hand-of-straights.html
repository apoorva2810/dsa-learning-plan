Hand of Straights Medium

LeetCode #846 ↗
Status

Decide whether a hand of cards can be split into groups of a fixed size, each group made of consecutive values.

Problem

You hold a hand of cards: hand[i] is the number written on card i. You want to arrange all the cards into groups so that:

  • every group has exactly groupSize cards, and
  • the numbers in a group are consecutive (like 4, 5, 6).

Return True if this is possible, and False otherwise.

Examples

Example 1
Input: hand = [1, 2, 3, 6, 2, 3, 4, 7, 8], groupSize = 3
Output: true
Three groups: [1, 2, 3], [2, 3, 4] and [6, 7, 8].
Example 2
Input: hand = [1, 2, 3, 4, 5], groupSize = 4
Output: false
Five cards can never be split into groups of four.
Example 3
Input: hand = [1, 1, 2, 2, 3, 3], groupSize = 3
Output: true
Two copies of the group [1, 2, 3].
Example 4
Input: hand = [1, 2, 3, 4, 4, 5], groupSize = 3
Output: false
[1, 2, 3] leaves [4, 4, 5]. Both 4s would need a 5 and a 6, but there is one 5 and no 6.

Constraints

  • 1 <= len(hand) <= 10^4
  • 0 <= hand[i] <= 10^9
  • 1 <= groupSize <= len(hand)

Think first try before reading the solution

A quick check first: every group has exactly groupSize cards, so len(hand) must be a multiple of groupSize.
Look at the smallest card still in your hand. Nothing smaller is left, so it can only be the lowest card of its group. That makes the whole group forced: v, v + 1, ..., v + groupSize - 1.
Repeat: take the smallest remaining value v, remove one card each of v .. v + groupSize - 1, and fail if one is missing. Count the cards with a Counter and visit sorted(counter) in order. If v still has c copies, c groups start at v, so remove c of each value at once.

Key idea

In most problems you have to choose. Here the smallest card has no choice at all. Every valid arrangement has a group containing it, and since nothing smaller exists, that card is the bottom of the group, and the group must be v, v + 1, ..., v + groupSize - 1. So you can build the groups by following the only possible move, and the hand can be split exactly when that process never gets stuck. A greedy algorithm is correct when each step is forced.

Duplicates need one more thought. Suppose the smallest value still has c unused copies. Every one of those copies must be the bottom of its own group (nothing below is available to attach them to), so exactly c groups start at v. Take c cards of each value from v to v + groupSize - 1 in one go. If any of those values has fewer than c copies, the answer is False.

Count the cards in a dictionary value -> copies left, then walk the distinct values in increasing order. Sorting costs O(n log n) and everything after it is O(n), because each group you build consumes at least groupSize cards.

Approaches from the obvious one to the one you want in an interview

Sort the cards. The first card is the smallest, so it starts a group. Remove it together with the next groupSize - 1 consecutive values, one card each, and give up if one is missing. Repeat until the list is empty.

The logic is already the right one. What is slow is the bookkeeping: card in cards and cards.remove(card) both scan the list, and they run for every card, so the total is O(n²).

Dry run

  1. hand = [1, 2, 3, 6, 2, 3, 4, 7, 8], groupSize = 3 → sorted [1, 2, 2, 3, 3, 4, 6, 7, 8]
  2. smallest is 1: remove 1, 2, 3 → [2, 3, 4, 6, 7, 8]
  3. smallest is 2: remove 2, 3, 4 → [6, 7, 8]
  4. smallest is 6: remove 6, 7, 8 → [] → True

Python

class Solution:
    def isNStraightHand(self, hand: List[int], groupSize: int) -> bool:
        if len(hand) % groupSize:
            return False
        cards = sorted(hand)
        while cards:
            first = cards[0]                     # the smallest card must start a group
            for card in range(first, first + groupSize):
                if card not in cards:            # O(n) scan
                    return False
                cards.remove(card)               # O(n) removal of one copy
        return True
Time O(n²)Space O(n)

n card removals, each scanning a list of up to n cards.

When to use: To see the forced-choice idea without any extra data structure.

Count the copies of every value in a Counter, then visit the distinct values in increasing order. For the current value first:

  1. Let copies = count[first]. If it is 0, earlier groups used every copy; skip it.
  2. Otherwise exactly copies groups start here (nothing smaller is left to join). Each needs first .. first + groupSize - 1.
  3. For each of those values, if count[value] < copies, return False; otherwise subtract copies.

If every value gets through, all cards were used. Sorting the distinct values is the only O(n log n) step; the group-building work is O(n) in total, because every group you start consumes at least groupSize cards.

Dry run

  1. hand = [1, 2, 3, 6, 2, 3, 4, 7, 8], groupSize = 3 → counts {1: 1, 2: 2, 3: 2, 4: 1, 6: 1, 7: 1, 8: 1}
  2. first = 1 (1 copy): take one each of 1, 2, 3 → {1: 0, 2: 1, 3: 1, 4: 1, ...}
  3. first = 2 (1 copy): take one each of 2, 3, 4 → those drop to 0
  4. first = 3 and first = 4: no copies left, skip
  5. first = 6 (1 copy): take 6, 7, 8 → all 0; first = 7 and 8 are skipped → True

Python

class Solution:
    def isNStraightHand(self, hand: List[int], groupSize: int) -> bool:
        if len(hand) % groupSize:
            return False
        count = Counter(hand)                    # value -> copies not used yet
        for first in sorted(count):              # smallest value first
            copies = count[first]                # this many groups must START at `first`
            if copies == 0:
                continue                         # all used by groups that started earlier
            for value in range(first, first + groupSize):
                if count[value] < copies:        # not enough cards to extend every group
                    return False
                count[value] -= copies
        return True
Time O(n log n)Space O(n)

Sorting the distinct values dominates. The inner loops do at most n card-removals in total.

When to use: The standard answer. Explain why the smallest card's group is forced.

Watch it run

Same forced choice, but build one group at a time and let a min-heap hand you the smallest value that still has cards, instead of sorting once. Take one card of each value first .. first + groupSize - 1. When a value's count reaches 0, remove it from the heap, and it must be the smallest value in the heap. If it is not, a smaller value is stranded: its group would need the value that just ran out.

The heap is the right tool when cards can still arrive or the "smallest remaining" changes as you go. Here it gives the same O(n log n).

Dry run

  1. hand = [1, 2, 3, 4, 4, 5], groupSize = 3: counts {1: 1, 2: 1, 3: 1, 4: 2, 5: 1}, heap [1, 2, 3, 4, 5]
  2. first = 1: take 1, 2, 3; each hits 0 and is the heap minimum, so pop them → heap [4, 5]
  3. first = 4: take 4 (count 2 → 1), take 5 (count 1 → 0)
  4. 5 reached 0 but the heap minimum is 4, so a 4 is stranded: False

Python

class Solution:
    def isNStraightHand(self, hand: List[int], groupSize: int) -> bool:
        if len(hand) % groupSize:
            return False
        count = Counter(hand)
        heap = list(count)                       # the distinct values
        heapq.heapify(heap)
        while heap:
            first = heap[0]                      # smallest value that still has cards
            for card in range(first, first + groupSize):
                if count[card] == 0:             # missing, or already used up
                    return False
                count[card] -= 1
                if count[card] == 0:
                    # `card` is used up, so it must be the smallest value left;
                    # otherwise a smaller value is stranded without a way to continue
                    if card != heap[0]:
                        return False
                    heapq.heappop(heap)
        return True
Time O(n log n)Space O(n)

Each card is removed once; each distinct value is pushed and popped once (O(log n) each).

When to use: When the "smallest remaining" has to be maintained dynamically; otherwise the sorted-keys version is simpler.

Common mistakes

  • Starting a group from any card, such as the first one in the input, instead of the smallest remaining one. Only the smallest card's group is forced; starting elsewhere can leave a smaller card with nothing to attach to.
  • Checking that each value is present but not that enough copies exist. In [1, 1, 2, 3] with groupSize = 2 every value needed is there, yet the second 1 has no 2 left to pair with.
  • Using a list of counts indexed by value. Values go up to 10^9, so use a dictionary (Counter).
  • Changing the Counter while looping over it (for example deleting entries that reach 0). Loop over sorted(count), which is a separate list, or leave the zero counts in place.
  • Using list.remove in a loop. Each call scans the list, so the brute force is O(n²), which is slow near 10^4 cards.

Python notes

  • Counter(hand) counts every value. Reading count[v] for a missing value returns 0 without adding the key, so count[v] < copies is safe.
  • sorted(count) returns a new list of the distinct keys in increasing order, so you can change count while looping over it.
  • range(first, first + group_size) produces exactly the values one group needs.
  • For the heap version, heapq.heapify(list(count)) builds a min-heap of the distinct values, heap[0] peeks at the smallest and heapq.heappop(heap) removes it.
  • Values up to 10^9 are ordinary Python integers; nothing here can overflow.
