Evaluate Reverse Polish Notation Medium

LeetCode #150 ↗
Status

Compute the value of an arithmetic expression written with each operator after its two operands.

Problem

You are given a list of strings tokens that spells an arithmetic expression in Reverse Polish Notation (RPN, also called postfix): every operator comes after the two values it combines. 3 4 + means 3 + 4, and 2 1 + 3 * means (2 + 1) * 3. RPN needs no parentheses and no precedence rules.

Each token is either an integer (possibly negative, like "-11") or one of "+", "-", "*", "/". Return the value of the expression as an integer.

  • Division between two integers truncates toward zero: 7 / 2 is 3 and -7 / 2 is -3.
  • The expression is always valid, and there is never a division by zero.
  • Every intermediate value and the answer fit in a 32-bit integer.

Examples

Example 1
Input: tokens = ["2", "1", "+", "3", "*"]
Output: 9
(2 + 1) * 3 = 9.
Example 2
Input: tokens = ["4", "13", "5", "/", "+"]
Output: 6
4 + (13 / 5) = 4 + 2 = 6.
Example 3
Input: tokens = ["10", "6", "9", "3", "+", "-11", "*", "/", "*", "17", "+", "5", "+"]
Output: 22
10 * (6 / ((9 + 3) * -11)) + 17 + 5 = 10 * (6 / -132) + 22 = 10 * 0 + 22. Note 6 / -132 truncates to 0, not -1.

Constraints

  • 1 <= len(tokens) <= 10^4
  • tokens[i] is "+", "-", "*", "/" or an integer in [-200, 200]
  • the expression is valid and never divides by zero

Think first try before reading the solution

An operator always applies to the two values produced most recently that have not been used yet. Which data structure hands you the most recent item first?
Push numbers onto a stack. On an operator, pop two values, combine them, and push the result back: it is now an operand for a later operator.
Mind the order: the first value you pop is the right operand (a - b needs b popped first). And Python's // rounds down, not toward zero.

Key idea

Read the tokens left to right and keep the numbers that are still waiting for an operator. When an operator arrives, the two values it needs are the two most recent waiting ones; once combined, their result becomes a new waiting value. "Most recent first" is exactly what a stack gives you.

So: push every number; on an operator pop b (top) and then a, push a op b. Because each operator replaces two values by one, a valid expression leaves exactly one value on the stack at the end: the answer. Every token is handled once with O(1) work, so the whole evaluation is O(n).

Approaches from the obvious one to the one you want in an interview

In valid RPN, the first operator (from the left) always has two plain numbers immediately before it, because no operator has run yet. Replace those three tokens by their value and the list is still valid RPN, just shorter. Repeat until one number is left.

It is correct and mirrors how you might work it out on paper, but every round scans from the start and rebuilds the list. With n tokens there are about n/2 operators, so the cost is O(n²).

Dry run

  1. ["2", "1", "+", "3", "*"]: the first operator is + at index 2 → 2 + 1 = 3 → ["3", "3", "*"]
  2. ["3", "3", "*"]: the first operator is * at index 2 → 3 * 3 = 9 → ["9"]
  3. one token left → 9

Python

class Solution:
    def evalRPN(self, tokens: List[str]) -> int:
        ops = {"+", "-", "*", "/"}
        items = list(tokens)                        # work on a copy: we rewrite it
        while len(items) > 1:
            # the first operator always has two plain numbers right before it
            i = next(k for k, tok in enumerate(items) if tok in ops)
            a, b = int(items[i - 2]), int(items[i - 1])
            op = items[i]
            if op == "+":
                value = a + b
            elif op == "-":
                value = a - b
            elif op == "*":
                value = a * b
            else:
                value = int(a / b)                  # truncate toward zero
            items[i - 2:i + 1] = [str(value)]       # replace "a b op" by its value
        return int(items[0])
Time O(n²)Space O(n)

Up to n/2 rounds; each scans from the left and splices the list, both O(n).

When to use: Only to see why RPN is unambiguous; the stack version does the same work without rescanning.

Watch it run

Keep a stack of values that are waiting for an operator.

  1. Number → push int(tok).
  2. Operator → pop b (the right operand, pushed last), pop a, push a op b.
  3. At the end the stack holds exactly one value: the answer.

The stack is the "scan from the left for the first operator" of the brute force, done incrementally: the two numbers before an operator are always the top two of the stack, so nothing is ever rescanned.

Dry run

  1. ["4", "13", "5", "/", "+"], stack []
  2. 4, 13, 5 → push each → [4, 13, 5]
  3. / → pop b = 5, pop a = 13 → int(13 / 5) = 2 → [4, 2]
  4. + → pop b = 2, pop a = 4 → 6 → [6]
  5. end → return 6

Python

class Solution:
    def evalRPN(self, tokens: List[str]) -> int:
        stack = []
        for tok in tokens:
            if tok in {"+", "-", "*", "/"}:
                b = stack.pop()                 # right operand: it was pushed last
                a = stack.pop()                 # left operand
                if tok == "+":
                    stack.append(a + b)
                elif tok == "-":
                    stack.append(a - b)
                elif tok == "*":
                    stack.append(a * b)
                else:
                    stack.append(int(a / b))    # truncate toward zero, not floor
            else:
                stack.append(int(tok))          # int() also parses negatives like "-11"
        return stack[0]
Time O(n)Space O(n)

One pass with O(1) work per token; the stack holds at most about n/2 numbers.

When to use: Always. This is the standard answer.

Watch it run

RPN is a postorder listing of an expression tree: left subtree, right subtree, then the operator. So the last token is the root. Read from the end: an operator first evaluates its right operand (the tokens just before it), then its left operand (the tokens before those), then combines them. A number is a leaf.

Same O(n) time, but the stack is now Python's call stack. A long chain like 1 2 + 3 + 4 + … nests about n/2 calls deep, past Python's default limit of 1000 frames, which is why the explicit stack is preferred.

Python

class Solution:
    def evalRPN(self, tokens: List[str]) -> int:
        pos = len(tokens) - 1                   # next token to read, moving right to left

        def evaluate() -> int:
            nonlocal pos
            tok = tokens[pos]
            pos -= 1
            if tok not in {"+", "-", "*", "/"}:
                return int(tok)                 # a number is a leaf
            right = evaluate()                  # the right operand ends just before the operator
            left = evaluate()
            if tok == "+":
                return left + right
            if tok == "-":
                return left - right
            if tok == "*":
                return left * right
            return int(left / right)

        return evaluate()
Time O(n)Space O(n)

Each token is read once; the recursion is as deep as the expression tree.

When to use: To show the link between RPN and trees; prefer the explicit stack for long inputs.

Common mistakes

  • Swapping the operands: the first pop is the right operand. ["5", "3", "-"] is 5 - 3 = 2, not -2; the same applies to /.
  • Using a // b: Python's floor division rounds toward minus infinity, so -7 // 2 == -4 and 6 // -132 == -1. The problem wants truncation toward zero: int(a / b) gives -3 and 0.
  • Detecting numbers with tok.isdigit(): it is False for "-11", so negative numbers get treated as operators. Test whether the token is one of the four operators instead.
  • Pushing the tokens as strings: "2" + "1" is "21". Convert with int(tok) when you push.

Python notes

  • int("-11") parses negative numbers, so one int(tok) covers every operand.
  • int(a / b) truncates toward zero. Float division is exact enough here (doubles hold every integer below 2^53 exactly); for arbitrarily large integers use only integer arithmetic: q = abs(a) // abs(b), then -q if the signs differ.
  • b, a = stack.pop(), stack.pop() evaluates left to right, so b gets the top. Writing two lines is clearer.
  • A dispatch table removes the if/elif chain: ops = {"+": operator.add, "-": operator.sub, "*": operator.mul, "/": lambda a, b: int(a / b)} (needs import operator).

Follow-up questions

What an interviewer might ask next, and what changes.

  • Basic Calculator II LC 227 — the usual infix form with * / binding tighter than + -, no parentheses: push signed terms and apply *// to the top of the stack immediately; the answer is the sum of the stack.
  • Basic Calculator LC 224 — infix with + - and parentheses: on ( push the running result and sign, on ) pop them and combine.
  • Basic Calculator III LC 772 — precedence and parentheses: recursion on each parenthesised group, or convert to RPN first and reuse this solution.
  • Convert infix to RPN (the shunting-yard algorithm) — a second stack holds operators; pop operators of higher or equal precedence before pushing a new one. The output is exactly the token list this problem evaluates.
  • Design an Expression Tree With Evaluate Function LC 1628 — push tree nodes instead of numbers: an operator pops two subtrees and pushes a new node. Evaluating the tree is a postorder traversal, which is what RPN is.
