Subtree of Another Tree Easy

LeetCode #572 ↗
Status

Decide whether one binary tree appears, in full, somewhere inside another.

Problem

Given the roots of two binary trees, root and subRoot, return True if some node of root has a subtree that is identical to subRoot (same shape, same values), and False otherwise.

A subtree of root is one node of root together with all of its descendants. root itself counts as a subtree of itself.

Examples

Example 1
Input: root = [3, 4, 5, 1, 2], subRoot = [4, 1, 2]
Output: true
The subtree that starts at node 4 is 4 with children 1 and 2, exactly subRoot.
Example 2
Input: root = [3, 4, 5, 1, 2, None, None, None, None, 0], subRoot = [4, 1, 2]
Output: false
The subtree at node 4 has an extra descendant, 0 (the left child of 2), so it is bigger than subRoot.
Example 3
Input: root = [1, 1], subRoot = [1]
Output: true
The left child of the root is a leaf holding 1, which is identical to subRoot. The root itself is not, because it has a child.

Constraints

  • 1 <= number of nodes in root <= 2000
  • 1 <= number of nodes in subRoot <= 1000
  • -10^4 <= root.val, subRoot.val <= 10^4

Think first try before reading the solution

If subRoot appears in root, it appears at one particular node of root. How many candidate nodes are there, and how can you test one candidate? Two trees being identical is exactly the Same Tree problem.
Visit every node of root. At each one ask: 'is the tree that starts here identical to subRoot?' using a Same Tree check. If the answer is yes anywhere, return True.
The comparison must cover the whole subtree: a node of root with extra descendants is not a match (see example 2). For a faster approach, turn both trees into text that records every missing child, and test whether one text occurs inside the other.

Key idea

Split the problem in two. Part 1: can I tell whether two specific trees are identical? That is Same Tree. Part 2: where could a match start? Only at a node of root, so try them all. subRoot is inside root if the tree at root itself matches, or it is inside the left subtree, or it is inside the right subtree.

Most Same Tree checks fail at the very first node (the values differ), so they are cheap. The worst case is a tree full of equal values, where a check can walk all m nodes of subRoot and there are n candidates: O(n · m).

For linear time, flatten each tree into text with a preorder walk, writing # for every missing child and a comma around every token. A subtree of root is a contiguous run in that text, so the question becomes "does one text occur inside the other?", which a substring search answers.

Approaches from the obvious one to the one you want in an interview

Turn the definition into code. A match must start at some node of root, so check the nodes one by one. At each node run a Same Tree comparison between the tree that starts there and subRoot. If any comparison succeeds, return True; if not, the match, if there is one, starts lower down on the left or on the right.

Most comparisons stop at the first node because the values differ. The worst case is a tree full of equal values, where each of the n candidates can walk up to m nodes: O(n · m). With at most 2000 and 1000 nodes that is fast enough, and this is the answer most interviewers expect first.

Dry run

  1. root = [3, 4, 5, 1, 2], subRoot = [4, 1, 2]
  2. Try node 3: its value 3 ≠ 4, so the comparison fails at once.
  3. Try node 4: 4 = 4, then the children 1 and 2 match subRoot's children, and no node has children left on either side → identical → True.
  4. With the extra node 0 under 2, node 4 fails at 2's left child (root has 0, subRoot has nothing). Nodes 1, 2, 0 and 5 are then tried and each has a value other than 4 → False.

Python

class Solution:
    def isSubtree(self, root: Optional[TreeNode], subRoot: Optional[TreeNode]) -> bool:
        def is_same(a, b):
            if a is None and b is None:                  # both empty: match
                return True
            if a is None or b is None or a.val != b.val:
                return False                             # shape or value differs
            return is_same(a.left, b.left) and is_same(a.right, b.right)

        if subRoot is None:                              # the empty tree is inside every tree
            return True                                  # (cannot happen under the official limits)
        if root is None:                                 # ran out of nodes without a match
            return False
        if is_same(root, subRoot):                       # does the tree that starts here equal subRoot?
            return True
        # otherwise the match, if there is one, starts lower on the left or the right
        return self.isSubtree(root.left, subRoot) or self.isSubtree(root.right, subRoot)
Time O(n · m)Space O(h)

n candidate nodes, each comparison walks at most m = size of subRoot nodes. The call stack is at most the height of root plus the height of subRoot.

When to use: The default first answer: short, easy to get right, and fast enough for these limits.

Watch it run

Flatten both trees with the same preorder walk (node, then left subtree, then right subtree), then ask whether the text of subRoot occurs inside the text of root.

For that to be a trustworthy test, the text must identify a tree uniquely and a match must line up with whole nodes:

  • write # for every missing child, so the shape is recorded (otherwise [1, 2] and [1, None, 2] look the same);
  • put a comma before and after every token, so 2 cannot match the end of 12.

In a preorder walk a subtree is a contiguous run of tokens, and because of the # markers a run can only read like a complete tree if it really is one. So subRoot is a subtree of root exactly when its text occurs inside root's text.

Dry run

  1. subRoot = [4, 1, 2] → tokens 4, 1, #, #, 2, #, # → text ,4,1,#,#,2,#,#,
  2. root = [3, 4, 5, 1, 2] → tokens 3, 4, 1, #, #, 2, #, #, 5, #, # → text ,3,4,1,#,#,2,#,#,5,#,#,
  3. The first text occurs inside the second, starting at token 1 → True.
  4. With the extra node 0, root's tokens are 3, 4, 1, #, #, 2, 0, #, #, #, 5, #, #. After 4, 1, #, #, 2 root has 0 where subRoot needs # → no match anywhere → False.

Python

class Solution:
    def isSubtree(self, root: Optional[TreeNode], subRoot: Optional[TreeNode]) -> bool:
        def serialize(node, tokens):
            if node is None:
                tokens.append("#")                 # marker: this child is missing
                return
            tokens.append(str(node.val))           # preorder: node, left subtree, right subtree
            serialize(node.left, tokens)
            serialize(node.right, tokens)

        root_tokens, sub_tokens = [], []
        serialize(root, root_tokens)
        serialize(subRoot, sub_tokens)
        # commas on both ends make a match start and end on a whole token ("2" cannot match inside "12")
        root_text = "," + ",".join(root_tokens) + ","
        sub_text = "," + ",".join(sub_tokens) + ","
        return sub_text in root_text
Time O(n + m)Space O(n + m)

Building the two texts is linear. The substring test is linear on average, and CPython 3.10+ also guarantees it for long patterns; KMP would guarantee it everywhere.

When to use: When asked for linear time. Mention the separator and # pitfalls, since they are the usual bugs.

Common mistakes

  • Stopping the comparison when subRoot runs out. If you treat 'subRoot is None' as a match, a node of root with extra descendants (example 2) is wrongly accepted. A subtree has to match completely: is_same(node, None) is False unless the node is None too.
  • Flattening without markers for missing children. [1, 2] and [1, None, 2] both flatten to 1, 2, so different trees look equal.
  • Flattening without a separator around the values. Joined with nothing, the text for a node 12 contains the text for a node 2, so [12] seems to hold [2]. Put a comma before and after every token.
  • Reading .val on None. In the outer recursion test root is None first, and in the comparison test the None cases before the values.
  • Combining the two outer recursive calls with and. The match can be on either side, so they are joined with or.

Python notes

  • sub_text in root_text is Python's substring test. It is linear on average, and since Python 3.10 CPython also switches to a linear-time algorithm for long patterns. If a guaranteed bound is wanted on any version, name KMP.
  • ",".join(tokens) builds the whole string in one pass. Returning concatenated strings from the recursion (a + serialize(left) + ...) would copy the growing text at every level, which is O(n²) on a chain.
  • str(node.val) keeps the minus sign of negative values; that is harmless because commas separate the tokens.
  • or returns its first truthy operand. Here every operand is a boolean, so the method returns a real bool.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Same Tree LC 100 — the building block: this problem is 'Same Tree at every node'.
  • Find Duplicate Subtrees LC 652 — flatten every subtree to text, as in the string approach, and use a dictionary from text to count to spot subtrees that occur twice.
  • Linked List in Binary Tree LC 1367 — the same two-level shape: try every tree node as a start, then match a linked list downward along one root-to-leaf direction.
  • Many different subRoots against one big tree — flatten (or assign an id to) every subtree of root once and keep the results in a set; each query then costs only O(m) to flatten and one lookup.
