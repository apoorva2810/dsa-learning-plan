Longest Increasing Path in a Matrix Hard

LeetCode #329 ↗
Status

Find the longest chain of strictly growing values you can walk through in a grid, moving up, down, left or right.

Problem

You are given a grid of integers matrix with m rows and n columns. Return the length of the longest strictly increasing path in it.

  • From a cell you can move up, down, left or right to a neighbouring cell. Diagonal moves and leaving the grid are not allowed.
  • Every move must go to a cell with a strictly larger value than the cell you are leaving.
  • A path may start at any cell. Its length is the number of cells on it, so a single cell is a path of length 1.

Examples

Example 1
Input: matrix = [[9, 9, 4], [6, 6, 8], [2, 1, 1]]
Output: 4
The path 1 → 2 → 6 → 9 starts at the 1 in the bottom middle, steps left to the 2, then goes up the left column through the 6 to the 9.
Example 2
Input: matrix = [[3, 4, 5], [3, 2, 6], [2, 2, 1]]
Output: 4
The path 3 → 4 → 5 → 6 runs along the top row and then down the right column.
Example 3
Input: matrix = [[7, 7], [7, 7]]
Output: 1
Equal values do not count as an increase, so no move is ever possible.

Constraints

  • 1 <= m, n <= 200
  • 0 <= matrix[i][j] <= 2^31 - 1

Think first try before reading the solution

Fix a starting cell. A path can continue only to a neighbour with a larger value. What is the longest path that starts at that neighbour, and does it depend on how you reached it?
Because every move goes strictly uphill, a path can never return to a cell, so no visited set is needed. The longest path starting at a cell is a fixed number: 1 + max(longest path from each larger neighbour), or just 1 when no neighbour is larger.
Many starting cells run into the same cells, so solving a cell once and storing the result removes the repeated work: DFS with a memo table, then take the maximum over all cells. The other option is to process cells from the largest value down, so the larger neighbours are already finished.

Key idea

Draw an arrow from every cell to each neighbour with a strictly larger value. Every arrow points uphill, so following arrows can never bring you back to a cell you have already left: the picture has no cycles. A set of arrows with no cycles is called a DAG (directed acyclic graph). Two things follow.

First, you never need a visited set. Second, the longest path that starts at a given cell is one fixed number, however you arrived there:

longest(r, c) = 1 + max(longest(neighbour) for each larger neighbour), and 1 when no neighbour is larger.

The answer is the largest longest(r, c) over all cells. Computed naively, a cell that many routes lead into is solved again for every route, and the number of routes can grow exponentially with the number of cells. Storing each result the first time it is computed (memoisation) solves every cell once: m·n cells with at most 4 neighbours each, so O(m·n).

The dependencies also allow a table without recursion. A cell depends only on larger cells, so if you process cells from the largest value to the smallest, every neighbour a cell needs is already final when its turn comes.

Approaches from the obvious one to the one you want in an interview

Treat every cell as a possible start. From a cell, try each strictly larger neighbour and keep the best: 1 + dfs(neighbour). No visited set is needed, because values strictly increase and a path cannot repeat a cell.

It is correct, but a cell that many routes lead into is explored again for every route. The number of increasing paths can grow exponentially with the number of cells. On an 8 × 8 'snake' (the numbers 0 to 63 laid out in a zig-zag, so a long path winds through every cell) this DFS makes 7,660,540 calls for 64 cells. Each call recomputes an answer that depends only on the cell.

Dry run

  1. matrix = [[3, 4, 5], [3, 2, 6], [2, 2, 1]]
  2. dfs(0, 0) (value 3): larger neighbour (0, 1) = 4 → dfs(0, 1) → (0, 2) = 5 → dfs(0, 2) → (1, 2) = 6 → dfs(1, 2) has no larger neighbour → 1.
  3. Unwinding: dfs(0, 2) = 2, dfs(0, 1) = 3, dfs(0, 0) = 4.
  4. Later dfs(1, 1) (value 2) has larger neighbours (0, 1), (1, 0) and (1, 2). It walks (0, 1) → (0, 2) → (1, 2) all over again, the same three calls as before.
  5. In total this tiny matrix costs 23 calls for 9 cells.

Python

class Solution:
    def longestIncreasingPath(self, matrix: List[List[int]]) -> int:
        rows, cols = len(matrix), len(matrix[0])

        def dfs(r: int, c: int) -> int:
            """Length of the longest increasing path that starts at (r, c)."""
            best = 1                                           # the cell itself
            for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and matrix[nr][nc] > matrix[r][c]:
                    best = max(best, 1 + dfs(nr, nc))          # strictly larger only: no cycles, no visited set
            return best

        return max(dfs(r, c) for r in range(rows) for c in range(cols))
Time Exponential in m·nSpace O(m·n)

The number of increasing paths can grow exponentially with the number of cells. The recursion is at most m·n frames deep (the length of the longest path).

When to use: Only to see the waste. Never submit it: a 6 × 6 snake already takes 46,101 calls.

The longest path starting at a cell is the same number no matter how you got there, so compute it once and store it. memo[r][c] holds that number, with 0 meaning "not computed yet" (a real answer is always at least 1).

longest_from(r, c) returns the stored value if there is one. Otherwise it takes 1 + longest_from(neighbour) over the strictly larger neighbours (or 1 if there are none), stores it and returns it. The answer is the maximum over all start cells. Each cell is solved once, with at most 4 neighbour checks, so the total work is O(m·n). Later starts that run into an already solved cell stop right there.

Dry run

  1. matrix = [[3, 4, 5], [3, 2, 6], [2, 2, 1]], memo all 0
  2. Start (0, 0): chain (0, 1) → (0, 2) → (1, 2). memo[1][2] = 1, then memo[0][2] = 2, memo[0][1] = 3, memo[0][0] = 4.
  3. Starts (0, 1) and (0, 2) are already filled. (1, 0) = 3 has no larger neighbour → 1.
  4. (1, 1) = 2: larger neighbours (0, 1) → 3, (1, 0) → 1, (1, 2) → 1, all stored → memo[1][1] = 1 + 3 = 4, with no new recursion.
  5. The rest are quick: memo = [[4, 3, 2], [1, 4, 1], [2, 1, 2]], so the answer is 4.

Python

class Solution:
    def longestIncreasingPath(self, matrix: List[List[int]]) -> int:
        rows, cols = len(matrix), len(matrix[0])
        memo = [[0] * cols for _ in range(rows)]               # memo[r][c]: longest path starting at (r, c); 0 = unknown

        def longest_from(r: int, c: int) -> int:
            if memo[r][c]:                                     # solved before: reuse it
                return memo[r][c]
            best = 1                                           # the cell itself
            for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and matrix[nr][nc] > matrix[r][c]:
                    best = max(best, 1 + longest_from(nr, nc))
            memo[r][c] = best                                  # store before returning
            return best

        return max(longest_from(r, c) for r in range(rows) for c in range(cols))
Time O(m·n)Space O(m·n)

Each cell is computed once with at most 4 neighbour checks. The memo holds m·n numbers, and the recursion can be as deep as the longest path.

When to use: The interview answer. Mention the recursion-depth limit and offer the bottom-up version if asked.

Watch it run

The recursion order is forced by one rule: a cell needs the answers of its larger neighbours. So sort all cells by value, largest first, and fill the table in that order. When a cell's turn comes, every larger neighbour has already been processed and its longest value is final: longest[r][c] = 1 + max(longest[neighbour]) over the larger neighbours, or 1. Keep the maximum seen.

No recursion means no recursion-depth limit, which matters for a 200 × 200 matrix. The cost is the sort, O(m·n · log(m·n)). A topological sort (peeling off cells that have no smaller neighbour, layer by layer) gets rid of the log factor, but the sorted order is shorter to write.

Dry run

  1. matrix = [[3, 4, 5], [3, 2, 6], [2, 2, 1]], cells by value: 6, 5, 4, 3, 3, 2, 2, 2, 1
  2. 6 at (1, 2): no larger neighbour → 1. 5 at (0, 2): larger neighbour 6 (final: 1) → 2. 4 at (0, 1): neighbour 5 → 3.
  3. The two 3s: (0, 0) has the larger neighbour 4 → 4, while (1, 0) has no larger neighbour → 1.
  4. 2 at (1, 1): larger neighbours 4, 3, 6 with lengths 3, 1, 1 → 4. The other 2s and the 1 get 1 (at (2, 1)), 2 (at (2, 0)) and 2 (at (2, 2)).
  5. Maximum = 4.

Python

class Solution:
    def longestIncreasingPath(self, matrix: List[List[int]]) -> int:
        rows, cols = len(matrix), len(matrix[0])
        # largest value first, so every strictly larger neighbour is processed before the cell itself
        cells = sorted(((matrix[r][c], r, c) for r in range(rows) for c in range(cols)), reverse=True)
        longest = [[1] * cols for _ in range(rows)]            # longest[r][c]: longest path starting at (r, c)
        best = 1
        for value, r, c in cells:
            for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and matrix[nr][nc] > value:
                    longest[r][c] = max(longest[r][c], 1 + longest[nr][nc])   # that neighbour is already final
            best = max(best, longest[r][c])
        return best
Time O(m·n·log(m·n))Space O(m·n)

Sorting m·n cells dominates; the table fill itself is O(m·n) with 4 neighbour checks per cell.

When to use: When recursion depth is a worry (Python's default limit is 1000 frames), or to show the DAG order explicitly.

Common mistakes

  • Copying the visited set from Number of Islands. It is never needed here, because a strictly increasing path cannot revisit a cell. Worse, a shared set that is never cleared blocks the second route into a cell and makes the answer too small.
  • Writing >= instead of >. Equal neighbours let the arrows form cycles, the DFS keeps bouncing between two equal cells, and the recursion never ends (RecursionError). The strict comparison is what makes the memo valid.
  • Passing the current path length down the recursion, dfs(r, c, length), and caching on (r, c) alone. A cached value must not depend on how you arrived. Cache 'the longest path starting here', which is the same for every route.
  • Returning memo[0][0] or the result of the first DFS. The best path can start anywhere; take the maximum over every cell.
  • Recursion depth. A 200 × 200 matrix can hold one increasing path through all 40,000 cells, far past Python's default limit of 1000 frames. Raise the limit with sys.setrecursionlimit, or use the bottom-up version (approach 3), which has no recursion.

Python notes

  • DIRS = ((-1, 0), (1, 0), (0, -1), (0, 1)) with for dr, dc in DIRS: is the standard way to visit the four neighbours of a cell.
  • 0 <= nr < rows and 0 <= nc < cols is a chained comparison: it reads like the maths and keeps the bounds check short.
  • The memo uses 0 for "not computed yet". That is safe because every real answer is at least 1, so if memo[r][c]: means "already solved".
  • @cache on longest_from(r, c) replaces the explicit memo table. The explicit table is easier to print and to draw.
  • Python's default recursion limit is 1000 frames; a 200 × 200 matrix can chain through 40,000 cells. The bottom-up version never recurses.
  • sorted(((value, r, c) ...), reverse=True) orders the tuples by value first; ties fall back to the coordinates, which is harmless because equal cells never read each other.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Number of Increasing Paths in a Grid LC 2328 — count all strictly increasing paths (length 1 or more) modulo 10^9 + 7: the same memo, but each cell stores 1 + sum(...) over its larger neighbours instead of 1 + max(...), and the answer is the sum over all cells.
  • Longest Increasing Subsequence LC 300 — the same 'longest chain of growing values' on a line: longest(i) looks at every earlier smaller value instead of four neighbours.
  • Course Schedule II LC 210 — the uphill arrows form a DAG, and a topological sort (Kahn's algorithm) handles a DAG in general. Peeling this grid layer by layer gives the answer as the number of layers, in O(m·n) without a sort.
  • Maximum Number of Moves in a Grid LC 2684 — moves go only one column to the right (up-right, right or down-right) onto a strictly larger value: the same recurrence, and the fixed direction lets you fill the table column by column from the right.
  • Print one longest path, not just its length — after filling the memo, start at a cell holding the maximum and repeatedly step to a larger neighbour whose memo is exactly one less.
  • What if equal values were allowed (non-decreasing paths)? — plateaus of equal cells create cycles, so the answer is no longer one fixed number per cell. Walking through a plateau without repeating a cell is a longest-simple-path search, which has no known efficient algorithm in general. The strict > is what keeps this problem easy.
