Redundant Connection Medium

LeetCode #684 ↗
Status

A tree got one extra edge; find the edge to delete so it becomes a tree again.

Problem

Start with a tree on n nodes labelled 1 to n (connected, no cycles). One extra edge is added between two different nodes that were not already directly joined. You receive the resulting n undirected edges as edges, where edges[i] = [a, b].

Return an edge that can be removed so that the remaining n - 1 edges form a tree on all n nodes. If more than one edge would work, return the one that appears last in edges.

Examples

Example 1
Input: edges = [[1, 2], [1, 3], [2, 3]]
Output: [2, 3]
The three edges form a triangle. Removing any of them leaves a tree; [2, 3] comes last.
Example 2
Input: edges = [[1, 2], [2, 3], [3, 4], [1, 4], [1, 5]]
Output: [1, 4]
The loop is 1–2–3–4–1. Of its four edges, [1, 4] appears last in the list.

Constraints

  • n == len(edges)
  • 3 <= n <= 1000
  • edges[i] = [a, b] with 1 <= a < b <= n
  • no repeated edges, and the graph is connected

Think first try before reading the solution

A tree plus one edge contains exactly one cycle. Which edges can you remove and still have a tree?
Only edges on that cycle. Now add the edges one by one in the given order: at which moment does the cycle first exist, and which edge completes it?
The first edge whose two ends are already connected is the answer, and it is automatically the cycle edge that appears last. Union-find answers 'already connected?' in near O(1).

Key idea

Adding one edge to a tree creates exactly one cycle. Removing any edge on that cycle gives a tree back; removing any other edge cuts the graph in two. So the candidates are the cycle edges, and the tie-break asks for the one that appears last.

Now replay the edges in input order. Before the last cycle edge arrives, the cycle edges seen so far form an open path, so nothing has closed yet. The moment that last cycle edge arrives, its two ends are already connected by the rest of the cycle. So the first edge that joins two already-connected nodes is exactly the answer.

Union-find keeps every node pointing towards a root that names its group, which turns "already connected?" into "same root?". One pass over the edges with near-constant work per edge solves it.

Approaches from the obvious one to the one you want in an interview

Rebuild the graph one edge at a time, in input order. Before adding a–b, run a DFS from a over the edges added so far. If it reaches b, the two were already connected and this edge closes the cycle: return it. Because the edges are processed in order, the first such edge is the cycle edge that appears last, exactly what is asked.

The weakness is the repeated search: each of the n edges may trigger a DFS over up to n nodes, O(n²) overall.

Dry run

  1. edges = [[1, 2], [2, 3], [3, 4], [1, 4], [1, 5]]
  2. 1–2: no path from 1 to 2 yet → add. 2–3 → add. 3–4 → add.
  3. 1–4: DFS from 1 finds 1 → 2 → 3 → 4 → already connected → return [1, 4]

Python

class Solution:
    def findRedundantConnection(self, edges: List[List[int]]) -> List[int]:
        graph = defaultdict(list)

        def has_path(src: int, dst: int) -> bool:  # DFS over the edges added so far
            seen = {src}
            stack = [src]
            while stack:
                node = stack.pop()
                if node == dst:
                    return True
                for nxt in graph[node]:
                    if nxt not in seen:
                        seen.add(nxt)
                        stack.append(nxt)
            return False

        for a, b in edges:
            if has_path(a, b):                     # a and b already connected: a-b closes the cycle
                return [a, b]
            graph[a].append(b)
            graph[b].append(a)
        return []
Time O(n²)Space O(n)

Up to n searches, each over a graph of up to n nodes and n edges.

When to use: Fine for n ≤ 1000, and a good way to explain the idea before introducing union-find.

Same replay in input order, but replace the search with union-find. Each node has a parent pointer, and following pointers from any node ends at its group's root.

  • find(a) == find(b): a and b are already connected, so [a, b] closes the cycle. Return it.
  • Otherwise merge the groups by pointing one root at the other.

Path halving and union by size keep the pointer chains very short, so each check costs amortised O(α(n)), which is constant for every practical purpose. Nodes are labelled from 1, so the arrays get n + 1 slots.

Dry run

  1. edges = [[1, 2], [1, 3], [2, 3]], parent = [0, 1, 2, 3] (slot 0 unused)
  2. 1–2: roots 1 and 2 differ → parent[2] = 1
  3. 1–3: roots 1 and 3 differ → parent[3] = 1
  4. 2–3: find(2) = 1 = find(3) → already connected → return [2, 3]

Python

class Solution:
    def findRedundantConnection(self, edges: List[List[int]]) -> List[int]:
        n = len(edges)                             # n nodes labelled 1..n
        parent = list(range(n + 1))                # slot 0 is unused
        size = [1] * (n + 1)

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]      # path halving
                x = parent[x]
            return x

        for a, b in edges:
            root_a, root_b = find(a), find(b)
            if root_a == root_b:                   # already connected: this edge closes the cycle
                return [a, b]
            if size[root_a] < size[root_b]:
                root_a, root_b = root_b, root_a
            parent[root_b] = root_a                # merge the two groups
            size[root_a] += size[root_b]
        return []
Time O(n · α(n))Space O(n)

One near-constant find/union per edge; α is the inverse Ackermann function.

When to use: The expected answer: short, fast, and the input order handles the tie-break for you.

Watch it run

Find the cycle itself. A leaf (a node with exactly one edge) can never be on the cycle, so remove it; that can turn its neighbour into a new leaf. Keep peeling with a queue (the same idea as Kahn's algorithm, using degrees instead of in-degrees) until no leaves remain. The nodes still standing are exactly the cycle.

Then walk edges from the back and return the first edge whose two ends both survived. Since the graph has a single cycle, an edge between two surviving nodes must be a cycle edge. Linear time and no union-find, at the price of a second pass and an adjacency list.

Dry run

  1. edges = [[1, 2], [2, 3], [3, 4], [1, 4], [1, 5]] → degrees {1: 3, 2: 2, 3: 2, 4: 2, 5: 1}
  2. Peel leaf 5 → degree of 1 drops to 2. No node has degree 1 any more → survivors {1, 2, 3, 4}
  3. From the back: [1, 5] (5 was peeled) → skip; [1, 4] (both survived) → return [1, 4]

Python

class Solution:
    def findRedundantConnection(self, edges: List[List[int]]) -> List[int]:
        n = len(edges)
        graph = defaultdict(list)
        degree = [0] * (n + 1)
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)
            degree[a] += 1
            degree[b] += 1
        leaves = deque(v for v in range(1, n + 1) if degree[v] == 1)
        while leaves:                              # strip everything that hangs off the cycle
            leaf = leaves.popleft()
            degree[leaf] = 0                       # removed
            for nxt in graph[leaf]:
                if degree[nxt] > 0:
                    degree[nxt] -= 1
                    if degree[nxt] == 1:           # nxt has just become a leaf
                        leaves.append(nxt)
        for a, b in reversed(edges):               # the cycle edge that appears last
            if degree[a] > 0 and degree[b] > 0:
                return [a, b]
        return []
Time O(n)Space O(n)

Every node is peeled at most once and every edge is read a constant number of times.

When to use: When you need the whole cycle (for example, to list every removable edge), not only one edge.

Common mistakes

  • Sizing parent as n when nodes are numbered 1..n: node n is then out of range. Allocate n + 1 slots and ignore index 0.
  • Finding the cycle with a DFS and returning the first cycle edge it meets. The question wants the cycle edge that appears last in the input; with union-find in input order that comes for free, with DFS you must compare positions.
  • Comparing parent[a] == parent[b]. Nodes in the same group can have different direct parents; compare find(a) and find(b).
  • A recursive find without path compression can follow a chain of 1000 nodes and hit Python's recursion limit. Use the iterative version with path halving.

Python notes

  • parent = list(range(n + 1)) gives 1-based labels their own slot; index 0 is never used.
  • for a, b in edges: processes the edges in input order, which is what makes the "last one wins" tie-break automatic.
  • for a, b in reversed(edges): scans from the end without copying the list.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Redundant Connection II LC 685 — edges are directed and the tree is rooted. Now a node can end up with two parents, so there are two candidate edges to test, plus the plain-cycle case handled by this problem's union-find.
  • Graph Valid Tree LC 261 — the same 'no edge may join two connected nodes' check, but you answer yes/no and must also verify connectivity.
  • Number of Connected Components in an Undirected Graph LC 323 — the same union-find; count successful merges instead of stopping at the first failure.
  • Min Cost to Connect All Points LC 1584 — Kruskal's algorithm sorts the edges by cost and keeps each one unless it fails exactly this 'already connected' test.
  • Satisfiability of Equality Equations LC 990 — union the letters of every a==b, then any a!=b whose letters share a root is a contradiction.
  • What if you must list every edge whose removal leaves a tree? — that is the whole cycle: repeatedly strip leaves (degree-1 nodes) and every edge left between two remaining nodes is on it.
