Count Good Nodes in Binary Tree Medium

LeetCode #1448 ↗
Status

Count the nodes that are at least as large as every node above them on the path from the root.

Problem

You are given the root of a binary tree. Call a node good if no node on the path from the root down to it (its ancestors) has a value greater than the node's own value.

Return how many good nodes the tree has.

  • The root is always good: nothing is above it.
  • A tie does not spoil a node: a node equal to the largest value above it is still good.

Examples

Example 1
Input: root = [3, 1, 4, 3, null, 1, 5]
Output: 4
Good: the root 3, the 4 (path 3 → 4), the 5 (3 → 4 → 5) and the lower-left 3 (3 → 1 → 3). Neither 1 is good: the root 3 sits above it.
Example 2
Input: root = [3, 3, null, 4, 2]
Output: 3
The bottom 2 is not good because the 3s above it are larger. The second 3 ties the root, so it is good.
Example 3
Input: root = [1]
Output: 1

Constraints

  • 1 <= number of nodes <= 10^5
  • -10^4 <= Node.val <= 10^4

Think first try before reading the solution

Whether a node is good depends only on the nodes above it. You do not need the whole path: which single number about the path is enough to decide?
Only the largest value seen so far on the path matters. The node is good exactly when node.val >= max_so_far.
Give the recursion an extra parameter: dfs(node, max_so_far) counts this node if it is good, then calls both children with max(max_so_far, node.val) and adds up what they return.

Key idea

Most tree recursions you have seen so far (depth, diameter) work bottom-up: the children report a number and the parent combines them. This one is top-down: what a node needs to know (what was above it) lives with its ancestors, so each parent hands it down as a function argument.

You might think a node needs the entire root-to-node path. It does not: "no ancestor is greater than me" is the same statement as "the largest ancestor is not greater than me". So each call receives one number, max_so_far, compares its own value with it, and passes max(max_so_far, node.val) to both children.

Every node is visited once, so the work is O(n). The recursion is as deep as the tree is tall.

Approaches from the obvious one to the one you want in an interview

Do a DFS that keeps a list path of the values from the root down to the current node's parent. At each node, check all(v <= node.val for v in path); if true, the node is good. Append the node's value before visiting the children and pop it afterwards, so path always describes the current root-to-node path.

It is correct, but the check rescans the path at every node. On a chain of n nodes the paths have length 0, 1, 2, ..., n - 1, so the total work is about n²/2. The waste is obvious once you see it: each scan recomputes a maximum that the parent already knew.

Dry run

  1. root = [3, 3, null, 4, 2], path = []
  2. 3 (root): all(...) over an empty path is True → good (1). path = [3]
  3. 3 (left child): every value in [3] is <= 3 → good (2). path = [3, 3]
  4. 4: [3, 3] all <= 4 → good (3). 2: 3 > 2 → not good. Answer 3.

Python

class Solution:
    def goodNodes(self, root: TreeNode) -> int:
        good = 0

        def dfs(node, path):              # path = values from the root down to node's parent
            nonlocal good
            if node is None:
                return
            if all(v <= node.val for v in path):   # rescans the whole path: O(depth)
                good += 1
            path.append(node.val)
            dfs(node.left, path)
            dfs(node.right, path)
            path.pop()                    # leave the path as we found it

        dfs(root, [])
        return good
Time O(n·h), O(n²) worst caseSpace O(h)

Each node scans its path of length up to h (the height); on a chain h = n. The path list and the call stack hold h items.

When to use: Only as a stepping stone: it shows that the path's maximum is the only thing the check needs.

Replace the path with the single number the check actually needs: the largest value above the current node.

  • dfs(None, m) = 0
  • dfs(node, m) = (1 if node.val >= m else 0) + dfs(node.left, M) + dfs(node.right, M), where M = max(m, node.val)

Start with dfs(root, -inf). Because max_so_far is an argument, each call has its own copy: when the left subtree finishes, the right subtree still receives the value from its path, not from the left side.

Dry run

  1. root = [3, 1, 4, 3, null, 1, 5]
  2. dfs(3, -∞): good. Children get max = 3.
  3. dfs(1, 3): 1 < 3, not good. dfs(3, 3) below it: 3 >= 3, good → subtree of 1 returns 1.
  4. dfs(4, 3): good. dfs(1, 4): not good. dfs(5, 4): good → subtree of 4 returns 2.
  5. root: 1 + 1 + 2 = 4.

Python

class Solution:
    def goodNodes(self, root: TreeNode) -> int:
        def dfs(node, max_so_far):
            if node is None:
                return 0
            good = 1 if node.val >= max_so_far else 0      # nothing above is larger
            new_max = max(max_so_far, node.val)            # what the children will see above them
            return good + dfs(node.left, new_max) + dfs(node.right, new_max)

        return dfs(root, float("-inf"))                    # nothing is above the root
Time O(n)Space O(h)

Each node is visited once and does O(1) work. The call stack is as deep as the tree height h (log n balanced, n for a chain).

When to use: The interview answer: short, and the template for every 'pass state down the path' tree problem.

Watch it run

The same idea without recursion. Store each node in a queue together with the maximum of the path above it. When you take a pair out, decide whether the node is good, then enqueue each child with max(max_so_far, node.val).

The order of visiting does not matter here, because every node carries its own path information. That is why a stack (DFS order) would work just as well as the queue.

Python

class Solution:
    def goodNodes(self, root: TreeNode) -> int:
        if root is None:
            return 0
        good = 0
        queue = deque([(root, float("-inf"))])    # (node, max value on the path above it)
        while queue:
            node, max_so_far = queue.popleft()
            if node.val >= max_so_far:
                good += 1
            new_max = max(max_so_far, node.val)
            for child in (node.left, node.right):
                if child:
                    queue.append((child, new_max))
        return good
Time O(n)Space O(w)

Every node enters the queue once; the queue holds at most about one level (width w).

When to use: When the tree can be very deep (a 10^5-node chain) and you want to avoid Python's recursion limit.

Common mistakes

  • Using > instead of >=. A node that ties the path maximum is good: in [3, 3, null, 4, 2] both 3s count.
  • Comparing with the parent only. In the path 3 → 1 → 2, node 2 is bigger than its parent 1 but is not good, because 3 is above it. Pass the running maximum, not the parent's value.
  • Keeping max_so_far in one shared variable that you overwrite. After the left subtree raises it, the right subtree would see the left side's maximum. A function argument is restored automatically when the call returns.
  • Starting the maximum at 0. With negative values, [-1, -2] would count no nodes at all. Start with float('-inf') (or the root's own value).

Python notes

  • float('-inf') compares smaller than every integer, so dfs(root, float('-inf')) makes the root good with no special case.
  • A nested def dfs(...) can read the outer method's variables, but to reassign one (say, a counter) it must declare it nonlocal. Returning counts (good + left + right) avoids shared state entirely.
  • Python's default recursion limit is 1000 frames, below the 10^5-node chain this problem allows. LeetCode raises the limit; the BFS version below has no limit to worry about.
