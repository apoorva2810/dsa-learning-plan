Find the Duplicate Number Medium

LeetCode #287 ↗
Status

Find the one repeated value in an array of n + 1 numbers from 1 to n, without changing it and with O(1) memory.

Problem

You are given a list nums of n + 1 integers, where every value is between 1 and n inclusive. Exactly one value appears more than once (it may appear two or more times). Return that value.

Do it without modifying nums and using only O(1) extra space.

Examples

Example 1
Input: nums = [1, 3, 4, 2, 2]
Output: 2
Example 2
Input: nums = [3, 1, 3, 4, 2]
Output: 3
Example 3
Input: nums = [3, 3, 3, 3, 3]
Output: 3
The repeated value can appear many times.

Constraints

  • 1 <= n <= 10^5
  • len(nums) == n + 1
  • 1 <= nums[i] <= n
  • exactly one value repeats
  • follow-up: no changes to nums, O(1) extra space, faster than O(n²)

Think first try before reading the solution

A set finds the repeat in O(n) time but O(n) memory, and sorting changes the array. The rules forbid both. What else does the input promise?
Treat every index i as a node with an arrow to index nums[i]. Values are in 1..n, so every arrow lands on a valid index. What shape does the path starting at index 0 make?
Two indices hold the duplicate value, so two arrows point at the same index: the place where the path enters a loop. Find a meeting point inside the loop with fast/slow pointers, then restart one pointer at 0; walking both one step at a time, they meet at the entrance.

Key idea

The array is a linked list in disguise: read index i as a node whose next is nums[i]. Start at index 0 and follow the arrows: 0 → nums[0] → nums[nums[0]] → …. There are only n + 1 indices, so the walk must eventually revisit one, and from then on it goes round a loop. The path looks like the Greek letter ρ (rho): a tail, then a cycle.

The node where the tail joins the cycle has two arrows coming in, one from the tail and one from inside the loop. Two arrows into index d means two different positions hold the value d, so the entrance is the duplicate. (Index 0 can never be inside the loop, because no value is 0, so nothing points back to it.)

That turns the problem into Linked List Cycle II, solved with Floyd's algorithm in O(n) time and O(1) memory:

  1. slow moves 1 arrow, fast moves 2, until they land on the same index inside the loop.
  2. Restart a pointer at index 0 and move it and slow one arrow at a time. They meet exactly at the entrance. Why: say the tail has F steps and the loop has length C. At the meeting, fast had walked twice as far as slow, and the extra distance (equal to slow's whole walk) is a whole number of laps. So slow is a whole number of laps past the start: after F more steps it stands on the entrance, the same place the restarted pointer reaches after F steps.

Approaches from the obvious one to the one you want in an interview

Walk the list and keep a set of values already seen. The first value that is already in the set is the duplicate.

O(n) time, and it is what you would write in real code, but the set can grow to n values: O(n) extra memory, which the problem forbids. (Sorting a copy has the same memory cost; sorting in place modifies nums.)

Python

class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        seen = set()
        for x in nums:
            if x in seen:                    # second time we meet this value
                return x
            seen.add(x)
        return -1                            # unreachable for valid input
Time O(n)Space O(n)

One pass; the set can hold up to n values.

When to use: When the memory rule does not apply.

The answer is a value between 1 and n, so binary search that value range. For a guess mid, count how many numbers are <= mid. If the duplicate were larger than mid, the numbers <= mid would all be distinct, so there would be at most mid of them. So:

  • count > mid → the duplicate is <= mid (search the lower half);
  • otherwise → it is > mid (search the upper half).

Each round scans all n + 1 numbers, and the range halves each time: O(n log n) time, O(1) memory, no changes to nums.

Dry run

  1. [1, 3, 4, 2, 2], values 1..4: mid = 2, numbers <= 2 are 1, 2, 2 → 3 > 2 → range 1..2
  2. mid = 1: numbers <= 1 are just 1 → 1 <= 1 → range 2..2
  3. one value left → 2

Python

class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        lo, hi = 1, len(nums) - 1             # the answer is a value in 1..n
        while lo < hi:
            mid = (lo + hi) // 2
            count = sum(1 for x in nums if x <= mid)
            if count > mid:                    # more than mid values fit in 1..mid
                hi = mid                       # so the duplicate is <= mid
            else:
                lo = mid + 1
        return lo
Time O(n log n)Space O(1)

About log n rounds, each counting over all n + 1 numbers.

When to use: Easier to justify than Floyd's algorithm and already meets the space rule; a good answer if you forget the cycle trick.

Watch it run

Follow arrows i → nums[i] from index 0. The path is a tail plus a loop, and the loop's entrance is the duplicate value (two indices point at it).

  1. Meet inside the loop: slow = nums[slow], fast = nums[nums[fast]], starting at 0, until slow == fast.
  2. Find the entrance: finder = 0; move finder and slow one arrow at a time until they are equal. Return that index.

Each phase takes O(n) steps and only a few integers are stored. The array is read, never written.

Dry run

  1. [1, 3, 4, 2, 2]: path 0 → 1 → 3 → 2 → 4 → 2 …, entrance 2
  2. phase 1: (slow, fast) = (1, 3), (3, 4), (2, 4), (4, 4) → meet at 4
  3. phase 2: (finder, slow) = (1, 2), (3, 4), (2, 2) → meet at 2
  4. return 2

Python

class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # read nums as a linked list: index i points to index nums[i]
        slow = fast = 0
        while True:                            # phase 1: meet somewhere inside the loop
            slow = nums[slow]
            fast = nums[nums[fast]]
            if slow == fast:
                break
        finder = 0                             # phase 2: walk from the start and from the meeting point
        while finder != slow:
            finder = nums[finder]
            slow = nums[slow]
        return finder                          # the loop's entrance = the duplicate value
Time O(n)Space O(1)

Phase 1 ends within about tail + loop length rounds; phase 2 takes exactly the tail length.

When to use: The answer to the full follow-up. Explain the 'array as linked list' view before writing it.

Common mistakes

  • Sorting nums or marking visited values by negating them: both find the duplicate quickly but break the rule against modifying the array.
  • Starting the pointers at nums[0] for phase 1 but restarting the finder at index 0 (or the other way round): both phases must use the same starting node, index 0.
  • Using a while slow != fast loop for phase 1 with both starting at 0: it never runs. Move first, then compare (a while True with break, or start fast one round ahead).
  • Assuming the duplicate appears exactly twice. With [3, 3, 3, 3, 3] several values are missing; the cycle argument and the counting argument both still hold.
  • Binary search version: searching over indices instead of values. The range being halved is the value range 1..n.

Python notes

  • slow = nums[slow] is the array version of slow = slow.next; fast = nums[nums[fast]] is fast.next.next.
  • sum(1 for x in nums if x <= mid) counts without building a list.
  • Phase 1 needs a do-while loop, which Python lacks: write while True: with a break.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Linked List Cycle II LC 142 — the same two-phase Floyd algorithm on real ListNodes: return the node where the cycle begins.
  • Linked List Cycle LC 141 — phase 1 only: does the walk ever loop?
  • First Missing Positive LC 41 — also treats values as indices, but you may modify the array: swap each value into its home slot, then scan.
  • Find All Duplicates in an Array LC 442 — several values repeat and modifying is allowed: mark nums[abs(x) - 1] negative; a value seen negative is a repeat.
  • Set Mismatch LC 645 — one value is duplicated and one is missing: counting or sum arithmetic finds both.
