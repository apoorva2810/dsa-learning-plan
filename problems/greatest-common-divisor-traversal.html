Greatest Common Divisor Traversal Hard 250

LeetCode #2709 ↗
Status

Decide whether every index of an array can reach every other one by hopping between numbers that share a factor.

Problem

You are given an array nums of positive integers. You may hop from index i to index j (with i != j) when gcd(nums[i], nums[j]) > 1, that is, when the two numbers share a factor larger than 1.

Return true if, for every pair of indices, there is a sequence of hops leading from one to the other, and false otherwise.

Examples

Example 1
Input: nums = [2, 3, 6]
Output: true
Indices 0 and 2 share the factor 2, indices 1 and 2 share 3. Index 0 reaches index 1 through index 2.
Example 2
Input: nums = [3, 9, 5]
Output: false
3 and 9 share 3, but 5 shares nothing with either: index 2 is stranded.
Example 3
Input: nums = [4, 3, 12, 8]
Output: true
4, 12 and 8 share the factor 2; 3 and 12 share 3. Everything hangs together through 12.

Constraints

  • 1 <= len(nums) <= 10^5
  • 1 <= nums[i] <= 10^5

Think first try before reading the solution

Two numbers share a factor larger than 1 exactly when they share a prime factor. How many distinct primes can a number up to 10^5 have?
At most six (2 · 3 · 5 · 7 · 11 · 13 = 30030, and the next prime pushes past 10^5). So instead of comparing every pair, connect each index to the handful of primes dividing its number.
Union-find over the indices: factor nums[i], and for each prime p remember the first index that had p; join i with it. At the end, all indices must share one root. Watch out for nums[i] == 1.

Key idea

Hopping is allowed between numbers that share a prime factor, so think of each prime as a hub: every index whose number is divisible by p is plugged into hub p. Two indices can reach each other exactly when they hang off the same hub or are linked through a chain of hubs. The question becomes: is that network connected?

Checking gcd for all pairs builds the same network in O(n²) comparisons, far too many for 10^5 numbers. Factoring instead costs little: a number up to 10^5 has at most six distinct primes, and trial division up to its square root (about 316) finds them. Union-find merges indices as factors appear: keep a dictionary first_index[p], the first index whose number contained prime p; every later index with that prime is unioned with it. Each prime therefore costs one union per index that has it, and the whole run is near-linear in the number of factors found.

Two traps hide in the statement. A single index needs no hops, so [x] is always true. And 1 has no prime factors, so an array with a 1 and anything else is false.

Approaches from the obvious one to the one you want in an interview

Build the graph the statement describes: for every pair of indices compute gcd(nums[i], nums[j]) and add an edge when it is larger than 1. Then a breadth-first search from index 0 counts how many indices are reachable; the answer is true exactly when all n are.

Correct and simple, but n(n - 1)/2 gcd calls is 5 · 10⁹ at the limit. The waste is that most pairs share nothing, and we learn that only after computing their gcd.

Dry run

  1. nums = [2, 3, 6]: gcd(2, 3) = 1, gcd(2, 6) = 2 → edge 0–2, gcd(3, 6) = 3 → edge 1–2
  2. BFS from 0: reach 2, then 1 → 3 of 3 indices → true

Python

class Solution:
    def canTraverseAllPairs(self, nums: List[int]) -> bool:
        n = len(nums)
        if n == 1:
            return True                        # a single index has no pairs to connect
        neighbours = [[] for _ in range(n)]
        for i in range(n):
            for j in range(i + 1, n):
                if math.gcd(nums[i], nums[j]) > 1:    # a shared factor: the two indices are linked
                    neighbours[i].append(j)
                    neighbours[j].append(i)
        seen = {0}
        queue = deque([0])
        while queue:
            i = queue.popleft()
            for j in neighbours[i]:
                if j not in seen:
                    seen.add(j)
                    queue.append(j)
        return len(seen) == n                  # everything reachable from index 0?
Time O(n² log M)Space O(n²)

n²/2 gcd computations of O(log M) each, M = the largest number; the edge lists can hold O(n²) entries.

When to use: Only to make the graph concrete; it times out well before n = 10^5.

Two numbers share a factor larger than 1 exactly when they share a prime. So treat each prime as a hub: factor every number by trial division and, for each prime p found in nums[i], union index i with first_index[p], the first index whose number contained p (or record i if p is new). Every index with prime p ends up in the group of that first index, without ever comparing two numbers directly.

Finally all indices must share one union-find root. Two special cases: a single index is trivially connected (true), and a 1 has no prime factors, so with two or more numbers it is stranded (false).

Trial division up to √M ≈ 316 per number gives O(n √M) in the worst case; a number has at most six distinct primes, so the union-find work is tiny next to the factoring.

Dry run

  1. nums = [2, 3, 6]: index 0 → prime 2 is new, first_index = {2: 0}
  2. Index 1 → prime 3 is new, first_index = {2: 0, 3: 1}
  3. Index 2 → 6 = 2 × 3: union(2, 0) and union(2, 1). Groups: 3 → 2 → 1
  4. All roots equal → true

Python

class Solution:
    def canTraverseAllPairs(self, nums: List[int]) -> bool:
        n = len(nums)
        if n == 1:
            return True                        # a single index needs no hops

        parent = list(range(n))

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]      # path halving
                x = parent[x]
            return x

        def union(a: int, b: int) -> None:
            root_a, root_b = find(a), find(b)
            if root_a != root_b:
                parent[root_a] = root_b

        first_index = {}                       # prime -> first index whose number has that prime
        for i, value in enumerate(nums):
            if value == 1:
                return False                   # 1 shares no factor with anything: index i is stranded
            p = 2
            while p * p <= value:              # trial division up to the square root
                if value % p == 0:
                    if p in first_index:
                        union(i, first_index[p])       # same prime as an earlier index: same group
                    else:
                        first_index[p] = i
                    while value % p == 0:
                        value //= p            # strip the prime completely
                p += 1
            if value > 1:                      # a leftover prime larger than the square root
                if value in first_index:
                    union(i, first_index[value])
                else:
                    first_index[value] = i
        root = find(0)
        return all(find(i) == root for i in range(n))
Time O(n · √M)Space O(n + π(M))

Trial division to √M per number dominates; union-find is near-constant per found prime. π(M) is the number of primes up to M.

When to use: The standard answer; factoring replaces n² pair checks with at most six unions per number.

Watch it run

When there are many numbers, trial division repeats work: every number re-tests the same small primes. Precompute once, for every value up to max(nums), its smallest prime factor with a sieve. Factoring a number is then a chain of lookups, value → spf[value] → value / spf[value] …, O(log M) per number. The union-find part is unchanged.

The sieve costs O(M log log M) time and O(M) memory up front, which pays off when n is large relative to √M; for a handful of numbers the plain trial division wins.

Dry run

  1. nums = [4, 3, 12, 8]: sieve up to 12 → spf = [·, ·, 2, 3, 2, 5, 2, 7, 2, 3, 2, 11, 2]
  2. Index 0: 4 → 2. Index 1: 3 → 3. Index 2: 12 → 2 (union with 0), 3 (union with 1). Index 3: 8 → 2 (union with 0)
  3. One group → true

Python

class Solution:
    def canTraverseAllPairs(self, nums: List[int]) -> bool:
        n = len(nums)
        if n == 1:
            return True
        if 1 in nums:
            return False                       # 1 has no prime factors

        limit = max(nums)
        spf = list(range(limit + 1))           # spf[v] = smallest prime factor of v (starts as v itself)
        for p in range(2, int(limit ** 0.5) + 1):
            if spf[p] == p:                    # p is prime: mark its multiples that have no smaller factor yet
                for multiple in range(p * p, limit + 1, p):
                    if spf[multiple] == multiple:
                        spf[multiple] = p

        parent = list(range(n))

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]      # path halving
                x = parent[x]
            return x

        def union(a: int, b: int) -> None:
            root_a, root_b = find(a), find(b)
            if root_a != root_b:
                parent[root_a] = root_b

        first_index = {}
        for i, value in enumerate(nums):
            while value > 1:
                p = spf[value]                 # one lookup per prime factor
                if p in first_index:
                    union(i, first_index[p])
                else:
                    first_index[p] = i
                while value % p == 0:
                    value //= p
        root = find(0)
        return all(find(i) == root for i in range(n))
Time O(M log log M + n log M)Space O(M + n)

The sieve is M log log M; afterwards each number factors in O(log M) lookups.

When to use: Many numbers with a moderate maximum; the sieve is shared by all of them.

Common mistakes

  • Returning false for a single element. One index has no pairs to connect, so the answer is true, even for [1].
  • Missing the 1s. gcd(1, x) = 1 for every x, so any 1 in an array of two or more numbers makes the answer false; trial division on 1 finds no primes and silently leaves the index isolated, which the final root check catches only if you remember to run it.
  • Trial division that stops at the square root and forgets the leftover. 100042 = 2 · 50021: after dividing out 2, the remaining 50021 is a prime above the square root and must be recorded too.
  • A recursive find on 10^5 indices: deep chains can exceed Python's recursion limit before path compression flattens them. Write find as a loop with path halving.
  • Comparing every pair with math.gcd: correct, but n²/2 = 5 · 10⁹ calls at the limit. Factoring is the whole point of the problem.

Python notes

  • math.gcd(a, b) is C-fast, but n²/2 calls is still too many; it belongs to the brute force only.
  • Trial division while p * p <= value avoids math.isqrt and floats; divide out each prime fully with while value % p == 0: value //= p so later p values are only true primes.
  • first_index.setdefault(p, i) would both look up and register a prime in one call; the explicit if p in first_index form is clearer when learning.
  • all(find(i) == root for i in range(n)) stops at the first index with a different root.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Largest Component Size by Common Factor LC 952 — the same prime-hub union-find, but return the size of the biggest group instead of asking for one group.
  • Number of Connected Components in an Undirected Graph LC 323 — the counting version of the root check: start with n groups and subtract one per successful union.
  • Accounts Merge LC 721 — the identical 'first owner of a key' trick, with e-mail addresses as the hubs instead of primes.
  • Redundant Connection LC 684 — plain union-find on explicit edges; here the edges are implied by shared primes.
  • What if the numbers were up to 10^9? — trial division to 31623 per number is too slow; use Pollard's rho, or precompute primes up to 31623 and divide only by those.
  • How would you return the number of groups instead of a boolean? — count distinct roots at the end, or decrement a counter on each union that merges two groups.
