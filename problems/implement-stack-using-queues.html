Implement Stack Using Queues Easy 250

LeetCode #225 ↗
Status

Build a last-in-first-out stack when the only container you may use is a first-in-first-out queue.

Problem

Build a stack (last in, first out) using only queues underneath. You may call only the standard queue operations: add to the back, remove from the front, look at the front, size, and is-empty. No appendleft, no popping from the back, no indexing into the middle.

Implement the class MyStack:

  • MyStack() creates an empty stack.
  • push(x) puts x on top of the stack.
  • pop() removes the top element and returns it.
  • top() returns the top element without removing it.
  • empty() returns True if the stack has no elements.

Every call to pop and top is made on a non-empty stack. Follow-up: can you do it with one queue?

Examples

Example 1
Input: ["MyStack","push","push","top","pop","empty"] [[],[1],[2],[],[],[]]
Output: [null, null, null, 2, 2, false]
Push 1, then 2. The top is 2. Pop removes 2 and returns it. One element (the 1) remains, so the stack is not empty.
Example 2
Input: ["MyStack","push","push","push","pop","top","empty"] [[],[1],[2],[3],[],[],[]]
Output: [null, null, null, null, 3, 2, false]
After pushing 1, 2, 3 the newest is 3, so pop returns 3; then 2 is on top.

Constraints

  • 1 <= x <= 9
  • at most 100 calls to push, pop, top and empty
  • every pop and top is called on a non-empty stack

After appending x at the back, what happens if you move each older item from the front to the back, one by one? Where does x end up?

Key idea

A queue is a line at a counter: the person who arrived first is served first. A stack is a pile of plates: the last plate put down is the first one picked up. We have to fake the pile using only the line.

The trick is to pay at push time. Append the new item at the back, as any queue does. Then take the people in front of it, one at a time, from the front of the line and send them to the back. After n - 1 such moves the new item is at the front, and the older items are behind it in the same order they had before. Read front to back, the queue is now the stack read top to bottom. pop and top just look at the front, in O(1).

Someone has to do O(n) work on every operation of one kind; the choice is only whether push pays (cheap reads) or pop/top pay (cheap writes). Both are fine answers; the one-queue version is the one interviewers ask for.

Approaches from the obvious one to the one you want in an interview

Keep the stack in q1 in the natural queue order: oldest at the front, newest at the back. push is a plain append, O(1). The trouble is pop: the item we need is at the back, and a queue only releases its front. So move every item except the last one into a second queue q2, take the last one, and then swap the two queues so the moved items are the stack again. top does the same walk and then puts the item back.

It is correct and easy to picture, but every pop and top costs O(n), and it needs a second queue. It is the baseline that shows where the unavoidable O(n) work lives.

Dry run

  1. push(1): q1 [1]. push(2): q1 [1, 2].
  2. top(): move 1 to q2 → q1 [2], q2 [1]; take 2 (the answer); append it to q2 → [1, 2]; swap → q1 [1, 2].
  3. pop(): move 1 to q2; take 2; swap → q1 [1]. Return 2.
  4. empty(): q1 is [1] → False.

Python

class MyStack:
    def __init__(self):
        self.q1 = deque()                     # the stack, oldest at the front, newest at the back
        self.q2 = deque()                     # scratch space used while digging out the back item

    def push(self, x: int) -> None:
        self.q1.append(x)                     # O(1): join the back of the line

    def pop(self) -> int:
        while len(self.q1) > 1:               # move everything except the last item
            self.q2.append(self.q1.popleft())
        top = self.q1.popleft()               # the last item is the newest = the stack top
        self.q1, self.q2 = self.q2, self.q1   # the moved items are the stack again
        return top

    def top(self) -> int:
        top = self.pop()                      # same walk as pop ...
        self.q1.append(top)                   # ... then put the item back at the end
        return top

    def empty(self) -> bool:
        return not self.q1
Time O(1) push, O(n) pop and topSpace O(n)

Each pop or top moves n - 1 items between the queues.

When to use: When pushes are far more common than pops and tops.

Watch it run

Move the O(n) work to push and arrange the single queue so that its front is always the stack top.

push(x): append x at the back, then move each of the n - 1 older items from the front to the back, one at a time. After those moves x is at the front and the older items follow in their previous order, so the queue read front to back is the stack read top to bottom. pop is popleft, top is a peek at the front, empty is a length check: all O(1).

Why this is the preferred answer: it needs one queue instead of two, and the operations that usually dominate (reading and popping the top) become constant time. The total work is the same as the two-queue version; only the operation that pays changes.

Dry run

  1. push(1): append → [1]; 0 rotations.
  2. push(2): append → [1, 2]; rotate once: move 1 to the back → [2, 1]. Front is 2, the newest.
  3. push(3): append → [2, 1, 3]; rotate twice: [1, 3, 2] → [3, 2, 1].
  4. top(): front → 3. pop(): popleft → 3, queue [2, 1].
  5. push(4): append → [2, 1, 4]; two rotations → [4, 2, 1]. top() → 4.

Python

class MyStack:
    def __init__(self):
        self.queue = deque()                        # front of the queue == top of the stack

    def push(self, x: int) -> None:
        self.queue.append(x)                        # x joins at the back ...
        for _ in range(len(self.queue) - 1):        # ... then every older item moves behind it
            self.queue.append(self.queue.popleft())

    def pop(self) -> int:
        return self.queue.popleft()                 # the front is the newest item

    def top(self) -> int:
        return self.queue[0]                        # peek at the front

    def empty(self) -> bool:
        return not self.queue
Time O(n) push, O(1) pop, top and emptySpace O(n)

A push rotates the n - 1 older items once each; nothing else moves anything.

When to use: The standard answer, and the one the 'single queue' follow-up asks for.

Watch it run

The same idea as the one-queue version, written with two queues: push the new item into the empty queue q2, then move every older item from q1 behind it, then swap. q1 always has the newest item at the front, so pop and top are O(1).

It is the one-queue solution with an extra container; the rotation in place does the same job without it.

Python

class MyStack:
    def __init__(self):
        self.q1 = deque()                     # the stack, newest at the FRONT
        self.q2 = deque()                     # empty between operations

    def push(self, x: int) -> None:
        self.q2.append(x)                     # the new item goes first into the empty queue
        while self.q1:                        # then all older items line up behind it
            self.q2.append(self.q1.popleft())
        self.q1, self.q2 = self.q2, self.q1   # q1 is the stack again, q2 is empty

    def pop(self) -> int:
        return self.q1.popleft()

    def top(self) -> int:
        return self.q1[0]

    def empty(self) -> bool:
        return not self.q1
Time O(n) push, O(1) pop, top and emptySpace O(n)

When to use: If rotating in place feels unclear; the costs are identical to the one-queue version.

Common mistakes

  • Using deque operations that a queue does not have (appendleft, pop() from the right, queue[-1]). The exercise is about the queue interface; collections.deque just happens to also be a deque.
  • Rotating len(queue) times instead of len(queue) - 1: one extra move brings the queue back to where it started, with the new item at the back.
  • In the two-queue version, forgetting to swap q1 and q2 after a pop, so the next operation works on the now-empty queue.
  • Implementing top() in the two-queue version by popping the last item and forgetting to put it back at the end.

Python notes

  • collections.deque is the queue: append adds at the back, popleft removes the front, queue[0] peeks at the front, len is the size. All O(1).
  • for _ in range(len(queue) - 1): queue.append(queue.popleft()) is the rotation; len is read once, before the loop starts.
  • deque.rotate(1) does the same rotation in one call, but it is a deque feature, not a queue operation, so say so if you use it in an interview.
  • A list works too (append / pop(0)), but pop(0) shifts every element and costs O(n), which hides the real cost of each queue operation.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Implement Queue using Stacks LC 232 — the mirror problem; there, two stacks give amortised O(1) for every operation, which is impossible here with queue operations only.
  • Design Circular Queue LC 622 — build the queue itself on a fixed-size array with head and tail indices that wrap around.
  • Min Stack LC 155 — a different design twist: the stack must also report its minimum in O(1) by storing extra data next to each element.
  • Design Circular Deque LC 641 — a deque supports both ends, so it is a stack and a queue at once; this is why the exercise bans deque operations.
  • Make pop O(1) instead of push — use two queues and do the moving at push time: push into the empty queue, then move all older items behind the new one, then swap.
  • Can every operation be O(1)? — not with queue operations only: at least one of push or pop must move the other n - 1 items. It needs a deque or a linked list.
