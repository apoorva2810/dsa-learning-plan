Insert Interval Medium

LeetCode #57 ↗
Status

Add one new range to a sorted list of non-overlapping ranges, merging it with every range it overlaps.

Problem

You are given intervals, a list of ranges [start, end] that is sorted by start and in which no two ranges overlap. You are also given one more range, newInterval.

Insert newInterval so that the list stays sorted and still has no overlaps, merging the new range with every existing range it overlaps. Return the resulting list.

  • Ranges that only share an endpoint overlap: inserting [4, 8] next to [8, 10] produces one range that covers both.
  • The list may be empty.
  • You may return a new list; the input does not have to be changed in place.

Examples

Example 1
Input: intervals = [[1, 3], [6, 9]], newInterval = [2, 5]
Output: [[1, 5], [6, 9]]
[2, 5] overlaps [1, 3], so they merge into [1, 5]. [6, 9] is untouched.
Example 2
Input: intervals = [[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]], newInterval = [4, 8]
Output: [[1, 2], [3, 10], [12, 16]]
[4, 8] overlaps [3, 5] and [6, 7], and touches [8, 10] at 8. All four become [3, 10].
Example 3
Input: intervals = [], newInterval = [5, 7]
Output: [[5, 7]]

Constraints

  • 0 <= len(intervals) <= 10^4
  • intervals[i] = [start, end] with 0 <= start <= end <= 10^5
  • intervals is sorted by start and has no overlapping ranges
  • newInterval = [start, end] with 0 <= start <= end <= 10^5

Think first try before reading the solution

The list is already sorted. Do you need to sort anything? Think about what you know about each existing interval compared with the new one.
Every existing interval is in exactly one of three groups: it ends before the new one starts, it overlaps the new one, or it starts after the new one ends. Because the list is sorted, the groups come in that order.
Copy the first group unchanged. For the overlapping group, grow the new interval with min of the starts and max of the ends. Then add the grown interval and copy the third group.

Key idea

Compare each existing interval with the new one, [start, end]. Exactly one of three things is true:

  1. It ends before the new interval starts (iv.end < start). It lies entirely to the left and stays as it is.
  2. It starts after the new interval ends (iv.start > end). It lies entirely to the right and stays as it is.
  3. Otherwise it overlaps the new interval (touching counts) and has to be absorbed into it.

The list is sorted and has no overlaps, so the intervals show up in exactly this order: all the "left" ones, then all the overlapping ones, then all the "right" ones. One pass can therefore handle the three zones in turn. Copy the left ones. Grow the new interval over the overlapping ones (min of the starts, max of the ends). Add it. Copy the rest.

No sorting is needed, so the cost is O(n), against O(n log n) for "append, sort, merge".

Approaches from the obvious one to the one you want in an interview

Treat it as Merge Intervals: add the new interval to the list, sort by start, and merge everything in one sweep. It is correct, short, and needs no new idea.

It throws away what the statement gives you for free, that the list is already sorted. Re-sorting costs O(n log n), where a single pass can do the job in O(n).

Dry run

  1. intervals = [[1, 3], [6, 9]], newInterval = [2, 5]
  2. Append and sort by start: [[1, 3], [2, 5], [6, 9]]
  3. Sweep: [1, 3] starts the first block. [2, 5]: 2 <= 3, so the block becomes [1, 5]. [6, 9]: 6 <= 5 is false, new block.
  4. Result: [[1, 5], [6, 9]]

Python

class Solution:
    def insert(self, intervals: List[List[int]], newInterval: List[int]) -> List[List[int]]:
        merged = []
        for start, end in sorted(intervals + [newInterval]):   # a new list, sorted by start
            if merged and start <= merged[-1][1]:              # overlaps (or touches) the last block
                merged[-1][1] = max(merged[-1][1], end)
            else:
                merged.append([start, end])
        return merged
Time O(n log n)Space O(n)

The sort dominates. The sweep after it is O(n).

When to use: When you need something that works in a minute and n is small. Mention that it ignores the sorted input.

Use the fact that the list is sorted and disjoint: the intervals fall into three consecutive zones relative to the new interval [start, end].

  1. Left: iv.end < start. Copy to the result.
  2. Overlapping: iv.start <= end. Grow the new interval: start = min(start, iv.start), end = max(end, iv.end).
  3. Right: everything after that. Append the grown new interval, then copy the rest.

The two comparisons are asymmetric on purpose. Zone 1 uses < and zone 2 uses <= so that an interval merely touching the new one lands in zone 2 and is merged. Each interval is looked at once: O(n), with no sort.

Dry run

  1. intervals = [[1, 3], [6, 9]], newInterval = [2, 5]: start = 2, end = 5
  2. Zone 1: [1, 3]: 3 < 2 is false, so zone 1 is empty.
  3. Zone 2: [1, 3]: 1 <= 5, absorb it: start = min(2, 1) = 1, end = max(5, 3) = 5. [6, 9]: 6 <= 5 is false, stop.
  4. Append [1, 5], then copy the rest, [6, 9]: [[1, 5], [6, 9]]

Python

class Solution:
    def insert(self, intervals: List[List[int]], newInterval: List[int]) -> List[List[int]]:
        result = []
        start, end = newInterval
        i, n = 0, len(intervals)

        while i < n and intervals[i][1] < start:          # zone 1: ends before the new one starts
            result.append(intervals[i])
            i += 1

        while i < n and intervals[i][0] <= end:           # zone 2: overlaps (or touches) the new one
            start = min(start, intervals[i][0])
            end = max(end, intervals[i][1])
            i += 1
        result.append([start, end])                       # the new interval, grown over everything it met

        result.extend(intervals[i:])                      # zone 3: starts after the new one ends
        return result
Time O(n)Space O(n)

Each interval is visited once. The output list is the only extra memory.

When to use: Always. It is the expected interview answer, and the three-zone shape is worth remembering.

Watch it run

In a sorted, disjoint list both the starts and the ends are in increasing order, so binary search can find the overlapping slice without walking to it:

  • lo = the first interval whose end is >= start. It is the first one that can reach the new interval.
  • hi = the first interval whose start is > end. It is the first one that begins too late.

The intervals lo .. hi - 1 are exactly the overlapping ones. Replace that slice by one merged interval and keep the rest.

Finding the slice takes O(log n) comparisons, but building the returned list still copies O(n) items, so the total is O(n) in Python. It pays off when the data lives in a structure that can splice in place, such as a calendar service.

Python

class Solution:
    def insert(self, intervals: List[List[int]], newInterval: List[int]) -> List[List[int]]:
        start, end = newInterval
        lo = bisect.bisect_left(intervals, start, key=lambda iv: iv[1])    # first interval with end >= start
        hi = bisect.bisect_right(intervals, end, key=lambda iv: iv[0])     # first interval with start > end
        if lo < hi:                                       # at least one interval overlaps the new one
            start = min(start, intervals[lo][0])
            end = max(end, intervals[hi - 1][1])
        return intervals[:lo] + [[start, end]] + intervals[hi:]
Time O(n)Space O(n)

O(log n) comparisons to find the slice, then O(n) to build the new list.

When to use: To show you know the list is searchable. In an interview, mention it after the linear pass.

Common mistakes

  • Writing iv[1] <= start in zone 1. An interval that ends exactly where the new one starts touches it and must be merged, not copied. Zone 1 needs the strict <.
  • Writing iv[0] < end in zone 2. An interval that starts exactly where the new one ends also touches it. Zone 2 needs <=.
  • Taking the new interval's own start and end for the merged range. The first overlapping interval may start earlier ([1, 3] vs [2, 5]) and the last may end later. Use min for the start and max for the end.
  • Forgetting to add the new interval when it overlaps nothing. It can fit in a gap or go at either end; the middle loop then does not run, but the new interval still has to be appended.
  • Forgetting result.extend(intervals[i:]) at the end, which silently drops every interval after the new one.

Python notes

  • while i < n and intervals[i][1] < start: tests the index first. When i == n the second half would raise IndexError, but and stops before evaluating it.
  • result.extend(intervals[i:]) copies everything left in one call. intervals[i:] is an empty list when i == n, so no guard is needed.
  • start, end = newInterval unpacks the new interval into two variables you can grow freely without changing the caller's list.
  • bisect.bisect_left(intervals, x, key=...) accepts a key function since Python 3.10, so a list of pairs can be searched by its ends or its starts without building a separate list.
