Interleaving String Medium

LeetCode #97 ↗
Status

Decide whether a third string can be woven from two strings that each keep their own character order.

Problem

You are given three strings s1, s2 and s3. Return True if s3 is an interleaving of s1 and s2: you can build s3 by repeatedly taking the next unused character of s1 or of s2, until both strings are used up.

  • Every character of s1 and of s2 is used exactly once.
  • The characters of s1 stay in their original order inside s3, and so do those of s2. Only the way the two sequences alternate is free (a run from one string can be any length, including zero).
  • Any of the strings may be empty.

Examples

Example 1
Input: s1 = "aabcc", s2 = "dbbca", s3 = "aadbbcbcac"
Output: true
aa from s1, dbbc from s2, bc from s1, a from s2, c from s1.
Example 2
Input: s1 = "aabcc", s2 = "dbbca", s3 = "aadbbbaccc"
Output: false
The letters are the right ones, but both a of s1 are used at the start, so the a at index 6 must be the last letter of s2, and s2's c would have to come before it.
Example 3
Input: s1 = "", s2 = "", s3 = ""
Output: true

Constraints

  • 0 <= len(s1), len(s2) <= 100
  • 0 <= len(s3) <= 200
  • all three strings contain only lowercase English letters

Think first try before reading the solution

If len(s1) + len(s2) != len(s3) the answer is immediately False. Otherwise, after you have used i characters of s1 and j of s2, how many characters of s3 have you produced? Which character of s3 is produced next?
The next character s3[i + j] must be s1[i] or s2[j]. When both match, one choice can lead to a dead end later, so keep both open. Picture (i, j) as a cell of a grid: a step down uses a character of s1, a step right uses a character of s2.
Let dp[i][j] = can s3[:i + j] be formed from s1[:i] and s2[:j]? The cell is True if the cell above is True and s1[i - 1] == s3[i + j - 1], or the cell to the left is True and s2[j - 1] == s3[i + j - 1].

Key idea

Draw a grid with len(s1) + 1 rows and len(s2) + 1 columns. Standing on cell (i, j) means "I have used the first i characters of s1 and the first j of s2". A step down uses the next character of s1; a step right uses the next character of s2. Interleaving the strings is a walk from the top-left corner (0, 0) to the bottom-right corner (m, n) using only down and right steps, which is the Unique Paths grid with a rule attached to every step.

After i + j steps exactly i + j characters of s3 have been produced, so the step that arrives at (i, j) has to produce s3[i + j - 1]. A down step into (i, j) is allowed when s1[i - 1] == s3[i + j - 1], a right step when s2[j - 1] == s3[i + j - 1]. Writing dp[i][j] for "cell (i, j) can be reached by a valid walk":

dp[i][j] = (dp[i - 1][j] and s1[i - 1] == s3[i + j - 1]) or (dp[i][j - 1] and s2[j - 1] == s3[i + j - 1])

with dp[0][0] = True, and the answer is dp[m][n]. The position in s3 never needs an index of its own: it is always i + j.

Why not just scan s3 and take the character from whichever string matches? When s1[i] and s2[j] both equal the needed letter, one choice may dead-end later and the other may not. The table keeps every reachable cell alive, so both options are explored at once. (Even example 1 breaks the rule "prefer s1".)

Each row reads only the row above and the cell to its left, so one list of n + 1 booleans is enough: before dp[j] is overwritten it still holds the cell above, and dp[j - 1] already holds the current row.

Approaches from the obvious one to the one you want in an interview

Let ok(i, j) mean: can the first i + j characters of s3 be formed from the first i of s1 and the first j of s2? Look at the last of those i + j characters, s3[i + j - 1]. It came from s1[i - 1] or from s2[j - 1]:

  • from s1: s1[i - 1] == s3[i + j - 1] and ok(i - 1, j);
  • from s2: s2[j - 1] == s3[i + j - 1] and ok(i, j - 1).

ok(0, 0) is True (nothing to build). The answer is ok(m, n). After checking that the lengths add up, the position in s3 is always i + j, so two numbers describe the state.

Without a cache the two branches overlap heavily: with s1 = "aaaa...", s2 = "aaaa..." and a b at the end of s3 the recursion tries every path through the grid, exponentially many. With @cache there are only (m + 1)(n + 1) states.

Dry run

  1. s1 = "aa", s2 = "ab", s3 = "aaba": ok(2, 2): s3[:4] ends in a. From s1: s1[1] = a fits → need ok(1, 2). From s2: s2[1] = b ≠ a.
  2. ok(1, 2): s3[:3] = aab ends in b. From s1: s1[0] = a ≠ b. From s2: s2[1] = b fits → need ok(1, 1).
  3. ok(1, 1): s3[:2] = aa ends in a. From s1: s1[0] fits → ok(0, 1); from s2: s2[0] fits → ok(1, 0).
  4. ok(0, 1): s3[:1] = a, from s2: s2[0] fits and ok(0, 0) is True → True.
  5. So ok(1, 1), ok(1, 2) and ok(2, 2) are True. One weave: s1 a, s2 a, s2 b, s1 a.

Python

class Solution:
    def isInterleave(self, s1: str, s2: str, s3: str) -> bool:
        m, n = len(s1), len(s2)
        if m + n != len(s3):                            # every character of s3 needs exactly one source
            return False

        @cache                                          # one stored answer per pair (i, j)
        def ok(i: int, j: int) -> bool:
            """Can s3[:i + j] be formed from s1[:i] and s2[:j]?"""
            if i == 0 and j == 0:
                return True
            k = i + j - 1                               # index of the last character of that s3 prefix
            if i > 0 and s1[i - 1] == s3[k] and ok(i - 1, j):    # it came from s1
                return True
            if j > 0 and s2[j - 1] == s3[k] and ok(i, j - 1):    # it came from s2
                return True
            return False

        return ok(m, n)
Time O(m·n)Space O(m·n)

(m + 1)(n + 1) states, O(1) work each. The recursion is at most m + n = 200 frames deep.

When to use: The natural first version, and fast enough here because the depth stays below Python's recursion limit.

Fill the same recursion as an (m + 1) × (n + 1) table of booleans, where dp[i][j] = can s3[:i + j] be formed from s1[:i] and s2[:j]. Only dp[0][0] = True is given. Every other cell, borders included, uses one rule:

dp[i][j] = (i > 0 and dp[i - 1][j] and s1[i - 1] == s3[i + j - 1]) or (j > 0 and dp[i][j - 1] and s2[j - 1] == s3[i + j - 1])

The first part is a step down (a character of s1 was used), the second a step right (a character of s2). The guards i > 0 and j > 0 handle the first row and column, where one of the two neighbours does not exist. The answer is dp[m][n].

Read the table as a map: a True cell is one that some valid walk from the top-left corner can reach. Walking back from the bottom-right corner through True cells tells you which string supplied each letter.

Dry run

  1. s1 = "aa", s2 = "ab", s3 = "aaba": dp[0][0] = True
  2. row 0: dp[0][1] (s2's a = s3[0]) True, dp[0][2] (s2's b vs s3[1] = a) False
  3. row 1: dp[1][0] True (s1's a), dp[1][1] True, dp[1][2] True (from the left: s2's b = s3[2])
  4. row 2: dp[2][0] True (aa), dp[2][1] False (s3[2] = b, but neither s1[1] nor s2[0] is b), dp[2][2] True (from above: dp[1][2] is True and s1[1] = a = s3[3]) → answer True

Python

class Solution:
    def isInterleave(self, s1: str, s2: str, s3: str) -> bool:
        m, n = len(s1), len(s2)
        if m + n != len(s3):
            return False
        # dp[i][j] = can s3[:i + j] be formed from s1[:i] and s2[:j]?
        dp = [[False] * (n + 1) for _ in range(m + 1)]
        dp[0][0] = True                                 # nothing used, nothing produced
        for i in range(m + 1):
            for j in range(n + 1):
                if i > 0 and dp[i - 1][j] and s1[i - 1] == s3[i + j - 1]:
                    dp[i][j] = True                     # arrive from above: the last letter came from s1
                if j > 0 and dp[i][j - 1] and s2[j - 1] == s3[i + j - 1]:
                    dp[i][j] = True                     # arrive from the left: the last letter came from s2
        return dp[m][n]
Time O(m·n)Space O(m·n)

One O(1) update per cell of the (m + 1) × (n + 1) table; no recursion.

When to use: When you want to see which cells are reachable, or to recover one valid weave by walking back.

Watch it run

Row i reads only the row above (dp[i - 1][j]) and the cell to its left in the same row (dp[i][j - 1]), so one list dp of n + 1 booleans can play every row in turn. Scanning j from left to right:

  • dp[j] before the assignment is still the cell above;
  • dp[j - 1] is already the current row, i.e. the cell to the left.

No diagonal is needed (unlike LCS or Edit Distance), so there is no saved variable; assign dp[j] = from_above or from_left directly. The guard j > 0 stops dp[j - 1] from wrapping around to dp[-1].

The extra memory is O(n), and the time is still one update per cell. You lose the table, so you can no longer walk back to list the weave.

Dry run

  1. s1 = "aa", s2 = "ab", s3 = "aaba": dp = [True, False, False]
  2. row 0: dp[1] True (left cell True, s2[0] = a = s3[0]), dp[2] False (s2[1] = b ≠ s3[1] = a) → [T, T, F]
  3. row 1 (s1[0] = a): dp[0] stays True, dp[1] True, dp[2] True (from the left: s2[1] = b = s3[2]) → [T, T, T]
  4. row 2 (s1[1] = a): dp[0] True, dp[1] False (no source for the b), dp[2] True (from above: old dp[2] is True and s1[1] = a = s3[3]) → [T, F, T], answer dp[2] = True

Python

class Solution:
    def isInterleave(self, s1: str, s2: str, s3: str) -> bool:
        m, n = len(s1), len(s2)
        if m + n != len(s3):
            return False
        dp = [False] * (n + 1)                          # dp[j] = dp[i][j] for the row being filled
        dp[0] = True
        for i in range(m + 1):
            for j in range(n + 1):
                if i == 0 and j == 0:
                    continue                            # the base case is already set
                # dp[j] still holds row i - 1 here: the cell above
                from_above = i > 0 and dp[j] and s1[i - 1] == s3[i + j - 1]
                # dp[j - 1] has already been rewritten for row i: the cell to the left
                from_left = j > 0 and dp[j - 1] and s2[j - 1] == s3[i + j - 1]
                dp[j] = from_above or from_left
        return dp[n]
Time O(m·n)Space O(n)

Same m·n cell updates as the table; a single list of n + 1 booleans.

When to use: The interview answer. Put the shorter string second to keep the list short.

Common mistakes

  • Skipping the length check. If len(s1) + len(s2) != len(s3) the answer is False, and s3[i + j - 1] can also run past the end of s3 (IndexError).
  • Greedy matching: taking from s1 whenever its next letter fits fails when both strings can supply the letter. With s1 = "aa", s2 = "ab", s3 = "aaba" the greedy takes both a from s1 and then has no source for b; the answer is True (s1, s2, s2, s1).
  • Wrong index into s3: with the extra empty row and column, cell (i, j) compares s1[i - 1], s2[j - 1] and s3[i + j - 1]. Using s3[i + j] reads one letter too far.
  • Setting the first row and column to True. They depend on matches: dp[0][j] is True only while s2[:j] equals s3[:j], and dp[i][0] only while s1[:i] equals s3[:i].
  • Treating a letter-count (anagram) check as enough. abc and def cannot make abcdfe although the letters agree: inside s2 the e must come before the f.

Python notes

  • Check len(s1) + len(s2) != len(s3) first. It also guarantees that s3[i + j - 1] is always in range.
  • @cache keys on (i, j) only. The position in s3 is i + j, so it must not be a third argument: that would add redundant data to every cache key.
  • and / or short-circuit, so i > 0 and dp[j] and s1[i - 1] == s3[i + j - 1] never evaluates s1[-1] when i == 0. Without the guard, index -1 silently reads the last character, and dp[j - 1] at j == 0 would read dp[-1].
  • In the one-list version dp[j] (before the assignment) is the cell above and dp[j - 1] is the cell to the left. s1 and s2 play symmetric roles, so you may swap them to keep the list short.
  • dp = [[False] * (n + 1) for _ in range(m + 1)] builds the table; [[False] * (n + 1)] * (m + 1) would share one row.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Unique Paths LC 62 — the same down/right walk, but every step is allowed and you count the walks; here each step needs a matching letter and you only ask whether one walk exists.
  • Edit Distance LC 72 — the same prefix-pair table with numbers instead of booleans: min over the diagonal, up and left neighbours plus a cost.
  • Distinct Subsequences LC 115 — count the ways one string appears inside another as a subsequence: the (i, j) table with sums instead of or.
  • Regular Expression Matching LC 10 — another boolean (i, j) table, over a string and a pattern; the * rule adds a third neighbour to read.
  • Merge Strings Alternately LC 1768 — the easy cousin where the letters must alternate strictly: two pointers, no DP.
  • Interleave k strings — the state becomes a tuple of k indices, so the table has len(s1) · len(s2) · ... · len(sk) cells: fine for k = 3, quickly too large beyond that.
