Sort Colors Medium 250

LeetCode #75 ↗
Status

Sort a list that holds only 0s, 1s and 2s, in place and in one pass.

Problem

You are given a list nums whose values are only 0, 1 and 2. They stand for the colours red, white and blue. Rearrange nums in place so that all the 0s come first, then all the 1s, then all the 2s.

  • The function returns nothing; the caller reads the modified nums.
  • You may not call the library sort.
  • Follow-up: do it in one pass over the list using only O(1) extra memory.

Examples

Example 1
Input: nums = [2, 0, 2, 1, 1, 0]
Output: [0, 0, 1, 1, 2, 2]
Two 0s, two 1s and two 2s, grouped in that order.
Example 2
Input: nums = [2, 0, 1]
Output: [0, 1, 2]
Example 3
Input: nums = [1, 2, 0, 0, 2, 1]
Output: [0, 0, 1, 1, 2, 2]

Constraints

  • 1 <= len(nums) <= 300
  • nums[i] is 0, 1 or 2
  • sort in place; no library sort
  • follow-up: one pass, O(1) extra space

Think first try before reading the solution

A general sort compares elements and needs O(n log n) time. Here there are only three possible values. What does that let you do that a general sort cannot?
Count how many 0s, 1s and 2s there are, then overwrite the list: that many 0s, then that many 1s, then the rest. Two passes. Can it be one?
Keep three regions: finished 0s at the front, finished 2s at the back, unknown cells in the middle. Look at the first unknown cell and send it to the side where it belongs; 1s can stay where they are.

Key idea

Sorting three values is really grouping: every 0 must end up before every 1, and every 1 before every 2. Counting the three values and rewriting the list does exactly that in two passes.

For one pass, think of the list as three growing regions with an unknown stretch in the middle: the 0s already placed at the front (up to low), the 2s already placed at the back (from high), and the 1s found so far sitting between low and mid. The cell at mid is the first unknown one. A 0 there is swapped to the front, a 2 is swapped to the back, and a 1 is already in the right band, so mid just moves on. Each step shrinks the unknown region by one cell, so the whole list is sorted after n steps. This three-way partition is known as the Dutch national flag algorithm, after the three bands of the flag.

Approaches from the obvious one to the one you want in an interview

nums.sort() sorts the list in place. It passes every test, but it breaks the rule of the exercise and it also wastes the one thing that makes this problem special: a general sort compares elements and needs O(n log n) time for any values, while here every value is 0, 1 or 2. Knowing the alphabet in advance is exactly what a faster method can exploit.

Timsort compares elements; it does not know there are only three values.

When to use: Never for this exercise; it is the baseline that shows what to beat.

Count how many 0s, 1s and 2s there are (one pass). Then overwrite the list from the left: that many 0s, then that many 1s, then that many 2s (a second pass). No comparisons at all, because the sorted order of three known values is fixed: all the 0s, then all the 1s, then all the 2s.

Two passes and three counters is already O(n) time and O(1) space. The only thing it does not satisfy is the follow-up's single pass.

Dry run

  1. nums = [2, 0, 2, 1, 1, 0]
  2. pass 1: count = {0: 2, 1: 2, 2: 2}
  3. pass 2: nums[0..1] = 0, nums[2..3] = 1, nums[4..5] = 2
  4. nums = [0, 0, 1, 1, 2, 2]

Python

class Solution:
    def sortColors(self, nums: List[int]) -> None:
        count = [0, 0, 0]                  # count[v] = how many times v appears
        for v in nums:
            count[v] += 1
        pos = 0
        for v in (0, 1, 2):                # write the values back in sorted order
            for _ in range(count[v]):
                nums[pos] = v
                pos += 1
Time O(n)Space O(1)

One counting pass and one writing pass; three counters regardless of n.

When to use: Simple and fast; the right answer when two passes are fine or when the values arrive as a stream.

Watch it run

Keep three indices. Everything before low is a 0, everything after high is a 2, everything between low and mid is a 1, and the cells from mid to high are still unknown. Look at nums[mid]:

  • 0 → swap it with nums[low], then advance low and mid. The value swapped into mid came from the 1-band (or was this very 0), so it is already known and mid may move on.
  • 1 → it is in its band already; advance mid only.
  • 2 → swap it with nums[high] and move high left. Do not advance mid: the value that came from the right is unknown and must be examined next.

Every step moves either mid right or high left, so the unknown region shrinks by one cell each time and the loop runs at most n times. When mid passes high nothing is unknown and the three bands are the sorted list.

Dry run

  1. nums = [2, 0, 2, 1, 1, 0], low = 0, mid = 0, high = 5
  2. nums[0] = 2 → swap with nums[5]: [0, 0, 2, 1, 1, 2], high = 4
  3. nums[0] = 0 → swap with itself: low = 1, mid = 1
  4. nums[1] = 0 → low = 2, mid = 2
  5. nums[2] = 2 → swap with nums[4]: [0, 0, 1, 1, 2, 2], high = 3
  6. nums[2] = 1 → mid = 3; nums[3] = 1 → mid = 4 > high: done

Python

class Solution:
    def sortColors(self, nums: List[int]) -> None:
        low, mid, high = 0, 0, len(nums) - 1   # 0s before low, 2s after high, unknown in mid..high
        while mid <= high:                     # the cell at high is still unknown, hence <=
            if nums[mid] == 0:
                nums[low], nums[mid] = nums[mid], nums[low]
                low += 1
                mid += 1                       # the swapped-in value was a 1 (or this 0): already known
            elif nums[mid] == 2:
                nums[mid], nums[high] = nums[high], nums[mid]
                high -= 1                      # mid stays: the new nums[mid] is still unknown
            else:
                mid += 1                       # a 1 is already in its band
Time O(n)Space O(1)

Each iteration shrinks the unknown region by one cell; only three indices are stored.

When to use: The interview answer and the follow-up's one-pass requirement.

Common mistakes

  • After swapping a 2 to the back, advancing mid as well: the value that arrived from high has not been looked at yet and may be a 0 or a 2. Only high moves.
  • Looping while mid < high instead of mid <= high: the cell at high is still unknown and would be skipped, as in [1, 2, 0].
  • Rebinding instead of mutating: nums = sorted(nums) creates a new list the caller never sees. Write into the same list (nums[i] = ... or nums[:] = ...).
  • Building the counting-sort answer as a new list and returning it: the problem wants the input list changed, and the return value is ignored.
  • Thinking a 1 at mid needs a swap: everything between low and mid is already a 1, so the 1 is in its band and mid simply advances.

Python notes

  • nums[low], nums[mid] = nums[mid], nums[low] swaps two cells without a temporary variable.
  • nums[:] = new_values writes into the existing list object, so the caller sees the change; nums = new_values only rebinds the local name.
  • nums.count(0) scans the whole list, so three count calls are three passes; one loop with a Counter (or three variables) counts everything in one pass.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Sort an Array LC 912 — general integers, so counting only works when the value range is small; otherwise merge sort or quicksort in O(n log n).
  • Kth Largest Element in an Array LC 215 — quickselect uses this same three-way partition (less than, equal to, greater than the pivot) and then recurses into one side only.
  • Remove Element LC 27 — two groups instead of three (keep or remove): a single low pointer that collects the kept values is enough.
  • Partition Array According to Given Pivot LC 2161 — three groups again, but the relative order inside each group must be kept, so the swapping trick is out: write into a new list in three passes.
  • What if there were k colours instead of 3? — counting sort still works in O(n + k) with k counters. The one-pass pointer trick does not extend cleanly; k - 1 passes of two-way partitioning is one option.
  • What if the colours arrive as a stream? — you cannot swap what you have not seen yet: keep three counters and emit the sorted list at the end, which is the counting approach.
