Minimum Size Subarray Sum Medium 250

LeetCode #209 ↗
Status

Find the shortest run of neighbouring positive numbers whose sum reaches a target.

Problem

You are given a list nums of positive integers and a positive integer target.

Find the shortest contiguous subarray (a run of neighbouring values) whose sum is at least target, and return its length. If no subarray reaches target, return 0.

Examples

Example 1
Input: target = 10, nums = [4, 2, 6, 1, 7, 3]
Output: 2
The run [7, 3] sums to exactly 10. No single value reaches 10, so 2 is the shortest length.
Example 2
Input: target = 8, nums = [1, 1, 1, 1]
Output: 0
Even the whole list adds up to only 4, so no subarray reaches 8.
Example 3
Input: target = 5, nums = [5, 1, 1]
Output: 1
The single value 5 already reaches the target.

Constraints

  • 1 <= target <= 10^9
  • 1 <= len(nums) <= 10^5
  • 1 <= nums[i] <= 10^4

Think first try before reading the solution

Try every start position and grow the subarray to the right until its sum reaches target. Why can you stop growing as soon as it does?
All values are positive, so adding a value always raises the sum and removing one always lowers it. How can that help you avoid restarting the sum for every start position?
Keep a window [left, right] and its sum. Move right to grow it. While the sum is at least target, record the length and move left to shrink it. left never moves backwards, so the scan is O(n).

Key idea

Because every value is positive, the sum of a subarray only grows when you extend it and only shrinks when you cut it. That makes the problem a fit for a sliding window: a range [left, right] that moves along the list while its sum is updated one value at a time, instead of being recomputed.

  • Move right forward, adding nums[right] to the running total.
  • As soon as total >= target, the window is big enough. Record its length, then move left forward, subtracting values, for as long as the window is still big enough. Every length seen on the way is a candidate for the answer.
  • When total drops below target, go back to growing.

left and right only move forward and each moves at most n times, so the scan is O(n). Dropping nums[left] loses nothing: a window that starts there and ends further right would be longer than the one just recorded, and its shorter versions were already below target.

Approaches from the obvious one to the one you want in an interview

For every start position, add values one at a time until the running sum reaches target. That end position gives the shortest subarray for this start; record its length and move on. Stopping at the first end that works is safe, because a longer subarray from the same start cannot be shorter.

It is simple and correct, but every start may scan almost the whole list, so the cost is O(n²). With n = 10^5 that is billions of additions when the target is out of reach.

Dry run

  1. target = 10, nums = [4, 2, 6, 1, 7, 3]
  2. start 0: sums 4, 6, 12 ≥ 10 → length 3. start 1: 2, 8, 9, 16 ≥ 10 → length 4. start 2: 6, 7, 14 ≥ 10 → length 3.
  3. start 3: 1, 8, 11 ≥ 10 → length 3. start 4: 7, 10 ≥ 10 → length 2. start 5: 3 never reaches 10.
  4. The smallest length seen is 2.

Python

class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        n = len(nums)
        best = n + 1                                # longer than any real subarray
        for start in range(n):
            total = 0
            for end in range(start, n):             # grow the subarray one value at a time
                total += nums[end]
                if total >= target:
                    best = min(best, end - start + 1)
                    break                           # a longer subarray from this start cannot be shorter
        return best if best <= n else 0
Time O(n²)Space O(1)

Each start may scan to the end of the list; only a few numbers are stored.

When to use: Only to define the problem; too slow for large lists.

Let prefix[i] be the sum of the first i values (prefix[0] = 0). The subarray nums[start:end] sums to prefix[end] - prefix[start]. For a fixed start we need the smallest end with prefix[end] >= prefix[start] + target.

Because every value is positive, prefix is strictly increasing, so that end can be found with binary search (bisect_left) instead of a scan. That is O(log n) per start and O(n log n) overall. It also needs the O(n) prefix list.

Dry run

  1. target = 10, nums = [4, 2, 6, 1, 7, 3] → prefix = [0, 4, 6, 12, 13, 20, 23]
  2. start 0: first prefix ≥ 0 + 10 is 12, at index 3 → length 3. start 4: first prefix ≥ 13 + 10 = 23 is at index 6 → length 2.
  3. start 5: no prefix reaches 20 + 10 = 30 (end would be 7 > n), so it is skipped. Best length: 2.

Python

class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        n = len(nums)
        prefix = [0] * (n + 1)                      # prefix[i] = sum of nums[:i], strictly increasing
        for i, x in enumerate(nums):
            prefix[i + 1] = prefix[i] + x
        best = n + 1
        for start in range(n):
            # first end whose prefix reaches prefix[start] + target (binary search)
            end = bisect.bisect_left(prefix, prefix[start] + target)
            if end <= n:                            # end == n + 1 means no such end exists
                best = min(best, end - start)
        return best if best <= n else 0
Time O(n log n)Space O(n)

n binary searches over a list of n + 1 prefix sums; the prefix list holds n + 1 numbers.

When to use: The usual follow-up when an interviewer asks for O(n log n). With negative numbers the prefix sums stop being sorted, and the binary search no longer works.

Keep a window [left, right] and its running sum total. For each right:

  1. add nums[right] to total;
  2. while total >= target: record the length right - left + 1, subtract nums[left] and move left forward.

Positive values make this safe: once a window reaches the target, shrinking from the left shows how short it can get, and a window can never need to move left backwards. Each index enters the window once and leaves it once, so the total work is O(n) with O(1) extra memory.

Dry run

  1. target = 10, nums = [4, 2, 6, 1, 7, 3], left = 0, total = 0
  2. right = 0, 1: total 4, then 6 (below 10). right = 2: total 12 ≥ 10 → length 3 (best 3). Remove 4 → total 8 < 10.
  3. right = 3: total 9. right = 4: total 16 → length 4; remove 2 → 14 → length 3; remove 6 → 8 < 10.
  4. right = 5: total 11 → length 3; remove 1 → 10 → length 2 (best 2); remove 7 → 3. The answer is 2.

Python

class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        left = 0
        total = 0                                   # sum of nums[left .. right]
        best = len(nums) + 1                        # longer than any real window
        for right, x in enumerate(nums):
            total += x                              # grow the window on the right
            while total >= target:                  # big enough: shrink while it stays big enough
                best = min(best, right - left + 1)
                total -= nums[left]
                left += 1
        return best if best <= len(nums) else 0
Time O(n)Space O(1)

left and right each move forward at most n times; only a few numbers are stored.

When to use: The standard answer. The nested while looks quadratic, but left only ever moves forward.

Common mistakes

  • Using if total >= target instead of while. After one shrink the window can still be big enough, and a shorter valid window is missed: with target = 10 and [1, 1, 1, 10], a single if records length 4 and moves on, instead of shrinking down to the single value 10 (length 1).
  • Applying this window to lists with negative numbers. Removing a negative value would raise the sum, so 'shrink while big enough' can skip answers. The window needs positive values (see Shortest Subarray with Sum at Least K).
  • An off-by-one length. The window [left, right] holds right - left + 1 values.
  • Returning the sentinel when nothing was found. If best starts at n + 1 (or infinity), convert it to 0 at the end; a list whose total is below target has no valid window.
  • Recomputing sum(nums[left:right + 1]) for every window. That hides an O(n) cost inside the loop and turns the scan back into O(n²).

Python notes

  • best = len(nums) + 1 is a sentinel for "no window found yet"; return best if best <= len(nums) else 0 turns it back into 0. float("inf") works as a sentinel too; just test for it before returning.
  • bisect.bisect_left(prefix, v) returns the first index of a sorted list whose value is at least v. The prefix sums are strictly increasing because every value is positive, so binary search is valid.
  • itertools.accumulate(nums, initial=0) builds the prefix sums in one call.
  • enumerate(nums) yields (right, x) pairs, so the loop needs no nums[right] lookup.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Subarray Sum Equals K LC 560 — count subarrays with an exact sum when values may be negative: the window no longer works, so use prefix sums and a hash map that counts how often each prefix sum has occurred.
  • Shortest Subarray with Sum at Least K LC 862 — this exact question with negative numbers allowed: prefix sums plus a monotonic deque of candidate start positions.
  • Subarray Product Less Than K LC 713 — count subarrays whose product stays below k: the same window, and each right adds right - left + 1 new subarrays at once.
  • Minimum Window Substring LC 76 — the same 'grow until valid, then shrink while still valid' pattern, with letter counts instead of a sum.
  • Minimum Operations to Reduce X to Zero LC 1658 — taking values from both ends adds up to x exactly when the untouched middle sums to total - x: find the longest middle window with that sum.
  • Max Consecutive Ones III LC 1004 — the longest window that may contain at most k zeros: the window must stay valid instead of reaching a target.
