Majority Element II Medium 250

LeetCode #229 ↗
Status

Find every value that appears more than n/3 times in a list, using O(1) extra space.

Problem

You are given a list of integers nums with n entries. Return every value that appears more than n / 3 times (rounded down: n // 3). The answers can come back in any order, and the result may be empty.

  • Exactly equal to n // 3 is not enough; the count must be strictly greater.
  • Follow-up: do it in O(n) time with O(1) extra space.

Examples

Example 1
Input: nums = [3, 2, 3, 1, 3, 2, 2]
Output: [3, 2]
n = 7, so a winner must appear more than 7 // 3 = 2 times. Both 3 and 2 appear 3 times; 1 appears once.
Example 2
Input: nums = [5, 1, 5, 2, 5, 3, 4]
Output: [5]
Only 5 appears 3 times. Every other value appears once.
Example 3
Input: nums = [1, 2]
Output: [1, 2]
n // 3 = 0, so any value that appears at all qualifies.

Constraints

  • 1 <= len(nums) <= 5 * 10^4
  • -10^9 <= nums[i] <= 10^9
  • follow-up: O(n) time, O(1) extra space

Think first try before reading the solution

How many different values can each appear more than n/3 times? Try to fit three of them into a list of n numbers.
A dictionary of counts solves it in O(n) time, but uses O(n) space. Since only a couple of values can possibly win, do you really have to remember a count for every value?
Track two candidates with a vote count each. A value equal to a candidate adds a vote; a value equal to neither takes a free slot, or, when both candidates hold votes, removes one vote from each. The survivors are only candidates, so count them properly in a second pass.

Key idea

First ask how many answers there can be. A winner appears more than n/3 times. Three different winners would need more than 3 × n/3 = n numbers, and the list only has n. So there are at most two answers, and two suspects are enough.

Boyer-Moore voting finds suspects by cancelling. Keep two candidates, each with a vote count. A value that equals a candidate gives it a vote. A value that equals neither takes an empty slot (a candidate with 0 votes), and if both candidates hold votes it removes one vote from each. That last move throws away three different values at once: the new value, candidate 1 and candidate 2.

Why does it work? Each cancellation removes three different values, so at most n/3 cancellations can happen, and each one removes at most one copy of any single value. A value that appears more than n/3 times therefore always keeps a copy that is never cancelled, so it finishes as a candidate.

The reverse is not true: a finishing candidate may be a loser (in [1, 2, 3, 4] the survivors win nothing). The vote counts are leftovers of the cancelling, not real frequencies. So a second pass counts each candidate for real and keeps only those above n/3.

Approaches from the obvious one to the one you want in an interview

For every value, count how often it occurs by scanning the whole list, and keep it when the count is above n // 3 and it is not in the answer already. At most two values can pass, so the answer list never grows beyond two entries.

Every one of the n values triggers a scan of n entries, so the cost is O(n²). It is easy to get right and a good way to check the faster solutions against.

Dry run

  1. nums = [3, 2, 3, 1, 3, 2, 2], limit = 7 // 3 = 2
  2. 3 occurs 3 times, 3 > 2 → winners = [3]
  3. 2 occurs 3 times, 3 > 2 → winners = [3, 2]
  4. later 3s and 2s are already in winners; 1 occurs once → skipped

Python

class Solution:
    def majorityElement(self, nums: List[int]) -> List[int]:
        limit = len(nums) // 3                 # a winner must appear MORE than this many times
        winners = []
        for x in nums:
            if x not in winners and nums.count(x) > limit:    # nums.count scans the whole list
                winners.append(x)
        return winners
Time O(n²)Space O(1)

n values, each followed by an O(n) scan. winners never holds more than two numbers.

When to use: Only as a baseline or a checker for the faster versions.

One pass builds a dictionary value -> count. A second loop over the dictionary keeps the values whose count is above n // 3. That is O(n) time, which is as fast as it gets.

The cost is memory: if all values are different the dictionary holds n entries. Since at most two values can win, it feels wasteful to remember a count for every value, and that is what the follow-up's O(1) space requirement removes.

Dry run

  1. nums = [3, 2, 3, 1, 3, 2, 2] → counts = {3: 3, 2: 3, 1: 1}
  2. limit = 7 // 3 = 2; keep counts above 2 → [3, 2]

Python

class Solution:
    def majorityElement(self, nums: List[int]) -> List[int]:
        counts = {}                            # value -> how many times it appears
        for x in nums:
            counts[x] = counts.get(x, 0) + 1
        limit = len(nums) // 3
        return [value for value, c in counts.items() if c > limit]
Time O(n)Space O(n)

One pass over the list plus one pass over at most n dictionary entries; the dictionary can hold n keys.

When to use: The practical answer when memory is no concern. State the O(n) space cost.

At most two values can win, so keep two candidates and a vote count for each. For every x:

  1. x equals candidate 1 → candidate 1 gets a vote.
  2. x equals candidate 2 → candidate 2 gets a vote.
  3. else, candidate 1 has 0 votes → x becomes candidate 1 with 1 vote.
  4. else, candidate 2 has 0 votes → x becomes candidate 2 with 1 vote.
  5. else → x and both candidates are three different values; each candidate loses one vote.

The checks for a match come first, so a value never occupies both slots. After the pass, any value above n/3 is guaranteed to be one of the two candidates, but a candidate is not guaranteed to be a winner, so a second pass counts them for real.

The state is four variables, so the extra space is O(1), and the two passes cost O(n).

Dry run

  1. nums = [3, 2, 3, 1, 3, 2, 2], no candidates yet
  2. 3 → candidate 1 (1 vote); 2 → candidate 2 (1 vote); 3 → candidate 1 now has 2 votes
  3. 1 matches neither and both hold votes → both lose one vote: (3, 1 vote), (2, 0 votes)
  4. 3 → candidate 1 has 2 votes; 2 equals candidate 2, which has 0 votes → starts again with 1 vote; 2 → 2 votes
  5. candidates 3 and 2. Pass 2: 3 occurs 3 times and 2 occurs 3 times, both above 2 → [3, 2]

Python

class Solution:
    def majorityElement(self, nums: List[int]) -> List[int]:
        cand1, count1 = None, 0                # two candidates with their vote counts
        cand2, count2 = None, 0
        for x in nums:                         # pass 1: find at most two candidates
            if x == cand1:                     # a match always votes first
                count1 += 1
            elif x == cand2:
                count2 += 1
            elif count1 == 0:                  # a free slot: x becomes a candidate
                cand1, count1 = x, 1
            elif count2 == 0:
                cand2, count2 = x, 1
            else:                              # x and both candidates are three different values:
                count1 -= 1                    # they cancel, one vote lost by each candidate
                count2 -= 1
        limit = len(nums) // 3                 # pass 2: keep the candidates that really exceed n/3
        return [c for c in (cand1, cand2) if c is not None and nums.count(c) > limit]
Time O(n)Space O(1)

Two linear passes (nums.count runs for at most two candidates); only four variables of state.

When to use: The follow-up answer: linear time and constant space.

Common mistakes

  • Skipping the second pass. The survivors of the voting are only candidates: in [5, 1, 5, 2, 5, 3, 4] the second survivor is 3, which appears once and must not be returned.
  • Starting both candidates at the same placeholder such as 0. For [0, 0, 0] both slots end up holding 0 and the answer lists 0 twice. Start with None (and check is not None), so a real 0 is never mistaken for 'no candidate'.
  • Testing 'free slot' before 'matches a candidate'. In [1, 2, 3, 2] the second 2 would be adopted as candidate 1 while it is already candidate 2, and the answer contains 2 twice. Check for a match with either candidate first.
  • Using >= instead of >. In [2, 2, 9, 9, 3, 3] every value appears exactly n/3 = 2 times, so the answer is empty; with >= the code would wrongly return 2 and 9.
  • Assuming there are always two answers. The result can be empty, one value, or two values.

Python notes

  • Counter(nums) builds the same value-to-count dictionary in one call; counts.items() yields (value, count) pairs.
  • n // 3 is floor division. For whole-number counts, count > n / 3 and count > n // 3 are the same test.
  • x == cand1 with cand1 = None is fine in Python: comparing an int with None is simply False.
  • nums.count(c) scans the list once. Calling it for at most two candidates keeps the second pass at O(n).

Follow-up questions

What an interviewer might ask next, and what changes.

  • Majority Element LC 169 — more than n/2 instead of n/3: one candidate and one counter. The problem guarantees a majority exists, so the second pass can be skipped.
  • Top K Frequent Elements LC 347 — no threshold, just the k most frequent values: voting does not help, so count and then pick with a heap or buckets.
  • More than n/k times, for any k — keep k - 1 candidates with counters (the Misra-Gries summary). When a value matches no candidate and every slot is taken, subtract one from all counters.
  • What if the numbers arrive as a stream? — the two-candidate scan only needs one pass and four variables, so it fits a stream; the verification pass needs a second look at the data, so a stream can only report candidates.
