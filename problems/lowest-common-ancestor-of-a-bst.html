Lowest Common Ancestor of a Binary Search Tree Medium

LeetCode #235 ↗
Status

Find the lowest node that has both given nodes at or below it, using the ordering of a binary search tree to steer.

Problem

Given a binary search tree (BST) and two of its nodes p and q, return their lowest common ancestor (LCA): the deepest node that has both p and q among its descendants. A node counts as a descendant of itself, so if p is an ancestor of q the answer is p.

In a BST every value in a node's left subtree is smaller than the node, and every value in its right subtree is larger. All values are unique, and both p and q are in the tree.

A note on this site: LeetCode passes p and q as TreeNode objects. Our test runner passes plain numbers, so every solution below also has a small adapter, lcaValue(root, p_val, q_val), that finds the two nodes by value, calls the real method and returns the value of the answer. The adapter is not part of the LeetCode answer.

Examples

Example 1
Input: root = [6, 2, 8, 0, 4, 7, 9, None, None, 3, 5], p = 2, q = 8
Output: 6
2 is in the left subtree of 6 and 8 is in the right subtree, so 6 is the lowest node above both.
Example 2
Input: root = [6, 2, 8, 0, 4, 7, 9, None, None, 3, 5], p = 2, q = 4
Output: 2
A node can be its own ancestor: 4 is below 2, so the answer is 2 itself, not 6.
Example 3
Input: root = [2, 1], p = 2, q = 1
Output: 2

Constraints

  • 2 <= number of nodes <= 10^5
  • -10^9 <= Node.val <= 10^9
  • all Node.val are unique
  • p != q
  • p and q both exist in the BST

Key idea

In a BST, comparing a value with a node tells you which side that value is on: smaller means left, larger means right. Stand at the root with both targets in mind.

  • If both targets are smaller than the node, they are both in its left subtree, so the lowest common ancestor is in the left subtree as well. Move left.
  • If both are larger, move right in the same way.
  • Otherwise the targets are split (one smaller, one larger) or one of them is this node. Then this node is above both, and no child can be: the left child has at most the smaller target below it, and the right child at most the larger one. So this node is the answer.

Put differently, the LCA is the first node on the way down whose value lies between p and q (inclusive). Every step throws away a whole subtree, so the walk follows a single path from the root: O(h) time, which is O(log n) when the tree is balanced.

In an ordinary binary tree there is no ordering to steer by, which is why that version of the problem needs a full search.

Approaches from the obvious one to the one you want in an interview

Forget the ordering for a moment and use the definition. The ancestors of p are the nodes on the path from the root down to p, and the same for q. The two paths start together at the root and split at some point; the last node they share is the lowest common ancestor.

To get a path, search the tree with DFS: add each node on the way down, and remove it again (backtrack) when its subtree does not contain the target. This works for any binary tree. Because it ignores the BST ordering it may visit every node, so the time is O(n).

Dry run

  1. root = [6, 2, 8, 0, 4, 7, 9, None, None, 3, 5], p = 3, q = 5
  2. path to 3: 6, 2, 4, 3
  3. path to 5: 6, 2, 4, 5
  4. walking both paths together they agree on 6, 2, 4 and split after that → the last shared node is 4.

Python

class Solution:
    def lowestCommonAncestor(self, root: TreeNode, p: TreeNode, q: TreeNode) -> TreeNode:
        def path_to(node, target, path):
            """Append the nodes from `node` down to `target` to `path`; return True if target was found."""
            if node is None:
                return False
            path.append(node)
            if node is target:
                return True
            if path_to(node.left, target, path) or path_to(node.right, target, path):
                return True
            path.pop()                              # target is not below this node: undo and backtrack
            return False

        path_p, path_q = [], []
        path_to(root, p, path_p)
        path_to(root, q, path_q)
        lca = root
        for a, b in zip(path_p, path_q):            # the two paths agree until they split
            if a is not b:
                break
            lca = a
        return lca

    # ---- Adapter for this site's test runner (not part of the LeetCode answer) ----
    # LeetCode passes p and q as TreeNode objects; our runner passes plain values. So: find the two
    # nodes by value, call the real method above, and return the value of the node it gives back.
    def lcaValue(self, root, p_val, q_val):
        def find(val):
            node = root
            while node.val != val:                  # ordinary BST search; both values are guaranteed to exist
                node = node.left if val < node.val else node.right
            return node

        return self.lowestCommonAncestor(root, find(p_val), find(q_val)).val
Time O(n)Space O(h)

The DFS may visit every node to find each target. The paths and the recursion stack are as long as the tree is tall.

When to use: When the tree is an ordinary binary tree (no ordering). For a BST the next two approaches are much faster.

Use the ordering to avoid searching. Look at the current node and compare it with both targets:

  • both p and q are smaller → the LCA is in the left subtree, so recurse left;
  • both are larger → recurse right;
  • otherwise the targets split here (or one of them is this node) → this node is the LCA.

Each call throws away a whole subtree, so the recursion follows a single path from the root: O(h) time. Because p and q are guaranteed to exist, the recursion always stops at a node and never runs off the tree.

Dry run

  1. root = [6, 2, 8, 0, 4, 7, 9, None, None, 3, 5], p = 3, q = 5
  2. node 6: 3 < 6 and 5 < 6 → both on the left → go left
  3. node 2: 3 > 2 and 5 > 2 → both on the right → go right
  4. node 4: 3 < 4 < 5 → they split here → return 4
  5. the callers lca(2) and lca(6) just pass 4 back up → answer 4

Python

class Solution:
    def lowestCommonAncestor(self, root: TreeNode, p: TreeNode, q: TreeNode) -> TreeNode:
        if p.val < root.val and q.val < root.val:      # both targets are in the left subtree
            return self.lowestCommonAncestor(root.left, p, q)
        if p.val > root.val and q.val > root.val:      # both targets are in the right subtree
            return self.lowestCommonAncestor(root.right, p, q)
        return root                                    # they split here, or root is p or q itself

    # nodes by value, call the real method above, and return the value of the node it gives back.

                node = node.left if val < node.val else node.right
            return node

        return self.lowestCommonAncestor(root, find(p_val), find(q_val)).val
Time O(h)Space O(h)

One path from the root, at most the height h of the tree: log n when balanced, n for a chain. The call stack is as deep as that path.

When to use: The clearest statement of the idea, and the natural first answer for a BST.

Watch it run

The recursive version never does anything after its recursive call: it just returns what it receives. A call like that can be replaced by moving a pointer. Keep node, starting at the root; move it left or right by the same two tests; return it as soon as neither test applies.

Same O(h) time, but only one variable of extra memory, and no recursion limit even for a 10⁵-node chain. This is the version to write in an interview once you have explained the idea.

Dry run

  1. root = [6, 2, 8, 0, 4, 7, 9, None, None, 3, 5], p = 2, q = 4, node = 6
  2. 6: 2 < 6 and 4 < 6 → both are smaller → node = node.left (now 2)
  3. 2: 'both smaller' is false (2 is not < 2) and 'both larger' is false (2 is not > 2) → return node 2, which is p itself.

Python

class Solution:
    def lowestCommonAncestor(self, root: TreeNode, p: TreeNode, q: TreeNode) -> TreeNode:
        node = root
        while node:
            if p.val < node.val and q.val < node.val:    # both targets are on the left
                node = node.left
            elif p.val > node.val and q.val > node.val:  # both targets are on the right
                node = node.right
            else:                                        # split here, or node is p or q itself
                return node
        return None                                      # unreachable: p and q are guaranteed to exist

    # ---- Adapter for this site's test runner (not part of the LeetCode answer) ----
    # LeetCode passes p and q as TreeNode objects; our runner passes plain values. So: find the two
    # nodes by value, call the real method above, and return the value of the node it gives back.
    def lcaValue(self, root, p_val, q_val):
        def find(val):
            node = root
            while node.val != val:                       # ordinary BST search; both values are guaranteed to exist
                node = node.left if val < node.val else node.right
            return node

        return self.lowestCommonAncestor(root, find(p_val), find(q_val)).val
Time O(h)Space O(1)

The same single path as the recursion, with one pointer instead of a call stack.

When to use: The version to write in an interview, and the only safe one for a very deep, chain-like BST.

Common mistakes

  • Using <= or >= in the 'go left' and 'go right' tests. If p.val == node.val, then p is this node and the answer is this node, but <= lets the walk continue past it. In example 2 (p = 2, q = 4) it slides past node 2 and returns 3 instead of 2. Use strict < and >.
  • Assuming p.val < q.val. The targets can arrive in either order, so test both of them against the node every time (or sort them first with min and max).
  • Returning the parent of p when p is an ancestor of q. A node is allowed to be its own ancestor.
  • Treating the tree as an ordinary binary tree and searching both sides. The result is right, but it ignores the ordering and costs O(n) instead of O(h).
  • Using recursion on a degenerate BST. With up to 10⁵ nodes in a chain the recursion is deeper than Python's default limit of 1000 frames; the loop version has no such limit.

Python notes

  • Compare .val, not the nodes: TreeNode defines no ordering, so p < node raises a TypeError.
  • lo, hi = min(p.val, q.val), max(p.val, q.val) removes the need to know which target is smaller: the LCA is the first node with lo <= node.val <= hi.
  • while node: works because a TreeNode object is truthy and None is falsy.
  • The adapter lcaValue only exists so this site can test the solution with plain numbers. On LeetCode you submit just lowestCommonAncestor.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Lowest Common Ancestor of a Binary Tree LC 236 — no ordering to steer by: search both subtrees, and the node that sees one target on each side (or is a target itself) is the LCA.
  • Lowest Common Ancestor of Deepest Leaves LC 1123 — the LCA of all deepest nodes: a bottom-up recursion that returns the depth together with the best candidate node.
  • Step-By-Step Directions From a Binary Tree Node to Another LC 2096 — find the LCA of the start and destination; the answer is one U per step up from the start to the LCA, then the L/R moves down to the destination.
  • Insert into a Binary Search Tree LC 701 — the same compare-and-go walk, but you keep going until you fall off the tree and attach the new node at that empty spot.
  • What if p or q might not be in the tree? — the walk would end at a wrong node. Check first that both values exist (each lookup is an O(h) BST search), then run the walk.
