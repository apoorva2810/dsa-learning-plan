Burst Balloons Hard

LeetCode #312 ↗
Status

Burst every balloon in a row, in the best order, to collect the most coins.

Problem

You are given nums, the numbers painted on n balloons that stand in a row. You must burst all of them, one at a time, in an order you choose.

Bursting balloon i earns left * nums[i] * right coins, where left and right are the numbers on the balloons currently next to it. Balloons that are already burst are gone, so the neighbours change as the game goes on. If there is no balloon on one side, that side counts as a balloon with the number 1. This imaginary balloon cannot be burst and earns nothing.

Return the maximum number of coins you can collect.

Examples

Example 1
Input: nums = [3, 1, 5, 8]
Output: 167
Burst 1 (3 · 1 · 5 = 15), then 5 (3 · 5 · 8 = 120), then 3 (1 · 3 · 8 = 24), then 8 (1 · 8 · 1 = 8). Total 15 + 120 + 24 + 8 = 167.
Example 2
Input: nums = [1, 5]
Output: 10
Burst 1 first: 1 · 1 · 5 = 5, then 5: 1 · 5 · 1 = 5. Bursting 5 first earns 5 and then only 1 for the other balloon, so 6 in total.
Example 3
Input: nums = [7]
Output: 7
The only balloon has two imaginary neighbours: 1 · 7 · 1.

Constraints

  • 1 <= len(nums) <= 300
  • 0 <= nums[i] <= 100

Think first try before reading the solution

Deciding which balloon to burst first leads nowhere: afterwards two former neighbours become adjacent, so the balloons on its left and on its right are tangled together. What if you decide which balloon is burst last?
Look at a stretch between two balloons l and r that are still standing, and let k be the last balloon burst inside it. When k goes, everything else between l and r is already gone, so its neighbours are exactly l and r. It earns nums[l] * nums[k] * nums[r]. The balloons between l and k and the balloons between k and r can no longer influence each other, so each side is the same problem on a shorter stretch.
Pad nums with a 1 on both ends (call it a). Let dp[l][r] be the best coins from bursting every balloon strictly between positions l and r. Then dp[l][r] is the maximum over l < k < r of dp[l][k] + a[l] * a[k] * a[r] + dp[k][r], and dp[l][l + 1] = 0. Fill the table by increasing r - l; the answer is dp[0][n + 1].

Key idea

The obvious question, "which balloon do I burst first?", is a trap. Once a balloon is gone, its two neighbours become adjacent, so the value of everything on the left depends on what happens on the right. The pieces cannot be solved separately.

Reverse the question. Take a stretch of balloons between two balloons l and r that stay standing for now, and ask which balloon k inside the stretch is burst last. When k finally goes, every other balloon between l and r has already burst, so its neighbours are exactly l and r, whatever happened earlier. It earns a[l] * a[k] * a[r]. Before that moment, k stood between the left part and the right part like a wall, so the balloons on the left only ever saw l and k as neighbours, and the balloons on the right only saw k and r. The two sides are independent subproblems of the same shape.

Pad the row with a 1 at each end, so every real balloon has two neighbours. These padding balloons are never burst. Let dp[l][r] be the best coins from bursting every balloon strictly between positions l and r:

dp[l][r] = max over l < k < r of ( dp[l][k] + a[l] * a[k] * a[r] + dp[k][r] ), and dp[l][l + 1] = 0 (nothing between).

The answer is dp[0][n + 1]. A cell reads dp[l][k] from its own row, to the left, and dp[k][r] from its own column, further down. Filling row by row therefore fails; fill by increasing interval length r - l, so every shorter interval is ready. There are about n²/2 intervals and up to n choices of k for each, so the work is O(n³) with O(n²) memory.

Approaches from the obvious one to the one you want in an interview

Play the game literally. With the row of balloons still standing, try each one as the next to burst: it earns left * value * right coins from its current neighbours, and then you solve the shorter row that remains. Take the best total. This tries every possible order, so it is always correct.

The number of orders is n! (n choices, then n - 1, then n - 2, and so on). For 8 balloons that is 40,320 orders and about 110,000 recursive calls; for 12 balloons it is almost half a billion; for 300 it is out of the question. Remembering the answer for every set of remaining balloons would merge repeated states but leaves up to 2^n of them, which is still hopeless. The next approach changes the question instead of the bookkeeping.

Dry run

  1. nums = [3, 1, 5], imaginary 1s on both sides. 3! = 6 orders.
  2. Burst 3 first: 1 · 3 · 1 = 3, then [1, 5]: best is 1 then 5 = 5 + 5 → total 13.
  3. Burst 5 first: 1 · 5 · 1 = 5, then [3, 1]: best is 3 + 3 → total 11.
  4. Burst 1 first: 3 · 1 · 5 = 15, then [3, 5]: best is 3 then 5 = 15 + 5 → total 35.
  5. The maximum over all orders is 35.

Python

class Solution:
    def maxCoins(self, nums: List[int]) -> int:
        def best(balloons: tuple) -> int:
            """Most coins from bursting every balloon in this row, in the best order."""
            if not balloons:
                return 0
            top = 0
            for i, value in enumerate(balloons):               # try every balloon as the NEXT one to burst
                left = balloons[i - 1] if i > 0 else 1         # missing neighbours count as 1
                right = balloons[i + 1] if i + 1 < len(balloons) else 1
                rest = balloons[:i] + balloons[i + 1:]         # the row after it bursts
                top = max(top, left * value * right + best(rest))
            return top

        return best(tuple(nums))
Time O(n!)Space O(n²)

n! orders. The recursion is n levels deep and each level holds a tuple of up to n numbers.

When to use: Only to understand the problem, or as a checker for the DP on up to about 8 balloons.

Change the question to "which balloon in this stretch is burst last?". Pad nums into a = [1] + nums + [1] and let solve(l, r) be the most coins from bursting everything strictly between positions l and r. For each k between them, treat k as the last balloon: its neighbours are the walls l and r, it earns a[l] * a[k] * a[r], and the two sides are the independent subproblems solve(l, k) and solve(k, r). Take the best k; an empty stretch (r = l + 1) gives 0.

There are only about n²/2 different stretches (l, r), and @cache (memoisation: store each result the first time it is computed) solves each once, with a loop of up to n choices for k. Total O(n³).

Dry run

  1. nums = [3, 1, 5], a = [1, 3, 1, 5, 1], solve(0, 4). The last balloon is 3, 1 or 5.
  2. k = 3 (5 last): solve(0, 3) + 1 · 5 · 1 + solve(3, 4); solve(3, 4) = 0, nothing between.
  3. solve(0, 3): the balloons 3 and 1 between walls 1 and 5. 3 last: 0 + 1 · 3 · 5 + solve(1, 3), and solve(1, 3) = 3 · 1 · 5 = 15, so 30. 1 last gives only 8. So solve(0, 3) = 30.
  4. k = 3 gives 30 + 5 + 0 = 35. The other choices: k = 1 gives 33 and k = 2 gives 9.
  5. solve(0, 4) = 35.

Python

class Solution:
    def maxCoins(self, nums: List[int]) -> int:
        a = [1] + nums + [1]                                   # imaginary balloons at both ends

        @cache                                                 # one stored answer per stretch (l, r)
        def solve(l: int, r: int) -> int:
            """Most coins from bursting every balloon strictly between positions l and r."""
            best = 0                                           # nothing between l and r: 0 coins
            for k in range(l + 1, r):                          # k is the LAST balloon burst between l and r
                coins = a[l] * a[k] * a[r]                     # its neighbours are exactly the walls l and r
                best = max(best, solve(l, k) + coins + solve(k, r))
            return best

        return solve(0, len(a) - 1)
Time O(n³)Space O(n²)

About n²/2 stretches, each trying up to n values of k. The cache and the recursion stack are O(n²) and O(n).

When to use: The quickest correct version once the 'last balloon' idea is clear.

Fill the same table without recursion. Pad the row (a = [1] + nums + [1]), set dp[l][l + 1] = 0, and compute the other cells by increasing length r - l, from 2 up to n + 1. When the table reaches a cell dp[l][r], every shorter interval inside it is already done: for each k in between, dp[l][k] and dp[k][r] are both shorter. Each cell keeps the best total over its choices of k.

Row-by-row order does not work for this table, because dp[k][r] lives in a row further down. Going by length does, and it is the standard shape for interval DP. The answer is the top-right cell dp[0][n + 1].

Dry run

  1. nums = [3, 1, 5], a = [1, 3, 1, 5, 1], table 5 × 5. dp[l][l + 1] = 0 for every l.
  2. Length 2 (one balloon between the walls): dp[0][2] = 1 · 3 · 1 = 3, dp[1][3] = 3 · 1 · 5 = 15, dp[2][4] = 1 · 5 · 1 = 5.
  3. Length 3: dp[0][3] = max(k = 1: 0 + 15 + 15, k = 2: 3 + 5 + 0) = 30; dp[1][4] = max(k = 2: 0 + 3 + 5, k = 3: 15 + 15 + 0) = 30.
  4. Length 4: dp[0][4] = max(k = 1: 0 + 3 + 30, k = 2: 3 + 1 + 5, k = 3: 30 + 5 + 0) = 35.

Python

class Solution:
    def maxCoins(self, nums: List[int]) -> int:
        a = [1] + nums + [1]                                   # imaginary balloons at both ends
        size = len(a)
        # dp[l][r]: most coins from bursting every balloon strictly between l and r (l and r stay)
        dp = [[0] * size for _ in range(size)]
        for length in range(2, size):                          # distance between the walls; 1 means nothing between
            for l in range(size - length):
                r = l + length
                for k in range(l + 1, r):                      # k = the last balloon burst between l and r
                    coins = dp[l][k] + a[l] * a[k] * a[r] + dp[k][r]
                    if coins > dp[l][r]:
                        dp[l][r] = coins
        return dp[0][size - 1]
Time O(n³)Space O(n²)

About n³/6 executions of the innermost line (4.5 million for n = 300); the table holds (n + 2)² numbers.

When to use: The interview answer: no recursion, and it shows the fill order clearly.

Common mistakes

  • Picking the balloon that is burst first and charging it its original neighbours, as if nothing had been burst yet. Then the sub-stretches still assume their original borders. On [3, 1, 5, 8] such a recurrence returns 98 instead of 167. Choose the last balloon: its neighbours are then known walls.
  • Greedy orders, such as bursting the smallest balloon first. On [3, 1, 5, 8] that earns 15 + 15 + 40 + 8 = 78, far below 167. Cheap balloons are often the best ones to keep as walls.
  • Forgetting the padding. Without the two extra 1s, the first and last balloons need special cases. Pad once with a = [1] + nums + [1] and let k run only over the real balloons.
  • Mixing inclusive and exclusive bounds. Here l and r are the two balloons that stay, and k ranges over l + 1 .. r - 1. The answer is dp[0][n + 1]. Using range(l, r + 1) for k would burst a wall.
  • Filling the table row by row. dp[l][r] needs dp[k][r] from a row below, which a top-to-bottom pass has not computed yet. Loop over interval lengths: for length in range(2, n + 2).

Python notes

  • a = [1] + nums + [1] builds a new padded list and leaves nums untouched.
  • for length in range(2, size): for l in range(size - length): r = l + length is the standard interval loop. Here l and r are the two walls, so the interval itself is l + 1 .. r - 1, and length = 2 is the smallest interval that contains a balloon.
  • max(dp[l][k] + a[l] * a[k] * a[r] + dp[k][r] for k in range(l + 1, r)) is a compact form of the inner loop. The generator is never empty when r - l >= 2, so no default value is needed.
  • For n = 300 the innermost line runs about 4.5 million times, which takes roughly a second in CPython.
  • @cache keys on (l, r). The recursion is at most n + 2 frames deep, inside Python's default limit.
  • Python integers do not overflow. In a fixed-width language the answer can grow to about 3 · 10^8 here, which still fits in 32 bits.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Minimum Cost to Cut a Stick LC 1547 — the same 'choose the last one' trick: the last cut inside a piece splits it into two independent pieces and costs the piece's length. Add the two ends of the stick as walls, like the padded 1s here.
  • Minimum Score Triangulation of Polygon LC 1039 — the last triangle drawn on the edge (l, r) has some apex k, and costs v[l] * v[k] * v[r]. It is the same recurrence with min instead of max, and it is also the classic Matrix Chain Multiplication.
  • Minimum Cost to Merge Stones LC 1000 — piles are merged k at a time, so an interval needs a third index for how many piles it has been reduced to before the final merge.
  • Remove Boxes LC 546 — interval DP where the value of removing a block also depends on how many equal boxes have already been attached to the stretch. The state grows to dp[l][r][extra].
  • Longest Palindromic Substring LC 5 — the other interval table in this list: is_pal[i][j] depends on is_pal[i + 1][j - 1], and it is also filled by increasing length.
  • Print the order of bursts, not just the coins — remember the best k for every cell. The order is then a post-order walk: the order for (l, k), then the order for (k, r), then k itself.
