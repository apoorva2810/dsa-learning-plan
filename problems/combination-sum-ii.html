Combination Sum II Medium

LeetCode #40 ↗
Status

Find every combination from a list with repeated numbers that adds up to a target, using each element at most once and listing no combination twice.

Problem

You are given a list candidates that may contain duplicates and a positive integer target. Return every unique combination of candidates that adds up to target.

  • Each element of candidates can be used at most once. If a value appears twice in the list it may appear twice in a combination, but never more often than it appears in the list.
  • The answer must not contain the same combination twice ([1, 2, 5] and [2, 1, 5] are the same combination).
  • The combinations can be returned in any order.

Examples

Example 1
Input: candidates = [10, 1, 2, 7, 6, 1, 5], target = 8
Output: [[1, 1, 6], [1, 2, 5], [1, 7], [2, 6]]
The list has two 1s, so [1, 1, 6] is allowed. [1, 7] is listed once even though either 1 could be used.
Example 2
Input: candidates = [2, 5, 2, 1, 2], target = 5
Output: [[1, 2, 2], [5]]
Example 3
Input: candidates = [4], target = 8
Output: []
There is only one 4, so 4 + 4 is not allowed.

Constraints

  • 1 <= len(candidates) <= 100
  • 1 <= candidates[i] <= 50
  • 1 <= target <= 30

Think first try before reading the solution

Compare with Combination Sum. What changes when every element can be used only once? Which index should the recursive call continue from?
With repeated values, two different positions hold the same number, so the same combination can be found twice (once through the first 1, once through the second). Sorting puts equal values next to each other, which makes repeats easy to spot.
Sort. Loop i from start, and recurse with i + 1. Skip candidates[i] when i > start and it equals candidates[i - 1]. Stop the loop when candidates[i] > remaining.

Key idea

This is Combination Sum with two changes, and each change is one line.

  • Each element at most once → recurse with i + 1 instead of i, so a call can only use elements after the one just chosen.
  • Duplicates in the input, none in the output → sort, then skip a candidate that equals the previous one at the same depth: if i > start and candidates[i] == candidates[i - 1]: continue. The earlier copy was already tried as the next element of this path, and its branch (which may use all the later elements) covers everything the later copy could build. As in Subsets II, the test is i > start, not i > 0: the second 1 in [1, 1, 6] is allowed because it is the first candidate of the next call.

The pruning from Combination Sum still applies. With the candidates sorted, the first one larger than remaining ends the loop. Every value is at least 1 and the target is at most 30, so a combination has at most 30 numbers and the recursion stays shallow even with 100 candidates.

Approaches from the obvious one to the one you want in an interview

Treat every position as a separate item and test every selection of positions: for each size from 1 to n, itertools.combinations(candidates, size) yields all of them. Keep the selections whose sum equals the target. Because the list was sorted first, two selections of the same numbers produce the same tuple, and a set removes the repeats.

It is correct and needs no tricks, but it examines all 2ⁿ − 1 selections whatever the target is. At n = 100 that is hopeless, and even at n = 20 it is a million sums for a handful of answers. Backtracking improves on it twice: it never extends a selection that already overshoots (sorted, then break), and it never generates a repeated combination in the first place.

Dry run

  1. candidates = [2, 5, 2, 1, 2], target = 5 → sorted [1, 2, 2, 2, 5].
  2. All 31 non-empty selections are summed. Four reach 5: (5,) once, and (1, 2, 2) three times (three ways to pick two of the three 2s).
  3. The set keeps one copy of each: {(5,), (1, 2, 2)}.

Python

class Solution:
    def combinationSum2(self, candidates: List[int], target: int) -> List[List[int]]:
        candidates = sorted(candidates)          # sorted: equal selections become equal tuples
        found = set()
        for size in range(1, len(candidates) + 1):
            for combo in itertools.combinations(candidates, size):   # every selection of positions
                if sum(combo) == target:
                    found.add(combo)             # a set drops repeated tuples
        return [list(combo) for combo in found]
Time O(n · 2ⁿ)Space O(n)

2ⁿ − 1 selections, each summed in O(n). Apart from the answers in found, one selection is held at a time.

When to use: A correct baseline for small n. It shows what sorting plus pruning buys.

Start from the Combination Sum solution and change two lines.

  1. Recurse with i + 1, so a call only uses elements after the one just chosen: each element is used at most once.
  2. Sort the candidates, and inside the loop skip a value that repeats its left neighbour within the same loop: if i > start and candidates[i] == candidates[i - 1]: continue.

Keep the earlier prune: if candidates[i] > remaining, break, since every later candidate is at least as big. The two tests are independent. One ends the loop, the other only skips a single candidate (continue).

Each distinct combination is built exactly once. The depth is at most target (every number is at least 1), and the prunes cut every branch that overshoots.

Dry run

  1. candidates = [2, 5, 2, 1, 2], target = 5 → sorted [1, 2, 2, 2, 5]. bt(0, 5): choose 1 → bt(1, 4): choose the first 2 → bt(2, 2): choose the next 2 (i == start, allowed) → bt(3, 0) records [1, 2, 2].
  2. Back in bt(2, 2): index 3 repeats the 2 just tried → skip; 5 > 2 → break.
  3. Back in bt(1, 4): indices 2 and 3 repeat → skip; 5 > 4 → break. Back at the root: choose 2 → bt(2, 3), where [2, 2] leaves 1 and nothing fits.
  4. Root: indices 2 and 3 repeat → skip. Choose 5 → bt(5, 0) records [5]. Result [[1, 2, 2], [5]].

Python

class Solution:
    def combinationSum2(self, candidates: List[int], target: int) -> List[List[int]]:
        candidates = sorted(candidates)          # equal values become neighbours; also enables the break
        result = []
        path = []

        def backtrack(start: int, remaining: int) -> None:
            if remaining == 0:                   # the path adds up to the target
                result.append(path[:])
                return
            for i in range(start, len(candidates)):
                if candidates[i] > remaining:    # this and every later candidate is too big: prune
                    break
                if i > start and candidates[i] == candidates[i - 1]:   # a sibling with this value was already tried
                    continue
                path.append(candidates[i])                       # choose
                backtrack(i + 1, remaining - candidates[i])      # explore; i + 1: each element used at most once
                path.pop()                                       # un-choose

        backtrack(0, target)
        return result
Time O(2ⁿ)Space O(n)

Worst case 2ⁿ branches, but far fewer in practice: branches over the target are cut by the break, and repeated values never start a duplicate branch. The recursion is at most min(n, target) deep.

When to use: The standard answer. Be ready to explain i + 1, i > start, and why break and continue differ.

Watch it run

Avoid the skip rule by construction. Count the copies of each distinct value with Counter, sort the distinct values, and let each call decide how many copies of the next value to use, from 0 up to its count. Different counts give different combinations, and one combination can be reached in only one way, so duplicates cannot occur.

backtrack(k, remaining) first tries 0 copies of counts[k] (move on to k + 1). Then it tries 1, 2, … copies while the total still fits, appending one more copy each time. Afterwards it pops all the copies it appended. It is still choose, explore, un-choose, but the choice is a repeat count. The recursion is as deep as the number of distinct values, which helps when one value repeats many times.

Dry run

  1. candidates = [2, 5, 2, 1, 2] → counts = [(1, 1), (2, 3), (5, 1)], target = 5.
  2. backtrack(0, 5) on value 1: first 0 copies → value 2: 0 copies → value 5: 0 copies leaves 5 unreached, 1 copy leaves 0 → record [5].
  3. Value 2 with 1 copy (remaining 3): 5 > 3, nothing. With 2 copies (remaining 1): nothing. A third copy would need 6 > 5, so the loop stops.
  4. Back on value 1: take its 1 copy (remaining 4) → value 2 with 2 copies leaves 0 → record [1, 2, 2]. Result [[5], [1, 2, 2]].

Python

class Solution:
    def combinationSum2(self, candidates: List[int], target: int) -> List[List[int]]:
        counts = sorted(Counter(candidates).items())      # [(value, copies), ...] in increasing value order
        result = []
        path = []

        def backtrack(k: int, remaining: int) -> None:
            if remaining == 0:
                result.append(path[:])
                return
            if k == len(counts) or counts[k][0] > remaining:   # no values left, or every remaining value is too big
                return
            value, copies = counts[k]
            backtrack(k + 1, remaining)                   # use 0 copies of this value
            taken = 0
            while taken < copies and (taken + 1) * value <= remaining:
                taken += 1
                path.append(value)                        # use `taken` copies
                backtrack(k + 1, remaining - taken * value)
            for _ in range(taken):                        # undo every copy appended above
                path.pop()

        backtrack(0, target)
        return result
Time O(2ⁿ)Space O(d)

The number of leaves is at most the product of (copies + 1) over the distinct values, which is at most 2ⁿ. d is the number of distinct values: the recursion depth.

When to use: When a value repeats many times, or when you prefer to avoid the i > start subtlety.

Common mistakes

  • Recursing with i instead of i + 1. An element could then be reused, and [4] with target 8 would wrongly return [[4, 4]].
  • Forgetting to sort. The duplicate test compares neighbours, so equal values must be adjacent, and the early break is only correct on sorted input.
  • Writing i > 0 instead of i > start. The second 1 of [1, 1, 6] is then skipped even though it is the first candidate of its call, and valid answers disappear.
  • Using break for the duplicate test. A repeat only means 'skip this one'; later candidates may still fit, so use continue. break is for 'too big'.
  • Removing duplicates only at the end (a set of sorted tuples) without pruning. It is correct, but with 100 candidates it would examine 2¹⁰⁰ selections.

Python notes

  • sorted(candidates) returns a copy. candidates.sort() would reorder the caller's list in place.
  • itertools.combinations(candidates, size) treats equal values at different positions as different items. That is why the brute force needs a set of tuples to remove repeats.
  • collections.Counter(candidates).items() gives (value, copies) pairs, the input of the third approach.
  • In the third approach the while loop appends one more copy each time and the closing for _ in range(taken): path.pop() undoes all of them. It is still choose, explore, un-choose, with a repeat count as the choice.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Combination Sum LC 39 — candidates are distinct but can be reused without limit: recurse with i instead of i + 1, and no duplicate skip is needed.
  • Combination Sum III LC 216 — exactly k different digits from 1 to 9 that add up to n: no duplicates in the input, so no skip rule, but len(path) == k becomes a second stopping condition.
  • Subsets II LC 90 — the same sort-and-skip rule without a target: every distinct subset is an answer.
  • 3Sum LC 15 — exactly three numbers that add up to 0: the 'sort and skip an equal neighbour' idea returns, but two pointers make it O(n²) instead of a search.
  • Partition Equal Subset Sum LC 416 — you only need to know whether some subset reaches half the total, not list them: DP over the sums that can be reached replaces the search.
  • Count the combinations instead of listing them — group equal values (Counter), then run a DP over (distinct value, sum) where each value can be used 0 to count times: polynomial in the target, no enumeration.
