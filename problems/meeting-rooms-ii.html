Meeting Rooms II Medium

LeetCode #253 ↗
Status

Find the minimum number of rooms needed to hold a list of meetings.

Problem

You are given a list intervals. Each item [start, end] is a meeting that begins at time start and finishes at time end. Return the minimum number of rooms needed to hold all the meetings.

  • A meeting uses its room from start up to, but not including, end. A meeting that ends at time t frees its room for a meeting that starts at t.
  • The meetings come in any order. If there are none, no room is needed.

Examples

Example 1
Input: intervals = [[0, 30], [5, 10], [15, 20]]
Output: 2
From time 5 to 10 the first two meetings run together, so two rooms are needed. The third meeting can reuse the second meeting's room.
Example 2
Input: intervals = [[7, 10], [2, 4]]
Output: 1
The meetings never overlap, so one room is enough.
Example 3
Input: intervals = [[1, 5], [5, 8]]
Output: 1
The second meeting starts exactly when the first one ends, so it can use the same room.

Constraints

  • 0 <= len(intervals) <= 10^4
  • intervals[i] = [start, end]
  • 0 <= start < end <= 10^6

Think first try before reading the solution

The number of rooms you need is the largest number of meetings running at the same moment. How could you find that moment?
The busiest moment is always the start of some meeting, because the count of running meetings only goes up when a meeting starts. Counting at every start works, but each count scans the whole list. Can you keep track of the running meetings as you go?
Handle the meetings in order of start time and keep a min-heap of end times, one per room. If the smallest end time is at or before the new meeting's start, that room is free: reuse it. Otherwise open a new room.

Key idea

The rooms you need equal the largest number of meetings running at the same moment: at that moment each running meeting needs its own room, and with that many rooms you can always cope.

Process the meetings in order of start time and keep track of the rooms already open. For a new meeting the only room worth asking about is the one that frees up first: if even that room is still busy, every room is. A min-heap (a structure that always gives you the smallest item in O(log n)) holds exactly that, one entry per room, with the time the room becomes free. The smallest, rooms[0], is on top.

  • If rooms[0] <= start, that room is free by the time the meeting starts. Give the meeting that room: replace its free time with this meeting's end.
  • Otherwise every room is busy. Open a new room: push end.

The heap never shrinks, so its size at the end is the number of rooms ever needed. Sorting costs O(n log n) and each heap operation O(log n).

Approaches from the obvious one to the one you want in an interview

The number of meetings running only goes up when a meeting starts, so the busiest moment is the start of some meeting. Check each start time: count the meetings that are running then, meaning s <= start < e (a meeting that ends at start has already freed its room). The largest count is the number of rooms.

It is correct and needs no sorting, but each of the n counts scans all n meetings: O(n²). For 10⁴ meetings that is 10⁸ checks.

Dry run

  1. intervals = [[0, 30], [5, 10], [15, 20]]
  2. At time 0: only [0, 30] is running, count 1.
  3. At time 5: [0, 30] and [5, 10], count 2.
  4. At time 15: [0, 30] and [15, 20] ([5, 10] ended at 10), count 2. The maximum is 2.

Python

class Solution:
    def minMeetingRooms(self, intervals: List[List[int]]) -> int:
        most = 0
        for start, _ in intervals:                    # the busiest moment is the start of some meeting
            running = 0
            for s, e in intervals:
                if s <= start < e:                    # this meeting is in progress at time `start`
                    running += 1
            most = max(most, running)
        return most
Time O(n²)Space O(1)

n start times, each checked against n meetings.

When to use: As the first idea: it shows what has to be computed. Too slow for large n.

Sort the meetings by start. Keep a min-heap rooms with one entry per room: the time that room becomes free. For each meeting:

  • if rooms is not empty and rooms[0] <= start, the room that frees up first is already free. Reuse it: heapreplace swaps its free time for this meeting's end;
  • otherwise every room is busy. Open a new room: heappush the end.

Only the room that frees up first matters, because if it is busy, all are. The heap gives that room in O(1) and updates in O(log n). The answer is len(rooms): the heap only grows when a meeting finds every room busy.

Dry run

  1. intervals = [[0, 30], [5, 10], [15, 20]] is already sorted. rooms = []
  2. [0, 30]: no rooms yet. Push 30: rooms = [30]
  3. [5, 10]: rooms[0] = 30 <= 5 is false, every room is busy. Push 10: rooms = [10, 30]
  4. [15, 20]: rooms[0] = 10 <= 15, reuse that room. heapreplace removes 10 and pushes 20: rooms = [20, 30]
  5. len(rooms) = 2

Python

class Solution:
    def minMeetingRooms(self, intervals: List[List[int]]) -> int:
        rooms = []                                    # min-heap: the time each room becomes free
        for start, end in sorted(intervals):          # in order of start time
            if rooms and rooms[0] <= start:           # the room that frees up first is free by now
                heapq.heapreplace(rooms, end)         # reuse it: pop its old free time, push the new one
            else:
                heapq.heappush(rooms, end)            # every room is busy: open a new one
        return len(rooms)
Time O(n log n)Space O(n)

The sort is O(n log n); each of the n meetings does one heap operation, O(log n).

When to use: The standard answer. The heap states the idea directly: rooms, and when each frees up.

Watch it run

Rooms in use at any moment = meetings that have started − meetings that have ended. So only two numbers matter, and the pairing of starts with ends does not: sort all the start times and all the end times separately.

Walk through the starts in order with a pointer e into the sorted ends, pointing at the earliest end not yet used. For each start s:

  • if s >= ends[e], a meeting has already ended, so a room is free: this meeting reuses it and e moves on;
  • otherwise nobody has finished: open a new room (rooms += 1).

There is no heap, only two sorted lists and two indexes, so the constant factor is smaller. The price is that the correctness argument is less visible than in the heap version.

Dry run

  1. intervals = [[0, 30], [5, 10], [15, 20]] gives starts = [0, 5, 15] and ends = [10, 20, 30]
  2. s = 0: 0 >= ends[0] = 10 is false, so rooms = 1
  3. s = 5: 5 >= 10 is false, so rooms = 2
  4. s = 15: 15 >= 10 is true, a room is reused: e = 1, rooms stays 2

Python

class Solution:
    def minMeetingRooms(self, intervals: List[List[int]]) -> int:
        starts = sorted(s for s, _ in intervals)      # the two columns, sorted on their own
        ends = sorted(e for _, e in intervals)
        rooms = 0
        e = 0                                         # earliest end time not yet used to free a room
        for s in starts:
            if s >= ends[e]:                          # some meeting has ended: reuse its room
                e += 1
            else:
                rooms += 1                            # nobody has finished: open a new room
        return rooms
Time O(n log n)Space O(n)

Two sorts of n numbers, then one pass.

When to use: When you want to avoid the heap, or the starts and ends arrive as two separate lists.

Common mistakes

  • Using < instead of <= for the reuse test. A meeting that ends at 5 frees its room for one that starts at 5. With rooms[0] < start, [[1, 5], [5, 8]] needs 2 rooms instead of 1.
  • Skipping the sort by start. The heap logic assumes meetings arrive in start order. In any other order a late meeting could take a room before an earlier one asks for it, and the count is wrong.
  • Storing start times in the heap. The heap must hold end times, the moments rooms become free. The start is only compared with the top of the heap.
  • In the two-pointer version, sorting (start, end) pairs together. Sort the start times and the end times as two separate lists. Which end belongs to which start does not matter, only how many meetings have started and how many have ended.
  • Counting overlapping pairs instead of the biggest group. Four meetings that all overlap form 6 overlapping pairs but need 4 rooms.

Python notes

  • heapq.heapreplace(rooms, end) removes the smallest item and pushes end in one step. That is exactly "this room is free, hand it to the next meeting", and it is a little cheaper than heappop followed by heappush.
  • rooms[0] reads the smallest end time without removing it. Check that rooms is not empty first.
  • sorted(intervals) orders the [start, end] pairs by start. For the two-pointer version, sorted(s for s, _ in intervals) and sorted(e for _, e in intervals) sort the two columns on their own.
  • In the reuse version the heap only ever grows (a reuse replaces an item), so len(rooms) at the end is the answer.

  • Car Pooling LC 1094 — each trip carries several passengers and you need the peak total: the same event sweep, with +passengers at the start and -passengers at the end.
  • Meeting Rooms III LC 2402 — rooms are numbered, a meeting takes the lowest-numbered free room or waits for one, and you report which room hosted the most meetings. Two heaps: free room numbers, and busy rooms by finish time.
