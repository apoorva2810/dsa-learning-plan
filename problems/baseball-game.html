Baseball Game Easy 250

LeetCode #682 ↗
Status

Replay a list of score-keeping commands, where some commands double, add or cancel earlier scores, and return the final total.

Problem

You keep score for an odd baseball game. You get a list of strings operations and apply them in order to a record of scores, which starts empty:

  • an integer such as "5" or "-2": write that number down as a new score;
  • "+": write down a new score equal to the sum of the previous two scores;
  • "D": write down a new score equal to double the previous score;
  • "C": cancel the previous score, removing it from the record.

Return the sum of every score still on the record after the last operation.

It is guaranteed that "+" always has at least two previous scores to use, and that "C" and "D" always have at least one.

Examples

Example 1
Input: operations = ["5","2","C","D","+"]
Output: 30
5 → record [5]. 2 → [5, 2]. C cancels the 2 → [5]. D doubles the 5 → [5, 10]. + adds 5 and 10 → [5, 10, 15]. Total 30.
Example 2
Input: operations = ["5","-2","4","C","D","9","+","+"]
Output: 27
After the C the record is [5, -2]; D doubles -2 to -4; then 9, then -4 + 9 = 5, then 9 + 5 = 14. The record [5, -2, -4, 9, 5, 14] sums to 27.
Example 3
Input: operations = ["1","C"]
Output: 0
The only score is cancelled, so the record is empty and the total is 0.

Constraints

  • 1 <= len(operations) <= 1000
  • operations[i] is "C", "D", "+", or a string holding an integer between -3 * 10^4 and 3 * 10^4
  • "+" always has two previous scores; "C" and "D" always have one

Think first try before reading the solution

Every command only talks about the most recent score or two. You never need to look further back than that.
C removes the newest score, and after that the one written just before it becomes the newest again. Which structure gives you 'newest first' with cheap removal?
Keep the scores on a stack. Push for numbers, + and D; pop for C; sum the stack at the end.

Key idea

The commands never ask about the oldest score or the third one from the end. They only ever ask about the newest score (D), the two newest (+), or they delete the newest (C). "Newest first, and the one before it takes over when the newest is removed" is the definition of a stack: last in, first out.

So the record is a stack. Numbers, D and + push one new value on top; C pops the top. Nothing is ever searched, so every command costs O(1), and the answer is the sum of what is left.

Approaches from the obvious one to the one you want in an interview

Keep every score ever written in a list. A C does not delete anything; it crosses out the newest live slot (sets it to None). Then D and + have to scan backwards past the crossed-out slots to find the newest live score (and the one before it). At the end, sum the slots that are not crossed out.

It gives the right answer, but each scan can pass over many dead slots: a long run of C commands followed by D or + makes every later command walk over all of them again, so the worst case is O(n²). The waste comes from keeping cancelled scores around; removing them is the whole fix.

Dry run

  1. ["1","2","3","C","C","D","+"]: write 1, 2, 3 → [1, 2, 3].
  2. C → cross out index 2 → [1, 2, ✗]; C → cross out index 1 → [1, ✗, ✗].
  3. D → scan back: index 2 dead, index 1 dead, index 0 holds 1 → append 2 → [1, ✗, ✗, 2].
  4. + → newest is 2 at index 3; for the second newest the scan passes index 2 and 1 again and finds 1 → append 3.
  5. Live slots 1, 2, 3 → total 6. Two scans walked over the same dead slots.

Python

class Solution:
    def calPoints(self, operations: List[str]) -> int:
        records = []                                   # every score ever written; None = cancelled

        def newest(skip: int) -> int:
            """Index of the newest live score, after skipping `skip` live ones. Scans backwards."""
            i = len(records) - 1
            while records[i] is None or skip > 0:
                if records[i] is not None:             # a live score we were told to skip
                    skip -= 1
                i -= 1
            return i

        for op in operations:
            if op == "C":
                records[newest(0)] = None              # cross it out, keep the slot
            elif op == "D":
                records.append(2 * records[newest(0)])
            elif op == "+":
                records.append(records[newest(0)] + records[newest(1)])
            else:
                records.append(int(op))                # int() handles "-2" too
        return sum(score for score in records if score is not None)
Time O(n²)Space O(n)

n commands, and a scan may walk over up to n dead slots.

When to use: Never; it is here to show that keeping cancelled scores is what makes the work grow.

Watch it run

Delete cancelled scores instead of crossing them out. Then the newest live score is always the top of the list, the second newest is right under it, and nothing ever needs to be searched.

  • number → push(int(op))
  • D → push(2 * top)
  • + → push(top + second), leaving both in place
  • C → pop()

Each command touches only the top one or two entries, so it is O(1); the final sum is one pass over at most n scores.

Dry run

  1. ["5","2","C","D","+"], scores []
  2. 5 → push → [5]
  3. 2 → push → [5, 2]
  4. C → pop 2 → [5]
  5. D → 2 × 5 → push 10 → [5, 10]
  6. + → 5 + 10 → push 15 → [5, 10, 15]
  7. sum → 30

Python

class Solution:
    def calPoints(self, operations: List[str]) -> int:
        scores = []                                    # a stack: the newest score is scores[-1]
        for op in operations:
            if op == "C":
                scores.pop()                           # cancel the most recent score
            elif op == "D":
                scores.append(2 * scores[-1])          # double the most recent score
            elif op == "+":
                scores.append(scores[-1] + scores[-2]) # sum of the two most recent; both stay
            else:
                scores.append(int(op))                 # a plain score, possibly negative
        return sum(scores)
Time O(n)Space O(n)

Each command is O(1) on the top of the list; the final sum visits each live score once.

When to use: Always. The whole problem is recognising that the record is a stack.

Watch it run

The same stack, but keep total up to date as you go: add every pushed value, subtract every popped one. The answer is ready the moment the loop ends, with no final pass over the stack. Same O(n) time and O(n) space; it only matters if the total is needed after every command (a live scoreboard).

The match statement is a tidy way to write the four cases.

Python

class Solution:
    def calPoints(self, operations: List[str]) -> int:
        scores = []
        total = 0
        for op in operations:
            match op:
                case "C":
                    total -= scores.pop()              # the cancelled score leaves the total
                case "D":
                    scores.append(2 * scores[-1])
                    total += scores[-1]
                case "+":
                    scores.append(scores[-1] + scores[-2])
                    total += scores[-1]
                case _:                                # any other string is a number
                    scores.append(int(op))
                    total += scores[-1]
        return total
Time O(n)Space O(n)

Identical work per command; it skips the final sum at the cost of two updates per push/pop.

When to use: When the running total must be available after every command.

Common mistakes

  • Detecting numbers with op.isdigit(): it is False for "-2", so negative scores fall into the wrong branch. Test for the three symbols first and treat everything else as a number with int(op).
  • Popping the two operands for +: they must stay on the record. Read them with stack[-1] and stack[-2], then push their sum.
  • Removing the oldest score on C (stack.pop(0) or del stack[0]). C cancels the most recent one, which is the top: stack.pop().
  • Returning the top of the stack instead of the sum of everything on it; the question asks for the total of the whole record.

Python notes

  • int("-2") works, so an else branch with int(op) handles negative scores; op.isdigit() does not.
  • A list is the stack: append pushes, pop() removes the top, stack[-1] and stack[-2] read the newest two.
  • Python 3.10+ match op: case "C": ... reads nicely for command dispatch; the case _: arm is the number case.
  • sum(stack) on an empty list is 0, which is the right answer when every score was cancelled.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Evaluate Reverse Polish Notation LC 150 — same shape, but an operator pops its two operands and pushes the result; here + keeps both operands on the record.
  • Backspace String Compare LC 844 — # behaves exactly like C: build each string with a stack, or walk both strings backwards to use O(1) space.
  • Simplify Path LC 71 — .. cancels the previous folder like C, . is a no-op; the record is the list of folders on the stack.
  • Crawler Log Folder LC 1598 — only the depth matters, not which folders: a single counter replaces the whole stack.
  • Min Stack LC 155 — a stack that must also answer a question about its contents in O(1); the trick is storing extra information next to each entry.
  • What if `C` cancelled the previous k scores? — pop k times; it is still O(1) amortised per score because each score is pushed and popped at most once overall.
