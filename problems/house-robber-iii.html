House Robber III Medium 250

LeetCode #337 ↗
Status

Rob houses arranged as a binary tree for the most money, never robbing a parent and its child.

Problem

The houses of a neighbourhood form a binary tree: root is the only entrance, and each house is linked to its parent. node.val is the money in that house. The alarm goes off when two directly connected houses (a parent and one of its children) are robbed on the same night.

Return the most money you can rob without triggering the alarm.

Examples

Example 1
Input: root = [3, 2, 3, null, 3, null, 1]
Output: 7
Rob the root 3 and the two bottom houses 3 and 1: 3 + 3 + 1 = 7. None of them is a parent of another.
Example 2
Input: root = [3, 4, 5, 1, 3, null, 1]
Output: 9
Rob the middle houses 4 and 5: 4 + 5 = 9. Taking the root 3 would force you to skip both of them.
Example 3
Input: root = [4, 1, null, 2, null, 3]
Output: 7
A chain 4 → 1 → 2 → 3. Rob 4 and 3 (7): two houses in a row, 1 and 2, are skipped.

Constraints

  • 1 <= number of nodes <= 10^4
  • 0 <= Node.val <= 10^4

Think first try before reading the solution

Decide about one house at a time, starting from the root. If you rob it, which houses become off limits? If you skip it, what is left to decide?
Robbing a house means its children are out, so the money comes from the house plus the best you can do in its grandchildren's subtrees. Skipping it leaves the best of each child's subtree. Write that as a recursion and notice which subtrees get solved more than once.
Let every subtree report two numbers: the best total if its root is robbed and the best if it is not. A parent needs only those two numbers from each child, so one post-order pass solves everything.

Key idea

This is House Robber on a tree. On the street, the rule 'no two neighbours' led to dp[i] = max(dp[i-1], dp[i-2] + nums[i]). Here 'no parent and child together' gives the same shape: either you rob the root, and then its children are out but their children are free, or you skip the root and solve each child's subtree on its own.

Written directly, rob(node) = max(node.val + rob(all four grandchildren), rob(left) + rob(right)) is correct but slow: rob(grandchild) is computed once for the grandparent and again when the parent asks for it, and the repeats compound down the tree. Memoising by node fixes that, but there is a cleaner way to see it.

Ask every subtree for a pair: (rob, skip), the best total when its root is robbed and when it is not.

  • rob = node.val + left.skip + right.skip: robbing this house forces both children to be skipped.
  • skip = max(left) + max(right): a skipped house frees each child to do whatever is best for it (rob or skip).

A leaf is (val, 0), and an empty subtree is (0, 0). One post-order traversal (children before parent) computes every pair once, and the answer is max of the root's pair. O(n) time, and the only extra memory is the recursion stack.

Approaches from the obvious one to the one you want in an interview

rob(node) is the most money from the subtree at node. Either rob node, which bans its children but not its grandchildren, or skip it and take rob(left) + rob(right):

rob(node) = max(node.val + rob(left.left) + rob(left.right) + rob(right.left) + rob(right.right), rob(left) + rob(right))

Correct, but each grandchild's subtree is solved twice: once directly for the grandparent and once inside the parent's call. The duplication repeats at every level, so the running time grows exponentially with the depth.

Dry run

  1. [3, 2, 3, null, 3, null, 1]: rob(root) asks rob(3 leaf) and rob(1) as grandchildren → 3 + 1
  2. then it asks rob(2) and rob(3): each of those asks rob(3 leaf) / rob(1) again
  3. rob(root) = max(3 + 3 + 1, 3 + 3) = 7

Python

class Solution:
    def rob(self, root: Optional[TreeNode]) -> int:
        def best(node):
            if node is None:
                return 0
            with_node = node.val                        # rob this house: children are out, grandchildren are in
            if node.left:
                with_node += best(node.left.left) + best(node.left.right)
            if node.right:
                with_node += best(node.right.left) + best(node.right.right)
            without = best(node.left) + best(node.right) # skip this house: solve the children freely
            return max(with_node, without)

        return best(root)
Time exponential in the heightSpace O(h)

Each subtree two levels down is solved twice, and the doubling repeats at every level.

When to use: Only to discover the recurrence; it times out on deep trees.

Same function, but remember the result for each node. There are only n distinct nodes, so every subtree is solved once and later calls are dictionary lookups: O(n) time, O(n) extra memory for the memo plus the stack.

Key the memo by the node object, not by node.val: two houses with equal values are different subproblems.

Python

class Solution:
    def rob(self, root: Optional[TreeNode]) -> int:
        memo = {}                                       # node -> best total for its subtree

        def best(node):
            if node is None:
                return 0
            if node in memo:
                return memo[node]
            with_node = node.val
            if node.left:
                with_node += best(node.left.left) + best(node.left.right)
            if node.right:
                with_node += best(node.right.left) + best(node.right.right)
            without = best(node.left) + best(node.right)
            memo[node] = max(with_node, without)
            return memo[node]

        return best(root)
Time O(n)Space O(n)

Each node is solved once; the memo holds one entry per node.

When to use: When you have the recurrence and want it fast with the least change.

Let each subtree report two numbers to its parent: rob, the best total if its root is robbed, and skip, the best total if it is not.

  • rob = node.val + left.skip + right.skip (robbing this house forces the children to be skipped);
  • skip = max(left) + max(right) (a skipped house lets each child pick its own better option).

An empty subtree is (0, 0). Children are computed before their parent (post-order), so every node is visited once and nothing is recomputed. The answer is max of the root's pair. No memo is needed because the parent gets everything it needs from two numbers per child.

Dry run

  1. [3, 2, 3, null, 3, null, 1]: leaves → 3: (3, 0) and 1: (1, 0)
  2. house 2: rob = 2 + 0 = 2, skip = max(3, 0) = 3 → (2, 3)
  3. house 3 (right): rob = 3 + 0 = 3, skip = max(1, 0) = 1 → (3, 1)
  4. root 3: rob = 3 + 3 + 1 = 7, skip = max(2, 3) + max(3, 1) = 6 → max(7, 6) = 7

Python

class Solution:
    def rob(self, root: Optional[TreeNode]) -> int:
        def dfs(node):
            """Return (best if this house is robbed, best if it is skipped)."""
            if node is None:
                return 0, 0
            rob_left, skip_left = dfs(node.left)
            rob_right, skip_right = dfs(node.right)
            rob_here = node.val + skip_left + skip_right          # children must be skipped
            skip_here = max(rob_left, skip_left) + max(rob_right, skip_right)   # children choose freely
            return rob_here, skip_here

        return max(dfs(root))
Time O(n)Space O(h)

One visit per node with O(1) work; the stack is as deep as the tree height h.

When to use: The interview answer: one pass, two numbers per node, no memo.

Common mistakes

  • Taking skip = left.rob + right.rob. Skipping a house does not force its children to be robbed; each child picks the better of its own two numbers. [4, 1, null, 2, null, 3] needs 1 and 2 both skipped to reach 7.
  • Greedy by levels (rob every other level). [3, 4, 5, 1, 3, null, 1] is best with the middle level only (9), not root plus leaves (3 + 1 + 3 + 1 = 8).
  • Memoising the plain recursion by node.val instead of by the node object: two houses with the same value are different subproblems. Use the node (or id(node)) as the key.
  • Returning only the best total from each subtree. The parent cannot tell whether that total robbed the child or not, which is exactly what it needs to know; return both numbers.
  • Recursion depth: a 10^4-node chain needs 10^4 frames, above Python's default limit of 1000. Raise the limit or run the post-order with an explicit stack.

Python notes

  • Returning a tuple and unpacking it, rob_left, skip_left = dfs(node.left), keeps the two numbers of each subtree together without a helper class.
  • max(dfs(child)) works on the tuple directly: it picks the better of the child's two numbers.
  • @cache memoises by argument; TreeNode objects hash by identity, so caching the plain recursion on the node itself is safe. Caching on node.val would be wrong.
  • With up to 10^4 nodes a chain-shaped tree exceeds the default recursion limit; sys.setrecursionlimit(20000) or an explicit post-order stack avoids RecursionError.

Follow-up questions

What an interviewer might ask next, and what changes.

  • House Robber LC 198 — the same choice on a line of houses; (rob, skip) for a tree collapses to the two rolling variables.
  • House Robber II LC 213 — the houses form a circle: run the line version twice, once without the first house and once without the last.
  • Binary Tree Cameras LC 968 — each node reports one of three states to its parent (has a camera, is covered, needs cover): the same post-order 'report a small state upward' pattern with three cases instead of two.
  • Binary Tree Maximum Path Sum LC 124 — a post-order pass where each node returns the best downward path to its parent while the answer is tracked on the side.
  • Houses form a general tree, not a binary one — rob = val + sum(child.skip) and skip = sum(max(child)) over all children; nothing else changes.
  • Return which houses to rob — store the chosen plan alongside each number, or walk down again from the root: a robbed node's children are skipped, a skipped node's children each take their own better option.
