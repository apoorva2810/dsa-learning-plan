Subsets II Medium

LeetCode #90 ↗
Status

List every distinct subset of a list that may contain repeated numbers, without listing any subset twice.

Problem

You are given a list nums that may contain duplicates. Return every possible subset, but no subset may appear twice. Two subsets are the same if they contain the same numbers the same number of times, whatever the order ([1, 2] and [2, 1] are the same subset).

  • The empty subset and the whole list both count.
  • The subsets can be returned in any order.

Examples

Example 1
Input: nums = [1, 2, 2]
Output: [[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]
Taking the first 2 or the second 2 gives the same subsets ([2], [1, 2]), and each is listed once.
Example 2
Input: nums = [0]
Output: [[], [0]]
Example 3
Input: nums = [4, 4, 4, 1, 4]
Output: [[], [1], [1, 4], [1, 4, 4], [1, 4, 4, 4], [1, 4, 4, 4, 4], [4], [4, 4], [4, 4, 4], [4, 4, 4, 4]]
Zero to four copies of 4, with or without the 1: 5 × 2 = 10 distinct subsets.

Constraints

  • 1 <= len(nums) <= 10
  • -10 <= nums[i] <= 10

Key idea

Subsets I treats every position as different, so with [1, 2, 2] taking the first 2 or the second 2 gives the same subset twice ([2], [1, 2]). The fix is to make "which copy" irrelevant by fixing an order among equal values.

Sort the list so equal values are neighbours. Inside one call to backtrack(start), the loop offers nums[start], nums[start + 1], … as the next element of the path. If nums[i] has the same value as nums[i - 1], the earlier copy was already tried as the next element in this very loop, and everything below it covers everything the later copy could build (the earlier copy can be followed by all the same later elements, and more). So the later copy adds only duplicates: skip it with if i > start and nums[i] == nums[i - 1]: continue.

i > start is the heart of it. At i == start an equal value is the first candidate of its call and must be allowed. That is how [2, 2] gets built: the second 2 is chosen one level deeper, as the first candidate of the next call. Only a repeat among siblings (same loop, same position in the path) is redundant.

Approaches from the obvious one to the one you want in an interview

Reuse the Subsets bitmask idea unchanged on the sorted list and put every subset into a set of tuples, so repeats collapse. Sorting first matters: every subset of a sorted list, picked in index order, is itself sorted, so equal subsets always become equal tuples. On an unsorted list (2, 1) and (1, 2) would stay different.

It is correct and short. The waste is that it builds all 2ⁿ position-subsets although the answer is smaller: [4, 4, 4, 1, 4] builds 32 subsets for 10 distinct answers, and ten equal numbers build 1,024 for 11 answers. The backtracking version never builds the duplicates.

Dry run

  1. nums = [2, 1, 2] → sorted [1, 2, 2]. Masks 0 to 7 build (), (1,), (2,), (1, 2), (2,), (1, 2), (2, 2), (1, 2, 2).
  2. Adding them to a set: (2,) and (1, 2) each appear twice and collapse.
  3. Six distinct subsets remain, after eight were built.

Python

class Solution:
    def subsetsWithDup(self, nums: List[int]) -> List[List[int]]:
        nums = sorted(nums)                      # sorted: equal subsets become equal tuples
        n = len(nums)
        unique = set()
        for mask in range(1 << n):               # all 2^n position-subsets, duplicates included
            subset = tuple(nums[i] for i in range(n) if (mask >> i) & 1)
            unique.add(subset)                   # a set silently drops the repeats
        return [list(s) for s in unique]
Time O(n · 2ⁿ)Space O(n · 2ⁿ)

All 2ⁿ masks are built and hashed at O(n) each, and the set holds the distinct subsets before they are copied out.

When to use: A correct fallback when you cannot remember the skip rule; it shows what the rule saves.

Take the Subsets loop and make two changes. First, sort nums, so equal values are neighbours. Second, inside the loop skip a candidate that repeats the previous one:

if i > start and nums[i] == nums[i - 1]:
    continue

i > start means "this value was already tried as the next element in this very loop". The earlier copy's branch can be followed by every element the later copy could be followed by, so the later copy would only rebuild subsets that already exist. When i == start the equal value is the first candidate of its call and is allowed, which is how [2, 2] is built.

Each distinct subset is generated exactly once, so there is no cleanup afterwards, and the duplicate branches are never entered at all.

Dry run

  1. nums = [1, 2, 2] (sorted). backtrack(0) records []. Choose 1 → backtrack(1) records [1].
  2. In backtrack(1): choose the first 2 (i = 1) → records [1, 2]; inside, i = 2 == start: allowed → records [1, 2, 2].
  3. Back in backtrack(1): i = 2 > start = 1 and nums[2] == nums[1] → skip. The loop ends.
  4. Back at the root: choose the first 2 → records [2], then [2, 2] one level deeper.
  5. Root again: i = 2 > start = 0 and nums[2] == nums[1] → skip. Six subsets, no repeats.

Python

class Solution:
    def subsetsWithDup(self, nums: List[int]) -> List[List[int]]:
        nums = sorted(nums)                      # equal values become neighbours
        result = []
        path = []

        def backtrack(start: int) -> None:
            result.append(path[:])               # every path is a subset
            for i in range(start, len(nums)):
                if i > start and nums[i] == nums[i - 1]:    # a sibling with this value was already tried
                    continue
                path.append(nums[i])             # choose
                backtrack(i + 1)                 # explore
                path.pop()                       # un-choose

        backtrack(0)
        return result
Time O(n · 2ⁿ)Space O(n)

At most 2ⁿ calls, one per distinct subset, each copying up to n numbers; fewer when values repeat. The recursion and path are at most n deep; the sort costs O(n log n).

When to use: The standard answer. Be ready to explain i > start versus i > 0.

Watch it run

Process the sorted list one value at a time, keeping in result all the distinct subsets of the values seen so far. A new value x is appended to existing subsets to create new ones.

  • If x differs from the previous value, extend every subset in result.
  • If x repeats the previous value, extending everything would recreate subsets the previous copy of x already made (a second [2]). Extend only the subsets added in the previous round: they are exactly the ones that end with the earlier copies of x, and each can legitimately take one more.

round_start is the index in result where the previous round began. There is no recursion and no skip test, but the rule is subtle: it depends on sorting and on result keeping subsets in the order they were created.

Dry run

  1. nums = [1, 2, 2], result = [[]].
  2. x = 1: extend everything → [[], [1]].
  3. x = 2 (new value): extend everything → [[], [1], [2], [1, 2]].
  4. x = 2 (repeat): extend only the last round, result[2:4] = [2], [1, 2] → adds [2, 2], [1, 2, 2].

Python

class Solution:
    def subsetsWithDup(self, nums: List[int]) -> List[List[int]]:
        nums = sorted(nums)
        result = [[]]
        round_start = 0                          # where the subsets made for the previous number begin
        for i, x in enumerate(nums):
            # a repeated value may only extend what the previous copy created
            begin = round_start if i > 0 and x == nums[i - 1] else 0
            round_start = len(result)            # subsets made for x will start here
            for j in range(begin, round_start):
                result.append(result[j] + [x])
        return result
Time O(n · 2ⁿ)Space O(1)

Each distinct subset is created once at O(n) for the copy. Apart from the output, only a few counters are stored.

When to use: When recursion is unwelcome. Harder to prove correct than the backtracking version, so explain the invariant.

Common mistakes

  • Forgetting to sort. Equal values must be neighbours for nums[i] == nums[i - 1] to catch them. With [2, 1, 2] unsorted, the repeat is missed and duplicate subsets are produced.
  • Writing i > 0 instead of i > start. That also skips an equal value that is the first candidate of its call, so [2, 2] and [1, 2, 2] disappear from the answer.
  • Skipping any value that is already in path. That blocks legal repeats too: [2, 2] needs two 2s in the path. Only a repeat among siblings is redundant.
  • Removing duplicates at the end with a set of tuples but without sorting first: (2, 1) and (1, 2) are different tuples, so equal subsets survive. (Sorted, the set approach is correct, just wasteful.)
  • Sorting with nums.sort() changes the caller's list, and storing path instead of path[:] fills the answer with copies of one list.

Python notes

  • sorted(nums) returns a sorted copy. nums.sort() sorts the caller's list in place, a side effect most callers do not expect.
  • Lists cannot go into a set, tuples can: set(tuple(s) for s in subsets) is the usual way to deduplicate lists.
  • collections.Counter(nums) gives {value: count}. Looping over the distinct values and choosing how many copies (0 to count) of each is another way to avoid duplicates by construction, with no skip rule.
  • nums[i] == nums[i - 1] is safe here because i > start >= 0 is tested first, so i - 1 is never negative.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Subsets LC 78 — all numbers distinct: the same skeleton without the sort and without the skip rule.
  • Combination Sum II LC 40 — the same sort-and-skip rule plus a target sum, with each number used at most once.
  • Permutations II LC 47 — duplicates in a permutation problem: sort, and skip nums[i] when it equals nums[i - 1] and nums[i - 1] is not currently in the path.
  • Non-decreasing Subsequences LC 491 — the order of the input is part of the problem, so you cannot sort. Dedupe per call instead: keep a set of the values already tried at this position of the path.
  • How many distinct subsets are there? — you do not need to list them: multiply (count + 1) over the distinct values. For [4, 4, 4, 1, 4] that is (4 + 1) × (1 + 1) = 10.
