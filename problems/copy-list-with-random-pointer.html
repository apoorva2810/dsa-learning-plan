Copy List with Random Pointer Medium

LeetCode #138 ↗
Status

Deep-copy a linked list whose nodes also carry a pointer to any node in the list.

Problem

Every node of this linked list has three fields: val, next (the following node, or None) and random, which may point to any node of the list or be None.

Return a deep copy of the list: brand-new nodes, one per original node, with the same values, where every next and random pointer of a copy points to a copy, never to an original node.

Lists are written as [val, random_index] pairs in order, where random_index is the position (0-based) of the node that random points to, or null.

Examples

Example 1
Input: head = [[7, null], [13, 0], [11, 4], [10, 2], [1, 0]]
Output: [[7, null], [13, 0], [11, 4], [10, 2], [1, 0]]
Same shape, but every node in the output is new. E.g. the copy of 13 has random pointing to the copy of 7.
Example 2
Input: head = [[1, 1], [2, 1]]
Output: [[1, 1], [2, 1]]
Both random pointers go to the second node; node 2's random points to itself.
Example 3
Input: head = [[3, null], [3, 0], [3, null]]
Output: [[3, null], [3, 0], [3, null]]
Equal values: a copy must be found by which node it copies, not by its value.

Constraints

  • 0 <= n <= 1000
  • -10^4 <= Node.val <= 10^4
  • random is None or points to a node in the list

Think first try before reading the solution

Copying val and next is a simple walk. The trouble is random: when you copy node A, the copy of A.random may not exist yet.
If you had a dictionary from every original node to its copy, copy.random = old_to_new[original.random] would be one lookup.
Separate creating from wiring: pass 1 creates every copy and fills old -> new; pass 2 sets each copy's next and random through the dictionary. For O(1) extra memory, store the mapping in the list itself by placing each copy right after its original.

Key idea

The difficulty is forward references: a random pointer can point to a node you have not copied yet, so you cannot finish a copy at the moment you create it. The fix is to split the work in two. First create all the copies, so every target exists. Then connect them. A dictionary old_to_new translates any original node into its copy, so every pointer of the original (next or random) becomes a pointer of the copy with one lookup.

The O(1)-extra-memory trick keeps that translation inside the list: weave each copy in right after its original (A → A′ → B → B′ → …). Then the copy of any node X is simply X.next, so A′.random = A.random.next. A last pass unzips the two lists and restores the original.

Approaches from the obvious one to the one you want in an interview

Turn pointers into positions. Walk the list once, keeping the originals and fresh copies in two Python lists and linking the copies with next. Then, for each original whose random is set, scan the originals to find the position j of its target, and set copies[i].random = copies[j].

Correct, but each scan is O(n), so n random pointers cost O(n²). The scan answers "which position is this node?" slowly; a dictionary answers it in O(1).

Python

class Solution:
    def copyRandomList(self, head: 'Optional[Node]') -> 'Optional[Node]':
        originals, copies = [], []
        cur = head
        while cur:                               # copy values, remember positions
            originals.append(cur)
            copies.append(Node(cur.val))
            cur = cur.next
        for a, b in zip(copies, copies[1:]):     # copy the next pointers
            a.next = b
        for i, node in enumerate(originals):
            if node.random is not None:
                # O(n) scan to find the target's position
                j = next(k for k, other in enumerate(originals) if other is node.random)
                copies[i].random = copies[j]
        return copies[0] if copies else None
Time O(n²)Space O(n)

Up to n random pointers, each found by scanning n originals.

When to use: Only to motivate the dictionary.

Pass 1 walks the list and creates a copy of every node, storing old_to_new[original] = copy. No pointers are set yet. Pass 2 walks again and wires each copy: copy.next = old_to_new[cur.next] and copy.random = old_to_new[cur.random]. Seeding the dictionary with {None: None} makes None pointers work without an if.

Every node is created once and every pointer is translated with one O(1) lookup: O(n) time, O(n) extra memory for the dictionary.

Dry run

  1. pass 1: create 7′, 13′, 11′, 10′, 1′ and map #0..#4 to them
  2. pass 2, #1 (13): next → #2′, random → #0′
  3. pass 2, #2 (11): next → #3′, random → #4′ (created in pass 1, so it exists)
  4. return old_to_new[head]

Python

class Solution:
    def copyRandomList(self, head: 'Optional[Node]') -> 'Optional[Node]':
        old_to_new = {None: None}                # a None pointer maps to None
        cur = head
        while cur:                               # pass 1: create every copy
            old_to_new[cur] = Node(cur.val)
            cur = cur.next
        cur = head
        while cur:                               # pass 2: translate both pointers
            copy = old_to_new[cur]
            copy.next = old_to_new[cur.next]
            copy.random = old_to_new[cur.random]
            cur = cur.next
        return old_to_new[head]
Time O(n)Space O(n)

Two passes; the dictionary holds n + 1 entries.

When to use: The standard interview answer: clear, and it generalises to graphs (Clone Graph).

Watch it run

Store the old → new mapping inside the list instead of a dictionary:

  1. Weave: insert each copy right after its original: A → A′ → B → B′ → …. Now the copy of any node X is X.next.
  2. Randoms: for each original cur, cur.next.random = cur.random.next (the copy of its random target), when cur.random is set.
  3. Unzip: restore cur.next = copy.next and set copy.next = copy.next.next, moving through the pairs.

Three linear passes and a few pointers: O(n) time and O(1) extra memory beyond the copy itself.

Dry run

  1. weave: 7 → 7′ → 13 → 13′ → 11 → 11′ → …
  2. randoms: 13's random is 7, so 13′.random = 7.next = 7′
  3. unzip: 7 → 13 → … is restored, 7′ → 13′ → … is the answer

Python

class Solution:
    def copyRandomList(self, head: 'Optional[Node]') -> 'Optional[Node]':
        if head is None:
            return None
        cur = head
        while cur:                               # 1. weave: A -> A' -> B -> B' ...
            copy = Node(cur.val)
            copy.next = cur.next
            cur.next = copy
            cur = copy.next
        cur = head
        while cur:                               # 2. the copy of X.random is X.random.next
            if cur.random:
                cur.next.random = cur.random.next
            cur = cur.next.next
        new_head = head.next
        cur = head
        while cur:                               # 3. unzip the two lists
            copy = cur.next
            cur.next = copy.next                 # restore the original link
            copy.next = copy.next.next if copy.next else None
            cur = cur.next
        return new_head
Time O(n)Space O(1)

Three passes; no dictionary. The n new nodes are the output, so they are not counted as extra.

When to use: When asked for O(1) extra memory. Harder to get right, so explain the dictionary version first.

Common mistakes

  • Setting copy.random = cur.random points into the original list: the result shares nodes with the input, so it is not a deep copy. (The checker on this site compares values and random positions only; LeetCode also rejects shared nodes.)
  • Keying the dictionary by value: values can repeat ([[3, null], [3, 0], [3, null]]). Key by the node object itself.
  • old_to_new[cur.random] raises KeyError when random is None. Seed the dictionary with {None: None} or check first.
  • Interleaving version: forgetting to restore the original list's next pointers when unzipping, or setting random after unzipping, when X.random.next no longer points to the copy.

Python notes

  • Objects are hashable by identity, so old_to_new[node] works even when values repeat.
  • {None: None} as the starting dictionary turns "random is None" into an ordinary lookup.
  • This site's Node class also serves Clone Graph, so its constructor is Node(val, neighbors, next, random). Create nodes with Node(cur.val) and assign .next / .random afterwards: that works here and on LeetCode.

What an interviewer might ask next, and what changes.

  • Clone Graph LC 133 — the same old → new dictionary, but nodes have many neighbours and the graph can have cycles: DFS or BFS, using the dictionary as the visited set.
  • Clone Binary Tree With Random Pointer LC 1485 — a tree instead of a list: one DFS creates the copies and fills the dictionary, a second sets random.
  • Clone N-ary Tree LC 1490 — no random pointers, so a single recursive copy works; it shows when the two-phase idea is unnecessary.
  • One pass with lazy creation — create a copy the first time any pointer needs it (get_copy(node) checks the dictionary first), so next and random are wired in the same walk.
