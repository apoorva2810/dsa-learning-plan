Min Cost to Connect All Points Medium

LeetCode #1584 ↗
Status

Link every point on a grid with the least total Manhattan-distance wiring.

Problem

You are given points, a list of distinct integer coordinates points[i] = [x, y]. Connecting two points costs their Manhattan distance, |x1 - x2| + |y1 - y2| (the distance if you may only move along the grid lines).

Return the minimum total cost to connect all the points, so that every point can reach every other one through the connections you paid for.

Examples

Example 1
Input: points = [[0, 0], [2, 2], [3, 10], [5, 2], [7, 0]]
Output: 20
Use the links 0–1 (cost 4), 1–3 (3), 3–4 (4) and 1–2 (9): 4 + 3 + 4 + 9 = 20.
Example 2
Input: points = [[3, 12], [-2, 5], [-4, 1]]
Output: 18
[-2, 5]–[-4, 1] costs 6 and [3, 12]–[-2, 5] costs 12.
Example 3
Input: points = [[0, 0]]
Output: 0
A single point is already connected.

Constraints

  • 1 <= len(points) <= 1000
  • -10^6 <= x, y <= 10^6
  • all points are distinct

Think first try before reading the solution

Picture every pair of points as a possible link. The cheapest set of links that connects everything never contains a loop. Why? What is that structure called?
It is a minimum spanning tree: n - 1 links, no cycle, least total cost. Two classic ways to build one: grow a tree outwards from one point (Prim), or take links cheapest-first while skipping any that would close a loop (Kruskal).
Prim: keep a min-heap of (cost, point) for links leaving the current tree. Pop the cheapest; if its point is new, add it and push its links to every point still outside.

Key idea

If the chosen links contained a loop, you could drop one link of the loop and everything would stay connected for less money. So the cheapest network is a tree that touches every point: a minimum spanning tree (MST), with exactly n - 1 links. Trying every possible tree is hopeless (there are n^(n-2) of them), but a greedy rule works.

Prim's algorithm: start the tree at any point. Repeatedly add the cheapest link that joins a point outside the tree to a point inside it. That is always safe: the tree must cross from "inside" to "outside" at some point, and the cheapest crossing can always be swapped in without making things worse (the "cut property"). A min-heap of candidate links finds that cheapest crossing quickly.

Here every pair of points is a possible link, so the graph is complete (about n²/2 edges). That makes a version of Prim without a heap the fastest: keep, for every outside point, the cheapest link to the tree in a plain array, and scan it to pick the next point.

Approaches from the obvious one to the one you want in an interview

List all n(n - 1)/2 possible links with their costs and sort them, cheapest first. Walk the sorted list and keep a link only if its two points are not already connected; union-find (see Redundant Connection) answers that in near O(1). Stop after n - 1 links have been kept.

Taking the cheapest link that does not close a loop is always safe, by the same cut property that justifies Prim. The weak spot here is the input: every pair is a link, so you build and sort about n²/2 edges, O(n² log n) time and O(n²) memory.

  2. Keep 1–3, 0–1, 3–4. Skip 0–3, 0–4 and 1–4: their points are already connected

Python

class Solution:
    def minCostConnectPoints(self, points: List[List[int]]) -> int:
        n = len(points)
        edges = []
        for i in range(n):
            for j in range(i + 1, n):
                d = abs(points[i][0] - points[j][0]) + abs(points[i][1] - points[j][1])
                edges.append((d, i, j))
        edges.sort()                               # cheapest links first
        parent = list(range(n))

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]      # path halving
                x = parent[x]
            return x

        total, used = 0, 0
        for d, i, j in edges:
            root_i, root_j = find(i), find(j)
            if root_i == root_j:                   # already connected: this link would close a loop
                continue
            parent[root_i] = root_j
            total += d
            used += 1
            if used == n - 1:                      # a spanning tree on n points has n - 1 links
                break
        return total
Time O(n² log n)Space O(n²)

n²/2 edges are generated and sorted; union-find work is nearly linear on top of that.

When to use: The natural choice when edges come as a list (sparse graphs). Here it wastes memory on every pair.

Grow one tree. A min-heap holds candidate links as (cost, point). Pop the cheapest:

  • if the point is already in the tree, the offer is stale (it was attached more cheaply), so skip it;
  • otherwise add the point, add the cost to the total, and push a link from it to every point still outside.

The heap always surfaces the cheapest link leaving the tree, which the cut property says is safe to take. Each point pushes up to n offers, so the heap sees O(n²) pushes: O(n² log n) time. This is the version most people write; the next one removes the heap.

Dry run

  1. Heap [(0, 0)]. Pop it: point 0 joins. Push (4, 1), (13, 2), (7, 3), (7, 4)
  2. Pop (4, 1): link 0–1, total 4. Push (9, 2), (3, 3), (7, 4)
  3. Pop (3, 3): link 1–3, total 7. Push (10, 2), (4, 4). Pop (4, 4): link 3–4, total 11. Push (14, 2)
  4. Pop (7, 3), (7, 4), (7, 4): all stale. Pop (9, 2): link 1–2, total 20

Python

class Solution:
    def minCostConnectPoints(self, points: List[List[int]]) -> int:
        n = len(points)
        in_tree = set()
        heap = [(0, 0)]                            # (cost to attach, point): point 0 joins for free
        total = 0
        while len(in_tree) < n:
            cost, i = heapq.heappop(heap)
            if i in in_tree:                       # stale offer: already attached more cheaply
                continue
            in_tree.add(i)
            total += cost
            xi, yi = points[i]
            for j in range(n):
                if j not in in_tree:
                    d = abs(xi - points[j][0]) + abs(yi - points[j][1])
                    heapq.heappush(heap, (d, j))   # a candidate link leaving the tree
        return total
Time O(n² log n)Space O(n²)

Up to n pushes per added point, each O(log) in a heap that can hold O(n²) offers.

When to use: The standard interview answer and the right tool on sparse graphs (adjacency lists).

Watch it run

On a complete graph the heap does needless work: most offers it stores are later beaten and thrown away. Keep instead one number per point, best[v] = the cheapest link from the tree to v, plus an in_tree flag.

Repeat n times: scan the outside points for the smallest best (O(n)), add that point u, then update best[v] = min(best[v], dist(u, v)) for every outside v (O(n)). That is n rounds of O(n) work: O(n²) time and O(n) memory, the best possible here since each of the n²/2 distances may matter.

Dry run

  1. best = [0, ∞, ∞, ∞, ∞]. Pick 0 → best = [0, 4, 13, 7, 7]
  2. Pick 1 (4), total 4 → point 1 is closer to 2 (9) and 3 (3) → best = [·, ·, 9, 3, 7]
  3. Pick 3 (3), total 7 → 4 improves to 4. Pick 4 (4), total 11 → 2 stays 9
  4. Pick 2 (9) → total 20

Python

class Solution:
    def minCostConnectPoints(self, points: List[List[int]]) -> int:
        n = len(points)
        in_tree = [False] * n
        best = [math.inf] * n                      # best[v] = cheapest link from the tree to point v
        best[0] = 0
        total = 0
        for _ in range(n):
            # the outside point that is cheapest to attach: a linear scan instead of a heap
            u = min((v for v in range(n) if not in_tree[v]), key=lambda v: best[v])
            in_tree[u] = True
            total += best[u]
            xu, yu = points[u]
            for v in range(n):
                if not in_tree[v]:
                    d = abs(xu - points[v][0]) + abs(yu - points[v][1])
                    if d < best[v]:
                        best[v] = d                # u offers v a cheaper link
        return total
Time O(n²)Space O(n)

n rounds, each one scan to pick and one scan to update; only two arrays of length n.

When to use: Best for complete graphs like this one. Mention it after the heap version to show you know why it is faster here.

Common mistakes

  • Pushing the total distance so far (cost + d), as you would in Dijkstra. Prim compares single links, so push d.
  • Adding a point every time it is popped. The heap can hold several offers for the same point; only the first pop counts and later ones must be skipped.
  • Building all n²/2 edges for Kruskal when n = 1000: half a million tuples plus a sort. It works, but it is the slowest and most memory-hungry option here.
  • Using Euclidean distance (sqrt) by habit: this problem measures Manhattan distance.
  • Forgetting the single-point case: the answer is 0, and some loops never run.

Python notes

  • heapq stores (cost, index) tuples; ties on cost compare the index, which is always safe.
  • math.inf starts each "cheapest link so far" entry; any real distance is smaller.
  • min(candidates, key=lambda i: best[i]) picks the index with the smallest best value in one readable line.
  • For n = 1000 the array version does about 10⁶ distance computations; the heap version can push that many entries.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Connecting Cities With Minimum Cost LC 1135 — the edges are given as a list and the graph may be disconnected: Kruskal with union-find, returning -1 if fewer than n - 1 edges get used.
  • Optimize Water Distribution in a Village LC 1168 — digging a well becomes an edge to an extra imaginary node 0; then it is a plain MST.
  • Find Critical and Pseudo-Critical Edges in Minimum Spanning Tree LC 1489 — rerun Kruskal while forcing an edge in or keeping it out, and compare the total cost.
  • Network Delay Time LC 743 — the same heap loop computes something different there: Dijkstra minimises the route from one source, Prim minimises the total weight of the tree.
  • Redundant Connection LC 684 — the union-find check Kruskal uses to reject a link whose two points are already connected.
  • What if the cost were straight-line (Euclidean) distance? — nothing changes in the algorithm; compare squared distances while choosing links and take square roots only when adding up the answer.
