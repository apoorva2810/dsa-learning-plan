Guess Number Higher or Lower Easy 250

LeetCode #374 ↗
Status

Find a secret number in 1..n using an oracle that only says 'too high', 'too low' or 'correct'.

Problem

I pick a secret number between 1 and n (both included). You have to find it.

You cannot look at the number, but you may call a function guess(num) as often as you like. It answers:

  • -1 when your num is higher than my number (guess lower next time),
  • 1 when your num is lower than my number (guess higher),
  • 0 when num is my number.

Return the number I picked.

On LeetCode the guess function is provided and hidden. In this file it is defined inside each solution from a pick argument that the tests pass in, so the code is self-contained and the tests can run; see the Python notes.

Examples

Example 1
Input: n = 10, pick = 6
Output: 6
Guessing 5 answers 1 (too low), guessing 8 answers -1 (too high), guessing 6 answers 0.
Example 2
Input: n = 1, pick = 1
Output: 1
Only one candidate, so the first guess is right.
Example 3
Input: n = 2, pick = 1
Output: 1

Constraints

  • 1 <= n <= 2^31 - 1
  • 1 <= pick <= n

Think first try before reading the solution

Guessing 1, 2, 3, … works but can take n calls. Every wrong guess tells you a direction; use it.
After guess(num) returns 1, every number up to and including num is too low. After -1, every number from num up is too high. One call rules out a whole side.
Keep the candidates as a range lo..hi, guess the middle, and move lo or hi past it according to the sign. This is Binary Search with guess(mid) in place of comparing nums[mid] with a target.

Key idea

Think of the candidates 1, 2, …, n as a sorted list that you cannot see. The answer to guess(num) is exactly the comparison binary search needs: 1 means "the secret is to the right of num", -1 means "to the left", 0 means "found". So you can run the ordinary binary search loop with guess(mid) where plain Binary Search compares nums[mid] with the target.

Every call halves the range of candidates, so even for n = 2³¹ − 1 (about two billion) at most 31 calls are needed. A linear sequence of guesses could take two billion.

Reading the sign correctly is the whole difficulty: -1 is about your guess, not about the secret. It means your guess is too high, so the secret is smaller and hi must come down.

Approaches from the obvious one to the one you want in an interview

Call guess(1), guess(2), guess(3), … and stop at the first 0. It always finishes, because the secret is one of the candidates.

It throws away most of the information: each answer is used only as "not yet", never as a direction. For a secret near n = 2³¹ − 1 that is about two billion calls.

Dry run

  1. n = 10, pick = 6
  2. guess(1) → 1, guess(2) → 1, guess(3) → 1, guess(4) → 1, guess(5) → 1
  3. guess(6) → 0 → return 6 (6 calls)

Python

def make_guess(pick: int):
    """Stand-in for LeetCode's hidden API. guess(num) -> -1 if num is too high, 1 if too low, 0 if correct."""
    def guess(num: int) -> int:
        if num > pick:
            return -1
        if num < pick:
            return 1
        return 0
    return guess


class Solution:
    def guessNumber(self, n: int, pick: int) -> int:
        guess = make_guess(pick)                # on LeetCode: guess() is given, drop this line and the pick argument
        num = 1
        while guess(num) != 0:                  # 'too low' every time until we hit the secret
            num += 1
        return num
Time O(n)Space O(1)

Up to n calls to guess, one per candidate.

When to use: Never for real; it only shows what information the answers carry.

Watch it run

Keep lo..hi as the numbers that can still be the secret, starting with 1..n. Guess the middle and read the sign:

  • 0 → found, return mid.
  • 1 → our guess is too low, so the secret is larger: lo = mid + 1.
  • -1 → our guess is too high, so the secret is smaller: hi = mid - 1.

Each call halves the range, so at most ⌊log₂ n⌋ + 1 calls are needed: 31 for the largest allowed n. The loop condition lo <= hi can never actually fail here, because the secret is guaranteed to exist; the return mid always fires first.

Dry run

  1. n = 10, pick = 6: lo = 1, hi = 10
  2. mid = 5 → guess(5) = 1 (too low) → lo = 6
  3. mid = 8 → guess(8) = -1 (too high) → hi = 7
  4. mid = 6 → guess(6) = 0 → return 6 (3 calls)

Python

def make_guess(pick: int):
    """Stand-in for LeetCode's hidden API. guess(num) -> -1 if num is too high, 1 if too low, 0 if correct."""
    def guess(num: int) -> int:
        if num > pick:
            return -1
        if num < pick:
            return 1
        return 0
    return guess


class Solution:
    def guessNumber(self, n: int, pick: int) -> int:
        guess = make_guess(pick)                # on LeetCode: guess() is given, drop this line and the pick argument
        lo, hi = 1, n                           # the secret is somewhere in lo..hi
        while lo <= hi:
            mid = (lo + hi) // 2
            answer = guess(mid)                 # call once per round and keep the result
            if answer == 0:
                return mid                      # correct
            if answer == 1:
                lo = mid + 1                    # our guess was too low: the secret is bigger
            else:
                hi = mid - 1                    # our guess was too high: the secret is smaller
        return -1                               # unreachable: the secret is always in 1..n
Time O(log n)Space O(1)

At most ⌊log₂ n⌋ + 1 calls: 31 for n = 2³¹ − 1.

When to use: The answer; identical to Binary Search with the oracle in place of the array comparison.

Watch it run

Along 1, 2, …, n the answers of guess read 1, 1, …, 1, 0, -1, …, -1: a sorted sequence. The secret is the first number whose answer is not 1. That is a lower-bound search exactly like Search Insert Position: keep mid when its answer is <= 0, skip it when the answer is 1, stop when lo == hi.

Same O(log n) and the same number of calls in the worst case, but it never returns early on a hit, so it is usually a call or two slower. Its value is the mindset: an interactive oracle is just a sorted list you cannot see, and every boundary template still applies.

Python

def make_guess(pick: int):
    """Stand-in for LeetCode's hidden API. guess(num) -> -1 if num is too high, 1 if too low, 0 if correct."""
    def guess(num: int) -> int:
        if num > pick:
            return -1
        if num < pick:
            return 1
        return 0
    return guess


class Solution:
    def guessNumber(self, n: int, pick: int) -> int:
        guess = make_guess(pick)                # on LeetCode: guess() is given, drop this line and the pick argument
        lo, hi = 1, n                           # inclusive: hi itself can be the secret
        while lo < hi:
            mid = (lo + hi) // 2
            if guess(mid) == 1:
                lo = mid + 1                    # mid is too low, so is everything below it
            else:
                hi = mid                        # mid is the secret or too high: the secret is at or below mid
        return lo                               # the first number whose answer is not 'too low'
Time O(log n)Space O(1)

When to use: When you want one template for every yes/no oracle (First Bad Version has no 0 answer at all).

Common mistakes

  • Mixing up the sign: -1 means your guess is too high. Moving lo up on -1 searches the wrong half and the loop ends with lo > hi and no answer.
  • lo = mid or hi = mid with the inclusive range lo..hi: once two candidates are left, mid equals lo and the range stops shrinking. Move past mid with mid + 1 / mid - 1.
  • Starting at lo = 0: 0 is never the secret, so the first call is wasted and, with n = 1, you guess a number outside the allowed range.
  • Calling guess twice per round (once to test == 0, once for the sign): the problem counts calls, and the answer may change between calls in the follow-ups. Store the result in a variable.
  • In Java or C the sum lo + hi can overflow for n near 2³¹ − 1; Python integers do not overflow, but write lo + (hi - lo) // 2 if you port the code.

Python notes

  • About the pick argument. LeetCode declares guessNumber(self, n) and injects a hidden guess(num) function. A self-contained test cannot do that, so here the tests pass the secret as a second argument and the solution builds the same oracle with make_guess(pick). When you submit on LeetCode, delete the pick parameter and the guess = make_guess(pick) line; the rest of the code is unchanged.
  • The oracle's -1 / 0 / 1 is the shape of an old-style comparison function. Think of it as "which way to move".
  • Since Python 3.10, bisect.bisect_left(range(1, n + 1), 0, key=lambda x: -guess(x)) finds the pick: -guess(x) is -1 for numbers below the secret, 0 at it and 1 above, a sorted sequence. Clever, but harder to read than the loop.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Guess Number Higher or Lower II LC 375 — every wrong guess now costs its value in money and you must guarantee a win: the search becomes a minimax dynamic program over ranges, not a binary search.
  • First Bad Version LC 278 — the oracle only says yes or no (isBadVersion), so there is no exact hit: search for the boundary with while lo < hi and hi = mid on yes.
  • Binary Search LC 704 — the same loop with a visible list: guess(mid) is replaced by comparing nums[mid] with the target.
  • Search Insert Position LC 35 — what the while lo < hi alternative below really is: the lower bound of the first candidate whose guess is not 'too low'.
  • Find in Mountain Array LC 1095 — another interactive problem with a call budget; three binary searches through a get(i) interface.
  • What if the secret may be any integer, with no upper bound? — first find a range: guess 1, 2, 4, 8, … until the answer is -1 (exponential search), then binary search between the last two guesses. Still O(log pick) calls.
