Binary Tree Right Side View Medium

LeetCode #199 ↗
Status

List the nodes you would see standing on the right side of a binary tree, from top to bottom.

Problem

Given the root of a binary tree, imagine standing on its right side and looking at it. Return the values of the nodes you can see, ordered from top to bottom.

A node is visible when no other node on the same level lies to its right. The visible node is not always a right child: when the right side of the tree is shorter than the left, the lower levels are seen through the left side.

Examples

Example 1
Input: root = [1, 2, 3, None, 5, None, 4]
Output: [1, 3, 4]
Level 0 shows 1. Level 1 holds 2 and 3, and 3 is further right. Level 2 holds 5 and 4, and 4 is further right.
Example 2
Input: root = [1, 2, 3, 4, None, None, None, 5]
Output: [1, 3, 4, 5]
The right side ends at 3, so levels 2 and 3 are seen through the left side: 4 and then 5.
Example 3
Input: root = [1, None, 3]
Output: [1, 3]
Example 4
Input: root = []
Output: []

Think first try before reading the solution

Think level by level. From the right, which node of a level do you see?
With a level-order traversal (BFS), the last node you take out of each level is the rightmost one. Keep only that value for every level.
Depth-first search works too if you visit the right child first and pass the depth down: the first node you reach at a new depth is the rightmost one at that depth. len(result) tells you how many depths you have already seen.

Key idea

From the right-hand side, the node you see on each level is simply the rightmost node of that level: nothing on the level is further right. So the problem is Level Order Traversal where you keep only the last node of every level.

With BFS that is direct. Process one level per round (freeze size = len(queue), as in Level Order Traversal) and record the value of the size-th node you pop.

Depth-first search finds the same nodes if it looks at the right child first. Carry the depth down. The first time the walk reaches a depth, it is at that depth's rightmost node, because any node further right would have been reached earlier. So record a value only when depth == len(result) (a depth with no entry yet) and ignore the other nodes at that depth.

Notice that the answer is not "follow the right child pointers": when the right side ends, the visible nodes come from the left side.

Approaches from the obvious one to the one you want in an interview

Reuse Level Order Traversal as it is: build the list of all levels, then take the last value of each inner list.

Nothing here is slow. It is wasteful: it stores all n values just to keep one per level, so the extra memory is O(n) where the idea below needs only the queue (O(w)) plus the answer. It is still a perfectly good first answer, and it shows that this problem really is 'level order, last of every level'.

Dry run

  1. root = [1, 2, 3, None, 5, None, 4]
  2. level order → [[1], [2, 3], [5, 4]]
  3. last of each level → [1, 3, 4]

Python

class Solution:
    def rightSideView(self, root: Optional[TreeNode]) -> List[int]:
        if root is None:
            return []
        levels, queue = [], deque([root])
        while queue:
            level = []
            for _ in range(len(queue)):            # exactly one level per round
                node = queue.popleft()
                level.append(node.val)
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
            levels.append(level)                   # keep every value of every level ...
        return [level[-1] for level in levels]     # ... only to throw most of them away
Time O(n)Space O(n)

Every node is visited once; the stored levels hold all n values.

When to use: A quick first answer that builds on Level Order Traversal. The next two versions avoid storing every level.

Run the same level-by-level BFS, but do not store the levels. In each round the queue holds exactly one level, and the nodes are popped from left to right, so the last node popped is the rightmost one. Append only that value to the answer.

for i in range(size) gives you the position i inside the level, and i == size - 1 marks the last one. The children of every node still go to the back of the queue, hidden or not, because a hidden node can have visible descendants (example 2). Time is O(n), and the extra space is one level (the queue) plus the answer.

Dry run

  1. root = [1, 2, 3, None, 5, None, 4], queue = [1]
  2. level 0, size 1: pop 1 (last) → record 1; queue 2, 3
  3. level 1, size 2: pop 2 (not last, hidden; queue its child 5), pop 3 (last) → record 3; queue 4
  4. level 2, size 2: pop 5 (hidden), pop 4 (last) → record 4
  5. queue empty → [1, 3, 4]

Python

class Solution:
    def rightSideView(self, root: Optional[TreeNode]) -> List[int]:
        if root is None:
            return []
        view = []
        queue = deque([root])
        while queue:
            size = len(queue)                      # exactly the nodes of this level
            for i in range(size):
                node = queue.popleft()
                if i == size - 1:                  # the last node of the level is the rightmost one
                    view.append(node.val)
                if node.left:                      # hidden nodes still pass their children on
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
        return view
Time O(n)Space O(w)

Each node enters and leaves the queue once. The queue holds at most one level; w (the widest level) is up to n/2.

When to use: The default: it is Level Order Traversal with one extra if.

Watch it run

Walk depth-first, carrying the depth, and look at the right child before the left. Keep a list view where view[d] is the visible value at depth d. When the walk reaches a node whose depth is len(view), the view has no entry for that depth yet, so this is the first node reached there. Since the right side is explored first, that node is the rightmost one at its depth: append it. Any later node at an already-seen depth is hidden and is skipped (but its children are still explored).

Same O(n) time. The extra space is the recursion depth h instead of the width w, which is smaller for a wide, shallow tree and larger for a chain.

Dry run

  1. root = [1, 2, 3, 4, None, None, None, 5], view = []
  2. dfs(1, depth 0): depth 0 == len(view) 0 → record 1. Go right: dfs(3, depth 1): 1 == 1 → record 3.
  3. Node 3 has no children. Back up, then left: dfs(2, depth 1): len(view) is 2, so depth 1 is already covered by 3 → hidden.
  4. 2 has no right child; its left child: dfs(4, depth 2): 2 == 2 → record 4. Then dfs(5, depth 3): 3 == 3 → record 5.
  5. view = [1, 3, 4, 5]

Python

class Solution:
    def rightSideView(self, root: Optional[TreeNode]) -> List[int]:
        view = []

        def dfs(node, depth):
            if node is None:
                return
            if depth == len(view):                 # first node reached at this depth: the rightmost one
                view.append(node.val)
            dfs(node.right, depth + 1)             # right first, so each depth is reached from its right edge
            dfs(node.left, depth + 1)

        dfs(root, 0)
        return view
Time O(n)Space O(h)

Every node is visited once. The call stack is as deep as the tree is tall.

When to use: When recursion is more natural than a queue, or when the tree is wide but shallow.

Common mistakes

  • Following only node.right from the root. In [1, 2, 3, 4] that gives [1, 3], but node 4 is visible on level 2 because nothing on that level is to its right.
  • Recording the first node of each level in BFS (level[0]). That is the left side view. The right side view needs the last one.
  • Mixing up the DFS rules. 'Record only when the depth is new' gives the right side view only if you visit the right child first. With the left child first it gives the left side view.
  • Not freezing the level size in BFS (re-reading len(queue) while appending). The 'last node of the level' then belongs to the next level.
  • Forgetting the empty tree: with root = None the answer is [], and deque([None]) would crash on .val.

Python notes

  • i == size - 1 identifies the last node popped in a round. A deque also lets you peek at its right end in O(1) with queue[-1], so view.append(queue[-1].val) before popping the level works as well.
  • In the DFS, len(view) doubles as 'the number of depths seen so far'. A depth is reached for the first time exactly when depth == len(view), because depths are first reached in the order 0, 1, 2, ...
  • [level[-1] for level in levels] takes the last item of every inner list with a list comprehension.
  • deque is pre-imported for solutions on this site (as it is on LeetCode). In your own file write from collections import deque.

What an interviewer might ask next, and what changes.

  • Binary Tree Level Order Traversal LC 102 — the traversal this solution is built on; there you keep every node of a level instead of only the last.
  • Find Largest Value in Each Tree Row LC 515 — the same level loop, keeping the maximum of each level instead of its last node.
  • Find Bottom Left Tree Value LC 513 — the leftmost node of the last level: BFS that records the first node of every round, or BFS that adds the right child before the left one.
  • Vertical Order Traversal of a Binary Tree LC 987 — a view from above instead of from the side: give each node a column number (left child = column − 1, right child = column + 1) and group by column.
  • Left side view — mirror image: record the first node of each level in BFS, or run the DFS with the left child visited first.
