IPO Hard 250

LeetCode #502 ↗
Status

With limited starting capital, finish at most k projects, each unlocked by a capital requirement and paying a profit, so that you end with as much capital as possible.

Problem

You start with w units of capital and may finish at most k projects out of n. Project i can only be started when your capital is at least capital[i]; starting it costs nothing (the requirement is a threshold, not a price), and finishing it adds profits[i] to your capital. Each project can be done at most once.

Pick the projects, in any order you like, so that your final capital is as large as possible, and return that capital.

Examples

Example 1
Input: k = 2, w = 0, profits = [1, 2, 3], capital = [0, 1, 1]
Output: 4
With 0 capital only project 0 (needs 0) is affordable: finish it, w = 1. Now projects 1 and 2 are both affordable; take the more profitable one, +3: w = 4.
Example 2
Input: k = 3, w = 0, profits = [1, 2, 3], capital = [0, 1, 2]
Output: 6
Each project unlocks the next: 0 → 1 → 3 → 6.
Example 3
Input: k = 1, w = 2, profits = [1, 2, 3], capital = [1, 1, 2]
Output: 5
All three are affordable from the start. One round only, so take the biggest profit: 2 + 3 = 5.

Constraints

  • 1 <= k <= 10^5
  • 0 <= w <= 10^9
  • 1 <= n = len(profits) = len(capital) <= 10^5
  • 0 <= profits[i] <= 10^4
  • 0 <= capital[i] <= 10^9

Think first try before reading the solution

Profits are never negative, so capital only grows. A project that is affordable now stays affordable: the set of affordable projects only ever gets bigger.
Among the affordable projects, which one should you finish next? The most profitable: there is no cost, and a bigger w can only unlock more. Picking the cheapest or the earliest unlocked is a mistake.
Sort the projects by capital. A pointer moves the newly affordable ones into a max-heap of profits as w grows; each round pops the root. If the heap is empty, nothing can ever unlock, so stop early.

Key idea

Two facts make this greedy. First, capital never shrinks (starting is free and profits are >= 0), so once a project is affordable it stays affordable. Second, every finished project adds its full profit to w, no matter which project it is. So in each round the best move is simply the most profitable project you can afford right now: if some optimal plan took a cheaper project instead, swapping in the more profitable one leaves w at least as large at every later step, so nothing that plan could afford becomes unaffordable.

Two orders are mixed again, like in Single Threaded CPU: projects unlock in order of capital, but we pick by profit. Sort the indices by capital once and sweep a pointer over them; every project whose requirement is <= w moves into a max-heap of profits. Each round: unlock, pop the root, add it to w. A project moves into the heap once and out at most once, so the whole thing is O(n log n) plus O(k log n).

If a round finds the heap empty, w cannot grow, so no further project will ever unlock: return w at once instead of spinning through the remaining rounds.

Approaches from the obvious one to the one you want in an interview

Repeat up to k times: scan all projects, and among the unused ones with capital[i] <= w pick the one with the largest profit; add that profit to w. If no project is affordable, stop.

The choice is the right greedy choice, so the answer is correct. The cost is the rescan: each round looks at all n projects, O(k · n), which is 10¹⁰ at the limits. Most of that work repeats itself, because a project that was affordable last round is still affordable now.

Dry run

  1. k = 2, w = 0, profits = [1, 2, 3], capital = [0, 1, 1]
  2. round 1: only project 0 is affordable → w = 1
  3. round 2: projects 1 (profit 2) and 2 (profit 3) are affordable → take 3 → w = 4

Python

class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        n = len(profits)
        used = [False] * n
        for _ in range(k):
            best = -1                             # affordable, unused project with the largest profit
            for i in range(n):
                if not used[i] and capital[i] <= w and (best == -1 or profits[i] > profits[best]):
                    best = i
            if best == -1:                        # nothing affordable: more rounds cannot help
                break
            used[best] = True
            w += profits[best]                    # starting costs nothing; finishing pays the profit
        return w
Time O(k · n)Space O(n)

Up to k rounds, each scanning all n projects.

When to use: To confirm the greedy rule on a small input; too slow for the real limits.

Sort the project indices by capital. Keep a pointer nxt into that order and a max-heap of profits (negated) for the projects we can afford. Each of the k rounds:

  1. while the project at nxt needs <= w, push its profit and advance nxt (capital never shrinks, so these projects stay affordable forever);
  2. if the heap is empty, stop: w cannot grow, so nothing else will unlock;
  3. pop the largest profit and add it to w.

Every project is pushed at most once and popped at most once: O(n log n) for the sort and the pushes, O(k log n) for the pops.

Dry run

  1. k = 2, w = 0, profits = [1, 2, 3], capital = [0, 1, 1] → sorted by capital: (0 → 1), (1 → 2), (1 → 3)
  2. round 1: unlock (0 → 1); pop 1 → w = 1
  3. round 2: unlock (1 → 2) and (1 → 3); pop 3 → w = 4

Python

class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        n = len(profits)
        by_capital = sorted(range(n), key=lambda i: capital[i])   # cheapest requirement first
        affordable = []                           # max-heap of profits (negated) we could start now
        nxt = 0                                   # next project in by_capital that is still locked
        for _ in range(k):
            while nxt < n and capital[by_capital[nxt]] <= w:      # unlock everything we can now afford
                heapq.heappush(affordable, -profits[by_capital[nxt]])
                nxt += 1
            if not affordable:                    # nothing affordable, and w cannot grow: stop early
                break
            w -= heapq.heappop(affordable)        # take the most profitable one (minus a negative = plus)
        return w
Time O(n log n + k log n)Space O(n)

One sort; each project is pushed at most once (O(n log n) total) and each round pops once (O(k log n)).

When to use: The interview answer: the 'sorted unlock order + heap for the pick order' pattern.

Watch it run

Instead of sorting and keeping a pointer, put every project into a min-heap keyed by capital (the locked pile). Each round, move projects from the locked pile into the max-heap of profits while the locked root's requirement is <= w, then pop the best profit.

Same complexity and the same greedy rule; the sorted list is replaced by a heap that hands out the cheapest locked project. Some people find the two symmetric heaps easier to reason about; the pointer version does slightly less work because heapify plus pops is a lazier sort.

Python

class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        locked = list(zip(capital, profits))      # min-heap by capital needed: the projects we cannot start yet
        heapq.heapify(locked)
        affordable = []                           # max-heap of profits (negated): the projects we can start
        for _ in range(k):
            while locked and locked[0][0] <= w:   # cheapest locked project is now within reach
                need, profit = heapq.heappop(locked)
                heapq.heappush(affordable, -profit)
            if not affordable:
                break
            w -= heapq.heappop(affordable)
        return w
Time O(n log n + k log n)Space O(n)

heapify is O(n); each project moves between the heaps once; k pops from the profit heap.

When to use: When you prefer symmetric data structures over a sorted list with a pointer.

Common mistakes

  • Subtracting capital[i] from w when starting a project. Nothing is spent: the requirement is a threshold and w only grows.
  • Taking the cheapest affordable project instead of the most profitable: k = 1, w = 5, profits = [1, 10], capital = [0, 5] must give 15, not 6.
  • Re-scanning every project in every round: O(k · n) is 10¹⁰ at the limits. Sort once and keep a heap.
  • Pushing profits into heapq without negating: you would pop the least profitable project.
  • Forgetting to advance the pointer after pushing, or re-pushing on every round: the same project ends up in the heap twice.
  • Looping all k rounds when the heap is empty: popping from an empty heap raises IndexError; break out instead.

Python notes

  • sorted(range(n), key=lambda i: capital[i]) sorts the indices, so profits[i] is still reachable for each project.
  • heapq is a min-heap: push -profit and pop with w -= heapq.heappop(heap) (subtracting a negative adds the profit).
  • zip(capital, profits) pairs the two lists; heapq.heapify turns the pair list into a min-heap by capital in O(n) for the two-heap version.
  • Python ints do not overflow: w can reach 10⁹ + 10⁵ · 10⁴ without any special care.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Maximum Performance of a Team LC 1383 — sort by one attribute (efficiency) and keep a heap on the other (speed), with a size limit k instead of a round limit.
  • Course Schedule III LC 630 — sort by deadline, keep a max-heap of durations, and undo the longest course when the schedule overruns.
  • Furthest Building You Can Reach LC 1642 — a heap decides where the k ladders go: the k largest climbs seen so far take ladders, the rest consume bricks.
  • Single Threaded CPU LC 1834 — the same 'sorted unlock order + heap for the pick order' shape, with time instead of capital as the unlocking resource.
  • What if starting a project *spent* its capital? — the exchange argument breaks (a costly project can lock you out of two cheaper ones); it becomes a knapsack-style dynamic program.
  • What if profits could be negative? — never take a project with negative profit: it lowers w and unlocks nothing; skip it when pushing, or stop when the root is negative.
