K Closest Points to Origin Medium

LeetCode #973 ↗
Status

From a list of 2-D points, return the k that are nearest to (0, 0).

Problem

You are given a list of points on a flat plane, points[i] = [x, y], and an integer k. Return the k points that are closest to the origin (0, 0), using ordinary straight-line (Euclidean) distance √(x² + y²).

  • You may return the points in any order.
  • The answer is guaranteed to be unique apart from its order (there is never a tie at the cut-off).

Examples

Example 1
Input: points = [[1, 3], [-2, 2]], k = 1
Output: [[-2, 2]]
Squared distances: 1² + 3² = 10 and (-2)² + 2² = 8. The second point is closer.
Example 2
Input: points = [[3, 3], [5, -1], [-2, 4]], k = 2
Output: [[3, 3], [-2, 4]]
Squared distances 18, 26 and 20. The two smallest are 18 and 20. [[-2, 4], [3, 3]] is also accepted.

Constraints

  • 1 <= k <= len(points) <= 10^4
  • -10^4 <= x, y <= 10^4

Think first try before reading the solution

You never need the square root. For non-negative numbers, a² < b² exactly when a < b, so compare x*x + y*y directly.
Sorting all points by distance works in O(n log n). Do you really need to put the far-away points in order?
Walk the points while keeping the k closest seen so far. The one you might have to throw out is the farthest of them, so keep them in a max-heap (push -distance) and replace the root whenever a closer point turns up.

Key idea

Only the k closest points matter, so keep a "shortlist" of k points while you scan. The shortlist member at risk is the farthest one: it sets the bar a newcomer has to beat. A max-heap keyed by distance keeps that farthest point at the root, readable in O(1).

For each point: if the shortlist is not full, add it. Otherwise compare with the root: closer → it replaces the root (heapreplace); not closer → ignore it forever. Python's heapq is a min-heap, so store -distance. Each point costs at most O(log k), and memory stays at k points: O(n log k) time, O(k) space.

Use the squared distance x*x + y*y throughout: it keeps everything in exact integers and preserves the order.

Approaches from the obvious one to the one you want in an interview

Sort the points by squared distance and return the first k. The key x*x + y*y gives the same order as the real distance, so no square root is needed.

Short and correct, but it puts all n points in order (O(n log n)) when only the k nearest matter, and it needs every point in memory at once.

Dry run

  1. [[3, 3], [5, -1], [-2, 4]] → squared distances 18, 26, 20
  2. sorted by distance: [3, 3] (18), [-2, 4] (20), [5, -1] (26)
  3. first k = 2 → [[3, 3], [-2, 4]]

Python

class Solution:
    def kClosest(self, points: List[List[int]], k: int) -> List[List[int]]:
        # squared distance keeps the same order as the real distance, and stays an int
        by_distance = sorted(points, key=lambda p: p[0] * p[0] + p[1] * p[1])
        return by_distance[:k]
Time O(n log n)Space O(n)

The sort dominates; sorted builds a new list of n points.

When to use: When n is small, or when you need the points in distance order anyway.

Scan the points while keeping a heap of the k closest seen so far, keyed by negated squared distance so the root is the farthest kept point:

  • fewer than k kept → push the point;
  • otherwise, if the point is closer than the root → heapreplace (drop the root, add the point);
  • otherwise → skip it; k points are already closer, so it can never be in the answer.

The heap never holds more than k entries, so each point costs O(log k). This is the size-k heap trick from Kth Largest, flipped: to keep the smallest distances, the heap must expose the largest one.

Dry run

  1. k = 2, points [[1, 3], [-2, 2], [5, 8], [0, 1], [3, -1]], d² = 10, 8, 89, 1, 10
  2. push [1, 3] (10), push [-2, 2] (8) → full, root = farthest kept = 10
  3. [5, 8] (89) is not closer than 10 → skip
  4. [0, 1] (1) is closer than 10 → replace [1, 3]; the root is now 8
  5. [3, -1] (10) is not closer than 8 → skip → answer [[-2, 2], [0, 1]]

Python

class Solution:
    def kClosest(self, points: List[List[int]], k: int) -> List[List[int]]:
        heap = []                                    # max-heap via negation: (-dist, x, y)
        for x, y in points:
            dist = x * x + y * y                     # squared distance
            if len(heap) < k:
                heapq.heappush(heap, (-dist, x, y))
            elif dist < -heap[0][0]:                 # closer than the farthest point we keep
                heapq.heapreplace(heap, (-dist, x, y))
        return [[x, y] for _, x, y in heap]
Time O(n log k)Space O(k)

n points, each with at most one heap operation on a heap of size k.

When to use: The interview answer: good when k is much smaller than n, and it works on a stream of points.

Watch it run

We do not need the k closest points sorted, only separated from the rest. Quickselect does exactly that. Pick a random pivot point and rearrange the list so every point closer than the pivot comes first, then the pivot. If the pivot lands at index k - 1, the first k points are the answer. Otherwise only one side can contain the cut, so repeat on that side alone.

Each round scans the current range and, on average, throws away about half of it: n + n/2 + n/4 + … ≈ 2n, so O(n) on average. An unlucky run of pivots costs O(n²); the random pivot makes that very unlikely. Many equal distances also slow this two-way split down; the three-way split in Kth Largest Element in an Array fixes that. It needs every point in memory and reorders the input list.

Python

class Solution:
    def kClosest(self, points: List[List[int]], k: int) -> List[List[int]]:
        def dist(p):
            return p[0] * p[0] + p[1] * p[1]

        def partition(lo, hi):
            r = random.randint(lo, hi)               # random pivot, parked at the end
            points[r], points[hi] = points[hi], points[r]
            pivot = dist(points[hi])
            store = lo                               # points[lo:store] are closer than the pivot
            for i in range(lo, hi):
                if dist(points[i]) < pivot:
                    points[store], points[i] = points[i], points[store]
                    store += 1
            points[store], points[hi] = points[hi], points[store]
            return store                             # the pivot's final position

        lo, hi = 0, len(points) - 1
        while lo < hi:
            p = partition(lo, hi)
            if p == k - 1:                           # the first k points are the k closest
                break
            if p < k - 1:
                lo = p + 1                           # the cut is to the right of the pivot
            else:
                hi = p - 1                           # the cut is to the left of the pivot
        return points[:k]
Time O(n) average, O(n²) worstSpace O(1) extra

Each partition is linear in the current range; on average the range halves. Works in place.

When to use: When all points are in memory and you want the best average time; mention the worst case and that the input is reordered.

Common mistakes

  • Taking math.sqrt for every point: it is slower, introduces floats, and changes nothing about the order. Compare squared distances.
  • Using a min-heap of size k: the root is then the closest point, so trimming the heap throws away exactly the points you want. A size-k shortlist of the smallest distances needs a max-heap (negate).
  • Returning the heap entries (-dist, x, y) instead of the points [x, y]. Unpack them at the end.
  • Pushing (dist, point_object) where the payload cannot be compared: on a distance tie Python compares the payloads. Plain ints (-dist, x, y) or an index (-dist, i) are always safe.
  • Quickselect without a random pivot degrades to O(n²) on already-sorted input. It also reorders the input list in place.

Python notes

  • heapq.heapreplace(heap, item) pops the root and pushes item in a single pass down the heap: exactly "swap out the farthest point".
  • heapq.nsmallest(k, points, key=lambda p: p[0] * p[0] + p[1] * p[1]) is a one-line answer; it keeps a size-k heap internally.
  • x * x stays an exact int; math.hypot(x, y) and math.dist return floats.
  • Tuples compare item by item, so (-dist, x, y) orders by distance first; equal distances fall back to plain ints, which is safe.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Kth Largest Element in an Array LC 215 — the same 'select k, do not sort everything' question on plain numbers; heap and quickselect both carry over.
  • Top K Frequent Elements LC 347 — the size-k heap ranks values by how often they occur instead of by distance.
  • Find K Closest Elements LC 658 — one dimension and the array is already sorted: binary-search the start of a k-wide window instead of using a heap.
  • What if the points arrive as a stream? — the size-k max-heap already works one point at a time with O(k) memory; sorting and quickselect need all points up front.
  • What if k is close to n? — a size-k heap saves little. Either sort, or keep the n - k farthest points in a min-heap and return everything else.
