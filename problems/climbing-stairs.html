Climbing Stairs Easy

LeetCode #70 ↗
Status

Count the different ways to reach the top of n stairs when every move climbs 1 or 2 stairs.

Problem

You stand at the bottom of a staircase with n stairs. Each move climbs either 1 or 2 stairs. Return how many different sequences of moves end exactly on stair n.

  • Order matters: 1 + 2 and 2 + 1 are two different ways.
  • n is at least 1 and the answer fits in a 32-bit integer.

Examples

Example 1
Input: n = 2
Output: 2
1 + 1 or 2.
Example 2
Input: n = 3
Output: 3
1 + 1 + 1, 1 + 2 or 2 + 1.
Example 3
Input: n = 5
Output: 8

Constraints

  • 1 <= n <= 45

Think first try before reading the solution

Do not try to list the sequences. Think about the last move: to stand on stair n, where could you have been just before it?
You were on stair n - 1 (then took 1 step) or on stair n - 2 (then took 2). Those two groups never overlap, so ways(n) = ways(n - 1) + ways(n - 2). What are the smallest cases?
The plain recursion recomputes the same ways(k) over and over. Store each answer once: fill a list from stair 0 upward, or keep only the last two values.

Key idea

Look at the last move. Whatever happened before, the final move onto stair n was either a 1-step from stair n - 1 or a 2-step from stair n - 2. The two groups never overlap (their last moves differ) and together they contain every way. So

ways(n) = ways(n - 1) + ways(n - 2), with ways(0) = 1 and ways(1) = 1.

ways(0) = 1 says there is exactly one way to climb zero stairs: make no move. It is what makes ways(2) = 1 + 1 = 2 come out right. The sequence 1, 1, 2, 3, 5, 8, ... is the Fibonacci sequence.

As plain recursion this is correct but slow: ways(5) computes ways(3) twice and ways(2) three times, and the repeats multiply as n grows. Dynamic programming computes each ways(k) once and stores it, either by caching the recursive function (memoisation) or by filling a list from stair 0 upward (tabulation). Each value needs only the two before it, so in the end two variables replace the whole list.

Approaches from the obvious one to the one you want in an interview

Turn the recurrence straight into code: ways(n) = ways(n - 1) + ways(n - 2), stopping at ways(0) = ways(1) = 1. It is correct, and it shows the structure of the problem clearly.

It is also exponential. Each call makes two more calls, and the same arguments come back many times: ways(5) computes ways(3) twice, ways(2) three times and ways(1) five times. The number of calls is 2 × answer − 1, which grows by a factor of about 1.6 per extra stair.

Dry run

  1. ways(4) → needs ways(3) and ways(2)
  2. ways(3) → needs ways(2) and ways(1); ways(2) → ways(1) + ways(0) = 1 + 1 = 2; so ways(3) = 2 + 1 = 3
  3. back in ways(4): ways(2) is computed again from scratch → 2
  4. ways(4) = 3 + 2 = 5, after 9 calls for 5 different arguments

Python

class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 1:                     # 0 stairs: no move; 1 stair: one 1-step
            return 1
        # the last move was a 1-step (from n - 1) or a 2-step (from n - 2)
        return self.climbStairs(n - 1) + self.climbStairs(n - 2)
Time O(φⁿ) ≈ O(1.62ⁿ)Space O(n)

Every call branches in two, and repeated arguments are recomputed; the call stack is at most n deep.

When to use: Only to discover the recurrence. It passes the small tests here and times out long before n = 45.

Watch it run

Keep the recursion and add a cache. Memoisation means storing the result of a function call the first time it is computed and returning the stored value on every later call with the same argument. In Python, @cache does this for you.

There are only n + 1 different arguments (0..n), each computed once with one addition, so the total work drops from exponential to O(n). The recursion still goes n frames deep, which is fine here.

Dry run

  1. ways(5) → ways(4) → ways(3) → ways(2) → base cases ways(1) = 1, ways(0) = 1; store ways(2) = 2
  2. ways(3) needs ways(1): cache hit → 1; store ways(3) = 3
  3. ways(4) needs ways(2): cache hit → 2; store ways(4) = 5
  4. ways(5) needs ways(3): cache hit → 3; ways(5) = 8

Python

class Solution:
    def climbStairs(self, n: int) -> int:
        @cache                          # remembers ways(k) after its first computation
        def ways(k: int) -> int:
            if k <= 1:
                return 1
            return ways(k - 1) + ways(k - 2)

        return ways(n)
Time O(n)Space O(n)

n + 1 distinct states, O(1) work each; the cache and the call stack both hold O(n) entries.

When to use: When the recursive formulation is the natural one; it is often the fastest DP to write correctly.

Watch it run

Turn the recursion inside out. Instead of starting at n and asking for smaller answers, start at the smallest stairs and build upward. Tabulation means filling a list dp where dp[i] = ways to reach stair i:

  • base cases dp[0] = dp[1] = 1;
  • for i = 2..n: dp[i] = dp[i - 1] + dp[i - 2].

Left to right is the right order because each cell reads only cells to its left, which are already final. No recursion means no recursion limit, and the table makes the next optimisation visible.

Dry run

  1. n = 5: dp = [1, 1, ?, ?, ?, ?]
  2. dp[2] = dp[1] + dp[0] = 1 + 1 = 2
  3. dp[3] = 2 + 1 = 3, dp[4] = 3 + 2 = 5, dp[5] = 5 + 3 = 8
  4. answer dp[5] = 8

Python

class Solution:
    def climbStairs(self, n: int) -> int:
        dp = [0] * (n + 1)              # dp[i] = number of ways to reach stair i
        dp[0] = 1                       # one way to climb nothing: make no move
        dp[1] = 1                       # one 1-step
        for i in range(2, n + 1):       # left to right: dp[i-1] and dp[i-2] are ready
            dp[i] = dp[i - 1] + dp[i - 2]
        return dp[n]
Time O(n)Space O(n)

One pass over n + 1 cells, one addition each.

When to use: The standard way to write DP without recursion; start here when you are unsure of the fill order.

Watch it run

Look at the table loop: cell i reads only cells i - 1 and i - 2. Everything older is never read again, so keep just two numbers, two_back and one_back, and slide them forward one stair per iteration.

This is the space optimisation step of the DP recipe: same recurrence, same O(n) time, but O(1) memory.

Dry run

  1. two_back, one_back = 1, 1 (stairs 0 and 1)
  2. stair 2: new = 1 + 1 = 2 → (1, 2)
  3. stair 3: new = 2 + 1 = 3 → (2, 3); stair 4: → (3, 5); stair 5: → (5, 8)
  4. answer one_back = 8

Python

class Solution:
    def climbStairs(self, n: int) -> int:
        two_back, one_back = 1, 1       # ways to reach stairs i - 2 and i - 1, starting with stairs 0 and 1
        for _ in range(2, n + 1):
            # the new value is the sum of the last two; tuple assignment uses the old values on the right
            two_back, one_back = one_back, one_back + two_back
        return one_back
Time O(n)Space O(1)

One pass, two integers of state.

When to use: The interview answer. Present it as the table with everything but the last two cells thrown away.

Common mistakes

  • Running the recursion without a cache. The number of calls is 2 × answer − 1, so n = 45 makes about 3.7 billion calls. Add @cache or loop bottom-up.
  • Treating 1 + 2 and 2 + 1 as the same way. The problem counts orderings; the last-move recurrence counts orderings automatically, while a formula over "how many 2-steps" needs extra arrangement counting.
  • Allocating dp = [0] * n and then writing dp[n]. Stairs are numbered 0 to n, so the list needs n + 1 slots.
  • Hard-coding dp[2] = 2 as a base case and crashing with IndexError when n = 1. Base cases dp[0] = dp[1] = 1 cover every n >= 1 without special cases.
  • Updating rolling variables in two lines (two_back = one_back, then one_back = one_back + two_back): the second line already sees the new two_back. Use one tuple assignment.

Python notes

  • @cache (from functools, pre-imported here) memoises a function: the first call with an argument runs the body, later calls with the same argument return the stored result. Put it on a helper defined inside the method so each call to climbStairs starts with a fresh cache.
  • Python's default recursion limit is 1000 frames. The top-down version recurses n deep, which is fine for n <= 45; for inputs in the thousands prefer the bottom-up loop (or raise the limit with sys.setrecursionlimit).
  • two_back, one_back = one_back, one_back + two_back evaluates the whole right side first, so both new values come from the old ones.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Min Cost Climbing Stairs LC 746 — each stair has a price and you want the cheapest climb: + becomes min, and each option adds the price of the stair you leave from.
  • N-th Tribonacci Number LC 1137 — each term is the sum of the previous three: keep three rolling variables.
  • Combination Sum IV LC 377 — the allowed step sizes come from a list nums: dp[i] = sum(dp[i - s] for s in nums if s <= i). Same "last move" idea with more choices.
  • Count Ways To Build Good Strings LC 2466 — steps of size zero or one, every length in [low, high] counts, answer modulo 10^9 + 7: fill the table, then sum a slice of it.
  • Decode Ways LC 91 — the same two-term recurrence, but a term only counts when its 1- or 2-digit piece is a valid code.
  • What if n is 10^18? — even an O(n) loop is too slow. The recurrence is a 2×2 matrix power, which repeated squaring computes in O(log n) multiplications (answer taken modulo a prime).
