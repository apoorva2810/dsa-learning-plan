Concatenation of Array Easy 250

LeetCode #1929 ↗
Status

Return the list followed by a second copy of itself.

Problem

You are given a list of integers nums with n elements. Build and return a new list ans with 2n elements that is nums followed by nums again.

In other words, for every index i from 0 to n - 1:

  • ans[i] = nums[i] (the first copy), and
  • ans[i + n] = nums[i] (the second copy, exactly n slots to the right).

Examples

Example 1
Input: nums = [1, 2, 1]
Output: [1, 2, 1, 1, 2, 1]
Slots 0..2 hold the first copy of nums, slots 3..5 hold the second copy.
Example 2
Input: nums = [1, 3, 2, 1]
Output: [1, 3, 2, 1, 1, 3, 2, 1]
n = 4, so nums[0] = 1 lands at index 0 and at index 4, nums[1] = 3 at 1 and 5, and so on.
Example 3
Input: nums = [7]
Output: [7, 7]

Constraints

  • n == len(nums)
  • 1 <= n <= 1000
  • 1 <= nums[i] <= 1000
  • the answer has exactly 2n elements

Think first try before reading the solution

The answer has twice as many slots as nums. Every value of nums must appear in it twice. Where exactly?
The second copy of nums[i] sits exactly n slots after the first one: ans[i + n] = nums[i].
Make a list of 2n slots and fill both positions in one pass. Or read it the other way round: ans[j] = nums[j % n] for every j from 0 to 2n - 1.

Key idea

Concatenation is copying: every value appears twice, once at its own index i and once shifted by n, at i + n. Any correct method has to write 2n slots, so every approach is O(n); there is no clever speed-up to find. What the problem really practises is index arithmetic: i + n says "the same position in the second copy", and j % n (the remainder of j divided by n) says "wrap j back into the first copy". Both come back in rotation and circular-array problems.

In Python the whole thing is also one expression, nums + nums, and it is worth knowing both the explicit loop and the idiom.

Approaches from the obvious one to the one you want in an interview

Read the problem literally: the answer is nums, then nums again. So start with an empty list, append every value of nums, then run a second loop that appends every value again.

It is already O(n), because any answer has to produce 2n values. The only waste is reading nums twice; the next approach reads it once and knows in advance where both copies go.

Dry run

  1. nums = [1, 2, 1], ans = []
  2. loop 1: append 1, 2, 1 → ans = [1, 2, 1]
  3. loop 2: append 1, 2, 1 again → ans = [1, 2, 1, 1, 2, 1]

Python

class Solution:
    def getConcatenation(self, nums: List[int]) -> List[int]:
        ans = []
        for x in nums:             # first copy
            ans.append(x)
        for x in nums:             # second copy: the same values again
            ans.append(x)
        return ans
Time O(n)Space O(n)

2n appends; the answer itself is the only extra memory.

When to use: A perfectly good answer. Reach for the next one when you want to see the index arithmetic.

Watch it run

Create the answer with 2n slots up front. Then walk nums once: the value at index i belongs at ans[i] and at ans[i + n], because the second copy starts n slots after the first.

Same O(n), one read per element instead of two, and no list growth during the loop. The habit of asking "which index in the other copy?" is what the later rotation and circular-array problems build on.

Dry run

  1. nums = [1, 2, 1], n = 3, ans = [0, 0, 0, 0, 0, 0]
  2. i = 0: ans[0] = 1 and ans[3] = 1
  3. i = 1: ans[1] = 2 and ans[4] = 2
  4. i = 2: ans[2] = 1 and ans[5] = 1 → [1, 2, 1, 1, 2, 1]

Python

class Solution:
    def getConcatenation(self, nums: List[int]) -> List[int]:
        n = len(nums)
        ans = [0] * (2 * n)        # 2n slots, filled in below
        for i in range(n):
            ans[i] = nums[i]       # first copy
            ans[i + n] = nums[i]   # second copy, n slots to the right
        return ans
Time O(n)Space O(n)

One loop of n iterations with two O(1) writes each; the answer is the only memory used.

When to use: The version to write by hand in an interview: it shows you know where every element lands.

Watch it run

List concatenation with + builds a new list holding both copies; nums * 2 does the same. Both run inside the interpreter's C code, so they are the fastest in practice, and they are what you would write in real code. In an interview, mention it and then show that you can do it by hand.

Python

class Solution:
    def getConcatenation(self, nums: List[int]) -> List[int]:
        return nums + nums         # or: nums * 2
Time O(n)Space O(n)

The copy still touches 2n elements; it is just done in C.

When to use: Real code. Be ready to explain that nums * 2 repeats the list, not the values inside it.

Common mistakes

  • Writing only the first copy (ans[i] = nums[i]) and forgetting ans[i + n], or using i * 2 instead of i + n for the second position.
  • Appending the second copy while iterating over ans itself (for x in ans: ans.append(x)) never ends: the list grows as fast as the loop reads it. Iterate over nums.
  • ans = [0] * n gives only n slots; writing ans[i + n] then raises IndexError. The answer needs 2 * n slots.
  • nums.extend(nums) works, but it changes the caller's list in place instead of returning a new one.

Python notes

  • nums + nums builds a new list of both copies; nums * 2 does the same. Both run in C and are the fastest way in practice.
  • [0] * (2 * n) creates a list of 2n zeros to fill in. The same trick with a list inside, [[0]] * k, repeats one inner list object k times, which is almost never what you want.
  • j % n is the remainder of j divided by n; for j in 0..2n-1 it gives 0..n-1 twice, which is exactly "wrap around to the start".

Follow-up questions

What an interviewer might ask next, and what changes.

  • Rotate Array LC 189 — rotate right by k: in the doubled list the answer is the slice ans[n - k : 2n - k]; the O(1)-space version uses the same wrap-around index (i + k) % n.
  • Shuffle the Array LC 1470 — the two halves must be interleaved instead of placed side by side: ans[2i] = nums[i] and ans[2i + 1] = nums[n + i].
  • Build Array from Permutation LC 1920 — ans[i] = nums[nums[i]]: the same preallocate-and-fill shape, with a value used as an index.
  • Next Greater Element II LC 503 — a circular array: instead of building the doubled list, loop i from 0 to 2n - 1 and read nums[i % n], which saves the O(n) copy.
  • Concatenate k copies instead of 2 — ans has k * n slots and ans[j] = nums[j % n]; in Python simply nums * k.
