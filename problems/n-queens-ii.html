N-Queens II Hard 250

LeetCode #52 ↗
Status

Count the ways to place n queens on an n x n board so that no two attack each other, without building the boards.

Problem

A chess queen attacks every square in her row, her column and both of her diagonals. Given an integer n, return how many ways there are to place n queens on an n x n board so that no two queens attack each other.

Two placements count as different whenever some queen stands on a different square, so mirror images and rotations are counted separately. Only the number is wanted, not the boards.

Examples

Example 1
Input: n = 4
Output: 2
The two solutions are mirror images of each other: queens in columns 1, 3, 0, 2 and in columns 2, 0, 3, 1 (top row first).
Example 2
Input: n = 1
Output: 1
A single queen on a single square.
Example 3
Input: n = 3
Output: 0
Three queens cannot be placed on a 3 x 3 board without an attack.

Constraints

  • 1 <= n <= 9

Think first try before reading the solution

This is N-Queens without the boards. Run the same row-by-row search, one queen per row, and add 1 to a counter instead of saving a board. Three sets (taken columns, taken r - c, taken r + c) already make the attack test O(1).
Only a number is wanted, so the state can shrink. For the row you are about to fill, all you need is: which of its n squares are attacked? That is one yes/no per column, and n yes/no values fit into one integer with n bits.
Keep three masks: cols (columns holding a queen), diag (squares of the current row attacked along a ↘ diagonal) and anti (along a ↙ diagonal). Going down one row shifts diag left and anti right. free = full & ~(cols | diag | anti) has a 1 on every safe column, and free & -free picks out the lowest set bit.

Key idea

The search tree is exactly the one from N-Queens: one queen per row, try each column, skip attacked squares, and go one row down. The only change is at the bottom: when row == n we add 1 instead of copying a board. So any N-Queens solution counts correctly. The interesting part is making the state as small as it can be.

Look at the row you are about to fill. Whether a square is safe depends only on which columns of this row are attacked, and that is n yes/no answers, one per column: a perfect fit for the bits of one integer (a bitmask, where bit c stands for column c). Three masks are enough. cols has a 1 for every column that already holds a queen. diag has a 1 for every square of the current row that is attacked along a ↘ diagonal, and anti for the ↙ diagonals. A queen placed in column c attacks, in the next row, column c (straight down), column c + 1 (↘) and column c - 1 (↙). So the masks for the next row are cols | bit, (diag | bit) << 1 and (anti | bit) >> 1: a shift by one bit moves every attacked column one step sideways, which is exactly what a diagonal does.

free = full & ~(cols | diag | anti) then has a 1 on every safe column of the row, all n of them in one operation, where full is n ones. free & -free keeps only the lowest set bit, the leftmost safe column, and free ^= bit removes it once it has been tried. No sets to update and undo, no loop over n columns per row: a call costs as many steps as it has safe columns. The tree is the same (17 calls for n = 4, 2,057 for n = 8), but each node is a handful of integer operations.

Approaches from the obvious one to the one you want in an interview

No two queens share a row or a column, so a solution is a permutation of the columns: cols[r] is the column of the queen in row r. Generate all n! permutations and count those in which no two queens share a diagonal: all r - c values are distinct and all r + c values are distinct.

Correct, and simple to write, but every permutation is built in full before the diagonals are checked: 362,880 permutations for n = 9, most of them doomed from their first two rows.

Dry run

  1. n = 4: 4! = 24 permutations of the columns 0, 1, 2, 3.
  2. (0, 1, 2, 3): r - c is 0, 0, 0, 0, so queens share a ↘ diagonal. Not counted.
  3. (1, 3, 0, 2): r - c is -1, -2, 2, 1, r + c is 1, 4, 2, 5, all distinct. Count 1.
  4. (2, 0, 3, 1) passes as well. The other 22 fail. Answer 2.

Python

class Solution:
    def totalNQueens(self, n: int) -> int:
        count = 0
        # cols[r] is the column of the queen in row r; a permutation uses every column once
        for cols in itertools.permutations(range(n)):
            diagonals = {r - c for r, c in enumerate(cols)}        # one value per "\" diagonal
            anti_diagonals = {r + c for r, c in enumerate(cols)}   # one value per "/" diagonal
            if len(diagonals) == n and len(anti_diagonals) == n:   # no two queens share a diagonal
                count += 1
        return count
Time O(n · n!)Space O(n)

All n! permutations are generated and each is checked in O(n). Memory is one permutation and two sets at a time.

When to use: Only to see the size of the unpruned search. Fine up to about n = 8.

The N-Queens search, with a counter at the bottom. place(row) tries every column of the row; a square is attacked when its column is in cols, its row - col is in diags or its row + col is in anti. For a safe square: add the three values (choose), recurse (explore), remove them again (un-choose). When row == n the call returns 1, and each call returns the sum over its columns.

Pruning kills a doomed branch at its first attacked row, so the tree has only 2,057 nodes for n = 8. Each node still loops over all n columns and does three set operations to choose and three to un-choose.

Dry run

  1. n = 4. place(0) tries columns 0 to 3 and adds up what each one returns.
  2. Column 0: place(1) finds columns 2 and 3 safe. Column 2 leaves no safe square in row 2; column 3 leads to column 1 in row 2 and a dead end in row 3. Returns 0.
  3. Column 1: rows 1, 2, 3 take columns 3, 0, 2 in turn. row == 4, returns 1.
  4. Column 2 returns 1 (the mirror image), column 3 returns 0. Total 2.

Python

class Solution:
    def totalNQueens(self, n: int) -> int:
        cols = set()                       # columns that already hold a queen
        diags = set()                      # row - col of every queen: one value per "\" diagonal
        anti = set()                       # row + col of every queen: one value per "/" diagonal

        def place(row):
            if row == n:                   # all n queens are placed: one complete board
                return 1
            count = 0
            for col in range(n):
                if col in cols or (row - col) in diags or (row + col) in anti:
                    continue               # this square is attacked
                cols.add(col)              # choose
                diags.add(row - col)
                anti.add(row + col)
                count += place(row + 1)    # explore: boards that extend this placement
                anti.remove(row + col)     # un-choose
                diags.remove(row - col)
                cols.remove(col)
            return count

        return place(0)
Time O(n · n!)Space O(n)

A loose upper bound: at most a small multiple of n! nodes, each scanning n columns with O(1) set checks. The sets and the recursion need O(n).

When to use: The natural first answer if you already know N-Queens. Then compress the sets into bitmasks.

Replace the sets by three integers in which bit c stands for column c:

  • cols: columns that hold a queen;
  • diag: squares of the current row attacked along a ↘ diagonal;
  • anti: squares of the current row attacked along a ↙ diagonal.

free = full & ~(cols | diag | anti) has a 1 on every safe column of the row, computed in one operation (full is n ones). Pick the lowest set bit with bit = free & -free, remove it with free ^= bit, and recurse with the masks for the next row: cols | bit, ((diag | bit) << 1) & full (every ↘ attack moves one column right) and (anti | bit) >> 1 (every ↙ attack moves one column left). The new masks are passed as arguments, so there is nothing to undo. row == n returns 1 and every call returns the sum over its safe columns.

Dry run

  1. n = 4, full = 1111. place(0, 0, 0, 0): free = 1111, every column is safe. Lowest bit: column 0.
  2. Row 1 gets cols = 0001, diag = 0010, anti = 0000 (bits written with column 0 on the right), so free = 1100: columns 2 and 3.
  3. Column 2 leads to free = 0 in row 2; column 3 leads to column 1 in row 2 and free = 0 in row 3. Column 0 contributes 0.
  4. Column 1 in row 0: rows 1, 2, 3 each have exactly one free column (3, 0, 2). row == 4 returns 1.
  5. Column 2 contributes 1 by symmetry and column 3 contributes 0. Answer 2, after 17 calls.

Python

class Solution:
    def totalNQueens(self, n: int) -> int:
        full = (1 << n) - 1                    # n ones: one bit per column

        def place(row, cols, diag, anti):
            # bit c of cols: column c holds a queen
            # bit c of diag / anti: square (row, c) is attacked along a "\" / "/" diagonal
            if row == n:                       # every row has a queen: one complete board
                return 1
            count = 0
            free = full & ~(cols | diag | anti)   # 1 = this column of the row is safe
            while free:
                bit = free & -free             # lowest set bit = leftmost safe column
                free ^= bit                    # it is being tried now, drop it from the candidates
                count += place(row + 1,
                               cols | bit,                  # this column is taken from now on
                               ((diag | bit) << 1) & full,  # "\" attacks move one column right
                               (anti | bit) >> 1)           # "/" attacks move one column left
            return count

        return place(0, 0, 0, 0)
Time O(n!)Space O(n)

Same tree as the set version (2,057 calls for n = 8), but a call costs a few integer operations per safe column instead of a scan of n columns with set updates. The recursion is n deep and holds three integers per frame.

When to use: The standard fast answer. Mention that the tree is unchanged and only the constant factor shrinks.

Common mistakes

  • Shifting the diagonal masks the wrong way. With bit c standing for column c, the ↘ diagonal reaches column c + 1 in the next row, which is << 1, and the ↙ diagonal reaches c - 1, which is >> 1. Swapping them counts attacked squares as safe.
  • Using ~x without & full. Python integers have no fixed width, so ~cols is a negative number with infinitely many 1 bits. Always mask with full = (1 << n) - 1, and keep & full after the left shift so diag cannot grow past n bits.
  • Forgetting free ^= bit inside the while free loop. The same bit is picked again and again, and the loop never ends.
  • Counting mirror images once. The problem counts every distinct board, so n = 4 gives 2, not 1. Symmetry can speed up the search (place the first queen in the left half and double), but the middle column of an odd n must then be handled separately.
  • Building the boards and returning len(boards). It is correct, but each solution costs O(n²) to build, and the point of this problem is to avoid that work.
  • Checking the diagonals only at the end, as the permutation brute force does. A doomed prefix is then completed in every possible way before it is rejected.

Python notes

  • full = (1 << n) - 1 is n ones in binary (0b1111 for n = 4). format(mask, f"0{n}b") prints a mask with leading zeros.
  • free & -free isolates the lowest set bit: -free is ~free + 1, so the two numbers share exactly one 1 bit. free &= free - 1 is the other classic, which clears the lowest set bit.
  • ~x on a Python int is -x - 1, a negative number. Combine it with & full to get the n-bit complement.
  • bin(mask).count("1") or mask.bit_count() (Python 3.10+) counts the set bits; mask.bit_length() gives the position of the highest one.
  • itertools.permutations(range(n)) yields every column order for the brute force; each is a tuple, so enumerate gives (row, column) pairs.
  • The nested place returns its count instead of touching an outer variable, so no nonlocal is needed.

Follow-up questions

What an interviewer might ask next, and what changes.

  • N-Queens LC 51 — return the boards themselves. Keep a placement list next to the masks and turn it into row strings whenever row == n.
  • Sudoku Solver LC 37 — the same 'what is already taken' idea with a 9-bit mask per row, column and 3 x 3 box; a cell's candidates are ~(rows[r] | cols[c] | boxes[b]) & 0x1FF.
  • Beautiful Arrangement LC 526 — count arrangements of 1..n under a divisibility rule. A used bitmask replaces the sets, and memoising on (position, used) removes repeated subtrees.
  • Maximum Students Taking Exam LC 1349 — rows of a grid again, but now a DP over row bitmasks: the previous row's mask decides which seats of this row are allowed, tested with shifts exactly like the diagonals here.
  • Use the left-right symmetry — only try the first-row queen in columns 0 .. n // 2 - 1, double the count, and for odd n add the count for the middle column once. The search tree shrinks by about half.
  • Stop at the first solution — return True as soon as row == n. The function then answers 'is there any solution?' and finishes much sooner, because it never explores the rest of the tree.
