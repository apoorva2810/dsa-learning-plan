Subarray Sum Equals K Medium 250

LeetCode #560 ↗
Status

Count the contiguous stretches of a list whose numbers add up to exactly k, even when some numbers are negative.

Problem

You are given a list of integers nums and an integer k. Return how many contiguous subarrays (stretches of neighbouring elements, at least one element long) have a sum equal to k.

  • Numbers can be negative or zero, so a longer stretch does not always have a bigger sum.
  • Count every qualifying stretch, including ones that overlap each other or share the same values.

Examples

Example 1
Input: nums = [1, 2, 1, 2, 1], k = 3
Output: 4
[1, 2], [2, 1], [1, 2] and [2, 1] all add up to 3 (positions 0-1, 1-2, 2-3 and 3-4).
Example 2
Input: nums = [4, -1, 2, 1, -2, 3], k = 2
Output: 3
[-1, 2, 1], [2] and [1, -2, 3] each add up to 2.
Example 3
Input: nums = [1, -1, 1, -1], k = 0
Output: 4
[1, -1] twice, [-1, 1], and the whole list all add up to 0.

Constraints

  • 1 <= len(nums) <= 2 * 10^4
  • -1000 <= nums[i] <= 1000
  • -10^7 <= k <= 10^7

Think first try before reading the solution

A list of n numbers has n(n+1)/2 subarrays. If you can get the sum of any subarray in O(1), checking all of them is fine as a first version. What precomputation gives you that?
Let prefix[j] be the sum of the first j numbers. The subarray from index i up to j-1 has sum prefix[j] - prefix[i]. For a fixed j, which earlier prefix values would make that difference equal k?
You need earlier prefix values equal to prefix[j] - k, and you need to know how many there are, not just whether one exists. Keep a dictionary of prefix sum -> number of times seen, and update it as you walk the list.

Key idea

Define the prefix sum at position j as the sum of the first j numbers (the empty prefix has sum 0). Then the sum of any subarray is a difference of two prefix sums: the numbers from index i to j-1 add up to prefix[j] - prefix[i].

So "subarrays that sum to k" are exactly "pairs of prefix sums, one earlier and one later, that differ by k". Fix the later one, prefix[j]. It pairs with every earlier prefix equal to prefix[j] - k, and each pair is one subarray ending at j.

The brute force finds those partners by scanning all earlier prefixes: O(n²). Instead, remember them in a dictionary prefix sum -> how many times it has occurred. Walking left to right, add the count stored for prefix - k to the answer, and then record the current prefix. One pass, one lookup per number: O(n).

Why not a sliding window? A window can decide when to shrink only if removing a number always lowers the sum, which is false as soon as a number is negative. The dictionary never has to decide anything, so it does not care about signs.

Approaches from the obvious one to the one you want in an interview

Let prefix[j] be the sum of the first j numbers (prefix[0] = 0). The subarray nums[start:end] then has sum prefix[end] - prefix[start], so once the prefix list is built, any subarray sum costs O(1).

Try every pair start < end, compare the difference with k, and count the hits. A list of n numbers has n(n+1)/2 subarrays, so this is O(n²). It is correct for negative numbers and zeros, but for n = 20,000 it makes about 200 million checks.

Dry run

  1. nums = [1, 2, 1, 2, 1], k = 3 → prefix = [0, 1, 3, 4, 6, 7]
  2. pairs with a difference of 3: (0, 2), (1, 3), (2, 4), (3, 5)
  3. that is nums[0:2], nums[1:3], nums[2:4], nums[3:5] → 4 subarrays; 15 pairs were checked in total

Python

class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        n = len(nums)
        prefix = [0] * (n + 1)                 # prefix[j] = sum of the first j numbers
        for j in range(n):
            prefix[j + 1] = prefix[j] + nums[j]
        count = 0
        for end in range(1, n + 1):            # the subarray is nums[start:end]
            for start in range(end):
                if prefix[end] - prefix[start] == k:
                    count += 1
        return count
Time O(n²)Space O(n)

n(n+1)/2 pairs, each checked in O(1); the prefix list holds n + 1 numbers.

When to use: Only as a baseline: it shows exactly which scan the dictionary replaces.

The brute force asks, for every end: how many earlier prefixes equal prefix[end] - k? and answers by scanning all of them. Answer it with a dictionary instead.

seen maps a prefix sum to how many times it has occurred. Start it with {0: 1}, the empty prefix. Then, for each number:

  1. add it to the running prefix;
  2. add seen.get(prefix - k, 0) to the answer: every earlier prefix equal to prefix - k is the start of one subarray that ends here and sums to k;
  3. then record the current prefix in seen.

Look up first, record second. If you recorded first, then for k = 0 the current prefix would match itself and count an empty subarray. The whole thing is one pass with one dictionary lookup and one update per number, O(n) time and O(n) space (the dictionary can hold up to n + 1 different prefixes).

Dry run

  1. nums = [1, 2, 1, 2, 1], k = 3, seen = {0: 1}, prefix = 0, count = 0
  2. x = 1: prefix 1, need 1 - 3 = -2 → not seen; seen = {0: 1, 1: 1}
  3. x = 2: prefix 3, need 0 → seen once → count 1 (nums[0..1]); seen[3] = 1
  4. x = 1: prefix 4, need 1 → seen once → count 2 (nums[1..2]); seen[4] = 1
  5. x = 2: prefix 6, need 3 → seen once → count 3 (nums[2..3]); seen[6] = 1
  6. x = 1: prefix 7, need 4 → seen once → count 4 (nums[3..4]) → return 4

Python

class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        seen = {0: 1}                          # prefix sum -> times seen; the empty prefix (sum 0) counts once
        prefix = 0
        count = 0
        for x in nums:
            prefix += x
            count += seen.get(prefix - k, 0)   # earlier prefixes that start a subarray summing to k here
            seen[prefix] = seen.get(prefix, 0) + 1    # record AFTER the lookup
        return count
Time O(n)Space O(n)

One pass; each number costs one dictionary lookup and one update. The dictionary holds at most n + 1 prefix sums.

When to use: The interview answer. It handles negatives and zeros, which rules out the sliding window.

Common mistakes

  • Forgetting to start the dictionary with {0: 1}. That entry stands for the empty prefix and counts the subarrays that begin at index 0: for nums = [3] and k = 3 the answer is 1, and it is missed without the seed.
  • Recording the current prefix before looking up prefix - k. With k = 0 the current prefix matches itself, which counts an empty subarray: nums = [5], k = 0 would answer 1 instead of 0.
  • Storing an index instead of a count (the trick for the longest subarray). Here several earlier prefixes can be equal: in [1, -1, 1, -1] with k = 0 the prefix 0 occurs three times, and every one of them is a valid start.
  • Using a sliding window or two pointers. Shrinking the window assumes the sum drops when you remove a number, which is wrong for negative values (and zeros make counting by window messy).
  • Off-by-one in the brute force: with n numbers the prefix list has n + 1 entries, and start must be smaller than end.

Python notes

  • seen.get(key, 0) returns 0 when the key is missing, so you need no if key in seen check. A defaultdict(int) would also work, but reading a missing key from it inserts that key.
  • itertools.accumulate(nums, initial=0) builds the whole prefix list, starting with the empty prefix 0, in one call.
  • Python integers do not overflow, so a long run of large values cannot wrap around in a prefix sum.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Two Sum LC 1 — the same 'look up the partner you need' idea: here the partner is the earlier prefix prefix - k, and you count matches instead of returning one.
  • Continuous Subarray Sum LC 523 — the sum must be a multiple of k and the length at least 2: store prefix % k with the first index where it appeared.
  • Subarray Sums Divisible by K LC 974 — count subarrays whose sum is a multiple of k: count prefix sums by their remainder modulo k, and pair equal remainders.
  • Maximum Size Subarray Sum Equals k LC 325 — the longest stretch instead of the number of them: the dictionary keeps the first index of each prefix, not a count.
  • Minimum Size Subarray Sum LC 209 — all numbers are positive, so a sliding window works again and needs no dictionary.
  • Number of Submatrices That Sum to Target LC 1074 — the 2D version: fix a pair of rows, collapse them into one row of column sums, and run this same prefix-sum counting on it.
