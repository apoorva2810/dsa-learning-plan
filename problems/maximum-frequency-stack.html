Maximum Frequency Stack Hard 250

LeetCode #895 ↗
Status

A stack whose pop removes the most frequent value, breaking ties in favour of the one pushed most recently.

Problem

Design a stack-like structure whose pop does not remove the top element but the most frequent one.

Implement the class FreqStack:

  • FreqStack() creates an empty structure.
  • push(val) puts the integer val on top of the stack.
  • pop() removes and returns the value that currently occurs most often in the stack. If several values tie for the highest frequency, remove the one whose occurrence is closest to the top, that is, the one pushed most recently.

Only one occurrence is removed per pop: a value that occurs three times is still in the stack, twice, after one pop. pop is only called when the stack is not empty.

Examples

Example 1
Input: ["FreqStack","push","push","push","push","push","push","pop","pop","pop","pop"] [[],[5],[7],[5],[7],[4],[5],[],[],[],[]]
Output: [null, null, null, null, null, null, null, 5, 7, 5, 4]
The stack from bottom to top is 5, 7, 5, 7, 4, 5. The 5 occurs three times, the most, so the first pop returns 5. Now 5 and 7 occur twice each; the 7 is closer to the top, so it goes next. Then the 5 (twice, the most), and finally every value occurs once, so the top, 4, goes.
Example 2
Input: ["FreqStack","push","push","push","push","pop","pop","pop","pop"] [[],[1],[1],[2],[3],[],[],[],[]]
Output: [null, null, null, null, null, 1, 3, 2, 1]
The 1 occurs twice, so it leaves first even though it sits deep in the stack. After that every value occurs once, and the pops follow the stack order: 3, 2, 1.

Constraints

  • 0 <= val <= 10^9
  • at most 2 * 10^4 calls in total to push and pop
  • pop is never called on an empty stack

Think first try before reading the solution

A plain stack knows the order of the pushes but not the frequencies, and a counter knows the frequencies but not the order. pop needs both. What can you record at push time so that the answer is ready at pop time?
Keep a dictionary of frequencies. Also group the values by the frequency level they have reached: when x is pushed for the third time, it joins the group for level 3. Which group does pop look at?
For each level f, keep a stack of the values that reached f, in the order they reached it. pop takes the top of the highest non-empty level. One variable, max_freq, tells you which level that is.

Key idea

pop needs two things at once: the highest frequency, and among ties the latest push. Scanning the stack for them costs O(n) per pop. The fix is to do the bookkeeping at push time.

Group the values by level. Every time val is pushed, its frequency rises by one, to f. Put val on a stack that belongs to level f. A value that has been pushed three times therefore sits on the stacks of levels 1, 2 and 3, once on each, and each level's stack is ordered by when values reached that level.

Now pop is easy. Look at the highest level, max_freq. The top of its stack is the value that reached that level most recently. Why is that the right tie-break? Any later push of the same value would have raised its frequency above max_freq, which is impossible, so reaching the level was also its latest push. Remove that value from its level and lower its frequency by one. It stays on all the lower levels, which record its earlier pushes. If the level is now empty, max_freq drops by one: the value we just removed still sits on the level below, so that level is not empty (and if we were at level 1, the whole stack is empty).

Every push adds exactly one entry and every pop removes exactly one, so both run in O(1).

Approaches from the obvious one to the one you want in an interview

Keep every pushed value in one list, so the stack order is exact. On pop, count how often each value occurs (Counter), find the highest frequency, then walk down from the top of the list and remove the first occurrence of a value that has that frequency. That occurrence is the one closest to the top, which is the tie-break we need.

It is correct, and push is O(1). But every pop counts the whole list, scans it, and removes from the middle, which shifts the rest: O(n) per call. With 10⁴ pushes followed by 10⁴ pops that is on the order of 10⁸ steps.

Dry run

  1. after pushes 5, 7, 5, 7, 4, 5 → the list is [5, 7, 5, 7, 4, 5]
  2. pop: counts are 5→3, 7→2, 4→1, highest 3 → scan from the top, the first 5 is the last element → remove it
  3. pop: counts 5→2, 7→2, 4→1, highest 2 → from the top: 4 has 1, 7 has 2 → remove that 7
  4. pop: counts 5→2, 7→1, 4→1 → remove the topmost 5
  5. pop: all counts 1 → the top element, 4

Python

class FreqStack:
    def __init__(self):
        self.items = []                              # the stack itself, bottom to top

    def push(self, val: int) -> None:
        self.items.append(val)

    def pop(self) -> int:
        counts = Counter(self.items)                 # O(n): count every value
        best = max(counts.values())                  # the highest frequency
        # walk down from the top: the first value with that frequency is the one closest to the top
        for i in range(len(self.items) - 1, -1, -1):
            if counts[self.items[i]] == best:
                return self.items.pop(i)             # remove that occurrence, even from the middle
Time O(1) push, O(n) popSpace O(n)

pop counts, scans and removes from the middle of a list of up to n items.

When to use: Only as the baseline that shows what must be precomputed.

Keep three things:

  • freq: how many times each value is in the stack now;
  • groups: for each level f, a stack of the values that reached frequency f, in the order they reached it;
  • max_freq: the highest level in use.

push(val): raise freq[val] to f, append val to groups[f], and set max_freq = max(max_freq, f).

pop(): take the top of groups[max_freq]. That value has the highest frequency, and among the values with that frequency it was pushed most recently. Lower its frequency by one. If groups[max_freq] is now empty, decrement max_freq.

Each call does a constant number of dictionary and list operations, and the groups hold exactly one entry per element in the stack.

Dry run

  1. push 5, 7, 5, 7, 4, 5 → freq 5:3, 7:2, 4:1; groups[1] = [5, 7, 4], groups[2] = [5, 7], groups[3] = [5]; max_freq = 3
  2. pop → top of groups[3] is 5 → freq[5] = 2 → groups[3] empty → max_freq = 2. Returns 5
  3. pop → top of groups[2] is 7 (it reached 2 after the 5 did) → freq[7] = 1 → groups[2] = [5]. Returns 7
  4. pop → top of groups[2] is 5 → freq[5] = 1 → groups[2] empty → max_freq = 1. Returns 5
  5. pop → top of groups[1] is 4 (the last value that reached 1) → returns 4

Python

class FreqStack:
    def __init__(self):
        self.freq = defaultdict(int)                 # value -> how many times it is in the stack now
        self.groups = defaultdict(list)              # level f -> values that reached frequency f, oldest first
        self.max_freq = 0                            # the highest level in use

    def push(self, val: int) -> None:
        self.freq[val] += 1
        f = self.freq[val]
        self.groups[f].append(val)                   # val joins level f; its entries on levels 1..f-1 stay
        self.max_freq = max(self.max_freq, f)

    def pop(self) -> int:
        group = self.groups[self.max_freq]
        val = group.pop()                            # most frequent value; ties go to the most recent push
        self.freq[val] -= 1
        if not group:                                # nobody else reached this level
            self.max_freq -= 1
        return val
Time O(1) for push and popSpace O(n)

One entry per element in the stack across all groups; each call touches one dictionary entry and one list end.

When to use: The standard answer: the 'bucket by frequency' idea with a stack in every bucket.

Watch it run

Let a heap do the choosing. Give every push an entry (-frequency after the push, -push time, value). heapq pops the smallest tuple, so the entry with the highest frequency comes out first, and among equal frequencies the newest push (the largest time).

pop removes the best entry and lowers the frequency of that value. No entry becomes stale: a pop always removes the latest remaining occurrence of its value, and the value's entries for lower frequencies describe exactly its earlier occurrences.

It is correct and short to write, but every call costs O(log n) instead of O(1).

Python

class FreqStack:
    def __init__(self):
        self.freq = defaultdict(int)                 # value -> how many times it is in the stack now
        self.heap = []                               # (-frequency after the push, -push time, value)
        self.time = 0                                # counts pushes, so recent pushes win ties

    def push(self, val: int) -> None:
        self.freq[val] += 1
        heapq.heappush(self.heap, (-self.freq[val], -self.time, val))
        self.time += 1

    def pop(self) -> int:
        _, _, val = heapq.heappop(self.heap)         # highest frequency first, then the newest push
        self.freq[val] -= 1
        return val
Time O(log n) for push and popSpace O(n)

One heap entry per push that is still in the stack; each heap operation is O(log n).

When to use: When you do not see the frequency levels but know how to use a heap with a tie-breaking key.

Common mistakes

  • Keeping one stack plus a frequency dictionary and scanning for the winner on each pop. That is O(n) per pop: the baseline below.
  • Forgetting to lower max_freq when the top level becomes empty. The next pop would read an empty level and fail.
  • Moving a value from level f - 1 to level f instead of adding it to level f. A value pushed three times belongs to levels 1, 2 and 3 at once; a pop removes only its top entry, so the lower entries must still be there.
  • Breaking ties by the value itself, or by which value appeared first, instead of by the most recent push. The top of the level's stack is the right choice.
  • Recomputing the maximum with max(self.freq.values()) after a pop. That is O(n). One decrement is enough, as explained above.
  • In the heap version, storing only (-frequency, value). Ties are then broken by value, not by recency: add a push counter as the second key.

Python notes

  • defaultdict(int) and defaultdict(list) remove the "does the key exist yet" checks: self.freq[val] += 1 and self.groups[f].append(val) just work.
  • Each level is a plain list used as a stack: append pushes and pop() removes the top.
  • heapq is a min-heap. To get "largest first" negate the keys: (-frequency, -time, value). Tuples compare field by field, so a tie on frequency falls through to the push time.
  • Counter(items) counts a list in one pass; list.pop(i) removes from the middle and costs O(n). Both appear in the baseline below.
