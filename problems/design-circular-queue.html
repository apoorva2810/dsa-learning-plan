Design Circular Queue Medium 250

LeetCode #622 ↗
Status

Build a fixed-size queue that reuses the slots of removed values, with every operation in O(1).

Problem

Design a circular queue: a first-in, first-out queue with a fixed capacity k. "Circular" means that storage is reused. Once a value leaves from the front, its slot can hold a new value at the back, so a queue that is not full can always accept one more value. Picture k seats around a table, with a front marker and a back marker that move round and round.

Implement the class MyCircularQueue:

  • MyCircularQueue(k) creates an empty queue that holds at most k values.
  • enQueue(value) adds value at the back and returns True. If the queue is full it changes nothing and returns False.
  • deQueue() removes the value at the front and returns True. If the queue is empty it returns False.
  • Front() returns the front value, or -1 if the queue is empty.
  • Rear() returns the back value, or -1 if the queue is empty.
  • isEmpty() says whether the queue holds no values; isFull() says whether it holds exactly k.

Every operation must run in O(1) time. Build the queue yourself from an array or a linked list; do not use a ready-made queue.

Examples

Example 1
Input: ["MyCircularQueue","enQueue","enQueue","enQueue","enQueue","deQueue","enQueue","Front","Rear","isFull"] [[3],[10],[20],[30],[40],[],[40],[],[],[]]
Output: [null, true, true, true, false, true, true, 20, 40, true]
The fourth enQueue fails because three values already fill the queue. deQueue frees the slot of 10, and the next enQueue(40) reuses it. The queue now reads 20, 30, 40 from front to back.
Example 2
Input: ["MyCircularQueue","Front","Rear","deQueue","isEmpty","isFull"] [[2],[],[],[],[],[]]
Output: [null, -1, -1, false, true, false]
Nothing has been added: Front and Rear return -1 and deQueue has nothing to remove.

Constraints

  • 1 <= k <= 1000
  • 0 <= value <= 1000
  • at most 3000 calls to the methods in total

Think first try before reading the solution

A Python list works as a queue if you append at the back and pop(0) at the front, but pop(0) shifts every remaining element: O(k). What if the front were just an index that moves forward, so that no element has to move?
Keep a fixed array of k slots, an index head for the front element, and a counter count. The last element is at head + count - 1 and the next free slot is at head + count. What goes wrong when those indices run past the end of the array?
Wrap around with the remainder operator: (head + count) % k. Keeping count also settles the 'empty or full?' question: head and the next free slot are on the same index in both cases, but count tells you which.

Key idea

A queue only touches its two ends, so its elements never need to move. Store them in a fixed array of k slots and track just two numbers: head, the index of the front element, and count, how many elements are inside. The back element sits count - 1 slots after the front, and the next free slot sits count slots after it.

An index runs out when it reaches the end of the array. The fix is to make the array a circle: after index k - 1 comes index 0 again, which is what index % k computes. So enQueue writes to (head + count) % k, and deQueue only moves head forward by one (also modulo k) and lowers count. Nothing is ever shifted, so every operation is O(1).

Why keep a counter and not a tail index? With only head and tail, an empty queue and a full queue look the same (tail == head in both). count tells them apart, and isEmpty and isFull become one comparison each.

Approaches from the obvious one to the one you want in an interview

Keep the values in a plain list and the capacity in a number. enQueue appends, Front and Rear read items[0] and items[-1], isFull compares the length with k. All of that is O(1).

deQueue calls items.pop(0). Removing the first element of a Python list moves every other element one place to the left, so one deQueue costs O(k). It behaves correctly, but it is not the O(1) the problem asks for, and it misses the idea of a circular queue: instead of moving the elements, move the front marker.

Dry run

  1. k = 3: enQueue 10, 20, 30 → items = [10, 20, 30]
  2. enQueue(40) → the length equals k, so → False
  3. deQueue() → items.pop(0) shifts 20 and 30 left → [20, 30]
  4. enQueue(40) → [20, 30, 40]; Front = 20, Rear = 40

Python

class MyCircularQueue:
    def __init__(self, k: int):
        self.capacity = k
        self.items = []

    def enQueue(self, value: int) -> bool:
        if self.isFull():
            return False
        self.items.append(value)
        return True

    def deQueue(self) -> bool:
        if self.isEmpty():
            return False
        self.items.pop(0)                  # O(k): every other element shifts left
        return True

    def Front(self) -> int:
        return -1 if self.isEmpty() else self.items[0]

    def Rear(self) -> int:
        return -1 if self.isEmpty() else self.items[-1]

    def isEmpty(self) -> bool:
        return len(self.items) == 0

    def isFull(self) -> bool:
        return len(self.items) == self.capacity
Time O(1) enQueue, O(k) deQueueSpace O(k)

pop(0) shifts up to k - 1 elements.

When to use: Only as a baseline that shows which operation the ring fixes.

Allocate slots = [None] * k once and keep two numbers: head, the index of the front element, and count, the number of stored values.

  • enQueue(v): if count == k return False. Otherwise write v into slot (head + count) % k and add 1 to count.
  • deQueue(): if count == 0 return False. Otherwise set head = (head + 1) % k and subtract 1 from count.
  • Front(): slots[head]. Rear(): slots[(head + count - 1) % k]. Both return -1 when count == 0.
  • isEmpty(): count == 0. isFull(): count == k.

The % k is what turns a line of slots into a ring: index k - 1 is followed by index 0. Freed slots are reused automatically, because the next free slot is always count places after head. No element moves, so every method is O(1).

Dry run

  1. k = 3, slots = [None, None, None], head = 0, count = 0
  2. enQueue 10, 20, 30 → slots 0, 1, 2 (each at (0 + count) % 3) → [10, 20, 30], count = 3
  3. enQueue(40) → count == 3, full → False
  4. deQueue() → head = 1, count = 2; slot 0 is free
  5. enQueue(40) → slot (1 + 2) % 3 = 0 (the wrap) → [40, 20, 30], count = 3
  6. Front() → slots[1] = 20; Rear() → slots[(1 + 3 - 1) % 3] = slots[0] = 40

Python

class MyCircularQueue:
    def __init__(self, k: int):
        self.capacity = k
        self.slots = [None] * k              # fixed storage; None marks a free slot
        self.head = 0                        # index of the front element
        self.count = 0                       # how many elements are stored

    def enQueue(self, value: int) -> bool:
        if self.isFull():
            return False
        tail = (self.head + self.count) % self.capacity   # first free slot behind the last element, wrapping
        self.slots[tail] = value
        self.count += 1
        return True

    def deQueue(self) -> bool:
        if self.isEmpty():
            return False
        self.slots[self.head] = None                      # free the slot (nothing reads it again)
        self.head = (self.head + 1) % self.capacity       # the next slot is now the front, wrapping
        self.count -= 1
        return True

    def Front(self) -> int:
        if self.isEmpty():
            return -1
        return self.slots[self.head]

    def Rear(self) -> int:
        if self.isEmpty():
            return -1
        return self.slots[(self.head + self.count - 1) % self.capacity]   # one slot before the next free one

    def isEmpty(self) -> bool:
        return self.count == 0

    def isFull(self) -> bool:
        return self.count == self.capacity
Time O(1) per callSpace O(k)

A few additions and one modulo per call; the array of k slots is allocated once.

When to use: The standard answer. Say why count is kept: it separates an empty ring from a full one.

Watch it run

Keep the values in a singly linked list and remember both ends: front (the oldest node) and back (the newest), plus count for the capacity check. enQueue links a new node behind back; deQueue moves front to front.next. Both are O(1), because a queue only ever touches its two ends.

It is not literally a ring (nodes are created and dropped instead of slots being reused), but it meets the same interface with the same bounds. The costs are one object per element and a little pointer care when the queue becomes empty or receives its first value.

Dry run

  1. k = 3: enQueue 10, 20, 30 → 10 → 20 → 30, front = 10, back = 30
  2. enQueue(40) → count == 3 → False
  3. deQueue() → front moves to 20; the node 10 is dropped
  4. enQueue(40) → 20 → 30 → 40, back = 40

Python

class MyCircularQueue:
    def __init__(self, k: int):
        self.capacity = k
        self.count = 0
        self.front = None                  # oldest node
        self.back = None                   # newest node

    def enQueue(self, value: int) -> bool:
        if self.isFull():
            return False
        node = ListNode(value)
        if self.back is None:              # empty queue: the new node is both ends
            self.front = node
        else:
            self.back.next = node          # link behind the current last node
        self.back = node
        self.count += 1
        return True

    def deQueue(self) -> bool:
        if self.isEmpty():
            return False
        self.front = self.front.next       # forget the oldest node
        if self.front is None:
            self.back = None               # the queue just became empty
        self.count -= 1
        return True

    def Front(self) -> int:
        return -1 if self.isEmpty() else self.front.val

    def Rear(self) -> int:
        return -1 if self.isEmpty() else self.back.val

    def isEmpty(self) -> bool:
        return self.count == 0

    def isFull(self) -> bool:
        return self.count == self.capacity
Time O(1) per callSpace O(k)

Each call changes at most two pointers; at most k nodes exist at a time.

When to use: Natural in a linked-list course; the array ring avoids allocating a node per value.

Common mistakes

  • Using pop(0) or list.remove on a Python list. It behaves correctly, but deQueue becomes O(k); the point of the ring is to move the front marker, not the elements.
  • Forgetting to wrap. head + 1 and head + count can reach k, one past the last slot. Apply % k to every index you compute.
  • Tracking only head and tail: head == tail then means both 'empty' and 'full'. Keep a count (or give up one slot) to tell the two states apart.
  • Reading Rear at (head + count) % k. That slot is the next free one. The last element is one slot before it: (head + count - 1) % k.
  • Testing for an element with truthiness (if slots[i]:). Values may be 0, and a freed slot still holds its old value unless you clear it; decide by count, never by what a slot contains.

Python notes

  • [None] * k builds the fixed array in one expression; None marks a free slot. (For a list of lists you would need a comprehension, but a flat list is safe.)
  • % with a positive divisor never returns a negative number in Python, so (head - 1) % k also wraps correctly when you step backwards. In C, Java or JavaScript the result can be negative.
  • collections.deque(maxlen=k) is a ready-made ring, but a full deque silently drops the oldest value on append instead of refusing the new one, and interviewers want to see the index arithmetic. That is why the solutions here do not use it.
  • Method names such as Front and isEmpty follow LeetCode, not Python naming style.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Design Circular Deque LC 641 — adds insertFront and deleteLast: head must also move backwards, and (head - 1) % k wraps below zero to the last slot.
  • Implement Queue using Stacks LC 232 — another 'build a queue out of simpler parts' question: two stacks, with the elements flipped over only when the output stack runs dry (amortised O(1)).
  • Implement Stack using Queues LC 225 — the reverse trade: a stack from queues, where each push rotates the queue so the newest value is at the front.
  • LRU Cache LC 146 — the other 'fixed capacity, O(1)' design: instead of reusing the oldest slot in order, it evicts the least recently used key, which needs a hash map plus a doubly linked list.
  • A queue that grows when it is full — allocate an array twice as large and copy the elements in queue order (starting at head, wrapping) into it; head becomes 0. Doubling keeps enQueue amortised O(1).
  • One producer thread and one consumer thread — a common lock-free design keeps separate head and tail indexes and leaves one slot unused to tell full from empty, because a shared count would be written by both threads.
