Search a 2D Matrix Medium

LeetCode #74 ↗
Status

Decide whether a value is in a matrix whose rows, read one after another, form a sorted list.

Problem

You are given an m × n integer matrix with two properties:

  • every row is sorted in increasing order;
  • the first number of each row is greater than the last number of the row above it.

Given an integer target, return True if it appears in the matrix and False otherwise. Your solution must run in O(log(m · n)) time.

Examples

Example 1
Input: matrix = [[1, 3, 5, 7], [10, 11, 16, 20], [23, 30, 34, 60]], target = 3
Output: true
Example 2
Input: matrix = [[1, 3, 5, 7], [10, 11, 16, 20], [23, 30, 34, 60]], target = 13
Output: false
13 would sit between 11 and 16 in the middle row, but it is not there.

Constraints

  • m == len(matrix), n == len(matrix[i])
  • 1 <= m, n <= 100
  • -10^4 <= matrix[i][j], target <= 10^4

Think first try before reading the solution

Write the rows out one after another: 1 3 5 7 10 11 16 20 23 30 34 60. What do you notice?
It is one sorted list of m·n numbers. You do not need to build it: position k of that list is row k // n, column k % n of the matrix.
Binary search k over 0 .. m·n − 1 and read matrix[k // n][k % n] wherever the 1-D version reads nums[mid].

Key idea

The two guarantees together say that reading the matrix row by row, left to right, gives one long sorted list. So this is the ordinary binary search of a sorted list of length m · n, except that the list is stored in rows.

Converting between the two views is arithmetic: list position k is in row k // n (how many full rows of n come before it) and column k % n (how far into that row). Binary search over k therefore needs no extra memory and O(log(m·n)) comparisons: at most 14 for a 100 × 100 matrix.

Approaches from the obvious one to the one you want in an interview

Scan the matrix row by row and compare each cell with the target. It is correct for any matrix, sorted or not, which is exactly the problem: it uses none of the ordering and costs O(m·n), up to 10,000 reads for 100 × 100.

Python

class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        for row in matrix:
            for value in row:
                if value == target:
                    return True
        return False
Time O(m · n)Space O(1)

When to use: Unsorted matrices.

Stand on the top-right cell. Its row extends to the left with smaller values and its column extends downward with larger values. If the cell is bigger than the target, the target cannot be anywhere below it, so drop the column and step left. If it is smaller, the target cannot be anywhere to its left, so drop the row and step down.

Each step removes a row or a column, so at most m + n − 1 cells are visited. It only needs rows and columns to be sorted, which is why it also solves LC 240; here, with the stronger guarantee, binary search does better.

Dry run

  1. target 13: start at 7 (row 0, col 3). 7 < 13 → drop row 0, move down
  2. 20 > 13 → drop column 3, move left
  3. 16 > 13 → drop column 2, move left
  4. 11 < 13 → drop row 1, move down
  5. 30 > 13 → left; 23 > 13 → left; off the grid → False

Python

class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        r, c = 0, len(matrix[0]) - 1            # start at the top-right corner
        while r < len(matrix) and c >= 0:
            value = matrix[r][c]
            if value == target:
                return True
            if value > target:
                c -= 1                          # everything below in this column is even bigger
            else:
                r += 1                          # everything to the left in this row is even smaller
        return False
Time O(m + n)Space O(1)

Every step discards one row or one column.

When to use: When only rows and columns are sorted (LC 240). Here it is beaten by the binary search.

Watch it run

Treat the matrix as a virtual sorted list of length m · n and run the standard binary search on positions 0 .. m·n − 1. Whenever the 1-D version would read nums[mid], read matrix[mid // n][mid % n] instead.

The list is never built: the index arithmetic is O(1), so the whole search is O(log(m·n)) time and O(1) memory. An equivalent alternative is two smaller binary searches, one to find the row and one inside it, with the same cost.

Dry run

  1. 3 × 4 matrix, target 3: lo = 0, hi = 11
  2. mid = 5 → row 1, col 1 → 11 > 3 → hi = 4
  3. mid = 2 → row 0, col 2 → 5 > 3 → hi = 1
  4. mid = 0 → 1 < 3 → lo = 1; mid = 1 → row 0, col 1 → 3 → True

Python

class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        rows, cols = len(matrix), len(matrix[0])
        lo, hi = 0, rows * cols - 1             # positions in the imaginary flat list
        while lo <= hi:
            mid = (lo + hi) // 2
            value = matrix[mid // cols][mid % cols]     # flat position -> (row, column)
            if value == target:
                return True
            if value < target:
                lo = mid + 1
            else:
                hi = mid - 1
        return False
Time O(log(m · n))Space O(1)

One binary search over m·n positions; each probe is O(1) arithmetic.

When to use: The intended answer whenever the rows chain into one sorted sequence.

Common mistakes

  • Dividing by the wrong dimension: the row is k // n and the column k % n, where n is the number of columns. Using the row count only works for square matrices.
  • Flattening into a new list first: correct, but O(m·n) time and memory, which defeats the logarithmic bound.
  • Using the flat trick on a matrix whose rows do not chain (each row and each column sorted, as in LC 240): the flattened list is not sorted and the search gives wrong answers.
  • Starting with hi = m * n in the inclusive template: the last mid can point one past the final cell.

Python notes

  • row, col = divmod(k, n) does the conversion in one call.
  • any(target in row for row in matrix) is a one-line brute force: readable, but O(m·n).
  • Python 3.10+ can search the virtual list directly: bisect.bisect_left(range(m * n), target, key=lambda k: matrix[k // n][k % n]) returns the first position whose value is >= target.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Search a 2D Matrix II LC 240 — rows and columns are sorted but rows do not chain, so the flat list is not sorted. Walk the staircase from the top-right corner in O(m + n) (the second approach here).
  • Kth Smallest Element in a Sorted Matrix LC 378 — binary search on the value: count the cells <= mid with a staircase walk and compare the count with k.
  • Find a Peak Element II LC 1901 — no sorting at all: binary search over columns, moving toward the larger neighbour of each column's maximum.
  • Count Negative Numbers in a Sorted Matrix LC 1351 — the staircase walk again, counting instead of searching: O(m + n).
  • Binary Search LC 704 — the same loop on an actual 1-D list; compare the two side by side.
