Missing Number Easy

LeetCode #268 ↗
Status

Find the one number in the range 0 to n that is absent from a list of n distinct numbers.

Problem

You are given a list nums of n distinct integers, each taken from the range 0 to n inclusive. That range holds n + 1 numbers but the list has only n, so exactly one number of the range is missing. Return it.

Aim for O(n) time and O(1) extra memory.

Examples

Example 1
Input: nums = [3, 0, 1]
Output: 2
n = 3, so the range is 0 to 3. The values 0, 1 and 3 are present; 2 is not.
Example 2
Input: nums = [0, 1]
Output: 2
n = 2, the range is 0 to 2. The missing number is 2 itself.
Example 3
Input: nums = [9, 6, 4, 2, 3, 5, 7, 0, 1]
Output: 8
n = 9, the range is 0 to 9, and only 8 never appears.

Constraints

  • n == len(nums)
  • 1 <= n <= 10^4
  • 0 <= nums[i] <= n
  • all values in nums are distinct

Think first try before reading the solution

You know exactly which numbers should be there: 0, 1, ..., n. How could you compare "what should be there" with "what is there" without storing either collection?
Add up what should be there with the formula n * (n + 1) // 2, then subtract the sum of the list. What is left?
The same idea works with XOR instead of a sum: XOR every number of the range together with every value of the list. Numbers that are present appear twice and cancel; the missing one appears once. Start the accumulator at n and XOR index i with nums[i] at each position.

Key idea

Two collections are almost the same: the full range 0..n, and the list, which is that range with one number removed. Any summary of a collection that changes in a predictable way when an element is removed can recover that element.

The sum. The range 0..n adds up to n * (n + 1) // 2: its average is n / 2 and it has n + 1 numbers. The list adds up to that total minus the missing number, so missing = expected - actual.

The XOR. Write down every number of the range once and every value of the list once, and XOR them all together. A number that is present appears twice and cancels (a ^ a = 0). The missing number appears only once and survives. Pairing each index i with the value nums[i], and starting the accumulator at n (the one range number that is never an index), does exactly that without building the range.

Both are one pass with O(1) memory. In a language with fixed-size integers the sum can overflow when n is large, while XOR never grows. Python integers do not overflow, so either one works there, and the sum is shorter to write.

Approaches from the obvious one to the one you want in an interview

The missing number is one of 0, 1, ..., n. Try each candidate in turn and ask whether it is in the list; the first one that is not in the list is the answer.

candidate not in nums scans the list, so each test costs O(n) and there are up to n + 1 of them: O(n²). Turning nums into a set first makes each test O(1) and the whole scan O(n), but it spends O(n) memory. The next two approaches get both down to O(n) time and O(1) memory.

Dry run

  1. nums = [3, 0, 1], n = 3, candidates 0, 1, 2, 3
  2. candidate 0: found in the list, move on
  3. candidate 1: found, move on
  4. candidate 2: scanned the whole list, not there → return 2

Python

class Solution:
    def missingNumber(self, nums: List[int]) -> int:
        for candidate in range(len(nums) + 1):     # every number 0..n
            if candidate not in nums:              # a list scan: O(n)
                return candidate
        return -1                                  # unreachable for valid input
Time O(n²)Space O(1)

Up to n + 1 candidates, each tested with an O(n) scan.

When to use: Only as a baseline. With set(nums) it becomes O(n) time and O(n) space.

The numbers 0..n add up to n * (n + 1) // 2: there are n + 1 of them and their average is n / 2. The list holds the same numbers minus one, so its sum is smaller by exactly the missing number:

missing = n * (n + 1) // 2 - sum(nums)

One pass to add up the list, one formula for the rest. In Python integers cannot overflow, so there is nothing to guard against.

Dry run

  1. nums = [3, 0, 1], n = 3
  2. expected = 3 * 4 // 2 = 6 (that is 0 + 1 + 2 + 3)
  3. actual = 3 + 0 + 1 = 4
  4. missing = 6 - 4 = 2

Python

class Solution:
    def missingNumber(self, nums: List[int]) -> int:
        n = len(nums)
        expected = n * (n + 1) // 2         # 0 + 1 + ... + n
        return expected - sum(nums)         # whatever is absent from the sum is the missing number
Time O(n)Space O(1)

sum makes one pass; the rest is arithmetic.

When to use: The shortest correct answer in Python. In C++ or Java mind integer overflow for large n.

Watch it run

Use XOR cancellation instead of arithmetic. XOR every number of 0..n and every value of nums. Each present number is XOR-ed in twice (once from the range, once from the list) and cancels because a ^ a = 0. The missing number is XOR-ed in only once, so it is what remains.

To avoid building the range, use the indices: index i stands for the number i. Start the accumulator at n (the one range number that is not an index) and XOR i ^ nums[i] at each position.

XOR never produces a number wider than its inputs, so it cannot overflow in any language, which is its advantage over the sum.

Dry run

  1. nums = [3, 0, 1], acc = n = 3
  2. i = 0, x = 3: acc ^= 0 ^ 3 → 3 ^ 3 = 0. The 3 from the range cancelled the 3 in the list
  3. i = 1, x = 0: acc ^= 1 ^ 0 → 0 ^ 1 = 1
  4. i = 2, x = 1: acc ^= 2 ^ 1 → 1 ^ 3 = 2. The 1 cancelled, and 2 stays
  5. return 2

Python

class Solution:
    def missingNumber(self, nums: List[int]) -> int:
        acc = len(nums)                  # n is never an index, so it enters here
        for i, x in enumerate(nums):
            acc ^= i ^ x                 # index i cancels value i whenever both exist
        return acc
Time O(n)Space O(1)

One pass, one integer of state; XOR cannot overflow.

When to use: When the topic is bit tricks, or in a fixed-width language where the sum could overflow.

Common mistakes

  • Using the wrong range for the expected sum. The range is 0..n inclusive, so the formula is n * (n + 1) // 2 with n = len(nums), not n * (n - 1) // 2.
  • Forgetting that the missing number can be n itself ([0, 1] gives 2) or 0 ([1] gives 0). A solution that sorts and looks for the first nums[i] != i must return n when it finds no mismatch.
  • Starting the XOR accumulator at 0 while XOR-ing only indices 0..n-1 with the values. The number n is never an index, so it must enter the accumulator some other way: start from n.
  • Writing / instead of // in the formula. n * (n + 1) / 2 is a float. The product of two consecutive integers is always even, so // divides it exactly.
  • Assuming nums is sorted. It is not, so scanning for the first gap or binary searching needs a sort first, which costs O(n log n).

Python notes

  • sum(nums) adds the whole list in C. n * (n + 1) // 2 uses integer division so the result stays an int.
  • Python integers never overflow, so the sum cannot wrap around. In a language with 32-bit integers the XOR version is the safe one for large n.
  • enumerate(nums) yields (i, x) pairs. acc ^= i ^ x evaluates i ^ x first and then XORs the result into acc.
  • set(range(n + 1)) - set(nums) returns the missing numbers directly as a set: O(n) time and memory, a handy way to check an answer.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Single Number LC 136 — the same XOR cancellation with one extra number instead of one missing number.
  • Find the Duplicate Number LC 287 — one value is repeated and nothing is missing. Sum and XOR stop working when the duplicate can appear more than twice, so treat the list as a linked list and use Floyd's cycle detection.
  • First Missing Positive LC 41 — the range is not given: the answer is somewhere in 1..n+1. Put each value v at index v - 1 by swapping, then scan for the first index that holds the wrong value.
  • Find All Numbers Disappeared in an Array LC 448 — several numbers are missing and others repeat. Mark that value v was seen by negating nums[abs(v) - 1] in place, then report the positions that stayed positive.
  • Set Mismatch LC 645 — one number appears twice and another is missing. The XOR of the list and 1..n is duplicate ^ missing; split on a bit where they differ, as in Single Number III.
  • What if nums is sorted? — binary search for the first index where nums[i] != i. That index is the answer, or n if there is none: O(log n).
