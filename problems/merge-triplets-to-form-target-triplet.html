Merge Triplets to Form Target Triplet Medium

LeetCode #1899 ↗
Status

Merge triplets by taking position-wise maximums, and decide whether the target triplet can be produced.

Problem

You are given a list triplets, where each item triplets[i] = [a, b, c] has three numbers, and a target = [x, y, z].

In one operation you pick two different triplets i and j and replace triplet j with the position-wise maximum of the two: [max(a_i, a_j), max(b_i, b_j), max(c_i, c_j)]. You may repeat this as often as you like.

Return True if some triplet in the list can be made equal to target, and False otherwise.

Examples

Example 1
Input: triplets = [[2, 5, 3], [1, 8, 4], [1, 7, 5]], target = [2, 7, 5]
Output: true
Merge the first and third triplets: [max(2, 1), max(5, 7), max(3, 5)] = [2, 7, 5]. The middle triplet is never needed.
Example 2
Input: triplets = [[3, 4, 5], [4, 5, 6]], target = [3, 2, 5]
Output: false
[3, 4, 5] has a 4 where the target has a 2, and [4, 5, 6] is too big in every position. Merging only raises numbers, so neither can ever be used.
Example 3
Input: triplets = [[2, 5, 3], [2, 3, 4], [1, 2, 5], [5, 2, 3]], target = [5, 5, 5]
Output: true
Merge [5, 2, 3] with [2, 5, 3] to get [5, 5, 3], then merge that with [1, 2, 5] to get [5, 5, 5].

Constraints

  • 1 <= len(triplets) <= 10^5
  • len(triplets[i]) == len(target) == 3
  • 1 <= triplets[i][k], target[k] <= 1000

Think first try before reading the solution

An operation only takes maximums, so numbers can only go up. What happens if you ever merge in a triplet that has a number above the target's number in the same position?
That position overshoots, and nothing can bring it back down. So such a triplet can never be part of the answer: throw it away.
Look only at the triplets that remain. Merging all of them gives, in every position, the largest number any of them has there. The target is reachable exactly when, in each of the three positions, some remaining triplet has exactly the target's number.

Key idea

Taking a maximum is a one-way street: values only go up. That gives a clear rule for each triplet.

  • If any of its three numbers is bigger than the target's number in that position, the triplet is unsafe. Merging it would push that position above the target, and nothing can lower it again. Never use it.
  • Every other triplet is safe: it never overshoots, so merging it can only help.

Because merging safe triplets can never overshoot, you do not have to search for the right subset. Merging all the safe triplets is at least as good as any subset of them: it gives the position-wise maximum over every safe triplet, which is the best you can possibly do in each position. So the target is reachable exactly when that combined maximum equals the target.

All safe values in a position are at most the target's value there, so equality needs some safe triplet whose number there equals the target. Three positions, three separate checks, one pass over the list.

Approaches from the obvious one to the one you want in an interview

Take the operation literally. Keep a set of every triplet you can currently hold, starting with the input. Merge every pair in the set, add any new results, and repeat until a round produces nothing new. Then check whether the target is in the set.

It is correct, but the set can grow to a huge number of combinations, and every round compares all pairs of them. Nearly all of that work is wasted on triplets that already overshoot the target.

Dry run

  1. triplets = [[2, 5, 3], [1, 8, 4], [1, 7, 5]], target = [2, 7, 5]
  2. round 1: first + second gives [2, 8, 4], first + third gives [2, 7, 5], second + third gives [1, 8, 5]
  3. [2, 7, 5] is the target → True. The merged triplets that contain an 8 were wasted work: they overshoot.

Python

class Solution:
    def mergeTriplets(self, triplets: List[List[int]], target: List[int]) -> bool:
        goal = tuple(target)
        reachable = {tuple(t) for t in triplets}          # every triplet we can hold right now
        changed = True
        while changed:                                    # repeat until a round adds nothing new
            changed = False
            for a in list(reachable):
                for b in list(reachable):
                    merged = tuple(max(x, y) for x, y in zip(a, b))
                    if merged not in reachable:
                        reachable.add(merged)
                        changed = True
        return goal in reachable
Time O(m²) per roundSpace O(m)

m is the number of distinct triplets that can be built; it can approach n³ (up to 10^9 with values to 1000).

When to use: Only to check the greedy answer on tiny inputs.

  1. A triplet is safe if none of its numbers is above the target's number in the same position. Skip every unsafe one.
  2. Merge all the safe triplets into one running triplet merged, using the position-wise maximum.
  3. Return whether merged == target.

Merging safe triplets never overshoots, so using all of them can only help, and no subset beats the full merge. One pass over the list, with three numbers of state.

Dry run

  1. triplets = [[2, 5, 3], [1, 8, 4], [1, 7, 5]], target = [2, 7, 5], merged = [0, 0, 0]
  2. [2, 5, 3]: safe → merged = [2, 5, 3]
  3. [1, 8, 4]: 8 > 7 → unsafe, skip
  4. [1, 7, 5]: safe → merged = [max(2, 1), max(5, 7), max(3, 5)] = [2, 7, 5]
  5. merged == target → True

Python

class Solution:
    def mergeTriplets(self, triplets: List[List[int]], target: List[int]) -> bool:
        merged = [0, 0, 0]                                # the best triplet we can build from the safe ones
        for triplet in triplets:
            if all(value <= goal for value, goal in zip(triplet, target)):    # safe: never overshoots
                merged = [max(m, value) for m, value in zip(merged, triplet)]
        return merged == target
Time O(n)Space O(1)

One pass; the running triplet always has three entries.

When to use: The standard answer. It mirrors the operation: filter, merge, compare.

Watch it run

The same filter, with less state. For each safe triplet, note which of the three positions it matches exactly. The target is reachable if all three positions end up matched by some safe triplet.

Because a safe triplet is never above the target, the maximum in a position reaches the target exactly when some safe triplet has that value there. A set of at most three positions replaces the running triplet, and you can stop as soon as it is full.

Dry run

  1. triplets = [[2, 5, 3], [1, 8, 4], [1, 7, 5]], target = [2, 7, 5], matched = {}
  2. [2, 5, 3] is safe and matches position 0 (2 = 2) → {0}
  3. [1, 8, 4] is unsafe, skip
  4. [1, 7, 5] is safe and matches positions 1 and 2 → {0, 1, 2} → True

Python

class Solution:
    def mergeTriplets(self, triplets: List[List[int]], target: List[int]) -> bool:
        matched = set()                                   # positions some safe triplet hits exactly
        for triplet in triplets:
            if all(value <= goal for value, goal in zip(triplet, target)):    # safe triplet
                for pos in range(3):
                    if triplet[pos] == target[pos]:
                        matched.add(pos)
        return len(matched) == 3
Time O(n)Space O(1)

One pass; the set holds at most three positions.

When to use: When you prefer the "which positions are covered" view, or want to stop early once all three are matched.

Common mistakes

  • Judging a triplet by its sum or by only some positions. [1, 8, 4] looks small, but its 8 overshoots the target's 7, so the whole triplet is unusable. One bad position makes it unsafe.
  • Looking for a single triplet that matches. The answer can need three different triplets, each supplying a different position ([1, 5, 1], [1, 1, 5], [5, 1, 1] for the target [5, 5, 5]).
  • Taking the maximum over all triplets, including unsafe ones. A single oversize triplet ruins the position-wise maximum. Filter first, then merge.
  • Treating an unsafe triplet as a reason to return False. It is only skipped; other triplets may still build the target.
  • Stopping at a maximum that is close to the target. The result has to equal the target exactly, and a safe maximum can only stay at or below it.

Python notes

  • all(value <= goal for value, goal in zip(triplet, target)) checks all three positions without indexing.
  • [max(m, value) for m, value in zip(merged, triplet)] builds the position-wise maximum of two triplets.
  • Lists compare element by element, so merged == target is a complete equality test.
  • In the brute force, triplets go into a set as tuples: lists are mutable and cannot be set members.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Use the minimum instead of the maximum — the logic mirrors: a triplet is unsafe if any number is below the target's, merge with min, and check that each position is hit exactly.
  • Use bitwise OR instead of the maximum — OR also only adds bits, so a triplet is safe if value | goal == goal (its bits are a subset of the target's); OR the safe ones together and compare.
  • More than three positions — loop over k positions instead of three; the cost becomes O(n·k), and the argument is unchanged.
  • Return which triplets you used — remember the first safe triplet that hits each position; at most three triplets are ever needed.
