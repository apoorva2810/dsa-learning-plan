Remove Duplicates from Sorted Array Easy 250

LeetCode #26 ↗
Status

Move the distinct values of a sorted array to its front, in place, and return how many there are.

Problem

You are given a list of integers nums sorted in non-decreasing order (each value is at least as large as the one before it). Rearrange nums in place so that every value appears only once, keeping the values in their original order, and return k, the number of distinct values.

After your function returns, the first k slots of nums must hold the distinct values in order. Whatever sits in the slots after them does not matter. Do not build a second list: the point of the exercise is to do it with O(1) extra memory, the way you would in a language where arrays cannot grow or shrink.

(Our tests check the whole list after the call: the first k slots must be the distinct values; the slots after them may keep whatever was there, or be gone if you shrank the list.)

Examples

Example 1
Input: nums = [1, 1, 2]
Output: 2, nums = [1, 2, _]
Two distinct values. The first two slots hold 1 and 2; the last slot is leftover and ignored.
Example 2
Input: nums = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]
Output: 5, nums = [0, 1, 2, 3, 4, _, _, _, _, _]
Five distinct values, 0 to 4, moved to the front. The five slots after them are ignored.
Example 3
Input: nums = [2, 2, 2, 2]
Output: 1, nums = [2, _, _, _]
Only one distinct value, so k = 1 and only the first slot counts.

Constraints

  • 1 <= len(nums) <= 3 * 10^4
  • -100 <= nums[i] <= 100
  • nums is sorted in non-decreasing order

Think first try before reading the solution

Because the list is sorted, every repeat of a value sits right next to the first copy. To know whether a value was seen before, you never need to search: compare it with the value you kept last.
Deleting from the middle of a list shifts everything after it, so repeated pop calls cost O(n²) in total. Do not delete; overwrite. Keep a write index that marks the next free slot of the clean prefix.
Walk a read index over the list. Whenever nums[read] differs from nums[write - 1], the last kept value, copy it to nums[write] and advance write. When read reaches the end, write is the answer.

Key idea

Two facts make this easy. First, the list is sorted, so copies of a value are adjacent: a value is a repeat exactly when it equals the value just before it. Second, the slots after the distinct values do not matter, so nothing has to be deleted or shifted; a repeat can be left where it is and simply overwritten later.

Picture two pointers moving in the same direction. read scans every slot. write lags behind and points at the next free slot of the clean prefix nums[0 .. write - 1], which holds the distinct values found so far, in order. When read meets a new value, copy it to nums[write] and move write one slot right; when it meets a repeat, do nothing. write can never pass read, so it only ever overwrites slots that read has already looked at. Nothing you still need is destroyed.

This "slow and fast pointer" shape, one index reading and one writing, is the template for every "filter an array in place" problem: Remove Element, Move Zeroes, and the "at most twice" version of this one.

Approaches from the obvious one to the one you want in an interview

Walk the list and delete every value that equals its left neighbour with nums.pop(i). It gives the right values and the right count, but pop(i) is not a cheap operation: Python moves every later element one slot left, which is O(n) work. A list of n copies of the same value triggers n − 1 pops of a shrinking tail, about n²/2 moves in total.

It also changes the length of the list, which the problem rules out in spirit: in most languages an array cannot shrink, and the point is to solve it with the array you were given.

Dry run

  1. [1, 1, 2], i = 1: nums[1] = 1 repeats nums[0] → pop(1) → [1, 2], i stays 1
  2. i = 1: nums[1] = 2 differs from nums[0] → keep, i = 2
  3. i = 2 = len(nums) → stop, return 2

Python

class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        i = 1
        while i < len(nums):
            if nums[i] == nums[i - 1]:
                nums.pop(i)                  # shifts every later value one slot left: O(n)
            else:
                i += 1                       # only advance when nothing was removed
        return len(nums)
Time O(n²)Space O(1)

Up to n − 1 pops, each shifting up to n elements; no extra memory.

When to use: Never in an interview; it is here to show why deleting from the middle of an array is the wrong tool.

Watch it run

Scan once and append a value to a new list unique whenever it differs from the last value appended. Because nums is sorted, that single comparison is enough to detect every repeat. Finally copy unique back into the front of nums with nums[:k] = unique and return k.

This is O(n) time, but it uses O(n) extra memory for unique. Look at where the values end up: unique[j] is written into nums[j], and j never gets ahead of the index being read. So the new list is not needed at all; the front of nums can play its role. That observation is the optimal approach.

Python

class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        unique = []
        for value in nums:
            if not unique or unique[-1] != value:   # sorted: a repeat can only equal the last kept value
                unique.append(value)
        nums[:len(unique)] = unique                 # copy back into the front of the SAME list
        return len(unique)
Time O(n)Space O(n)

One pass plus one copy; unique can hold all n values when there are no repeats.

When to use: Fine when the problem allows a new list; it also makes the copy-back step visible before you remove it.

Keep two indices. read visits every slot from 1 to n − 1. write starts at 1 and points at the next free slot of the clean prefix nums[0 .. write - 1].

  • If nums[read] equals nums[write - 1], the last kept value, it is a repeat: do nothing.
  • Otherwise it is a new value: copy it to nums[write] and advance write.

write <= read always holds, so a copy only ever lands on a slot that read has already passed; no unread value is lost. When the loop ends, the prefix holds every distinct value in order and write is their count. One pass, no extra memory.

Dry run

  1. [0, 0, 1, 1, 1, 2, 2, 3, 3, 4], write = 1
  2. read = 1: 0 equals nums[0] → skip
  3. read = 2: 1 is new → nums[1] = 1, write = 2
  4. read = 3, 4: both 1 → skip
  5. read = 5: 2 is new → nums[2] = 2, write = 3; read = 6: skip
  6. read = 7: 3 is new → nums[3] = 3, write = 4; read = 8: skip
  7. read = 9: 4 is new → nums[4] = 4, write = 5 → return 5, nums starts [0, 1, 2, 3, 4]

Python

class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        if not nums:
            return 0
        write = 1                                # next free slot; nums[0] is always kept
        for read in range(1, len(nums)):
            if nums[read] != nums[write - 1]:    # differs from the last kept value: a new value
                nums[write] = nums[read]
                write += 1
        return write                             # the clean prefix is nums[0 .. write - 1]
Time O(n)Space O(1)

read touches each slot once; only two integer indices are stored.

When to use: Always. The same read/write loop solves Remove Element, Move Zeroes and the 'at most twice' variant.

Common mistakes

  • Deleting with pop(i), del nums[i] or nums.remove(x) inside the loop. Each call shifts every later value one slot left, so a list full of repeats costs O(n²). It also changes the length, which the problem forbids in spirit.
  • Popping index i and then still doing i += 1. After the pop, the next value slides into slot i, so the increment skips it, and two equal values in a row survive.
  • Returning len(set(nums)) without touching the list. The count is right, but the judge reads the first k slots of nums, which still hold repeats.
  • Building a clean list and writing nums = unique. That rebinds the local name; the caller's list is unchanged. You must write into the existing list: nums[:k] = unique, or better, overwrite slot by slot.
  • Starting write at 0 and comparing with nums[write - 1]. In Python nums[-1] is the last element, so the first value may be dropped. The first value is always kept: start write at 1.

Python notes

  • list.pop(i) costs O(n − i): every element after i is moved one slot left in C. Popping near the front of a long list is the slowest case.
  • nums[:k] = unique replaces the first k slots of the same list object; nums = unique only rebinds the local name and the caller never sees the change.
  • The tests here compare nums after the call. The optimal and the copy-back approaches leave the leftover values in the tail, so [1, 1, 2] becomes [1, 2, 2]; the pop approach shrinks the list to [1, 2]. Both are accepted.
  • LeetCode's judge does the same thing: it reads your return value k and compares nums[:k] with the expected values.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Remove Duplicates from Sorted Array II LC 80 — each value may appear at most twice: compare nums[read] with nums[write - 2] instead of nums[write - 1], and start both pointers at 2.
  • Remove Element LC 27 — same read/write walk, but the test is nums[read] != val; the list need not be sorted.
  • Move Zeroes LC 283 — keep the non-zero values with the same walk, then fill slots write .. n - 1 with zeros, because here the tail does matter.
  • Remove Duplicates from Sorted List LC 83 — the same idea on a linked list: when node.val == node.next.val, skip the next node by relinking instead of copying values.
  • What if nums is not sorted? — repeats are no longer adjacent, so comparing with the last kept value fails. Either sort first (O(n log n), the original order is lost) or keep a set of seen values (O(n) extra memory).
  • Return the distinct values as a new list — then write is not needed: append to a new list whenever the value differs from the last one appended; O(n) extra space, same O(n) time.
