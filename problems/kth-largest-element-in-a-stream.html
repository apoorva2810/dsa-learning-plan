Kth Largest Element in a Stream Easy

LeetCode #703 ↗
Status

Numbers arrive one at a time; after each one, report the k-th largest number seen so far.

Problem

Design a class KthLargest that keeps track of the k-th largest number in a stream of numbers. "k-th largest" means k-th in sorted order from the top, counting duplicates (in [5, 5, 3] the 2nd largest is 5).

  • KthLargest(k, nums) starts the stream with the integer k and an initial list nums (which may be empty).
  • add(val) appends val to the stream and returns the k-th largest number among everything added so far, including the initial nums.

It is guaranteed that whenever add returns, the stream holds at least k numbers.

Examples

Example 1
Input: ["KthLargest","add","add","add","add","add"] [[3,[4,5,8,2]],[3],[5],[10],[9],[4]]
Output: [null, 4, 5, 5, 8, 8]
After add(3) the stream is 2, 3, 4, 5, 8: the 3rd largest is 4. After add(10) the top three are 10, 8, 5, so the answer is 5. After add(9) they are 10, 9, 8.
Example 2
Input: ["KthLargest","add","add","add","add"] [[4,[7,7,7,7,8,3]],[2],[10],[9],[9]]
Output: [null, 7, 7, 7, 8]
Duplicates count separately: the top four after add(2) are 8, 7, 7, 7.

Constraints

  • 0 <= len(nums) <= 10^4
  • 1 <= k <= len(nums) + 1
  • -10^4 <= nums[i], val <= 10^4
  • at most 10^4 calls to add

Think first try before reading the solution

Do you really need to remember every number? Once a number is smaller than k others, can it ever be the answer again?
Only the k largest numbers so far matter. Among those, the answer is the smallest one. Which structure gives you the smallest of a group quickly, and lets you throw it away quickly?
Keep a min-heap of at most k numbers. On add, push the value; if the heap now has k + 1 numbers, pop the smallest. The root is the answer.

Key idea

The k-th largest of everything seen is the smallest member of the top-k club. A number that falls out of the club can never come back: new arrivals only push the bar higher. So store just the club, k numbers, and make it cheap to (a) see its weakest member and (b) kick that member out.

A min-heap does both: heap[0] is the weakest member in O(1), and heappop removes it in O(log k). On every add, push the newcomer; if the club now has k + 1 members, pop the weakest. The root is then the answer. It sounds backwards (a min-heap to track the largest values) but the thing you keep throwing away is always the smallest of the group.

Approaches from the obvious one to the one you want in an interview

Store the whole stream, kept in sorted order. bisect.insort finds the right position by binary search and inserts there, so the list stays sorted; the k-th largest is then nums[-k], k places from the end.

The binary search is O(log n), but inserting into a Python list shifts every element after the insertion point: O(n) per add, and the list grows forever. Re-sorting the whole list on every call is the same idea done worse. The waste: we keep (and keep moving) values that can never be the answer again.

Dry run

  1. k = 3, start [2, 4, 5, 8]
  2. add(3) → [2, 3, 4, 5, 8], nums[-3] = 4
  3. add(5) → [2, 3, 4, 5, 5, 8], nums[-3] = 5
  4. add(10) → [2, 3, 4, 5, 5, 8, 10], nums[-3] = 5; the values 2, 3, 4 are dead weight from here on.

Python

class KthLargest:
    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.nums = sorted(nums)                 # the whole stream, ascending

    def add(self, val: int) -> int:
        bisect.insort(self.nums, val)            # binary search for the spot, then shift to insert: O(n)
        return self.nums[-self.k]                # k-th from the end = k-th largest
Time O(n) per addSpace O(n)

n = values seen so far. The insert shifts up to n elements; memory grows with the whole stream.

When to use: When you also need other ranks (k changes, or you need the median too) and n is modest.

Keep a min-heap that holds at most k values: the k largest seen so far. On add(val):

  1. push val;
  2. if the heap now holds k + 1 values, pop the smallest; it is beaten by k others and can never be the answer again;
  3. return heap[0], the smallest of the k largest, which is by definition the k-th largest.

The constructor just runs the initial numbers through the same steps. The heap never exceeds k + 1 items, so each call is O(log k), and values that can no longer matter are discarded immediately.

Dry run

  1. k = 3. Push 4, 5, 8 → heap [4, 5, 8]. Push 2 → 4 items → pop 2. Heap [4, 5, 8].
  2. add(3): push → pop 3 (it is the smallest) → return 4
  3. add(5): push → pop 4 → heap [5, 5, 8] → return 5
  4. add(10): push → pop 5 → heap [5, 8, 10] → return 5
  5. add(9): push → pop 5 → heap [8, 9, 10] → return 8
  6. add(4): push → pop 4 → return 8

Python

class KthLargest:
    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.heap = []                           # min-heap of the k largest values seen
        for x in nums:
            self.add(x)

    def add(self, val: int) -> int:
        heapq.heappush(self.heap, val)
        if len(self.heap) > self.k:              # one too many:
            heapq.heappop(self.heap)             # the smallest can never be the answer again
        return self.heap[0]                      # smallest of the k largest = k-th largest
Time O(log k) per addSpace O(k)

The heap holds at most k + 1 values, so a push or pop costs O(log k). The constructor is O(n log k).

When to use: The standard answer: constant memory per stream and fast updates.

Common mistakes

  • Pushing every value and never popping: heap[0] is then the smallest number overall, not the k-th largest. Trim back to k after each push.
  • Using a max-heap of everything: the k-th largest is no longer at the top, so every add would need k pops and k pushes back.
  • Popping before the heap has k numbers. When nums starts shorter than k, only trim when the size exceeds k.
  • Peeking at heap[0] to decide whether to push (the heappushpop shortcut) before the heap is full: on an empty heap it raises IndexError, and on a part-full heap it wrongly rejects values.

Python notes

  • heapq.heappushpop(self.heap, val) pushes and then pops the smallest in a single pass over the heap. Use it only once the heap already holds k numbers.
  • Another constructor: heapq.heapify(nums) (O(n)), then heappop until len(nums) == k. That costs O(n + (n - k) log n), which beats n pushes (O(n log k)) when k is close to n.
  • self.heap[0] reads the smallest item without removing it.
  • Design problems are tested as a list of calls; the first entry is the constructor and returns None.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Kth Largest Element in an Array LC 215 — the same question on a fixed array: the size-k heap still works, and quickselect becomes possible because all the data is known up front.
  • Find Median from Data Stream LC 295 — track the middle instead of the k-th: two heaps whose tops meet in the middle.
  • Top K Frequent Elements LC 347 — the same size-k min-heap, but it holds (count, value) pairs, ranked by count.
  • Sliding Window Median LC 480 — numbers also leave (they slide out of a window), and a heap cannot delete from the middle: add lazy deletion (remember what left and discard it only when it reaches the top), or use a sorted container.
  • What if k changes between calls? — a heap sized for one k no longer helps. Keep every value in a sorted structure (bisect on a list, or sortedcontainers.SortedList) and index [-k].
