Reverse Linked List Easy

LeetCode #206 ↗
Status

Turn a singly linked list around so the last node becomes the first.

Problem

You are given head, the first node of a singly linked list: every node has a value val and a pointer next to the node after it, and the last node's next is None.

Reverse the list so that every next pointer points to the node that used to come before it, and return the new head (the old last node). Change the pointers, not the values.

An empty list (head is None) stays empty.

Examples

Example 1
Input: head = [1, 2, 3, 4, 5]
Output: [5, 4, 3, 2, 1]
Example 2
Input: head = [1, 2]
Output: [2, 1]
Example 3
Input: head = []
Output: []
Nothing to reverse; return None.

Constraints

  • 0 <= number of nodes <= 5000
  • -5000 <= Node.val <= 5000

Think first try before reading the solution

You cannot walk backwards in a singly linked list, but you can change where each next points while you walk forwards.
The moment you set cur.next to the previous node, the rest of the list is unreachable, unless you saved cur.next first.
Keep three names: prev (head of the part already reversed), cur (the node being flipped) and nxt (the saved rest). Save, flip, then move prev and cur one step to the right.

Key idea

A linked list is a chain of arrows: 1 → 2 → 3 → None. Reversing it means flipping every arrow, giving None ← 1 ← 2 ← 3, so 3 becomes the head. No values move; only next pointers change.

Walk the list once and flip one arrow per node. The only danger is the order of operations: the arrow you are about to overwrite (cur.next) is your only way to reach the rest of the list, so save it first (nxt = cur.next), then flip (cur.next = prev), then step forward (prev = cur, cur = nxt). When cur falls off the end, prev is the old tail, which is the new head. One pass and three variables: O(n) time, O(1) extra space.

The same idea also reads as recursion (a function that calls itself on a smaller input): reverse everything after the head, then hook the head onto the end of that reversed rest.

Approaches from the obvious one to the one you want in an interview

You cannot walk a singly linked list backwards, so make it walkable: copy every node reference into a Python list. Now nodes[i - 1] is the node before nodes[i], and reversing is just nodes[i].next = nodes[i - 1] for every i, plus making the old head point to None.

It is correct and still O(n) time, but it needs O(n) extra memory for the list of nodes. The point of the problem is that the reversal can be done with three variables instead.

Dry run

  1. head = [1, 2, 3] → nodes = [n1, n2, n3]
  2. n3.next = n2, n2.next = n1
  3. n1.next = None (the old head is the new tail); return n3

Python

class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        nodes = []
        while head:                          # remember every node, in order
            nodes.append(head)
            head = head.next
        if not nodes:
            return None
        for i in range(len(nodes) - 1, 0, -1):
            nodes[i].next = nodes[i - 1]     # point each node at the one before it
        nodes[0].next = None                 # the old head becomes the tail
        return nodes[-1]
Time O(n)Space O(n)

Two passes over n nodes, and a list that stores all n references.

When to use: Only as a stepping stone; it shows what the O(1)-space version must replace.

Walk the list once with two pointers: prev is the head of the part already reversed (it starts as None), and cur is the next node to flip. For each node:

  1. nxt = cur.next: save the rest of the list.
  2. cur.next = prev: flip this node's arrow.
  3. prev, cur = cur, nxt: step forward.

When cur becomes None, every arrow has been flipped and prev is the new head. Each node is touched once and only three variables are used, whatever the length.

Dry run

  1. prev = None, cur = 1: list 1 → 2 → 3 → None
  2. save nxt = 2; flip 1.next = None; step → prev = 1, cur = 2
  3. save nxt = 3; flip 2.next = 1; step → prev = 2, cur = 3
  4. save nxt = None; flip 3.next = 2; step → prev = 3, cur = None
  5. loop ends; return prev: 3 → 2 → 1 → None

Python

class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev = None                          # head of the reversed part
        cur = head                           # next node to flip
        while cur:
            nxt = cur.next                   # 1. save the rest of the list
            cur.next = prev                  # 2. flip this node's arrow
            prev = cur                       # 3. step forward
            cur = nxt
        return prev                          # the old tail is the new head
Time O(n)Space O(1)

One pass; three pointer variables regardless of the list length.

When to use: The interview answer. It is also the building block for k-group reversal, palindrome checks and Reorder List.

Watch it run

Define the answer in terms of a smaller answer. A list of 0 or 1 nodes is already reversed (the base case). Otherwise:

  1. new_head = reverseList(head.next) reverses everything after head. Its tail is head.next, the node that used to follow head, and head still points to it.
  2. head.next.next = head makes that tail point back at head.
  3. head.next = None makes head the new tail.

new_head (the original last node) is passed back up unchanged through every call. Same O(n) time, but each call waits on the call stack, so it uses O(n) memory and hits Python's recursion limit on long lists.

Dry run

  1. reverseList(1) calls reverseList(2), which calls reverseList(3)
  2. reverseList(3): 3.next is None → base case, return 3
  3. back in reverseList(2): 2.next.next = 2 (so 3 → 2), 2.next = None, return 3
  4. back in reverseList(1): 1.next.next = 1 (so 2 → 1), 1.next = None, return 3

Python

class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if head is None or head.next is None:   # 0 or 1 node: already reversed
            return head
        new_head = self.reverseList(head.next)  # reverse everything after head
        head.next.next = head                   # the old next node points back at head
        head.next = None                        # head becomes the tail
        return new_head
Time O(n)Space O(n)

One call per node; up to n frames wait on the call stack at the deepest point.

When to use: When asked for a recursive solution, or to show you can reason about what happens on the way back up.

Common mistakes

  • Overwriting cur.next before saving it: the rest of the list becomes unreachable and the loop stops after one node.
  • Returning head at the end. After the loop, head is the tail (its next is None); the new head is prev.
  • Recursive version: forgetting head.next = None. The old first node keeps pointing at the second node, which now points back at it, so the result ends in a two-node cycle.
  • Tuple assignment order: cur.next, prev, cur = prev, cur, cur.next is correct, but cur, cur.next, prev = cur.next, prev, cur sets .next on the new cur, because the targets are assigned left to right. An explicit nxt variable avoids the trap.
  • Recursion depth: 5000 nodes means 5000 nested calls, past Python's default limit of 1000. The iterative version has no limit.

Python notes

  • while cur: loops until cur is None: None is falsy and any node is truthy.
  • cur.next, prev, cur = prev, cur, cur.next is the popular one-liner. Python evaluates the whole right side first, then assigns the targets left to right, so this particular order works. Write the three-line version until that rule feels obvious.
  • The tests write lists as Python lists: the site turns [1, 2, 3] into ListNode(1) → ListNode(2) → ListNode(3) before calling reverseList, and turns the head you return back into a list. Returning None means the empty list.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Reverse Linked List II LC 92 — reverse only positions left..right: walk to the node before left, run the same flip loop right - left + 1 times, then reconnect both ends of the reversed piece.
  • Reverse Nodes in k-Group LC 25 — reverse every block of k nodes: this loop once per block, plus stitching each block to its neighbours.
  • Palindrome Linked List LC 234 — find the middle with slow/fast pointers, reverse the second half, then compare the halves node by node in O(1) extra space.
  • Reorder List LC 143 — split at the middle, reverse the second half, then weave the two halves together.
  • Swap Nodes in Pairs LC 24 — the k = 2 case of k-group reversal; good practice for reconnecting the pieces.
  • Reverse a doubly linked list — swap prev and next on every node; the old tail becomes the head. No saved pointer is needed because prev already remembers the way back.
