Find the Town Judge Easy 250

LeetCode #997 ↗
Status

Find the one person whom everybody trusts and who trusts nobody, from a list of trust pairs.

Problem

A town has n people, labelled 1 to n. Rumour says one of them is secretly the town judge. If the judge exists, three things are true:

  1. the judge trusts nobody;
  2. everybody else trusts the judge;
  3. exactly one person satisfies both 1 and 2.

You are given trust, a list of pairs [a, b] meaning "person a trusts person b". Nobody trusts themselves and no pair appears twice. Return the label of the judge, or -1 if there is no judge.

Examples

Example 1
Input: n = 2, trust = [[1, 2]]
Output: 2
Person 1 trusts person 2, and person 2 trusts nobody.
Example 2
Input: n = 3, trust = [[1, 3], [2, 3]]
Output: 3
Both other people trust person 3, who trusts nobody.
Example 3
Input: n = 3, trust = [[1, 3], [2, 3], [3, 1]]
Output: -1
Everybody trusts person 3, but person 3 trusts person 1, so there is no judge.

Constraints

  • 1 <= n <= 1000
  • 0 <= len(trust) <= 10^4
  • trust[i] = [a, b] with 1 <= a, b <= n and a != b
  • all pairs are distinct

Think first try before reading the solution

Draw an arrow from a to b for every pair. What do the arrows around the judge look like?
Every other person has an arrow into the judge, and the judge has no arrow going out. Count incoming and outgoing arrows for each person: the judge has n − 1 in and 0 out.
One number per person is enough: incoming minus outgoing. Only someone with n − 1 in and 0 out can reach n − 1.

Key idea

The pairs form a directed graph: one node per person, and an arrow a → b for "a trusts b". In graph words, the judge is the node with in-degree n − 1 (an arrow from every other person) and out-degree 0 (no arrow leaving). So count arrows: one pass over the pairs adds one to trusted_by[b] and one to trusts[a], and one pass over the people finds the one with trusted_by == n − 1 and trusts == 0.

The two counts can be merged into one score = trusted-by minus trusts. Why is score == n − 1 enough to be sure? Nobody trusts themselves and pairs are unique, so a person is trusted by at most n − 1 others. Trusting even one person costs a point and drops the score to n − 2 at best. The only way to reach n − 1 is to be trusted by everyone and trust nobody, which is exactly the judge. The same reasoning shows at most one person can have that score: two such people would each have to trust the other.

Both passes are linear: O(n + T) for T trust pairs. The one special case to keep in mind is n = 1 with no pairs: the lone person is trusted by all zero others and trusts nobody, so the answer is 1.

Approaches from the obvious one to the one you want in an interview

Take each person in turn as a candidate and scan the whole trust list twice: does the candidate ever appear as the truster a? How many pairs have the candidate as the trusted b? The candidate is the judge when the first answer is "never" and the second is n − 1.

Correct and easy to read, but every candidate rescans all T pairs: O(n · T), which is 10 million checks at the limits. The two counts for a person never change, so computing them n times is the waste the next approach removes.

Dry run

  1. Example 2: n = 3, trust = [[1, 3], [2, 3]].
  2. Candidate 1: appears as a truster in [1, 3] → not the judge.
  3. Candidate 2: appears as a truster in [2, 3] → not the judge.
  4. Candidate 3: never a truster; trusted in 2 pairs = n − 1 → return 3.

Python

class Solution:
    def findJudge(self, n: int, trust: List[List[int]]) -> int:
        for candidate in range(1, n + 1):
            trusts_nobody = all(a != candidate for a, b in trust)          # never on the left of a pair
            trusted_by = sum(1 for a, b in trust if b == candidate)        # how often on the right
            if trusts_nobody and trusted_by == n - 1:
                return candidate
        return -1
Time O(n · T)Space O(1)

n candidates, each scanning all T pairs; no extra memory beyond two counters.

When to use: Only as a first draft to confirm you understand the two conditions.

Go through the pairs once. For [a, b], subtract 1 from score[a] (a trusts someone) and add 1 to score[b] (b is trusted by one more person). Then look for the person whose score is exactly n − 1.

That single number carries both conditions. A person can be trusted by at most n − 1 others, so the only way to score n − 1 is to collect all of those and lose none, that is, to trust nobody. Anyone who trusts even one person tops out at n − 2. One pass over the pairs and one over the people: O(n + T).

Dry run

  1. Example 3: n = 3, trust = [[1, 3], [2, 3], [3, 1]], target score 2.
  2. [1, 3]: score[1] = -1, score[3] = 1. [2, 3]: score[2] = -1, score[3] = 2.
  3. [3, 1]: score[3] = 1, score[1] = 0. Person 3 lost the point for trusting someone.
  4. Scan: scores are 0, -1, 1; nobody has 2 → return -1.

Python

class Solution:
    def findJudge(self, n: int, trust: List[List[int]]) -> int:
        score = [0] * (n + 1)                  # index = person label; slot 0 is unused
        for a, b in trust:
            score[a] -= 1                      # a trusts someone: a cannot be the judge
            score[b] += 1                      # b is trusted by one more person
        for person in range(1, n + 1):
            if score[person] == n - 1:         # trusted by all others and trusts nobody
                return person
        return -1
Time O(n + T)Space O(n)

One pass over the T pairs, one over the n people; one integer per person.

When to use: The default answer: shortest code, one array, and the reasoning behind n - 1 makes a good interview explanation.

Watch it run

Keep the two conditions separate: trusted_by[p] counts arrows into p (its in-degree) and trusts[p] counts arrows out of p (its out-degree). The judge is the person with trusted_by == n − 1 and trusts == 0.

Same O(n + T) time and twice the memory, but nothing clever to justify, and the test is easy to change when the rules change (for example, a judge who may trust up to k people).

Dry run

  1. Example 2: [1, 3] → trusts[1] = 1, trusted_by[3] = 1. [2, 3] → trusts[2] = 1, trusted_by[3] = 2.
  2. Person 1: trusts 1 → no. Person 2: trusts 1 → no. Person 3: trusted_by 2 = n − 1 and trusts 0 → return 3.

Python

class Solution:
    def findJudge(self, n: int, trust: List[List[int]]) -> int:
        trusted_by = [0] * (n + 1)             # arrows into each person (in-degree)
        trusts = [0] * (n + 1)                 # arrows out of each person (out-degree)
        for a, b in trust:
            trusts[a] += 1
            trusted_by[b] += 1
        for person in range(1, n + 1):
            if trusted_by[person] == n - 1 and trusts[person] == 0:
                return person
        return -1
Time O(n + T)Space O(n)

Same passes as the score version, with two integers per person instead of one.

When to use: When the conditions might change, or when you want the two graph degrees visible in the code.

Common mistakes

  • Checking only 'trusted by everyone'. In example 3 person 3 is trusted by both others but trusts person 1, so there is no judge. Both conditions are needed.
  • Returning the first person who trusts nobody. Several people may trust nobody; the judge is the one who is also trusted by all n − 1 others.
  • Off-by-one with labels. People are numbered from 1, so either allocate n + 1 slots and ignore index 0, or subtract 1 everywhere. Mixing the two is the usual bug.
  • Forgetting n = 1. With no pairs, the loop over trust does nothing and a solution that only looks at people who appear in pairs returns -1 instead of 1.
  • Scanning the whole trust list once per candidate (trust.count, any(...) inside the loop). That is the O(n · T) brute force; count everything in one pass instead.

Python notes

  • score = [0] * (n + 1) lets you index by label directly; slot 0 stays unused. A dict works too but the list is faster.
  • for a, b in trust: unpacks each pair into two named variables; much clearer than pair[0] and pair[1].
  • next((p for p in range(1, n + 1) if score[p] == n - 1), -1) finds the judge or returns the default -1 in one line.
  • collections.Counter(b for a, b in trust) counts the incoming arrows if you prefer not to pre-size a list.
