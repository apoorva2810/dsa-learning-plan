Merge Two Sorted Lists Easy

LeetCode #21 ↗
Status

Splice two sorted linked lists into one sorted list.

Problem

You are given the heads of two linked lists, list1 and list2. Each is sorted in non-decreasing order (every value is at most the next one).

Merge them into one sorted list made from the nodes of the two inputs (re-link the existing nodes; you do not need new ones) and return its head. Either list, or both, may be empty.

Examples

Example 1
Input: list1 = [1, 2, 4], list2 = [1, 3, 4]
Output: [1, 1, 2, 3, 4, 4]
Example 2
Input: list1 = [], list2 = []
Output: []
Example 3
Input: list1 = [], list2 = [0]
Output: [0]
One side is empty, so the answer is the other list as it is.

Constraints

  • 0 <= number of nodes in each list <= 50
  • -100 <= Node.val <= 100
  • both lists are sorted in non-decreasing order

Think first try before reading the solution

Which node must come first in the merged list? Compare only two nodes to decide.
After you take that node, the rest of the problem is the same problem with one list a node shorter.
Start the answer with a dummy node and keep a tail pointer to its last node. Attach the smaller of the two fronts to tail, advance that list, and repeat. When one list runs out, attach the other one whole.

Key idea

Think of two sorted piles of cards, face up. The smallest card overall is on top of one of the piles, so take the smaller of the two top cards, then compare the new tops, and so on. Each comparison places one card, so merging n + m cards takes about n + m comparisons.

Linked lists make "take a card" cheap: point the end of the result (tail.next) at the chosen node and move that list's head forward. A dummy node (a placeholder node before the real answer) means there is always a tail to attach to, even before the first real node, so the first node needs no special case; the answer is dummy.next. When one list is empty, everything left in the other is already sorted and larger than what we placed, so it is attached in one step.

Approaches from the obvious one to the one you want in an interview

Ignore the fact that the inputs are sorted: copy every value into a Python list, sort it, and build a fresh linked list from the sorted values.

It is short and correct, but sorting costs O((n + m) log(n + m)) and the copy costs O(n + m) memory. It also creates new nodes instead of re-linking the given ones. The inputs are already sorted, which is exactly the information that lets a merge do it in one linear pass.

Python

class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        values = []
        for node in (list1, list2):
            while node:                      # copy every value out
                values.append(node.val)
                node = node.next
        values.sort()
        dummy = tail = ListNode()
        for v in values:                     # build a new list from the sorted values
            tail.next = ListNode(v)
            tail = tail.next
        return dummy.next
Time O((n + m) log(n + m))Space O(n + m)

Sorting dominates; the value list and the new nodes take linear memory.

When to use: Never needed here; it is the baseline that ignores the sorted input.

The merged list starts with the smaller of the two heads, and the rest of it is the merge of everything else. That sentence is the recursion:

  • if one list is empty, the answer is the other list;
  • if list1.val <= list2.val, then list1.next = merge(list1.next, list2) and the answer is list1;
  • otherwise the same with the roles swapped.

Each call places one node, so it is O(n + m) time. Each call also waits on the call stack until the calls below it finish, so it uses O(n + m) stack memory.

Dry run

  1. merge([1,2,4], [1,3,4]): 1 <= 1 → keep list1's 1, its next = merge([2,4], [1,3,4])
  2. merge([2,4], [1,3,4]): 1 < 2 → keep list2's 1, next = merge([2,4], [3,4])
  3. … until one side is empty, which returns the other side whole

Python

class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        if list1 is None:
            return list2
        if list2 is None:
            return list1
        if list1.val <= list2.val:
            list1.next = self.mergeTwoLists(list1.next, list2)   # list1's head goes first
            return list1
        list2.next = self.mergeTwoLists(list1, list2.next)       # list2's head goes first
        return list2
Time O(n + m)Space O(n + m)

One call per placed node; the call stack is as deep as the merged list is long.

When to use: Short and elegant for small inputs; prefer the loop when lists can be long.

Keep a dummy node in front of the answer and a tail pointer to the last node placed so far. While both lists have nodes, attach the smaller front to tail, advance that list, and move tail forward. When one list is empty, attach the other in one step: it is already sorted and nothing in it is smaller than what was placed.

Every node is attached exactly once and only two pointers are used, so it is linear time and O(1) extra memory. This dummy + tail loop is the template for building any list in place.

Dry run

  1. list1 = [1, 2, 4], list2 = [1, 3, 4], merged: dummy
  2. 1 vs 1 → take list1's 1 → dummy → 1
  3. 2 vs 1 → take list2's 1 → dummy → 1 → 1
  4. 2 vs 3 → take 2; 4 vs 3 → take 3; 4 vs 4 → take list1's 4
  5. list1 is empty → attach list2's remaining [4] → return dummy.next = [1, 1, 2, 3, 4, 4]

Python

class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode()                   # placeholder before the real head
        tail = dummy                         # last node of the merged list so far
        while list1 and list2:
            if list1.val <= list2.val:       # <= keeps equal values in order
                tail.next = list1
                list1 = list1.next
            else:
                tail.next = list2
                list2 = list2.next
            tail = tail.next
        tail.next = list1 or list2           # attach whatever is left
        return dummy.next
Time O(n + m)Space O(1)

Each node is attached once; only dummy and tail are extra.

When to use: The interview answer, and the inner loop of Merge k Sorted Lists and merge sort on lists.

Common mistakes

  • Forgetting to attach the leftover after the loop (tail.next = list1 or list2): you drop the largest values.
  • Not moving tail forward after attaching a node: the next attachment overwrites it.
  • Returning dummy instead of dummy.next: the answer gains a fake 0 at the front.
  • Ties: <= takes from list1 first, < from list2. Both give a sorted list; <= also keeps equal values in their original order (a stable merge).
  • The recursive version uses one call per node; that is fine for 50 + 50 nodes, but long lists exceed Python's 1000-frame recursion limit.

Python notes

  • dummy = tail = ListNode() creates one node with two names; moving tail later does not move dummy.
  • tail.next = list1 or list2 attaches whichever list is non-empty: or returns its first truthy operand (a node), or the second one when the first is None.
  • Tests write lists as Python lists, and a returned None means the empty list.
