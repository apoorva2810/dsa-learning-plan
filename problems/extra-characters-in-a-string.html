Extra Characters in a String Medium 250

LeetCode #2707 ↗
Status

Cut a string into dictionary words, leaving as few characters as possible unused.

Problem

You are given a string s and a list of words dictionary. You may keep some non-overlapping pieces of s, where each kept piece is a contiguous slice of s that equals a word of the dictionary. The characters of s that are not inside any kept piece are extra.

Return the smallest possible number of extra characters.

A word may be kept several times if it occurs at several places in s, and not every word has to be used. The words in the dictionary are distinct.

Examples

Example 1
Input: s = "xhelloyworld", dictionary = ["hello", "world"]
Output: 2
Keep "hello" and "world". The "x" before them and the "y" between them are extra.
Example 2
Input: s = "abcd", dictionary = ["ab", "bcd"]
Output: 1
Keeping "ab" first leaves "c" and "d" extra (2). Skipping "a" and keeping "bcd" leaves only "a" extra (1).
Example 3
Input: s = "zzz", dictionary = ["a", "b"]
Output: 3
No word occurs in "zzz", so every character is extra.

Constraints

  • 1 <= len(s) <= 50
  • 1 <= len(dictionary) <= 50
  • 1 <= len(dictionary[i]) <= 50
  • s and every word consist of lowercase English letters
  • the words in dictionary are distinct

Think first try before reading the solution

Scanning left to right and always keeping the first word that matches is not safe: try s = "abcd" with ["ab", "bcd"]. You have to compare choices.
Look at the last character of a prefix s[:i]. In the best cut of that prefix it is either an extra character, or the last letter of a kept word s[j:i]. Let dp[i] be the fewest extra characters in s[:i].
dp[i] = min(dp[i - 1] + 1, dp[j]) over every j where s[j:i] is a dictionary word, with dp[0] = 0. The answer is dp[n].

Key idea

Greedy matching does not work. In "abcd" with the words "ab" and "bcd", the first word that matches, "ab", leaves "c" and "d" extra (2), while skipping "a" and keeping "bcd" leaves one. Every choice changes what the rest of the string can do, so the choices have to be compared.

Look at the end of a prefix. In the best cut of s[:i], the last character is either extra or the last letter of a kept word s[j:i]. If it is extra, the rest is the best cut of s[:i - 1] plus 1. If it ends the word s[j:i], the rest is the best cut of s[:j], and the word itself adds nothing. With dp[i] = the fewest extra characters in the first i characters:

dp[i] = min(dp[i - 1] + 1, dp[j] for every j with s[j:i] in the dictionary), and dp[0] = 0.

Each cell reads only cells to its left, so one left-to-right pass fills the table and dp[n] is the answer. This is the Word Break DP with one addition: a character may be skipped for a cost of 1. A set makes each word test O(1) on average, and only cut points within the longest word's length need checking. A trie (prefix tree) of the dictionary can replace the slicing: walk it forward from each start and every word end it meets updates a later cell.

Approaches from the obvious one to the one you want in an interview

Scan the string from the left. Standing at position i, there are two kinds of move:

  • skip: s[i] is an extra character. That costs 1, and we continue at i + 1;
  • use a word: if a dictionary word starts at i, keep it for free and continue right after its last letter.

solve(i) returns the fewest extra characters in the suffix s[i:] by trying every move and keeping the smallest total. solve(len(s)) is 0, because nothing is left.

It is correct, but it repeats work. Position i can be reached by many different mixes of skips and words, and every route explores everything after i again. For a run of a's with the words "a" and "aa", the number of calls grows by a factor of about 2.4 for every extra letter. Remembering the answer per position is exactly the next approach.

Dry run

  1. s = "abcd", words {"ab", "bcd"}: solve(0) tries skipping "a" → 1 + solve(1), and the word "ab" → solve(2)
  2. solve(1): skip "b" → 1 + solve(2), or the word "bcd" → solve(4) = 0. The best is 0
  3. solve(2): no word starts at "c"; skip "c" and then "d" → 2
  4. back at solve(0): the skip route costs 1 + 0 = 1, the word route costs 2 → answer 1

Python

class Solution:
    def minExtraChar(self, s: str, dictionary: List[str]) -> int:
        n = len(s)

        def solve(i: int) -> int:
            """Fewest extra characters in the suffix s[i:]."""
            if i == n:                                   # nothing left
                return 0
            best = 1 + solve(i + 1)                      # option 1: s[i] is an extra character
            for word in dictionary:                      # option 2: a word starts at i
                if s.startswith(word, i):
                    best = min(best, solve(i + len(word)))
            return best

        return solve(0)
Time ExponentialSpace O(n)

Every route of skips and word choices is explored, and the same suffix is solved again on each route. The call stack is at most n deep.

When to use: Only to see the two choices at each position and why the repetition has to go.

Build the answer for every prefix instead. Let dp[i] be the fewest extra characters in s[:i], with dp[0] = 0. The last character of the prefix is either extra or the end of a word:

  • extra: dp[i] = dp[i - 1] + 1;
  • the prefix ends with the word s[j:i]: dp[i] = dp[j], because the word itself adds nothing.

dp[i] is the smaller of these over every j where s[j:i] is a dictionary word, and dp[n] is the answer. Each cell uses only cells to its left, so one left-to-right pass is enough. The words go into a set for O(1) average lookups, and only cut points j >= i - longest are tried, since a longer piece cannot be a word. That is O(n · L) pieces, each hashed in O(L): O(n · L²) in total, where L is the longest word.

Dry run

  1. s = "abcd", words {"ab", "bcd"}, longest word 3: dp[0] = 0
  2. dp[1]: no word ends here; "a" is extra → dp[0] + 1 = 1
  3. dp[2]: extra → dp[1] + 1 = 2; the word "ab" = s[0:2] → dp[0] = 0, so dp[2] = 0
  4. dp[3]: no word ends here ("abc", "bc", "c"); "c" is extra → dp[2] + 1 = 1
  5. dp[4]: extra → dp[3] + 1 = 2; the word "bcd" = s[1:4] → dp[1] = 1, so dp[4] = 1
  6. dp[4] = 1 is the answer: skip the first letter and keep "bcd"

Python

class Solution:
    def minExtraChar(self, s: str, dictionary: List[str]) -> int:
        words = set(dictionary)                       # O(1) average membership tests
        longest = max(len(w) for w in words)          # a longer piece cannot be a word
        n = len(s)
        dp = [0] * (n + 1)                            # dp[i] = fewest extras in s[:i]; dp[0] = 0
        for i in range(1, n + 1):
            dp[i] = dp[i - 1] + 1                     # option 1: s[i - 1] is an extra character
            for j in range(max(0, i - longest), i):   # option 2: the prefix ends with the word s[j:i]
                if s[j:i] in words:
                    dp[i] = min(dp[i], dp[j])         # the word itself is free
        return dp[n]
Time O(n · L²)Space O(n + W)

n cells × at most L cut points × O(L) to hash a piece. L = longest word, W = total letters in the dictionary (held in the set).

When to use: The standard answer: a short table fill that is easy to explain and to get right.

Watch it run

Slicing and hashing a piece costs O(L), and the set version does it for up to L cut points at each of n positions. A trie of the dictionary removes the slicing. Run the same DP forward:

  1. For each start, dp[start] is already final (every update comes from the left). Relax dp[start + 1] with dp[start] + 1: that is the skip option.
  2. Walk the trie along s[start:], one letter at a time. Whenever the walk is on a node that ends a word, at index end, relax dp[end + 1] with dp[start].
  3. Stop the walk as soon as the trie has no edge for the next letter.

The walk reads at most L letters per start, so the DP costs O(n · L) after building the trie in O(W), where W is the total number of letters in the dictionary. It is the same recurrence, written as "push forward" instead of "pull from the left". For a 50-character string the difference is tiny; with a huge dictionary and long words the trie also avoids creating substrings.

Dry run

  1. s = "abcd", words {"ab", "bcd"}: trie holds a→b (word) and b→c→d (word); dp = [0, ∞, ∞, ∞, ∞]
  2. start 0: skip → dp[1] = 1; walk a, b: word "ab" ends at index 1 → dp[2] = dp[0] = 0; next letter c: no edge, stop
  3. start 1: skip → dp[2] = min(0, 2) = 0; walk b, c, d: word "bcd" ends at index 3 → dp[4] = dp[1] = 1
  4. start 2: skip → dp[3] = 1; letter c: no edge from the root, stop
  5. start 3: skip → dp[4] = min(1, 2) = 1 → answer 1

Python

class TrieNode:
    def __init__(self):
        self.children = {}                            # letter -> TrieNode
        self.is_end = False                           # True if a word ends exactly here


class Solution:
    def minExtraChar(self, s: str, dictionary: List[str]) -> int:
        root = TrieNode()
        for word in dictionary:                       # build the trie once
            node = root
            for ch in word:
                if ch not in node.children:
                    node.children[ch] = TrieNode()
                node = node.children[ch]
            node.is_end = True

        n = len(s)
        dp = [float("inf")] * (n + 1)                 # dp[i] = fewest extras in s[:i]
        dp[0] = 0
        for start in range(n):                        # dp[start] is final: updates only come from the left
            dp[start + 1] = min(dp[start + 1], dp[start] + 1)    # s[start] is an extra character
            node = root
            for end in range(start, n):               # walk the trie along s[start:]
                node = node.children.get(s[end])
                if node is None:                      # no word continues this way: stop early
                    break
                if node.is_end:                       # s[start:end + 1] is a word
                    dp[end + 1] = min(dp[end + 1], dp[start])
        return dp[n]
Time O(W + n · L)Space O(W + n)

Building the trie reads every dictionary letter once (W). Each start walks at most L trie edges. The trie holds up to W nodes.

When to use: When the dictionary is large or the words are long: it avoids creating and hashing substrings.

Common mistakes

  • Keeping the first (or the longest) word that matches while scanning left to right. "abcd" with ["ab", "bcd"] gives 2 extras that way; the best answer is 1.
  • Forgetting the skip option. If dp[i] looks only at words, a position where no word ends has no value. The option dp[i - 1] + 1 keeps every cell defined.
  • Mixing up the slice indices. s[j:i] ends at index i - 1, and dp[j] is the answer for the part before the piece, s[:j].
  • Overwriting instead of taking the smaller value. Write dp[i] = min(dp[i], dp[j]); a plain dp[i] = dp[j] can replace a better value found from a different j.
  • Keeping the words in a list. s[j:i] in words then scans the whole list on every test; a set answers in O(1) on average.
  • Trie version: stopping the walk at the first word end. A longer word can share the prefix (ab and abc), so keep walking until the trie has no edge for the next letter.

Python notes

  • words = set(dictionary) turns each membership test into an average O(1) hash lookup (plus O(L) to hash the piece).
  • s[j:i] builds a new string of length i - j; s.startswith(word, i) compares in place when you loop over words instead of cut points.
  • max(len(w) for w in words) is the longest word; the cut points range(max(0, i - longest), i) never produce a piece longer than that.
  • float("inf") is a handy "not reached yet" value for a minimum table; min(inf, 3) returns the int 3.
  • @cache on solve(i) turns the plain recursion into the top-down version of this DP; the recursion is at most len(s) deep.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Word Break LC 139 — the same prefix DP with a yes/no answer: dp[i] is True when s[:i] can be cut exactly into words. Here the skip option turns it into a minimum.
  • Word Break II LC 140 — return every possible sentence instead of one number: memoise on the suffix and build the lists of splits.
  • Implement Trie (Prefix Tree) LC 208 — the data structure behind the alternative approach: one walk from a start position finds every dictionary word that begins there.
  • Palindrome Partitioning II LC 132 — another prefix DP that minimises over the last piece: dp[i] = min(dp[j] + 1) over every palindrome s[j:i] counts the fewest pieces, and the number of cuts is one less.
  • Decode Ways LC 91 — the 'last piece' DP again, with pieces of one or two digits, counting ways instead of minimising.
  • Which characters are extra? — remember for each i which option won (skip, or the word starting at j), then walk back from dp[n] to list the words used and the extra characters.
  • What if every word has a cost? — replace dp[j] by dp[j] + cost(word) in the word option; the shape of the DP does not change.
