Single Threaded CPU Medium 250

LeetCode #1834 ↗
Status

Tasks arrive over time; a CPU that runs one task at a time always picks the shortest available one. Return the order it runs them in.

Problem

You are given tasks, where tasks[i] = [arrival, work]: task i becomes available at time arrival and needs work units of CPU time. The CPU is single-threaded: it runs one task at a time and never interrupts a task once it has started.

Whenever the CPU is idle:

  • if at least one available task is waiting, it starts the one with the smallest work; on a tie, the one with the smallest index;
  • if nothing has arrived yet, it stays idle until the next task arrives.

Return the order of the task indices in which the CPU runs them.

Examples

Example 1
Input: tasks = [[1, 2], [2, 4], [3, 2], [4, 1]]
Output: [0, 2, 3, 1]
t = 1: only task 0 is available; it runs until t = 3. Then tasks 1 and 2 are waiting; task 2 is shorter (2 vs 4) and runs until t = 5. Then task 3 (work 1) beats task 1 (work 4). Task 1 runs last.
Example 2
Input: tasks = [[7, 10], [7, 12], [7, 5], [7, 4], [7, 2]]
Output: [4, 3, 2, 0, 1]
Everything arrives at t = 7, so the CPU idles until then and runs the tasks from shortest to longest.
Example 3
Input: tasks = [[5, 3], [1, 3], [1, 3]]
Output: [1, 2, 0]
Tasks 1 and 2 arrive at t = 1 with the same work, so the smaller index goes first. Task 0 only arrives at t = 5 and runs last.

Constraints

  • 1 <= len(tasks) <= 10^5
  • 1 <= arrival, work <= 10^9

Think first try before reading the solution

The CPU only makes a choice when it becomes idle. At that moment, which tasks are candidates? Exactly those with arrival <= current time that have not run yet.
Two different orders are mixed here: tasks arrive in order of arrival, but the CPU picks by work. Sort the indices by arrival once, and sweep a pointer over that list as the clock moves forward.
Keep the tasks that have arrived in a min-heap of (work, index): the root is always the right pick, ties included. If the heap is empty, do not tick the clock one unit at a time; jump straight to the next arrival.

Key idea

Picture a ready pool: every task that has arrived but not run yet. The CPU always takes the pool's shortest task, so the pool needs two things to be cheap: add a task (when it arrives) and remove the shortest (when the CPU is free). That is a min-heap keyed by (work, index); Python compares tuples item by item, so the index breaks ties for free.

Arrivals happen in a fixed order, so sort the task indices by arrival once and keep a pointer into that sorted list. Each time the CPU becomes free at time t, move every task with arrival <= t from the sorted list into the heap, then pop the root and advance the clock by its work. Every task enters the heap once and leaves once.

When the heap is empty, nothing can run until the next arrival. Instead of counting the idle time unit by unit (times go up to 10⁹), set the clock to that next arrival directly.

Approaches from the obvious one to the one you want in an interview

Follow the rules literally. Keep a done flag per task and a clock. Each time the CPU is free, scan every task: among the unfinished ones that have arrived, remember the one with the smallest (work, index); among the ones that have not arrived, remember the earliest arrival. Run the best one (the clock jumps forward by its work), or, if none is available, move the clock to that earliest arrival.

The choices are right, so the answer is right. The cost is the scan: n decisions, each looking at all n tasks, so O(n²). With 10⁵ tasks that is 10¹⁰ comparisons.

Dry run

  1. [[1, 2], [2, 4], [3, 2], [4, 1]], clock 0: nothing has arrived → jump to t = 1
  2. t = 1: only task 0 is available → run it, clock becomes 3
  3. t = 3: tasks 1 (work 4) and 2 (work 2) are available → run task 2, clock 5
  4. t = 5: tasks 1 (work 4) and 3 (work 1) → run task 3, clock 6
  5. t = 6: only task 1 is left → run it → order [0, 2, 3, 1]

Python

class Solution:
    def getOrder(self, tasks: List[List[int]]) -> List[int]:
        n = len(tasks)
        done = [False] * n
        order = []
        time = 0
        while len(order) < n:
            best = -1                         # available task with the smallest (work, index)
            next_arrival = math.inf           # earliest arrival among tasks not yet available
            for i, (arrival, work) in enumerate(tasks):
                if done[i]:
                    continue
                if arrival <= time:
                    if best == -1 or (work, i) < (tasks[best][1], best):
                        best = i
                else:
                    next_arrival = min(next_arrival, arrival)
            if best == -1:                    # nothing available: idle until the next arrival
                time = next_arrival
                continue
            order.append(best)
            done[best] = True
            time += tasks[best][1]            # the task runs to completion
        return order
Time O(n²)Space O(n)

n decisions, each scanning all n tasks; the idle jump adds at most one extra scan per task.

When to use: Only to check your understanding of the rules on a small input.

Separate the two orders:

  1. Arrival order is fixed: sort the indices by arrival once and keep a pointer nxt into that list.
  2. Pick order changes as tasks arrive: keep the arrived-but-unfinished tasks in a min-heap of (work, index).

Loop until every task has run. If the heap is empty, jump the clock to the next arrival. Move every task with arrival <= time from the sorted list into the heap (the pointer only moves forward). Pop the root, append its index to the answer and advance the clock by its work.

Each task is pushed and popped exactly once, so the heap work is O(n log n), the same as the sort.

Dry run

  1. [[1, 2], [2, 4], [3, 2], [4, 1]] → by arrival [0, 1, 2, 3], heap empty, t = 0
  2. heap empty → jump to t = 1; push (2, 0); pop task 0 → runs until t = 3
  3. t = 3: push (4, 1) and (2, 2); pop (2, 2) → task 2 runs until t = 5
  4. t = 5: push (1, 3); pop (1, 3) → task 3 runs until t = 6
  5. t = 6: nothing new; pop (4, 1) → task 1 runs until t = 10 → [0, 2, 3, 1]

Python

class Solution:
    def getOrder(self, tasks: List[List[int]]) -> List[int]:
        n = len(tasks)
        by_arrival = sorted(range(n), key=lambda i: tasks[i][0])   # indices, earliest arrival first
        ready = []                            # min-heap of (work, index): tasks that have arrived
        order = []
        time = 0
        nxt = 0                               # next position in by_arrival to move into the heap
        while len(order) < n:
            if not ready:                     # idle: jump to the next arrival (never move backwards)
                time = max(time, tasks[by_arrival[nxt]][0])
            while nxt < n and tasks[by_arrival[nxt]][0] <= time:   # everything that has arrived is ready
                i = by_arrival[nxt]
                heapq.heappush(ready, (tasks[i][1], i))
                nxt += 1
            work, i = heapq.heappop(ready)    # shortest work; ties go to the smaller index
            order.append(i)
            time += work                      # the task runs to completion
        return order
Time O(n log n)Space O(n)

One sort, then every task is pushed and popped once from a heap of at most n entries.

When to use: The interview answer. The same shape (sorted arrivals + a heap of what is ready) solves most scheduling problems.

Common mistakes

  • Sorting tasks itself and losing the original indices: the answer is made of indices, so sort a list of indices (sorted(range(n), key=...)) or attach the index to each task before sorting.
  • Ticking the clock one unit at a time while idle. Arrivals can be 10⁹ apart; jump the clock to the next arrival instead.
  • Pushing only one arrived task per loop pass. After a long task finishes, several tasks may have arrived; all of them must be in the heap before the next pop, or the CPU may pick a longer task while a shorter one has already arrived.
  • Using arrival < time instead of arrival <= time: a task that arrives exactly when the CPU frees up is available. [[1, 3], [4, 1], [2, 5]] must give [0, 1, 2], not [0, 2, 1].
  • Heap entries of (index, work) or plain work: the tie rule needs (work, index) in that order.
  • Running tasks in arrival order (a plain queue) instead of shortest first: example 1 would come out as [0, 1, 2, 3].

Python notes

  • sorted(range(n), key=lambda i: tasks[i][0]) sorts the indices by arrival and keeps the original index with each task.
  • Tuples compare item by item, so a heap of (work, index) pops the shortest work and, on a tie, the smallest index. No extra code.
  • max(time, next_arrival) is the idle jump: it only moves the clock forward, never back.
  • Python ints have no overflow, so times up to 2 · 10⁹ need no special care.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Task Scheduler LC 621 — the constraint is a cooldown between equal letters instead of arrival times: a max-heap by remaining count plus a cooling queue.
  • Meeting Rooms III LC 2402 — several CPUs (rooms) instead of one: a min-heap of free rooms and a min-heap of busy rooms keyed by finish time.
  • Process Tasks Using Servers LC 1882 — k servers with weights and tasks arriving one per second: two heaps, free servers by weight and busy servers by finish time.
  • Course Schedule III LC 630 — pick which courses fit before their deadlines: sort by deadline and keep a max-heap of durations to undo the longest one.
  • What if the CPU may interrupt a task when a shorter one arrives? — shortest remaining time first: on every arrival compare with the running task's remaining work and push the loser back into the heap.
  • Return each task's finish time or the total waiting time — the same loop already knows the clock: record time + work when a task is popped, or time - arrival as its wait.
