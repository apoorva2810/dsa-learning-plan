Design Twitter Medium

LeetCode #355 ↗
Status

Users post, follow and unfollow; a news feed shows the 10 newest tweets from you and the people you follow.

Problem

Design a tiny version of Twitter. Users post tweets, follow and unfollow each other, and read a news feed: the 10 most recent tweet ids posted by the user or by anyone they follow, newest first.

Implement the class Twitter:

  • Twitter() starts with no users and no tweets.
  • postTweet(userId, tweetId): userId posts a new tweet with id tweetId. Every call uses a different id, and each call is more recent than all earlier ones.
  • getNewsFeed(userId): return up to 10 tweet ids posted by userId or by users userId follows, newest first.
  • follow(followerId, followeeId): followerId starts following followeeId.
  • unfollow(followerId, followeeId): followerId stops following followeeId (nothing happens if they were not following).

Tweet ids say nothing about time: tweet 5 may be newer than tweet 9.

Examples

Example 1
Input: ["Twitter","postTweet","getNewsFeed","follow","postTweet","getNewsFeed","unfollow","getNewsFeed"] [[],[1,5],[1],[1,2],[2,6],[1],[1,2],[1]]
Output: [null, null, [5], null, null, [6, 5], null, [5]]
User 1 posts tweet 5 and sees [5]. After following user 2, who posts tweet 6, user 1 sees [6, 5] (newest first). After unfollowing user 2, tweet 6 disappears from the feed again.
Example 2
Input: ["Twitter","postTweet","postTweet","follow","getNewsFeed"] [[],[1,9],[2,3],[1,2],[1]]
Output: [null, null, null, null, [3, 9]]
Tweet 3 was posted after tweet 9, so it comes first even though its id is smaller.

Constraints

  • 1 <= userId, followerId, followeeId <= 500
  • 0 <= tweetId <= 10^4, and all tweet ids are different
  • at most 3 * 10^4 calls in total
  • follow / unfollow are never called with followerId == followeeId

Key idea

Keep three things: a global clock that stamps each tweet, a list of tweets per user (appending keeps it in time order for free), and a set of followees per user (O(1) follow and unfollow).

A news feed asks for the 10 newest items across several lists that are each sorted already. That is the k-way merge from Merge k Sorted Lists, stopped early. Put the newest tweet of every relevant user (the user and each followee) into a max-heap keyed by time. The root is the newest tweet of the whole feed: pop it. Only the user it came from can supply the next candidate, so push that user's next-older tweet. After 10 pops, or when the heap runs dry, the feed is done.

With F sources this costs O(F) to build the heap plus 10 pops and pushes of O(log F), however many tweets those users have ever posted.

Approaches from the obvious one to the one you want in an interview

Store every tweet ever posted in one list, oldest first, as (userId, tweetId). To build a feed, walk that list backwards (newest first) and keep each tweet whose author is the user or someone they follow, stopping at 10.

Posting, following and unfollowing are O(1), and the feed is correct because the global list is time order. The cost is the scan: if the user follows quiet accounts, getNewsFeed may walk past every tweet anyone ever wrote, O(T) for T tweets in the whole system.

Dry run

  1. timeline [(1, 5), (2, 6)], user 1 follows 2
  2. getNewsFeed(1): (2, 6) → author 2 is followed → keep; (1, 5) → own tweet → keep → [6, 5]
  3. after unfollow(1, 2): (2, 6) is skipped → [5]

Python

class Twitter:
    def __init__(self):
        self.timeline = []                       # every tweet ever, oldest first: (userId, tweetId)
        self.following = defaultdict(set)        # user -> the users they follow

    def postTweet(self, userId: int, tweetId: int) -> None:
        self.timeline.append((userId, tweetId))

    def getNewsFeed(self, userId: int) -> List[int]:
        feed = []
        for author, tweet in reversed(self.timeline):     # newest first
            if author == userId or author in self.following[userId]:
                feed.append(tweet)
                if len(feed) == 10:
                    break
        return feed

    def follow(self, followerId: int, followeeId: int) -> None:
        if followerId != followeeId:
            self.following[followerId].add(followeeId)

    def unfollow(self, followerId: int, followeeId: int) -> None:
        self.following[followerId].discard(followeeId)    # no error if they were not following
Time O(T) per feed, O(1) otherwiseSpace O(T + follows)

T = tweets in the whole system; a feed may scan all of them when the user's sources are quiet.

When to use: A fine first version; it shows why per-user lists help.

Give each user their own list of (time, tweetId) and stamp tweets with a global clock. No source can contribute more than its 10 newest tweets to a feed, so collect tweets[source][-10:] from the user and each followee, sort those candidates newest first, and keep 10.

The feed no longer depends on how many tweets exist overall: with F sources it sorts at most 10F candidates, O(F log F). It still sorts about ten times more candidates than it returns.

Python

class Twitter:
    def __init__(self):
        self.time = 0                            # global clock: bigger = newer
        self.tweets = defaultdict(list)          # user -> [(time, tweetId), ...], oldest first
        self.following = defaultdict(set)

    def postTweet(self, userId: int, tweetId: int) -> None:
        self.tweets[userId].append((self.time, tweetId))
        self.time += 1

    def getNewsFeed(self, userId: int) -> List[int]:
        candidates = []
        for user in self.following[userId] | {userId}:
            candidates.extend(self.tweets[user][-10:])    # nobody contributes more than 10
        candidates.sort(reverse=True)                     # newest (largest time) first
        return [tweet for _, tweet in candidates[:10]]

    def follow(self, followerId: int, followeeId: int) -> None:
        if followerId != followeeId:
            self.following[followerId].add(followeeId)

    def unfollow(self, followerId: int, followeeId: int) -> None:
        self.following[followerId].discard(followeeId)
Time O(F log F) per feed, O(1) otherwiseSpace O(T + follows)

F = number of sources (followees + 1); at most 10F candidates are sorted.

When to use: Simple and fast enough here; the heap version is what the problem is testing.

Same per-user lists, but build the feed with a k-way merge that stops after 10 items:

  1. For every source (the user and each followee), put its newest tweet in a max-heap keyed by time (store -time), together with the source and the tweet's index in that source's list.
  2. Pop the root: it is the newest tweet among all candidates, so it goes into the feed.
  3. Push the same source's next-older tweet (index − 1), if it has one. No other source's candidate changed.
  4. Repeat until the feed has 10 tweets or the heap is empty.

Building the heap is O(F) with heapify; each of the at most 10 pops and pushes is O(log F).

Dry run

  1. user 1: [(t0, 101), (t4, 102)], user 2: [(t1, 201), (t3, 202)], user 3: [(t2, 301)]; 1 follows 2 and 3
  2. seed the heap with 102@t4, 202@t3, 301@t2 → pop 102, push 101@t0
  3. pop 202, push 201@t1 → pop 301 (user 3 has nothing older)
  4. pop 201 → pop 101 → heap empty → feed [102, 202, 301, 201, 101]

Python

class Twitter:
    def __init__(self):
        self.time = 0                            # global clock: bigger = newer
        self.tweets = defaultdict(list)          # user -> [(time, tweetId), ...], oldest first
        self.following = defaultdict(set)        # user -> the users they follow

    def postTweet(self, userId: int, tweetId: int) -> None:
        self.tweets[userId].append((self.time, tweetId))
        self.time += 1

    def getNewsFeed(self, userId: int) -> List[int]:
        heap = []                                # max-heap via negated time: (-time, tweetId, user, index)
        for user in self.following[userId] | {userId}:    # a set, so nobody is merged twice
            tweets = self.tweets.get(user)
            if tweets:
                posted, tweet = tweets[-1]                # that user's newest tweet
                heap.append((-posted, tweet, user, len(tweets) - 1))
        heapq.heapify(heap)
        feed = []
        while heap and len(feed) < 10:
            _, tweet, user, i = heapq.heappop(heap)       # newest tweet still in the race
            feed.append(tweet)
            if i > 0:                                     # the same user's next-older tweet replaces it
                posted, older = self.tweets[user][i - 1]
                heapq.heappush(heap, (-posted, older, user, i - 1))
        return feed

    def follow(self, followerId: int, followeeId: int) -> None:
        if followerId != followeeId:
            self.following[followerId].add(followeeId)

    def unfollow(self, followerId: int, followeeId: int) -> None:
        self.following[followerId].discard(followeeId)    # no error if they were not following
Time O(F + 10 log F) per feed, O(1) otherwiseSpace O(T + follows)

F = sources; heapify is O(F) and at most 10 pops/pushes of O(log F) follow. Memory holds every tweet and follow.

When to use: The intended answer: it touches only the tweets that end up in the feed (plus one candidate per source).

Common mistakes

  • Ordering the feed by tweet id instead of by time. Ids are arbitrary; stamp each tweet with a counter.
  • Leaving the user out of their own feed: the sources are the followees plus the user themself.
  • Adding the user to their own followee set (or a duplicate follow) and then merging the same list twice, which repeats tweets. Build the sources as a set: following[user] | {user}.
  • set.remove on unfollow raises KeyError when the user was not following; discard does nothing instead.
  • Pushing every tweet of every followee into the heap: correct, but it costs O(total tweets) per feed. Seed one tweet per source and refill from the same source only after a pop.

Python notes

  • defaultdict(list) and defaultdict(set) remove all "does this user exist yet?" checks.
  • self.following[userId] | {userId} builds a new set, so the user's own followee set is not modified.
  • Heap entries (-time, tweetId, user, index) compare by -time first; times are unique, so the later fields never decide anything, but they carry what the refill step needs.
  • heapq.heapify on the F seed entries is O(F), cheaper than F separate pushes.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Merge k Sorted Lists LC 23 — the same heap merge run to the end, with list nodes instead of per-user tweet lists.
  • What if the feed needs a 'load more' button? — remember the time of the last tweet shown; the next page seeds the heap with each source's newest tweet older than that (a binary search in each sorted list) and pops 10 more.
  • Find K Pairs with Smallest Sums LC 373 — a heap merge over an implicit grid of pairs: pop the smallest pair, push its neighbours.
  • Design a Leaderboard LC 1244 — another design question where 'top K' is read often: a hash map of scores plus heapq.nlargest for the query.
  • What if a celebrity has millions of followers? — real feeds precompute (fan-out on write): each post is pushed into followers' stored feeds, except for very popular accounts, which are merged at read time like here.
