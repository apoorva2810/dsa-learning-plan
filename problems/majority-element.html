Majority Element Easy 250

LeetCode #169 ↗
Status

Find the value that takes up more than half of the list.

Problem

You are given a list of integers nums with n values. Return the majority element: the value that appears more than n // 2 times (n // 2 is n divided by 2, rounded down).

The list always contains a majority element, so you never have to handle the case where there is none.

Examples

Example 1
Input: nums = [4, 1, 4, 2, 4]
Output: 4
The list has 5 values and 4 appears 3 times. 3 is more than 5 // 2 = 2.
Example 2
Input: nums = [7, 7, 5, 7, 5, 5, 5]
Output: 5
5 appears 4 times out of 7, more than 7 // 2 = 3, even though 7 leads for the first four values.
Example 3
Input: nums = [6, 6, 1, 1, 1, 6, 6, 1, 1]
Output: 1
1 appears 5 times and 6 appears 4 times. 5 is more than 9 // 2 = 4, but only just.

Constraints

  • 1 <= len(nums) <= 5 * 10^4
  • -10^9 <= nums[i] <= 10^9
  • a majority element always exists

Think first try before reading the solution

A value that appears more than half the time has more copies than all the other values added together. How could you find out how many copies of each value there are?
Sort the list and look at the value in the middle position. Why does the majority element have to be there?
You can also cancel values against each other: pair each copy of one value with a different value and cross both out. The majority element has more copies than everything else, so it cannot be fully crossed out. Track one candidate and one counter, and do the crossing-out as you walk the list.

Key idea

The straightforward way is to count: tally every value in a dictionary and return the one whose tally passes n // 2. That is O(n) time but O(n) memory.

The guarantee is much stronger than "the most common value". The answer takes more than half of all positions, so it has more copies than every other value put together. Imagine pairing each copy of the majority value with some other value and crossing both out. Some copies of the majority are always left over, and nothing else can be left over with them, so the survivors are all the majority element.

Boyer-Moore voting does the crossing-out on the fly with only two variables. Keep a candidate and a count. A value equal to the candidate adds a vote; a different value cancels one vote; when the count is 0, nobody leads and the next value becomes the candidate. Whenever the count drops back to 0, the part of the list read so far can be split into pairs of different values, and each such pair holds at most one copy of the majority. Throwing that part away cannot cost the majority its place, so it is still a majority of the rest. The candidate can change several times along the way, but at the end it is the majority element.

Approaches from the obvious one to the one you want in an interview

For every element x, scan the whole list and count how many copies of x there are. The first x whose count is more than n // 2 is the answer. It needs no extra memory, but it re-counts a value every time that value shows up again, and each count is a full scan: about n² comparisons, which is 2.5 billion for n = 50 000.

Dry run

  1. nums = [4, 1, 4, 2, 4], n // 2 = 2
  2. x = 4 (index 0): a scan finds 3 copies, and 3 > 2 → return 4
  3. With [7, 7, 5, 7, 5, 5, 5] the scan for 7 finds 3 (not above 3), the scan for the second 7 repeats that work, and only the scan for 5 finds 4.

Python

class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        half = len(nums) // 2
        for x in nums:
            count = 0
            for y in nums:               # a full scan for copies of x
                if y == x:
                    count += 1
            if count > half:             # strictly more than half
                return x
        # a majority element is guaranteed, so one of the returns above always fires
Time O(n²)Space O(1)

n values, each counted with a scan of n values; only two counters are stored.

When to use: Only as a warm-up; it shows the repeated work that the next approaches remove.

Watch it run

Count the copies of every value in a dictionary while walking the list once. The moment any value's count passes n // 2, return it; there is no need to finish the list. Each element costs one dictionary update, so the time is O(n).

The price is memory. Before the majority element reaches its count, the dictionary can hold up to about n / 2 different values, so the space is O(n). Voting, below, gets the same answer with two variables.

Dry run

  1. nums = [4, 1, 4, 2, 4], half = 2, counts = {}
  2. 4 → {4: 1}; 1 → {4: 1, 1: 1}; 4 → {4: 2, 1: 1}
  3. 2 → {4: 2, 1: 1, 2: 1}; 4 → {4: 3, ...}: 3 > 2 → return 4

Python

class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        counts = {}                          # value -> copies seen so far
        half = len(nums) // 2
        for x in nums:
            counts[x] = counts.get(x, 0) + 1
            if counts[x] > half:             # strictly more than half of the list
                return x
        # a majority element is guaranteed, so the return above always fires
Time O(n)Space O(n)

One pass with a dictionary update per element; up to about n / 2 distinct keys.

When to use: The safe, obvious answer. Also the one to use if you must double-check a candidate.

Watch it run

Keep a candidate and a count, both starting at "nobody". For each value x:

  • if count is 0, nobody leads: x becomes the candidate;
  • then, if x equals the candidate add 1 to count, otherwise subtract 1.

A different value cancels one vote of the candidate, so a pair of different values is crossed out. Whenever the count returns to 0, everything read so far splits into pairs of different values, and each pair holds at most one copy of the majority element; dropping that part leaves the majority still in the lead. The majority has more than half the copies, so it can never be cancelled completely, and at the end the candidate is the majority element.

One pass, two variables. It relies on the guarantee: with no majority, the candidate could be any value.

Dry run

  1. nums = [7, 7, 5, 7, 5, 5, 5]: candidate = none, count = 0
  2. 7: count is 0 → candidate 7, count 1; 7: count 2
  3. 5: differs → count 1; 7: count 2; 5: count 1
  4. 5: differs → count 0
  5. 5: count is 0 → candidate 5, count 1 → return 5

Python

class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        candidate, count = None, 0
        for x in nums:
            if count == 0:                   # nobody leads: x steps up as the candidate
                candidate = x
            count += 1 if x == candidate else -1   # same value votes for it, a different one cancels a vote
        return candidate                     # the majority element is guaranteed to exist
Time O(n)Space O(1)

One pass; two variables.

When to use: The interview answer. State clearly that it depends on the guarantee that a majority exists.

Common mistakes

  • Treating 'at least half' as 'more than half'. In [1, 1, 2, 2] no value appears more than 2 times. The guarantee here is a strict majority, so compare with > n // 2, not >= n // 2.
  • Trusting Boyer-Moore when a majority might not exist. On [1, 2, 3] it returns 3, a value that appears once. Without the guarantee, add a second pass that counts the candidate and checks count > n // 2.
  • Forgetting that the new candidate also casts its own vote. In the loop, the reset if count == 0: candidate = x must be followed by the count += 1 for x; if you skip it, count stays at 0 and the next value replaces the candidate again.
  • Calling nums.count(x) for every value, as in max(set(nums), key=nums.count). It is one short line but each count scans the whole list, so it is O(n²) when there are many distinct values.
  • Sorting with nums.sort() to read the middle value. It works, but it reorders the caller's list and costs O(n log n), where counting or voting needs only O(n).

Python notes

  • collections.Counter(nums) counts every value in one pass; Counter(nums).most_common(1)[0][0] is the most frequent value.
  • counts.get(x, 0) + 1 reads a count with a default of 0, so a first-time value does not raise KeyError.
  • sorted(nums)[len(nums) // 2] is the middle value of a sorted copy. A value that fills more than half the list must cover the middle position.
  • count += 1 if x == candidate else -1 is a conditional expression: it picks +1 or -1 and adds it, in one line.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Majority Element II LC 229 — values that appear more than n / 3 times: at most two can qualify, so keep two candidates with two counters, then make a second pass to confirm their counts.
  • Top K Frequent Elements LC 347 — not just the top value but the top k: count everything, then pick the k largest counts with a heap or a bucket per frequency.
  • Single Number LC 136 — another cancellation trick: XOR cancels equal pairs, where Boyer-Moore cancels different ones.
  • Online Majority Element In Subarray LC 1157 — many queries, each on a range of the list: store the positions of every value and use binary search to count copies inside a range (a randomised pick or a segment tree finds the candidate).
  • What if a majority might not exist? — run the voting pass to get a candidate, then count its copies in a second pass; only return it if the count is more than n // 2.
  • What if the numbers arrive as a stream? — voting keeps just two variables, so it fits a stream; confirming the answer needs a second look at the data.
