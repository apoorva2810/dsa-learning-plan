Group Anagrams Medium

LeetCode #49 ↗
Status

Put words that are rearrangements of each other into the same group.

Problem

You are given a list of lowercase words strs. Group together the words that are anagrams of each other (same letters, same number of times each, any order) and return the list of groups.

The groups can be returned in any order, and the words inside a group can be in any order too. Every word belongs to exactly one group; a word with no anagram partner forms a group by itself.

Examples

Example 1
Input: strs = ["eat", "tea", "tan", "ate", "nat", "bat"]
Output: [["bat"], ["nat", "tan"], ["ate", "eat", "tea"]]
"eat", "tea" and "ate" all use one a, one e and one t.
Example 2
Input: strs = [""]
Output: [[""]]
The empty string is a valid word and forms its own group.
Example 3
Input: strs = ["aab", "abb"]
Output: [["aab"], ["abb"]]
Same letters, different counts: not anagrams.

Constraints

  • 1 <= len(strs) <= 10^4
  • 0 <= len(strs[i]) <= 100
  • strs[i] consists of lowercase English letters

Think first try before reading the solution

What could act as a label that every anagram of a word shares, and no other word has?
Sorting a word's letters gives such a label: "eat", "tea" and "ate" all become "aet".
Use a dictionary from label to the list of words with that label. To skip the sort, the label can be a tuple of 26 letter counts.

Key idea

Comparing every word with every other word is the slow way. The fast way is to compute, for each word, a signature: a value that is identical for anagrams and different for everything else. Then grouping is just a dictionary from signature to the list of words, built in one pass.

Two signatures work. The sorted letters ("aet" for "eat") are easy to understand. The letter counts (1, 0, 0, 0, 1, ..., 1, ...) (how many a's, b's, ..., z's) avoid sorting. Both must be hashable to be dictionary keys: strings and tuples are, lists are not.

Approaches from the obvious one to the one you want in an interview

Keep a list of groups. For each word, walk the groups and test whether the word is an anagram of the group's first word (compare sorted letters). Join the first group that matches; if none does, start a new group.

Correct, but every word may be compared with every existing group. When most words have no partner there are about n groups, so the work is about n² comparisons, each costing a sort of k letters.

Dry run

  1. eat → no groups → [[eat]]
  2. tea vs eat: same letters → [[eat, tea]]
  3. tan vs eat: no → new group → [[eat, tea], [tan]]
  4. ate → group 0; nat → no, then group 1; bat → no, no → new group

Python

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        groups = []                                   # each group is a list of words
        for word in strs:
            key = sorted(word)
            placed = False
            for group in groups:
                if sorted(group[0]) == key:           # anagram of this group's first word?
                    group.append(word)
                    placed = True
                    break
            if not placed:                            # no existing group fits
                groups.append([word])
        return groups
Time O(n²·k log k)Space O(n·k)

n words, up to n groups to compare against, and each comparison sorts words of length up to k.

When to use: Only to show why a dictionary keyed by a signature is needed.

Watch it run

Sorting a word's letters gives a signature shared by all its anagrams: "eat", "tea" and "ate" all become "aet". Use it as a dictionary key and append each word to the list stored under its key. Looking up a key is O(1) on average, so no word is ever compared with the groups that do not match.

The only remaining cost is the sort inside each word: O(k log k) for a word of length k.

Dry run

  1. eat → "aet" → {aet: [eat]}
  2. tea → "aet" → {aet: [eat, tea]}
  3. tan → "ant" → new key; ate → "aet"; nat → "ant"; bat → "abt" → new key

Python

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        groups = defaultdict(list)                    # signature -> words with that signature
        for word in strs:
            key = "".join(sorted(word))               # "eat", "tea", "ate" -> "aet"
            groups[key].append(word)
        return list(groups.values())
Time O(n·k log k)Space O(n·k)

One sort of length k per word; the dictionary stores every word once plus one key per group.

When to use: The most common interview answer; short and clearly correct. Works for any characters, not only a-z.

Watch it run

Replace the sort with counting. For each word, fill a list of 26 counts (count[0] = number of a's, ..., count[25] = number of z's). Two words are anagrams exactly when their count lists are equal, so the counts are a signature too. Convert the list to a tuple so it can be a dictionary key.

Building the counts is O(k) per word instead of O(k log k). For short words the difference is small; the point interviewers look for is recognising that a signature can be counted rather than sorted.

Dry run

  1. eat → a:1, e:1, t:1 → key (1, 0, 0, 0, 1, ..., 1, ...)
  2. tea → the same 26 counts → same key → same list
  3. aab → a:2, b:1 and abb → a:1, b:2 → different keys, different groups

Python

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        groups = defaultdict(list)
        for word in strs:
            count = [0] * 26                          # how many a's, b's, ..., z's
            for ch in word:
                count[ord(ch) - ord("a")] += 1
            groups[tuple(count)].append(word)         # lists cannot be keys; tuples can
        return list(groups.values())
Time O(n·k)Space O(n·k)

k steps to count each word plus 26 to build its tuple; the dictionary holds all n words.

When to use: When asked to beat the sort. Relies on a fixed alphabet (26 lowercase letters).

Common mistakes

  • Using a list as a key: groups[sorted(word)] or groups[count] raises TypeError: unhashable type: 'list'. Convert with "".join(...) or tuple(...).
  • Using the set of letters as the key (frozenset(word)) puts "aab" and "abb" together; the counts matter, not just which letters appear.
  • Building a count key by gluing digits together without a separator: counts [1, 11, ...] and [11, 1, ...] both become "111...", so "abbbbbbbbbbb" and "aaaaaaaaaaab" collide. Use a tuple, or put a separator between the numbers.
  • Returning the dictionary itself, or groups.values() (a view), instead of list(groups.values()).

Python notes

  • defaultdict(list) creates an empty list the first time a key is used, so groups[key].append(word) needs no if key in groups check.
  • "".join(sorted(word)) turns the sorted list of characters back into a string key.
  • Dictionaries keep insertion order (Python 3.7+), so list(groups.values()) lists groups in order of their first word.
  • ord(ch) - ord("a") maps "a".."z" to 0..25.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Valid Anagram LC 242 — the two-word version: compute both signatures (or one count table) and compare them directly.
  • Group Shifted Strings LC 249 — "abc" and "bcd" belong together: the signature becomes the tuple of gaps between neighbouring letters, taken mod 26.
  • Find All Anagrams in a String LC 438 — one pattern, many windows of a long text: slide a fixed-size window and update its letter counts in O(1) per step.
  • What if words can contain any Unicode character? — a 26-slot count no longer fits. Use the sorted string, or tuple(sorted(Counter(word).items())) as the signature.
