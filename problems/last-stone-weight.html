Last Stone Weight Easy

LeetCode #1046 ↗
Status

Keep smashing the two heaviest stones together and report what is left at the end.

Problem

You are given the weights of some stones, stones (positive integers). Each turn, take the two heaviest stones, with weights x <= y, and smash them together:

  • if x == y, both stones are destroyed;
  • otherwise the lighter stone is destroyed and the heavier one now weighs y - x.

Repeat until at most one stone is left. Return the weight of the last stone, or 0 if no stones remain.

Examples

Example 1
Input: stones = [2, 7, 4, 1, 8, 1]
Output: 1
8 and 7 → a stone of 1, leaving [2, 4, 1, 1, 1]. 4 and 2 → 2, leaving [2, 1, 1, 1]. 2 and 1 → 1, leaving [1, 1, 1]. 1 and 1 → both destroyed, leaving [1].
Example 2
Input: stones = [1]
Output: 1
Only one stone, so nothing is smashed.
Example 3
Input: stones = [5, 5]
Output: 0
Equal weights destroy each other; nothing is left.

Constraints

  • 1 <= len(stones) <= 30
  • 1 <= stones[i] <= 1000

Think first try before reading the solution

Simulate exactly what the statement says. The only real question is how to find the two heaviest stones quickly, every turn.
After a smash a stone with a new weight can appear, so a list you sorted once at the start goes out of date. You need something that stays ordered while stones come and go.
A max-heap hands you the heaviest stone in O(log n) and takes a new stone in O(log n). Python's heapq is a min-heap, so store -weight: the heaviest stone becomes the most negative number and comes out first.

Key idea

Each turn asks the same question of a collection that keeps changing: which two are the heaviest right now? Sorting answers it once, but every smash can create a stone of a new weight, and then the order has to be repaired.

A max-heap is built for "give me the largest, then let me add something": both cost O(log n). Python's heapq only provides a min-heap, so we store negated weights. Among -8, -7, -4, the smallest is -8, so the heaviest stone (8) sits at the root. Pop twice, push back -(y - x) if the stones were not equal, repeat. Every turn removes at least one stone, so there are at most n - 1 turns.

Approaches from the obvious one to the one you want in an interview

Keep the stones in a sorted list. The two heaviest are the last two items: pop them, append the survivor (if any), and sort again so the next turn can trust the order.

It is correct, but every turn re-sorts the whole list: O(n log n) per turn and up to n - 1 turns, so O(n² log n) overall. The sort repeats work: before the smash, everything except the top two was already in order. (Inserting the survivor with bisect.insort instead of re-sorting is O(n) per turn, still O(n²) in total.)

Dry run

  1. [2, 7, 4, 1, 8, 1] → sorted [1, 1, 2, 4, 7, 8]
  2. pop 8 and 7 → append 1 → re-sort → [1, 1, 1, 2, 4]
  3. pop 4 and 2 → append 2 → [1, 1, 1, 2]
  4. pop 2 and 1 → append 1 → [1, 1, 1]
  5. pop 1 and 1 → equal, nothing appended → [1] → return 1

Python

class Solution:
    def lastStoneWeight(self, stones: List[int]) -> int:
        stones = sorted(stones)                  # a new sorted list; the input is untouched
        while len(stones) > 1:
            y = stones.pop()                     # heaviest
            x = stones.pop()                     # second heaviest
            if y != x:
                stones.append(y - x)
                stones.sort()                    # repair the order for the next turn
        return stones[0] if stones else 0
Time O(n² log n)Space O(n)

Up to n - 1 turns, each re-sorting up to n stones.

When to use: Fine for n ≤ 30, and a good way to check the heap version; not what an interviewer wants to see last.

Put every weight into a heap as -weight, so heapq's smallest item is the heaviest stone. Each turn:

  1. y = -heappop(heap): the heaviest stone;
  2. x = -heappop(heap): the next heaviest;
  3. if y != x, push -(y - x), the survivor.

Stop when at most one item is left. A pop or push is O(log n) and nothing else is re-ordered, so the waste of re-sorting disappears.

Dry run

  1. heap of [-2, -7, -4, -1, -8, -1] → root -8
  2. pop 8 and 7 → push -1 → weights left 4, 2, 1, 1, 1
  3. pop 4 and 2 → push -2 → weights left 2, 1, 1, 1
  4. pop 2 and 1 → push -1 → weights left 1, 1, 1
  5. pop 1 and 1 → equal, push nothing → one stone left → return 1

Python

class Solution:
    def lastStoneWeight(self, stones: List[int]) -> int:
        heap = [-s for s in stones]              # negate: the heaviest stone becomes the smallest number
        heapq.heapify(heap)                      # O(n)
        while len(heap) > 1:
            y = -heapq.heappop(heap)             # heaviest (negate back to the real weight)
            x = -heapq.heappop(heap)             # second heaviest
            if y != x:
                heapq.heappush(heap, -(y - x))   # the survivor goes back in
        return -heap[0] if heap else 0
Time O(n log n)Space O(n)

heapify is O(n); at most n - 1 turns, each with two pops and at most one push of O(log n).

When to use: The standard answer: it is the textbook use of a max-heap.

Common mistakes

  • Forgetting to undo the negation: heappop returns -8, and using it as the weight turns y - x into nonsense. Negate on the way out (y = -heappop(heap)).
  • Sorting once and appending the new stone at the end: the list is no longer sorted, so pop() stops returning the heaviest.
  • Reading heap[0] when every stone was destroyed raises IndexError. Return 0 when the heap is empty.
  • Pushing back a stone of weight 0 when the two are equal does not change the answer, but it adds pointless turns. Push only when y != x.

Python notes

  • heapq.heapify(heap) turns the negated list into a heap in O(n), cheaper than n pushes.
  • y = -heapq.heappop(heap) reads the real weight back in one expression.
  • heap = [-s for s in stones] builds a new list, so the caller's stones is left untouched.
  • Python 3.14 added heapq.heapify_max / heappop_max, which avoid the negation; LeetCode and this site's 3.12 runtime may not have them yet.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Last Stone Weight II LC 1049 — you may smash any two stones and want the smallest possible leftover: no heap at all, it becomes a subset-sum DP (split the stones into two groups whose totals are as close as possible).
  • Take Gifts From the Richest Pile LC 2558 — the same max-heap loop: pop the biggest pile, push back its square root, k times.
  • Remove Stones to Minimize the Total LC 1962 — pop the heaviest pile, push back what remains after removing half, k times.
  • Kth Largest Element in a Stream LC 703 — another 'largest few of a changing collection' question, solved with a size-k min-heap.
  • What if weights are small integers (≤ 1000)? — count stones per weight in an array of 1001 buckets and walk it from the heaviest down: O(n + W) instead of O(n log n).
