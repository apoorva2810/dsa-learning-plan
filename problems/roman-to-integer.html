Roman to Integer Easy 250

LeetCode #13 ↗
Status

Read a Roman numeral such as XLII and return its value, 42.

Problem

Roman numerals use seven symbols: I = 1, V = 5, X = 10, L = 50, C = 100, D = 500 and M = 1000. Symbols are usually written from largest to smallest and simply added: XII is 10 + 1 + 1 = 12.

Six subtractive pairs break that rule: a smaller symbol placed before a larger one is subtracted. IV is 4 and IX is 9 (I before V or X), XL is 40 and XC is 90 (X before L or C), CD is 400 and CM is 900 (C before D or M).

You are given a string s that is a valid Roman numeral. Return the integer it represents.

Examples

Example 1
Input: s = "XIV"
Output: 14
X = 10, then IV = 4 because I comes before the larger V.
Example 2
Input: s = "XLII"
Output: 42
XL = 40 (10 before 50), then I + I = 2.
Example 3
Input: s = "CDXLIV"
Output: 444
Three subtractive pairs in a row: CD = 400, XL = 40, IV = 4.

Constraints

  • 1 <= len(s) <= 15
  • s contains only the characters I, V, X, L, C, D, M
  • s is a valid Roman numeral for a number between 1 and 3999

In IV the I must count as −1 instead of +1. What is true about the symbol after it, and only in those cases?

Key idea

If every symbol were simply added, XIV would read 10 + 1 + 5 = 16 instead of 14. The only thing that ever changes a symbol's sign is its right neighbour: in the six subtractive pairs the left symbol is smaller than the one that follows it, and in every other position a symbol is followed by something equal or smaller (or by nothing). So the rule is local and needs no table of pairs:

look at s[i]; if s[i + 1] exists and is worth more, subtract value[s[i]], otherwise add it.

Reading XIV that way gives +10, −1, +5 = 14, and CDXLIV gives −100 +500 −10 +50 −1 +5 = 444. One pass, one dictionary lookup per character: O(n) time with a fixed-size table, and the input is at most 15 characters anyway.

The same comparison can be done from the right: scanning IV right to left you meet V first, then an I that is smaller than what you just saw, which is exactly the subtractive case.

Approaches from the obvious one to the one you want in an interview

Treat the six subtractive pairs as symbols in their own right. With a dictionary of 13 tokens (I, V, ..., M and IV, IX, XL, XC, CD, CM), walk the string and at each position try the two-character token first; if it is in the table, take it and jump two places, otherwise take the one-character symbol and jump one.

It is a tiny tokenizer, and it works because no pair is a prefix of another token. It needs the bigger table and a bounds check for the two-character look-ahead, which is what the next approach removes.

Dry run

  1. s = "XLII", i = 0: "XL" is a token → +40, i = 2
  2. i = 2: "II" is not a token, "I" is → +1, i = 3
  3. i = 3: no two-character slice fits, "I" → +1, i = 4. Total 42.

Python

class Solution:
    def romanToInt(self, s: str) -> int:
        tokens = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000,
                  "IV": 4, "IX": 9, "XL": 40, "XC": 90, "CD": 400, "CM": 900}
        total = 0
        i = 0
        while i < len(s):
            if i + 1 < len(s) and s[i:i + 2] in tokens:   # a subtractive pair takes two characters
                total += tokens[s[i:i + 2]]
                i += 2
            else:
                total += tokens[s[i]]
                i += 1
        return total
Time O(n)Space O(1)

Each character is consumed once; the table has 13 entries whatever the input.

When to use: When you want the six pairs to be visible as data. Fine, but twice the table.

Keep only the seven symbol values. For each position, compare the symbol with the one after it: smaller than the next means it is the left half of a subtractive pair, so subtract it; otherwise add it. The last symbol has no successor and is added.

One rule replaces the six pairs, because the pairs are exactly the places where a smaller symbol precedes a larger one. One pass, one lookup and one comparison per character.

Dry run

  1. s = "XIV": X = 10, next I = 1 is not larger → +10 (total 10)
  2. I = 1, next V = 5 is larger → −1 (total 9)
  3. V = 5 is last → +5 (total 14)
  4. s = "CDXLIV": −100, +500, −10, +50, −1, +5 = 444

Python

class Solution:
    def romanToInt(self, s: str) -> int:
        value = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}
        total = 0
        for i, ch in enumerate(s):
            if i + 1 < len(s) and value[ch] < value[s[i + 1]]:   # smaller than the next symbol: subtractive pair
                total -= value[ch]
            else:
                total += value[ch]                              # includes the last symbol, which has no next
        return total
Time O(n)Space O(1)

One pass; the dictionary has seven entries.

When to use: The interview answer: one local rule, no pair table.

Watch it run

Read the numeral backwards. The first symbol you meet is the rightmost one, which is always added. From then on, a symbol that is smaller than the one you just processed is the left half of a subtractive pair, so subtract it; otherwise add it.

Same rule as the left-to-right version, mirrored. The comparison is now with a value you already have in hand, so there is no bounds check, at the price of walking the string in the less natural direction.

Dry run

  1. s = "XIV" reversed: V first → +5 (prev 5)
  2. I = 1 < 5 → −1 (prev 1), total 4
  3. X = 10 ≥ 1 → +10, total 14

Python

class Solution:
    def romanToInt(self, s: str) -> int:
        value = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}
        total = 0
        prev = 0                                   # value of the symbol to the right of the current one
        for ch in reversed(s):
            v = value[ch]
            if v < prev:                           # smaller than its right neighbour: subtract
                total -= v
            else:
                total += v
            prev = v
        return total
Time O(n)Space O(1)

One pass from the right; a single extra variable.

When to use: When you prefer no index arithmetic; prev = 0 makes the first (rightmost) symbol count as added.

Common mistakes

  • Adding every symbol. IV then becomes 6 instead of 4. A smaller symbol before a larger one is subtracted.
  • Reading past the end. s[i + 1] raises IndexError on the last character; guard with i + 1 < len(s), loop to len(s) - 1 and add the last symbol separately, or scan from the right so the comparison is with a symbol you have already seen.
  • Comparing with the previous symbol while scanning left to right. The sign of s[i] depends on what comes after it. Compare with the previous one only when you scan right to left.
  • Looking for subtractive pairs with in or replace on the whole string without care: "XIX".replace("IX", ...) is fine, but "XCIX" contains CI, which is not a pair, and such approaches get order-dependent fast. The next-symbol rule needs no pair table.
  • Validating the input. The problem promises a valid numeral; code that rejects IIII or VX is extra work and a source of bugs here.

Python notes

  • value = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000} is the whole table; every lookup is O(1).
  • for i, ch in enumerate(s) gives you the index you need to peek at s[i + 1]; zip(s, s[1:]) pairs each symbol with its right neighbour and avoids the index entirely.
  • Scanning from the right with reversed(s) lets you compare each symbol with the one you processed just before, which removes the bounds check.
  • With at most 15 characters, all three versions run in the same tiny time; pick the one you can explain most clearly.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Integer to Roman LC 12 — the reverse direction. Keep the 13 tokens (seven symbols plus six pairs) in descending order and take each as many times as it fits: a greedy loop.
  • String to Integer (atoi) LC 8 — also parsing a number out of a string, but with leading spaces, an optional sign, junk after the digits and 32-bit clamping to handle.
  • Excel Sheet Column Number LC 171 — letters to a number in a positional system: total = total * 26 + value. Roman numerals are not positional, which is why they need the subtraction rule instead.
  • Excel Sheet Column Title LC 168 — the opposite job, number to letters, with its own off-by-one trap.
  • Validate the numeral — return −1 for IIII, VX or IC: a symbol may repeat at most three times, V, L, D never repeat, and only the six listed pairs may subtract. Easiest by converting and re-encoding, then comparing.
  • Numerals above 3999 — a bar over a symbol multiplies it by 1000. With an input alphabet for barred symbols the same next-symbol rule still works; only the value table grows.
