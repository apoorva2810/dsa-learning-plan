Asteroid Collision Medium 250

LeetCode #735 ↗
Status

Asteroids fly left or right along a line; when two meet, the smaller explodes. Return who survives.

Problem

Asteroids sit in a row, listed from left to right in the array asteroids. The absolute value of a number is the asteroid's size; its sign is its direction: positive means moving right, negative means moving left. All asteroids move at the same speed.

When two asteroids meet, the smaller one explodes. If both have the same size, both explode. Asteroids moving in the same direction never meet. An asteroid that survives a collision keeps flying and may meet the next one.

Return the asteroids that are left after all collisions, in their original left-to-right order. No asteroid has size 0.

Examples

Example 1
Input: asteroids = [5, 10, -5]
Output: [5, 10]
The -5 flies left into the 10. The 10 is bigger, so the -5 explodes. The 5 and the 10 move the same way and never meet.
Example 2
Input: asteroids = [8, -8]
Output: []
Same size, so both explode.
Example 3
Input: asteroids = [10, 2, -5]
Output: [10]
The -5 destroys the 2, then meets the 10 and explodes.
Example 4
Input: asteroids = [-2, -1, 1, 2]
Output: [-2, -1, 1, 2]
The left-movers are already on the left and the right-movers on the right. They fly apart and nobody meets.

Constraints

  • 2 <= len(asteroids) <= 10^4
  • -1000 <= asteroids[i] <= 1000
  • asteroids[i] != 0

Think first try before reading the solution

Two asteroids can only meet if a right-mover is somewhere to the left of a left-mover. Which right-mover does a new left-mover meet first?
A new left-mover meets the closest right-mover before it that is still flying: the most recent survivor. 'Most recent first' is a stack.
Keep the survivors on a stack. Push a right-mover at once. A left-mover keeps fighting the top of the stack while the top moves right; stop when it explodes, ties, or has nothing left to hit.

Key idea

Only one situation causes a collision: a right-mover with a left-mover somewhere after it. So read the row from left to right and keep the survivors so far on a stack (the leftmost at the bottom).

A new right-mover cannot hit anything yet: whatever it may hit comes later in the row. Push it. A new left-mover can only hit the asteroid closest to it on the left, which is the top of the stack, and only if that one moves right. They fight: the smaller explodes, equal sizes destroy both. If the left-mover wins, the next asteroid on the stack is now in its way, so it fights again. It stops when it explodes, when both explode, or when the top is a left-mover (same direction) or the stack is empty. In the last two cases it survives, and we push it.

Every asteroid is pushed at most once and popped at most once, so the whole pass is O(n).

Approaches from the obvious one to the one you want in an interview

The only pair that can collide is a right-mover directly followed by a left-mover. Scan from the left until you find one, resolve it (delete the smaller asteroid, or both if they tie), and start scanning again from the left, because deleting asteroids can bring a new colliding pair next to each other. When a full scan finds no such pair, the row is final.

It is correct, but every collision costs a fresh scan. A row like [1, 2, 3, 4, -10] is resolved one asteroid at a time, and each scan re-reads all the pairs before the collision: O(n) scans of O(n) pairs, so O(n²) in total.

Dry run

  1. [3, 5, -6, 2, -1, 4]: the first pair that can collide is 5, -6 → the 5 explodes → [3, -6, 2, -1, 4].
  2. Rescan from the left: 3, -6 collide → the 3 explodes → [-6, 2, -1, 4].
  3. Rescan: -6, 2 do not collide, 2, -1 do → the -1 explodes → [-6, 2, 4].
  4. Rescan: no right-mover is directly followed by a left-mover → done.

Python

class Solution:
    def asteroidCollision(self, asteroids: List[int]) -> List[int]:
        row = list(asteroids)                          # work on a copy
        changed = True
        while changed:                                 # sweep again until a sweep finds no collision
            changed = False
            for i in range(len(row) - 1):
                left, right = row[i], row[i + 1]
                if left > 0 and right < 0:             # a right-mover directly before a left-mover: they collide
                    if left > -right:
                        del row[i + 1]                 # the left-mover explodes
                    elif left < -right:
                        del row[i]                     # the right-mover explodes
                    else:
                        del row[i:i + 2]               # same size: both explode
                    changed = True
                    break                              # positions shifted: start the sweep again
        return row
Time O(n²)Space O(n)

Up to n collisions, and each one is followed by a scan over up to n pairs.

When to use: Only as the baseline; it shows that the rescans re-read pairs that cannot have changed.

Watch it run

Walk the row once, keeping the survivors so far on a stack (leftmost at the bottom). For each asteroid a:

  • a > 0 (moving right): push it. Whatever it may hit comes later in the row.
  • a < 0 (moving left): it can only hit the top of the stack, and only if that top moves right. While that holds, they fight: a smaller top explodes (pop it and keep fighting), an equal top explodes together with a, and a bigger top destroys a.
  • If a is still alive after the fights, push it. Reaching an empty stack or a left-moving top means there is nothing left to hit.

Each asteroid is pushed at most once and popped at most once, so the pass is O(n).

Dry run

  1. [3, 5, -6, 2, -1, 4], stack []
  2. 3, 5 move right → push both → [3, 5]
  3. -6 meets 5: 5 is smaller → pop. Meets 3: smaller → pop. Stack empty → push -6 → [-6]
  4. 2 moves right → push → [-6, 2]
  5. -1 meets 2: the 2 is bigger → -1 explodes → [-6, 2]
  6. 4 moves right → push → [-6, 2, 4]

Python

class Solution:
    def asteroidCollision(self, asteroids: List[int]) -> List[int]:
        stack = []                                     # survivors so far, leftmost at the bottom
        for a in asteroids:
            alive = True
            # only a left-mover (a < 0) can hit a right-mover on top of the stack (stack[-1] > 0)
            while alive and a < 0 and stack and stack[-1] > 0:
                top = stack[-1]
                if top < -a:                           # the top is smaller: it explodes, a keeps flying
                    stack.pop()
                elif top == -a:                        # same size: both explode
                    stack.pop()
                    alive = False
                else:                                  # the top is bigger: a explodes
                    alive = False
            if alive:
                stack.append(a)                        # a survived every fight (or never had one)
        return stack
Time O(n)Space O(n)

Each asteroid is pushed once and popped at most once, so the loop body runs at most 2n times in total.

When to use: Always. The 'left-mover fights down the stack' loop is the whole problem.

Watch it run

The finished row always has the shape some left-movers, then some right-movers: a left-mover that survives has no right-mover alive to its left. So keep the two groups apart. A stack right_movers holds the right-moving survivors, and a list escaped collects the left-movers that got past every right-mover. A left-mover fights down the right_movers stack; if the stack runs out, it escapes. The answer is escaped + right_movers.

Same O(n) work. There is no alive flag, but the code relies on the observation about the shape of the answer.

Python

class Solution:
    def asteroidCollision(self, asteroids: List[int]) -> List[int]:
        right_movers = []                              # stack of right-moving asteroids still flying
        escaped = []                                   # left-movers that got past every right-mover
        for a in asteroids:
            if a > 0:
                right_movers.append(a)
                continue
            size = -a                                  # the left-mover fights the right-movers one by one
            while right_movers and right_movers[-1] < size:
                right_movers.pop()                     # a smaller right-mover explodes
            if right_movers and right_movers[-1] == size:
                right_movers.pop()                     # same size: both explode
            elif not right_movers:
                escaped.append(a)                      # nothing left to hit: it flies away to the left for good
            # otherwise the top right-mover is bigger, so this asteroid explodes
        return escaped + right_movers
Time O(n)Space O(n)

Same push-once, pop-once argument as the single stack.

When to use: If the 'answer is left-movers, then right-movers' picture makes the code easier to follow for you.

Common mistakes

  • Comparing signed numbers. For a left-mover a the size is -a; writing top < a compares a positive with a negative and is always false. Compare top with -a.
  • Colliding when the top moves left. A left-mover on top and a new left-mover fly the same way, and a left-mover followed by a right-mover ([-5, 5]) fly apart. Only right-mover then left-mover collides.
  • Stopping after one fight. A big left-mover can destroy several right-movers in a row, so the fight must be a loop.
  • Forgetting the tie. On equal sizes both explode: pop the top and do not push the new asteroid.
  • Pushing a left-mover that has just exploded. Track whether it is still alive after the loop.

Python notes

  • A left-mover's size is -a (or abs(a)). Compare sizes, never signed values.
  • stack[-1] > 0 reads as "the top moves right". Check stack first (while stack and stack[-1] > 0) so you never read the top of an empty list.
  • The stack already holds the survivors in left-to-right order, so return stack needs no reversing.
  • A boolean such as alive keeps the loop easy to read; break plus else on the while is shorter but harder to follow.
