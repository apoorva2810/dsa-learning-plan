Open the Lock Medium 250

LeetCode #752 ↗
Status

Find the fewest single-wheel turns that take a 4-wheel combination lock from 0000 to a target without landing on any forbidden combination.

Problem

A lock has 4 wheels, each showing a digit 0-9. One move turns one wheel one notch in either direction; the digits wrap around, so 9 turns up to 0 and 0 turns down to 9. The lock starts at "0000".

deadends is a list of combinations that must never appear on the lock: if the wheels ever show one of them, they freeze for good. target is the combination that opens the lock.

Return the minimum number of moves that reaches target, or -1 if it cannot be reached.

Examples

Example 1
Input: deadends = ["0201","0101","0102","1212","2002"], target = "0202"
Output: 6
One shortest route: 0000 → 1000 → 1100 → 1200 → 1201 → 1202 → 0202. The direct route 0000 → 0001 → 0002 → 0102 → 0202 is blocked because 0102 is a dead end.
Example 2
Input: deadends = ["8888"], target = "0009"
Output: 1
Turn the last wheel one notch down: 0 wraps to 9.
Example 3
Input: deadends = ["8887","8889","8878","8898","8788","8988","7888","9888"], target = "8888"
Output: -1
Every combination one move away from 8888 is a dead end, so 8888 is walled off.

Constraints

  • 1 <= len(deadends) <= 500
  • deadends[i] and target are strings of exactly 4 digits
  • target is not "0000"
  • target and the dead ends are all distinct

Think first try before reading the solution

Think of every 4-digit combination as a place you can stand on. From any place, how many places are exactly one move away?
All moves cost the same, so 'fewest moves' is a shortest-path question in a graph of 10,000 nodes with 8 edges each. Which search explores a graph in order of distance?
Breadth-first search from 0000: keep a queue and a visited set, skip dead ends and anything already seen, and stop the first time you generate the target. Store the move count with each combination.

Key idea

The natural first idea, turning each wheel straight towards its target digit, ignores the dead ends: in example 1 the four wheels are only 4 notches away in total, yet the answer is 6 because 0102 and 0201 block the short routes. The dead ends make this a search problem.

Picture a graph whose nodes are the 10,000 combinations 0000-9999. Two nodes are joined when one wheel turned one notch converts one into the other, so every node has exactly 8 neighbours. Dead ends are nodes that have been removed. Nobody hands us this graph; we generate a node's neighbours when we need them, which is why it is called an implicit graph. The question becomes: what is the shortest path from 0000 to target?

Every edge costs one move, so breadth-first search (BFS) is the tool. It explores all combinations one move away, then all at two moves, and so on, so the first time it generates the target it has found the fewest moves. A visited dictionary stores each combination with its distance and makes sure no combination is expanded twice. At most 10,000 combinations and 80,000 edges are touched, so the search takes O(10⁴) work no matter what the input is. If the queue runs empty first, the dead ends wall the target off and the answer is -1.

Approaches from the obvious one to the one you want in an interview

Treat every combination as a node whose 8 neighbours are produced by turning one wheel one notch up or down. Start a BFS at 0000 with visited = {"0000": 0}. Pop a combination, generate its 8 neighbours, and for each one that is neither a dead end nor already visited, record its distance (one more than the current one) and queue it. The first time the target is generated, its recorded distance is the answer.

BFS hands out distances in increasing order, so nothing shorter can appear later. Every combination is queued at most once (it is marked visited when queued), so the work is bounded by 10,000 nodes and 80,000 neighbour checks whatever the input is. An empty queue means the target is unreachable.

Dry run

  1. deadends = ["0001"], target = "0011". Queue [0000], visited {0000: 0}.
  2. Pop 0000: neighbours 1000, 9000, 0100, 0900, 0010, 0090, 0009 are new (1 move); 0001 is a dead end.
  3. Pop 1000, 9000, 0100, 0900: each adds its unseen neighbours at 2 moves; 0011 is not among them.
  4. Pop 0010: its neighbours include 0011, the target, recorded at 2 moves → return 2.

Python

class Solution:
    def openLock(self, deadends: List[str], target: str) -> int:
        dead = set(deadends)                                  # O(1) membership tests
        if "0000" in dead or target in dead:
            return -1                                         # frozen at the start, or the target freezes the lock
        if target == "0000":
            return 0
        visited = {"0000": 0}                                 # combination -> fewest moves that reach it
        queue = deque(["0000"])
        while queue:
            combo = queue.popleft()
            for i in range(4):                                # for each wheel ...
                digit = int(combo[i])
                for turned in ((digit + 1) % 10, (digit - 1) % 10):     # ... one notch up, one notch down
                    nxt = combo[:i] + str(turned) + combo[i + 1:]
                    if nxt in dead or nxt in visited:
                        continue
                    visited[nxt] = visited[combo] + 1         # first visit = shortest distance
                    if nxt == target:
                        return visited[nxt]
                    queue.append(nxt)
        return -1                                             # the queue ran dry: the target is walled off
Time O(10⁴ · 8) ≈ O(1)Space O(10⁴)

At most 10,000 combinations are queued once each and each generates 8 neighbours; for a lock with k wheels that is O(10^k · k) nodes and edges.

When to use: The default answer, and the template for every 'fewest moves between states' problem.

Watch it run

Run two searches at once, one from 0000 and one from target, always expanding the smaller frontier by one level. The moment a neighbour generated by one side belongs to the other side's frontier, the two searches have met, and the number of levels expanded so far is the distance.

A BFS frontier roughly multiplies in size at every level, so two half-depth searches explore far fewer combinations than one full-depth search. On this 10,000-node graph the gain is modest, but the same trick is what makes Word Ladder and larger state spaces practical. The code is trickier: one shared seen set, a level counter, and the meeting test before the dead-end test.

Dry run

  1. deadends = ["0001"], target = "0011": front {0000}, back {0011}, moves 0.
  2. Expand front: moves = 1; its 7 allowed neighbours are not in back → front becomes those 7.
  3. Now back is smaller, so the sides swap and we expand {0011}: moves = 2; its neighbour 0010 is in the other frontier → return 2.

Python

class Solution:
    def openLock(self, deadends: List[str], target: str) -> int:
        dead = set(deadends)
        if "0000" in dead or target in dead:
            return -1
        if target == "0000":
            return 0

        def turns(combo: str):
            for i in range(4):
                digit = int(combo[i])
                yield combo[:i] + str((digit + 1) % 10) + combo[i + 1:]
                yield combo[:i] + str((digit - 1) % 10) + combo[i + 1:]

        front, back = {"0000"}, {target}                     # the two frontiers
        seen = {"0000", target}
        moves = 0
        while front and back:
            if len(front) > len(back):
                front, back = back, front                     # always expand the smaller side
            moves += 1
            next_front = set()
            for combo in front:
                for nxt in turns(combo):
                    if nxt in back:
                        return moves                          # the two searches meet
                    if nxt in dead or nxt in seen:
                        continue
                    seen.add(nxt)
                    next_front.add(nxt)
            front = next_front
        return -1
Time O(10⁴ · 8)Space O(10⁴)

Same worst case as plain BFS, but typically each side only explores combinations within half the distance, so far fewer in practice.

When to use: When the state space is big and the target is known in advance (Word Ladder, puzzles with many states).

For any combination we can estimate how many moves remain if nothing were in the way: for each wheel, the shorter way round to the target digit, summed over the four wheels. A* keeps the unexplored combinations in a min-heap ordered by moves so far + estimate, so it works on the combinations that look closest to the target first and may ignore most of the 10,000 states.

The estimate never overstates the true distance, and one move changes it by at most one, which is what guarantees that the first time the target is popped its distance is minimal. With the estimate replaced by 0 this is Dijkstra's algorithm, the right tool when moves have different costs.

Dry run

  1. deadends = ["0001"], target = "0011": heap [(2, 0, 0000)] (estimate 2, 0 moves).
  2. Pop 0000: push its neighbours with estimate + moves; 0010 and 0001 would score 1 + 1 = 2, but 0001 is dead.
  3. Pop 0010 (score 2): push 0011 with 2 moves and estimate 0 → score 2.
  4. Pop 0011 == target → return 2. Only a handful of combinations were ever looked at.

Python

class Solution:
    def openLock(self, deadends: List[str], target: str) -> int:
        dead = set(deadends)
        if "0000" in dead or target in dead:
            return -1

        def turns(combo: str):
            for i in range(4):
                digit = int(combo[i])
                yield combo[:i] + str((digit + 1) % 10) + combo[i + 1:]
                yield combo[:i] + str((digit - 1) % 10) + combo[i + 1:]

        def remaining(combo: str) -> int:                     # moves still needed if no dead end were in the way
            total = 0
            for a, b in zip(combo, target):
                gap = abs(int(a) - int(b))
                total += min(gap, 10 - gap)                   # the shorter way round the wheel
            return total

        best = {"0000": 0}                                    # fewest moves found so far for each combination
        heap = [(remaining("0000"), 0, "0000")]               # (moves + estimate, moves, combination)
        while heap:
            _, moves, combo = heapq.heappop(heap)
            if combo == target:
                return moves
            if moves > best[combo]:
                continue                                      # a stale entry; this combo was reached cheaper later
            for nxt in turns(combo):
                if nxt in dead:
                    continue
                if moves + 1 < best.get(nxt, math.inf):
                    best[nxt] = moves + 1
                    heapq.heappush(heap, (moves + 1 + remaining(nxt), moves + 1, nxt))
        return -1
Time O(10⁴ · 8 · log 10⁴)Space O(10⁴)

Worst case a heap operation per edge; in practice the estimate steers the search straight at the target and only a small fraction of the states is touched.

When to use: When the state space is far bigger than 10,000 and a cheap, never-overestimating guess of the remaining distance exists; or, with the estimate set to 0, whenever moves have different costs.

Common mistakes

  • Turning each wheel greedily toward its target digit. It gives the distance when nothing is in the way, but a dead end on the straight route forces a detour: example 1 needs 6 moves, not 4.
  • Forgetting the wrap-around. 0 turned down is 9 and 9 turned up is 0; (digit - 1) % 10 and (digit + 1) % 10 handle both ends in Python because % never returns a negative number.
  • Not checking the start. If "0000" is itself a dead end, the lock is frozen before the first move and the answer is -1; a BFS that only checks neighbours would happily explore from it.
  • Marking a combination visited when it leaves the queue instead of when it is pushed. Each combination can then be pushed by up to 8 neighbours, and the queue swells to many times the 10,000 states.
  • Using a list as the queue or as the visited set. list.pop(0) shifts every element and x in list scans it: both are O(n) per operation, which turns the search into O(n²). Use deque and a set/dict.
  • Using depth-first search. DFS finds a path to the target, not the shortest one, and it can wander through thousands of states before trying the one-move neighbour.

Python notes

  • (d + 1) % 10 and (d - 1) % 10 do the wrap-around: Python's % returns 9 for -1 % 10, unlike some languages.
  • Strings are immutable, so a neighbour is built by slicing: combo[:i] + str(new_digit) + combo[i + 1:].
  • set(deadends) first. Membership in a list is O(n) and runs up to 80,000 times.
  • collections.deque gives O(1) popleft(). A dict for visited stores the distance with each combination, so no separate level counter is needed.
  • A nested generator def turns(combo): ... yield ... keeps the neighbour logic in one place for all three approaches.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Word Ladder LC 127 — the same BFS where the states are words and a move changes one letter; the word list plays the role of the allowed combinations instead of the dead ends.
  • Minimum Genetic Mutation LC 433 — 8-letter strings over an alphabet of 4; a move changes one letter, and the result must be in the bank. Same code, different neighbour generator.
  • Sliding Puzzle LC 773 — a 2 × 3 board encoded as a string; a move swaps the empty tile with a neighbour. BFS over board states, with the solved board as the target.
  • Shortest Path in Binary Matrix LC 1091 — an explicit grid instead of an implicit graph, with 8 directions; the visited set and queue are the same.
  • Return the sequence of combinations, not just the count — store parent[nxt] = combo when you first reach nxt, then walk the parents back from the target and reverse the list.
  • What if turning different wheels takes different times? — edges now have weights, so BFS no longer finds the cheapest route; switch to Dijkstra's algorithm with a heap, which is the A* code below with the estimate set to 0.
