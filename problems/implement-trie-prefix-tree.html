Implement Trie (Prefix Tree) Medium

LeetCode #208 ↗
Status

Build a prefix tree that stores words and answers 'was this word inserted?' and 'does any word start with this?'.

Problem

A trie (prefix tree) stores strings so that whole words and prefixes can both be looked up quickly. Implement the class Trie:

  • Trie() creates an empty trie.
  • insert(word) adds word to the trie.
  • search(word) returns True if word was inserted earlier as a whole word, otherwise False.
  • startsWith(prefix) returns True if at least one inserted word starts with prefix, otherwise False.

All strings consist of lowercase English letters.

Examples

Example 1
Input: ["Trie","insert","search","search","startsWith","insert","search"] [[],["apple"],["apple"],["app"],["app"],["app"],["app"]]
Output: [null, null, true, false, true, null, true]
After inserting apple, app is only a prefix: search says false, startsWith says true. Once app is inserted as well, search('app') is true.

Constraints

  • 1 <= len(word), len(prefix) <= 2000
  • word and prefix consist of lowercase English letters
  • at most 3 * 10^4 calls in total

Think first try before reading the solution

A set answers search at once, but startsWith only by checking every stored word. What structure would let words that start the same way share that work?
Build a tree where every edge is a letter: following a word's letters from the root spells the word. Words with a common prefix then share the same path.
Each node needs a children dictionary (letter → node) and a flag saying whether a word ends there. search checks the flag at the end of the walk; startsWith only needs the walk to succeed.

Key idea

Think of each word as a path. Start at an empty root; to insert apple, follow (or create) an edge a, then p, p, l, e. Inserting app afterwards walks the first three of those edges and creates nothing. So each node stands for one prefix, and every prefix of every stored word has exactly one node.

Both questions then become the same walk: follow the query's letters from the root. If some letter has no edge, no stored word starts with that prefix. If the walk gets to the end, startsWith is true. search needs one more fact, because the node for app may only be a stop on the way to apple: every node keeps a flag is_end, which insert sets on the node where a word finishes.

Every operation takes one step per letter, O(L) for a string of length L, no matter how many words are stored.

Approaches from the obvious one to the one you want in an interview

Store the words in a Python set. insert adds, search is a membership test (hash the string, O(L)), and startsWith asks every stored word whether it begins with the prefix.

Two of the three operations are fast. startsWith is O(N · L) for N stored words: it re-reads the same shared beginnings over and over, which is exactly the repeated work a trie removes.

Dry run

  1. insert apple → words = {apple}
  2. search app → 'app' in words → False
  3. startsWith app → check each word: 'apple'.startswith('app') → True

Python

class Trie:
    def __init__(self):
        self.words = set()

    def insert(self, word: str) -> None:
        self.words.add(word)

    def search(self, word: str) -> bool:
        return word in self.words                  # hashing: O(len(word))

    def startsWith(self, prefix: str) -> bool:
        return any(w.startswith(prefix) for w in self.words)   # O(N · L): checks every word
Time O(L) insert/search, O(N·L) startsWithSpace O(total letters)

N = number of stored words, L = string length. The prefix scan dominates when startsWith is called often.

When to use: When prefix queries are rare; it shows exactly which operation the trie is for.

Each node holds children (a dict from letter to node) and is_end.

  • insert: walk from the root, creating any missing child, then set is_end on the last node.
  • _find(s): walk from the root; return None as soon as a letter is missing, else the final node.
  • search(word): _find(word) exists and has is_end.
  • startsWith(prefix): _find(prefix) exists.

Every operation is one walk of at most L steps, each an O(1) dictionary lookup.

Dry run

  1. insert apple: create a → p → p → l → e; mark e as an end
  2. search apple: walk 5 letters, is_end True → True
  3. search app: walk 3 letters, is_end False → False
  4. startsWith app: walk 3 letters → True
  5. insert app: walk 3 existing nodes, set is_end on the second p → search app is now True

Python

class TrieNode:
    def __init__(self):
        self.children = {}          # letter -> TrieNode
        self.is_end = False         # True if a word ends exactly here


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            if ch not in node.children:          # extend the path when needed
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def _find(self, s: str):
        """Follow s from the root; return the node where it ends, or None."""
        node = self.root
        for ch in s:
            if ch not in node.children:
                return None
            node = node.children[ch]
        return node

    def search(self, word: str) -> bool:
        node = self._find(word)
        return node is not None and node.is_end  # the path AND the end flag

    def startsWith(self, prefix: str) -> bool:
        return self._find(prefix) is not None     # the path is enough
Time O(L) for every operationSpace O(total letters)

One node per distinct prefix; each operation follows at most L edges with O(1) dictionary lookups.

When to use: The interview answer in Python.

Watch it run

The classic textbook layout: each node has a list of 26 slots, one per letter, where children[ord(ch) - ord('a')] is the child for ch or None. Lookups become list indexing instead of hashing.

Same O(L) per operation. The trade-off: every node reserves 26 slots even if it uses one, so memory is higher, and only lowercase a-z are supported. In C++ or Java this layout is common because it is fast; in Python the dictionary version is usually just as fast and smaller.

Python

class TrieNode:
    __slots__ = ("children", "is_end")

    def __init__(self):
        self.children = [None] * 26     # children[0] is 'a', children[25] is 'z'
        self.is_end = False


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            i = ord(ch) - ord("a")
            if node.children[i] is None:
                node.children[i] = TrieNode()
            node = node.children[i]
        node.is_end = True

    def _find(self, s: str):
        node = self.root
        for ch in s:
            node = node.children[ord(ch) - ord("a")]
            if node is None:
                return None
        return node

    def search(self, word: str) -> bool:
        node = self._find(word)
        return node is not None and node.is_end

    def startsWith(self, prefix: str) -> bool:
        return self._find(prefix) is not None
Time O(L) for every operationSpace O(26 · number of nodes)

Each node allocates 26 slots up front, used or not.

When to use: When the alphabet is small and fixed and you want array indexing (common in compiled languages).

Common mistakes

  • Returning True from search because the path exists. After insert('apple'), search('app') must be False: check is_end.
  • Creating nodes while looking up, for example with setdefault or a defaultdict inside search. A lookup must not change the trie.
  • Writing def __init__(self, children={}): that default dictionary is created once and shared by every node.
  • Indexing a fixed array with ord(ch) - ord('a') breaks on any character outside a-z; the dictionary version accepts any character.

Python notes

  • node.children.get(ch) returns None for a missing letter, which keeps the lookup loop short.
  • One helper that walks a string and returns the node where it ends (or None) makes search and startsWith one line each.
  • Nested dictionaries work too: node = node.setdefault(ch, {}) to insert and a key such as "$" to mark a word's end. Fewer lines, but harder to read aloud in an interview.
