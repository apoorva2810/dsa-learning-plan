Swim in Rising Water Hard

LeetCode #778 ↗
Status

Find the earliest water level at which you can swim from the top-left to the bottom-right square.

Problem

You are given an n × n grid. grid[r][c] is the elevation of square (r, c), and the elevations are the numbers 0 to n² - 1, each used exactly once.

Rain starts falling. At time t the water is at level t everywhere. You may swim from a square to one of its four neighbours (up, down, left, right) when both squares have elevation at most t. Swimming any distance takes no time.

Starting on square (0, 0), return the smallest t at which you can reach square (n - 1, n - 1).

Examples

Example 1
Input: grid = [[0, 2], [1, 3]]
Output: 3
The target square has elevation 3, so nothing earlier than t = 3 can work, and at t = 3 every square is under water.
Example 2
Input: grid = [[0, 8, 1], [2, 7, 3], [4, 6, 5]]
Output: 6
Go down the left column and along the bottom: 0 → 2 → 4 → 6 → 5. The highest square on that route is 6. Every other route climbs over 7 or 8.

Constraints

  • n == len(grid) == len(grid[i])
  • 1 <= n <= 50
  • 0 <= grid[r][c] < n², and every value appears once

Think first try before reading the solution

Fix a time t. Can you tell whether the corner is reachable at that time? And if it is reachable at t, what about t + 1?
Reachable at t means reachable at every later time, so you are looking for the first t that works: try values in order, or binary-search them with a BFS check. Another view: a route 'costs' its highest square, and you want the cheapest route.
Dijkstra where a route's cost is the maximum elevation on it: a min-heap of (level, r, c); when you step to a neighbour the new level is max(level, grid[nr][nc]). The level at which you pop the corner is the answer.

Key idea

At time t you can use exactly the squares with elevation ≤ t. So a route becomes swimmable at the moment of its highest square, and the answer is the smallest possible "highest square" over all routes from start to corner. That is a bottleneck (or minimax) path: minimise the maximum along the way, instead of the sum.

Dijkstra handles this if "route length" means "highest elevation so far". Keep a min-heap of squares keyed by the level needed to reach them, and always expand the lowest one. Think of the water rising: you swim to whatever lowest square touches the region you can already reach. Stepping onto a neighbour costs max(level, its elevation), which never goes down along a route, so squares come out of the heap in non-decreasing level order and the level when the corner comes out is the answer.

A second view uses the fact that "reachable by time t" is monotonic: false, false, …, false, true, true, …. Binary search finds the first true, checking each guess with a BFS over the squares with elevation ≤ guess.

Approaches from the obvious one to the one you want in an interview

Start with t = max(grid[0][0], grid[n-1][n-1]) (you must stand on both end squares) and ask "can I reach the corner using only squares with elevation ≤ t?" with a breadth-first search. If not, try t + 1, and so on. The first t that works is the answer.

Each check is O(n²), and in the worst case you try up to n² values of t: O(n⁴), about 6 million square visits for n = 50. It is correct, and it introduces the BFS check that the faster versions reuse.

Dry run

  1. grid = [[0, 8, 1], [2, 7, 3], [4, 6, 5]]: start at t = max(0, 5) = 5
  2. t = 5: from 0 you reach 2 and 4, but every way onward needs 6, 7 or 8 → no
  3. t = 6: 0 → 2 → 4 → 6 → 5 is all ≤ 6 → yes → answer 6

Python

class Solution:
    def swimInWater(self, grid: List[List[int]]) -> int:
        n = len(grid)

        def can_reach(t: int) -> bool:             # BFS over squares with elevation <= t
            seen = {(0, 0)}
            queue = deque([(0, 0)])
            while queue:
                r, c = queue.popleft()
                if (r, c) == (n - 1, n - 1):
                    return True
                for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                    if 0 <= nr < n and 0 <= nc < n and (nr, nc) not in seen and grid[nr][nc] <= t:
                        seen.add((nr, nc))
                        queue.append((nr, nc))
            return False

        t = max(grid[0][0], grid[n - 1][n - 1])    # you must stand on both end squares
        while not can_reach(t):
            t += 1
        return t
Time O(n⁴)Space O(n²)

Up to n² candidate times, each checked by an O(n²) BFS.

When to use: Only as a stepping stone: it shows the yes/no check and the monotonic structure.

The check is monotonic: if the corner is reachable at time t, it is reachable at any later time (more squares are under water, none dry up). So the answers to "reachable at t?" look like no, no, …, no, yes, yes, …, and binary search finds the first yes in O(log n²) checks instead of trying every t.

lo starts at the higher of the two end squares, hi at n² - 1 (everything is under water then). Each round tests mid: if it works, the answer is mid or smaller (hi = mid); if not, it is larger (lo = mid + 1).

Dry run

  1. grid = [[0, 8, 1], [2, 7, 3], [4, 6, 5]]: lo = 5, hi = 8
  2. mid = 6 → reachable → hi = 6. mid = 5 → not reachable → lo = 6
  3. lo == hi == 6 → answer 6

Python

class Solution:
    def swimInWater(self, grid: List[List[int]]) -> int:
        n = len(grid)

        def can_reach(t: int) -> bool:
            seen = {(0, 0)}
            queue = deque([(0, 0)])
            while queue:
                r, c = queue.popleft()
                if (r, c) == (n - 1, n - 1):
                    return True
                for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                    if 0 <= nr < n and 0 <= nc < n and (nr, nc) not in seen and grid[nr][nc] <= t:
                        seen.add((nr, nc))
                        queue.append((nr, nc))
            return False

        lo, hi = max(grid[0][0], grid[n - 1][n - 1]), n * n - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if can_reach(mid):
                hi = mid                           # mid works: the answer is mid or earlier
            else:
                lo = mid + 1                       # mid is too early
        return lo
Time O(n² log n)Space O(n²)

log₂(n²) = 2 log₂ n checks, each an O(n²) BFS.

When to use: Easy to get right, and the pattern carries over to many 'smallest value that works' questions.

Treat every square as a node and define the cost of a route as the highest elevation on it. Run Dijkstra with that cost:

  1. Push (grid[0][0], 0, 0) and mark (0, 0).
  2. Pop the lowest (level, r, c). If it is the corner, return level.
  3. For each unmarked neighbour, mark it and push (max(level, grid[nr][nc]), nr, nc).

The heap always expands the lowest square touching the area you can already reach, like rising water spilling into the lowest gap. Levels never drop along a route, so pops come out in non-decreasing order and the corner's pop level is the minimum possible. Marking when pushed is safe here: the first offer a square gets comes from the lowest popped neighbour, and any later neighbour has a level at least as high, so it could never offer less.

Same O(n² log n) as binary search, but a single pass that stops as soon as the corner is reached.

Dry run

  1. grid = [[0, 8, 1], [2, 7, 3], [4, 6, 5]]: heap [(0, (0,0))]
  2. Pop (0, (0,0)) → push (2, (1,0)), (8, (0,1))
  3. Pop (2, (1,0)) → push (4, (2,0)), (7, (1,1))
  4. Pop (4, (2,0)) → push (6, (2,1)). Pop (6, (2,1)) → push (max(6, 5) = 6, (2,2))
  5. Pop (6, (2,2)): the corner → answer 6

Python

class Solution:
    def swimInWater(self, grid: List[List[int]]) -> int:
        n = len(grid)
        heap = [(grid[0][0], 0, 0)]                # (highest elevation on the way here, r, c)
        seen = {(0, 0)}
        while heap:
            level, r, c = heapq.heappop(heap)      # the lowest square we can spill into next
            if (r, c) == (n - 1, n - 1):
                return level
            for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                if 0 <= nr < n and 0 <= nc < n and (nr, nc) not in seen:
                    seen.add((nr, nc))             # safe here: the first offer is the lowest it will get
                    heapq.heappush(heap, (max(level, grid[nr][nc]), nr, nc))
        return -1                                  # unreachable for valid input
Time O(n² log n)Space O(n²)

Each of the n² squares is pushed and popped once; heap operations cost O(log n²) = O(log n).

When to use: The standard answer. Mention the binary-search version as the alternative with the same bound.

Common mistakes

  • Starting the level at 0 instead of grid[0][0]: you are standing on the start square, so t can never be smaller than its elevation.
  • Adding elevations up as in ordinary Dijkstra. The cost of a route is its highest square: combine with max.
  • Copying 'mark visited when pushed' into other Dijkstra problems. It is safe here only because the cost of entering a square depends on that square alone and pops come out in non-decreasing order; in Network Delay Time a node must be final only when popped.
  • Binary-search bounds that exclude the answer. The answer lies in [max(grid[0][0], grid[n-1][n-1]), n² - 1]; with lo < hi and hi = mid on success, the loop ends exactly on it.
  • A recursive DFS for the reachability check: a 50 × 50 grid can need 2500 nested calls, beyond Python's default recursion limit. Use BFS with a deque.

Python notes

  • Heap entries (level, r, c) compare by level first, so heapq.heappop always returns the lowest reachable square.
  • for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)): lists the four neighbours; check 0 <= nr < n and 0 <= nc < n before indexing, because negative indices silently wrap around in Python.
  • A set of (r, c) tuples works as the visited set; a 2-D list of booleans is a little faster for a fixed grid.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Path With Minimum Effort LC 1631 — the cost of a route is its largest difference between neighbouring heights: the same max-Dijkstra with abs(h1 - h2) as the step cost.
  • Path With Maximum Minimum Value LC 1102 — the mirror image: maximise the smallest value on the route, with a max-heap and min instead of max.
  • Last Day Where You Can Still Cross LC 1970 — binary search on the day with a BFS check, exactly like the second approach here, or union-find adding land cells in reverse.
  • Trapping Rain Water II LC 407 — a min-heap grows inward from the border and tracks the water level, the same 'expand the lowest square next' idea used for a different question.
  • Union-find instead of a heap — add squares in increasing elevation and join each to its already-added neighbours; the elevation at which (0, 0) and (n - 1, n - 1) first share a root is the answer.
  • Network Delay Time LC 743 — ordinary Dijkstra, where costs add up and a node is final only when it is popped.
