Status

Rotate a list to the right by k places, in place, using three reversals.

Problem

You are given a list of integers nums and a non-negative integer k. Rotate the list to the right by k places, in place.

One right rotation moves the last element to the front and shifts every other element one place to the right. Doing it k times sends the value at index i to index (i + k) % len(nums). k may be larger than the length of the list.

Change nums itself and return nothing.

Examples

Example 1
Input: nums = [10, 20, 30, 40, 50, 60], k = 2
Output: [50, 60, 10, 20, 30, 40]
The last two values, 50 and 60, move to the front and keep their order.
Example 2
Input: nums = [4, 5, 6], k = 5
Output: [5, 6, 4]
Five steps on a list of three is the same as 5 % 3 = 2 steps: the last two values come to the front.
Example 3
Input: nums = [7], k = 3
Output: [7]
A single value has nowhere to go.

Constraints

  • 1 <= len(nums) <= 10^5
  • -2^31 <= nums[i] <= 2^31 - 1
  • 0 <= k <= 10^5

Think first try before reading the solution

Rotating by exactly len(nums) puts every value back where it started. What does that say about a k that is bigger than the length?

Key idea

Rotating right by k takes the last k values and puts them in front of the rest, each group keeping its own order. Two facts make this easy:

  1. Rotating by n (the length) changes nothing, so only k % n matters. Reduce k first.
  2. Reversing the whole list brings the last k values to the front, but backwards, and sends the first n - k values to the back, also backwards. Reversing each of those two groups once more restores their order.

So three reversals do the whole job: reverse everything, reverse the first k, reverse the remaining n - k. Each reversal is a two-pointer swap from both ends (the same loop as Reverse String). Every value is swapped at most twice and no second list is needed: O(n) time, O(1) extra space.

Approaches from the obvious one to the one you want in an interview

One right rotation is easy to write: save the last value, shift every other value one place to the right, and put the saved value at index 0. Do that k times.

First reduce k with k %= n, because n rotations bring the list back to the start. Even then the work is about n · k moves: for n = 10^5 and k near n / 2 that is billions of assignments, far too slow.

Dry run

  1. nums = [1, 2, 3, 4], k = 2
  2. Round 1: save 4, shift → [1, 1, 2, 3], put 4 in front → [4, 1, 2, 3]
  3. Round 2: save 3, shift → [4, 4, 1, 2], put 3 in front → [3, 4, 1, 2]
  4. Each round touches all n values, and there are k rounds.

Python

class Solution:
    def rotate(self, nums: List[int], k: int) -> None:
        n = len(nums)
        k %= n                               # a full turn changes nothing
        for _ in range(k):                   # rotate right by ONE place, k times
            last = nums[-1]
            for i in range(n - 1, 0, -1):    # shift every value one place to the right
                nums[i] = nums[i - 1]
            nums[0] = last                   # the old last value wraps around to the front
Time O(n·k)Space O(1)

k rounds, each shifting n values; only one saved value is stored.

When to use: Only to understand what a rotation does; it times out on large inputs.

Every value has a known destination: the value at index i goes to index (i + k) % n. The % n makes the index wrap around the end of the list, and it also takes care of a k bigger than n.

Write each value into its destination in a new list rotated, then copy rotated back into nums. One pass, O(n) time. The price is a second list of the same size, and the copy-back must be nums[:] = rotated, because the function has to change the list the caller passed in.

Dry run

  1. nums = [1, 2, 3, 4], k = 2, rotated = [0, 0, 0, 0]
  2. i = 0: 1 goes to (0 + 2) % 4 = 2; i = 1: 2 goes to 3; i = 2: 3 goes to (2 + 2) % 4 = 0; i = 3: 4 goes to 1
  3. rotated = [3, 4, 1, 2], copied back into nums.

Python

class Solution:
    def rotate(self, nums: List[int], k: int) -> None:
        n = len(nums)
        rotated = [0] * n
        for i in range(n):
            rotated[(i + k) % n] = nums[i]   # value i lands k places to the right, wrapping around
        nums[:] = rotated                    # copy back INTO the same list object
Time O(n)Space O(n)

One pass over n values; the second list holds n values.

When to use: When O(n) extra memory is fine. Simple and hard to get wrong.

Reduce k with k %= n, then reverse three ranges, each with the two-pointer swap loop:

  1. the whole list: the last k values come to the front, but backwards;
  2. the first k values: they are back in their original order;
  3. the remaining n - k values: also back in their original order.

Each reversal swaps pairs from both ends until the pointers meet. Every value is touched at most twice, so the total is O(n) time, and only two index variables are used: O(1) extra space.

Dry run

  1. nums = [1, 2, 3, 4, 5, 6, 7], k = 3
  2. Reverse all → [7, 6, 5, 4, 3, 2, 1]: the values 5, 6, 7 are now in front, but backwards.
  3. Reverse the first 3 → [5, 6, 7, 4, 3, 2, 1]
  4. Reverse the remaining 4 → [5, 6, 7, 1, 2, 3, 4]

Python

class Solution:
    def rotate(self, nums: List[int], k: int) -> None:
        n = len(nums)
        k %= n                               # rotating by n is the same as not rotating

        def reverse(left: int, right: int) -> None:
            while left < right:
                nums[left], nums[right] = nums[right], nums[left]
                left += 1
                right -= 1

        reverse(0, n - 1)                    # 1) whole list: the last k values lead, but backwards
        reverse(0, k - 1)                    # 2) first k values: back in their original order
        reverse(k, n - 1)                    # 3) remaining n - k values: back in their original order
Time O(n)Space O(1)

Each value is swapped at most twice; only the indices left and right are stored.

When to use: The in-place answer interviewers expect. The reversal idea is reused in Rotate Image and Reverse Words.

Common mistakes

  • Forgetting k %= n. With n = 3 and k = 5, reverse(0, k - 1) runs past the end of the list and raises IndexError, and a plain nums[-k:] + nums[:-k] slice silently returns the wrong list. Reduce k first.
  • Writing nums = rotated instead of nums[:] = rotated. The first only rebinds the local name nums, so the caller's list is never changed. The slice assignment copies the values into the same list object.
  • Rotating the wrong way. Reversing the first n - k values and then the last k values turns a right rotation into a left one. For a right rotation, reverse everything first, then the first k, then the rest.
  • Off-by-one in the reversal bounds: the second reversal is reverse(0, k - 1) and the third is reverse(k, n - 1). Both ends are inclusive indices.
  • Shifting by one place k times. It is correct, but with n = 10^5 and k near n / 2 that is billions of moves.

Python notes

  • nums[:] = rotated assigns into the existing list, so the caller sees the change. nums = rotated does not.
  • The one-liner nums[:] = nums[-k:] + nums[:-k] also works once k %= n has run (and for k = 0, because nums[:-0] is empty and nums[-0:] is the whole list). It builds two temporary lists, so it uses O(n) extra memory.
  • nums[left], nums[right] = nums[right], nums[left] swaps two values without a temporary variable.
  • k %= n is the same as k = k % n; Python's % gives a non-negative result for a positive n.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Rotate List LC 61 — the same rotation on a linked list: join the tail to the head to make a ring, then cut it after node number n - k % n (counting the head as 1), which becomes the new tail.
  • Rotate Image LC 48 — rotate a square matrix 90 degrees in place: transpose it, then reverse every row. It is the same 'reverse to move things' idea in two dimensions.
  • Reverse String LC 344 — the swap-from-both-ends loop that each of the three reversals here is made of.
  • Reverse Words in a String LC 151 — reverse the whole string, then reverse each word on its own: the same trick with word boundaries.
  • Rotate String LC 796 — is goal some rotation of s? Both must have the same length, and then goal in s + s decides it.
  • Rotate with cycles (juggling) — a fourth O(n) / O(1) method: follow i -> (i + k) % n, carrying one value along each cycle. There are gcd(n, k) cycles, so stop after n moves in total. Harder to get right than three reversals.
