Valid Anagram Easy

LeetCode #242 ↗
Status

Check whether one word is a rearrangement of the other's letters.

Problem

You are given two strings s and t. Return True if t is an anagram of s, and False otherwise.

An anagram uses exactly the same characters as the original, each one the same number of times, possibly in a different order. "listen" and "silent" are anagrams; "aacc" and "ccac" are not (two as versus one).

Examples

Example 1
Input: s = "anagram", t = "nagaram"
Output: true
Both contain a × 3, n × 1, g × 1, r × 1, m × 1.
Example 2
Input: s = "rat", t = "car"
Output: false
t has a c that s does not have.
Example 3
Input: s = "aacc", t = "ccac"
Output: false
Same set of letters, but s has two as and t has only one.

Constraints

  • 1 <= len(s), len(t) <= 5 * 10^4
  • s and t consist of lowercase English letters

Think first try before reading the solution

If the two strings have different lengths, can they be anagrams?
Order does not matter, only how many times each character appears. How could you record those counts?

Key idea

An anagram is a rearrangement, so positions carry no information. What has to match is the multiset: each character together with how many times it occurs.

There are two standard ways to compare multisets. Put both strings into a fixed order (sort them) and compare position by position, or count characters in a dictionary. Counting is a single pass: +1 for every character of s, -1 for every character of t. If the strings have equal length and no count ever has to drop below zero, every count ends at exactly zero and the strings are anagrams.

Approaches from the obvious one to the one you want in an interview

Copy t into a list. For every character of s, find one equal character in the list and remove it. If some character of s has no partner left, the strings are not anagrams. If the lengths match and every character found a partner, nothing is left over and they are.

It is correct but slow: c in remaining and remaining.remove(c) both scan the list, so each of the n characters costs O(n), O(n²) in total.

Dry run

  1. s = "rat", t = "car" → remaining = [c, a, r]
  2. r found → remove → [c, a]; a found → remove → [c]
  3. t is not in [c] → False

Python

class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
        remaining = list(t)
        for c in s:
            if c not in remaining:             # O(n) scan
                return False
            remaining.remove(c)                # removes one copy, O(n)
        return True                            # equal lengths and every character matched
Time O(n²)Space O(n)

n characters, each needing a linear scan and a linear removal in a list of up to n items.

When to use: Never in practice; it shows that the expensive part is searching for each character.

Sorting puts characters in a fixed order, so two anagrams become the same sequence: "anagram" and "nagaram" both sort to aaagmnr. Compare the sorted versions and you are done.

It is short and hard to get wrong, but sorting costs O(n log n), more than needed to compare counts.

Dry run

  1. sorted("anagram") = a a a g m n r
  2. sorted("nagaram") = a a a g m n r → equal → True
  3. sorted("rat") = a r t, sorted("car") = a c r → differ at position 1 → False

Python

class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        return len(s) == len(t) and sorted(s) == sorted(t)
Time O(n log n)Space O(n)

Two sorts of length n; sorted builds new lists of n characters.

When to use: A fine first answer and a good one-liner; mention that counting is faster.

Watch it run

Count how often each character occurs in s. Then walk t and use up one count per character. If t asks for a character whose count is already 0, t has more of it than s does: not an anagram.

Why no final check is needed: the lengths are equal, so the total of all counts goes from n down to exactly 0. Since no single count went below zero, every count must be exactly zero at the end.

Each character costs one dictionary update, so this is O(n). The dictionary holds at most one entry per distinct character: 26 for lowercase letters, so O(1) extra space.

Dry run

  1. s = "anagram" → count = {a: 3, n: 1, g: 1, r: 1, m: 1}
  2. t = "nagaram": n → 0, a → 2, g → 0, a → 1, r → 0, a → 0, m → 0
  3. no count was needed while already 0 → True

Python

class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
        count = {}                             # character -> how many are still unmatched
        for c in s:
            count[c] = count.get(c, 0) + 1
        for c in t:
            if count.get(c, 0) == 0:           # t needs a c that s cannot supply
                return False
            count[c] -= 1
        return True                            # equal lengths + no shortage -> all counts are 0
Time O(n)Space O(1)

Two linear passes. At most 26 keys for lowercase letters (O(k) for an alphabet of k characters).

When to use: The interview answer. A [0] * 26 list instead of a dict is the same idea and slightly faster.

Common mistakes

  • Skipping the length check. The "decrement and stop at zero" loop only proves t uses nothing more than s has; with s = "ab", t = "a" it would wrongly return True.
  • Comparing sets: set("aacc") == set("ccac") is True because a set forgets how many times each letter occurs.
  • The 26-slot list version indexes with ord(c) - ord("a"), which assumes lowercase letters. "Z" gives index -7, which Python silently treats as slot 19 (the t slot); an emoji gives an index far past 25 and raises IndexError. A dict works for any character.
  • sorted(s) returns a list, not a string. Comparing two lists works; if you need a string (for example as a key), use "".join(sorted(s)).

Python notes

  • collections.Counter(s) == Counter(t) is the idiomatic one-liner; two Counters are equal when every key has the same count.
  • count.get(c, 0) reads a count with a default of 0, so unseen characters do not raise KeyError. defaultdict(int) is the alternative.
  • ord(c) - ord("a") maps "a".."z" to 0..25, which is how the fixed-size list version picks a slot.
