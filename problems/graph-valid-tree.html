Graph Valid Tree Medium

LeetCode #261 ↗
Status

Decide whether a list of undirected edges joins n nodes into a single tree.

Problem

You are given n nodes labelled 0 to n - 1 and a list edges, where edges[i] = [a, b] is an undirected edge between nodes a and b.

Return True if these edges form a valid tree, and False otherwise. A tree is a graph that is

  • connected: every node can be reached from every other node, and
  • acyclic: there is no loop, so between any two nodes there is exactly one path.

There are no self-loops (a != b) and no edge is listed twice.

Examples

Example 1
Input: n = 5, edges = [[0, 1], [0, 2], [0, 3], [1, 4]]
Output: true
Node 0 connects to 1, 2 and 3, and node 4 hangs off 1. Everything is reachable and there is no loop.
Example 2
Input: n = 5, edges = [[0, 1], [1, 2], [2, 3], [1, 3], [1, 4]]
Output: false
1 → 2 → 3 → 1 is a loop.
Example 3
Input: n = 4, edges = [[0, 1], [2, 3]]
Output: false
No loop, but {0, 1} and {2, 3} are two separate pieces.

Constraints

  • 1 <= n <= 2000
  • 0 <= len(edges) <= 5000
  • 0 <= a, b < n and a != b
  • no repeated edges

Think first try before reading the solution

A tree must be connected and have no cycle. Draw a few trees: how many edges does a tree on n nodes have?
Always exactly n - 1. Any other edge count is an immediate False, and with exactly n - 1 edges, 'connected' and 'no cycle' imply each other, so you only have to check one of them.
After the edge count check, run one DFS or BFS from node 0 and see whether it reaches all n nodes. Alternatively, union-find: no edge may join two nodes that are already connected.

Key idea

Picture the n nodes as n separate pieces. Adding an edge does one of two things: it joins two different pieces (one piece fewer), or both ends are already in the same piece and it closes a cycle. A tree ends as exactly one piece with no cycle, so every edge must have been a joining edge, and going from n pieces to 1 takes exactly n - 1 of them.

That gives a cheap first test: if len(edges) != n - 1, answer False. With exactly n - 1 edges, a cycle would waste an edge and leave at least two pieces, so "connected" already proves "no cycle". One traversal from node 0 that reaches all n nodes finishes the job in O(V + E).

Approaches from the obvious one to the one you want in an interview

Build the graph one edge at a time. Before adding edge a–b, run a search from a: if it already reaches b, the new edge would create a second route between them, which is a cycle, so return False. If every edge goes in without a cycle, the graph is a forest (a set of trees); it is one tree exactly when it has n - 1 edges.

Correct, but each edge pays for a fresh search over the graph built so far: O(E · (V + E)) in total.

Dry run

  1. n = 5, edges [[0, 1], [1, 2], [2, 3], [1, 3], [1, 4]]
  2. 0–1: no path from 0 to 1 yet → add. 1–2 → add. 2–3 → add.
  3. 1–3: a search from 1 finds 1 → 2 → 3 → a path exists → this edge closes a cycle → False.

Python

class Solution:
    def validTree(self, n: int, edges: List[List[int]]) -> bool:
        graph = {node: [] for node in range(n)}

        def connected(a: int, b: int) -> bool:     # is there already a path from a to b?
            seen = {a}
            stack = [a]
            while stack:
                node = stack.pop()
                if node == b:
                    return True
                for nxt in graph[node]:
                    if nxt not in seen:
                        seen.add(nxt)
                        stack.append(nxt)
            return False

        for a, b in edges:
            if connected(a, b):                    # a second route a-b would form a cycle
                return False
            graph[a].append(b)
            graph[b].append(a)
        return len(edges) == n - 1                 # a forest with n - 1 edges is a single tree
Time O(E · (V + E))Space O(V + E)

One search per edge, each over the graph built so far.

When to use: Only as the first idea; it repeats a full search per edge.

Use the counting fact: a tree on n nodes has exactly n - 1 edges. So:

  1. If len(edges) != n - 1, return False straight away.
  2. Otherwise build the adjacency list and run one DFS (or BFS) from node 0.
  3. Return whether it reached all n nodes.

Step 3 is enough because with exactly n - 1 edges a cycle would waste an edge, and the graph could then not be connected. Connected plus n - 1 edges therefore means no cycle. One traversal: O(V + E), and E = n - 1 here.

Dry run

  1. n = 5, edges [[0, 1], [0, 2], [0, 3], [1, 4]]: 4 edges = n - 1 ✓
  2. DFS from 0 reaches 1, 2, 3, then 4 via 1 → 5 nodes seen = n → True
  3. n = 4, edges [[0, 1], [1, 2], [2, 0]]: 3 edges = n - 1, but the DFS reaches only {0, 1, 2} → False

Python

class Solution:
    def validTree(self, n: int, edges: List[List[int]]) -> bool:
        if len(edges) != n - 1:                    # a tree on n nodes has exactly n - 1 edges
            return False
        graph = {node: [] for node in range(n)}
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)
        seen = {0}
        stack = [0]
        while stack:
            node = stack.pop()
            for nxt in graph[node]:
                if nxt not in seen:
                    seen.add(nxt)
                    stack.append(nxt)
        return len(seen) == n                      # connected + n - 1 edges => no cycle
Time O(V + E)Space O(V + E)

One pass to build the lists and one traversal; E = n - 1 whenever the search runs.

When to use: The simplest correct answer. Say the n - 1 argument out loud: it is what interviewers listen for.

Watch it run

Union-find (also called a disjoint set) keeps the nodes in groups. Each group is a small tree of parent pointers whose top node, the root, names the group. find(x) climbs from x to its root; union hangs one root under the other.

Process the edges one by one. If both ends already have the same root, they are already connected and this edge closes a cycle: return False. Otherwise merge their groups. With the n - 1 count checked first, n - 1 successful merges leave a single group, so the graph is also connected.

Two tricks keep the trees flat: path halving (while climbing, point each node at its grandparent) and union by size (hang the smaller group under the larger one). Together they make each operation amortised nearly O(1): averaged over all calls, the cost per call is O(α(n)), where α grows so slowly it is below 5 for any realistic n.

Dry run

  1. n = 4, edges [[0, 1], [1, 2], [2, 0]]: 3 edges = n - 1 ✓; parent = [0, 1, 2, 3]
  2. 0–1: roots 0 and 1 differ → parent[1] = 0. 1–2: roots 0 and 2 differ → parent[2] = 0
  3. 2–0: find(2) = 0 and find(0) = 0, the same root → already connected → cycle → False

Python

class Solution:
    def validTree(self, n: int, edges: List[List[int]]) -> bool:
        if len(edges) != n - 1:
            return False
        parent = list(range(n))                    # every node starts as the root of its own group
        size = [1] * n

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]      # path halving: skip one level while climbing
                x = parent[x]
            return x

        for a, b in edges:
            root_a, root_b = find(a), find(b)
            if root_a == root_b:                   # already connected: this edge closes a cycle
                return False
            if size[root_a] < size[root_b]:
                root_a, root_b = root_b, root_a
            parent[root_b] = root_a                # union by size: smaller group under the larger
            size[root_a] += size[root_b]
        return True                                # n - 1 merges and no cycle => one tree
Time O(V + E · α(V))Space O(V)

α is the inverse Ackermann function, effectively a constant; no adjacency list is needed.

When to use: When edges arrive one at a time (online), or when you will reuse the same structure for Redundant Connection and Number of Connected Components. Same speed as DFS in practice.

Common mistakes

  • Checking only the edge count. n = 4, [[0, 1], [1, 2], [2, 0]] has the right count (3) but contains a cycle and leaves node 3 alone.
  • Checking only connectivity. A connected graph with one edge too many always contains a cycle.
  • Detecting cycles in an undirected DFS without remembering where you came from: the parent is always already visited, so every edge looks like a cycle. The edge-count shortcut avoids the issue; otherwise skip the parent.
  • In union-find, comparing a == b instead of find(a) == find(b). Two nodes are connected when their groups share a root, not when their labels match.
  • Forgetting that n = 1 with no edges is a valid tree (one node, zero edges = n - 1).

Python notes

  • {node: [] for node in range(n)} gives every node an entry, so a node with no edges still exists in the graph.
  • len(seen) == n is the whole connectivity test once the search is over.
  • parent = list(range(n)) is the usual union-find start: every node is the root of its own one-node group.
  • An explicit stack (stack.append, stack.pop()) avoids Python's recursion limit on long chains.
