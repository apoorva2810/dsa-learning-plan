Minimum Array End Medium 250

LeetCode #3133 ↗
Status

Build a strictly increasing array of n positive integers whose bitwise AND is x, and make its last element as small as possible.

Problem

You are given two positive integers n and x. Build an array nums of n positive integers that is strictly increasing (every element is bigger than the one before it) and whose bitwise AND is exactly x. The AND of the array looks at each binary position on its own: the result has a 1 there only if every element has a 1 there.

Return the smallest possible value of the last element, nums[n - 1].

Examples

Example 1
Input: n = 4, x = 5
Output: 15
The array [5, 7, 13, 15] (101, 111, 1101, 1111) increases, every element keeps the 1-bits of 101, and their AND is 5. No valid array ends lower.
Example 2
Input: n = 3, x = 6
Output: 14
[6, 7, 14] (110, 111, 1110): every element keeps the 1-bits of 110, and their AND is 6.
Example 3
Input: n = 1, x = 9
Output: 9
A one-element array must be [x] itself.

Constraints

  • 1 <= n, x <= 10^8

Key idea

For the AND of the array to be exactly x, every element must keep all of x's 1-bits: one element with a 0 in such a position would put a 0 in the AND. So only numbers that contain every 1-bit of x may be used.

The reverse also holds. If the array starts with x and every other element contains the 1-bits of x, the AND is exactly x: no bit of x can be lost, and no extra bit can appear because x itself is in the array. The best array therefore uses the n smallest allowed numbers, and its last element is the n-th allowed number, counting x as the first.

What do the allowed numbers look like? The positions where x has a 1 are fixed. The positions where x has a 0 are free. Listing the allowed numbers from smallest to largest is counting in binary, except that the counter's digits are written only into the free positions. For x = 5 (101) the free positions are 1, 3, 4, 5, ... and the allowed numbers are 5, 7, 13, 15, 21, ...

So the last element is x with the binary digits of n - 1 placed into its free positions, lowest digit first (the first element has index 0, so the last one has index n - 1). Walk the positions from bit 0 upward: at a position where x has a 1, do nothing; at a free position, take the next digit of n - 1 and set the bit if the digit is 1. Stop when the digits run out. That is at most about 54 positions, so the cost is O(log x + log n), however large n is.

Approaches from the obvious one to the one you want in an interview

Start the array at x, the smallest number that can begin it. Then pick each next element as small as possible while it still keeps every 1-bit of x and stays above the previous one. That number is (previous + 1) | x: adding 1 gives the next integer, but the carry may have wiped some of x's 1-bits, and OR-ing with x puts them back. (This is the smallest such number because the previous element already contains x.)

After n - 1 steps cur is the last element, so the array never has to be stored. It is correct, but it takes n - 1 steps, up to 10^8 here, which is far too slow.

Dry run

  1. cur = 5 (101)
  2. (5 + 1) | 5 = 110 | 101 = 111, cur = 7
  3. (7 + 1) | 5 = 1000 | 101 = 1101, cur = 13
  4. (13 + 1) | 5 = 1110 | 101 = 1111, cur = 15. Return 15

Python

class Solution:
    def minEnd(self, n: int, x: int) -> int:
        cur = x                              # nums[0] = x is the smallest possible start
        for _ in range(n - 1):
            cur = (cur + 1) | x              # next number above cur that still contains every 1-bit of x
        return cur
Time O(n)Space O(1)

One step per element after the first. For n = 10^8 that is a hundred million loop rounds.

When to use: To see what a valid array looks like and to check the fast version on small inputs.

Every element has to keep the 1-bits of x, so the allowed numbers differ only in the positions where x has a 0. In increasing order they count up in binary, with the counter's digits written into those free positions. The last element is the allowed number with index n - 1, so write the binary digits of n - 1 into the free positions of x, lowest digit first.

Walk the positions from bit 0 upward. Where x has a 1, skip the position. Where x has a 0, look at the lowest remaining digit of k = n - 1: if it is 1, set the bit in the result; either way, drop that digit. Stop when no digits are left.

Dry run

  1. x = 5 (101), n - 1 = 3 (11), result = 5
  2. position 0: x has a 1, skip
  3. position 1: free, lowest digit of k is 1, set it: result = 111 (7)
  4. position 2: x has a 1, skip
  5. position 3: free, last digit of k is 1, set it: result = 1111 (15). No digits left: return 15

Python

class Solution:
    def minEnd(self, n: int, x: int) -> int:
        k = n - 1                            # index of the last element among the allowed numbers (x has index 0)
        result = x
        bit = 1                              # the position we are looking at, as a power of two
        while k:                             # until every binary digit of k has been placed
            if (x & bit) == 0:               # x has a 0 here: a free position
                if k & 1:                    # the next digit of k is 1 ...
                    result |= bit            # ... so set this position
                k >>= 1                      # that digit is used up
            bit <<= 1                        # move to the next position
        return result
Time O(log x + log n)Space O(1)

At most about 54 positions: the bits of x (up to 27) plus the digits of n - 1 (up to 27) that still have to find a free place.

When to use: The interview answer. Explain why only numbers that keep x's 1-bits are allowed, and why they count like an odometer.

Common mistakes

  • Answering x + n - 1. For x = 5, n = 4 that is 8, which contains none of the 1-bits of 5, so the AND would be 0. Counting up from x runs into the 1-bits of x; they must be skipped, not changed.
  • Using n instead of n - 1. The first element is x itself, so it has index 0. With n = 1 the digits of 0 leave x untouched, which is correct.
  • Putting the lowest digit of n - 1 into the highest free position. The lowest digit goes into the lowest free position.
  • Stopping at the length of x. Free positions continue above the top bit of x: for x = 1, n = 3 the answer is 101 (5), which uses bit 2. Keep going while digits of n - 1 remain.
  • Overflow in Java or C++. The answer can be about 6.7 x 10^15 (for x = 67108863, n = 10^8), far beyond a 32-bit int. Use a 64-bit integer.

Python notes

  • k & 1 is the lowest bit of k and k >>= 1 drops it, so the loop consumes the digits of n - 1 lowest first.
  • result |= bit sets one bit. (x & bit) == 0 tests whether the position bit (a power of two) is free; keep the parentheses, because in C, C++ and Java == binds tighter than &.
  • This operation, depositing the low bits of one number into the positions chosen by a mask, is called a parallel bit deposit. Many x86 processors have it as a single instruction, PDEP. Here the mask is the set of positions where x has a 0.
  • Python integers do not overflow, so the answer needs no special type even when it is far above 2^31.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Bitwise AND of Numbers Range LC 201 — another AND over an increasing run of integers, asked the other way round: the numbers are given and the AND is unknown.
  • Subsets LC 78 — counting from 0 to 2^n - 1 in binary lists every subset, one bitmask per subset. Here the counter's digits go only into the free positions of x.
  • Gray Code LC 89 — another way to run through all n-bit patterns, ordered so that neighbours differ in exactly one bit.
  • What if the array only has to be non-decreasing? — then [x, x, ..., x] works and the answer is x. The strict increase is what forces the array to climb.
  • Walk through all supersets or submasks of a mask — s = (s + 1) | mask steps through the numbers that contain mask, in increasing order (the brute-force approach here). Its mirror image s = (s - 1) & mask steps through the submasks of mask, the classic loop in bitmask DP.
