Minimum Height Trees Medium 250

LeetCode #310 ↗
Status

Find the node(s) that, used as the root, give the tree its smallest possible height.

Problem

You get a tree with n nodes labelled 0 to n - 1: edges holds n - 1 undirected pairs [a, b], every node is reachable from every other, and there are no cycles.

Pick any node as the root and the tree hangs down from it; its height is the number of edges on the longest path from the root down to a leaf. Different roots give different heights. Return every node that, as the root, gives the minimum possible height. There are always one or two such nodes; return them in any order.

Examples

Example 1
Input: n = 4, edges = [[1, 0], [1, 2], [1, 3]]
Output: [1]
Rooted at 1 the height is 1. Rooted at any other node it is 2.
Example 2
Input: n = 6, edges = [[3, 0], [3, 1], [3, 2], [3, 4], [5, 4]]
Output: [3, 4]
Rooted at 3 or at 4 the height is 2; every other root gives 3.
Example 3
Input: n = 7, edges = [[0, 1], [0, 2], [1, 3], [1, 4], [2, 5], [5, 6]]
Output: [0, 2]
The longest path is 3 – 1 – 0 – 2 – 5 – 6, six nodes, so its two middle nodes 0 and 2 both give height 3.

Constraints

  • 1 <= n <= 2 * 10^4
  • len(edges) == n - 1, edges[i] = [a, b] with 0 <= a, b < n and a != b
  • no repeated edges; the edges form a tree (connected, acyclic)

Think first try before reading the solution

Trying every node as the root and measuring the height is correct but O(n²). Which nodes are obviously bad roots?
A leaf. Move the root from a leaf to its only neighbour and the tree gets shorter. So peel off all the leaves; the leaves of what remains are the next-worst roots.
Peel one whole layer of leaves at a time, using degrees and a queue like Kahn's algorithm, until one or two nodes remain. Those are the centres.

Key idea

A leaf is never the best root (unless the tree has at most two nodes): shift the root from the leaf to its single neighbour, and every other node gets one step closer while only the leaf itself gets one step farther. So peel all the leaves off. The tree that remains has new leaves, which are the next-worst roots; peel them too. The one or two nodes left standing at the end are the centres, the roots of minimum height.

Why one or two? Take any longest path in the tree. Each round of peeling removes exactly one node from each end of it, so the path shrinks evenly towards its middle: a single middle node if the path has an odd number of nodes, two adjacent middle nodes if even. The same argument shows that the best height equals the number of peeling rounds (plus one when two centres remain).

The implementation is Kahn's algorithm with degree 1 instead of in-degree 0: keep each node's degree, queue the current leaves, peel a whole layer per round, and lower the degree of each leaf's remaining neighbour. A neighbour that drops to degree 1 is a leaf for the next round. Every node and edge is handled once: O(n).

Approaches from the obvious one to the one you want in an interview

Do exactly what the statement says: for each node, root the tree there and measure the height with a breadth-first search (the number of levels below the root). Then return every node whose height equals the minimum.

Each BFS touches all n nodes, and there are n candidates: O(n²), or 4 · 10⁸ steps at the upper limit. The waste is that neighbouring roots have almost the same height, yet each is measured from scratch.

Dry run

  1. Example 1: height from 1 → levels {1}, {0, 2, 3} → 1
  2. Height from 0 → levels {0}, {1}, {2, 3} → 2; same for 2 and 3
  3. Minimum 1, reached only by node 1 → [1]

Python

class Solution:
    def findMinHeightTrees(self, n: int, edges: List[List[int]]) -> List[int]:
        graph = [[] for _ in range(n)]
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)

        def height(root: int) -> int:                # BFS: number of levels below root
            seen = {root}
            frontier = [root]
            levels = -1
            while frontier:
                levels += 1
                nxt = []
                for node in frontier:
                    for nb in graph[node]:
                        if nb not in seen:
                            seen.add(nb)
                            nxt.append(nb)
                frontier = nxt
            return levels

        heights = [height(root) for root in range(n)]
        best = min(heights)
        return [root for root in range(n) if heights[root] == best]
Time O(n²)Space O(n)

n breadth-first searches, each over all n nodes and n - 1 edges.

When to use: Only to confirm an answer on a tiny tree; far too slow for 20 000 nodes.

A leaf is never a best root, so remove all leaves; the new leaves of the smaller tree are the next-worst roots, so remove them too. Repeat until one or two nodes remain: the centres.

Mechanics, borrowed from Kahn's algorithm: compute every node's degree, queue the degree-1 nodes, and peel one whole layer per round. Peeling a leaf lowers its remaining neighbour's degree; a neighbour that drops to 1 is a leaf for the next round. Stop when remaining <= 2. Each round takes one node off each end of every longest path, so the survivors are the middle of the longest path: one node if it has an odd number of nodes, two if even. Every node is peeled once and every edge lowered once: O(n).

Dry run

  1. Example 3: degrees [2, 3, 2, 1, 1, 2, 1]; leaves 3, 4, 6; remaining 7
  2. Round 1: peel 3 and 4 → degree of 1 drops to 1 (new leaf); peel 6 → degree of 5 drops to 1 (new leaf). Remaining 4
  3. Round 2: peel 1 → degree of 0 drops to 1; peel 5 → degree of 2 drops to 1. Remaining 2 → stop
  4. Survivors 0 and 2 → [0, 2], minimum height 3

Python

class Solution:
    def findMinHeightTrees(self, n: int, edges: List[List[int]]) -> List[int]:
        if n <= 2:
            return list(range(n))                     # one or two nodes: every node is a centre
        graph = [[] for _ in range(n)]
        degree = [0] * n
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)
            degree[a] += 1
            degree[b] += 1
        leaves = deque(node for node in range(n) if degree[node] == 1)
        remaining = n
        while remaining > 2:
            layer = len(leaves)                       # peel one whole layer per round
            remaining -= layer
            for _ in range(layer):
                leaf = leaves.popleft()
                degree[leaf] = 0                      # mark as peeled
                for nb in graph[leaf]:
                    if degree[nb] > 0:                # the neighbour still standing
                        degree[nb] -= 1
                        if degree[nb] == 1:           # nb has become a leaf
                            leaves.append(nb)
        return list(leaves)
Time O(n)Space O(n)

Each node is queued and peeled once; each edge lowers one degree once.

When to use: The expected answer: linear time, no recursion, and the same shape as Kahn's algorithm.

Watch it run

The centres are the middle of the tree's diameter, its longest path. Two breadth-first searches find that path: BFS from any node and take a farthest node u; a farthest node from anywhere is always one end of a longest path. Then BFS from u and take its farthest node v, recording parents. The parent pointers give the path u … v; return its middle node, or the two middle nodes when the path has an even number of nodes.

Also O(n), with two passes instead of one. It is the right tool when you need the diameter anyway (Tree Diameter) or want the minimum height directly: it is len(path) // 2.

  2. BFS from 5 → farthest node is 0, 1 or 2 (distance 3); say 2, with path 5 – 4 – 3 – 2
  3. Four nodes, even → the two middle nodes 4 and 3 → [4, 3]

Python

class Solution:
    def findMinHeightTrees(self, n: int, edges: List[List[int]]) -> List[int]:
        graph = [[] for _ in range(n)]
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)

        def farthest(start: int):                     # BFS: (a farthest node, parent pointers)
            parent = {start: None}
            frontier = [start]
            last = start
            while frontier:
                nxt = []
                for node in frontier:
                    for nb in graph[node]:
                        if nb not in parent:
                            parent[nb] = node
                            nxt.append(nb)
                if nxt:
                    last = nxt[-1]                    # any node on the deepest level
                frontier = nxt
            return last, parent

        end_a, _ = farthest(0)                        # one end of a longest path
        end_b, parent = farthest(end_a)               # the other end, with the path recorded
        path = [end_b]
        while parent[path[-1]] is not None:           # walk back to end_a
            path.append(parent[path[-1]])
        mid = len(path) // 2
        return [path[mid]] if len(path) % 2 == 1 else [path[mid - 1], path[mid]]
Time O(n)Space O(n)

Two breadth-first searches over the whole tree, then a walk along one path.

When to use: When you also need the diameter or the height value itself.

Common mistakes

  • Peeling leaves one at a time and checking remaining > 2 after each one. A node that becomes a leaf halfway through a layer belongs to the next round; process a whole layer (for _ in range(len(leaves))) before testing how many nodes remain, or you can stop with the wrong survivors.
  • Forgetting n == 1. A single node has degree 0, so it is never queued as a leaf; without a special case the function returns [] instead of [0]. For n == 2 both nodes are leaves and both are centres.
  • Lowering the degree of a neighbour that was already peeled. Mark peeled nodes (degree 0) and skip them, or a removed node can be queued a second time.
  • Returning only the smallest centre. Even-length longest paths have two middle nodes and both must be returned.
  • Measuring heights with a recursive DFS in the brute force: a path of 20 000 nodes blows Python's recursion limit. Use BFS, or avoid measuring heights altogether.

Python notes

  • for _ in range(len(leaves)): processes exactly one layer even while new leaves are appended to the same deque.
  • [[] for _ in range(n)] builds n independent adjacency lists; [[]] * n would share one list.
  • list(leaves) turns the final deque into the list the problem expects.
  • In the diameter approach len(path) // 2 is integer division; len(path) % 2 tells one centre from two.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Course Schedule II LC 210 — the same queue-driven peeling, but on a directed graph with in-degree 0 instead of degree 1, and the order of removal is the answer.
  • Redundant Connection LC 684 — peel leaves off a graph with one cycle and the nodes left standing are exactly the cycle; here the survivors are the centres instead.
  • Diameter of Binary Tree LC 543 — the longest path itself. Its middle node(s) are this problem's answer, and its length is 2h or 2h - 1 for minimum height h.
  • Tree Diameter LC 1245 — the general-tree version of the diameter: two BFS passes, exactly the alternative approach here.
  • Collect Coins in a Tree LC 2603 — peel leaves twice with different rules (first coin-less leaves, then two more layers); the edges left decide the answer.
  • What if you must return the minimum height itself? — count the peeling rounds: the height is the number of rounds when one centre remains, and one more when two remain.
