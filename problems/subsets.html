Status

List every subset of a list of distinct numbers, including the empty one and the whole list.

Problem

You are given a list nums of distinct integers. Return every possible subset (the power set): all the lists you can form by keeping some of the numbers, none of them, or all of them. The empty list and nums itself both count.

  • The answer must not contain the same subset twice.
  • The subsets can be returned in any order, and inside a subset the order of the numbers does not matter ([1, 2] and [2, 1] are the same subset).

Examples

Example 1
Input: nums = [1, 2, 3]
Output: [[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]]
Eight subsets, which is 2³: each of the three numbers is either in a subset or out of it.
Example 2
Input: nums = [0]
Output: [[], [0]]
One number gives two subsets: without it and with it.
Example 3
Input: nums = [5, 9]
Output: [[], [5], [9], [5, 9]]

Constraints

  • 1 <= len(nums) <= 10
  • -10 <= nums[i] <= 10
  • all the numbers in nums are unique

Key idea

Every number has two fates: it is in a subset or it is not. For n numbers that gives 2 × 2 × … × 2 = 2ⁿ subsets, so the answer itself contains 2ⁿ lists and no algorithm can finish faster than that. The real task is to produce each subset exactly once and never miss one.

Decide the numbers one at a time, left to right. Deciding nums[0] splits all subsets into those that contain it and those that do not. Each half splits again on nums[1], and so on. Drawn out, this is a decision tree with n levels and 2ⁿ leaves, one leaf per subset.

Backtracking walks that tree depth first with one shared list, path. Append a number (choose), recurse to decide the rest (explore), then pop the number (un-choose) so the same list can serve the next branch. Reusing one list keeps the extra memory at O(n) instead of one fresh list per node of the tree.

Approaches from the obvious one to the one you want in an interview

A list of n numbers has 2ⁿ subsets, and there are also exactly 2ⁿ numbers that fit in n bits: 0, 1, 2, …, 2ⁿ − 1. Let bit i of the number say whether nums[i] is in the subset (1 = in, 0 = out). Every subset then has one number and every number describes one subset.

So loop mask over range(1 << n) and, for each mask, collect the elements whose bit is set. No recursion is needed. The cost is n bit tests for each of the 2ⁿ masks, O(n · 2ⁿ). That order of growth cannot be beaten, because the output alone has 2ⁿ lists.

The weakness is flexibility. A mask always builds the whole subset before you can judge it, so there is no way to abandon a doomed partial subset early. Problems such as Combination Sum need exactly that, which is where backtracking comes in.

Dry run

  1. nums = [1, 2, 3]: three bits, masks 0 to 7.
  2. mask = 0 (000): no bit set → [].
  3. mask = 1 (001): bit 0 → [1]. mask = 3 (011): bits 0 and 1 → [1, 2].
  4. mask = 5 (101): bits 0 and 2 → [1, 3].
  5. mask = 7 (111): every bit → [1, 2, 3]. Eight masks gave eight different subsets.

Python

class Solution:
    def subsets(self, nums: List[int]) -> List[List[int]]:
        n = len(nums)
        result = []
        for mask in range(1 << n):               # 2^n masks: 0 .. 2^n - 1
            subset = []
            for i in range(n):
                if (mask >> i) & 1:              # bit i is set: nums[i] is in this subset
                    subset.append(nums[i])
            result.append(subset)
        return result
Time O(n · 2ⁿ)Space O(n)

2ⁿ masks, each tested against n bits. Apart from the output, only the subset being built is stored.

When to use: A short, recursion-free answer for 'all subsets'. It cannot prune, so it does not carry over to problems with a target.

Watch it run

Walk through the numbers left to right and decide each one: take it or skip it. dfs(i) means "the numbers before index i are decided and path holds the ones taken". When i == len(nums) everything is decided, so path is one finished subset: store a copy.

Otherwise make two calls. First append nums[i] and call dfs(i + 1) (the take branch). Then pop it and call dfs(i + 1) again (the skip branch). The pop is the backtracking step: it restores path to what it was before the take, so the skip branch starts from the same state.

The recursion has depth n and 2ⁿ leaves, one per subset. Copying a finished subset costs up to n, so the total is O(n · 2ⁿ) again. It makes about twice as many calls as the next approach, because only the leaves record an answer, but the take / skip picture is the clearest way to see why there are 2ⁿ subsets, and it is how Combination Sum is often written.

Dry run

  1. nums = [1, 2]. dfs(0) takes 1, dfs(1) takes 2, dfs(2) records [1, 2].
  2. Back in dfs(1): pop 2, skip it → dfs(2) records [1].
  3. Back in dfs(0): pop 1, skip it. dfs(1) takes 2 → dfs(2) records [2]; pop 2, skip it → records [].
  4. result = [[1, 2], [1], [2], []]: four leaves for two numbers.

Python

class Solution:
    def subsets(self, nums: List[int]) -> List[List[int]]:
        result = []
        path = []                                # numbers taken so far

        def dfs(i: int) -> None:
            if i == len(nums):                   # every number has been decided
                result.append(path[:])           # a copy: path keeps changing
                return
            path.append(nums[i])                 # branch 1: take nums[i]
            dfs(i + 1)
            path.pop()                           # undo, so branch 2 starts from the same path
            dfs(i + 1)                           # branch 2: skip nums[i]

        dfs(0)
        return result
Time O(n · 2ⁿ)Space O(n)

The tree has 2ⁿ leaves and 2ⁿ⁺¹ − 1 calls; each leaf copies up to n numbers. The recursion is n deep.

When to use: When you want the clearest picture of the decision tree, or the problem is naturally take / skip.

Watch it run

Squash the tree so that every node is already an answer. Instead of asking "take or skip nums[i]?", let each call choose which element comes next. backtrack(start) first stores a copy of path, because every path is a subset by itself. Then it loops i from start to the end: append nums[i] (choose), call backtrack(i + 1) (explore), pop it (un-choose).

Passing i + 1 means a call only looks at elements to the right of the one just chosen. That one rule makes every subset appear exactly once, in increasing index order: [1, 3] can be built, [3, 1] never can.

There are exactly 2ⁿ calls, one per subset, which is half as many as take / skip, and every call records something. This loop with a start index is the template that Combinations, Combination Sum and Subsets II reuse.

Dry run

  1. nums = [1, 2, 3]. backtrack(0) records [], then chooses 1 and calls backtrack(1).
  2. backtrack(1) records [1], chooses 2 → backtrack(2) records [1, 2] → chooses 3 → backtrack(3) records [1, 2, 3].
  3. Pop 3 and pop 2. backtrack(1) continues with 3 → records [1, 3], then returns.
  4. Back in backtrack(0): pop 1, choose 2 → records [2], then [2, 3]; pop, choose 3 → records [3].
  5. Eight records: [], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3].

Python

class Solution:
    def subsets(self, nums: List[int]) -> List[List[int]]:
        result = []
        path = []                                # the subset being built

        def backtrack(start: int) -> None:
            result.append(path[:])               # every path is a subset: record a copy
            for i in range(start, len(nums)):    # candidates: the elements at or after start
                path.append(nums[i])             # choose
                backtrack(i + 1)                 # explore: only elements to the right of i
                path.pop()                       # un-choose

        backtrack(0)
        return result
Time O(n · 2ⁿ)Space O(n)

2ⁿ calls, each copying a path of up to n numbers. The recursion and path are at most n deep; the output is not counted.

When to use: The standard answer, and the skeleton for most of the problems that follow in this topic.

Common mistakes

  • Writing result.append(path) instead of result.append(path[:]). Every entry is then the same list object, and it is empty once the recursion has unwound.
  • Forgetting the path.pop() after the recursive call. path keeps growing across branches, so later subsets contain numbers that do not belong to them.
  • Recursing with backtrack(start + 1) instead of backtrack(i + 1) in the loop version. After choosing nums[2] the next call may pick nums[1] or nums[2] again, so subsets repeat ([3, 2] after [2, 3]) or contain a number twice.
  • Testing a bit with mask & (1 << i) == 1. In Python == binds more loosely than &, and the AND gives 2 ** i, not 1, so only bit 0 ever matches. Write (mask >> i) & 1 or compare with != 0.
  • Dropping the empty subset or the full list. Both belong in the answer, so a base case that returns early on an empty path is wrong, and range(len(nums)) should be range(len(nums) + 1) when looping over subset sizes.

Python notes

  • path[:] copies a list (so do list(path) and path.copy()). result.append(path) stores a reference, not a snapshot.
  • 1 << n is 2ⁿ, and (mask >> i) & 1 reads bit i of mask.
  • itertools.combinations(nums, r) yields every subset of size r as a tuple. Chaining it over r in range(n + 1) is a one-line cross-check for your own answer: [list(c) for r in range(n + 1) for c in itertools.combinations(nums, r)].
  • A nested function can call result.append(...) and path.append(...) without nonlocal, because that mutates an object it can see instead of rebinding a name.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Subsets II LC 90 — nums may contain repeated values but the answer must not repeat a subset: sort first, then skip a value equal to the previous one at the same depth of the recursion.
  • Combinations LC 77 — only the subsets of exactly k numbers from 1..n: the same loop, but record only when len(path) == k, and stop early when there are not enough numbers left to reach size k.
  • Letter Case Permutation LC 784 — every letter is a two-way choice (lower or upper case) and every digit has one option: the take / skip tree again.
  • Partition Equal Subset Sum LC 416 — you no longer list subsets, you only ask whether one of them sums to half the total: the 2ⁿ search collapses into a DP table over the sums that can be reached.
  • Sum of All Subset XOR Totals LC 1863 — add up a value over every subset. Enumerating works for n <= 12, but each bit that appears in any number is set in the XOR of exactly half of the subsets, so the answer is OR(nums) * 2 ** (n - 1).
  • What if n is 30? — 2³⁰ lists cannot be stored. Return a generator that yields one subset at a time (the bitmask loop converts directly), or ask what the caller really needs: a count (2ⁿ) or one subset with a property.
