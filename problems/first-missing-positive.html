First Missing Positive Hard 250

LeetCode #41 ↗
Status

Find the smallest positive integer that is missing from an unsorted list, in O(n) time and O(1) extra space.

Problem

You are given an unsorted list of integers nums. Return the smallest positive integer (1, 2, 3, ...) that does not appear in it.

  • The list may contain zeros, negative numbers, duplicates and very large values.
  • Follow-up: run in O(n) time and use only O(1) extra space (you may rearrange the list itself).

Examples

Example 1
Input: nums = [4, 1, -3, 2, 6]
Output: 3
1, 2 and 4 are present. -3 and 6 are not in the range 1..5 that could matter, and 3 is the smallest positive number that is absent.
Example 2
Input: nums = [2, 2, 1, 5, 3]
Output: 4
1, 2, 3 and 5 are present (2 twice), so 4 is the first gap.
Example 3
Input: nums = [3, 1, 2]
Output: 4
Every value from 1 to 3 is present, so the answer is one past the end: n + 1 = 4.

Constraints

  • 1 <= len(nums) <= 10^5
  • -2^31 <= nums[i] <= 2^31 - 1
  • follow-up: O(n) time, O(1) extra space

Think first try before reading the solution

If the list has n numbers, what is the largest value the answer can possibly be? Think about what happens when the list already holds 1, 2, ..., n.
A set of all values answers 'is v present?' in O(1) but costs O(n) memory. To use O(1) memory, let the list itself be the table: which slot could mean 'the value v is here'?
Give each value v in 1..n the home slot v - 1. Swap values into their homes, repeating with whatever lands in the current slot, and ignore values outside 1..n. Then the first slot i whose value is not i + 1 tells you i + 1 is missing.

Key idea

Let n be the length of the list. The answer is always between 1 and n + 1: n numbers can cover at most the values 1..n, so either some value in 1..n is missing (and the answer is the smallest such value), or all of them are present and the answer is n + 1. Zeros, negatives and values bigger than n can never be the answer, so they are just noise.

That gives the list a job. There are n slots (indexes 0..n-1) and n interesting values (1..n). Give the value v its own home slot, index v - 1. If every value of 1..n sat in its home slot, slot i would hold i + 1, and the first slot that holds something else would point straight at the answer.

To get there with no extra memory, swap values into their homes (this is called cyclic sort, because values travel along chains of slots). Look at nums[i]: if it is in 1..n and its home does not already hold that value, swap it home, then look at whatever arrived in slot i and repeat. Stop when slot i holds an out-of-range value, or a duplicate (its home already has that value). Every swap puts one value into its final slot for good, so there are at most n swaps in total: the nested loop is still O(n).

Finally scan from the left: the first index i with nums[i] != i + 1 means i + 1 is missing.

Approaches from the obvious one to the one you want in an interview

Start with candidate = 1. While the candidate is in the list, try the next one. The first value that is not found is the answer. Because the answer is at most n + 1, there are at most n + 1 tests.

The problem is that candidate in nums scans the list from the start every time, so n tests cost O(n²). It uses no extra memory, and it is a good way to check the faster solutions.

Dry run

  1. nums = [4, 1, -3, 2, 6], candidate = 1
  2. 1 is in the list → 2 is in the list → 3 is not → return 3
  3. each in check scans the list, so a list that holds 1..n makes n + 1 scans of up to n cells

Python

class Solution:
    def firstMissingPositive(self, nums: List[int]) -> int:
        candidate = 1
        while candidate in nums:               # a list membership test scans the whole list
            candidate += 1
        return candidate
Time O(n²)Space O(1)

Up to n + 1 candidates, each tested with an O(n) scan.

When to use: Only as a baseline.

Build a set of the values, then count up from 1 until a value is not in the set. A set answers "is it present?" in O(1) on average, so building it costs O(n) and the probing costs at most n + 1 lookups: O(n) time in total.

The price is O(n) extra memory for the set. The follow-up asks for O(1), which means the list itself must do the work of the set.

Dry run

  1. nums = [4, 1, -3, 2, 6] → present = {4, 1, -3, 2, 6}
  2. probe 1 ✓, 2 ✓, 3 ✗ → return 3

Python

class Solution:
    def firstMissingPositive(self, nums: List[int]) -> int:
        present = set(nums)                    # O(1) membership tests, O(n) memory
        candidate = 1
        while candidate in present:
            candidate += 1
        return candidate
Time O(n)Space O(n)

Building the set is O(n). The loop runs at most n + 1 times, because a list of n values cannot hold more than n different positives.

When to use: The practical answer when O(n) memory is fine. Mention that the follow-up needs the in-place version.

The answer lies in 1..n+1, so only values in 1..n matter. Treat the list as a table whose slot v - 1 is the home of the value v.

For each index i, keep swapping while nums[i] is in 1..n and its home slot does not already hold that value:

  • the value goes to its home slot, where it stays for good;
  • whatever lived there arrives in slot i and gets the same treatment.

The loop stops for slot i when it holds its own number, an out-of-range value, or a duplicate. After the pass, scan for the first i with nums[i] != i + 1 and return i + 1; if none, return n + 1.

Every swap sends one value to its final slot, so there are at most n swaps overall, and the inner while does not make the algorithm quadratic. The list is rearranged in place, so the extra space is O(1).

Dry run

  1. nums = [4, 1, -3, 2, 6], n = 5: only values 1..5 matter, value v goes to index v - 1
  2. i = 0: 4 belongs at index 3 → swap → [2, 1, -3, 4, 6]
  3. still i = 0: 2 belongs at index 1 → swap → [1, 2, -3, 4, 6]
  4. still i = 0: 1 sits in slot 0, its own slot → move on
  5. i = 1 (2) and i = 3 (4) are already home; i = 2 (-3) and i = 4 (6) have no home slot
  6. scan: slot 2 holds -3 instead of 3 → return 3

Python

class Solution:
    def firstMissingPositive(self, nums: List[int]) -> int:
        n = len(nums)
        for i in range(n):
            # keep sending nums[i] to its home slot (value v lives at index v - 1)
            while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
                home = nums[i] - 1             # compute first: the swap below changes nums[i]
                nums[i], nums[home] = nums[home], nums[i]
        for i in range(n):                     # the first slot without its own number gives the answer
            if nums[i] != i + 1:
                return i + 1
        return n + 1                           # 1..n are all present
Time O(n)Space O(1)

At most n swaps in total (each fixes one value for good) plus two linear scans. Only a few index variables.

When to use: The follow-up answer. It rewrites the input list, so say so.

Common mistakes

  • Writing the swap as nums[i], nums[nums[i] - 1] = nums[nums[i] - 1], nums[i]. Python assigns the left-hand targets from left to right, so nums[i] changes first and the second target nums[nums[i] - 1] is then computed from the new value. The value lands in the wrong slot and overwrites another one; on [3, 1, 2] the loop never ends. Compute home = nums[i] - 1 before swapping.
  • Using if instead of while. After one swap, the value that arrives in slot i has not been placed yet. With nums = [2, 3, 4, 1] an if version returns 1, but every value from 1 to 4 is present and the answer is 5.
  • Missing the duplicate check (nums[home] != nums[i]). With [1, 1] slot 0 holds 1, whose home is slot 0, so the swap changes nothing and the loop never ends. The same happens for [2, 2].
  • Indexing before checking the range. A value above n raises IndexError, and in Python a 0 does not even raise: nums[0 - 1] is nums[-1], the last element, so the code swaps with the wrong slot. With [0, 2] and no range check the loop never ends. Check 1 <= nums[i] <= n first.
  • Forgetting the answer can be n + 1. For [1, 2, 3] every slot is correct, and the scan must fall through to return n + 1.

Python notes

  • In a tuple swap a[i], a[j] = a[j], a[i] the right side is fully evaluated first, then the targets are assigned left to right. That is safe when i and j are plain variables, and a trap when a target's index depends on a cell the same statement changes.
  • Negative indexes wrap around: nums[-1] is the last element (and an index below -len(nums) raises IndexError), so out-of-range values must be filtered out before they are used as an index.
  • 1 <= v <= n is a chained comparison: it reads like the maths and evaluates v once.
  • candidate in nums scans a list in O(n), while candidate in some_set is O(1) on average.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Missing Number LC 268 — the values are 0..n with exactly one missing: a similar placement works (value v goes to slot v), and a sum or XOR does it with no swapping at all.
  • Find the Duplicate Number LC 287 — n + 1 values in 1..n with one repeated: treat 'index -> value at that index' as a linked list and find the cycle, or, if you may modify the list, swap values home until two collide.
  • Find All Numbers Disappeared in an Array LC 448 — values in 1..n, some missing: after the same placement, every slot i with nums[i] != i + 1 names a missing value i + 1.
  • Find All Duplicates in an Array LC 442 — values in 1..n, some appearing twice: after placement, the value stuck in a wrong slot is the duplicate.
  • Set Mismatch LC 645 — one number was copied over another: after placement, the one wrong slot shows the duplicate, and its index + 1 is the missing number.
  • What if the input must stay unchanged? — both O(1)-space tricks rewrite the list, so you would copy it first (O(n) space) or use the set approach.
