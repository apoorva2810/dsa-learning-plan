Reverse Nodes in k-Group Hard

LeetCode #25 ↗
Status

Reverse a linked list in blocks of k nodes, leaving a short final block as it is.

Problem

You are given head, the first node of a linked list, and a positive integer k. Reverse the nodes of the list k at a time: the first k nodes are reversed, then the next k, and so on. If fewer than k nodes remain at the end, leave them in their original order. Return the head of the modified list.

Change the links between nodes; do not change the values. k is at most the length of the list.

Examples

Example 1
Input: head = [1, 2, 3, 4, 5], k = 2
Output: [2, 1, 4, 3, 5]
Blocks [1, 2] and [3, 4] are reversed; [5] is shorter than 2 and stays.
Example 2
Input: head = [1, 2, 3, 4, 5], k = 3
Output: [3, 2, 1, 4, 5]
Example 3
Input: head = [1, 2, 3], k = 1
Output: [1, 2, 3]
Blocks of one node do not change anything.

Constraints

  • 1 <= k <= n <= 5000
  • 0 <= Node.val <= 1000
  • follow-up: O(1) extra memory

Key idea

This is Reverse Linked List, applied to one block at a time. The reversal loop itself is unchanged; the work is in the stitching around each block. When the block a → … → b is reversed into b → … → a:

  • the node before the block must now point to b (the block's new first node), and
  • a (the block's new last node) must point to the first node of the next block.

A dummy node before the head gives the first block a "node before" like every other block. Starting the reversal with prev = group_next (instead of None) makes a point at the next block automatically, because a is the first node flipped. After the block is done, a is the node before the next block, so it becomes the new group_prev.

Before reversing, walk k steps to check the block is complete; a short tail block is left alone. Every node is visited a constant number of times: O(n) time, O(1) extra memory.

Approaches from the obvious one to the one you want in an interview

Copy all node references into a Python list. Reverse every full slice of k nodes with slicing (nodes[s:s+k] = nodes[s:s+k][::-1]), leaving a short tail slice alone. Then relink the nodes in their new order and end the list with None.

The relinking guarantees correct next pointers without any careful stitching, which makes this a good way to check your understanding. It costs O(n) extra memory for the array, which the follow-up rules out.

Dry run

  1. [1, 2, 3, 4, 5], k = 2 → nodes = [n1, n2, n3, n4, n5]
  2. full slices start at 0 and 2: → [n2, n1, n4, n3, n5]
  3. relink in that order; n5.next = None → [2, 1, 4, 3, 5]

Python

class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        nodes = []
        while head:
            nodes.append(head)
            head = head.next
        for s in range(0, len(nodes) - k + 1, k):          # only full blocks
            nodes[s:s + k] = nodes[s:s + k][::-1]
        for a, b in zip(nodes, nodes[1:]):                  # relink in the new order
            a.next = b
        nodes[-1].next = None
        return nodes[0]
Time O(n)Space O(n)

Each node is copied, moved once by slicing and relinked once; the array holds n references.

When to use: To get a correct answer quickly or to test the pointer version against.

First check that at least k nodes exist; if not, return head unchanged (this is the short final block). Otherwise the answer is "the first k nodes reversed, followed by the answer for the rest". Reverse the first k nodes with the usual loop, but start prev at the reversed rest (self.reverseKGroup(node_after_block, k)), so the block's new last node is linked to it directly. Return prev, the block's new first node.

O(n) time; the recursion keeps one frame per block, so O(n / k) memory.

Dry run

  1. [1, 2, 3, 4, 5], k = 2: the first block [1, 2] is full; the rest starts at 3
  2. rest: block [3, 4] is full; its rest [5] is short → returned as is
  3. reverse [3, 4] onto [5] → 4 → 3 → 5; reverse [1, 2] onto that → 2 → 1 → 4 → 3 → 5

Python

class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        node = head
        for _ in range(k):                   # is there a full block?
            if not node:
                return head                  # short block: leave it as it is
            node = node.next
        # node is the first node after the block; reverse the block onto the reversed rest
        prev, cur = self.reverseKGroup(node, k), head
        for _ in range(k):
            nxt = cur.next
            cur.next = prev
            prev, cur = cur, nxt
        return prev                          # the block's new first node
Time O(n)Space O(n / k)

Each node is checked and flipped once; one stack frame per block.

When to use: Shorter to write and easy to reason about; mention its stack usage.

group_prev is the node just before the current block; it starts as a dummy node in front of the head.

  1. Find the block: walk k steps from group_prev to kth. If the walk falls off the end, return dummy.next.
  2. Save group_next = kth.next, the first node after the block.
  3. Reverse the block with prev = group_next, cur = group_prev.next, flipping until cur reaches group_next. The block's old first node now points to group_next.
  4. Stitch: group_prev.next = kth (the new first node), and the old first node becomes group_prev.

Each node is walked over twice (once to find kth, once to flip it): O(n) time, O(1) extra memory.

Dry run

  1. dummy → 1 → 2 → 3 → 4 → 5, k = 2, group_prev = dummy
  2. block 1: kth = 2, group_next = 3; flip → 2 → 1 → 3; dummy.next = 2; group_prev = 1
  3. block 2: kth = 4, group_next = 5; flip → 4 → 3 → 5; 1.next = 4; group_prev = 3
  4. block 3: only [5] remains → return dummy.next = [2, 1, 4, 3, 5]

Python

class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        group_prev = dummy                       # node just before the current block
        while True:
            kth = group_prev                     # walk k steps to the block's last node
            for _ in range(k):
                kth = kth.next
                if not kth:
                    return dummy.next            # fewer than k nodes left: done
            group_next = kth.next                # first node of the next block
            # reverse the block; prev starts at group_next, so the block's
            # new last node is already linked to the rest of the list
            prev, cur = group_next, group_prev.next
            while cur is not group_next:
                nxt = cur.next
                cur.next = prev
                prev, cur = cur, nxt
            old_first = group_prev.next          # was the block's first node, now its last
            group_prev.next = kth                # kth is the block's new first node
            group_prev = old_first               # the node before the next block
Time O(n)Space O(1)

Each node is passed by the kth walk once and flipped once; only a handful of pointers are kept.

When to use: The answer to the O(1)-memory follow-up.

Common mistakes

  • Reversing the final short block: check that k nodes exist before reversing (or, in the recursive version, return early).
  • Losing the next block: save group_next = kth.next before any pointer in the block changes.
  • Forgetting group_prev.next = kth: the node before the block still points at the old first node, which is now the block's tail, so the rest of the block disappears from the list.
  • Moving group_prev to kth instead of the old first node: after the reversal the old first node is the block's last node, the one in front of the next block.
  • Testing while cur: in the inner loop instead of while cur is not group_next: it would keep reversing past the block into the rest of the list.

Python notes

  • while cur is not group_next: compares node identity; it is the clearest way to say "stop at the next block".
  • The for _ in range(k) walk with an early return dummy.next both finds kth and handles the short last block.
  • The recursive version uses one call per block (n / k frames), so it stays under Python's recursion limit unless k is tiny and the list is long.
