Reverse Integer Medium

LeetCode #7 ↗
Status

Reverse the decimal digits of a 32-bit integer, and return 0 if the result no longer fits in 32 bits.

Problem

Given a signed 32-bit integer x, return x with its decimal digits reversed, keeping its sign.

If the reversed number falls outside the signed 32-bit range [-2^31, 2^31 - 1], return 0.

The original problem adds a rule: assume the environment cannot store numbers wider than 32 bits. A good solution therefore detects the overflow before it happens instead of building the too-large number first. Python has no overflow, so the last approach below simulates that rule.

Examples

Example 1
Input: x = 123
Output: 321
Example 2
Input: x = -123
Output: -321
The sign stays; only the digits are reversed.
Example 3
Input: x = 120
Output: 21
The trailing zero becomes a leading zero, which disappears.
Example 4
Input: x = 1534236469
Output: 0
The reversal is 9646324351, which is larger than 2^31 - 1 = 2147483647.

Constraints

  • -2^31 <= x <= 2^31 - 1

Think first try before reading the solution

Handle the sign separately: reverse the digits of abs(x) and put the sign back at the end. How can you read the last digit of a number? How can you remove it?

Key idea

Reversing digits is the pop-and-push from Reverse Bits, in base 10 instead of base 2. Pop the last digit off x and push it onto the right end of rev:

  • pop: digit = x % 10 and x //= 10 (divmod(x, 10) returns both at once);
  • push: rev = rev * 10 + digit. Multiplying by 10 opens a gap on the right, like << 1 in binary, and the digit fills it.

Do this on abs(x) and attach the sign at the end. The reason is that Python's // and % round toward minus infinity: -123 // 10 is -13 and -123 % 10 is 7, which are not the digits you want. (C and Java round toward zero, so -123 % 10 is -3 there, and the digit loop works on negative numbers without this care.)

Overflow. The 32-bit range is lopsided: the largest positive result is 2147483647, but a negative result may go down to magnitude 2147483648. Python never overflows, so you could reverse first and compare at the end. The original problem imagines a machine that cannot hold the too-large number, so a more faithful solution checks before each push. Pushing digit breaks the limit exactly when rev * 10 + digit > limit. For whole numbers that is the same as rev > (limit - digit) // 10, and that comparison never builds the too-large number.

Approaches from the obvious one to the one you want in an interview

Turn abs(x) into a string, reverse the string, turn it back into an integer, and re-attach the sign. Finally check that the number is inside the 32-bit range and return 0 if it is not.

This is short and correct. It sidesteps the digit arithmetic that the problem is about, builds a string, and creates the too-large number before testing it. That last point is exactly what the original problem tells you to avoid.

Dry run

  1. x = -123: sign is -1, abs(x) is 123
  2. str(123)[::-1] is '321', so the number is 321
  3. apply the sign: -321. It is inside [-2^31, 2^31 - 1], so return -321
  4. x = 1534236469 → 9646324351 is larger than 2147483647 → return 0

Python

class Solution:
    def reverse(self, x: int) -> int:
        sign = -1 if x < 0 else 1
        rev = sign * int(str(abs(x))[::-1])     # reverse the digits as text, then restore the sign
        return rev if -2**31 <= rev <= 2**31 - 1 else 0
Time O(d)Space O(d)

d is the number of digits (at most 10 for 32-bit input). The string holds one character per digit.

When to use: Quick scripts. In an interview, say it and then show the arithmetic version.

Peel digits off the right of abs(x) with divmod(x, 10) and build the reversed number with rev = rev * 10 + digit. This is the pop-and-push loop of Reverse Bits in base 10. Put the sign back and compare the final number with the 32-bit range.

Working on abs(x) matters in Python, because % and // round toward minus infinity and give the wrong digits for negative numbers. Python integers never overflow, so building the large number first is harmless here.

Dry run

  1. x = 123, rev = 0
  2. pop 3 → rev = 0 * 10 + 3 = 3; pop 2 → rev = 32; pop 1 → rev = 321; x is 0
  3. no sign to restore; 321 is inside the range → return 321

Python

class Solution:
    def reverse(self, x: int) -> int:
        sign = -1 if x < 0 else 1
        x = abs(x)                              # % and // behave on non-negative numbers
        rev = 0
        while x:
            x, digit = divmod(x, 10)            # pop the last digit
            rev = rev * 10 + digit              # push it onto the right end of rev
        rev *= sign
        return rev if -2**31 <= rev <= 2**31 - 1 else 0
Time O(d)Space O(1)

One round per digit, at most 10 for 32-bit input.

When to use: The practical answer in Python, where overflow cannot happen.

Keep the same loop, but never build a number that is out of range. Before pushing digit, ask whether rev * 10 + digit > limit. For whole numbers that is the same as

rev > (limit - digit) // 10

and the right-hand side is a number no bigger than limit. If the test is true, return 0 immediately. If it is false, the push is guaranteed to stay within the limit.

The limit depends on the sign because the 32-bit range is lopsided: 2^31 - 1 for a positive result and 2^31 for a negative one (the magnitude of -2^31). This is what the problem means by "do not store 64-bit values", and it is how you would write the loop in C++ or Java.

Dry run

  1. x = 1534236469: positive, so limit = 2147483647
  2. pop 9, 6, 4, 6, 3, 2, 4, 3, 5 → rev = 964632435, every check passed
  3. pop 1: is 964632435 > (2147483647 - 1) // 10 = 214748364? Yes → return 0
  4. x = -120: negative, so limit = 2147483648. Pop 0 → rev stays 0; pop 2 → 2; pop 1 → 21; return -21

Python

class Solution:
    def reverse(self, x: int) -> int:
        negative = x < 0
        limit = 2**31 if negative else 2**31 - 1     # largest magnitude the answer may have
        x = abs(x)
        rev = 0
        while x:
            x, digit = divmod(x, 10)                 # pop the last digit
            # rev * 10 + digit > limit  <=>  rev > (limit - digit) // 10
            if rev > (limit - digit) // 10:
                return 0                             # the push would leave the 32-bit range
            rev = rev * 10 + digit                   # safe: the result stays within the limit
        return -rev if negative else rev
Time O(d)Space O(1)

One round per digit, at most 10 for 32-bit input; the check is O(1).

When to use: The faithful answer to the problem as stated. It also shows you can reason about overflow without a wider type.

Common mistakes

  • Using x % 10 and x // 10 directly on a negative x in Python. They round toward minus infinity (-123 // 10 is -13), so the digits come out wrong. Work on abs(x).
  • Forgetting the overflow rule. 1534236469 reverses to 9646324351, which Python stores without complaint, so you must compare with the limit yourself and return 0.
  • Using one limit for both signs. The range is lopsided: -2147483648 is a valid result but 2147483648 is not. On abs(x), the limit is 2^31 - 1 for positive results and 2^31 for negative ones.
  • Reversing the text of a negative number: str(-123)[::-1] is '321-', and int('321-') raises a ValueError. Reverse str(abs(x)) and apply the sign yourself.

Python notes

  • x, digit = divmod(x, 10) returns (x // 10, x % 10) in one call, so it pops the last digit and shrinks x together.
  • Python's // rounds toward minus infinity and % takes the sign of the divisor: divmod(-123, 10) is (-13, 7). Take abs(x) first.
  • Python integers do not overflow, so rev * 10 + digit is always exact. The 32-bit rule is a requirement of the problem, and you enforce it with a comparison. In C++ or Java you would compare against INT_MAX and INT_MIN directly.
  • 2**31 is 2147483648, -2**31 is -2147483648 (the power binds tighter than the minus sign), and 2**31 - 1 is 2147483647.
  • int(str(abs(x))[::-1]) reverses the digits as text: [::-1] reverses a string, and int drops leading zeros for you.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Palindrome Number LC 9 — reverse the digits and compare with the original, or reverse only the second half so the reversed part can never overflow.
  • String to Integer (atoi) LC 8 — the same 32-bit clamp, but while reading digits from text: check before every res * 10 + digit, and clamp to INT_MAX or INT_MIN instead of returning 0.
  • Happy Number LC 202 — peel digits off with divmod(n, 10) to add their squares, and detect a repeated value.
  • Plus One LC 66 — digit arithmetic again, with a carry that can ripple through a run of 9s.
  • Reverse Bits LC 190 — the same pop-and-push in base 2: n & 1 and n >>= 1 to pop, (result << 1) | bit to push.
  • No 64-bit help in C++ or Java — the overflow test has to run before the multiplication: compare rev with INT_MAX / 10, and when equal compare digit with INT_MAX % 10 (7 for positive results, 8 for negative ones).
