Construct Binary Tree from Preorder and Inorder Traversal Medium

LeetCode #105 ↗
Status

Rebuild a binary tree from the order its nodes appear in a preorder walk and in an inorder walk.

Problem

You are given two lists of integers produced by walking the same binary tree:

  • preorder: each node is listed before its left subtree, which comes before its right subtree (node, left, right);
  • inorder: each node is listed between its left subtree and its right subtree (left, node, right).

Rebuild the tree and return its root.

  • All values are distinct.
  • The two lists always describe a real tree, and they have the same length.

Examples

Example 1
Input: preorder = [3, 9, 20, 15, 7], inorder = [9, 3, 15, 20, 7]
Output: [3, 9, 20, null, null, 15, 7]
3 comes first in preorder, so it is the root. In inorder, 9 is left of 3 (left subtree) and 15, 20, 7 are right of it (right subtree).
Example 2
Input: preorder = [-1], inorder = [-1]
Output: [-1]

Constraints

  • 1 <= len(preorder) <= 3000
  • len(inorder) == len(preorder)
  • -3000 <= value <= 3000
  • all values are distinct

Key idea

The two traversals answer different questions. Preorder says who the root is: a subtree's root always comes first. Inorder says what goes where: in it, the root sits exactly between its left subtree and its right subtree.

So: take the first preorder value as the root, find it in inorder, and split. If k values lie left of the root in inorder, the left subtree has k nodes, and in preorder they are the k values right after the root. Recurse on both halves.

The straightforward version searches with inorder.index and slices both lists, which costs O(n) per call and O(n²) on a lopsided tree. Two changes make it linear. A dictionary value → inorder index replaces the search. And instead of slicing preorder, keep one pointer into it: the recursion builds the whole left subtree before starting the right one, which is exactly the order preorder lists them in, so the next unused preorder value is always the root of the subtree being built next. Each call then only needs the inorder index range [lo, hi] it covers.

Approaches from the obvious one to the one you want in an interview

Translate the observation literally:

  1. root = preorder[0].
  2. mid = inorder.index(root): the left subtree has mid nodes.
  3. Left subtree: preorder[1 : mid + 1] with inorder[:mid]. Right subtree: preorder[mid + 1:] with inorder[mid + 1:].

It is correct and short. The cost hides in steps 2 and 3: index scans and every slice copies, both O(n) per call. On a chain-shaped tree there are n nested calls, so O(n²) time and O(n²) memory in total for the copies.

Dry run

  1. preorder [3, 9, 20, 15, 7], inorder [9, 3, 15, 20, 7]
  2. root 3, inorder.index(3) = 1 → left: pre [9] / in [9]; right: pre [20, 15, 7] / in [15, 20, 7]
  3. left: root 9, nothing on either side
  4. right: root 20, index 1 in [15, 20, 7] → left [15], right [7]

Python

class Solution:
    def buildTree(self, preorder: List[int], inorder: List[int]) -> Optional[TreeNode]:
        if not preorder:
            return None
        root = TreeNode(preorder[0])            # preorder starts with the root
        mid = inorder.index(root.val)           # O(n) search; mid = size of the left subtree
        root.left = self.buildTree(preorder[1:mid + 1], inorder[:mid])
        root.right = self.buildTree(preorder[mid + 1:], inorder[mid + 1:])
        return root

Each call scans and copies lists as long as its subtree. Balanced trees cost O(n log n); a chain costs O(n²).

When to use: To explain the idea on a whiteboard before optimising it.

Keep the same split, but remove both linear costs:

  • index_of = {value: inorder index} makes finding the root O(1).
  • No preorder slices: one shared pointer next_root walks preorder from left to right. Because build finishes the entire left subtree before starting the right subtree (the same order preorder uses), the value under the pointer is always the root of the subtree being built.
  • Each call receives only the inorder range [lo, hi] its subtree covers; lo > hi means an empty subtree.

Every node is created once with O(1) work: O(n) time, O(n) for the dictionary and up to O(n) for the call stack.

Dry run

  1. index_of = {9: 0, 3: 1, 15: 2, 20: 3, 7: 4}
  2. build(0, 4): root preorder[0] = 3, mid 1 → build(0, 0) then build(2, 4)
  3. build(0, 0): root 9, mid 0 → build(0, -1) = None, build(1, 0) = None
  4. build(2, 4): root 20, mid 3 → build(2, 2) = 15, build(4, 4) = 7

Python

class Solution:
    def buildTree(self, preorder: List[int], inorder: List[int]) -> Optional[TreeNode]:
        index_of = {val: i for i, val in enumerate(inorder)}   # value -> inorder position
        next_root = 0                                           # next unused preorder index

        def build(lo: int, hi: int) -> Optional[TreeNode]:
            """Build the subtree made of inorder[lo..hi]."""
            nonlocal next_root
            if lo > hi:                          # empty range: no node here
                return None
            root = TreeNode(preorder[next_root])
            next_root += 1
            mid = index_of[root.val]
            root.left = build(lo, mid - 1)       # must come first: preorder lists the left subtree next
            root.right = build(mid + 1, hi)
            return root

        return build(0, len(inorder) - 1)
Time O(n)Space O(n)

One O(1) step per node. The dictionary holds n entries; the recursion is as deep as the tree height.

When to use: The interview answer.

Watch it run

A recursion-free O(n) method. Walk preorder and keep a stack of nodes that may still receive a right child, plus a pointer j into inorder.

  • If the top of the stack is not inorder[j], the top still has a left subtree being built, so the new value becomes its left child.
  • If it is, the top's left side is finished. Pop while the top equals inorder[j] (advancing j); the last node popped is the one whose right child the new value is.

Push every new node. The insight is that inorder tells you the moment a node's left subtree is complete: its own value shows up next in inorder.

Python

class Solution:
    def buildTree(self, preorder: List[int], inorder: List[int]) -> Optional[TreeNode]:
        if not preorder:
            return None
        root = TreeNode(preorder[0])
        stack = [root]                   # nodes that may still get a right child
        j = 0                            # next inorder index to be 'closed'
        for val in preorder[1:]:
            node = TreeNode(val)
            parent = stack[-1]
            if parent.val != inorder[j]:
                parent.left = node       # parent's left subtree is still growing
            else:
                while stack and stack[-1].val == inorder[j]:
                    parent = stack.pop()  # these nodes' left sides are complete
                    j += 1
                parent.right = node
            stack.append(node)
        return root
Time O(n)Space O(h)

Each node is pushed and popped once; the stack holds at most one root-to-leaf path.

When to use: When recursion depth matters (a 3000-node chain is beyond Python's default limit) or as a show of depth.

Common mistakes

  • Building the right subtree before the left one while sharing a single preorder pointer. Preorder lists the left subtree first, so the right side would consume the left side's values.
  • Off-by-one in the brute-force slices: with the root at inorder index mid, the left subtree is preorder[1:mid + 1] (the mid values after the root), not preorder[1:mid].
  • Calling inorder.index(value) in every call. It is O(n), so a chain-shaped tree costs O(n²). Precompute the dictionary once.
  • Assuming duplicates are fine. With repeated values the root's position in inorder is ambiguous and two different trees can have the same pair of traversals; the problem guarantees distinct values for this reason.

Python notes

  • {val: i for i, val in enumerate(inorder)} builds the value-to-index lookup in one line.
  • A nested function needs nonlocal next_root to move the shared preorder pointer. An alternative is it = iter(preorder) and TreeNode(next(it)) in each call.
  • Slices such as preorder[1:mid + 1] copy the elements. In recursive code, pass index bounds instead of slices.
