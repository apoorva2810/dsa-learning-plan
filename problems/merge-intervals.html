Merge Intervals Medium

LeetCode #56 ↗
Status

Combine every group of overlapping ranges into one range and return the merged list.

Problem

You are given a list intervals. Each item [start, end] is a range of numbers. Merge every group of overlapping ranges into a single range, and return the merged ranges sorted by start.

  • Two ranges overlap when they share at least one point, so [1, 4] and [4, 5] do overlap and become [1, 5].
  • A range may lie completely inside another one. The bigger range absorbs it.
  • The input is not sorted. In the result no two ranges overlap, and together they cover exactly the points the input covered.

Examples

Example 1
Input: intervals = [[1, 3], [2, 6], [8, 10], [15, 18]]
Output: [[1, 6], [8, 10], [15, 18]]
[1, 3] and [2, 6] overlap, so they become [1, 6]. The other two stand alone.
Example 2
Input: intervals = [[1, 4], [4, 5]]
Output: [[1, 5]]
They share the single point 4, and that counts as overlapping.
Example 3
Input: intervals = [[1, 10], [2, 3], [4, 8]]
Output: [[1, 10]]
Both smaller ranges lie inside [1, 10].

Constraints

  • 1 <= len(intervals) <= 10^4
  • intervals[i] = [start, end]
  • 0 <= start <= end <= 10^4

Key idea

Picture the intervals as bars on a timeline. Read them left to right, in order of where they start, and merging is easy. Keep the block you are building and ask of each new bar: does it begin inside my block, or right where it ends? If yes, the bar extends the block. If no, there is a gap: the block is finished and the bar starts a new one.

That only works if the bars come in order of start, so sort by start first. Then one comparison per bar is enough, for two reasons. The new bar starts no earlier than any bar before it, so it can only reach the last block: every earlier block ended before the last one began. And when it does reach the block, the block's new end is max(old_end, bar_end), because the bar may be shorter than the block and sit inside it.

The sort costs O(n log n). The pass afterwards, a left-to-right sweep that touches each interval once, is O(n).

Approaches from the obvious one to the one you want in an interview

Apply the definition literally. While some pair of intervals overlaps, replace the two by their union, [min(starts), max(ends)]. When no pair overlaps any more, the list is the answer (sorted at the end, since the problem wants it ordered).

Merging two overlapping intervals never changes which points are covered, so the result is right. The cost is the rescanning: finding an overlapping pair takes up to n² / 2 tests, a merge removes only one interval, and after every merge the search starts again from the beginning. That is up to n merges times n² tests, O(n³).

Dry run

  1. intervals = [[8, 10], [1, 3], [15, 18], [2, 6]]
  2. Round 1: scan the pairs in order. [8, 10] overlaps none of the others; then [1, 3] and [2, 6] do (1 <= 6 and 2 <= 3). Replace them with [1, 6]: [[8, 10], [1, 6], [15, 18]].
  3. Round 2: scan again from the start. None of the 3 pairs overlaps, so stop. Sort and return [[1, 6], [8, 10], [15, 18]].

Python

class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        pieces = [list(iv) for iv in intervals]           # work on copies
        while True:
            pair = self.find_overlap(pieces)
            if pair is None:                              # nothing overlaps any more
                break
            i, j = pair
            a, b = pieces[i], pieces[j]
            pieces[i] = [min(a[0], b[0]), max(a[1], b[1])]   # replace the pair by its union
            pieces.pop(j)
        return sorted(pieces)

    def find_overlap(self, pieces):
        for i in range(len(pieces)):
            for j in range(i + 1, len(pieces)):
                a, b = pieces[i], pieces[j]
                if a[0] <= b[1] and b[0] <= a[1]:         # touching counts as overlapping
                    return i, j
        return None
Time O(n³)Space O(n)

Up to n − 1 merges; each one is preceded by a scan of up to n² / 2 pairs.

When to use: To see that the definition is enough to solve it; far too slow for 10⁴ intervals.

Sort by start, then walk the list once with a result list merged. For each [start, end]:

  • if merged is non-empty and start <= merged[-1][1], the interval overlaps the last block. Stretch that block: merged[-1][1] = max(merged[-1][1], end);
  • otherwise there is a gap. Append [start, end] as a new block.

Sorting guarantees that the new interval starts no earlier than any interval before it. So it can only reach the last block, and when the last block's end is smaller than start, no later interval can reach it either: it is final. The max matters because the new interval may end before the block does.

Dry run

  1. intervals = [[8, 10], [1, 3], [15, 18], [2, 6]] sorted by start: [[1, 3], [2, 6], [8, 10], [15, 18]]
  2. [1, 3]: merged is empty, so merged = [[1, 3]]
  3. [2, 6]: 2 <= 3, overlap. End becomes max(3, 6) = 6: merged = [[1, 6]]
  4. [8, 10]: 8 <= 6 is false, a gap. Append: merged = [[1, 6], [8, 10]]
  5. [15, 18]: 15 <= 10 is false. Append: merged = [[1, 6], [8, 10], [15, 18]]

Python

class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        merged = []
        for start, end in sorted(intervals):              # by start, ties by end
            if merged and start <= merged[-1][1]:         # overlaps (or touches) the last block
                merged[-1][1] = max(merged[-1][1], end)   # stretch it; never shrink it
            else:                                         # a gap: this interval opens a new block
                merged.append([start, end])               # a fresh list, so the input is untouched
        return merged
Time O(n log n)Space O(n)

The sort dominates; the sweep is one pass. Space is the output list plus the sorted copy.

When to use: Always. This is the standard answer, and the template for Insert Interval and Meeting Rooms.

Watch it run

Turn every interval into two events: an open at start and a close at end. Sort all events by position, and at the same position put opens before closes, so that [1, 4] and [4, 5] stay joined. Walk the events with a counter of how many intervals are open: when it goes from 0 to 1 a new block begins at that position, and when it falls back to 0 the block ends there.

The cost is the same O(n log n) (sorting 2n events) with more code than sorting the intervals themselves. It is worth knowing because the same walk answers "how many intervals are open at once?", which is Meeting Rooms II.

Python

class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        events = []
        for start, end in intervals:
            events.append((start, 0))                     # 0 = open: sorts before a close at the same position
            events.append((end, 1))                       # 1 = close
        events.sort()
        merged = []
        open_count = 0
        block_start = 0
        for position, kind in events:
            if kind == 0:
                if open_count == 0:                       # first open interval: a block begins here
                    block_start = position
                open_count += 1
            else:
                open_count -= 1
                if open_count == 0:                       # last open interval closed: the block ends here
                    merged.append([block_start, position])
        return merged
Time O(n log n)Space O(n)

2n events to sort, then one pass over them.

When to use: When the problem is really about how many intervals are open at a time, or the data arrives as separate start and end lists.

Common mistakes

  • Skipping the sort. For [[1, 3], [8, 10], [2, 6]], [2, 6] is compared only with [8, 10], which gives [[1, 3], [2, 10]] instead of [[1, 6], [8, 10]].
  • Setting the end to the new interval's end instead of the larger of the two. [[1, 10], [2, 3]] would come out as [[1, 3]]. Use max(merged[-1][1], end).
  • Using < instead of <= in the overlap test. [1, 4] and [4, 5] share the point 4 and must merge, so equal endpoints count as overlapping.
  • Comparing with the previous interval instead of the last merged block. In [[1, 10], [2, 3], [4, 5]], [4, 5] does not reach [2, 3], but it lies inside the block [1, 10].
  • Appending the input's own list (merged.append(interval)) and stretching it later. That edits the caller's data. Append a new list, [start, end].

Python notes

  • sorted(intervals) orders the [start, end] lists by start and breaks ties by end, so no key is needed. Prefer it to intervals.sort() unless you are happy to reorder the caller's list.
  • for start, end in sorted(intervals): unpacks each pair into two names, which reads better than interval[0] and interval[1].
  • merged[-1][1] is the end of the last block. Keep the if merged and ... guard: merged[-1] raises IndexError on an empty list.
  • merged.append([start, end]) builds a new list, so stretching merged[-1] later never touches the input.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Insert Interval LC 57 — the list is already sorted and disjoint and one new interval is added: no sort needed, one pass in three zones (before, overlapping, after), O(n).
  • Interval List Intersections LC 986 — two sorted, disjoint lists; return where they overlap. Two pointers, and after each comparison advance the pointer whose interval ends first.
  • Employee Free Time LC 759 — merge everyone's schedules into busy blocks; the gaps between consecutive blocks are the free time. (Premium on LeetCode.)
  • Remove Covered Intervals LC 1288 — count the intervals not fully inside another. Sort by start ascending and, for equal starts, by end descending, so a covering interval always comes first.
  • Merge ranges that are close enough — merge intervals whose gap is at most k: the overlap test becomes start <= merged[-1][1] + k. Nothing else changes.
