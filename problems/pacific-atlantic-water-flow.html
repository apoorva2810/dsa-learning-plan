Pacific Atlantic Water Flow Medium

LeetCode #417 ↗
Status

Find every cell of a height map from which rain water can reach both the Pacific and the Atlantic.

Problem

An island is drawn as an m × n grid heights, where heights[r][c] is the height of that cell. The Pacific ocean touches the island's top and left edges; the Atlantic touches its bottom and right edges.

Rain water on a cell can flow to a neighbouring cell (up, down, left or right) whose height is less than or equal to the current one. A cell on an edge drains straight into the ocean beside that edge.

Return the coordinates [r, c] of every cell from which water can reach both oceans, in any order.

Examples

Example 1
Input: heights = [[1,2,3],[2,1,2],[3,2,1]]
Output: [[0,2],[2,0]]
The two corners of height 3 sit on both coasts. The centre (height 1) is lower than all its neighbours, so its water cannot leave.
Example 2
Input: heights = [[1,2,2,3,5],[3,2,3,4,4],[2,4,5,3,1],[6,7,1,4,5],[5,1,1,2,4]]
Output: [[0,4],[1,3],[1,4],[2,2],[3,0],[3,1],[4,0]]
For example, (2,2) has height 5: water runs 5 → 3 → 2 → 2 to the top edge, and 5 → 4 → 4 to the right edge.
Example 3
Input: heights = [[1]]
Output: [[0,0]]
A single cell touches all four edges.

Constraints

  • 1 <= m, n <= 200
  • 0 <= heights[r][c] <= 10^5

Think first try before reading the solution

The direct approach follows the water downhill from every cell and checks which edges it reaches. Why does that repeat a lot of work?
Reverse the question: instead of asking where water from a cell can go, ask which cells can send water to the Pacific. Start at the Pacific coast and walk uphill (to neighbours at least as high).
Do that walk once from all Pacific border cells and once from all Atlantic border cells, each with its own visited set. The answer is the intersection of the two sets.

Key idea

Following water downhill from each of the m · n cells means one search per cell, and neighbouring cells repeat almost the same search. Turn the flow around. Water can travel from cell A to a lower-or-equal neighbour B; read backwards, from B you can climb to A whenever A is at least as high as B.

So start at every cell on the Pacific coast (all of them drain into the Pacific directly) and climb uphill with DFS. Every cell the climb reaches can send water down the reverse path to the Pacific; collect them in a set. Do the same from the Atlantic coast with a second set. A cell is in the answer exactly when it is in both sets. Each cell is visited at most once per ocean, so the work is O(m · n).

Approaches from the obvious one to the one you want in an interview

For each cell, run a search that follows the water downhill (to neighbours with height ≤ the current one) and records whether it touches the Pacific edge (top row or left column) and the Atlantic edge (bottom row or right column). Keep the cell if it touches both.

It works, but each search can cover the whole grid, so m · n searches cost O((m · n)²). Neighbouring cells usually share most of their downhill paths, so the same cells are explored again and again.

Dry run

  1. Example 1: from (0,0) (height 1) water cannot move anywhere (every neighbour is 2), but (0,0) is on the Pacific edge → Pacific only.
  2. From (0,2) (height 3): it is on the top edge (Pacific) and the right edge (Atlantic) → keep it.
  3. From (1,1) (height 1): no neighbour is ≤ 1 and it touches no edge → neither.
  4. Checking all 9 cells this way gives [(0,2), (2,0)].

Python

class Solution:
    def pacificAtlantic(self, heights: List[List[int]]) -> List[List[int]]:
        rows, cols = len(heights), len(heights[0])

        def oceans_reached(sr: int, sc: int):
            pacific = atlantic = False
            seen = {(sr, sc)}
            stack = [(sr, sc)]
            while stack:                                  # follow the water downhill from (sr, sc)
                r, c = stack.pop()
                if r == 0 or c == 0:
                    pacific = True
                if r == rows - 1 or c == cols - 1:
                    atlantic = True
                if pacific and atlantic:
                    break                                 # nothing more to learn
                for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                    if (0 <= nr < rows and 0 <= nc < cols and (nr, nc) not in seen
                            and heights[nr][nc] <= heights[r][c]):   # water flows down or level
                        seen.add((nr, nc))
                        stack.append((nr, nc))
            return pacific, atlantic

        result = []
        for r in range(rows):
            for c in range(cols):
                pacific, atlantic = oceans_reached(r, c)
                if pacific and atlantic:
                    result.append([r, c])
        return result

Run the flow backwards. climb(r, c, reached) adds (r, c) to reached, then recurses into every neighbour that is inside the grid, not yet in reached, and at least as high as (r, c), because water from that neighbour could flow down into (r, c).

Start a climb from every Pacific coast cell into the set pacific, then from every Atlantic coast cell into the set atlantic. Every cell is added to each set at most once, so each ocean costs O(m · n). The cells in both sets are the answer.

Dry run

  1. Example 1, Pacific: from (0,0) (1) climb down to (1,0) (2), then to (2,0) (3). Back at (0,0), climb right to (0,1) (2), then (0,2) (3).
  2. The other Pacific coast cells are already in the set → pacific = {(0,0), (1,0), (2,0), (0,1), (0,2)}. The centre (1,1) is lower than everything around it, so no climb enters it.
  3. Atlantic: (2,0) and (2,1) cannot climb anywhere new; (2,2) (1) climbs up to (1,2) (2) and on to (0,2) (3).
  4. atlantic = {(2,0), (2,1), (2,2), (1,2), (0,2)}. Intersection → [[0,2], [2,0]].

Python

class Solution:
    def pacificAtlantic(self, heights: List[List[int]]) -> List[List[int]]:
        rows, cols = len(heights), len(heights[0])

        def climb(r: int, c: int, reached: set) -> None:
            reached.add((r, c))                           # water from (r, c) can reach this ocean
            for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                if (0 <= nr < rows and 0 <= nc < cols and (nr, nc) not in reached
                        and heights[nr][nc] >= heights[r][c]):   # it could flow down into (r, c)
                    climb(nr, nc, reached)

        pacific, atlantic = set(), set()
        for r, c in [(0, c) for c in range(cols)] + [(r, 0) for r in range(1, rows)]:
            if (r, c) not in pacific:                     # top row and left column touch the Pacific
                climb(r, c, pacific)
        for r, c in [(rows - 1, c) for c in range(cols)] + [(r, cols - 1) for r in range(rows - 1)]:
            if (r, c) not in atlantic:                    # bottom row and right column touch the Atlantic
                climb(r, c, atlantic)
        return [[r, c] for r, c in sorted(pacific & atlantic)]
Time O(m · n)Space O(m · n)

Each cell enters each set once and checks 4 neighbours; two sets plus a call stack of up to m · n frames.

When to use: The standard answer. The 'start from the target and search backwards' idea is worth remembering on its own.

Watch it run

The same reversed search, written as a multi-source BFS. Put every coast cell of one ocean in a queue and in its reached set, then repeatedly pop a cell and add each unvisited neighbour that is at least as high. Run it once per ocean and intersect the results.

Identical complexity; the queue replaces recursion, so a 200 × 200 grid cannot hit Python's recursion limit.

Python

class Solution:
    def pacificAtlantic(self, heights: List[List[int]]) -> List[List[int]]:
        rows, cols = len(heights), len(heights[0])

        def reach(starts):
            reached = set(starts)                         # every coast cell drains straight into the ocean
            queue = deque(starts)
            while queue:
                r, c = queue.popleft()
                for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                    if (0 <= nr < rows and 0 <= nc < cols and (nr, nc) not in reached
                            and heights[nr][nc] >= heights[r][c]):
                        reached.add((nr, nc))
                        queue.append((nr, nc))
            return reached

        pacific = reach([(0, c) for c in range(cols)] + [(r, 0) for r in range(1, rows)])
        atlantic = reach([(rows - 1, c) for c in range(cols)] + [(r, cols - 1) for r in range(rows - 1)])
        return [[r, c] for r, c in sorted(pacific & atlantic)]
Time O(m · n)Space O(m · n)

When to use: When the grid can be large enough for deep recursion to be a risk.

Common mistakes

  • Climbing in the wrong direction. From the ocean you move to neighbours that are higher or equal (heights[next] >= heights[cur]); if you copy the downhill rule you compute the wrong sets.
  • Using > instead of >=: water flows across flat ground, so equal heights must connect.
  • Sharing one visited set between the two oceans: a cell reached from the Pacific would then be skipped by the Atlantic climb. Each ocean needs its own set.
  • Forgetting a coast: the Pacific is the top row and the left column; the Atlantic is the bottom row and the right column. Corners belong to both of their edges.
  • Comparing [r, c] order-sensitively: the answer may be returned in any order, but each pair itself must be [r, c], not [c, r].

Python notes

  • Sets of (r, c) tuples make the final step one operator: pacific & atlantic is the intersection.
  • The answer must be a list of lists: [[r, c] for r, c in pacific & atlantic]. Sorting it first keeps the output stable, which is handy when debugging.
  • Build each coast as a list of cells ([(0, c) for c in range(cols)] + [(r, 0) for r in range(1, rows)]) so the corner cell is not listed twice.
  • The recursive climb can go as deep as m · n = 40,000 calls on a 200 × 200 grid; the BFS version avoids the recursion limit.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Surrounded Regions LC 130 — the same 'start from the border and work inward' trick, with no heights: border-connected cells are safe.
  • Number of Enclaves LC 1020 — flood from every border land cell, then count the land cells the flood never reached.
  • Trapping Rain Water II LC 407 — heights again, but you need how much water each cell holds: grow inward from the border with a min-heap (always expand the lowest wall first).
  • Return the cells that reach exactly one ocean — take the symmetric difference pacific ^ atlantic instead of the intersection.
  • What if water only flows strictly downhill? — change the climb test from >= to >; everything else stays the same.
