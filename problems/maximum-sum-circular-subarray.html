Maximum Sum Circular Subarray Medium 250

LeetCode #918 ↗
Status

Find the largest sum of a contiguous stretch of a circular list, where the stretch may run off the end and continue at the front.

Problem

You are given an integer list nums that is circular: the element after the last one is the first one again, and the element before the first one is the last.

Return the largest possible sum of a non-empty subarray (a contiguous stretch) of this circular list. A stretch may start near the end and carry on past it into the front, for example nums[n - 2], nums[n - 1], nums[0]. Each element may be used at most once, so a stretch holds at most n elements.

Examples

Example 1
Input: nums = [4, -1, -3, 2, 6]
Output: 12
The stretch 2, 6, 4 runs off the end and wraps to the front. It adds up to 12. The best ordinary stretch, [2, 6], only reaches 8.
Example 2
Input: nums = [-3, 4, 5, -1, -1]
Output: 9
The ordinary stretch [4, 5] gives 9. Wrapping around would only add negative numbers, so it cannot do better.
Example 3
Input: nums = [-4, -2, -7]
Output: -2
Every number is negative and the stretch cannot be empty, so the best choice is the single element -2.

Constraints

  • 1 <= len(nums) <= 3 * 10^4
  • -3 * 10^4 <= nums[i] <= 3 * 10^4

Think first try before reading the solution

A stretch that does not wrap is the ordinary Maximum Subarray problem. Now look at a stretch that does wrap: which elements does it leave out?
The elements a wrapping stretch leaves out form one ordinary stretch in the middle of the list. So a wrapping stretch adds up to total - (the stretch left out). To make that as big as possible, which stretch should you leave out?
The one with the smallest sum. Run Kadane's algorithm twice, once for the biggest sum and once for the smallest. The answer is the larger of best_max and total - best_min, with one special case: when every number is negative, leaving out everything means taking nothing, which is not allowed.

Key idea

Split the possible stretches into two kinds.

  1. Stretches that do not wrap. This is Maximum Subarray, solved by Kadane's algorithm in one pass. Call its answer best_max.
  2. Stretches that wrap past the end. Picture the circle: a wrapping stretch takes some elements at the end and some at the front, so it leaves out one unbroken stretch in the middle. Its sum is total - (the sum of the stretch left out).

To make a wrapping sum as large as possible, leave out the smallest middle stretch. Finding the smallest stretch is Kadane's algorithm turned upside down: best_min is the smallest sum of any ordinary stretch. So

answer = max(best_max, total - best_min)

and one pass can track best_max, best_min and the running total together.

There is one trap. If every number is negative, the smallest stretch is the whole list, so total - best_min is 0, which stands for taking nothing. A stretch cannot be empty, so in that case the answer is just best_max, the least negative number. The test best_max < 0 catches exactly this case. When best_max is 0 or more, leaving out the whole list gives 0, which can never beat best_max, so the formula is safe.

Approaches from the obvious one to the one you want in an interview

Try every start. From each start, extend the stretch one element at a time, up to n elements, using % n to wrap past the end. Keep a running total, so each new stretch costs one addition. The largest total seen is the answer.

That is n starts times up to n lengths: about n² stretches. For n = 3·10^4 it is around 900 million additions, far too slow, and it never uses the fact that a wrapping stretch is "everything except one middle stretch".

Dry run

  1. nums = [4, -1, -3, 2, 6], best = 4
  2. start 0: totals 4, 3, 0, 2, 8 → best 8
  3. start 2: totals -3, -1, 5, 9, 8 → best 9
  4. start 3: totals 2, 8, 12, 11, 8 → best 12 (the stretch 2, 6, 4 wraps around the end)
  5. start 4: totals 6, 10, 9, 6, 8 → best stays 12

Python

class Solution:
    def maxSubarraySumCircular(self, nums: List[int]) -> int:
        n = len(nums)
        best = nums[0]                           # the stretch cannot be empty
        for start in range(n):
            total = 0
            for length in range(n):              # a stretch holds at most n elements, each used once
                total += nums[(start + length) % n]   # % n wraps past the end back to the front
                best = max(best, total)
        return best
Time O(n²)Space O(1)

n starts, each extended up to n times.

When to use: To check a faster solution on small inputs.

A best stretch either does not wrap, or it wraps and leaves out one middle stretch.

  • Not wrapping: the biggest ordinary subarray, found with Kadane's algorithm (best_max).
  • Wrapping: total - (the stretch left out). The biggest value comes from leaving out the smallest ordinary subarray, found with Kadane's algorithm turned upside down (best_min).

Take the larger of best_max and total - best_min. If best_max is negative, every number is negative and the wrap formula would stand for an empty stretch, so return best_max instead. One pass, five variables.

Dry run

  1. nums = [4, -1, -3, 2, 6]: everything starts at 4, total = 4
  2. x = -1: max side extends (3), min side restarts (-1) → best_min = -1, total 3
  3. x = -3: max side extends (0), min side extends (-4) → best_min = -4, total 0
  4. x = 2: max side restarts (2), min side extends (-2), total 2
  5. x = 6: max side extends (8) → best_max = 8, min side extends (4), total 8
  6. best_max is 8 and total - best_min is 8 + 4 = 12, so the answer is 12 (the stretch 2, 6, 4)

Python

class Solution:
    def maxSubarraySumCircular(self, nums: List[int]) -> int:
        cur_max = best_max = nums[0]             # Kadane for the biggest stretch: ending here / overall
        cur_min = best_min = nums[0]             # Kadane for the smallest stretch: ending here / overall
        total = nums[0]
        for x in nums[1:]:
            cur_max = max(x, cur_max + x)        # extend the biggest run, or restart at x
            best_max = max(best_max, cur_max)
            cur_min = min(x, cur_min + x)        # extend the smallest run, or restart at x
            best_min = min(best_min, cur_min)
            total += x
        if best_max < 0:                         # all negative: the wrap would be an empty stretch
            return best_max
        return max(best_max, total - best_min)   # no wrap, or everything except the smallest stretch
Time O(n)Space O(1)

One pass over the list; a handful of integers.

When to use: The standard answer. Be ready to explain why the wrapping stretch is the total minus a middle stretch.

Watch it run

Write the list twice, nums + nums, so that every wrapping stretch becomes an ordinary stretch of the doubled list that is at most n long. With prefix sums prefix (where prefix[k] is the sum of the first k doubled elements), the stretch from start up to end adds up to prefix[end] - prefix[start], and it is allowed when end - n <= start < end.

For each end you want the smallest prefix[start] among the last n positions. A deque that keeps candidate starts with increasing prefix values hands you that minimum at its front, and it forgets starts that are too old. This is the sliding window maximum trick, used here for a minimum. The idea generalises to "best stretch of length at most k" problems, but for this task Kadane twice is simpler and uses no extra memory.

Dry run

  1. nums = [4, -1, -3, 2, 6] doubled: 4, -1, -3, 2, 6, 4, -1, -3, 2, 6
  2. prefix sums: 0, 4, 3, 0, 2, 8, 12, 11, 8, 10, 16
  3. end = 6 (prefix 12): the allowed starts are 1 to 5, whose prefixes are 4, 3, 0, 2, 8; the smallest is 0 → 12 − 0 = 12
  4. no other end does better, so the answer is 12 (the stretch 2, 6, 4)

Python

class Solution:
    def maxSubarraySumCircular(self, nums: List[int]) -> int:
        n = len(nums)
        prefix = [0] * (2 * n + 1)               # prefix[k] = sum of the first k elements of nums written twice
        for k in range(2 * n):
            prefix[k + 1] = prefix[k] + nums[k % n]
        best = float("-inf")
        window = deque([0])                      # candidate starts; their prefix values increase front to back
        for end in range(1, 2 * n + 1):
            if window[0] < end - n:              # that start would make the stretch longer than n elements
                window.popleft()
            best = max(best, prefix[end] - prefix[window[0]])     # best stretch ending at this end
            while window and prefix[window[-1]] >= prefix[end]:   # a newer, smaller prefix beats these starts
                window.pop()
            window.append(end)
        return best
Time O(n)Space O(n)

2n positions, each pushed and popped from the deque at most once; the prefix array has 2n + 1 entries.

When to use: When you want a method that also handles "at most k elements" limits, or the interviewer asks for the prefix-sum view.

Common mistakes

  • Using total - best_min without the all-negative check. For [-4, -2, -7] it gives 0, but the stretch cannot be empty and the answer is -2.
  • Writing the list twice and running plain Kadane on it. The stretch can then be longer than n and use an element twice: for [2, 3] it finds 2 + 3 + 2 + 3 = 10, but the answer is 5.
  • Always returning total - best_min. For [-3, 4, 5, -1, -1] that gives 7, but the ordinary stretch [4, 5] gives 9. Take the larger of the two kinds.
  • Starting best_max and best_min at 0 instead of nums[0]. With all-negative input best_max would stay at 0 (an empty stretch), the special case would not fire and the function would return 0 instead of the least negative number.

Python notes

  • (start + length) % n walks around a circle: when the index reaches n it wraps back to 0.
  • max(x, cur + x) is Kadane's "extend or restart" for the biggest run, and min(x, cur + x) is the same for the smallest.
  • sum(nums) gives the total in one call. The one-pass version here adds to total inside the loop so that a single scan collects everything.
  • collections.deque (already imported) gives O(1) popleft() and pop(). A plain list's pop(0) is O(n), which would turn the deque approach back into O(n²).

Follow-up questions

What an interviewer might ask next, and what changes.

  • Maximum Subarray LC 53 — the non-wrapping half of this problem. Circular adds one more Kadane scan (for the minimum) and the all-negative special case.
  • Gas Station LC 134 — running totals on a circle: the lowest point of the running total tells you where the lap must start.
  • House Robber II LC 213 — another circular list. The first and last houses are neighbours, so solve the line twice, once without the first house and once without the last, and take the larger answer.
  • Maximum Absolute Sum of Any Subarray LC 1749 — the same two Kadane scans, but you return the larger magnitude of the biggest and the smallest sum instead of combining them with the total.
  • Sliding Window Maximum LC 239 — the monotonic deque used in the third approach: it hands you the best value of the last k positions in O(1) per step.
  • Return the stretch itself, not just its sum — remember where each best run starts and ends. A wrapping answer starts right after the smallest run and ends right before it, going around the end of the list.
