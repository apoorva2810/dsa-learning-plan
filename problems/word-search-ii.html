Word Search II Hard

LeetCode #212 ↗
Status

Find every word from a list that can be traced on a letter grid through neighbouring cells.

Problem

You are given an m x n grid of lowercase letters, board, and a list of distinct strings, words. Return every word from the list that can be traced on the board.

A word is traced by starting on some cell and moving, one letter at a time, to a cell directly above, below, left or right of the previous one (no diagonals). A single cell may be used at most once within one word.

Return the found words in any order, each word once.

Examples

Example 1
Input: board = [["o","a","a","n"],["e","t","a","e"],["i","h","k","r"],["i","f","l","v"]], words = ["oath","pea","eat","rain"]
Output: ["eat", "oath"]
oath runs o(0,0) → a(0,1) → t(1,1) → h(2,1); eat runs e(1,3) → a(1,2) → t(1,1). The board has no p, and no r next to an a.
Example 2
Input: board = [["a","b"],["c","d"]], words = ["abcb"]
Output: []
After a → b, the next letter c is not next to b (diagonals do not count).

Constraints

  • 1 <= m, n <= 12
  • board[i][j] is a lowercase English letter
  • 1 <= len(words) <= 3 * 10^4
  • 1 <= len(words[i]) <= 10
  • all words are distinct

Think first try before reading the solution

Running Word Search (one word at a time) for every word repeats the same exploration for words that share a beginning: oath, oat and oak all start by finding an o next to an a. Can one search serve all words?
Put the words into a trie. During the DFS, carry the trie node for the letters picked so far, and only step to a neighbour whose letter is a child of that node. A path stops the moment it is not the start of any word.
Store each word on its last trie node. When the DFS reaches it, record the word and clear it, so it is reported once. Delete trie nodes that end up with no children and no word: finished branches are then never searched again.

Key idea

Word Search (one word) is backtracking: start on every cell, step to neighbours that match the next letter, and undo the step when the path fails. Repeating that for each of up to 3 * 10^4 words redoes the same walks over and over, because many words share their first letters.

Turn the loops around: explore the board once, and at every step ask a trie whether the letters picked so far are the beginning of any word. Each DFS call carries the trie node for its current path. Stepping onto a neighbour is allowed only if that cell's letter is a child of the current node, so a path dies as soon as it stops being a prefix of every word still wanted. When the current node stores a word, that word is on the board.

Two details make it fast in practice:

  • Store the whole word on its end node and set it to None once reported. Nothing has to be rebuilt from the path, and a word that can be traced along two paths is reported once.
  • Prune the trie: when a node has no children left and no unreported word, delete it from its parent. Later searches then stop even earlier, and once every word is found the trie is empty.

Approaches from the obvious one to the one you want in an interview

Reuse the single-word algorithm. For each word, try every cell as a start and backtrack: step to a neighbour that holds the next letter, mark cells on the current path so none is reused, and undo the mark when returning.

Each word costs up to O(m · n · 4 · 3^(L-1)) (every start cell, then at most 3 new directions per step), and the work is repeated for all W words even when they share long beginnings. With 3 * 10^4 words on a 12 x 12 board, that is far too slow.

Dry run

  1. word oath: start at (0,0) o → a (0,1) → t (1,1) → h (2,1) ✓
  2. word pea: no cell holds p, but all 16 start cells are still checked
  3. word eat: tries (1,0) e (no a beside it), then (1,3) e → a (1,2) → t (1,1) ✓
  4. word rain: (2,3) r has no neighbouring a ✗ → answer [oath, eat]

Python

class Solution:
    def findWords(self, board: List[List[str]], words: List[str]) -> List[str]:
        rows, cols = len(board), len(board[0])

        def exists(word):
            def dfs(r, c, i):
                if i == len(word):
                    return True                       # every letter matched
                if not (0 <= r < rows and 0 <= c < cols) or board[r][c] != word[i]:
                    return False
                board[r][c] = "#"                     # used on this path
                ok = (dfs(r + 1, c, i + 1) or dfs(r - 1, c, i + 1)
                      or dfs(r, c + 1, i + 1) or dfs(r, c - 1, i + 1))
                board[r][c] = word[i]                 # undo
                return ok

            return any(dfs(r, c, 0) for r in range(rows) for c in range(cols))

        return [w for w in words if exists(w)]
Time O(W · m·n · 4·3^(L-1))Space O(L)

W words, an m x n board, words up to L letters. The recursion is L deep.

When to use: Fine for a handful of words; it is Word Search (LC 79) in a loop.

Build a trie of all the words, storing each word on its last node. Then, for every cell whose letter is a child of the root, run dfs(r, c, parent):

  1. node = parent.children[board[r][c]]. If node.word is set, record it and clear it.
  2. Mark the cell #, and recurse into each in-bounds neighbour whose letter is a child of node.
  3. Restore the cell. If node now has no children and no word, delete it from parent (pruning).

All words are searched at the same time, a path stops the moment it leaves the trie, and pruning shrinks the trie as words are found.

Dry run

  1. trie: o-a-t-h, p-e-a, e-a-t, r-a-i-n
  2. (0,0) o → (0,1) a → (1,1) t → (2,1) h: node stores oath → found; prune h, t, a, o on the way back
  3. (1,0) e: neighbours o, i, t; none is a child of e → dead end (e stays, eat is still wanted)
  4. (1,3) e → (1,2) a → (1,1) t: eat → found; prune t, a, e
  5. (2,3) r: neighbours e, k, v; none is a child of r → dead end. Answer [oath, eat].

Python

class TrieNode:
    def __init__(self):
        self.children = {}            # letter -> TrieNode
        self.word = None              # the full word if one ends here


class Solution:
    def findWords(self, board: List[List[str]], words: List[str]) -> List[str]:
        root = TrieNode()
        for w in words:               # build the trie once
            node = root
            for ch in w:
                if ch not in node.children:
                    node.children[ch] = TrieNode()
                node = node.children[ch]
            node.word = w

        rows, cols = len(board), len(board[0])
        found = []

        def dfs(r, c, parent):
            ch = board[r][c]
            node = parent.children[ch]
            if node.word is not None:         # a complete word ends here
                found.append(node.word)
                node.word = None              # report it only once
            board[r][c] = "#"                 # in use on the current path
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] in node.children:
                    dfs(nr, nc, node)         # only step where some word continues
            board[r][c] = ch                  # backtrack: restore the letter
            if not node.children and node.word is None:
                del parent.children[ch]       # prune: nothing left to find below

        for r in range(rows):
            for c in range(cols):
                if board[r][c] in root.children:
                    dfs(r, c, root)
        return found
Time O(m·n · 4·3^(L-1)) worst case + O(total letters)Space O(total letters)

Each start explores at most 4·3^(L-1) paths, but only along trie prefixes, and pruned branches are never revisited. Building the trie costs one step per letter.

Common mistakes

  • Reporting a word twice when it can be traced along two paths ([['a', 'a']] with aa). Clear the stored word after the first find, or collect results in a set.
  • Using a cell twice in one word. Mark the cell (for example, overwrite it with #) before exploring its neighbours and restore it afterwards: abab on [['a','b'],['c','d']] must not be found.
  • Returning as soon as a word is found. oa and oaa can both be on the board, so keep exploring below a found word.
  • Forgetting to restore the cell after the recursive calls. Later start cells then see a board full of #.
  • Building the trie but still searching each word separately. The speed-up comes from checking the trie on every single move.
  • Deleting a trie node that still holds an unreported word or has children. Prune only when both are gone.

Python notes

  • Writing board[r][c] = "#" marks the cell as used without a separate visited set; # is never a trie key, so the in node.children check also rejects used cells. Restore the letter after exploring.
  • for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)): is the usual way to list the four neighbours.
  • The recursion is at most as deep as the longest word (10 letters), so recursion is safe.
  • The TrieNode class must be defined inside the solution code: only LeetCode's own node classes are pre-imported on this site.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Word Search LC 79 — a single word: plain backtracking from every cell, no trie needed.
  • Implement Trie (Prefix Tree) LC 208 — the structure used here, built and queried on its own.
  • Concatenated Words LC 472 — find words made of two or more other words from the list: a word-break DP that checks pieces against a set or trie.
  • Word Squares LC 425 — build squares that read the same across and down: a trie of prefixes proposes the candidates for each new row.
  • Boggle: diagonal moves allowed — loop over 8 directions instead of 4; everything else, including the trie pruning, stays the same.
  • What if a cell may be reused within a word? — drop the # marking; with reuse there is no path to protect, so you could memoise on (cell, trie node).
