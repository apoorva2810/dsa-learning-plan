Search Insert Position Easy 250

LeetCode #35 ↗
Status

Return where a target sits in a sorted list, or where it would be inserted, in O(log n).

Problem

You are given a list of distinct integers nums sorted in increasing order, and an integer target.

If target is in the list, return its index. If it is not, return the index where it would be inserted so that the list stays sorted: every value before that index is smaller than target, every value from that index on is larger.

Your algorithm must run in O(log n) time.

Examples

Example 1
Input: nums = [1, 3, 5, 6], target = 5
Output: 2
5 is already there, at index 2.
Example 2
Input: nums = [1, 3, 5, 6], target = 2
Output: 1
2 is missing. It belongs after the 1 and before the 3, so it would go in at index 1.
Example 3
Input: nums = [1, 3, 5, 6], target = 7
Output: 4
7 is larger than everything, so it would be appended at index 4, one past the last element.

Constraints

  • 1 <= len(nums) <= 10^4
  • -10^4 <= nums[i], target <= 10^4
  • all values are distinct and sorted in increasing order

Think first try before reading the solution

Both cases, found and missing, have the same answer: the first index whose value is greater than or equal to target. If no value qualifies, that index is len(nums). Check this against the three examples.
So you are not looking for an exact match. You are looking for the boundary between the values that are smaller than target and the values that are not. Everything left of the boundary is smaller.
Keep lo..hi so that the boundary is inside it, with hi = len(nums) allowed. If nums[mid] < target, the boundary is right of mid: lo = mid + 1. Otherwise mid itself may be the boundary: hi = mid. Stop when lo == hi.

Key idea

Read the task as one question instead of two: where does the run of values smaller than target end? If the target is present, it sits right after that run. If it is missing, that is exactly where it would be inserted. So the answer is always the first index i with nums[i] >= target, and len(nums) when there is none. This position is called the lower bound of target.

The list is sorted, so the test nums[i] < target is true for a prefix of the list and false after it. One look at the middle tells you which side of the boundary you are on: if nums[mid] < target, the boundary is to the right of mid; otherwise mid is at or past the boundary. Each look halves the range, so a list of 10,000 values needs about 14 looks.

The search range is half-open, lo..hi with hi excluded, so that hi = len(nums) can stand for "after the last element". When the loop stops, lo == hi and that single value is the answer.

Approaches from the obvious one to the one you want in an interview

Walk the list from the left and return the index of the first value that is >= target. If the target is present, that value is the target; if it is missing, it is the first bigger value, which is exactly where the target would be inserted. If the loop finishes, every value is smaller and the answer is len(nums).

Correct, and it already shows that both cases share one answer. But it ignores the sorted order and costs O(n), so it does not meet the required O(log n).

Dry run

  1. nums = [1, 3, 5, 6], target 2
  2. i = 0 → 1 < 2, keep going
  3. i = 1 → 3 ≥ 2 → return 1
  4. target 7: 1, 3, 5, 6 are all < 7 → loop ends → return 4

Python

class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        for i, value in enumerate(nums):
            if value >= target:                 # found it, or found the first bigger value
                return i
        return len(nums)                        # everything is smaller: append at the end
Time O(n)Space O(1)

When to use: Only to see that 'found' and 'missing' share one answer; too slow for the stated limit.

Watch it run

The answer is the lower bound of target: the first index i with nums[i] >= target, or len(nums).

Keep a half-open range lo..hi (index hi excluded as an element, but allowed as the answer) that contains the boundary, starting with lo = 0, hi = len(nums).

  1. mid = (lo + hi) // 2.
  2. nums[mid] < target → the boundary is right of mid: lo = mid + 1.
  3. Otherwise mid may be the boundary: hi = mid (keep it).
  4. Stop when lo == hi and return lo.

There is no early exit on an exact hit: finding the target is just the special case where nums[lo] equals it. The range halves each round, so there are at most about log₂ n rounds, and hi = len(nums) falls out of the loop naturally when every value is smaller.

Dry run

  1. nums = [1, 3, 5, 6], target 2: lo = 0, hi = 4
  2. mid = 2 → 5 ≥ 2 → hi = 2
  3. mid = 1 → 3 ≥ 2 → hi = 1
  4. mid = 0 → 1 < 2 → lo = 1 → lo == hi → return 1
  5. target 7: mid = 2 → 5 < 7 → lo = 3; mid = 3 → 6 < 7 → lo = 4 → lo == hi == 4 → return 4

Python

class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        lo, hi = 0, len(nums)                   # half-open: hi = len(nums) means "after the last element"
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] < target:
                lo = mid + 1                    # mid and everything left of it are too small
            else:
                hi = mid                        # mid is >= target, so it may be the first such index
        return lo                               # lo == hi: first index with nums[i] >= target
Time O(log n)Space O(1)

The range halves every round: at most ⌈log₂(n + 1)⌉ rounds, each O(1).

When to use: The answer here, and the lower-bound template reused by every 'first position where ...' problem.

bisect.bisect_left(nums, target) is the lower bound by definition: the leftmost position where target could be inserted and keep the list sorted. That is this problem in one call, in C.

Same O(log n). Write the loop yourself in an interview, then mention that this is what real code would use.

Python

class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        return bisect.bisect_left(nums, target)     # first index with nums[i] >= target, or len(nums)
Time O(log n)Space O(1)

When to use: Production Python; it also handles duplicates by inserting before the copies.

Common mistakes

  • Returning -1 when the target is missing, as in plain Binary Search. This problem wants the insert position; the search must keep going until the range collapses to one index.
  • Setting hi = len(nums) - 1 in the half-open version: a target larger than every element must return len(nums), which that range can never produce.
  • Writing hi = mid - 1 when nums[mid] >= target: mid may be the very boundary you want, so skipping it can return an index that is one too far right. Keep it with hi = mid.
  • Using while lo <= hi together with hi = mid: once lo == hi the range never shrinks and the loop runs forever. The half-open version loops while lo < hi.
  • Calling nums.index(target) or target in nums: both scan the whole list in O(n) and the first one raises ValueError when the target is missing.

Python notes

  • bisect.bisect_left(nums, target) is exactly the lower bound: the first index i with nums[i] >= target, or len(nums). bisect.bisect_right returns the first index with nums[i] > target instead; the two differ only when the target is present.
  • bisect.insort(nums, target) finds the position and inserts in one call. The insert itself shifts the tail, so it is O(n); only the search is O(log n).
  • (lo + hi) // 2 rounds down and cannot overflow in Python, so the lo + (hi - lo) // 2 form from C and Java is not needed.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Binary Search LC 704 — the plain version: return -1 instead of the insert position, so the loop can stop early on an exact hit.
  • Find First and Last Position of Element in Sorted Array LC 34 — duplicates are allowed: the lower bound of target gives the first position and the lower bound of target + 1, minus one, gives the last.
  • First Bad Version LC 278 — the same boundary search with no list at all: the check isBadVersion(mid) is false, then true, and you want the first true.
  • Search a 2D Matrix LC 74 — the sorted data is a matrix: treat it as one long list and map mid to a row and column.
  • Find Smallest Letter Greater Than Target LC 744 — an upper bound: first letter strictly greater than the target, with wrap-around to the first letter when none exists.
  • What if the list may contain duplicates? — the same code still returns the first index with nums[i] >= target, so a duplicate target is inserted before its copies. Nothing changes.
