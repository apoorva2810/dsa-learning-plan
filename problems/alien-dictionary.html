Alien Dictionary Hard

LeetCode #269 ↗
Status

Recover an unknown alphabet's letter order from a word list sorted in that alphabet.

Problem

An alien language uses lowercase English letters, but in an order you do not know. You are given words, a list that is claimed to be sorted in the alien dictionary order.

Return a string containing every letter that appears in words, each exactly once, in an order that makes the list sorted. If several orders work, return any of them. If no order can make the list sorted, return "".

"Sorted" means the usual dictionary rule: compare two words letter by letter; the first position where they differ decides; if one word runs out first (it is a prefix of the other), the shorter word comes first.

Examples

Example 1
Input: words = ["wrt", "wrf", "er", "ett", "rftt"]
Output: "wertf"
wrt/wrf gives t < f, wrf/er gives w < e, er/ett gives r < t, ett/rftt gives e < r. Chained: w < e < r < t < f.
Example 2
Input: words = ["z", "x"]
Output: "zx"
Example 3
Input: words = ["z", "x", "z"]
Output: ""
The list says z < x and also x < z. No alphabet can do both.
Example 4
Input: words = ["abc", "ab"]
Output: ""
"ab" is a prefix of "abc", so it must come first under every alphabet.

Constraints

  • 1 <= len(words) <= 100
  • 1 <= len(words[i]) <= 100
  • words[i] consists of lowercase English letters

Think first try before reading the solution

Look at two neighbouring words, like wrt and wrf. Which part of them tells you anything about the alphabet?
Only the first position where they differ: there, the letter of the first word comes before the letter of the second (t before f). Everything after that position says nothing. Each such fact is an arrow between two letters.
Collect one arrow per neighbouring pair, then list the letters so every arrow points forward: a topological sort (Kahn's algorithm). A cycle, or a word placed directly before its own prefix, means the answer is "".

Key idea

The alphabet is hidden in the comparisons. Take two neighbouring words: up to their first difference they agree, so the letters there tell you nothing; at the first difference, the first word's letter must come before the second word's letter. Nothing after that position matters, because the first difference already decided the comparison. Each pair of neighbours gives at most one rule, and each rule is a directed edge between two letters.

Now the question is Course Schedule II on letters: put the letters in an order where every edge points forward, a topological order. Kahn's algorithm builds it, and if a cycle stops it from placing every letter, no alphabet exists. Letters that appear in the words but in no rule are still part of the answer; they have no constraints.

Comparing only neighbouring words is enough: if an alphabet puts every neighbouring pair in order, the whole list is in order, because "comes before" is transitive. One special case gives no rule but breaks everything: a word followed by its own prefix ("abc" then "ab") is wrong under every alphabet.

Approaches from the obvious one to the one you want in an interview

Take the distinct letters and try every ordering of them. For each candidate alphabet, turn every word into a list of letter ranks and check that the list of words is in non-decreasing order (Python compares lists exactly like a dictionary does, including the "prefix comes first" rule). Return the first alphabet that works, or "".

It is a direct translation of the question, but with k distinct letters there are k! alphabets: 5 letters give 120 candidates, 10 letters give 3.6 million, and all 26 give about 4 · 10²⁶.

Dry run

  1. words = ["z", "x"]: letters x, z → try "xz": ranks [[1], [0]] are not sorted → try "zx": [[0], [1]] ✓
  2. Return "zx". With ["z", "x", "z"] neither alphabet works → ""

Python

class Solution:
    def alienOrder(self, words: List[str]) -> str:
        letters = sorted(set("".join(words)))
        for alphabet in itertools.permutations(letters):          # every possible order
            rank = {c: i for i, c in enumerate(alphabet)}
            keys = [[rank[c] for c in word] for word in words]    # words as lists of ranks
            if all(keys[i] <= keys[i + 1] for i in range(len(keys) - 1)):
                return "".join(alphabet)                           # the list is sorted under this alphabet
        return ""
Time O(k! · C)Space O(C)

k distinct letters give k! alphabets; each check reads all C characters.

When to use: Never beyond toy inputs; it shows that the real task is to derive constraints, not to search.

  1. Make a node for every letter that appears.
  2. For each pair of neighbouring words, find the first position where they differ. If the letters there are x and y, add the edge x → y (once) and raise y's in-degree. If there is no difference and the first word is longer, return "": a word cannot come after its own prefix.
  3. Topologically sort with Kahn's algorithm: queue the letters with in-degree 0, pop one, append it, lower the in-degree of its successors, queue any that reach 0.
  4. If every letter was placed, return the order; otherwise the rules contain a cycle, so return "".

Building the rules reads each character at most once, and there are at most 26 nodes and N - 1 edges: O(C) for C total characters.

Dry run

  1. ["wrt", "wrf", "er", "ett", "rftt"] → rules t → f, w → e, r → t, e → r
  2. In-degrees: w 0, e 1, r 1, t 1, f 1 → queue [w]
  3. Place w → e free → place e → r free → place r → t free → place t → f free → place f
  4. Five letters placed → "wertf"

Python

class Solution:
    def alienOrder(self, words: List[str]) -> str:
        graph = {c: [] for word in words for c in word}       # every letter is a node
        indegree = {c: 0 for c in graph}
        for first, second in zip(words, words[1:]):           # neighbouring words only
            for x, y in zip(first, second):
                if x != y:                                    # the first difference decides: x before y
                    if y not in graph[x]:                     # add each rule once
                        graph[x].append(y)
                        indegree[y] += 1
                    break
            else:                                             # no difference within the shorter word
                if len(first) > len(second):                  # e.g. "abc" listed before "ab"
                    return ""
        queue = deque(c for c in graph if indegree[c] == 0)
        order = []
        while queue:
            c = queue.popleft()
            order.append(c)
            for nxt in graph[c]:
                indegree[nxt] -= 1
                if indegree[nxt] == 0:
                    queue.append(nxt)
        return "".join(order) if len(order) == len(graph) else ""   # leftovers mean a cycle
Time O(C)Space O(1) beyond the input

C = total characters. The graph has at most 26 nodes and N - 1 edges, so it is constant-sized.

When to use: The standard answer: rules from neighbours, then the same Kahn loop as Course Schedule II.

Watch it run

Build the rules exactly as above, then order the letters with depth-first search. Colour letters white (unvisited), grey (on the current path) and black (finished). A letter is appended to finished only after every letter that must come after it is finished, so finished holds the alphabet back to front; reverse it. Meeting a grey letter means the rules loop back on themselves: return "".

Same O(C); it trades the in-degree counts for recursion.

Dry run

  1. Rules t → f, w → e, r → t, e → r. dfs(w) → dfs(e) → dfs(r) → dfs(t) → dfs(f)
  2. f finishes first, then t, r, e, w → finished = [f, t, r, e, w]
  3. Reversed: "wertf"

Python

class Solution:
    def alienOrder(self, words: List[str]) -> str:
        graph = {c: [] for word in words for c in word}
        for first, second in zip(words, words[1:]):
            for x, y in zip(first, second):
                if x != y:
                    if y not in graph[x]:
                        graph[x].append(y)
                    break
            else:
                if len(first) > len(second):
                    return ""
        WHITE, GREY, BLACK = 0, 1, 2
        colour = {c: WHITE for c in graph}
        finished = []                                  # letters in the order their search completes

        def dfs(c: str) -> bool:                       # False means a cycle was found
            colour[c] = GREY
            for nxt in graph[c]:
                if colour[nxt] == GREY:                # back onto the current path: contradictory rules
                    return False
                if colour[nxt] == WHITE and not dfs(nxt):
                    return False
            colour[c] = BLACK
            finished.append(c)                         # everything that must follow c is already finished
            return True

        for c in graph:
            if colour[c] == WHITE and not dfs(c):
                return ""
        return "".join(reversed(finished))
Time O(C)Space O(1) beyond the input

Same rule-building pass; the DFS touches at most 26 letters and N - 1 edges.

When to use: If you already think of topological sort as 'reverse finishing order'.

Common mistakes

  • Reading rules beyond the first difference. "ab" before "ba" says a < b, and nothing about b and a in the second position.
  • Dropping letters that appear in no rule. In ["ab", "adc"] only b < d is known, but a and c must still be in the output. Create a node for every letter of every word first.
  • Missing the prefix case. ["abc", "ab"] has no differing position at all, yet it is invalid: return "".
  • Counting the same rule twice. If y is added to x's list twice but you guard the in-degree with a set (or the other way round), y's count never reaches 0. Add each edge once and keep both structures in step.
  • Comparing every pair of words. It is O(N²) comparisons and adds no information beyond the N - 1 neighbouring pairs.

Python notes

  • {c: [] for word in words for c in word} makes a node for every letter that appears, in order of first appearance.
  • zip(words, words[1:]) walks the neighbouring pairs; zip(first, second) stops at the shorter word.
  • for ... else: the else branch runs only if the loop finished without break, i.e. no differing letter was found. That is exactly where the prefix check belongs.
  • Using lists for the adjacency (instead of sets) keeps the output order the same on every run; Python randomises the iteration order of sets of strings between runs.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Verifying an Alien Dictionary LC 953 — the reverse question: the order is given and you check the list. Map each letter to its rank and compare neighbours.
  • Course Schedule II LC 210 — the same topological sort when the rules are handed to you directly as pairs.
  • Sequence Reconstruction LC 444 — is the order unique? Only if Kahn's queue never holds more than one node at a time.
  • What if you must return the alphabetically smallest valid order? — replace the queue with a min-heap, so the smallest free letter is always placed next.
  • What if some words are not distinct or the list is huge? — duplicates add no rule and need no special case; a huge list still needs only one pass over neighbouring pairs, O(total characters).
