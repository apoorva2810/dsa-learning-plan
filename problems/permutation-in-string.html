Permutation in String Medium

LeetCode #567 ↗
Status

Decide whether some window of one string is a rearrangement of another string.

Problem

Given two strings s1 and s2, return True if s2 contains a permutation (a rearrangement) of s1 as a contiguous substring, and False otherwise.

Equivalently: is there a window of exactly len(s1) consecutive characters in s2 that holds the same letters as s1, with the same counts? Both strings consist of lowercase English letters.

Examples

Example 1
Input: s1 = "ab", s2 = "eidbaooo"
Output: true
"ba" starts at index 3 of s2.
Example 2
Input: s1 = "ab", s2 = "eidboaoo"
Output: false
s2 contains an a and a b, but never next to each other.
Example 3
Input: s1 = "adc", s2 = "dcda"
Output: true
"cda" at index 1.

Constraints

  • 1 <= len(s1), len(s2) <= 10^4
  • s1 and s2 consist of lowercase English letters

Key idea

Two strings are permutations of each other exactly when they contain the same letters with the same counts. So the question becomes: does some window of length m = len(s1) in s2 have the same counts as s1?

Recounting every window costs O(m) each. A fixed-size sliding window updates the counts in O(1) per step: add the letter entering on the right, remove the one leaving on the left. To avoid comparing all 26 counts at every step, keep one extra number, missing: how many of s1's letters the window still lacks. When missing hits 0 the window holds every letter it needs, and because it is exactly m long, there is no room for anything extra. It is a permutation.

Approaches from the obvious one to the one you want in an interview

Two strings are permutations of each other exactly when their sorted forms are equal. So sort s1 once, then sort every window of len(s1) characters in s2 and compare.

There are n - m + 1 windows and each sort costs O(m log m). Neighbouring windows share all but one character, yet each one is rebuilt and re-sorted from scratch: that repeated work is what the sliding window removes. (Generating all m! permutations of s1 would be far worse still.)

Python

class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        m = len(s1)
        target = sorted(s1)
        for start in range(len(s2) - m + 1):          # empty range when s1 is longer than s2
            if sorted(s2[start:start + m]) == target:  # same letters, same counts
                return True
        return False
Time O((n − m + 1) · m log m)Space O(m)

n = len(s2), m = len(s1); each window is copied and sorted.

When to use: Fine for tiny inputs or a quick correctness check.

Count the 26 letters of s1 in an array need, and the letters of the first window of s2 in window. Then slide: add the entering letter, subtract the leaving one, and compare the two arrays after each step.

Sliding is O(1), but comparing two arrays of 26 counts is O(26) per window, so the total is O(26 · n). That is linear, and it is the version most people write first.

Python

class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        m, n = len(s1), len(s2)
        if m > n:
            return False
        need = [0] * 26
        window = [0] * 26
        for i in range(m):                            # counts for s1 and for the first window
            need[ord(s1[i]) - ord("a")] += 1
            window[ord(s2[i]) - ord("a")] += 1
        if need == window:
            return True
        for right in range(m, n):
            window[ord(s2[right]) - ord("a")] += 1        # letter entering on the right
            window[ord(s2[right - m]) - ord("a")] -= 1    # letter leaving on the left
            if need == window:                            # 26 comparisons
                return True
        return False
Time O(26 · n)Space O(26)

Each slide is O(1); each comparison scans 26 counts.

When to use: Simple and fast enough; the optimal version removes the 26× comparison cost.

Track how far the window is from a match with a single number instead of comparing whole count arrays.

  • need = Counter(s1): copies of each letter still required (it goes negative for surplus copies).
  • missing = len(s1): required letters not yet in the window.
  • Letter c enters: if need[c] > 0 it fills a gap, so missing -= 1; then need[c] -= 1.
  • Once the window is longer than len(s1), letter old leaves: need[old] += 1, and if that makes it positive, a gap reopened, so missing += 1.
  • missing == 0 with a window of exactly len(s1) letters means a permutation.

Every step is O(1), so the scan is O(n).

Dry run

  1. s1 = "ab", s2 = "eidbaooo": need {a: 1, b: 1}, missing 2
  2. e and i enter (both surplus) → window ei, missing 2
  3. d enters, e leaves (both surplus) → window id, missing 2
  4. b enters (needed) → missing 1; i leaves (surplus) → window db
  5. a enters (needed) → missing 0; d leaves (surplus) → window ba → True

Python

class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        m = len(s1)
        if m > len(s2):
            return False
        need = Counter(s1)                    # copies still needed (negative = surplus in the window)
        missing = m                           # letters of s1 the window still lacks
        for right, c in enumerate(s2):
            if need[c] > 0:
                missing -= 1                  # c fills a real gap
            need[c] -= 1
            if right >= m:                    # window too long: the letter at right - m leaves
                old = s2[right - m]
                need[old] += 1
                if need[old] > 0:
                    missing += 1              # we just lost a letter we needed
            if missing == 0:
                return True
        return False
Time O(n)Space O(26)

Constant work per character of s2 (plus O(m) to count s1); at most 26 keys in need.

When to use: The optimal answer, and the same bookkeeping that Minimum Window Substring uses.

Common mistakes

  • Forgetting the case len(s1) > len(s2): no window fits, so return False before indexing into s2.
  • Letting the window grow past len(s1). A longer window that merely contains the letters is not a permutation (that is Minimum Window Substring).
  • Decrementing missing for every incoming letter. Only a letter that was still needed (need[c] > 0 before the decrement) reduces it; surplus copies do not.
  • Comparing plain dictionaries of counts after decrementing to 0 without deleting the key: {'a': 0} != {}.

Python notes

  • ord(c) - ord("a") maps a lowercase letter to 0..25, so two lists of 26 counts can stand in for dictionaries; list_a == list_b compares them in O(26).
  • Counter(s1) builds the needed counts in one call, and reading a letter that is not in it returns 0 instead of raising KeyError.
  • sorted(window) == sorted(s1) is a quick but O(m log m) check of a single window.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Find All Anagrams in a String LC 438 — collect every start index where missing == 0 instead of returning at the first one.
  • Minimum Window Substring LC 76 — the window may contain extra letters and its size is free: grow until it covers t, then shrink to find the shortest.
  • Valid Anagram LC 242 — the single-window version: compare the counts of two whole strings.
  • Substring with Concatenation of All Words LC 30 — the units are equal-length words instead of letters: slide the window one word at a time, from each of the word_len possible starting offsets.
  • What if the strings use all of Unicode? — the 26-slot count arrays become dictionaries; the missing counter version works unchanged.
