Surrounded Regions Medium

LeetCode #130 ↗
Status

Flip every region of 'O' cells that is completely enclosed by 'X' cells, in place.

Problem

You are given an m × n board of "X" and "O" characters. A region is a group of "O" cells joined horizontally or vertically. A region is surrounded when none of its cells lies on the border of the board: then it is completely enclosed by "X" cells.

Capture every surrounded region by turning all of its "O" cells into "X". Regions that touch the border stay as they are. Modify board in place; the method returns nothing.

Examples

Example 1
Input: board = [["X","X","X","X"],["X","O","O","X"],["X","X","O","X"],["X","O","X","X"]]
Output: [["X","X","X","X"],["X","X","X","X"],["X","X","X","X"],["X","O","X","X"]]
The three O cells in the middle are enclosed and get captured. The O at (3,1) is on the border, so it stays.
Example 2
Input: board = [["X"]]
Output: [["X"]]
Example 3
Input: board = [["O","O"],["O","O"]]
Output: [["O","O"],["O","O"]]
Every cell is on the border, so nothing can be surrounded.

Constraints

  • 1 <= m, n <= 200
  • board[i][j] is "X" or "O"

Think first try before reading the solution

Checking every region for a way out to the border works, but how could you tell which O cells are safe without examining each region separately?
An O region survives exactly when one of its cells is on the border. So start from the border O cells and flood inward: everything you reach is safe.
Mark every O reachable from a border O as safe (DFS or BFS). Then sweep the board once: an O that is not safe is surrounded, so flip it.

Key idea

The definition hides a simpler test: a region is not captured exactly when it touches the border. So instead of asking each region "can you reach the border?", ask the border "which O cells can you reach?".

Walk along the four edges. From every border "O", flood fill through neighbouring "O" cells and mark them all as safe. Any "O" the flood never touched must belong to a region with no border cell, so it is surrounded: one final sweep flips it to "X". Each cell is marked at most once and swept once, so the work is O(m · n).

Approaches from the obvious one to the one you want in an interview

For each "O", search through neighbouring "O" cells (with a fresh visited set) to see whether any of them is on the border. If none is, the cell is enclosed; remember it. After every cell has been checked, flip the remembered cells. Flipping only at the end keeps each search looking at the original board.

Each search can walk a whole region, and a region of k cells is searched once from each of its k cells, so the worst case is O((m · n)²).

Dry run

  1. Example 1: from (1,1) the search reaches (1,2) and (2,2) and finds no border cell → enclosed.
  2. (1,2) and (2,2) repeat the same search and reach the same verdict.
  3. (3,1) is itself on the border → safe. Flip (1,1), (1,2), (2,2).

Python

class Solution:
    def solve(self, board: List[List[str]]) -> None:
        rows, cols = len(board), len(board[0])

        def escapes(sr: int, sc: int) -> bool:
            seen = {(sr, sc)}
            stack = [(sr, sc)]
            while stack:
                r, c = stack.pop()
                if r in (0, rows - 1) or c in (0, cols - 1):
                    return True                       # this region touches the border
                for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                    if board[nr][nc] == "O" and (nr, nc) not in seen:   # inner cells: neighbours are in range
                        seen.add((nr, nc))
                        stack.append((nr, nc))
            return False

        enclosed = [(r, c) for r in range(rows) for c in range(cols)
                    if board[r][c] == "O" and not escapes(r, c)]
        for r, c in enclosed:                         # flip only after every search is finished
            board[r][c] = "X"
Time O((m · n)²)Space O(m · n)

Up to m · n searches, each of which may cover the whole board.

When to use: Only as the first idea. It shows that the real question is 'does the region touch the border?'.

Reverse the search. Run a DFS from every "O" on the border, adding each "O" it reaches to safe. These are exactly the cells whose region touches the border. Then sweep the board: every "O" not in safe is enclosed, so flip it to "X".

Each cell enters safe at most once and the sweep looks at each cell once: O(m · n) in total, compared with one search per cell in the brute force.

Dry run

  1. Example 1. Border cells: only (3,1) is an O → dfs(3,1) marks it safe; its up neighbour (2,1) is X, so the flood stops.
  2. Sweep: (1,1), (1,2), (2,2) are O and not safe → flip them to X.
  3. (3,1) is safe → it stays O.

Python

class Solution:
    def solve(self, board: List[List[str]]) -> None:
        rows, cols = len(board), len(board[0])
        safe = set()                                  # O cells connected to the border

        def dfs(r: int, c: int) -> None:
            if r < 0 or r >= rows or c < 0 or c >= cols:
                return
            if board[r][c] != "O" or (r, c) in safe:
                return
            safe.add((r, c))
            dfs(r + 1, c)
            dfs(r - 1, c)
            dfs(r, c + 1)
            dfs(r, c - 1)

        for r in range(rows):                         # 1) flood inward from every border cell
            dfs(r, 0)
            dfs(r, cols - 1)
        for c in range(cols):
            dfs(0, c)
            dfs(rows - 1, c)
        for r in range(rows):                         # 2) every other O is enclosed: capture it
            for c in range(cols):
                if board[r][c] == "O" and (r, c) not in safe:
                    board[r][c] = "X"
Time O(m · n)Space O(m · n)

Each cell is added to safe at most once and swept once; safe and the call stack can each hold every cell.

When to use: The standard answer. The 'search from the border inward' trick appears in many grid problems.

Watch it run

Give every cell a number r * cols + c and add one extra node, BORDER, that stands for "touches the edge". Union every border "O" with BORDER, and union every pair of neighbouring "O" cells (looking right and down covers each pair once). Afterwards an "O" is safe exactly when it is in the same group as BORDER; flip all the others.

find(x) follows parent links up to the group's root; on the way it re-points each node to its grandparent (path halving), which keeps the trees flat so later finds are almost free. Same O(m · n) work in practice, no recursion, and the virtual-node trick ("one node that means connected to something special") is reusable.

Python

class Solution:
    def solve(self, board: List[List[str]]) -> None:
        rows, cols = len(board), len(board[0])
        BORDER = rows * cols                          # an extra node meaning "connected to the edge"
        parent = list(range(rows * cols + 1))

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]         # path halving keeps the trees flat
                x = parent[x]
            return x

        def union(a: int, b: int) -> None:
            parent[find(a)] = find(b)

        for r in range(rows):
            for c in range(cols):
                if board[r][c] != "O":
                    continue
                if r in (0, rows - 1) or c in (0, cols - 1):
                    union(r * cols + c, BORDER)       # a border O joins the border group
                for nr, nc in ((r + 1, c), (r, c + 1)):   # down and right: each neighbouring pair once
                    if nr < rows and nc < cols and board[nr][nc] == "O":
                        union(r * cols + c, nr * cols + nc)
        border_root = find(BORDER)
        for r in range(rows):
            for c in range(cols):
                if board[r][c] == "O" and find(r * cols + c) != border_root:
                    board[r][c] = "X"                 # not connected to the edge: captured
Time O(m · n · α(m · n))Space O(m · n)

α is the inverse Ackermann function, below 5 for any real input.

When to use: When recursion depth is a concern, or when the board changes and connectivity must be updated incrementally.

Common mistakes

  • Flipping cells during the first scan, before you know whether their region touches the border: a region that is safe through a far-away border cell gets captured by mistake. Mark first, flip afterwards.
  • Starting the flood only from the first and last rows: O cells on the left and right columns are on the border too.
  • Treating corner contact as a connection: only up, down, left and right join cells.
  • Assigning a new board (board = [...]) inside the method: the caller keeps the old one. Change the cells of board itself.
  • Recursion depth on a 200 × 200 board of O cells: up to 40,000 nested calls. Use the BFS or union-find variant when the limit is a concern.

Python notes

  • The method returns None; change board[r][c] directly so the caller sees the result.
  • A common trick avoids the safe set: mark border-connected cells with a temporary letter such as "T", then sweep once turning "O" into "X" and "T" back into "O".
  • r in (0, rows - 1) or c in (0, cols - 1) is a compact "is this a border cell?" test.
  • Iterating over the border twice (rows, then columns) visits the corners twice; the visited check makes that harmless.
