Maximum Product Subarray Medium

LeetCode #152 ↗
Status

Find the contiguous stretch of an array whose product is largest, where negatives can flip signs.

Problem

Given an integer list nums, find the contiguous, non-empty subarray whose product is as large as possible and return that product.

The values can be negative or zero. The answer fits in a 32-bit integer.

Examples

Example 1
Input: nums = [2, 3, -2, 4]
Output: 6
[2, 3] has product 6.
Example 2
Input: nums = [-2, 0, -1]
Output: 0
[-2, -1] would give 2, but it is not contiguous: the 0 sits between them.
Example 3
Input: nums = [-2, 3, -4]
Output: 24
The whole array: two negatives multiply to a positive.

Constraints

  • 1 <= len(nums) <= 2 * 10^4
  • -10 <= nums[i] <= 10
  • every prefix and suffix product fits in a 32-bit integer

Think first try before reading the solution

For sums (Maximum Subarray) you only track the best sum ending at each index. Why is that not enough for products? Try [-2, 3, -4].
A negative number turns the smallest product into the largest one. So for each index track both the largest and the smallest product of a subarray ending there.
At each x, the new maximum and minimum come from three candidates: x alone, max_before × x and min_before × x. A zero resets both to 0, and the next element starts fresh.

Key idea

For sums, "the best subarray ending here" only needs the best one ending at the previous index. Products break that rule because a negative number flips the order: the most negative product so far, times another negative, becomes the largest. In [-2, 3, -4] the best product ending at 3 is 3, but the answer uses the worst one, -2 × 3 = -6, which times -4 gives 24.

So keep two numbers per position: hi, the largest product of a subarray ending here, and lo, the smallest (most negative). For the next element x there are only three ways to form a subarray ending at x: start fresh (x), extend the largest run (hi × x) or extend the smallest (lo × x). The new hi is the largest of those three, the new lo the smallest. Including x alone is what handles zeros: after a zero both runs are 0, and the next element simply starts over.

The answer is the largest hi seen anywhere, since the best subarray can end at any index.

Approaches from the obvious one to the one you want in an interview

Fix a start i and extend the end j one element at a time, multiplying the running product by nums[j]. Every subarray nums[i..j] gets its product in O(1) from the previous one, so the whole scan is O(n²) instead of O(n³).

It is simple and obviously correct, but with 2 × 10^4 elements it computes about 2 × 10^8 products.

Dry run

  1. nums = [2, 3, -2, 4]
  2. i = 0: products 2, 6, -12, -48 → best 6
  3. i = 1: 3, -6, -24; i = 2: -2, -8; i = 3: 4 → best stays 6

Python

class Solution:
    def maxProduct(self, nums: List[int]) -> int:
        best = nums[0]
        for i in range(len(nums)):
            product = 1
            for j in range(i, len(nums)):      # subarray nums[i..j]
                product *= nums[j]             # extend the previous product by one element
                best = max(best, product)
        return best
Time O(n²)Space O(1)

n(n + 1)/2 subarrays, O(1) each thanks to the running product.

When to use: As a correctness check for small inputs.

Keep two tables. hi[i] = largest product of a subarray that ends exactly at i; lo[i] = the smallest. A subarray ending at i is either nums[i] alone or a subarray ending at i - 1 extended by nums[i], and the extension that matters is the largest or the smallest one (a negative x reverses which is which). So

  • hi[i] = max(x, hi[i-1] × x, lo[i-1] × x)
  • lo[i] = min(x, hi[i-1] × x, lo[i-1] × x)

and the answer is max(hi). This is the "best answer ending at index i" DP pattern, with two values per index.

Dry run

  1. nums = [-2, 3, -4]: hi[0] = lo[0] = -2
  2. x = 3: candidates (3, -6, -6) → hi[1] = 3, lo[1] = -6
  3. x = -4: candidates (-4, -12, 24) → hi[2] = 24, lo[2] = -12
  4. answer max(hi) = 24

Python

class Solution:
    def maxProduct(self, nums: List[int]) -> int:
        n = len(nums)
        hi = [0] * n        # hi[i] = largest product of a subarray ending at i
        lo = [0] * n        # lo[i] = smallest product of a subarray ending at i
        hi[0] = lo[0] = nums[0]
        for i in range(1, n):
            x = nums[i]
            # start fresh at x, or extend the largest / smallest run that ends at i - 1
            candidates = (x, hi[i - 1] * x, lo[i - 1] * x)
            hi[i] = max(candidates)
            lo[i] = min(candidates)
        return max(hi)      # the best subarray may end anywhere
Time O(n)Space O(n)

One pass with three candidates per index; two tables of n entries.

When to use: To see the state clearly before compressing it.

Watch it run

Each step reads only hi[i-1] and lo[i-1], so keep them as cur_max and cur_min, plus best for the answer. Compute both new values from the same three candidates before overwriting either.

Dry run

  1. nums = [2, 3, -2, 4]: cur_max = cur_min = best = 2
  2. x = 3: (3, 6, 6) → max 6, min 3, best 6
  3. x = -2: (-2, -12, -6) → max -2, min -12
  4. x = 4: (4, -8, -48) → max 4, min -48; best stays 6

Python

class Solution:
    def maxProduct(self, nums: List[int]) -> int:
        cur_max = cur_min = best = nums[0]
        for x in nums[1:]:
            candidates = (x, cur_max * x, cur_min * x)
            cur_max, cur_min = max(candidates), min(candidates)   # both from the OLD values
            best = max(best, cur_max)
        return best
Time O(n)Space O(1)

One pass, three variables.

When to use: The interview answer; explain why the minimum must be kept.

Watch it run

A different argument with the same O(n). Zeros split the array into zero-free segments. Inside a segment, if the number of negatives is even, the whole segment is best; if it is odd, the best drops everything up to the first negative (a suffix of the segment) or everything from the last negative on (a prefix). So the answer is always a prefix or a suffix of some segment.

Scan from the left and from the right at the same time, multiplying running products, and restart a product after a zero ((product or 1) * x). The largest running product seen in either direction is the answer.

Dry run

  1. nums = [2, -5, -2, -4, 3] (three negatives)
  2. prefix products: 2, -10, 20, -80, -240
  3. suffix products: 3, -12, 24, -120, -240
  4. largest value seen: 24 (the suffix [-2, -4, 3])

Python

class Solution:
    def maxProduct(self, nums: List[int]) -> int:
        n = len(nums)
        best = nums[0]
        prefix = suffix = 0
        for i in range(n):
            prefix = (prefix or 1) * nums[i]           # restart after a zero
            suffix = (suffix or 1) * nums[n - 1 - i]
            best = max(best, prefix, suffix)
        return best
Time O(n)Space O(1)

One pass, two running products.

When to use: A neat alternative if the interviewer asks for a second O(n) idea; the DP version generalises better.

Common mistakes

  • Tracking only the maximum, as in Kadane's algorithm for sums: [-2, 3, -4] returns 3 instead of 24, because the needed -6 was thrown away.
  • Updating cur_max first and then computing cur_min from the new cur_max. Compute both from the old values (tuple assignment or a temporary).
  • Starting best at 0. For [-2] the answer is -2; start from nums[0].
  • Dropping the "start fresh" candidate x: after a zero, hi × x and lo × x are both 0, and a following positive run would never be counted.

Python notes

  • max(a, b, c) and min(a, b, c) take any number of arguments, so the three candidates fit on one line.
  • cur_max, cur_min = max(cands), min(cands) computes both from the same old-value candidates; never update one before the other is computed.
  • Python integers never overflow, so the brute force's long products are exact (in Java or C++ they could wrap).
  • A top-down version would return a (hi, lo) pair per index with @cache, but it would recurse n deep: with 2 × 10^4 elements that breaks Python's default recursion limit of 1000. The loop is the natural form here.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Maximum Subarray LC 53 — sums instead of products: adding a negative never helps the minimum become the maximum, so one running best (Kadane) is enough.
  • Maximum Length of Subarray With Positive Product LC 1567 — track the lengths of the longest positive-product and negative-product runs ending at i; a negative swaps them, exactly like hi and lo here.
  • Subarray Product Less Than K LC 713 — all values positive and you count subarrays below k: products only grow, so a sliding window works.
  • Product of Array Except Self LC 238 — the other classic use of prefix and suffix products, without division.
  • Return the subarray, not just its product — store where the current hi and lo runs started; when a candidate x alone wins, the run restarts at the current index.
