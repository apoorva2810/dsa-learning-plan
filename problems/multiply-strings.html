Multiply Strings Medium

LeetCode #43 ↗
Status

Multiply two non-negative integers given as strings, without converting the whole strings to numbers.

Problem

You are given two non-negative integers num1 and num2 as strings of decimal digits (no leading zeros, except for "0" itself). Return their product, also as a string.

You may not convert the inputs directly to integers with int(num1) or similar, and you may not use a big-integer library. The point is to do the arithmetic digit by digit, the way you would on paper.

Examples

Example 1
Input: num1 = "2", num2 = "3"
Output: "6"
Example 2
Input: num1 = "123", num2 = "456"
Output: "56088"
123 × 456 = 56088.
Example 3
Input: num1 = "0", num2 = "9999"
Output: "0"
Anything times zero is zero; make sure you do not return "0000".

Constraints

  • 1 <= len(num1), len(num2) <= 200
  • num1 and num2 consist of digits only
  • no leading zeros except the number 0 itself

Think first try before reading the solution

How do you multiply 123 × 456 on paper? You multiply 123 by each digit of 456 separately, shift each partial result left by the digit's position, and add everything up.
Every pair of digits num1[i] * num2[j] lands in a known column of the answer. If you count positions from the right, digit i from the right times digit j from the right contributes to position i + j.
Add all pair products into a list of columns first, without worrying about values above 9. Then do one pass from the right carrying anything ≥ 10 into the next column, exactly like Plus One.

Key idea

Schoolbook multiplication is two separate jobs: where each digit product goes, and carrying.

Write both numbers with digit 0 as the units digit (count from the right). The product a_i × b_j is worth a_i × b_j × 10^(i+j), so it belongs in column i + j. The answer has at most len(num1) + len(num2) digits, so make that many columns, all zero, and add every pair product into its column. The columns can temporarily hold numbers far bigger than 9, and that is fine.

Once every pair has been added, sweep the columns from right to left: each column keeps value % 10 and passes value // 10 to the next one. Finally drop leading zeros and reverse. Every one of the n × m digit pairs is visited once, so the whole thing is O(n·m), and 200 × 200 = 40,000 steps is nothing.

Approaches from the obvious one to the one you want in an interview

Do exactly what the paper method does, one row at a time: multiply num1 by a single digit of num2 (a small helper), append the right number of zeros for that digit's position, and add the row into a running total with a string-addition helper (the Add Strings problem).

It is correct and shows the structure clearly, but each row addition is O(n + m) and there are m rows, with extra string building on top. The column method below does the same work with far less machinery.

Dry run

  1. 123 × 456: rows are 123×6 = 738, 123×5 = 615 shifted one place → 6150, 123×4 = 492 shifted two → 49200.
  2. Sum: 738 + 6150 = 6888, 6888 + 49200 = 56088.

Python

class Solution:
    def multiply(self, num1: str, num2: str) -> str:
        if num1 == "0" or num2 == "0":
            return "0"

        def times_digit(num: str, d: int) -> str:
            """num (a digit string) times a single digit d."""
            out, carry = [], 0
            for ch in reversed(num):
                carry, digit = divmod(int(ch) * d + carry, 10)
                out.append(str(digit))
            if carry:
                out.append(str(carry))
            return "".join(reversed(out))

        def add(x: str, y: str) -> str:
            out, carry = [], 0
            i, j = len(x) - 1, len(y) - 1
            while i >= 0 or j >= 0 or carry:
                total = carry
                if i >= 0:
                    total += int(x[i]); i -= 1
                if j >= 0:
                    total += int(y[j]); j -= 1
                carry, digit = divmod(total, 10)
                out.append(str(digit))
            return "".join(reversed(out))

        total = "0"
        for pos, ch in enumerate(reversed(num2)):
            row = times_digit(num1, int(ch)) + "0" * pos   # shift by the digit's place value
            total = add(total, row)
        return total
Time O(n·m + m·(n+m))Space O(n + m)

m rows, each costing a digit multiply and a string addition of length up to n + m.

When to use: To explain the method; the column array below is the version to write.

Every pair num1[i] × num2[j] (indices counted from the right) contributes to column i + j of the product. So:

  1. Reverse both strings so index 0 is the units digit.
  2. Make len(num1) + len(num2) zero columns.
  3. For every pair of digits, add the product into cols[i + j]. Columns may exceed 9 for now.
  4. Sweep the columns from right (units) to left, keeping value % 10 and carrying value // 10.
  5. Reverse, strip leading zeros, join.

Separating "place the products" from "carry" is what makes the code short and hard to get wrong.

Dry run

  1. "123" × "456": reversed a = "321", b = "654", 6 columns.
  2. Pair products fill cols = [18, 27, 28, 13, 4, 0] (units column first).
  3. Carry sweep: 18 → 8 carry 1; 27+1 = 28 → 8 carry 2; 28+2 = 30 → 0 carry 3; 13+3 = 16 → 6 carry 1; 4+1 = 5; 0.
  4. cols = [8, 8, 0, 6, 5, 0] → reversed 056088 → strip the leading zero → "56088".

Python

class Solution:
    def multiply(self, num1: str, num2: str) -> str:
        if num1 == "0" or num2 == "0":
            return "0"
        a, b = num1[::-1], num2[::-1]          # index 0 is now the units digit
        cols = [0] * (len(a) + len(b))         # the product has at most this many digits
        for i, da in enumerate(a):
            for j, db in enumerate(b):
                cols[i + j] += int(da) * int(db)   # 10^i * 10^j lands in column i + j
        carry = 0
        for k in range(len(cols)):             # one carry sweep from the units column up
            carry, cols[k] = divmod(cols[k] + carry, 10)
        digits = cols[::-1]                    # most significant digit first
        while len(digits) > 1 and digits[0] == 0:
            digits.pop(0)                      # drop leading zeros, keep a lone 0
        return "".join(map(str, digits))
Time O(n·m)Space O(n + m)

n·m digit products, then a linear carry pass; the column list has n + m entries.

When to use: The interview answer. Mention that int(num1) * int(num2) is forbidden and why.

Common mistakes

  • Returning "0000" or "00" for products that are zero. Strip leading zeros, but keep one 0 if everything was stripped.
  • Putting a_i × b_j in column i + j + 1 or mixing up which end is the units digit. Reverse both strings first so index 0 is the units digit, then the column is just i + j.
  • Carrying inside the double loop. It works but is easy to get wrong; adding everything first and carrying once at the end is simpler.
  • Building the answer with string concatenation in a loop (s = c + s), which is O(n²). Collect characters in a list and join.
  • Using int(num1) * int(num2). It passes on LeetCode because Python has big integers, but it is exactly what the problem forbids and an interviewer will not accept it.

Python notes

  • ord(c) - ord("0") or int(c) converts one character to its digit; converting single characters is allowed, converting the whole string is not.
  • divmod(value, 10) returns (carry, digit) in one call.
  • Reversing with num1[::-1] makes the units digit index 0 so the column index is simply i + j.
  • "".join(reversed(chars)) builds the final string in O(n); avoid result = ch + result in a loop.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Add Strings LC 415 — the carry sweep on its own: walk two strings from the right with one shared carry.
  • Add Binary LC 67 — same idea in base 2; divmod(total, 2) instead of 10.
  • Plus One LC 66 — the simplest carry problem; Multiply Strings is this carry loop applied to a column array.
  • Multiply with negatives or decimals — handle a leading - by recording the sign and multiplying the absolute values; for decimals, remove the points, multiply, then re-insert a point d1 + d2 digits from the right.
  • Faster than O(n·m)? — Karatsuba splits each number in halves and does 3 multiplications instead of 4, giving O(n^1.58); ask whether the 200-digit limit makes that worth it (it does not).
