Merge Strings Alternately Easy 250

LeetCode #1768 ↗
Status

Interleave two strings character by character, starting with the first, and append whatever is left of the longer one.

Problem

You are given two strings, word1 and word2.

Build a new string by taking characters alternately: the first character of word1, then the first of word2, then the second of word1, then the second of word2, and so on. word1 always contributes first within each pair.

If one word is longer, append its remaining characters, in order, to the end of the merged string. Return the merged string.

Examples

Example 1
Input: word1 = "abc", word2 = "pqr"
Output: "apbqcr"
Same length: a, p, b, q, c, r. Every character of word1 is followed by the matching character of word2.
Example 2
Input: word1 = "ab", word2 = "pqrs"
Output: "apbqrs"
word1 runs out after a, p, b, q. The rest of word2, "rs", is appended unchanged.
Example 3
Input: word1 = "abcd", word2 = "pq"
Output: "apbqcd"
word2 runs out after a, p, b, q. The rest of word1, "cd", is appended unchanged.

Constraints

  • 1 <= len(word1), len(word2) <= 100
  • word1 and word2 consist of lowercase English letters

Think first try before reading the solution

Walk both words at the same time with one position. At position i, what goes into the result, and in which order?
The words can have different lengths. Once the shorter one is used up, the rest of the longer one goes on the end exactly as it is; no more alternating.
Collect the characters in a list and "".join them once at the end, rather than growing a string with += inside the loop.

Key idea

Picture two zippers being closed together: one tooth from the left side, one from the right, left first, until one side has no teeth left. The alternating part lasts exactly min(len(word1), len(word2)) rounds. After that, whatever remains of the longer word is simply the tail of the result.

Two pointers make this explicit: i walks word1, j walks word2, and both advance once per round while neither has run out. Then the leftover slice word1[i:] or word2[j:] (the other one is empty) is appended in one go. Every character is appended exactly once, so the time is O(n + m); collecting the pieces in a list and joining once keeps it that way instead of copying the growing string on every append.

Approaches from the obvious one to the one you want in an interview

Loop i from 0 to max(len(word1), len(word2)) - 1. At each i, append word1[i] if word1 is long enough, then word2[i] if word2 is long enough, with result += ....

The bounds checks handle the unequal lengths, and the loop visits every character once, so the logic is fine. The weak spot is += on a string: strings are immutable, so each append may copy everything built so far, which makes the total work quadratic in the worst case. With inputs of at most 100 characters nobody notices, but the list-and-join version costs nothing extra and scales.

Dry run

  1. word1 = "ab", word2 = "pqrs": i=0 → "a" → "ap"
  2. i=1 → "apb" → "apbq"
  3. i=2: word1 has no index 2, skip; "apbqr"
  4. i=3: skip word1 again; "apbqrs" → return

Python

class Solution:
    def mergeAlternately(self, word1: str, word2: str) -> str:
        result = ""
        for i in range(max(len(word1), len(word2))):
            if i < len(word1):
                result += word1[i]          # may copy the whole result so far
            if i < len(word2):
                result += word2[i]
        return result
Time O((n + m)²)Space O(n + m)

n + m appends; each one may copy the growing string, so the worst case is quadratic.

When to use: Fine for tiny inputs; avoid the +=-in-a-loop habit for anything longer.

Watch it run

Keep a pointer in each word: i for word1, j for word2.

  1. While both pointers are inside their words, append word1[i] then word2[j] to a list of parts and advance both.
  2. When the loop stops, one word is used up. Append the leftover slice of the other, word1[i:] or word2[j:] (one of them is empty, so appending both is safe).
  3. "".join(parts) builds the result in one pass.

Each character is appended exactly once and the join is linear, so the whole thing is O(n + m) time and space, with no repeated copying.

Dry run

  1. word1 = "abcd", word2 = "pq": round 1 → parts [a, p], i=1, j=1
  2. round 2 → parts [a, p, b, q], i=2, j=2
  3. j == len(word2): stop alternating
  4. append word1[2:] = "cd" and word2[2:] = "" → join → "apbqcd"

Python

class Solution:
    def mergeAlternately(self, word1: str, word2: str) -> str:
        parts = []                               # collect characters, join once at the end
        i, j = 0, 0
        while i < len(word1) and j < len(word2):
            parts.append(word1[i])               # word1 goes first in each pair
            parts.append(word2[j])
            i += 1
            j += 1
        parts.append(word1[i:])                  # whichever word still has characters ...
        parts.append(word2[j:])                  # ... the other slice is empty
        return "".join(parts)
Time O(n + m)Space O(n + m)

min(n, m) rounds, one leftover slice, one linear join; the parts list holds the whole answer.

When to use: The intended answer: linear, and the pattern you reuse for every two-sequence merge.

Watch it run

itertools.zip_longest(word1, word2, fillvalue="") yields the pairs (word1[k], word2[k]) and pads the shorter word with empty strings once it runs out. Joining a + b over those pairs produces the merge, including the tail of the longer word, because the empty fill values contribute nothing.

Same O(n + m) cost as the two-pointer version, written in two lines. Good to know as the idiomatic Python; in an interview, show the explicit loop first so the pointer logic is visible.

Python

class Solution:
    def mergeAlternately(self, word1: str, word2: str) -> str:
        pairs = itertools.zip_longest(word1, word2, fillvalue="")   # ('a','p'), ('b','q'), ('', 'r'), ...
        return "".join(first + second for first, second in pairs)
Time O(n + m)Space O(n + m)

One pass over max(n, m) pairs and one join.

When to use: When brevity matters and the reader knows zip_longest.

Common mistakes

  • Stopping as soon as the shorter word ends. For "ab" and "pqrs" that gives "apbq" instead of "apbqrs"; the leftover "rs" must be appended.
  • Looping over range(max(n, m)) and indexing both words without a bounds check: word1[i] raises IndexError as soon as i passes the end of the shorter word.
  • Taking word2 first within a pair, or alternating from the wrong word after the shorter one ends. The order is fixed: word1 then word2 in every round, then the tail.
  • Growing a string with result += ch inside the loop. Strings are immutable, so each += may copy everything built so far; with the inputs capped at 100 characters it passes, but it is the wrong habit for longer inputs.

Python notes

  • "".join(parts) builds the final string in one linear pass. result += ch in a loop may copy the whole string each time; CPython optimises some cases, but the guarantee is not part of the language.
  • Slicing past the end is safe: "ab"[5:] is "". That is why word1[i:] and word2[j:] can both be appended without checking which word ran out.
  • itertools.zip_longest(word1, word2, fillvalue="") pairs the characters and pads the shorter word with empty strings, so "".join(a + b for a, b in pairs) is a correct one-liner.

What an interviewer might ask next, and what changes.

  • Merge Sorted Array LC 88 — the two pointers still walk two inputs, but which one advances is decided by comparing values, not by taking turns, and the result must be written in place.
  • Merge Two Sorted Lists LC 21 — the same comparison-driven merge on linked lists: re-link the smaller node instead of appending a character.
  • Interleaving String LC 97 — the reverse question: can s3 be formed by interleaving s1 and s2 while keeping each one's order? The interleaving is no longer fixed, so it becomes a dynamic-programming problem.
  • Zigzag Conversion LC 6 — characters are dealt into rows in a zigzag and read back row by row: a different fixed pattern, solved with one pointer per row or a direction flag.
  • Shuffle String LC 1528 — each character is given its target index explicitly: fill a list of the right size, then join.
  • Merge k strings in round-robin order — keep one pointer per string and cycle through the strings, dropping each one when its pointer reaches the end; itertools.zip_longest(*words, fillvalue="") does exactly this.
