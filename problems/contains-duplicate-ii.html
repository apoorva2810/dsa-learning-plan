Contains Duplicate II Easy 250

LeetCode #219 ↗
Status

Decide whether the same value appears twice within k positions of itself.

Problem

Given a list of integers nums and an integer k, decide whether the list has two different positions i and j such that:

  • nums[i] == nums[j], and
  • abs(i - j) <= k, so the two equal values are at most k positions apart.

Return True if such a pair exists, otherwise False.

Examples

Example 1
Input: nums = [6, 2, 9, 6], k = 3
Output: true
The two 6s sit at positions 0 and 3, which are 3 apart: within k.
Example 2
Input: nums = [6, 2, 9, 6], k = 2
Output: false
The same list, but 3 apart is now more than k = 2, and no other value repeats.
Example 3
Input: nums = [3, 8, 3, 8], k = 0
Output: false
k = 0 would need i == j, but the two positions must be different.

Constraints

  • 1 <= len(nums) <= 10^5
  • -10^9 <= nums[i] <= 10^9
  • 0 <= k <= 10^5

Key idea

Two equal values are "close enough" when their positions differ by at most k. So for the value at position i, only the previous k positions matter. That is a window of values that slides one step at a time. A sliding window is a range of positions that moves along the list, adding the new value on one side and dropping the oldest on the other.

Keep the window's values in a set. At each position, ask the set "is this value already here?". If yes, a copy sits within the last k positions and the answer is True. If not, add the value, and once the window holds more than k earlier values, remove the oldest one.

A set lookup is O(1), so the scan is O(n). The window never holds more than k + 1 values, so the memory is O(min(n, k)).

Approaches from the obvious one to the one you want in an interview

For every position i, compare nums[i] with the values at the next k positions, i + 1 up to i + k. If any of them is equal, the answer is True. Stopping at k positions ahead (instead of the end of the list) is already the whole idea of "close enough".

It is correct, but each position scans up to k neighbours, so the cost is about n · k comparisons. With n = 10^5 and k = 10^5, that is billions of comparisons.

Dry run

  1. nums = [6, 2, 9, 6], k = 3
  2. i = 0 (6): compare with positions 1, 2, 3 → 2, 9, then 6 → equal, return True.
  3. With k = 2 the scan from i = 0 stops after positions 1 and 2, and the later positions repeat nothing → False.

Python

class Solution:
    def containsNearbyDuplicate(self, nums: List[int], k: int) -> bool:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, min(i + k + 1, n)):    # only the next k positions
                if nums[i] == nums[j]:
                    return True
        return False
Time O(n·k)Space O(1)

Each position compares against at most k later positions; no extra memory.

When to use: Fine when k is tiny; too slow when k is close to n.

Remember where each value was last seen: last_seen[value] = index. At position i, if x is in the dictionary and i - last_seen[x] <= k, the answer is True. Then overwrite last_seen[x] with i.

Only the latest occurrence matters: it is the closest one to every future occurrence, so overwriting loses nothing. One pass, O(n) time. The dictionary keeps every distinct value ever seen, so memory is O(n), even when k is small.

Dry run

  1. nums = [6, 2, 9, 6], k = 3, last_seen = {}
  2. i = 0 → 6 is new → {6: 0}; i = 1 → {6: 0, 2: 1}; i = 2 → {6: 0, 2: 1, 9: 2}
  3. i = 3 (6): seen at index 0, and 3 - 0 = 3 ≤ 3 → return True.

Python

class Solution:
    def containsNearbyDuplicate(self, nums: List[int], k: int) -> bool:
        last_seen = {}                       # value -> index of its most recent occurrence
        for i, x in enumerate(nums):
            if x in last_seen and i - last_seen[x] <= k:
                return True
            last_seen[x] = i                 # the latest index is the closest one for future matches
        return False
Time O(n)Space O(n)

One pass with a dictionary lookup and update per position; the dictionary holds up to n values.

When to use: Short and easy to get right. Choose the window if memory matters and k is small.

Keep a set window with the values at positions left .. right - 1. For each right:

  1. if the window already spans more than k earlier positions, remove nums[left] and move left up;
  2. if nums[right] is in the window, an equal value sits within k positions: return True;
  3. otherwise add nums[right] to the window.

Each value is added once and removed once, so the scan is O(n). The set never holds more than k + 1 values, so memory is O(min(n, k)): the same time as the dictionary, with less memory when k is small.

Dry run

  1. nums = [6, 2, 9, 6], k = 2 → window = {}, left = 0
  2. right = 0 (6), 1 (2), 2 (9): the window spans at most 2 earlier positions, so nothing is dropped. None of them is in the set, so each is added → {6, 2, 9}.
  3. right = 3 (6): the window would span 3 earlier positions, more than k = 2, so nums[0] = 6 is removed → {2, 9}. The 6 is not in the set, so it is added, and the scan ends without a hit: False.

Python

class Solution:
    def containsNearbyDuplicate(self, nums: List[int], k: int) -> bool:
        window = set()                       # values at positions left .. right - 1
        left = 0
        for right, x in enumerate(nums):
            if right - left > k:             # more than k positions behind: the oldest value drops out
                window.remove(nums[left])
                left += 1
            if x in window:                  # an equal value within the last k positions
                return True
            window.add(x)
        return False
Time O(n)Space O(min(n, k))

Each value is added and removed at most once; the set holds at most k + 1 values.

When to use: The standard sliding-window answer, and the one to give when k is small compared with n.

Common mistakes

  • Remembering every value seen so far and ignoring distance. That solves the plain duplicate problem: [1, 2, 3, 1] with k = 2 would wrongly return True, because the two 1s are 3 apart.
  • Keeping only the first index of a value in a dictionary. With [1, 2, 3, 1, 1] and k = 1 the answer is True (the last two 1s are neighbours), but comparing the last 1 with index 0 says 4 apart. Always overwrite with the latest index.
  • An off-by-one window size. The window holds the k positions before the current one, not k - 1 or k + 1. With k = 1 only the immediate neighbour counts.
  • Forgetting that k = 0 means an empty window. The two positions must differ, so the answer is always False; the window code handles this naturally because it drops each value as soon as the next position arrives.
  • Brute-forcing every pair (i, j) instead of only the next k positions after i. That is O(n²) even when k is tiny.

Python notes

  • set.remove(x) raises KeyError if x is missing, set.discard(x) does not. Here the removed value is always present, so remove is safe, and it would reveal a bug in the window logic.
  • enumerate(nums) gives the position and the value together, so the loop needs no nums[right] lookups.
  • x in window on a set is a hash lookup, O(1) on average; on a list it would be a scan of up to k items.
  • min(i + k + 1, n) caps the inner range in the brute force so it never runs past the end of the list.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Contains Duplicate LC 217 — no distance limit: a set of everything seen so far is enough, with no removals.
  • Contains Duplicate III LC 220 — the two values only need to be within value_diff of each other, not equal: put values into buckets of width value_diff + 1, or keep a sorted window, and look at the neighbouring buckets.
  • Longest Substring Without Repeating Characters LC 3 — a window that must stay free of repeats: it grows on the right and shrinks on the left until the repeat is gone, so its size changes instead of staying at k.
  • Maximum Sum of Distinct Subarrays With Length K LC 2461 — a window of exactly k positions that must hold distinct values: keep a count per value and the window's sum while sliding.
  • Sliding Window Maximum LC 239 — a fixed-size window again, but the question is the maximum of the window, which needs a deque instead of a set.
  • Smallest distance between two equal values — return the minimum gap instead of a yes/no answer: keep the latest index of each value and update the best gap with i - last_seen[x] at every repeat.
