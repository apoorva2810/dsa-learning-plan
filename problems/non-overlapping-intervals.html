Non-overlapping Intervals Medium

LeetCode #435 ↗
Status

Find the fewest ranges to remove so that the ones left do not overlap.

Problem

You are given a list intervals of ranges [start, end]. Return the minimum number of ranges you must remove so that the ranges that remain do not overlap each other.

  • Ranges that only touch, such as [1, 2] and [2, 3], do not overlap, so both can stay.
  • The ranges are not sorted, and the same range can appear more than once. Every range has start < end.

Examples

Example 1
Input: intervals = [[1, 2], [2, 3], [3, 4], [1, 3]]
Output: 1
Remove [1, 3]. What is left, [1, 2], [2, 3] and [3, 4], only touches end to start.
Example 2
Input: intervals = [[1, 2], [1, 2], [1, 2]]
Output: 2
Identical ranges overlap completely: keep one, remove the other two.
Example 3
Input: intervals = [[1, 2], [2, 3]]
Output: 0
They touch at 2, which is allowed.

Constraints

  • 1 <= len(intervals) <= 10^5
  • intervals[i] = [start, end]
  • -5 * 10^4 <= start < end <= 5 * 10^4

Think first try before reading the solution

Removing the fewest ranges is the same as keeping the most. Flip the question: what is the largest set of ranges that do not overlap?
Suppose you must choose which range to keep first. Which one leaves the most room for the others: the one that starts first, the shortest one, or the one that ends first?
Sort by end. Walk through the ranges, keeping one when it starts at or after the end of the last kept range, and counting a removal when it does not.

Key idea

"Remove the fewest" is the same question as "keep the most", and keeping the most is a scheduling problem: several requests want the same room, so accept as many as you can.

Which request should be accepted first? The one that ends earliest. It frees the room as early as possible, so it leaves the most time for everything else. Starting early does not help (one long early range can block everything), and neither does being short (a short range in the middle of a busy stretch can overlap two others).

So sort by end and sweep. Keep a range if it starts at or after the end of the last kept one. Otherwise it overlaps something already kept, and because the list is sorted by end it ends no earlier than that one, so it is the one to discard.

Why is taking the earliest end safe? Take any best schedule and replace its first range by the range that ends first overall. The replacement ends no later, so everything that fitted after the old one still fits after the new one, and we keep as many as before. So some best schedule starts with the earliest-ending range, and the same argument repeats on what is left. This kind of proof is called an exchange argument.

Approaches from the obvious one to the one you want in an interview

Sort by start. Then decide about the ranges one at a time, and every range has two branches: remove it, or keep it (allowed only if it starts at or after the end of the last kept range). Take the branch that ends up keeping more, and answer n - most_kept.

It is correct because it tries every legal choice. It is hopeless for real inputs: each range doubles the number of branches, so n ranges mean up to 2ⁿ branches. With 40 ranges that is over a trillion.

Dry run

  1. intervals = [[1, 2], [2, 3], [3, 4], [1, 3]] sorted by start: [[1, 2], [1, 3], [2, 3], [3, 4]]
  2. Each range has two branches, keep or remove. The branch keep [1, 2], remove [1, 3], keep [2, 3], keep [3, 4] keeps 3 ranges.
  3. No branch keeps 4, because [1, 2] and [1, 3] overlap. So the answer is 4 − 3 = 1, after exploring up to 2⁴ = 16 branches.

Python

class Solution:
    def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
        intervals = sorted(intervals)                         # by start
        n = len(intervals)

        def most_kept(i, last_end):
            """Most ranges we can keep among intervals[i:], if the last kept range ends at last_end."""
            if i == n:
                return 0
            best = most_kept(i + 1, last_end)                 # branch 1: remove intervals[i]
            if intervals[i][0] >= last_end:                   # branch 2: keep it, if it fits
                best = max(best, 1 + most_kept(i + 1, intervals[i][1]))
            return best

        return n - most_kept(0, float("-inf"))
Time O(2ⁿ)Space O(n)

Two branches per range. The recursion is at most n calls deep.

When to use: Only to see what is being decided. It cannot handle more than about 20 ranges.

The branches of the brute force keep revisiting the same question: "what is the most I can keep if range i is the last one I kept?" Answer it once per range. Sort by start and let best_chain[i] be the longest run of non-overlapping ranges that ends with range i. It is 1 + best_chain[j] for the best earlier range j that ends at or before range i starts (touching is fine), or 1 if there is none. The most you can keep is max(best_chain), and the answer is n minus that.

Two nested loops over the ranges make it O(n²). That is fine for a few thousand ranges and too slow for 10⁵.

Dry run

  1. Sorted by start: [[1, 2], [1, 3], [2, 3], [3, 4]], best_chain = [1, 1, 1, 1]
  2. [2, 3] can follow [1, 2] (2 <= 2), so best_chain[2] = 2. It cannot follow [1, 3] (3 <= 2 is false).
  3. [3, 4] can follow [2, 3] (3 <= 3), so best_chain[3] = best_chain[2] + 1 = 3.
  4. max(best_chain) = 3, so remove 4 − 3 = 1 range.

Python

class Solution:
    def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
        intervals = sorted(intervals)                         # by start
        n = len(intervals)
        best_chain = [1] * n                                  # best_chain[i]: most ranges kept if range i is the last kept
        for i in range(n):
            for j in range(i):
                if intervals[j][1] <= intervals[i][0]:        # j ends before i starts (touching is fine)
                    best_chain[i] = max(best_chain[i], best_chain[j] + 1)
        return n - max(best_chain, default=0)
Time O(n²)Space O(n)

Two nested loops over n ranges; one number per range is stored.

When to use: As the stepping stone between brute force and greedy. It is the same DP as Longest Increasing Subsequence.

Sort by end. Keep a variable last_end, the end of the last kept range, starting at -inf. For each range:

  • if start >= last_end, it does not overlap the last kept range: keep it and set last_end = end;
  • otherwise it overlaps: remove it (add 1 to the answer) and leave last_end alone.

The earliest-ending range is always safe to keep, because swapping it into the first slot of any best schedule cannot cost anything (it ends no later than the one it replaces). The same holds for the next choice, and the next. When a conflict happens, the range being looked at ends no earlier than the kept one, so discarding it is the better choice.

A common variant sorts by start instead and, on every overlap, discards whichever of the two ends later. It removes the same number of ranges; sorting by end gives the shorter argument.

Dry run

  1. intervals = [[1, 2], [2, 3], [3, 4], [1, 3]] sorted by end: [[1, 2], [2, 3], [1, 3], [3, 4]], last_end = -inf, removed = 0
  2. [1, 2]: 1 >= -inf, keep. last_end = 2.
  3. [2, 3]: 2 >= 2, keep (touching is fine). last_end = 3.
  4. [1, 3]: 1 >= 3 is false, overlap. Remove it: removed = 1.
  5. [3, 4]: 3 >= 3, keep. last_end = 4. Answer: 1.

Python

class Solution:
    def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
        removed = 0
        last_end = float("-inf")                              # end of the last kept range
        for start, end in sorted(intervals, key=lambda iv: iv[1]):   # earliest end first
            if start >= last_end:                             # fits after the last kept range (touching is fine)
                last_end = end                                # keep it
            else:
                removed += 1                                  # overlaps a kept range: remove it
        return removed
Time O(n log n)Space O(n)

The sort dominates; the sweep is one pass. The sorted copy is the extra space.

When to use: Always. It is the expected answer, and the earliest-end greedy is worth remembering for any 'schedule the most' question.

Common mistakes

  • Sorting by start instead of by end. For [[1, 10], [2, 3], [3, 4], [4, 5], [5, 6]], start order keeps [1, 10] first and then has to remove the other four. The best answer removes only [1, 10].
  • Using <= in the overlap test (start <= last_end). Touching ranges may stay, so a range overlaps the last kept one only when start < last_end. With <=, [[1, 2], [2, 3]] wrongly gives 1.
  • Keeping the shortest range first. For [[1, 4], [3, 5], [4, 8]] the shortest is [3, 5], which overlaps both others, so that choice keeps 1 range. Keeping [1, 4] and [4, 8] keeps 2.
  • Moving last_end when a range is removed. Only a kept range moves the boundary; a removed range is thrown away and must not change it.
  • Returning the number kept instead of the number removed. The question asks how many to remove: len(intervals) - kept.

Python notes

  • sorted(intervals, key=lambda iv: iv[1]) sorts by the second item, the end. The sort is stable, so ranges with the same end keep their input order, which does not matter here.
  • float("-inf") is a starting last_end that every range passes, so the first range is always kept with no special case.
  • for start, end in ... unpacks each pair, so the test reads start < last_end: "begins before the last kept range has ended".
  • max(best_chain, default=0) avoids a ValueError when the list is empty.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Meeting Rooms LC 252 — the yes/no version: can all the ranges stay? Equivalent to 'is the answer 0?'.
  • Minimum Number of Arrows to Burst Balloons LC 452 — the same sort by end, but you count groups instead of removals, and touching balloons share an arrow, so the test becomes start > last_end.
  • Maximum Length of Pair Chain LC 646 — the 'keep the most' form: sort by end and count the pairs you keep. Touching is not allowed there (left > previous_right).
  • Maximum Profit in Job Scheduling LC 1235 — each range has a profit, and the earliest-ending greedy no longer works. You need DP over the ranges sorted by end, with binary search for the last compatible one.
  • Return which ranges to remove — report the removed ranges (or their positions) instead of the count: sort (end, start, index) triples and collect the index of every discarded range.
