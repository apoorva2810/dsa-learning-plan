Binary Tree Preorder Traversal Easy 250

LeetCode #144 ↗
Status

List a binary tree's values in preorder: the node first, then its left subtree, then its right subtree, at every node.

Problem

Given the root of a binary tree, return the preorder traversal of its values as a list.

Preorder means: at every node, list the node's own value first, then everything in its left subtree, then everything in its right subtree. The same rule applies inside each subtree, all the way down. So a parent always appears before its descendants, and a left subtree is listed completely before the right one starts.

An empty tree gives an empty list. The recursive solution is three lines; the exercise is to also write it without recursion, with a stack you manage yourself.

Examples

Example 1
Input: root = [1, 2, 3, 4, 5, None, 6]
Output: [1, 2, 4, 5, 3, 6]
1 comes first. Its whole left subtree (2, then its children 4 and 5) is listed before the right subtree (3, then its child 6).
Example 2
Input: root = [7, None, 9, 8]
Output: [7, 9, 8]
7 has no left subtree, so its right child 9 follows at once, and 9's left child 8 right after 9.
Example 3
Input: root = []
Output: []

Constraints

  • 0 <= number of nodes <= 100
  • -100 <= Node.val <= 100

Key idea

Preorder is a rule about when a node is recorded: before anything in either of its subtrees. Recursion states that directly. preorder(node) appends node.val, then calls preorder(node.left), then preorder(node.right). Python's call stack remembers the right subtrees that are still waiting while the left ones are being listed.

To drop the recursion, keep that memory yourself on a stack (last in, first out). Put the root on it, then repeat: pop a node, record it, push its children. The order of the pushes is the whole trick. Push the right child first and the left child second, so the left child is on top and is popped next. The right child stays underneath, untouched, until the entire left subtree has been recorded and removed. Every node is pushed once and popped once, so the time is O(n). At any moment the stack holds the current path's waiting right children, so the space is O(h) for a tree of height h.

If even that is too much, Morris traversal hides the way back inside the tree with temporary links. It is the inorder version with one change: the node is recorded on its first visit, before the walk goes left.

Approaches from the obvious one to the one you want in an interview

The definition of preorder is already a recursive procedure: to list a subtree, write down its root, then list its left subtree, then its right subtree. An empty subtree lists nothing.

Write preorder(node) exactly like that. Python's call stack remembers the right subtrees that are still waiting while the left ones are being listed. Each node is visited once, so the time is O(n). The call stack is as deep as the tree is tall, O(h), and Python raises RecursionError after about 1000 nested calls.

Dry run

  1. root = [1, 2, 3, 4, 5, None, 6], result = []
  2. preorder(1): record 1 → [1], then the left subtree preorder(2)
  3. preorder(2): record 2, then preorder(4) records 4 and returns, then preorder(5) records 5 → [1, 2, 4, 5]
  4. back in preorder(1): now the right subtree preorder(3) records 3; its left is empty, preorder(6) records 6
  5. result = [1, 2, 4, 5, 3, 6]

Python

class Solution:
    def preorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        result = []

        def preorder(node):
            if node is None:                    # empty subtree: nothing to record
                return
            result.append(node.val)             # 1. this node first
            preorder(node.left)                 # 2. everything on the left
            preorder(node.right)                # 3. everything on the right

        preorder(root)
        return result
Time O(n)Space O(h)

Each node is entered once. The call stack holds one root-to-node path, h frames at most (n for a chain).

When to use: The natural first answer, and the shape of most tree recursions.

Watch it run

Replace the call stack with a list. The stack holds the nodes whose turn has not come yet, the next one on top.

  1. Start with the root on the stack.
  2. Pop the top and record it. A node is listed before everything below it, so it can be recorded the moment it is reached.
  3. Push its right child, then its left child (only the ones that exist). The last item pushed is the first one popped, so the left child comes out next, and the right child waits underneath until the whole left subtree is finished.

Repeat until the stack is empty. Every node is pushed once and popped once: O(n) time. The stack holds the waiting right children along one root-to-node path, so O(h) space, and there is no recursion limit.

Dry run

  1. root = [1, 2, 3, 4, 5, None, 6], stack = [1]
  2. pop 1 → [1]; push 3, then 2 → stack [3, 2]
  3. pop 2 → [1, 2]; push 5, then 4 → stack [3, 5, 4]
  4. pop 4 → [1, 2, 4] (leaf); pop 5 → [1, 2, 4, 5] (leaf) → stack [3]
  5. pop 3 → [1, 2, 4, 5, 3]; only a right child, push 6 → stack [6]
  6. pop 6 → [1, 2, 4, 5, 3, 6]; stack empty → done

Python

class Solution:
    def preorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        if root is None:
            return []
        result = []
        stack = [root]                          # nodes still to visit; the top is next
        while stack:
            node = stack.pop()
            result.append(node.val)             # a node comes before everything below it
            if node.right:                      # right goes in first...
                stack.append(node.right)
            if node.left:                       # ...so the left is on top and is popped next
                stack.append(node.left)
        return result
Time O(n)Space O(h)

Every node is pushed and popped exactly once. The stack never holds more than the waiting right children of one root-to-node path, plus the current node.

When to use: The answer interviewers want after the recursive one. Change the order of the pushes and the same loop gives the mirror order.

Watch it run

Recursion and the stack both exist to remember how to get back from a left subtree. Morris traversal stores that way back inside the tree: before going left from cur, find the rightmost node of its left subtree (the node that comes just before cur in inorder, its predecessor) and point that node's empty right at cur. This temporary link is a thread.

The only difference from the inorder version is when the node is recorded. In preorder, cur is recorded on the first visit, just before the thread is laid and the walk goes left. On the second visit (the walk has come back along the thread) the left subtree is done, so the thread is removed and the walk goes right. Every edge is walked a constant number of times, so the time is still O(n), with no stack. The tree is changed while the walk runs but is fully restored by the end.

Dry run

  1. root = [1, 2, 3, 4, 5, None, 6], cur = 1
  2. 1 has a left child; its predecessor is 5 (rightmost under 2). Record 1, thread 5.right = 1, cur = 2
  3. 2 has a left child; predecessor 4. Record 2, thread 4.right = 2, cur = 4
  4. 4 has no left child: record 4, follow the thread to 2. The thread is found: unlink it, cur = 2.right = 5
  5. 5 has no left child: record 5, follow its thread back to 1; the thread is found: unlink it, cur = 1.right = 3
  6. 3 has no left child: record 3, cur = 6; 6: record 6 → [1, 2, 4, 5, 3, 6]

Python

class Solution:
    def preorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        result = []
        cur = root
        while cur:
            if cur.left is None:                # nothing on the left: record, then go right
                result.append(cur.val)
                cur = cur.right
                continue
            pred = cur.left                     # rightmost node of the left subtree
            while pred.right and pred.right is not cur:
                pred = pred.right
            if pred.right is None:              # first visit: record now, leave a thread back, go left
                result.append(cur.val)
                pred.right = cur
                cur = cur.left
            else:                               # second visit: the left subtree is done
                pred.right = None               # remove the thread, restoring the tree
                cur = cur.right
        return result
Time O(n)Space O(1)

Each predecessor search walks edges that are walked at most three times in total, so the whole run is linear.

When to use: Only when memory is the constraint and the tree may be changed temporarily; it is rarely expected in an interview.

Common mistakes

  • Pushing the left child before the right one. The stack then returns the right subtree first, and you get the mirror image: node, right subtree, left subtree.
  • Pushing None children. The next pop returns None and node.val raises AttributeError. Push only children that exist.
  • Taking from the front of a deque (popleft()) instead of the end of a list. That visits level by level, which is breadth-first order, not preorder.
  • Starting with stack = [root] when the tree may be empty. The first pop returns None and crashes; return [] early or start from [root] if root else [].
  • Building the answer with [node.val] + preorder(left) + preorder(right). Each + copies a list, so a value is copied once per ancestor: O(n · h) time, quadratic on a chain. Append to one shared list instead.
  • Trusting recursion on deep trees. Python stops at about 1000 nested calls (RecursionError), so a chain of a few thousand nodes crashes the recursive version. The stack version has no such limit.

Python notes

  • A plain list is the stack: append pushes and pop() removes the last item, both O(1).
  • while stack: is enough here, unlike the inorder loop: every node still to visit is already on the stack.
  • for child in (node.right, node.left): if child: stack.append(child) keeps the "right first" rule in one place and also works for any number of children if you reverse their order.
  • The nested preorder function may call result.append(...) without nonlocal: it changes the list's contents, it does not rebind the name.
  • sys.getrecursionlimit() is 1000 by default. The stack version is the real fix for very deep trees.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Binary Tree Inorder Traversal LC 94 — the node is recorded after its left subtree instead of before it, so the loop slides left first and records a node when it is popped.
  • Binary Tree Postorder Traversal LC 145 — the node comes last. A preorder that visits the right child before the left, reversed, is exactly postorder.
  • Serialize and Deserialize Binary Tree LC 297 — write the preorder with a marker for every missing child; reading the same sequence back rebuilds one unique tree.
  • Construct Binary Tree from Preorder and Inorder Traversal LC 105 — the first preorder value is the root; its position in the inorder list tells you how many values belong to the left subtree.
  • Flatten Binary Tree to Linked List LC 114 — rewire the nodes in place into preorder order, each right pointing to the next node and every left set to None.
  • N-ary Tree Preorder Traversal LC 589 — push all children in reverse order, so the first child is on top and is popped first.
  • What if you may use no extra memory at all? — Morris traversal: thread the rightmost node of the left subtree back to the current node, record the node on the first visit, and remove the thread on the second.
