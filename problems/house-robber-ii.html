House Robber II Medium

LeetCode #213 ↗
Status

House Robber on a circular street: the first and last houses are neighbours too.

Problem

Houses are arranged in a circle and nums[i] is the money in house i. As in House Robber, you may not take from two adjacent houses, and now house 0 and house len(nums) - 1 are adjacent as well.

Return the largest total you can collect.

Examples

Example 1
Input: nums = [2, 3, 2]
Output: 3
Houses 0 and 2 would give 4, but they are neighbours on the circle. Take house 1.
Example 2
Input: nums = [1, 2, 3, 1]
Output: 4
Houses 0 and 2: 1 + 3.
Example 3
Input: nums = [200, 3, 140, 20, 10]
Output: 340
Houses 0 and 2. Adding house 4 is not allowed: it touches house 0.

Constraints

  • 1 <= len(nums) <= 100
  • 0 <= nums[i] <= 1000

Key idea

A circle has no natural place to start a left-to-right DP: whatever you decide about the last house depends on the first. The trick is to break the circle by case analysis.

The only rule the circle adds is "not both house 0 and house n - 1". So every valid plan falls into at least one of two cases:

  • it does not use the last house, so it is a plan for the straight street nums[0..n-2];
  • it does not use the first house, so it is a plan for the straight street nums[1..n-1].

Inside either range the first and last houses of the range are not neighbours any more, so plain House Robber applies. The answer is the better of the two runs. Plans that skip both end houses are counted in both cases, which is harmless for a maximum.

One house is special: it has no neighbour, but both ranges would be empty. Return nums[0] directly.

Approaches from the obvious one to the one you want in an interview

Break the circle into the two straight streets nums[0..n-2] and nums[1..n-1], and solve each with the plain House Robber recursion best(lo, i) = max(best(lo, i - 1), nums[i] + best(lo, i - 2)).

The case split is already the key insight; what makes this version slow is the recursion itself, which recomputes the same best(lo, i) exponentially often. Adding @cache (the state is the pair (lo, i)) would make it O(n).

Dry run

  1. nums = [2, 3, 2]: case A is [2, 3] → max(3, 2) = 3
  2. case B is [3, 2] → max(2, 3) = 3
  3. answer max(3, 3) = 3; the plan 2 + 2 = 4 is correctly impossible, since it uses both ends

Python

class Solution:
    def rob(self, nums: List[int]) -> int:
        n = len(nums)
        if n == 1:                             # a lone house has no neighbour
            return nums[0]

        def best(lo: int, i: int) -> int:
            """Most money from the straight street nums[lo..i]."""
            if i < lo:
                return 0
            return max(best(lo, i - 1), nums[i] + best(lo, i - 2))

        return max(best(0, n - 2),             # case A: the last house is never used
                   best(1, n - 1))             # case B: the first house is never used
Time O(φⁿ) ≈ O(1.62ⁿ)Space O(n)

Two exponential recursions without memory; the call stack is at most n deep.

When to use: Only to check the case split on tiny inputs.

Write House Robber as a helper over a straight list and call it on the two ranges:

  • rob_line(houses): dp[0] = houses[0], dp[1] = max(houses[0], houses[1]), dp[k] = max(dp[k - 1], dp[k - 2] + houses[k]).
  • answer max(rob_line(nums[:-1]), rob_line(nums[1:])), after handling n == 1.

Python

class Solution:
    def rob(self, nums: List[int]) -> int:
        if len(nums) == 1:
            return nums[0]

        def rob_line(houses: List[int]) -> int:
            """Plain House Robber on a straight street."""
            if len(houses) == 1:
                return houses[0]
            dp = [0] * len(houses)             # dp[k] = most money from houses[0..k]
            dp[0] = houses[0]
            dp[1] = max(houses[0], houses[1])
            for k in range(2, len(houses)):
                dp[k] = max(dp[k - 1], dp[k - 2] + houses[k])
            return dp[-1]

        return max(rob_line(nums[:-1]),        # without the last house
                   rob_line(nums[1:]))         # without the first house
Time O(n)Space O(n)

Two passes of n - 1 houses; the slices and tables are O(n) each.

When to use: When you want to see (or reconstruct) the choices of each case.

Python

class Solution:
    def rob(self, nums: List[int]) -> int:
        n = len(nums)
        if n == 1:
            return nums[0]

        def rob_line(lo: int, hi: int) -> int:
            """House Robber on nums[lo..hi] with two rolling variables."""
            two_back, one_back = 0, 0
            for i in range(lo, hi + 1):
                two_back, one_back = one_back, max(one_back, two_back + nums[i])
            return one_back

        return max(rob_line(0, n - 2), rob_line(1, n - 1))
Time O(n)Space O(1)

Two linear passes over index ranges; four integers of state in total.

When to use: The interview answer: state the case split first, then reuse House Robber.

Common mistakes

  • Forgetting n == 1: both ranges are empty and the answer would come out as 0 instead of nums[0].
  • Running House Robber once on the whole array and subtracting something afterwards. You cannot repair a plan that used both ends; you have to compare the two restricted problems.
  • Excluding both end houses in one run (nums[1:-1]). That misses every plan that uses exactly one end, such as houses 0 and 2 in [200, 3, 140, 20, 10].
  • Copying with nums[1:] and nums[:-1] is fine at this size, but a helper that takes index bounds avoids the O(n) copies when memory matters.

Python notes

  • A helper rob_line(lo, hi) that works on index bounds avoids copying slices; with slices the code is shorter and, for 100 houses, just as fast.
  • If you memoise the recursive version, the state is (lo, i): @cache handles a tuple of arguments automatically. Define the cached helper inside the method so the cache does not survive between calls.
  • The recursion is at most n frames deep, far below Python's default recursion limit of 1000 for n <= 100.
