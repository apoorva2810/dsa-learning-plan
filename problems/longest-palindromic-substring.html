Longest Palindromic Substring Medium

LeetCode #5 ↗
Status

Find the longest contiguous piece of a string that reads the same forwards and backwards.

Problem

Given a string s, return its longest palindromic substring: a contiguous piece of s that reads the same from left to right and from right to left.

If several palindromes share the maximum length, return any one of them.

Examples

Example 1
Input: s = "babad"
Output: "bab"
"aba" is equally long and also accepted.
Example 2
Input: s = "cbbd"
Output: "bb"
An even-length palindrome: its centre is between the two b's.
Example 3
Input: s = "a"
Output: "a"

Constraints

  • 1 <= len(s) <= 1000
  • s consists of digits and English letters

Think first try before reading the solution

Checking every substring works but costs O(n³). What do all palindromes have in common, structurally?
A palindrome stays a palindrome when you strip its two ends: s[i..j] is one exactly when s[i] == s[j] and s[i+1..j-1] is one. That gives a DP table over (i, j).
The same fact read outwards: every palindrome grows from a centre (one character, or the gap between two equal characters). Try all 2n − 1 centres and expand while the ends match, in O(1) extra space.

Key idea

A palindrome is built from the middle out: "racecar" is "aceca" with an r on both ends, which is "cec" with an a on both ends, and so on down to "e". So

s[i..j] is a palindrome ⇔ s[i] == s[j] and s[i+1..j-1] is a palindrome (or is empty or one character).

DP table: let is_pal[i][j] answer that question. Each cell reads only the cell for the substring two characters shorter, so fill the table by increasing length. That is O(n²) cells, O(1) each, and O(n²) memory.

Expand around the centre: the same fact, used outwards. Every palindrome has a centre: a character (odd length) or the gap between two characters (even length), 2n − 1 centres in total. From each centre, move two pointers outward while the characters match; the last matching span is the longest palindrome with that centre. Still O(n²) time in the worst case, but O(1) memory and usually much faster in practice, because most expansions stop immediately. That is the practical optimum; Manacher's algorithm reaches O(n) by reusing mirror information, but it is rarely expected in interviews.

Approaches from the obvious one to the one you want in an interview

Try lengths from n down to 1, and for each length every start position; return the first substring that equals its reverse. Because lengths are tried longest first, the first hit is a correct answer.

There are about n²/2 substrings and each test costs up to O(n), so the worst case is O(n³), e.g. when the answer is a single character and every longer substring has to be checked first.

Dry run

  1. s = "babad": length 5 "babad" is not a palindrome
  2. length 4: "baba", "abad" are not
  3. length 3: "bab" reads the same backwards → return "bab"

Python

class Solution:
    def longestPalindrome(self, s: str) -> str:
        n = len(s)
        for length in range(n, 0, -1):            # longest lengths first
            for start in range(n - length + 1):
                piece = s[start:start + length]
                if piece == piece[::-1]:          # O(length) palindrome test
                    return piece
        return ""                                 # unreachable: one character is always a palindrome
Time O(n³)Space O(n)

O(n²) substrings, O(n) to copy and reverse each one.

When to use: Only as a baseline; 1000 characters would take seconds in Python.

is_pal[i][j] is True when s[i..j] is a palindrome:

  • every single character is one (is_pal[i][i] = True);
  • two characters are one when they are equal;
  • longer pieces need s[i] == s[j] and is_pal[i + 1][j - 1].

Fill by increasing length so the inner cell is always ready, and remember the longest True cell. Each of the n²/2 cells is O(1), so O(n²) time, at the cost of an n × n table.

Dry run

  1. s = "babad": the diagonal (length 1) is all True
  2. length 2: ba, ab, ba, ad all have different ends → False
  3. length 3: bab (ends b = b, inside a True) → True; aba → True; bad → False
  4. lengths 4 and 5: ends differ or the inside is False → longest stays bab

Python

class Solution:
    def longestPalindrome(self, s: str) -> str:
        n = len(s)
        is_pal = [[False] * n for _ in range(n)]     # is_pal[i][j]: is s[i..j] a palindrome?
        best_start, best_len = 0, 1
        for i in range(n):
            is_pal[i][i] = True                      # single characters
        for length in range(2, n + 1):               # shorter pieces are always filled first
            for i in range(n - length + 1):
                j = i + length - 1
                # matching ends, and the inside (if there is one) is already known to be a palindrome
                if s[i] == s[j] and (length == 2 or is_pal[i + 1][j - 1]):
                    is_pal[i][j] = True
                    if length > best_len:
                        best_start, best_len = i, length
        return s[best_start:best_start + best_len]
Time O(n²)Space O(n²)

n(n + 1)/2 cells with O(1) work each; the table itself is n × n booleans.

When to use: When you need the whole table afterwards (palindrome partitioning, counting); otherwise expand around centres.

Watch it run

Every palindrome has a centre, and there are only 2n − 1 of them: n characters (odd lengths) and n − 1 gaps (even lengths). For each centre, set left and right on it and move them outward while s[left] == s[right]. When the loop stops, the palindrome is s[left + 1 .. right - 1].

Worst case O(n²) (a string like "aaaa..." expands far from every centre), but only O(1) extra memory, and on typical strings most expansions stop after a step or two.

Dry run

  1. s = "cbbd": odd centres give only single letters (c, b, b, d)
  2. gap between 0 and 1: c ≠ b, nothing
  3. gap between 1 and 2: b = b → "bb"; next pair c ≠ d → stop
  4. gap between 2 and 3: b ≠ d → answer "bb"

Python

class Solution:
    def longestPalindrome(self, s: str) -> str:
        def expand(left: int, right: int) -> tuple[int, int]:
            """Grow outward while the ends match; return the bounds of the palindrome found."""
            while left >= 0 and right < len(s) and s[left] == s[right]:
                left -= 1
                right += 1
            return left + 1, right - 1           # the loop stopped one step past the palindrome

        best_lo, best_hi = 0, 0
        for c in range(len(s)):
            for lo, hi in (expand(c, c), expand(c, c + 1)):   # odd centre, then even centre
                if hi - lo > best_hi - best_lo:
                    best_lo, best_hi = lo, hi
        return s[best_lo:best_hi + 1]
Time O(n²)Space O(1)

2n − 1 centres, each expanding at most n/2 steps; only a few indices are stored.

When to use: The standard interview answer. Mention Manacher's O(n) algorithm if asked for better.

Common mistakes

  • Forgetting even-length centres: with only single-character centres, "cbbd" returns "b" instead of "bb".
  • Filling the DP table row by row from the top: is_pal[i][j] reads is_pal[i+1][j-1], a row that is not filled yet. Go by increasing length, or with i from n - 1 down to 0.
  • Off-by-one after expanding: the loop stops one step past the palindrome, so the answer is s[left + 1 : right], not s[left : right + 1].
  • Building a 2-D list with [[False] * n] * n: all rows are the same list, so writing one cell writes a whole column. Use a list comprehension.
  • Comparing piece == piece[::-1] for every substring: correct, but O(n³) for 1000 characters is about 10^8 character comparisons.

Python notes

  • piece == piece[::-1] is the shortest palindrome test, but [::-1] builds a reversed copy (O(length) time and memory).
  • Create the table with [[False] * n for _ in range(n)]; [[False] * n] * n repeats one row object n times.
  • A top-down version would put @cache on is_pal(i, j). It recurses about n/2 levels deep (well within Python's default recursion limit of 1000), but the cache holds up to n²/2 entries, as much memory as the table.
  • Track the best span as two indices and slice once at the end, instead of slicing a new string at every improvement.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Palindromic Substrings LC 647 — count all palindromic substrings instead of finding the longest: the same expansions, adding 1 per successful step.
  • Longest Palindromic Subsequence LC 516 — characters may be skipped, so centres no longer work: a 2-D DP where mismatched ends take max(dp[i+1][j], dp[i][j-1]).
  • Palindrome Partitioning LC 131 — list every way to cut the string into palindromes: backtracking, with this is_pal table to test pieces in O(1).
  • Palindrome Partitioning II LC 132 — the fewest cuts: a 1-D DP over prefixes (cuts[j] = min(cuts[i - 1] + 1) over palindromes s[i..j]) on top of this table.
  • Shortest Palindrome LC 214 — add characters only at the front: find the longest palindromic prefix, which KMP or rolling hashes do in O(n).
  • Can you do it in O(n)? — Manacher's algorithm reuses the radius of a mirrored centre inside the current rightmost palindrome, so each character is expanded past at most once.
