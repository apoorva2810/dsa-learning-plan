Island Perimeter Easy 250

LeetCode #463 ↗
Status

Measure the outline of the single island in a grid of land and water cells.

Problem

You are given a row × col grid of integers in which 1 is land and 0 is water. The land cells form exactly one island: they are all joined horizontally or vertically, and the island has no lakes (no water that is completely surrounded by land). Everything outside the grid is water.

Every cell is a square with side length 1. Return the perimeter of the island: the total length of the border between land and water, counting the grid's edge as water.

Examples

Example 1
Input: grid = [[0,1,0,0],[1,1,1,0],[0,1,0,0],[1,1,0,0]]
Output: 16
Seven land cells. Walk around the island and you cross 16 unit sides.
Example 2
Input: grid = [[1]]
Output: 4
A lone cell: all four of its sides face water (the outside of the grid).
Example 3
Input: grid = [[1,1],[1,1]]
Output: 8
A 2 × 2 block has 16 sides in total, but 4 of them are shared between two land cells and are not part of the outline.

Constraints

  • row == len(grid), col == len(grid[0])
  • 1 <= row, col <= 100
  • grid[i][j] is 0 or 1
  • there is exactly one island, and it has no lakes

Think first try before reading the solution

Forget the whole island for a moment. Look at a single land cell: it has four sides. Which of them are part of the perimeter?
A side is on the perimeter exactly when the cell on the other side of it is water, or when there is no cell there at all because the side lies on the edge of the grid.
Visit every land cell, look at its four neighbours (up, down, left, right) and add 1 for each neighbour that is water or off the grid. The sum is the perimeter.

Key idea

The perimeter is made of unit sides, and each side belongs to exactly one land cell. So instead of walking around the island, which is awkward to program, count sides cell by cell. A land cell contributes one unit for every neighbour that is water or outside the grid. A neighbour that is land shares that side, so the side is inside the island and does not count.

Because every land cell is checked once and each check looks at four neighbours, the work is proportional to the number of cells: O(row · col). There is nothing faster, since every cell has to be looked at anyway.

The same count can be reorganised as a formula: start with 4 sides per land cell and subtract 2 for every pair of neighbouring land cells, because a shared side was counted once from each cell. And since the island is a connected group of cells, you can also reach every cell with a depth-first search from any one land cell and add up the sides on the way. That is why this problem sits with the graph problems: the grid is a graph in disguise.

Approaches from the obvious one to the one you want in an interview

Every unit of perimeter is a side of some land cell that faces water or the edge of the grid. So visit each land cell, look at its four neighbours, and add 1 for each neighbour that is water or off the grid. The sides between two land cells are inside the island and are never counted.

Each cell is visited once and makes four constant-time checks, so the time is O(row · col) with no extra memory. Every cell has to be looked at anyway, so nothing can be faster.

Dry run

  1. Example 1. (0,1): up is off the grid, left (0,0) and right (0,2) are water, down (1,1) is land → 3 sides. perimeter = 3.
  2. (1,0): up water, down water, left off the grid, right land → 3. perimeter = 6.
  3. (1,1): all four neighbours are land → 0. perimeter = 6.
  4. (1,2): up water, down water, right water, left land → 3. perimeter = 9.
  5. (2,1): left water, right water, up and down land → 2. perimeter = 11.
  6. (3,0): up water, down and left off the grid, right land → 3. perimeter = 14.
  7. (3,1): down off the grid, right water, up and left land → 2. perimeter = 16.

Python

class Solution:
    def islandPerimeter(self, grid: List[List[int]]) -> int:
        rows, cols = len(grid), len(grid[0])
        perimeter = 0
        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == 0:
                    continue                                   # water adds nothing
                for nr, nc in ((r - 1, c), (r + 1, c), (r, c - 1), (r, c + 1)):   # up, down, left, right
                    if nr < 0 or nr >= rows or nc < 0 or nc >= cols:
                        perimeter += 1                         # this side is on the edge of the grid
                    elif grid[nr][nc] == 0:
                        perimeter += 1                         # this side faces water
        return perimeter
Time O(row · col)Space O(1)

Every cell is read once and each land cell checks four neighbours; only a counter is stored.

When to use: The default answer: shortest to write, no recursion, and it still works if the grid has several islands or lakes.

Watch it run

Count differently: every land cell has 4 sides, giving 4 · land in total. A side shared by two touching land cells was counted twice (once from each cell) and is not on the outline, so subtract 2 for every touching pair. To count each pair exactly once, look only right and down from each land cell; the pair's other cell will look back at it with up or left, which we deliberately skip.

Same O(row · col) time, with half the neighbour checks and no bounds checks for up and left. It mainly earns its place because the formula makes the structure of the answer obvious, and because it adapts directly to a sparse list of coordinates.

Dry run

  1. Example 3, the 2 × 2 block. (0,0): land = 1; right (0,1) and down (1,0) are land → shared = 2.
  2. (0,1): land = 2; down (1,1) is land → shared = 3. (1,0): land = 3; right (1,1) is land → shared = 4.
  3. (1,1): land = 4; right and down are off the grid → shared stays 4.
  4. Perimeter = 4 · 4 − 2 · 4 = 8.

Python

class Solution:
    def islandPerimeter(self, grid: List[List[int]]) -> int:
        rows, cols = len(grid), len(grid[0])
        land = shared = 0
        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == 1:
                    land += 1
                    if c + 1 < cols and grid[r][c + 1] == 1:
                        shared += 1                 # this cell and its right neighbour share a side
                    if r + 1 < rows and grid[r + 1][c] == 1:
                        shared += 1                 # this cell and the cell below share a side
        return 4 * land - 2 * shared                # each shared side was counted from both cells
Time O(row · col)Space O(1)

One pass over the cells with at most two neighbour checks per land cell.

When to use: When the input is a list of land coordinates (put them in a set and the pass is O(land)), or when you want to explain the answer with a formula.

Watch it run

Treat the grid as a graph: land cells are nodes, and two land cells are connected when they share a side. The problem promises exactly one island, so a depth-first search from any land cell visits every land cell. While visiting a cell, add 1 for each of its sides that faces water or the grid edge, and recurse into land neighbours that have not been visited yet.

Same O(row · col) bound, but it also needs a visited set and a call stack as deep as the island. You would pick it when the next question is about the island's shape, where the DFS already does the walking.

Dry run

  1. Example 1, start at (0,1): 3 exposed sides → perimeter 3; walk down into (1,1).
  2. (1,1): 0 exposed sides; walk down into (2,1): 2 sides → 5; down into (3,1): 2 sides → 7; left into (3,0): 3 sides → 10.
  3. (3,0) has no unvisited land around it → return to (3,1) → return to (2,1) → return to (1,1).
  4. Back at (1,1): left into (1,0): 3 sides → 13; right into (1,2): 3 sides → 16. Everything returns → 16.

Python

class Solution:
    def islandPerimeter(self, grid: List[List[int]]) -> int:
        rows, cols = len(grid), len(grid[0])
        visited = set()

        def dfs(r: int, c: int) -> int:
            visited.add((r, c))
            total = 0
            for nr, nc in ((r - 1, c), (r + 1, c), (r, c - 1), (r, c + 1)):
                if nr < 0 or nr >= rows or nc < 0 or nc >= cols or grid[nr][nc] == 0:
                    total += 1                       # this side faces the edge or water
                elif (nr, nc) not in visited:
                    total += dfs(nr, nc)             # a land neighbour: add its sides too
            return total

        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == 1:
                    return dfs(r, c)                 # one island, so one search is enough
        return 0
Time O(row · col)Space O(row · col)

Each land cell is visited once; visited and the recursion depth can both reach the island's size.

When to use: When you want the graph view of the grid, for example as a warm-up for Max Area of Island. Mind the recursion limit on big islands.

Common mistakes

  • Counting diagonal neighbours. Two cells that only touch at a corner share no side, so only up, down, left and right matter.
  • Forgetting the border. A side on the edge of the grid faces 'outside', which counts as water. Worse, in Python grid[r - 1] with r = 0 silently returns the last row instead of failing, so check the bounds before indexing.
  • Subtracting one per shared edge in the formula version. A shared side was counted from both cells, so each pair of touching land cells removes 2 from 4 · land.
  • Looking only right and down in the side-counting version. That trick is for counting each shared edge once; when you count exposed sides, a cell's left and upper sides can face water too.
  • Recursion depth in the DFS version: a 100 × 100 grid of land means up to 10,000 nested calls, well past Python's default limit of 1000. Prefer the plain scan, or raise the limit.

Python notes

  • Keep the four moves in one tuple, ((-1, 0), (1, 0), (0, -1), (0, 1)), and loop over it. Four copy-pasted if blocks are where the off-by-one bugs live.
  • Check bounds before indexing: 0 <= nr < rows and 0 <= nc < cols is one chained comparison. Python's negative indexes mean grid[-1][c] is a valid (and wrong) lookup, not an error.
  • sum(...) over a generator reads well for the side count: sum(1 for nr, nc in moves if not land(nr, nc)).
  • The DFS version needs a visited set of (r, c) tuples (hashable). Lists like [r, c] cannot go in a set.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Max Area of Island LC 695 — count cells instead of sides, and there can be many islands: the same DFS returns the size of the island it floods, and an outer scan keeps the maximum.
  • Number of Islands LC 200 — several islands: the single DFS is no longer enough, so scan all cells and start a flood fill from every land cell that has not been visited yet.
  • Number of Enclaves LC 1020 — count land cells that cannot walk off the grid: flood from every border land cell first, then count what was never reached.
  • Flood Fill LC 733 — the same four-direction DFS, but it recolours the cells it visits instead of counting sides.
  • What if there can be several islands, or lakes? — the side count does not change at all: every land side facing water still counts, including the shore of a lake. Only the DFS version needs an outer loop to reach every island.
  • What if you get a list of land coordinates instead of a grid? — put the coordinates in a set; perimeter = 4 · L minus 2 for each cell whose right or lower neighbour is also in the set. O(L) regardless of the grid size.
