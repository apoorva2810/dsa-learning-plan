Longest Turbulent Subarray Medium 250

LeetCode #978 ↗
Status

Find the longest contiguous stretch of a list whose neighbours keep switching between going up and going down.

Problem

Look at two neighbours in a list. The step between them is up if the right one is bigger, down if it is smaller, and flat if they are equal.

A stretch of the list (a subarray, which is contiguous) is turbulent, or a zigzag, when its steps alternate: up, down, up, down... or down, up, down, up... A flat step breaks a zigzag. A stretch with a single element counts as turbulent, and so does any stretch of two different numbers.

Given the list arr, return the length of the longest turbulent stretch.

Examples

Example 1
Input: arr = [3, 7, 4, 9, 5, 5, 8]
Output: 5
The stretch [3, 7, 4, 9, 5] goes up, down, up, down. The equal pair 5, 5 ends it, and the stretch after it, [5, 8], has only 2.
Example 2
Input: arr = [2, 4, 6, 8, 3]
Output: 3
Going up three times in a row is not a zigzag. The best stretch is [6, 8, 3]: up, then down.
Example 3
Input: arr = [5, 5, 5]
Output: 1
Equal neighbours never form a zigzag, so the best stretch is a single element.

Constraints

  • 1 <= len(arr) <= 4 * 10^4
  • 0 <= arr[i] <= 10^9

Think first try before reading the solution

Do not look at the numbers, look at the steps between neighbours. Write down up, down or flat for each pair in the first example. Where do the zigzag stretches start and stop?
A stretch stops growing when a step is flat, or when it goes in the same direction as the step before. After a repeated direction the next stretch starts at the previous element (the two numbers differ, so they already form a 2-element zigzag). After a flat step it starts at the new element.
Keep two counters while scanning: up, the length of the longest zigzag ending here whose last step went up, and down, the same for a last step that went down. An up step can only extend a stretch that ended with a down step.

Key idea

Look at the steps between neighbours instead of the numbers. Every pair is up, down or flat, and a zigzag stretch is a run of steps that alternates with no flat step in it. The question becomes: what is the longest alternating run of steps?

Scan left to right and keep two counters for the stretch that ends at the current index:

  • up: the length of the longest zigzag ending here whose last step went up,
  • down: the same for a last step that went down.

When a new element arrives, look at the step into it:

  • up: a zigzag can end with an up step only if it went down just before, so up = down + 1. No zigzag ends here with a down step, so down = 1 (just this element).
  • down: the mirror image, down = up + 1 and up = 1.
  • flat: no zigzag holds two equal neighbours, so up = down = 1.

After each element, best = max(best, up, down). Two up steps in a row show why the resets matter: the second one finds down == 1, so up restarts at 2, which is exactly the two-element zigzag formed by the last two numbers. One pass, two integers, O(1) extra space. It is the same "extend or restart" thinking as Kadane's algorithm, with directions instead of sums.

Approaches from the obvious one to the one you want in an interview

Try every start. From each one, walk right while the steps keep alternating, and stop at the first flat step or the first step that goes in the same direction as the one before. The length of the stretch walked is a candidate; the biggest candidate is the answer.

A list that zigzags all the way (such as [1, 6, 2, 7, 3, 8, ...]) makes every start walk to the end, so it is O(n²). It also re-walks the same alternating steps from each start, even though a zigzag that begins one step later is just the same zigzag with its first element removed.

Dry run

  1. arr = [2, 4, 6, 8, 3], best = 1
  2. start 0: 2 → 4 is up, then 4 → 6 is up again → stop. Length 2
  3. start 1: 4 → 6 is up, then 6 → 8 is up again → stop. Length 2
  4. start 2: 6 → 8 is up, then 8 → 3 is down, which flips the direction → length 3 → best 3
  5. start 3: 8 → 3 is down → length 2; start 4: length 1. Answer 3

Python

class Solution:
    def maxTurbulenceSize(self, arr: List[int]) -> int:
        n = len(arr)
        best = 1                                 # one element is always a zigzag
        for start in range(n):
            last_step = 0                        # +1 up, -1 down, 0 no step yet
            for end in range(start + 1, n):
                step = (arr[end] > arr[end - 1]) - (arr[end] < arr[end - 1])   # +1 up, -1 down, 0 flat
                if step == 0 or step == last_step:   # flat, or the direction did not flip: the zigzag stops
                    break
                last_step = step
                best = max(best, end - start + 1)
        return best
Time O(n²)Space O(1)

Up to n starts, each walking up to n elements (a fully alternating list).

When to use: To check a faster solution on small inputs.

Keep up and down for the stretch ending at the current index, and update both from the step into the new element.

  • Up step: up = down + 1, down = 1.
  • Down step: down = up + 1, up = 1.
  • Flat step: up = down = 1.

best = max(best, up, down) after every element. A zigzag that ends with an up step must have gone down just before, which is why the new up is built from the old down. The reset of the other counter to 1 is what makes a repeated direction start a fresh two-element stretch. Every element is looked at once.

Dry run

  1. arr = [3, 7, 4, 9, 5, 5, 8], up = down = best = 1
  2. 7 > 3, up: up = down + 1 = 2, down = 1
  3. 4 < 7, down: down = up + 1 = 3, up = 1
  4. 9 > 4, up: up = 4, down = 1; then 5 < 9, down: down = 5, up = 1 → best 5
  5. 5 = 5, flat: both counters back to 1
  6. 8 > 5, up: up = 2; the best stays 5

Python

class Solution:
    def maxTurbulenceSize(self, arr: List[int]) -> int:
        up = down = 1                            # longest zigzag ending here whose last step went up / down
        best = 1
        for i in range(1, len(arr)):
            if arr[i] > arr[i - 1]:              # an up step can follow a down step
                up, down = down + 1, 1
            elif arr[i] < arr[i - 1]:            # a down step can follow an up step
                up, down = 1, up + 1
            else:                                # flat: no zigzag holds both neighbours
                up = down = 1
            best = max(best, up, down)
        return best
Time O(n)Space O(1)

One pass, three integers.

When to use: The standard answer. Say "the last step decides which counter I extend".

Watch it run

Think of the list as a chain of zigzag pieces. A piece cannot contain a flat step, and it cannot contain two steps in the same direction. Walk with an anchor, the start of the current piece.

At each index i (from 1), compute the step into i:

  • if it is flat, no zigzag holds arr[i - 1] and arr[i] together: move the anchor to i;
  • otherwise look one step ahead. If the next step does not flip the direction (or there is no next step), the piece ends at i: record its length i - anchor + 1 and start the next piece at i, since arr[i] is shared with it.

This is a sliding window where the left edge only ever jumps forward. It is the same O(n), with a bit more index juggling than the two counters.

Dry run

  1. arr = [3, 7, 4, 9, 5, 5, 8], anchor = 0, best = 1
  2. i = 1 to 3: each next step flips the direction, so the piece keeps growing
  3. i = 4: the step into 5 is down, and the next step (5 → 5) is flat → the piece ends: length 4 − 0 + 1 = 5, anchor = 4
  4. i = 5: flat step → anchor = 5
  5. i = 6 is the last index: the piece 5, 8 has length 2 → best stays 5

Python

class Solution:
    def maxTurbulenceSize(self, arr: List[int]) -> int:
        n = len(arr)
        best = 1
        anchor = 0                               # start of the current zigzag piece
        for i in range(1, n):
            step = (arr[i] > arr[i - 1]) - (arr[i] < arr[i - 1])    # +1 up, -1 down, 0 flat
            if step == 0:                        # no zigzag holds both neighbours: start over at i
                anchor = i
                continue
            next_step = (arr[i + 1] > arr[i]) - (arr[i + 1] < arr[i]) if i + 1 < n else 0
            if next_step != -step:               # the next step does not flip the direction (or there is none)
                best = max(best, i - anchor + 1)     # the piece ends at i
                anchor = i                       # arr[i] is the first element of the next piece
        return best
Time O(n)Space O(1)

One pass; each index looks one step back and one step ahead.

When to use: When you prefer the "window with a jumping left edge" view, or the interviewer asks for a sliding-window solution.

Common mistakes

  • Counting equal neighbours as an up or down step. In [5, 5, 5] the answer is 1, because a flat step must reset both counters to 1.
  • Updating only one counter per step. If an up step sets up = down + 1 but leaves down alone, a stale down inflates the next stretch: [1, 5, 2, 6, 7, 3] gives 5 instead of 4.
  • Restarting at length 1 when a step repeats the previous direction. The new stretch starts at the previous element and already has length 2. With length 1, [2, 4, 6, 8, 3] would give 2 instead of 3.
  • Only counting stretches that contain a direction flip. A stretch of two different numbers is already turbulent, so [1, 2] has answer 2, and a one-element list has answer 1.
  • Starting best at 0. An array of equal numbers, or a single element, still has a turbulent stretch of length 1.

Python notes

  • (a > b) - (a < b) is a compact sign function: Python treats True as 1 and False as 0, so the result is -1, 0 or 1.
  • up, down = down + 1, 1 is a tuple assignment: the right side is evaluated first, so it uses the old down and the two counters update together without a temporary variable.
  • max(best, up, down) accepts any number of arguments.
  • itertools.pairwise(arr) (Python 3.10+) yields neighbour pairs without index arithmetic, but the explicit index keeps the trace and the pointer variable easy to follow.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Longest Continuous Increasing Subsequence LC 674 — only one direction counts: extend the run while each step goes up and reset to 1 otherwise. It is the one-counter version of this problem.
  • Longest Mountain in Array LC 845 — steps must go up and then down, once. Keep an up run length and a down run length, and only count a mountain when both are non-zero.
  • Wiggle Subsequence LC 376 — the elements no longer need to be neighbours, so you may skip any. The answer is the same up/down idea without the resets: up = down + 1 on an up step, down = up + 1 on a down step.
  • Maximum Subarray LC 53 — the same "extend or restart" scan with sums instead of directions.
  • Return the stretch itself, not just its length — remember the index where the current stretch started: it moves to i - 1 after a repeated direction and to i after a flat step. Record (start, i) whenever the length beats best.
  • What if one element may be changed? — you need the best zigzag with at most one repair, which means keeping separate counters for stretches that have used the repair and stretches that have not.
