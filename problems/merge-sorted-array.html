Merge Sorted Array Easy 250

LeetCode #88 ↗
Status

Merge a sorted list into the spare tail of another sorted list, in place, by filling from the back.

Problem

You are given two integer lists sorted in non-decreasing order, nums1 and nums2, and two integers m and n: the number of real values in each.

nums1 has length m + n. Its first m entries are the real values; the last n entries are 0 placeholders that exist only to make room. nums2 has exactly n values.

Merge nums2 into nums1 so that nums1 ends up holding all m + n values in non-decreasing order. Change nums1 in place and return nothing. The expected answer uses O(1) extra memory: the spare tail of nums1 is the only workspace you need.

Examples

Example 1
Input: nums1 = [1,2,3,0,0,0], m = 3, nums2 = [2,5,6], n = 3
Output: [1,2,2,3,5,6]
The real values are [1,2,3] and [2,5,6]; the three zeros are placeholders that get overwritten.
Example 2
Input: nums1 = [1], m = 1, nums2 = [], n = 0
Output: [1]
Nothing to merge: nums1 already holds the whole answer.
Example 3
Input: nums1 = [0], m = 0, nums2 = [1], n = 1
Output: [1]
nums1 has no real values (m = 0); its single placeholder slot receives the 1.

Constraints

  • len(nums1) == m + n
  • len(nums2) == n
  • 0 <= m, n <= 200
  • 1 <= m + n <= 200
  • -10^9 <= nums1[i], nums2[j] <= 10^9

Think first try before reading the solution

The extra space you need is already there: the n placeholder slots at the end of nums1. Which value belongs in the very last slot?
The largest of all values is either nums1[m - 1] or nums2[n - 1]. Put it at index m + n - 1, then the same question applies to the remaining values and the slot before it.
Three pointers: i on the last real nums1 value, j on the last nums2 value, k on the last slot. Write the larger of nums1[i] and nums2[j] at k, move that pointer and k back, and stop when j < 0.

Key idea

Merging two sorted lists is the classic two-pointer walk: compare the fronts, take the smaller, advance that pointer. The twist here is that the result must go into nums1 itself, and a front-to-back merge would overwrite nums1 values before they have been read.

Turn it around. The free space is at the back of nums1, so fill from the back with the largest values first. The largest unplaced value is either nums1[i] or nums2[j] (the last unplaced value of each); write it at k, the last unfilled slot. The write position k is always at or beyond the read position i, because k - i = j + 1 while nums2 still has values to place, so nothing unread is ever destroyed.

The loop runs until every nums2 value is placed. If nums1 values are left over, they are already sitting in their final positions at the front. That is O(m + n) time with no extra list.

Approaches from the obvious one to the one you want in an interview

The placeholder slots are exactly big enough for nums2, so copy it there and sort the whole list in place. Two lines, obviously correct.

It ignores the one useful fact about the input: both halves are already sorted. A general sort costs O((m + n) log(m + n)) comparisons, while a merge needs only O(m + n). (Python's Timsort happens to detect the two sorted runs and merge them quickly, but that is an implementation detail, not something you can argue from.)

Python

class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        nums1[m:] = nums2        # overwrite the n placeholder slots with nums2's values
        nums1.sort()             # sort the whole list in place
Time O((m + n) log(m + n))Space O(1)

One slice assignment plus a comparison sort of m + n values.

When to use: A quick first answer; the interviewer will ask you to use the sorted order.

Watch it run

The textbook merge: compare the smallest unused value of each input, write the smaller one next, advance that pointer. Writing directly into nums1 from the front would overwrite values not yet compared, so first copy nums1's real prefix into first and read from the copy.

This is O(m + n) time, the best possible, but it spends O(m) extra memory on the copy. The copy is only there to protect unread values, which hints at the final trick: write where nothing unread lives.

Dry run

  1. nums1 = [1,2,3,0,0,0], nums2 = [2,5,6]: first = [1,2,3]
  2. 1 <= 2 → nums1[0] = 1; 2 <= 2 → nums1[1] = 2 (from first); 3 > 2 → nums1[2] = 2 (from nums2)
  3. 3 <= 5 → nums1[3] = 3; first used up → copy 5, 6 → [1,2,2,3,5,6]

Python

class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        first = nums1[:m]                  # copy of nums1's real values: reads never see our writes
        i, j = 0, 0
        for k in range(m + n):             # fill nums1 from the front
            if j >= n or (i < m and first[i] <= nums2[j]):
                nums1[k] = first[i]        # take from the copy (also when nums2 is used up)
                i += 1
            else:
                nums1[k] = nums2[j]        # take from nums2 (also when the copy is used up)
                j += 1
Time O(m + n)Space O(m)

Every value is written once; the copy holds m values.

When to use: When you may use extra memory, or as the stepping stone to the in-place version.

Watch it run

Use the free space where it is: at the back. The largest value overall is either nums1[m - 1] or nums2[n - 1], and it belongs in the last slot, index m + n - 1. Place it, then ask the same question about the remaining values and the slot before it.

  • i = m - 1, j = n - 1, k = m + n - 1.
  • While j >= 0: if i >= 0 and nums1[i] > nums2[j], write nums1[i] at k and i -= 1; otherwise write nums2[j] at k and j -= 1. Then k -= 1.

The loop stops when every nums2 value is placed; any nums1 values still unplaced are already in their final positions. No nums1 value is ever overwritten before it is read, because k - i = j + 1 >= 1 throughout the loop.

Dry run

  1. nums1 = [1,2,3,0,0,0], nums2 = [2,5,6]: i=2, j=2, k=5
  2. 3 vs 6 → 6 to index 5; 3 vs 5 → 5 to index 4
  3. 3 vs 2 → 3 to index 3 (i → 1); 2 vs 2 → 2 from nums2 to index 2 (j → -1)
  4. j < 0: stop. [1, 2] at indices 0..1 are already in place → [1,2,2,3,5,6]

Python

class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        i, j = m - 1, n - 1               # last real value of nums1, last value of nums2
        k = m + n - 1                     # last slot of nums1
        while j >= 0:                     # until every nums2 value has been placed
            if i >= 0 and nums1[i] > nums2[j]:
                nums1[k] = nums1[i]       # nums1's value is larger: it belongs further back
                i -= 1
            else:
                nums1[k] = nums2[j]       # nums2's value is larger or equal, or nums1 is used up
                j -= 1
            k -= 1
Time O(m + n)Space O(1)

At most m + n writes; only three indices are stored.

When to use: The intended answer: linear time, no extra list.

Common mistakes

  • Merging from the front in place. With nums1 = [4,5,6,0,0,0] and nums2 = [1,2,3], writing the 1 at index 0 destroys the 4 before it is read. Fill from the back, or keep a copy of nums1's first m values.
  • Looping while i >= 0 instead of while j >= 0. On the same input the loop stops after placing 6, 5, 4 at the back, leaving 1, 2, 3 unplaced. The nums2 values are the ones that must all be moved; leftover nums1 values are already where they belong.
  • Reading nums1[i] when i has reached -1. Python does not raise: nums1[-1] is the last element, so the merge silently uses a wrong value. Guard with i >= 0 and ... so the else branch copies from nums2.
  • Treating the placeholder zeros as values, for example by using len(nums1) instead of m. The zeros are not part of the input; only the first m entries are.
  • Returning a new merged list. The official signature returns None; LeetCode and this site's tests inspect nums1 after the call.

Python notes

  • nums1[m:] = nums2 replaces the placeholder tail with nums2's values in place, and nums1.sort() sorts the same list object: together they are the two-line brute force.
  • Python's sort (Timsort) notices that the list is two sorted runs and merges them in linear time, so the brute force is fast in practice. The interview still wants the pointer logic.
  • Negative indices never raise: nums1[-1] is the last element. Always test i >= 0 before nums1[i].
  • nums1[:m] copies the real prefix; it is what the front-to-back merge needs to avoid overwriting values.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Merge Two Sorted Lists LC 21 — the same compare-and-advance merge, but on linked lists: there is no index and no spare tail, so you re-link nodes behind a dummy head from the front instead.
  • Merge k Sorted Lists LC 23 — k inputs instead of two: merge them pairwise, or keep the k current heads in a min-heap and pop the smallest each time.
  • Squares of a Sorted Array LC 977 — the largest square is at one of the two ends of the input, so two pointers from both ends fill the result from the back: the same fill-the-largest-first trick.
  • Intersection of Two Arrays II LC 350 — walk two sorted arrays with two pointers, advancing the smaller value and recording matches instead of merging.
  • Sort Colors LC 75 — also in place with pointers, but it partitions one array into three groups rather than merging two.
  • What if nums1 had no spare slots? — merging two full arrays in place with O(1) extra memory is a Hard problem (the gap method, a Shell-sort style comparison with shrinking gaps). The placeholder tail is what keeps this version Easy.
