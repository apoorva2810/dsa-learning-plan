Delete Node in a BST Medium 250

LeetCode #450 ↗
Status

Remove the node holding a given key from a binary search tree and return the root, keeping the tree a valid BST.

Problem

You are given the root of a binary search tree (BST) and an integer key. Delete the node whose value is key, if there is one, and return the root of the updated tree.

The result must still be a BST: for every node, all values in its left subtree are smaller and all values in its right subtree are larger. All values in the tree are distinct, and key may or may not be present. If it is absent, return the tree unchanged.

The problem accepts any valid result. When the deleted node has two children there is more than one correct shape, so the tests here list every shape that the approaches below produce.

Examples

Example 1
Input: root = [5, 3, 6, 2, 4, null, 7], key = 3
Output: [5, 4, 6, 2, null, null, 7]
3 has two children. Its inorder successor 4 (the smallest value to its right) takes its place and the old 4 is removed. [5, 2, 6, null, 4, null, 7] is also a valid answer.
Example 2
Input: root = [5, 3, 6, 2, 4, null, 7], key = 0
Output: [5, 3, 6, 2, 4, null, 7]
0 is not in the tree, so nothing changes.
Example 3
Input: root = [], key = 0
Output: []

Constraints

  • 0 <= number of nodes <= 10^4
  • -10^5 <= Node.val <= 10^5
  • every value is unique
  • root is a valid BST
  • -10^5 <= key <= 10^5

Think first try before reading the solution

Finding the node is an ordinary BST search: go left when key is smaller than the node, right when it is larger. Which of the three cases (no child, one child, two children) is the hard one?
A node with one child can be spliced out: its parent simply points at that child. A node with two children cannot be removed that way. Which value could sit in its place without breaking the ordering?
The smallest value in the right subtree (the inorder successor) is larger than everything on the left and smaller than everything else on the right. Copy it into the node, then delete that successor from the right subtree. It has no left child, so that second deletion is an easy case.

Key idea

Deleting from a BST has two halves: find the node, then unhook it without breaking the ordering. The search is the usual one, since the key can only be on one side of each node. The recursion makes the unhooking painless: every call returns the root of its (possibly changed) subtree, and the caller stores it with root.left = deleteNode(root.left, key). So removing a node means returning something other than the node itself from its call.

Three cases once the node is found:

  • No children: return None; the parent's pointer to it disappears.
  • One child: return that child. Its whole subtree was already on the correct side of the parent, so the ordering holds.
  • Two children: nothing can simply move up. Instead find the inorder successor, the smallest value in the right subtree (walk left from root.right until you cannot). It is larger than every value on the left and smaller than every other value on the right, so copying it into the node keeps the BST property. The successor now exists twice; delete it from the right subtree, which is one of the two easy cases because a leftmost node never has a left child.

Everything happens along one or two root-to-leaf paths, so the work is O(h) for a tree of height h. The inorder predecessor (largest value on the left) works just as well, which is why the problem accepts several shapes.

Approaches from the obvious one to the one you want in an interview

Ignore the shape of the tree. An inorder walk lists the values in sorted order; skip key while collecting. Then build a new BST from the sorted list: the middle element becomes the root, the left half becomes the left subtree and the right half the right subtree.

Correct, and it produces a nicely balanced tree, but it touches every node and allocates a new one for each: O(n) time and space for a change that affects a single path. It is the baseline the O(h) solution improves on.

Dry run

  1. [5, 3, 6, 2, 4, null, 7], key 3: inorder without 3 → [2, 4, 5, 6, 7]
  2. middle index 2 → root 5; left half [2, 4] → 2 with right child 4; right half [6, 7] → 6 with right child 7
  3. result [5, 2, 6, null, 4, null, 7], a valid BST with the same values minus 3

Python

class Solution:
    def deleteNode(self, root: Optional[TreeNode], key: int) -> Optional[TreeNode]:
        values = []

        def inorder(node):                     # left, node, right -> sorted order
            if node is None:
                return
            inorder(node.left)
            if node.val != key:                # leave the key out
                values.append(node.val)
            inorder(node.right)

        def build(lo, hi):                     # balanced BST from values[lo..hi]
            if lo > hi:
                return None
            mid = (lo + hi) // 2
            node = TreeNode(values[mid])
            node.left = build(lo, mid - 1)
            node.right = build(mid + 1, hi)
            return node

        inorder(root)
        return build(0, len(values) - 1)
Time O(n)Space O(n)

Every node is visited once and a new node is created for each remaining value.

When to use: Only as a baseline; it rebuilds the whole tree for a one-node change.

Search for key recursively. The call for each subtree returns its new root, and the parent stores it: root.left = self.deleteNode(root.left, key). Removing a node is then just returning something else from its call.

  • Node not found (None): return None.
  • Leaf, or one child: return the child (or None); the parent links to it directly.
  • Two children: find the inorder successor by walking left from root.right. Copy its value into the node, then delete the successor from the right subtree with the same function. The successor has no left child, so that deletion is one of the easy cases.

The successor is larger than everything on the left and smaller than everything else on the right, so the ordering survives the copy.

Dry run

  1. [5, 3, 6, 2, 4, null, 7], key 3: at 5, 3 < 5 → left
  2. at 3: found, two children (2 and 4) → successor = leftmost of the right subtree = 4
  3. copy 4 into the node; delete 4 from the right subtree: it is a leaf → None
  4. back at 5: 5.left is the node now holding 4 → [5, 4, 6, 2, null, null, 7]

Python

class Solution:
    def deleteNode(self, root: Optional[TreeNode], key: int) -> Optional[TreeNode]:
        if root is None:                       # empty subtree: key is not here
            return None
        if key < root.val:                     # key can only be on the left
            root.left = self.deleteNode(root.left, key)
        elif key > root.val:                   # key can only be on the right
            root.right = self.deleteNode(root.right, key)
        else:                                  # this is the node to delete
            if root.left is None:              # leaf or only a right child
                return root.right
            if root.right is None:             # only a left child
                return root.left
            successor = root.right             # two children: smallest value on the right
            while successor.left:
                successor = successor.left
            root.val = successor.val           # it takes over this spot...
            root.right = self.deleteNode(root.right, successor.val)   # ...and is removed below
        return root                            # this subtree keeps the same root
Time O(h)Space O(h)

One path down to the key, at most one more path down to the successor and back; h = height (log n when balanced, n for a chain).

When to use: The standard answer. Mention that the predecessor (largest on the left) works just as well.

Same search, same easy cases. For two children, instead of copying a value, find the smallest node of the right subtree and attach the whole left subtree under its empty left slot. Then return root.right as the new root of this subtree. Every value on the left is smaller than key, so it is smaller than that leftmost node and than everything above it; the ordering holds and no second deletion is needed.

Same O(h) time. It produces a different, usually taller shape: the left subtree moves down by the length of the walk. That is the trade-off against the copy version, which keeps the height.

  1. [5, 3, 6, 2, 4, null, 7], key 3: found 3 with children 2 and 4
  2. leftmost node of the right subtree is 4; set 4.left = 2
  3. return 4 in place of 3 → [5, 4, 6, 2, null, null, 7] (the same shape here, because 4 was a leaf)

Python

class Solution:
    def deleteNode(self, root: Optional[TreeNode], key: int) -> Optional[TreeNode]:
        if root is None:
            return None
        if key < root.val:
            root.left = self.deleteNode(root.left, key)
        elif key > root.val:
            root.right = self.deleteNode(root.right, key)
        else:
            if root.left is None:
                return root.right
            if root.right is None:
                return root.left
            leftmost = root.right              # smallest value of the right subtree
            while leftmost.left:
                leftmost = leftmost.left
            leftmost.left = root.left          # everything on the left is smaller than it
            return root.right                  # the right child replaces the deleted node
        return root
Time O(h)Space O(h)

One search path plus one walk down the right subtree; no second deletion.

When to use: When you want to avoid copying values (for example when nodes carry extra data); accept the taller tree.

Common mistakes

  • Forgetting to store the result of the recursive call: self.deleteNode(root.left, key) without root.left = ... finds the node but never unhooks it, and the tree comes back unchanged.
  • Returning the deleted node's child in only one of the one-child cases. Handle root.left is None and root.right is None before the two-children logic; the first check also covers a leaf (both None).
  • Deleting the successor with a fresh search for the key instead of self.deleteNode(root.right, successor.val). After the copy the tree holds the successor value twice; the recursive call must run on the right subtree.
  • Expecting one exact output. Successor replacement, predecessor replacement and re-linking all give valid but different trees. Compare with a BST check and a value count, or list every valid shape as the tests here do.
  • Deep recursion: a chain of 10^4 nodes needs 10^4 frames, above Python's default limit of 1000. Use an iterative version with a parent pointer when the input can be that unbalanced.

Python notes

  • root.left = self.deleteNode(root.left, key) is the idiom: the call returns the new root of that subtree (often the same node), and assigning it is what unhooks a removed node. Forgetting the assignment is the classic bug.
  • node.left or node.right picks the only child when one side is None; it reads well but hides a leaf (None or None is None), which is fine here because a leaf should return None anyway.
  • TreeNode does not define __eq__, so comparing two trees means comparing their level-order lists. The tests here use any_of(tree(...), tree(...)) because more than one shape is a correct answer.
  • Default recursion limit is 1000 frames; an iterative version is safer for very skewed trees.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Insert into a Binary Search Tree LC 701 — the same search, but the empty spot you reach is where the new node goes; return it so the parent links to it.
  • Search in a Binary Search Tree LC 700 — only the first half of this problem: steer left or right by comparing with key and return the node you land on.
  • Trim a Binary Search Tree LC 669 — delete every value outside [low, high]: a node below low is replaced by its trimmed right subtree, a node above high by its trimmed left subtree, so no two-children case ever appears.
  • Convert Sorted Array to Binary Search Tree LC 108 — the rebuild step of the brute force on its own: the middle element becomes the root, the halves become the subtrees.
  • Kth Smallest Element in a BST LC 230 — the successor search generalised: an inorder walk visits the values in sorted order, and the k-th one is the answer.
  • Delete without recursion — track parent while searching, then redirect parent.left or parent.right to the replacement; the root needs its own case because it has no parent.
