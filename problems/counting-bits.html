Counting Bits Easy

LeetCode #338 ↗
Status

For every number from 0 to n, count its 1-bits, and fill the whole answer list in O(n).

Problem

Given an integer n, return a list ans of length n + 1 where ans[i] is the number of 1 digits in the binary representation of i, for every i from 0 to n.

Counting each number's bits separately works. The real task is to fill the whole list in a single pass by reusing answers you already have, without calling a built-in bit counter.

Examples

Example 1
Input: n = 2
Output: [0, 1, 1]
0 is 0, 1 is 1, 2 is 10.
Example 2
Input: n = 5
Output: [0, 1, 1, 2, 1, 2]
0 → 0, 1 → 1, 2 → 10, 3 → 11, 4 → 100, 5 → 101.
Example 3
Input: n = 0
Output: [0]
The list has length 1: only the number 0, which has no 1-bits.

Constraints

  • 0 <= n <= 10^5

Key idea

Counting the bits of every number from scratch repeats work: 6 is 110 and 3 is 11, and the first is just the second with a 0 stuck on the end. Their counts are the same.

In general, writing i in binary and cutting off the last digit gives i >> 1 (shift right by one, the same as i // 2). So i is i >> 1 followed by one more bit, and that last bit is i & 1:

ans[i] = ans[i >> 1] + (i & 1)

For every i >= 1 the number i >> 1 is smaller than i, so its answer is already in the list if we fill from left to right. The base case is ans[0] = 0. One lookup and one addition per number give O(n) in total, where the from-scratch version needs O(n log n).

There is a second view of the same idea: i & (i - 1) erases the lowest set bit, leaving a smaller number with exactly one fewer 1, so ans[i] = ans[i & (i - 1)] + 1. This is the Kernighan step from Number of 1 Bits, used as a table lookup.

Approaches from the obvious one to the one you want in an interview

For every i from 0 to n, count its 1-bits with the shift-and-test loop from Number of 1 Bits, and append the result.

It is correct and easy to trust. But every number is counted as if the others did not exist: 5 (101) is 2 (10) with a 1 appended, yet we re-read all of its digits. Each count takes about log n steps, so the total is O(n log n).

Dry run

  1. n = 5
  2. i = 0: no bits → 0
  3. i = 1 (1) → 1, i = 2 (10) → 1, i = 3 (11) → 2
  4. i = 4 (100) → 1, i = 5 (101) → 2
  5. result [0, 1, 1, 2, 1, 2], after re-reading every digit of every number

Python

class Solution:
    def countBits(self, n: int) -> List[int]:
        ans = []
        for i in range(n + 1):
            count, x = 0, i
            while x:                      # count the 1-bits of i from scratch
                count += x & 1
                x >>= 1
            ans.append(count)
        return ans
Time O(n log n)Space O(1)

n numbers, each with up to log n binary digits. Space is O(1) beyond the output list.

When to use: As the correct baseline, or as a reference to test the faster version against.

Let ans[i] be the number of 1-bits in i. Shifting right by one cuts off the last digit, so i is the number i >> 1 followed by one extra bit, i & 1. Their counts differ by exactly that bit:

ans[i] = ans[i >> 1] + (i & 1), with ans[0] = 0.

Because i >> 1 < i for every i >= 1, filling the list from left to right guarantees the cell we read is already final. This is dynamic programming (solve small cases first and build larger ones from them): one lookup and one addition per number, O(n) overall.

Dry run

  1. n = 5, ans = [0, ?, ?, ?, ?, ?]
  2. i = 1: 1 >> 1 = 0, last bit 1 → ans[1] = ans[0] + 1 = 1
  3. i = 2 (10): 2 >> 1 = 1, last bit 0 → ans[2] = ans[1] + 0 = 1
  4. i = 3 (11): 3 >> 1 = 1, last bit 1 → ans[3] = ans[1] + 1 = 2
  5. i = 4 (100): 4 >> 1 = 2, last bit 0 → ans[4] = ans[2] + 0 = 1
  6. i = 5 (101): 5 >> 1 = 2, last bit 1 → ans[5] = ans[2] + 1 = 2

Python

class Solution:
    def countBits(self, n: int) -> List[int]:
        ans = [0] * (n + 1)                   # ans[0] = 0: zero has no 1-bits
        for i in range(1, n + 1):
            # i is (i >> 1) followed by the bit (i & 1); i >> 1 < i, so it is already filled
            ans[i] = ans[i >> 1] + (i & 1)
        return ans
Time O(n)Space O(n)

One pass with O(1) work per cell. The O(n) space is the answer itself.

When to use: The interview answer. State the recurrence first, then the code writes itself.

Watch it run

The same table can be filled from a different smaller number. i & (i - 1) erases the lowest set bit of i, so the result is smaller than i and has exactly one fewer 1:

ans[i] = ans[i & (i - 1)] + 1.

This reuses the Kernighan step from Number of 1 Bits, and it needs no if or parity test. Both recurrences cost the same.

Dry run

  1. ans[0] = 0
  2. i = 3 (11): erase the lowest 1 → 10 = 2, so ans[3] = ans[2] + 1 = 2
  3. i = 4 (100): erase the only 1 → 0, so ans[4] = ans[0] + 1 = 1
  4. i = 5 (101): erase the lowest 1 → 100 = 4, so ans[5] = ans[4] + 1 = 2

Python

class Solution:
    def countBits(self, n: int) -> List[int]:
        ans = [0] * (n + 1)
        for i in range(1, n + 1):
            ans[i] = ans[i & (i - 1)] + 1     # i & (i - 1) is i without its lowest 1-bit
        return ans
Time O(n)Space O(n)

One pass with O(1) work per cell; the list is the output.

When to use: When you have just used n & (n - 1) elsewhere and want a single formula without the parity test.

Common mistakes

  • Creating a list of length n instead of n + 1. The answer covers both 0 and n.
  • Operator precedence: ans[i >> 1] + i & 1 parses as (ans[i >> 1] + i) & 1, because + binds tighter than &. Write ans[i >> 1] + (i & 1).
  • Filling from right to left, or reading ans[i >> 1] before it is set. Loop i upward from 1: i >> 1 is always smaller, so it is already filled.
  • Using i / 2 as the index. In Python 3 it is a float, and indexing a list with a float raises a TypeError. Use i >> 1 or i // 2.
  • Calling bin(i).count("1") for every i and stopping there. It is correct but O(n log n); the point of the problem is the O(n) recurrence.

Python notes

  • i >> 1 and i // 2 give the same result for non-negative i; the shift says "drop the last bit" more directly. i & 1 is that last bit (1 for odd numbers, 0 for even ones).
  • [0] * (n + 1) creates the list with ans[0] = 0 already in place, which is the base case. Preallocating also makes every index explicit; ans.append(...) works too because ans[i >> 1] always exists by the time it is read.
  • bin(i).count("1") for each i is a handy reference: compare your table with [bin(i).count("1") for i in range(n + 1)] in a test.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Number of 1 Bits LC 191 — one number instead of a whole range, so no table: Kernighan's n & (n - 1) loop counts it in O(popcount).
  • Sort Integers by The Number of 1 Bits LC 1356 — sort by the pair (popcount, value). The popcount can come from bin(x).count("1"), or from this table if the values are small.
  • Gray Code LC 89 — another sequence defined purely by bit patterns: the i-th Gray code is i ^ (i >> 1), so neighbours differ by exactly one bit.
  • Offset recurrence — a variant of the same table: let offset be the largest power of two that is at most i, then ans[i] = ans[i - offset] + 1, because removing the top bit leaves a smaller number with one fewer 1.
  • Total number of 1-bits in 1..n, without building the list — count per bit position instead: bit k repeats a block of 2^k zeros then 2^k ones, so full blocks contribute 2^k ones each and only the last partial block needs a remainder calculation.
