Maximum Depth of Binary Tree Easy

LeetCode #104 ↗
Status

Count how many nodes lie on the longest root-to-leaf path.

Problem

Given the root of a binary tree, return its maximum depth: the number of nodes on the longest path from the root down to a leaf (a node with no children).

An empty tree has depth 0; a single node has depth 1.

Examples

Example 1
Input: root = [3, 9, 20, null, null, 15, 7]
Output: 3
The path 3 → 20 → 15 (or 3 → 20 → 7) has three nodes.
Example 2
Input: root = [1, null, 2]
Output: 2
Example 3
Input: root = []
Output: 0

Constraints

  • 0 <= number of nodes <= 10^4
  • -100 <= Node.val <= 100

Think first try before reading the solution

What is the depth of a tree in terms of the depths of its left and right subtrees?
An empty tree (None) has depth 0. That is your base case; everything else is 1 + max(left, right).
Without recursion: visit the tree level by level with a queue and count how many levels you process.

Key idea

Trees are self-similar: the left child is the root of a smaller tree, and so is the right child. That makes recursion natural. The depth of a tree is 1 (for the root itself) plus the depth of its deeper subtree. The recursion stops at None, which has depth 0.

The same question can be answered level by level: put the root in a queue, and repeatedly take out everything on the current level while adding their children. Each round is one level; count the rounds. Both ways touch every node once, so both are O(n).

Approaches from the obvious one to the one you want in an interview

Define the answer in terms of smaller answers:

  • depth(None) = 0
  • depth(node) = 1 + max(depth(node.left), depth(node.right))

That definition is the code. Python's call stack remembers where we are in the tree, so no extra bookkeeping is needed. Each node is visited exactly once.

Dry run

  1. depth(3) → needs depth(9) and depth(20)
  2. depth(9) → both children None → 1 + max(0, 0) = 1
  3. depth(20) → depth(15) = 1, depth(7) = 1 → 1 + max(1, 1) = 2
  4. depth(3) = 1 + max(1, 2) = 3

Python

class Solution:
    def maxDepth(self, root: Optional[TreeNode]) -> int:
        if root is None:                       # empty subtree
            return 0
        left = self.maxDepth(root.left)
        right = self.maxDepth(root.right)
        return 1 + max(left, right)            # this node + deeper side
Time O(n)Space O(h)

Every node once. The call stack is as deep as the tree height h (log n when balanced, n when a chain).

When to use: Default choice; shortest to write and the pattern for most tree problems.

Watch it run

Use a queue. Start with the root. In each round, pop exactly the nodes currently in the queue (one level) and push their children. Every round is one more level of depth.

This avoids recursion entirely, which matters when the tree can be very deep, and it is the skeleton of every "level order" problem.

Dry run

  1. queue = [3], depth 0
  2. round 1: pop 3, push 9 and 20 → queue [9, 20], depth 1
  3. round 2: pop 9 and 20, push 15 and 7 → queue [15, 7], depth 2
  4. round 3: pop 15 and 7, no children → queue [], depth 3 → stop

Python

class Solution:
    def maxDepth(self, root: Optional[TreeNode]) -> int:
        if root is None:
            return 0
        queue = deque([root])
        depth = 0
        while queue:
            depth += 1
            for _ in range(len(queue)):        # exactly the current level
                node = queue.popleft()
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
        return depth
Time O(n)Space O(w)

Every node enters the queue once; the queue holds at most one level (width w, up to n/2).

When to use: When recursion depth is a concern, or when the question is really about levels.

Watch it run

Recursion is just a stack of (node, depth) pairs managed for you. Manage it yourself: push the root with depth 1; pop a node, update the best depth, push its children with depth + 1. Same O(n), no recursion limit, and it generalises to any traversal.

Python

class Solution:
    def maxDepth(self, root: Optional[TreeNode]) -> int:
        stack = [(root, 1)] if root else []
        best = 0
        while stack:
            node, d = stack.pop()
            best = max(best, d)
            if node.left:
                stack.append((node.left, d + 1))
            if node.right:
                stack.append((node.right, d + 1))
        return best
Time O(n)Space O(h)

When to use: Useful to show you understand what recursion does under the hood.

Common mistakes

  • Returning max(left, right) without the + 1 for the current node: you get depth − 1.
  • Treating a None child as depth 1 instead of 0, which inflates every answer by one.
  • In the BFS version, forgetting to freeze the level size (for _ in range(len(queue))) and processing children in the same round.
  • Recursion depth: a degenerate tree with 10⁴ nodes in a line is deeper than Python's default recursion limit (1000). LeetCode raises the limit, but if asked, mention the iterative version.

Python notes

  • collections.deque gives O(1) popleft(); a plain list's pop(0) is O(n).
  • Python's default recursion limit is 1000 frames. LeetCode raises it, but for very deep trees prefer the BFS version or sys.setrecursionlimit.
  • max(left, right) + 1 reads better than an if/else and is just as fast.
