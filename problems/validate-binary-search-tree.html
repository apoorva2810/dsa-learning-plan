Validate Binary Search Tree Medium

LeetCode #98 ↗
Status

Decide whether a binary tree obeys the search-tree ordering rule at every node, not just between parent and child.

Problem

Given the root of a binary tree, return True if it is a valid binary search tree (BST) and False otherwise.

A tree is a valid BST when, for every node:

  • every value in its left subtree is strictly smaller than the node's value,
  • every value in its right subtree is strictly larger than the node's value,
  • and both subtrees are valid BSTs themselves.

Duplicate values are therefore not allowed anywhere.

Examples

Example 1
Input: root = [2, 1, 3]
Output: true
Example 2
Input: root = [5, 1, 4, null, null, 3, 6]
Output: false
4 is the root's right child but 4 < 5.
Example 3
Input: root = [5, 4, 6, null, null, 3, 7]
Output: false
Every parent-child pair looks fine (3 < 6), but 3 is in the root's right subtree and 3 < 5.

Constraints

  • 1 <= number of nodes <= 10^4
  • -2^31 <= Node.val <= 2^31 - 1

Think first try before reading the solution

Checking each node only against its two children is not enough. Find a small tree where every parent-child pair looks correct but the tree is still not a BST.
Every node must fall inside an allowed range (lo, hi) set by its ancestors. Stepping left lowers the upper bound to the parent's value; stepping right raises the lower bound to the parent's value.
Another view: an inorder traversal (left, node, right) of a BST lists its values in strictly increasing order. Compare each value with the previous one.

Key idea

The tempting check, "left child < node < right child", only looks one level down. In [5, 4, 6, null, null, 3, 7] the 3 is a fine left child of 6, yet it lives in the right subtree of 5, where everything must be larger than 5.

So the rule a node must satisfy comes from all its ancestors, and it always boils down to an open range (lo, hi). The root may hold anything: (-∞, ∞). Its left child must be below the root: (-∞, root). A node reached by going right from a node with value v must be above v. Pass the range down the recursion, tightening one side at each step, and check lo < node.val < hi at every node. One visit per node: O(n).

The second way to see it: an inorder walk (left subtree, node, right subtree) of a BST produces its values sorted. So the tree is valid exactly when that sequence is strictly increasing, which you can check with one prev variable.

Approaches from the obvious one to the one you want in an interview

Turn the definition into code directly. For every node, compute the largest value in its left subtree and the smallest value in its right subtree, and require left_max < node.val < right_min. Then check both subtrees the same way.

It is correct because it compares each node with all the values below it, which is exactly the rule. But computing a subtree's max or min walks the whole subtree, and it is repeated for every node: O(n²) on a chain-shaped tree. Each node is re-examined once for every ancestor it has.

Dry run

  1. [5, 4, 6, null, null, 3, 7]
  2. node 5: max(left subtree) = 4 < 5 ✓, but min(right subtree) = min(6, 3, 7) = 3, and 3 <= 5 → False.

Python

class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        def subtree_max(node):
            if node is None:
                return float("-inf")
            return max(node.val, subtree_max(node.left), subtree_max(node.right))

        def subtree_min(node):
            if node is None:
                return float("inf")
            return min(node.val, subtree_min(node.left), subtree_min(node.right))

        def check(node):
            if node is None:
                return True
            # everything on the left must be smaller, everything on the right larger
            if subtree_max(node.left) >= node.val or subtree_min(node.right) <= node.val:
                return False
            return check(node.left) and check(node.right)

        return check(root)
Time O(n²) worst caseSpace O(h)

Every node triggers a full walk of its subtrees; on a chain that is n + (n-1) + ... = O(n²). Balanced trees cost O(n log n).

When to use: Only to make the definition concrete before optimising.

Instead of looking down at the subtree, pass the constraints down from the ancestors. valid(node, lo, hi) means "every value in this subtree must be strictly between lo and hi".

  • valid(None, lo, hi) is True.
  • Otherwise require lo < node.val < hi, then check valid(node.left, lo, node.val) and valid(node.right, node.val, hi).

Going left, the parent's value becomes the new upper bound; going right, it becomes the new lower bound. The other bound is inherited unchanged, which is how a grandparent's limit reaches the 3 in [5, 4, 6, null, null, 3, 7].

Dry run

  1. [5, 4, 6, null, null, 3, 7]
  2. valid(5, -∞, ∞): ✓ → left child gets (-∞, 5), right child gets (5, ∞)
  3. valid(4, -∞, 5): ✓, leaf
  4. valid(6, 5, ∞): ✓ → its left child gets (5, 6)
  5. valid(3, 5, 6): 3 <= 5 ✗ → False

Python

class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        def valid(node, lo, hi):
            """Is every value in this subtree strictly between lo and hi?"""
            if node is None:
                return True
            if not (lo < node.val < hi):        # outside the range its ancestors allow
                return False
            return (valid(node.left, lo, node.val)       # left: new upper bound
                    and valid(node.right, node.val, hi)) # right: new lower bound

        return valid(root, float("-inf"), float("inf"))
Time O(n)Space O(h)

Each node is checked once against two numbers. The call stack is as deep as the tree height h.

When to use: The standard answer; it also stops at the first violation.

Watch it run

An inorder traversal visits left subtree, node, right subtree, so a BST comes out sorted. Run it iteratively with a stack: slide left pushing nodes, pop one (the next value in sorted order), compare it with the previously popped value prev, then move into its right subtree. Any value that is not strictly larger than prev means the tree is not a BST.

Same O(n) time as the bounds version. The trade-off: no recursion (no depth limit), and the same loop answers other BST questions (k-th smallest, iterator), but the reason it works is one step less direct than the range rule.

Dry run

  1. [5, 4, 6, null, null, 3, 7]: inorder visits 4, 5, 3, ...
  2. 4 (prev None) ✓ → 5 > 4 ✓ → 3 <= 5 ✗ → False

Python

class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        stack, node = [], root
        prev = None                     # last value visited in inorder (None = nothing yet)
        while stack or node:
            while node:                 # slide as far left as possible
                stack.append(node)
                node = node.left
            node = stack.pop()          # next value in sorted order
            if prev is not None and node.val <= prev:
                return False            # inorder must be strictly increasing
            prev = node.val
            node = node.right           # then everything just above it
        return True
Time O(n)Space O(h)

Each node is pushed and popped once; the stack holds at most one root-to-leaf path.

When to use: When recursion depth is a concern, or when you want one traversal pattern for several BST questions.

Common mistakes

  • Comparing a node only with its children. It accepts [5, 4, 6, null, null, 3, 7], where 3 is below 6 but in 5's right subtree.
  • Using <= / >= in the wrong place. The rule is strict: [2, 2, 2] and [1, 1] are not BSTs.
  • Using the integer limits -2^31 and 2^31 - 1 as the starting bounds: a node holding exactly 2^31 - 1 then fails val < hi. Use float('-inf') / float('inf'), or None for 'no bound'.
  • In the inorder version, starting prev at a number like -2^31: the tree [-2147483648] is valid but would fail. Start with prev = None and skip the comparison for the first value.
  • Collecting the whole inorder list and testing values == sorted(values) misses duplicates ([1, 1] sorted is itself). Check strictly increasing neighbours instead.

Python notes

  • float('inf') and float('-inf') compare correctly with any int, so they make safe 'no bound yet' values even when a node holds 2^31 - 1.
  • Python chains comparisons: lo < node.val < hi means lo < node.val and node.val < hi.
  • valid(node.left, ...) and valid(node.right, ...) short-circuits: once the left side returns False, the right side is never visited.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Kth Smallest Element in a BST LC 230 — the same inorder walk, but stop after k values instead of checking order.
  • Lowest Common Ancestor of a Binary Search Tree LC 235 — use the BST ordering to steer: go left if both targets are smaller, right if both are larger.
  • Recover Binary Search Tree LC 99 — two nodes were swapped by mistake: an inorder walk shows one or two 'drops' in the sequence, which pinpoint them.
  • Largest BST Subtree LC 333 — find the biggest subtree that is a BST: work bottom-up, each call returning (is_bst, min, max, size).
  • Binary Search Tree Iterator LC 173 — package the iterative inorder walk as a class whose next() returns the next smallest value in O(1) amortised time.
  • What if duplicates are allowed on the left? — the left range becomes (lo, hi]: change < to <= on that side only, and test with repeated values.
