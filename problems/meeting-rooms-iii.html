Meeting Rooms III Hard 250

LeetCode #2402 ↗
Status

Assign meetings to numbered rooms by fixed rules (lowest free room, or wait for the first to free up) and report the busiest room.

Problem

A building has n meeting rooms numbered 0 to n - 1. You are given a list meetings where each item [start, end] is a meeting that wants to run from time start up to, but not including, time end. No two meetings have the same start time.

Meetings are placed in order of their start time, by these rules:

  • If at least one room is free at time start, the meeting takes the free room with the smallest number.
  • If every room is busy, the meeting waits for the room that frees up first and then runs in that room with the same duration it originally had. If several rooms free up at that same moment, it takes the one with the smallest number.
  • A room in use until time t is free for a meeting that starts at t.

Return the number of the room that hosted the most meetings. If several rooms tie, return the smallest room number.

Examples

Example 1
Input: n = 2, meetings = [[0, 10], [1, 3], [2, 4], [5, 6]]
Output: 1
[0, 10] takes room 0 and [1, 3] takes room 1. At time 2 both rooms are busy; room 1 frees up first (at 3), so [2, 4] waits and runs in room 1 from 3 to 5. [5, 6] starts exactly when room 1 frees up, so it takes room 1 too. Room 1 hosted 3 meetings, room 0 hosted 1.
Example 2
Input: n = 3, meetings = [[4, 9], [1, 2], [3, 6], [2, 5]]
Output: 0
In start order: [1, 2] takes room 0. [2, 5] starts at 2, when room 0 is free again, and room 0 is the lowest free room, so it takes room 0. [3, 6] finds rooms 1 and 2 free and takes room 1. [4, 9] takes room 2. Room 0 hosted 2 meetings, the others 1 each.
Example 3
Input: n = 3, meetings = [[0, 2], [1, 3]]
Output: 0
Rooms 0 and 1 host one meeting each and room 2 is never used. Ties go to the smallest room number.

Constraints

  • 1 <= n <= 100
  • 1 <= len(meetings) <= 10^5
  • meetings[i] = [start, end] with 0 <= start < end <= 5 * 10^5
  • all start times are distinct

Think first try before reading the solution

Run the rules by hand on a tiny input, meeting by meeting in start order. The only thing you ever need to know about a room is when it becomes free.
For each meeting you ask two questions: which rooms have freed up by now, and, if none is free, which room frees up first? Both are 'give me the smallest of a changing collection' questions, and a min-heap answers those in O(log n).
Keep two min-heaps: free, holding room numbers, and busy, holding (free_time, room) pairs. Before placing a meeting, move every room whose free time is at or before start from busy to free. Then pop from free if you can, otherwise pop from busy and shift the meeting to that free time, keeping its duration.

Key idea

This is a simulation: there is no formula, you replay the rules in start order and count. The rules themselves say what the data structures must be. Twice per meeting you need "the smallest of a changing collection": the lowest-numbered free room, and the busy room that frees up first. A min-heap (a list kept so that the smallest item is always at index 0, with O(log n) insert and remove) is exactly that.

So keep two heaps. free holds room numbers, so heappop(free) is the lowest free room. busy holds (free_time, room) pairs; Python compares tuples element by element, so heappop(busy) returns the room that frees up first and, on ties, the lowest number. That is the tie rule from the statement for free.

Before placing a meeting that starts at start, every busy room with free_time <= start has become free: pop them all into free. Then either a free room exists (take the smallest) or none does. In the second case the meeting waits for the top of busy; it runs from that free_time with the same duration, so its new end is free_time + (end - start). Each meeting costs a few heap operations: O(m log m) for the sort plus O(m log n) for the heaps.

Approaches from the obvious one to the one you want in an interview

Keep free_at[r], the time room r becomes free (0 at the start), and count[r]. Walk the meetings in start order. Scan the rooms from 0 upwards and take the first one with free_at[r] <= start. If the scan finds none, the meeting waits for the room with the smallest free_at (list.index(min(...)) returns the lowest room on ties) and runs there for its original duration.

This is the statement turned into code, and it is easy to trust. Each meeting scans all n rooms, so it costs O(m · n). With n ≤ 100 that passes, but it does 100 comparisons to answer a question a heap answers in one.

Dry run

  1. n = 2, meetings = [[0, 10], [1, 3], [2, 4], [5, 6]], free_at = [0, 0], count = [0, 0]
  2. [0, 10]: room 0 has free_at = 0 <= 0, take it: free_at = [10, 0], count = [1, 0]
  3. [1, 3]: room 0 is busy, room 1 is free: free_at = [10, 3], count = [1, 1]
  4. [2, 4]: both busy; the smallest free_at is 3 (room 1). Wait until 3, run 3 → 5: free_at = [10, 5], count = [1, 2]
  5. [5, 6]: room 0 busy, room 1 free at 5 <= 5: free_at = [10, 6], count = [1, 3]. Answer: room 1.

Python

class Solution:
    def mostBooked(self, n: int, meetings: List[List[int]]) -> int:
        free_at = [0] * n                           # the time each room becomes free
        count = [0] * n
        for start, end in sorted(meetings):         # the rules apply in start order
            room = -1
            for r in range(n):                      # lowest-numbered room that is free by `start`
                if free_at[r] <= start:
                    room = r
                    break
            if room == -1:                          # every room is busy: wait for the first to free up
                room = free_at.index(min(free_at))  # index() picks the lowest room on ties
                end = free_at[room] + (end - start) # same duration, later start
            free_at[room] = end
            count[room] += 1
        return count.index(max(count))              # lowest room among the most used
Time O(m log m + m · n)Space O(n)

Sorting m meetings, then a scan of n rooms per meeting. Two arrays of size n.

When to use: As the first version: it is the statement written out, and with n ≤ 100 it is fast enough.

Replace the two room scans with two heaps. free is a min-heap of room numbers, so popping gives the lowest free room. busy is a min-heap of (free_time, room) pairs, so popping gives the room that frees up first, and, because tuples compare element by element, the lowest room number among those that free up at the same time.

For each meeting in start order:

  1. Release: while the top of busy has free_time <= start, pop it and push its room into free.
  2. Place: if free is not empty, pop the lowest room and push (end, room) into busy. Otherwise pop (free_time, room) from busy: the meeting waits, runs from free_time for its original duration, so push (free_time + end - start, room).
  3. count[room] += 1.

Every room is pushed and popped a bounded number of times per meeting, so after the O(m log m) sort the simulation costs O(m log n).

Dry run

  1. n = 2, meetings = [[0, 10], [1, 3], [2, 4], [5, 6]], free = [0, 1], busy = []
  2. [0, 10]: nothing to release; pop room 0 from free, push (10, 0): busy = [(10, 0)], count = [1, 0]
  3. [1, 3]: top of busy frees at 10 > 1; pop room 1, push (3, 1): busy = [(3, 1), (10, 0)], count = [1, 1]
  4. [2, 4]: nothing frees by 2 and free is empty; pop (3, 1), duration 2, push (5, 1): count = [1, 2]
  5. [5, 6]: (5, 1) has 5 <= 5, release room 1; pop it from free, push (6, 1): count = [1, 3]
  6. count.index(3) = 1

Python

class Solution:
    def mostBooked(self, n: int, meetings: List[List[int]]) -> int:
        free = list(range(n))                       # min-heap of free room numbers (sorted = valid heap)
        busy = []                                   # min-heap of (time the room frees up, room)
        count = [0] * n
        for start, end in sorted(meetings):         # the rules apply in start order
            while busy and busy[0][0] <= start:     # release every room that is free by `start`
                _, room = heapq.heappop(busy)
                heapq.heappush(free, room)
            if free:
                room = heapq.heappop(free)          # lowest-numbered free room
                heapq.heappush(busy, (end, room))
            else:
                free_time, room = heapq.heappop(busy)   # frees up first; lowest room on ties
                heapq.heappush(busy, (free_time + end - start, room))   # delayed, same duration
            count[room] += 1
        return count.index(max(count))              # lowest room among the most used
Time O(m log m + m log n)Space O(n)

The sort dominates. Each meeting does O(1) pops and pushes on heaps of at most n items; every room entry released was pushed once, so releases are paid for by the pushes.

When to use: The interview answer: the two heaps are the two rules of the statement, and nothing is scanned.

Common mistakes

  • Keeping the original end when a meeting is delayed. A meeting that waits keeps its duration, not its end time: the new free time is free_time + (end - start). Using end makes a delayed meeting end early or even before it starts.
  • Releasing only one room per meeting. Several rooms can free up before the next start, so loop while busy and busy[0][0] <= start. A single if leaves a free room marked busy, and a later meeting waits for nothing.
  • Using < instead of <= when releasing rooms. A room busy until 5 is free for a meeting that starts at 5 (example 1 depends on it).
  • Storing only the free time in busy. Without the room number in the tuple you cannot tell which room you popped, and ties between rooms that free up at the same time would not go to the lowest number.
  • Skipping the sort. The rules apply in start order, and the input comes in any order; placing meetings as given changes which rooms are free when.
  • Breaking the final tie the wrong way. count.index(max(count)) returns the lowest room with the top count; Counter(...).most_common(1) or a dictionary scan may return a different room when several tie.

Python notes

  • list(range(n)) is sorted, and a sorted list is already a valid min-heap; heapq.heapify on it is harmless but does nothing.
  • Tuples compare element by element, so a heap of (free_time, room) pairs pops the earliest free time and, on ties, the lowest room. That is exactly the tie rule in the statement.
  • while busy and busy[0][0] <= start: reads the top of the heap without removing it. Test busy first: busy[0] on an empty list raises.
  • count.index(max(count)) returns the first index that holds the maximum, which is the lowest room number.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Meeting Rooms II LC 253 — only the number of rooms is asked and nothing waits: one heap of end times is enough, and the heap size is the answer.
  • Meeting Rooms LC 252 — yes or no, can one room host everything? Sort by start and compare each meeting with the previous end.
  • Single-Threaded CPU LC 1834 — one 'room' and tasks that wait: when the CPU frees up, the shortest waiting task goes first, so the waiting side needs its own heap. Here the waiting side is trivial because meetings are served in start order.
  • Process Tasks Using Servers LC 1882 — the same two heaps with servers instead of rooms: the free heap is keyed by (weight, index), and you return the server of every task instead of the busiest one.
  • Return the actual schedule — report, for every meeting, its room and the time it really started: record (room, start) when you place it; for a delayed meeting the real start is the free_time you popped.
  • A waiting meeting may be overtaken — if a room that frees up should take the shortest waiting meeting rather than the earliest one, you need a heap of waiting meetings keyed by duration and must advance time to the next event, as in Single-Threaded CPU.
