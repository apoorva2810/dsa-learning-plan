Maximum Subarray Medium

LeetCode #53 ↗
Status

Find the contiguous stretch of a list whose elements add up to the largest sum.

Problem

Given an integer list nums, find the contiguous stretch of it (a subarray) with the largest sum and return that sum.

The list can hold negative numbers, zeros and positive numbers. The subarray must contain at least one element.

Examples

Example 1
Input: nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
Output: 6
The subarray [4, -1, 2, 1] adds up to 6, and no other stretch does better.
Example 2
Input: nums = [-3, -1, -2]
Output: -1
Every number is negative and the subarray cannot be empty, so the best choice is the single element -1.
Example 3
Input: nums = [5, 4, -1, 7, 8]
Output: 23
The whole list. The running total never turns negative, so there is nothing worth dropping.

Constraints

  • 1 <= len(nums) <= 10^5
  • -10^4 <= nums[i] <= 10^4

Think first try before reading the solution

Trying every start and end is easy to write. Before optimising it, ask: if the stretch you have built so far adds up to a negative number, would you ever want it at the front of a longer stretch?
A negative running sum can only drag down whatever comes after it. So when the stretch you are building drops to a sum of 0 or less, throw it away and start a new stretch at the next element.
Keep two numbers while scanning: cur, the best sum of a stretch that ends at the current index, and best, the largest cur seen so far. Start both at nums[0], not at 0, because the whole list may be negative.

Key idea

Look at where a best subarray could end. For each index i, let cur be the largest sum of a subarray that ends exactly at i. That subarray is either nums[i] alone, or some subarray ending at i - 1 with nums[i] added on. The best one to extend is the best one ending at i - 1, so

cur = max(nums[i], cur_before + nums[i])

The answer is the largest cur over all i, because the best subarray has to end somewhere.

Read as a greedy rule, this says: if the stretch built so far sums to 0 or less, drop it. That is safe. Take any subarray that starts with a part adding up to 0 or less. Cut that part off and the sum does not go down, so a best subarray never needs such a start (this is the exchange argument: swap "part + rest" for "rest"). Because dropping never loses anything, you never look back. One pass, O(n) time, O(1) space. This is Kadane's algorithm.

It is also a tiny dynamic program: the state "best sum ending at i" reads only the previous state, so a single variable replaces the table.

Approaches from the obvious one to the one you want in an interview

A subarray is fixed by its start and its end. For each start, move the end to the right one element at a time and keep a running total, so each new subarray costs one addition instead of re-adding the whole stretch.

That is about n²/2 subarrays. For n = 10^5 it is around 5 billion additions, far too slow. (Calling sum(nums[i:j]) for each pair would be O(n³).)

Dry run

  1. nums = [-2, 1, -3, 4], best = -2
  2. start 0: totals -2, -1, -4, 0 → best 0
  3. start 1: totals 1, -2, 2 → best 2
  4. start 2: totals -3, 1 → best stays 2
  5. start 3: total 4 → best 4

Python

class Solution:
    def maxSubArray(self, nums: List[int]) -> int:
        best = nums[0]                           # the subarray cannot be empty
        for start in range(len(nums)):
            total = 0
            for end in range(start, len(nums)):  # grow the subarray one element at a time
                total += nums[end]
                best = max(best, total)
        return best
Time O(n²)Space O(1)

n(n + 1)/2 subarrays, each updated in O(1) from the previous one.

When to use: To check a faster solution on small inputs.

Scan once and keep cur, the best sum of a subarray ending at the current index.

  • If the run so far adds up to more than 0, it helps: extend it, cur = cur + x.
  • Otherwise it can only drag x down (or add nothing): drop it and restart, cur = x.

max(x, cur + x) is exactly that choice. After each element, best = max(best, cur). Every element is looked at once and only two numbers are stored.

Dry run

  1. nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4], cur = best = -2
  2. x = 1: run before is -2 (≤ 0) → restart, cur = 1, best 1
  3. x = -3: run before is 1 → extend, cur = -2, best stays 1
  4. x = 4: run before is -2 (≤ 0) → restart, cur = 4, best 4
  5. x = -1, 2, 1: extend → cur = 3, 5, 6 → best 6
  6. x = -5: cur = 1; x = 4: cur = 5 → best stays 6
  7. answer 6 (the run [4, -1, 2, 1])

Python

class Solution:
    def maxSubArray(self, nums: List[int]) -> int:
        cur = best = nums[0]                     # best sum of a run ending at index 0
        for x in nums[1:]:
            cur = max(x, cur + x)                # extend the run, or restart at x
            best = max(best, cur)                # the best run can end at any index
        return best
Time O(n)Space O(1)

One pass, two variables.

When to use: The interview answer. Say "best sum ending here" out loud and connect it to the drop-a-negative-prefix rule.

Watch it run

Split the list in half. The best subarray lies in one of three places:

  1. entirely in the left half,
  2. entirely in the right half, or
  3. across the middle.

The first two are the same problem on half the input. For the third, the best crossing subarray is the best suffix of the left half (ending at the middle) plus the best prefix of the right half (starting just after it), and each is found with one scan outward from the middle. The work is T(n) = 2·T(n/2) + O(n), which is O(n log n).

Kadane is faster, but this is the official follow-up and the shape generalises to problems that cannot be solved with a single left-to-right state.

Python

class Solution:
    def maxSubArray(self, nums: List[int]) -> int:
        def solve(lo: int, hi: int) -> int:      # best subarray inside nums[lo..hi]
            if lo == hi:
                return nums[lo]
            mid = (lo + hi) // 2

            # best suffix of the left half, scanning left from mid
            left_best, running = float("-inf"), 0
            for i in range(mid, lo - 1, -1):
                running += nums[i]
                left_best = max(left_best, running)

            # best prefix of the right half, scanning right from mid + 1
            right_best, running = float("-inf"), 0
            for i in range(mid + 1, hi + 1):
                running += nums[i]
                right_best = max(right_best, running)

            crossing = left_best + right_best    # the stretch that joins both halves
            return max(solve(lo, mid), solve(mid + 1, hi), crossing)

        return solve(0, len(nums) - 1)
Time O(n log n)Space O(log n)

log n levels of recursion, O(n) scanning work per level; the call stack is log n deep.

When to use: When the interviewer asks for the divide and conquer solution, or to show the idea beyond Kadane.

Common mistakes

  • Starting best at 0. For [-3, -1, -2] that returns 0, but the subarray cannot be empty, so the answer is -1. Start from nums[0].
  • Mixing up subarray (contiguous) and subsequence (any chosen elements). Adding up all the positive numbers of the first example gives 12, but only an unbroken stretch counts, and the best one is 6.
  • Comparing cur with best only when you extend. After a restart cur can already be the new best (in [-3, -1, -2] the answer -1 appears right after a restart), so compare on every index.
  • Computing each stretch with sum(nums[i:j]) inside two loops. That is O(n³). Carry a running total along the end index instead, which makes the brute force O(n²).
  • Resetting cur to 0 before updating best (the if cur < 0: cur = 0 shortcut placed at the top of the loop). Add the element, update best, and only then reset.

Python notes

  • max(x, cur + x) is the whole "extend or restart" decision. The two-line if cur > 0: ... else: ... form means the same.
  • Start with cur = best = nums[0] and loop over nums[1:]. The slice copies the list; range(1, len(nums)) avoids the copy.
  • float("-inf") is an alternative start value for best that also works for any non-empty list.
  • The same answer is max(P[j] - min(P[i] for i < j)) for the prefix sums P (itertools.accumulate builds them). That is exactly the Best Time to Buy and Sell Stock formula.
  • Python integers do not overflow, so large sums need no special care. The divide and conquer version recurses only about log2(n) levels deep, far below Python's recursion limit.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Best Time to Buy and Sell Stock LC 121 — a trade's profit is the sum of consecutive daily price changes, so this is the same problem on prices[i] - prices[i - 1], with the empty trade allowed (the answer is at least 0).
  • Maximum Product Subarray LC 152 — products instead of sums. A negative number turns the smallest product into the largest, so keep both the maximum and the minimum product ending at each index.
  • Maximum Sum Circular Subarray LC 918 — the stretch may wrap around the end. Either it does not wrap (plain Kadane) or it equals the total minus the smallest subarray (Kadane for the minimum). Treat an all-negative list as a special case.
  • Maximum Subarray Sum with One Deletion LC 1186 — you may delete one element: keep two values per index, the best sum ending here with no deletion and the best with one deletion.
  • Maximum Absolute Sum of Any Subarray LC 1749 — run Kadane twice, once for the largest sum and once for the smallest, and return the bigger magnitude.
  • Return the subarray itself, not just its sum — remember where the current run began: set start = i when you restart, and when best improves record (start, i).
