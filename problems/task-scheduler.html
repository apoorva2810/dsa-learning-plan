Task Scheduler Medium

LeetCode #621 ↗
Status

Schedule lettered CPU tasks so two runs of the same letter have at least n intervals between them, using as few intervals as possible.

Problem

A CPU must run a list of tasks. Each task is a capital letter (A–Z), and the same letter can appear many times. Time is split into intervals; in each interval the CPU either runs one task or sits idle.

Two runs of the same letter must be separated by at least n intervals (a cooldown). Different letters have no such restriction, and tasks may run in any order.

Return the minimum number of intervals needed to run every task, idle intervals included.

Examples

Example 1
Input: tasks = ["A","A","A","B","B","B"], n = 2
Output: 8
A B idle A B idle A B. A runs at intervals 1, 4 and 7: two intervals between each pair.
Example 2
Input: tasks = ["A","C","A","B","D","B"], n = 1
Output: 6
A B C A B D: the other letters fill every gap, so the CPU never idles.
Example 3
Input: tasks = ["A","A","A","B","B","B"], n = 3
Output: 10
A B idle idle A B idle idle A B.

Constraints

  • 1 <= len(tasks) <= 10^4
  • tasks[i] is an uppercase English letter
  • 0 <= n <= 100

Key idea

Idle intervals are forced by the most frequent letter: its copies must be spread out, and the gaps between them can only be filled with other letters. So the greedy rule is: in every interval, run the available letter with the most copies left. It keeps the big piles shrinking evenly, which leaves the most choices later.

Two structures make the rule cheap:

  • a max-heap of remaining counts (stored negated) for letters that may run now;
  • a queue of letters that are cooling down, each with the first interval it may run again. Every letter cools down for exactly n intervals, so they become ready in the same order they entered: first in, first out.

When the heap is empty but the queue is not, the CPU has to idle; instead of ticking through each idle interval, jump the clock to the time the front of the queue becomes ready. There is also a counting formula ((max_count - 1) * (n + 1) + ties) that gives the number without simulating; it is the alternative below.

Approaches from the obvious one to the one you want in an interview

Apply the greedy rule directly. Keep, for every letter, how many copies are left and the first interval it may run again. Then walk time forward one interval at a time: scan all letters, run the available one with the most copies left, or idle if none is available.

The greedy choice is right (it is the same rule the heap applies); the cost is the bookkeeping. Every interval, idle ones included, scans every letter, so the work is O(T · 26), where T is the answer itself. With 10⁴ tasks of one letter and n = 100 that is about a million intervals.

Dry run

  1. ["A","A","A","B","B","B"], n = 2
  2. t1: A and B both have 3 left → run A (A may run again at t4)
  3. t2: only B is available → run B (again at t5); t3: nothing available → idle
  4. t4: A, t5: B, t6: idle, t7: A, t8: B → 8 intervals

Python

class Solution:
    def leastInterval(self, tasks: List[str], n: int) -> int:
        left = Counter(tasks)                    # copies still to run, per letter
        next_ok = {}                             # letter -> first interval it may run again
        remaining = len(tasks)
        time = 0
        while remaining:
            time += 1
            best = None                          # available letter with the most copies left
            for letter, count in left.items():
                if count and next_ok.get(letter, 0) <= time:
                    if best is None or count > left[best]:
                        best = letter
            if best is not None:                 # otherwise this interval is idle
                left[best] -= 1
                next_ok[best] = time + n + 1
                remaining -= 1
        return time
Time O(T · 26)Space O(26)

T = number of intervals in the answer, up to about len(tasks) · (n + 1); each interval scans up to 26 letters.

When to use: To check your understanding of the greedy rule; too slow when n is large.

Same greedy rule, without scanning:

  1. Put every count into a max-heap (negated). These letters may run now.
  2. Each interval: pop the biggest count and run that letter. If copies remain, append it to a queue with the first interval it may run again, time + n + 1.
  3. When the front of the queue reaches its ready time, push it back into the heap. Every letter cools down for the same n, so the queue is always in ready-time order.
  4. If the heap is empty, the CPU must idle: jump time straight to the front of the queue's ready time.

Every pass through the loop runs exactly one task (an idle stretch is skipped by the jump inside the same pass), so the loop runs len(tasks) times, each with O(log 26) heap work.

Dry run

  1. heap {A: 3, B: 3}, queue empty
  2. t1: run A → queue [A×2 @t4]; t2: run B → queue [A×2 @t4, B×2 @t5]
  3. t3: heap empty → idle, jump to t4; A rejoins the heap and runs → queue [B×2 @t5, A×1 @t7]
  4. t5: B rejoins and runs; t6: heap empty → idle, jump to t7; A runs (last copy)
  5. t8: B rejoins and runs its last copy → both empty → answer 8

Python

class Solution:
    def leastInterval(self, tasks: List[str], n: int) -> int:
        heap = [-c for c in Counter(tasks).values()]   # max-heap of copies left (negated)
        heapq.heapify(heap)
        cooling = deque()                        # (negated copies left, first interval it may run again)
        time = 0
        while heap or cooling:
            time += 1
            if not heap:                         # nothing may run: idle until the next letter is ready
                time = cooling[0][1]
            if cooling and cooling[0][1] == time:
                heapq.heappush(heap, cooling.popleft()[0])   # cooldown over: ready again
            left = heapq.heappop(heap) + 1       # run the letter with the most copies left (-3 + 1 = -2)
            if left:                             # copies remain: cool down for n intervals
                cooling.append((left, time + n + 1))
        return time
Time O(N)Space O(1)

N = len(tasks). Each loop runs one task (plus at most one idle jump); heap and queue hold at most 26 letters.

When to use: The general technique: it also produces the schedule and adapts to variants such as Reorganize String.

Watch it run

Let max_count be the highest count and ties the number of letters that have it. Lay the most frequent letter out as max_count - 1 frames of length n + 1, each starting with that letter, plus one last frame holding only the tied letters:

n = 2, A×3 B×3:   [A B _] [A B _] [A B]   → (3 - 1) * 3 + 2 = 8

Other letters fill the gaps; any gap left over is idle. If there are more tasks than gaps, the frames stretch and no idle is needed, so the answer is len(tasks). Hence max(len(tasks), (max_count - 1) * (n + 1) + ties). It is O(N) and short, but it gives only the number, not a schedule, and the argument is harder to come up with under pressure.

Python

class Solution:
    def leastInterval(self, tasks: List[str], n: int) -> int:
        counts = Counter(tasks).values()
        max_count = max(counts)
        ties = sum(1 for c in counts if c == max_count)   # letters tied for the top count
        frames = (max_count - 1) * (n + 1) + ties         # full frames + the final, partial frame
        return max(len(tasks), frames)                    # enough other tasks means no idle at all
Time O(N)Space O(1)

One counting pass; the counter holds at most 26 letters.

When to use: When only the number is asked and you can explain the frame argument.

Common mistakes

  • Running whichever available letter comes first (alphabetical or input order) instead of the one with the most copies left. ["B","B","B","A","C"], n = 2: A-first gives A B C idle B idle idle B = 8 intervals; most-copies-first gives B A C B idle idle B = 7.
  • Forgetting letters that tie for the highest count in the formula: ["A","A","B","B"], n = 2 needs A B idle A B = 5, not 4.
  • Forgetting that the answer is never less than len(tasks): with many different letters the frame formula comes out too small, so take the max.
  • Counting an idle interval after the very last task. The schedule ends the moment the last task runs.
  • Ticking the clock through long idle stretches one interval at a time in the heap version. When the heap is empty, jump straight to the next ready time.

Python notes

  • Counter(tasks).values() gives the counts; the heap version never needs the letters themselves.
  • heapq.heappop(heap) + 1 on a negated count means "one copy fewer": -3 + 1 = -2, and 0 means the letter is done.
  • deque.popleft() is O(1). A plain list's pop(0) would shift every element.
  • The heap never holds more than 26 entries, so each heap operation is O(log 26), effectively constant.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Reorganize String LC 767 — the cooldown is 1 and you must return the arrangement (or "" if impossible): the same max-heap, holding back the letter just used for one step.
  • Rearrange String k Distance Apart LC 358 — any cooldown k, and you return the string: this exact heap + cooling queue, but report failure where this problem would idle.
  • Task Scheduler II LC 2365 — tasks must run in the given order, so there is nothing to choose: a dictionary of each task type's next allowed day replaces the heap.
  • Single-Threaded CPU LC 1834 — tasks arrive over time and the CPU picks the shortest available one: a heap keyed by processing time, fed in arrival order.
  • Return the schedule, not just its length — keep the letter in each heap entry, (-count, letter), and record what runs in every interval (the trace below does this).
