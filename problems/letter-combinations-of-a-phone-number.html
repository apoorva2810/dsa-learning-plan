Letter Combinations of a Phone Number Medium

LeetCode #17 ↗
Status

List every string you could spell by replacing each digit with one of its phone-keypad letters.

Problem

On an old phone keypad every digit from 2 to 9 stands for a few letters:

digitlettersdigitletters
2abc6mno
3def7pqrs
4ghi8tuv
5jkl9wxyz

You are given a string digits that contains only the digits 2 to 9. Return every string you could spell by replacing each digit with one of its letters, keeping the digits in their original order. The strings may be returned in any order.

If digits is empty, return an empty list.

Examples

Example 1
Input: digits = "23"
Output: ["ad", "ae", "af", "bd", "be", "bf", "cd", "ce", "cf"]
2 can be a, b or c and 3 can be d, e or f, so there are 3 x 3 = 9 strings.
Example 2
Input: digits = ""
Output: []
No digits means nothing to spell.
Example 3
Input: digits = "2"
Output: ["a", "b", "c"]

Constraints

  • 0 <= len(digits) <= 4
  • each character of digits is one of '2' ... '9'

Think first try before reading the solution

Every answer picks exactly one letter for each digit, and the digits do not influence each other. How many independent choices are there, and how many options does each one have?
Fill the positions from left to right. Write a function backtrack(i) that decides the letter for digits[i]. What should it do when i has reached len(digits)?
Keep one shared list path. For each letter of the current digit: append it, call backtrack(i + 1), then remove it again so the next letter starts from the same path. At the end of the digits, join the path into a string and save it.

Key idea

Every output string has exactly one letter per digit, and the choices for different digits are independent. So the answers are all the ways to pick one letter from each digit's group: 3 x 3 = 9 strings for "23", and at most 4^4 = 256 for four digits. Nothing can be skipped, so the job is to list them all without missing or repeating one.

Backtracking lists answers by building one choice at a time. Keep a partial answer (path), try each option for the next position, go one level deeper, and when you come back undo the last choice so the next option starts from the same partial answer. The calls form a tree: level i holds the choices for digit i, and every leaf is a finished string.

Here every branch ends in a valid string, so nothing is ever abandoned early. That makes this the cleanest place to learn the choose, explore, un-choose rhythm. The harder problems in this topic use the same three lines and only add a test that cuts a branch off before it grows.

Approaches from the obvious one to the one you want in an interview

Start with one empty prefix, [""]. For each digit, build a new list in which every existing prefix is extended by each letter of that digit. After the last digit the list holds all the answers.

It is not slow: it produces exactly the 4^n strings the output needs, so no solution can be faster in big-O terms. Its limit is structural: it keeps every partial string alive at once and has no way to drop one early. That costs nothing here, where every partial string is useful, but it is a dead end for problems in which most partial answers turn out to be wrong.

Dry run

  1. digits = "23", start with combos = [""] (one empty prefix).
  2. digit 2 stands for abc: each prefix gets each letter, so combos = ["a", "b", "c"].
  3. digit 3 stands for def: each of the 3 prefixes gets 3 letters, so combos = ["ad", "ae", "af", "bd", "be", "bf", "cd", "ce", "cf"].
  4. No digits are left, so those 9 strings are the answer.

Python

class Solution:
    def letterCombinations(self, digits: str) -> List[str]:
        if not digits:                       # no digits -> no combinations (not [""])
            return []
        letters = {"2": "abc", "3": "def", "4": "ghi", "5": "jkl",
                   "6": "mno", "7": "pqrs", "8": "tuv", "9": "wxyz"}
        combos = [""]                        # one empty prefix to start from
        for digit in digits:
            # every existing prefix is extended by every letter of this digit
            combos = [prefix + ch for prefix in combos for ch in letters[digit]]
        return combos
Time O(n · 4^n)Space O(n · 4^n)

n digits with at most 4 letters each give at most 4^n strings of length n. The lists of prefixes are no bigger than the output itself.

When to use: The shortest correct solution. Use it to see the structure, then learn backtracking, which keeps one partial answer instead of all of them.

Keep a single list path with the letters chosen so far, and a recursive function backtrack(i) that fills position i.

  • Base case: i == len(digits) means every digit has a letter. Join path into a string and save it.
  • Otherwise: for each letter of digits[i], choose it (append), explore with backtrack(i + 1), then un-choose it (pop) so the next letter starts from the same path.

Only one partial answer exists at any moment, so the extra memory is the recursion depth, len(digits) frames. The running time is the same as the loop version, but this shape is the one you will reuse when some choices have to be rejected.

Dry run

  1. digits = "23", path = []. backtrack(0): digit 2 offers a, b, c. Choose a, so path = [a].
  2. backtrack(1): digit 3 offers d, e, f. Choose d, so path = [a, d]. backtrack(2) is the base case: save "ad".
  3. Pop d, choose e, save "ae", pop, choose f, save "af", pop. Digit 3 has no letters left, so backtrack(1) returns.
  4. Pop a, choose b and repeat: "bd", "be", "bf". Then c: "cd", "ce", "cf".
  5. 9 leaves means 9 strings.

Python

class Solution:
    def letterCombinations(self, digits: str) -> List[str]:
        if not digits:                       # no digits -> no combinations (not [""])
            return []
        letters = {"2": "abc", "3": "def", "4": "ghi", "5": "jkl",
                   "6": "mno", "7": "pqrs", "8": "tuv", "9": "wxyz"}
        combos = []
        path = []                            # the letters chosen so far, one per digit

        def backtrack(i):
            if i == len(digits):             # every digit has a letter
                combos.append("".join(path)) # save a copy as a string
                return
            for ch in letters[digits[i]]:    # every letter this digit can stand for
                path.append(ch)              # choose
                backtrack(i + 1)             # explore the next digit
                path.pop()                   # un-choose

        backtrack(0)
        return combos
Time O(n · 4^n)Space O(n)

At most 4^n leaves, and the inner nodes of the tree add only a constant factor to that. Joining a path into a string costs O(n). Besides the output, memory is the path and the recursion, both n deep.

When to use: The interview answer. Say 'choose, explore, un-choose' out loud while you write it.

Watch it run

The answers are the Cartesian product of the letter groups: one letter from the first group, one from the second, and so on. Python has that built in, so itertools.product(*groups) produces every combination as a tuple of letters, and "".join turns each tuple into a string.

Knowing the one-liner is useful, but interviewers usually ask for the recursive version, because it is the one that extends to problems where some choices are not allowed.

Dry run

  1. groups = ["abc", "def"] for "23".
  2. product("abc", "def") yields ("a","d"), ("a","e"), ("a","f"), ("b","d"), ... ("c","f").
  3. Joining each tuple gives "ad", "ae", ... "cf".

Python

class Solution:
    def letterCombinations(self, digits: str) -> List[str]:
        if not digits:                       # product() of nothing yields one empty tuple, so guard first
            return []
        letters = {"2": "abc", "3": "def", "4": "ghi", "5": "jkl",
                   "6": "mno", "7": "pqrs", "8": "tuv", "9": "wxyz"}
        groups = [letters[d] for d in digits]
        return ["".join(combo) for combo in itertools.product(*groups)]
Time O(n · 4^n)Space O(n · 4^n)

Common mistakes

  • Returning [""] for empty input. A recursion that saves the empty path at depth 0 does exactly that, so guard with if not digits: return [] first.
  • Saving path (the list) instead of "".join(path). Every saved entry is the same list object, and the final pop() calls leave all of them empty.
  • Forgetting path.pop(). The next letter is then appended after the previous one and strings grow longer than len(digits).
  • Writing one for loop per digit. The number of digits is not fixed, so the number of loops cannot be fixed either. Recursion depth (or a growing list of prefixes) replaces the nested loops.
  • Using integer keys for the mapping. digits[i] is a character, so the dictionary needs "2", not 2.

Python notes

  • A string is iterable, so for ch in "abc": loops over its letters. Storing each digit's letters as one string is shorter than a list of one-letter strings.
  • "".join(path) turns the list of chosen letters into a new string. That new string is what you store, because path keeps changing.
  • itertools.product(*groups) yields every way to take one item from each group, in order. The * unpacks the list of groups into separate arguments.
  • The nested helper backtrack can use path and combos from the enclosing method without nonlocal, because it only calls methods on them (append, pop) and never assigns to those names.
  • The recursion is only len(digits) (at most 4) calls deep, so Python's recursion limit does not matter.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Generate Parentheses LC 22 — the choice at each position is ( or ), but many choices are illegal. Cut a branch the moment it can no longer become a balanced string.
  • Combinations LC 77 — choose k numbers from 1..n. The options shrink as you go, because each step only looks at numbers after the one just chosen (a start index).
  • Letter Case Permutation LC 784 — each letter has two choices (lower or upper) and each digit has one: the same tree with a different branching factor.
  • Restore IP Addresses LC 93 — each level picks a segment of 1 to 3 digits. Segments with a leading zero or a value above 255 are pruned, so some branches die early.
  • Only keep real words (predictive text) — store the dictionary in a trie and extend a path only while it is a prefix of some word. This is the pruning idea from Word Search II.
  • Just count the combinations — no strings needed: multiply the number of letters of each digit (3 x 3 = 9 for "23"). That is O(n) instead of O(4^n).
