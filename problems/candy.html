Candy Hard 250

LeetCode #135 ↗
Status

Hand out the fewest candies to a line of children so that every child gets one and anyone with a higher rating than a neighbour gets more than that neighbour.

Problem

There are n children standing in a line, and child i has a rating ratings[i]. You give out candies under two rules:

  1. every child gets at least one candy;
  2. a child whose rating is higher than a neighbour's gets more candies than that neighbour. A neighbour is the child directly to the left or directly to the right. Two children with equal ratings place no demand on each other.

Return the smallest total number of candies that satisfies both rules.

Examples

Example 1
Input: ratings = [1, 2, 5, 4, 3, 2, 1]
Output: 18
The candies are [1, 2, 5, 4, 3, 2, 1]. The staircase 5, 4, 3, 2, 1 going down forces those counts on the right of the peak. The climb on the left would only need 1, 2, 3, but the peak must also beat the 4 next to it, so it gets 5.
Example 2
Input: ratings = [2, 4, 4, 1, 5]
Output: 8
The candies are [1, 2, 2, 1, 2]. The two children rated 4 are equal, so neither has to beat the other. The first beats the child on its left and the second beats the child on its right, so each gets 2.
Example 3
Input: ratings = [1, 2, 3, 4, 1]
Output: 11
The candies are [1, 2, 3, 4, 1]. The climb already gives the child rated 4 four candies. The drop at the end asks them to beat a child holding 1, which four candies already do, so the climb's requirement wins.

Constraints

  • 1 <= len(ratings) <= 2 * 10^4
  • 0 <= ratings[i] <= 2 * 10^4

Think first try before reading the solution

Start every child at 1 candy. Look at only one rule first, the one about the left neighbour. How would you fix it with a single pass? Then think about the right neighbour separately.
A left-to-right sweep handles the left rule: if a child out-rates the left neighbour, they need one more candy than that neighbour. A right-to-left sweep handles the right rule in the same way. Can the two rules ever disagree about what a child needs?
No, a child just needs the larger of the two requirements. Do it in place: after the first sweep, the second sweep sets candies[i] = max(candies[i], candies[i + 1] + 1) whenever ratings[i] > ratings[i + 1].

Key idea

Every child has two neighbours, and the two rules about them are independent. Handle them one at a time.

Left rule. Sweep from left to right. If a child out-rates the one on their left, they need at least one more candy than that child, so candies[i] = candies[i - 1] + 1. Otherwise the left rule asks for nothing. After this sweep every child respects their left neighbour.

Right rule. Sweep from right to left in the same way. If a child out-rates the one on their right, they need at least one more candy than that child. A child must satisfy both rules, so keep the larger requirement: candies[i] = max(candies[i], candies[i + 1] + 1).

Why is this the smallest total? Each requirement is forced by a chain of ratings: a child at the end of a climb of length k needs at least k + 1 candies, and the same on a descent. Nobody can receive less than the larger of the two chains, and giving each child exactly that larger number satisfies every pair. For any two neighbours with different ratings, only one sweep puts a demand on the higher child, so the two sweeps never fight over the same pair.

In the second sweep, candies[i + 1] already holds the child's finished count, not just the right-rule count. That is safe: if ratings[i] > ratings[i + 1], the right child does not out-rate the child on their left, so the first sweep gave them only the base candy, and their finished count comes entirely from the right rule.

Approaches from the obvious one to the one you want in an interview

Give everyone 1 candy. Then scan the line again and again. At each child, if they out-rate a neighbour but do not have more candies, raise them to one more than that neighbour. Stop when a whole scan changes nothing.

Because candies only ever go up, and only by the amount a rule forces, the result is the smallest valid assignment. But a raise travels only a few places per scan. A long descent such as [5, 4, 3, 2, 1] needs about n scans before the left end catches up, so the total work is O(n²).

Dry run

  1. ratings = [4, 3, 2, 1], candies = [1, 1, 1, 1]
  2. scan 1: child 0 beats child 1 → 2; child 1 beats child 2 → 2; child 2 beats child 3 → 2 → [2, 2, 2, 1]
  3. scan 2: child 0 and child 1 are raised again → [3, 3, 2, 1]
  4. scan 3: child 0 → [4, 3, 2, 1]; scan 4 changes nothing → total 10

Python

class Solution:
    def candy(self, ratings: List[int]) -> int:
        n = len(ratings)
        candies = [1] * n                        # everyone starts with one candy
        changed = True
        while changed:                           # repeat until no child is unhappy
            changed = False
            for i in range(n):
                if i > 0 and ratings[i] > ratings[i - 1] and candies[i] <= candies[i - 1]:
                    candies[i] = candies[i - 1] + 1      # must beat the left neighbour
                    changed = True
                if i + 1 < n and ratings[i] > ratings[i + 1] and candies[i] <= candies[i + 1]:
                    candies[i] = candies[i + 1] + 1      # must beat the right neighbour
                    changed = True
        return sum(candies)

Up to about n scans of n children each (a long descent or climb).

When to use: To see the rules in action, and to check a faster solution on small inputs.

Handle the two neighbour rules one at a time.

  1. Left to right: if ratings[i] > ratings[i - 1], set candies[i] = candies[i - 1] + 1. Now every child respects their left neighbour.
  2. Right to left: if ratings[i] > ratings[i + 1], set candies[i] = max(candies[i], candies[i + 1] + 1). The max keeps the left requirement while adding the right one.

The answer is sum(candies). Each sweep is one pass, so the whole thing is O(n) time, with a single list of n counts.

Dry run

  1. ratings = [1, 2, 5, 4, 3, 2, 1], candies = [1, 1, 1, 1, 1, 1, 1]
  2. left to right: 2 > 1 → 2; 5 > 2 → 3; the drops 4, 3, 2, 1 change nothing → [1, 2, 3, 1, 1, 1, 1]
  3. right to left: child 5 (2 > 1) → 2; child 4 (3 > 2) → 3; child 3 (4 > 3) → 4
  4. child 2 (5 > 4) needs 5 and has 3, so it is raised to 5; children 1 and 0 are not higher than their right neighbours
  5. [1, 2, 5, 4, 3, 2, 1] adds up to 18

Python

class Solution:
    def candy(self, ratings: List[int]) -> int:
        n = len(ratings)
        candies = [1] * n                        # everyone starts with one candy
        for i in range(1, n):                    # sweep 1: respect the left neighbour
            if ratings[i] > ratings[i - 1]:
                candies[i] = candies[i - 1] + 1
        for i in range(n - 2, -1, -1):           # sweep 2: respect the right neighbour
            if ratings[i] > ratings[i + 1]:
                candies[i] = max(candies[i], candies[i + 1] + 1)    # keep the left requirement too
        return sum(candies)
Time O(n)Space O(n)

Two linear sweeps and one list of n counts.

When to use: The standard answer. Be ready to explain why max is needed in the second sweep.

Watch it run

View the ratings as a sequence of hills. Walk once and keep four numbers: total, the candies give handed to the previous child while climbing, the candy count peak at the top of the current hill, and down, how many children we have walked down since the top.

  • Climbing (ratings[i] > ratings[i - 1]): give += 1, the child gets give, and that count is the new peak.
  • Flat (equal ratings): start over, the child gets 1.
  • Descending: the new child gets 1 and every child of the descent so far gets one more, which adds down candies in total. If the descent has become as long as the peak is tall (down >= peak), the peak needs one more candy as well.

It never stores the candy counts, only their running total.

Dry run

  1. ratings = [1, 2, 5, 4, 3, 2, 1]: total = 1, give = peak = 1
  2. climb to 2 and 5: give = 2, 3, peak = 3, total = 1 + 2 + 3 = 6
  3. descend to 4: down = 1, add 1 → 7; down is below peak (3), so the peak keeps its candies
  4. descend to 3: down = 2, add 2 → 9; descend to 2: down = 3, add 3 → 12, and down >= peak, so add 1 for the peak → 13
  5. descend to 1: down = 4, add 4 → 17, and add 1 more for the peak → 18

Python

class Solution:
    def candy(self, ratings: List[int]) -> int:
        total = 1                                # the first child gets one candy
        give = 1                                 # candies given to the previous child while climbing
        peak = 1                                 # candies at the top of the current hill
        down = 0                                 # children walked down since the top
        for i in range(1, len(ratings)):
            if ratings[i] > ratings[i - 1]:      # climbing: one more than the child before
                down = 0
                give += 1
                peak = give
                total += give
            elif ratings[i] == ratings[i - 1]:   # flat: a fresh start with one candy
                down = 0
                give = peak = 1
                total += 1
            else:                                # descending
                down += 1
                total += down                    # the new child gets 1 and each earlier child of the descent gets one more
                if down >= peak:                 # the top must stay above the first child of the descent
                    total += 1
                give = 1
        return total

Common mistakes

  • Only sweeping once. A left-to-right sweep alone gives [1, 1, 1, 1], so 4 candies, for ratings [4, 3, 2, 1], but the answer is 10. The descent needs the right-to-left sweep.
  • Overwriting instead of taking the larger value in the second sweep. For [1, 2, 3, 4, 1] the first sweep gives [1, 2, 3, 4, 1]; writing candies[3] = candies[4] + 1 = 2 breaks the climb and totals 9 instead of 11. Use max.
  • Giving more candies to a child with an equal rating. The rule only applies to strictly higher ratings, so equal neighbours may hold the same count: [4, 4] needs 2 candies in total, not 3.
  • Adding the two sweeps together (left[i] + right[i]) instead of taking the maximum. Each sweep already includes the base candy, so the sum counts it twice and hands out far too many.
  • Treating the line as a series of independent hills. A peak belongs to two slopes: its count must beat both the climb before it and the descent after it, which is why the second sweep must compare with the first.

Python notes

  • [1] * n builds the starting list of ones, and sum(candies) adds up the answer.
  • range(n - 2, -1, -1) walks from the second-to-last index down to 0 for the right-to-left sweep.
  • max(candies[i], candies[i + 1] + 1) is the whole "keep the larger requirement" step.
  • With two separate arrays, sum(max(a, b) for a, b in zip(left, right)) combines them. Reusing a single list, as in the code here, saves one array of memory.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Trapping Rain Water LC 42 — the same two-sided idea: compute the best value seen from the left and from the right, then combine them per position, with min instead of max.
  • Product of Array Except Self LC 238 — a left-to-right pass builds prefix products, a right-to-left pass folds in suffix products, and each position combines the two.
  • Valid Parenthesis String LC 678 — a wildcard problem with a two-sweep solution: one sweep from the left treats every * as ( and checks that no ) is left uncovered, and one sweep from the right treats every * as ) and checks the same for (.
  • Longest Mountain in Array LC 845 — the hill-and-valley view of this problem: measure the length of each climb and descent around a peak. The O(1)-space approach here uses the same runs.
  • Can you do it with O(1) extra space? — yes: walk the ratings once and treat each peak as a climb followed by a descent. The third approach keeps a running total, the peak's candy count and the descent length, and once the descent is at least as long as the peak is tall, it adds one more candy for the peak at every further step.
  • What if the children stand in a circle? — the first and last children become neighbours, so one sweep in each direction misses the pair (last, first). Think about where you could cut the circle so that no demand crosses the cut.
