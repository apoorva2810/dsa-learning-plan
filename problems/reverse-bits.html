Reverse Bits Easy

LeetCode #190 ↗
Status

Reverse the order of the 32 binary digits of a number, leading zeros included.

Problem

Given a 32-bit unsigned integer n, reverse the order of its 32 binary digits and return the integer they now spell.

n counts as exactly 32 bits wide, so leading zeros are part of the number. Counting positions from the right (position 0 is the rightmost bit), the bit at position i moves to position 31 - i.

Examples

Example 1
Input: n = 43261596
Output: 964176192
00000010100101000001111010011100 reversed is 00111001011110000010100101000000.
Example 2
Input: n = 4294967293
Output: 3221225471
11111111111111111111111111111101 reversed is 10111111111111111111111111111111.
Example 3
Input: n = 1
Output: 2147483648
The only 1 starts at position 0 and ends at position 31, which is worth 2^31.

Constraints

  • 0 <= n <= 2^32 - 1
  • n is an unsigned 32-bit integer (an ordinary non-negative int in Python)

Think first try before reading the solution

Reverse a short example by hand first: 0011 becomes 1100 in 4 bits. For 32 bits, where does the bit at position 0 end up? And the bit at position i?
Build the answer like moving cards between two piles. Take the lowest bit off n (read it with n & 1, drop it with n >>= 1) and put it on the right end of result (result = (result << 1) | bit). How many times must you repeat that? Think about numbers with many leading zeros.
Repeat exactly 32 times, not while n:, or the leading zeros of n are lost. For a version that is fast when called many times, swap the two 16-bit halves, then the bytes inside each half, then nibbles, pairs and single bits: five masked swaps.

Key idea

Reversing is the same as popping items off one pile and pushing them onto another, which flips their order. Here the pile is a row of bits. The lowest bit of n is the top of the first pile: n & 1 reads it and n >>= 1 removes it. Pushing onto the second pile means shifting result left to open a gap and writing the bit into the new lowest position: result = (result << 1) | bit.

After 32 pops the bit that came off first sits at the far left of result and the one that came off last sits at the far right: the order has flipped. The loop must run exactly 32 times. A small n has zeros in its high positions, and those zeros have to become the low positions of the answer. Stopping as soon as n reaches 0 would throw them away.

A faster version treats reversal as swapping at every scale: swap the two 16-bit halves, then swap the two bytes inside each half, then the 4-bit nibbles, the 2-bit pairs, and finally single bits. After those five swaps every bit sits at the mirrored position. Each swap is ((n & high_mask) >> k) | ((n & low_mask) << k): the masks choose which blocks move down and which move up, and they also keep every result inside 32 bits, which Python will not do for us.

Approaches from the obvious one to the one you want in an interview

Turn n into a 32-character string of 0 and 1, reverse the string, and read it back as a binary number.

It is short and correct, and it shows what the problem asks for. It sidesteps the bit operations, though, and it hides one trap: the string must be padded to exactly 32 digits, otherwise the leading zeros vanish and the answer is wrong.

Dry run

  1. n = 1
  2. format(1, "032b") is '000...0001' (31 zeros, then a 1)
  3. reversed: '1000...000'
  4. int(..., 2) = 2147483648

Python

class Solution:
    def reverseBits(self, n: int) -> int:
        bits = format(n, "032b")          # exactly 32 characters; leading zeros are kept
        return int(bits[::-1], 2)         # reverse the text, then read it back as binary
Time O(w)Space O(w)

w = 32 is the width. The string holds one character per bit.

When to use: Quick scripts and as a reference to test the bit versions against.

Keep result, starting at 0. Repeat exactly 32 times:

  1. read the lowest bit of n with n & 1;
  2. shift result left by one to open a gap, then OR the bit into it: result = (result << 1) | bit;
  3. shift n right by one to discard the bit that was just moved.

The first bit popped ends up at the far left, the last at the far right, so the order is reversed. Running a fixed 32 rounds (not while n:) is what carries the input's leading zeros over to the answer as trailing zeros.

Dry run

  1. Shrunk to 8 bits to fit here: n = 00010110, result = 0
  2. pop 0 → result = 0; pop 1 → 01; pop 1 → 011; pop 0 → 0110
  3. pop 1 → 01101; pop 0 → 011010; pop 0 → 0110100; pop 0 → 01101000
  4. 8 rounds done: 01101000 is 00010110 reversed. The real function runs 32 rounds.

Python

class Solution:
    def reverseBits(self, n: int) -> int:
        result = 0
        for _ in range(32):                      # exactly 32 rounds: leading zeros count too
            result = (result << 1) | (n & 1)     # push n's lowest bit onto the right of result
            n >>= 1                              # drop that bit from n
        return result
Time O(w)Space O(1)

32 rounds of constant work. w = 32, so effectively constant time.

When to use: The interview answer. Explain why the loop is range(32) and not while n.

Watch it run

Mirror a word by swapping in halves, recursively. Swap the upper and lower 16 bits; then, inside each half, swap the two bytes; then the nibbles; then the 2-bit pairs; then single bits. Five stages for 32 bits.

Each stage is ((n & high) >> k) | ((n & low) << k), where high selects every upper block of size k and low every lower block. The masks also confine the shifted bits to 32 positions, which Python would not do on its own.

This is the answer to the follow-up "what if the function is called many times?": it has no loop at all.

Dry run

  1. Shrunk to 8 bits: n = 00010110
  2. swap nibbles (4 bits): 0110 0001
  3. swap bit-pairs (2 bits): 10 01 01 00
  4. swap single bits: 01101000, which is the reverse of 00010110
  5. for 32 bits, add the first two stages (halves, then bytes)

Python

class Solution:
    def reverseBits(self, n: int) -> int:
        n = ((n & 0xFFFF0000) >> 16) | ((n & 0x0000FFFF) << 16)   # swap the two 16-bit halves
        n = ((n & 0xFF00FF00) >> 8) | ((n & 0x00FF00FF) << 8)     # swap bytes inside each half
        n = ((n & 0xF0F0F0F0) >> 4) | ((n & 0x0F0F0F0F) << 4)     # swap nibbles inside each byte
        n = ((n & 0xCCCCCCCC) >> 2) | ((n & 0x33333333) << 2)     # swap 2-bit pairs inside each nibble
        n = ((n & 0xAAAAAAAA) >> 1) | ((n & 0x55555555) << 1)     # swap single bits inside each pair
        return n
Time O(log w)Space O(1)

log2(32) = 5 stages of constant work, with no loop over individual bits.

When to use: Hot paths and the "called many times" follow-up. Harder to read, so comment each mask.

Common mistakes

  • Looping while n: instead of exactly 32 times. For n = 1 the loop stops after one round and returns 1 instead of 2147483648.
  • Reversing bin(n)[2:] without padding. bin drops leading zeros, so the reversed text is shorter than 32 digits and the answer loses its trailing zeros. Pad with format(n, "032b").
  • Forgetting that Python never wraps. In the swap version n << 16 is wider than 32 bits; the masks in (n & low_mask) << k are what keep the shifted part inside 32 bits.
  • Precedence: result << 1 | n & 1 happens to work (<< binds tighter than &, which binds tighter than |), but (result << 1) | (n & 1) is the version a reader can trust at a glance.
  • Passing a negative number (other languages hand you a signed 32-bit int). Mask it first with n & 0xFFFFFFFF, otherwise n >>= 1 keeps copying the sign bit.

Python notes

  • format(n, "032b") writes n as exactly 32 binary digits, zero-padded. int(text, 2) reads binary text back into an integer, and text[::-1] reverses a string.
  • result << 1 opens a gap on the right and | (n & 1) fills it. + (n & 1) gives the same value, because the new lowest bit is 0, but | states the intent.
  • Python integers never overflow. If you kept shifting result left it would grow without limit; the loop stops after 32 rounds so it ends with at most 32 bits.
  • Hex literals make 32-bit masks short to write: each hex digit is 4 bits, so 0xFFFF0000 is sixteen 1s followed by sixteen 0s.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Number of 1 Bits LC 191 — the other fixed-width 32-bit problem: count the bits instead of moving them, with the Kernighan step n & (n - 1).
  • Reverse Integer LC 7 — the same pop-and-push loop on decimal digits (% 10, * 10), plus a check that the result still fits in 32 bits.
  • Bitwise AND of Numbers Range LC 201 — the answer is the common binary prefix of the two endpoints: shift both right until they are equal, then shift back.
  • Number Complement LC 476 — flip only the bits up to the highest 1: XOR with a mask of n.bit_length() ones, not with ~n.
  • What if it is called millions of times? — precompute the reversal of every byte (256 entries) and combine four lookups, or use the five-swap mask version below.
  • Other widths — for 8, 16 or 64 bits change the loop count to the width and use masks of that width in the swap version.
