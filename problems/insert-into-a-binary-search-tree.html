Insert into a Binary Search Tree Medium 250

LeetCode #701 ↗
Status

Add a new value to a binary search tree so that the tree is still a valid search tree, and return its root.

Problem

You are given the root of a binary search tree (BST) and an integer val. Insert val into the tree and return the root of the updated tree.

In a BST, every node's left subtree holds only smaller values and its right subtree only larger ones. All values in the tree are distinct, and val is not in the tree yet. The root may be None (an empty tree); then the new node is the whole tree.

More than one resulting shape is a valid BST (a rebuilt or rotated tree is one too). The tests on this page expect the standard result: the new value becomes a new leaf, and no existing node moves.

Examples

Example 1
Input: root = [10, 5, 15, 3, 7], val = 6
Output: [10, 5, 15, 3, 7, null, null, null, null, 6]
6 < 10, so go left to 5. 6 > 5, so go right to 7. 6 < 7, so go left. 7 has no left child, so 6 becomes it.
Example 2
Input: root = [4, 2, 9], val = 12
Output: [4, 2, 9, null, null, null, 12]
12 is larger than 4 and than 9, so it goes right twice and becomes the right child of 9.
Example 3
Input: root = [], val = 5
Output: [5]
Nothing to search: the new node is the root.

Constraints

  • 0 <= number of nodes <= 10^4
  • -10^8 <= Node.val <= 10^8
  • all Node.val are distinct
  • -10^8 <= val <= 10^8
  • val does not occur in the tree

Key idea

A BST keeps one rule at every node: smaller values on the left, larger values on the right. The rule tells you where a value must be if it is in the tree: compare it with the node and go left or right, so there is only one road from the root. Insertion follows the same road. Because val is not in the tree yet, the road ends at an empty slot, a None child.

That slot is the one place where val fits without moving any other node. The slot lies on the road the search takes, so every comparison made above it still holds with the new node in place. Create the node, hang it there, and it is a leaf. Nothing else changes.

The recursive form is the neat one. insert(node, val) returns the root of its subtree after the insertion: an empty subtree returns the new node, and any other node stores the result of the recursive call in the correct child with node.left = insert(node.left, val) and returns itself. The iterative form walks down with a pointer and attaches the node when the child it wants is None. Both visit one node per level: O(h) for a tree of height h, which is log n for a balanced tree and n for a chain.

Approaches from the obvious one to the one you want in an interview

Let insertIntoBST(node, val) return the root of the subtree rooted at node after the insertion.

  • If node is None, this empty spot is where val belongs: return a new TreeNode(val).
  • If val < node.val, the value belongs on the left: node.left = insertIntoBST(node.left, val).
  • Otherwise it belongs on the right: node.right = insertIntoBST(node.right, val).
  • Return node, which is still the root of its subtree.

Only the last call, the one that meets None, creates anything. Every caller above it stores what it gets back, which is the same node it already had, until the call right above the new leaf stores the leaf itself. One call per level: O(h) time, and O(h) for the call stack.

Dry run

  1. root = [10, 5, 15, 3, 7], val = 6: insert(10, 6): 6 < 10 → 10.left = insert(5, 6)
  2. insert(5, 6): 6 > 5 → 5.right = insert(7, 6)
  3. insert(7, 6): 6 < 7 → 7.left = insert(None, 6)
  4. insert(None, 6): empty spot → return a new TreeNode(6)
  5. back up: 7.left becomes the new node, then 5.right = 7 and 10.left = 5 change nothing; return 10

Python

class Solution:
    def insertIntoBST(self, root: Optional[TreeNode], val: int) -> Optional[TreeNode]:
        if root is None:                        # an empty spot: the new node goes here
            return TreeNode(val)
        if val < root.val:
            root.left = self.insertIntoBST(root.left, val)     # the left subtree after the insertion
        else:
            root.right = self.insertIntoBST(root.right, val)   # the right subtree after the insertion
        return root                             # this node is still the root of its subtree
Time O(h)Space O(h)

One call per level of the road down; h is the height (log n for a balanced tree, n for a chain). The call stack is as deep as the road.

When to use: The shortest correct answer, and the pattern for every 'modify a BST' problem.

Watch it run

Do the same walk with a pointer. Keep cur, starting at the root. At each node compare val with cur.val:

  • if the child on that side is None, this is the empty slot: attach the new node there and return root;
  • otherwise move cur into that child and repeat.

Looking at the child before stepping into it keeps the parent in hand, so there is nothing to remember. The empty tree is the one special case, handled before the loop. Same O(h) time as the recursion, but only O(1) extra space and no recursion limit.

Dry run

  1. root = [10, 5, 15, 3, 7], val = 6, cur = 10
  2. 6 < 10 and 10.left is 5, not empty → cur = 5
  3. 6 > 5 and 5.right is 7, not empty → cur = 7
  4. 6 < 7 and 7.left is empty → 7.left = TreeNode(6); return the root

Python

class Solution:
    def insertIntoBST(self, root: Optional[TreeNode], val: int) -> Optional[TreeNode]:
        new_node = TreeNode(val)
        if root is None:                        # empty tree: the new node is the whole tree
            return new_node
        cur = root
        while True:
            if val < cur.val:
                if cur.left is None:            # empty slot on the left: attach here
                    cur.left = new_node
                    return root
                cur = cur.left                  # otherwise keep going down
            else:
                if cur.right is None:           # empty slot on the right: attach here
                    cur.right = new_node
                    return root
                cur = cur.right
Time O(h)Space O(1)

At most one comparison per level; only the new node and the pointer cur are allocated.

When to use: The version to prefer for deep or skewed trees; the same idea without the call stack.

Common mistakes

  • Discarding the recursive result: self.insertIntoBST(root.left, val) alone changes nothing when root.left is None, because the new node is only returned, never linked. Assign it: root.left = self.insertIntoBST(...).
  • Forgetting return root after the two branches. The caller then stores None in its child, and a whole subtree disappears.
  • In the loop version, stepping into the None child (cur = cur.left and then testing cur). You have lost the parent and cannot attach anything. Look one step ahead: test cur.left is None before moving.
  • Not handling the empty tree. root is None on the first call, so the function must return the new node itself.
  • Rebuilding or rebalancing the tree 'to be safe'. It is allowed, but it is far more work than hanging one leaf, and this page's tests expect the leaf.
  • Deep recursion: a chain of 10^4 nodes needs 10^4 frames, above Python's default limit of 1000. The loop version has no such limit.

Python notes

  • root.left = self.insertIntoBST(root.left, val) is the idiom. The call returns the new root of that subtree (usually the same node) and the assignment is what links a newly created node. Assigning an unchanged value is harmless.
  • TreeNode(val) creates the new leaf; left and right default to None.
  • Because the values are distinct, val < node.val and an else branch cover every case. If duplicates were allowed you would have to pick a side for equal values (for example, always right).
  • while True with a return inside both branches is easier to get right than a while cur: loop that has to remember the parent.
  • Python's default recursion limit is 1000 frames; use the loop version for very skewed trees.

What an interviewer might ask next, and what changes.

  • Delete Node in a BST LC 450 — the opposite operation. Finding the node is the same walk, but a node with two children needs its inorder successor to take its place.
  • Validate Binary Search Tree LC 98 — how to check that a tree really satisfies the rule: every node must lie inside a (low, high) window that narrows as you descend.
  • Lowest Common Ancestor of a Binary Search Tree LC 235 — the same descent, steered by two values: stop at the first node where they would go different ways.
  • Construct Binary Search Tree from Preorder Traversal LC 1008 — inserting the values one by one with this function works, in O(n · h) time; passing a (low, high) bound down while reading the list once makes it O(n).
  • What if the tree must stay balanced? — Inserting sorted values with this function builds a chain and costs O(n²) in total. Self-balancing trees (AVL, red-black) insert the same way and then rotate nodes on the way back up to keep the height O(log n).
