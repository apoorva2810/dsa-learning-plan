Build a Matrix With Conditions Hard 250

LeetCode #2392 ↗
Status

Place the numbers 1..k in a k × k grid so that given above/below and left/right orderings all hold.

Problem

You are given a positive integer k and two lists of conditions. Build a k × k matrix that contains each of the numbers 1 … k exactly once; every other cell is 0.

  • Each rowConditions[i] = [above, below] requires the number above to sit in a row strictly above the row of below.
  • Each colConditions[i] = [left, right] requires the number left to sit in a column strictly to the left of the column of right.

Return any matrix that satisfies every condition, or an empty list [] if no such matrix exists.

Examples

Example 1
Input: k = 3, rowConditions = [[1, 2], [3, 2]], colConditions = [[2, 1], [3, 2]]
Output: [[0, 0, 1], [3, 0, 0], [0, 2, 0]]
1 and 3 must be above 2; 3 must be left of 2, and 2 left of 1. Rows top to bottom hold 1, 3, 2; columns left to right hold 3, 2, 1. Swapping the rows of 1 and 3 gives another valid answer.
Example 2
Input: k = 3, rowConditions = [[1, 2], [2, 3], [3, 1], [2, 3]], colConditions = [[2, 1]]
Output: []
1 above 2, 2 above 3 and 3 above 1 cannot all hold: the row conditions go round in a circle.
Example 3
Input: k = 2, rowConditions = [], colConditions = [[2, 1]]
Output: [[0, 1], [2, 0]]
Rows are unconstrained, so 1 may take the top row. 2 must be left of 1.

Constraints

  • 2 <= k <= 400
  • 1 <= len(rowConditions), len(colConditions) <= 10^4
  • 1 <= above, below, left, right <= k, with above != below and left != right

Think first try before reading the solution

Forget the matrix for a moment. If you only knew in which row each number goes, would the column conditions care? What does that tell you about the two lists?
Row conditions and column conditions are independent: solve 'order the numbers top to bottom' and 'order the numbers left to right' separately. 'a must come before b' is a directed edge a → b, and an order that respects all edges is a topological order.
Run a topological sort (Kahn's algorithm: repeatedly take a number with no remaining incoming edges) twice. If either sort cannot place all k numbers, there is a cycle: return []. Otherwise put number v at (row position of v, column position of v).

Key idea

Each number occupies one row and one column, and a row condition says nothing about columns (nor the other way round). So the problem splits into two independent copies of the same sub-problem: order the numbers 1 … k so that every [a, b] puts a before b.

That sub-problem is topological sorting: draw an arrow a → b for each condition and find an order in which every arrow points forward. Kahn's algorithm does it with a queue: a number with no incoming arrows (in-degree 0) has nothing that must precede it, so it can go first; remove its outgoing arrows, which may free up other numbers, and repeat. If the queue runs dry before all k numbers are placed, the leftovers all wait for one another: a cycle, and no valid matrix exists.

Once you hold a row order and a column order, the matrix almost builds itself: number v goes to row row_of[v] (its position in the row order) and column col_of[v]. Rows are distinct because each number has its own position in the row order, so every row and column holds exactly one number and the rest is zeros.

Approaches from the obvious one to the one you want in an interview

Rows and columns never interact, so look for a top-to-bottom order of the numbers that satisfies the row conditions, and separately a left-to-right order for the column conditions. The naive way to find one is to try all k! permutations and keep the first that puts a before b for every condition.

Two independent searches instead of one joint search over k!² pairs is already the first insight, but k! is hopeless beyond about ten numbers, and the real limit is k = 400.

Dry run

  1. Example 1, rows: try 1,2,3 (3 is not above 2: fail), 1,3,2 (1 above 2, 3 above 2: ok)
  2. Columns: 1,2,3 fails (2 must be left of 1), … , 3,2,1 is the first that works
  3. Place 1 at (row 0, col 2), 3 at (1, 0), 2 at (2, 1)

Python

class Solution:
    def buildMatrix(self, k: int, rowConditions: List[List[int]], colConditions: List[List[int]]) -> List[List[int]]:
        def find_order(conditions: List[List[int]]) -> List[int]:
            for perm in itertools.permutations(range(1, k + 1)):
                position = {v: i for i, v in enumerate(perm)}
                if all(position[a] < position[b] for a, b in conditions):
                    return list(perm)          # the first order that satisfies every condition
            return []                          # none does: the conditions contradict each other

        row_order = find_order(rowConditions)
        col_order = find_order(colConditions)
        if not row_order or not col_order:
            return []

        row_of = {v: r for r, v in enumerate(row_order)}   # position of each number in its order
        col_of = {v: c for c, v in enumerate(col_order)}
        matrix = [[0] * k for _ in range(k)]
        for v in range(1, k + 1):
            matrix[row_of[v]][col_of[v]] = v
        return matrix
Time O(k! · (k + m))Space O(k)

Up to k! permutations per list, each checked against its m conditions.

When to use: Only to see that the two orderings are independent; it cannot handle k beyond about 10.

Treat each condition [a, b] as a directed edge a → b and find a topological order: a sequence in which every edge points forward. Kahn's algorithm:

  1. Count each number's in-degree (incoming edges). Put every number with in-degree 0 in a queue.
  2. Pop a number, append it to the order, and lower the in-degree of each number it points to. Anything that reaches 0 joins the queue.
  3. If fewer than k numbers come out, the rest are stuck in a cycle: no valid order.

Do this once for the row conditions and once for the column conditions. Then row_of[v] and col_of[v], the positions of v in the two orders, are its coordinates. Building each graph and running Kahn is linear in k + m, where m is the number of conditions.

Dry run

  1. Example 1, rows: in-degrees 1:0, 2:2, 3:0 → queue [1, 3]
  2. Pop 1 (row 0): 2 drops to 1. Pop 3 (row 1): 2 drops to 0, queue [2]. Pop 2 (row 2). Order 1, 3, 2
  3. Columns: in-degrees 1:1, 2:1, 3:0 → pop 3, then 2, then 1. Order 3, 2, 1
  4. 1 → (0, 2), 2 → (2, 1), 3 → (1, 0): [[0, 0, 1], [3, 0, 0], [0, 2, 0]]

Python

class Solution:
    def buildMatrix(self, k: int, rowConditions: List[List[int]], colConditions: List[List[int]]) -> List[List[int]]:
        def topo_order(conditions: List[List[int]]) -> List[int]:
            """Kahn's algorithm over the numbers 1..k; [] when the conditions contain a cycle."""
            after = defaultdict(list)          # a -> numbers that must come after a
            indegree = [0] * (k + 1)
            for a, b in conditions:
                after[a].append(b)
                indegree[b] += 1
            ready = deque(v for v in range(1, k + 1) if indegree[v] == 0)   # nothing has to precede these
            order = []
            while ready:
                v = ready.popleft()
                order.append(v)
                for nxt in after[v]:
                    indegree[nxt] -= 1         # one fewer number that must come before nxt
                    if indegree[nxt] == 0:
                        ready.append(nxt)
            return order if len(order) == k else []    # numbers left over are stuck in a cycle

        row_order = topo_order(rowConditions)
        col_order = topo_order(colConditions)
        if not row_order or not col_order:
            return []

        row_of = {v: r for r, v in enumerate(row_order)}   # position of each number in its order
        col_of = {v: c for c, v in enumerate(col_order)}
        matrix = [[0] * k for _ in range(k)]
        for v in range(1, k + 1):
            matrix[row_of[v]][col_of[v]] = v
        return matrix
Time O(k + m)Space O(k + m)

Each of the two sorts touches every number and every condition once; m = total conditions.

When to use: The standard answer: linear, iterative, and the cycle check falls out of the count.

Watch it run

The other classic topological sort: depth-first search where a number is appended to the order after all the numbers that must follow it have been visited; reversing the finish order gives a topological order. Each number carries a state: unvisited, on the current path, or finished. Reaching a number that is on the current path means the path loops back on itself: a cycle.

Same linear complexity as Kahn's algorithm. It is a little shorter but recursive (k ≤ 400 keeps it within Python's default recursion limit), and the cycle check is a state comparison rather than a count.

Dry run

  1. Example 1, rows: visit 1 → visit 2 (no outgoing edges, finished) → 1 finished → visit 3 → 2 already finished
  2. Finish order 2, 1, 3; reversed: 3, 1, 2 (a different valid row order from Kahn's)
  3. Columns: visit 1 (finished), visit 2 → 1 done → 2 finished, visit 3 → finished. Reversed: 3, 2, 1

Python

class Solution:
    def buildMatrix(self, k: int, rowConditions: List[List[int]], colConditions: List[List[int]]) -> List[List[int]]:
        def topo_order(conditions: List[List[int]]) -> List[int]:
            after = defaultdict(list)
            for a, b in conditions:
                after[a].append(b)
            state = [0] * (k + 1)              # 0 = unvisited, 1 = on the current path, 2 = finished
            finished = []                      # numbers in the order they finish (reverse topological order)

            def visit(v: int) -> bool:         # False as soon as a cycle is found
                if state[v] == 1:
                    return False               # back on the current path: a cycle
                if state[v] == 2:
                    return True
                state[v] = 1
                for nxt in after[v]:
                    if not visit(nxt):
                        return False
                state[v] = 2
                finished.append(v)             # everything that must follow v is already in the list
                return True

            for v in range(1, k + 1):
                if not visit(v):
                    return []
            finished.reverse()
            return finished

        row_order = topo_order(rowConditions)
        col_order = topo_order(colConditions)
        if not row_order or not col_order:
            return []

        row_of = {v: r for r, v in enumerate(row_order)}   # position of each number in its order
        col_of = {v: c for c, v in enumerate(col_order)}
        matrix = [[0] * k for _ in range(k)]
        for v in range(1, k + 1):
            matrix[row_of[v]][col_of[v]] = v
        return matrix
Time O(k + m)Space O(k + m)

Every number and edge is visited once; the recursion stack is at most k deep.

When to use: When you prefer the recursive formulation, or already have a DFS topological sort at hand.

Common mistakes

  • Trying to solve the two orderings together, or placing numbers greedily in the grid. The conditions never mix rows and columns; two independent topological sorts are the whole algorithm.
  • Returning the first k - 1 placements when the queue empties early. Kahn's algorithm placing fewer than k numbers means a cycle: return [], not a half-filled matrix.
  • Numbers that appear in no condition still need a row and a column. Build the graph over all of 1 … k, not only over the numbers mentioned, so they start with in-degree 0 and get placed.
  • Duplicate conditions such as [2, 3] twice: count the in-degree twice and store the edge twice so that both decrements happen, or deduplicate the edges first. Mixing the two leaves a number stuck at in-degree 1.
  • Using the number as a row index directly (matrix[v]). Rows come from the position of v in the order, which is why a dictionary or array row_of[v] is needed.

Python notes

  • deque(v for v in range(1, k + 1) if indegree[v] == 0) seeds the queue with every ready number in one line; include numbers that appear in no condition.
  • defaultdict(list) for the adjacency list means a number with no outgoing edges simply yields an empty loop.
  • {v: i for i, v in enumerate(order)} turns an order into a position lookup; order.index(v) inside a loop would make the fill step O(k²).
  • Build each row with [0] * k inside a list comprehension; [[0] * k] * k would alias one row k times.

What an interviewer might ask next, and what changes.

  • Course Schedule II LC 210 — the same Kahn's algorithm with the same cycle check; this problem runs it twice and turns the orders into coordinates.
  • Alien Dictionary LC 269 — the edges must first be extracted from adjacent words; the topological sort afterwards is identical.
  • Sort Items by Groups Respecting Dependencies LC 1203 — two topological sorts again, but nested: one over groups, one over the items inside each group.
  • Parallel Courses III LC 2050 — Kahn's order plus a DP along it: the finishing time of a course is its duration added to the latest prerequisite.
  • What if the matrix should be the lexicographically smallest valid one? — replace the queue with a min-heap so the smallest ready number is placed first in each order.
  • How many valid matrices are there? — count the topological orders of each graph (exponential in general, #P-hard) and multiply the two counts; the brute force enumerates them for tiny k.
