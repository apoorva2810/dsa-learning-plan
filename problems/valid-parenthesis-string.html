Valid Parenthesis String Medium

LeetCode #678 ↗
Status

Check whether a string of brackets and wildcards can be read as a correctly matched bracket string.

Problem

You are given a string s made only of the characters (, ) and *.

A bracket string is valid when every ( has a matching ) somewhere after it, every ) has a matching ( before it, and the pairs nest correctly. The empty string is valid.

The character * is a wildcard: you may treat each one as (, as ), or as an empty string. Return True if you can pick a meaning for every * that makes the whole string valid, and False otherwise.

Examples

Example 1
Input: s = "(*)"
Output: true
Treat * as an empty string and you get ().
Example 2
Input: s = "(*))"
Output: true
Treat * as ( and you get (()).
Example 3
Input: s = "(((*)"
Output: false
Three openers need three closers, but there is only one ) and one *. One ( stays open.
Example 4
Input: s = "*("
Output: false
The final ( has nothing after it to close it. A * that comes before it cannot help.

Constraints

  • 1 <= len(s) <= 100
  • each character of s is '(', ')' or '*'

Think first try before reading the solution

With only ( and ), you would keep one counter of open brackets. What can a * do to that counter? It has three possible effects.
Do not try every combination: that is 3 to the power of the number of stars. Instead keep the whole range of open-bracket counts that are still possible: lo (the fewest) and hi (the most). ( adds 1 to both, ) subtracts 1 from both, and * subtracts 1 from lo and adds 1 to hi.
If hi ever drops below 0, even reading every * as ( leaves too many ), so return False. Clamp lo at 0, because a negative count is not a real state. At the end the string is valid exactly when lo == 0.

Key idea

Without wildcards a string is valid when a running count of open brackets never goes below 0 and ends at 0. A * makes the count ambiguous: afterwards it could be one lower ()), the same (empty) or one higher ((). Trying every reading costs 3 to the power of the number of stars.

You do not need to remember each possible count separately. The possible counts always form an unbroken range. ( shifts the whole range up by 1. ) shifts it down by 1 and discards any count that became negative, because a ) with nothing to close is not allowed in any reading. * widens it by one on each side. So two numbers describe everything: lo, the fewest open brackets any reading can have, and hi, the most.

  • If hi < 0, even the most generous reading has too many ): the string is invalid.
  • lo is clamped at 0, because a count below 0 is not a real state.
  • At the end, a count of 0 must be possible. The range is unbroken and hi >= 0, so that happens exactly when lo == 0.

This is greedy in a particular sense: instead of deciding what each * is when you meet it, you defer the decision and keep the best case and the worst case alive. No guess is ever made, so none has to be undone.

Approaches from the obvious one to the one you want in an interview

Walk through the string with a count of open brackets. A ( adds 1, a ) subtracts 1 (and the branch dies if the count goes below 0). At a *, branch three ways: treat it as (, as ) or as nothing. A branch succeeds if it reaches the end of the string with the count at 0.

With k stars there are up to 3^k branches, so the cost explodes. Caching the answer for each pair (position, open count) would limit the work to O(n²) states, but the next two approaches need no table at all.

Dry run

  1. s = "(*))": start at index 0 with 0 open brackets
  2. ( → 1 open. * → try it as ( first → 2 open
  3. ) → 1 open. ) → 0 open. End of string with 0 open → True
  4. for s = "(((*)" every branch ends with at least one bracket open, after trying all 3 meanings of the star

Python

class Solution:
    def checkValidString(self, s: str) -> bool:
        def ok(i: int, open_count: int) -> bool:   # can s[i:] be completed, given `open_count` unmatched '(' ?
            if open_count < 0:                      # a ')' had nothing to close
                return False
            if i == len(s):
                return open_count == 0
            c = s[i]
            if c == "(":
                return ok(i + 1, open_count + 1)
            if c == ")":
                return ok(i + 1, open_count - 1)
            # '*' can be '(' , ')' or nothing: try all three
            return ok(i + 1, open_count + 1) or ok(i + 1, open_count - 1) or ok(i + 1, open_count)

        return ok(0, 0)
Time O(3^k)Space O(n)

k is the number of stars. The recursion is at most n frames deep.

When to use: Only to define the problem and to test a faster solution on strings with few stars.

Remember where the unmatched openers and the stars are, and decide their roles as late as possible. Keep two stacks of indices: opens for each unmatched (, and stars for each *.

  • On ): cancel a real ( if there is one; otherwise spend a * as an opener; otherwise return False.
  • After the scan, every leftover ( must be closed by a * that comes later in the string. Pair them from the right (the last ( with the last *), and return False if any ( is to the right of the star it is paired with. Leftover stars can be empty.

Each character is pushed and popped at most once, so it is O(n) time, but the stacks take O(n) space.

Dry run

  1. s = "(*))": index 0 ( → opens = [0]; index 1 * → stars = [1]
  2. index 2 ): a real ( is available → pop it → opens = []
  3. index 3 ): no ( left, a star is → spend it as ( → stars = []
  4. nothing is left over → True
  5. for s = "*(": stars = [0], opens = [1]; the ( at 1 is to the right of the star at 0 → False

Python

class Solution:
    def checkValidString(self, s: str) -> bool:
        opens, stars = [], []                      # indices of unmatched '(' and of '*'
        for i, c in enumerate(s):
            if c == "(":
                opens.append(i)
            elif c == "*":
                stars.append(i)
            else:                                  # ')' needs something to its left
                if opens:
                    opens.pop()                    # best: cancel a real '('
                elif stars:
                    stars.pop()                    # otherwise use a '*' as '('
                else:
                    return False
        # each leftover '(' needs a '*' that comes AFTER it, to be used as ')'
        while opens and stars:
            if opens.pop() > stars.pop():          # the '(' is to the right of the star
                return False
        return not opens                           # leftover '(' with no star left means invalid
Time O(n)Space O(n)

One scan plus one pass over the leftovers; the stacks hold up to n indices.

When to use: When the "match concretely" view is easier for you to prove than the range.

Keep two numbers instead of two stacks: lo, the fewest open brackets any reading could have, and hi, the most.

  • (: lo += 1, hi += 1.
  • ): lo -= 1, hi -= 1.
  • *: lo -= 1, hi += 1 (as ), as nothing, as ().

After each character: if hi < 0, return False; then clamp lo = max(lo, 0). At the end return lo == 0.

Every count between lo and hi stays possible, so this tracks all 3^k readings at once, in O(1) space.

Dry run

  1. s = "(*))", lo = hi = 0
  2. ( → lo = 1, hi = 1
  3. * → lo = 0, hi = 2
  4. ) → lo = -1 (clamped to 0), hi = 1
  5. ) → lo = -1 (clamped to 0), hi = 0. End: lo == 0 → True

Python

class Solution:
    def checkValidString(self, s: str) -> bool:
        lo = hi = 0                                # fewest / most '(' that could still be open
        for c in s:
            if c == "(":
                lo += 1
                hi += 1
            elif c == ")":
                lo -= 1
                hi -= 1
            else:                                  # '*': as ')' lowers, as '(' raises, as nothing keeps
                lo -= 1
                hi += 1
            if hi < 0:                             # even if every '*' so far were '(', too many ')'
                return False
            lo = max(lo, 0)                        # an open count below 0 is not a real state
        return lo == 0                             # can we end with nothing open?
Time O(n)Space O(1)

One pass, two integers.

When to use: The interview answer. State the invariant: "every count between lo and hi is achievable".

Common mistakes

  • Not clamping lo at 0. In *(, the star cannot act as ) because nothing is open. Without the clamp lo goes to -1, then back to 0 after the (, and the string wrongly looks valid. With the clamp lo ends at 1, which is correct.
  • Skipping the early exit on hi < 0. In ()) there are no stars at all. The clamp drags lo back to 0, so without the hi check the string ends with lo == 0 and looks valid.
  • Testing hi == 0 at the end instead of lo == 0. For (*) the range ends as [0, 1]: hi is 1, yet the string is valid because 0 is a possible count.
  • Giving every * one fixed meaning, or deciding it when you read it. *) needs the star to be ( while (* needs it to be ); the right meaning depends on what comes later.
  • In the two-stack version, pairing a leftover ( with a * that sits to its left. The star has to come after the bracket: *( has one of each left over and is still invalid.

Python notes

  • Tuple assignment lo, hi = lo - 1, hi + 1 updates both bounds from their old values at once.
  • lo = max(lo, 0) is the whole clamp. Keep it after the hi < 0 check so a failed string is rejected first.
  • a or b or c stops at the first True, so the brute-force recursion does not explore the other branches once one works.
  • A list works as a stack: append to push, pop() to remove the last item. while opens and stars: checks both are non-empty.
  • The recursion is at most len(s) frames deep (100 here), well inside Python's default limit; the branching is what is expensive.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Valid Parentheses LC 20 — no wildcards but three kinds of brackets: a stack of the open brackets, because now it matters which kind is open.
  • Check if a Parentheses String Can Be Valid LC 2116 — each position is either locked or free to be either bracket: one pass left to right and one pass right to left, each treating free positions in the way that helps that direction.
  • Minimum Add to Make Parentheses Valid LC 921 — count the closers that find nothing open and the openers left at the end; no wildcards, so no range.
  • Longest Valid Parentheses LC 32 — find the longest valid stretch: push indices on a stack, or sweep with open and close counters in both directions.
  • Generate Parentheses LC 22 — build all valid strings of length 2n, using the same "open count never below 0" rule as a pruning check.
  • Wildcards with several kinds of brackets — the counting trick fails, because you also need to know which bracket is open. This needs interval DP or memoised search over (position, stack contents).
