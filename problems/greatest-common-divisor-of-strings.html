Greatest Common Divisor of Strings Easy 250

LeetCode #1071 ↗
Status

Find the longest block that, repeated, builds both given strings.

Problem

A string t divides a string s when s is t written one or more times in a row: t + t + ... + t. For example "AB" divides "ABABAB", and so does "ABABAB" itself, but "ABA" does not.

You are given two strings str1 and str2 of uppercase letters. Return the longest string that divides both of them. If no such string exists, return the empty string "".

Examples

Example 1
Input: str1 = "XYXYXYXY", str2 = "XYXY"
Output: "XYXY"
"XY" divides both too, but "XYXY" is longer: it is str1 written twice and str2 written once.
Example 2
Input: str1 = "ABCABCABC", str2 = "ABCABC"
Output: "ABC"
The lengths are 9 and 6. A common block must fit a whole number of times into both, so its length divides 3; "ABC" works.
Example 3
Input: str1 = "ABAB", str2 = "ABBA"
Output: ""
Same letters, same length, but a block that divides a 4-letter string has length 1, 2 or 4, and no prefix of str1 of those lengths builds str2.

Constraints

  • 1 <= len(str1), len(str2) <= 1000
  • str1 and str2 consist of uppercase English letters

Think first try before reading the solution

If a block t divides s, what must be true of the lengths? Try t = "AB" against "ABABAB" and against "ABABA".
Any common divisor is a prefix of both strings, and its length divides both lengths. So only prefixes whose length divides both lengths can work, and the longest possible one has length gcd(len(str1), len(str2)).
If both strings are repeats of one block, then str1 + str2 and str2 + str1 are the same string: both are that block written (m + n) / len(block) times. The converse holds too, so one comparison tells you whether a divisor exists; then return str1[:gcd(m, n)].

Key idea

A divisor of s is a block that tiles s with no gap and no overhang, so its length divides len(s), and it is the prefix of s of that length. A common divisor of both strings is therefore a prefix of both whose length divides both lengths. The longest such length is the greatest common divisor g = gcd(m, n) of the two lengths, and if any common divisor exists at all, then str1[:g] is one: a shorter divisor of length d has d | g, so the prefix of length g is that divisor repeated g / d times, which still tiles both strings. That is why the answer is always str1[:g] or nothing.

Whether a common divisor exists has a neat test: str1 + str2 == str2 + str1. If both are repeats of a block t, both concatenations are t repeated (m + n) / len(t) times, so they are equal. The other direction is a classic fact about strings: two strings that commute (can be swapped around a + without changing the result) are always repeats of one common block. So one comparison replaces all the divisibility checking, and the whole solution is two lines.

Everything is linear in m + n: the comparison builds two strings of length m + n, and gcd on two integers is a handful of divisions.

Approaches from the obvious one to the one you want in an interview

A common divisor is a prefix of str1, so there are only min(m, n) candidates. Try them from the longest down, and return the first that divides both strings. divides(block, s) is "the length fits a whole number of times and block repeated that many times is s".

Each candidate costs O(m + n) to check, and there are up to min(m, n) of them, so the worst case is about O(min(m, n) · (m + n)). For strings of length 1000 that is a few million character comparisons: fine here, but most of the candidates are doomed by their length alone.

Dry run

  1. str1 = "XYXYXYXY", str2 = "XYXY": candidates are the prefixes of length 4, 3, 2, 1
  2. length 4: "XYXY"; 8 % 4 = 0 and 4 % 4 = 0; "XYXY" * 2 == str1 and "XYXY" * 1 == str2 → answer "XYXY"
  3. str1 = "ABAB", str2 = "ABBA": length 4 fails ("ABAB" != "ABBA"), 3 fails on length, 2 gives "ABAB" != "ABBA", 1 gives "AAAA" → ""

Python

class Solution:
    def gcdOfStrings(self, str1: str, str2: str) -> str:
        def divides(block: str, s: str) -> bool:
            return len(s) % len(block) == 0 and block * (len(s) // len(block)) == s

        for length in range(min(len(str1), len(str2)), 0, -1):   # longest candidate first
            block = str1[:length]
            if divides(block, str1) and divides(block, str2):
                return block
        return ""
Time O(min(m, n) · (m + n))Space O(m + n)

Up to min(m, n) candidates, each verified by building a string of length m or n.

When to use: As the first idea; it also shows that a divisor's length must divide the string's length.

Watch it run

A common divisor's length divides both m and n, so it divides g = gcd(m, n), and it is at most g letters long. Better: if any common divisor exists, the prefix of length g is one (a shorter divisor repeated g / d times is exactly that prefix, and it still tiles both strings). So only one candidate needs checking: str1[:g].

Verify it by repetition against both strings. One gcd, one slice, two string builds: O(m + n).

Dry run

  1. m = 8, n = 4: g = gcd(8, 4) = 4, candidate str1[:4] = "XYXY"
  2. "XYXY" * 2 == "XYXYXYXY" and "XYXY" * 1 == "XYXY" → return "XYXY"
  3. "ABAB", "ABBA": g = 4, candidate "ABAB"; "ABAB" * 1 != "ABBA" → ""

Python

class Solution:
    def gcdOfStrings(self, str1: str, str2: str) -> str:
        g = math.gcd(len(str1), len(str2))             # the only length a longest common block can have
        block = str1[:g]
        if block * (len(str1) // g) == str1 and block * (len(str2) // g) == str2:
            return block
        return ""
Time O(m + n)Space O(m + n)

gcd of two integers up to 1000 takes a few divisions; the two repetitions build strings of length m and n.

When to use: When you want the verification to be explicit and readable.

Replace the verification by one comparison: str1 + str2 == str2 + str1. If both strings are repeats of a block t, both sides are t repeated (m + n) / len(t) times, so they are equal. And if the two sides are equal, the strings are known to be repeats of a common block (two strings that can be swapped around + always are). So the test is exactly "a common divisor exists", and the answer is then str1[:gcd(m, n)].

Same O(m + n) as the previous approach, in two lines, and the reasoning about lengths is done once by gcd instead of by hand.

Dry run

  1. str1 = "XYXYXYXY", str2 = "XYXY": str1 + str2 = "XYXYXYXYXYXY" and str2 + str1 = "XYXYXYXYXYXY" are equal
  2. gcd(8, 4) = 4 → str1[:4] = "XYXY"
  3. "ABAB", "ABBA": "ABABABBA" != "ABBAABAB" → ""

Python

class Solution:
    def gcdOfStrings(self, str1: str, str2: str) -> str:
        if str1 + str2 != str2 + str1:                 # they share no block: nothing divides both
            return ""
        return str1[:math.gcd(len(str1), len(str2))]   # the longest block has the gcd of the lengths
Time O(m + n)Space O(m + n)

Two concatenations of length m + n and one comparison; gcd is a few integer divisions.

When to use: The interview answer. Be ready to explain why commuting strings are repeats of one block.

Common mistakes

  • Testing only str1.startswith(str2) or str2 in str1. Being a prefix is not enough: "ABCDEF" starts with "ABC", but "ABC" does not divide it. The block must tile the whole string.
  • Returning the shortest repeating unit instead of the longest common divisor. For "XYXYXYXY" and "XYXY" the answer is "XYXY", not "XY": the question asks for the largest.
  • Taking str1[:gcd(m, n)] without checking anything. "ABAB" and "ABBA" have g = 4, but "ABAB" does not divide "ABBA". Either verify the candidate by repetition or test str1 + str2 == str2 + str1 first.
  • Checking the block against only one of the two strings. It must divide both; the prefix of str1 of length g always divides str1 when it divides str2, but you still have to test str2.
  • An off-by-one in the brute force range. range(min(m, n), 0, -1) visits every length from the shorter string down to 1; range(min(m, n), 1, -1) skips length 1 and misses answers like "A".

Python notes

  • math.gcd(a, b) is pre-imported and runs Euclid's algorithm in C.
  • block * k repeats a string k times, so block * (len(s) // len(block)) == s is the whole divisibility test (check len(s) % len(block) == 0 first).
  • str1 + str2 != str2 + str1 builds two strings of length m + n and compares them in O(m + n); the operands are not modified.
  • str1[:g] is the candidate; slicing copies, which is fine at these sizes.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Rotate String LC 796 — is goal a rotation of s? Same lengths and goal in s + s. Same idea of gluing a string to itself.
  • Repeated String Match LC 686 — how many copies of a are needed so that b appears inside? Repeat a until it is at least as long as b, then check one more copy.
  • Longest Common Prefix LC 14 — a different question with a similar name: the longest prefix shared by all strings, with no tiling requirement.
  • GCD of a whole list of strings — fold the pairwise answer across the list, like gcd of many numbers; stop early as soon as the running answer becomes "".
  • Least common multiple of two strings — the shortest string both divide: it exists only if they commute, and then it is the block repeated lcm(m, n) / len(block) times.
