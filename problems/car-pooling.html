Car Pooling Medium 250

LeetCode #1094 ↗
Status

A car with a fixed number of seats drives one way; given groups with pick-up and drop-off points, decide whether it can carry everyone.

Problem

A car with capacity seats drives east only along a straight road; positions are kilometre marks 0 … 1000. You are given trips, where trips[i] = [passengers, start, end]: a group of passengers people gets in at kilometre start and gets out at kilometre end (start < end).

At a given kilometre, people getting out leave before people getting in. Return True if the car can carry every group without ever holding more than capacity passengers, and False otherwise.

Examples

Example 1
Input: trips = [[2, 1, 5], [3, 3, 7]], capacity = 4
Output: False
From km 3 to km 5 both groups are in the car: 2 + 3 = 5 passengers, more than 4 seats.
Example 2
Input: trips = [[2, 1, 5], [3, 3, 7]], capacity = 5
Output: True
The same overlap, 5 passengers, now fits exactly.
Example 3
Input: trips = [[2, 1, 5], [3, 5, 7]], capacity = 3
Output: True
The first group gets out at km 5 just before the second group gets in there, so the car never holds more than 3.

Constraints

  • 1 <= len(trips) <= 1000
  • 1 <= passengers <= 100
  • 0 <= start < end <= 1000
  • 1 <= capacity <= 10^5

Think first try before reading the solution

The number of people in the car only changes at pick-up and drop-off points. Nothing happens in between, so those are the only moments worth checking.
Go through the pick-ups in order of position. When a group gets in at km s, every group whose drop-off is <= s has already left the car.
Keep the groups currently in the car in a min-heap keyed by drop-off. At each pick-up, pop the root while its drop-off is <= s (subtracting its passengers), add the new group, and compare the load with the capacity.

Key idea

Think of driving the route and only looking up at the moments something changes. The load goes up at pick-ups and down at drop-offs, so the maximum load is reached right after some pick-up. Check the load after every pick-up and the answer follows.

Sort the trips by pick-up point and sweep east. Groups in the car are waiting to get out, and the one that matters first is the one with the earliest drop-off: that is a min-heap keyed by end. At each pick-up at km s, drop off everything at the root with end <= s, then add the new passengers. If the load ever exceeds the capacity, stop with False. This is the same sweep as Meeting Rooms II, where the heap holds the rooms' end times and the load is the number of rooms in use.

Because positions are small integers here, a difference array does the same in O(n + 1000): +passengers at start, -passengers at end, and a running total is the load at every kilometre. The heap version needs no such limit, which is why it is the one to remember.

Approaches from the obvious one to the one you want in an interview

Keep an array on_board[km] for every kilometre mark 0 … 1000. For each trip add its passengers to every kilometre from start up to but not including end (the group is out at end), and stop as soon as some kilometre exceeds the capacity.

Correct and simple, but every trip touches every kilometre it covers: O(n · L) with L = 1000, about a million updates in the worst case here, and hopeless if positions went up to 10⁹.

Dry run

  1. [[2, 1, 5], [3, 3, 7]], capacity 4: trip 1 adds 2 to km 1, 2, 3, 4
  2. trip 2 adds 3 to km 3 → 5 > 4 → False

Python

class Solution:
    def carPooling(self, trips: List[List[int]], capacity: int) -> bool:
        on_board = [0] * 1001                     # passengers in the car at each kilometre mark
        for passengers, start, end in trips:
            for km in range(start, end):          # in the car from start up to, not including, end
                on_board[km] += passengers
                if on_board[km] > capacity:
                    return False
        return True
Time O(n · L)Space O(L)

n trips, each painting up to L = 1000 kilometres.

When to use: Only when the road is short and you want the most literal solution.

Sort the trips by pick-up point and drive east. Groups in the car sit in a min-heap keyed by drop-off, so the group that leaves first is at the root. At each pick-up at km s:

  1. while the root's drop-off is <= s, pop it and subtract its passengers (they are already out);
  2. add the new passengers; if the load exceeds the capacity, return False;
  3. push (end, passengers) for the new group.

Every trip is pushed once and popped at most once, so the heap work is O(n log n), like the sort. The sweep never looks at the road itself, only at the trips, so positions can be anything, not just 0 … 1000.

Dry run

  1. [[2, 1, 5], [3, 3, 7]], capacity 4, already sorted by pick-up
  2. km 1: nothing to drop off; 2 get in → load 2 ≤ 4; push (5, 2)
  3. km 3: root drop-off 5 > 3, nobody leaves; 3 get in → load 5 > 4 → False

Python

class Solution:
    def carPooling(self, trips: List[List[int]], capacity: int) -> bool:
        on_board = []                             # min-heap of (drop-off, passengers) for groups in the car
        load = 0
        for passengers, start, end in sorted(trips, key=lambda t: t[1]):   # by pick-up point
            while on_board and on_board[0][0] <= start:    # these groups are out before this pick-up
                load -= heapq.heappop(on_board)[1]
            load += passengers
            if load > capacity:
                return False
            heapq.heappush(on_board, (end, passengers))
        return True
Time O(n log n)Space O(n)

One sort, then each trip is pushed once and popped at most once.

When to use: The general technique: works for any coordinates and is the same sweep as Meeting Rooms II.

Watch it run

Record only the changes: change[start] += passengers (they get in) and change[end] -= passengers (they get out). A running total over change is then the number of passengers in the car at every kilometre, and the answer is whether that total ever exceeds the capacity.

Each trip costs O(1), plus one pass over the 1001 marks: O(n + L). It is the fastest option when positions are small integers, and it also hands you the load at every single kilometre for free. It cannot be used when positions are large or not integers.

Dry run

  1. [[2, 1, 5], [3, 3, 7]]: change[1] += 2, change[5] -= 2, change[3] += 3, change[7] -= 3
  2. running total: km 0: 0, km 1: 2, km 2: 2, km 3: 5 > 4 → False

Python

class Solution:
    def carPooling(self, trips: List[List[int]], capacity: int) -> bool:
        change = [0] * 1002                       # change[km]: how the load changes at that kilometre mark
        for passengers, start, end in trips:
            change[start] += passengers           # the group gets in here
            change[end] -= passengers             # and out here, so the seats are free from km end on
        load = 0
        for delta in change:                      # running total = passengers in the car at each kilometre
            load += delta
            if load > capacity:
                return False
        return True
Time O(n + L)Space O(L)

O(1) per trip plus one pass over the L = 1001 kilometre marks.

When to use: When positions are small integers; mention that it also yields the load at every position.

Common mistakes

  • Dropping off with < instead of <=: a group leaving at km 5 is out before a group entering at km 5. Example 3 must be True.
  • Comparing the capacity with the sum of all passengers: groups that never overlap do not count together. Only overlapping trips add up.
  • Checking the capacity before dropping off the groups whose trip has ended: you count people who have already left and reject valid inputs.
  • In the difference array, subtracting at end + 1 instead of end: passengers are out at end, so the seat is free from km end on.
  • Sorting by passengers or by drop-off instead of by pick-up: the sweep must meet the pick-ups in road order.
  • Painting every kilometre of every trip is fine for positions up to 1000, but it breaks when positions go up to 10⁹; the heap sweep does not care.

Python notes

  • sorted(trips, key=lambda t: t[1]) orders by pick-up without changing the input list; trips.sort(...) would reorder the caller's data.
  • Heap entries (end, passengers) are tuples, so the earliest drop-off is the root; heapq.heappop(on_board)[1] is the group size leaving.
  • for passengers, start, end in trips unpacks each trip in one line, which keeps the three numbers named.
  • With a difference array, itertools.accumulate(change) yields the running load at every kilometre.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Meeting Rooms II LC 253 — the same sweep with every 'group' of size 1: the maximum load is the number of rooms needed.
  • Corporate Flight Bookings LC 1109 — return the number of seats booked on every flight instead of a yes/no: the difference array's running total is the answer itself.
  • Maximum Population Year LC 1854 — find the position where the load peaks: same difference array, track the maximum and its index.
  • My Calendar III LC 732 — bookings arrive one at a time and you need the maximum overlap after each: a sorted map of +1/-1 events instead of a fixed array.
  • What if positions went up to 10⁹? — the difference array no longer fits in memory; the sorted sweep with the heap (or sorted +/- events) works unchanged in O(n log n).
  • Return the maximum number of passengers on board instead of True/False — keep the sweep, record the largest load seen after a pick-up, and return it at the end.
