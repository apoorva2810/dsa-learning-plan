Target Sum Medium

LeetCode #494 ↗
Status

Count the ways to put a plus or minus sign in front of every number so that the signed numbers add up to a target.

Problem

You are given a list nums of non-negative integers and an integer target.

Put either + or - in front of every number and add the results. Return how many different sign choices make the total equal to target.

  • Two choices are different if at least one number gets a different sign. A 0 can be +0 or -0, so every zero doubles the count.
  • Every number is used exactly once.

Examples

Example 1
Input: nums = [1, 1, 1, 1, 1], target = 3
Output: 5
Exactly one of the five 1s gets a minus sign (1 + 1 + 1 + 1 - 1 = 3), and there are five positions for it.
Example 2
Input: nums = [1], target = 1
Output: 1
Only +1.
Example 3
Input: nums = [1, 0], target = 1
Output: 2
+1+0 and +1-0 both work; the zero counts twice.

Constraints

  • 1 <= len(nums) <= 20
  • 0 <= nums[i] <= 1000
  • 0 <= sum(nums) <= 1000
  • -1000 <= target <= 1000

Key idea

Each number gets one of two signs, so there are 2^n expressions (about a million for n = 20). After the signs of the first i numbers are fixed, only the running total matters for the rest. Two different sign patterns that reach the same total at the same position behave identically from there on, so cache by (i, total). That is the memoised recursion, with at most n × (2 · sum + 1) states.

There is a neater way to see it. Split the numbers into the group that gets + (its sum is P) and the group that gets - (its sum is N). Then P - N = target and P + N = total, where total = sum(nums). Adding the two equations gives 2P = total + target, so

P = (total + target) / 2.

A sign pattern is the same thing as a subset (the numbers with +), and it works exactly when that subset sums to P. So the answer is the number of subsets of nums whose sum is P. Two cases have no answer: total + target odd (P would be a fraction) and abs(target) > total (even all plus or all minus cannot reach it).

Counting subsets with a given sum is a 0/1 knapsack: each item is taken at most once. Let dp[i][s] be the number of subsets of the first i numbers with sum s. The number x = nums[i - 1] is either left out (dp[i - 1][s]) or put in (dp[i - 1][s - x]). Both terms read the row above, which is what "at most once" means in a table; in Coin Change II the second term came from the same row. Because only the previous row is read, a single list is enough, but it must be scanned from high s to low s so that dp[s - x] still belongs to the previous row.

Zeros need no special case: for x = 0 both terms are the same cell, so every count doubles, which is exactly the +0 / -0 rule.

Approaches from the obvious one to the one you want in an interview

Try both signs for each number in turn. Let ways(i, total) be the number of ways to sign nums[i:] so that, starting from the running total total, the final sum is target. At the end of the list there is exactly one way if total == target and none otherwise. Before that, add the two choices:

ways(i, total) = ways(i + 1, total + nums[i]) + ways(i + 1, total - nums[i])

Without a cache this visits all 2^n sign patterns. But different patterns often arrive at the same running total at the same position (+1 -1 and -1 +1 are both 0 after two numbers), and from there they behave identically. @cache on (i, total) collapses them: at most n × (2 · sum + 1) different calls, each O(1).

Dry run

  1. nums = [1, 1, 2], target = 2: ways(0, 0) = ways(1, 1) (the first 1 gets +) + ways(1, -1) (it gets -)
  2. ways(1, 1) = ways(2, 2) + ways(2, 0); ways(1, -1) = ways(2, 0) + ways(2, -2). The state (2, 0) is reached from both branches and computed once.
  3. ways(2, 0) = ways(3, 2) + ways(3, -2) = 1 + 0 = 1 (giving the 2 a + hits the target); ways(2, 2) = 0 and ways(2, -2) = 0
  4. ways(1, 1) = 0 + 1 = 1 and ways(1, -1) = 1 + 0 = 1, so ways(0, 0) = 2

Python

class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        n = len(nums)

        @cache                                          # one stored answer per (i, running total)
        def ways(i: int, total: int) -> int:
            """Sign choices for nums[i:] that turn the running total into target."""
            if i == n:                                  # every number has a sign
                return 1 if total == target else 0
            return (ways(i + 1, total + nums[i])        # give nums[i] a plus sign
                    + ways(i + 1, total - nums[i]))     # give nums[i] a minus sign

        return ways(0, 0)
Time O(n · sum)Space O(n · sum)

At most n × (2 · sum + 1) distinct (i, total) pairs, O(1) work each; the recursion is n deep.

When to use: The first version to write: no algebra needed. The cache can hold tens of thousands of entries when the sum is large.

Let P be the sum of the numbers that get + and N the sum of those that get -. Then P - N = target and P + N = total, so P = (total + target) / 2. Each sign pattern is one subset (the numbers with +), and it works when that subset sums to P. So the answer is the number of subsets of nums with sum P.

First rule out the impossible cases: if abs(target) > total or total + target is odd, return 0.

Then count subsets with a table. dp[i][s] = number of subsets of the first i numbers with sum exactly s, for s = 0..P. Row 0 has only the empty subset: dp[0][0] = 1. For the number x = nums[i - 1]:

dp[i][s] = dp[i - 1][s] + dp[i - 1][s - x]

  • first term: x is not in the plus-group (it gets -);
  • second term (only if s >= x): x is in the plus-group (it gets +).

Both terms read the row above, never the current row: each number is used at most once. The answer is dp[n][P]. Zeros need no special case: for x = 0 both terms are the same cell, so the count doubles.

Dry run

  1. nums = [1, 1, 1, 1, 1], target = 3: total 5, P = (5 + 3) / 2 = 4; row ∅ = [1, 0, 0, 0, 0]
  2. row 1 (x = 1) = [1, 1, 0, 0, 0]; row 2 = [1, 2, 1, 0, 0]; row 3 = [1, 3, 3, 1, 0]
  3. row 4 = [1, 4, 6, 4, 1]; row 5 = [1, 5, 10, 10, 5] (Pascal's triangle: choose which of the 1s are in the group)
  4. the answer is dp[5][4] = 5: the five subsets of four 1s, i.e. the five places for the minus sign

Python

class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        total = sum(nums)
        if abs(target) > total or (total + target) % 2:
            return 0                                    # the plus-group would need a negative or fractional sum
        goal = (total + target) // 2                    # sum of the numbers that get a plus sign
        n = len(nums)
        # dp[i][s] = number of subsets of nums[:i] whose sum is exactly s
        dp = [[0] * (goal + 1) for _ in range(n + 1)]
        dp[0][0] = 1                                    # the empty subset
        for i in range(1, n + 1):
            x = nums[i - 1]
            for s in range(goal + 1):
                dp[i][s] = dp[i - 1][s]                 # x gets a minus sign: not in the subset
                if s >= x:
                    dp[i][s] += dp[i - 1][s - x]        # x gets a plus sign: in the subset
        return dp[n][goal]
Time O(n · P)Space O(n · P)

(n + 1) × (P + 1) cells, O(1) work each, with P at most the total (1000 here).

When to use: When you want to see the 0/1 structure and check it by hand. The one-list version below is the same loop with less memory.

Watch it run

Row i reads only row i - 1, so one list can play every row in turn: dp[s] = number of subsets of the numbers handled so far with sum s, starting from dp[0] = 1. For each number x, update dp[s] += dp[s - x].

The scan must go from goal down to x. At the moment dp[s] is updated, dp[s - x] (a smaller index) has not been touched in this pass yet, so it still holds the previous row and counts subsets that do not contain x. Adding it puts x in at most once. Scanning upward would read cells already updated in this pass and use x again and again: that is the unbounded knapsack of Coin Change II. For [1, 1, 1, 1, 1] with target 3 the downward scan gives 5 and the upward scan gives 70.

For x = 0 the scan covers every index and dp[s] += dp[s] doubles each cell, which is the +0 / -0 rule.

Dry run

  1. nums = [1, 1, 1, 1, 1], target = 3: total 5, goal = 4, dp = [1, 0, 0, 0, 0]
  2. first 1: scan s = 4, 3, 2, 1; only dp[1] += dp[0] adds anything → [1, 1, 0, 0, 0]
  3. second 1: dp[2] += dp[1] → 1, then dp[1] += dp[0] → 2 → [1, 2, 1, 0, 0] (going downward means dp[1] was still 1 when dp[2] read it)
  4. after the fifth 1: [1, 5, 10, 10, 5] → dp[4] = 5

Python

class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        total = sum(nums)
        if abs(target) > total or (total + target) % 2:
            return 0
        goal = (total + target) // 2                    # sum of the numbers that get a plus sign
        dp = [1] + [0] * goal                           # dp[s] = subsets of the numbers so far with sum s
        for x in nums:
            for s in range(goal, x - 1, -1):            # HIGH to LOW: dp[s - x] still belongs to the previous row
                dp[s] += dp[s - x]
        return dp[goal]
Time O(n · P)Space O(P)

n passes over at most P + 1 cells; one list of integers.

When to use: The standard answer. Be ready to explain the downward scan and the (total + target) / 2 rewrite.

Common mistakes

  • Zeros: +0 and -0 are different expressions, so each zero doubles the count ([0, 0, 1], target 1 gives 4). Skipping zeros, or tracking only a set of reachable totals, loses that.
  • Skipping the parity and range checks in the subset-sum rewrite. For nums = [1, 2], target = 2 the total is 3 and (3 + 2) // 2 = 2; the subset {2} then makes the code answer 1, but the real answer is 0 because the plus-group would have to sum to 2.5. Return 0 when total + target is odd or abs(target) > total.
  • Scanning s upward in the 1-D table lets a number be used again and again (that is Coin Change II). For [1, 1, 1, 1, 1] and target 3 the upward scan gives 70 instead of 5. Scan from goal down to x.
  • In the direct approach, indexing a list by the running total: totals range from -total to +total, and a negative index silently wraps to the end of the list. Key a dictionary (or the cache) by the total instead.
  • Using a set of reachable totals, as in Partition Equal Subset Sum. A set says whether a total is possible, not in how many ways. Keep counts.

Python notes

  • @cache works with negative totals: the key (i, total) is a tuple, so -3 is a key like any other.
  • total + target odd or abs(target) > total means the answer is 0. goal = (total + target) // 2 is exact once those checks have passed.
  • dp = [1] + [0] * goal builds the 1-D table: one way (the empty subset) to reach sum 0.
  • range(goal, x - 1, -1) walks from goal down to x inclusive. For x = 0 it covers every index and dp[s] += dp[s] doubles each cell, which is the zero rule.
  • A compact alternative keeps a Counter of signed totals: for x in nums: build new with new[t + x] += w and new[t - x] += w for every (t, w) in the old counter.
  • Python integers do not overflow, so the problem's guarantee that the answer fits in 32 bits is only a promise to languages with fixed-size integers.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Partition Equal Subset Sum LC 416 — yes/no instead of counting: the goal is total / 2, booleans replace counts, and the same downward scan applies.
  • Last Stone Weight II LC 1049 — minimise the difference between two groups: compute the reachable subset sums and pick the one closest to total / 2; the answer is total - 2 * best.
  • Coin Change II LC 518 — unlimited copies of each item: the scan runs upward and the second term comes from the same row, with the coin loop outside.
  • Ones and Zeroes LC 474 — each string costs some zeros and some ones out of two capacities: a 2-D 0/1 table scanned downward in both dimensions.
  • Expression Add Operators LC 282 — insert +, - or * between digits and list the expressions that hit a target: * breaks the running-total state, so this is backtracking rather than DP.
  • Huge values, up to about 40 numbers — a table of size total is too big: split the list in half, enumerate each half's 2^20 signed totals and match them with a hash map (meet in the middle).
