Diameter of Binary Tree Easy

LeetCode #543 ↗
Status

Find the number of edges on the longest path between any two nodes of a binary tree.

Problem

Given the root of a binary tree, return the length of its diameter: the number of edges on the longest path between any two nodes.

The path does not have to pass through the root. It moves along parent-child links and never visits a node twice. Only the shape of the tree matters; the values stored in the nodes play no role.

Examples

Example 1
Input: root = [1, 2, 3, 4, 5]
Output: 3
The path 4 → 2 → 1 → 3 (or 5 → 2 → 1 → 3) uses three edges.
Example 2
Input: root = [1, 2]
Output: 1
Example 3
Input: root = [1]
Output: 0
A single node has no edge to walk along.

Constraints

  • 1 <= number of nodes <= 10^4
  • -100 <= Node.val <= 100

Think first try before reading the solution

Pick any node and imagine the longest path turns around at it, so it is the highest node of the path. How far can that path go down on the left, and how far down on the right?
The best path that turns at a node is the deepest chain going down its left side plus the deepest chain going down its right side. Those chain lengths are the depths of the two child subtrees. So the diameter is the largest depth(left) + depth(right) over all nodes.
Calling a separate depth function at every node repeats work (O(n²) on a long chain). Compute the depths with one recursion instead: at each node record left + right in a running maximum, but return only 1 + max(left, right) to the parent.

Key idea

A path between two nodes climbs from one node up to the place where it turns around, then comes down to the other node. So every path has a highest node, its turning point. Fix that node, and the longest path turning there goes as deep as possible on the left and as deep as possible on the right.

Let depth(node) be the number of nodes on the longest chain going down from node, with depth(None) = 0. Then the longest path turning at node has depth(left) + depth(right) edges: each side adds one edge for the link to node plus the edges inside its chain. The diameter is the best of that number over every node, and the winning node does not have to be the root.

One post-order recursion (children first, then the node) does both jobs with the same two numbers. It returns 1 + max(left, right), the only thing the parent can extend, because a path cannot fork. And at every node it also compares left + right with the best answer so far.

Approaches from the obvious one to the one you want in an interview

Use the observation directly. For each node, the best path turning there has depth(left) + depth(right) edges, and the diameter is the best of that number over all nodes (and over the same question asked in both subtrees). So write a depth function and call it on both children of every node.

It is correct, but depth walks a whole subtree each time, and the same nodes are walked again at every ancestor above them. On a chain of n nodes that is (n − 1) + (n − 2) + ... = O(n²) steps. On a balanced tree each node is re-walked once per ancestor, about O(n log n).

Dry run

  1. root = [1, 2, 3, 4, 5]
  2. node 1: depth(2) = 2 and depth(3) = 1 → 2 + 1 = 3 edges
  3. node 2: depth(4) = 1 and depth(5) = 1 → 2 edges (nodes 4 and 5 are walked again here)
  4. nodes 3, 4 and 5 have no children → 0 edges each
  5. the largest is 3 → answer 3

Python

class Solution:
    def diameterOfBinaryTree(self, root: Optional[TreeNode]) -> int:
        def depth(node):
            """Number of nodes on the longest chain going down from node."""
            if node is None:
                return 0
            return 1 + max(depth(node.left), depth(node.right))

        def diameter(node):
            if node is None:
                return 0
            through_node = depth(node.left) + depth(node.right)   # walks both subtrees again
            return max(through_node, diameter(node.left), diameter(node.right))

        return diameter(root)
Time O(n²) worst caseSpace O(h)

On a chain, the depth calls walk n−1, n−2, ... nodes. A balanced tree costs about O(n log n).

When to use: Only to see the depth(left) + depth(right) formula in its plainest form.

The brute force recomputes depths that were already known one level lower. Let the recursion return the depth and use it on the way back up:

  1. depth(None) is 0.
  2. At a node, get left = depth(node.left) and right = depth(node.right).
  3. The longest path turning here has left + right edges, so update best = max(best, left + right).
  4. Return 1 + max(left, right), the depth the parent needs.

Every node is visited once, and the two jobs (reporting upward and recording the answer) share the same two numbers. Nothing is recomputed.

Dry run

  1. root = [1, 2, 3, 4, 5], best = 0
  2. depth(4) and depth(5) are leaves: left = right = 0, so the candidate is 0 and each returns 1.
  3. node 2: left = 1, right = 1 → candidate 2 → best = 2; returns 1 + 1 = 2.
  4. depth(3) is a leaf and returns 1.
  5. node 1: left = 2, right = 1 → candidate 3 → best = 3; returns 3.
  6. The answer is best = 3.

Python

class Solution:
    def diameterOfBinaryTree(self, root: Optional[TreeNode]) -> int:
        best = 0                                  # longest path (in edges) seen so far

        def depth(node):
            """Number of nodes on the longest chain going down from node."""
            nonlocal best
            if node is None:
                return 0
            left = depth(node.left)
            right = depth(node.right)
            best = max(best, left + right)        # the path that turns at this node
            return 1 + max(left, right)           # what the parent is allowed to extend

        depth(root)
        return best
Time O(n)Space O(h)

Every node is visited once. The call stack is as deep as the tree is tall: log n when balanced, n for a chain.

When to use: The default and the interview answer. The same shape solves Balanced Binary Tree and Binary Tree Maximum Path Sum.

Watch it run

Recursion can be replaced by an order in which every node comes after its children. A walk that visits parents before children (preorder), read backwards, gives exactly that. Collect the nodes with a stack, then go through them in reverse and store each node's depth in a dictionary. A missing child counts as depth 0, which depth.get(child, 0) gives for free because None is never a key.

The result is the same O(n) time with no recursion limit, at the price of keeping a depth for every node (O(n) space).

Dry run

  1. root = [1, 2, 3, 4, 5]: the stack walk visits 1, 3, 2, 5, 4 (parents before children).
  2. Reversed: 4, 5, 2, 3, 1, so every node comes after its children.
  3. 4, 5: depth 1 each. Node 2: left 1, right 1 → candidate 2, depth 2. Node 3: depth 1.
  4. Node 1: left = depth[2] = 2, right = depth[3] = 1 → candidate 3, depth 3 → best = 3.

Python

class Solution:
    def diameterOfBinaryTree(self, root: Optional[TreeNode]) -> int:
        if root is None:
            return 0
        order, stack = [], [root]
        while stack:                              # preorder: every node appears after its parent
            node = stack.pop()
            order.append(node)
            if node.left:
                stack.append(node.left)
            if node.right:
                stack.append(node.right)

        depth = {}                                # node -> nodes on the longest chain going down from it
        best = 0
        for node in reversed(order):              # so every node is handled after its children
            left = depth.get(node.left, 0)        # None is never a key, so a missing child gives 0
            right = depth.get(node.right, 0)
            best = max(best, left + right)
            depth[node] = 1 + max(left, right)
        return best
Time O(n)Space O(n)

Each node is pushed, popped and processed once. The order list and the dictionary hold up to n nodes.

When to use: When the tree can be deeper than the recursion limit, or you are asked to avoid recursion.

Common mistakes

  • Counting nodes instead of edges. The path 4 → 2 → 1 → 3 has four nodes but three edges, and a single node has diameter 0. The formula is left + right, with no + 1.
  • Assuming the longest path goes through the root. In [1, 2, None, 3, 4, 5, 6, None, 8, 7] the best path 7 → 5 → 3 → 2 → 4 → 8 (five edges) turns at node 2, while a path through the root gives only 4.
  • Returning left + right to the parent. The parent can extend only one branch of its child, so the value passed up must be 1 + max(left, right). Record left + right in the running best instead.
  • Forgetting nonlocal best in the nested helper. best = max(best, ...) then makes best a local variable and Python raises UnboundLocalError at the first read.
  • Setting the running best once on the class and never resetting it. A value left over from the previous tree leaks into the next answer, because the same Solution object may be reused for several test cases. Initialise it inside the method.

Python notes

  • A nested function can read variables of the enclosing function, but to assign to one it needs nonlocal best. Without it, best = ... quietly creates a new local variable.
  • best = max(best, left + right) keeps a running maximum in one readable line.
  • Instead of nonlocal, the helper can return a pair (depth, best_in_subtree). That avoids shared state, at the cost of unpacking a tuple at every node.
  • A chain of 10⁴ nodes recurses deeper than Python's default limit of 1000 frames. LeetCode raises the limit; elsewhere use the iterative version below or sys.setrecursionlimit.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Binary Tree Maximum Path Sum LC 124 — the same 'turn at each node' idea with node values instead of edge counts; branches with a negative sum are dropped with max(gain, 0).
  • Longest Univalue Path LC 687 — a diameter that may only pass through nodes holding equal values: extend a child's chain only when the child's value equals the node's.
  • Balanced Binary Tree LC 110 — the same bottom-up depth recursion, but instead of a running maximum it checks that the two child depths differ by at most 1.
  • Return the path itself, not just its length — remember which node produced the best left + right, then walk down the deeper child on each side (or keep parent pointers).
  • Diameter of a general tree given as an edge list — breadth-first search from any node finds the farthest node a; a second search from a finds the farthest distance, which is the diameter. This works for any tree, not just binary ones.
