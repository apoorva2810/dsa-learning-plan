Matchsticks to Square Medium 250

LeetCode #473 ↗
Status

Decide whether a set of sticks can be laid end to end into the four equal sides of a square, using every stick once.

Problem

You are given a list matchsticks where matchsticks[i] is the length of the i-th stick. Use every stick exactly once, without breaking any of them, to form the four sides of a square. Return True if that is possible and False otherwise.

  • Several sticks may be placed end to end to make one side.
  • All four sides must have the same total length, and every side needs at least one stick.

Examples

Example 1
Input: matchsticks = [7, 3, 2, 2, 7, 3, 2, 2]
Output: true
The total is 28, so every side is 7 long: (7), (7), (3 + 2 + 2) and (3 + 2 + 2).
Example 2
Input: matchsticks = [2, 2, 2, 3, 3]
Output: false
The total 12 would allow sides of 3, but a stick of length 2 can only be completed by a stick of length 1, and there is none.
Example 3
Input: matchsticks = [1, 2, 3, 4]
Output: false
The total is 10, which cannot be split into four equal sides.

Constraints

  • 1 <= len(matchsticks) <= 15
  • 1 <= matchsticks[i] <= 10^8

Think first try before reading the solution

A square has four equal sides, so each side must be total / 4 long. What can you answer at once if the total does not divide by 4, or if the longest stick is already longer than a side?
Think of four sides that each have room for side units of length. Lay the sticks one at a time on any side where they still fit. If a stick fits nowhere, take the previous stick off and try another side for it. Which sticks should go first, so that dead ends show up early?
Sort the sticks longest first. Then add two cuts: for one stick, try each distinct side length only once (two sides with the same length are interchangeable), and if the stick fails on an empty side, stop: every later side is empty too.

Key idea

A square has four equal sides, so the length of a side is fixed before any search: side = total / 4. If total % 4 != 0, or one stick is longer than side, the answer is False immediately.

Now picture four sides, each with a running length that may not go above side. Lay the sticks one by one on any side where they still fit. If a stick fits on no side, an earlier stick was put in the wrong place: take it off and try the next side for it. That is backtracking (choose a side, explore the remaining sticks, undo the choice when it fails). Each stick has up to 4 choices, so the tree can have 4ⁿ leaves. For 15 sticks that is about a billion, too many to walk without cuts.

Three observations remove almost all of it. Longest first: a long stick fits on few sides, so a doomed arrangement fails near the top of the tree, where cutting a branch saves the most work. Equal lengths are interchangeable: laying a stick on a side that holds 3 leads to exactly the same future as laying it on another side that holds 3, so each distinct length is tried only once per stick. And if a stick fails on an empty side, stop trying sides: a stick always takes the first side that accepts it, so every side after an empty one is empty too and would fail the same way.

The tempting shortcut is a greedy rule: put each stick on the first side where it fits and never undo it. It is wrong. On [7, 3, 2, 2, 7, 3, 2, 2] it puts the two 3s together on one side, which leaves the four 2s unable to fill the last side of 7. Only taking a 3 off again finds the arrangement (3 + 2 + 2) twice.

Approaches from the obvious one to the one you want in an interview

Check total % 4 == 0 and set side = total / 4. Then try every way of laying the sticks on four sides: place(i) puts matchsticks[i] on each side whose length stays at or below side, and recurses on the next stick. When i == len(matchsticks) every stick has a place; no side went above side and the lengths add up to 4 * side, so every side is exactly side. If a choice leads to a dead end, take the stick off again and try the next side.

This is already backtracking, but a naive version. It takes the sticks in the order given and treats the four sides as different even when they hold the same length. The tree has up to 4ⁿ leaves, and for a False input it visits most of them: the 10 sticks [3, 3, 3, 3, 3, 3, 3, 3, 2, 2] need 7,365 calls just to answer False.

Dry run

  1. matchsticks = [7, 3, 2, 2, 7, 3, 2, 2]: total 28, side = 7, sides = [0, 0, 0, 0].
  2. 7 → side 0 [7, 0, 0, 0]. 3: side 0 would be 10, so side 1 [7, 3, 0, 0]. 2 → side 1 [7, 5, 0, 0]. 2 → side 1 [7, 7, 0, 0].
  3. 7: sides 0 and 1 are full, side 2 [7, 7, 7, 0]. 3 → side 3, then 2 and 2 → side 3: [7, 7, 7, 7]. i == 8: True after 9 calls.
  4. That order was lucky. On [2, 2, 2, 3, 3] (side = 3) the same code tries every side for every stick before giving up: 65 calls for False.

Python

class Solution:
    def makesquare(self, matchsticks: List[int]) -> bool:
        total = sum(matchsticks)
        if total % 4:                              # four equal sides need a total divisible by 4
            return False
        side = total // 4
        sides = [0] * 4                            # sides[b] = total length laid on side b so far

        def place(i):
            if i == len(matchsticks):              # every stick lies on a side, none went over: all four equal `side`
                return True
            for b in range(4):
                if sides[b] + matchsticks[i] <= side:     # only the room test, no other cut
                    sides[b] += matchsticks[i]            # choose
                    if place(i + 1):                      # explore
                        return True
                    sides[b] -= matchsticks[i]            # un-choose
            return False

        return place(0)
Time O(4ⁿ)Space O(n)

Each of the n sticks chooses one of 4 sides, and a False input visits most of the tree. The recursion is n deep and the sides list has 4 entries.

When to use: Only as the starting point: it shows the model of four sides. Too slow without cuts for 15 sticks.

The same search with three additions that remove most of the waste:

  1. Quick exits. total % 4 != 0 or max(matchsticks) > side means False before any search.
  2. Longest first. Sort descending. A long stick fits on few sides, so a doomed arrangement dies in the first few levels instead of after twelve short sticks have been placed.
  3. Interchangeable sides. Inside place(i) keep the set tried of side lengths already attempted for sticks[i]: a second side with the same length leads to the same future, so skip it. And if sticks[i] fails on an empty side, return False right away: a stick always takes the first side that accepts it, so every side after an empty one is empty too.

Choose (sides[b] += stick), explore (place(i + 1)), un-choose (sides[b] -= stick). When i == n every stick is placed, no side is above side, and the lengths total 4 * side, so each side is exactly side.

  2. 7 → side 0 [7, 0, 0, 0]. 7: side 0 is full, side 1 [7, 7, 0, 0]. 3: sides 0 and 1 have no room, side 2 [7, 7, 3, 0].
  3. 3 → side 2 again [7, 7, 6, 0]. 2: side 2 would be 8, side 3 [7, 7, 6, 2], then [7, 7, 6, 4] and [7, 7, 6, 6].

  5. Back at the second 3: take it off side 2 (back to 3). Side 3 has length 0, not tried yet → [7, 7, 3, 3].
  6. 2 → side 2 [7, 7, 5, 3], 2 → side 2 [7, 7, 7, 3], 2 → side 3 [7, 7, 7, 5], 2 → side 3 [7, 7, 7, 7]. i == 8: True after 13 calls.

Python

class Solution:
    def makesquare(self, matchsticks: List[int]) -> bool:
        total = sum(matchsticks)
        if total % 4:                              # four equal sides need a total divisible by 4
            return False
        side = total // 4
        sticks = sorted(matchsticks, reverse=True) # longest first: fewest sides with room, early dead ends
        if sticks[0] > side:                       # one stick alone is longer than a side
            return False
        sides = [0] * 4                            # sides[b] = total length laid on side b so far

        def place(i):
            if i == len(sticks):                   # every stick is placed and no side is above `side`: all four equal it
                return True
            tried = set()                          # side lengths already attempted for sticks[i]
            for b in range(4):
                if sides[b] + sticks[i] > side or sides[b] in tried:
                    continue                       # no room, or a side with this length was tried already
                tried.add(sides[b])
                sides[b] += sticks[i]              # choose
                if place(i + 1):                   # explore the next stick
                    return True
                sides[b] -= sticks[i]              # un-choose
                if sides[b] == 0:                  # failed on an empty side: every later side is empty too
                    return False
            return False

        return place(0)
Time O(4ⁿ)Space O(n)

The worst-case bound does not change, but the cuts shrink real runs a lot: the ten sticks that take 7,365 calls above need 64. Memory is the sides list, the per-call set and a recursion n deep.

When to use: The standard interview answer. State the three cuts and why each one is safe.

Watch it run

A bound that does not depend on how well the cuts work. A bitmask is an integer whose bit j says whether stick j has been used, so one number from 0 to 2ⁿ - 1 describes a set of used sticks. Build the sides one after another: fill[mask] is the total length of the sticks in mask modulo side, which is how full the side currently being built is, or -1 if that set of sticks can never be arranged into complete sides plus one partial side.

From a reachable mask, add any unused stick j that fits (fill[mask] + matchsticks[j] <= side). When the side reaches side, the remainder becomes 0 and the next side starts. The full mask is reachable exactly when a square exists, because any square can be listed side by side, and every prefix of that list is a reachable mask.

Dry run

  1. matchsticks = [1, 1, 1, 1, 2, 2]: total 8, side = 2. fill[empty set] = 0.
  2. From the empty set, adding a 2 gives (0 + 2) % 2 = 0: a complete side. Adding a 1 gives fill = 1.
  3. From fill = 1, another 1 gives (1 + 1) % 2 = 0: a side made of two 1s. Adding a 2 would give 3 > 2, so that move is not allowed.
  4. Continuing, the set of all six sticks is reachable with fill = 0: the square (2), (2), (1 + 1), (1 + 1) exists. True.

Python

class Solution:
    def makesquare(self, matchsticks: List[int]) -> bool:
        total = sum(matchsticks)
        if total % 4:
            return False
        side = total // 4
        if max(matchsticks) > side:
            return False
        n = len(matchsticks)
        # fill[mask] = (total length of the sticks in mask) % side = how full the side being built is,
        #              or -1 if those sticks cannot be arranged into complete sides plus one partial side
        fill = [-1] * (1 << n)
        fill[0] = 0                                  # no sticks used, first side empty
        for mask in range(1 << n):
            if fill[mask] < 0:
                continue                             # this set of sticks cannot be reached
            for j in range(n):
                if mask & (1 << j):
                    continue                         # stick j is already used in this mask
                if fill[mask] + matchsticks[j] <= side:   # it fits on the side being built
                    fill[mask | (1 << j)] = (fill[mask] + matchsticks[j]) % side
        return fill[(1 << n) - 1] >= 0               # all sticks used
Time O(n · 2ⁿ)Space O(2ⁿ)

2ⁿ masks, each tries n sticks: about half a million operations for n = 15, whatever the input. The table has 2ⁿ entries.

When to use: When you want a guaranteed bound, or as the base for 'minimum number of sides' variants.

Common mistakes

  • Skipping the quick exits. Without total % 4 == 0 and max(matchsticks) <= side, the search can run for a long time only to answer False. With them, those inputs cost nothing.
  • Using the greedy rule (first side where the stick fits, never undone). It fails on valid inputs such as [7, 3, 2, 2, 7, 3, 2, 2]: after the two 3s share a side, the 2s have no room.
  • Forgetting sides[b] -= stick after a failed recursive call. The side stays longer than it really is, and later sticks are refused for no reason.
  • Not sorting. The answer stays correct, but short sticks go first, fit almost anywhere, and the dead end shows up only after most of the work is done: for [3, 3, 3, 3, 3, 3, 3, 3, 2, 2] the plain search makes 7,365 calls and the sorted one makes 64.
  • Sharing the set of tried lengths between calls. It belongs to one stick: create it fresh at the start of place(i), or a length tried for one stick wrongly blocks the next stick.

Python notes

  • sorted(matchsticks, reverse=True) returns a sorted copy. matchsticks.sort(reverse=True) sorts in place and would change the caller's list.
  • total % 4 is the remainder and total // 4 the integer quotient, so side stays an int.
  • place changes sides[b] through indexing, which needs no nonlocal. Only rebinding a name (sides = ...) would.
  • set() inside place is recreated on every call, so the 'lengths already tried' belong to one stick only.
  • Bit tricks for the DP: 1 << n is 2ⁿ, mask & (1 << j) tests bit j and mask | (1 << j) sets it.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Partition to K Equal Sum Subsets LC 698 — the same problem with k groups instead of 4 sides: the same search, with k buckets and the same two cuts.
  • Partition Equal Subset Sum LC 416 — only two groups. The question becomes 'is there a subset with sum total / 2', which a boolean DP over sums answers in O(n · sum) without any search.
  • Split Array Largest Sum LC 410 — the groups must be contiguous pieces of the array. That removes the freedom to choose, and a binary search on the answer with a greedy check replaces the backtracking.
  • Find Minimum Time to Finish All Jobs LC 1723 — give jobs to k workers and minimise the busiest worker's load. The same bucket search, but a worker is rejected when the load would reach the best answer so far instead of a fixed side.
  • Fair Distribution of Cookies LC 2305 — share bags of cookies among k children to minimise the largest share: the same bucket backtracking with a best-so-far bound.
  • Return one valid square — keep a list of sticks per side next to the lengths, append and pop together, and return the lists when i == n.
