4Sum Medium 250

LeetCode #18 ↗
Status

List every distinct group of four values in an array that adds up to a given target.

Problem

You are given a list of integers nums and an integer target. Find every set of four values from nums that add up to target.

  • The four values must come from four different positions in the list. The same number may be used twice only if it appears twice.
  • Two quadruplets count as the same when they hold the same four values in any order: [1, 0, 0, 3] and [0, 3, 0, 1] are one quadruplet.
  • Return each distinct quadruplet once. The order of the quadruplets, and the order of the values inside each one, does not matter.

Examples

Example 1
Input: nums = [-1, -1, 0, 0, 1, 1, 2], target = 1
Output: [[-1, -1, 1, 2], [-1, 0, 0, 2], [-1, 0, 1, 1]]
Each answer uses a repeated value at two different positions: the two -1s, the two 0s, the two 1s. For example (-1) + (-1) + 1 + 2 = 1.
Example 2
Input: nums = [2, 2, 2, 2, 2, 3], target = 8
Output: [[2, 2, 2, 2]]
Five 2s give five ways to pick four positions, but they all make the same quadruplet, listed once. The 3 never fits: 3 + 2 + 2 + 2 = 9.
Example 3
Input: nums = [1, 2, 3], target = 6
Output: []
Fewer than four values, so there is nothing to choose.

Constraints

  • 1 <= len(nums) <= 200
  • -10^9 <= nums[i] <= 10^9
  • -10^9 <= target <= 10^9

Think first try before reading the solution

Choosing 4 positions out of n = 200 gives about 65 million groups. What if you fixed two of the four numbers first: what problem is left for the other two?
With two numbers fixed, the other two must add up to target - nums[i] - nums[j]. That is Two Sum. On a sorted list it is one two-pointer walk: O(n) time and no extra memory.
Sort once. Loop over i, loop over j > i, and run two pointers over j + 1 .. n - 1. To avoid repeats, skip an i equal to nums[i - 1], skip a j equal to nums[j - 1] (only when j > i + 1), and after a match move left past every copy of the value it just used.

Key idea

3Sum fixes one number and leaves a Two Sum. 4Sum is the same idea one level deeper: fix two numbers and the other two form a Two Sum. After sorting, that Two Sum is the two-pointer walk from Two Sum II: O(n) time, no extra memory. Two fixed indices give about n²/2 pairs, so the total is O(n³), instead of the O(n⁴) of trying every group of four.

Sorting also puts equal values side by side, so duplicates can be skipped while the answers are generated, and no set of tuples is needed:

  • skip an i that repeats the previous first value;
  • skip a j that repeats the previous second value, but only when j > i + 1. The value right after i may equal nums[i], because it sits at a different position (that is how [2, 2, 2, 2] is built);
  • after a match, move left past the copies of the value just used.

A cheap speed-up: in a sorted list, the smallest sum that starts at nums[i] uses the next three values. If even that sum is above target, every larger i is worse, so the loop can stop. The same test works for j.

Approaches from the obvious one to the one you want in an interview

Try every choice of four different positions a < b < c < d. When the four values add up to target, sort them and store them as a tuple in a set, so the same values found at other positions (or in another order) are stored once.

There are about n⁴/24 groups. For n = 200 that is roughly 65 million sums, far too slow for repeated use. It is still worth writing once, because it pins down exactly what counts as a duplicate.

Dry run

  1. nums = [1, 2, 3, 4], target = 10: only one choice of positions (0, 1, 2, 3), and 1 + 2 + 3 + 4 = 10, so record (1, 2, 3, 4).
  2. nums = [2, 2, 2, 2, 2], target = 8: five different choices of four positions all sum to 8 and all become the tuple (2, 2, 2, 2). The set keeps one.
  3. With 7 values there are 35 groups to test, with 200 values about 65 million.

Python

class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:
        n = len(nums)
        found = set()                                   # sorted tuples, so (0, 1, 3, 0) and (0, 0, 1, 3) collide
        for a in range(n):
            for b in range(a + 1, n):
                for c in range(b + 1, n):
                    for d in range(c + 1, n):
                        if nums[a] + nums[b] + nums[c] + nums[d] == target:
                            found.add(tuple(sorted((nums[a], nums[b], nums[c], nums[d]))))
        return [list(q) for q in found]
Time O(n⁴)Space O(q)

Four nested loops; the set holds the q distinct quadruplets found.

When to use: Only to define the problem precisely; it is too slow for large inputs.

Sort, then fix the first two values nums[i] and nums[j]. Scan k to the right of j: the fourth value must be need = target - nums[i] - nums[j] - nums[k], and a set of the values already passed between j and k answers "is need there?" in O(1). That is Two Sum with a hash set, run for every pair (i, j).

Each pair costs one linear scan, so the total is O(n³), already much better than n⁴. Because the list is sorted, the tuple (nums[i], nums[j], need, nums[k]) is already in increasing order, so a set of tuples removes repeats. The price: an extra set per pair, and duplicates are still generated before they are discarded.

Dry run

  1. Sorted [-1, -1, 0, 0, 1, 1, 2], target 1. Fix i = 0 (-1) and j = 1 (-1): the last two must add up to 3.
  2. Scan k = 2..6 (values 0, 0, 1, 1, 2), looking for need = 3 - nums[k] among the values already seen: nothing until k = 6 (value 2), where need = 1 was seen. Add (-1, -1, 1, 2).
  3. Every pair (i, j) repeats a scan like this: about n² pairs times n steps each.

Python

class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:
        nums.sort()
        n = len(nums)
        found = set()
        for i in range(n - 3):
            if i > 0 and nums[i] == nums[i - 1]:
                continue                                  # same first value as the previous round
            for j in range(i + 1, n - 2):
                if j > i + 1 and nums[j] == nums[j - 1]:
                    continue                              # same second value as the previous j
                seen = set()                              # values strictly between j and k
                for k in range(j + 1, n):
                    need = target - nums[i] - nums[j] - nums[k]
                    if need in seen:
                        found.add((nums[i], nums[j], need, nums[k]))   # already in increasing order
                    seen.add(nums[k])
        return [list(q) for q in found]
Time O(n³)Space O(n)

n² pairs, each with a linear scan; the per-pair set holds up to n values.

When to use: A fine stepping stone if you remember Two Sum's hash map but not the two-pointer walk.

Sort the list. For each i (the smallest value of the quadruplet) and each j > i (the second smallest), run two pointers on j + 1 .. n - 1: sum below target → left += 1; above → right -= 1; equal → record the quadruplet, move both pointers, and keep moving left while it sits on the value it just used.

Three skip rules produce every quadruplet exactly once, so no set is needed: skip an i equal to nums[i - 1], skip a j equal to nums[j - 1] when j > i + 1, and skip repeated left values after a match.

Two cheap exits use the sorted order. If the smallest sum from nums[i] onward (`nums[i] + nums[i+1] + nums[i+2] + nums[i+3]) is already above target, no later i can work, so break. The same test on j ends the j` loop. The inner walk is Two Sum II, so each pair costs O(n) and nothing extra is stored.

Dry run

  1. [-1, -1, 0, 0, 1, 1, 2], target 1 (already sorted)
  2. i = 0 (-1), j = 1 (-1): pointers L = 2, R = 6. Sums 0, 0 are too small, so L moves to 4; (-1) + (-1) + 1 + 2 = 1 → record [-1, -1, 1, 2]
  3. j = 2 (0): L = 3, R = 6 → (-1) + 0 + 0 + 2 = 1 → record [-1, 0, 0, 2]; L = 4, R = 5 → (-1) + 0 + 1 + 1 = 1 → record [-1, 0, 1, 1]
  4. j = 3 (0) repeats j = 2 → skip. j = 4 (1): the smallest sum (-1) + 1 + 1 + 2 = 3 is above 1 → leave the j loop
  5. i = 1 (-1) repeats i = 0 → skip. i = 2 (0): smallest sum 0 + 0 + 1 + 1 = 2 is above 1 → stop. 3 quadruplets.

Python

class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:
        nums.sort()
        n = len(nums)
        res = []
        for i in range(n - 3):
            if i > 0 and nums[i] == nums[i - 1]:
                continue                                  # same first value as the previous round
            if nums[i] + nums[i + 1] + nums[i + 2] + nums[i + 3] > target:
                break                                     # smallest possible sum from here on is already too big
            for j in range(i + 1, n - 2):
                if j > i + 1 and nums[j] == nums[j - 1]:
                    continue                              # same second value as the previous j
                if nums[i] + nums[j] + nums[j + 1] + nums[j + 2] > target:
                    break                                 # smallest possible sum with this i and j is too big
                left, right = j + 1, n - 1
                while left < right:
                    total = nums[i] + nums[j] + nums[left] + nums[right]
                    if total < target:
                        left += 1                         # need a bigger sum
                    elif total > target:
                        right -= 1                        # need a smaller sum
                    else:
                        res.append([nums[i], nums[j], nums[left], nums[right]])
                        left += 1
                        right -= 1
                        while left < right and nums[left] == nums[left - 1]:
                            left += 1                     # skip copies of the value just used
        return res
Time O(n³)Space O(1)

O(n log n) to sort plus about n²/2 walks of O(n); extra space is O(1) apart from the output (Python's sort itself may use up to O(n)).

When to use: The standard answer. The same template gives 3Sum, and k-Sum by recursion.

Common mistakes

  • Pruning with if nums[i] > target: break, the 3Sum habit (where the target is 0). With negative numbers it throws answers away: in [-4, -3, -2, -1] with target -10, nums[0] = -4 is above -10, yet the whole list is the answer. Compare the smallest possible sum, nums[i] + nums[i+1] + nums[i+2] + nums[i+3], with the target.
  • Skipping a j whenever nums[j] == nums[j - 1] without the j > i + 1 guard. The value right after i is allowed to equal nums[i]: with [2, 2, 2, 2, 2] and target 8 the unguarded version skips every j and loses the only answer.
  • After a match, moving the pointers without skipping repeated values: the next comparison finds the same quadruplet again.
  • Removing duplicates at the end with a set of tuples. It is correct, but every repeat is still generated first, and the set costs extra memory.
  • Forgetting to sort. The rule 'sum too small, so move left' only holds when the range is in increasing order.

Python notes

  • nums.sort() sorts in place in O(n log n) and changes the caller's list. Use sorted(nums) if the original order matters.
  • Python integers never overflow, so the sum of four values near 10⁹ is safe. In Java or C++ that sum can reach 4·10⁹ and does not fit in a 32-bit int; use a 64-bit type there.
  • tuple(sorted((a, b, c, d))) turns four values into an order-free, hashable key, which is how the brute force collapses (0, 1, 3, 0) and (0, 0, 1, 3) into one entry of a set.

Follow-up questions

What an interviewer might ask next, and what changes.

  • 3Sum LC 15 — one fixed index instead of two: the same sorted walk and the same three duplicate rules.
  • Two Sum II - Input Array Is Sorted LC 167 — the inner loop of this problem on its own.
  • 4Sum II LC 454 — four separate arrays, count the tuples (one value from each) that sum to 0: store every pair sum of the first two arrays in a hash map, then look up the negated pair sums of the last two. O(n²).
  • 3Sum Closest LC 16 — return the sum closest to a target instead of listing exact matches: the same sorted walk, keeping the total with the smallest abs(total - target).
  • k-Sum for any k — write kSum(start, target, k): fix one value and recurse with k - 1 until k == 2, then run the two-pointer walk. The cost is O(n^(k-1)), and 3Sum and 4Sum are the cases k = 3 and k = 4.
