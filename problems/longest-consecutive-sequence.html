Longest Consecutive Sequence Medium

LeetCode #128 ↗
Status

Find the length of the longest run of consecutive integers hidden in an unsorted list.

Problem

You are given an unsorted list of integers nums. Return the length of the longest run of consecutive integers (x, x + 1, x + 2, ...) whose values all appear in nums.

The values can appear anywhere in the list and in any order; repeated values count once. An empty list has answer 0. Your algorithm must run in O(n) time.

Examples

Example 1
Input: nums = [100, 4, 200, 1, 3, 2]
Output: 4
1, 2, 3 and 4 are all present, which is a run of length 4.
Example 2
Input: nums = [0, 3, 7, 2, 5, 8, 4, 6, 0, 1]
Output: 9
Every value from 0 to 8 is present.
Example 3
Input: nums = [1, 0, 1, 2]
Output: 3
The duplicate 1 does not make the run longer.

Constraints

  • 0 <= len(nums) <= 10^5
  • -10^9 <= nums[i] <= 10^9
  • required: O(n) time

Think first try before reading the solution

Sorting makes runs easy to see, but it costs O(n log n). What would let you ask "is x + 1 present?" in O(1)?
Put all values in a set. From a value x, you can walk x + 1, x + 2, ... while they are in the set. Walking from every value repeats work, though: why?
Only start walking from values that begin a run, i.e. x - 1 is not in the set. Then each value is walked over at most once.

Key idea

With all values in a set, "is x + 1 present?" costs O(1). From any value you can then walk upward and measure the run. Done from every value, though, the same run is walked again and again: in 1, 2, 3, 4 you walk 4 steps from 1, 3 from 2, 2 from 3 and 1 from 4.

The fix is to walk only from the start of a run: a value x whose predecessor x - 1 is missing. Every run has exactly one start, so every value is stepped over once in total, plus one O(1) "is it a start?" check per value. That makes the whole algorithm O(n), even though it contains a loop inside a loop.

Approaches from the obvious one to the one you want in an interview

Put the values in a set so "is y present?" is O(1). Then, for every number x, count how far the run x, x + 1, x + 2, ... goes, and keep the longest.

Each lookup is fast, but the walks overlap: in [4, 3, 2, 1] the walk from 1 covers four values, from 2 three, from 3 two and from 4 one. For one long run of n values that is about n²/2 steps.

Dry run

  1. nums = [100, 4, 200, 1, 3, 2], set = {1, 2, 3, 4, 100, 200}
  2. from 100: length 1; from 4: length 1; from 200: length 1
  3. from 1: 1 → 2 → 3 → 4 → length 4; from 3: 3 → 4; from 2: 2 → 3 → 4
  4. best = 4, but the run 1..4 was walked three times

Python

class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        values = set(nums)
        best = 0
        for x in nums:
            length = 0
            while x + length in values:        # walk up from x, whatever x is
                length += 1
            best = max(best, length)
        return best
Time O(n²)Space O(n)

n walks, and a walk can be as long as the run it starts in (up to n steps).

When to use: Never as the final answer; it shows exactly which work the start check removes.

Watch it run

After sorting, the members of a run sit next to each other. Scan once and compare each value with the one before it:

  • equal → a duplicate: skip it (it neither extends nor breaks the run);
  • exactly one more → the run grows;
  • anything bigger → a gap: a new run starts with length 1.

Simple and reliable, but the sort makes it O(n log n), which misses the O(n) requirement.

Dry run

  1. sorted [1, 2, 3, 4, 100, 200]
  2. 2, 3, 4 each continue the run → length 4
  3. 100 is a gap → length 1; 200 is a gap → length 1; best stays 4

Python

class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        if not nums:
            return 0
        s = sorted(nums)
        best = length = 1
        for i in range(1, len(s)):
            if s[i] == s[i - 1]:               # duplicate: run unchanged
                continue
            if s[i] == s[i - 1] + 1:           # next consecutive value: run grows
                length += 1
            else:                              # gap: start a new run
                length = 1
            best = max(best, length)
        return best
Time O(n log n)Space O(n)

The sort dominates; sorted returns a new list of n values.

When to use: When O(n log n) is acceptable or the data is already sorted.

Watch it run

Put the values in a set. Loop over the set, and for each value x first ask: is x - 1 present?

  • yes → x is in the middle of some run; that run will be counted from its start, so skip x;
  • no → x starts a run: walk x + 1, x + 2, ... while present and record the length.

Every run has one start, so every value is walked over by exactly one walk. Across the whole loop that is at most n walking steps plus n start checks: O(n) in total, although there is a loop inside a loop. (Counting the total work of a loop instead of multiplying worst cases is called amortised analysis.)

Dry run

  1. set = {1, 2, 3, 4, 100, 200}
  2. 1: 0 missing → start → walk 2, 3, 4; 5 missing → length 4
  3. 2: 1 present → skip; 3 and 4 are skipped the same way
  4. 100: start → 101 missing → length 1; 200: start → length 1; answer 4

Python

class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        values = set(nums)                     # O(1) lookups; duplicates collapse
        best = 0
        for x in values:                       # each distinct value once
            if x - 1 in values:                # not a start: counted from its run's start
                continue
            length = 1
            while x + length in values:        # walk up the run that starts at x
                length += 1
            best = max(best, length)
        return best
Time O(n)Space O(n)

Each value gets one start check and is stepped over by at most one walk; the set holds up to n values.

When to use: The required O(n) answer.

Common mistakes

  • Walking from every value instead of only from run starts: correct, but a long run like 1..n costs n + (n − 1) + ... = O(n²).
  • Looping over nums instead of the set: if the start of a long run is repeated many times, each copy walks the whole run again. Loop over the set so each value is handled once.
  • Testing x + 1 in nums on the list: every lookup scans the list, which brings back O(n²) or worse.
  • In the sorting version, a duplicate must neither extend nor break the run: [1, 2, 2, 3] has a run of 3. Skip equal neighbours.
  • Forgetting the empty list: max() of nothing raises ValueError; start best at 0.

Python notes

  • set(nums) removes duplicates and gives O(1) average membership tests.
  • Small non-negative integers often look sorted when you print a set; that is an accident of how integers hash. Never rely on set order.
  • The while x + length in values loop is the idiom: test the next value, then grow the run.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Binary Tree Longest Consecutive Sequence LC 298 — the run must follow parent-to-child edges in a tree: a DFS passes the current run length down and extends it when child.val == node.val + 1.
  • Summary Ranges LC 228 — the input is sorted and distinct, and you must list every run as "a->b": one scan that closes a range at each gap.
  • Longest Increasing Subsequence LC 300 — looks similar, but there the order in the list matters and values need not be consecutive: dynamic programming instead of a set.
  • Can you solve it with union-find? — union each value with x + 1 when present; the answer is the size of the largest component. It is useful when values arrive one at a time.
  • Return the run itself, not just its length — remember the start x with the best length; the run is range(x, x + best).
