Integer Break Medium 250

LeetCode #343 ↗
Status

Split a number into at least two positive integers so that their product is as large as possible.

Problem

You are given an integer n with n >= 2. Write n as a sum of at least two positive integers (the same value may repeat) and return the largest product those integers can have.

You have to cut at least once. For n = 2 the only choice is 1 + 1, so the answer is 1, not 2.

Examples

Example 1
Input: n = 3
Output: 2
3 must be cut: 1 + 2 gives 2. Keeping the 3 whole is not allowed.
Example 2
Input: n = 8
Output: 18
3 + 3 + 2 gives 18. Two equal halves, 4 + 4, give only 16.
Example 3
Input: n = 11
Output: 54
3 + 3 + 3 + 2 gives 54.

Constraints

  • 2 <= n <= 58

Key idea

The table. Every answer has at least two pieces, so it can be cut into two groups of pieces. Each group is worth at most the best product for its total. A group that is one piece of size x is worth exactly x; a group of several pieces is worth at most dp[x]. So the worth of a part of size x is max(x, dp[x]): keep it whole, or break it further, whichever is bigger. With dp[m] = the best product for m cut into at least two pieces:

dp[m] = max over i of max(i, dp[i]) × max(m - i, dp[m - i]), trying i = 1 .. m // 2 (the other cuts mirror these).

dp[1] = 0, because 1 cannot be cut into two positive integers. A part of size 1 is still worth max(1, 0) = 1. Every cell reads only smaller cells, so filling dp[2], dp[3], ..., dp[n] in order works: O(n²) time.

The pattern. Print the table for m = 2 .. 10: 1, 2, 4, 6, 9, 12, 18, 27, 36. From m = 7 on, each value is exactly 3 times the value three places earlier, so the best answers are made of 3s. Why?

  • A piece x >= 5 is always better cut: 3 × (x - 3) > x. So a best answer has no piece of 5 or more.
  • A piece of 4 is the same as 2 + 2 (both give 4), so only 2s and 3s are needed.
  • A piece of 1 only wastes a unit: merging it into a neighbour x gives x + 1 > x × 1.
  • Three 2s give 8, but two 3s (same total 6) give 9. So at most two 2s.

So take as many 3s as possible. If a remainder of 1 is left, a 3 + 1 is better as 2 + 2 (4 beats 3); if a remainder of 2 is left, keep one 2. That is the O(1) rule, with n <= 3 handled separately because the cut is forced.

Approaches from the obvious one to the one you want in an interview

best(m) = the largest product when m is cut into at least two positive integers (0 for m = 1, which cannot be cut). Try every cut of m into i and m - i, with i up to m // 2. Each part is either kept whole or broken further, so its worth is max(part, best(part)). The answer for the cut is the product of the two worths.

It is correct, but the same sizes are solved again and again (best(3) appears in the cut of 4, of 5, of 6, ...), so the number of calls doubles with every +1 on n: 825 calls for n = 10, 211,479 for 18 and over 13 million for 24.

Dry run

  1. n = 6: cuts 1 | 5, 2 | 4, 3 | 3
  2. 1 | 5: worth 1 and max(5, best(5)) = max(5, 6) = 6, product 6
  3. 2 | 4: worth 2 and max(4, best(4)) = max(4, 4) = 4, product 8
  4. 3 | 3: worth max(3, best(3)) = max(3, 2) = 3 on each side, product 9 → best(6) = 9

Python

class Solution:
    def integerBreak(self, n: int) -> int:
        def best(m: int) -> int:
            """Largest product from cutting m into at least two positive integers (0 when m = 1)."""
            result = 0
            for i in range(1, m // 2 + 1):          # cut m into i and m - i; the other cuts mirror these
                left = max(i, best(i))              # a part of size i: keep it whole, or break it further
                right = max(m - i, best(m - i))
                result = max(result, left * right)
            return result

        return best(n)
Time O(2^n)Space O(n)

The number of calls roughly doubles for every +1 on n; the recursion is at most n deep.

When to use: Only to discover the recurrence; it is fine up to n = 18 or so and hopeless at 58.

Fill dp[2..n] in increasing order. For each m, try every cut into i and m - i with i up to m // 2. A part of size x is worth max(x, dp[x]), so the cut is worth max(i, dp[i]) × max(m - i, dp[m - i]), and dp[m] is the best cut.

Both parts are smaller than m, so their cells are final when m reads them. dp[1] stays 0, but a part of size 1 is worth max(1, 0) = 1. Caching the plain recursion gives the same table from the top down.

Dry run

  1. n = 6: dp = [-, 0, ?, ?, ?, ?, ?]
  2. dp[2] = 1 × 1 = 1, dp[3]: cut 1 | 2 is worth 1 × max(2, 1) = 2
  3. dp[4]: cut 2 | 2 is worth max(2, 1) × max(2, 1) = 4, better than 1 | 3 = 3
  4. dp[5]: cut 2 | 3 is worth 2 × 3 = 6; dp[6]: cut 3 | 3 is worth 3 × 3 = 9 → answer 9

Python

class Solution:
    def integerBreak(self, n: int) -> int:
        dp = [0] * (n + 1)                          # dp[m] = best product of cutting m into at least two parts
        for m in range(2, n + 1):                   # small sizes first: both parts are already final
            for i in range(1, m // 2 + 1):          # cut m into i and m - i
                left = max(i, dp[i])                # a part of size i: keep it whole, or break it further
                right = max(m - i, dp[m - i])
                dp[m] = max(dp[m], left * right)
        return dp[n]
Time O(n²)Space O(n)

About n/2 cuts for each of the n cells; one list of n + 1 integers.

When to use: The derivation to give first: it needs no insight beyond the recurrence.

Watch it run

The table shows that a best answer is made of 3s. A piece x >= 5 is better cut (3 × (x - 3) > x), 4 equals 2 + 2, a 1 wastes a unit, and three 2s lose to two 3s. So use as many 3s as possible and fix up the remainder:

  • remainder 0: all 3s, product 3^(n / 3);
  • remainder 1: one 3 + 1 becomes 2 + 2 (equivalently a 4): 3^(k - 1) × 4;
  • remainder 2: one extra 2: 3^k × 2.

For n <= 3 the cut is forced, so the answer is n - 1.

Dry run

  1. n = 10: divmod(10, 3) = (3, 1), a remainder of 1
  2. the leftover 1 and one 3 become a 4: pieces 3 + 3 + 4
  3. 3^2 × 4 = 36

Python

class Solution:
    def integerBreak(self, n: int) -> int:
        if n <= 3:                                  # the cut is forced: 2 = 1 + 1, 3 = 1 + 2
            return n - 1
        threes, rest = divmod(n, 3)
        if rest == 0:
            return 3 ** threes                      # all threes
        if rest == 1:
            return 3 ** (threes - 1) * 4            # 3 + 1 is worse than 2 + 2: make a 4
        return 3 ** threes * 2                      # one 2 left over
Time O(log n)Space O(1)

One division and one power; 3^k by repeated squaring takes O(log k) multiplications.

When to use: Once you have seen the pattern; explain why 3s are best, or the answer looks like a guess.

Common mistakes

  • Forgetting the forced cut. n = 2 gives 1 and n = 3 gives 2, not 2 and 3. Code that takes max(n, best split) at the top level returns n.
  • Valuing a part as dp[x] alone. A part may also stay whole, and the small parts 2, 3 and 4 almost always should: dp[3] is 2 (the cut 1 + 2), but a part of size 3 is worth 3. Without max(x, dp[x]) the whole table collapses to 0s (or to 1s if you set dp[1] = 1).
  • Cutting into two equal halves. (n // 2) × (n - n // 2) is right up to n = 7 and wrong from 8 on: it gives 16 for n = 8, but 3 + 3 + 2 gives 18.
  • A remainder of 1 in the 3s rule. For n = 10, 3 + 3 + 3 + 1 gives 27, but 3 + 3 + 4 gives 36. Merge the 1 into a 3 to make a 4.
  • Plain recursion doubles its calls with every +1 on n: 825 calls for n = 10, 211,479 for 18 and over 13 million for 24. It cannot reach n = 58.

Python notes

  • divmod(n, 3) returns the quotient and the remainder together: threes, rest = divmod(n, 3).
  • 3 ** k is exact for any size. The largest answer here, for n = 58, is 1,549,681,956.
  • dp = [0] * (n + 1) leaves dp[0] and dp[1] at 0. dp[0] is never read, and max(1, dp[1]) makes a part of size 1 worth 1.
  • @cache on the recursive best turns the plain recursion into an O(n²) top-down solution; the recursion is only n deep, so there is no recursion-limit trouble.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Perfect Squares LC 279 — also splits a number into parts with a table over smaller values, but it counts the parts and minimises instead of multiplying and maximising.
  • Pow(x, n) LC 50 — the 3s rule needs 3^k; for a huge n compute it by repeated squaring, O(log k) multiplications.
  • Maximize Number of Nice Divisors LC 1808 — the same 3s rule in disguise, with n up to 10^9: answer modulo 10^9 + 7 using pow(3, k, MOD).
  • Break into exactly k pieces — the product is largest when the pieces are as equal as possible: n % k pieces of size n // k + 1 and the rest of size n // k.
  • Return the pieces themselves — remember the best cut for each m while filling the table, then expand the cut of n recursively (a part is kept whole when x >= dp[x]).
