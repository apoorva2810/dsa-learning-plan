Jump Game VII Medium 250

LeetCode #1871 ↗
Status

Decide whether you can hop from the first character of a 0/1 string to the last, jumping a distance between two limits and landing only on 0s.

Problem

You are given a string s made of the characters '0' and '1', and two integers minJump and maxJump. You start on index 0, which is always '0'.

From index i you may jump to index j when both of these hold:

  • the distance is within the limits, i + minJump <= j <= i + maxJump, and j is inside the string;
  • you land on a '0': s[j] == '0'. A '1' is a wall you cannot stand on.

Return True if you can reach the last index, and False otherwise.

Examples

Example 1
Input: s = "0100100", minJump = 2, maxJump = 3
Output: true
Jump 0 → 3 (distance 3, and s[3] is '0'), then 3 → 6 (distance 3). Index 6 is the last one.
Example 2
Input: s = "00011100", minJump = 1, maxJump = 2
Output: false
The three '1' characters at indexes 3, 4 and 5 form a wall. Crossing it needs a jump of 4 or more from index 2, but no jump is longer than 2.
Example 3
Input: s = "01010", minJump = 2, maxJump = 2
Output: true
Every jump is exactly 2, so the route is 0 → 2 → 4, and all three landing cells are '0'.

Constraints

  • 2 <= len(s) <= 10^5
  • s[i] is '0' or '1'
  • s[0] == '0'
  • 1 <= minJump <= maxJump < len(s)

Think first try before reading the solution

Do not search for the route. Ask which indexes you can stand on. For one index j, which starting indexes i can jump onto it in a single jump? Write the condition on i using minJump and maxJump.
Index j can be reached from any reachable i with j - maxJump <= i <= j - minJump, as long as s[j] == '0'. So reachable[j] only asks: is there at least one reachable index inside a window of starting points?
That window slides one step to the right each time j grows by one: one index enters on the right and one leaves on the left. Keep a running count of reachable indexes in the window instead of looping over it.

Key idea

Turn the question around. Instead of asking where each index can jump to, ask who can jump onto index j. An index i can reach j when minJump <= j - i <= maxJump, so the possible starting points form one window of indexes, j - maxJump .. j - minJump. Therefore

reachable[j] = (s[j] == '0') and (some reachable index lies in that window).

Filling reachable from left to right is a small dynamic program. Looping over the window for every j would cost up to maxJump - minJump + 1 per index, which is the same slow O(n·k) as a plain BFS. But the window moves exactly one step to the right when j goes up by one: index j - minJump enters and index j - maxJump - 1 leaves. So keep a count of the reachable indexes in the window, add the one that enters and subtract the one that leaves. Each j now costs O(1).

A wall is simply never reachable (s[j] == '1'), so it never adds to the count later. Prefix sums of reachable give the same answer: the window holds a reachable index when the prefix count at its right edge exceeds the prefix count just before its left edge.

Approaches from the obvious one to the one you want in an interview

Treat each index as a node and each legal jump as an edge. Start a queue at index 0. Take an index i off the queue and try every landing index i + minJump .. i + maxJump (not past the end). Each one that is a '0' and not seen yet is marked and queued. Return True as soon as the last index comes off the queue.

Every index enters the queue at most once, so the number of pops is at most n. But each pop scans its whole jump range, maxJump - minJump + 1 cells, even when almost all of them were already seen. For a wide range on 10^5 characters that is billions of checks.

Dry run

  1. s = "0100100", minJump = 2, maxJump = 3: queue [0]
  2. pop 0: scan 2 and 3, both '0' → queue [2, 3]
  3. pop 2: scan 4 ('1', skip) and 5 ('0') → queue [3, 5]
  4. pop 3: scan 5 (already seen) and 6 ('0') → queue [5, 6]
  5. pop 5: nothing to scan. pop 6: it is the last index → True

Python

class Solution:
    def canReach(self, s: str, minJump: int, maxJump: int) -> bool:
        n = len(s)
        seen = [False] * n
        seen[0] = True
        queue = deque([0])
        while queue:
            i = queue.popleft()
            if i == n - 1:
                return True
            for j in range(i + minJump, min(i + maxJump, n - 1) + 1):   # every cell this jump can land on
                if s[j] == "0" and not seen[j]:
                    seen[j] = True
                    queue.append(j)
        return False
Time O(n · k)Space O(n)

k = maxJump − minJump + 1: each of the n pops scans up to k cells. That is O(n²) when the range is wide.

When to use: To define the problem and to check faster solutions on small inputs.

Fill a reachable list from left to right. Index j is reachable when s[j] == '0' and at least one reachable index lies in the window j - maxJump .. j - minJump.

Keep in_window, the number of reachable indexes in that window. Moving from j - 1 to j:

  1. the index j - minJump enters the window: add 1 if it is reachable,
  2. the index j - maxJump - 1 leaves it: subtract 1 if it was reachable.

Then reachable[j] = s[j] == '0' and in_window > 0. The answer is reachable[n - 1]. One pass, O(1) per index.

Dry run

  1. s = "0100100", minJump = 2, maxJump = 3: reachable[0] = True
  2. j = 1: the window is empty (index −1) → not reachable (and s[1] is a wall anyway)
  3. j = 2: index 0 enters (+1) → in_window = 1, s[2] = '0' → reachable
  4. j = 3: index 1 enters (not reachable) → in_window = 1 → reachable
  5. j = 4: index 2 enters (+1), index 0 leaves (−1) → in_window = 1, but s[4] is a wall → not reachable
  6. j = 5: index 3 enters (+1), index 1 leaves (−0) → in_window = 2 → reachable
  7. j = 6: index 4 enters (+0), index 2 leaves (−1) → in_window = 1 → reachable → True

Python

class Solution:
    def canReach(self, s: str, minJump: int, maxJump: int) -> bool:
        n = len(s)
        reachable = [False] * n
        reachable[0] = True
        in_window = 0                            # reachable indexes in [j - maxJump, j - minJump]
        for j in range(1, n):
            if j - minJump >= 0 and reachable[j - minJump]:          # this start just entered the window
                in_window += 1
            if j - maxJump - 1 >= 0 and reachable[j - maxJump - 1]:  # this start just left the window
                in_window -= 1
            reachable[j] = s[j] == "0" and in_window > 0
        return reachable[n - 1]
Time O(n)Space O(n)

One pass; the reachable list has n entries.

When to use: The standard answer. Explain the window as "who can jump onto j", then the add-one, remove-one update.

Watch it run

Keep the BFS, but stop rescanning cells. The queue holds increasing indexes, so the jump ranges of successive pops only ever move to the right. Remember farthest, the highest index any earlier pop has already scanned up to. For a new pop i, everything at or below farthest was covered by an earlier range (it lies between that pop's left edge and farthest), so start scanning at max(i + minJump, farthest + 1).

Each index is scanned once over the whole run, so the BFS becomes O(n). It is the same saving as the sliding window count, written as a graph search.

Dry run

  1. s = "0100100", minJump = 2, maxJump = 3: queue [0], farthest = 0
  2. pop 0: scan 2..3, both '0' → queue [2, 3], farthest = 3
  3. pop 2: scan from max(4, 4) = 4 to 5: 4 is a wall, 5 is '0' → queue [3, 5], farthest = 5
  4. pop 3: scan from max(5, 6) = 6 to 6: '0' and the last index → True

Python

class Solution:
    def canReach(self, s: str, minJump: int, maxJump: int) -> bool:
        n = len(s)
        queue = deque([0])
        farthest = 0                             # every index up to here has already been looked at
        while queue:
            i = queue.popleft()
            for j in range(max(i + minJump, farthest + 1), min(i + maxJump, n - 1) + 1):
                if s[j] == "0":
                    if j == n - 1:
                        return True
                    queue.append(j)
            farthest = max(farthest, i + maxJump)
        return False
Time O(n)Space O(n)

Each index is scanned at most once across all pops; the queue holds up to n indexes.

When to use: When you think of the problem as a graph search and want to keep the BFS shape.

Common mistakes

  • Scanning the whole jump range from every reachable index. A BFS that only marks seen still touches up to maxJump - minJump + 1 cells per pop, so a wide range on 10^5 characters needs billions of steps.
  • Off-by-one on the window edges. The index that enters is j - minJump and the one that leaves is j - maxJump - 1 (not j - maxJump). Check minJump == maxJump, where the window is a single index.
  • Reading reachable[j - minJump] or reachable[j - maxJump - 1] without checking that the index is at least 0. In Python a negative index silently wraps to the end of the list and gives a wrong count.
  • Letting a '1' cell become reachable because the window has reachable starts. A wall cannot be landed on, so it must stay False, otherwise it would count as a start for later jumps.
  • Writing the search as a recursive DFS. With 10^5 characters the recursion is far deeper than Python's default limit of 1000 frames; use a loop or a BFS queue.

Python notes

  • collections.deque (already imported) gives O(1) popleft(). A list's pop(0) is O(n), which would turn the BFS into O(n²).
  • s[j] == "0" compares characters; indexing a string is O(1).
  • range(a, b) is empty when a >= b, so a pop whose jump range starts beyond the last index simply scans nothing.
  • Python lists accept negative indexes (reachable[-1] is the last element), so guard index >= 0 explicitly in a sliding window; otherwise the left edge silently wraps around.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Jump Game LC 55 — no walls, and a jump may be any length up to nums[i]. The reachable indexes form one block, so a single farthest number is enough.
  • Jump Game II LC 45 — the fewest jumps. It is a BFS by levels, and the same "never rescan what an earlier window already covered" idea keeps it O(n).
  • Jump Game VI LC 1696 — every landing adds its value to a score and jumps are at most k long, so you want the best score. The window now needs its maximum, which a monotonic deque provides.
  • Sliding Window Maximum LC 239 — the deque technique Jump Game VI needs: the best value of a window that slides right, in O(1) per step.
  • Jump Game III LC 1306 — you can jump i + arr[i] or i - arr[i] and must reach any 0. Moves go both ways, so use BFS or DFS with a visited set.
  • What is the fewest number of jumps? — run the BFS by levels. The "farthest scanned" pointer still gives O(n), and the level of the last index is the answer.
