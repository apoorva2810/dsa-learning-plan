Balanced Binary Tree Easy

LeetCode #110 ↗
Status

Check that at every node the heights of the left and right subtrees differ by at most one.

Problem

Given the root of a binary tree, decide whether it is height-balanced.

A tree is height-balanced when, for every node, the heights of its left and right subtrees differ by at most 1. Here the height of a subtree is the number of nodes on its longest downward path, so an empty subtree has height 0 and a leaf has height 1.

Examples

Example 1
Input: root = [3, 9, 20, None, None, 15, 7]
Output: true
Node 3 sees subtree heights 1 and 2, node 20 sees 1 and 1, and the leaves see 0 and 0. Every difference is at most 1.
Example 2
Input: root = [1, 2, 2, 3, 3, None, None, 4, 4]
Output: false
At the root, the left subtree (2 → 3 → 4) has height 3 and the right subtree (a lone 2) has height 1.
Example 3
Input: root = []
Output: true
An empty tree has no node that could break the rule.

Constraints

  • 0 <= number of nodes <= 5000
  • -10^4 <= Node.val <= 10^4

Key idea

Balance is a rule about every node, and the rule needs the heights of the node's two child subtrees. The direct translation is: for each node compute both heights (two walks over its subtrees), then check the children the same way. On a long chain this is quadratic, because the same nodes are walked again for every ancestor above them.

The walks are wasteful because a height is already known on the way back up. Let the recursion return the height of its subtree, and let each node compare the two heights it receives. Now every node is handled once.

An unbalanced node anywhere makes the whole tree unbalanced, so there is no point computing more. Return the sentinel -1 (a value no real height can have) to mean "unbalanced below here". A parent that receives -1 passes it straight up without comparing anything. The tree is balanced exactly when the root's result is not -1.

Approaches from the obvious one to the one you want in an interview

Translate the definition literally. A tree is balanced when (1) the heights of the root's two subtrees differ by at most 1, and (2) the left subtree is balanced, and (3) the right subtree is balanced. Heights come from a plain height function (the Maximum Depth recursion).

It is correct, but height walks an entire subtree and is called again at every node above it. On a chain of n nodes the walks cost n + (n − 1) + ... = O(n²). On a balanced tree each node is walked once per ancestor, about O(n log n).

Dry run

  1. root = [3, 9, 20, None, None, 15, 7]
  2. node 3: height(9) = 1, height(20) = 2 → differ by 1, fine
  3. node 9: heights 0 and 0, fine
  4. node 20: height(15) = 1, height(7) = 1, fine (the leaves 15 and 7 are walked again here)
  5. every node passed → True

Python

class Solution:
    def isBalanced(self, root: Optional[TreeNode]) -> bool:
        def height(node):
            if node is None:
                return 0
            return 1 + max(height(node.left), height(node.right))

        if root is None:
            return True
        if abs(height(root.left) - height(root.right)) > 1:   # this node breaks the rule
            return False
        # the rule must also hold at every node below
        return self.isBalanced(root.left) and self.isBalanced(root.right)
Time O(n²) worst caseSpace O(h)

On a chain, height walks n−1, n−2, ... nodes. A balanced tree costs about O(n log n).

When to use: Only to make the definition concrete before improving it.

Let each call return the height of its subtree, or -1 if any node inside it is unbalanced:

  1. height(None) is 0.
  2. Get left from the left child. If it is -1, return -1 immediately (the right side need not be visited).
  3. Get right the same way.
  4. If abs(left - right) > 1, this node is unbalanced: return -1.
  5. Otherwise return the height 1 + max(left, right).

The tree is balanced exactly when height(root) is not -1. Every node is visited once, and the walk stops at the first unbalanced node.

Dry run

  1. root = [1, 2, 3, 4, None, None, None, 5]: node 2 has only a left child 4, and 4 has only a left child 5.
  2. height(5): a leaf → 1. height(4): left 1, right 0, differ by 1 → height 2.
  3. height(2): left 2, right 0, differ by 2 → return -1.
  4. height(1): the left side is -1 → return -1 at once. Node 3 is never visited.
  5. The root returned -1 → not balanced → False.

Python

class Solution:
    def isBalanced(self, root: Optional[TreeNode]) -> bool:
        def height(node):
            """Height of the subtree, or -1 if some node inside it is unbalanced."""
            if node is None:
                return 0
            left = height(node.left)
            if left == -1:                    # unbalanced below: stop, do not compare
                return -1
            right = height(node.right)
            if right == -1:
                return -1
            if abs(left - right) > 1:         # this node is the unbalanced one
                return -1
            return 1 + max(left, right)

        return height(root) != -1
Time O(n)Space O(h)

Each node is visited at most once. The call stack is as deep as the tree is tall.

When to use: The default and the interview answer. The same bottom-up shape solves Diameter of Binary Tree.

Watch it run

The -1 trick packs two facts into one number. Returning both facts explicitly is easier to read and cannot be mixed up: the helper returns (balanced, height). A node is balanced when both children are balanced and their heights differ by at most 1, and its height is 1 + max(left height, right height).

The trade-off: this simple version keeps walking after it finds an unbalanced node (it still visits every node, O(n)), where the -1 version stops early. It also builds a small tuple at every node. Adding if not left_ok: return False, 0 restores the early exit.

Dry run

  1. root = [3, 9, 20, None, None, 15, 7]
  2. leaf 9: left (True, 0), right (True, 0) → (True, 1)
  3. leaves 15 and 7: (True, 1) each; node 20: heights 1 and 1 → (True, 2)
  4. node 3: heights 1 and 2, both children balanced → (True, 3) → answer True.

Python

class Solution:
    def isBalanced(self, root: Optional[TreeNode]) -> bool:
        def check(node):
            """Return (is this subtree balanced?, its height)."""
            if node is None:
                return True, 0
            left_ok, left_h = check(node.left)
            right_ok, right_h = check(node.right)
            ok = left_ok and right_ok and abs(left_h - right_h) <= 1
            return ok, 1 + max(left_h, right_h)

        return check(root)[0]
Time O(n)Space O(h)

Every node is visited once, with no early exit. One tuple is created per node.

When to use: When you prefer explicit values over a sentinel number, or want the heights for something else too.

Common mistakes

  • Checking only the root. In [1, 2, 5, 3, None, 6, 7, 4, None, 8, 9, 10, 11] both subtrees of the root have height 3, yet node 2 has a left subtree of height 2 and an empty right subtree. The tree is unbalanced.
  • Comparing -1 with real heights. If the left call returns -1 and the right call returns 0, then abs(-1 - 0) = 1 looks fine and the unbalanced subtree is silently accepted. Test for -1 first.
  • Mixing height conventions. With the -1 sentinel an empty subtree must have height 0 (count nodes). If you count edges (empty = -1, leaf = 0), -1 becomes a legitimate height and the sentinel is ambiguous.
  • Calling a separate height() for every node inside the recursion. It is correct but O(n²) on a chain: 5000 nodes cost about 12 million steps.
  • Confusing 'balanced' with 'perfect' or 'complete'. A node with a single child is allowed as long as that child is a leaf: [1, 2] is balanced.

Python notes

  • abs(left - right) > 1 is the whole balance test. The absolute value covers both 'left is taller' and 'right is taller'.
  • Returning -1 packs two answers (the height, and 'unbalanced') into one integer. Returning a tuple (is_balanced, height) is easier to read, at the cost of unpacking at every node.
  • height(root) != -1 evaluates to a real bool, so the method returns True or False and not an integer.
  • A chain of 5000 nodes recurses deeper than Python's default limit of 1000 frames. LeetCode raises the limit; elsewhere call sys.setrecursionlimit.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Diameter of Binary Tree LC 543 — the same bottom-up height recursion, but it keeps a running maximum of left + right instead of testing the difference.
  • Convert Sorted Array to Binary Search Tree LC 108 — build a height-balanced tree instead of testing one: make the middle element the root and recurse on each half.
  • Balance a Binary Search Tree LC 1382 — repair an existing BST: an inorder walk gives the sorted values, then rebuild from the middle.
  • Minimum Depth of Binary Tree LC 111 — another depth question, but a node with one child is not a leaf, so the base cases change.
  • How does an AVL tree stay balanced? — it stores each node's height and rotates whenever a node's balance factor (left height minus right height) reaches ±2. The test in this problem is exactly that factor.
