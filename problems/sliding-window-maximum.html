Sliding Window Maximum Hard

LeetCode #239 ↗
Status

Report the maximum of every window of k consecutive numbers as the window slides across the list.

Problem

You are given a list of integers nums and a window size k. A window covering k consecutive elements starts at the left end of the list and moves right one position at a time until it reaches the right end.

Return a list with the maximum of each window position, in order. With n = len(nums) there are n - k + 1 windows.

Examples

Example 1
Input: nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
Output: [3, 3, 5, 5, 6, 7]
Windows: [1, 3, -1] → 3, [3, -1, -3] → 3, [-1, -3, 5] → 5, [-3, 5, 3] → 5, [5, 3, 6] → 6, [3, 6, 7] → 7.
Example 2
Input: nums = [1], k = 1
Output: [1]
Example 3
Input: nums = [9, 8, 7, 6], k = 2
Output: [9, 8, 7]
Each maximum leaves the window right after it is reported, so the next one takes over.

Constraints

  • 1 <= len(nums) <= 10^5
  • -10^4 <= nums[i] <= 10^4
  • 1 <= k <= len(nums)

Think first try before reading the solution

Taking max of every window is O(n · k). When the window slides, only one element enters and one leaves. Which elements in the window can never be a maximum again?
If a newer element is at least as large as an older one, the older one is useless from now on: it leaves the window first, and while both are inside, the newer one wins. You can throw it away immediately.
Keep a deque of indices whose values are decreasing from front to back. For each new index: pop smaller values from the back, push the index, pop the front if it has slid out of the window, then read the maximum at the front.

Key idea

When a new element x enters the window, every older element that is not larger than x is useless from then on: it will leave the window before x does, and as long as both are inside, x is at least as big. So it can be forgotten right away.

After discarding all such elements, the candidates that remain have decreasing values from oldest to newest. Keeping them in a monotonic deque (a double-ended queue whose values stay in sorted order) makes the answer easy: the oldest candidate, at the front, is the largest, so it is the window maximum, unless it has already slid out of the window, in which case pop it from the front.

Store indices rather than values so you can tell when the front has left the window. Every index is pushed once and popped at most once, so the total work is O(n) even though there is a while loop inside the for. Counting the total work over the whole run like this, instead of the worst single step, is called amortised analysis.

Approaches from the obvious one to the one you want in an interview

For every start position, scan the k elements of the window and take their maximum.

There are n − k + 1 windows and each scan costs O(k), so the total is O(n · k): about 2.5·10⁹ steps when n = 10⁵ and k = n / 2. Consecutive windows share k − 1 elements, yet every window is scanned from scratch.

Python

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        result = []
        for start in range(len(nums) - k + 1):
            result.append(max(nums[start:start + k]))   # O(k) scan of this window
        return result
Time O(n · k)Space O(k)

n − k + 1 windows, each copied (the slice) and scanned; the output list is not counted.

When to use: Fine when k is tiny; otherwise only a baseline.

A heap returns its largest item in O(1) and accepts new items in O(log n). Push every element as (-value, index) (negated, because heapq is a min-heap). Before reading the maximum of the window ending at i, pop entries from the top whose index is already outside the window.

Entries that left the window but are not on top stay in the heap until they surface. That is called lazy deletion: it avoids searching the heap for them. Each element is pushed and popped at most once, giving O(n log n).

Dry run

  1. nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
  2. push 1, 3, -1 → top is 3 (index 1, inside) → 3
  3. push -3 → top 3 (index 1, inside window [1, 3]) → 3
  4. push 5 → top 5 → 5; push 3 → top 5 → 5
  5. push 6 → top 6 → 6; push 7 → top 7 → 7

Python

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        heap = []                                  # (-value, index): a max-heap via negation
        result = []
        for i, x in enumerate(nums):
            heapq.heappush(heap, (-x, i))
            if i >= k - 1:
                while heap[0][1] <= i - k:         # the top slid out of the window: discard it now
                    heapq.heappop(heap)
                result.append(-heap[0][0])
        return result
Time O(n log n)Space O(n)

n pushes and at most n pops, each O(log n); stale entries can make the heap hold up to n items.

When to use: A reasonable answer if you do not know the deque trick; it also generalises to other 'top' queries.

Keep a deque of indices whose values decrease from front to back. For each index i with value x:

  1. While the value at the back is <= x, pop it: it can never be a window maximum again.
  2. Push i at the back.
  3. If the front index is <= i - k, it has left the window: pop it from the front.
  4. Once i >= k - 1, the front holds the window maximum: append nums[dq[0]].

Step 1 keeps the values sorted, so the front is always the largest candidate. Each index is pushed once and popped at most once (from one end or the other), so the whole scan is O(n).

Dry run

  1. nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
  2. 1 → [0]; 3 pops 1 → [1]; -1 → [1, 2] → window full, max nums[1] = 3
  3. -3 → [1, 2, 3] → max 3
  4. 5 pops -3, -1, 3 → [4] → max 5; 3 → [4, 5] → max 5
  5. 6 pops 3, 5 → [6] → 6; 7 pops 6 → [7] → 7

Python

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        dq = deque()                               # indices; values strictly decrease front to back
        result = []
        for i, x in enumerate(nums):
            while dq and nums[dq[-1]] <= x:        # older, smaller values can never be a maximum again
                dq.pop()
            dq.append(i)
            if dq[0] <= i - k:                     # the front index slid out of the window
                dq.popleft()
            if i >= k - 1:                         # the first full window ends at index k - 1
                result.append(nums[dq[0]])
        return result
Time O(n)Space O(k)

Each index enters and leaves the deque once; the deque never holds more than k indices.

When to use: The optimal answer and the standard monotonic-deque template for window maxima or minima.

Common mistakes

  • Storing values instead of indices. You then cannot tell whether the front has slid out of the window, especially when values repeat.
  • Reading an answer before the first window is complete. Only start appending once i >= k - 1.
  • Using list.pop(0) for the front: it shifts every element, O(n) per call. collections.deque.popleft() is O(1).
  • Popping the back with < or <=: both give correct maxima (with <, equal values stay and the older one expires first). <= keeps the deque shorter, so be deliberate rather than accidental about the choice.
  • Thinking the inner while makes it O(n · k). Count pushes and pops instead of loop iterations: n of each at most.

Python notes

  • collections.deque supports O(1) append, pop, appendleft and popleft; dq[0] and dq[-1] peek at the two ends.
  • heapq only provides a min-heap. Push (-value, index) to get max-heap behaviour, and keep the index for expiry checks.
  • max(nums[i:i + k]) copies k elements and then scans them, so the brute force pays O(k) per window twice over.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Sliding Window Median LC 480 — a median cannot be read off a monotonic deque: use two heaps with lazy deletion, or a sorted list with binary-search inserts and removals.
  • Min Stack LC 155 — the stack version of 'always know the extreme': elements leave from the end they entered, so a parallel list of running minimums is enough.
  • Shortest Subarray with Sum at Least K LC 862 — negative numbers break the plain sliding window; a monotonic deque over prefix sums takes its place.
  • Constrained Subsequence Sum LC 1425 — a DP where each state needs the maximum of the previous k DP values: run this exact deque over the DP array.
  • Longest Continuous Subarray With Absolute Diff Less Than or Equal to Limit LC 1438 — a variable-size window: keep a max-deque and a min-deque together and shrink while max - min > limit.
