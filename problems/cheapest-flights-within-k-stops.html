Cheapest Flights Within K Stops Medium

LeetCode #787 ↗
Status

Find the cheapest route between two cities that changes planes at most k times.

Problem

There are n cities numbered 0 to n - 1 and a list of one-way flights, flights[i] = [from, to, price].

Return the cheapest total price to travel from src to dst using at most k stops, where a stop is a city you land in on the way (so the route has at most k + 1 flights). If no such route exists, return -1.

  • There is at most one flight from any city to any other city, and no flight starts and ends in the same city.

Examples

Example 1
Input: n = 4, flights = [[0, 1, 100], [1, 2, 100], [2, 0, 100], [1, 3, 600], [2, 3, 200]], src = 0, dst = 3, k = 1
Output: 700
0 → 1 → 3 costs 700 with one stop. 0 → 1 → 2 → 3 costs only 400 but needs two stops.
Example 2
Input: n = 3, flights = [[0, 1, 100], [1, 2, 100], [0, 2, 500]], src = 0, dst = 2, k = 1
Output: 200
0 → 1 → 2 uses one stop and costs 200.
Example 3
Input: n = 3, flights = [[0, 1, 100], [1, 2, 100], [0, 2, 500]], src = 0, dst = 2, k = 0
Output: 500
No stops allowed, so only the direct flight counts.

Constraints

  • 1 <= n <= 100
  • 0 <= len(flights) <= n * (n - 1) / 2
  • flights[i] = [from, to, price] with from != to and 1 <= price <= 10^4
  • 0 <= src, dst, k < n and src != dst

Think first try before reading the solution

Why does plain Dijkstra fail here? Look at example 1: the cheapest way to reach city 2 uses a stop that the route to city 3 can no longer afford.
Count flights instead of stops: at most k + 1. What are the cheapest prices if you may take at most one flight? At most two? Each answer builds on the previous one.
Bellman-Ford with exactly k + 1 rounds. In each round relax every flight, but read prices from the previous round only (copy the array first), so a round can extend a route by one flight and no more.

Key idea

Without the stop limit this would be Dijkstra. The limit breaks it: a city's value now depends on two things, the price paid and the flights used. Dijkstra settles a city on its cheapest route and forgets the rest, but the cheapest route might have spent so many flights that it cannot finish in time, while a dearer route with fewer flights could.

Bellman-Ford measures exactly the right thing. Let prices after round i be the cheapest cost to each city using at most i flights. Round 0 knows only src (cost 0). Each round tries every flight u → v once, reading the previous round's price of u and writing an improved price for v into a fresh copy. Reading from the old array is what limits each round to one extra flight. After k + 1 rounds, prices[dst] is the answer. That is k + 1 passes over the E flights: O(k · E). It is the same idea as dynamic programming over "number of flights used".

Approaches from the obvious one to the one you want in an interview

Explore every route from src with a depth-first search that carries the cost so far and the number of flights still allowed. Reaching dst records a candidate price; running out of flights ends the route. A small prune helps: stop as soon as the cost is no better than the best complete price found so far.

Every city can branch to up to n - 1 others at each of the k + 1 levels, so the number of routes is up to O(n^(k+1)). For n = 100 and k = 10 that is hopeless, even with pruning.

Dry run

  1. Example 1, k = 1 (two flights): dfs(0) → 1 (100) → 2 (200): out of flights, not dst
  2. → 1 → 3 (700): dst reached, best = 700
  3. No other route within two flights reaches 3 → 700

Python

class Solution:
    def findCheapestPrice(self, n: int, flights: List[List[int]], src: int, dst: int, k: int) -> int:
        graph = defaultdict(list)
        for u, v, price in flights:
            graph[u].append((v, price))
        best = math.inf

        def dfs(city: int, cost: int, flights_left: int) -> None:
            nonlocal best
            if city == dst:
                best = min(best, cost)
                return
            if flights_left == 0 or cost >= best:  # out of flights, or already too expensive
                return
            for nxt, price in graph[city]:
                dfs(nxt, cost + price, flights_left - 1)

        dfs(src, 0, k + 1)                         # k stops = k + 1 flights
        return best if best < math.inf else -1
Time O(n^(k+1))Space O(k)

Up to n - 1 choices at each of k + 1 levels; the recursion is k + 1 deep.

When to use: Only to see the shape of the search; it does not survive large k.

Keep prices[c] = cheapest known cost to city c, starting with 0 at src and ∞ elsewhere. Repeat k + 1 times:

  1. new_prices = prices[:];
  2. for every flight u → v with price w: if prices[u] + w < new_prices[v], set new_prices[v];
  3. prices = new_prices.

By induction, after round i the list holds the cheapest prices using at most i flights: round i can only extend routes of at most i - 1 flights (read from the old list) by one more flight. Reading and writing the same list would let a single round chain several flights and break the limit. The answer is prices[dst], or -1 if it is still ∞.

Dry run

  1. Example 1, k = 1: round 0 → [0, ∞, ∞, ∞]
  2. Round 1 reads [0, ∞, ∞, ∞]: only 0 → 1 helps → [0, 100, ∞, ∞]
  3. Round 2 reads [0, 100, ∞, ∞]: 1 → 2 gives 200, 1 → 3 gives 700 → [0, 100, 200, 700]
  4. 2 → 3 would give 400, but it reads city 2's round-1 price (∞), so the three-flight route is not allowed
  5. Answer prices[3] = 700

Python

class Solution:
    def findCheapestPrice(self, n: int, flights: List[List[int]], src: int, dst: int, k: int) -> int:
        prices = [math.inf] * n
        prices[src] = 0
        for _ in range(k + 1):                     # k stops = at most k + 1 flights
            new_prices = prices[:]                 # read last round, write this round
            for u, v, price in flights:
                if prices[u] + price < new_prices[v]:
                    new_prices[v] = prices[u] + price
            prices = new_prices
        return prices[dst] if prices[dst] < math.inf else -1
Time O(k · E)Space O(n)

k + 1 rounds, each one pass over the E flights plus an O(n) copy.

When to use: The cleanest answer: short, visibly respects the limit, and needs no heap.

Watch it run

Make the number of flights part of the state. The heap holds (cost, city, flights_used) and pops the cheapest state first, so the first time dst is popped its cost is the answer. Two rules keep it correct and fast:

  • never push a state that would exceed k + 1 flights;
  • skip a popped city if an earlier (so no more expensive) pop reached it with no more flights; that earlier state can do everything this one can, for no more money. A pop that used fewer flights must still be expanded.

In the worst case each city is expanded once per possible flight count: O(k · E · log(k · E)).

Dry run

  1. Example 1, k = 1: heap [(0, 0, 0)]. Pop → push (100, 1, 1)
  2. Pop (100, 1, 1) → push (200, 2, 2) and (700, 3, 2)
  3. Pop (200, 2, 2): out of flights (2 = k + 1), do not expand
  4. Pop (700, 3, 2): it is dst → 700

Python

class Solution:
    def findCheapestPrice(self, n: int, flights: List[List[int]], src: int, dst: int, k: int) -> int:
        graph = defaultdict(list)
        for u, v, price in flights:
            graph[u].append((v, price))
        fewest = {}                                # city -> fewest flights among its earlier (cheaper) pops
        heap = [(0, src, 0)]                       # (cost so far, city, flights used)
        while heap:
            cost, city, used = heapq.heappop(heap)
            if city == dst:
                return cost                        # cheapest valid way to reach dst
            if used == k + 1:                      # no flights left
                continue
            if city in fewest and fewest[city] <= used:
                continue                           # a cheaper pop got here with no more flights
            fewest[city] = used
            for nxt, price in graph[city]:
                heapq.heappush(heap, (cost + price, nxt, used + 1))
        return -1
Time O(k · E · log(k · E))Space O(k · E)

A city can be expanded once per distinct flight count; each expansion pushes its flights.

When to use: Often faster in practice when the limit is loose, and the 'budget in the state' idea generalises.

Common mistakes

  • Updating prices in place during a round. A price written early in the round can be read again later in the same round, chaining two or more flights. With [[0,1,1],[0,2,5],[1,2,1],[2,3,1]], k = 1, in-place updates return 3 (three flights) instead of 6.
  • Off by one: k stops means k + 1 flights, so run k + 1 rounds, not k.
  • Plain Dijkstra with a visited set: city 2 in example 1 would be settled at 200 via two flights, and the one-stop-only route to city 3 is never found correctly.
  • Returning prices[dst] while it is still infinity. Convert 'unreachable within the limit' to -1.
  • In the heap version, skipping a city just because it was popped before. A later pop that used fewer flights can still lead somewhere the earlier one could not.

Python notes

  • new_prices = prices[:] copies the list. Writing into the copy while reading from the original is the whole trick.
  • math.inf + 100 is still math.inf, so an unreachable city never produces a finite price by accident.
  • The heap version stores triples (cost, city, flights_used); tuples compare by cost first.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Network Delay Time LC 743 — the same shortest-route question with no limit on flights: Dijkstra in O(E log V).
  • Minimum Cost to Reach Destination in Time LC 1928 — a budget on total time instead of on flights. Again two quantities per city: run Dijkstra on cost but keep a city only when it is reached faster than before.
  • Shortest Path in a Grid with Obstacles Elimination LC 1293 — BFS over states (cell, eliminations left): the same trick of putting the remaining budget into the state.
  • What if you must also return the route? — keep a parent array per round alongside prices (copy it with the prices) and walk back from dst.
  • What if some prices could be negative? — Bellman-Ford already handles that. Without a stop limit, a further round that still lowers a price would reveal a negative cycle.
