Boats to Save People Medium 250

LeetCode #881 ↗
Status

Find the fewest boats that carry everyone when a boat holds at most two people and a weight limit.

Problem

A list people gives the weight of each person waiting to cross a river. You have as many identical boats as you need.

  • A boat carries at most two people at the same time.
  • The combined weight on a boat must not exceed limit.
  • Every single person weighs at most limit, so anyone can always cross alone.

Return the smallest number of boats that gets everyone across.

Examples

Example 1
Input: people = [4, 1, 3, 2], limit = 5
Output: 2
Boat 1 carries the weights 1 and 4, boat 2 carries 2 and 3. Both boats weigh exactly 5.
Example 2
Input: people = [1, 9, 9, 3, 3], limit = 10
Output: 3
Boat 1: 1 and 9. Boat 2: the other 9 alone, because 3 + 9 = 12 is too much. Boat 3: 3 and 3.
Example 3
Input: people = [5, 5, 5], limit = 5
Output: 3
Everyone weighs the limit, so no two people can share a boat.

Constraints

  • 1 <= len(people) <= 5 * 10^4
  • 1 <= people[i] <= limit <= 3 * 10^4

Key idea

A boat carries one or two people, so the number of boats is n minus the number of boats that carry two. Fewer boats means more pairs.

Think about the heaviest person, who is the hardest to pair. Compare them with the lightest person who is left:

  • If even the lightest person is too much with them (light + heavy > limit), everyone else weighs at least as much as the lightest, so nobody can share their boat. They go alone.
  • If the two fit, send them together. This never hurts. Suppose the best plan seats the heaviest person with someone of weight x, and the lightest person elsewhere. Swap x and the lightest. The first boat still fits, because the lightest weighs no more than x. The second boat now holds x and someone no heavier than the heaviest, and x plus the heaviest already fit, so it fits too.

After sorting, this is two pointers from both ends: each round the heaviest person leaves, and the lightest leaves with them when they fit. Sorting costs O(n log n) and the walk costs O(n).

Approaches from the obvious one to the one you want in an interview

Sort the weights from heaviest to lightest. Take the heaviest person who has not boarded yet and start a new boat for them. Then scan the rest of the list for the heaviest person who has not boarded and still fits with them. If one exists, that person boards too.

Because the list is sorted, the first person who fits is the heaviest possible partner. The plan is right, but looking for a partner costs a scan per boat. If nobody can share (everyone is too heavy), each of the n boats scans the whole list: about n²/2 comparisons, over a billion for 50,000 people.

Dry run

  1. people = [4, 1, 3, 2], limit = 5 → sorted from heaviest [4, 3, 2, 1]
  2. Boat 1: 4 boards. Scan: 4 + 3 = 7 > 5, 4 + 2 = 6 > 5, 4 + 1 = 5 ≤ 5 → 1 boards too.
  3. Boat 2: 3 boards. Scan: 3 + 2 = 5 ≤ 5 → 2 boards too. Everyone is on board: 2 boats.

Python

class Solution:
    def numRescueBoats(self, people: List[int], limit: int) -> int:
        people = sorted(people, reverse=True)       # heaviest first
        n = len(people)
        boarded = [False] * n
        boats = 0
        for i in range(n):
            if boarded[i]:
                continue                            # already riding with someone heavier
            boarded[i] = True                       # person i starts a new boat
            boats += 1
            for j in range(i + 1, n):               # look for the heaviest partner who still fits
                if not boarded[j] and people[i] + people[j] <= limit:
                    boarded[j] = True
                    break
        return boats
Time O(n²)Space O(n)

Sorting is O(n log n); the nested scan for partners is O(n²) in the worst case; the flags take O(n).

When to use: A correct stepping stone that shows the greedy choice; too slow for the largest inputs.

Sort ascending and keep two pointers: light at the lightest person who has not boarded and heavy at the heaviest. Each round starts one boat:

  • the heaviest person always boards, so heavy moves left and the boat count goes up by one;
  • if people[light] + people[heavy] <= limit, the lightest person boards too, so light moves right.

Stop when the pointers pass each other. The condition is light <= heavy, not <, so that a last single person still gets a boat.

Why the lightest? If even the lightest person cannot share with the heaviest, nobody can. If the lightest can, pairing them is at least as good as any other pairing (see the Intuition). Sorting costs O(n log n), and the walk is O(n).

Dry run

  1. people = [1, 9, 9, 3, 3], limit = 10 → sorted [1, 3, 3, 9, 9], light = 0, heavy = 4
  2. Boat 1: 1 + 9 = 10 ≤ 10 → both board. light = 1, heavy = 3.
  3. Boat 2: 3 + 9 = 12 > 10 → the 9 goes alone. Only heavy moves: heavy = 2.
  4. Boat 3: 3 + 3 = 6 ≤ 10 → both board. The pointers have passed each other: 3 boats.

Python

class Solution:
    def numRescueBoats(self, people: List[int], limit: int) -> int:
        people.sort()                               # lightest ... heaviest
        light, heavy = 0, len(people) - 1
        boats = 0
        while light <= heavy:                       # <= so a last single person still gets a boat
            if people[light] + people[heavy] <= limit:
                light += 1                          # the lightest fits with the heaviest: they share
            heavy -= 1                              # the heaviest leaves in this boat either way
            boats += 1
        return boats
Time O(n log n)Space O(1)

Sorting dominates; the walk visits each person once. Extra space is O(1) besides the sort (Python's sort may use up to O(n)).

When to use: The standard answer. Mention the swap argument for why pairing the lightest with the heaviest is safe.

Common mistakes

  • Pairing neighbours in sorted order. With [1, 2, 3, 4] and limit 5, the pairs (1, 2) and (3, 4) fail because 3 + 4 = 7, so you would use 3 boats. Pairing the lightest with the heaviest, (1, 4) and (2, 3), needs only 2.
  • Looping while light < heavy. When the pointers meet there is still one person left who needs a boat. With [5, 5, 5] and limit 5 the strict version reports 2 boats instead of 3. Use light <= heavy.
  • Moving light even when the pair does not fit. The lightest person would then be dropped without ever boarding, and the count comes out too small. Only heavy moves every round; light moves only on a fit.
  • Assuming a boat can take a third person when the weights are small. The two-person cap holds no matter how large limit is.

Python notes

  • sorted(people) returns a new sorted list and leaves the input alone; people.sort() sorts in place.
  • In the loop, heavy -= 1 and boats += 1 always run, while light += 1 runs only on a fit. Keeping the always-run lines outside the if is what makes the loop short.
  • Weights are at most limit <= 3 * 10^4, so a counting sort (an array of limit + 1 counters) can replace sorted and bring the total down to O(n + limit). Most solutions simply sort.
