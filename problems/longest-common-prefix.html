Longest Common Prefix Easy 250

LeetCode #14 ↗
Status

Find the longest string that every string in a list starts with.

Problem

You are given a list of strings strs. Return the longest common prefix of all of them: the longest string that every string in the list starts with.

  • A prefix is a piece cut from the front of a string. "pe" is a prefix of "pencil"; "enc" is not, even though it appears inside it.
  • If the strings share nothing at the start, return the empty string "".
  • The list holds at least one string, and a string in it may be empty.

Examples

Example 1
Input: strs = ["pencil", "pen", "pepper"]
Output: "pe"
All three start with "p" and then "e". Column 2 holds "n", "n" and "p", so the shared part stops there.
Example 2
Input: strs = ["apple", "banana", "cherry"]
Output: ""
The very first letters are "a", "b" and "c", so nothing is shared.
Example 3
Input: strs = ["interview", "internet", "interval"]
Output: "inter"
The first five letters agree; the sixth letters are "v", "n" and "v".

Constraints

  • 1 <= len(strs) <= 200
  • 0 <= len(strs[i]) <= 200
  • strs[i] contains only lowercase English letters

Think first try before reading the solution

The answer can never be longer than the shortest string in the list. Should you compare whole strings, or one letter at a time?
Write the strings one under another, like rows of a table. Look at the first letter of every string, then the second letter of every string, and so on. Which column ends the shared part?
Walk the columns of the first string. At column i, every other string must have a letter there, and it must equal the first string's letter. Return first[:i] the moment one of them fails.

Key idea

A common prefix is shared from the left, one letter at a time. The strings agree in column 0, then in column 1, and so on, until the first column where some string has a different letter or has run out of letters. Everything left of that column is the answer. Nothing to its right can matter, because a prefix is not allowed to skip a column.

That points to a vertical scan: take the letter of the first string in column i and compare it with the same column of every other string. The first failure ends the whole search. You never read a letter to the right of the failing column, so the work depends on how long the answer is, not on how long the strings are.

The other natural idea is a horizontal scan: start with the first string as the prefix, trim it against the second string, then trim the result against the third, and so on. It is correct and also linear, but it reads whole strings even when a later string (say, the last one) would have ended the search at column 0.

Approaches from the obvious one to the one you want in an interview

Take the first string as the current prefix. For each following string, compare letter by letter from the left and cut the prefix down to the part the two strings share. After the last string, whatever is left is shared by all of them. If the prefix ever becomes empty you can stop at once.

It is correct and linear in the total number of letters, but its work depends on the order of the strings. With ["abcdefgh", "abcdefgh", "abcdefgh", "xyz"] it reads three full strings before the last one reveals that the answer is empty, while a column-by-column scan sees the mismatch in column 0.

Dry run

  1. strs = ["pencil", "pen", "pepper"], prefix = "pencil"
  2. strs[1] = "pen": "pencil" and "pen" agree for 3 letters, then "pen" ends → prefix = "pen"
  3. strs[2] = "pepper": agree for "p", "e", then "n" meets "p" → prefix = "pe"
  4. No strings left → return "pe"

Python

class Solution:
    def longestCommonPrefix(self, strs: List[str]) -> str:
        prefix = strs[0]                       # the answer is never longer than any single string
        for s in strs[1:]:
            j = 0                              # how many leading letters prefix and s share
            while j < len(prefix) and j < len(s) and prefix[j] == s[j]:
                j += 1
            prefix = prefix[:j]                # keep only the shared part
            if not prefix:                     # nothing shared: no later string can change that
                break
        return prefix
Time O(n·m)Space O(m)

n strings of up to m letters: each comparison reads at most m letters. The trimmed prefix is a new string of up to m letters.

When to use: A good first answer. Its weakness is reading whole strings that a later string would have made irrelevant.

Watch it run

Walk the columns of the first string, left to right. In column col, check every other string: it must have a letter at index col, and that letter must equal first[col]. The first time a string runs out (col == len(s)) or shows a different letter, return first[:col], the columns that did pass. If every column passes, the first string itself is the answer.

Because the scan stops at the first bad column, no letter to the right of it is ever read. The work is about n × (length of the answer + 1) comparisons, which is never more than the total number of letters, and a mismatch in column 0 costs only one pass over the strings.

Dry run

  1. strs = ["pencil", "pen", "pepper"], first = "pencil"
  2. column 0: "p" in "pen" and "pepper" → match
  3. column 1: "e" in "pen" and "pepper" → match
  4. column 2: "n" in "pen" → match; "pepper" has "p" → mismatch, return first[:2] = "pe"

Python

class Solution:
    def longestCommonPrefix(self, strs: List[str]) -> str:
        first = strs[0]
        for col in range(len(first)):               # walk the columns of the first string
            ch = first[col]
            for s in strs[1:]:
                if col == len(s) or s[col] != ch:   # s ran out of letters, or has a different one
                    return first[:col]              # the columns before this one were all shared
        return first                                # no column failed: first is a prefix of every string
Time O(n·m)Space O(1)

At most n comparisons per column and at most m columns; no extra memory besides the returned string.

When to use: The interview answer. It does the least work, because it stops at the first mismatch anywhere.

Watch it run

Put the strings in alphabetical order. The first and the last string of that order are the two that differ the most, and every string between them has to start with whatever those two share: a string that left their shared prefix would sort before the smallest or after the largest. So the common prefix of the whole list equals the common prefix of just min(strs) and max(strs), and only those two strings need a letter-by-letter comparison.

Finding the minimum and the maximum is one pass each, with no sorting. This is exactly what the standard library's os.path.commonprefix does.

Dry run

  1. strs = ["pencil", "pen", "pepper"]: smallest = "pen", largest = "pepper"
  2. "p" = "p", "e" = "e", then "n" meets "p" → mismatch at index 2 → return "pe"

Python

class Solution:
    def longestCommonPrefix(self, strs: List[str]) -> str:
        smallest, largest = min(strs), max(strs)      # alphabetical first and last
        for i, (a, b) in enumerate(zip(smallest, largest)):   # zip stops at the shorter string
            if a != b:
                return smallest[:i]                   # first column where the two disagree
        return smallest                               # smallest is a prefix of largest
Time O(n·m)Space O(1)

min and max compare strings (up to m letters each) n times; then one comparison of two strings.

When to use: Short and idiomatic in Python. Be ready to explain why the two extreme strings are enough.

Common mistakes

  • Reading s[col] before checking that s is long enough. With ["care", "car"], column 3 of "car" does not exist and raises IndexError. Test col == len(s) first.
  • Returning first[:col + 1] at a mismatch. Column col is the column that failed, so the answer is first[:col]: the columns before it.
  • Falling off the end of the loop without a return. When no column fails (for example ["ab", "abc"]), the first string itself is the answer, and a function that just ends returns None.
  • Using in instead of a prefix test. "enc" in "pencil" is True, yet "enc" is not a prefix. Compare letters from index 0, or use startswith.
  • Not testing an empty string in the list. Both ["", "abc"] and ["abc", ""] must return ""; the col == len(s) check is what catches the second one.

Python notes

  • strs[1:] makes a copy of the list from index 1 onward (O(n) extra pointers). It is fine here; the index-based loop for i in range(1, len(strs)) avoids the copy.
  • s.startswith(prefix) is the built-in prefix test, and s[:j] slices the first j letters (it never raises, even when j is larger than the string).
  • min(strs) and max(strs) compare strings alphabetically (letter by letter, and a shorter string that is a prefix of a longer one counts as smaller).
  • The standard library has this function: os.path.commonprefix(strs) finds the common prefix of any list of strings, letter by letter, and it uses the same min/max idea as the last approach. Despite the name it knows nothing about paths.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Implement Trie (Prefix Tree) LC 208 — a trie stores every shared prefix once. The common prefix of all inserted words is the path from the root that keeps exactly one child and does not pass a word that ends early.
  • Search Suggestions System LC 1268 — after each typed letter you need up to three products that start with the typed prefix: sort the products once, then binary-search the block of words that share the prefix (or walk a trie).
  • Longest Common Subsequence LC 1143 — the letters no longer have to be at the start or next to each other, so a column scan cannot work; a two-dimensional table of prefixes of the two strings does.
  • Longest common suffix — same scan from the right: compare s[-1 - i] in every string, or reverse each string, run this solution, and reverse the answer.
  • What if the strings are huge or live on different machines? — the min/max trick helps: each machine reports only its alphabetically smallest and largest string, and the answer is the common prefix of the overall smallest and largest.
