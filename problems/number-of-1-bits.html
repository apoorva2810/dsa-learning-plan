Number of 1 Bits Easy

LeetCode #191 ↗
Status

Count how many of the binary digits of a number are 1.

Problem

Given a non-negative integer n, return how many of the digits in its binary representation are 1. This count is called the Hamming weight or popcount (short for "population count").

For example, 11 is 1011 in binary, which contains three 1s.

Examples

Example 1
Input: n = 11
Output: 3
11 is 1011 in binary: three 1s.
Example 2
Input: n = 128
Output: 1
128 is 10000000: a single 1.
Example 3
Input: n = 2147483645
Output: 30
It is 1111111111111111111111111111101: 31 digits, and only the digit for 2 is 0.

Constraints

  • 1 <= n <= 2^31 - 1
  • (the older version allowed any unsigned 32-bit value, 0 <= n <= 2^32 - 1; every solution here accepts that too)

Think first try before reading the solution

Write n in binary and count the 1s by eye first. What is the cheapest test for "is the lowest bit a 1"? (n & 1, or n % 2.)
After testing the lowest bit, shift the number right (n >>= 1) to bring the next bit down. Stop when n is 0. How many rounds is that at most for a 32-bit number?
Can you skip the zeros? Take a few numbers in binary and compare n with n & (n - 1). Which bit disappears? Then count how many times you can apply it before the number reaches 0.

Key idea

The direct way looks at the bits one at a time: test the lowest bit with n & 1, shift right to expose the next one, and repeat. That visits every position between the lowest bit and the highest 1, zeros included, so 128 (a single 1 followed by seven 0s) takes eight rounds to count one bit.

You can jump from one 1 straight to the next. Subtracting 1 works like borrowing in decimal (1000 - 1 = 0999): the lowest 1 becomes 0 and every 0 below it becomes 1. Compare n with n - 1. The bits above that spot are identical, and the bits from that spot downward are all opposite. AND keeps only the positions where both numbers have a 1, so n & (n - 1) is n with its lowest 1 erased and nothing else changed.

Repeat until nothing is left and count the rounds. The loop body runs once per 1-bit, so it costs O(k) for k set bits (at most 32 for a 32-bit number). This is Brian Kernighan's algorithm.

Approaches from the obvious one to the one you want in an interview

Look at the lowest bit with n & 1 (AND with 1 keeps only that bit), add it to the count, then shift n right by one so the next bit becomes the lowest. Stop when n is 0.

It is correct and needs no extra memory. The cost is one round per binary digit, up to 32 here, including the zeros: counting the single 1 in 128 takes eight rounds.

Dry run

  1. n = 11 is 1011
  2. lowest bit 1: count = 1, shift: 101
  3. lowest bit 1: count = 2, shift: 10
  4. lowest bit 0: nothing to add, shift: 1
  5. lowest bit 1: count = 3, shift: 0. Stop: return 3

Python

class Solution:
    def hammingWeight(self, n: int) -> int:
        count = 0
        while n:
            count += n & 1               # 1 if the lowest bit is set, else 0
            n >>= 1                      # bring the next bit down
        return count
Time O(log n)Space O(1)

One round per binary digit of n, at most 32 for the inputs here, so effectively constant.

When to use: A fine first answer. Say that it visits zeros it does not need to.

Watch it run

n & (n - 1) is n with its lowest set bit erased. Subtracting 1 flips that bit to 0 and every 0 below it to 1, while the bits above stay the same. AND with the original keeps only what both numbers share, and below and at that position they share nothing.

Apply it until n becomes 0 and count the rounds. Each round removes exactly one 1, so the loop runs once per set bit and never touches a zero. 128 takes one round, 2^31 - 1 takes 31.

Dry run

  1. n = 11 is 1011
  2. 1011 & 1010 = 1010: the lowest 1 is gone, count = 1
  3. 1010 & 1001 = 1000: count = 2
  4. 1000 & 0111 = 0000: the borrow ran through three zeros, count = 3
  5. n is 0: return 3

Python

class Solution:
    def hammingWeight(self, n: int) -> int:
        count = 0
        while n:
            n &= n - 1                   # erase the lowest 1-bit
            count += 1                   # one set bit accounted for
        return count
Time O(k)Space O(1)

k is the number of set bits, at most 32. Each round removes one of them.

When to use: The interview answer. It also gives you the n & (n - 1) tool used for powers of two.

Watch it run

bin(n) turns the number into text like '0b1011', and str.count("1") counts the 1 characters. Python 3.10 and later also has the built-in n.bit_count().

This is the shortest correct answer and perfectly fine in everyday code. In an interview it shows little, so use it to check your bit-twiddling version, not to replace it.

Python

class Solution:
    def hammingWeight(self, n: int) -> int:
        return bin(n).count("1")         # bin(11) == '0b1011'; on Python 3.10+ n.bit_count() also works
Time O(log n)Space O(log n)

Builds a string with one character per binary digit.

When to use: Production code, quick checks, or when the problem is not about the technique.

Common mistakes

  • Looping while n: n >>= 1 on a negative number. Python keeps copying the sign bit, so n never reaches 0 and the loop never ends. The inputs here are non-negative; for a signed 32-bit value apply n & 0xFFFFFFFF first.
  • Counting the wrong digits: str(n).count("1") counts decimal digits. Use bin(n).count("1").
  • Using n / 2 to shift. In Python 3 / returns a float, and then n & 1 raises a TypeError. Use n >> 1 or n // 2.
  • Running a fixed number of rounds that is too small. while n: stops by itself when the last 1 has been handled; a for loop must cover all 32 positions.

Python notes

  • bin(n) returns text such as '0b1011', so bin(n).count("1") counts the 1s. The 0b prefix contains no 1.
  • n.bit_count() (Python 3.10 and later) is the built-in popcount, and n.bit_length() is the number of binary digits.
  • n & 1 is 1 when n is odd and 0 when it is even. n >> 1 equals n // 2 for non-negative n.
  • Python integers have unlimited size, so nothing overflows, but nothing wraps at 32 bits either. A negative number needs n & 0xFFFFFFFF first, which maps -1 to 4294967295 (thirty-two 1s).

Follow-up questions

What an interviewer might ask next, and what changes.

  • Counting Bits LC 338 — the popcount of every number from 0 to n: reuse earlier answers (dp[i >> 1] + (i & 1)) instead of recounting each number.
  • Reverse Bits LC 190 — another fixed-width 32-bit problem, where the loop must run all 32 times because leading zeros matter.
  • Power of Two LC 231 — a power of two has exactly one set bit, so n > 0 and n & (n - 1) == 0: one Kernighan step and a comparison.
  • Hamming Distance LC 461 — the number of positions where two numbers differ is the popcount of their XOR: bin(x ^ y).count("1").
  • Total Hamming Distance LC 477 — sum over all pairs in a list. Do not compare pairs. For each bit position count how many numbers have a 1 there (ones) and add ones * (n - ones).
  • What if it is called millions of times? — precompute the popcount of every 8-bit (or 16-bit) value in a table and add up four lookups, or use the built-in n.bit_count().
