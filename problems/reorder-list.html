Reorder List Medium

LeetCode #143 ↗
Status

Re-link a list in place into the order first, last, second, second-to-last, and so on.

Problem

You are given head, the first node of a linked list L0 → L1 → … → Ln-1 → Ln. Reorder it in place to

L0 → Ln → L1 → Ln-1 → L2 → Ln-2 → …

that is, alternately take one node from the front and one from the back. Change the next pointers, not the values. The function returns nothing; the list starting at head must end up in the new order.

Examples

Example 1
Input: head = [1, 2, 3, 4]
Output: [1, 4, 2, 3]
Example 2
Input: head = [1, 2, 3, 4, 5]
Output: [1, 5, 2, 4, 3]
Front 1, back 5, front 2, back 4, and the middle node 3 ends the list.

Constraints

  • 1 <= number of nodes <= 5 * 10^4
  • 1 <= Node.val <= 1000

Think first try before reading the solution

Write the target order as first, last, second, second-to-last, … You need nodes from both ends. Which end is hard to reach in a singly linked list?
Copying the nodes into a Python list gives you index access from both ends, but costs O(n) memory. To do it in O(1), make the back half walkable from the end by reversing it.
Three steps: find the middle with slow/fast pointers, cut there and reverse the second half, then weave the two halves together by alternating one node from each.

Key idea

The new order needs the nodes from the back in reverse order: Ln, then Ln-1, and so on. A singly linked list only walks forwards, so either remember the nodes (an array gives you both ends) or change the list so that the back half does walk backwards.

The O(1)-memory solution is three small routines you already know, glued together:

  1. Find the middle with slow/fast pointers and cut the list in two: 1 → 2 → 3 and 4 → 5.
  2. Reverse the second half: 5 → 4. Its head is now the old last node.
  3. Weave the halves: take one node from the first half, one from the second, and repeat. This is a merge that alternates instead of comparing.

The first half gets the extra node when the length is odd, so the weave starts and ends with first-half nodes.

Approaches from the obvious one to the one you want in an interview

Do literally what the target order says. Starting at the head: walk to the last node, unlink it, and insert it right after the current node. Then jump two nodes ahead (over the node you just placed) and repeat while at least two nodes remain after the current one.

It uses no extra memory, but finding the tail is a walk of up to n nodes, and it happens about n/2 times: O(n²). For 5 · 10⁴ nodes that is over a billion steps.

Dry run

  1. 1 → 2 → 3 → 4 → 5: tail is 5 → insert after 1 → 1 → 5 → 2 → 3 → 4
  2. jump to 2: tail is 4 → insert after 2 → 1 → 5 → 2 → 4 → 3
  3. jump to 3: fewer than two nodes after it → stop

Python

class Solution:
    def reorderList(self, head: Optional[ListNode]) -> None:
        cur = head
        while cur and cur.next and cur.next.next:
            before_tail = cur                    # walk to the node before the tail
            while before_tail.next.next:
                before_tail = before_tail.next
            tail = before_tail.next
            before_tail.next = None              # unlink the tail ...
            tail.next = cur.next                 # ... and splice it in after cur
            cur.next = tail
            cur = tail.next                      # skip over the node just placed
Time O(n²)Space O(1)

About n/2 rounds, each walking to the current tail.

When to use: Only to show why reaching the back is the real problem.

Copy every node reference into a Python list. Now both ends are one index away: i starts at 0 and j at the end. Link nodes[i] → nodes[j] → nodes[i + 1], move both indices inward, and repeat until they meet. The node where they meet is the new tail, so set its next to None.

O(n) time, but the list of nodes costs O(n) extra memory, which the in-place version avoids.

Dry run

  1. nodes = [1, 2, 3, 4, 5], i = 0, j = 4
  2. 1 → 5, then 5 → 2; i = 1, j = 3
  3. 2 → 4, then 4 → 3; i = 2, j = 2 → stop; 3.next = None

Python

class Solution:
    def reorderList(self, head: Optional[ListNode]) -> None:
        nodes = []
        cur = head
        while cur:                               # random access to every node
            nodes.append(cur)
            cur = cur.next
        i, j = 0, len(nodes) - 1
        while i < j:
            nodes[i].next = nodes[j]             # a front node points to a back node
            i += 1
            if i == j:
                break
            nodes[j].next = nodes[i]             # the back node points to the next front node
            j -= 1
        nodes[i].next = None                     # the meeting node is the new tail
Time O(n)Space O(n)

One pass to collect, one pass to relink; the node list holds n references.

When to use: Quick to get right; mention it, then offer the O(1)-memory version.

  1. Middle: slow = head, fast = head.next; move slow 1 and fast 2 while fast and fast.next. Then slow is the last node of the first half (the first half gets the extra node when n is odd).
  2. Cut and reverse: second = slow.next, slow.next = None, then reverse second with the usual prev/cur loop.
  3. Weave: with first = head and second = the reversed half's head, save both next pointers, link first → second → first's old next, and advance both. Stop when second is None.

Every node is visited a constant number of times and only a handful of pointers are stored: O(n) time, O(1) memory.

Dry run

  1. 1 → 2 → 3 → 4 → 5: slow stops at 3 → halves 1 → 2 → 3 and 4 → 5
  2. reverse the second half → 5 → 4
  3. weave: 1 → 5 → 2, then 2 → 4 → 3; second is None → done: 1 → 5 → 2 → 4 → 3

Python

class Solution:
    def reorderList(self, head: Optional[ListNode]) -> None:
        # 1. find the middle: slow stops on the last node of the first half
        slow, fast = head, head.next
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
        # 2. cut the list in two and reverse the second half
        second = slow.next
        slow.next = None                         # the first half now ends here
        prev = None
        while second:
            nxt = second.next
            second.next = prev
            prev, second = second, nxt
        # 3. weave: one node from the front half, one from the reversed back half
        first, second = head, prev
        while second:                            # the back half is never longer
            first_next, second_next = first.next, second.next
            first.next = second
            second.next = first_next
            first, second = first_next, second_next
Time O(n)Space O(1)

Three linear passes (middle, reverse, weave) and a fixed number of pointers.

When to use: The interview answer: it shows you can combine three standard list routines.

Common mistakes

  • Forgetting to cut the first half (slow.next = None): its last node still points into the second half, which after the reversal creates a cycle and an infinite weave.
  • Choosing the wrong middle: the second half must not be longer than the first. Starting fast = head.next (or using while fast.next and fast.next.next) leaves the extra node in the first half.
  • Weaving without saving both next pointers first: after first.next = second the rest of the first half is lost.
  • Returning a new list or the head: the function must modify the given list in place and return None; the checker reads the original head afterwards.
  • Swapping values instead of nodes passes the tests but ignores the rule that only links may change.

Python notes

  • The official signature returns None. Tests on this site use check_arg=0: they inspect the list starting at the original head after your function returns.
  • first_next, second_next = first.next, second.next saves both pointers in one line before any of them changes.
  • while second: is enough for the weave, because the second half is never longer than the first.
