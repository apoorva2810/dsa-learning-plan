Design HashMap Easy 250

LeetCode #706 ↗
Status

Build your own hash map from integer keys to integer values (put, get, remove) without using dict.

Problem

Design your own hash map (a key-value store) for integers, without using Python's built-in dict.

Implement the class MyHashMap:

  • MyHashMap() creates an empty map.
  • put(key, value) stores the pair. If key is already in the map, its value is replaced by value.
  • get(key) returns the value stored for key, or -1 if the map has no such key.
  • remove(key) deletes the key and its value. If the key is not there, nothing happens.

Keys and values are integers from 0 to 10^6.

Examples

Example 1
Input: ["MyHashMap","put","put","get","get","put","get","remove","get"] [[],[1,10],[6,60],[6],[2],[1,11],[1],[6],[6]]
Output: [null, null, null, 60, -1, null, 11, null, -1]
With 5 buckets, keys 1 and 6 both leave remainder 1 and share a bucket. put(1, 11) replaces the old value of key 1, and after remove(6) the key 6 is gone.
Example 2
Input: ["MyHashMap","put","put","get"] [[],[3,5],[3,8],[3]]
Output: [null, null, null, 8]
A second put on the same key replaces the value; it does not add a second pair.
Example 3
Input: ["MyHashMap","get","remove","put","get"] [[],[0],[0],[0,0],[0]]
Output: [null, -1, null, null, 0]
A stored value of 0 is a real value. Only a missing key gives -1.

Constraints

  • 0 <= key, value <= 10^6
  • at most 10^4 calls in total to put, get and remove

Think first try before reading the solution

Key idea

A hash map is a hash set whose entries carry a value. Everything that made the set fast carries over: the key decides its own bucket with key % B, and only the short list in that bucket, the chain, is searched. The only new idea is what the chain stores: each entry is a [key, value] pair, so get returns the value that sits next to the matching key.

put has two jobs. If the key is already in the chain, overwrite the value in place; otherwise append a new pair. A second pair for an existing key would leave the old value behind, and get might find that stale one first. remove finds the pair and deletes it, and get returns -1 when the chain has no such key.

Notice that a chain is just the slow list-of-pairs map scanned from the start. Hashing does not remove that scan; it splits one big scan into B small ones and lets the key choose which small one to run. With a sensible B the chains stay short, and every operation is O(1) on average.

Approaches from the obvious one to the one you want in an interview

Keep all the pairs in a single Python list. Every operation scans it from the start for the key: put overwrites the pair if it finds the key and appends otherwise, get returns the matching value (or -1), and remove pops the matching pair. It is correct for any key range, but nothing in the key says where its pair is, so each call scans up to n pairs.

Python

class MyHashMap:
    def __init__(self):
        self.pairs = []                      # [key, value] pairs, in no particular order

    def put(self, key: int, value: int) -> None:
        for pair in self.pairs:              # O(n): look for the key
            if pair[0] == key:
                pair[1] = value              # key exists: overwrite its value
                return
        self.pairs.append([key, value])      # new key

    def get(self, key: int) -> int:
        for k, v in self.pairs:              # O(n)
            if k == key:
                return v
        return -1

    def remove(self, key: int) -> None:
        for i, pair in enumerate(self.pairs):    # O(n)
            if pair[0] == key:
                self.pairs.pop(i)
                return
Time O(n) per callSpace O(n)

n is the number of stored pairs; every call scans them.

When to use: A baseline. Notice that the optimal version below reuses this exact code for each bucket.

Keys are at most 10^6, so use the key as an index into a list of 10^6 + 1 values. Store -1 in a slot to mean "no value". That works because stored values are never negative, so -1 cannot be confused with a real value. put writes the slot, get reads it, remove writes -1 back. Every call is one list access: O(1) in the worst case.

The price is memory: a million slots whatever the number of pairs, and the idea is impossible if keys can be huge. Hashing keeps the O(1) speed with a table whose size you choose.

Python

class MyHashMap:
    def __init__(self):
        self.table = [-1] * (10 ** 6 + 1)    # table[key] is the value, or -1 if the key is absent

    def put(self, key: int, value: int) -> None:
        self.table[key] = value

    def get(self, key: int) -> int:
        return self.table[key]

    def remove(self, key: int) -> None:
        self.table[key] = -1
Time O(1) per callSpace O(R), R = size of the key range

One list access per call; the table has R = 10^6 + 1 slots no matter how many pairs it holds.

When to use: When the key range is small and known, and there is a safe value that means 'empty'.

Make B buckets, each an empty list, and use key % B to choose the bucket for a key. A bucket holds the [key, value] pairs whose keys landed there. Inside one bucket, run the plain scan from the first approach:

  • put(key, value): if a pair with this key is in the bucket, overwrite its value; otherwise append [key, value].
  • get(key): return the value of the matching pair, or -1 if the bucket has none.
  • remove(key): delete the matching pair if there is one.

Keys that collide share a chain, which is fine because each chain is short: with a prime B like 1009 and at most 10^4 calls it holds about ten pairs. Average cost O(1) (more precisely O(n / B)); the worst case is O(n) if every key lands in one bucket.

Dry run

  1. 5 buckets for the example: put(1, 10) → 1 % 5 = 1 → bucket 1 = [1→10]
  2. put(6, 60) → 6 % 5 = 1 → collision → bucket 1 = [1→10, 6→60]
  3. get(6) → scan bucket 1 → 60; get(2) → bucket 2 is empty → -1
  4. put(1, 11) → key 1 is in the chain → overwrite → [1→11, 6→60]; remove(6) → [1→11]

Python

class MyHashMap:
    def __init__(self):
        self.num_buckets = 1009                          # a prime number spreads keys evenly
        self.buckets = [[] for _ in range(self.num_buckets)]   # each bucket: a list of [key, value] pairs

    def _bucket(self, key: int) -> list:
        return self.buckets[key % self.num_buckets]      # the hash function picks the bucket

    def put(self, key: int, value: int) -> None:
        bucket = self._bucket(key)
        for pair in bucket:
            if pair[0] == key:                           # key already stored: overwrite its value
                pair[1] = value
                return
        bucket.append([key, value])                      # new key: add a pair

    def get(self, key: int) -> int:
        for k, v in self._bucket(key):
            if k == key:
                return v
        return -1                                        # the chain has no such key

    def remove(self, key: int) -> None:
        bucket = self._bucket(key)
        for i, pair in enumerate(bucket):
            if pair[0] == key:
                bucket.pop(i)                            # delete the pair, then stop looking
                return
Time O(1) average per callSpace O(B + n)

Each call scans one chain of about n / B pairs. B buckets plus n stored pairs.

When to use: The answer to give. It is how real hash maps work; mention resizing for a growing map.

Common mistakes

  • Appending a new pair on every put. After put(3, 5) and put(3, 8) the chain holds both pairs, and get(3) may return the stale 5. Search the chain first and overwrite.
  • Treating a stored value of 0 as 'missing'. if pair: or if self.table[key]: is false for 0, so put(0, 0) followed by get(0) wrongly returns -1. Compare keys, or compare with -1 explicitly.
  • Continuing the loop after bucket.pop(i). The next pair slides into index i and gets skipped; once the pair is deleted, return straight away.
  • Using -1 as the 'empty' marker in the direct table without checking the limits. It is safe here only because values are never negative; if they could be -1 you would need a separate marker.
  • Making the buckets with [[]] * B. That repeats one list B times, so every key shares a single chain. Use [[] for _ in range(B)].

Python notes

  • Python's built-in dict is a hash map. d.get(key, -1) is the call that behaves like get here: the value if the key exists, otherwise a default.
  • Each pair is a list [key, value] so that pair[1] = value updates it in place. A tuple cannot be changed, so you would have to replace it in the chain.
  • for k, v in bucket unpacks every pair; for i, (k, v) in enumerate(bucket) gives the index as well, which pop(i) needs.
  • Returning inside the loop (return v, return after pop) ends the search at the first match; a key appears at most once in a chain, so there is nothing else to find.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Design HashSet LC 705 — the same table without values: the chains hold bare keys, and add only has to avoid duplicates.
  • LRU Cache LC 146 — a hash map plus a doubly linked list: the map finds an entry in O(1) and the list keeps the usage order so the oldest entry can be evicted in O(1).
  • LFU Cache LC 460 — evict the least frequently used key: keep a map from key to value and frequency, and a map from frequency to the keys that have it, plus the current minimum frequency.
  • Time Based Key-Value Store LC 981 — each key stores many (timestamp, value) pairs, and get asks for the latest value at or before a timestamp: binary search inside the key's list.
  • What if the keys are strings? — you need a hash function for text, for example a polynomial hash that mixes in one character at a time and then takes the result modulo the bucket count. (Python's built-in hash for strings changes from run to run.)
  • Resize when the table fills up — track the number of pairs; when n / B passes about 0.75, double B and re-insert every pair so the chains stay short.
