Top K Frequent Elements Medium

LeetCode #347 ↗
Status

Return the k values that occur most often in a list.

Problem

You are given a list of integers nums and an integer k. Return the k values that appear most often. The answer can be in any order.

The input is chosen so that the answer is unique: there is never a tie for the last of the k places. k is at least 1 and at most the number of distinct values.

Examples

Example 1
Input: nums = [1, 1, 1, 2, 2, 3], k = 2
Output: [1, 2]
1 appears three times, 2 twice and 3 once; the two most frequent are 1 and 2.
Example 2
Input: nums = [1], k = 1
Output: [1]
Example 3
Input: nums = [4, 1, -1, 2, -1, 2, 3], k = 2
Output: [-1, 2]
-1 and 2 appear twice each; every other value appears once.

Constraints

  • 1 <= len(nums) <= 10^5
  • -10^4 <= nums[i] <= 10^4
  • 1 <= k <= number of distinct values in nums
  • the answer is unique
  • follow-up: do better than O(n log n)

Think first try before reading the solution

First count how many times each value occurs. Which data structure maps a value to a count?
Sorting the distinct values by count works but costs O(n log n). If you only need the top k, do you need the whole order?
A count can only be between 1 and len(nums). Make one bucket per possible count, drop each value into the bucket of its count, then read buckets from the highest count down.

Key idea

The work splits into two parts: count (a dictionary from value to frequency, one pass), then select the k largest counts. Sorting all counts is the obvious selection, but it orders far more than needed.

Two better selections exist. A heap (a structure that always gives you its smallest item in O(log size)) of size k keeps only the best k seen so far. Or notice that a frequency is a whole number between 1 and n: that small range lets you bucket values by frequency, an O(n) sort that needs no comparisons. Walking the buckets from frequency n down to 1 yields the most frequent values first.

Approaches from the obvious one to the one you want in an interview

Count each value with a dictionary, then sort the distinct values by their count, largest first, and take the first k.

It is correct and short. The waste is in the sort: it puts all m distinct values in order (O(m log m), which is O(n log n) when most values are distinct) although only the top k are needed. The follow-up asks to beat exactly this.

Dry run

  1. nums = [1, 1, 1, 2, 2, 3] → count = {1: 3, 2: 2, 3: 1}
  2. sort the keys by count, descending → [1, 2, 3]
  3. take the first k = 2 → [1, 2]

Python

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        count = Counter(nums)                         # value -> how many times it occurs
        by_count = sorted(count.keys(), key=lambda v: count[v], reverse=True)
        return by_count[:k]                           # the k most frequent
Time O(n log n)Space O(n)

Counting is O(n); sorting m ≤ n distinct values is O(m log m).

When to use: A fine first answer when the follow-up is not asked.

Keep only the best k candidates. Walk the (count, value) pairs and push each onto a min-heap; whenever the heap holds more than k pairs, pop its smallest. The pair popped can never be in the answer, because k pairs with larger (or equal) counts are already kept.

A heap of size k costs O(log k) per push or pop, so selection is O(m log k) instead of O(m log m). With k = 10 and a million distinct values, log k is about 3 while log m is about 20.

Dry run

  1. count = {1: 3, 2: 2, 3: 1}, k = 2
  2. push (3, 1) → heap [(3, 1)]; push (2, 2) → heap [(2, 2), (3, 1)]
  3. push (1, 3) → 3 pairs > k → pop the smallest (1, 3)
  4. heap holds (2, 2) and (3, 1) → answer [2, 1]

Python

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        count = Counter(nums)
        heap = []                                     # min-heap of (count, value), never more than k
        for value, c in count.items():
            heapq.heappush(heap, (c, value))
            if len(heap) > k:                         # one too many: drop the least frequent
                heapq.heappop(heap)
        return [value for c, value in heap]
Time O(n log k)Space O(n)

O(n) to count; each of the m ≤ n distinct values costs one push and at most one pop on a heap of size k. The counts take O(m) memory, the heap only k slots.

When to use: When values arrive as a stream, or k is small and you want a general-purpose tool.

Watch it run

A count is a whole number from 1 to n, where n = len(nums). Use that small range directly: make n + 1 buckets, where buckets[c] lists the values that occur exactly c times. After filling them, walk from c = n down to 1 and collect values until there are k.

No comparisons between counts are ever made, so the selection is O(n). This is a bucket sort: when the keys are small integers, placing items at their key's index is faster than any comparison sort.

Dry run

  1. count = {1: 3, 2: 2, 3: 1}, n = 6
  2. buckets: [3] at index 1, [2] at index 2, [1] at index 3; indices 0, 4, 5, 6 empty
  3. scan from 6 down: 6, 5, 4 empty; index 3 → take 1; index 2 → take 2 → k values → [1, 2]

Python

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        count = {}
        for x in nums:
            count[x] = count.get(x, 0) + 1
        # buckets[c] = values that occur exactly c times; a count is at most len(nums)
        buckets = [[] for _ in range(len(nums) + 1)]
        for value, c in count.items():
            buckets[c].append(value)
        result = []
        for c in range(len(buckets) - 1, 0, -1):      # highest count first
            for value in buckets[c]:
                result.append(value)
                if len(result) == k:
                    return result
        return result
Time O(n)Space O(n)

Counting, filling the buckets and scanning them are each O(n); there are n + 1 buckets.

When to use: The answer to the follow-up. It works because frequencies are bounded by n.

Common mistakes

  • Creating buckets with [[]] * (n + 1): every slot is the same list object, so appending to one bucket appends to all. Use [[] for _ in range(n + 1)].
  • Making only n buckets: a value that fills the whole list ([5, 5, 5, 5]) has frequency n and needs index n, so you need n + 1 buckets.
  • heapq is a min-heap: the smallest item comes out first. To keep the k most frequent, push (count, value) and pop whenever the heap holds more than k, which discards the least frequent. For a max-heap instead, push (-count, value).
  • Collecting from the buckets without stopping at k returns too many values; return as soon as len(result) == k.

Python notes

  • Counter(nums).most_common(k) returns the k most common (value, count) pairs. Use it in practice, and be ready to explain what it does.
  • heapq.nlargest(k, count, key=count.get) selects with a size-k heap internally: O(m log k) for m distinct values.
  • Tuples compare item by item, so (count, value) orders a heap by count first.
  • [[] for _ in range(n + 1)] builds n + 1 separate lists; [[]] * (n + 1) repeats one list.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Kth Largest Element in an Array LC 215 — the same size-k heap, applied to values instead of counts; quickselect brings it to O(n) on average.
  • Top K Frequent Words LC 692 — ties are broken alphabetically and the output must be sorted: order by (-count, word) in a sort or heap; buckets need sorting inside each bucket.
  • Sort Characters By Frequency LC 451 — output every character, most frequent first: the same buckets, read completely instead of stopping at k.
  • K Closest Points to Origin LC 973 — a different score (distance) but the same "keep the best k in a heap of size k" pattern.
  • What if nums is a stream that is too big to store? — exact counts need memory for every distinct value. Approximate heavy-hitter algorithms (Misra-Gries, Count-Min sketch) keep a fixed-size summary instead.
