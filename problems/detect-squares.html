Detect Squares Medium

LeetCode #2013 ↗
Status

Store points on a grid and, for a query point, count how many axis-aligned squares it completes with stored points.

Problem

You are given a stream of points on a 2-D integer grid, and you need to answer queries about axis-aligned squares (sides parallel to the x and y axes, positive area).

Implement the class DetectSquares:

  • DetectSquares() creates the data structure.
  • add(point) stores the point [x, y]. The same point may be added several times; each copy counts separately.
  • count(point) returns how many ways the query point [x, y] can be one corner of an axis-aligned square whose other three corners are stored points. Duplicate points make duplicate squares (multiply the counts).

The query point itself does not have to be stored.

Examples

Example 1
Input: add([3, 10]), add([11, 2]), add([3, 2]), count([11, 10])
Output: 1
The stored points (3, 10), (11, 2) and (3, 2) form a square of side 8 with the query (11, 10).
Example 2
Input: count([14, 8])
Output: 0
No stored point sits diagonally from (14, 8) with matching partners.

Example 3
Input: add([11, 2]), count([11, 10])
Output: 2
(11, 2) is now stored twice, so the same square is counted twice.

Constraints

  • 0 <= x, y <= 1000
  • at most 3000 calls to add and count in total

Think first try before reading the solution

A square has four corners. If you know the query corner and the diagonally opposite corner, the other two corners are fixed. How many candidates are there for the diagonal corner?
The diagonal corner (px, py) must satisfy |px - x| == |py - y| != 0. The other two corners are then (x, py) and (px, y).
Store a counter of points. For each stored point that can be a diagonal corner, multiply the counts of the two remaining corners (and of the diagonal point itself).

Key idea

Checking every triple of stored points for each query is hopeless (n³). The trick is to notice that one well-chosen partner pins down the whole square. Take the query (x, y) as one corner and any stored point (px, py) as the opposite corner. That is only possible if the two are a diagonal, which means |px - x| == |py - y| and both are non-zero. Then the remaining two corners must be (x, py) and (px, y). No search needed, just two lookups.

Each (px, py) that qualifies contributes count(px, py) × count(x, py) × count(px, y) squares, because any copy of each corner makes a different square. Summing over all stored points gives the answer in O(n) per query with a dictionary of point counts. Since x and y are at most 1000, you can also loop over the stored points that share the query's x-coordinate (candidates for a vertical side) and derive everything from those, which is what the optimal version does: it only touches points in the same column instead of all stored points.

Approaches from the obvious one to the one you want in an interview

Keep a Counter of points. For a query (x, y), try every stored point (px, py) as the opposite corner of the square. It qualifies when |px - x| == |py - y| != 0. The other two corners are then (x, py) and (px, y); multiply the three counts and add to the total.

This is already a big improvement over checking triples: O(n) per query with n distinct stored points. Its only waste is that most stored points are not on a diagonal with the query at all.

Dry run

  1. add (3,10), (11,2), (3,2). count (11,10): try (3,10): |3−11| = 8 but |10−10| = 0 → no. Try (11,2): |0| vs |8| → no. Try (3,2): |8| == |8| → corners (11,2) ×1 and (3,10) ×1 → 1 × 1 × 1 = 1.
  2. add (11,2) again. count (11,10): the diagonal (3,2) gives 1 × count(11,2)=2 × count(3,10)=1 = 2.

Python

class DetectSquares:
    def __init__(self):
        self.points = Counter()                      # (x, y) -> how many copies

    def add(self, point: List[int]) -> None:
        self.points[tuple(point)] += 1

    def count(self, point: List[int]) -> int:
        x, y = point
        total = 0
        for (px, py), c in list(self.points.items()):
            if abs(px - x) != abs(py - y) or px == x:   # not a diagonal corner (or zero size)
                continue
            total += c * self.points[(x, py)] * self.points[(px, y)]
        return total
Time O(n) per count, O(1) per addSpace O(n)

n = number of distinct stored points; every one is examined per query.

When to use: Perfectly acceptable in an interview; the column version is a small refinement.

A square with the query (x, y) as a corner has one side that is vertical, from (x, y) to some (x, py). So only stored points in the same column matter. Group the stored points by x. For each (x, py) in the query's column with d = py - y != 0, the square can extend to the right (px = x + d) or to the left (px = x − d). Each direction needs the corners (px, py) and (px, y); multiply the three counts.

Per query this touches only the points sharing the query's x, which is at most 1001 distinct y-values and usually far fewer, instead of all n stored points.

Dry run

  1. add (3,10), (11,2), (3,2). count (11,10): column x = 11 holds (11,2). d = 2 − 10 = −8.
  2. Right: px = 11 + (−8) = 3 → corners (3,2) ×1 and (3,10) ×1 → 1 × 1 × 1 = 1. Left: px = 19 → nothing stored → 0.
  3. Result 1. After another add (11,2), the side (11,2) has count 2, so the same square contributes 2.

Python

class DetectSquares:
    def __init__(self):
        self.points = Counter()                      # (x, y) -> count
        self.by_x = defaultdict(Counter)             # x -> Counter of y values in that column

    def add(self, point: List[int]) -> None:
        x, y = point
        self.points[(x, y)] += 1
        self.by_x[x][y] += 1

    def count(self, point: List[int]) -> int:
        x, y = point
        total = 0
        for py, c_side in self.by_x[x].items():      # (x, py) is the other end of a vertical side
            d = py - y
            if d == 0:
                continue                             # zero-length side is not a square
            for px in (x + d, x - d):                # the square can lie to the right or to the left
                total += c_side * self.points[(px, py)] * self.points[(px, y)]
        return total
Time O(k) per count, O(1) per add, where k = stored points in the query's columnSpace O(n)

k ≤ 1001 because coordinates are bounded; the all-points scan is O(n) with n up to 3000.

When to use: The standard answer. Explain why one vertical side determines the square.

Common mistakes

  • Forgetting to exclude a side length of zero. A stored point at the same x and y as the query is not a diagonal corner; |px - x| == |py - y| == 0 must be skipped or you count degenerate squares.
  • Counting only one orientation. For a point (x, py) in the query's column, the square can extend to the right (x + d) or to the left (x − d). Check both.
  • Treating duplicates as a set. add([11, 2]) twice must make count return 2 for that square; use a Counter, not a set.
  • Confusing which coordinates the two 'other' corners take: with query (x, y) and diagonal (px, py), the others are (x, py) and (px, y), not (px, px) or (py, py).
  • Iterating over self.points (a Counter) while also counting the query point itself as a stored partner. Only stored points count; the query may or may not be in the structure.

Python notes

  • Counter with tuple keys (x, y) is the natural store; self.points[(x, y)] += 1 needs no existence check.
  • Lookups of missing keys on a Counter return 0 instead of raising, which keeps the multiplication clean.
  • Also keep defaultdict(list) or Counter keyed by x to iterate only points in the query's column.
  • Points arrive as lists [x, y]; convert to a tuple before using them as dictionary keys.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Count squares of any orientation (rotated) — pairs of points define a side; the other two corners come from rotating the side vector by 90°. Still O(n²) per query with a point set.
  • Minimum Area Rectangle LC 939 — static version for rectangles: fix two points as a diagonal and look up the other two in a set.
  • Minimum Area Rectangle II LC 963 — rectangles of any orientation; group point pairs by centre and length of the diagonal.
  • Number of Boomerangs LC 447 — another 'fix one point, count partners by a hashed property (distance)' problem.
  • Remove points — add remove(point): decrement the counter and delete zero entries; nothing else changes because counts are looked up live.
  • Count on a huge sparse grid — coordinates up to 10⁹ with few points: the Counter approach still works unchanged, while a 1001×1001 grid array would not.
