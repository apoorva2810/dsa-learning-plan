Best Time to Buy and Sell Stock Easy

LeetCode #121 ↗
Status

Buy on one day and sell on a later day; return the largest profit possible, or 0.

Problem

You are given a list prices where prices[i] is the price of a stock on day i.

You may make one trade: buy one share on some day, then sell it on a later day. Return the largest profit you can make. If no trade makes money, return 0 (you are allowed not to trade at all).

Examples

Example 1
Input: prices = [7, 1, 5, 3, 6, 4]
Output: 5
Buy on day 1 at price 1 and sell on day 4 at price 6. Selling at 7 is not possible: day 0 comes before the purchase.
Example 2
Input: prices = [7, 6, 4, 3, 1]
Output: 0
The price only falls, so the best choice is not to trade.

Constraints

  • 1 <= len(prices) <= 10^5
  • 0 <= prices[i] <= 10^4

Think first try before reading the solution

Suppose you already knew the day you will sell. Which day would you buy on?
The cheapest day before it. So while you scan the days left to right, remember the lowest price seen so far.
On each day, price - lowest_so_far is the best profit if you sell today. Keep the largest of those values.

Key idea

Fix the selling day and the best buying day is obvious: the cheapest day before it. So one left-to-right scan is enough. Remember the cheapest price so far; on each day, selling today would earn price - cheapest; keep the best.

In sliding-window terms, the window is [buy, sell]. sell moves forward one day at a time. buy stays put until a day is cheaper than the current buy day, and then it jumps straight to that day: from now on, buying there beats buying anywhere earlier for every future sale. The window never needs to shrink back. One pass, O(n) time, O(1) memory.

Approaches from the obvious one to the one you want in an interview

Try every pair buy < sell and keep the largest prices[sell] - prices[buy] (and never less than 0).

Correct, but it is n(n−1)/2 subtractions. It also repeats the same question for every sell day: "what is the cheapest earlier price?" The optimal approach answers that question once, incrementally.

Python

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        best = 0
        n = len(prices)
        for buy in range(n):
            for sell in range(buy + 1, n):             # sell strictly after buying
                best = max(best, prices[sell] - prices[buy])
        return best
Time O(n²)Space O(1)

All pairs of days; nothing stored except the best profit.

When to use: Only as the starting point that defines the problem.

Keep the window [buy, sell], where buy is the cheapest day seen so far.

  • Move sell forward one day at a time.
  • If prices[sell] < prices[buy], this day is a new low: move buy here. No future sale would prefer the old buy day.
  • Otherwise prices[sell] - prices[buy] is the best profit for selling today; compare it with the best so far.

buy only moves forward and every day is visited once, so the scan is O(n) with two indices and one number of memory. Writing it with a min_price variable instead of a buy index is the same algorithm.

Dry run

  1. prices = [7, 1, 5, 3, 6, 4], buy = day 0 (7)
  2. day 1 (1) < 7 → new low, buy = day 1
  3. day 2 (5): profit 4 → best 4
  4. day 3 (3): profit 2
  5. day 4 (6): profit 5 → best 5
  6. day 5 (4): profit 3 → answer 5

Python

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        buy = 0                                        # index of the cheapest day so far
        best = 0
        for sell in range(1, len(prices)):
            if prices[sell] < prices[buy]:
                buy = sell                             # new low: better buy day for every later sale
            else:
                best = max(best, prices[sell] - prices[buy])
        return best
Time O(n)Space O(1)

Each day is looked at once; only two indices and the best profit are stored.

When to use: The standard answer for one trade.

Watch it run

Rewrite the input as daily changes: prices[i] - prices[i - 1]. Buying on day b and selling on day s earns the sum of the changes on days b+1 .. s, a contiguous run. So the answer is the maximum-sum run of changes (or 0).

That is the Maximum Subarray problem, solved by Kadane's algorithm: keep run, the best sum of a run ending today. Either extend yesterday's run or start fresh, run = max(0, run + change), and track the largest run. Same O(n) and O(1); it is worth knowing because it carries over to the multi-transaction variants.

Dry run

  1. prices = [7, 1, 5, 3, 6, 4] → changes [-6, 4, -2, 3, -2]
  2. run: max(0, -6) = 0 → 4 → 2 → 5 → 3
  3. largest run = 5 → buy at 1, sell at 6

Python

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        best = 0
        run = 0                                        # best profit of a trade that sells today
        for yesterday, today in zip(prices, prices[1:]):
            run = max(0, run + (today - yesterday))    # extend the trade, or restart by buying today
            best = max(best, run)
        return best
Time O(n)Space O(1)

One pass over the n − 1 daily changes. (prices[1:] makes a copy; iterate by index to avoid it.)

When to use: When you want to connect the problem to Maximum Subarray, or extend it to more transactions.

Common mistakes

  • Subtracting the global minimum from the global maximum. The maximum can come before the minimum: in [7, 1, 5, 3, 6, 4] the maximum 7 is on day 0.
  • Returning a negative number when prices only fall. Start best at 0, because not trading is allowed.
  • Starting the running minimum at 0 instead of prices[0] (or infinity): every profit then looks like the full price.
  • Checking every pair of days: n(n−1)/2 pairs is about 5·10⁹ for 10⁵ days, which times out.

Python notes

  • float("inf") is the usual starting value for a running minimum; prices[0] works too because the list is never empty.
  • best = max(best, price - min_price) and min_price = min(min_price, price) are the whole loop in the running-minimum style.
  • zip(prices, prices[1:]) pairs every day with the next one, which is how the daily-change (Kadane) version reads the input.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Best Time to Buy and Sell Stock II LC 122 — unlimited trades, holding at most one share at a time: add up every rise from one day to the next, max(0, prices[i] - prices[i - 1]).
  • Best Time to Buy and Sell Stock III LC 123 — at most two trades: keep four running values (best after the first buy, first sale, second buy, second sale) and update them every day.
  • Best Time to Buy and Sell Stock IV LC 188 — at most k trades: those running values become a DP over the trade count, O(n · k).
  • Best Time to Buy and Sell Stock with Cooldown LC 309 — after selling you must wait a day: a small state machine (holding, just sold, resting) solved with DP.
  • Best Time to Buy and Sell Stock with Transaction Fee LC 714 — unlimited trades, but every sale pays a fee: two states (holding, not holding) updated each day.
  • Maximum Subarray LC 53 — a profit is a sum of consecutive daily changes, so Kadane's maximum-subarray algorithm on those changes solves this problem too.
