Longest Common Subsequence Medium

LeetCode #1143 ↗
Status

Find the length of the longest sequence of characters that appears, in the same order, in both strings.

Problem

Given two strings text1 and text2, return the length of their longest common subsequence, or 0 if they have no character in common.

A subsequence of a string keeps some of its characters (possibly none, possibly all) in their original order; the kept characters do not have to be next to each other. "ace" is a subsequence of "abcde", but "aec" is not. A common subsequence is a subsequence of both strings.

Examples

Example 1
Input: text1 = "abcde", text2 = "ace"
Output: 3
"ace" appears in order in both strings.
Example 2
Input: text1 = "abc", text2 = "abc"
Output: 3
Example 3
Input: text1 = "abc", text2 = "def"
Output: 0
No character is shared.

Constraints

  • 1 <= len(text1), len(text2) <= 1000
  • both strings contain only lowercase English letters

Think first try before reading the solution

Compare the last characters of the two strings. If they are equal, is it ever a mistake to use them as the last character of the common subsequence?
If they differ, at least one of them is not used, so the answer is the better of 'drop the last character of text1' and 'drop the last character of text2'.
The state is a pair of prefix lengths (i, j). Cache it, or fill an (m + 1) × (n + 1) table whose row 0 and column 0 stand for the empty prefix.

Key idea

Look at the last characters of the prefixes text1[:i] and text2[:j].

  • They are equal: pair them up. Some longest common subsequence ends with exactly this pair (any common subsequence that does not use it can be rewritten to end with it without getting shorter). What is left is the LCS of the two shorter prefixes: dp[i][j] = dp[i - 1][j - 1] + 1.
  • They differ: they cannot be paired with each other, so at least one of them is not in the answer. Try dropping each: dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]).

A brute force would list all 2^m subsequences of one string and test each against the other. The DP has only (m + 1) · (n + 1) states, one per pair of prefix lengths, each computed in O(1).

This step, "compare the last characters, then shrink one or both strings", is the template for Edit Distance, Distinct Subsequences, Interleaving String and Regular Expression Matching.

Approaches from the obvious one to the one you want in an interview

Let lcs(i, j) be the answer for the suffixes text1[i:] and text2[j:]:

  • if either suffix is empty, the answer is 0;
  • if text1[i] == text2[j], use that character: 1 + lcs(i + 1, j + 1);
  • otherwise skip a character of one string: max(lcs(i + 1, j), lcs(i, j + 1)).

Without a cache the mismatch branch splits in two again and again, and the same (i, j) pairs are recomputed along many different branches: exponential time. With @cache there are only (m + 1) · (n + 1) different calls, each doing O(1) work.

Dry run

  1. text1 = "abc", text2 = "ac": lcs(0, 0): a == a → 1 + lcs(1, 1)
  2. lcs(1, 1): b ≠ c → max(lcs(2, 1), lcs(1, 2))
  3. lcs(2, 1): c == c → 1 + lcs(3, 2) = 1; lcs(1, 2): text2's suffix is empty → 0
  4. lcs(1, 1) = max(1, 0) = 1, so lcs(0, 0) = 2

Python

class Solution:
    def longestCommonSubsequence(self, text1: str, text2: str) -> int:
        m, n = len(text1), len(text2)

        @cache                                       # one stored answer per pair (i, j)
        def lcs(i: int, j: int) -> int:
            """LCS length of the suffixes text1[i:] and text2[j:]."""
            if i == m or j == n:                     # an empty suffix shares nothing
                return 0
            if text1[i] == text2[j]:                 # same first character: use it
                return 1 + lcs(i + 1, j + 1)
            return max(lcs(i + 1, j), lcs(i, j + 1)) # skip one character of one string

        return lcs(0, 0)
Time O(m·n)Space O(m·n)

(m + 1)(n + 1) states, O(1) work each; the recursion can be m + n frames deep.

When to use: The natural first version. In Python, prefer the table once the strings reach a few hundred characters.

Store dp[i][j] = LCS length of the prefixes text1[:i] and text2[:j] in an (m + 1) × (n + 1) table. Row 0 and column 0 are the empty prefix, all 0. Fill row by row, left to right:

  • text1[i - 1] == text2[j - 1] → dp[i][j] = dp[i - 1][j - 1] + 1 (diagonal);
  • otherwise → dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]) (up or left).

The answer is dp[m][n]. Keeping the whole table also lets you recover one actual subsequence by walking back from the corner, which the one-row version below cannot do.

Dry run

  1. text1 = "abcde", text2 = "ace": row a → [0, 1, 1, 1] (match on a, then copies from the left)
  2. row b → [0, 1, 1, 1] (no match, every cell copies the larger of up and left)
  3. row c → [0, 1, 2, 2] (c == c: diagonal 1 + 1)
  4. row d → [0, 1, 2, 2]; row e → [0, 1, 2, 3] (e == e: diagonal 2 + 1) → answer 3

Python

class Solution:
    def longestCommonSubsequence(self, text1: str, text2: str) -> int:
        m, n = len(text1), len(text2)
        dp = [[0] * (n + 1) for _ in range(m + 1)]   # dp[i][j] = LCS of text1[:i] and text2[:j]
        for i in range(1, m + 1):
            for j in range(1, n + 1):
                if text1[i - 1] == text2[j - 1]:     # both prefixes end in the same character
                    dp[i][j] = dp[i - 1][j - 1] + 1
                else:                                # drop the last character of one prefix
                    dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
        return dp[m][n]
Time O(m·n)Space O(m·n)

One O(1) update per cell of the (m + 1) × (n + 1) table.

When to use: When you also need the subsequence itself (walk back from the corner), or to debug by printing the table.

Watch it run

Row i reads only row i - 1 and itself, so one list of length n + 1 is enough. Moving left to right, row[j] still holds the value from the row above (up) and row[j - 1] already holds the current row (left). The diagonal dp[i - 1][j - 1] sat in row[j - 1] a moment ago but was just overwritten, so save it in a variable diag before each write.

Memory drops to O(n), or O(min(m, n)) when the shorter string goes on the columns. The trade-off: the information needed to walk back and print the subsequence is gone.

Dry run

  1. text1 = "abc", text2 = "ac", row = [0, 0, 0]
  2. row a: j = 1 match → diag + 1 = 1; j = 2 mismatch → max(0, 1) = 1 → [0, 1, 1]
  3. row b: no matches → [0, 1, 1]
  4. row c: j = 1 → max(1, 0) = 1; j = 2 match, diag = old row[1] = 1 → 2 → [0, 1, 2] → answer 2

Python

class Solution:
    def longestCommonSubsequence(self, text1: str, text2: str) -> int:
        if len(text2) > len(text1):
            text1, text2 = text2, text1              # shorter string on the columns: shorter row
        n = len(text2)
        row = [0] * (n + 1)                          # row[j] = dp[i][j] for the row being filled
        for i in range(1, len(text1) + 1):
            diag = 0                                 # dp[i - 1][0]: the empty prefix of text2
            for j in range(1, n + 1):
                up = row[j]                          # dp[i - 1][j], about to be overwritten
                if text1[i - 1] == text2[j - 1]:
                    row[j] = diag + 1
                else:
                    row[j] = max(up, row[j - 1])     # row[j - 1] is already dp[i][j - 1]
                diag = up                            # the diagonal for column j + 1
        return row[n]
Time O(m·n)Space O(min(m, n))

Same m·n cell updates as the table; only one row plus one saved number is kept.

When to use: The interview answer when only the length is asked for. Mention the full table if they want the subsequence itself.

Common mistakes

  • Index shift: with the extra empty row and column, cell (i, j) compares text1[i - 1] with text2[j - 1]. Comparing text1[i] reads the wrong characters and runs off the end of the string.
  • Adding 1 in the mismatch case, or taking only the diagonal on a mismatch. Write the two cases separately and check them against the 3-cell picture: match → diagonal + 1, mismatch → max(up, left).
  • Confusing subsequence with substring. A substring is contiguous; for the longest common substring the mismatch case resets the cell to 0 and the answer is the largest cell anywhere.
  • Top-down recursion on two 1000-character strings goes up to 2000 calls deep, past Python's default limit of 1000. Use the table, or raise the limit with sys.setrecursionlimit.
  • In the one-row version, writing row[j - 1] destroys the diagonal value that column j needs. Save it in a variable before the write.

Python notes

  • [[0] * (n + 1) for _ in range(m + 1)] builds the table with its empty-prefix row and column already set to 0.
  • @cache keys on the pair (i, j); the strings are read from the enclosing scope and are not part of the key.
  • The memoised recursion can reach m + n frames: 2000 for the largest inputs, beyond the default limit of 1000. LeetCode raises the limit, but the table avoids the question entirely.
  • For the one-row version, put the shorter string on the columns so the row is as short as possible.

  • Uncrossed Lines LC 1035 — the same problem told with integer arrays and non-crossing lines; the code does not change.
  • Maximum Length of Repeated Subarray LC 718 — the contiguous version: a mismatch sets the cell to 0, and the answer is the largest cell in the table.
