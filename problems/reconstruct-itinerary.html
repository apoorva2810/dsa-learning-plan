Reconstruct Itinerary Hard

LeetCode #332 ↗
Status

Chain a pile of plane tickets into one trip from JFK that uses every ticket once, smallest order first.

Problem

You are given a list of plane tickets, tickets[i] = [from, to], where each airport is a three-letter code. All the tickets belong to one traveller whose trip starts at "JFK".

Return the itinerary (the list of airports visited, in order) that uses every ticket exactly once. If several itineraries do that, return the one that comes first alphabetically when compared airport by airport.

  • At least one valid itinerary exists.
  • The same ticket can appear more than once; each copy must be used.

Examples

Example 1
Input: tickets = [["MUC", "LHR"], ["JFK", "MUC"], ["SFO", "SJC"], ["LHR", "SFO"]]
Output: ["JFK", "MUC", "LHR", "SFO", "SJC"]
Only one way to chain these four tickets.
Example 2
Input: tickets = [["JFK", "SFO"], ["JFK", "ATL"], ["SFO", "ATL"], ["ATL", "JFK"], ["ATL", "SFO"]]
Output: ["JFK", "ATL", "JFK", "SFO", "ATL", "SFO"]
["JFK", "SFO", "ATL", "JFK", "ATL", "SFO"] also uses every ticket, but "ATL" < "SFO" at the second stop.
Example 3
Input: tickets = [["JFK", "KUL"], ["JFK", "NRT"], ["NRT", "JFK"]]
Output: ["JFK", "NRT", "JFK", "KUL"]
KUL is alphabetically first, but flying there first strands the NRT tickets. KUL has to be the last stop.

Constraints

  • 1 <= len(tickets) <= 300
  • every airport code is 3 uppercase English letters, and from != to
  • the tickets form at least one valid itinerary starting at JFK

Think first try before reading the solution

Airports are nodes and tickets are directed edges. A trip that uses every edge exactly once has a name: an Euler path.
Always taking the alphabetically smallest ticket can strand you (example 3). But being stuck is informative: an airport you cannot leave must be the final stop of whatever is left of the trip.
Walk greedily with a stack. When the airport on top has no unused tickets, pop it and append it to the answer. The answer comes out back to front; reverse it at the end.

Key idea

The tickets form a directed graph, and an itinerary that uses each ticket once is an Euler path: a walk that uses every edge exactly once. Hierholzer's algorithm builds one with a single observation. Walk from JFK taking any unused ticket; eventually you land somewhere with no unused ticket out. That airport can only be the end of the trip, because every other airport you entered still has a way out, so write it down as the last stop. Step back to the previous airport: if it still has unused tickets, they form a detour that must happen before the part you already wrote down. Walk the detour the same way.

Writing airports down at the moment they run out of tickets, then reversing the list, splices every detour into the right place automatically. To get the alphabetically smallest trip, always take the smallest remaining destination: a smaller choice is only pushed later in the route when it leads to a dead end, which has to come last anyway. Each ticket is used once, so after sorting the work is O(E).

Approaches from the obvious one to the one you want in an interview

Sort each airport's destinations and run a DFS that always tries the smallest unused ticket first. If the walk gets stuck before every ticket is used, undo the last ticket (give it back) and try the next destination. Because the choices are tried in alphabetical order, the first complete itinerary found is the smallest one.

This is correct but can be very slow: a wrong early choice is only discovered after a long walk, and the search may undo and redo the same stretches many times. In the worst case the number of attempts grows exponentially.

Dry run

  1. [["JFK","KUL"], ["JFK","NRT"], ["NRT","JFK"]] → JFK: [KUL, NRT], NRT: [JFK]
  2. JFK → KUL (smallest). KUL has no tickets, but 2 are unused → dead end, give the ticket back
  3. JFK → NRT → JFK → KUL: all 3 tickets used → return [JFK, NRT, JFK, KUL]

Python

class Solution:
    def findItinerary(self, tickets: List[List[str]]) -> List[str]:
        graph = defaultdict(list)
        for src, dst in sorted(tickets):            # destinations in alphabetical order
            graph[src].append(dst)
        route = ["JFK"]

        def dfs(airport: str) -> bool:
            if len(route) == len(tickets) + 1:      # every ticket used
                return True
            destinations = graph[airport]
            for i in range(len(destinations)):
                nxt = destinations.pop(i)           # use this ticket ...
                route.append(nxt)
                if dfs(nxt):
                    return True
                route.pop()                         # ... dead end: give it back
                destinations.insert(i, nxt)
            return False

        dfs("JFK")
        return route
Time exponential in the worst caseSpace O(E)

Every dead end costs a retry; the route and recursion hold at most E + 1 airports.

When to use: Acceptable for 300 tickets in practice, and easy to explain, but it has no good worst-case bound.

Keep each airport's destinations sorted in reverse, so pop() hands out the smallest. Then loop:

  • look at the airport on top of the stack;
  • if it has an unused ticket, pop the smallest destination and push it (keep walking);
  • otherwise it is a dead end, and therefore the last stop of everything that remains: pop it and append it to route.

When the stack is empty, route lists the trip back to front; reverse it. A dead end is written down first and so ends up at the end of the trip, while detours discovered on the way back are inserted before it. Each ticket is pushed and popped once, so after sorting the walk is O(E).

Dry run

  1. [["JFK","KUL"], ["JFK","NRT"], ["NRT","JFK"]], stack [JFK]
  2. JFK → KUL (smallest): stack [JFK, KUL]. KUL has no tickets → route [KUL], stack [JFK]
  3. JFK → NRT: stack [JFK, NRT]. NRT → JFK: stack [JFK, NRT, JFK]
  4. JFK, NRT, JFK all run out in turn → route [KUL, JFK, NRT, JFK]
  5. Reverse → [JFK, NRT, JFK, KUL]

Python

class Solution:
    def findItinerary(self, tickets: List[List[str]]) -> List[str]:
        graph = defaultdict(list)
        for src, dst in sorted(tickets, reverse=True):
            graph[src].append(dst)                  # largest first, so pop() gives the smallest
        stack = ["JFK"]
        route = []
        while stack:
            airport = stack[-1]
            if graph[airport]:                      # an unused ticket leaves this airport
                stack.append(graph[airport].pop())
            else:                                   # stuck: final stop of what remains of the trip
                route.append(stack.pop())
        return route[::-1]                          # airports were written down back to front
Time O(E log E)Space O(E)

Sorting the tickets dominates; the walk itself pushes and pops each ticket once.

When to use: The answer to give. It is short, has no backtracking, and works for any Euler-path question.

Watch it run

The same algorithm with the call stack instead of an explicit one: visit(airport) keeps flying out of airport on the smallest unused ticket, recursing into each destination, and appends airport to route once its tickets are used up. That append is the "write it down when stuck" moment, so route again comes out back to front.

Python

class Solution:
    def findItinerary(self, tickets: List[List[str]]) -> List[str]:
        graph = defaultdict(list)
        for src, dst in sorted(tickets, reverse=True):
            graph[src].append(dst)
        route = []

        def visit(airport: str) -> None:
            while graph[airport]:
                visit(graph[airport].pop())         # fly the smallest unused ticket
            route.append(airport)                   # nothing left to fly from here

        visit("JFK")
        return route[::-1]
Time O(E log E)Space O(E)

Same work as the stack version; the recursion depth can reach E + 1.

When to use: Shortest to write. Prefer the stack version if the input could be deep enough to hit the recursion limit.

Common mistakes

  • Pure greedy: always flying to the smallest destination and recording airports as you arrive. Example 3 returns JFK → KUL and then is stuck with two unused tickets.
  • Recording an airport when you arrive instead of when it runs out of tickets. The dead end then lands in the middle of the route instead of at its end.
  • Taking the smallest destination with min() or pop(0) each time: both cost O(degree) per ticket. Sort each list in reverse once and pop() from the end, or keep a heap per airport.
  • Storing destinations in a set. Duplicate tickets (two JFK → ATL) collapse into one and the route comes out too short. Use a list.
  • Forgetting to reverse the finished list: the airports come out in reverse order.

Python notes

  • sorted(tickets, reverse=True) sorts by departure, then destination, both descending. Appending in that order leaves each airport's list largest-first, so list.pop() (O(1)) hands out the smallest destination.
  • defaultdict(list) returns an empty list for an airport with no tickets out, so if graph[airport]: needs no in check.
  • route[::-1] returns a reversed copy; route.reverse() reverses in place.
  • The recursive version is shorter, but 300 tickets mean up to 301 nested calls, which is within Python's default limit of 1000.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Valid Arrangement of Pairs LC 2097 — the same Hierholzer walk on integer pairs, but nobody tells you the start: begin at the node whose out-degree is one more than its in-degree (any node if all are balanced).
  • Cracking the Safe LC 753 — build a graph whose nodes are (n - 1)-digit strings and whose edges are digits; an Euler circuit spells the shortest string containing every password.
  • What if the trip must end back at JFK? — that is an Euler circuit. It exists when every airport has as many tickets in as out; the algorithm does not change.
  • What if a valid itinerary is not guaranteed? — check the degrees first (JFK may have one extra ticket out, one airport one extra ticket in, every other airport balanced), and check that the finished route has len(tickets) + 1 airports.
  • Course Schedule II LC 210 — another answer assembled in DFS finishing order: a node is written down only once nothing reachable from it is left to do.
