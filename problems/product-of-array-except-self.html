Product of Array Except Self Medium

LeetCode #238 ↗
Status

For every position, multiply all the other numbers, without using division.

Problem

You are given a list of integers nums. Return a list answer of the same length where answer[i] is the product of every element except nums[i].

  • Your solution must run in O(n) time and must not use division.
  • Every product of a prefix or suffix of nums fits in a 32-bit integer.

Examples

Example 1
Input: nums = [1, 2, 3, 4]
Output: [24, 12, 8, 6]
answer[0] = 2·3·4 = 24, answer[1] = 1·3·4 = 12, and so on.
Example 2
Input: nums = [-1, 1, 0, -3, 3]
Output: [0, 0, 9, 0, 0]
Every product that includes the 0 is 0; only answer[2] skips it: (-1)·1·(-3)·3 = 9.
Example 3
Input: nums = [2, 3]
Output: [3, 2]

Constraints

  • 2 <= len(nums) <= 10^5
  • -30 <= nums[i] <= 30
  • every prefix and suffix product fits in a 32-bit integer
  • follow-up: O(1) extra space (the output list does not count)

Think first try before reading the solution

Split "everything except i" into two parts. What are they?
answer[i] = (product of everything left of i) × (product of everything right of i). Both parts can be built for all i in one sweep each.
Store the left products in answer during a left-to-right pass, then sweep right to left with one running variable and multiply the right products in.

Key idea

"Everything except nums[i]" is two pieces: the elements before i and the elements after i. The product of the elements before i is a prefix product, and it grows by one factor as i moves right: left[i + 1] = left[i] × nums[i]. The same holds for suffix products from the right.

So two linear sweeps compute every left product and every right product, and answer[i] is their product. No division is involved, so zeros need no special handling. Writing the left products straight into answer and keeping the right product in a single running variable brings the extra memory down to O(1).

Approaches from the obvious one to the one you want in an interview

For each index i, loop over the whole list and multiply every element whose index is not i.

It follows the definition directly and needs no division, but each of the n answers costs n − 1 multiplications, O(n²) in total. For 100,000 numbers that is about 10 billion multiplications. The repeated work is obvious once you look: answer[1] and answer[2] share almost every factor.

Dry run

  1. nums = [1, 2, 3, 4]
  2. i = 0: 2·3·4 = 24; i = 1: 1·3·4 = 12; i = 2: 1·2·4 = 8; i = 3: 1·2·3 = 6
  3. every answer recomputes products the previous answer already had

Python

class Solution:
    def productExceptSelf(self, nums: List[int]) -> List[int]:
        n = len(nums)
        answer = []
        for i in range(n):
            product = 1
            for j in range(n):
                if j != i:                     # skip only position i itself
                    product *= nums[j]
            answer.append(product)
        return answer
Time O(n²)Space O(1)

n answers × (n - 1) multiplications each; extra memory is one running product (the output does not count).

When to use: Only as the starting point that shows the shared work.

Precompute two lists:

  • prefix[i] = product of nums[0..i-1] (with prefix[0] = 1),
  • suffix[i] = product of nums[i+1..n-1] (with suffix[n-1] = 1).

Each is built in one sweep, because every entry is the previous entry times one more element. Then answer[i] = prefix[i] * suffix[i]. Three linear passes, no division, and zeros are handled naturally.

Dry run

  1. nums = [1, 2, 3, 4]
  2. prefix = [1, 1, 2, 6] (left to right)
  3. suffix = [24, 12, 4, 1] (right to left)
  4. answer = [1·24, 1·12, 2·4, 6·1] = [24, 12, 8, 6]

Python

class Solution:
    def productExceptSelf(self, nums: List[int]) -> List[int]:
        n = len(nums)
        prefix = [1] * n                       # prefix[i] = product of nums[:i]
        for i in range(1, n):
            prefix[i] = prefix[i - 1] * nums[i - 1]
        suffix = [1] * n                       # suffix[i] = product of nums[i+1:]
        for i in range(n - 2, -1, -1):
            suffix[i] = suffix[i + 1] * nums[i + 1]
        return [prefix[i] * suffix[i] for i in range(n)]
Time O(n)Space O(n)

Three linear passes; prefix and suffix are two extra lists of length n.

When to use: The clearest O(n) version; a good stepping stone before the space optimisation.

Watch it run

The prefix list from the previous approach can live inside answer: a left-to-right pass writes the product of everything left of i into answer[i], keeping a running variable prefix.

A right-to-left pass then keeps a running suffix (the product of everything right of i) and multiplies it into answer[i]. The order matters in both passes: use the running value first, then multiply nums[i] into it, so that position i itself is never included.

Same O(n) time, and apart from the output only two numbers are stored.

Dry run

  1. nums = [1, 2, 3, 4]
  2. pass 1 (prefix 1 → 1 → 2 → 6 → 24): answer = [1, 1, 2, 6]
  3. pass 2 from the right (suffix 1 → 4 → 12 → 24 → 24): answer[3] = 6·1, answer[2] = 2·4, answer[1] = 1·12, answer[0] = 1·24
  4. answer = [24, 12, 8, 6]

Python

class Solution:
    def productExceptSelf(self, nums: List[int]) -> List[int]:
        n = len(nums)
        answer = [1] * n
        prefix = 1                             # product of everything left of i
        for i in range(n):
            answer[i] = prefix
            prefix *= nums[i]                  # include nums[i] only after using prefix
        suffix = 1                             # product of everything right of i
        for i in range(n - 1, -1, -1):
            answer[i] *= suffix
            suffix *= nums[i]
        return answer
Time O(n)Space O(1)

Two linear passes; besides the output list only prefix and suffix are stored.

When to use: The interview answer, and the one the follow-up asks for.

Common mistakes

  • Dividing the total product by nums[i]: forbidden here, and it breaks on zeros (ZeroDivisionError, or wrong answers when exactly one zero is present).
  • Off by one: answer[i] must exclude nums[i], so store prefix before multiplying nums[i] into it.
  • Starting the running products at 0 instead of 1. The product of no numbers (the empty product) is 1, which is what answer[0]'s left part and answer[n-1]'s right part need.
  • Counting the output list as extra space: the follow-up explicitly excludes it, so the two-pass version is O(1) extra.

Python notes

  • [1] * n creates n ones; this is safe because ints are immutable (unlike [[]] * n).
  • range(n - 1, -1, -1) walks indices from right to left.
  • Python integers never overflow, but the 32-bit guarantee matters in Java or C++.

Follow-up questions

What an interviewer might ask next, and what changes.

  • What if division were allowed? — count the zeros first. No zeros: total // nums[i]. Exactly one zero: only that position gets the product of the others, every other entry is 0. Two or more: everything is 0.
  • Trapping Rain Water LC 42 — the same left-pass / right-pass shape, with running maximums instead of products.
  • Maximum Product Subarray LC 152 — products of contiguous runs: negatives flip signs, so track the running maximum and minimum together.
  • Range Sum Query - Immutable LC 303 — prefix sums answer any range sum in O(1): prefix[r + 1] - prefix[l].
  • Product of the Last K Numbers LC 1352 — prefix products over a stream; a 0 resets the list, which is how division by zero is avoided.
