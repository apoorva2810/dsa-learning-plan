Delete Leaves With a Given Value Medium 250

LeetCode #1325 ↗
Status

Repeatedly remove every leaf whose value equals a target, including the new leaves that appear after a removal.

Problem

You are given the root of a binary tree and an integer target. Delete every leaf whose value is target.

Deleting a leaf may turn its parent into a leaf. If that new leaf also has value target, delete it as well, and keep going until no leaf with value target is left. Return the root of the resulting tree, or None if every node was deleted.

A node with at least one child is never deleted, whatever its value.

Examples

Example 1
Input: root = [1, 2, 3, 2, null, 2, 4], target = 2
Output: [1, null, 3, null, 4]
The two leaves with value 2 (under 2 and under 3) go first. The node 2 on the left then has no children and equals the target, so it goes too. The 3 keeps its child 4, so both stay.
Example 2
Input: root = [1, 3, 3, 3, 2], target = 3
Output: [1, 3, null, null, 2]
The leaf 3 under the left 3 and the right leaf 3 are removed. The left 3 keeps its child 2, so it stays although its value is 3.
Example 3
Input: root = [1, 2, null, 2, null, 2], target = 2
Output: [1]
A chain 1 → 2 → 2 → 2. The bottom 2 is a leaf; removing it makes the next 2 a leaf, and so on: all three go.
Example 4
Input: root = [1, 1, 1], target = 1
Output: []
Both leaves go, then the root is a leaf with value 1 and goes as well. The tree becomes empty.

Constraints

  • 1 <= number of nodes <= 3000
  • 1 <= Node.val, target <= 1000

Key idea

The wording 'delete, and then delete the new leaves that appear' sounds like a loop, and the straightforward solution is one: sweep the tree, remove the matching leaves, sweep again, until nothing changes. Each sweep is O(n), and a chain of h target values needs h sweeps, so the loop costs O(n · h) in the worst case.

The repetition disappears once you notice when a node can become a leaf: only after its children have been removed. So handle the children first. In a post-order traversal (left subtree, right subtree, then the node) both subtrees are already cleaned by the time you look at a node, so you can decide about it once: if it is a leaf at that moment and its value is target, it goes; otherwise it stays.

The recursion returns the new root of each subtree, and the parent stores it: root.left = remove(root.left). Returning None is how a node is deleted. One visit per node, O(n), with the recursion stack as the only extra memory.

Approaches from the obvious one to the one you want in an interview

Do what the statement says, literally. One sweep walks the tree and removes every leaf whose value is target; the parent of a removed leaf may now be a leaf, but that is only noticed in the next sweep. Repeat until a sweep removes nothing.

Each sweep is O(n). A chain of h target values loses one node per sweep, so there can be h sweeps: O(n · h) time.

Dry run

  1. [1, 2, null, 2, null, 2], target 2: sweep 1 removes the bottom 2
  2. sweep 2 removes the middle 2 (now a leaf), sweep 3 removes the last 2
  3. sweep 4 finds only the leaf 1 → stop; result [1]

Python

class Solution:
    def removeLeafNodes(self, root: Optional[TreeNode], target: int) -> Optional[TreeNode]:
        def sweep(node):
            """Remove the current target leaves of this subtree once.
            Returns (new subtree root, whether anything was removed)."""
            if node is None:
                return None, False
            if node.left is None and node.right is None:          # a leaf: keep or drop it
                return (None, True) if node.val == target else (node, False)
            node.left, removed_left = sweep(node.left)
            node.right, removed_right = sweep(node.right)
            return node, removed_left or removed_right             # this node was not a leaf in this sweep

        changed = True
        while changed and root is not None:                        # repeat until a sweep removes nothing
            root, changed = sweep(root)
        return root
Time O(n · h)Space O(h)

Up to h sweeps (one per level of a chain of targets), each visiting all n nodes.

When to use: Only to make the 'repeat' in the statement concrete; the recursion below needs one pass.

Watch it run

A node can only become a leaf after its children are gone, so process the children first. removeLeafNodes cleans the left subtree, cleans the right subtree, stores what comes back, and then looks at the node: if it is a leaf now and its value is target, return None (the parent drops it); otherwise return the node.

Every node is examined once, after its subtrees are final, so the repeated sweeps are not needed. The root is handled by the same rule, which is how the whole tree can become None.

Dry run

  1. [1, 2, 3, 2, null, 2, 4], target 2: leaf 2 under the left 2 → None
  2. left 2: no children left and value 2 → None
  3. leaf 2 under 3 → None; leaf 4 stays; 3 keeps 4 → stays
  4. root 1 keeps 3 → [1, null, 3, null, 4]

Python

class Solution:
    def removeLeafNodes(self, root: Optional[TreeNode], target: int) -> Optional[TreeNode]:
        if root is None:
            return None
        root.left = self.removeLeafNodes(root.left, target)       # clean the subtrees first
        root.right = self.removeLeafNodes(root.right, target)
        if root.left is None and root.right is None and root.val == target:
            return None                                            # a leaf (possibly a new one) with the target value
        return root
Time O(n)Space O(h)

One visit per node; the recursion stack is as deep as the tree height h.

When to use: The interview answer: post-order, return the new subtree root.

Watch it run

The same order without recursion. A first pass with a stack records every node and its parent; because a node is recorded before its children, reading that list backwards visits children before parents. For each node in that order, if it is a leaf with value target, detach it from its parent (or return None if it is the root).

Same O(n) time. The trade-off: O(n) extra memory for the list and the parent map instead of O(h) stack frames, but no recursion limit to worry about on a 3000-node chain.

Python

class Solution:
    def removeLeafNodes(self, root: Optional[TreeNode], target: int) -> Optional[TreeNode]:
        if root is None:
            return None
        parent = {root: None}
        order, stack = [], [root]
        while stack:                                   # every node is recorded before its children
            node = stack.pop()
            order.append(node)
            for child in (node.left, node.right):
                if child is not None:
                    parent[child] = node
                    stack.append(child)
        for node in reversed(order):                   # children before parents
            if node.left is None or node.right is None:
                if node.left is None and node.right is None and node.val == target:
                    p = parent[node]
                    if p is None:
                        return None                    # the root itself is a target leaf
                    if p.left is node:
                        p.left = None
                    else:
                        p.right = None
        return root
Time O(n)Space O(n)

Two linear passes; the list and the parent dictionary hold every node.

When to use: When recursion depth is a concern.

Common mistakes

  • Checking the node before cleaning its children (pre-order). [1, 2, null, 2, null, 2] with target 2 then keeps the upper 2s, because they were not leaves yet when they were examined.
  • Deleting any node whose value is target. Only leaves are deleted: in [1, 3, 3, 3, 2] with target 3 the left 3 stays because it keeps its child 2.
  • Forgetting to store the returned subtree: remove(root.left, target) without root.left = ... computes everything and changes nothing.
  • Returning root unconditionally at the end. The root itself can be deleted ([1, 1, 1], target 1 → empty tree), so the final check applies to it as well.
  • Stopping the sweep version after one pass. The second example of a chain shows why the loop must run until a pass removes nothing.

Python notes

  • root.left = self.removeLeafNodes(root.left, target) is the whole trick: the call returns either the same node or None, and assigning it is what detaches a deleted leaf.
  • root.left is None and root.right is None is the leaf test; write it after the two recursive calls so it sees the cleaned children.
  • Up to 3000 nodes in a chain means up to 3000 frames, above Python's default recursion limit of 1000. Call sys.setrecursionlimit(5000) for such inputs, or use the iterative version with a parent dictionary.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Binary Tree Pruning LC 814 — remove every subtree that contains no 1: the same post-order shape, with the condition 'leaf with value 0' instead of 'leaf with value target'.
  • Find Leaves of Binary Tree LC 366 — peel off all leaves round by round and report each round: the sweep version of this problem, where the round number of a node equals its height.
  • Delete Nodes And Return Forest LC 1110 — delete a set of values anywhere in the tree, not only leaves: post-order again, and the children of a deleted node become new roots.
  • Delete Node in a BST LC 450 — deleting an inner node of a search tree needs a replacement; here only leaves go, so returning None is enough.
  • Delete leaves whose value is in a set — replace node.val == target by node.val in targets; nothing else changes, and a set keeps the test O(1).
  • Count the deleted nodes — increment a counter in the branch that returns None, or compare node counts before and after.
