Jump Game Medium

LeetCode #55 ↗
Status

Decide whether you can hop from the first index of a list to the last, when each value is the longest hop allowed from that index.

Problem

You are given a list of non-negative integers nums and you start on index 0. The value nums[i] is the longest jump you may make from index i: from there you can move forward by any distance from 1 up to nums[i] (a shorter jump is always allowed).

Return True if you can reach the last index, and False otherwise.

Examples

Example 1
Input: nums = [2, 3, 1, 1, 4]
Output: true
Jump 1 step from index 0 to index 1, then 3 steps to the last index.
Example 2
Input: nums = [3, 2, 1, 0, 4]
Output: false
Every route lands on index 3, whose value is 0, so you can never get past it to index 4.
Example 3
Input: nums = [2, 5, 0, 0]
Output: true
Jumping the full 2 from index 0 would land on a 0 and get stuck. Jumping just 1 reaches index 1, which allows a jump of 5.

Constraints

  • 1 <= len(nums) <= 10^4
  • 0 <= nums[i] <= 10^5

Think first try before reading the solution

Do not try to pick the jumps. Ask a different question: which indices can you stand on? If you can stand on index i, which indices can you stand on next?
From a reachable index i you may land on any of i + 1 .. i + nums[i], because shorter jumps are allowed. So the reachable indices never have a hole: they are always one block from index 0 up to some farthest index. One number describes the whole block.
Sweep left to right and keep farthest = max(farthest, i + nums[i]). If you arrive at an index i > farthest, no jump can land there, so return False. If you get through the whole list without being stuck, return True.

Key idea

Instead of searching for a path, track which indices you can stand on. Index 0 is reachable. From any reachable index i you can land on i + 1 through i + nums[i]. So the reachable indices always form one unbroken block 0 .. farthest, with no holes in it, and a block is described by a single number. That number is all you need to remember.

Sweep i from left to right. If i <= farthest, index i is reachable and may push the block further, to max(farthest, i + nums[i]). If i > farthest, nothing before i can land on it (those indices have all been used to compute farthest), and nothing after i can either, since jumps only go forward. You are stuck: the answer is False. If the sweep reaches the last index without getting stuck, the answer is True.

This is a greedy algorithm in an unusual way: it never commits to a jump. It keeps the best summary of every possibility, and the summary is small enough to fit in one variable.

Approaches from the obvious one to the one you want in an interview

Ask "from index i, can I get to the last index?" and answer it by trying every jump length from 1 to nums[i]: the answer is yes if any of the landing indices says yes. The base case is an index at or past the last one.

This is correct, but it repeats work. Different routes land on the same index again and again, and each time the whole search below it is redone. When the answer is False, every route has to be explored, which is exponential in the worst case. Remembering the answer for each index (a cache) would fix that, which leads to the next approach.

Dry run

  1. nums = [2, 3, 1, 1, 4]: from 0 try the jump of 2 first, landing on index 2
  2. from 2 try the jump of 1 → index 3; from 3 try the jump of 1 → index 4 = last → True
  3. nums = [3, 2, 1, 0, 4]: from 0 the jumps land on 3, 2, 1 and every route dies at the 0 on index 3
  4. index 3 and index 2 are searched again from other routes: that repeated work is the waste

Python

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        last = len(nums) - 1

        def can_finish(i: int) -> bool:          # from index i, can we reach the last index?
            if i >= last:
                return True
            for step in range(nums[i], 0, -1):   # try the longest jump first
                if can_finish(i + step):
                    return True
            return False                         # no jump length works (also when nums[i] == 0)

        return can_finish(0)
Time O(2ⁿ)Space O(n)

Worst case every route is explored; the recursion is at most n frames deep.

When to use: Only to define the problem. Never for real input sizes.

Work backwards and remember the answers. Let good[i] mean "from index i the last index can be reached". The last index is good. Index i is good if some index in i + 1 .. i + nums[i] is good. Going from right to left means every index it might jump to has already been decided, so each index costs one scan over its jump range.

That is O(n²) in the worst case. But look at what the inner scan asks: "can I land on any good index?" If one good index is in range, the leftmost good index to the right is in range too, because it is the nearest one. So remembering just that one index would be enough. Following that thought turns this table into the greedy solution.

Dry run

  1. nums = [3, 2, 1, 0, 4], good = [?, ?, ?, ?, True]
  2. i = 3: jump range is empty (value 0) → False
  3. i = 2: can land on 3 only, good[3] is False → False
  4. i = 1: can land on 2 or 3, both False → False
  5. i = 0: can land on 1, 2 or 3, all False → False, so the answer is False

Python

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        n = len(nums)
        good = [False] * n                       # good[i]: from index i we can reach the last index
        good[n - 1] = True
        for i in range(n - 2, -1, -1):           # right to left: everything i can reach is already decided
            farthest_jump = min(n - 1, i + nums[i])
            for j in range(i + 1, farthest_jump + 1):
                if good[j]:
                    good[i] = True
                    break
        return good[0]
Time O(n²)Space O(n)

For each index, a scan over up to n later indices. One boolean per index.

When to use: To see the DP version of the idea; it is also what a cached recursion computes.

Keep farthest, the highest index you know you can reach, and sweep i from left to right.

  1. If i > farthest, nothing lands on index i: return False.
  2. Otherwise index i is reachable, so farthest = max(farthest, i + nums[i]).
  3. If you get through the list, the last index was reachable: return True.

Because every index up to farthest is reachable (you can always take a shorter jump), this one number is a complete description of everything the earlier indices can do. Each index is visited once.

Dry run

  1. nums = [2, 3, 1, 1, 4], last index 4, farthest = 0
  2. i = 0: reachable (0 ≤ 0), 0 + 2 = 2 → farthest 2
  3. i = 1: reachable (1 ≤ 2), 1 + 3 = 4 → farthest 4 ≥ last, so True
  4. nums = [3, 2, 1, 0, 4]: i = 0 → farthest 3; i = 1, 2, 3 give 3, 3, 3 so farthest stays 3
  5. i = 4: 4 > 3 → no jump lands here → False

Python

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        farthest = 0                             # highest index we know we can land on
        for i, jump in enumerate(nums):
            if i > farthest:                     # nothing lands on i: we are stuck before it
                return False
            farthest = max(farthest, i + jump)   # best landing spot reachable from i
        return True                              # we got through every index, including the last
Time O(n)Space O(1)

One pass, one variable. (You may return True early once farthest >= len(nums) - 1.)

When to use: The standard answer. Say "the reachable indices form a block, so I only track its right edge".

Common mistakes

  • Treating nums[i] as an exact jump, or always taking the longest jump. In [2, 5, 0, 0] the full jump of 2 from index 0 lands on a 0 and looks hopeless, yet jumping 1 reaches the 5 and the answer is True.
  • Using i >= farthest as the stuck test. Index i == farthest is reachable: in [1, 0] index 1 is the last index and you can stand on it. The stuck test is i > farthest.
  • Updating farthest before checking that index i is reachable. In [0, 5, 0] index 1 cannot be reached, but adding 1 + 5 first makes the answer True. Check i > farthest first.
  • Returning False as soon as you see a 0. A zero only blocks you when farthest itself stops on it: [2, 0, 1] is True because you jump from index 0 straight over the zero.
  • Writing the recursive search with a cache for n = 10^4: the recursion goes about n levels deep and passes Python's default limit of 1000 frames. The loop has no such limit.

Python notes

  • for i, jump in enumerate(nums) gives the index and the value together. max(farthest, i + jump) is the whole update.
  • In the DP version, min(n - 1, i + nums[i]) keeps the inner range from running past the end of the list.
  • Python's default recursion limit is 1000, so the recursive version fails for long lists. LeetCode may raise the limit, but do not depend on it; the loop is the safe form.
  • You can also sweep from the right: goal = n - 1, then for i from n - 2 down to 0, set goal = i whenever i + nums[i] >= goal. The answer is goal == 0. It is the same idea mirrored.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Jump Game II LC 45 — the end is guaranteed reachable and you want the fewest jumps: the same sweep, but split into levels (all the indices one more jump can reach).
  • Jump Game III LC 1306 — you may jump i + arr[i] or i - arr[i] and must land on any 0. Moves go both ways, so the reachable set is no longer a block: use BFS or DFS with a visited set.
  • Jump Game VI LC 1696 — every landing adds its value to a score, jumps are at most k, and you want the best score: DP over positions plus a monotonic deque for the best of the last k cells.
  • Jump Game VII LC 1871 — on a 0/1 string you may jump between minJump and maxJump onto 0 cells. The reachable cells inside the window need a sliding count, or a BFS that never revisits an index.
  • Minimum Number of Taps to Open to Water a Garden LC 1326 — turn each tap into its farthest right edge from every left edge, and the question becomes Jump Game II.
  • Print one valid path — for each index remember which earlier index first stretched farthest to cover it (a parent pointer), then walk back from the last index.
