Min Stack Medium

LeetCode #155 ↗
Status

A stack that can also tell you its smallest element, all operations in O(1).

Problem

Design a stack that supports push, pop, top and getMin (return the minimum element), each in O(1) time.

Implement the class MinStack:

  • MinStack() creates an empty stack.
  • push(val) pushes val.
  • pop() removes the top element.
  • top() returns the top element.
  • getMin() returns the minimum element currently in the stack.

pop, top and getMin are only called on a non-empty stack.

Examples

Example 1
Input: ["MinStack","push","push","push","getMin","pop","top","getMin"] [[],[-2],[0],[-3],[],[],[],[]]
Output: [null, null, null, null, -3, null, 0, -2]
After pushing -2, 0, -3 the minimum is -3. Pop removes -3; top is 0 and the minimum is back to -2.

Constraints

  • -2^31 <= val <= 2^31 - 1
  • at most 3 * 10^4 calls in total

Think first try before reading the solution

Scanning the stack for the minimum on every getMin is O(n). Where could you store the minimum so it is ready?
When you pop the current minimum, what is the new minimum? It is whatever the minimum was before that element was pushed.
Store, next to each element, the minimum of the stack at the time it was pushed. Then popping restores the old minimum automatically.

Key idea

A single min variable fails because after a pop you would need to know the previous minimum, and the one before that, and so on. That is itself a stack of minimums. So keep two stacks that move together: the real values, and the "minimum so far" at each height. getMin is just the top of the second stack, and pop pops both. Everything is O(1) because nothing ever scans.

Approaches from the obvious one to the one you want in an interview

Use one list. push, pop and top are the normal list operations; getMin calls min(self.stack). Three of the four operations are O(1), but getMin is O(n), which violates the requirement. It is the baseline that shows exactly which operation needs the clever idea.

Python

class MinStack:
    def __init__(self):
        self.stack = []

    def push(self, val: int) -> None:
        self.stack.append(val)

    def pop(self) -> None:
        self.stack.pop()

    def top(self) -> int:
        return self.stack[-1]

    def getMin(self) -> int:
        return min(self.stack)          # O(n): scans everything
Time O(1) push/pop/top, O(n) getMinSpace O(n)

When to use: Never for the actual question; only to explain what must be improved.

Keep a second list mins where mins[i] is the smallest value among stack[0..i]. On push(v), append min(v, mins[-1]) (or v if empty). On pop, pop both. getMin returns mins[-1].

Why it works: the minimum of the stack after popping is exactly the minimum of the elements that remain, and that number was computed and stored when the new top was pushed.

Dry run

  1. push(-2): stack [-2], mins [-2]
  2. push(0): stack [-2, 0], mins [-2, -2]
  3. push(-3): stack [-2, 0, -3], mins [-2, -2, -3]
  4. getMin → -3; pop → stack [-2, 0], mins [-2, -2]
  5. top → 0; getMin → -2

Python

class MinStack:
    def __init__(self):
        self.stack = []
        self.mins = []                    # mins[i] = min(stack[:i+1])

    def push(self, val: int) -> None:
        self.stack.append(val)
        current_min = val if not self.mins else min(val, self.mins[-1])
        self.mins.append(current_min)

    def pop(self) -> None:
        self.stack.pop()
        self.mins.pop()                   # restores the previous minimum

    def top(self) -> int:
        return self.stack[-1]

    def getMin(self) -> int:
        return self.mins[-1]
Time O(1) for every operationSpace O(n)

Two lists of equal length; each operation touches only their tops.

When to use: The standard answer. Mention the tuple variant (val, min) as the same idea in one list.

Watch it run

Identical idea, packed into one list: each entry is (value, minimum_at_this_height). Slightly less memory bookkeeping, same O(1) everywhere.

Python

class MinStack:
    def __init__(self):
        self.stack = []                   # (val, min_so_far)

    def push(self, val: int) -> None:
        current_min = val if not self.stack else min(val, self.stack[-1][1])
        self.stack.append((val, current_min))

    def pop(self) -> None:
        self.stack.pop()

    def top(self) -> int:
        return self.stack[-1][0]

    def getMin(self) -> int:
        return self.stack[-1][1]
Time O(1) for every operationSpace O(n)

Common mistakes

  • Keeping one min variable and recomputing with min(stack) after a pop: that makes pop O(n).
  • Pushing onto the min-stack only when the new value is strictly smaller, then popping it whenever tops are equal. Duplicates break it (push -2, -2, pop → min lost). Use <= if you go that route.
  • Forgetting that getMin must reflect only elements currently in the stack, not the all-time minimum.

Python notes

  • Two lists kept in lockstep are the simplest implementation; a single list of (val, current_min) tuples is equivalent.
  • self.mins[-1] reads the top without removing it.
  • Design problems on LeetCode are tested by a sequence of method calls; the first entry is the constructor.
