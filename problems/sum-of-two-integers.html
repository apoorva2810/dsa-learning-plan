Sum of Two Integers Medium

LeetCode #371 ↗
Status

Add two integers using only bit operations: XOR for the digits, AND and a shift for the carries.

Problem

Given two integers a and b, return a + b without using the + or - operators. Use bit operations instead. The inputs can be negative.

Examples

Example 1
Input: a = 1, b = 2
Output: 3
Example 2
Input: a = 2, b = 3
Output: 5
Example 3
Input: a = -2, b = 3
Output: 1
Negative numbers are allowed, so the method must work in two's complement.

Constraints

  • -1000 <= a, b <= 1000
  • (the solutions here work for any pair whose true sum fits in a signed 32-bit integer)

Think first try before reading the solution

How do you add 5 + 3 on paper in binary? Write the numbers in columns and mark where a carry appears.
Adding two bits without a carry is XOR: 0 + 0 = 0, 1 + 0 = 1, 1 + 1 = 0 (and a carry). A carry is produced exactly when both bits are 1, which is AND, and it belongs one column to the left: << 1.
So a + b = (a ^ b) + ((a & b) << 1). That still has a plus, but the second number (the carries) keeps moving left, so repeat the step until it is 0. In Python, mask to 32 bits so negative numbers also finish, then convert the result back to a signed number.

Key idea

Add in binary the way you add in decimal, column by column. In one column the digit you write is the XOR of the bits (and of the carry coming in), and a carry goes to the next column whenever at least two of those bits are 1.

Now do all columns at once instead of one at a time:

  • a ^ b is the sum of every column ignoring carries;
  • a & b has a 1 exactly in the columns that produce a carry, and (a & b) << 1 moves each carry one column left, to the column where it must be added.

So a + b = (a ^ b) + ((a & b) << 1). The right-hand side still contains an addition, but the second number (the carries) is further left than before. Apply the same identity again, and again. The lowest carry bit moves up at least one column per round, so after at most 32 rounds it has fallen off the end and the carry is 0. At that point a ^ b is the answer.

Python needs a 32-bit simulation. Python integers have no width, and a negative number behaves as if it had infinitely many 1s on its left. Then a carry can keep rippling left forever, and the loop never ends (try -1 + 1). The fix is to imitate a 32-bit machine: AND with 0xFFFFFFFF to keep only 32 bits, and at the end turn a pattern with bit 31 set back into a negative number with ~(a ^ 0xFFFFFFFF).

Approaches from the obvious one to the one you want in an interview

Add the way you do on paper, one column at a time from the right. In each column you have three bits: the two digits and the carry from the previous column.

  • the digit to write is 1 when an odd number of the three bits are 1: bit_a ^ bit_b ^ carry;
  • the carry going out is 1 when at least two of the three are 1: (bit_a & bit_b) | (carry & (bit_a ^ bit_b)).

Do that for all 32 columns, collect the digits in result, and convert the pattern back to a signed number when bit 31 is set. It uses only bit operations, and it always takes 32 rounds even for 1 + 2.

Dry run

  1. a = 5 (0101), b = 3 (0011), carry = 0
  2. column 0: bits 1, 1, carry 0 → digit 0, carry out 1
  3. column 1: bits 0, 1, carry 1 → digit 0, carry out 1
  4. column 2: bits 1, 0, carry 1 → digit 0, carry out 1
  5. column 3: bits 0, 0, carry 1 → digit 1, carry out 0. Result 1000 = 8

Python

class Solution:
    def getSum(self, a: int, b: int) -> int:
        MASK = 0xFFFFFFFF                      # 32 one-bits
        MAX_INT = 0x7FFFFFFF                   # largest positive signed 32-bit value
        result = 0
        carry = 0
        for i in range(32):                    # one column per bit, right to left
            bit_a = (a >> i) & 1
            bit_b = (b >> i) & 1
            digit = bit_a ^ bit_b ^ carry                          # odd number of 1s -> write a 1
            carry = (bit_a & bit_b) | (carry & (bit_a ^ bit_b))    # two or more 1s -> carry a 1
            result |= digit << i
        # bit 31 set means the 32-bit pattern is a negative number
        return result if result <= MAX_INT else ~(result ^ MASK)
Time O(w)Space O(1)

w = 32 columns, each with constant work.

When to use: To understand where XOR and AND come from. It is exactly a hardware full adder.

Watch it run

The column-by-column adder does the same small job 32 times. Do every column at once with whole-number operations:

  • a ^ b is the sum of every column ignoring carries;
  • (a & b) << 1 collects the carries and moves each one column to the left, where it must be added.

Then a + b equals (a ^ b) plus the carries. Make a the XOR, make b the carries, and repeat. Each round the lowest carry bit moves up by at least one column, so after at most 32 rounds the carry is 0 and a is the sum.

In Python add the 32-bit simulation: mask both inputs and every new carry with 0xFFFFFFFF, and at the end turn a pattern above 0x7FFFFFFF back into a negative number with ~(a ^ MASK).

Dry run

  1. a = 5 (0101), b = 3 (0011)
  2. round 1: a ^ b = 0110, carry (0101 & 0011) << 1 = 0010 → a = 0110, b = 0010
  3. round 2: a ^ b = 0100, carry (0110 & 0010) << 1 = 0100 → a = 0100, b = 0100
  4. round 3: a ^ b = 0000, carry (0100 & 0100) << 1 = 1000 → a = 0000, b = 1000
  5. round 4: a ^ b = 1000, carry 0 → b = 0. Stop: a = 1000 = 8

Python

class Solution:
    def getSum(self, a: int, b: int) -> int:
        MASK = 0xFFFFFFFF                      # 32 one-bits: keeps only the low 32 bits
        MAX_INT = 0x7FFFFFFF                   # largest positive signed 32-bit value
        a &= MASK                              # work on 32-bit patterns, like a 32-bit machine
        b &= MASK
        while b:                               # b holds the carries still to be added
            carry = ((a & b) << 1) & MASK      # columns with two 1s carry into the next column
            a = a ^ b                          # every column added without its carry
            b = carry
        # bit 31 set means the 32-bit pattern is a negative number
        return a if a <= MAX_INT else ~(a ^ MASK)
Time O(w)Space O(1)

At most 32 rounds, because the lowest carry bit moves left in every round and leaves the 32-bit mask. Often far fewer.

When to use: The interview answer. Say why the masks are needed in Python and how the sign is restored.

Common mistakes

  • Not masking. With a negative input the carry never reaches 0, because the endless run of 1s on the left keeps producing carries, and the while b loop runs forever.
  • Masking but not converting back. The loop then returns 4294967295 for -1 + 0. A pattern above 0x7FFFFFFF has bit 31 set and stands for a negative number.
  • Precedence: a & b << 1 means a & (b << 1), because << binds tighter than &. The carry is (a & b) << 1; write the parentheses.
  • Updating a before computing the carry. If you run a = a ^ b first, then (a & b) << 1 uses the new a and the answer is wrong. Compute the carry first.
  • Converting back with a - 2**32. It is correct arithmetic but it uses the forbidden -. ~(a ^ MASK) gives the same number with bit operations only.

Python notes

  • Python integers are unbounded. A negative number acts as if it had endless 1s to the left, so -1 & 0xFFFFFFFF is 4294967295. Masking turns it into the 32-bit pattern a C or Java int would hold.
  • Mask after every step that can grow past 32 bits. (a & b) << 1 can create bit 32, and Python will keep it unless you cut it off.
  • ~(a ^ MASK) turns a 32-bit pattern with bit 31 set into the negative number it stands for, without subtraction. For a = 0xFFFFFFFE, a ^ MASK is 1 and ~1 is -2.
  • In C++ or Java the same algorithm needs no masks, because the machine integer wraps by itself. The masks are how we make Python behave like that.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Add Binary LC 67 — the same carry logic on two strings of 0 and 1, digit by digit from the right. Strings have no 32-bit limit, so no masks are needed.
  • Add Two Numbers LC 2 — carry across the digits of two linked lists, stored in reverse order.
  • Plus One LC 66 — a carry rippling through a run of 9s: the decimal version of 0111 + 1 = 1000.
  • Divide Two Integers LC 29 — no /, * or %: subtract the divisor shifted left by k for the largest k that fits, add 1 << k to the quotient, repeat. Mind the 32-bit overflow case -2^31 / -1.
  • Subtraction without `-` — negate with two's complement and reuse the adder: a - b = a + (~b + 1), where each + is the XOR-and-carry loop.
  • Multiplication without `*` — shift-and-add: for each set bit k of b, add a << k to the total using this adder.
