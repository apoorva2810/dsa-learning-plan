Contains Duplicate Easy

LeetCode #217 ↗
Status

Decide whether any value appears more than once in a list.

Problem

You are given a list of integers nums. Return True if some value appears at least twice, and False if every value in the list is different from every other.

Only the values matter, not where they are: two equal numbers anywhere in the list count as a duplicate.

Examples

Example 1
Input: nums = [1, 2, 3, 1]
Output: true
The value 1 appears at index 0 and again at index 3.
Example 2
Input: nums = [1, 2, 3, 4]
Output: false
All four values are different.
Example 3
Input: nums = [1, 1, 1, 3, 3, 4, 3, 2, 4, 2]
Output: true

Constraints

  • 1 <= len(nums) <= 10^5
  • -10^9 <= nums[i] <= 10^9

Think first try before reading the solution

Comparing every pair of positions works. How many pairs does a list of 100,000 numbers have?
If the list were sorted, where would two equal values have to be?
Walk the list once and remember every value you have met. A set answers "have I met this value before?" in O(1) on average, so you can stop at the first repeat.

Key idea

The question "does any value repeat?" can be read as "while walking the list, do I ever meet a value I have already met?". If you remember every value you pass in a set, each check is one O(1) lookup instead of a rescan of everything before it, and you can stop the moment a lookup says yes.

Sorting is the middle ground: after sorting, equal values sit next to each other, so one comparison per neighbour pair finds them. It needs no hash set but pays O(n log n) for the sort.

Approaches from the obvious one to the one you want in an interview

For every position i, compare nums[i] with every later position j. If any pair is equal, there is a duplicate. Starting j at i + 1 tests each pair once and never compares an element with itself.

There are n(n-1)/2 pairs. For 100,000 numbers that is about 5 billion comparisons, far too slow. The approach is still worth writing first: it makes clear that the work to remove is the rescan of earlier elements.

Dry run

  1. nums = [1, 2, 3, 1]
  2. i = 0: compare with j = 1 (1 vs 2), j = 2 (1 vs 3), j = 3 (1 vs 1) → equal → True
  3. With [1, 2, 3, 4] all 6 pairs are checked before returning False.

Python

class Solution:
    def containsDuplicate(self, nums: List[int]) -> bool:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):          # every later element
                if nums[i] == nums[j]:
                    return True
        return False
Time O(n²)Space O(1)

Two nested loops over n elements; only two index variables of extra memory.

When to use: Only to state the baseline; too slow for the real constraints.

Watch it run

After sorting, equal values are adjacent: if a value occurs twice, nothing that sorts between them can separate them. So one pass comparing each element with its right-hand neighbour finds any duplicate.

The sort costs O(n log n), and the scan afterwards is O(n). No hash set is needed, which makes this the option to reach for when memory is tighter than time.

Dry run

  1. nums = [3, 1, 4, 1] → sorted [1, 1, 3, 4]
  2. compare sorted[0] = 1 with sorted[1] = 1 → equal → True

Python

class Solution:
    def containsDuplicate(self, nums: List[int]) -> bool:
        s = sorted(nums)                       # a sorted copy; nums is left untouched
        for i in range(len(s) - 1):
            if s[i] == s[i + 1]:               # duplicates must be neighbours now
                return True
        return False
Time O(n log n)Space O(n)

The sort dominates. sorted copies the list; nums.sort() avoids the copy but reorders the caller's list.

When to use: When you cannot afford a hash set, or the data is already sorted (then it is O(n)).

Watch it run

Walk the list once and keep a set of the values already visited. For each x:

  • x in seen → this value appeared earlier: return True immediately;
  • otherwise add x to seen and continue.

A set lookup is O(1) on average (it jumps to the value's hash slot instead of scanning), so the whole walk is O(n). The price is O(n) memory for the set.

Dry run

  1. nums = [1, 2, 3, 1], seen = {}
  2. 1 not seen → seen = {1}; 2 not seen → {1, 2}; 3 not seen → {1, 2, 3}
  3. 1 is in seen → return True

Python

class Solution:
    def containsDuplicate(self, nums: List[int]) -> bool:
        seen = set()
        for x in nums:
            if x in seen:                      # met this value before
                return True
            seen.add(x)
        return False
Time O(n)Space O(n)

One pass with one average-O(1) lookup and insert per element; the set can grow to n values.

When to use: The default answer. Mention len(set(nums)) < len(nums) as the one-line version without early exit.

Common mistakes

  • Keeping the seen values in a list: x in seen_list scans the list, so the "fast" version silently becomes O(n²) again. Use a set.
  • nums.sort() reorders the caller's list. If the original order matters elsewhere, use sorted(nums) and accept the O(n) copy.
  • In the sorted version, comparing s[i] with s[i + 1] must stop at len(s) - 2; looping to the end raises IndexError.
  • len(set(nums)) < len(nums) is correct and short, but it always builds the whole set; the loop version can stop at the first repeat.

Python notes

  • x in some_set is a hash lookup, O(1) on average; x in some_list checks elements one by one, O(n).
  • len(set(nums)) < len(nums) is the idiomatic one-liner: a set keeps one copy of each value.
  • nums.sort() sorts in place and returns None; sorted(nums) returns a new sorted list.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Contains Duplicate II LC 219 — the two equal values must be at most k positions apart: store each value's latest index in a dict, or keep a set of only the last k values (a sliding window).
  • Contains Duplicate III LC 220 — values only need to be close (within valueDiff) and indices within indexDiff: put values into buckets of width valueDiff + 1 so near values land in the same or a neighbouring bucket.
  • Find the Duplicate Number LC 287 — n + 1 numbers in the range 1..n, O(1) extra memory and no changes to the list: treat values as next pointers and use Floyd's cycle detection.
  • Find All Duplicates in an Array LC 442 — values are in 1..n: mark value v as seen by flipping the sign of nums[v - 1], which gives O(1) extra space.
  • What if memory is very tight? — sort in place and compare neighbours: O(n log n) time but no hash set. This is the classic time-for-memory trade.
