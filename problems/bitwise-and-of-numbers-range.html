Bitwise AND of Numbers Range Medium 250

LeetCode #201 ↗
Status

Find the bitwise AND of every integer in the range from left to right without visiting each one.

Problem

You are given two integers left and right with left <= right. Return the bitwise AND of every integer in the inclusive range from left to right.

The bitwise AND of several numbers looks at each binary position on its own: the result has a 1 in a position only if every number has a 1 in that position.

Examples

Example 1
Input: left = 12, right = 15
Output: 12
12, 13, 14, 15 are 1100, 1101, 1110, 1111. All start with 11, but the last two bits take every combination, so they end up 0.
Example 2
Input: left = 9, right = 12
Output: 8
9, 10, 11, 12 are 1001, 1010, 1011, 1100. Only the leading 1 is shared by all four, so the AND is 1000.
Example 3
Input: left = 7, right = 8
Output: 0
0111 and 1000 have no 1-bit in common.

Constraints

  • 0 <= left <= right <= 2^31 - 1

Key idea

The AND keeps a bit only if it is 1 in every number of the range. Count up from left to right and watch one bit position (counted from the right, starting at 0). Bit 0 flips on every step, bit 1 on every second step, bit 2 on every fourth, and so on. A position that flips inside the range has shown both a 0 and a 1, so it is 0 in the answer.

Which positions never flip? Only the leading ones, the bits left and right have in common when you read from the top down to the first place where they disagree. At that first disagreement left has a 0 and right has a 1. That means the range contains the number "shared prefix, 0, then all 1s" and the number "shared prefix, 1, then all 0s". Together they hold a 0 and a 1 in every position from the disagreement downward, so all of those positions are 0 in the answer.

So the answer is the common binary prefix of left and right, followed by zeros. To find it, shift both numbers right by one until they are equal, counting the shifts. What remains is the prefix. Shift it back left by that count to restore its place value. There are at most 31 rounds: O(log right) time and O(1) space, however long the range is.

Approaches from the obvious one to the one you want in an interview

Start with result = left and AND in left + 1, left + 2, and so on up to right. AND can only clear bits, never set them, so the running result only ever loses 1s.

It is correct, but it makes right - left steps. With right near 2^31 that is billions of operations, far too slow, and the loop cannot stop early in general: from 2^30 to 2^31 - 1 the leading 1 survives to the very end.

Dry run

  1. result = 9 (1001)
  2. 9 & 10 = 1000: the lowest bit meets a 0 and is cleared, result = 8
  3. 8 & 11 = 1000: no change
  4. 8 & 12 = 1000: no change. Return 8

Python

class Solution:
    def rangeBitwiseAnd(self, left: int, right: int) -> int:
        result = left
        for number in range(left + 1, right + 1):
            result &= number                 # AND can only clear bits, never set them
        return result
Time O(right - left)Space O(1)

One AND per number in the range, up to about two billion for the largest inputs.

When to use: As the warm-up that shows what the answer is. Not for large ranges.

Watch it run

The answer is the common binary prefix of left and right, followed by zeros. Every position below the first place where the two numbers disagree holds both a 0 and a 1 somewhere in the range, so it is 0 in the AND. Every position above it is the same in all the numbers of the range, so it is kept.

To find the prefix, shift both numbers right by one until they are equal, and count the shifts in shift. At that point left holds the shared prefix, sitting shift places too low. Shift it back with left << shift to get the answer.

Dry run

  1. left = 9 (1001), right = 12 (1100), shift = 0
  2. different: shift both, 100 and 110, shift = 1
  3. different: shift both, 10 and 11, shift = 2
  4. different: shift both, 1 and 1, shift = 3. Equal: stop
  5. 1 << 3 = 8

Python

class Solution:
    def rangeBitwiseAnd(self, left: int, right: int) -> int:
        shift = 0
        while left != right:                 # they still disagree somewhere in the bits that remain
            left >>= 1
            right >>= 1
            shift += 1
        return left << shift                 # put the shared prefix back in place, zeros below it
Time O(log right)Space O(1)

At most 31 rounds, because each round removes one bit from both numbers.

When to use: The interview answer: short, constant space, and easy to explain with the common-prefix picture.

Watch it run

Think of right as the shared prefix, then a 1 at the first disagreement, then some lower bits. Erasing the lowest 1-bit of right with right & (right - 1) removes those lower bits one at a time, from the bottom. As long as the 1 at the disagreement is still there, right stays bigger than left, so keep erasing.

The moment that 1 is erased too, right becomes the shared prefix followed by zeros. That is no bigger than left, so the loop stops, and right is the answer. This is Brian Kernighan's trick from Number of 1 Bits, used here to peel right down.

Dry run

  1. left = 9 (1001), right = 12 (1100)
  2. right is bigger than left: 12 & 11 = 1000, so right = 8
  3. 8 is not bigger than 9: stop. Return 8

Python

class Solution:
    def rangeBitwiseAnd(self, left: int, right: int) -> int:
        while right > left:
            right &= right - 1               # erase the lowest 1-bit of right
        return right
Time O(log right)Space O(1)

One round per 1-bit that has to go, at most 31.

When to use: A second way to see the same answer. It is the shortest code, but the shifting version is easier to justify.

Common mistakes

  • Looping over the whole range and ANDing each number. right can be 2^31 - 1, so a range such as 2^30 to 2^31 - 1 means a billion iterations.
  • Answering left & right. For left = 9, right = 11 that gives 9, but 9 & 10 & 11 = 8: the number in between (10, 1010) clears bit 0 as well. The two ends can agree on a low bit that the middle of the range destroys.
  • Forgetting to shift the prefix back. When the loop ends, left holds the prefix in its shifted-down form (for 9 to 12 that is just 1). The answer is left << shift.
  • Shifting only one of the numbers, or stopping when a number reaches 0 instead of when the two become equal. The loop condition is left != right.

Python notes

  • x >> k drops the lowest k bits and x << k appends k zero bits, so x >> k << k clears the lowest k bits of x.
  • (left ^ right).bit_length() is the position of the highest bit where the numbers differ, plus one. That gives a one-line solution: n = (left ^ right).bit_length(), then return left >> n << n.
  • right & (right - 1) clears the lowest 1-bit of right. right & -right isolates it.
  • Python integers do not overflow, so left << shift is safe. In Java or C++ the largest input is 2^31 - 1, which still fits a 32-bit int.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Number of 1 Bits LC 191 — the step n & (n - 1) that erases the lowest 1-bit is the one the second approach here applies to right.
  • Power of Two LC 231 — a power of two has exactly one 1-bit, so n > 0 and n & (n - 1) == 0: one erase and a comparison.
  • Hamming Distance LC 461 — XOR marks the positions where two numbers differ. Here the highest 1 of left ^ right is the first disagreement, and (left ^ right).bit_length() is how many low bits to clear.
  • Minimum Array End LC 3133 — another AND over an increasing run of integers, asked the other way round: the AND is given, and you look for the smallest possible last element.
  • Bitwise OR of a range — the same prefix, but every position from the first disagreement down becomes 1, because the range holds a 0 and a 1 there and OR keeps any 1.
  • Longest Common Prefix LC 14 — the same idea of keeping the shared leading part, on strings: compare from the front until the first mismatch.
