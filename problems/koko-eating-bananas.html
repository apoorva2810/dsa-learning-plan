Koko Eating Bananas Medium

LeetCode #875 ↗
Status

Find the slowest eating speed that still finishes every pile of bananas within h hours.

Problem

There are n piles of bananas; pile i holds piles[i] bananas. Koko has h hours before the guards come back.

She picks one eating speed k (bananas per hour) and keeps it. Each hour she chooses one pile and eats k bananas from it. If that pile has fewer than k left, she finishes it and eats nothing else during that hour.

Return the minimum integer k that lets her eat every banana within h hours. It is guaranteed that h >= n, so an answer always exists.

Examples

Example 1
Input: piles = [3, 6, 7, 11], h = 8
Output: 4
At k = 4 the piles take 1 + 2 + 2 + 3 = 8 hours. At k = 3 they take 1 + 2 + 3 + 4 = 10 hours: too slow.
Example 2
Input: piles = [30, 11, 23, 4, 20], h = 5
Output: 30
5 piles in 5 hours means one hour per pile, so k must be at least the largest pile.
Example 3
Input: piles = [30, 11, 23, 4, 20], h = 6
Output: 23

Constraints

  • 1 <= len(piles) <= 10^4
  • len(piles) <= h <= 10^9
  • 1 <= piles[i] <= 10^9

Think first try before reading the solution

For a fixed speed k, how many hours does a pile of p bananas take? Add that up over all piles.
If Koko finishes at speed k, she also finishes at any faster speed. So along k = 1, 2, 3, … the answers to "does k work?" look like no, no, …, no, yes, yes, …: sorted.
Binary search k over [1, max(piles)] (max(piles) always works because h >= n). If k works, try smaller (hi = mid); otherwise go faster (lo = mid + 1).

Key idea

Computing the best speed directly is awkward, but checking one speed is easy: a pile of p takes ⌈p / k⌉ hours, so speed k works when sum(⌈p / k⌉) <= h. That check is monotonic: a faster speed never needs more hours. So the speeds 1, 2, …, max(piles) split into a run of "too slow" followed by a run of "fast enough", and we want the first "fast enough" one.

That is a binary search over the range of possible answers rather than over an input array, often called binary search on the answer. Each check costs O(n) and the range has max(piles) values, so the total is O(n · log(max(piles))): about 30 checks even when piles hold a billion bananas.

Approaches from the obvious one to the one you want in an interview

Start at k = 1 and increase it until the total hours sum(⌈p / k⌉) fit within h. The first speed that fits is the answer, because every slower one was just shown to fail.

Each check is O(n), and the loop may run up to max(piles) times. With piles of 10⁹ bananas that is up to 10⁹ checks of 10⁴ piles: hopeless.

Dry run

  1. piles = [3, 6, 7, 11], h = 8
  2. k = 1 → 3 + 6 + 7 + 11 = 27 hours ✗
  3. k = 2 → 2 + 3 + 4 + 6 = 15 ✗
  4. k = 3 → 1 + 2 + 3 + 4 = 10 ✗
  5. k = 4 → 1 + 2 + 2 + 3 = 8 ✓ → answer 4

Python

class Solution:
    def minEatingSpeed(self, piles: List[int], h: int) -> int:
        k = 1
        # ceil(p / k) hours per pile; keep speeding up while the total is too large
        while sum((p + k - 1) // k for p in piles) > h:
            k += 1
        return k
Time O(n · max(piles))Space O(1)

Up to max(piles) speeds, each checked in O(n).

When to use: Only to state the check; the search over k is what needs fixing.

Watch it run

The check "does speed k finish in time?" is false for small k and true from some point on, so binary search the first k where it is true.

  • Range: lo = 1 (the slowest legal speed), hi = max(piles) (always works, since h >= n).
  • mid works → the answer is mid or smaller: hi = mid.
  • mid fails → the answer is bigger: lo = mid + 1.
  • Stop when lo == hi.

Each round halves the range, so only about log₂(max(piles)) checks are needed.

Dry run

  1. piles = [3, 6, 7, 11], h = 8: lo = 1, hi = 11
  2. mid = 6 → 1 + 1 + 2 + 2 = 6 ≤ 8 ✓ → hi = 6
  3. mid = 3 → 1 + 2 + 3 + 4 = 10 > 8 ✗ → lo = 4
  4. mid = 5 → 1 + 2 + 2 + 3 = 8 ✓ → hi = 5
  5. mid = 4 → 1 + 2 + 2 + 3 = 8 ✓ → hi = 4 → lo == hi → 4

Python

class Solution:
    def minEatingSpeed(self, piles: List[int], h: int) -> int:
        def hours_needed(k: int) -> int:
            return sum((p + k - 1) // k for p in piles)     # ceil(p / k) per pile, integers only

        lo, hi = 1, max(piles)                  # speed max(piles) always works: one hour per pile
        while lo < hi:
            mid = (lo + hi) // 2
            if hours_needed(mid) <= h:
                hi = mid                        # mid works; maybe something slower works too
            else:
                lo = mid + 1                    # mid is too slow, so is everything below it
        return lo                               # lo == hi: the slowest speed that works
Time O(n · log(max(piles)))Space O(1)

About log₂(max(piles)) ≤ 30 rounds, each summing over n piles.

When to use: The standard answer, and the template for every 'minimum value that works' problem.

Watch it run

range(1, max(piles) + 1) is a sorted, lazy sequence of candidate speeds, and the check turns each speed into False or True, which sort as False < True. Since Python 3.10, bisect_left accepts a key, so it can find the first speed whose key is True without building a list.

Identical complexity; shorter, but the reader has to know the key trick. Write the explicit loop in an interview.

Python

class Solution:
    def minEatingSpeed(self, piles: List[int], h: int) -> int:
        def finishes(k: int) -> bool:
            return sum((p + k - 1) // k for p in piles) <= h

        speeds = range(1, max(piles) + 1)       # candidate answers, already in order
        # first index whose key is True (False < True)
        return speeds[bisect.bisect_left(speeds, True, key=finishes)]
Time O(n · log(max(piles)))Space O(1)

When to use: Python 3.10+ code where brevity matters.

Common mistakes

  • Using p // k for the hours of a pile: a partly eaten pile still costs a full hour. Use the ceiling, (p + k - 1) // k.
  • math.ceil(p / k) goes through floats. It is fine at these sizes, but the integer form is exact for any size.
  • Starting the search at lo = 0: checking speed 0 divides by zero. The slowest legal speed is 1.
  • Using the inclusive template's hi = mid - 1 after a success: mid itself may be the answer. With while lo < hi, keep it: hi = mid.
  • Trying speeds one by one from 1 upward: correct, but up to 10⁹ checks when a pile is huge.

Python notes

  • -(-p // k) is another integer ceiling: floor division of the negation, negated back.
  • sum((p + k - 1) // k for p in piles) uses a generator, so no temporary list is built per check.
  • Python 3.10+ can binary-search a lazy range with a key: speeds = range(1, max(piles) + 1) then speeds[bisect.bisect_left(speeds, True, key=finishes)]. False < True, so this finds the first speed whose check is True.
