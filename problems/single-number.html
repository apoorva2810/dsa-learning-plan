Single Number Easy

LeetCode #136 ↗
Status

Find the one number in a list that appears once while every other number appears exactly twice.

Problem

You are given a non-empty list of integers nums. Every number appears exactly twice, except for one number that appears once. Return that single number.

Aim for linear time and constant extra memory, so no hash set that grows with the input and no sorting.

Examples

Example 1
Input: nums = [2, 2, 1]
Output: 1
Example 2
Input: nums = [4, 1, 2, 1, 2]
Output: 4
1 and 2 each appear twice. 4 appears once.
Example 3
Input: nums = [1]
Output: 1

Constraints

  • 1 <= len(nums) <= 3 * 10^4
  • -3 * 10^4 <= nums[i] <= 3 * 10^4
  • every value appears twice except one value, which appears once

Think first try before reading the solution

A set or a Counter finds the number that appears once, but it needs O(n) memory. Which operation on two equal numbers makes them cancel out to something harmless?
Look at XOR, written ^ in Python. Work out 5 ^ 5 and 5 ^ 0 in binary. Does the order of a long chain of XORs change the result?
a ^ a = 0, a ^ 0 = a, and XOR does not care about order. XOR every element together: each pair collapses to 0 and only the single number is left.

Key idea

Think of each bit position as a light switch. XOR-ing a number into a running value flips the switch at every position where that number has a 1.

A value that appears twice flips exactly the same switches twice, and flipping a switch twice puts it back where it was. So once both copies have been XOR-ed in, they have left no trace, no matter what else happened in between. That is why the pairs do not need to sit next to each other or be sorted.

In algebra: a ^ a = 0, a ^ 0 = a, and XOR is commutative and associative (order and grouping do not matter). So 4 ^ 1 ^ 2 ^ 1 ^ 2 = 4 ^ (1 ^ 1) ^ (2 ^ 2) = 4 ^ 0 ^ 0 = 4.

One pass and one integer of state give O(n) time and O(1) space. Negative numbers work too: XOR acts bit by bit on the two's complement pattern, and Python treats every integer that way.

Approaches from the obvious one to the one you want in an interview

Take each number and count how many times it occurs in the list. The first one whose count is 1 is the answer.

list.count scans the whole list, and we may do that for every element, so the cost is n scans of n elements: O(n²). For 30,000 numbers that is up to about 900 million comparisons, far too slow. It uses no extra memory, which is the only thing going for it.

Dry run

  1. nums = [2, 2, 1]
  2. x = 2: nums.count(2) scans the list and finds 2 copies, so skip it
  3. x = 2 again: the same scan, the same answer. Work is being repeated
  4. x = 1: nums.count(1) is 1, so return 1

Python

class Solution:
    def singleNumber(self, nums: List[int]) -> int:
        for x in nums:
            if nums.count(x) == 1:        # count() walks the whole list: O(n) per element
                return x
        return 0                          # unreachable for valid input
Time O(n²)Space O(1)

n elements, and each count call scans all n of them.

When to use: Only to get a correct baseline on a tiny input.

Keep a set of the numbers that are still waiting for their partner. When a number arrives:

  • not in the set yet: add it (its partner has not shown up);
  • already in the set: remove it (the pair is complete).

At the end the set holds exactly the number that never found a partner. Each step is an O(1) hash operation, so the whole pass is O(n). The price is memory: with [1, 2, 3, 1, 2, 3, 4] the set grows to hold half of the list.

Dry run

  1. nums = [4, 1, 2, 1, 2], unpaired = {}
  2. 4 is new, add it: {4}; 1 is new: {4, 1}; 2 is new: {4, 1, 2}
  3. 1 is already there, so its pair is complete. Remove it: {4, 2}
  4. 2 is already there, remove it: {4}
  5. return the one element left: 4

Python

class Solution:
    def singleNumber(self, nums: List[int]) -> int:
        unpaired = set()
        for x in nums:
            if x in unpaired:
                unpaired.remove(x)        # second copy: the pair cancels out
            else:
                unpaired.add(x)           # first copy: wait for its partner
        return unpaired.pop()             # exactly one number is left
Time O(n)Space O(n)

One pass with O(1) set operations; the set can hold up to about n/2 numbers.

When to use: The right tool if values may repeat a different number of times and you only need the odd one out of a more general rule.

Watch it run

The toggling set is doing what XOR does to the bits of a number. XOR (exclusive or) compares two bits and gives 1 only when they are different, so x ^ y flips every bit of x where y has a 1. Three facts follow:

  • a ^ a = 0: every bit is flipped twice;
  • a ^ 0 = a: nothing is flipped;
  • the order does not matter, so a pair cancels even when other numbers sit between its two copies.

Replace the whole set by one integer acc, start it at 0, and XOR every number into it. Each pair cancels to 0 and the single number is what remains. This is O(n) time with a single integer of memory.

Dry run

  1. nums = [4, 1, 2, 1, 2], acc = 0
  2. acc ^= 4 gives 100 = 4
  3. acc ^= 1 gives 101 = 5; acc ^= 2 gives 111 = 7
  4. acc ^= 1 gives 110 = 6: the bit that the first 1 set is cleared again
  5. acc ^= 2 gives 100 = 4: the second 2 undoes the first
  6. return 4

Python

class Solution:
    def singleNumber(self, nums: List[int]) -> int:
        acc = 0                           # XOR's neutral value: 0 ^ x == x
        for x in nums:
            acc ^= x                      # a number seen twice flips the same bits twice
        return acc
Time O(n)Space O(1)

One pass, one integer of state.

When to use: The interview answer. Say out loud why a pair cancels: a ^ a = 0.

Common mistakes

  • Starting the accumulator at anything other than 0. 0 is XOR's neutral value (0 ^ x = x); starting at 1 returns answer ^ 1.
  • Assuming the pairs must be adjacent, or sorting first. Sorting works but costs O(n log n); XOR does not care where the copies sit.
  • Using the trick when a value can appear three times (Single Number II). a ^ a ^ a is a, so the extra copies do not cancel.
  • Writing ^ when you mean a power. In Python ^ is XOR and ** is the exponent: 2 ^ 3 is 1, not 8.

Python notes

  • ^ is XOR in Python and ** is the exponent. acc ^= x updates in place.
  • Python integers have no fixed width and behave like infinite two's complement, so -3 ^ -3 is 0 and -3 ^ 0 is -3. XOR never needs a mask here, because the result cannot be longer than the longer input.
  • For sets, seen ^= {x} (symmetric difference) toggles whether x is in the set. It is the set version of what XOR does to a bit.
  • The whole function is reduce(xor, nums) with from functools import reduce and from operator import xor. The loop is kept in the solution because it is easier to step through.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Single Number II LC 137 — every other number appears three times. XOR no longer cancels, so count each of the 32 bit positions modulo 3 (or keep two integers ones and twos that act as a base-3 counter per bit).
  • Single Number III LC 260 — two numbers appear once. The XOR of everything is a ^ b; its lowest set bit (x & -x) is a position where a and b differ, so split the list by that bit and XOR each half on its own.
  • Missing Number LC 268 — the same cancellation with one number missing instead of one extra: XOR the indices together with the values.
  • Find the Duplicate Number LC 287 — one value repeats, possibly more than twice, and the list must not be modified. XOR fails here (three copies leave one), so treat the list as a linked list and use Floyd's cycle detection.
  • Find the Difference LC 389 — the second string is the first one shuffled plus one extra letter: XOR the character codes of both strings.
  • What if the numbers arrive as a stream? — XOR is an online algorithm. Keep one accumulator, update it on every arrival, and at any moment it equals the XOR of the values that have appeared an odd number of times.
