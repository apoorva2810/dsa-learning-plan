Remove Element Easy 250

LeetCode #27 ↗
Status

Take every copy of one value out of a list, in place, and return how many values are left.

Problem

You are given a list of integers nums and an integer val. Remove every occurrence of val from nums in place and return k, the number of values that are not equal to val.

After your function returns, the first k slots of nums must hold the values that are not val, in any order. Whatever sits in the slots after them does not matter. Do not build a second list: use O(1) extra memory, the way you would in a language where an array cannot grow or shrink.

(Our tests check the returned k. LeetCode's judge also reads nums[:k], so make sure those slots really hold the values you kept.)

Examples

Example 1
Input: nums = [4, 7, 7, 4, 1], val = 7
Output: 3, nums = [4, 4, 1, _, _]
Three values are not 7. They sit in the first three slots; the other two slots are ignored.
Example 2
Input: nums = [9, 3, 5, 3, 3, 8, 1, 3], val = 3
Output: 4, nums = [9, 5, 8, 1, _, _, _, _]
Four values are not 3. They move to the front (any order of those four is accepted).
Example 3
Input: nums = [5, 5, 5], val = 5
Output: 0, nums = [_, _, _]
Every value is removed, so k = 0 and no slot counts.

Constraints

  • 0 <= len(nums) <= 100
  • 0 <= nums[i] <= 50
  • 0 <= val <= 100

Think first try before reading the solution

Deleting from the middle of a list makes every later value slide one slot left. How many slides can one delete cost, and how many deletes might there be?
You do not have to delete anything. The slots after the first k are ignored, so you may overwrite a slot instead of removing it. Which slot is free to overwrite?
Keep a write index: the next slot where a kept value goes. Scan with a read index and, only when nums[read] != val, copy it to nums[write] and advance write.

Key idea

Two facts make this easy. The slots after the first k are ignored, and the order of the kept values does not matter. So nothing needs to be deleted: a kept value only has to land in the front part.

Use two indices that both move left to right. read looks at every slot. write marks the next free slot of the kept front part nums[0 .. write - 1]. When nums[read] is not val, copy it to nums[write] and move write forward; when it equals val, skip it. write can never get ahead of read, so a copy only overwrites a slot that read has already looked at, and no value you still need is destroyed. When read reaches the end, write is the answer.

If val is rare, there is a variant with even fewer writes: when you find val, overwrite it with the last value that is still live and shrink the live part by one. That changes the order of the kept values, which this problem allows.

Approaches from the obvious one to the one you want in an interview

Walk the list and call nums.pop(i) on every value equal to val; step forward only when nothing was removed. The values and the count come out right, but pop(i) is not cheap: Python moves every later value one slot left, which is O(n) work. A list made of n copies of val triggers n pops of a shrinking tail, about n²/2 moves in total.

It also changes the length of the list, which the problem rules out in spirit: in most languages an array cannot shrink, and the exercise is to solve it with the array you were given.

Dry run

  1. nums = [4, 7, 7, 4, 1], val = 7, i = 0
  2. nums[0] = 4 is kept → i = 1
  3. nums[1] is 7 → pop(1) → [4, 7, 4, 1], i stays 1
  4. nums[1] is 7 again → pop(1) → [4, 4, 1], i stays 1
  5. nums[1] = 4 and nums[2] = 1 are kept → i = 3 = len(nums) → return 3

Python

class Solution:
    def removeElement(self, nums: List[int], val: int) -> int:
        i = 0
        while i < len(nums):
            if nums[i] == val:
                nums.pop(i)              # every later value slides one slot left: O(n)
            else:
                i += 1                   # advance only when nothing was removed
        return len(nums)
Time O(n²)Space O(1)

Up to n pops, each moving up to n values; no extra memory.

When to use: Never in an interview. It shows why deleting from the middle of an array is the wrong tool.

Watch it run

Keep two indices. read visits every slot from 0 to n − 1. write starts at 0 and points at the next free slot of the kept front part nums[0 .. write - 1].

  • If nums[read] equals val, skip it.
  • Otherwise copy it to nums[write] and advance write.

write <= read always holds, so a copy only lands on a slot that read has already passed; no unread value is lost. When the loop ends, the front part holds every kept value, in their original order, and write is how many there are. One pass, no extra memory, and no value ever moves more than once.

Dry run

  1. nums = [4, 7, 7, 4, 1], val = 7, write = 0
  2. read = 0: 4 is kept → already in slot 0, write = 1
  3. read = 1 and read = 2: both 7 → skip
  4. read = 3: 4 is kept → nums[1] = 4, write = 2
  5. read = 4: 1 is kept → nums[2] = 1, write = 3. read is past the end → return 3, nums starts [4, 4, 1]

Python

class Solution:
    def removeElement(self, nums: List[int], val: int) -> int:
        write = 0                        # next slot of the kept front part
        for read in range(len(nums)):
            if nums[read] != val:        # keep this value
                nums[write] = nums[read]
                write += 1
        return write                     # nums[:write] holds the values that are not val
Time O(n)Space O(1)

read touches each slot once; only two integer indices are stored.

When to use: The default answer. The same read/write loop solves Move Zeroes and the sorted 'remove duplicates' problems.

Watch it run

Keep i and a length n that marks the end of the part still being sorted out. When nums[i] equals val, copy the last live value nums[n - 1] into slot i and shrink n by one. Do not advance i: the value that just arrived has not been checked and may also be val. When nums[i] is not val, move on.

It does one write per removed value instead of one per kept value, so it wins when val is rare (a long list with a few matches). The price is that the kept values can end up in a different order, which this problem allows.

Dry run

  1. nums = [4, 7, 7, 4, 1], val = 7, i = 0, n = 5
  2. nums[0] = 4 is kept → i = 1
  3. nums[1] is 7 → nums[1] = nums[4] = 1, n = 4 (i stays 1)
  4. nums[1] = 1 is kept → i = 2; nums[2] is 7 → nums[2] = nums[3] = 4, n = 3
  5. nums[2] = 4 is kept → i = 3 = n → return 3, nums starts [4, 1, 4]

Python

class Solution:
    def removeElement(self, nums: List[int], val: int) -> int:
        i, n = 0, len(nums)              # nums[:n] is the part still being sorted out
        while i < n:
            if nums[i] == val:
                nums[i] = nums[n - 1]    # pull the last live value into this slot
                n -= 1                   # one fewer live slot; do NOT advance i yet
            else:
                i += 1
        return n
Time O(n)Space O(1)

Every iteration either advances i or shrinks n, so there are at most n iterations in total.

When to use: When matches are rare or the order of the kept values does not matter.

Common mistakes

  • Deleting inside the loop with nums.remove(val) or nums.pop(i). Each call shifts every later value one slot left, so a list full of val costs O(n²). remove also searches from the front each time.
  • Popping index i and then still doing i += 1. The next value slides into slot i and is never checked, so two copies of val in a row survive ([3, 3, 1] with val = 3).
  • Returning the count and never touching nums: return len([x for x in nums if x != val]) is the right number, but the judge reads nums[:k], which still holds copies of val.
  • Building a clean list and writing nums = kept. That rebinds the local name; the caller's list is unchanged. Write into the list you were given: nums[write] = ..., or nums[:] = kept.
  • In the swap-with-last version, moving on after pulling the last value into slot i. That value has not been checked yet and may itself equal val ([3, 3] with val = 3), so i must stay where it is.

Python notes

  • list.remove(x) deletes only the first match and raises ValueError when x is absent, so while val in nums: nums.remove(val) scans from the front on every round: O(n²).
  • list.pop(i) costs O(n − i) because everything after i moves one slot left.
  • nums[:] = [x for x in nums if x != val] rewrites the contents of the same list object in one line. It builds a temporary list, so it is O(n) extra memory, and nums = [...] would only rebind the local name.
  • nums[write] = nums[read] is a plain copy of one reference; when read == write it copies a value onto itself, which is harmless.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Remove Duplicates from Sorted Array LC 26 — the same read/write walk, but the test is 'differs from the last kept value' instead of 'is not val'; sortedness is what makes that one comparison enough.
  • Move Zeroes LC 283 — keep the non-zero values in their original order with the same walk, then fill slots write .. n - 1 with zeros, because here the tail does matter.
  • Remove Duplicates from Sorted Array II LC 80 — each value may stay at most twice: compare nums[read] with nums[write - 2], and the first two values are always kept.
  • Sort Colors LC 75 — not one value to remove but three groups to separate: the same in-place idea becomes a three-way partition with swaps.
  • Remove Linked List Elements LC 203 — the same task on a linked list: instead of copying values you relink around matching nodes, and a dummy head node removes the special case at the front.
  • Order does not matter and `val` is rare — overwrite each match with the last live value and shrink the live part: one write per removed value instead of one per kept value.
