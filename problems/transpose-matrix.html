Transpose Matrix Easy 250

LeetCode #867 ↗
Status

Flip a matrix over its main diagonal so that rows become columns and columns become rows.

Problem

You are given a 2-D list matrix with m rows and n columns. Return its transpose: the matrix you get by flipping it over its main diagonal, so that the value at row r, column c moves to row c, column r.

The result has n rows and m columns. The input may be rectangular, so in general the answer has a different shape from the input.

Examples

Example 1
Input: matrix = [[2, 4, 6], [8, 10, 12]]
Output: [[2, 8], [4, 10], [6, 12]]
2 rows × 3 columns becomes 3 rows × 2 columns. The first row [2, 4, 6] is now the first column.
Example 2
Input: matrix = [[1, 2], [3, 4]]
Output: [[1, 3], [2, 4]]
A square matrix keeps its shape; the diagonal values 1 and 4 stay put and 2 and 3 swap places.
Example 3
Input: matrix = [[5, 6, 7]]
Output: [[5], [6], [7]]
A single row becomes a single column.

Constraints

  • 1 <= m, n <= 1000
  • 1 <= m * n <= 10^5
  • -10^9 <= matrix[i][j] <= 10^9

Think first try before reading the solution

Where does the value at row r, column c end up? Write the rule as a pair of indices.
The result has as many rows as the input has columns. Build a new grid of that shape; swapping cells in place only works when the matrix is square.
Fill result[c][r] = matrix[r][c] for every r and c. In Python, zip(*matrix) hands you the columns one at a time, which is the same thing.

Key idea

Transposing is only a relabelling of coordinates: what was at (r, c) is now at (c, r). Nothing is computed, nothing is compared, every value moves exactly once. So the whole job is to allocate the right shape and copy each value to its mirrored position.

The shape is the part people get wrong. An m × n input becomes an n × m output, so make n rows of m cells, where n is len(matrix[0]). With the shape right, a double loop over r and c writing result[c][r] = matrix[r][c] is the entire algorithm, and reading the input row by row means every write lands in a different output row, which is exactly the "rows become columns" picture.

Each of the m · n cells is read once and written once: O(m · n) time, and the output itself is the O(m · n) space.

Approaches from the obvious one to the one you want in an interview

Say it in words: the first column of the input is the first row of the output, the second column is the second row, and so on. So loop over the column index c, walk down that column collecting matrix[r][c] for every row r, and append the collected list as the next row of the result.

This reads the input column by column, jumping between rows at every step, which is a little slower in practice on big matrices than reading rows in order, but the complexity is the same: every cell is touched once.

Dry run

  1. matrix = [[2, 4, 6], [8, 10, 12]], 3 columns
  2. column 0 is [2, 8] → row 0 of the result
  3. column 1 is [4, 10] → row 1; column 2 is [6, 12] → row 2: [[2, 8], [4, 10], [6, 12]]

Python

class Solution:
    def transpose(self, matrix: List[List[int]]) -> List[List[int]]:
        m, n = len(matrix), len(matrix[0])
        result = []
        for c in range(n):                       # one result row per input column
            column = []
            for r in range(m):                   # walk down column c
                column.append(matrix[r][c])
            result.append(column)
        return result
Time O(m · n)Space O(m · n)

Every cell is read once and appended once; the result holds all m · n values.

When to use: When 'columns become rows' is the way you think about it; it needs no pre-allocation.

Allocate an n × m grid first, then read the input in its natural row order and drop each value at its mirrored position: result[c][r] = matrix[r][c]. That one assignment is the definition of the transpose, so the code is nothing more than two loops around it.

Reading rows in order is friendly to the machine (the values sit next to each other in memory), and because the shape is fixed up front, there is no appending and no question about how many rows the answer has.

Dry run

  1. matrix = [[2, 4, 6], [8, 10, 12]]: m = 2, n = 3, result is 3 rows of 2 empty cells
  2. (0, 0) = 2 → result[0][0]; (0, 1) = 4 → result[1][0]; (0, 2) = 6 → result[2][0]: row 0 has become column 0
  3. (1, 0) = 8 → result[0][1]; (1, 1) = 10 → result[1][1]; (1, 2) = 12 → result[2][1]
  4. result = [[2, 8], [4, 10], [6, 12]]

Python

class Solution:
    def transpose(self, matrix: List[List[int]]) -> List[List[int]]:
        m, n = len(matrix), len(matrix[0])
        result = [[0] * m for _ in range(n)]     # n rows of m cells; NOT [[0] * m] * n
        for r in range(m):
            for c in range(n):
                result[c][r] = matrix[r][c]      # the value at (r, c) lands at (c, r)
        return result
Time O(m · n)Space O(m · n)

One read and one write per cell; the only memory is the output.

When to use: The interview answer: the index swap states the definition directly, and it generalises to in-place transposes of square matrices.

Watch it run

zip(*matrix) unpacks the rows as separate arguments to zip, which then yields the first items of all rows, then the second items, and so on: exactly the columns. Turn each tuple into a list and you have the transpose in one line.

It is the same O(m · n) work done inside the interpreter's C code, so it is the fastest version in Python. Know it, but in an interview also be able to write the loops, since the idiom hides the index swap that other languages need spelled out.

Dry run

  1. zip(*[[2, 4, 6], [8, 10, 12]]) is zip([2, 4, 6], [8, 10, 12])
  2. it yields (2, 8), (4, 10), (6, 12)
  3. list(...) on each tuple → [[2, 8], [4, 10], [6, 12]]

Python

class Solution:
    def transpose(self, matrix: List[List[int]]) -> List[List[int]]:
        return [list(column) for column in zip(*matrix)]   # zip(*rows) yields the columns as tuples
Time O(m · n)Space O(m · n)

Same work as the loops, performed by zip in C.

When to use: In real Python code. Mention the loops version so the interviewer knows you understand what it does.

Common mistakes

  • Swapping in place: matrix[r][c], matrix[c][r] = matrix[c][r], matrix[r][c] only makes sense when m == n. For a 2 × 3 input, matrix[2][0] does not exist, and the result has to be 3 × 2 anyway. Build a new matrix.
  • Allocating the result as [[0] * m] * n. That is one row object repeated n times; writing to any row changes all of them. Use [[0] * m for _ in range(n)].
  • Mixing up the two dimensions: the result has len(matrix[0]) rows and len(matrix) columns. result[c][r] with r < m and c < n is the safe way to think about it.
  • Confusing transpose with rotation. Rotate Image is a transpose followed by reversing every row; a transpose alone flips over the diagonal and keeps the diagonal in place.
  • zip(*matrix) yields tuples. If the caller expects lists, convert each row: [list(col) for col in zip(*matrix)].

Python notes

  • zip(*matrix) unpacks the rows as separate arguments and zips them, so its i-th item is the i-th column. It stops at the shortest row, which is fine for a proper matrix.
  • [[0] * m for _ in range(n)] creates n independent rows; [[0] * m] * n creates one row referenced n times.
  • len(matrix) is the number of rows m; len(matrix[0]) is the number of columns n. The result has n rows of m values.
  • A list comprehension over the columns, [[row[c] for row in matrix] for c in range(n)], reads the input column by column; the index-swapping double loop reads it row by row. Same result, same cost.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Rotate Image LC 48 — rotating a square matrix 90° clockwise is a transpose followed by reversing each row, and that one can be done in place.
  • Flipping an Image LC 832 — reverse each row and invert the bits; another 'move every cell by a fixed rule' problem, this time within a row.
  • Reshape the Matrix LC 566 — the same values poured into a different r × c shape: number the cells 0..mn-1 and map k to (k // c, k % c).
  • Spiral Matrix LC 54 — visits the cells in a different order instead of moving them; good practice at keeping row and column bounds straight.
  • Transpose a square matrix in place — swap each cell above the diagonal with its mirror below it, for r in range(n): for c in range(r + 1, n), so every pair is swapped once and the diagonal is untouched.
  • Transpose a sparse matrix — when most cells are zero and the matrix is stored as (row, col, value) triples, the transpose is just swapping the first two fields of every triple, then sorting if row-major order is required.
