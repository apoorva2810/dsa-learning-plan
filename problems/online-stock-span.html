Online Stock Span Medium 250

LeetCode #901 ↗
Status

Prices arrive one day at a time; after each one, report how many consecutive days up to today were not higher.

Problem

Design a class that receives the daily price of one stock, one day at a time, and after each new price reports that day's span: the number of consecutive days, ending today and counting backwards, on which the price was less than or equal to today's price. Today always counts, so a span is at least 1.

Implement the class StockSpanner:

  • StockSpanner() creates the object with no history.
  • next(price) records today's price and returns today's span.

The prices arrive in order and you never see a future price when answering next.

Examples

Example 1
Input: ["StockSpanner","next","next","next","next","next","next","next"] [[],[100],[80],[60],[70],[60],[75],[85]]
Output: [null, 1, 1, 1, 2, 1, 4, 6]
The fourth price, 70, has span 2: the 60 just before it is not higher, but the 80 before that is. The last price, 85, has span 6: 85, 75, 60, 70, 60 and 80 are all at most 85, and the 100 before them is higher.
Example 2
Input: ["StockSpanner","next","next","next","next"] [[],[1],[2],[3],[4]]
Output: [null, 1, 2, 3, 4]
Prices keep rising, so every day's span reaches all the way back to the first day.
Example 3
Input: ["StockSpanner","next","next","next"] [[],[7],[7],[3]]
Output: [null, 1, 2, 1]
An equal price counts: the second 7 has span 2. The 3 is lower than the 7 before it, so its span is 1.

Constraints

  • 1 <= price <= 10^5
  • at most 10^4 calls to next

Think first try before reading the solution

Storing every price and walking backwards from today works. What does a steadily rising price do to the total work?
Once today's price is at least a previous day's price, that previous day can never stop a span again: any future day that is at least today's price is also at least that older price. You can forget the older day, if you remember how many days it stood for.
Keep the days that could still stop a span on a stack, each with the span it earned. Pop every day whose price is at most today's and add its span to today's, then push today's (price, span).

Key idea

Think of each day as a bar you look back across. A span stops at the first bar that is higher than today's. When today's price is at least a previous day's price, that day is now hidden: every future day that can see past today is at least as high as today, so it is also at least as high as the hidden day. The hidden day never stops anything again, and it can be thrown away.

The days that are still visible always have strictly decreasing prices from oldest to newest (if an older visible day were not higher than a newer one, the newer one would have hidden it). That is a monotonic stack: the newest visible day is on top. When a new price arrives, pop every day on top that is not higher. Each popped day already knows the span it earned, which is a block of consecutive days that today's span swallows whole, so nothing is ever re-counted. Then push today with its total.

Every day is pushed once and popped at most once, so n calls cost O(n) in total. A single call can pop many days, but that cost is "paid for" by the pushes that put them there; this is what amortised O(1) per call means.

Approaches from the obvious one to the one you want in an interview

Keep a list of all prices. On next(price), append it, then walk backwards from today while the price you pass is at most today's, counting the days. The walk stops at the first higher price or at the start of the history.

Correct, and fine for a falling market where every walk stops after one comparison. But on rising prices every walk goes all the way back to day 0: the k-th call makes k comparisons, so n calls cost about n²/2. The same old days are re-read by call after call.

Dry run

  1. next(100): nothing before it → 1
  2. next(80): 100 is higher → 1
  3. next(60): 80 is higher → 1
  4. next(70): 60 is not higher, 80 is → 2
  5. next(60): 70 is higher → 1
  6. next(75): 60, 70, 60 are not higher, 80 is → 4 (it re-reads the 60 and 70 that day 4 already walked)
  7. next(85): 75, 60, 70, 60, 80 are not higher, 100 is → 6

Python

class StockSpanner:
    def __init__(self):
        self.prices = []                        # every price seen so far, oldest first

    def next(self, price: int) -> int:
        self.prices.append(price)
        span = 0
        j = len(self.prices) - 1                # start at today and walk back
        while j >= 0 and self.prices[j] <= price:
            span += 1
            j -= 1                              # stops at the first higher price
        return span
Time O(n) per call, O(n²) for n callsSpace O(n)

A rising sequence makes the k-th call walk back k days: 1 + 2 + … + n comparisons.

When to use: Only as the baseline that shows which work is repeated.

Watch it run

Keep a stack of (price, span) pairs for the days that are still visible, that is, not yet matched or beaten by a later price. On next(price):

  1. Start with span = 1 (today).
  2. While the top's price is <= price, pop it and add its span to today's. That day is now hidden behind today forever, and the days it stood for are swallowed as one block.
  3. Push (price, span) and return span.

Prices on the stack strictly decrease from bottom to top, so a new price only ever needs to look at the top. Each day is pushed once and popped at most once: n calls cost O(n) in total, amortised O(1) each.

Dry run

  1. next(100): stack empty → push (100, 1) → 1
  2. next(80): top 100 is higher → push (80, 1) → 1
  3. next(60): top 80 is higher → push (60, 1) → 1
  4. next(70): pop (60, 1), span = 1 + 1 = 2; top 80 is higher → push (70, 2) → 2
  5. next(60): top 70 is higher → push (60, 1) → 1
  6. next(75): pop (60, 1) and (70, 2), span = 1 + 1 + 2 = 4; top 80 is higher → push (75, 4) → 4
  7. next(85): pop (75, 4) and (80, 1), span = 1 + 4 + 1 = 6; top 100 is higher → push (85, 6) → 6

Python

class StockSpanner:
    def __init__(self):
        self.stack = []                 # (price, span) pairs; prices strictly decrease bottom -> top

    def next(self, price: int) -> int:
        span = 1                        # today always counts
        # every day on top that is not higher than today belongs to today's streak
        while self.stack and self.stack[-1][0] <= price:
            _, hidden_span = self.stack.pop()
            span += hidden_span         # swallow the whole block that day already stood for
        self.stack.append((price, span))
        return span
Time O(1) amortised per call, O(n) for n callsSpace O(n)

Each pair is pushed once and popped at most once. Falling prices keep every day on the stack.

When to use: The standard answer: the 'previous greater element' stack, fed one element at a time.

Watch it run

Keep every price in a list and a stack of day indices whose price has not yet been matched or beaten. On next(price), pop the indices whose price is <= price; the index left on top is the previous strictly higher day, so the span is today - that index (or today + 1 when nothing is left). Push today.

It is the Daily Temperatures stack fed one element at a time, with the answer read from index differences instead of stored spans. Same amortised O(1) time, but the price list can never be trimmed, so memory is always the full history, where the pair stack shrinks on rising prices.

Python

class StockSpanner:
    def __init__(self):
        self.prices = []                # all prices, indexed by day
        self.stack = []                 # day indices with no later price >= theirs, prices decreasing

    def next(self, price: int) -> int:
        today = len(self.prices)
        self.prices.append(price)
        while self.stack and self.prices[self.stack[-1]] <= price:
            self.stack.pop()            # that day can never stop a span again
        # the span reaches back to the previous strictly higher day
        previous_higher = self.stack[-1] if self.stack else -1
        self.stack.append(today)
        return today - previous_higher

Same push-once, pop-once argument; the price list holds all n prices regardless.

Common mistakes

  • Popping on < instead of <=: an equal price belongs to the span. With prices 7, 7 the second call must return 2, not 1.
  • Pushing only the price and trying to rebuild the span while popping: the days hidden behind a popped day are gone. Store the span with the price (or keep every price and store indices).
  • Starting span at 0: today always counts, so the span starts at 1 and the loop adds the spans of the days it pops.
  • Calling the inner while loop O(n) per call and the whole thing O(n²): count pushes and pops instead. Each day is pushed once and popped at most once, so n calls cost O(n) in total.
  • Keeping the stack as a class attribute (stack = [] directly under class StockSpanner) instead of on self: every object then shares one history, and a second test case sees the first case's prices.

Python notes

  • A list of tuples is the natural stack: self.stack[-1][0] peeks at the top price, and _, hidden_span = self.stack.pop() unpacks a popped pair, naming only what you need.
  • while self.stack and self.stack[-1][0] <= price: tests emptiness first, so the peek never fails.
  • Naming a method next does not break the built-in next(iterator): a method name lives on the class, not in the module scope.
  • Design problems are tested by a sequence of calls on one object; keep the history on self so a second object starts empty.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Daily Temperatures LC 739 — the same stack run over a whole array, looking forward for the next higher value: a popped index learns its answer from the day that pops it instead of the pusher learning it from what it pops.
  • Next Greater Element I LC 496 — report the next higher value instead of a distance: run the stack over the array and store value -> next greater in a dictionary.
  • Largest Rectangle in Histogram LC 84 — each bar needs the nearest lower bar on both sides; a popped bar learns both at once, so one pass over the array suffices.
  • Sum of Subarray Minimums LC 907 — for each element count the subarrays in which it is the minimum: the span back to the previous smaller value times the span forward to the next smaller one, both from monotonic stacks.
  • Number of Visible People in a Queue LC 1944 — scan from the right with a decreasing stack; the number of people a person pops, plus one if someone taller remains, is their answer.
  • Only the last k days count — if a span may never reach further back than k days, keep day indices on the stack and also drop days that have fallen out of the window from the bottom, as in Sliding Window Maximum (a deque instead of a list).
