Binary Tree Level Order Traversal Medium

LeetCode #102 ↗
Status

List the values of a binary tree row by row, from the root down, each row from left to right.

Problem

Given the root of a binary tree, return its level order traversal: a list of lists. The first inner list holds the root, the second holds the root's children from left to right, the third holds the grandchildren from left to right, and so on.

An empty tree gives an empty list.

Examples

Example 1
Input: root = [3, 9, 20, None, None, 15, 7]
Output: [[3], [9, 20], [15, 7]]
Level 0 is the root 3, level 1 holds 9 and 20, and level 2 holds 15 and 7.
Example 2
Input: root = [1]
Output: [[1]]
Example 3
Input: root = []
Output: []

Constraints

  • 0 <= number of nodes <= 2000
  • -1000 <= Node.val <= 1000

Think first try before reading the solution

Which kind of traversal visits every node at depth 1 before any node at depth 2? Think of a line of people: whoever arrives first is served first.
A queue is first-in, first-out. Start with the root in the queue. Repeatedly take a node out, record its value, and add its left and right children to the back of the queue.
The tricky part is knowing where one level ends. Just before a level starts, read len(queue): exactly that many nodes belong to this level. Process only that many; the children they add are the next level. (Depth-first search can also do it if you pass the depth down.)

Key idea

A queue serves things in the order they arrived (first in, first out). Put the root in a queue. Each time you take a node out, add its children to the back. The nodes then come out as: the root, its children, their children, and so on. That is level by level, and left to right inside a level, because the left child is added before the right child.

To split the output into levels, use one fact: at the moment a level starts, the queue holds exactly the nodes of that level and nothing else. So read len(queue) first, freeze that number, and process exactly that many nodes. The children they add to the back belong to the next level and wait for the next round.

Depth-first search builds the same answer a different way: pass the depth down the recursion and drop each value into the list for its depth, creating a new list the first time a depth is reached. Visiting the left child before the right keeps every row ordered left to right.

Approaches from the obvious one to the one you want in an interview

Answer the question in the most literal way. For depth 0, walk the whole tree and collect the values of the nodes at depth 0. For depth 1, walk the whole tree again and collect the nodes at depth 1. Keep going until a depth contains no nodes at all.

It is correct and needs no queue. But every level costs a fresh walk from the root, and a tree with h levels needs h walks: O(n · h), which is O(n²) for a chain of n nodes. The walk can stop descending once it reaches the wanted depth, but it still passes through every node above that depth on every pass.

Dry run

  1. root = [3, 9, 20, None, None, 15, 7]
  2. depth 0: walk from the root and keep nodes at depth 0 → [3]
  3. depth 1: walk from the root again and keep nodes at depth 1 → [9, 20]
  4. depth 2: walk again → [15, 7]
  5. depth 3: walk again, nothing found → stop. Result [[3], [9, 20], [15, 7]].

Python

class Solution:
    def levelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        def collect(node, depth, target, out):
            """Append the values of the nodes at exactly `target` depth, left to right."""
            if node is None:
                return
            if depth == target:
                out.append(node.val)
                return                             # nothing below this node is at the target depth
            collect(node.left, depth + 1, target, out)
            collect(node.right, depth + 1, target, out)

        result, target = [], 0
        while True:
            values = []
            collect(root, 0, target, values)       # a full walk from the root for every depth
            if not values:                         # no node at this depth: we are below the tree
                return result
            result.append(values)
            target += 1
Time O(n · h)Space O(h)

h walks, each touching up to n nodes. A chain of n nodes costs about n²/2 steps. The output itself is not counted in the space.

When to use: Only to see why a single pass is worth having.

Use a queue (first in, first out) so that nodes are visited in the order they were discovered, which is level by level.

  1. Put the root in the queue.
  2. While the queue is not empty, a new level starts. Read size = len(queue): those are exactly the nodes of this level.
  3. Pop size nodes. For each one, record its value in this level's list and append its existing children to the back.
  4. Append the finished list to the result.

Freezing size is what separates the levels: the children added during step 3 sit behind the current level and are only counted at the start of the next round. Every node is added and removed once, so the time is O(n).

Dry run

  1. queue = [3]
  2. round 1: size = 1 → pop 3, queue its children 9 and 20 → level [3]
  3. round 2: size = 2 → pop 9 (no children), pop 20 (queue 15 and 7) → level [9, 20]
  4. round 3: size = 2 → pop 15 and 7 (no children) → level [15, 7]
  5. queue empty → [[3], [9, 20], [15, 7]]

Python

class Solution:
    def levelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        if root is None:
            return []
        result = []
        queue = deque([root])
        while queue:
            level = []
            for _ in range(len(queue)):            # the length is read once: exactly this level
                node = queue.popleft()
                level.append(node.val)
                if node.left:                      # children wait for the next round
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
            result.append(level)
        return result
Time O(n)Space O(w)

Each node enters and leaves the queue once. The queue holds at most one level, so w (the widest level) is up to n/2.

When to use: The default, and the skeleton behind every 'per level' tree question.

Watch it run

You do not need a queue if every node knows its depth. Walk the tree depth-first (node, then left subtree, then right subtree) and carry depth as a parameter. Keep result[d] as the list for depth d: the first time the walk reaches a new depth, open an empty list for it; then append the node's value to the list for its depth.

Because the left subtree is walked before the right one, the values at each depth arrive in left-to-right order. Time is O(n); the extra space is the recursion depth h instead of the width w. For a wide, shallow tree that is smaller than the queue; for a chain it is larger.

Dry run

  1. root = [3, 9, 20, None, None, 15, 7], result = []
  2. dfs(3, depth 0): no row 0 yet → open it, append 3 → [[3]]
  3. dfs(9, depth 1): open row 1 → [[3], [9]]; its children are None
  4. dfs(20, depth 1): row 1 exists → [[3], [9, 20]]
  5. dfs(15, depth 2) opens row 2, dfs(7, depth 2) adds to it → [[3], [9, 20], [15, 7]]

Python

class Solution:
    def levelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        result = []

        def dfs(node, depth):
            if node is None:
                return
            if depth == len(result):               # first time we reach this depth: open a new row
                result.append([])
            result[depth].append(node.val)
            dfs(node.left, depth + 1)              # left before right keeps each row left to right
            dfs(node.right, depth + 1)

        dfs(root, 0)
        return result
Time O(n)Space O(h)

Every node is visited once. The call stack is as deep as the tree is tall.

When to use: When recursion feels more natural than a queue, or when the tree is wide but shallow.

Common mistakes

  • Not freezing the level size. Looping with while i < len(queue) (or any loop that re-reads the length) while you keep appending children mixes the next level into the current one. Compute size = len(queue) once, or use for _ in range(len(queue)), which evaluates the length only once at the start.
  • Forgetting the empty tree. deque([root]) with root = None puts None in the queue and the first .val crashes. Return [] first, or start with deque([root] if root else []).
  • Using list.pop(0) as the queue. Each call shifts every remaining element, so it is O(n) and a wide tree turns the traversal quadratic. Use collections.deque and popleft().
  • Appending missing children as None and then testing for None after popping. It can work, but every later line then needs a guard. Check if node.left: before appending instead.
  • In the DFS version, visiting the right child first (rows come out right to left), or forgetting to open a new row when depth == len(result) (an IndexError).

Python notes

  • collections.deque is a double-ended queue: append and popleft are both O(1). A plain list's pop(0) is O(n).
  • for _ in range(len(queue)) computes the length once, before the loop starts, so appending to the queue inside the loop does not change how many times it runs.
  • if node.left: skips a missing child. TreeNode objects are always truthy, None is falsy.
  • deque is pre-imported for solutions on this site (as it is on LeetCode). In your own file write from collections import deque.

What an interviewer might ask next, and what changes.

  • Binary Tree Right Side View LC 199 — the same level loop, but keep only the last node of each level.
  • Binary Tree Zigzag Level Order Traversal LC 103 — same loop, but every other level is read right to left: reverse that level's list, or fill it from the other end.
  • Average of Levels in Binary Tree LC 637 — compute sum(level) / size for each level instead of storing the values.
  • N-ary Tree Level Order Traversal LC 429 — identical loop, but push node.children (a list of any length) instead of left and right.
