Decode Ways Medium

LeetCode #91 ↗
Status

Count the ways a string of digits can be read back as letters when A = 1, B = 2, ..., Z = 26.

Problem

A message of capital letters was encoded with A → "1", B → "2", ..., Z → "26", and the codes were written next to each other. Given the digit string s, return the number of different ways to split it back into letters.

  • A piece must be "1" to "9" (one digit) or "10" to "26" (two digits).
  • "0" on its own is not a letter, and a piece may not start with 0 ("06" is not F).
  • If no split works, the answer is 0. The answer fits in a 32-bit integer.

Examples

Example 1
Input: s = "12"
Output: 2
"1 2" → AB, or "12" → L.
Example 2
Input: s = "226"
Output: 3
"2 2 6" → BBF, "22 6" → VF, "2 26" → BZ.
Example 3
Input: s = "06"
Output: 0
"0" is not a letter and "06" is not a valid code.

Constraints

  • 1 <= len(s) <= 100
  • s contains only digits and may start with 0

Think first try before reading the solution

Think about how a decoding of s can end: its last letter used either the last digit alone or the last two digits.
Let dp[i] = number of ways to decode the first i characters. If s[i-1] is not '0', add dp[i-1]. If s[i-2:i] is between 10 and 26, add dp[i-2].
dp[0] = 1: the empty prefix has exactly one decoding (nothing). Watch the zeros: a '0' can only be the second digit of "10" or "20".

Key idea

This is Climbing Stairs with rules about which steps are allowed. Reading the digits left to right, each letter consumes one digit or two digits, like a 1-step or a 2-step. The difference is that a step only counts if the piece it consumes is a real code:

  • one digit: "1".."9" (anything except "0");
  • two digits: "10".."26" (so not "06", and not "27").

Let dp[i] be the number of ways to decode the prefix s[:i]. Look at the last letter of such a decoding: it used s[i-1] alone (then the rest is a decoding of s[:i-1]) or s[i-2:i] (then the rest decodes s[:i-2]). So

dp[i] = (dp[i-1] if the one-digit piece is valid) + (dp[i-2] if the two-digit piece is valid)

with dp[0] = 1 for the empty prefix. Zeros are where the count can collapse: "30" has no decoding at all, because "0" cannot stand alone and "30" is too large.

Approaches from the obvious one to the one you want in an interview

ways(i) = number of decodings of the prefix s[:i]. The last letter used one digit (s[i-1], valid unless it is '0') or two digits (s[i-2:i], valid if 10..26), so add ways(i-1) and/or ways(i-2). ways(0) = 1.

Correct, but each call can branch twice and the same prefixes are recounted many times. On a string of 1s it is exactly the exponential Fibonacci recursion.

Dry run

  1. s = "226": ways(3) = ways(2) (piece "6") + ways(1) (piece "26")
  2. ways(2) = ways(1) (piece "2") + ways(0) (piece "22") = 1 + 1 = 2
  3. ways(1) = ways(0) = 1, computed again for the second branch
  4. ways(3) = 2 + 1 = 3

Python

class Solution:
    def numDecodings(self, s: str) -> int:
        def ways(i: int) -> int:
            """Number of ways to decode the prefix s[:i]."""
            if i == 0:                                  # empty prefix: one way (decode nothing)
                return 1
            total = 0
            if s[i - 1] != "0":                         # last letter is one digit, 1..9
                total += ways(i - 1)
            if i >= 2 and 10 <= int(s[i - 2:i]) <= 26:  # last letter is two digits, 10..26
                total += ways(i - 2)
            return total

        return ways(len(s))
Time O(2ⁿ)Space O(n)

Up to two recursive calls per position without memory; the call stack is n deep.

When to use: Only to find the recurrence; a 100-digit string of 1s would take longer than the age of the universe.

Cache ways(i). Only n + 1 prefixes exist, and each does O(1) work (two checks and up to two lookups), so the whole thing is O(n). The validity checks are unchanged; the cache only removes the repeated subtrees.

Python

class Solution:
    def numDecodings(self, s: str) -> int:
        @cache                                          # ways(i) is computed once per prefix length
        def ways(i: int) -> int:
            if i == 0:
                return 1
            total = 0
            if s[i - 1] != "0":
                total += ways(i - 1)
            if i >= 2 and 10 <= int(s[i - 2:i]) <= 26:
                total += ways(i - 2)
            return total

        return ways(len(s))
Time O(n)Space O(n)

n + 1 states, O(1) work each; cache and call stack are O(n).

When to use: Natural if you think recursively; fine for n = 100.

Fill dp[0..n] left to right. dp[0] = 1; for each i, start at 0, add dp[i-1] if the last digit is a valid one-digit code, and add dp[i-2] if the last two digits are a valid two-digit code.

A cell that ends up 0 means that prefix cannot be decoded, and then no longer prefix can be either: a two-digit piece that "jumps over" the bad position would start with 1 or 2, and that digit alone would have decoded the shorter prefix. So once a 0 appears, the answer is 0 (you could stop early).

Dry run

  1. s = "226": dp = [1, ?, ?, ?]
  2. dp[1]: "2" valid → 1
  3. dp[2]: "2" valid → +dp[1] = 1; "22" valid → +dp[0] = 1; total 2
  4. dp[3]: "6" valid → +dp[2] = 2; "26" valid → +dp[1] = 1; total 3

Python

class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)
        dp = [0] * (n + 1)              # dp[i] = ways to decode the prefix s[:i]
        dp[0] = 1                       # the empty prefix: one way
        for i in range(1, n + 1):
            if s[i - 1] != "0":                         # one-digit piece 1..9
                dp[i] += dp[i - 1]
            if i >= 2 and 10 <= int(s[i - 2:i]) <= 26:  # two-digit piece 10..26
                dp[i] += dp[i - 2]
        return dp[n]
Time O(n)Space O(n)

One pass, constant work per character.

When to use: The clearest way to see where zeros make the count collapse.

Watch it run

As in Climbing Stairs, each cell reads only the previous two, so keep two_back (dp[i-2]) and one_back (dp[i-1]). Start with one_back = dp[0] = 1. two_back starts at 0 and is never read at i = 1, because there is no two-digit piece yet.

Dry run

  1. s = "11106": start (two_back, one_back) = (0, 1)
  2. "1" → 1; "1","11" → 2; "1","11" → 3
  3. "0" alone invalid, "10" valid → +dp[2] = 2 → 2
  4. "6" valid → +2, "06" invalid → 2. Answer 2

Python

class Solution:
    def numDecodings(self, s: str) -> int:
        two_back, one_back = 0, 1       # dp[i-2] and dp[i-1]; one_back starts as dp[0] = 1
        for i in range(1, len(s) + 1):
            current = 0
            if s[i - 1] != "0":
                current += one_back
            if i >= 2 and 10 <= int(s[i - 2:i]) <= 26:
                current += two_back
            two_back, one_back = one_back, current
        return one_back
Time O(n)Space O(1)

One pass, three integers of state.

When to use: The interview answer once the table version is clear.

Common mistakes

  • Checking the two-digit piece with int(piece) <= 26 only: "06" becomes 6 and passes. Require 10 <= int(piece) <= 26, which also rules out a leading zero.
  • Treating "0" as a letter. A single '0' adds nothing; it must be the second digit of "10" or "20".
  • Starting with dp[0] = 0. Every count is built from dp[0], so the whole table would be 0. The empty prefix has one decoding.
  • Returning 0 as soon as you see a '0': "10" and "2101" are decodable. Let the recurrence handle zeros.

Python notes

  • @cache on an inner ways(i) memoises the top-down version; the string s is read from the enclosing scope. The recursion is len(s) frames deep (at most 100 here), well below Python's default recursion limit of 1000.
  • s[i - 2:i] is the two-character piece ending at position i - 1; int("06") is 6, which is exactly why the lower bound 10 matters.
  • "10" <= piece <= "26" also works for two-digit strings (string comparison is lexicographic), but int states the intent more plainly.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Decode Ways II LC 639 — '*' stands for any digit 1-9: each piece contributes a number of letters (e.g. "1*" has 9), so you multiply counts and work modulo 10^9 + 7.
  • Climbing Stairs LC 70 — the same two-term recurrence with every step always allowed: a string of only 1s gives Fibonacci numbers.
  • Word Break LC 139 — pieces are dictionary words of any length, and you ask "possible?" instead of "how many?": the look-back is over all cut points.
  • Count Number of Texts LC 2266 — pressing a phone key 1-4 times makes one letter: look back up to 3 or 4 equal digits instead of 2.
  • List all decodings — the count can be exponential, so listing needs backtracking (as in Letter Combinations of a Phone Number); the DP only counts.
