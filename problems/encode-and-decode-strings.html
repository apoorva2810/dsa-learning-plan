Encode and Decode Strings Medium

LeetCode #271 ↗
Status

Pack a list of strings into one string so the exact list can be rebuilt later.

Problem

Design a way to send a list of strings as one string and rebuild exactly the same list on the other side.

Implement a class Codec:

  • encode(strs) takes a list of strings and returns a single string.
  • decode(s) takes a string produced by encode and returns the original list.

The strings may contain any of the 256 characters with codes 0–255: letters, digits, #, ,, spaces, newlines and so on. Strings may be empty, and the list itself may be empty. You choose the format, but do not use eval or a serialisation library such as json or pickle: designing the format is the exercise.

On this site the tests call Solution().roundTrip(strs), which encodes with one Codec object, decodes with a fresh one (like two machines), and compares the result with strs. Keep that small class when you edit the code.

Examples

Example 1
Input: strs = ["neet", "code", "love", "you"]
Output: ["neet", "code", "love", "you"]
One possible encoding is 4#neet4#code4#love3#you. Any format is fine as long as decode rebuilds the list.
Example 2
Input: strs = ["we", "say", ":", "yes"]
Output: ["we", "say", ":", "yes"]
Example 3
Input: strs = ["", "#", "4#ab"]
Output: ["", "#", "4#ab"]
Empty strings, # and digits inside the data are exactly what breaks naive formats.

Constraints

  • 1 <= len(strs) <= 200 (the tests here also try an empty list)
  • 0 <= len(strs[i]) <= 200
  • strs[i] may contain any character with code 0-255
  • follow-up: make it work for any characters at all

Think first try before reading the solution

Joining with a separator such as , fails as soon as a string contains ,. What could tell the decoder where a string ends without looking at its contents?
If the decoder knew a string's length before reading it, it could copy exactly that many characters, whatever they are.

Key idea

The decoder sees one long string and has to find where each original string ends. Any marker you choose, such as , or #, can also appear inside the data, and then the decoder cannot tell a real boundary from a character that only looks like one.

There are two standard fixes. Escaping rewrites every marker-like character inside the data, so an unescaped marker can only mean "boundary"; the decoder must then read the data one character at a time. A length prefix announces how long the next string is before sending it; the decoder copies that many characters by count and never inspects them, so their content cannot confuse it. Real protocols such as HTTP chunked transfer encoding frame their data the second way.

Approaches from the obvious one to the one you want in an interview

The input only uses characters 0–255, so pick a character outside that range, chr(256), and put it after every string. Decoding is a single split. Ending each string with the marker (instead of placing it only between strings) keeps [] (encodes to "") and [""] (encodes to one marker) distinct.

This is not slow; its weakness is that it is correct only because of a promise about the input. If the strings could contain arbitrary Unicode (the follow-up), no character is guaranteed to be unused and the format breaks.

Dry run

  1. ["we", "say"] → "we" + END + "say" + END
  2. split(END) → ["we", "say", ""]; drop the last, always empty, piece → ["we", "say"]
  3. [""] → one END → split gives ["", ""] → [""]

Python

class Codec:
    END = chr(256)                     # first character above the 0-255 range of the input

    def encode(self, strs: List[str]) -> str:
        # END after every string (a terminator, not a separator), so [] and [""] differ
        return "".join(s + self.END for s in strs)

    def decode(self, s: str) -> List[str]:
        parts = s.split(self.END)
        return parts[:-1]              # the piece after the last END is always ""



# The judge's check, written out so the tests can run it: one Codec encodes,
# a fresh Codec decodes (as if on another machine), and the result must equal strs.
class Solution:
    def roundTrip(self, strs: List[str]) -> List[str]:
        wire = Codec().encode(strs)
        assert isinstance(wire, str), "encode must return a single string"
        return Codec().decode(wire)
Time O(L)Space O(L)

L = total number of characters. One join and one split, each linear.

When to use: Acceptable when the alphabet is guaranteed; fails the "any character" follow-up.

Use / as an escape character. While encoding, double every real / (a/b becomes a//b) and end every string with /:. While decoding, read one character at a time: // means one real slash, /: means "this string is complete", and anything else is ordinary data. After escaping, a single / can only start one of those two pairs, so the format is unambiguous for any characters.

It works for every alphabet, but the decoder must examine every character in a Python-level loop, and data full of slashes doubles in size.

Dry run

  1. ["a/b", ":"] → a//b/: + :/: → "a//b/::/:"
  2. decode: a → data; // → /; b → data; /: → emit a/b
  3. : → data; /: → emit : → ["a/b", ":"]

Python

class Codec:
    def encode(self, strs: List[str]) -> str:
        parts = []
        for s in strs:
            parts.append(s.replace("/", "//"))    # every real '/' becomes '//'
            parts.append("/:")                    # '/:' can only mean "end of string"
        return "".join(parts)

    def decode(self, s: str) -> List[str]:
        result, current = [], []
        i = 0
        while i < len(s):
            if s[i] == "/":
                if s[i + 1] == "/":               # escaped slash -> one real '/'
                    current.append("/")
                else:                             # '/:' -> the current string is complete
                    result.append("".join(current))
                    current = []
                i += 2                            # both pairs are two characters long
            else:
                current.append(s[i])
                i += 1
        return result



# The judge's check, written out so the tests can run it: one Codec encodes,
# a fresh Codec decodes (as if on another machine), and the result must equal strs.
class Solution:
    def roundTrip(self, strs: List[str]) -> List[str]:
        wire = Codec().encode(strs)
        assert isinstance(wire, str), "encode must return a single string"
        return Codec().decode(wire)
Time O(L)Space O(L)

Every character is read once while encoding and once while decoding; the output is at most about 2L characters.

When to use: When the format must stay readable or be streamed character by character; more fiddly than length prefixes.

Write every string as its length, a #, then the string: ["neet", "co#de"] becomes 4#neet5#co#de.

To decode, keep an index i that always points at the start of a length field. Find the first # at or after i: everything between them is digits, so that # must be the end of the length field (length fields contain no #). Convert the digits to a number n, copy the next n characters as one string, and move i just past them. The contents are copied by count and never inspected, so they may contain #, digits or anything else.

Dry run

  1. ["neet", "co#de", ""] → 4#neet + 5#co#de + 0# = "4#neet5#co#de0#"
  2. i = 0: # at 1 → length 4 → copy neet → i = 6
  3. i = 6: # at 7 → length 5 → copy co#de (its # is never examined) → i = 13
  4. i = 13: # at 14 → length 0 → copy "" → i = 15 = end

Python

class Codec:
    def encode(self, strs: List[str]) -> str:
        # each chunk: the length in decimal, a '#', then the raw string
        return "".join(f"{len(s)}#{s}" for s in strs)

    def decode(self, s: str) -> List[str]:
        result = []
        i = 0                                     # always at the start of a length field
        while i < len(s):
            j = s.index("#", i)                   # first '#' after the digits
            length = int(s[i:j])
            start = j + 1
            result.append(s[start:start + length])   # copy by count, whatever the characters are
            i = start + length                    # jump to the next length field
        return result



# The judge's check, written out so the tests can run it: one Codec encodes,
# a fresh Codec decodes (as if on another machine), and the result must equal strs.
class Solution:
    def roundTrip(self, strs: List[str]) -> List[str]:
        wire = Codec().encode(strs)
        assert isinstance(wire, str), "encode must return a single string"
        return Codec().decode(wire)
Time O(L)Space O(L)

L = total characters. Length fields add a few digits per string; each data character is copied once.

When to use: The standard answer. Works for any alphabet and never scans the data itself.

Common mistakes

  • Joining with a delimiter that can occur in the data: ",".join(["a,b"]) decodes to ["a", "b"].
  • Separator instead of terminator: SEP.join(strs) turns both [] and [""] into "", so one of them cannot be decoded correctly. Put a marker after every string, or use length prefixes.
  • Searching for # from the start of the whole string, or calling s.split("#"): the contents may contain #. Search only from the current position i, which always sits on a length field.
  • Reading only one digit for the length. A 12-character string needs the length field 12; read every digit up to the #.
  • Using str.split() with no argument in the delimiter version: it splits on any whitespace and drops empty strings.

Python notes

  • s.index("#", i) finds the first # at or after position i (and raises ValueError if there is none; s.find returns -1 instead).
  • f"{len(s)}#{s}" builds one chunk; "".join(chunks) concatenates many pieces in linear time.
  • Slicing s[a:b] copies b - a characters, so the decoder copies every character exactly once.
  • chr(256) is a valid Python character (strings are Unicode), but it lies outside the 0–255 range of the input.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Serialize and Deserialize Binary Tree LC 297 — the same framing question for a tree: write values in preorder with a marker for missing children, then rebuild recursively.
  • Serialize and Deserialize BST LC 449 — the BST ordering lets you drop the missing-child markers and rebuild from preorder with value bounds.
  • Fixed-width length header — write each length as exactly 4 characters (or 4 bytes). The decoder never searches for a # at all, at the cost of a maximum string length. Binary protocols work this way.
  • What if the strings can contain any Unicode character? — LeetCode's follow-up. The length-prefix format already handles it unchanged; the reserved-character approach breaks, because no character is guaranteed to be unused.
  • What if the encoded string arrives in pieces over a network? — with length prefixes the receiver always knows how many more characters it is waiting for; with a terminator it has to scan everything that arrives.
