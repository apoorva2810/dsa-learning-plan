Linked List Cycle Easy

LeetCode #141 ↗
Status

Decide whether following next pointers from the head ever loops back.

Problem

You are given head, the first node of a linked list. Return True if the list contains a cycle: some node's next points back to a node that appears earlier, so following next from the head never reaches None. Otherwise return False.

LeetCode describes each test with the list's values plus pos, the index of the node that the last node links back to (pos = -1 means no cycle). pos is not given to your function; you only get head.

On this site the tests are plain data, so every solution also has a small helper hasCycleFromList(vals, pos) that builds the list (closing the loop when pos != -1) and then calls hasCycle(head), the method LeetCode calls.

Examples

Example 1
Input: head = [3, 2, 0, -4], pos = 1
Output: true
The last node (-4) links back to the node at index 1 (value 2).
Example 2
Input: head = [1, 2], pos = 0
Output: true
Node 2 links back to node 1.
Example 3
Input: head = [1], pos = -1
Output: false
A single node whose next is None.

Constraints

  • 0 <= number of nodes <= 10^4
  • -10^5 <= Node.val <= 10^5
  • pos is -1 or a valid index
  • follow-up: O(1) extra memory

Think first try before reading the solution

Without a cycle, walking next eventually reaches None. With one, you walk forever. How could you notice you are going round in circles?
Remembering every node you have visited in a set works, but costs O(n) memory. Could two walkers moving at different speeds tell you the same thing?
Move slow one step and fast two steps at a time. If fast reaches None, there is no cycle. If there is one, both end up inside it and fast closes the gap by one node per step, so they must land on the same node.

Key idea

Picture two runners on a track. If the track is a straight road, the fast runner reaches the end and stops. If the track is a loop, the fast runner eventually comes up behind the slow one and passes it.

Floyd's cycle detection (also called tortoise and hare) does exactly that with two pointers: slow moves one node per step and fast moves two. With no cycle, fast reaches None first. With a cycle, both pointers end up inside it, and from then on every step brings fast exactly one node closer to slow (it gains 2 − 1 = 1). A gap that shrinks by one each step cannot jump over zero, so they meet on the same node, within one lap of slow.

Only two pointers are stored, so the memory use is O(1), and the number of steps is at most about the list length plus the cycle length: O(n).

Approaches from the obvious one to the one you want in an interview

Walk the list and put every node (the node object, not its value) into a set. If you reach a node that is already in the set, you have come back to it, so there is a cycle. If you reach None, there is not.

This is correct and O(n) time, since each node is added and looked up once. The cost is memory: the set can hold all n nodes. The follow-up asks for O(1) extra memory, which this cannot give.

Dry run

  1. [3, 2, 0, -4], pos 1: visit 3, 2, 0, -4 → set has 4 nodes
  2. -4.next is the node 2 again → already in the set → True

Python

class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        seen = set()                            # nodes (not values) visited so far
        cur = head
        while cur:
            if cur in seen:                     # reached the same node twice: a loop
                return True
            seen.add(cur)
            cur = cur.next
        return False                            # fell off the end

    # LeetCode builds the (possibly cyclic) list for you and calls hasCycle(head) directly.
    # This site's tests are plain data, so this helper builds the list from vals and pos first.
    def hasCycleFromList(self, vals: List[int], pos: int) -> bool:
        nodes = [ListNode(v) for v in vals]
        for a, b in zip(nodes, nodes[1:]):
            a.next = b
        if nodes and pos != -1:
            nodes[-1].next = nodes[pos]         # close the loop
        return self.hasCycle(nodes[0] if nodes else None)
Time O(n)Space O(n)

Each node is added to and looked up in the set once; the set grows to n nodes.

When to use: Fine when memory does not matter, and it extends to 'return the first repeated node'.

Start slow and fast at the head. Each round, slow = slow.next and fast = fast.next.next, then check slow is fast.

  • No cycle: fast runs off the end (fast or fast.next becomes None) and we return False.
  • Cycle: once both pointers are inside the loop, fast gains exactly one node on slow per round. The gap between them shrinks 3, 2, 1, 0, so they meet, and we return True.

Two pointers, no set: O(1) extra memory.

Dry run

  1. [3, 2, 0, -4], tail → index 1. Start: slow = 0, fast = 0
  2. round 1: slow = 1 (2), fast = 2 (0)
  3. round 2: slow = 2 (0), fast = 1 (2): fast went round the loop and is now behind slow
  4. round 3: slow = 3 (-4), fast = 3 (-4) → same node → True

Python

class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        slow = fast = head
        while fast and fast.next:               # fast can jump two nodes
            slow = slow.next                    # 1 step
            fast = fast.next.next               # 2 steps
            if slow is fast:                    # the fast runner caught up: a loop
                return True
        return False                            # fast reached the end

    # LeetCode builds the (possibly cyclic) list for you and calls hasCycle(head) directly.
    # This site's tests are plain data, so this helper builds the list from vals and pos first.
    def hasCycleFromList(self, vals: List[int], pos: int) -> bool:
        nodes = [ListNode(v) for v in vals]
        for a, b in zip(nodes, nodes[1:]):
            a.next = b
        if nodes and pos != -1:
            nodes[-1].next = nodes[pos]         # close the loop
        return self.hasCycle(nodes[0] if nodes else None)
Time O(n)Space O(1)

fast reaches the end within n/2 rounds, or both enter the loop and meet within one more lap.

When to use: The interview answer, and the first half of Linked List Cycle II and Find the Duplicate Number.

Common mistakes

  • Reading fast.next.next without checking fast and fast.next first: while fast and fast.next: must test fast first, otherwise a list of even length raises AttributeError on None.
  • Comparing values (slow.val == fast.val) instead of nodes (slow is fast): [1, 1, 1, 1] without a cycle would report one.
  • Checking slow is fast before moving them: both start at head, so the check is true immediately. Move first, then compare.
  • Storing values in the visited set instead of nodes: duplicate values look like a revisit.

Python notes

  • slow is fast asks "are these the same object?". ListNode defines no __eq__, so == would also compare identity, but is says what you mean.
  • A set of nodes works because Python objects are hashable by identity unless their class says otherwise.
  • hasCycleFromList exists only because the site's tests are plain lists. On LeetCode, submit just hasCycle.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Linked List Cycle II LC 142 — return the node where the cycle starts: after slow and fast meet, restart one pointer at head and move both one step at a time; they meet again exactly at the cycle's entrance.
  • Find the Duplicate Number LC 287 — an array whose values are indices is a hidden linked list (i → nums[i]); the duplicate is the entrance of its cycle.
  • Happy Number LC 202 — the sequence of digit-square sums either reaches 1 or loops forever: run slow/fast on numbers instead of nodes.
  • Middle of the Linked List LC 876 — the same two speeds on a list without a cycle: when fast reaches the end, slow is at the middle.
  • How long is the cycle? — after the meeting, keep one pointer still and walk the other until it comes back, counting steps.
