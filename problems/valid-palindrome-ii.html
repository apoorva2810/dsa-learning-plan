Valid Palindrome II Easy 250

LeetCode #680 ↗
Status

Decide whether a string can become a palindrome by deleting at most one character.

Problem

You are given a string s of lowercase letters.

Return True if s can be turned into a palindrome (a string that reads the same forwards and backwards) by deleting at most one character, and False otherwise.

"At most one" includes zero: a string that is already a palindrome counts. The string is used exactly as given; there is no cleaning step and every character matters.

Examples

Example 1
Input: s = "aba"
Output: true
Already a palindrome. No deletion is needed, and zero deletions is allowed.
Example 2
Input: s = "abca"
Output: true
Delete the c to get "aba", or delete the b to get "aca". Either one works.
Example 3
Input: s = "abc"
Output: false
Deleting one character leaves "bc", "ac" or "ab"; none of them is a palindrome.

Constraints

  • 1 <= len(s) <= 10^5
  • s consists of lowercase English letters

Think first try before reading the solution

Start with the plain palindrome check: left and right walk inward while the characters match. If they never disagree, the answer is True. What do you know at the moment they first disagree?
Every pair outside the mismatch already matched its mirror, so the character to delete must be one of the two mismatched ones: s[left] or s[right].
Try both. Is s[left+1..right] a plain palindrome? Is s[left..right-1]? If either is, return True. The helper is the ordinary inward walk with no deletions left.

Key idea

Run the ordinary two-pointer palindrome check. While s[left] == s[right], those two characters are fine as they are, so the character we delete (if any) cannot be among them. Step inward.

At the first mismatch there are only two candidates: the deletion has to remove either s[left] or s[right], because removing anything else leaves this mismatched pair facing each other. Deleting s[left] means the rest must be a plain palindrome from left + 1 to right; deleting s[right] means left to right - 1. Check both with the same inward walk, this time with no deletions allowed. Either success means True; two failures mean False.

The main walk plus the two checks each cover the string at most once, so the whole thing is O(n) time with O(1) extra memory. Nothing is ever copied: "deleting" a character just means skipping its index.

Approaches from the obvious one to the one you want in an interview

Test s itself (zero deletions is allowed). If that fails, for every index i build the string without character i and test whether it is a palindrome.

Each test is O(n) and there are up to n + 1 of them, so the time is O(n²): for n = 10⁵ that is about 10¹⁰ character comparisons, far too slow. Every candidate is also a fresh string of n − 1 characters. The waste is that we re-check pairs that already matched, and that we try deletions at positions that cannot possibly help.

Dry run

  1. s = "abca": "abca" vs "acba" → differ at index 1 → a deletion is needed
  2. delete index 0 → "bca" vs "acb" → no
  3. delete index 1 → "aca" vs "aca" → palindrome → True

Python

class Solution:
    def validPalindrome(self, s: str) -> bool:
        def is_palindrome(text: str) -> bool:
            return text == text[::-1]

        if is_palindrome(s):                      # zero deletions is allowed
            return True
        for i in range(len(s)):
            candidate = s[:i] + s[i + 1:]         # s without character i
            if is_palindrome(candidate):
                return True
        return False
Time O(n²)Space O(n)

Up to n + 1 palindrome checks of O(n) each; every candidate is a new string of length n − 1.

When to use: Only as a way to see the structure of the problem; it times out on the real input size.

Walk left and right inward while s[left] == s[right]. Those pairs are fine as they are, so the deletion cannot involve them.

At the first mismatch, only two deletions can still work: remove s[left] or remove s[right]. Removing any other character leaves this mismatched pair facing each other. So test whether s[left+1..right] is a plain palindrome, or s[left..right-1] is. If either is, return True; otherwise False. If the main walk never finds a mismatch, s is already a palindrome.

The helper is the ordinary inward walk with no deletions. The main walk and the two helper calls each visit every character at most once, so the total is O(n) time, O(1) extra memory.

Dry run

  1. s = "abca": L=0 a, R=3 a → match → L=1, R=2
  2. L=1 b, R=2 c → mismatch: try deleting one of them
  3. option A: delete b, check s[2..2] = "c" → single character → palindrome → True

Python

class Solution:
    def validPalindrome(self, s: str) -> bool:
        def is_palindrome(lo: int, hi: int) -> bool:
            while lo < hi:                        # plain inward walk, no deletions left
                if s[lo] != s[hi]:
                    return False
                lo += 1
                hi -= 1
            return True

        left, right = 0, len(s) - 1
        while left < right:
            if s[left] != s[right]:               # first mismatch: one of these two must go
                return is_palindrome(left + 1, right) or is_palindrome(left, right - 1)
            left += 1
            right -= 1
        return True                               # no mismatch at all: already a palindrome
Time O(n)Space O(1)

The main walk stops at the first mismatch; each helper call walks the remaining window once.

When to use: The intended answer: linear time, constant extra memory, one branch point.

Watch it run

The same idea written so that the number of allowed deletions is a parameter. can_fix(lo, hi, deletions) walks inward; at a mismatch, if the budget is empty it fails, otherwise it tries deleting either side with one deletion fewer.

With a budget of 1 this does exactly what the optimal version does, in O(n). Its value is that it generalises: a budget of k costs O(2^k · n), which is fine for small k and shows why Valid Palindrome III (k up to n) needs dynamic programming instead. The recursion depth is at most k + 1, so there is no stack problem here.

Python

class Solution:
    def validPalindrome(self, s: str) -> bool:
        def can_fix(lo: int, hi: int, deletions: int) -> bool:
            while lo < hi:
                if s[lo] == s[hi]:
                    lo += 1
                    hi -= 1
                    continue
                if deletions == 0:                # mismatch with no deletion left
                    return False
                return (can_fix(lo + 1, hi, deletions - 1)      # delete s[lo] ...
                        or can_fix(lo, hi - 1, deletions - 1))  # ... or delete s[hi]
            return True

        return can_fix(0, len(s) - 1, 1)
Time O(n)Space O(1)

O(2^k · n) time and O(k) recursion depth for a budget of k; here k = 1.

When to use: When the interviewer asks 'and with k deletions?' for small k; otherwise the iterative version is clearer.

Common mistakes

  • Trying only one of the two skips, for example always deleting s[left]. On "cbbcc" the mismatch is b vs c; skipping the b leaves "bc" (not a palindrome), but skipping the c leaves "bb". Both options must be tested.
  • Using a deleted flag inside the main loop and skipping the left character on the first mismatch. Once you have committed to that skip you cannot go back and try the right one, which is the same bug in disguise.
  • Letting the helper delete again. After the one skip, the inner check must be a strict palindrome test; a second skip would allow two deletions.
  • Off-by-one bounds in the helper. After a mismatch at (left, right) the two windows are [left + 1, right] and [left, right - 1], both inclusive. Mixing inclusive and exclusive ends silently drops a character.
  • Deciding which side to skip by peeking one character ahead (if s[left + 1] == s[right]: skip left). On "abbab" the peek says skip the a, which leaves "bbab" and fails, while skipping the final b leaves "abba". Only a full check of each window is safe.

Python notes

  • A nested helper is_palindrome(lo, hi) can read s from the enclosing function (a closure), so it only needs the two indices. Walking lo and hi inward keeps the extra memory at O(1).
  • s[lo:hi + 1] == s[lo:hi + 1][::-1] is a one-line palindrome test, but it copies the slice twice: O(n) extra memory.
  • Strings are immutable, so "deleting" a character is never done by building a new string here: skip the index instead.
  • a or b short-circuits: when the first window is a palindrome, the second check never runs.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Valid Palindrome LC 125 — no deletion allowed, but spaces, punctuation and case must be ignored: the inner helper of this problem plus skipping over non-alphanumeric characters.
  • Valid Palindrome III LC 1216 — at most k deletions: branching at every mismatch costs O(2^k · n). The real fix is dynamic programming: compute the longest palindromic subsequence and check n - LPS <= k.
  • Longest Palindromic Subsequence LC 516 — the DP that powers the k-deletion version: dp[i][j] is the longest palindrome you can keep inside s[i..j].
  • Minimum Insertion Steps to Make a String Palindrome LC 1312 — insertions instead of deletions give the same answer, n - LPS: inserting a mirror for a character is as good as deleting it.
  • Palindrome Linked List LC 234 — a linked list has no right index to walk backwards from: find the middle with slow/fast pointers, reverse the second half, then compare.
  • Which character should be deleted? — return the index instead of a boolean: remember which of the two skips succeeded and return left or right, or -1 when the string is already a palindrome.
