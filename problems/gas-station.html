Gas Station Medium

LeetCode #134 ↗
Status

Find the one gas station on a circular road where you can start with an empty tank and drive all the way around.

Problem

There are n gas stations on a circular road. Station i holds gas[i] units of fuel. Driving from station i to the next one (i + 1, and from the last station back to station 0) uses cost[i] units.

You choose one station to start at, with an empty tank that can hold any amount. At every station you arrive at, you take all of its fuel, then drive to the next one. The tank must never go below 0 on the way.

Return the index of the starting station that lets you drive once all the way around, or -1 if no station works. If a valid start exists, it is unique.

Examples

Example 1
Input: gas = [1, 2, 3, 4, 5], cost = [3, 4, 5, 1, 2]
Output: 3
The change in fuel per station (gas minus cost) is [-2, -2, -2, 3, 3]. Starting at station 3 the tank reads 3, 6, 4, 2, 0 after each leg: never negative, and you are back at station 3.
Example 2
Input: gas = [2, 3, 4], cost = [3, 4, 3]
Output: -1
The stations supply 9 units in total but the lap needs 10, so no start can work.
Example 3
Input: gas = [5, 1, 2, 3, 4], cost = [4, 4, 1, 5, 1]
Output: 4
Changes per station: [1, -3, 1, -2, 3]. Start at station 4 and the tank reads 3, 4, 1, 2, 0.

Constraints

  • n == len(gas) == len(cost)
  • 1 <= n <= 10^5
  • 0 <= gas[i], cost[i] <= 10^4
  • if a valid starting station exists, it is unique

Think first try before reading the solution

Start with a simpler question: when is the lap impossible from every station? Compare the total fuel on the road with the total cost.
Suppose you start at station s and first run out of fuel on the leg after station j. Could any station between s and j be a good start instead? Think about how much fuel you had when you arrived at each of them.
No: you arrived at each of those stations with at least 0 fuel, so starting there with an empty tank is no better, and you would run dry at the same place. Jump straight to j + 1, reset the tank to 0 and keep going. If the total fuel is enough, the last candidate left is the answer.

Key idea

Write net[i] = gas[i] - cost[i]: how much the tank changes at station i (fill up, then drive on). You need a start where the running total of net stays at 0 or above for the whole lap. Two facts solve it.

1. The total decides whether an answer exists. If all the net values add up to a negative number, no start works. If the sum is 0 or more, some start does, so you only have to find it.

2. A failed start rules out everything it passed. Start at s and keep a running tank. Say the tank first goes negative on the leg after station j. Station s failed, and so does every station k with s < k <= j: you reached k with a tank of 0 or more, so starting there with an empty tank gives you no more fuel and you run dry at the same place. The next candidate is j + 1: reset the tank and carry on. One pass, and the stations are never re-tested.

Why does the last candidate work when the total is enough? The part of the circle before it is made of failed stretches, so its running total never dips below the final total of that part, which is some deficit D (zero or negative). The stretch from the candidate to the end never goes negative and finishes with a surplus S. Because the overall total is 0 or more, S + D >= 0, so the surplus covers the worst dip when the lap wraps around.

Approaches from the obvious one to the one you want in an interview

Try each station as the start. Drive around the circle once, adding gas[i] - cost[i] at every station, and stop that attempt the moment the tank goes negative. The first start whose lap finishes is the answer.

Each attempt can take up to n steps and there are n attempts, so it is O(n²). It repeats a lot of work: when a start fails, the attempts from every station it passed are re-run even though they were bound to fail too.

Dry run

  1. gas = [1, 2, 3, 4, 5], cost = [3, 4, 5, 1, 2] → changes [-2, -2, -2, 3, 3]
  2. start 0: tank -2 → fails at once; start 1 and start 2 fail the same way
  3. start 3: tank 3, 6, 4, 2, 0 → never negative, lap completed → return 3

Python

class Solution:
    def canCompleteCircuit(self, gas: List[int], cost: List[int]) -> int:
        n = len(gas)
        for start in range(n):
            tank = 0
            for step in range(n):                # visit n stations, wrapping around
                i = (start + step) % n
                tank += gas[i] - cost[i]         # fill up at i, then drive to the next station
                if tank < 0:                     # ran dry on this leg
                    break
            else:                                # no break: the whole lap worked
                return start
        return -1
Time O(n²)Space O(1)

Up to n stations per attempt and n attempts.

When to use: To confirm a faster solution on small inputs.

Make two checks in one pass.

  1. Total: if sum(gas) < sum(cost), return -1.
  2. Start: keep a running tank for the current candidate start. Add gas[i] - cost[i] at each station. If the tank goes negative, every station from start to i is ruled out, so set start = i + 1 and tank = 0.

After the loop, start is the answer. The total check guarantees that the final candidate is not just the last one standing: it really can finish the lap, because its surplus covers the deficits of everything before it. Every station is visited once.

Dry run

  1. gas = [5, 1, 2, 3, 4], cost = [4, 4, 1, 5, 1]: totals are 15 and 15, so a start exists
  2. station 0: tank 0 + 1 = 1 → keep going (start = 0)
  3. station 1: tank 1 - 3 = -2 → negative: stations 0..1 are out → start = 2, tank = 0
  4. station 2: tank 1; station 3: tank 1 - 2 = -1 → out: start = 4, tank = 0
  5. station 4: tank 3 → loop ends, return start = 4

Python

class Solution:
    def canCompleteCircuit(self, gas: List[int], cost: List[int]) -> int:
        if sum(gas) < sum(cost):                 # not enough fuel in total: no start works
            return -1
        tank = 0                                 # fuel since the current candidate start
        start = 0
        for i in range(len(gas)):
            tank += gas[i] - cost[i]             # fill up at i, then drive to i + 1
            if tank < 0:                         # cannot leave station i from `start`
                start = i + 1                    # no station in start..i can work either
                tank = 0
        return start
Time O(n)Space O(1)

Two sums plus one loop; three variables.

When to use: The standard answer. Be ready to explain why skipping start..i is safe.

Watch it run

Draw the running total P of gas[i] - cost[i] as a path that starts at 0. If it ends below 0, return -1. Otherwise start at the station right after the lowest point of the path.

Why: measured from that point, the path never goes below the start for the rest of the lap (it is the lowest point), and after it wraps around, the total, which is 0 or more, lifts the earlier part of the path. This is the same algorithm as the reset version, because each reset happens exactly when the path sets a new low. It is a good way to see why the answer is right.

Dry run

  1. gas = [5, 1, 2, 3, 4], cost = [4, 4, 1, 5, 1] → changes [1, -3, 1, -2, 3]
  2. running totals after each station: 1, -2, -1, -3, 0
  3. the lowest point is -3, reached after station 3 → start at station 4
  4. the total is 0, which is not negative, so return 4

Python

class Solution:
    def canCompleteCircuit(self, gas: List[int], cost: List[int]) -> int:
        total = 0                                # running total of gas[i] - cost[i]
        lowest = 0                               # lowest running total so far (the empty prefix counts as 0)
        start = 0                                # station right after the lowest point
        for i in range(len(gas)):
            total += gas[i] - cost[i]
            if total < lowest:                   # a new low after station i
                lowest = total
                start = i + 1
        return start if total >= 0 else -1
Time O(n)Space O(1)

One pass.

When to use: When you want the picture (a path and its lowest point) instead of the "reset" argument.

Common mistakes

  • Dropping the global check. Resetting the tank throws away the total, so the loop still ends with some start even when the lap is impossible (gas = [2, 3, 4], cost = [3, 4, 3]). Compare sum(gas) with sum(cost), or keep a separate running total.
  • Restarting at the station where you ran dry instead of the next one. You ran out on the leg after station j, so j belongs to the failed stretch and the next candidate is j + 1.
  • Picking the station with the most fuel or the best single net gain. In the first example the station with the most gas is index 4, but starting there fails: the tank reads 3, 1, -1.
  • Accepting any start when total gas equals total cost. With gas = [5, 1, 2, 3, 4] and cost = [4, 4, 1, 5, 1] the totals match (15 and 15), yet only station 4 works. The tank has to stay at 0 or above after every leg.
  • Simulating the lap with the wrong number of steps. Visit exactly n stations, using (start + step) % n for the wrap.

Python notes

  • for step in range(n): ... else: return start uses for/else: the else block runs only if the loop finished without break.
  • (start + step) % n walks around a circular list without special cases for the wrap.
  • sum(gas) < sum(cost) reads the whole check in one line. Two passes over the data are still O(n).
  • for g, c in zip(gas, cost) pairs the two lists without indexing; itertools.accumulate builds the prefix sums for the "start after the lowest point" version.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Maximum Subarray LC 53 — the rule "drop the prefix once the running total is negative" is Kadane's algorithm; Gas Station asks for where the best run starts instead of its sum.
  • Candy LC 135 — another greedy that is solved in two directions: satisfy the left neighbour in one pass and the right neighbour in a second pass, then take the larger requirement.
  • Minimum Number of Refueling Stops LC 871 — refuelling is optional and you want the fewest stops: drive until you cannot, then retroactively take the biggest tank among the stations you passed, using a max-heap.
  • Maximum Sum Circular Subarray LC 918 — the same running-sum view on a circle: a wrapping stretch is the total minus the smallest non-wrapping subarray.
  • What if several starts may work and you need all of them? — resetting at the first failure no longer suffices. Use prefix sums with running minimums from both ends to test each station in O(1), for O(n) overall.
  • What if the tank has a capacity limit? — surplus can now be wasted when the tank is full, so the "skip everything we passed" argument breaks and the problem needs a different method.
