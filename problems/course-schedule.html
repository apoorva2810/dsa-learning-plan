Course Schedule Medium

LeetCode #207 ↗
Status

Decide whether a set of courses with 'take this one first' rules can all be finished.

Problem

There are numCourses courses, numbered 0 to numCourses - 1. Each pair [a, b] in prerequisites is a rule: course b must be finished before course a can start.

Return True if there is some order in which you can complete every course, and False if there is not.

  • Every rule appears at most once.
  • A course can have any number of prerequisites, including none.

Examples

Example 1
Input: numCourses = 2, prerequisites = [[1, 0]]
Output: true
Take course 0, then course 1.
Example 2
Input: numCourses = 2, prerequisites = [[1, 0], [0, 1]]
Output: false
Course 1 needs course 0 first and course 0 needs course 1 first, so neither can ever start.
Example 3
Input: numCourses = 4, prerequisites = [[1, 0], [2, 0], [3, 1], [3, 2]]
Output: true
Take 0, then 1 and 2 in either order, then 3.

Constraints

  • 1 <= numCourses <= 2000
  • 0 <= len(prerequisites) <= 5000
  • prerequisites[i] = [a, b] with 0 <= a, b < numCourses
  • all pairs are distinct

Think first try before reading the solution

Draw every rule [a, b] as an arrow b → a. Picture a group of courses where nobody can go first. What shape do their arrows make?
Finishing is impossible exactly when the arrows contain a cycle (a loop that leads back to where it started). A course with no incoming arrows can be taken right now.
Count each course's unmet prerequisites. Repeatedly take a course whose count is 0 and lower the counts of the courses it unlocks. If you manage to take all numCourses, there is no cycle.

Key idea

The rules form a directed graph: one node per course and an arrow b → a for every rule "b before a". A valid plan is an ordering of the nodes where every arrow points forward, called a topological order. One exists exactly when the graph has no cycle: a cycle is a group of courses that each wait for another course in the same group, so none of them can ever be first.

Instead of hunting for cycles directly, simulate a student. A course's in-degree is the number of arrows coming into it, that is, how many prerequisites it still waits for. Every course with in-degree 0 can be taken right now. Taking it removes its outgoing arrows, which can drop other courses to 0. That is Kahn's algorithm, a breadth-first search (BFS) driven by a queue of free courses. Each course enters the queue once and each arrow is crossed once: O(V + E) for V courses and E rules. If the queue runs dry before every course is taken, the leftover courses sit on a cycle or wait behind one.

Approaches from the obvious one to the one you want in an interview

Act out the semester planning literally. Go through all the courses; take any course whose prerequisites are all already taken. Repeat full rounds until either every course is taken (True) or a whole round takes nothing new (False: the courses that are left all wait on each other).

It is correct, but it keeps re-checking courses that cannot possibly be ready yet. When the rules form a long chain listed in an unlucky order, each round frees a single course, so there are V rounds of O(V + E) work each.

Dry run

  1. numCourses = 4, rules [[1, 0], [2, 0], [3, 1], [3, 2]] → needs = {1: [0], 2: [0], 3: [1, 2]}
  2. Round 1: 0 needs nothing → take. 1 needs 0 (taken) → take. 2 needs 0 → take. 3 needs 1 and 2 → take.
  3. All four taken → True.
  4. With [[1, 0], [0, 1]]: round 1 takes nothing, since each course waits for the other → False.

Python

class Solution:
    def canFinish(self, numCourses: int, prerequisites: List[List[int]]) -> bool:
        needs = [[] for _ in range(numCourses)]     # needs[a] = prerequisites of course a
        for course, pre in prerequisites:
            needs[course].append(pre)
        taken = [False] * numCourses
        remaining = numCourses
        while remaining > 0:
            progress = False
            for course in range(numCourses):        # one full round over every course
                if not taken[course] and all(taken[p] for p in needs[course]):
                    taken[course] = True            # every prerequisite is already done
                    remaining -= 1
                    progress = True
            if not progress:                        # a whole round freed nothing: the rest wait on each other
                return False
        return True
Time O(V · (V + E))Space O(V + E)

Each round reads every course and every rule once; a chain can force V rounds.

When to use: Only to explain the idea. It is Kahn's algorithm without the bookkeeping that avoids rescanning.

Keep, for every course, a count of prerequisites it still waits for (its in-degree) and the list of courses it unlocks. Put every course with in-degree 0 in a queue. Then repeat: take a course from the queue, and for each course it unlocks lower the count by one; a count that reaches 0 joins the queue.

A course enters the queue only once its last prerequisite is taken, so the order of removal is always a legal plan. If the queue empties before all courses were taken, the leftovers each still wait on another leftover course, which means they sit on a cycle or behind one. Every course and every rule is handled once: O(V + E).

Dry run

  1. Rules [[1, 0], [2, 0], [3, 1], [3, 2]] → arrows 0→1, 0→2, 1→3, 2→3; in-degree {0: 0, 1: 1, 2: 1, 3: 2}
  2. Queue [0]. Take 0 → in-degrees of 1 and 2 drop to 0 → queue [1, 2]
  3. Take 1 → in-degree of 3 drops to 1. Take 2 → it drops to 0 → queue [3]
  4. Take 3. Four courses taken = numCourses → True

Python

class Solution:
    def canFinish(self, numCourses: int, prerequisites: List[List[int]]) -> bool:
        unlocks = [[] for _ in range(numCourses)]   # unlocks[b] = courses that need b
        indegree = [0] * numCourses                 # prerequisites each course still waits for
        for course, pre in prerequisites:
            unlocks[pre].append(course)
            indegree[course] += 1
        queue = deque(c for c in range(numCourses) if indegree[c] == 0)
        taken = 0
        while queue:
            pre = queue.popleft()
            taken += 1
            for course in unlocks[pre]:
                indegree[course] -= 1               # one prerequisite of `course` is now done
                if indegree[course] == 0:
                    queue.append(course)
        return taken == numCourses                  # anything left over is stuck on a cycle
Time O(V + E)Space O(V + E)

Each course is queued once and each rule lowers one count once; the lists hold all E rules.

When to use: The default answer: iterative, no recursion limit, and it extends directly to Course Schedule II.

Watch it run

Search the graph depth-first and colour each course: white (not visited yet), grey (on the path the search is walking right now) and black (fully explored, no cycle below it). Following an arrow into a grey course means the path has looped back on itself: a cycle. An arrow into a black course is harmless, because everything beyond it was already checked.

Two colours are not enough. With only "visited", the diamond 0 → 1 → 3, 0 → 2 → 3 would report a cycle when the second path reaches 3. Same O(V + E) as Kahn's algorithm; the trade-off is recursion depth.

Dry run

  1. Diamond [[1, 0], [2, 0], [3, 1], [3, 2]]: 0 grey → 1 grey → 3 grey; 3 has no arrows → black; 1 → black
  2. Back at 0 → 2 grey → arrow 2 → 3 finds 3 black: already safe, not a cycle → 2 black → 0 black → True
  3. With [[1, 0], [0, 1]]: 0 grey → 1 grey → arrow 1 → 0 finds 0 grey → cycle → False

Python

class Solution:
    def canFinish(self, numCourses: int, prerequisites: List[List[int]]) -> bool:
        unlocks = [[] for _ in range(numCourses)]
        for course, pre in prerequisites:
            unlocks[pre].append(course)
        WHITE, GREY, BLACK = 0, 1, 2                # unvisited / on the current path / finished
        colour = [WHITE] * numCourses

        def has_cycle(node: int) -> bool:
            colour[node] = GREY
            for nxt in unlocks[node]:
                if colour[nxt] == GREY:             # back onto the current path: a loop
                    return True
                if colour[nxt] == WHITE and has_cycle(nxt):
                    return True
            colour[node] = BLACK                    # everything reachable from here is cycle-free
            return False

        for course in range(numCourses):
            if colour[course] == WHITE and has_cycle(course):
                return False
        return True
Time O(V + E)Space O(V + E)

Each course turns grey and black once; each arrow is followed once. The call stack can be V deep.

When to use: When you also need the cycle itself (the grey path) or the 'safe' nodes. Mind the recursion limit.

Common mistakes

  • Detecting the cycle with a plain visited set in DFS. In 0 → 1 → 3, 0 → 2 → 3 the search meets course 3 a second time, but that is not a cycle. Use three colours: only reaching a node that is still on the current path (grey) means a loop.
  • Starting a single search from course 0. The rules can form several unconnected groups and the cycle may sit in one that 0 never reaches. Queue every course with in-degree 0, or start a DFS from every unvisited course.
  • Building the lists with [[]] * numCourses: that is one list repeated, so every append lands in all of them. Use [[] for _ in range(numCourses)].
  • Recomputing in-degrees by rescanning all the rules after every course you take. That is the brute force below, O(V · (V + E)). Lower the counts as you go.
  • Deep recursion: a chain of 2000 courses means 2000 nested DFS calls, past Python's default limit of 1000. Kahn's version has no recursion at all.

Python notes

  • for course, pre in prerequisites: unpacks each rule into two named parts, which is far easier to read than p[0] and p[1].
  • [[] for _ in range(n)] builds n separate lists; [[]] * n builds n references to the same list.
  • collections.deque gives O(1) popleft(). A list's pop(0) shifts every element and costs O(n).
  • If you choose the recursive DFS, sys.setrecursionlimit(10_000) raises Python's default limit of 1000 nested calls.
