Insert Greatest Common Divisors in Linked List Medium 250

LeetCode #2807 ↗
Status

Between every two neighbouring nodes of a linked list, insert a node holding their greatest common divisor.

Problem

You are given the head of a singly linked list whose nodes hold positive integers.

For every pair of nodes that sit next to each other, insert a new node between them whose value is the greatest common divisor of the two values (the largest integer that divides both). Return the head of the changed list.

A list with a single node has no neighbouring pair, so it is returned unchanged.

Examples

Example 1
Input: head = [12, 18, 8]
Output: [12, 6, 18, 2, 8]
gcd(12, 18) = 6 goes between 12 and 18; gcd(18, 8) = 2 goes between 18 and 8.
Example 2
Input: head = [7, 5]
Output: [7, 1, 5]
7 and 5 share no divisor but 1, so a node with value 1 is inserted.
Example 3
Input: head = [5]
Output: [5]
One node, no pair, nothing to insert.

Constraints

  • 1 <= number of nodes <= 5000
  • 1 <= Node.val <= 1000

Think first try before reading the solution

Two sub-problems: computing a gcd (Euclid, or math.gcd) and inserting a node between two others. Solve them separately.
To insert new between cur and cur.next, point new at cur.next first, then point cur at new. ListNode(g, cur.next) does the first part in the constructor.
After inserting, the next pair to look at is the old neighbour and the node after it. So move cur two steps: over the node you just inserted, onto the old neighbour. Moving one step would pair the new node with the neighbour and insert forever.

Key idea

The problem is two small things glued together. The gcd of two numbers is found by Euclid's algorithm: gcd(a, b) = gcd(b, a % b) until the second number is 0 (so gcd(18, 8) → gcd(8, 2) → gcd(2, 0) = 2); Python's math.gcd does it for you. Inserting into a singly linked list only needs the node before the gap: cur.next = ListNode(g, cur.next) creates the new node already pointing at the old neighbour, then hooks cur onto it. No node is lost because the old neighbour is read before cur.next is overwritten.

The only trap is the walk. After an insertion the list looks like cur → new → old neighbour → ..., and the next pair to handle is old neighbour and whatever follows it. So cur must jump two nodes, cur = cur.next.next, skipping the node just inserted. Stop when cur.next is None: the last node has no neighbour after it.

Every original node is visited once and one node is created per gap: O(n) time, O(1) extra space besides the new nodes.

Approaches from the obvious one to the one you want in an interview

Avoid pointer surgery altogether. Read the values into a Python list, build a second list with gcd(a, b) placed between every two neighbours, then turn that into fresh nodes with a dummy head and a tail pointer.

It works and it is hard to get wrong, but it allocates a new node for every value instead of only for the gaps, and it needs an O(n) array. The in-place version below does the same job with the nodes you already have.

Dry run

  1. [12, 18, 8] → values = [12, 18, 8]
  2. pairs (12, 18) → 6 and (18, 8) → 2: with_gcds = [12, 6, 18, 2, 8]
  3. build nodes 12 → 6 → 18 → 2 → 8 after a dummy, return dummy.next

Python

class Solution:
    def insertGreatestCommonDivisors(self, head: Optional[ListNode]) -> Optional[ListNode]:
        values = []
        node = head
        while node:                                   # 1. read every value
            values.append(node.val)
            node = node.next
        with_gcds = [values[0]]
        for a, b in zip(values, values[1:]):          # 2. gcd(a, b) between every neighbouring pair
            with_gcds.append(math.gcd(a, b))
            with_gcds.append(b)
        dummy = ListNode()                            # 3. build a fresh list behind a dummy head
        tail = dummy
        for v in with_gcds:
            tail.next = ListNode(v)
            tail = tail.next
        return dummy.next
Time O(n)Space O(n)

Three linear passes; the value array and the rebuilt list both hold about 2n items.

When to use: When you want to separate the arithmetic from the pointer work, or the input must not be modified.

Walk with one pointer cur. While cur has a neighbour, compute g = gcd(cur.val, cur.next.val) and insert a node: cur.next = ListNode(g, cur.next) builds the node already pointing at the old neighbour and hooks cur onto it. Then move cur two steps, cur = cur.next.next, so it skips the new node and lands on the old neighbour, which is the left end of the next pair.

Nothing is copied, no extra array, one new node per gap. The head is unchanged, so return the pointer you were given.

Dry run

  1. [12, 18, 8], cur = 12: gcd(12, 18) = 6 → 12 → 6 → 18 → 8, cur jumps to 18
  2. cur = 18: gcd(18, 8) = 2 → 12 → 6 → 18 → 2 → 8, cur jumps to 8
  3. cur = 8 has no next: stop, return head

Python

class Solution:
    def insertGreatestCommonDivisors(self, head: Optional[ListNode]) -> Optional[ListNode]:
        cur = head
        while cur.next:                               # the last node has no neighbour: stop there
            g = math.gcd(cur.val, cur.next.val)
            cur.next = ListNode(g, cur.next)          # new node -> old neighbour, then cur -> new node
            cur = cur.next.next                       # jump over the node we just inserted
        return head
Time O(n)Space O(1)

Each original node is visited once; the only allocations are the n - 1 inserted nodes, which are the output.

When to use: The interview answer. Say out loud why cur moves two steps.

Watch it run

Insert into everything after head first (the recursive call returns the same neighbour node, now with gcds behind it), then put gcd(head.val, neighbour.val) between head and that neighbour. A list of 0 or 1 nodes is returned as is.

It reads well, but each node costs a stack frame, and 5000 nodes is far beyond Python's default recursion limit of 1000 frames. This version is for understanding the structure, not for the largest inputs.

Dry run

  1. f([12, 18, 8]): first f([18, 8]), which first f([8]) = [8]
  2. f([18, 8]): insert gcd(18, 8) = 2 → 18 → 2 → 8
  3. f([12, 18, 8]): insert gcd(12, 18) = 6 → 12 → 6 → 18 → 2 → 8

Python

class Solution:
    def insertGreatestCommonDivisors(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if head is None or head.next is None:         # 0 or 1 node: nothing to insert
            return head
        neighbour = self.insertGreatestCommonDivisors(head.next)   # the same node, with gcds behind it
        head.next = ListNode(math.gcd(head.val, neighbour.val), neighbour)
        return head
Time O(n)Space O(n)

One call per node, so the call stack is as deep as the list is long.

When to use: For understanding the structure; the loop is the one to use for long lists.

Common mistakes

  • Moving cur one step after inserting (cur = cur.next). cur then sits on the new gcd node and pairs it with the old neighbour, inserting another node, and another: the loop never reaches the end of the list.
  • Overwriting cur.next before saving the old neighbour. new = ListNode(g); cur.next = new; new.next = cur.next loses the rest of the list (new.next becomes new itself, a cycle). Build the new node with ListNode(g, cur.next) or save nxt = cur.next first.
  • Computing the gcd after the insertion. Then cur.next.val is the gcd you just inserted, not the neighbour's value.
  • Looping while cur: and reading cur.next.val inside. On the last node cur.next is None and .val raises; the loop condition must be while cur.next: (or while cur and cur.next: if an empty list were possible).
  • Returning cur instead of head. The head node never changes here, so return the pointer you were given.

Python notes

  • math.gcd(a, b) is pre-imported. Writing Euclid yourself is three lines: while b: a, b = b, a % b then return a.
  • ListNode(val, next) takes the successor as its second argument, so ListNode(g, cur.next) builds the node already linked into place.
  • cur = cur.next.next is safe right after the insertion: cur.next is the new node and cur.next.next is the old neighbour, which exists.
  • The tests write lists as Python lists; the site turns [12, 18, 8] into nodes before the call and converts the head you return back.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Remove Duplicates from Sorted List LC 83 — the mirror image: look at neighbouring pairs and delete a node (cur.next = cur.next.next) instead of inserting one.
  • Insert into a Sorted Circular Linked List LC 708 — one insertion, but you must find the gap first in a list that loops back on itself, with all-equal values and an empty list as edge cases.
  • Add Two Numbers LC 2 — also builds new nodes while walking, but into a separate result list with a dummy head, and with a carry between steps.
  • Reverse Linked List LC 206 — pointer surgery practice: here you relink existing nodes instead of creating new ones, and a saved next is again what keeps the rest of the list reachable.
  • Insert the least common multiple instead — lcm(a, b) = a * b // gcd(a, b) (also math.lcm in Python 3.9+); the walk is identical, only the value changes.
  • Insert only when the gcd is greater than 1 — coprime neighbours get no node. Now cur moves one step when nothing was inserted and two when something was, so the jump depends on the branch.
