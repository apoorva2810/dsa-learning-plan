Reverse Linked List II Medium 250

LeetCode #92 ↗
Status

Reverse only the nodes between two given positions of a linked list and leave the rest as it is.

Problem

You are given head, the first node of a singly linked list, and two positions left and right, counted from 1 at the head, with left <= right.

Reverse the nodes from position left to position right (both included), leave every other node where it is, and return the head of the resulting list. If left is 1, the head itself is inside the window, so the result starts with a different node.

Aim to re-link the nodes rather than copy values from node to node.

Examples

Example 1
Input: head = [2, 4, 6, 8, 10, 12], left = 2, right = 5
Output: [2, 10, 8, 6, 4, 12]
Positions 2 to 5 hold 4, 6, 8, 10. Reversed, they read 10, 8, 6, 4. The 2 in front and the 12 behind stay.
Example 2
Input: head = [3, 5, 7], left = 1, right = 3
Output: [7, 5, 3]
The window is the whole list, so the head changes.
Example 3
Input: head = [9, 8], left = 2, right = 2
Output: [9, 8]
A window of one node reverses to itself.

Constraints

  • 1 <= n <= 500, where n is the number of nodes
  • -500 <= Node.val <= 500
  • 1 <= left <= right <= n
  • follow-up: do it in a single pass over the list

Reversing a whole list takes three variables: prev, cur and a saved nxt. Could you run the same loop on just the window? What must you know before starting it?

Key idea

Reverse Linked List flips every arrow from the head to the end. Here only the arrows inside the window may flip, and the window must still be connected to the nodes on both sides of it.

Walk to the node just before the window (before) and remember the window's first node (start). After the reversal start will be the window's last node. Then run exactly the flip loop from Reverse Linked List, once per window node (right - left + 1 times). When it stops, prev is the first node of the reversed window and cur is the first node after the window. Two pointer changes finish the job: before.next = prev (front part → reversed window) and start.next = cur (reversed window → back part).

A dummy node (a throwaway node placed in front of the head) means before always exists, even when left = 1, so the case where the head changes needs no special code. The walk and the loop together pass over at most right nodes: O(n) time and O(1) extra space.

Approaches from the obvious one to the one you want in an interview

Walk the list once and copy every value into a Python list. Reverse the slice from left - 1 to right with slicing, then walk the list a second time and write the values back, node by node.

It is correct and easy to see, but it never re-links anything: it moves values between nodes, which is not possible when the nodes carry other data that must stay attached, and it needs O(n) extra memory for the copy. The problem is really asking for the pointer version.

Dry run

  1. [2, 4, 6, 8, 10, 12], left = 2, right = 5 → values = [2, 4, 6, 8, 10, 12]
  2. slice values[1:5] = [4, 6, 8, 10] reversed → [2, 10, 8, 6, 4, 12]
  3. walk the nodes again and overwrite each val in order → the list reads [2, 10, 8, 6, 4, 12]

Python

class Solution:
    def reverseBetween(self, head: Optional[ListNode], left: int, right: int) -> Optional[ListNode]:
        values = []
        node = head
        while node:                                           # copy every value into a Python list
            values.append(node.val)
            node = node.next
        values[left - 1:right] = values[left - 1:right][::-1]  # reverse the window (positions start at 1)
        node = head
        for value in values:                                  # write the values back, node by node
            node.val = value
            node = node.next
        return head
Time O(n)Space O(n)

Two passes over the list and a copy of all n values.

When to use: A quick way to check an answer, not a pointer solution.

Reuse the flip loop from Reverse Linked List, but only for the window:

  1. Put a dummy node in front of the head and walk left - 1 steps from it. That node is before, the node just before the window.
  2. start = before.next is the window's first node. It will end up as the window's last node.
  3. Flip right - left + 1 nodes with the usual nxt = cur.next, cur.next = prev, prev, cur = cur, nxt, beginning with prev = None.
  4. Stitch the two ends: before.next = prev (the front part leads into the reversed window) and start.next = cur (the reversed window leads into the back part).

One pass over at most right nodes and three extra pointers: O(n) time, O(1) space. The dummy node makes left = 1 work without a special case.

Dry run

  1. 2 → 4 → 6 → 8 → 10 → 12, left = 2, right = 5. Walk 1 step from the dummy: before = 2, start = 4.
  2. Flip 4 nodes: 4.next = None, 6.next = 4, 8.next = 6, 10.next = 8. Now prev = 10 and cur = 12.
  3. before.next = prev → 2 → 10 → 8 → 6 → 4 → None.
  4. start.next = cur → 4 → 12. The list reads 2 → 10 → 8 → 6 → 4 → 12; return dummy.next.

Python

class Solution:
    def reverseBetween(self, head: Optional[ListNode], left: int, right: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)                 # a node before the head, so left = 1 needs no special case
        before = dummy
        for _ in range(left - 1):                 # walk to the node just before the window
            before = before.next
        start = before.next                       # the window's first node; it will end up as its last
        prev, cur = None, start
        for _ in range(right - left + 1):         # the usual flip loop, once per window node
            nxt = cur.next
            cur.next = prev
            prev, cur = cur, nxt
        before.next = prev                        # front part -> reversed window
        start.next = cur                          # reversed window -> back part
        return dummy.next
Time O(n)Space O(1)

At most right nodes are visited once; only a few pointers are kept.

When to use: The standard answer: it is Reverse Linked List plus two reconnections.

A different way to reverse a window without ever breaking the list. After finding before, let cur = before.next be the window's first node and keep it where it is. Repeat right - left times:

  • nxt = cur.next is the node right behind cur;
  • cur.next = nxt.next unhooks nxt from the chain;
  • nxt.next = before.next points nxt at the current front of the window;
  • before.next = nxt makes nxt the new front.

Each round moves one node in front of the others, so the window is built in reverse order, and cur sinks to its end by itself. There is no separate stitch step, because the front and back parts were never disconnected. The cost is the same as the other pointer version.

Dry run

  1. 2 → 4 → 6 → 8 → 10 → 12, left = 2, right = 5: before = 2, cur = 4, three rounds.
  2. Round 1: move 6 to the front of the window → 2 → 6 → 4 → 8 → 10 → 12.
  3. Round 2: move 8 → 2 → 8 → 6 → 4 → 10 → 12. Round 3: move 10 → 2 → 10 → 8 → 6 → 4 → 12.

Python

class Solution:
    def reverseBetween(self, head: Optional[ListNode], left: int, right: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        before = dummy
        for _ in range(left - 1):                 # walk to the node just before the window
            before = before.next
        cur = before.next                         # the window's first node; it stays put and sinks to the end
        for _ in range(right - left):             # one node per round moves, and cur itself needs no move
            nxt = cur.next                        # the node right behind cur
            cur.next = nxt.next                   # unhook nxt from the chain
            nxt.next = before.next                # point nxt at the current front of the window ...
            before.next = nxt                     # ... and make it the new front
        return dummy.next
Time O(n)Space O(1)

The same walk and the same number of node visits; three arrow changes per moved node.

When to use: Handy when you prefer the list to be valid after every round, or want to avoid the final stitch.

Common mistakes

  • Forgetting the dummy node. When left = 1 there is no node before the window, so before.next = prev has nothing to attach to and the new head is lost.
  • Counting the loop wrongly. The window has right - left + 1 nodes and the flip loop handles one per round. (The head-insertion variant below moves only right - left nodes, because the window's first node never needs to move.)
  • Skipping start.next = cur. After the loop start.next is None (the first value it was flipped to), so every node after the window is cut off.
  • Walking left steps instead of left - 1. Positions start at 1, and the walk starts on the dummy, so left - 1 steps reach the node before the window.
  • Returning head. If left = 1 the old head sits inside the window and is no longer first; return dummy.next.

Python notes

  • for _ in range(left - 1): repeats a step a fixed number of times. The underscore says that the loop variable itself is not needed.
  • prev, cur = cur, nxt evaluates the right side first and then assigns both names, so neither is overwritten too early.
  • ListNode(0, head) builds the dummy node in front of the head in one expression; the value 0 is never read.
  • The tests write lists as Python lists: the site turns [2, 4, 6] into nodes, calls reverseBetween, and turns the returned head back into a list.
