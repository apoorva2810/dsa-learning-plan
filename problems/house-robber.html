House Robber Medium

LeetCode #198 ↗
Status

Pick houses along a street to maximise the money taken, never taking two neighbours.

Problem

Houses stand in a row and nums[i] is the amount of money in house i. You may take the money from any set of houses, except that you can never take from two adjacent houses (their alarms are linked).

Return the largest total you can collect.

Examples

Example 1
Input: nums = [1, 2, 3, 1]
Output: 4
Take houses 0 and 2: 1 + 3 = 4.
Example 2
Input: nums = [2, 7, 9, 3, 1]
Output: 12
Take houses 0, 2 and 4: 2 + 9 + 1 = 12.
Example 3
Input: nums = [2, 1, 1, 2]
Output: 4
Houses 0 and 3. Neither "every other house" pattern finds it (both give 3).

Constraints

  • 1 <= len(nums) <= 100
  • 0 <= nums[i] <= 400

Think first try before reading the solution

Decide about the last house first. If you take it, which house is forbidden? If you skip it, what problem is left?
Let best(i) be the most money from houses 0..i. Skipping house i leaves best(i - 1); taking it gives nums[i] + best(i - 2). Take the larger.
Fill dp[i] left to right from dp[0] = nums[0] and dp[1] = max(nums[0], nums[1]), then notice you only ever read the last two cells.

Key idea

Greedy ideas fail here: taking the richest house first ([2, 3, 2] → 3, but 2 + 2 = 4) or taking every other house ([2, 1, 1, 2] → 3, but 2 + 2 = 4). The choice at one house affects what is allowed next to it, so compare whole plans instead.

Ask about the last house only. Every valid plan for houses 0..i either skips house i, and is then just a plan for houses 0..i-1, or takes house i, and then house i - 1 must be skipped, so the rest is a plan for houses 0..i-2. With dp[i] = the most money from houses 0..i:

dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])

That is the whole problem. As in Climbing Stairs, the plain recursion repeats work, a table fixes it, and because each cell reads only the two before it, two variables are enough.

Approaches from the obvious one to the one you want in an interview

best(i) = most money from houses 0..i. Either house i is skipped (best(i - 1)) or robbed (nums[i] + best(i - 2)); with no houses left (i < 0) the answer is 0.

This explores every valid plan, so it is correct, but best(i - 1) and best(i - 2) both end up asking for best(i - 3), best(i - 4) and so on: the same subproblems are solved many times and the call count grows exponentially (like Fibonacci).

Dry run

  1. nums = [2, 7, 9]: best(2) = max(best(1), 9 + best(0))
  2. best(1) = max(best(0), 7 + best(-1)) = max(2, 7) = 7
  3. best(0) = max(best(-1), 2 + best(-2)) = 2 (computed a second time for the other branch)
  4. best(2) = max(7, 9 + 2) = 11

Python

class Solution:
    def rob(self, nums: List[int]) -> int:
        def best(i: int) -> int:
            """Most money from houses 0..i."""
            if i < 0:                          # no houses left
                return 0
            skip = best(i - 1)                 # leave house i alone
            take = nums[i] + best(i - 2)       # rob house i, so house i - 1 is off limits
            return max(skip, take)

        return best(len(nums) - 1)
Time O(φⁿ) ≈ O(1.62ⁿ)Space O(n)

Two calls per house without memory; the stack is at most n deep.

When to use: Only as the stepping stone to the recurrence; 100 houses would take forever.

Same function, wrapped in @cache. There are only n different arguments, so each best(i) is computed once and all later calls are lookups. Time becomes O(n).

Python

class Solution:
    def rob(self, nums: List[int]) -> int:
        @cache                                 # best(i) is computed once per i
        def best(i: int) -> int:
            if i < 0:
                return 0
            return max(best(i - 1), nums[i] + best(i - 2))

        return best(len(nums) - 1)
Time O(n)Space O(n)

n states, O(1) work each; cache plus call stack.

When to use: When you think recursively first; convert to a loop if the input can be deep.

Store dp[i] = most money from houses 0..i in a list aligned with nums:

  • dp[0] = nums[0] and dp[1] = max(nums[0], nums[1]);
  • dp[i] = max(dp[i - 1], dp[i - 2] + nums[i]) for i >= 2.

Each cell reads two cells to its left, so a left-to-right loop works. The table also lets you recover which houses were robbed by walking back from the end.

Dry run

  1. nums = [2, 7, 9, 3, 1]: dp[0] = 2, dp[1] = max(2, 7) = 7
  2. dp[2] = max(7, 2 + 9) = 11 (rob)
  3. dp[3] = max(11, 7 + 3) = 11 (skip)
  4. dp[4] = max(11, 11 + 1) = 12 (rob) → answer 12

Python

class Solution:
    def rob(self, nums: List[int]) -> int:
        n = len(nums)
        if n == 1:
            return nums[0]
        dp = [0] * n                           # dp[i] = most money from houses 0..i
        dp[0] = nums[0]
        dp[1] = max(nums[0], nums[1])          # two neighbours: take the richer one
        for i in range(2, n):
            skip = dp[i - 1]                   # house i untouched
            take = dp[i - 2] + nums[i]         # house i robbed, house i - 1 skipped
            dp[i] = max(skip, take)
        return dp[-1]
Time O(n)Space O(n)

One pass over the houses.

When to use: When you also need to reconstruct the chosen houses.

The loop only ever reads dp[i - 1] and dp[i - 2]. Keep them as one_back and two_back, both starting at 0 (no houses yet), and update them once per house. Starting from zeros also removes the special cases for one or two houses.

Dry run

  1. nums = [2, 7, 9, 3, 1], (two_back, one_back) = (0, 0)
  2. 2 → (0, 2); 7 → (2, 7); 9 → (7, 11)
  3. 3 → (11, 11); 1 → (11, 12) → answer 12

Python

class Solution:
    def rob(self, nums: List[int]) -> int:
        two_back, one_back = 0, 0              # best totals up to two houses ago and up to the previous house
        for x in nums:
            # skip this house (one_back) or rob it (two_back + x)
            two_back, one_back = one_back, max(one_back, two_back + x)
        return one_back
Time O(n)Space O(1)

One pass, two integers.

When to use: The interview answer. Mention the table version if they ask which houses were chosen.

Common mistakes

  • Greedy shortcuts: richest house first fails on [2, 3, 2]; "all even or all odd indices" fails on [2, 1, 1, 2], where the best plan skips two houses in a row.
  • Leaving out the skip option (dp[i] = dp[i - 2] + nums[i] only). A plan may skip house i entirely; the max with dp[i - 1] is what allows it.
  • Setting dp[1] = nums[1]. With two houses you take the richer one: dp[1] = max(nums[0], nums[1]).
  • Reading nums[1] when there is only one house. The table version needs an n == 1 check; the rolling version starting from two zeros needs none.

Python notes

  • @cache on an inner function memoises it for one call of rob; the inner function reads nums from the enclosing scope, so only the index is part of the cache key.
  • With at most 100 houses the top-down recursion is only 100 frames deep, well below Python's default recursion limit of 1000. The same code on 10^5 houses would raise RecursionError; the loop versions would not.
  • two_back, one_back = one_back, max(one_back, two_back + x) updates both rolling values from the old ones in a single statement.

Follow-up questions

What an interviewer might ask next, and what changes.

  • House Robber II LC 213 — the street is a circle, so the first and last houses are neighbours: run this solution twice, once without the first house and once without the last.
  • House Robber III LC 337 — houses form a binary tree: each node returns a pair (best if robbed, best if skipped), computed bottom-up by a DFS.
  • Delete and Earn LC 740 — sum the points per value into buckets; taking value v forbids v - 1 and v + 1, which is House Robber over the buckets.
  • Paint House LC 256 — three colours instead of rob/skip: the state becomes (house, colour) and each cell reads the other two colours of the previous house.
  • Return which houses to rob — keep the table and walk back from the end: if dp[i] == dp[i - 1] house i was skipped, otherwise it was taken and you jump to i - 2.
