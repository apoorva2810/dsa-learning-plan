Partition to K Equal Sum Subsets Medium 250

LeetCode #698 ↗
Status

Decide whether a list of positive numbers can be split into k groups that all have the same sum.

Problem

You are given a list of positive integers nums and an integer k. Decide whether the numbers can be split into exactly k groups so that every group has the same sum.

  • Every number goes into exactly one group and every group gets at least one number.
  • The order of the numbers inside a group does not matter.

Return True if such a split exists and False otherwise.

Examples

Example 1
Input: nums = [4, 3, 2, 3, 5, 2, 1], k = 4
Output: true
The total is 20, so each group must sum to 5: (5), (4, 1), (3, 2), (3, 2).
Example 2
Input: nums = [1, 2, 3, 4], k = 3
Output: false
The total is 10, which does not divide by 3, so three equal groups are impossible.
Example 3
Input: nums = [1, 1, 1, 1, 2, 2, 2, 2], k = 4
Output: true
The total is 12, so each group must sum to 3: four groups of (2, 1).

Constraints

  • 1 <= k <= len(nums) <= 16
  • 1 <= nums[i] <= 10^4
  • each value appears at most 4 times

Think first try before reading the solution

All k groups share one sum, so that sum must be total / k. If the total does not divide by k, or one number is bigger than that share, answer False at once.
Picture k empty buckets that must each end up holding exactly target. Take the numbers one at a time and try every bucket that still has room. If a later number fits nowhere, come back and move an earlier number. Which numbers should go first so that dead ends show up early?
Sort the numbers from largest to smallest. Then two prunings make the search fast: skip a bucket whose sum equals one you already tried for this number (the outcome would repeat), and if the number fails in an empty bucket, stop trying buckets: every bucket after it is empty too.

Key idea

Every group has the same sum, so that sum is fixed before any search: target = total / k. If total % k != 0, or some number is larger than target, the answer is False immediately.

Now imagine k buckets that each have room for exactly target. Walk through the numbers and put each one into some bucket that still has room. If a number fits nowhere, the earlier choices were wrong: take the previous number out of its bucket and try the next bucket for it. That is backtracking (choose a bucket, explore the rest, un-choose when it fails). Each number has at most k choices, so the decision tree has up to k^n leaves: 4^16 is about 4 billion, far too many to visit, so the search needs pruning.

Three observations cut almost all of it. First, big numbers first: a large number has few buckets with enough room, so placing it early finds dead ends near the top of the tree, where cutting a branch removes the most work. Second, buckets are interchangeable: putting the number into a bucket with sum 3 leads to exactly the same future as putting it into another bucket with sum 3, so each bucket sum is tried only once per number. Third, if a number fails in an empty bucket, there is no point trying the buckets after it: a number always takes the first bucket that accepts it, so every bucket behind an empty one is empty too and would fail the same way. With these rules a 16-number input is decided in a few thousand calls.

Approaches from the obvious one to the one you want in an interview

Check total % k == 0 and set target = total / k. Then try every assignment of numbers to k buckets: place(i) puts nums[i] into each bucket whose sum stays at or below target, and recurses on nums[i + 1]. When i == len(nums) every number has a home; since no bucket went above target and the sums add up to k * target, every bucket holds exactly target, so return True. If a bucket choice leads to a dead end, take the number out again and try the next bucket.

This is already backtracking, but a naive one. It walks the numbers in the given order and treats the buckets as different even when they look the same. The tree has up to k^n leaves, and for a False instance it has to visit most of them: 4 buckets and 16 numbers is 4^16, about 4.3 billion assignments.

Dry run

  1. nums = [4, 3, 2, 3, 5, 2, 1], k = 4: total 20, target = 5. buckets = [0, 0, 0, 0].
  2. 4 → bucket 0 [4, 0, 0, 0]. 3: bucket 0 would be 7, so bucket 1 [4, 3, 0, 0]. 2: bucket 0 would be 6, bucket 1 [4, 5, 0, 0].
  3. 3: buckets 0 and 1 are too full, bucket 2 [4, 5, 3, 0]. 5: only bucket 3 [4, 5, 3, 5].
  4. 2: bucket 2 [4, 5, 5, 5]. 1: bucket 0 [5, 5, 5, 5]. i == 7: return True.
  5. On [5, 5, 3, 3, 2] with k = 2 the same code tries both buckets for every number before giving up, including mirror images of arrangements it has already rejected.

Python

class Solution:
    def canPartitionKSubsets(self, nums: List[int], k: int) -> bool:
        total = sum(nums)
        if total % k:                          # k equal groups must add up to the total
            return False
        target = total // k
        buckets = [0] * k                      # buckets[b] = sum of the numbers already in group b

        def place(i):
            if i == len(nums):                 # every number has a group: all k sums are exactly target
                return True
            for b in range(k):
                if buckets[b] + nums[i] <= target:   # only the room test, no other pruning
                    buckets[b] += nums[i]      # choose
                    if place(i + 1):           # explore
                        return True
                    buckets[b] -= nums[i]      # un-choose
            return False

        return place(0)
Time O(kⁿ)Space O(n + k)

Each of the n numbers chooses one of k buckets, and a False instance visits most of the tree. The recursion is n deep and the bucket list has k entries.

When to use: Only as the starting point: it shows the bucket model. Too slow for n = 16 without pruning.

The same bucket search with three additions that remove almost all of the waste:

  1. Quick exits. total % k != 0 or max(nums) > target means False before any search.
  2. Largest first. Sort descending. A big number has few buckets with enough room, so a doomed branch dies in the first few levels instead of after placing a dozen small numbers.
  3. Interchangeable buckets. Inside place(i) keep the set tried of bucket sums already attempted for nums[i]: a second bucket with the same sum leads to the same future, skip it. And if nums[i] fails in an empty bucket, return False right away: a number always takes the first bucket that accepts it, so the non-empty buckets form a prefix and every bucket after an empty one is empty too.

Choose (buckets[b] += nums[i]), explore (place(i + 1)), un-choose (buckets[b] -= nums[i]). When i == n every number is placed, no bucket is above target, and the sums total k * target, so each bucket is exactly target.

  2. 5 → bucket 0 [5, 0, 0, 0]. 4: bucket 0 is full, bucket 1 [5, 4, 0, 0]. 3: buckets 0 and 1 have no room, bucket 2 [5, 4, 3, 0].
  3. 3: bucket 2 would be 6, bucket 3 [5, 4, 3, 3]. 2: bucket 1 would be 6, bucket 2 [5, 4, 5, 3]. 2: bucket 3 [5, 4, 5, 5].
  4. 1: bucket 1 [5, 5, 5, 5]. i == 7: True, after 8 calls and no backtracking.
  5. nums = [5, 5, 3, 3, 2], k = 2, target = 9: 5 → bucket 0, 5 → bucket 1, 3 → bucket 0 [8, 5], 3 → bucket 1 [8, 8], 2 fits nowhere.

Python

class Solution:
    def canPartitionKSubsets(self, nums: List[int], k: int) -> bool:
        total = sum(nums)
        if total % k:                          # k equal groups must add up to the total
            return False
        target = total // k
        nums = sorted(nums, reverse=True)      # biggest first: fewest buckets with room, early dead ends
        if nums[0] > target:                   # one number alone is already too big for a group
            return False
        buckets = [0] * k                      # buckets[b] = sum of the numbers already in group b

        def place(i):
            if i == len(nums):                 # every number is placed, no bucket above target: all equal target
                return True
            tried = set()                      # bucket sums already attempted for nums[i]
            for b in range(k):
                if buckets[b] + nums[i] > target or buckets[b] in tried:
                    continue                   # no room, or a bucket with this sum was tried already
                tried.add(buckets[b])
                buckets[b] += nums[i]          # choose
                if place(i + 1):               # explore the next number
                    return True
                buckets[b] -= nums[i]          # un-choose
                if buckets[b] == 0:            # failed in an empty bucket: every later bucket is empty too
                    return False
            return False

        return place(0)
Time O(kⁿ)Space O(n + k)

The worst-case bound does not improve, but the prunings cut the real tree to a few thousand calls for n = 16. Memory is the bucket list, the per-call set and a recursion n deep.

When to use: The standard interview answer. State the three prunings and why each one is safe.

Watch it run

A guaranteed bound instead of a well-pruned search. A bitmask is an integer whose bit j says whether nums[j] has been used, so one number from 0 to 2^n - 1 describes a set of used numbers. Fill the buckets one after another: rem[mask] is the sum of the numbers in mask modulo target, which is how full the bucket currently being filled is, or -1 if that set can never be reached.

From a reachable mask, add any unused nums[j] that fits into the current bucket (rem[mask] + nums[j] <= target). When the bucket reaches target, the remainder becomes 0 and the next bucket starts. The full mask is reachable exactly when a valid split exists, because any split can be listed bucket by bucket, and every prefix of that list is a reachable mask.

Dry run

  1. nums = [1, 1, 2, 2], k = 2: target = 3. rem[0000] = 0.
  2. From 0000: add 1 (bit 0) → rem[0001] = 1; add 1 (bit 1) → rem[0010] = 1; add 2 → rem[0100] = 2, rem[1000] = 2.
  3. From 0001 (sum 1): add 2 → rem[0101] = 0: the first bucket is full. Add 1 → rem[0011] = 2.
  4. From 0101 (remainder 0, a fresh bucket): add 1 → rem[0111] = 1; then add 2 → rem[1111] = 0. The full mask is reachable: True.

Python

class Solution:
    def canPartitionKSubsets(self, nums: List[int], k: int) -> bool:
        total = sum(nums)
        if total % k:
            return False
        target = total // k
        if max(nums) > target:
            return False
        n = len(nums)
        # rem[mask] = (sum of the numbers in mask) % target = how full the bucket being filled is,
        #             or -1 if the numbers in mask can never be arranged into full buckets plus one partial bucket
        rem = [-1] * (1 << n)
        rem[0] = 0                                   # no numbers used, first bucket empty
        for mask in range(1 << n):
            if rem[mask] < 0:
                continue                             # this set of numbers cannot be reached
            for j in range(n):
                if mask & (1 << j):
                    continue                         # nums[j] is already used in this mask
                if rem[mask] + nums[j] <= target:    # it fits into the bucket being filled
                    rem[mask | (1 << j)] = (rem[mask] + nums[j]) % target
        return rem[(1 << n) - 1] >= 0                # all numbers used (and the last bucket is full)
Time O(n · 2ⁿ)Space O(2ⁿ)

2^n masks, each tries n numbers: about one million operations for n = 16, whatever the input. The table has 2^n entries.

When to use: When you want a bound that does not depend on luck with pruning, or as the base for 'minimum number of buckets' variants.

Common mistakes

  • Skipping the quick checks. Without total % k == 0 and max(nums) <= target, the search can run for a long time only to report False. With them the hopeless cases cost nothing.
  • Using >= in the room test. A bucket may reach exactly target; reject a number only when buckets[b] + nums[i] > target.
  • Forgetting to undo buckets[b] -= nums[i] when the recursive call fails. The bucket then stays fuller than it is and later numbers are refused for no reason.
  • Sharing the 'sums already tried' set between calls. It belongs to one number: create it fresh inside place(i) so a sum tried for nums[3] does not block nums[4].
  • Not sorting. The code stays correct, but small numbers go first, fit almost anywhere, and the dead end only appears when the big numbers come up near the bottom of the tree, after most of the work is done.
  • Trusting i == n without the room test. The proof that every bucket ends at exactly target needs two facts: no bucket ever went above target, and the sums add up to k * target.

Python notes

  • sorted(nums, reverse=True) returns a sorted copy; nums.sort(reverse=True) sorts in place and changes the caller's list.
  • total % k is the remainder and total // k the integer quotient; Python keeps them separate, so target is an int.
  • place changes buckets[b] through indexing, which needs no nonlocal. Only rebinding a name (buckets = ...) would.
  • set() inside place is recreated on every call: the 'sums already tried' belong to one number.
  • Bit tricks for the DP: 1 << n is 2^n, mask & (1 << j) tests bit j, mask | (1 << j) sets it, and bin(mask) shows the bits.
  • Another valid pruning is a memo on tuple(sorted(buckets)): states that differ only by bucket order are the same state.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Matchsticks to Square LC 473 — the same problem with k = 4 fixed: four sides of equal length. Same bucket search, same prunings.
  • Partition Equal Subset Sum LC 416 — k = 2. With only two groups the question becomes 'is there a subset with sum total / 2', which a boolean DP over sums answers in O(n · sum) instead of a search.
  • Fair Distribution of Cookies LC 2305 — the groups no longer have to be equal: minimise the largest group sum. Same bucket backtracking, but a bucket is rejected when it would exceed the best answer so far instead of a fixed target.
  • Split Array Largest Sum LC 410 — the groups must be contiguous pieces of the array. That removes the combinatorial freedom, and a binary search on the answer with a greedy check replaces the backtracking.
  • Minimum Number of Work Sessions to Finish the Tasks LC 1986 — minimise k for a given bucket size. The bitmask DP below fits directly: dp[mask] keeps (sessions used, time left in the current session).
  • Return one valid split — keep a list of members per bucket next to the sums, append and pop them with the sum, and return the lists when i == n.
