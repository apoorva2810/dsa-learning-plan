Unique Paths Medium

LeetCode #62 ↗
Status

Count the different routes from the top-left to the bottom-right cell of a grid when you may only move right or down.

Problem

A robot stands on the top-left cell of a grid with m rows and n columns. In one move it goes one cell right or one cell down; it never moves up or left. Return how many different routes bring it to the bottom-right cell.

Two routes are different if their sequences of moves differ. The answer is guaranteed to be at most 2 · 10^9.

Examples

Example 1
Input: m = 3, n = 7
Output: 28
Example 2
Input: m = 3, n = 2
Output: 3
right → down → down, down → right → down, and down → down → right.
Example 3
Input: m = 1, n = 1
Output: 1
The robot already stands on the goal. Making no moves is one route.

Constraints

  • 1 <= m, n <= 100
  • the answer is at most 2 * 10^9

Think first try before reading the solution

Look at the last move into the goal: the robot arrived either from the cell above or from the cell to the left. How do the route counts of those two cells combine?
paths(r, c) = paths(r - 1, c) + paths(r, c - 1). Every cell in the top row or the left column has exactly one route: a straight line.
Fill a table row by row; each row only reads the row above, so one list of length n is enough. For a formula instead: every route is some ordering of m - 1 downs and n - 1 rights.

Key idea

Every route into a cell (r, c) makes its last move either down from (r - 1, c) or right from (r, c - 1). The two groups never share a route (their last moves differ) and together they contain every route, so the counts add:

paths(r, c) = paths(r - 1, c) + paths(r, c - 1)

The top row and the left column are the base cases: exactly one route reaches each of their cells. Fill the grid row by row and the bottom-right cell is the answer. Because a row reads only the row above it, a single list of length n can replace the whole table.

A second view gives a formula. Every route is a sequence of exactly m - 1 downs and n - 1 rights, and every ordering of those moves is a valid route. Counting routes is counting the ways to choose which of the m + n - 2 moves are the downs: the binomial coefficient C(m + n - 2, m - 1).

Approaches from the obvious one to the one you want in an interview

Write the recurrence as a function. paths(r, c) counts the routes from the start to cell (r, c):

  • paths(0, c) = paths(r, 0) = 1: top row and left column, one straight route;
  • paths(r, c) = paths(r - 1, c) + paths(r, c - 1) otherwise.

Without a cache this is hopeless: every route ends in its own base-case call, so the number of calls grows with the answer itself (up to 2 · 10^9). @cache stores each answer the first time, so each of the m · n cells is computed once and every later request is a lookup.

Dry run

  1. 3 × 3 grid: paths(2, 2) = paths(1, 2) + paths(2, 1)
  2. paths(1, 2) = paths(0, 2) + paths(1, 1), and paths(1, 1) = paths(0, 1) + paths(1, 0) = 2, so paths(1, 2) = 3
  3. paths(2, 1) = paths(1, 1) + paths(2, 0): paths(1, 1) is a cache hit → 2 + 1 = 3
  4. paths(2, 2) = 3 + 3 = 6

Python

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        @cache                                       # each (r, c) is computed once
        def paths(r: int, c: int) -> int:
            """Routes from (0, 0) to (r, c)."""
            if r == 0 or c == 0:                     # top row or left column: one straight route
                return 1
            return paths(r - 1, c) + paths(r, c - 1) # last move was down, or last move was right

        return paths(m - 1, n - 1)
Time O(m·n)Space O(m·n)

m·n states with O(1) work each. The cache holds every state; the recursion is at most m + n deep.

When to use: The quickest correct version to write when you think recursively.

Store dp[r][c] = number of routes to cell (r, c) in an m × n table. The top row and the left column are 1; fill the rest row by row, left to right, with

dp[r][c] = dp[r - 1][c] + dp[r][c - 1]

Both cells a formula reads (above and to the left) are filled before it, so the order is safe. The answer is the bottom-right cell. Same work as the memoised version, but no recursion and every intermediate count is visible.

Dry run

  1. 3 × 3 grid: row 0 = [1, 1, 1], column 0 = 1 everywhere
  2. row 1: dp[1][1] = 1 + 1 = 2, dp[1][2] = 1 + 2 = 3
  3. row 2: dp[2][1] = 2 + 1 = 3, dp[2][2] = 3 + 3 = 6 → answer 6

Python

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        dp = [[1] * n for _ in range(m)]             # row 0 and column 0 stay 1: one straight route each
        for r in range(1, m):
            for c in range(1, n):
                dp[r][c] = dp[r - 1][c] + dp[r][c - 1]   # arrived from above + arrived from the left
        return dp[m - 1][n - 1]
Time O(m·n)Space O(m·n)

Each of the (m - 1)(n - 1) inner cells is one addition.

When to use: When you want to inspect the counts per cell, or adapt the solution to blocked cells (Unique Paths II).

Watch it run

Row r reads only row r - 1, so keep a single list row of length n. When cell c of the new row is about to be updated, row[c] still holds the count from the row above, and row[c - 1] has already been updated, so it holds the count from the left. The update row[c] += row[c - 1] is therefore exactly up + left.

Memory drops from O(m·n) to O(n); passing the smaller dimension as the row length makes it O(min(m, n)).

Dry run

  1. 3 × 3 grid: row = [1, 1, 1] (row 0)
  2. row 1: row[1] = 1 + 1 = 2, row[2] = 1 + 2 = 3 → [1, 2, 3]
  3. row 2: row[1] = 2 + 1 = 3, row[2] = 3 + 3 = 6 → [1, 3, 6] → answer 6

Python

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        row = [1] * n                                # row 0: one route to every top-row cell
        for _ in range(1, m):                        # turn the list into rows 1 .. m-1, in place
            for c in range(1, n):
                row[c] += row[c - 1]                 # old row[c] = from above, row[c - 1] = from the left
        return row[-1]
Time O(m·n)Space O(n)

Same additions as the table; only the current row is kept.

When to use: The usual DP interview answer; it is also the template for grid problems with obstacles or costs.

Watch it run

Every route consists of exactly m - 1 down moves and n - 1 right moves, m + n - 2 moves in total, and every ordering of those moves is a valid route: you never make more downs or rights than the grid allows, so you never leave it. A route is therefore decided by which of the m + n - 2 positions hold the downs:

routes = C(m + n - 2, m - 1)

math.comb computes this exactly. By hand, multiply and divide one factor at a time: after step i the running value is itself a binomial coefficient, a whole number, so integer division is exact at every step. Since C(N, k) == C(N, N - k), loop over the smaller of m - 1 and n - 1.

Dry run

  1. m = 3, n = 7: a route is 2 downs and 6 rights, 8 moves; answer C(8, 2)
  2. k = 2: i = 1 → 1 * 7 // 1 = 7; i = 2 → 7 * 8 // 2 = 28
  3. 28 routes, the same as the table

Python

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        moves = m + n - 2                            # every route has exactly this many moves
        k = min(m, n) - 1                            # choose positions for the rarer move: C(N, k) == C(N, N - k)
        result = 1
        for i in range(1, k + 1):
            # after this line result == C(moves - k + i, i), a whole number, so // is exact
            result = result * (moves - k + i) // i
        return result                                # same as math.comb(moves, k)
Time O(min(m, n))Space O(1)

k = min(m, n) - 1 multiply-and-divide steps on exact integers. It is often called the O(1) formula; math.comb does the same k steps in C.

When to use: When the grid is completely open. Any twist (walls, costs, a modulus with huge m and n) sends you back to the DP or to modular factorials.

Common mistakes

  • Plain recursion without a cache: every route ends in its own base-case call, so it makes about as many calls as there are routes (up to 2 · 10^9). Add @cache or fill a table.
  • Starting the top row and left column at 0 instead of 1. Those cells have one route each; with zeros every sum stays 0.
  • Building the table with [[1] * n] * m: all m rows are the same list object, so writing one row overwrites every row. Use [[1] * n for _ in range(m)].
  • Off-by-one in the formula: a route has m + n - 2 moves, of which m - 1 are downs. C(m + n, m) counts routes on a grid one row and one column larger.
  • Computing the binomial with floats, such as math.factorial(a) / math.factorial(b), loses precision for large values. Stay in integers: math.comb, or multiply then // one factor at a time.

Python notes

  • math.comb(n, k) (Python 3.8+) returns the exact binomial coefficient. Python integers never overflow, so no modulo or long type is needed.
  • [[1] * n for _ in range(m)] builds m independent rows; [[1] * n] * m builds one row referenced m times.
  • With @cache the recursion is at most m + n - 2 calls deep (198 here), well under Python's default limit of 1000.
  • In the one-row version, row[c] += row[c - 1] is the whole update: the old row[c] is the count from above and row[c - 1] has just been updated for the current row.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Unique Paths II LC 63 — some cells are blocked: a blocked cell holds 0, so the top row and left column are no longer all ones after a wall. The table survives, the formula does not.
  • Minimum Path Sum LC 64 — every cell has a cost and you want the cheapest route: same table, with min(up, left) + cost instead of a sum.
  • Dungeon Game LC 174 — the minimum starting health depends on what comes after a cell, so the table is filled backwards from the goal.
  • Unique Paths III LC 980 — four directions and every empty cell visited exactly once: moves are no longer one-way, so a per-cell count does not work. Backtracking over the grid does.
  • Cherry Pickup LC 741 — two walkers move at the same time; the state grows to (step, row of walker 1, row of walker 2).
  • m and n up to 10^5, answer modulo 10^9 + 7 — an m × n table is far too large: precompute factorials and inverse factorials modulo the prime and evaluate the formula.
