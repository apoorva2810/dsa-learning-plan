Two Sum II - Input Array Is Sorted Medium

LeetCode #167 ↗
Status

In a sorted list, find the two positions (counted from 1) whose values add up to a target, using O(1) extra space.

Problem

You are given a list of integers numbers sorted in non-decreasing order (each value is at least the one before it) and an integer target.

Find the two numbers that add up to target and return their positions as [index1, index2], where:

  • positions are 1-indexed (the first element is position 1, not 0),
  • index1 < index2, so the same element cannot be used twice.

Exactly one valid answer exists. Your solution may only use a constant amount of extra memory.

Examples

Example 1
Input: numbers = [2, 7, 11, 15], target = 9
Output: [1, 2]
2 + 7 = 9. They sit at 0-based indices 0 and 1, which are positions 1 and 2.
Example 2
Input: numbers = [2, 3, 4], target = 6
Output: [1, 3]
Example 3
Input: numbers = [-1, 0], target = -1
Output: [1, 2]

Constraints

  • 2 <= len(numbers) <= 3 * 10^4
  • -1000 <= numbers[i] <= 1000
  • numbers is sorted in non-decreasing order
  • -1000 <= target <= 1000
  • exactly one valid answer exists

Think first try before reading the solution

The Two Sum dictionary trick would work, but it uses O(n) memory. What does the sorted order give you for free?
Add the smallest and the largest number. If the sum is too big, can the largest number be part of any valid pair?
Keep left at the start and right at the end. Sum too small → left += 1; too big → right -= 1; equal → return [left + 1, right + 1].

Key idea

Sorted order tells you which way to move. Look at numbers[left] + numbers[right], the smallest and the largest values still in play.

  • If the sum is too big, numbers[right] is too big to pair with anything: its smallest possible partner, numbers[left], already overshoots. Discard it with right -= 1.
  • If the sum is too small, numbers[left] is too small to pair with anything: even its largest possible partner falls short. Discard it with left += 1.

Every comparison removes one number for good, so after at most n − 1 steps the pointers have found the pair. That is O(n) time with two integers of memory, which the dictionary version cannot match.

Approaches from the obvious one to the one you want in an interview

Try every pair (i, j) with i < j and return the first one that sums to target. It ignores the sorted order completely, and with up to 3·10⁴ numbers that is about 4.5·10⁸ pair checks: too slow in Python. It does meet the O(1) memory rule, so it is a fair starting point to improve on.

Python

class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        n = len(numbers)
        for i in range(n):
            for j in range(i + 1, n):                  # j > i: never the same element twice
                if numbers[i] + numbers[j] == target:
                    return [i + 1, j + 1]              # 1-indexed answer
        return []
Time O(n²)Space O(1)

n(n−1)/2 pairs in the worst case; only loop counters are stored.

When to use: Never for the real input size; it only shows what the sorted order lets you skip.

For each numbers[i] the partner is fixed: need = target - numbers[i]. The list is sorted, so look for need with binary search (repeatedly halve the range that could contain it) in the part of the list to the right of i.

Each search costs O(log n), so the total is O(n log n) with O(1) memory. It uses the sorted order, but only half of what it offers: each search starts from scratch and forgets what the previous one learned.

Dry run

  1. numbers = [2, 7, 11, 15], target = 9
  2. i = 0, value 2, need 7: search [7, 11, 15] → middle is 11 > 7 → go left → 7 found at index 1
  3. return [1, 2]

Python

class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        n = len(numbers)
        for i in range(n):
            need = target - numbers[i]
            lo, hi = i + 1, n - 1                  # search only to the right of i
            while lo <= hi:
                mid = (lo + hi) // 2
                if numbers[mid] == need:
                    return [i + 1, mid + 1]
                if numbers[mid] < need:
                    lo = mid + 1                   # the partner, if any, is further right
                else:
                    hi = mid - 1                   # ... or further left
        return []
Time O(n log n)Space O(1)

n binary searches, each over at most n elements.

When to use: Useful when one side of the pair is fixed per query; for a single pair the two-pointer walk is simpler and faster.

Start with left = 0 and right = n - 1 and compare numbers[left] + numbers[right] with target:

  • equal → done;
  • too small → left += 1, because numbers[left] falls short even with the largest value still available;
  • too big → right -= 1, because numbers[right] overshoots even with the smallest value still available.

Each step discards exactly one number that provably cannot be in the answer, so the answer is never skipped and the loop runs at most n − 1 times.

Dry run

  1. numbers = [1, 3, 4, 6, 8, 11], target = 10
  2. 1 + 11 = 12 > 10 → drop 11 (right -= 1)
  3. 1 + 8 = 9 < 10 → drop 1 (left += 1)
  4. 3 + 8 = 11 > 10 → drop 8
  5. 3 + 6 = 9 < 10 → drop 3
  6. 4 + 6 = 10 → return [3, 4]

Python

class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        left, right = 0, len(numbers) - 1
        while left < right:
            total = numbers[left] + numbers[right]
            if total == target:
                return [left + 1, right + 1]       # the answer is 1-indexed
            if total < target:
                left += 1                          # numbers[left] is too small for any partner
            else:
                right -= 1                         # numbers[right] is too big for any partner
        return []
Time O(n)Space O(1)

Every iteration moves one pointer inward and they start n − 1 apart.

When to use: The intended answer: linear time and constant memory.

Common mistakes

  • Returning 0-indexed positions. The answer is 1-indexed: [left + 1, right + 1].
  • Looping with left <= right: when the pointers are equal you would pair an element with itself.
  • Moving both pointers after a miss. One comparison only proves that one number is useless; moving both can step over the answer.
  • Using a dictionary as in Two Sum: it passes the tests but breaks the O(1) extra memory requirement.

Python notes

  • left, right = 0, len(numbers) - 1 sets both pointers in one line.
  • Python lists are 0-indexed and the answer is 1-indexed. Convert only in the return, so the rest of the code stays in normal indices.
  • bisect.bisect_left(numbers, x, lo) is the standard library's binary search; it returns the first index >= lo where x could be inserted.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Two Sum LC 1 — the input is not sorted and original indices matter: use a dictionary, or sort (value, index) pairs first.
  • 3Sum LC 15 — fix one number, then run this exact loop on the rest of the sorted list; skip repeated values to avoid duplicate triplets.
  • Two Sum IV - Input is a BST LC 653 — an in-order traversal of a BST is sorted, so run the two pointers on it (or walk two iterators, smallest-first and largest-first).
  • Two Sum Less Than K LC 1099 — there is no exact target: when the sum is below k, record it as a candidate and move left; otherwise move right.
  • Count the pairs with sum <= target — when numbers[left] + numbers[right] <= target, every index between left and right also pairs with left: add right - left to the count at once, then move left.
