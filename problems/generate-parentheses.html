List every string of n opening and n closing parentheses that is correctly balanced.

Problem

Given an integer n, return all strings made of exactly n pairs of parentheses that are well formed: every ( is closed by a later ), and no ) appears before the ( it closes.

The strings can be returned in any order.

Examples

Example 1
Input: n = 3
Output: ["((()))", "(()())", "(())()", "()(())", "()()()"]
Example 2
Input: n = 1
Output: ["()"]
Example 3
Input: n = 2
Output: ["(())", "()()"]
)(() and ())( have the right counts but close something that was never opened.

Constraints

  • 1 <= n <= 8

Think first try before reading the solution

Every answer has length 2n. You could try all 2^(2n) strings of ( and ) and keep the valid ones. Most of them are invalid early on: can you notice that while building, instead of at the end?
Build the string one character at a time. When is ( allowed? When is ) allowed? Keep two counters: how many ( and how many ) you have placed.
( is allowed while open < n; ) is allowed while close < open. Recurse on both choices and undo the character when the call returns (backtracking). A string of length 2n built this way is always valid.

Key idea

A string is balanced exactly when, reading left to right, the number of ) never exceeds the number of (, and the totals are both n at the end. Both conditions can be checked while building: keep open and close counters, place ( only if open < n, and place ) only if close < open (it closes something).

Every prefix built this way can still be completed, so the search never walks into a dead end. That is backtracking: extend a partial answer, recurse, then undo the last choice and try the next one. The recursion produces each valid string exactly once, and there are only the Catalan number C(n) of them (5 for n = 3, 1430 for n = 8), far fewer than the 2^(2n) raw strings (64 for n = 3, 65,536 for n = 8).

Approaches from the obvious one to the one you want in an interview

Generate all 2^(2n) strings of length 2n over ( and ), and keep those that are balanced. A string is balanced if a running counter (+1 for (, −1 for )) never drops below zero and ends at zero.

It is correct, but almost all the work is wasted: for n = 3 only 5 of 64 strings survive, and for n = 8 only 1,430 of 65,536. Every rejected string is still built and scanned.

Python

class Solution:
    def generateParenthesis(self, n: int) -> List[str]:
        def balanced(s: str) -> bool:
            depth = 0
            for c in s:
                depth += 1 if c == "(" else -1
                if depth < 0:                   # a ")" with nothing to close
                    return False
            return depth == 0

        result = []
        for chars in itertools.product("()", repeat=2 * n):   # all 2^(2n) strings
            s = "".join(chars)
            if balanced(s):
                result.append(s)
        return result
Time O(4ⁿ · n)Space O(n)

2^(2n) = 4ⁿ strings, each built and checked in O(n); extra space excludes the output.

When to use: As the starting point that shows why pruning matters.

Grow one string in a shared list path. At each call:

  • if len(path) == 2n, the string is complete and valid: record it;
  • if open < n, append (, recurse, then pop it (undo);
  • if close < open, append ), recurse, then pop it.

The undo step is what makes it backtracking: after exploring every string that starts with a prefix, the prefix is restored so the other choice can be explored from the same point. Because both rules keep every prefix completable, each leaf of the recursion is an answer and no work is thrown away.

  4. result ["(())", "()()"]

Python

class Solution:
    def generateParenthesis(self, n: int) -> List[str]:
        result = []
        path = []                                 # the string being built, as a list of chars

        def backtrack(open_count: int, close_count: int) -> None:
            if len(path) == 2 * n:                # n opens and n closes placed
                result.append("".join(path))
                return
            if open_count < n:                    # an opening bracket is still available
                path.append("(")
                backtrack(open_count + 1, close_count)
                path.pop()                        # undo, then try the other choice
            if close_count < open_count:          # a ")" here closes something
                path.append(")")
                backtrack(open_count, close_count + 1)
                path.pop()

        backtrack(0, 0)
        return result
Time O(4ⁿ / √n)Space O(n)

There are C(n) ≈ 4ⁿ / (n^1.5 · √π) answers and each costs O(n) to build; the recursion and path are 2n deep (output excluded).

When to use: The standard answer: shortest to write and does no wasted work.

Watch it run

The recursion only remembers three things per call: the prefix and the two counters. Push those as tuples on your own stack and pop them in a loop. It explores exactly the same prefixes, with no recursion limit to worry about. Pushing the ( branch last makes it pop first, which reproduces the recursive order.

Python

class Solution:
    def generateParenthesis(self, n: int) -> List[str]:
        result = []
        stack = [("", 0, 0)]                      # (prefix, opens used, closes used)
        while stack:
            s, open_count, close_count = stack.pop()
            if len(s) == 2 * n:
                result.append(s)
                continue
            if close_count < open_count:
                stack.append((s + ")", open_count, close_count + 1))
            if open_count < n:
                stack.append((s + "(", open_count + 1, close_count))   # pushed last, explored first
        return result
Time O(4ⁿ / √n)Space O(n²)

Same prefixes as the recursion. Each stack entry holds its own string copy, and up to about 2n entries wait at once.

When to use: When you want to show that recursion is just a stack, or the language limits recursion depth.

Common mistakes

  • Allowing ) whenever close < n instead of close < open: you get strings like "())(" that close before opening.
  • Forgetting to undo the choice (path.pop()) after the recursive call when you reuse one list: later strings inherit leftover characters.
  • Appending the shared list itself (result.append(path)) instead of a snapshot ("".join(path)): every entry then points at the same list, which is empty at the end.
  • Base case on the wrong condition: stop at len(path) == 2 * n (or open == close == n), not at open == n, which still needs its closing brackets.

Python notes

  • A list used as a stack (path.append, path.pop()) plus "".join(path) at the leaves avoids building a new string at every call. Passing s + "(" down instead is simpler and fine for n ≤ 8.
  • result.append(...) inside the nested function needs no nonlocal: it mutates the list, it does not rebind the name.
  • "(" sorts before ")", so trying ( first yields the answers in sorted order for free.
  • itertools.product("()", repeat=2 * n) produces every string of length 2n, which is all the brute force needs.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Valid Parentheses LC 20 — check one string instead of generating all of them; with one bracket type a counter replaces the stack.
  • Remove Invalid Parentheses LC 301 — start from a broken string and delete the fewest characters: BFS over deletions, or backtracking that first counts how many ( and ) must go.
  • Letter Combinations of a Phone Number LC 17 — the same build-recurse-undo skeleton, but every choice is always allowed, so there is nothing to prune.
  • Unique Binary Search Trees LC 96 — only count the answers: every valid string is ( + A + ) + B, so C(n) = sum of C(k)·C(n−1−k). The same Catalan recurrence counts binary search trees.
  • Several bracket types — with (), [] and {} the counters are not enough: keep a stack of open types so a closer matches the most recent opener.
