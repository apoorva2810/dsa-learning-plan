Kth Largest Element in an Array Medium

LeetCode #215 ↗
Status

Return the value that would be k-th from the top if the list were sorted, ideally without sorting it.

Problem

Given a list of integers nums and an integer k, return the k-th largest element: the value that would sit at position k if nums were sorted from largest to smallest.

  • Duplicates count separately: in [3, 3, 1] the 2nd largest is 3.
  • The challenge is to do better than sorting the whole list.

Examples

Example 1
Input: nums = [3, 2, 1, 5, 6, 4], k = 2
Output: 5
Largest first: 6, 5, 4, 3, 2, 1.
Example 2
Input: nums = [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4
Output: 4
Largest first: 6, 5, 5, 4, 3, 3, 2, 2, 1. The two 5s take positions 2 and 3.

Constraints

  • 1 <= k <= len(nums) <= 10^5
  • -10^4 <= nums[i] <= 10^4

Think first try before reading the solution

Sorting puts the answer at index len(nums) - k. That costs O(n log n): which part of the sorting work does the question never use?
You only need the k largest values, and among those the smallest. A min-heap that never holds more than k values keeps exactly that group.
To beat O(n log k): pick a pivot and split the values into bigger, equal and smaller. Just counting the bigger ones tells you which group holds the answer, so throw the others away and repeat on that group (quickselect).

Key idea

Sorting does far more than asked: it orders every pair of values, while we need one position. Two ideas avoid the waste.

Keep only a top-k club. Exactly as in the stream version, a min-heap of the k largest values seen so far has the k-th largest at its root. A value that cannot beat the root is ignored. That is O(n log k).

Quickselect. Pick a pivot and split the list into values bigger than, equal to, and smaller than it. If at least k values are bigger, the answer is among them. If the bigger and equal values together reach k, the answer is the pivot. Otherwise it is among the smaller values, with a smaller rank. One group survives each round and, with a random pivot, it is about half the size on average: n + n/2 + n/4 + … ≈ 2n work, so O(n) on average.

Approaches from the obvious one to the one you want in an interview

Sort the list in ascending order; the k-th largest is k places from the end, sorted(nums)[-k].

It is one line and hard to get wrong, which makes it a good first answer. But sorting orders every value (O(n log n)) when the question asks about a single position, and the follow-up explicitly asks you to avoid it.

Dry run

  1. [3, 2, 1, 5, 6, 4] → sorted [1, 2, 3, 4, 5, 6]
  2. k = 2 → index 6 - 2 = 4 → 5

Python

class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        return sorted(nums)[-k]                  # k-th from the end of the ascending order
Time O(n log n)Space O(n)

sorted builds and sorts a copy; nums.sort() would sort in place.

When to use: Quick scripts, or when you need several ranks from the same data.

Heapify the first k values. Then, for every remaining value x:

  • if x > heap[0], it beats the weakest of the current top k: heapreplace pops the root and pushes x;
  • otherwise skip it; k values at least as big are already kept.

At the end the heap holds the k largest values and its root is the answer. Each replace costs O(log k), so the total is O(n log k) with only O(k) extra memory, and it works even if the values arrive one at a time.

Dry run

  1. k = 2: heapify [3, 2] → root 2
  2. 1 ≤ 2 → skip; 5 > 2 → replace → root 3
  3. 6 > 3 → replace → heap holds 5 and 6, root 5
  4. 4 ≤ 5 → skip → answer 5

Python

class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        heap = nums[:k]                          # the first k values ...
        heapq.heapify(heap)                      # ... as a min-heap, O(k)
        for x in nums[k:]:
            if x > heap[0]:                      # beats the weakest of the current top k
                heapq.heapreplace(heap, x)       # pop the root and push x in one pass
        return heap[0]                           # smallest of the k largest
Time O(n log k)Space O(k)

At most one O(log k) heap operation per value; the heap never grows beyond k.

When to use: The safe default: predictable time, small memory, works on streams. Expected in a heap-focused interview.

Watch it run

Pick a random pivot and split the candidates into three groups: bigger than the pivot, equal to it, and smaller. Let b and e be the sizes of the first two groups.

  • k <= b: the k-th largest is among the bigger values; continue there with the same k.
  • k <= b + e: ranks b + 1 to b + e are all the pivot, so the pivot is the answer.
  • otherwise: every bigger or equal value ranks above the answer; continue in the smaller group with k - b - e.

Only one group survives each round. With a random pivot it is about half the size on average, so the total work is n + n/2 + n/4 + … ≈ 2n: O(n) on average. A long run of bad pivots costs O(n²), but that is extremely unlikely. Keeping the equal values apart is what stops lists full of duplicates from being slow.

Dry run

  1. [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4. Pivot 3 → bigger [4, 5, 5, 6], equal [3, 3], smaller [2, 1, 2]
  2. k = 4 ≤ 4 bigger values → continue with [4, 5, 5, 6], k = 4
  3. pivot 5 → bigger [6], equal [5, 5], smaller [4]; 4 > 1 + 2 → continue with [4], k = 4 - 3 = 1
  4. pivot 4 → bigger [], equal [4] → k = 1 is within ranks 1..1 → answer 4

Python

class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        while True:
            pivot = random.choice(nums)          # random pivot: no input can force the worst case
            bigger = [x for x in nums if x > pivot]
            smaller = [x for x in nums if x < pivot]
            equal = len(nums) - len(bigger) - len(smaller)
            if k <= len(bigger):                 # the answer is among the bigger values
                nums = bigger
            elif k <= len(bigger) + equal:       # ranks b+1 .. b+e are all the pivot
                return pivot
            else:                                # the answer is among the smaller values
                k -= len(bigger) + equal
                nums = smaller
Time O(n) average, O(n²) worstSpace O(n)

Each round is one linear pass over the surviving candidates; the lists it builds are at most n long.

When to use: Best average time when all the data is in memory. Mention the worst case and the duplicate-safe three-way split.

Common mistakes

  • Off-by-one after sorting: in ascending order the k-th largest is at index n - k (sorted(nums)[-k]), not k or n - k - 1.
  • Using a size-k max-heap: its root is the largest value, and trimming it throws away the values you need. The k largest belong in a min-heap.
  • Quickselect with a fixed pivot (always the first or last element) is O(n²) on already-sorted input. LeetCode has such tests; pick the pivot at random.
  • A two-way split (< pivot / >= pivot) barely shrinks a list full of duplicates (for example all 1s) and also goes O(n²). Keep the values equal to the pivot in their own group.
  • Confusing k-th largest with k-th largest distinct: duplicates count, so do not deduplicate with set.

Python notes

  • heapq.nlargest(k, nums)[-1] is a one-liner that keeps a size-k heap internally.
  • heapq.heapreplace(heap, x) pops the root and pushes x in a single pass down the heap; call it only on a non-empty heap.
  • heapq.heapify(heap) builds the first heap of k values in O(k).
  • The in-place quickselect (Lomuto partition, as in K Closest Points to Origin) needs only O(1) extra memory; the list version below is easier to get right and copes with duplicates.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Kth Largest Element in a Stream LC 703 — the values arrive one by one and you answer after each: quickselect no longer fits, the size-k heap does.
  • K Closest Points to Origin LC 973 — the same selection with a computed key (squared distance) and the k smallest: a max-heap of size k, or quickselect.
  • Top K Frequent Elements LC 347 — select by frequency instead of by value; bucket sort by count beats the heap there.
  • Third Maximum Number LC 414 — k = 3 but distinct values: three variables (or a set with a size-3 heap), and a fallback when fewer than 3 exist.
  • Kth Smallest Element in a Sorted Matrix LC 378 — rows and columns are sorted: pop k times from a heap seeded with each row's first value, or binary-search on the value.
  • What if the values lie in a small range (here -10⁴..10⁴)? — count each value in an array of 20,001 slots and walk it from the top until k values are passed: O(n + range), no comparisons at all.
