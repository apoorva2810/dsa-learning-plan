Largest Rectangle in Histogram Hard

LeetCode #84 ↗
Status

Find the biggest rectangle that fits under a bar chart of side-by-side bars.

Problem

You are given a list heights describing a histogram: bar i has width 1 and height heights[i], and the bars stand side by side with no gaps.

Return the area of the largest rectangle that fits entirely inside the histogram. The rectangle must be axis-aligned and may span several neighbouring bars; its height can be at most the height of the shortest bar it covers.

Examples

Example 1
Input: heights = [2, 1, 5, 6, 2, 3]
Output: 10
Bars 2 and 3 (heights 5 and 6) hold a rectangle of height 5 and width 2.
Example 2
Input: heights = [2, 4]
Output: 4
Either the single bar of height 4, or height 2 across both bars.
Example 3
Input: heights = [2, 1, 2]
Output: 3
The short middle bar spans all three bars: height 1 × width 3.

Constraints

  • 1 <= len(heights) <= 10^5
  • 0 <= heights[i] <= 10^4

Think first try before reading the solution

Any rectangle is limited by its shortest bar. Flip it around: for each bar, what is the widest rectangle in which that bar is the shortest?
From bar i, that rectangle stretches left and right until the first bar that is shorter than heights[i]. "Nearest shorter bar on each side" is a monotonic stack question.
Keep a stack of indices with increasing heights. When bar i is shorter than the top, the top's rectangle is finished: its right limit is i and its left limit is the index below it on the stack.

Key idea

Every candidate rectangle has a shortest bar, and it is as tall as that bar. So the best rectangle is, for some bar i, "height heights[i], stretched as far as possible in both directions", and it stops exactly at the first shorter bar on the left and on the right. If we knew those two limits for every bar, the answer would be max(heights[i] × (right[i] − left[i] − 1)).

A stack of indices whose heights increase from bottom to top finds both limits at once. A bar waits on the stack while the bars after it are at least as tall. When a shorter bar arrives at index i, every taller bar on top is finished: i is its right limit, and the bar now below it on the stack is the nearest shorter bar on its left (all bars in between were taller and were popped earlier). Every index is pushed and popped once, so this is O(n).

Approaches from the obvious one to the one you want in an interview

Fix a left edge i, then grow the right edge j one bar at a time while keeping the running minimum height. The rectangle over i..j has area shortest × (j − i + 1); keep the largest.

Updating the minimum incrementally avoids a third loop, but there are still n(n+1)/2 spans, so the time is O(n²).

Dry run

  1. [2, 1, 5, 6, 2, 3]
  2. i = 0: spans give 2, then shortest 1 → 2, 3, 4, 5, 6
  3. i = 2: [5] → 5, [5, 6] → 5 × 2 = 10, [5, 6, 2] → 2 × 3 = 6, [5, 6, 2, 3] → 8
  4. no later span beats 10 → answer 10

Python

class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        best = 0
        n = len(heights)
        for i in range(n):                          # left edge
            shortest = heights[i]
            for j in range(i, n):                   # right edge
                shortest = min(shortest, heights[j])    # a rectangle is only as tall as its shortest bar
                best = max(best, shortest * (j - i + 1))
        return best
Time O(n²)Space O(1)

n(n+1)/2 spans, O(1) work each.

When to use: As a checker for small inputs, or as the first idea to state in an interview.

For every bar compute left[i], the index of the nearest shorter bar to its left (−1 if none), and right[i], the nearest shorter bar to its right (n if none). Then bar i is the shortest bar of the rectangle spanning left[i] + 1 .. right[i] − 1, and its area is heights[i] × (right[i] − left[i] − 1).

Each array is filled by one monotonic-stack pass: going left to right, pop every bar at least as tall as the current one; whatever remains on top is the nearest shorter bar. The right-to-left pass is the mirror image. Three O(n) passes in total. It is easier to reason about than the one-pass version, at the cost of two extra arrays.

Dry run

  1. [2, 1, 5, 6, 2, 3] → left = [-1, -1, 1, 2, 1, 4], right = [1, 6, 4, 4, 6, 6]
  2. bar 2 (height 5): width = 4 − 1 − 1 = 2 → area 10
  3. bar 1 (height 1): width = 6 − (−1) − 1 = 6 → area 6
  4. maximum over all bars → 10

Python

class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        n = len(heights)
        left = [-1] * n                       # nearest shorter bar on the left (-1 = none)
        right = [n] * n                       # nearest shorter bar on the right (n = none)
        stack = []
        for i in range(n):                    # left to right
            while stack and heights[stack[-1]] >= heights[i]:
                stack.pop()                   # not shorter than bar i, so it cannot limit bar i
            left[i] = stack[-1] if stack else -1
            stack.append(i)
        stack = []
        for i in range(n - 1, -1, -1):        # right to left, the mirror image
            while stack and heights[stack[-1]] >= heights[i]:
                stack.pop()
            right[i] = stack[-1] if stack else n
            stack.append(i)
        # bar i is the shortest bar of the rectangle strictly between left[i] and right[i]
        return max(heights[i] * (right[i] - left[i] - 1) for i in range(n))
Time O(n)Space O(n)

Two stack passes where each index is pushed and popped at most once, plus one pass for the areas.

When to use: When you want the limits explicitly, for instance to report the rectangle itself.

Merge the two passes. Keep a stack of indices with increasing heights and scan heights + [0]:

  1. While the bar on top is taller than the current bar i, pop it. Its right limit is i (the first shorter bar to its right) and its left limit is the new top of the stack (the first shorter bar to its left; −1 if the stack is empty). Record height × (i − left − 1).
  2. Push i.

The sentinel 0 at the end is shorter than every bar, so it pops everything that is left. Each index is pushed once and popped once: O(n) time, and only the stack as extra memory.

Dry run

  1. [2, 1, 5, 6, 2, 3] + [0]
  2. i = 1 (1): pop 0 (2) → width 1 → 2. Push 1
  3. push 2 (5), push 3 (6)
  4. i = 4 (2): pop 3 (6) → width 4 − 2 − 1 = 1 → 6; pop 2 (5) → width 4 − 1 − 1 = 2 → 10. Push 4
  5. push 5 (3). i = 6 (0): pop 5 → 3; pop 4 (2) → width 6 − 1 − 1 = 4 → 8; pop 1 (1) → width 6 → 6
  6. best = 10

Python

class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        bars = heights + [0]                  # the final 0 forces every bar off the stack
        stack = []                            # indices whose heights increase bottom -> top
        best = 0
        for i, h in enumerate(bars):
            while stack and bars[stack[-1]] > h:
                top = stack.pop()             # bar `top` cannot extend past i: measure it now
                left = stack[-1] if stack else -1     # nearest shorter bar on its left
                width = i - left - 1
                best = max(best, bars[top] * width)
            stack.append(i)
        return best
Time O(n)Space O(n)

Each index is pushed and popped once; an increasing histogram keeps all n on the stack.

When to use: The interview answer. Explain the pop moment: that is when a bar learns both of its limits.

Common mistakes

  • Forgetting the bars left on the stack at the end: an increasing histogram like [1, 2, 3] never pops inside the loop. Append a sentinel bar of height 0 (or run a final cleanup loop) so every bar gets measured.
  • Measuring the width from the popped index (i - top): the rectangle extends further left, over taller bars that were popped earlier. Use the new top: width = i - stack[-1] - 1, or i when the stack is empty.
  • Mutating the input with heights.append(0): the caller's list changes. Build heights + [0] instead.
  • Duplicates: with equal heights one copy may get a too-narrow width when popped, but the copy measured last gets the full width, so the maximum is still right. Test [3, 3, 3] (answer 9) to be sure.
  • The O(n²) brute force does 5·10⁹ steps at n = 10⁵; it only serves to check the fast version on small inputs.

Python notes

  • heights + [0] creates a new list with the sentinel; the input stays untouched.
  • left = stack[-1] if stack else -1 reads as "the nearest shorter bar on the left, or the wall before index 0".
  • Store indices, not heights, on the stack: widths need positions, and heights[i] recovers the height.
  • max(best, area) in the loop is clearer than collecting every area in a list.
