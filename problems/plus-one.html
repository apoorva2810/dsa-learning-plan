Plus One Easy

LeetCode #66 ↗
Status

Add 1 to a number that is stored as a list of its decimal digits.

Problem

You are given a non-empty list digits that holds the decimal digits of a non-negative integer, most significant digit first. So [1, 2, 3] is the number one hundred twenty-three. The number has no leading zeros, except that zero itself is written [0].

Add 1 to the number and return its digits in the same format.

Examples

Example 1
Input: digits = [1, 2, 3]
Output: [1, 2, 4]
123 + 1 = 124.
Example 2
Input: digits = [1, 2, 9]
Output: [1, 3, 0]
The 9 plus 1 is 10: write 0 and carry the 1 into the tens place.
Example 3
Input: digits = [9, 9]
Output: [1, 0, 0]
99 + 1 = 100, which has one more digit than the input.

Constraints

  • 1 <= len(digits) <= 100
  • 0 <= digits[i] <= 9
  • digits has no leading zero, except for the number 0 itself

Think first try before reading the solution

Do it the way you would on paper: add 1 to the last digit. When does that go wrong?
A digit below 9 can take the 1 and nothing else changes. A 9 plus 1 is 10, so it becomes 0 and a carry of 1 (the 1 you write above the next column) moves one place to the left.
Scan from the right: turn each 9 into 0 and keep going; at the first digit below 9, add 1 and stop. If you run off the left end, every digit was 9, and the number needs a new leading 1.

Key idea

Adding 1 only ever disturbs a run of 9s at the right end, plus one more digit. Look at 1299 + 1 = 1300: the two 9s became 0s, the 2 became 3, and the 1 on the far left did not change at all.

So walk from the last digit toward the first. A 9 turns into 0 and passes the carry to the digit on its left. The first digit that is not 9 takes the carry (it just gets 1 added) and the job is finished, because nothing further left can change. If the walk falls off the left end, every digit was 9 (999 becomes 1000), so the answer is a new leading 1 followed by the zeros that are already there.

The worst case touches every digit once, which is O(n). With no 9 at the end it is a single step.

Approaches from the obvious one to the one you want in an interview

Join the digits into a string, turn it into an int, add 1, and split the result back into digits. Python integers have no size limit, so this works even for 100 digits.

It is not what the question is after. In most languages the number would not fit in a 64-bit integer, so you are expected to work on the digits directly. The conversions are also slower than they look: turning a long string into a number, or back, takes time that grows with the square of the digit count in CPython (which is part of why Python refuses to convert more than 4300 digits by default).

Dry run

  1. digits = [1, 2, 9] → "129" → the integer 129
  2. 129 + 1 = 130 → "130" → [1, 3, 0]

Python

class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        number = int("".join(map(str, digits)))       # [1, 2, 9] -> "129" -> 129
        return [int(ch) for ch in str(number + 1)]    # 130 -> "130" -> [1, 3, 0]
Time O(n²)Space O(n)

Converting between a digit string and an integer is not linear: in CPython it grows roughly with the square of the number of digits.

When to use: Fine for a quick script. In an interview it counts as skipping the problem.

Do exactly what you do on paper. Start with carry = 1; that is the "+ 1". Walk the digits from the right. At each digit compute total = digit + carry, write total % 10 back, and pass total // 10 on to the digit on the left. A carry that is still 1 after the leftmost digit becomes a new leading digit.

This is the loop you will reuse for adding any two numbers (Add Strings, Add Binary, Add Two Numbers). For "+ 1" it does a little more work than needed: once the carry is 0 the remaining digits cannot change, but the loop still visits them.

Dry run

  1. digits = [1, 2, 9], carry = 1
  2. i = 2: 9 + 1 = 10 → write 0, carry 1
  3. i = 1: 2 + 1 = 3 → write 3, carry 0
  4. i = 0: 1 + 0 = 1 → write 1, carry 0 (nothing changed, but we still looked)
  5. carry is 0, so no new leading digit → [1, 3, 0]

Python

class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        carry = 1                                          # the "+ 1" is a carry waiting to be added
        for i in range(len(digits) - 1, -1, -1):           # rightmost digit first
            carry, digits[i] = divmod(digits[i] + carry, 10)   # new carry, new digit
        if carry:                                          # carried out of the leftmost digit: 999 + 1
            digits.insert(0, carry)
        return digits
Time O(n)Space O(1)

One pass over the digits. The answer reuses the input list; the only growth is a new leading 1.

When to use: When you want one loop that also works for adding bigger numbers.

Watch it run

Only a run of 9s at the right end can change, plus the first non-9 digit to its left. So scan from the right. A 9 becomes 0 (the carry moves on). The first digit below 9 simply gets 1 added, and we return at once: nothing to its left is touched. If the scan ends without returning, every digit was 9 and is now 0, so the answer is [1] + digits.

The worst case is the same O(n) as the carry loop ([9, 9, 9]), but most inputs stop after one or two digits, and there is no divmod bookkeeping: each case is a plain if.

Dry run

  1. digits = [4, 9, 9]
  2. i = 2: it is a 9 → set to 0, carry on
  3. i = 1: it is a 9 → set to 0, carry on
  4. i = 0: it is 4, below 9 → becomes 5, return [5, 0, 0]
  5. [9, 9, 9]: all three become 0, the loop ends, return [1, 0, 0, 0]

Python

class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        for i in range(len(digits) - 1, -1, -1):           # rightmost digit first
            if digits[i] < 9:
                digits[i] += 1                             # this digit absorbs the carry: done
                return digits
            digits[i] = 0                                  # 9 + 1 = 10: write 0, carry 1 to the left
        return [1] + digits                                # every digit was 9: 999 + 1 = 1000
Time O(n)Space O(1)

At most one pass; it usually stops after the first digit that is not 9. Only the all-9 case builds a new list of n + 1 digits.

When to use: The interview answer: short, and it shows you know that a carry stops at the first non-9.

Common mistakes

  • Forgetting the all-nines case. For [9, 9, 9] the loop turns every digit into 0 and the carry still has nowhere to go; you must put a 1 in front, which makes the list one longer.
  • Doing digits[i] += 1 on a 9. That leaves a 10 inside a single digit slot. A 9 must become 0 and pass the carry on.
  • Not stopping at the first digit that is not 9. If the loop keeps going left it keeps adding 1 to digits that must stay unchanged ([1, 2, 3] would turn into [2, 3, 4]).
  • Scanning left to right. The carry travels toward the left, so the scan has to go right to left.
  • Converting the list to an integer and back. It works in Python only because Python integers have no size limit; in most languages a 100-digit number does not fit in any integer type, which is the point of the exercise.

Python notes

  • range(len(digits) - 1, -1, -1) visits the indices from last to first. reversed(range(len(digits))) says the same thing more readably.
  • divmod(digits[i] + carry, 10) returns (carry, digit) in one call, which is exactly what a column sum needs.
  • [1] + digits builds a new list in O(n). That is fine because it happens at most once, at the very end.
  • The shortcut [int(ch) for ch in str(int("".join(map(str, digits))) + 1)] is valid Python, but it skips the exercise.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Add Binary LC 67 — the same carry loop in base 2 on two strings: keep one index per string and use divmod(total, 2).
  • Add Strings LC 415 — two decimal numbers of different lengths: walk both from the right while either has digits left or a carry remains.
  • Add to Array-Form of Integer LC 989 — add an integer k instead of 1: start with carry = k and use carry, digit = divmod(digits[i] + carry, 10). Leftover carry may be several digits, not just one.
  • Add Two Numbers LC 2 — the same carry on linked lists whose digits are stored least significant first, so you walk left to right.
  • Multiply Strings LC 43 — multiplication instead of addition: every pair of digits contributes to two result positions and the carries pile up.
  • Digits stored least significant first — the carry loop then runs left to right, and a leftover carry is appended at the end instead of put in front, which is cheaper.
