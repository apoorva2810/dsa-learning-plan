Minimum Path Sum Medium 250

LeetCode #64 ↗
Status

Find the smallest total of the numbers on a route from the top-left to the bottom-right cell of a grid, moving only right or down.

Problem

You get an m × n grid grid of non-negative integers. Every cell has a cost. Start on the top-left cell and walk to the bottom-right cell, moving one cell right or one cell down at a time.

Return the smallest possible sum of the costs of the cells on a route, counting both the start cell and the goal cell.

Examples

Example 1
Input: grid = [[3, 2, 7], [6, 1, 4], [5, 9, 2]]
Output: 12
Go right, down, right, down: 3 + 2 + 1 + 4 + 2 = 12. Every other route costs more.
Example 2
Input: grid = [[1, 4, 1], [3, 9, 9]]
Output: 15
The cheaper first step (down, cost 3) is a trap: it leads into the row of 9s and the route costs 1 + 3 + 9 + 9 = 22. Walking along the top row and dropping at the end costs 1 + 4 + 1 + 9 = 15.
Example 3
Input: grid = [[7]]
Output: 7
The start is also the goal. The route is that single cell, and its cost counts.

Constraints

  • m == len(grid) and n == len(grid[0])
  • 1 <= m, n <= 200
  • 0 <= grid[r][c] <= 200

Think first try before reading the solution

Look at the last cell of the route. The robot got there from the cell above or from the cell to the left. Which of the two should it have come from?

Key idea

Every route into a cell (r, c) ends with a move down from (r - 1, c) or right from (r, c - 1). What happens after the cell does not depend on how the robot arrived, so for the cheapest route into (r, c) it is always best to arrive by the cheaper of the two cheapest routes into those predecessors. Writing best(r, c) for that cost:

best(r, c) = grid[r][c] + min(best(r - 1, c), best(r, c - 1))

The top row can only be entered from the left and the left column only from above, so those cells are running sums. Fill the table row by row, left to right, and the bottom-right cell is the answer. Walking back from the goal to the cheaper predecessor at each cell recovers the route itself.

Why not just step to the cheaper neighbour each time? A greedy walk looks only one cell ahead. A cheap cell can be a doorway to a region of expensive cells, and the table avoids this by never committing early: it compares complete routes at every cell.

Because a row reads only the row above, a single list of length n can replace the table.

Approaches from the obvious one to the one you want in an interview

cost(r, c) is the cheapest total from cell (r, c) to the goal, counting both ends. At the goal it is just that cell's cost. Anywhere else the robot must step down or right (only the moves that stay inside the grid), so

cost(r, c) = grid[r][c] + min(cost(r + 1, c), cost(r, c + 1))

This mirrors the definition and is correct, but every route is explored on its own, and the same cell is reached again and again through different routes. The number of calls grows with the number of routes: an open 12 × 12 grid already makes about 2.7 million calls. Remembering each (r, c) after its first computation would cut that to one call per cell, which is what the table does without recursion.

Dry run

  1. grid [[1, 4, 1], [3, 9, 9]]: the goal cost(1, 2) = 9
  2. cost(0, 2) = 1 + cost(1, 2) = 10 (only a step down is possible); cost(1, 1) = 9 + cost(1, 2) = 18
  3. cost(0, 1) = 4 + min(cost(1, 1), cost(0, 2)) = 4 + min(18, 10) = 14
  4. cost(1, 0) = 3 + cost(1, 1) = 21; cost(0, 0) = 1 + min(21, 14) = 15

Python

class Solution:
    def minPathSum(self, grid: List[List[int]]) -> int:
        rows, cols = len(grid), len(grid[0])

        def cost(r: int, c: int) -> int:
            """Cheapest total from (r, c) to the bottom-right cell, counting both ends."""
            if r == rows - 1 and c == cols - 1:          # at the goal: just its own cost
                return grid[r][c]
            options = []
            if r + 1 < rows:                             # we may step down
                options.append(cost(r + 1, c))
            if c + 1 < cols:                             # we may step right
                options.append(cost(r, c + 1))
            return grid[r][c] + min(options)             # pay for this cell, then take the cheaper way on

        return cost(0, 0)
Time O(2^(m+n))Space O(m+n)

The calls form a tree with one leaf per route, and the recursion is at most m + n deep.

When to use: Only to see the recurrence. Beyond a dozen rows and columns it never finishes.

Store dp[r][c] = the cheapest total cost of any route from the start to cell (r, c), counting both ends.

  • dp[0][0] = grid[0][0];
  • top row: dp[0][c] = dp[0][c - 1] + grid[0][c], because a cell there can only be entered from the left;
  • left column: dp[r][0] = dp[r - 1][0] + grid[r][0], because a cell there can only be entered from above;
  • every other cell: dp[r][c] = grid[r][c] + min(dp[r - 1][c], dp[r][c - 1]).

The cell above and the cell to the left are always filled before the cell that reads them. The answer is the bottom-right cell. To recover the route, walk back from the goal and step to the cheaper predecessor at each cell.

Dry run

  1. grid [[3, 2, 7], [6, 1, 4], [5, 9, 2]]: dp[0][0] = 3; top row running totals [3, 5, 12]; left column [3, 9, 14]
  2. dp[1][1] = 1 + min(dp[0][1] = 5, dp[1][0] = 9) = 6; dp[1][2] = 4 + min(12, 6) = 10
  3. dp[2][1] = 9 + min(dp[1][1] = 6, dp[2][0] = 14) = 15; dp[2][2] = 2 + min(10, 15) = 12
  4. walking back from the goal: 2 ← 4 ← 1 ← 2 ← 3 is the route, 12 in total

Python

class Solution:
    def minPathSum(self, grid: List[List[int]]) -> int:
        rows, cols = len(grid), len(grid[0])
        dp = [[0] * cols for _ in range(rows)]       # dp[r][c] = cheapest cost from (0, 0) to (r, c)
        dp[0][0] = grid[0][0]
        for c in range(1, cols):                     # top row: only reachable from the left
            dp[0][c] = dp[0][c - 1] + grid[0][c]
        for r in range(1, rows):                     # left column: only reachable from above
            dp[r][0] = dp[r - 1][0] + grid[r][0]
        for r in range(1, rows):
            for c in range(1, cols):
                # the cheaper of the two ways in, plus the cost of this cell
                dp[r][c] = grid[r][c] + min(dp[r - 1][c], dp[r][c - 1])
        return dp[rows - 1][cols - 1]
Time O(m·n)Space O(m·n)

Each of the m·n cells is visited once and costs one comparison and one addition.

When to use: The version to write first. It also lets you rebuild the route by walking back, and it is the same shape as Unique Paths II.

Watch it run

Row r reads only row r - 1, so one list row of length n is enough. Visit the cells row by row, left to right:

  • the start: row[0] = grid[0][0];
  • the top row (r = 0): row[c] = row[c - 1] + grid[0][c];
  • the left column (c = 0): row[0] += grid[r][0], because the slot still holds the value from the row above;
  • everywhere else: row[c] = min(row[c], row[c - 1]) + grid[r][c]. Before the update, row[c] is the cost from above and row[c - 1] has already been updated for this row, so it is the cost from the left.

Memory drops from O(m·n) to O(n). If the interviewer lets you modify the input, the same loop written into grid itself needs no extra memory at all.

Dry run

  1. grid [[3, 2, 7], [6, 1, 4], [5, 9, 2]]: row 0 gives row = [3, 5, 12]
  2. row 1: row[0] = 3 + 6 = 9; row[1] = min(5, 9) + 1 = 6; row[2] = min(12, 6) + 4 = 10 → [9, 6, 10]
  3. row 2: row[0] = 9 + 5 = 14; row[1] = min(6, 14) + 9 = 15; row[2] = min(10, 15) + 2 = 12 → answer 12

Python

class Solution:
    def minPathSum(self, grid: List[List[int]]) -> int:
        cols = len(grid[0])
        row = [0] * cols                             # row[c] = cheapest cost to column c of the current row
        for r, grid_row in enumerate(grid):
            for c in range(cols):
                if r == 0 and c == 0:
                    row[0] = grid_row[0]             # the start
                elif r == 0:
                    row[c] = row[c - 1] + grid_row[c]            # top row: only from the left
                elif c == 0:
                    row[0] += grid_row[0]                        # left column: only from above (old row[0])
                else:
                    # old row[c] = cost from above, row[c - 1] = cost from the left (already this row)
                    row[c] = min(row[c], row[c - 1]) + grid_row[c]
        return row[-1]
Time O(m·n)Space O(n)

Same work as the table; only the current row is kept.

When to use: The usual follow-up when asked to reduce memory; the same pattern as the one-row Unique Paths.

Common mistakes

  • Greedy: always stepping to the cheaper of the right and the down neighbour. On [[1, 4, 1], [3, 9, 9]] it goes down first (3 is cheaper than 4) and pays 1 + 3 + 9 + 9 = 22, while the best route costs 15.
  • Treating a missing neighbour as cost 0 in min(up, left). On the top row min(0, left) is always 0, so the cost is understated. Use running sums for the first row and column, or use infinity for a missing neighbour.
  • Indexing a missing neighbour with -1: in Python dp[r - 1][c] with r = 0 reads the last row, and the wrong answer looks plausible.
  • Leaving the start cell out of the sum. The route cost includes grid[0][0] as well as the goal cell.
  • Plain recursion without a cache. The same cell is reached through many routes; an open 12 × 12 grid already makes about 2.7 million calls. Cache by (r, c) or fill a table.
  • Overwriting the input grid to save memory without asking. It is a fine O(1)-space trick when the interviewer allows it, but it destroys the caller's data.

Python notes

  • min(dp[r - 1][c], dp[r][c - 1]) is the whole decision. In row-by-row order both cells are already filled when the cell needs them.
  • float("inf") works as the cost of a missing neighbour inside min; the code here avoids it by treating the top row and left column as running sums.
  • [[0] * n for _ in range(m)] builds m independent rows; [[0] * n] * m builds one row referenced m times.
  • [row[:] for row in grid] copies a grid row by row. grid.copy() copies only the outer list, so the rows stay shared with the original.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Unique Paths II LC 63 — count routes instead of pricing them, with blocked cells: same table, up + left instead of min(up, left) + cost, and a blocked cell holds 0.
  • Dungeon Game LC 174 — the starting health you need depends on the cells after the current one, so the table is filled backwards from the goal.
  • Triangle LC 120 — same recurrence on a triangle: each number is entered from one of two numbers above it, so one list updated from the bottom row up is enough.
  • Minimum Falling Path Sum LC 931 — a move may also go down-left or down-right, so a cell takes the minimum of three cells above it instead of two.
  • Path With Minimum Effort LC 1631 — the cost is the biggest height jump along the route and moves go in four directions. A cell can now be revisited, so the one-pass table breaks; use Dijkstra's algorithm.
  • Return the route, not just its cost — walk back from the goal through the finished table: step to the cheaper of the cell above and the cell on the left, until you reach the start.
