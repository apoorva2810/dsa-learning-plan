Longest Repeating Character Replacement Medium

LeetCode #424 ↗
Status

With at most k letter changes, find the longest substring that can be turned into one repeated letter.

Problem

You are given a string s of uppercase English letters and an integer k. You may pick any character of s and change it to any other uppercase letter, at most k times in total.

Return the length of the longest substring that can consist of one repeated letter after those changes.

Examples

Example 1
Input: s = "ABAB", k = 2
Output: 4
Change both A's to B (or both B's to A): "BBBB".
Example 2
Input: s = "AABABBA", k = 1
Output: 4
Change the A at index 3 to B: "AABBBBA" contains "BBBB". No window of length 5 can be fixed with one change.

Constraints

  • 1 <= len(s) <= 10^5
  • s consists only of uppercase English letters
  • 0 <= k <= len(s)

Think first try before reading the solution

For one fixed substring, what is the fewest changes that make it a single repeated letter? Which letter should you keep?
Keep its most common letter and change everything else: length - (count of the most common letter) changes. A window is fixable when that number is at most k. Grow a window on the right and move left when it stops being fixable.
You only care about beating the best length so far, and that needs a letter count higher than any seen before. So max_freq can be the highest count ever seen (never lowered), and an unfixable window can slide by one instead of shrinking.

Key idea

The cheapest way to turn a window into one repeated letter is to keep its most frequent letter and replace the rest. So s[left..right] is fixable exactly when window length - max count <= k. Shrinking a window can never make that harder, which is the property a sliding window needs: extend right, and move left whenever the window is not fixable. A dictionary of letter counts keeps the check cheap.

The neat part is that the max count never needs to be recomputed downwards. The answer only improves when a window is longer than any fixable one found so far, and with the same k that requires a letter count higher than before. So keep max_freq as the largest count seen in any window. When the window is not fixable, slide it (move left by one, which keeps its length) instead of shrinking it. It can only grow again once some letter's count beats max_freq, which is exactly when a longer answer exists.

Approaches from the obvious one to the one you want in an interview

For each start, extend the substring one letter at a time, updating a count dictionary and the top count. The substring is fixable while length - top count <= k.

Once a substring from this start stops being fixable, every longer one fails too (adding a letter raises the length by 1 and the top count by at most 1), so you can stop that start early. Still, each start rescans what the previous start already counted: O(n²) in the worst case.

Dry run

  1. s = "AABABBA", k = 1
  2. start 0: A, AA, AAB (3 − 2 = 1 change), AABA (4 − 3 = 1), AABAB (5 − 3 = 2) → stop, best 4
  3. start 1: A, AB, ABA, ABAB (4 − 2 = 2) → stop
  4. ... no start reaches length 5 → answer 4

Python

class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        best = 0
        for start in range(len(s)):
            count = {}
            top = 0                                   # highest letter count in s[start..end]
            for end in range(start, len(s)):
                count[s[end]] = count.get(s[end], 0) + 1
                top = max(top, count[s[end]])
                if (end - start + 1) - top > k:
                    break                             # longer windows from `start` need even more changes
                best = max(best, end - start + 1)
        return best
Time O(n²)Space O(26)

Up to n starts with up to n ends each; the dictionary holds at most 26 letters.

When to use: Only to see which condition the sliding window maintains.

Keep one window and its letter counts. Move right forward; while the window needs more than k changes (length - max(count.values()) > k), remove s[left] and move left. Every window seen after the inner loop is fixable, so the best length is the answer.

Both pointers move forward only, so there are O(n) moves. Each validity check calls max(count.values()), which looks at up to 26 counts, so the total is O(26 · n): linear, with a constant factor the optimal version removes.

Python

class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        count = {}
        left = 0
        best = 0
        for right, c in enumerate(s):
            count[c] = count.get(c, 0) + 1
            while (right - left + 1) - max(count.values()) > k:   # too many letters to change
                count[s[left]] -= 1
                left += 1
            best = max(best, right - left + 1)
        return best
Time O(26 · n)Space O(26)

O(n) pointer moves, each validity check scanning at most 26 counts.

When to use: Easy to reason about: the window is always genuinely fixable.

Replace max(count.values()) with a running max_freq: the largest count any letter has reached in any window so far. It is updated only when the letter just added beats it, and it is never lowered.

When length - max_freq > k, move left by exactly one. The window's length stays the same, so it slides instead of shrinking. Why this is safe: the answer only improves if some window is longer than best, which needs a letter count above max_freq. Until a letter beats it, the window just carries the best length along; once one does, max_freq rises and the window can grow again. Every step is O(1).

Dry run

  1. s = "AABABBA", k = 1
  2. A, A, B, A → window AABA, max_freq 3, 4 − 3 = 1 change → best 4
  3. B → AABAB needs 5 − 3 = 2 > 1 → slide: drop A → ABAB (length 4)
  4. B → ABABB needs 2 → slide → BABB; A → BABBA needs 2 → slide → ABBA
  5. max_freq never got past 3, so the window never grew past 4 → answer 4

Python

class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        count = {}
        left = 0
        max_freq = 0                                  # highest count of one letter in any window so far
        best = 0
        for right, c in enumerate(s):
            count[c] = count.get(c, 0) + 1
            max_freq = max(max_freq, count[c])
            if (right - left + 1) - max_freq > k:     # not fixable even with the best letter count seen
                count[s[left]] -= 1                   # slide: drop one letter on the left,
                left += 1                             # so the window keeps its length
            best = max(best, right - left + 1)
        return best
Time O(n)Space O(26)

Constant work per character; the count dictionary holds at most 26 letters.

When to use: The optimal answer. Be ready to explain why the stale max_freq cannot produce a wrong length.

Common mistakes

  • Counting the changes wrongly: the number needed is length - count of the most common letter, not the number of distinct letters or the count of some fixed letter.
  • Forgetting count[s[left]] -= 1 when left moves. The counts then describe a bigger window than the one you think you have.
  • "Fixing" the stale max_freq by recomputing it after every move. It is correct but costs O(26) per step, and it is unnecessary: a too-high max_freq can only stop the window from shrinking, never let it grow past a real answer.
  • Reading the current window as the answer in the max_freq version. After a slide it may need more than k changes; only its length is guaranteed. To return the substring, record left at the moment best increases (the window is fixable then).

Python notes

  • count[c] = count.get(c, 0) + 1 (or a defaultdict(int) / Counter) updates letter counts without a key check.
  • max(count.values()) scans at most 26 keys here. That makes it a constant, but a 26× one, paid on every step of the simpler window.
  • right - left + 1 is the length of the inclusive window s[left..right].
