Meeting Rooms Easy

LeetCode #252 ↗
Status

Decide whether one person can attend every meeting on a list, that is, whether no two meetings overlap.

Problem

You are given a list intervals. Each item [start, end] is a meeting that begins at time start and finishes at time end. Return True if one person could attend all of the meetings, and False if any two of them overlap.

  • A meeting that ends at time t does not clash with one that starts at t: the person walks straight from one to the next.
  • The list is not sorted and may be empty.

Examples

Example 1
Input: intervals = [[0, 30], [5, 10], [15, 20]]
Output: false
The meeting from 5 to 10 happens while the meeting from 0 to 30 is still running.
Example 2
Input: intervals = [[7, 10], [2, 4]]
Output: true
Sorted by start they are 2 to 4, then 7 to 10: far apart.
Example 3
Input: intervals = [[1, 5], [5, 8]]
Output: true
The first meeting ends at 5 exactly when the second begins. That is allowed.

Constraints

  • 0 <= len(intervals) <= 10^4
  • intervals[i] = [start, end]
  • 0 <= start < end <= 10^6

Think first try before reading the solution

Start with one pair. When are two meetings not in conflict? Work out the condition for a pair before looking at the list.
Testing every pair works but takes about n² / 2 checks. If the meetings were sorted by start time, which meetings could possibly clash with a given one?
After sorting by start, compare each meeting only with the one immediately before it: its start must be at or after that meeting's end. If every neighbouring pair is fine, the whole list is fine.

Key idea

Two meetings clash when each starts before the other ends. The slow way tests that for every pair.

The fix is to sort by start time. Suppose meeting i clashes with a later meeting j in the sorted list, which means j starts before i ends. The meeting right after i starts no later than j does (that is what sorted means), so it also starts before i ends, and it clashes with i too. So whenever any clash exists, some neighbouring pair clashes. It is enough to compare each meeting's start with the previous meeting's end: start < previous_end means a clash.

One sort and one pass over the neighbours: O(n log n) in total, instead of O(n²).

Approaches from the obvious one to the one you want in an interview

Two meetings clash when each one starts before the other ends: a.start < b.end and b.start < a.end. The comparison is strict (<) because a meeting that ends at 5 and another that starts at 5 do not clash.

Test every pair once (j > i, so no meeting is compared with itself and no pair is tested twice). If one pair clashes, return False; if none does, return True.

There are n(n − 1) / 2 pairs. For 10,000 meetings that is almost 50 million tests, and the work does not shrink even when the meetings are far apart, because nothing tells you which pairs could clash.

Dry run

  1. intervals = [[0, 30], [5, 10], [15, 20]]
  2. Pair (0, 1): [0, 30] and [5, 10]. 0 < 10 and 5 < 30, both true, so they clash. Return False right away.
  3. With [[7, 10], [2, 4]] there is one pair: 7 < 4 is false, so no clash. Nothing else to check: return True.

Python

class Solution:
    def canAttendMeetings(self, intervals: List[List[int]]) -> bool:
        n = len(intervals)
        for i in range(n):
            for j in range(i + 1, n):                     # each pair once
                a, b = intervals[i], intervals[j]
                if a[0] < b[1] and b[0] < a[1]:           # each starts before the other ends
                    return False
        return True
Time O(n²)Space O(1)

Two nested loops over n meetings; no extra memory.

When to use: As a warm-up, or when n is tiny. It also doubles as an easy way to check a faster solution.

Watch it run

Sort the meetings by start time, then check each meeting against the one right before it. A meeting clashes with its predecessor exactly when it starts before the predecessor ends: start < previous_end.

Why neighbours are enough: if meeting i clashes with some later meeting j, then j starts before i ends. The meeting right after i starts no later than j (the list is sorted), so it starts before i ends too, and i clashes with its own neighbour. So if no neighbouring pair clashes, no pair does.

Sorting costs O(n log n) and the scan O(n), so the sort is the whole cost.

Dry run

  1. intervals = [[7, 10], [2, 4], [4, 7]] sorted by start: [[2, 4], [4, 7], [7, 10]]
  2. [4, 7] starts at 4, the previous meeting ends at 4: 4 < 4 is false, so they only touch. Fine.
  3. [7, 10] starts at 7, the previous meeting ends at 7: 7 < 7 is false. Fine.
  4. End of the list with no clash: True.
  5. [[0, 30], [5, 10], [15, 20]] is already sorted: [5, 10] starts at 5 < 30, so return False immediately.

Python

class Solution:
    def canAttendMeetings(self, intervals: List[List[int]]) -> bool:
        intervals = sorted(intervals)                     # by start time (ties by end)
        for i in range(1, len(intervals)):
            if intervals[i][0] < intervals[i - 1][1]:     # starts before the previous meeting ends
                return False
        return True                                       # also the answer for 0 or 1 meetings
Time O(n log n)Space O(n)

The sort dominates. sorted returns a copy (O(n) extra space); the scan afterwards is O(n).

When to use: Always. This is the interview answer, and the same sort-then-compare-neighbours idea runs through the rest of the topic.

Common mistakes

  • Writing <= in the neighbour check. [1, 5] and [5, 8] do not clash, but intervals[i][0] <= intervals[i - 1][1] reports a clash and returns False. A clash needs the next start to be strictly before the previous end.
  • Comparing neighbours without sorting first. For [[1, 5], [8, 9], [4, 6]] neither neighbouring pair clashes, yet [1, 5] and [4, 6] do.
  • Reading intervals[0] before checking that the list is non-empty. No meetings means nothing can clash: return True. Looping over range(1, len(intervals)) handles 0 and 1 meetings with no special case.
  • A one-sided pair test such as b[0] < a[1] in the brute force. It is only right when a starts first. For any pair, test both directions: a[0] < b[1] and b[0] < a[1].

Python notes

  • sorted(intervals) orders the inner [start, end] lists by start, then by end, with no key. intervals.sort() does the same in place and reorders the caller's list.
  • range(1, len(intervals)) is empty for 0 or 1 meetings, so the loop body never runs and the function falls through to return True.
  • The whole check also fits in one line, all(b[0] >= a[1] for a, b in zip(intervals, intervals[1:])), where zip pairs each meeting with the next one. The explicit loop is easier to step through.

Follow-up questions

What an interviewer might ask next, and what changes.

  • Meeting Rooms II LC 253 — instead of yes or no, return how many rooms are needed: a min-heap of end times (or an event sweep) tracks how many meetings run at once.
  • Non-overlapping Intervals LC 435 — if the answer is no, how many meetings must be cancelled so the rest fit? Sort by end and keep greedily.
  • My Calendar I LC 729 — meetings arrive one at a time and each is accepted only if it clashes with none so far. You cannot sort once up front, so keep a sorted list and use bisect to find the two neighbours of the new meeting.
  • Determine if Two Events Have Conflict LC 2446 — only one pair, with times as HH:MM strings, and both ends are inclusive, so touching is a conflict there: <= instead of <.
  • Return a conflicting pair — return the positions of two meetings that clash instead of True or False. Sort (start, end, index) triples so the original positions survive.
