Heap / Priority Queue

Always grab the smallest or largest item fast: top-k, scheduling, medians.

Prerequisites: Trees

What it is

A heap is a list arranged so that the smallest item is always at the front, heap[0], while adding or removing an item costs only O(log n). It is the usual way to build a priority queue: a waiting line where the most urgent item is served next, whatever order the items arrived in. A hospital emergency room works this way: patients are not seen in arrival order, the most urgent one is always next.

Inside, the list is a binary tree stored level by level. The children of index i live at 2*i + 1 and 2*i + 2, and the parent of i is at (i - 1) // 2. There is one rule, the heap property: every parent is ≤ its children. That makes the root the minimum but leaves everything else only partly ordered, which is why a heap is cheaper to maintain than a sorted list. A push appends at the end and sifts up (swaps with its parent while it is smaller); a pop moves the last item into the root's place and sifts down (swaps with its smaller child while it is larger). Each walks a single root-to-leaf path, so at most about log₂ n swaps.

Python's heapq module works on a plain list and gives only a min-heap:

  • Max-heap: push negated numbers (-x) and negate again when you read them (-heap[0]).
  • Priorities with several parts: push tuples. Tuples compare field by field, so (priority, tie_breaker, item) orders by priority and falls back to the tie-breaker when two priorities are equal.

How to recognise it

  • The words k-th largest / smallest, top k, k closest, k most frequent: keep a heap of size k.
  • You repeatedly need the current smallest or largest item while items keep arriving or changing (a stream, or a simulation like smashing stones or running tasks).
  • Several sorted sequences must be combined in order, or you only need the first few items of their merge (merge k sorted lists, a news feed built from many timelines).
  • A running median, or anything that splits the data into a lower and an upper half: use two heaps.
  • Scheduling by time or cost: always process the earliest-finishing or cheapest option next (meeting rooms, CPU scheduling, Dijkstra's shortest paths, Prim's spanning tree).

heapq push and pop, one swap at a time

Six values are pushed onto an empty min-heap, then the smallest is popped three times. A pushed value bubbles up past larger parents (sift-up); after a pop, the value moved into the root sinks down past smaller children (sift-down). The list and the tree are the same data drawn two ways.

Patterns and Python templates

Max-heap by negating

Use it when: you need the largest item first and heapq only gives you the smallest.

import heapq

def largest_first(nums: list[int]) -> list[int]:
    heap = [-x for x in nums]              # the largest x becomes the smallest -x
    heapq.heapify(heap)                    # O(n), rearranges the list in place
    out = []
    while heap:
        out.append(-heapq.heappop(heap))   # negate back when reading
    return out

Negate on the way in and on the way out. With tuples, negate only the numeric key: (-count, letter).

Keep the k largest with a size-k min-heap

Use it when: top-k / k-th largest questions, especially when the data is large or arrives as a stream.

import heapq

def k_largest(nums: list[int], k: int) -> list[int]:
    heap = []                              # min-heap holding the k largest values seen so far
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:                  # one too many:
            heapq.heappop(heap)            # the smallest of them cannot be in the top k
    return heap                            # heap[0] is the k-th largest

O(n log k) time, O(k) memory. The counter-intuitive part: the k largest live in a min-heap, because the one to throw out is always the smallest of them. For the k smallest, use a max-heap of size k.

Tuple priorities with a tie-breaker

Use it when: the priority has several parts, or the items themselves cannot be compared with <.

import heapq
import itertools

heap = []
order = itertools.count()                  # 0, 1, 2, ...: unique and increasing

def push(priority: int, item) -> None:
    # tuples compare field by field: priority first, then insertion order.
    # The item is never compared, so it may be a ListNode, a dict, anything.
    heapq.heappush(heap, (priority, next(order), item))

def pop():
    priority, _, item = heapq.heappop(heap)
    return priority, item

Without the middle field, two equal priorities make Python compare the items, which raises TypeError for objects like ListNode. Any unique number works as the tie-breaker (a counter, a list index, a timestamp).

K-way merge

Use it when: you need sorted output from k sorted sources, or only the first few items of that merge.

import heapq

def merge_sorted(lists: list[list[int]]) -> list[int]:
    # one candidate per list: (value, which list, position in that list)
    heap = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
    heapq.heapify(heap)
    out = []
    while heap:
        value, i, j = heapq.heappop(heap)          # smallest front among all lists
        out.append(value)
        if j + 1 < len(lists[i]):                  # that list's next item replaces it
            heapq.heappush(heap, (lists[i][j + 1], i, j + 1))
    return out

The heap never holds more than k items, so each output item costs O(log k). Stop early when you only need the first few (Design Twitter's feed stops after 10).

Two heaps for a running median

Use it when: numbers arrive one at a time and you must report the middle value (or balance a lower and an upper half).

import heapq

class RunningMedian:
    def __init__(self):
        self.low = []                      # smaller half, max-heap (stored negated)
        self.high = []                     # larger half, min-heap

    def add(self, x: int) -> None:
        heapq.heappush(self.low, -x)
        heapq.heappush(self.high, -heapq.heappop(self.low))   # low's largest moves up
        if len(self.high) > len(self.low):                     # keep len(low) >= len(high)
            heapq.heappush(self.low, -heapq.heappop(self.high))

    def median(self) -> float:
        if len(self.low) > len(self.high):
            return float(-self.low[0])
        return (-self.low[0] + self.high[0]) / 2

The two tops are the middle of the data: -low[0] is the largest small value and high[0] the smallest large one.

Compared with a sorted list: a sorted list also has O(1) access to the minimum, but inserting into it shifts elements (O(n)). A heap gives up full ordering to make insertion O(log n).

Common mistakes

  • heapq is a min-heap only. For the largest first, push -x and negate again when you read (-heap[0]). Forgetting one of the two negations is the most common heap bug.
  • The list is not sorted. Only heap[0] is guaranteed (the smallest); heap[1] is not the second smallest and heap[-1] is not the largest.
  • Tuples break ties with their next field. If that field is an object without < (ListNode, dict), two equal priorities raise TypeError. Put a unique number (an index or a counter) before the object.
  • You cannot cheaply change or delete an item in the middle of a heap. Push a fresh entry instead and skip outdated ones when they reach the top (lazy deletion: delete later, at the moment the item would be used).
  • heapq trusts you: it never checks the heap property. Pushing onto a list you never heapify-ed, or edited by hand, silently gives wrong answers.

Python tips

  • heapq.heapify(lst) turns a list into a heap in place in O(n), cheaper than n separate pushes (O(n log n)).
  • heapq.heappushpop(heap, x) (push then pop) and heapq.heapreplace(heap, x) (pop then push) each do the work of two calls with a single sift: handy for size-k heaps.
  • heapq.nlargest(k, xs, key=...) and heapq.nsmallest(...) are one-line top-k helpers; they keep a size-k heap internally.
  • Python 3.14 added heapq.heappush_max, heappop_max and heapify_max. This site and many online judges run older versions, so learn the negation trick: it works everywhere.
