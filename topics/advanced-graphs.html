Advanced Graphs

Shortest paths and spanning trees: Dijkstra, Prim, Bellman-Ford, Euler paths.

Prerequisites: Graphs, Heap / Priority Queue

What it is

The Graphs topic treated every edge as one step, and BFS found the route with the fewest steps. Here edges carry a weight: a travel time, a price, a distance. The route with the fewest edges is no longer the cheapest one, and a few classic algorithms take over.

  • Dijkstra's algorithm finds the cheapest route from one source to every node when no weight is negative. Picture ripples spreading from the source at a steady speed along the roads: they reach nearer places first, and the first ripple to reach a place came along its shortest route. A min-heap (Python's heapq) plays the ripple: it always hands back the closest place not yet settled.
  • Bellman-Ford relaxes every edge in rounds. It is slower, but it copes with negative weights, and when each round reads only the previous round's distances, round i knows exactly the best routes that use at most i edges, which is what "at most k stops" questions need.
  • A minimum spanning tree (MST) links all nodes using edges of the least total weight, with no cycle. Prim grows one tree outward with a heap; Kruskal takes edges cheapest-first and uses union-find to skip any edge that would close a cycle.
  • An Euler path uses every edge exactly once (every plane ticket, every domino). Hierholzer's algorithm walks until it is stuck and writes the route down backwards.
  • Sometimes the graph is hidden in the data, as in a list of words sorted by an unknown alphabet. Build the edges yourself, then run the topological sort from the Graphs topic.

In Python, weighted graphs are usually a dictionary of lists of pairs: graph[u].append((v, w)). The heap stores tuples (priority, node), and heapq.heappop always returns the smallest priority.

How to recognise it

  • Cheapest / fastest / minimum cost from a start, and edges have different non-negative weights: Dijkstra.
  • Connect all the points, cities or houses for the least total cost, and any connection is allowed: a minimum spanning tree (Prim on dense graphs, Kruskal on edge lists).
  • A limit on the number of edges or stops (at most k flights), or negative weights: Bellman-Ford rounds, or a search over (node, steps used) states.
  • Use every ticket, edge or domino exactly once and return the route: an Euler path, Hierholzer's algorithm.
  • An ordering you must infer from data (an alien alphabet from sorted words, versions from changelogs): build a directed graph from neighbouring items, then topologically sort it.
  • Minimise the largest single step along a route (highest water level, biggest climb): Dijkstra with max instead of +, or binary search on the answer with a BFS check.

Patterns and Python templates

Dijkstra with a min-heap

Use it when: shortest routes from one source, every weight >= 0.

import heapq


def dijkstra(graph: dict, source) -> dict:
    """graph[u] = [(v, weight), ...] with weights >= 0. Returns the shortest distance to every reachable node."""
    dist = {source: 0}
    heap = [(0, source)]                           # (distance so far, node): smallest distance pops first
    while heap:
        d, node = heapq.heappop(heap)
        if d > dist[node]:                         # stale entry: a shorter route was found after this push
            continue
        for nxt, w in graph.get(node, []):
            nd = d + w
            if nd < dist.get(nxt, float("inf")):  # relax: a shorter way into nxt
                dist[nxt] = nd
                heapq.heappush(heap, (nd, nxt))
    return dist

A node's distance is final when it is popped, not when it is pushed: a cheaper route may still turn up later through a node that is close to the source. Instead of deleting outdated heap entries, skip them when they surface ("lazy deletion"); that is the d > dist[node] line.

Prim's minimum spanning tree

Use it when: connect every node at minimum total weight, especially on dense graphs (every pair of points is an edge).

import heapq


def prim_mst_cost(n: int, graph: dict) -> int:
    """Undirected graph[u] = [(v, weight), ...] on nodes 0..n-1. Returns the MST cost, or -1 if disconnected."""
    in_tree = set()
    heap = [(0, 0)]                                # (cost to attach, node): node 0 joins for free
    total = 0
    while heap and len(in_tree) < n:
        cost, node = heapq.heappop(heap)
        if node in in_tree:                        # already attached by a cheaper edge
            continue
        in_tree.add(node)
        total += cost
        for nxt, w in graph.get(node, []):
            if nxt not in in_tree:
                heapq.heappush(heap, (w, nxt))     # push the EDGE weight, not a path length
    return total if len(in_tree) == n else -1

It looks like Dijkstra, with one difference that matters: Prim pushes the weight w of the single edge that would attach nxt, while Dijkstra pushes the whole route length d + w.

Kruskal's minimum spanning tree with union-find

Use it when: the input is an edge list, or edges can be sorted cheaply; also the base of 'critical edge' questions.

def kruskal_mst_cost(n: int, edges: list[tuple[int, int, int]]) -> int:
    """edges = [(weight, u, v), ...] on nodes 0..n-1. Returns the MST cost, or -1 if disconnected."""
    parent = list(range(n))

    def find(x: int) -> int:
        while parent[x] != x:
            parent[x] = parent[parent[x]]          # path halving
            x = parent[x]
        return x

    total = used = 0
    for w, u, v in sorted(edges):                  # cheapest edges first
        root_u, root_v = find(u), find(v)
        if root_u == root_v:
            continue                               # u and v already connected: this edge would close a cycle
        parent[root_u] = root_v
        total += w
        used += 1
        if used == n - 1:                          # a spanning tree on n nodes has n - 1 edges
            break
    return total if used == n - 1 else -1

Why cheapest-first is safe: any cheapest edge that crosses between two groups can be swapped into an optimal tree without raising its cost (the "cut property").

Bellman-Ford, optionally limited to k edges

Use it when: negative weights, a cap on the number of edges or stops, or detecting a negative cycle.

def bellman_ford(n: int, edges: list[list[int]], source: int, max_edges: int | None = None) -> list[float]:
    """edges = [[u, v, w], ...] (w may be negative). max_edges caps the route length (k stops = k + 1 edges)."""
    INF = float("inf")
    dist = [INF] * n
    dist[source] = 0
    rounds = n - 1 if max_edges is None else max_edges
    for _ in range(rounds):
        new_dist = dist[:]                         # read last round's values, write this round's
        for u, v, w in edges:
            if dist[u] + w < new_dist[v]:
                new_dist[v] = dist[u] + w
        if new_dist == dist:                       # nothing improved: every distance is final
            break
        dist = new_dist
    return dist

After round i, dist holds the best routes that use at most i edges. The copy is what enforces that: updating in place lets one round chain several edges and silently breaks a stop limit. If an n-th round still improves something, the graph has a negative cycle.

Hierholzer's Euler path

Use it when: use every edge exactly once (tickets, dominoes, de Bruijn strings) and return the walk.

from collections import defaultdict


def euler_path(edges: list[list[str]], start: str) -> list[str]:
    """Directed edges [u, v], each used once. Picks the smallest neighbour first at every fork."""
    graph = defaultdict(list)
    for u, v in sorted(edges, reverse=True):       # reverse-sorted, so pop() returns the smallest
        graph[u].append(v)
    route, stack = [], [start]
    while stack:
        node = stack[-1]
        if graph[node]:
            stack.append(graph[node].pop())         # walk an unused edge
        else:
            route.append(stack.pop())               # stuck: node is the last stop of what remains
    return route[::-1]                              # nodes were written down back to front

A node goes into route only when it has no unused edges left. Dead ends are therefore recorded first and end up at the end of the reversed route, which is the only place they can go.

Topological sort of a graph you derive yourself

Use it when: the ordering rules are not given as edges but are implied by the data, e.g. words sorted in an unknown alphabet.

from collections import deque


def order_from_sorted_words(words: list[str]) -> str:
    """The letter order implied by a sorted word list, or "" if the list contradicts itself."""
    graph = {c: [] for word in words for c in word}
    indegree = {c: 0 for c in graph}
    for first, second in zip(words, words[1:]):    # only neighbouring words carry information
        for x, y in zip(first, second):
            if x != y:                              # the first difference decides: x comes before y
                if y not in graph[x]:
                    graph[x].append(y)
                    indegree[y] += 1
                break
        else:                                       # no difference inside the shorter word
            if len(first) > len(second):            # "abc" listed before "ab" is impossible
                return ""
    queue = deque(c for c in graph if indegree[c] == 0)
    order = []
    while queue:
        c = queue.popleft()
        order.append(c)
        for nxt in graph[c]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    return "".join(order) if len(order) == len(graph) else ""

Comparing only adjacent items is enough: any rule implied by two far-apart items is implied by the chain of neighbours between them.

The log factors come from the heap or the sort. Lazy deletion lets a heap hold up to E entries instead of V; since log E ≤ 2 log V, that does not change the bound.

Common mistakes

  • Running Dijkstra with a negative edge. A node that was already popped as final can later be reached more cheaply through the negative edge, and the answer is wrong. Use Bellman-Ford.
  • Treating a node as final when it is pushed, as you would in BFS. In Dijkstra it is final only when popped; and without the d > dist[node] check, stale entries get expanded again and waste time.
  • Updating distances in place during a Bellman-Ford round that must respect a stop limit. Copy the array each round, or a single round can chain several edges together.
  • Mixing up Prim and Dijkstra: Prim pushes the single edge weight w, Dijkstra pushes the route length d + w. The code looks almost identical, but the two compute different things.
  • Writing a node into the Euler route the first time you visit it. Hierholzer's algorithm writes it when it is stuck, then reverses the list; otherwise a dead-end branch ends up in the middle of the route.

Python tips

  • heapq works on a plain list and is a min-heap. Push tuples (priority, node); on a priority tie Python compares the next field, so keep it comparable (ints, strings) or add a counter (priority, count, item).
  • float("inf") (or math.inf) marks 'no route yet'. inf + 5 is still inf, so relaxation needs no special case for unreachable nodes.
  • graph = defaultdict(list) with graph[u].append((v, w)) builds a weighted adjacency list; for v, w in graph[u]: unpacks each neighbour and its weight.
  • For a max-heap, push negated priorities: heapq.heappush(heap, (-value, item)).
