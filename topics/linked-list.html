Linked List

Pointer surgery: reverse, split, merge and detect cycles without extra memory.

Prerequisites: Two Pointers

What it is

A linked list stores items in separate nodes. Each node holds a value and a reference (next) to the node after it. You reach the list through its first node, the head; the last node's next is None. Think of a scavenger hunt: every clue tells you where the next clue is hidden, so you cannot jump to clue 5 without following clues 1 to 4.

On LeetCode a node is this small class (it is pre-defined for you):

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

head = ListNode(1, ListNode(2, ListNode(3)))   # 1 -> 2 -> 3 -> None

Compared with a Python list (an array: items side by side in memory), a linked list gives up fast indexing (nums[5] is O(1), reaching the 6th node is O(n)) in exchange for cheap surgery: once you hold a node, inserting or removing next to it is O(1), because only a couple of next references change and nothing has to shift.

That is what interview problems test: pointer surgery. You re-point next fields to reverse, split, merge or reorder a list, usually with O(1) extra memory. Variants: a doubly linked list also has prev on every node (remove any node you hold in O(1)), and a cycle is a list whose last node points back into the list.

How to recognise it

  • The input is a ListNode head, and the task says in place, O(1) extra memory, or do not change the values.
  • Anything counted from the end or from the middle (n-th from the end, middle node, palindrome check): two pointers with a fixed gap or two speeds.
  • Reverse all or part of the order, or reorder it (front/back alternating, blocks of k).
  • Combine sorted sequences: merge two (or k) sorted lists.
  • Does it loop? Where does it repeat?, including disguised versions: an array whose values are indices (Find the Duplicate Number) or a number sequence that may cycle (Happy Number).
  • You need O(1) lookup and O(1) reordering of items (move to front, evict the oldest): a hash map pointing into a doubly linked list (LRU cache).

Reversing a list in place with three pointers

Watch prev, cur and nxt. Each round saves the rest of the list, flips one arrow, then steps forward. The top row is the part already reversed; the bottom row is what is still in the original order.

Patterns and Python templates

Dummy (sentinel) head

Use it when: the head itself may be removed or replaced, or you are building a new list node by node.

def remove_all(head, target):
    dummy = ListNode(0, head)            # a fake node in front of the real head
    prev = dummy
    while prev.next:
        if prev.next.val == target:
            prev.next = prev.next.next   # unlink: jump over the node
        else:
            prev = prev.next
    return dummy.next                    # the real head (it may have changed)

Without the dummy, removing the first node is a special case. With it, every node has a node before it.

In-place reversal (prev / cur / nxt)

Use it when: reverse a whole list, a range, or blocks of it, with O(1) extra memory.

def reverse(head):
    prev, cur = None, head
    while cur:
        nxt = cur.next                   # 1. save the rest of the list
        cur.next = prev                  # 2. flip this node's arrow
        prev, cur = cur, nxt             # 3. step forward
    return prev                          # the old tail is the new head

The order matters: if you flip before saving cur.next, the rest of the list is unreachable.

Fast and slow pointers

Use it when: find the middle, detect a cycle, or find where a cycle starts, without extra memory.

def middle(head):
    slow = fast = head
    while fast and fast.next:            # fast moves 2, slow moves 1
        slow = slow.next
        fast = fast.next.next
    return slow                          # for even lengths: the second middle

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:                 # the fast runner lapped the slow one
            return True
    return False

When fast reaches the end, slow has covered half the distance. Inside a loop the gap between them shrinks by one node per step, so they must meet.

Two pointers with a fixed gap

Use it when: you need the k-th node from the end in one pass.

def kth_from_end(head, k):
    lead = trail = head
    for _ in range(k):                   # lead starts k nodes ahead
        lead = lead.next
    while lead:                          # move both until lead falls off the end
        lead = lead.next
        trail = trail.next
    return trail                         # k = 1 gives the last node

The gap is a ruler of length k: when its front end leaves the list, its back end is k nodes from the end. Start both at a dummy node to stop one node before the target (needed to delete it).

Merge with a tail pointer

Use it when: weave two lists into one: sorted merge, alternating merge, digit-by-digit addition.

def merge_sorted(a, b):
    dummy = tail = ListNode()            # tail is the last node of the result so far
    while a and b:
        if a.val <= b.val:
            tail.next = a
            a = a.next
        else:
            tail.next = b
            b = b.next
        tail = tail.next
    tail.next = a if a else b            # one list is empty: attach the other whole
    return dummy.next

Complexity cheat-sheet

Read the i-th itemO(n): walk i stepsO(1)

Delete a node you holdO(n) singly (find its predecessor), O(1) doubly linkedO(n)

Amortised means averaged over many operations: an occasional append is slow (the array grows), but the average is O(1).

Common mistakes

  • Losing the rest of the list: save cur.next before you overwrite it.
  • AttributeError: 'NoneType' object has no attribute 'next': test fast and fast.next (in that order) before jumping two steps, and cur before reading cur.next.
  • Returning a stale head. If the head can change (it was removed, or the list was reversed), return dummy.next or the new head variable.
  • Leaving an accidental cycle: after reversing or splitting, the new tail must point to None. A cycle makes any loop over the list run forever.
  • Comparing values when you mean the same node: a.val == b.val is true for different nodes holding equal values; a is b checks identity.

Python tips

  • Tuple assignment evaluates the whole right side first, then assigns left to right. cur.next, prev, cur = prev, cur, cur.next is a correct reversal step, but cur, cur.next = cur.next, prev sets .next on the new cur. When unsure, use a temporary nxt.
  • heapq cannot compare two ListNodes. Push (node.val, i, node) where i is unique, so ties never reach the nodes.
  • Nodes are hashable by identity, so a set of nodes answers 'have I been here?' and a dict maps an old node to its copy.
  • A debugging helper with a length cap survives cycles: def show(h, cap=20): out = [] then while h and len(out) < cap: out.append(h.val); h = h.next.
