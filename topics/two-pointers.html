Two Pointers

Walk two indices toward each other (or together) to avoid nested loops.

Prerequisites: Arrays & Hashing

What it is

The two pointers technique walks two indices over a sequence instead of one, so a single pass does the work a pair of nested loops would. A pointer here is just an integer index, such as left or right.

It comes in three shapes:

  • Converging pointers start at both ends and move toward each other: palindromes, pair sums in a sorted array, "widest container" problems.
  • Same-direction pointers both move left to right at different speeds. A fast read pointer looks at every element while a slow write pointer marks where the next kept element goes, which filters an array in place.
  • One pointer per sequence: merging two sorted lists, or checking that one string is a subsequence of another.

Picture two people looking for two books on a sorted shelf whose page counts add up to 500. One starts at the thin end, the other at the thick end. Too many pages in total, and the person at the thick end steps inward; too few, and the thin end steps inward. Nobody ever walks back.

The technique works when every pointer move can be justified: the element you step past provably cannot be part of a better answer. Sorted order is the usual source of that guarantee; symmetry (palindromes) and "the shorter wall caps the water" (containers) are others.

left, right = 0, len(nums) - 1      # converging pointers
while left < right:
    ...                             # look at nums[left] and nums[right], then move at least one of them inward

How to recognise it

  • The input is sorted (or you may sort it) and you need a pair or triplet with a given sum or difference.
  • The answer compares the two ends of something: palindromes, reversing in place, the widest or tallest container.
  • You must change an array in place with O(1) extra memory: remove duplicates, move zeros, partition by a condition.
  • Two sorted sequences must be merged, intersected or compared element by element.
  • The brute force tries every pair (i, j), and one comparison is enough to rule out a whole row of those pairs.

Converging pointers: a pair with a target sum in a sorted array

Each comparison proves one number cannot be in the answer. Dimmed cells are ruled out for good, and the count shows how many of the n(n−1)/2 pairs each single step eliminated.

Patterns and Python templates

Converging pointers on a sorted array

Use it when: find a pair with a target sum (or closest sum) in sorted data.

def pair_with_sum(nums: list[int], target: int) -> list[int]:
    """nums is sorted. Return [i, j] with nums[i] + nums[j] == target, or []."""
    left, right = 0, len(nums) - 1
    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return [left, right]
        if total < target:
            left += 1             # nums[left] is too small even with the biggest partner
        else:
            right -= 1            # nums[right] is too big even with the smallest partner
    return []

Each comparison rules out one element for good, so the loop runs at most n − 1 times.

Compare from both ends

Use it when: the property is symmetric: palindromes, reversing, comparing a sequence with its mirror image.

def is_palindrome(s: str) -> bool:
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True

To ignore some characters, add inner while left < right and ... loops that skip them.

Read/write pointers (filter in place)

Use it when: keep some elements and drop others without a second array.

def remove_duplicates_sorted(nums: list[int]) -> int:
    """Keep one copy of each value at the front of nums; return how many were kept."""
    if not nums:
        return 0
    write = 1                                 # nums[:write] is the cleaned prefix
    for read in range(1, len(nums)):
        if nums[read] != nums[write - 1]:     # a value we have not kept yet
            nums[write] = nums[read]
            write += 1
    return write

read visits every element; write advances only when an element is kept. 'Move zeros to the end' and 'remove every copy of a value' use the same shape.

Fix one element, two-pointer the rest (k-sum)

Use it when: triplets (or quadruplets) with a target sum, without duplicate answers.

def three_sum_zero(nums: list[int]) -> list[list[int]]:
    nums.sort()
    res = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                          # same first value as the previous round
        left, right = i + 1, len(nums) - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                res.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1                 # skip repeated values: they would rebuild the same triplet
    return res

Sorting puts equal values next to each other, so skipping duplicates is one comparison with the previous element.

One pointer per sequence (merge)

Use it when: two sorted sequences must be combined or compared in order.

def merge_sorted(a: list[int], b: list[int]) -> list[int]:
    i = j = 0
    out = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:                      # take the smaller head
            out.append(a[i])
            i += 1
        else:
            out.append(b[j])
            j += 1
    out.extend(a[i:])                         # at most one of these is non-empty
    out.extend(b[j:])
    return out

Complexity cheat-sheet

PatternTimeExtra space
Converging pointersO(n)O(1)
Read/write pointersO(n)O(1)
Merge two sorted listsO(n + m)O(n + m) for the output
Sort, then converging pointersO(n log n)O(1) besides the sort
Fix one + two pointers (3Sum)O(n²)O(1) besides the output

Why the walks are linear: every iteration moves at least one pointer, and no pointer ever moves back, so the loop runs at most about n times in total. A nested loop over pairs checks n(n−1)/2 of them.

Common mistakes

  • while left < right versus while left <= right: with <= the pointers can meet on one element and pair it with itself. Choose the condition from what a single leftover element means in your problem.
  • Moving a pointer without a reason. Before writing left += 1, say why no pair using the old nums[left] can win; if you cannot, the move may skip the answer.
  • Sorting destroys the original indices. If the answer needs positions in the unsorted input, sort (value, index) pairs or use a hash map instead.
  • Infinite loops: every branch of the loop body must move at least one pointer.
  • Skipping duplicates by looking ahead (nums[i] == nums[i + 1]) instead of behind (nums[i] == nums[i - 1]) throws away answers that use a repeated value, such as [-1, -1, 2].

Python tips

  • left, right = 0, len(nums) - 1 and the swap nums[left], nums[right] = nums[right], nums[left] are the two idioms you will type most.
  • str.isalnum() and str.lower() handle the 'ignore punctuation and case' part of string problems.
  • nums.sort() sorts in place and returns None; sorted(nums) returns a new list. nums = nums.sort() is a classic bug.
  • s[::-1] reverses a string or list but makes a copy; two pointers compare in place.
