Greedy

Take the locally best choice when you can prove it never hurts.

Prerequisites: Heap / Priority Queue

What it is

A greedy algorithm builds an answer one decision at a time and never takes a decision back. At each step it takes the option that looks best right now and moves on. A cashier handing back change does this: give the largest coin that still fits, repeat. There is no table of alternatives and no backtracking, so a greedy solution is usually one loop, or one sort followed by one loop.

The catch is that "looks best right now" is only correct for some problems. A greedy choice is safe when it can never rule out a best final answer. Two properties make it so:

  • Greedy choice: some best overall solution contains your choice.
  • Optimal substructure: after you make the choice, what is left is a smaller version of the same problem, so the same rule can be applied again.

The usual way to check the first property is an exchange argument. In plain words: take any best solution that does not make your greedy choice, swap its first step for your greedy step, and show the result is still valid and no worse. If the swap always works, a best solution that starts with your choice exists, and the same argument covers the rest.

A worked example is picking the most meetings that do not overlap, with the rule "take the meeting that ends first". Call that meeting E and let OPT be any best schedule. OPT's first meeting ends no earlier than E does. Replace it with E: E ends no later, so it cannot collide with OPT's second meeting. The schedule is still valid and has the same size, so a best schedule starting with E exists. Now repeat on the meetings that start after E ends.

When the swap fails, the rule is wrong. Take Coin Change with coins [1, 3, 4] and amount 6. The rule "largest coin first" gives 4 + 1 + 1 (three coins). The best answer is 3 + 3 (two coins). Swapping its first coin for the greedy 4 leaves 2 to pay, which costs two more coins, so the swap makes it worse. This problem needs dynamic programming.

Greedy versus DP. Both need optimal substructure. DP tries every choice at each step and stores the best result for every sub-problem. Greedy commits to the one choice it can prove is safe, so it can drop the table.

Many greedy solutions are a DP whose table is only ever read at one cell. In Jump Game, "can I reach index i?" as a DP reads every earlier cell, but only the farthest reach matters, so the table shrinks to one number.

Five shapes cover almost every problem in this section:

  • Farthest reach: sweep once and remember the furthest point you can get to (Jump Game I and II, Partition Labels).
  • Running sum that resets: a total that has gone negative is dead weight, so start over (Maximum Subarray, Gas Station).
  • Sort or count, then sweep: the smallest remaining item has a forced role (Hand of Straights, interval problems).
  • Two-bound tracking: when one item is ambiguous, track the best and worst case together (Valid Parenthesis String).
  • Discard what can only hurt, then check coverage (Merge Triplets to Form Target Triplet).

In Python, greedy code is mostly a for loop with a few variables, max/min, sorted(..., key=...), Counter and heapq.

How to recognise it

  • The question asks for a yes/no answer, a minimum count (fewest jumps, groups, stops) or a maximum value, and at each step one option clearly dominates the others: the farthest reach, the earliest finish, the smallest card left.
  • The input is too big to try all combinations (10^4 to 10^5 items), and the problem suggests that one pass, or one sort plus one pass, is enough.
  • What you need to remember fits in one or two numbers: the farthest index I can reach, the best sum of a run ending here, the range of open brackets that is still possible.
  • A DP table comes to mind, but each cell would only read the best, farthest or smallest of the earlier cells, never a combination of them.
  • A running total or balance that goes negative means "the part so far is useless, start again from the next item" (Maximum Subarray, Gas Station).
  • Some item has a forced role: the smallest card left can only be the bottom of a group, and a letter's last occurrence is the earliest point where its part can end. When a choice is forced, there is nothing to search.

Farthest reach: can we get to the last index?

nums[i] is the longest jump allowed from index i. We never choose a jump. We sweep once and keep one number, farthest. Green cells under the blue bar are the indices we know we can reach.

Patterns and Python templates

Farthest reach

Use it when: you move over positions with jump lengths, or a block must stretch to cover everything inside it (Jump Game, Jump Game II, Partition Labels).

def can_reach_end(nums: list[int]) -> bool:
    """nums[i] is the longest jump from index i. Can we get from index 0 to the last index?"""
    farthest = 0                                  # highest index we know we can land on
    for i, jump in enumerate(nums):
        if i > farthest:                          # nothing lands on i: we are stuck before it
            return False
        farthest = max(farthest, i + jump)        # best landing spot reachable from i
    return True


def min_jumps(nums: list[int]) -> int:
    """Fewest jumps to the last index (it is guaranteed to be reachable)."""
    jumps = 0
    level_end = 0                                 # right edge of what `jumps` jumps can reach
    farthest = 0                                  # right edge of what `jumps + 1` jumps can reach
    for i in range(len(nums) - 1):                # never jump FROM the last index
        farthest = max(farthest, i + nums[i])
        if i == level_end:                        # we have scanned the whole level: jump now
            jumps += 1
            level_end = farthest
    return jumps

Every index up to farthest is reachable, because from any reachable index you may take a shorter jump. That is why one number summarises everything. Partition Labels is the same loop with end = max(end, last[c]) and a cut when i == end.

Running sum that resets

Use it when: the best answer is a stretch of the input and a bad prefix can be thrown away (Maximum Subarray, Gas Station).

def max_subarray(nums: list[int]) -> int:
    cur = best = nums[0]                          # cur = best sum of a run ENDING at the current index
    for x in nums[1:]:
        cur = max(x, cur + x)                     # extend the run, or restart if it is dead weight
        best = max(best, cur)
    return best


def start_station(gas: list[int], cost: list[int]) -> int:
    if sum(gas) < sum(cost):                      # not enough fuel in total: no start works
        return -1
    tank, start = 0, 0
    for i in range(len(gas)):
        tank += gas[i] - cost[i]                  # fill up at i, then drive to i + 1
        if tank < 0:                              # started at `start` and ran dry at i:
            start, tank = i + 1, 0                # every start in start..i fails too, so try i + 1
    return start

Keep two numbers: the running value that can reset, and a global one that does not (best in Kadane's algorithm, the sum(gas) >= sum(cost) check for the circuit).

Count or sort, then sweep with the forced choice

Use it when: the smallest or earliest remaining item must play a fixed role, so processing in order leaves no decision (Hand of Straights, interval scheduling).

from collections import Counter


def can_split_into_runs(cards: list[int], k: int) -> bool:
    """Can the cards be split into groups of k consecutive values?"""
    if len(cards) % k:
        return False
    count = Counter(cards)                        # value -> copies not used yet
    for first in sorted(count):                   # smallest value first
        copies = count[first]                     # nothing smaller is left, so this many groups START here
        if copies == 0:
            continue                              # already used up by earlier groups
        for value in range(first, first + k):
            if count[value] < copies:             # not enough cards to extend every group
                return False
            count[value] -= copies
    return True


def max_non_overlapping(meetings: list[tuple[int, int]]) -> int:
    """Most meetings with no overlap: always take the one that ENDS first."""
    taken, free_at = 0, float("-inf")
    for start, end in sorted(meetings, key=lambda m: m[1]):     # sort by END time
        if start >= free_at:                      # fits after the last meeting we took
            taken += 1
            free_at = end
    return taken

The sort key is the whole idea. Sorting these meetings by start time or by length gives wrong answers. When the pool changes as you go (new items appear, old ones expire), use a heap (heapq) instead of sorting once.

Two-bound tracking

Use it when: one item has several possible meanings, and instead of trying them all you track the lowest and highest value the state could have (Valid Parenthesis String).

def check_valid_string(s: str) -> bool:
    """s holds '(', ')' and '*'; a '*' may be '(', ')' or empty."""
    lo = hi = 0                                   # fewest / most '(' that could still be open
    for c in s:
        if c == "(":
            lo, hi = lo + 1, hi + 1
        elif c == ")":
            lo, hi = lo - 1, hi - 1
        else:                                     # '*': as ')' lowers, as '(' raises, as nothing keeps
            lo, hi = lo - 1, hi + 1
        if hi < 0:                                # even the best case has too many ')'
            return False
        lo = max(lo, 0)                           # an open count below 0 is not a real state
    return lo == 0                                # can we end with nothing open?

Every value between lo and hi stays possible, so two numbers describe all 3^k ways to read the wildcards.

Discard what can only hurt, then check coverage

Use it when: combining items can only move a value in one direction (max never goes down), so any item that overshoots the goal is useless (Merge Triplets to Form Target Triplet).

def can_build(triplets: list[list[int]], target: list[int]) -> bool:
    hit = [False, False, False]                   # which of the three target values some safe triplet reaches
    for t in triplets:
        if all(t[k] <= target[k] for k in range(3)):    # safe: merging it never overshoots
            for k in range(3):
                if t[k] == target[k]:
                    hit[k] = True
    return all(hit)

Merging all the safe items gives the best you can do in every position at once, so you never need to search for a good subset.

Complexity cheat-sheet

Greedy code is cheap to run; the cost that matters is the proof that it is correct.

If a solution sorts first, the sort dominates: a "linear" loop after an O(n log n) sort is still O(n log n) overall.

Common mistakes

  • Trusting a rule because it passes the examples. Try to break it with 3 to 5 element inputs, equal values, negatives and an all-bad input before you code it. Coins [1, 3, 4] with amount 6 breaks "largest coin first".
  • Being greedy about the wrong quantity. For non-overlapping meetings, earliest start and shortest length both fail and earliest end works. In Jump Game, choosing the farthest landing index fails while tracking the farthest reach (i + nums[i]) works.
  • Off-by-one at the boundary: stuck means i > farthest (standing exactly on farthest is fine), a part is closed when i == end, and an open-bracket count must be clamped at 0.
  • Resetting the running value and losing the global one. Gas Station resets tank but still needs the total fuel check, and Kadane's algorithm resets cur but must keep best.
  • Starting a maximum at 0 when every value can be negative: the best subarray of [-3, -1] is -1, not 0.

Python tips

  • max(farthest, i + jump) and min(...) express most greedy updates in one line. Keep the stuck-check, the update and the goal-check as separate lines so the loop reads in that order.
  • Counter(xs) returns 0 for a missing key without inserting it, so count[v + 1] < copies is safe. sorted(counter) returns a new list of the distinct keys, so you can change counts while looping over it.
  • sorted(items, key=lambda m: m[1]) sorts by one field. A tuple key such as (m[1], m[0]) breaks ties. When items arrive or expire while you work, heapq gives the smallest remaining item in O(log n).
  • sum(gas) < sum(cost), all(...) and any(...) replace flag variables, and enumerate replaces range(len(...)) when you need both the index and the value.
