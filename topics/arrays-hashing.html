Arrays & Hashing

Count, group and look things up in O(1) with sets and dictionaries.

Prerequisites: none

What it is

An array (a Python list) keeps items in numbered slots. Reading nums[i] is instant, but finding a value means checking the slots one by one. A hash map (dict) and a hash set (set) remove that search: a hash function turns each key into a slot number, so x in s, d[key] and s.add(x) take O(1) time on average, however many items are stored.

Think of a coat check. The attendant does not search the racks for your coat; your ticket says exactly which hook it is on. A dictionary key works like that ticket.

Most problems in this topic come down to one move: spend memory to save time. Instead of rescanning the list to answer "have I seen this value?", "how many of these are there?" or "where is this number's partner?", store the answer in a set or dictionary as you go and look it up in O(1). The array side of the topic is about precomputing running values (prefix sums and products) so each answer is one step away.

seen = set()                         # membership:  x in seen
count = {}                           # frequencies: count[x] = count.get(x, 0) + 1
index_of = {}                        # positions:   index_of[x] = i

How to recognise it

  • The statement asks whether something repeats, is unique, or was seen before: use a set.
  • The answer depends on how many times each value occurs (anagrams, most frequent, majority): count with a dict or Counter.
  • Every element has one specific partner to find, such as target - x or x + 1: store what you have seen and look the partner up instead of searching.
  • Items must be grouped by a shared property (same letters, same row, same remainder): a dict from a computed key to a list.
  • The required time is O(n), or the statement says "without sorting", where sorting would give O(n log n): hashing or counting into buckets.
  • Each position's answer combines everything to its left and everything to its right: prefix and suffix running values.

One pass with a dictionary: counting pairs that sum to a target

The dictionary plays both roles from this topic at once: it counts the values seen so far, and it answers "how many earlier values complete the current one?" in O(1), so no pair is ever checked explicitly.

Patterns and Python templates

Seen set: membership and duplicates

Use it when: you must know whether a value appeared earlier, or skip values you have already handled.

def has_duplicate(nums: list[int]) -> bool:
    seen = set()
    for x in nums:
        if x in seen:                    # O(1) on average
            return True
        seen.add(x)
    return False

Look up before you insert. Then a hit always refers to an earlier element, never to the current one.

Frequency count

Use it when: the answer depends on how often each value occurs: anagrams, top-k, majority, "appears exactly twice".

from collections import Counter

def frequencies(items) -> dict:
    count = {}
    for x in items:
        count[x] = count.get(x, 0) + 1   # same result as Counter(items)
    return count

def same_multiset(a, b) -> bool:         # e.g. anagram check
    return Counter(a) == Counter(b)

When counts are bounded by n, a list of buckets indexed by count (bucket sort) can replace sorting by frequency.

Complement lookup (Two Sum style)

Use it when: each element needs one specific partner and you want all the pairing done in a single pass.

def two_sum(nums: list[int], target: int) -> list[int]:
    index_of = {}                        # value -> index, for elements already visited
    for i, x in enumerate(nums):
        need = target - x
        if need in index_of:             # was the partner seen earlier?
            return [index_of[need], i]
        index_of[x] = i
    return []

Store data in the shape you will query it: the value you will search for is the key, the thing you want back is the value.

Group by signature

Use it when: equivalent items must end up together. Compute a key that all equivalent items share and nothing else has.

from collections import defaultdict

def group_by_signature(words: list[str]) -> list[list[str]]:
    groups = defaultdict(list)
    for w in words:
        key = "".join(sorted(w))         # any hashable value shared by equivalent items
        groups[key].append(w)
    return list(groups.values())

Keys must be hashable: strings, numbers and tuples work; convert a list with tuple(...).

Prefix and suffix running values

Use it when: each position needs the sum, product or maximum of everything before it, after it, or both.

def product_except_self(nums: list[int]) -> list[int]:
    n = len(nums)
    out = [1] * n
    left = 1
    for i in range(n):                   # out[i] = product of nums[:i]
        out[i] = left
        left *= nums[i]
    right = 1
    for i in range(n - 1, -1, -1):       # times the product of nums[i+1:]
        out[i] *= right
        right *= nums[i]
    return out

Use the running value first and fold in nums[i] afterwards, so position i is excluded. Prefix sums have the same shape: prefix[i + 1] = prefix[i] + nums[i].

"Average O(1)" assumes the keys spread evenly over the slots. If many keys collide, a single lookup can degrade to O(n); Python's hashing makes that rare, and interviews treat hash operations as O(1). A set or dict holding n items uses O(n) memory: that is the price of the fast lookups.

Common mistakes

  • x in some_list inside a loop costs O(n) per check and quietly turns an O(n) idea into O(n²). Use a set for membership.
  • Lists, dicts and sets cannot be dictionary keys or set members (TypeError: unhashable type). Use tuples, frozenset or strings.
  • [[]] * n and [set()] * n repeat one object n times, so changing one slot changes them all. Build independent containers with [[] for _ in range(n)].
  • Adding or removing keys while looping over a dict or set raises RuntimeError. Loop over a copy (for k in list(d)) or collect the changes first.
  • Sets have no meaningful order (dicts keep insertion order). Sort explicitly whenever the output order matters.

Python tips

  • collections.Counter(items) counts in one call; most_common(k) returns the k most frequent (value, count) pairs.
  • defaultdict(list) and defaultdict(int) create the default value on first access, so groups[key].append(x) needs no existence check.
  • d.get(k, 0) reads with a default instead of raising KeyError; enumerate(nums) yields (index, value) pairs.
  • set(nums) removes duplicates in O(n), and len(set(nums)) < len(nums) tests for duplicates in one line.
