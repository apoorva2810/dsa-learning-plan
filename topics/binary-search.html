Binary Search

Halve the search space every step: sorted data, or any monotonic answer.

Prerequisites: Two Pointers

What it is

Binary search finds something in a sorted range by looking at the middle and throwing away the half that cannot contain the answer. Every look halves what is left, so a million items need about 20 looks (2^20 ≈ 10^6). That is what O(log n) means: the work grows by one step each time the input doubles.

The everyday version is the number-guessing game. Someone picks a number from 1 to 100 and only answers "higher" or "lower". You guess 50, then 25 or 75, and so on; 7 guesses always suffice.

The real requirement is not "a sorted list" but a monotonic yes/no question: one whose answers switch only once along the range (no, no, no, yes, yes). In a sorted list, "is nums[i] >= target?" is such a question. So is "can Koko eat all the bananas at speed k?" over the range of possible speeds. Searching a range of candidate answers like that is called binary search on the answer, and it solves many problems that do not look like searching at all.

In Python you keep two indices lo and hi, compute mid = (lo + hi) // 2, and move one of them past mid. The standard library's bisect module does the sorted-list version for you.

How to recognise it

  • The input is sorted (or sorted and then rotated) and you need a position, a first or last occurrence, or an insert position.
  • The required complexity is O(log n), or a value range is so large (up to 10^9) that even trying every value is too slow.
  • The question asks for the minimum or maximum value that satisfies a condition: smallest speed, least capacity, largest gap. That is binary search on the answer.
  • Checking whether one candidate answer works is easy, but computing the answer directly is hard.
  • Lookups like "the latest record at or before time t" on data that arrives in time order.
  • A 2-D grid whose rows chain into one sorted sequence: treat it as one long sorted list.

Watch lo, hi and mid close in

Two searches in a sorted list (one hit, one miss), then the same halving on a range of candidate answers where nothing is stored at all.

Patterns and Python templates

Exact match in a sorted list

Use it when: find the index of a value, or report that it is missing.

def binary_search(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1             # if target is present, it is inside nums[lo..hi]
    while lo <= hi:                       # the range is empty once lo passes hi
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1                  # target is right of mid
        else:
            hi = mid - 1                  # target is left of mid
    return -1                             # here lo is where target would be inserted

Both ends move past mid, so the range shrinks every round and the loop always ends.

First position where a condition holds (lower bound)

Use it when: first element >= x, first occurrence of a duplicate, insert position. Same result as bisect.bisect_left.

def lower_bound(nums: list[int], target: int) -> int:
    """Index of the first element >= target, or len(nums) if there is none."""
    lo, hi = 0, len(nums)                 # the answer is somewhere in lo..hi (hi = "past the end")
    while lo < hi:                        # stop when one candidate is left
        mid = (lo + hi) // 2
        if nums[mid] >= target:
            hi = mid                      # mid qualifies: the answer is mid or left of it
        else:
            lo = mid + 1                  # mid is too small: the answer is right of it
    return lo                             # lo == hi

hi = mid, not mid - 1, because mid itself may be the answer. For "last element <= x" use the first element > x, minus one.

Binary search on the answer

Use it when: minimise (or maximise) a value subject to a yes/no check that stays true once it becomes true.

def smallest_that_works(lo: int, hi: int, works) -> int:
    """Smallest value v in [lo, hi] with works(v) True.
    Needs: works(hi) is True, and works(v) True implies works(v + 1) True."""
    while lo < hi:
        mid = (lo + hi) // 2
        if works(mid):
            hi = mid                      # mid is good enough; try smaller
        else:
            lo = mid + 1                  # mid fails, and so does everything below it
    return lo

# Koko: slowest eating speed that finishes in h hours
# smallest_that_works(1, max(piles), lambda k: sum((p + k - 1) // k for p in piles) <= h)

Choose lo and hi so the answer is surely inside. To find the largest value that works, set lo = mid on success and round the middle up, mid = (lo + hi + 1) // 2, or the loop can stall.

Rotated sorted array: one half is always sorted

Use it when: the list was sorted, then rotated at an unknown point.

def search_rotated(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[lo] <= nums[mid]:             # left half lo..mid is sorted
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1                  # target lies in the sorted left half
            else:
                lo = mid + 1
        else:                                 # right half mid..hi is sorted
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1                  # target lies in the sorted right half
            else:
                hi = mid - 1
    return -1

You can only test "is the target in this half?" on a sorted half, so find the sorted one first.

Let `bisect` do it

Use it when: any sorted Python list: membership, counts in a range, latest value at or before a time.

import bisect

times = [1, 4, 4, 9]
bisect.bisect_left(times, 4)        # 1: first index with times[i] >= 4
bisect.bisect_right(times, 4)       # 3: first index with times[i] > 4
bisect.bisect_right(times, 5) - 1   # 2: last index with times[i] <= 5 (-1 means none)
bisect.bisect_right(times, 4) - bisect.bisect_left(times, 4)   # 2: how many 4s
bisect.insort(times, 6)             # insert and keep the list sorted (O(n): elements shift)

Complexity cheat-sheet

TaskCost
Search a sorted list of n itemsO(log n)
bisect.bisect_left / bisect.bisect_rightO(log n)
bisect.insort or list.insert into a sorted listO(n): shifting the elements dominates
Search an m × n matrix whose rows chain into one sorted listO(log(m·n))
Binary search on the answer: range of size R, each check costs CO(C · log R)
Sort first, then binary searchO(n log n) once; worth it when you search many times

log₂ of a billion is about 30, so even a range of 10^9 candidate answers needs only ~30 checks.

Common mistakes

  • Mixing templates: while lo <= hi goes with lo = mid + 1 / hi = mid - 1; while lo < hi goes with hi = mid. Mixing them either skips the answer or loops forever.
  • An update that does not move: lo = mid with mid = (lo + hi) // 2 never changes lo when hi = lo + 1, so the loop never ends. Round the middle up when you assign lo = mid.
  • Binary search needs a monotonic condition. If the yes/no answers flip more than once along the range, discarding a half can throw the answer away.
  • Bounds that do not contain the answer: make sure hi always works and lo is a legal value (a speed of 0 divides by zero).
  • Python's negative indices: nums[mid - 1] with mid == 0 silently reads the last element. Guard the edges explicitly.

Python tips

  • bisect.bisect_left(a, x) is the lower-bound template; bisect.bisect_right(a, x) - 1 is the index of the last element <= x.
  • Since Python 3.10, bisect accepts key=. bisect_left(range(1, hi + 1), True, key=works) binary-searches a lazy range of candidate answers without building a list.
  • Python integers never overflow, so (lo + hi) // 2 is safe. In Java or C++ write lo + (hi - lo) / 2.
  • Integer ceiling division: (a + b - 1) // b or -(-a // b). It avoids float rounding in math.ceil(a / b) for huge values.
