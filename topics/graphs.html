Graphs

BFS, DFS, topological sort and union-find on grids and adjacency lists.

Prerequisites: Backtracking

What it is

A graph is a set of nodes (also called vertices) joined by edges. Cities joined by roads, people joined by friendships, courses joined by "take this one first" rules: all graphs. An edge can be undirected (a road you can drive both ways) or directed (a one-way street, a prerequisite), and it can carry a weight (a distance, a cost).

Problems rarely hand you a graph object. You build one of two pictures yourself:

  • Adjacency list: for every node, the list of its neighbours. In Python a dict of lists, filled from the edge list: graph[a].append(b), plus graph[b].append(a) when the edge is undirected. Memory is O(V + E) for V nodes and E edges.
  • Grid as an implicit graph: every cell (r, c) is a node, and its neighbours are the cells directly up, down, left and right. You never store the edges; you generate them on the fly from four direction offsets.

Almost every solution is then a traversal: visit everything reachable from a start.

  • DFS (depth-first search) follows one path as deep as it can, then backs up and tries the next branch. Recursion or an explicit stack. Use it to explore a whole region, to ask "is there any path?", to detect cycles and to order tasks.
  • BFS (breadth-first search) uses a queue and visits nodes in rings: everything 1 step away, then 2 steps, and so on. When every edge costs the same, BFS reaches each node first along a shortest route, so it answers "fewest steps" and "how many minutes".

Both need a visited set. Graphs have cycles (A → B → A), and without remembering where you have been a search would loop forever or count the same region twice.

Two more tools complete the kit. Topological sort lists the nodes of a directed graph so every edge points forward (take prerequisites before the courses that need them). Union-find (also called a disjoint set) keeps track of which nodes are already connected while edges arrive one at a time, and spots the edge that would close a cycle.

How to recognise it

  • A 2-D grid where you move up, down, left or right and the question is about regions, islands, flooding or spreading: the grid is a graph, each cell a node.
  • Fewest moves, steps, minutes or transformations, where every move costs the same: BFS.
  • Pairs like [a, b] meaning 'b must come before a', or the words prerequisite, order, schedule, dependency: a directed graph and a topological sort.
  • Count the groups, components or provinces, or ask whether two things are connected: start a DFS/BFS from every unvisited node, or use union-find.
  • Is there a cycle? Is this a valid tree? Which edge is extra? DFS colouring for directed graphs, union-find for undirected ones.
  • Several starting points spread at the same time (rot, fire, gates, oceans): multi-source BFS, or a search that starts at the border and works inward.

BFS flood fill: the search spreads in rings

Start from one open cell and explore with a queue. Each reached cell shows how many steps it is from the start; walls (#) block the way. Every cell is reached first along a shortest route.

Patterns and Python templates

Build the graph: adjacency list, or a grid's neighbours

Use it when: the input is an edge list ([[a, b], ...]) or a 2-D grid, and you need to ask 'who are my neighbours?' fast.

def build_graph(n: int, edges: list[list[int]], directed: bool = False) -> dict[int, list[int]]:
    graph = {node: [] for node in range(n)}       # every node gets a list, even with no edges
    for a, b in edges:
        graph[a].append(b)
        if not directed:
            graph[b].append(a)                    # an undirected edge works both ways
    return graph


DIRS = ((1, 0), (-1, 0), (0, 1), (0, -1))         # down, up, right, left


def grid_neighbours(grid: list[list[int]], r: int, c: int):
    rows, cols = len(grid), len(grid[0])
    for dr, dc in DIRS:
        nr, nc = r + dr, c + dc
        if 0 <= nr < rows and 0 <= nc < cols:     # bounds first: grid[-1] would silently wrap around
            yield nr, nc

Creating an entry for every node up front means isolated nodes still show up when you loop over graph. For a grid you never build anything: the four offsets are the edges.

DFS flood fill: explore a region, count components

Use it when: you need everything connected to a start (an island, a region, a component), or the number of such groups.

def count_regions(grid: list[list[str]]) -> int:
    rows, cols = len(grid), len(grid[0])
    visited = set()

    def dfs(r: int, c: int) -> None:
        if not (0 <= r < rows and 0 <= c < cols):         # off the grid
            return
        if grid[r][c] != "1" or (r, c) in visited:         # wrong kind of cell, or already seen
            return
        visited.add((r, c))                                # mark BEFORE recursing, so no cell is entered twice
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            dfs(r + dr, c + dc)

    regions = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "1" and (r, c) not in visited:
                regions += 1                               # an unvisited start = a brand-new component
                dfs(r, c)                                  # mark the whole component
    return regions

The same shape works on an adjacency list: loop over every node and call dfs(node) on each unvisited one. When a region can be huge, swap recursion for an explicit stack (stack.append, stack.pop()): Python stops at about 1000 nested calls by default.

BFS: fewest steps from one source or many

Use it when: shortest path / fewest moves with equal-cost steps; spreading from several sources at once (multi-source BFS).

from collections import deque


def bfs_distances(grid: list[list[int]], sources: list[tuple[int, int]]) -> dict[tuple[int, int], int]:
    """Steps from the NEAREST source to every reachable open cell (0 = open, 1 = wall)."""
    rows, cols = len(grid), len(grid[0])
    dist = {s: 0 for s in sources}                # doubles as the visited set
    queue = deque(sources)                        # many sources = they all start at distance 0 together
    while queue:
        r, c = queue.popleft()
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 0 and (nr, nc) not in dist:
                dist[(nr, nc)] = dist[(r, c)] + 1     # mark when you ENQUEUE, not when you pop
                queue.append((nr, nc))
    return dist

When the answer is a number of rounds (minutes, levels), process the queue one level at a time with for _ in range(len(queue)): and count the rounds.

Topological sort: Kahn's algorithm, or DFS with three colours

Use it when: a directed graph of dependencies: produce a valid order, or decide that none exists because of a cycle.

from collections import deque


def topo_kahn(n: int, edges: list[list[int]]) -> list[int]:
    """edges [a, b] mean a must come before b. Returns an order, or [] if there is a cycle."""
    graph = {i: [] for i in range(n)}
    indegree = [0] * n                            # unmet prerequisites per node
    for a, b in edges:
        graph[a].append(b)
        indegree[b] += 1
    queue = deque(i for i in range(n) if indegree[i] == 0)   # nodes that are free right now
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in graph[node]:
            indegree[nxt] -= 1                    # one prerequisite of nxt is done
            if indegree[nxt] == 0:
                queue.append(nxt)
    return order if len(order) == n else []       # nodes never freed sit on a cycle


def topo_dfs(n: int, edges: list[list[int]]) -> list[int]:
    graph = {i: [] for i in range(n)}
    for a, b in edges:
        graph[a].append(b)
    WHITE, GREY, BLACK = 0, 1, 2                  # unvisited / on the current path / finished
    colour = [WHITE] * n
    order = []

    def dfs(node: int) -> bool:                   # returns False if it finds a cycle
        colour[node] = GREY
        for nxt in graph[node]:
            if colour[nxt] == GREY:               # back to a node on the current path: a cycle
                return False
            if colour[nxt] == WHITE and not dfs(nxt):
                return False
        colour[node] = BLACK
        order.append(node)                        # everything after node is already placed
        return True

    for node in range(n):
        if colour[node] == WHITE and not dfs(node):
            return []
    return order[::-1]                            # reverse finishing order = topological order

A node's in-degree is the number of edges pointing into it (its unmet prerequisites). Kahn's version is iterative, and any node whose in-degree never reaches 0 is stuck on a cycle. The DFS version needs three colours: meeting a BLACK (finished) node again is harmless, only meeting a GREY one means you walked in a circle.

Union-find with path compression

Use it when: edges arrive one by one and you keep asking 'are these two already connected?', count groups, or find the edge that closes a cycle in an undirected graph.

class UnionFind:
    def __init__(self, n: int):
        self.parent = list(range(n))              # every node starts as its own group
        self.size = [1] * n
        self.groups = n

    def find(self, x: int) -> int:
        root = x
        while self.parent[root] != root:          # climb to the group's representative
            root = self.parent[root]
        while self.parent[x] != root:             # path compression: point every node on the way at the root
            nxt = self.parent[x]
            self.parent[x] = root
            x = nxt
        return root

    def union(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                          # already connected: this edge would close a cycle
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra                      # union by size: hang the smaller tree under the bigger one
        self.size[ra] += self.size[rb]
        self.groups -= 1
        return True

With path compression and union by size, each operation is amortised nearly O(1): averaged over many calls the cost per call is O(α(n)), and α (the inverse Ackermann function) is below 5 for any input that fits in a computer.

Complexity cheat-sheet

TaskTimeExtra space
Build an adjacency listO(V + E)O(V + E)
DFS or BFS over an adjacency listO(V + E)O(V): visited set + stack/queue
DFS or BFS over an R × C gridO(R · C)O(R · C)
Topological sort (Kahn or DFS)O(V + E)O(V + E)
Union-find, m operations on n nodesO(m · α(n)), effectively O(m)O(n)
Adjacency matrix instead of a listO(V²) to buildO(V²); edge test is O(1)

Each node is visited once and each edge is looked at once (twice if undirected), which is where V + E comes from. A recursive DFS also uses the call stack: as deep as the longest path it follows, up to V (or R · C) frames.

Common mistakes

  • Marking a node visited when you pop it instead of when you push it. In BFS the same node can then sit in the queue several times; mark it the moment it is queued.
  • Negative indices do not raise in Python: grid[r - 1][c] with r = 0 quietly reads the last row. Check 0 <= r < rows and 0 <= c < cols before you index.
  • Starting one search from node 0 and stopping. Graphs can be disconnected: loop over every node (or cell) and start a new search from each one that is still unvisited.
  • Detecting a cycle in a directed graph with a plain visited set. Reaching a node that is already finished is fine; only reaching a node on the current path is a cycle. Use three colours, or Kahn's leftover count.
  • Deep recursion: a 300 × 300 grid can need 90,000 nested calls, far past Python's default limit of 1000. Use BFS or an explicit stack when a region can be large.

Python tips

  • collections.deque is the BFS queue: append at the back and popleft() at the front are both O(1). list.pop(0) is O(n).
  • Store cells as tuples (r, c): tuples are hashable, so they can live in a set or be dictionary keys. Lists cannot.
  • DIRS = ((1, 0), (-1, 0), (0, 1), (0, -1)) with for dr, dc in DIRS: keeps the four neighbour moves in one place.
  • {i: [] for i in range(n)} or defaultdict(list) builds an adjacency list; the dict comprehension also lists nodes that have no edges.
