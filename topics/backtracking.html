Backtracking

Build candidates step by step and undo when a path cannot work.

Prerequisites: Trees

What it is

Backtracking builds an answer one decision at a time. You choose an option, explore everything that can follow from it, then un-choose it (undo it) and try the next option. The undo is where the name comes from: you walk back to the last junction and take a different turning.

Picture a maze and a ball of string. At every junction you pick a corridor and unroll string behind you. At a dead end you wind the string back to the last junction and try another corridor. The string always shows exactly where you are. In code the string is the partial answer, usually a list called path.

All possible partial answers form a tree, often called the decision tree. The root is the empty answer, every node is a partial answer, and the children of a node are the ways to extend it by one more choice. Backtracking is a depth-first walk of that tree, and the recursion's call stack remembers the route from the root to where you are now.

Two facts decide whether the technique is practical:

  • The tree is huge: 2ⁿ subsets, n! orderings. That is why these problems come with tiny limits such as n <= 10, and why seeing such a limit is itself a hint.
  • Pruning means cutting off a branch the moment you can tell it cannot lead to a valid answer (the running sum is already over the target, two queens attack each other). A pruned branch removes its whole subtree from the work.

In Python the skeleton is a nested function that appends to a shared path, and stores a copy of path in result whenever it holds a complete answer.

How to recognise it

  • The task says all, every, list or generate: subsets, permutations, combinations, partitions, placements. The output is a list of answers, not one number.
  • The input is tiny (n <= 10, n <= 20, a 6 x 6 board). That is the problem setter telling you that an exponential search is expected.
  • The answer is built from a sequence of small choices (take or skip an item, pick a letter for the next digit, place a queen in the next row, cut a string here) and some choices must be rejected (sum too big, two queens attack, cell already used).
  • Whether order matters decides the template: a combination or subset ignores order (use a start index), a permutation does not (any unused element can come next).
  • The input has repeated values but the answer must not repeat itself: sort, then skip a repeat at the same depth.
  • The question is does a path exist on a grid or board where a cell cannot be reused: the same skeleton, with mark and unmark, returning True as soon as one path is found.

Choose, explore, un-choose on the subsets of [1, 2, 3]

Each call stores its path, then tries every later element: choose it (append), explore (recurse), un-choose it (pop). Watch path grow on the way down and shrink on the way back while result collects copies.

Patterns and Python templates

Choose, explore, un-choose (the skeleton)

Use it when: any 'list all ...' problem. Start from this shape and change only three things: when a path counts as an answer, which candidates the loop offers, and the start passed to the next call.

def subsets(nums: list[int]) -> list[list[int]]:
    result = []
    path = []                                # the partial answer, shared by every call

    def backtrack(start: int) -> None:
        result.append(path[:])               # every path is a subset: store a COPY, path keeps changing
        for i in range(start, len(nums)):    # candidates: the elements at or after `start`
            path.append(nums[i])             # choose
            backtrack(i + 1)                 # explore (i + 1: never look back, so no subset repeats)
            path.pop()                       # un-choose: restore the state for the next candidate

    backtrack(0)
    return result

The loop does not have to run over array elements. The same three beats work over cut positions (Palindrome Partitioning), the letters of a digit (Letter Combinations) or the columns of a row (N-Queens).

Combinations: a `start` index, with or without reuse

Use it when: you pick items and order does not matter ([2, 3] and [3, 2] are the same answer), usually with a target sum or a fixed size.

def combination_sum(candidates: list[int], target: int) -> list[list[int]]:
    candidates = sorted(candidates)          # sorted, so one failing candidate rules out all later ones
    result, path = [], []

    def backtrack(start: int, remaining: int) -> None:
        if remaining == 0:                   # the path adds up to the target
            result.append(path[:])
            return
        for i in range(start, len(candidates)):
            if candidates[i] > remaining:    # prune: this and every later candidate is too big
                break
            path.append(candidates[i])
            backtrack(i, remaining - candidates[i])   # i, not i + 1: the same number may be used again
            path.pop()

    backtrack(0, target)
    return result

The start index is what makes [2, 3] and [3, 2] one answer: later calls may only look at positions at or after start. Pass i + 1 when each element may be used once (subsets, Combination Sum II) and i when it may repeat (Combination Sum). break is only valid on sorted input; on unsorted input use continue.

Permutations: any unused element goes next

Use it when: order matters, so two arrangements of the same items are different answers.

def permutations(nums: list[int]) -> list[list[int]]:
    result, path = [], []
    used = [False] * len(nums)               # used[i]: is nums[i] already in path?

    def backtrack() -> None:
        if len(path) == len(nums):           # every position is filled
            result.append(path[:])
            return
        for i in range(len(nums)):           # any element may fill the next position ...
            if used[i]:                      # ... unless it is already placed
                continue
            used[i] = True                   # choose: two things change, path and used
            path.append(nums[i])
            backtrack()                      # explore
            path.pop()                       # un-choose: undo BOTH
            used[i] = False

    backtrack()
    return result

There is no start here: the loop always begins at 0 and used takes over the job of 'what is still available'. A choice that changes two pieces of state must undo both.

Duplicates in the input: sort, then skip repeats at the same depth

Use it when: the input contains repeated values, but the answer must not list the same subset or combination twice.

def subsets_with_dup(nums: list[int]) -> list[list[int]]:
    nums = sorted(nums)                      # equal values become neighbours
    result, path = [], []

    def backtrack(start: int) -> None:
        result.append(path[:])
        for i in range(start, len(nums)):
            if i > start and nums[i] == nums[i - 1]:   # same value already tried at THIS position of the path
                continue
            path.append(nums[i])
            backtrack(i + 1)
            path.pop()

    backtrack(0)
    return result

i > start is the whole trick. A repeated value is allowed one level deeper (where i == start), so [2, 2] is still produced, but a second sibling with the same value in the same loop would only recreate answers the first sibling already made. The test i > 0 is the classic bug: it also blocks the legitimate deeper repeat.

Find one answer: mark, recurse, unmark, return early

Use it when: the question is does a path exist (Word Search), or a choice uses a shared resource that must be released afterwards (board cells; columns and diagonals in N-Queens).

def exists(board: list[list[str]], word: str) -> bool:
    rows, cols = len(board), len(board[0])

    def dfs(r: int, c: int, k: int) -> bool:      # k letters of `word` are matched so far
        if k == len(word):
            return True                           # found one: stop the whole search
        if not (0 <= r < rows and 0 <= c < cols) or board[r][c] != word[k]:
            return False                          # prune: off the board, or the wrong letter
        saved, board[r][c] = board[r][c], "#"     # choose: mark the cell so the path cannot reuse it
        found = (dfs(r + 1, c, k + 1) or dfs(r - 1, c, k + 1)
                 or dfs(r, c + 1, k + 1) or dfs(r, c - 1, k + 1))   # explore (stops at the first True)
        board[r][c] = saved                       # un-choose: put the letter back
        return found

    return any(dfs(r, c, 0) for r in range(rows) for c in range(cols))

Returning a boolean lets or stop the search at the first success. The unmark must still run on the way out, otherwise a failed branch leaves cells blocked for the next start cell. N-Queens follows the same shape with three sets (cols, diag1, diag2) that are added to before the recursive call and removed from after it.

Complexity cheat-sheet

Problem shapeComplete answersTimeExtra space
All subsets of n items2ⁿO(n · 2ⁿ)O(n)
All permutations of n itemsn!O(n · n!)O(n)
Combinations: k of n itemsC(n, k)O(k · C(n, k))O(k)
Combination Sum (target t, smallest candidate m)depends on the dataO(n^(t/m)) worst caseO(t/m)
N-Queens on an n × n boardheavily pruned, at most n!roughly O(n!)O(n)
Word Search (word of length L, board m × n)at most 3 new directions per stepO(m · n · 3^L)O(L)

The factor n (or k) in the time column is the cost of copying each finished path into result. Extra space counts the recursion depth and path, not the output. The real cost is the number of nodes in the decision tree, which is why pruning matters: it removes nodes, not just answers.

How fast the tree grows: n = 10 gives 1,024 subsets or 3,628,800 permutations. n = 20 gives 1,048,576 subsets or about 2.4 × 10¹⁸ permutations. Hence the small limits.

Common mistakes

  • Storing result.append(path) instead of a copy (path[:]). Every entry is the same list object, and it is empty once the recursion has unwound.
  • Forgetting to un-choose, or undoing only part of the state. If a choice changes path and also used, a visited set or a running sum kept outside the call, every one of them must be restored after the recursive call.
  • Using i > 0 instead of i > start when skipping duplicates. It silently drops answers such as [2, 2] that need the same value twice at different depths.
  • Pruning too late. Checking a bound after the recursive call still pays for the call; check it before you recurse. And break is only correct on sorted candidates; on unsorted ones it drops answers (use continue).
  • Mixing the two state styles. Either mutate one shared list and undo it, or pass a fresh list down (backtrack(path + [x])) and skip the undo. Doing both, or neither, corrupts the path.

Python tips

  • path[:], path.copy() and list(path) each make a shallow copy. tuple(path) makes a hashable one that can go into a set to remove duplicates.
  • A nested function can call result.append(...) and path.append(...) without nonlocal, because that mutates an object it can read. Rebinding a number (count += 1) does need nonlocal count.
  • itertools.permutations, combinations, combinations_with_replacement and product generate the same families. They are handy for writing a brute-force checker for your own backtracking code.
  • The recursion is as deep as path is long, so for the input sizes these problems allow it stays far below Python's default limit of 1000 frames.
