Stack

Last-in-first-out: match brackets, track 'previous smaller', undo work.

Prerequisites: Arrays & Hashing

What it is

A stack is a list where you only ever touch one end: you push (add) on top and pop (remove) from the top. The last thing in is the first thing out (LIFO). Think of a stack of plates: you add to the top and take from the top.

In Python a plain list is a stack: append pushes, pop() pops, stack[-1] peeks. All three are O(1).

Stacks show up whenever the problem has "most recent first" logic: matching brackets (the last opened must close first), undo buttons, function calls (the last called returns first), and the big family of monotonic stack problems where you want, for each element, the nearest element to its left or right that is bigger or smaller.

How to recognise it

  • Words like nested, balanced, matching, most recent, undo, backtrack one step.
  • You need, for every element, the next greater / next smaller element to the left or right (daily temperatures, histogram).
  • You are evaluating an expression written in postfix (Reverse Polish) or with parentheses.
  • Simulation where items 'wait' and are processed only when something later arrives (car fleet, asteroid collision).
  • You would naturally write recursion but want to control the call stack yourself (iterative DFS).

A monotonic stack finding the next warmer day

Temperatures arrive left to right. Indices wait on the stack until a warmer day pops them, at which point we know their answer.

Patterns and Python templates

Matching pairs

Use it when: brackets, tags, or any open/close structure must nest correctly.

def is_balanced(s: str) -> bool:
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for c in s:
        if c in pairs:                        # closer: must match the top
            if not stack or stack[-1] != pairs[c]:
                return False
            stack.pop()
        else:                                 # opener
            stack.append(c)
    return not stack

Push openers, pop on a matching closer, require an empty stack at the end.

Monotonic stack (next greater element)

Use it when: for each index you need the nearest later (or earlier) element that is larger/smaller, in O(n) total.

def next_greater_index(nums: list[int]) -> list[int]:
    """res[i] = index of the first element to the right of i that is bigger, or -1."""
    res = [-1] * len(nums)
    stack = []                                # indices whose 'next greater' is still unknown; values decreasing
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:  # x is the answer for everyone smaller on the stack
            res[stack.pop()] = i
        stack.append(i)
    return res

Each index is pushed once and popped at most once, so the whole loop is O(n) despite the inner while. Flip the comparison for 'next smaller'; scan right-to-left for 'previous'.

Evaluate postfix / simulate with operands

Use it when: tokens arrive in an order where operators apply to the most recent operands.

def eval_rpn(tokens: list[str]) -> int:
    stack = []
    for tok in tokens:
        if tok in "+-*/":
            b, a = stack.pop(), stack.pop()   # note the order: a came first
            if tok == "+": stack.append(a + b)
            elif tok == "-": stack.append(a - b)
            elif tok == "*": stack.append(a * b)
            else: stack.append(int(a / b))    # truncate toward zero
        else:
            stack.append(int(tok))
    return stack[0]

Iterative DFS with an explicit stack

Use it when: recursion would be too deep, or you want to pause/resume the traversal.

def dfs(root):
    stack = [root] if root else []
    while stack:
        node = stack.pop()
        visit(node)
        if node.right: stack.append(node.right)   # push right first so left is processed first
        if node.left: stack.append(node.left)

Common mistakes

  • Peeking or popping an empty list raises IndexError; always guard with if stack / while stack and ....
  • In monotonic stacks, decide early whether you store indices or values. Indices let you compute distances and look up values; values alone usually cannot.
  • Strict vs non-strict comparisons (< vs <=) change how duplicates are handled. Test with repeated values.
  • Forgetting the end-of-input flush: elements still on the stack after the loop often need a default answer (e.g. -1 or 0).

Python tips

  • stack[-1] is peek; stack[-2] is the one below it, handy for RPN-style problems.
  • while stack and stack[-1] < x: is the idiom: the emptiness check must come first.
  • Pushing tuples (value, extra) keeps related data together, e.g. (height, start_index) in histogram problems.
