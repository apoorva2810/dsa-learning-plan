Trees

Recursion on binary trees: depth, paths, BST properties, traversals.

Prerequisites: Binary Search, Linked List

What it is

A binary tree is a set of nodes where each node holds a value and up to two children, left and right. One node, the root, has no parent; nodes with no children are leaves. A family tree drawn top-down, with at most two children per person, is the picture to keep in mind.

The one idea behind almost every tree problem: a subtree is itself a tree. Whatever question you ask about the whole tree (how deep is it? is it balanced? what is the sum of its paths?) you can ask about each child subtree, combine the two answers, and return the result upward. That is recursion, and Python's call stack does the bookkeeping for you.

A binary search tree (BST) adds an ordering rule: everything in the left subtree is smaller than the node, everything in the right subtree is larger. That rule lets you throw away half the tree at every step, the same way binary search throws away half an array, and it means an inorder traversal (left, node, right) visits the values in sorted order.

In Python a node is a tiny class: TreeNode(val, left, right). An empty tree is None.

How to recognise it

  • The input is a TreeNode (or the problem builds one), or the data has a natural parent/child hierarchy.
  • Words like depth, height, ancestor, leaf, subtree, path from root, level.
  • You need every value in sorted order and the data is a BST: inorder traversal.
  • You need to process nodes layer by layer (left to right at each depth): BFS with a queue.
  • The answer at a node depends only on answers from its children: write a recursive helper that returns information upward.
  • You need to pass constraints down (allowed value range, current path sum): add parameters to the recursive helper.

Three ways to walk the same tree

Preorder (node, left, right), inorder (left, node, right) and postorder (left, right, node) visit the same nodes in different orders. On a BST, inorder gives sorted output.

Patterns and Python templates

Return information upward (post-order)

Use it when: the result for a node is computed from the results of its two subtrees: depth, balance, diameter, max path sum, 'is this a valid subtree'.

def depth(node: Optional[TreeNode]) -> int:
    if node is None:                 # base case: the empty tree
        return 0
    left = depth(node.left)          # ask the children first ...
    right = depth(node.right)
    return 1 + max(left, right)      # ... then combine for this node

Visit children before the node itself. When you also need a global answer (diameter, max path sum), update a variable in the enclosing scope (self.best or nonlocal best) at every node and return only what the parent needs.

Pass constraints downward (pre-order)

Use it when: validity depends on the ancestors: BST bounds, 'good nodes' (no bigger ancestor), path sums that must hit a target.

def valid(node: Optional[TreeNode], lo: float, hi: float) -> bool:
    if node is None:
        return True
    if not (lo < node.val < hi):      # this node must sit inside the range its ancestors allow
        return False
    return valid(node.left, lo, node.val) and valid(node.right, node.val, hi)

# call: valid(root, float("-inf"), float("inf"))

The parameters carry everything the node is allowed to know about its ancestors. Tighten them on the way down.

Level-order traversal (BFS)

Use it when: anything phrased per level: level order lists, right side view, zigzag, minimum depth, 'connect nodes at the same level'.

def level_order(root: Optional[TreeNode]) -> List[List[int]]:
    if root is None:
        return []
    result, queue = [], deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):          # exactly the nodes of the current level
            node = queue.popleft()
            level.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        result.append(level)
    return result

for _ in range(len(queue)) freezes the level size before you start appending children; that is what separates levels.

Iterative inorder with a stack

Use it when: you need sorted order from a BST without recursion, or you want to stop early (k-th smallest).

def inorder(root: Optional[TreeNode]) -> Iterator[int]:
    stack, node = [], root
    while stack or node:
        while node:                   # go as far left as possible, remembering the way
            stack.append(node)
            node = node.left
        node = stack.pop()            # the next smallest value
        yield node.val
        node = node.right             # then handle its right subtree the same way

BST search: discard half the tree

Use it when: the tree is a BST and you are looking for a value, an insertion point, or the lowest common ancestor.

def lca(root: TreeNode, p: int, q: int) -> TreeNode:
    node = root
    while node:
        if p < node.val and q < node.val:
            node = node.left          # both targets are smaller: the answer is on the left
        elif p > node.val and q > node.val:
            node = node.right         # both larger: on the right
        else:
            return node               # they split here (or one equals node): this is the LCA

Complexity cheat-sheet

OperationBalanced treeDegenerate (a chain)
Visit every node (any traversal)O(n)O(n)
Recursion depth / stack spaceO(log n)O(n)
BST search / insert / deleteO(log n)O(n)
BFS queue sizeO(n) (widest level, up to n/2)O(1)

n is the number of nodes, h the height. Most tree solutions are O(n) time, O(h) space; the BFS queue costs O(w) where w is the widest level.

Common mistakes

  • Forgetting the None base case, or giving an empty subtree the wrong value (depth 0, not 1; sum 0; True for 'is valid').
  • Checking the BST rule only against the direct parent (left.val < node.val). [5, 1, 7, None, None, 3, 8] passes that check but 3 is in 5's right subtree, which is wrong. Carry the full (lo, hi) range down.
  • Returning the wrong thing from a recursive helper: parents usually need a local quantity (height of this subtree), while the final answer is a global one (the best diameter seen). Keep them separate.
  • Mutating the tree during traversal (e.g. inverting children) while also iterating over the original children. Swap first, then recurse on the swapped pointers.
  • In BFS, appending children in the same loop that reads len(queue) live instead of the frozen range(len(queue)), which merges levels.
  • Recursion limit: a 10⁴-node chain exceeds CPython's default 1000 frames. LeetCode raises it; locally use the iterative version or sys.setrecursionlimit.

Python tips

  • if node.left: is the idiomatic None check for children; node.left is not None is equivalent and clearer when the value could be 0.
  • To update a global best inside a nested helper, use nonlocal best or store it on self. Plain reassignment inside the helper would create a new local variable.
  • float('-inf') and float('inf') make clean initial bounds for BST checks.
  • collections.deque for BFS: popleft() is O(1); a list's pop(0) is O(n).
  • Trees in tests are given in LeetCode level order with None for missing children, e.g. [3, 9, 20, None, None, 15, 7].
