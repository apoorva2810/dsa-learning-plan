1-D Dynamic Programming

Break a problem into overlapping subproblems along one dimension.

Prerequisites: Backtracking

What it is

Dynamic programming (DP) solves a problem by first answering smaller versions of the same problem and storing those answers, so each one is computed only once. It applies when two things are true:

  • the answer can be built from the answers to smaller subproblems, and
  • the same subproblems come up again and again (they overlap), so plain recursion would redo work.

An everyday picture: someone writes 1 + 1 + 1 + 1 + 1 on a board and asks for the total. You count to 5. They append + 1 and ask again. You say 6 at once, because you remembered the 5 instead of recounting. DP is that habit applied on purpose.

Every DP solution follows the same recipe:

  1. State: one sentence saying what dp[i] means, e.g. "dp[i] = number of ways to reach stair i". Most DP bugs come from a vague state.
  2. Recurrence: express dp[i] through smaller states by asking "what was the last choice?" (the last move was 1 or 2 stairs; house i was robbed or skipped; the last coin was c).
  3. Base cases: the smallest states you can answer directly, often the empty prefix (dp[0]).
  4. Order of filling: compute states so that every cell dp[i] reads is already filled (usually left to right).
  5. Answer: say where it lives: dp[n], max(dp), or dp[0].
  6. Space: if dp[i] only reads the previous one or two cells, keep just those in variables.

"1-D" means the state is a single number: a position in an array or string, or an amount of money.

There are two ways to turn the recipe into code. Top-down (memoisation): write the recursion as it reads and add a cache (@cache in Python), so a state solved once is never solved again. Bottom-up (tabulation): allocate a list and fill it with a loop, from the base cases upward. Both do the same work. Bottom-up has no recursion-depth limit and makes the space optimisation easy to spot.

How to recognise it

  • The question asks for a number of ways, a minimum or maximum (cost, length, count), or whether something is possible, and you make a sequence of choices along an array, a string or an amount.
  • A recursive brute force exists, but it calls itself with the same arguments many times. Draw the recursion tree for a small input and look for repeated calls.
  • The choice at position i depends only on a few earlier positions or on a smaller amount: "the last step was 1 or 2", "rob or skip this house", "which coin did I use last".
  • Greedy looks tempting but a small counterexample breaks it: coins [1, 3, 4] and amount 6, where greedy takes 4 + 1 + 1 (three coins) and the best is 3 + 3 (two).
  • The input size is around 10^3 to 10^4 (or a target up to 10^4): far too big for 2^n, fine for O(n), O(n·k) or O(n²).
  • You want the best subarray or subsequence, and "the best one ending at index i" is easy to extend to index i + 1.

Filling a DP table: Climbing Stairs

How many ways are there to climb n stairs taking 1 or 2 at a time? Each cell is computed from two finished cells to its left, so one left-to-right pass fills the whole table.

Patterns and Python templates

Top-down: recursion plus a cache

Use it when: the recurrence is easy to state as a recursive function; write it first, then memoise it.

from functools import cache

def max_non_adjacent_sum(nums: list[int]) -> int:
    n = len(nums)

    @cache                                   # each best(i) is computed once, then looked up
    def best(i: int) -> int:
        """State: the best total using only nums[i:]."""
        if i >= n:                           # base case: no elements left
            return 0
        skip = best(i + 1)                   # choice 1: do not take nums[i]
        take = nums[i] + best(i + 2)         # choice 2: take it, so nums[i + 1] is off limits
        return max(skip, take)

    return best(0)                           # answer: the whole array

Define the cached function inside the solving function so every call starts with an empty cache. The recursion goes up to n levels deep, so Python's 1000-frame default limit matters for large n.

Bottom-up: fill a table in dependency order

Use it when: you know which cells each state reads; fill those first with a loop. No recursion at all.

def max_non_adjacent_sum(nums: list[int]) -> int:
    n = len(nums)
    dp = [0] * (n + 2)                       # dp[i] = best total using nums[i:]; dp[n] = dp[n + 1] = 0
    for i in range(n - 1, -1, -1):           # right to left, because dp[i] reads dp[i + 1] and dp[i + 2]
        dp[i] = max(dp[i + 1], nums[i] + dp[i + 2])
    return dp[0]

The loop direction comes from the recurrence: fill a cell only after every cell it reads. Padding the table (n + 2 cells) turns the base cases into ordinary zeros.

Rolling variables (space optimisation)

Use it when: each state reads only the previous one or two states, as in Fibonacci-like recurrences.

def max_non_adjacent_sum(nums: list[int]) -> int:
    two_back, one_back = 0, 0                # best totals for the prefixes ending two and one positions ago
    for x in nums:
        # tuple assignment: the right side uses the OLD values of both variables
        two_back, one_back = one_back, max(one_back, two_back + x)
    return one_back

O(n) space becomes O(1). Write the table version first; the rolling version is the same recurrence with every cell older than the window thrown away.

Look back over a set of choices (amounts and prefixes)

Use it when: a state can be reached from many smaller states: coins of different values, dictionary words of different lengths.

def fewest_coins(coins: list[int], amount: int) -> int:
    INF = float("inf")
    dp = [0] + [INF] * amount                # dp[a] = fewest coins that make amount a; dp[0] = 0
    for a in range(1, amount + 1):           # small amounts first
        for c in coins:                      # the LAST coin used could be any coin that fits
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
    return dp[amount] if dp[amount] != INF else -1   # INF means "cannot be made"

For "is it possible" problems the cell is a bool and min becomes or (Word Break). Use infinity, not 0, as the start value of a minimum.

Best answer ending at index i

Use it when: subarray or subsequence problems where the best result ending at i is built from results ending earlier.

def longest_increasing_subsequence(nums: list[int]) -> int:
    dp = [1] * len(nums)                     # dp[i] = longest increasing subsequence that ENDS at nums[i]
    for i in range(len(nums)):
        for j in range(i):                   # any earlier, smaller element can come right before nums[i]
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp, default=0)                # the best subsequence can end anywhere

"Ending at i" is what makes the state extendable. The final answer is a max over all cells, not the last cell.

Plain recursion without a cache is usually exponential (about 2^n calls) because it re-solves the same states. Adding a cache makes it exactly as fast as the table; the table only adds control over memory and fill order.

Common mistakes

  • A vague state. Write # dp[i] = ... as a comment before any code, and say whether i is an index ("ending at i") or a length ("the first i items"). Mixing the two causes most off-by-one bugs.
  • Wrong fill order: reading a cell before it is computed. If dp[i] reads dp[i + 1], the loop must run from right to left.
  • Wrong start values: a minimum must start at infinity (or amount + 1), a maximum at -inf when negatives are possible. Starting a minimum at 0 makes every answer 0.
  • Forgetting the base case of the empty prefix: dp[0] = 1 (one way to decode nothing), dp[0] = True (the empty string is always breakable), dp[0] = 0 (no coins make 0).
  • Top-down recursion on large inputs: Python stops at about 1000 nested calls (RecursionError). For n in the thousands, go bottom-up.

Python tips

  • from functools import cache (Python 3.9+) is shorthand for lru_cache(maxsize=None). The arguments must be hashable: pass indices or tuples, not lists.
  • Put @cache on a helper defined inside the method. A cache at class level keys on self and keeps growing across test cases.
  • float("inf") compares larger than every integer, which makes it a clean "impossible" marker for minimum problems; min(dp[a], dp[a - c] + 1) still works because inf + 1 is inf.
  • a, b = b, a + b updates two rolling variables at once from their old values; two separate assignments would use the new a by mistake.
