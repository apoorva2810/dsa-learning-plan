Intervals

Sort by start, then sweep: merge, insert, count overlaps.

Prerequisites: Heap / Priority Queue

What it is

An interval is a pair [start, end] that stands for every point on a number line from start to end: a meeting from 9 to 10, a hotel stay from day 3 to day 7, a range of IDs. Interval problems ask how a pile of such ranges relate to each other. Do two of them overlap (share at least one point)? Can a chain of them be merged into one block? How many are active at the same moment? Which ones must be dropped so the rest do not collide?

A calendar app is the everyday picture. Each event is a bar on a timeline. Two bars that overlap are a double booking, a run of overlapping bars forms one long busy block, and the tallest stack of bars at any moment is the number of rooms you need.

Almost every interval problem opens with the same move: sort first. Once the intervals are ordered by start (sometimes by end), everything that can interact with the current interval sits right next to it. One left-to-right pass, called a sweep, with a small piece of state (the last merged block, the earliest end time, a counter) finishes the job. The sort costs O(n log n) and is usually the whole bill; the sweep after it is O(n).

Before you compare anything, decide what happens when two intervals only touch: [1, 4] and [4, 5] share the single point 4. Merge Intervals says they overlap and joins them into [1, 5]. Meeting Rooms says they do not, because one meeting may end at the minute the next one begins. In code the difference is <= versus <, and it decides whether the answer is right.

In Python an interval is usually a two-item list. sorted(intervals) orders them by start and breaks ties by end, heapq keeps the earliest end time within reach, and for start, end in intervals: unpacks each pair.

How to recognise it

  • The input is a list of [start, end] pairs: meetings, bookings, jobs, flights, or ranges of numbers.
  • The statement says overlap, conflict, merge, cover, free time or non-overlapping, or asks you to remove the fewest ranges so that the rest do not collide.
  • You are asked how many things happen at the same time: rooms, platforms, servers, peak load. That number is the deepest stack of overlapping intervals.
  • You must answer questions about single points against many ranges, such as the smallest range that contains each query.
  • The input arrives unsorted, but the answer depends only on how the endpoints are ordered. Sorting is then the first step.
  • Your first idea compares every pair of ranges (O(n²)). With intervals, sorting almost always brings that down to O(n log n).

Merge Intervals: sort once, then sweep

Five intervals arrive out of order. After sorting by start, each one is compared with the last merged block. If it starts at or before that block's end, the block's end is stretched with max; otherwise it opens a new block. The blocks drawn under the input are merged.

Patterns and Python templates

Sort by start, then sweep and merge

Use it when: touching or overlapping ranges must be combined into bigger blocks, or you need the gaps between busy blocks.

def merge(intervals: list[list[int]]) -> list[list[int]]:
    merged = []                                       # finished blocks, left to right
    for start, end in sorted(intervals):              # sorted by start, ties by end
        if merged and start <= merged[-1][1]:         # starts before (or when) the last block ends
            merged[-1][1] = max(merged[-1][1], end)   # stretch that block; never shrink it
        else:                                         # a gap: this interval opens a new block
            merged.append([start, end])               # a fresh list, so the input is never edited
    return merged

After sorting by start, an interval can only reach the last block, never an earlier one: every earlier block ended before the last one began, and the current interval starts even later. That is why one comparison per interval is enough. Take the max of the two ends because a long interval can swallow the next ones whole. The free time is the gaps between merged[i][1] and merged[i + 1][0]. If the list is already sorted and disjoint (Insert Interval), skip the sort and walk it once.

The overlap test

Use it when: you have two intervals and need to know whether they collide, or which part they share.

def overlaps(a: list[int], b: list[int]) -> bool:
    """Closed intervals: [1, 4] and [4, 5] overlap, they share the point 4."""
    return a[0] <= b[1] and b[0] <= a[1]

def overlaps_strictly(a: list[int], b: list[int]) -> bool:
    """Touching does not count: a meeting may start the moment another one ends."""
    return a[0] < b[1] and b[0] < a[1]

def intersection(a: list[int], b: list[int]) -> list[int] | None:
    """The shared stretch: it starts at the later start and ends at the earlier end."""
    lo, hi = max(a[0], b[0]), min(a[1], b[1])
    return [lo, hi] if lo <= hi else None

Two intervals are apart only when one ends before the other starts: a.end < b.start or b.end < a.start. Negate that and you get the test, a.start <= b.end and b.start <= a.end. It needs both halves, works whichever interval comes first, and also covers one interval sitting inside the other. A one-sided check such as b[0] <= a[1] is only right once you know a starts first.

Min-heap of end times (how many are running right now?)

Use it when: you walk the intervals in order of start and need to know how many are still active, or which one finishes first (rooms, platforms, servers).

import heapq

def most_at_once(intervals: list[list[int]]) -> int:
    """Largest number of intervals running at the same moment (the rooms you need)."""
    ends = []                                  # min-heap: end times of the intervals still running
    most = 0
    for start, end in sorted(intervals):       # in order of start time
        while ends and ends[0] <= start:       # the earliest finisher is over by now ...
            heapq.heappop(ends)                # ... so its slot is free again
        heapq.heappush(ends, end)              # this interval takes a slot
        most = max(most, len(ends))            # slots in use right now
    return most

ends[0] is the smallest end time, the interval that frees up first. If even that one is still running when the new interval starts, every slot is busy and the heap grows. Use <= to free a slot when an interval ends exactly as the next begins, and < if touching counts as overlapping.

Sweep line over start and end events

Use it when: you only need the number of active intervals over time and would rather not keep a heap.

def most_at_once_events(intervals: list[list[int]]) -> int:
    events = []
    for start, end in intervals:
        events.append((start, 1))              # +1: an interval opens here
        events.append((end, -1))               # -1: an interval closes here
    events.sort()                              # at equal times -1 sorts before +1: a closing comes first
    active = most = 0
    for _, change in events:
        active += change
        most = max(most, active)
    return most

Split every interval into two events, an opening at start and a closing at end, and sort all of them. Adding the +1 or -1 as you walk gives the number of active intervals after each event. Python sorts tuples field by field, so (10, -1) comes before (10, 1): a meeting that ends at 10 is closed before one that starts at 10 is opened, and touching meetings do not count as overlapping. Same O(n log n) as the heap, and it is the shape of every 'something starts here, something ends there' problem.

Sort by end, keep what finishes first

Use it when: you want to keep as many non-overlapping intervals as possible, or equivalently remove as few as possible.

def keep_most(intervals: list[list[int]]) -> int:
    kept = 0
    last_end = float("-inf")                   # end of the last interval we kept
    for start, end in sorted(intervals, key=lambda iv: iv[1]):   # earliest end first
        if start >= last_end:                  # fits after the last kept one (touching is fine)
            kept += 1
            last_end = end
    return kept                                # intervals to remove = len(intervals) - kept

Of all the intervals you could take next, the one that ends first leaves the most room for the rest. Any best schedule can swap its first interval for the earliest-ending one without losing another, so the greedy choice is safe (an exchange argument). Sorting by start instead would let one huge early interval block many short ones.

Almost every interval solution costs O(n log n) in total: the sort, then a linear sweep or an n-step loop with a heap. If the input is already sorted, as in Insert Interval, the sweep alone is O(n).

Common mistakes

  • Touching endpoints. Decide first whether [1, 4] and [4, 5] overlap. Merge Intervals joins them (<=); Meeting Rooms and Non-overlapping Intervals allow them (<). Make the touching case your first test.
  • Sorting by the wrong end of the interval. Merging, inserting and counting rooms need the intervals ordered by start; 'keep as many as possible' needs them ordered by end. The wrong key still runs and gives plausible, wrong answers.
  • Assigning the new end when merging: merged[-1][1] = end shrinks [1, 10] to [1, 3] when [2, 3] follows. Take max(merged[-1][1], end).
  • Editing the caller's data by accident. merged.append(interval) stores the same list object as the input, so stretching merged[-1] also changes the input. Append a new list, [start, end]. Likewise intervals.sort() reorders the input in place; use sorted if the caller's order matters.
  • Opening before closing at the same time in an event sweep. If one meeting ends at 10 and another starts at 10, process the closing first or you count two rooms. Check the tie-break whenever you build events.

Python tips

  • sorted(intervals) compares the inner lists item by item, so it sorts by start and breaks ties by end without a key. Use key=lambda iv: iv[1] to sort by end.
  • merged[-1][1] is the end of the last block. Guard it with if merged and ..., since merged[-1] raises IndexError on an empty list.
  • float('-inf') is a handy first value for 'end of the last kept interval': the first interval always passes the check.
  • To answer queries in sorted order but report them in the original order, sort (value, index) pairs: sorted((q, i) for i, q in enumerate(queries)).
