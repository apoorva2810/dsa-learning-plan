Tries

Prefix trees for fast word and prefix lookups.

Prerequisites: Trees

What it is

A trie (say "try", from re*trie*val; also called a prefix tree) stores a set of words letter by letter. Every node stands for a prefix: the root is the empty prefix, and following the edges c → a → t from the root spells "cat". Words that start the same way share the same path, so "cat" and "car" use the same two nodes for "ca" and only split at the last letter. Each node also has a flag, is_end, that says whether a stored word ends exactly there; that is how the trie tells the word "car" apart from the mere prefix "ca".

An everyday analogy is a phone's contact search: each letter you type narrows the candidates, and names that do not start with what you typed are never looked at.

In Python a node is a small class holding a dictionary children (letter → child node) and a boolean is_end. Some solutions skip the class and nest plain dictionaries, using a special key such as "$" to mark word ends. Inserting a word, looking it up, and asking "does any word start with this prefix?" each take O(L) for a string of length L, no matter how many words are stored.

How to recognise it

  • The task is about prefixes: starts with, autocomplete, search suggestions, replacing a word by its shortest root.
  • Many words must be matched against the same input (a letter grid, a stream of characters, a long text), and checking them one by one would repeat the work on their shared beginnings.
  • Lookups contain a wildcard (. matches any one letter) against a fixed dictionary of words.
  • A backtracking search should stop as soon as the letters chosen so far cannot begin any valid word.
  • Bitwise questions over many numbers, such as the maximum XOR of two of them: a trie over the binary digits of each number.

Patterns and Python templates

Trie node class: insert, search, starts_with

Use it when: the standard trie: exact-word lookups and prefix checks on a growing set of words.

class TrieNode:
    def __init__(self):
        self.children = {}        # letter -> TrieNode
        self.is_end = False       # does a stored word end exactly here?


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            if ch not in node.children:          # create the missing step
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def _walk(self, s: str):
        """Follow s from the root; return the node it ends at, or None."""
        node = self.root
        for ch in s:
            node = node.children.get(ch)
            if node is None:
                return None
        return node

    def search(self, word: str) -> bool:
        node = self._walk(word)
        return node is not None and node.is_end  # the path AND the end flag

    def starts_with(self, prefix: str) -> bool:
        return self._walk(prefix) is not None    # the path is enough

search and starts_with share one walk; they differ only in whether the end flag matters.

Nested dictionaries with an end marker, and wildcard search

Use it when: you want a short trie, or lookups may contain '.' meaning any one letter.

END = "$"                                    # a key that can never be a letter


def build(words: list[str]) -> dict:
    root = {}
    for w in words:
        node = root
        for ch in w:
            node = node.setdefault(ch, {})   # walk, creating as needed
        node[END] = w                        # store the whole word at its end
    return root


def matches(node: dict, pattern: str, i: int = 0) -> bool:
    """Does some stored word match pattern, where '.' is any one letter?"""
    if i == len(pattern):
        return END in node
    ch = pattern[i]
    if ch == ".":                            # branch into every child
        return any(matches(child, pattern, i + 1)
                   for key, child in node.items() if key != END)
    return ch in node and matches(node[ch], pattern, i + 1)

A pattern with d dots can visit up to 26^d paths, so the worst case is O(26^d · L); without dots it is O(L).

Collect every word under a prefix (autocomplete)

Use it when: you need the stored words that start with a given prefix, not just a yes/no answer.

def words_with_prefix(root: dict, prefix: str) -> list[str]:
    node = root
    for ch in prefix:                        # 1) walk down to the prefix node
        if ch not in node:
            return []
        node = node[ch]
    found, stack = [], [node]                # 2) gather every word below it
    while stack:
        cur = stack.pop()
        for key, child in cur.items():
            if key == END:
                found.append(child)          # END maps to the stored word
            else:
                stack.append(child)
    return sorted(found)

Cost: O(len(prefix)) to find the node, plus the size of the subtree below it. Uses build and END from the pattern above.

Trie + grid DFS with pruning

Use it when: find which of many words can be traced on a board (Word Search II style).

def find_words(board: list[list[str]], words: list[str]) -> list[str]:
    root = build(words)                      # nested-dict trie, words stored at END
    rows, cols, found = len(board), len(board[0]), []

    def dfs(r, c, parent):
        ch = board[r][c]
        node = parent[ch]
        if END in node:
            found.append(node.pop(END))      # report each word once
        board[r][c] = "#"                    # this cell is on the current path
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] in node:
                dfs(nr, nc, node)            # only step where the trie continues
        board[r][c] = ch
        if not node:                         # nothing left below: prune the branch
            del parent[ch]

    for r in range(rows):
        for c in range(cols):
            if board[r][c] in root:
                dfs(r, c, root)
    return found

The trie check board[nr][nc] in node stops a path the moment it cannot be a prefix of any remaining word, and deleting finished branches keeps later searches from re-walking them.

Complexity cheat-sheet

For a string of length L, N stored words and alphabet size 26:

OperationTrieSet of words
insert a wordO(L)O(L) (hashing the string)
exact lookupO(L)O(L) on average
does any word start with p?O(len(p))O(N · L): check every word
list the words starting with pO(len(p) + size of the subtree)O(N · L)
wildcard lookup with d dotsO(26^d · L) worst caseO(N · L)
memoryone node per distinct prefix, each with a small dictthe strings themselves

The trie wins whenever the question is about prefixes; for exact lookups only, a set is simpler and usually smaller.

Common mistakes

  • Forgetting the end-of-word flag: after inserting apple, search('app') must be False even though the path a-p-p exists.
  • A mutable default argument, def __init__(self, children={}), makes every node share one dictionary. Create the dictionary inside __init__.
  • Treating 'the path exists' and 'the word exists' as the same question. starts_with needs only the path; search needs the path and is_end.
  • In grid or backtracking searches, building the trie but not consulting it at every step. The speed-up comes from stopping a path the moment it leaves the trie.
  • Assuming a trie saves memory. Each node carries a dictionary, so many long, unrelated words can take several times the space of the strings in a set.

Python tips

  • node = node.children.setdefault(ch, TrieNode()) is compact, but it builds a throwaway TrieNode() on every call (the argument is evaluated even when the key exists). The two-line if ch not in node.children: form avoids that.
  • __slots__ = ('children', 'is_end') on the node class saves memory per node, which adds up with tens of thousands of words.
  • The one-line trie Trie = lambda: defaultdict(Trie) creates children on demand, but a mere lookup like node[ch] also creates them. Use ch in node to test without growing the trie.
  • Storing the whole word at its end node (node.word = w) saves rebuilding it from the path later; Word Search II uses this.
