Sliding Window

Keep a moving range over an array or string and update it incrementally.

Prerequisites: Two Pointers

What it is

A sliding window is a contiguous range nums[left..right] (or s[left..right]) that moves along the input. Instead of recomputing an answer for every possible range from scratch, you update it as the window changes: add the element that enters on the right, remove the element that leaves on the left.

Picture reading a long line of text through a slot cut in a piece of card. Sliding the card one letter to the right reveals one new letter and hides one old one; you do not reread the letters in between.

Windows come in two kinds:

  • Fixed size k: every step adds one element and removes one (moving sums and averages, "an anagram of length k", "the maximum of every k consecutive values").
  • Variable size: right grows the window, and left shrinks it when the problem requires (the longest substring with no repeats, the shortest substring containing given letters).

A variable window works only when the condition is monotone: for "longest" problems, every smaller window inside a valid one is valid too; for "shortest" problems, every bigger window around a valid one is valid too. That is what allows left to move forward and never come back.

left = 0
for right, x in enumerate(nums):      # x enters the window
    add(x)
    while window_is_invalid():
        remove(nums[left])            # nums[left] leaves the window
        left += 1
    best = max(best, right - left + 1)

How to recognise it

  • The question is about a contiguous subarray or substring, not a subsequence.
  • It asks for the longest, shortest, or the maximum/minimum of something over such ranges.
  • A window of fixed length k is named outright: "every k consecutive days", "a substring of length len(p)".
  • Validity depends on counts inside the range: at most k distinct, no repeats, contains all these letters, at most k changes.
  • The brute force is two nested loops over (start, end), and the work for end + 1 mostly repeats the work for end.

A variable-size window with a Counter: the longest substring with at most k distinct letters

right adds one letter per step. When the window holds more than k different letters, left moves forward until it is valid again. The Counter records how many of each letter are inside, and a letter whose count drops to 0 is deleted so that len(count) is the number of distinct letters.

Patterns and Python templates

Fixed-size window

Use it when: every window has exactly k elements: sums, averages, counts over each k consecutive items.

def max_sum_of_k(nums: list[int], k: int) -> int:
    window = sum(nums[:k])                    # the first window
    best = window
    for right in range(k, len(nums)):
        window += nums[right] - nums[right - k]   # one element enters, one leaves
        best = max(best, window)
    return best

Longest valid window: shrink while invalid

Use it when: find the longest range that satisfies a condition which only gets easier as the range shrinks.

def longest_without_repeats(s: str) -> int:
    window = set()
    left = best = 0
    for right, c in enumerate(s):
        while c in window:                    # invalid: shrink from the left
            window.remove(s[left])
            left += 1
        window.add(c)
        best = max(best, right - left + 1)    # the window is valid here
    return best

Record the answer after the shrink loop, once the window is valid again.

Shortest valid window: shrink while valid

Use it when: find the shortest range that satisfies a condition which only gets easier as the range grows.

from collections import Counter

def shortest_covering(s: str, t: str) -> int:
    need = Counter(t)                         # copies still needed (negative = surplus)
    missing = len(t)
    left, best = 0, float("inf")
    for right, c in enumerate(s):
        if need[c] > 0:
            missing -= 1
        need[c] -= 1
        while missing == 0:                   # valid: record, then try to shrink
            best = min(best, right - left + 1)
            need[s[left]] += 1
            if need[s[left]] > 0:
                missing += 1
            left += 1
    return 0 if best == float("inf") else best

Record the answer inside the shrink loop: the window is at its shortest just before it becomes invalid.

Fixed window with counts (anagram check)

Use it when: a window of fixed length must match a multiset of letters (permutation, anagram).

from collections import Counter

def has_anagram_window(p: str, s: str) -> bool:
    k = len(p)
    need = Counter(p)
    missing = k                               # letters of p the window still lacks
    for right, c in enumerate(s):
        if need[c] > 0:
            missing -= 1
        need[c] -= 1
        if right >= k:                        # keep the window at exactly k characters
            old = s[right - k]
            need[old] += 1
            if need[old] > 0:
                missing += 1
        if missing == 0:
            return True
    return False

One missing number replaces comparing two count tables, so each step is O(1).

Monotonic deque (window maximum or minimum)

Use it when: you need the largest (or smallest) value of every window in O(1) per step.

from collections import deque

def window_maxima(nums: list[int], k: int) -> list[int]:
    dq = deque()                              # indices; their values decrease front to back
    out = []
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:       # smaller, older values can never be the max again
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:                    # the front left the window
            dq.popleft()
        if i >= k - 1:
            out.append(nums[dq[0]])
    return out

Flip the comparison (>=) for window minima. Store indices, not values, so you can tell when the front expires.

Complexity cheat-sheet

PatternTimeExtra space
Fixed-size window with a running sumO(n)O(1)
Variable window with a set or counterO(n)O(alphabet) or O(window)
Comparing two count tables at every stepO(n · alphabet)O(alphabet)
Monotonic deque for window max/minO(n)O(k)
Brute force over all (start, end) pairsO(n²) ranges, times the cost of checking onevaries

The while inside the for does not make it O(n²): left and right each move forward at most n times in total, so the loop body runs at most 2n times. Counting the total work over the whole run, rather than the worst single step, is called amortised analysis.

Common mistakes

  • Using a sliding window when validity is not monotone. With negative numbers, "a subarray with sum exactly k" can become valid again after growing, so left would need to move back; use prefix sums with a hash map instead.
  • Updating the answer at the wrong moment: after the shrink loop for longest problems, inside it for shortest problems.
  • Forgetting to undo left's contribution. Every left += 1 must first remove nums[left] from the set, sum or counter.
  • Off-by-one window lengths: the inclusive window left..right has right - left + 1 elements.
  • Comparing whole counters at every step (Counter(a) == Counter(b)) costs O(alphabet) per step; a single "how many are still missing" number makes it O(1).

Python tips

  • for right, c in enumerate(s) gives the right edge and the entering element together; left is a plain integer you advance.
  • collections.Counter and defaultdict(int) let you write count[c] += 1 without checking for the key; reading a missing key from a Counter returns 0.
  • A plain dict that still holds a key with count 0 is not equal to one without that key. Delete keys that reach 0 if you compare dicts (since Python 3.10, Counter equality treats missing keys as 0).
  • collections.deque gives O(1) append, pop, appendleft and popleft, which a monotonic deque needs at both ends.
