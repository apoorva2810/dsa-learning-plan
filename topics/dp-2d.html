2-D Dynamic Programming

Two indices or two sequences: grids, string alignment, intervals.

Prerequisites: 1-D Dynamic Programming, Graphs

What it is

In 2-D dynamic programming a state needs two numbers to pin it down, so the stored answers form a table instead of a list. The 1-D recipe still applies (state, recurrence, base cases, fill order, answer, space). The new skill is reading a table: what a row means, what a column means, which neighbouring cells a cell reads, and which cell holds the answer.

An everyday picture: a spreadsheet where every formula refers only to the cell above, the cell to the left and the cell diagonally up-left. Fill it row by row, left to right, and every formula finds its inputs already computed.

The two numbers usually mean one of these:

ShapeStateTypical questionA cell reads
Grid pathsdp[r][c] = answer for cell (r, c)count paths, cheapest pathup (r-1, c) and left (r, c-1)
Two strings aligneddp[i][j] = answer for the prefixes a[:i] and b[:j]common subsequence, edit distance, pattern matchingdiagonal (i-1, j-1), up, left
Knapsack rowsdp[i][x] = answer using the first i items with target xcount or test subsets that hit a sumthe row above at x and at x - item
Intervaldp[l][r] = answer for the piece l..r of one arrayburst, merge or cut piecesshorter intervals inside l..r
Position + modedp[i][s] = best result after step i while in mode sstock trading with a cooldownthe previous step's modes

Prefix tables get an extra row and column. For strings of lengths m and n the table is (m + 1) × (n + 1). Row 0 and column 0 stand for the empty prefix, and that is where the base cases live: the longest common subsequence with an empty string is 0, and turning "abc" into "" takes 3 deletions. The answer for the full strings is the bottom-right cell dp[m][n].

Top-down or bottom-up. A recursive function of two arguments, f(i, j), with @cache on top is the quickest correct version to write, and it only computes the cells it actually reaches. The bottom-up table makes the fill order explicit, has no recursion-depth limit, and opens the door to the space trick below.

Rolling rows. When row i reads only row i - 1, keep one or two rows instead of all m + 1, and memory falls from O(m·n) to O(n). With a single list, row[j] before you overwrite it still holds the value from the row above, while row[j - 1] already holds the current row; the diagonal value needs one saved variable. The price is that you can no longer walk back through the table to rebuild the actual path, alignment or subsequence.

How to recognise it

  • Two strings or sequences are compared, aligned, merged or matched: common subsequence, edit, convert, interleave, matches the pattern. The state is a pair of prefix lengths (i, j).
  • A grid where you may only move one way (right or down) and the question is how many paths there are or what the cheapest path costs. Each cell depends on the cells it can be entered from.
  • You choose a subset of items to hit a target or fit a capacity and must count the ways or test whether it is possible (coins, +/- signs, subset sums): items on one axis, the running amount on the other.
  • Pieces of one array are burst, merged or cut, and the cost of an action depends on which neighbours are still there. Ask which action happens last inside an interval l..r.
  • A sequence where every step is in one of a few modes (holding a stock, just sold, resting). The second index is the mode, so the table has only a handful of columns.
  • A plain recursion has two arguments that change, each ranging up to about 10^3. That is about 10^6 states, fine for a table; the 2^n recursion tree is not.

Filling a 2-D table: Longest Common Subsequence

Each cell answers the question for one pair of prefixes. A cell reads the cell diagonally up-left when its two characters match, otherwise the cells above and to its left, so a row-by-row fill always finds its inputs ready.

Patterns and Python templates

Two-argument recursion with @cache (top-down)

Use it when: you can state the answer for (i, j) through answers for smaller pairs; write it recursively first.

from functools import cache

def lcs_length(a: str, b: str) -> int:
    @cache                                     # one stored answer per pair (i, j)
    def f(i: int, j: int) -> int:
        """State: length of the longest common subsequence of the suffixes a[i:] and b[j:]."""
        if i == len(a) or j == len(b):         # base case: one suffix is empty
            return 0
        if a[i] == b[j]:                       # same first character: use it in both
            return 1 + f(i + 1, j + 1)
        return max(f(i + 1, j), f(i, j + 1))   # otherwise skip the first character of one string

    return f(0, 0)                             # answer: both strings in full

m·n distinct pairs, O(1) work each, so O(m·n) time. The recursion can be m + n calls deep: for strings longer than a few hundred characters, convert it to the table below.

Two sequences bottom-up: an (m + 1) × (n + 1) table with labels

Use it when: the state is a pair of prefixes; every cell reads the diagonal, the cell above and the cell to the left.

def lcs_table(a: str, b: str) -> list[list[int]]:
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]   # dp[i][j] = LCS of a[:i] and b[:j]; row 0 / col 0 = empty prefix
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:              # cell (i, j) talks about the characters a[i-1] and b[j-1]
                dp[i][j] = dp[i - 1][j - 1] + 1   # diagonal: the shared character ends the subsequence
            else:
                dp[i][j] = max(dp[i - 1][j],      # up: leave out a[i-1]
                               dp[i][j - 1])      # left: leave out b[j-1]
    return dp                                     # the answer is dp[m][n]


def print_table(dp: list[list[int]], a: str, b: str) -> None:
    """Debugging aid: print the table with its row and column labels ('' = the empty prefix)."""
    print("    " + " ".join(f"{c:>3}" for c in ["''"] + list(b)))
    for label, row in zip(["''"] + list(a), dp):
        print(f"{label:>3} " + " ".join(f"{x:>3}" for x in row))

The extra row and column turn the base cases into ordinary cells. The price is an index shift: cell (i, j) compares a[i - 1] with b[j - 1]. Printing the table for a 4-character example finds most bugs at a glance.

Grid paths with one rolling row

Use it when: moves go only right or down, so a cell is entered from above or from the left.

def count_paths(grid: list[list[int]]) -> int:
    """Paths from the top-left to the bottom-right cell moving right or down; grid[r][c] == 1 is a wall."""
    rows, cols = len(grid), len(grid[0])
    row = [0] * cols              # row[c] = number of paths into (r, c) for the row being filled
    row[0] = 1                    # one way to stand on the start cell (made 0 below if it is a wall)
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == 1:
                row[c] = 0        # no path goes through a wall
            elif c > 0:
                row[c] += row[c - 1]   # old row[c] = paths from above, row[c - 1] = paths from the left
    return row[-1]

The full table is dp[r][c] = dp[r - 1][c] + dp[r][c - 1]. It only ever reads the row above, so one list is enough. For a cheapest path, replace the sum with min(up, left) + cost[r][c].

Knapsack rows rolled into one list (0/1 versus unbounded)

Use it when: items on one axis and a target amount on the other; count the ways or test whether the target is reachable.

def count_subsets(nums: list[int], target: int) -> int:
    """0/1 knapsack: subsets (each item used at most once) whose sum is target."""
    dp = [1] + [0] * target                # dp[x] = ways to reach x with the items seen so far (1 way to make 0)
    for x in nums:                         # one row of the 2-D table per item
        for total in range(target, x - 1, -1):   # DOWNWARD: dp[total - x] still belongs to the previous row
            dp[total] += dp[total - x]
    return dp[target]


def count_coin_combinations(coins: list[int], amount: int) -> int:
    """Unbounded knapsack: ways to make amount when every coin can be reused."""
    dp = [1] + [0] * amount
    for c in coins:                        # items in the OUTER loop: each combination is counted once
        for total in range(c, amount + 1): # UPWARD: dp[total - c] may already contain coin c
            dp[total] += dp[total - c]
    return dp[amount]

The underlying table is dp[i][x] = ways using the first i items to reach x. Row i reads only row i - 1, so one list works, and the direction of the inner loop decides whether dp[x - item] is the old row (item used at most once) or the new row (item reusable).

Interval DP: fill dp[l][r] by increasing length

Use it when: the answer for a piece l..r of one array depends on how that piece splits, often around the last action performed inside it.

def merge_piles(piles: list[int]) -> int:
    """Merge adjacent piles until one pile is left. Merging two piles costs their combined size.
    Return the minimum total cost."""
    n = len(piles)
    prefix = [0]
    for p in piles:
        prefix.append(prefix[-1] + p)       # sum(piles[l:r + 1]) == prefix[r + 1] - prefix[l]
    dp = [[0] * n for _ in range(n)]        # dp[l][r] = cheapest way to merge piles l..r; one pile costs 0
    for length in range(2, n + 1):          # short intervals first: longer ones read them
        for l in range(n - length + 1):
            r = l + length - 1
            # the LAST merge joins (piles l..k) with (piles k+1..r) and costs the size of everything in l..r
            best_split = min(dp[l][k] + dp[k + 1][r] for k in range(l, r))
            dp[l][r] = best_split + prefix[r + 1] - prefix[l]
    return dp[0][n - 1]

Row-by-row filling breaks here, because dp[l][r] reads cells to its left and below it. Going by length guarantees every shorter interval is done. The answer is the top-right cell. O(n³): n² intervals, up to n split points each.

Complexity cheat-sheet

Time = number of states × work per state. Space = the states you keep.

T is the target amount. A running time like O(n·T) is called pseudo-polynomial: it grows with the value of the target, not with the length of the input, so a target of 10^9 is out of reach even for ten items.

Rolling rows only cuts memory when a row reads a fixed number of earlier rows. Interval tables read cells from many rows and keep their full size.

Common mistakes

  • [[0] * n] * m creates m references to one list, so writing dp[1][2] changes every row. Build tables with [[0] * n for _ in range(m)].
  • Off-by-one with the empty-prefix row: in an (m + 1) × (n + 1) table, cell (i, j) compares a[i - 1] with b[j - 1]. Mixing a[i] and a[i - 1] in one solution is the most common 2-D DP bug.
  • Wrong fill order. A table over suffixes (dp[i][j] about a[i:]) fills from the bottom-right corner backwards, and an interval table fills by increasing length, not row by row.
  • Rolling a row in the wrong direction: an upward inner loop overwrites dp[x - item] before it is read, which turns a 0/1 knapsack into an unbounded one. In one-row string DPs, forgetting to save the diagonal before overwriting it gives the same kind of silent error.
  • Base cases on the borders are not always 0: edit distance has dp[i][0] = i, and a pattern like a*b* matches the empty string, so row 0 of the regex table needs its own loop.

Python tips

  • @cache works with any number of hashable arguments: f(i, j) is cached per pair. Strings and tuples are hashable; lists are not.
  • Define the cached helper inside the method so each test case starts with an empty cache; a module-level cached function needs f.cache_clear() between inputs.
  • for length in range(2, n + 1): for l in range(n - length + 1): r = l + length - 1 is the standard interval loop; keep it as a snippet.
  • prev, cur = cur, prev swaps two rolling rows in one statement, because the right-hand side is evaluated before either name is reassigned.
